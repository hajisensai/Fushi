## BUG-3801 · 云同步有声书阶段逐本遍历全部书（含漫画）且收尾阶段无进度，最后一本像卡死
- **报告**：2026-10-25 / 2026-10-26（应用内反馈 y3tzvcnrPU：Android + Google Drive「每次同步到最后一本书都好长时间没反应」；DRXb43v3fA：macOS「只有 1 本有声书却显示有声书 0/4，逐本走过漫画，最后一本漫画卡 10–20 秒才完成」）
- **真实性**：✅ 真 bug，两个根因叠加（基线 `4f66a48452`）：
  1. **有声书阶段的工作集是全表**：`fushi/lib/src/sync/sync_orchestrator.dart:1866-1867`（`syncAudiobookPackages`）以 `_db.getAllEpubBooks()` 为循环集合、`itemTotal = books.length`——漫画与无有声书的书都在 `EpubBooks` 表里；每本都在 `:1870` 发「同步有声书 (k/N)」，并在 `:1895-1904` 无条件 `ensureBookFolder` + 最多两次 `findAsset`（Drive 上每本最多 3 次网络往返）。`:1888` 算出的 `hasLocal` 只在 `:1906` 决定传不传，没有用来缩小工作集。而这条通道是 upload-only（远端独有包不自动拉），远端状态只对本端确有有声书的书才有意义。
  2. **收尾阶段不发进度**：`run()` 在有声书 / 视频之后的 `_syncAggregate`（`:870`）、`syncCollections` + `_syncMediaLinksCloud`（`:890`）、`syncDeletionTombstones`（`:901`）、待发制卡中转都不 emit；`syncProgress` 只在整轮结束时清空（`sync_auto_trigger.dart:89`），于是进度行停在上一阶段最后一本书上——这正是「最后一本卡住」的那段时间。互联通道同样：live 进度 / 聚合 / 合集 / 标签 / 墓碑全程静默。
  - 互联通道的有声书阶段**不同型**：`sync_orchestrator/audiobooks.part.dart` 的 `_syncAudiobooksLive` 已经是一次 `listRemoteAudiobooks` + 本地 key 集合 diff，分母 = push + pull 真实工作集；只补了阶段开工 tick。
- **[x] ① 已修复** — `a1d0a6104a`（`fix(sync): audiobook phase iterates only books with a local audiobook`）：`syncAudiobookPackages` 的工作集改由 `_localAudiobookPushSet` 纯本地决定（`getAllAudiobooks` 建 key 表 → 按书架顺序取有 SrtBooks 行且 `audiobookAudioIsIntact` 的书），只对工作集里的书碰远端，分母 = 工作集大小；新增 `SyncPhase.statistics / collections / deletions / pendingMines` 与 `_emitPhaseStart`（`itemTotal 0` = 只显阶段名 + 不确定进度条），两条通道的每个收尾阶段与有声书阶段开工前都发一次；三个新 i18n key 经 `i18n_sync --add`。
- **[x] ② 已加自动化测试** — `fushi/test/sync/sync_orchestrator_test.dart` 组 `audiobook phase work set (DRXb43v3fA / y3tzvcnrPU)`：计数假后端 `_CountingSyncBackend` 钉死 3 漫画 + 1 有声书 + 1 断链有声书时 `ensureBookFolder` 只调 1 次、`findAsset` 2 次、计数 tick 分母恒为 1；无有声书时零远端调用；`run()` 后有声书之后依次出现 `collections` / `deletions` tick。变异实测：换回旧实现三条全红（`ensureBookFolder` 实际走了 5 本 / 3 本、无阶段 tick）。
- **备注**：未在真机 / 真 Google Drive 上复测耗时；收尾阶段本身（Drive 上聚合 / 合集 / 墓碑的多次往返）的绝对耗时没有缩短，这次只让界面如实显示当前在做哪一步——若用户仍嫌慢，需看诊断日志 `SyncRunReport.timing` 的分阶段耗时再定。反馈里「点开进度看详情」的功能诉求未做。
