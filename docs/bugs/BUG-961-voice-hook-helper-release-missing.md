## BUG-961 · galgame voice hook helper 引擎组件下载 404（release 从未产出）
- **报告**：2026-07-21（用户：开 galgame 时「引擎组件下载失败: HttpException: download failed (404): https://gh.llkk.cc/https://github.com/hajisensai/hibiki/releases/download/voice-hook-helper/voice_hook_x86.zip」）
- **真实性**：✅ 真 bug。app 端 `hibiki/lib/src/mining/galgame_helper_installer.dart:44` 拼的稳定下载 URL（`releases/download/voice-hook-helper/voice_hook_<arch>.zip`）正确，但固定 tag `voice-hook-helper` 的 prerelease **在 hajisensai/hibiki 上根本不存在**（`gh release view voice-hook-helper` → release not found），所有镜像/直连自然 404。根因不在 app 代码，在发布侧：
  - `.github/workflows/voice-hook-helper.yml:19-22` 仅 `workflow_dispatch` 触发，从未被成功运行过。
  - 该 workflow 文件**只在 develop 分支**，不在默认分支 `main`（`gh api .../contents/...yml?ref=main` → 404）。GitHub 的 `workflow_dispatch` 只对**默认分支上存在**的 workflow 暴露「Run workflow」入口，故 `gh workflow run voice-hook-helper` 报 `could not find any workflows`、API dispatch 也 404 —— 这个 helper release **无法经正常 dispatch 产出**，于是永远缺席。
- **[x] ① 已修复** — 本地用 CI 同款工具链（MSVC 2022 + 现装 user-local .NET 8 SDK `C:\Users\wrds\.dotnet`；系统只有 .NET 6，装 8 是因 `unity_audio_extract` 目标 net8.0）复现 `voice-hook-helper.yml` 全流程：x64/x86 各 `cmake -A x64/-A Win32 --config Release` 构建通过，`ctest` 各 7 项全过，`hibiki_luna_symcheck` x64/x86 必需导出齐全；按契约每架构打包正好 4 文件（injector.exe + hook.dll + LunaHook<arch>.dll + LunaHost<arch>.dll）平铺进 `voice_hook_<arch>.zip` + sha256 侧车；`gh release create voice-hook-helper --prerelease --latest=false --target 48cf9152`（develop HEAD）上传 4×2 资产。核实：4 资产直连与用户报错的 `gh.llkk.cc` 镜像均 HTTP 200；远端 sha256 侧车与本地打包哈希逐位相等（x64 `bc474042…31cfb`）；仓库 Latest 仍是正式 `v1.2.0`（未被 helper 顶替，遵守发布通道硬规则）。发布 commit：本 bug 档提交哈希见下。
  - ⚠️ **复发根源未根治**：workflow 仍只在 develop、不可 dispatch。要让后续刷新 helper 不必手动本地发布，需把 `voice-hook-helper.yml` 放到默认分支 `main`（或改用别的触发方式）。但 develop→main 属发布动作、且规则禁止 push main，本轮不做，留作跟进。
- **[x] ② 已加自动化测试** — 下载 URL/资产名/tag 契约已有 `hibiki/test/mining/galgame_helper_installer_test.dart` 守卫（`galgameHelperZipName`/`galgameHelperDownloadUrl`/`kGalgameHelperReleaseTag` 断言）。release 是否真实存在属**发布侧运行时事实**，非单测可覆盖（需网络+GitHub 状态），不加空转测试；本 bug 的实测证据（4 资产 200 + sha256 匹配）即验收。
- **备注**：helper 首版仅 Windows。x64 构建含 `unity_audio_runtime`（Unity IL2CPP 音频提取运行时），但 CI 契约与 app 端 `_extractZip`（只取 basename 平铺、丢目录结构）都只分发/解压那 4 个平铺文件，故本次打包与之一致；Unity 音频运行时的分发若有需要属另一独立问题，不在本 bug 范围。
