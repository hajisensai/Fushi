## BUG-4281 · Game stream: companion R1 panel drive takes the controller when the stream leaves the second screen to the companion
- **报告**：2026-11-08（双屏真机串流排查：AYN Thor 串流时「手柄好像不工作」。用户实际遇到的是主机端问题——Windows 主机后台模式只向游戏窗口 PostMessage、Unity 游戏未获焦点时不读，前台模式 `SetForegroundWindow` 被前台锁拒绝，见双屏进度日志「Game stream audio/controller」；本条是排查中沿代码路径发现的分支引入问题）
- **真实性**：✅ 真 bug（本分支引入）：S6 在 `GamepadService` 装了 Android 早期按键处理器 `_onEarlyKey` → `interceptNativeControllerLookupKey`（`fushi/lib/src/shortcuts/gamepad_service.dart`），先把每个手柄键交给 `ControllerLookupMode.onPress`（`fushi/lib/src/second_screen/input/controller_lookup_mode.dart`）。只要副屏伴侣处于 companion 模式（`SecondScreenController.isActive`，`second_screen_controller.dart:107`），R1 就被当成「按住 R1 驱动副屏」吃掉，按住期间其余所有键也被吞（`return true; // everything else is swallowed`），松开只经 `_dispatchButtonCore` 重放、不进串流页的按键处理器。串流时把「第二块屏」设为关闭（或串流面板尚未接管副屏）时伴侣仍在 companion 模式 → 串流页收不到 R1，按住 R1 时游戏收不到任何键。
- **[x] ① 已修复** — `ControllerLookupMode.claimRawInput / releaseRawInput`：转发原始手柄的页面在屏期间声明占有，期间查词模式与 R1 驱动副屏一律不截获（`onPress` / `onRelease` / `onStickMove` / `onRightStick` / `swallowsRepeat` 都放行，声明时结束进行中的副屏驱动）；`GameStreamPage` 在 `initState` 声明、`dispose` 释放。
- **[x] ② 已加自动化测试** — `fushi/test/second_screen/controller_lookup_mode_test.dart`（声明后所有键、摇杆、Android 早期处理器都放行，只认本人释放，释放后 R1 恢复驱动副屏）；`fushi/test/pages/game_stream_page_test.dart`（串流页挂载即声明、卸载即释放，伴侣在线时 R1 不再被截获）。
- **备注**：串流面板占着副屏时伴侣不是 companion 模式，R1 本来就不被截获；本条只影响「串流不用第二块屏」或面板接管前的时段。
