## BUG-5556 · 桌面手柄绑定的全屏 / AI 助手等 global 动作按了没反应
- **报告**：2026-11-27（做应用内反馈 OElRvCndxk「打开待发卡片」快捷键时沿代码路径发现，非用户报告）
- **真实性**：✅ 真 bug（代码路径确认，未在真机按过）。global scope 开着手柄通道（`fushi/lib/src/shortcuts/shortcut_action.dart` `ShortcutScope.channels` 的 `global` 分支），设置页能给「窗口全屏」「呼出 AI 助手」绑手柄键；但它们的执行体只在 app 根的键事件处理器里（`fushi/lib/src/shortcuts/global_navigation.dart:551` `_handleGlobalOpenAiAssistant`、`_handleGlobalToggleFullscreen`，挂在 `:941` `wrapWithGlobalNavigation` 的 `Focus.onKeyEvent`）。Android 的手柄按钮是引擎送来的键事件，能走到那里；桌面（Windows / macOS / Linux）的手柄由 `gamepads` 插件轮询，`GamepadService._dispatchButtonCore` 只把按钮派给页面 Actions（`GamepadButtonIntent`），页面没消费时只兜滚页（`fushi/lib/src/shortcuts/gamepad_service.dart:558` `_tryScrollPage`）、「返回上一级」和焦点导航，global 的这几个动作没有任何执行点——绑了按下去没反应（首页 `_handleGamepadButton` 能解析到 global 动作，但它的 `_executeShortcutAction` 对它们落 default 返回 ignored）。
- **[x] ① 已修复** — 「直接做一件事」的 global 动作（全屏 / AI 助手 / 新增的打开待发卡片）收口到一个执行体 `runGlobalCommandAction`（`global_navigation.dart`），键盘 / Android 手柄键事件（`_handleGlobalCommand`）、鼠标（`_executeGlobalMouseAction`）共用；`GamepadService.runGlobalCommand`（main.dart 装上同一个执行体）在桌面手柄按钮没被页面消费、也不是滚页时按 global scope 解析并执行。
- **[x] ② 已加自动化测试** — `fushi/test/shortcuts/global_open_pending_cards_shortcut_test.dart`「桌面手柄：页面没消费的按钮绑到它时经 GamepadService 打开」与「runGlobalCommandAction 只认领直接做一件事的动作」。
- **备注**：视频页自己处理 `globalToggleFullscreen`（`video_player_shortcuts.dart`），不受影响。未做真机手柄复测。
