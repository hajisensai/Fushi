## BUG-664 · 查词卡音高数字浮动/读音位置不如 Niratan 整齐
- **报告**：2026-07-09（用户：TODO-1354）
- **真实性**：✅ 真 bug — 根因 `hibiki/assets/popup/popup.css` 的 `.pitch-entries { list-style: circle inside }`（旧版）。查词卡音高区（`createPitchGroup`，`hibiki/assets/popup/popup.js:1650`）把每条音高渲染成 `<ul class="pitch-entries"><li>…</li></ul>` 的 list-item，CSS 用 `list-style: circle inside` 让每条各占一行竖排；音高数字 `[n]`（`popup.js:1658` 的 `document.createTextNode(' [${pitch}]')`）跟着各自的读音换行，与音高来源药丸(`.pitch-dict-label`)、片假名读音基线错开，多词典/多读法时尤其散——即用户对比 Niratan 说的「音高数字浮动」。参考同源项目 Niratan（`W1ght/Niratan`）的 `Features/Popup/popup.js:1921` 的 `compactPitchAccents`：把 `.pitch-entries` 及其 `> li` 设为 `display:inline`、多条用暗淡 ` | ` 分隔，整行平铺即「整齐」。Hibiki 已对 glossary 释义做过等价行内压缩（`popup.js:2352` glossary-list），唯独音高区没做。例句缩进两者一致（都 `ol{padding-left:1.8em}`），headword 振假名两者都走原生 ruby（`postProcessRuby` 只碰 `.glossary-content ruby`，不碰 headword），故本次只需修音高区。
- **[x] ① 已修复** — `hibiki/assets/popup/popup.css` 把 `.pitch-entries` 从 `list-style: circle inside`（竖排）改为 `display: inline` + `list-style: none`，`.pitch-entries > li` 行内 + `white-space: nowrap`，`.pitch-entries > li:not(:last-child)::after { content: " | "; opacity: 0.6 }` 多条暗淡分隔（单条无分隔，观感等同旧单行）。来源药丸 + 读音 + `[n]` 同基线平铺，与 Niratan 一致。IPA 转写(`.pitch-transcriptions`)是独立兄弟块、音高 overline(`.pronunciation-mora-line`) 绝对定位逻辑均不变，零回归。改后已 re-vendor（字节拷 popup.css 到两 extension vendor + `node tools/browser-extension/scripts/generate-content-css.mjs` 重生成 content.css，parity/mirror 守卫绿）。提交见分支 `todo1352-popup-layout`。
- **[x] ② 已加自动化测试** — `hibiki/test/pages/popup_layout_width_columns_test.dart` 的「TODO-1354 音高读音条行内化」组：源码守卫 `.pitch-entries` 含 `display: inline`、不再含 `list-style: circle`，且 `.pitch-entries > li:not(:last-child)::after` 用 `content: " | "` + `opacity: 0.6`。既有 `browser_extension_popup_parity_guard_test.dart` 兜住 re-vendor 字节一致 + content.css 含新选择器。
- **备注**：音高区是纯展示（`user-select:none`），行内化不影响查词/制卡/嵌套导航。最终「与 Niratan 一样整齐」的视觉验收需真机（桌面查同一多音高词，看药丸+读音+[n]单行平铺）。
