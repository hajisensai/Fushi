## BUG-3800 · 悬浮球切换配置按钮文案被换成配置名
- **报告**：2026-10-27（用户：PR #2565 合入后审查）
- **真实性**：✅ 真 bug。`fushi/lib/src/floating_ball/app_floating_ball_host.dart` 的 `FloatingBallGlobalAction.switchProfile` 分支（提交 fb48f2eeb9）把 `ReaderHeaderAction.label` 换成 `_switchProfileLabel`（当前配置名），而 PR 描述只说 tooltip 带配置名；标签胶囊（显示文字时）里只剩「Default」，看不出按钮是「切换」。
- **[x] ① 已修复** — `label` 恢复为 `t.floating_ball_action_switch_profile`，删掉 `_switchProfileLabel`；当前配置名只进 tooltip（`floating_ball_action_switch_profile_tooltip`，「切换配置（当前：xxx）」）。悬浮球没有另外的溢出菜单，按钮文字只来自 `label`。
- **[x] ② 已加自动化测试** — `fushi/test/floating_ball/app_floating_ball_host_test.dart`「切换配置按钮：文案仍是「切换配置」，当前配置名只进悬停提示」
- **备注**：
- **追加（悬停提示停在旧配置名）**：切换配置期间悬停提示 / 无障碍名要等 `ProfileViewModel._switchLocked` 里 `await _repo.applyProfile(...)`（秒级）跑完才变，因为 `state.activeProfileId` 在其后才更新；快照 / 等锁 / `ankiRepositoryProvider` 失效导致 provider 重建的窗口里也读到旧值甚至通用文案。修复：`ProfileUiState.pendingProfile` / `displayProfile`（目标配置优先，否则装载完成时的激活配置）+ `ProfileDraftCoordinator.pendingSwitchTarget`（跨 provider 重建存活）+ `switchProfile` 乐观设置 pending（仅在仍是自己时清）+ 激活 id 落库后、重活 `applyProfile` 之前先发布到 state，失败回滚到切换前 id；`_switchProfileTooltip` 改读 `displayProfile`。可见标签仍是「切换配置」。测试：`fushi/test/profile/profile_switch_state_timing_test.dart`、`fushi/test/profile/profile_switch_label_window_test.dart`、`fushi/test/floating_ball/floating_ball_profile_switch_label_widget_test.dart`（断言 tooltip 随目标变化、可见文字不变）。来源提交 `2500628924` / `e5777310d5` / `6cb698368c`（samu-on-develop，已剔除其「标签换成配置名」部分）。
