## BUG-2204 · 听书 ASR 字幕前句多吃下一句首字，后句跳到远处同前缀句、中间十几句全未匹配
- **报告**：2026-09-07（用户：录屏 `2026-09-07 01-26-36.mp4`，无職転生 21 第 9 节——「突然播放突然渲染成别的样子然后有声书直接卡住高亮一直不动」，并怀疑连带统计出问题）
- **真实性**：✅ 真 bug。DB `audio_cues` 实证：cue 64 ASR 文本「エリスだけは好きそうだけどな、高い所。**と**」多带下一句首字，命中 ns=673..691；cue 65「とはいえ、」在游标 691 后找不到（真实起点 690 已被吃掉），`EpubSrtMatcher` 快速通道 `big.indexOf(nc, cursor)`（`packages/fushi_audio/lib/src/matching/epub_srt_matcher.dart:293`）在 200 字窗口里撞上 155 字外的第二个「とはいえ、冒険者区も広い」（ns=846）；随后 cue 66～80（「今はそれを考慮している暇はない」…「へたり込むアイシャをおんぶして捜索開始だ」）全部 `text_fragment_id=''`（游标单调，真实位置在游标之前），到 43 秒后的 cue 81「冒険者区も広い。」才恢复。运行期：cue 65 reveal 把视口翻到下一页（录屏第 5 秒「渲染成别的样子」），66～80 无 fragment id → `AudiobookBridge.highlight` 走空选择器分支，高亮停在「とはいえ、」不动。运行时 JS 解析器 `collectSentenceAudioCueRanges`（`fushi/lib/src/reader/reader_pagination_scripts.dart`）同样只在 `max(cursor, hint-256)` 之后按「离 hint 最近」找，旧数据 hint 本身指着 846，重定位不了。
- **统计影响**：视口被 cue 65 拽到下一页时账本按「翻走即计」结算了上一页（用户实际还在听上一页），随后 43 秒无翻页；用户手动翻回去会按回翻口径撤回、再前进恢复——数字来回跳是这个匹配错误的下游表现，账本本身没有独立缺陷。
- **[x] ① 已修复** — 匹配器：搜索起点允许回到 `cursor - cueTailOverlap`（4 字，不越过前一条命中的起点），命中在游标之前时把前一条 `normCharEnd` 裁到本条起点（`trimPreviousTo`），快速通道与模糊通道同律。运行时 JS 解析器 + Dart 影子 `resolveCueNormSpansForTesting`：同样回吃 `OVERLAP=4`；紧接前一条命中处 `[cursor-OVERLAP, cursor+ADJACENT]` 的「延续」命中优先于离 hint 最近者（旧数据的错 hint 也能自愈）；回吃后前一条 span 裁短、range 在全部 span 定稿后统一生成。**已导入的书要在有声书导入弹层点「重新匹配」**，66～80 那批空 fragment id 才会重新写入（运行时自愈只覆盖 cue 65 这类有 hint 的条目）。
- **[x] ② 已加自动化测试** — `fushi/test/media/audiobook/epub_srt_matcher_tail_overlap_test.dart`（真机 24 条 ASR 文本逐字复现：cue 65 紧接 cue 64 被裁短的终点、66/67/72/76/79 在两个「とはいえ」之间命中、18/24；无重叠时不回退到前句中段）+ `fushi/test/reader/sentence_audio_cue_mapping_drift_test.dart`（影子解析器：错 hint 指远处时延续优先并裁前句；回吃上限；JS 源码守卫钉 OVERLAP/ADJACENT 常量与延续分支）。
- **备注**：ASR 切句边界漂移是 ReazonSpeech 字符级模型的常态（句末停顿短时把下一句首字并进前句），本修复只兜 4 字以内；更长的吞并仍会 miss 一条但不会再把游标拽到远处。
