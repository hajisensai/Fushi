## BUG-2967 · Android 空闲后首次查词卡顿：AnkiDroid 制卡态探测在主线程冷启动 AnkiDroid
- **报告**：2026-10-05（用户：shishamo，经维护者转述——「安卓小说里查词，每次查第一个词都要等挺久，查过第一个词之后就正常」，补充「好像是一段时间没查词再点就很费时，一直查就没影响」）
- **真实性**：✅ 真 bug（HiBreak / Android 14 真机复现）。查词弹窗渲染后逐条探测「这个词是否已制卡」：`fushi/assets/popup/popup.js:4552`（`callHandler('duplicateCheck')`）→ `dictionary_popup_webview.dart:2605` → `AnkiRepository.isDuplicate`（`packages/fushi_anki/lib/src/ankidroid/anki_repository.dart:731`）→ 原生 `AnkiChannelHandler.java`。该 handler 用内联 lambda 注册在主线程（`AnkiChannelHandler.java:95`，修前行号），`checkForDuplicates` / `findNotesByContent` 还特意 `new Handler(Looper.getMainLooper()).post(...)`（`:257` / `:220`）在主线程跑 ContentProvider 查询。空闲约 10 分钟后系统已回收 AnkiDroid 进程（两次自然空闲实测 `pidof com.ichi2.anki` 为空），第一次查询要先冷启动整个 AnkiDroid（`ActivityManager: Start proc com.ichi2.anki for content provider`），期间主线程被占住；Hybrid Composition 下 Flutter raster 与 WebView 都在主线程，弹窗与整个界面一起冻住。一直查词时 AnkiDroid 是热的，所以只有「空闲后第一次」慢。
  - 修前实测（同一 APK，`debug.fushi.anki_main=1` 走旧主线程路径，杀掉 AnkiDroid 后查词）：主线程被 `checkForDuplicates` 占 212–251 ms，`Choreographer: Skipped 37 frames`，一次弹窗渲染信号从 ~50 ms 推迟到 492 ms，另一次出现 235 ms 的卡帧（vsyncOverhead 214 ms）。AnkiDroid 热时同一探测只占 37–45 ms。测试机牌组小；牌组大、机器慢时冷启动更久。
  - 排除项（同机实测，空闲 1 / 3 / 5 / 10 分钟、切后台 90 s、`am send-trim-memory RUNNING_CRITICAL`）：选区回调 10–20 ms、FFI 查询 1–42 ms、热槽始终命中（`warm=hit`，没有任何空闲计时器销毁弹窗 WebView）、注入→渲染 40–190 ms，均与空闲无关。
- **[x] ① 已修复** — 根因修复：`AnkiChannelHandler` 的方法分发改走 `dispatch`：除需要 Activity / 不做 IPC 的四个方法（`requestAnkidroidPermissions` / `hasAnkidroidPermission` / `openAnkiPermissionSettings` / `openNote`）外，所有 ContentProvider 方法都在单线程后台执行器 `fushi-anki-provider` 上执行（保持 FIFO），结果经 `MainThreadResult` 回投主线程且只回复一次；删掉两处 `post` 回主线程。修后同条件：冷启动 AnkiDroid 的 266–396 ms 全落在后台线程，零丢帧、无慢帧，弹窗渲染信号 54–129 ms。另给阅读器家族（`base_source_page.dart`）接上 `LookupPerfTrace`（search / fill / shown / revealed），设置 › 诊断打开后可直接拆段。提交见分支 `claude/sh-first-lookup`。
- **[x] ② 已加自动化测试** — `fushi/test/android/anki_provider_off_main_thread_guard_test.dart`（分发机制源码守卫）、`fushi/android/app/src/test/kotlin/app/fushi/reader/AnkiChannelHandlerThreadingTest.kt`（主线程白名单纯函数 JVM 单测）、`fushi/test/diagnostics/video_diag_wiring_guard_test.dart`（阅读器查词流水接线）。
- **备注**：未覆盖的情形——若用户没配 AnkiDroid（不做制卡态探测），本修复不改变其体验；该情形下本次实测没有找到空闲相关的慢点，需要用户在 设置 › 诊断 打开日志复现后导出 `lookup` 段再判。
