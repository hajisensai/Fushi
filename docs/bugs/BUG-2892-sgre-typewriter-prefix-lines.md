## BUG-2892 · SGRE 打字机逐字显示的半句被当成独立台词
- **报告**：2026-10-03（agent 在 STEINS;GATE RE:BOOT `sgre_steam.exe`（x64）原始启动路径上发现：选中 `ENGINE:SGRE:wind3d11` 精确文本线程后，同一句台词在台词列表里出现成「聞か」→「聞かれ」→ 整句三条；「うなずいてから、改めて…」前面多出一条只有「うなず」的行）
- **真实性**：✅ 真 bug。`native/galgame_hook/hook/adapters/sgre_lookup.inc` 的 `CopySgreLookupDrawState` 只复制 `visible_glyphs`（`+0x3cc`，打字机当前已显示字数）个字形，`CaptureSgreLookupDrawState` 每次绘制都把这段前缀交给 `PublishSgreExactText`，后者只按「和上一次发布的文本是否相同」去重——逐字显示时每一帧文本都在变，于是每个被画出来的前缀都成了文本通道的一行。渲染器的字形向量（`+0x2d0..+0x2d8`）在显示前就已排好整句，可见字数只是在它上面递增。
- **[x] ① 已修复** — 捕获额外记下排版字形数（向量长度）`layout_glyph_count`；只有 `IsSgreScenarioLineFullyRevealed(visible, layout)`（可见 == 排版且非 0）时才发布到文本通道。打字中的前缀照样进查词快照（字已经在屏上，可以点），但不拿文本行序号，命中时制卡按既有失败关闭语义不配句，而不是配一条半句。真机复测（同一游戏、新 hook `d56aec07…`）：新会话 -21 到 -32 全部是整句，「うなずいてから…」只出一条；带注音的「そうか、それが運命石の扉の選択か」accept4 `verdict=full`（文本 / game_resource xwma 语音 / 卡片 / 不推进 / 关后再查 / 真卡写入）。
- **[x] ② 已加自动化测试** — `native/galgame_hook/tests/sgre_adapter_test.cpp` 钉纯函数（2/47、46/47 不发布，47/47 发布，0/0 不发布）；`native/galgame_hook/tests/adapter_structure_test.py::test_sgre_lookup_inc_call_sites_use_the_tested_helpers` 守 `.inc` 调用点（门在 `PublishSgreExactText` 之前且只此一处、`layout_glyph_count` 取自向量长度）。变异实测：把门改回 `if (text_requested)`，该用例变红；还原后绿。
- **备注**：同一轮顺带修了 `adapter_structure_test.py::test_kirikiri_voice_enqueue_rejects_non_audio_payloads`——BUG-2887 把 IStream 读取收进 `CaptureKirikiriVoiceIStream` 后守卫仍在 detour 体里找入队调用，这是那次提交引入的红。SGRE 在触摸下查词不可用：引擎只读 DirectInput 鼠标，触摸提升出的鼠标只到窗口消息、进不了 DirectInput，游戏本身也不响应触摸（空白处点按 / 长按都不推进），本修复不涉及。
