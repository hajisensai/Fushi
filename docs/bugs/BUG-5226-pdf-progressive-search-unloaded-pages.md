## BUG-5226 · PDF 逐步加载时搜索 / 查词 / 有声书高亮把未加载的页当成空白页
- **报告**：2026-11-22（2026-11-22 合并审查 HBK-AUDIT-210，针对 PR #4128 的 PDF 全文搜索）。
- **真实性**：✅ **真 bug（生命周期 / 依赖契约）**。`PdfViewer.file` 默认 `useProgressiveLoading: true`（pdfrx 2.4.5 `pdf_document_ref.dart:209`），控制器 `isReady` 时只有首批页加载好，其余是 `isLoaded == false` 的占位实例；pdfrx_engine 0.4.4 的占位页 `loadText()` 直接 `return null`（`native/pdfrx_pdfium.dart:1711`），`PdfTextFormatter.loadStructuredText` 因而返回**空 `fullText`**（`pdf_text_formatter.dart:49`），`loadStructuredText({ensureLoaded})` 的参数被忽略（`pdf_page.dart:115`）。阅读页三处直接读占位页：① 搜索 `_searchPageSource`（旧 `reader_pdf_page.dart:631` `document.pages[i].loadStructuredText()`）——开书立即搜，后半本未加载的页都按「无字」跳过，`PdfTextSearchController.search` 对同一查询已 `done` 不重搜，漏搜结果被沿用；② 点选查词 `_pageText`（旧 `:414`）把空文本写进 `_pageTextCache`，这页之后永远提示「无文本层」；③ 有声书句高亮 `_normalizedTextOf` 经同一缓存把空归一化写进 `_normalizedPageText`，该页高亮永远不出。
- **[x] ① 已修复** — 新增 `fushi/lib/src/pdf/pdf_page_ready.dart`：`pdfLoadedPage(document, pageIndex, {cancel})` 订阅 `document.events`、每个事件重取 `document.pages[i]` 直到拿到已加载实例；文档销毁（pdfrx 关事件流）/ 调用方 `cancel` / 越界返回 null，不挂死；`pdfLoadPageText` 在其上读文本层。阅读页三处统一走 `_loadPageText`（`useDocument` + `pdfLoadPageText`，`cancel` = 本页 dispose 信号），只有拿到真实文本才进缓存；查词在等完文本后重取页实例与页框再做坐标换算（占位页的尺寸是猜的）。
- **[x] ② 已加自动化测试** — `fushi/test/pdf/pdf_page_ready_test.dart`：替身文档与 pdfium 同口径（占位页 `loadText` 返回 null、加载时换实例并发 `PdfDocumentPageStatusChangedEvent`、销毁关流）。钉住：占位页直读得空文本（旧实现漏读的来源）、未加载页等到加载后读到真实文本、文档销毁 / cancel 返回 null 不挂死、越界 null；以及「开页立即搜索末页唯一词」端到端——用真 `PdfTextSearchController` 搜，末页后加载仍命中（旧做法 0 命中）。
- **备注**：阅读器类修复，真机复测（大型 PDF 末页唯一词，开书立即搜 / 立即点末页查词）待后补。其他两处读 PDF 文本层的路径（`pdf_text_sections.dart`、`pdf_text_layer_backfill.dart`）用 `PdfDocument.openFile` 默认非逐步加载，不受影响。
