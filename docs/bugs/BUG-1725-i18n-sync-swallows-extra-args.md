## BUG-1725 · i18n_sync 多个 --remove 只生效第一个，多余参数被静默吞掉
- **报告**：2026-08-19（发现于删除字幕列表制卡勾选框时批量删 5 个 i18n key）
- **真实性**：✅ 真 bug。根因 `fushi/tool/i18n_sync.dart:24`（旧 `_removeKey`：`args.indexOf('--remove')` 只认第一个 flag）+ 旧 `_removeKey/_addKey/_renameKey` 三处同形的 `args.sublist(idx + 1).where((a) => !a.startsWith('--'))` 后只取 `rest[0..n]`。多出来的 operand 没有任何归宿，只能被吞：`--remove a --remove b --remove c` 只删掉 `a`，且**不报错、退出码 0、照常打印 `Changed 17 files.`**。实测一次「删 5 个 key」的调用只删了 1 个，剩下 4 个留在 17 份 json 里，直到再 grep 才发现。`--add` / `--rename` 是同一形状（多传的组、多余的裸参数同样消失），且三者经 `if / else if` 互斥，混用时后者整个失效；`--remove --dry-run` 还会把 `--dry-run` 当 key 删掉。
- **[x] ① 已修复** — commit `fd6ff2a1a2`。**根因修（换数据结构，不是加使用限制）**：命令行建模成**有序 op 列表**（`AddKeyOp` / `RemoveKeyOp` / `RenameKeyOp` / `SortKeysOp`），逐 token 消费而不是「先按 flag 找位置再过滤 `--`」。① 四个操作 flag 可重复、可混用，按给出顺序执行；每个文件读一次、应用全部 op、写一次（多 op 下文件计数也不再重复累加）。② 任何没被 flag 消费的 token、缺失的 operand、operand 位置上的 flag 一律 usage error 退出——**参数没有可以被静默忽略的位置了**。③ 解析 / 应用拆成纯函数 `parseI18nCommand` / `applyI18nOps`（无 IO、不改入参），写盘前全量内存预演，op 报错整轮中止，不留半份。④ 命中数按 op 统计：`--rename` 全场未命中仍报错中止（保持旧行为），`--remove` / `--add` 未命中打 warning（旧实现完全无声），退出码不变以免破坏既有脚本。
- **[x] ② 已加自动化测试** — `fushi/test/tools/i18n_sync_ops_test.dart`（16 例）：重复 flag 全部生效（本 bug 的直接回归）、混用与顺序语义、四类 usage error（未知参数 / 缺 operand / operand 位置是 flag / rename 同名）、单 op 向后兼容（add 已存在跳过、remove 缺失不改、rename 目标存在抛错、sort 幂等、入参不被就地改）。**变异实测三处均被抓到**：① `ops` 只留第一个 → 4 红；② 未知参数静默跳过 → 1 红；③ operand 位置接受 flag → 1 红；每次还原后源码 sha256 与变异前一致（`74a7d082…`）。
- **备注**：端到端验证走真实 17 份 json——`--add zz_tmp_probe_one … --add zz_tmp_probe_two …` 两个 key 各写进 17 个文件、zh-CN 取中文值，再 `--remove` 两个全清、目录字节级复原（旧实现这一步会漏掉第二个）。另落两条一并写进 `CLAUDE.md` 的 i18n 纪律：① 批量删 key 后必须按**精确键名**复核（`grep '"<key>"'` 带引号），裸子串会被同前缀 key 假阳性命中（`..._favorites` 命中 `..._favorites_empty`）；② `--remove` + `--add` **不等于** `--rename`——前者会把 16 种语言的既有翻译降级成英文值并把 key 挪到文件末尾（本次验证时踩到，已 `git checkout -- lib/i18n` 复原）。
