## BUG-4803 · 图形字幕位图时间表抽取的取消权归第一个调用方：本地文件由控制器发起时取消不了，换集 / 退出后 ffmpeg 仍把整个文件读完
- **报告**：2026-11-17（优化计划代码复核 gap-disc-3，连带 gap-disc-7；非用户反馈）
- **真实性**：✅ 真 bug（读代码确证，未在真机量残留读盘的影响）。根因（修前，基准 `1f7e30e4168`）：
  - `fushi/lib/src/media/video/video_graphic_subtitle_regions.dart:340-347`：同一键的第二个调用方直接拿第一个调用方的在途 Future，抽轨进程只挂第一个调用方传进来的 `cancel`。两个调用方是控制器（逐句时间表）和模糊遮蔽层。
  - `fushi/lib/src/media/video/video_graphic_subtitle_timing.part.dart:411-413`：控制器因此对本地文件故意不传取消（怕连带撤掉遮蔽层那一份）；选图形轨时控制器先发起，所以本地文件通常是「不可取消」的那一份，`_cancelGraphicTimingFetch()` 完成的 completer 根本没传下去——换集 / 退出播放页后 ffmpeg 把整个容器读到底，只受 90 s 无进度判活约束。
  - 同文件 `:415-424`：`for (attempt < 2)` 再要一次，是在补「遮蔽层先发起又取消，控制器拿到 null」这个所有权缺陷；遮蔽层连着取消两次，时间表就静默没有了。网络流那一支是镜像问题：谁先发起谁的取消生效，另一方的取消是空操作。
  - 连带（gap-disc-7）：`video_graphic_subtitle_regions.dart:381-389` 调 `extractGraphicSubtitleTrack` 没传 `onFailure`，ffmpeg 失败是返回 false 而不是抛异常，上层两处 `catch` 碰不到，用户看到的是「模糊只糊整条字幕带 / 图形字幕制卡没有逐句时间」而日志里没有任何原因；失败也不记，下次选轨再整文件抽一遍。
- **[x] ① 已修复** — `ae8c38aed6a`。`FfmpegGraphicSubtitleRegionLoader` 的在途任务改成按等待者计数（`_InflightRegionLoad`）：每个调用方的 `cancel` 只让它自己那一份以 null 返回，全部等待者都放弃才完成任务自己的 `abort`（抽轨进程被杀）；最后一位放弃时在同一个同步回调里先把条目从 `_inflight` 摘掉再杀，之后来的调用方开新任务，不会接到正在被杀的那份。控制器对本地文件也传自己的取消，删掉 `attempt < 2`。失败摘要经 `onFailure` 进 `ErrorLogService`（`video.graphicSubtitleRegions.extract`）；只有「本地文件 + ffmpeg 非零退出」按现有缓存键（含大小与修改时间）记进内存里的 `_failed`，取消、网络流失败、卡死 / 超时（退出码 null）、探测失败都不记。上层两处 `debugPrint` 改进错误日志。顺带把 isolate 解码挪进静态函数：闭包和 `onFailure` 闭包同处一个作用域时会把 loader 本身（在途任务表里的 Completer）一起发给 isolate。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_graphic_subtitle_regions_test.dart` 的「FfmpegGraphicSubtitleRegionLoader 在途任务」组（注入脚本化的 `FfmpegBackend`，真文件 / 真 isolate 解码）：A 发起、B 加入、A 取消后 B 仍拿到结果且进程只起一次没被杀；A、B 都取消后进程被杀、在途条目已摘、之后的调用方开新任务拿到结果且不记日志；不传 cancel 的等待者不受别人取消影响；本地非零退出记日志并在本次运行内不再起进程（另一条轨不受牵连）；没有退出码的失败与网络流失败不记。`fushi/test/media/video/graphic_subtitle_anchor_cue_test.dart`「本地文件也把自己的取消交给 loader…」钉控制器一侧：本地抽轨带取消、换轨复位即取消、拿到 null 不再发第二次请求。`fushi/test/media/video/bitmap_subtitle/bitmap_subtitle_track_test.dart`「位图时间表加载器对 VobSub 跑通」（真 ffmpeg，在 dist Mac worker 上执行）覆盖生产后端经转发壳的整条路。
- **备注**：
  - 真机未验：Windows 上放带 PGS 轨的大 REMUX，选图形轨后立刻换集 / 退出播放页，数 `ffmpeg.exe` 进程应随之消失；模糊档 + 图形轨同时在场时换轨，时间表与模糊框互不影响。
  - 失败记忆只活在内存里，重启 app 会再试一次。非零退出里出在环境上的不记（审查后补）：失败摘要含 `No space left on device` / `Disk quota exceeded` / `Permission denied` / `Input/output error` / `I/O error` / `Error opening output` 的（临时目录所在盘写满、网络盘读到一半断开）下次选轨照常重抽；判据 `graphicSubtitleExtractFailureIsEnvironmental`，测试在同一组里。摘要里认不出这些文本的环境失败仍会被记到本次运行结束（文件大小 / 修改时间一变键就失效）。
  - 已知未修（审查发现）：没开「模糊」档时控制器是唯一等待者，抽取跑到一半**重新选同一条图形轨**会把 ffmpeg 杀掉从头再抽——`selectEmbeddedGraphicTrack` 一进来就 `_resetGraphicTimingTables()`（撤销在途抽取），隔着几次 mpv 调用才重新发请求，旧任务等不到新等待者。修前本地文件不传取消，第二次请求直接接上在途任务。要修得让选轨路径知道「还是同一条轨」再决定撤不撤，改动点在 `video_player_controller.dart` 主文件，该文件当时被三个在途分支占用，没有动。
