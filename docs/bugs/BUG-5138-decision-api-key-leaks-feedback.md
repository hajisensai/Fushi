## BUG-5138 · 拍板台个人密钥 API 带出关联反馈原文 / 附件与账户 id
- **报告**：2026-11-22（外部审计 Codex 2026-11-21 PR 审查 HBK-AUDIT-024，PR #4022）
- **真实性**：✅ 真 bug。`/v1/decisions` 与 `/v1/decisions/:id` 的约定（`services/leaderboard/src/decisions_api.js` 文件头、`docs/agent/decision-board.md:7`）是「密钥只能读写拍板台，碰不到反馈和账户数据」，但 GET 路由直接回 `listDecisions` / `getDecision` 的完整行再加 stage（PR head 4375dab3fe `decisions_api.js:126` 的 `withStage` = `{ ...row, stage }`，用在 `:225` / `:233`）。完整行来自 `services/leaderboard/src/decisions.js:273` 的 `DECISION_COLUMNS_SQL`：反馈类事项联表带 `feedback_id / feedback_title / feedback_body / feedback_attachments`（附件 R2 key），还有 `verdict_by` 与每条留言的 `account_id`（账户 id）。复现：库里放一条反馈 + 按 id / source 关联它的两条反馈类事项，持密钥 GET 列表与单条，响应里出现反馈标题、正文、截图 key 与开发者账户 id。
- **[x] ① 已修复** — `decisions_api.js` 新增 `apiDecision`：按 `API_ITEM_FIELDS` / `API_NOTE_FIELDS` 白名单逐字段挑（拍板台自己的列 + 开发者署名 `verdict_nick` / 留言 `nick` + CLI 算 stage 用的 `claude_at`），列表与单条都走它；以后 `DECISION_COLUMNS_SQL` 加列也默认不出去。网页与 wrangler CLI 仍用完整行，不受影响。提交 c0a14cd7eb。
- **[x] ② 已加自动化测试** — `services/leaderboard/test/decisions_api.test.js`「个人密钥只拿拍板台字段…（HBK-AUDIT-024）」：按 id 与按 source 两种反馈关联 + 开发者拍板与留言，断言三个响应都不含反馈标题 / 正文 / 附件 key / 账户 id，字段集合 ⊆ 白名单，且 original / verdict_nick / 留言 / stage 照常带。变异实测：把 `...pick(row, API_ITEM_FIELDS)` 换回 `...row` 后该用例变红。
- **备注**：HTTP 模式的 `decisions.mjs show` 对没写 `original` 的反馈类事项不再显示反馈原文（这正是约定要求的隔离；要看原文的用 wrangler 模式或网页）。
