## BUG-2624 · 哈希指向同一部 AniDB 剧的散文件不合并成剧集单元，只出逐集 sidecar
- **报告**：2026-09-22（用户：刮削日志截图，`[UHA-WINGS&VCB-Studio] Karakai Jouzu no Takagi-san 2 [04]…[12].mkv` 每集各自一条「AniDB 文件身份 → TMDB 集逐集链接：1 个文件对上」+「无法证明电视剧具有来源根目录下的专属作品目录；仅生成逐集 sidecar。」，issue 标题是文件名而不是合集名）
- **真实性**：✅ 真 bug。日志形态说明这 12 个文件在用户库里没进多成员 playlist 合集，计划器（`video_source_work_planner.dart:88-100`）把每个文件当独立 `book:` 单元；文件名解析与扫描归组本身正常（实跑 `parseVideoFilename` → 系列 Takagi-san / 季 2 / 集 4，`groupVideosIntoPlaylists` 能成组），散着的原因在用户库历史状态（删过合集留墓碑 / 分组模式 / 非扫描路径入库）。但 Shoko 口径是**文件身份决定作品归属**：`AnimeSeriesRepository.GetByAnimeID(aid)` 一 aid 一 series（`references/ShokoServer/Shoko.Server/Services/AnidbService.cs:614-620`、`Repositories/Cached/AnimeSeriesRepository.cs:290`），目录、文件名、同目录邻居在导入方向零参与。Fushi 协调器只有反方向的 `_splitByAnidbWork`（`video_source_scrape_coordinator.dart:1755`，成员分属不同 aid → 拆），没有「单文件单元哈希同属一部剧 → 合」；单成员电视剧单元在 `video_sidecar_target_resolver.dart:245-262` 永远证明不了专属根目录（候选目录下还有其它 11 个非本单元文件），所以 `tvshow.nfo` / `season.nfo` 写不出、作品行一集一份、日志一集四条。
- **[x] ① 已修复** — 协调器主循环前新增 `_mergeStandaloneByAnidbWork`：对**单文件、无已确认身份**的单元先做哈希识别（结果进 `anidb_file_identities` 存储，主循环再问是「已记录，未重算」），按 aid 分组，≥2 个且形态非电影（AniDB 动画类型，旧行看 Fribb `isMovie`）的组新建 playlist 合集（撞名加「（AniDB aid）」后缀）收下成员，作为 `collection:` 剧集单元顶替第一个成员的位置进主循环；身份按主源给（AniDB 主源直接 aid，否则唯一 MAL / TMDB）。与 `_splitByAnidbWork` 共用抽出来的 `_planAnidbGroup` / `_createAnidbEpisodicUnit`。电影一文件一作品（Shoko `CrossRef_AniDB_TMDB_Movie`）不合；哈希关闭 / 未配置 / 识别不了的文件原样留给主循环。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/metadata/tvdb_season_offset_coordinator_test.dart`：`standalone files hashed to the same AniDB TV work merge into one collection unit (Shoko series by anime id)`（三个散文件 → 一个合集单元、三个文件各绑到集、身份 anidb+mal 落库）、`standalone files hashed to the same AniDB movie work stay separate`（电影反例）。
- **备注**：合并会新建合集——用户曾「删除合集（保留条目）」留下的同名墓碑不阻止它（与拆分建合集同口径：合集名来自 AniDB 标题，通常与按文件名归组的旧名不同）。尚未覆盖：散文件与**同一批里已有的**剧集合集单元同属一部 aid 时并入既有合集（现在只在散文件之间合并）。
