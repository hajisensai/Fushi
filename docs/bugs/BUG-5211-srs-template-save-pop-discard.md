## BUG-5211 · 卡片模板保存在途时按返回误报「放弃修改」，途中再改的被记成已保存
- **报告**：2026-11-22（用户：卡片模板保存后返回仍弹「放弃修改？」）
- **真实性**：✅ 真 bug。真机（安装版，500 MB 的 srs4.db）上点保存后约 2 秒内按返回，弹「放弃修改？」，几秒后才出「已保存」。根因：`fushi/lib/src/pages/implementations/srs/srs_template_editor_page.dart` 的 `PopScope.canPop: !_dirty` 只看「编辑框 ≠ 已保存快照」，而快照要等 `saveTemplateEdits`（写命令 + 缓存刷新，大库要好几秒）回来才更新；保存在途时按返回就被当成未保存，问放弃——可写入已发出，「放弃」撤不回，提示本身是错的。同处还有一个潜伏问题：保存完成时用 `_savedFront = _front.text` 记快照，取的是**写完那一刻**的编辑框，保存途中又改的字被误记成已保存，之后返回不再提醒（会丢改动）。
- **[x] ① 已修复** — 保存时先取快照（`srs_template_editor_page.dart:511` 起），写入与「已保存」都用这份快照；保存期间留一个结束信号 `_saveDone`，`canPop` 改为 `!_dirty && !_saving`，被拦下时 `_onPopBlocked`（`:577`）先等在途保存写完，写完没有未保存修改就直接退出，仍有（保存失败 / 途中又改）才问放弃；`_popPending` 防连按返回写完后 pop 两次。AI 途中整份替换的字段说明按 identical 判断，不被误清。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_note_types_pages_test.dart`「模板编辑器：保存在途时返回不问放弃，写完自动退出；途中再改的仍算未保存」：写命令停在 worker 往返途中时返回 → 不出放弃框、写完自动退出且已落库；保存途中再改 → 落库的是点保存时的内容、返回仍问放弃。MD3 / Apple 两套各跑一遍。
- **备注**：保存要好几秒本身（`saveTemplateEdits` 触发全类型卡缓存刷新）是性能问题，不在本条范围。
