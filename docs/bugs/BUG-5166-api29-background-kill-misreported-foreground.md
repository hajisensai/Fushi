## BUG-5166 · Android 10 进程退到后台后被系统回收（死前已收到 UI_HIDDEN），下次启动误报前台闪退
- **报告**：2026-11-22（应用内反馈 ywhUI7Adc1：realme RMX1971 / Android 10（SDK 29），标题「Crash report: unexpected exit」）
- **真实性**：✅ 真 bug（误报）。日志：pid=12266 `lastLifecycle=inactive@16:30:24.890`，同 pid `UI_HIDDEN@16:30:25.592`，新进程约 16:30:28 启动；SDK 29 没有 `Process.androidExitInfo`。`fushi/android/app/src/main/java/app/fushi/reader/ProcessExitChannel.java:216` 只在 SDK >= R 时往 payload 放 `reasons`；`fushi/lib/src/diagnostics/previous_exit_log.dart:891` `androidSessionUiVisibleAtDeath` 要从 `reasons` 里取死亡时刻，取不到就返回 null，把同 pid 的 UI_HIDDEN 证据丢掉；`androidDiedInForeground` 在 importance 为 null 时退回会话标记，标记停在 inactive 按前台算 → 弹「意外退出」。BUG-4744 只覆盖了有 `ApplicationExitInfo` 的情形。
- **[x] ① 已修复** — `androidSessionUiVisibleAtDeath` 新增 `nextProcessStartedAtMs` / `currentPid`：没有对得上的退出记录（API < 30 没有 `reasons`，或有但没这个 pid）时，用本次进程读会话标记的时刻作死亡时刻上界（同名进程同时只活一个，旧进程必死在它之前），照常按同 pid、`[startedAt, 上界]` 内最晚的可见性 / trim 判断；旧 pid 等于本进程 pid（pid 复用，分不清记录归属）时不用上界。`PreviousExitLog.collect` 调用处（同文件约 2213 行）传 `now` 与 `dart:io` 的 `pid`。原生侧不用改：trim / 可见性记录在所有 API 级别都已按 pid 写入。
- **[x] ② 已加自动化测试** — `fushi/test/diagnostics/previous_exit_log_test.dart`「Android：同一 pid 的死时重要性压过会话标记的前后台推断」组：SDK 29 无 `reasons` + 标记 inactive + 同 pid UI_HIDDEN → 不上报；只有 RUNNING_CRITICAL → 照常上报；trim 早于本会话启动（pid 复用）不算；有 `reasons` 但没这个 pid → 同样用上界；`androidSessionUiVisibleAtDeath` 单元用例（无上界 null、上界生效、pid 复用不用上界、有记录时以记录时刻为准）。变异实测：还原回「取不到死亡时刻就 null」后 3 条用例红，恢复后绿。
- **备注**：反馈 ywhUI7Adc1。
