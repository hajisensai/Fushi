## BUG-4285 · 播放会话结束 / 换档换集后旧 token 的转码分段照样转完，占满转码名额拖慢新流起播
- **报告**：2026-11-10（用户：互联远程长任务审查 R11(c)）
- **真实性**：✅ 真 bug。`packages/fushi_engine/lib/media/video/live_transcode.dart:377-397`（修复前）的并发闸门（`kMaxConcurrentTranscodes` 个名额 + FIFO `_transcodeQueue`）与 `:437-482` 的 `_spawnSegment` 只受 90 s 单段超时约束，没有任何入口能让「已经不需要的」分段离队或停下；host 侧 `packages/fushi_engine/lib/sync/fushi_sync_server/video.part.dart` 的 `hlsseg.ts` 分支对每个请求 `await _runTranscode(() => transcodeSegment(...))`，转码工作与签发它的 token 没有关联，client 退出 / 换集 / 换档后旧流已请求的分段照样排队、转完，占着名额拖慢新流第一段。
- **[x] ① 已修复（engine 原语）** — 9bc4512e181：`live_transcode.dart` 新增 `TranscodeCancelled`、`cancelTranscodeWork(String key)`、`pendingTranscodeWorkKeys`（测试用）；`transcodeSegment` / `runGuardedTranscodeForTesting` 加可选 `workKey` / `isAlive`。同一 key 的在途工作登记成一组（最后一个结束或被取消即移出登记表）；登记后同步判一次存活（与调用方同步的「作废 token → 取消」之间无 await，无漏网窗口），排队者被取消直接离队、不占名额不交棒，拿到名额后再判一次存活、不通过即交还，在跑 ffmpeg 被 SIGKILL 并以 `TranscodeCancelled` 结束，两处「回退 PATH ffmpeg」前判存活（被杀进程「非 0 + 无产出」不再误触发回退）。不传 `workKey` / `isAlive` 时行为不变。host / client 接线见下一条。
- **[x] ① 已修复（host / client 接线）** — 7a1ce3be952。根因另两处：host `packages/fushi_engine/lib/sync/fushi_sync_server/video.part.dart` 的 `hlsseg.ts` 分支（修复前 `:1125`）转码工作不挂 token，`/streamurl` 为光盘标题另签的制卡 token（`:151`）与主 token 无关联；client `fushi/lib/src/sync/interconnect_sync_backend.dart`（修复前 `:221-231` 的 implements 列表）不实现 `RemoteVideoPlaybackStop`，页面在退出 / 换集 / 换档边界调的 `_reportRemotePlaybackStopped` 对互联 host 是空操作。修法：`_VideoStreamToken` 加 `ticket`（制卡 token 指向主 token）；`/streamurl` 回 `ticket`；新增 `POST /api/library/videos/<id>/streamrelease?ticket=`（要 Basic，405/400/幂等 204），`_releaseVideoTicket` 同步作废该视频下的票及随票 token 并 `cancelTranscodeWork`；`hlsseg` 传 `workKey: token` / `isAlive: token 仍在`，`TranscodeCancelled` → 410。client 每次 `remoteVideoStreamUrls` 在入口同步开一个播放会话，播放取流（含自动档测链路的原画票）把 `(基址, ticket)` 记进会话，下载取流不记；`stopRemoteVideoPlayback` 在首个 await 前摘下会话并逐票发 `/streamrelease`（失败只记日志，TTL 兜底），停止后才签回的票收到即释放；同一 id 的新会话只顶替登记、不释放旧票（避免掐断同视频的另一个播放页）。另修一处会被引入的竞态：`video_fushi_page.dart` 的 `_persistRemotePositionAndReportPlaybackStopped` / `_flushPositionAndReportRemotePlaybackStopped` 原先先 await 落库再报停止，换集时新集取流会先于停止到达、被停止一并释放；改为先同步发起停止再落库、最后等停止。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/live_transcode_cancel_test.dart` 5 条（排队者被取消离队且不吃交棒名额 / isAlive=false 立即放弃不占名额 / 排队中作废拿到名额后交还 / 取消在跑分段 runner 只被调一次 / 取消只作用于该 key 且之后同 key 新工作不受影响）。修复前先放只有签名的桩跑过一次：5 条全部断言失败（排队者不离队超时、名额泄漏、runner 未被取消）。

- **[x] ① 评审返修** — `865e7ad9ef6`、`0beb484f13d`。上一条接线把「释放流票」挂在 `RemoteVideoPlaybackStop` 上有三处错：(1) 页面在自然播完 `fushi/lib/src/pages/implementations/video_fushi/episode.part.dart:21-29`（`_handlePlaybackCompleted`）也报停止，而 media_kit `keep-open` 下页面与播放器都还在，回拖 / 重看会拿已作废的 token 得 403 / 410，制卡 token 一并作废；(2) 为兜「按视频 id 摘会话」而把两个落库+报停止 helper 改成先报停止，对 Jellyfin / Plex 也生效，Stopped 跑到最后一次 Progress 之前；(3) 外链跳转在可能取消导航的分支之前就释放。另 `stopRemoteVideoPlayback` 逐票串行 await（每票最长 15 s）挡在换档 / 跳转前。修法：`fushi/lib/src/sync/remote_video_client.dart` 新增 `RemoteVideoPlaybackRelease`（契约：首个 await 前同步摘下会话、释放为后台尽力清理），`InterconnectSyncBackend` 改实现它、不再实现 Stop，各票 `/streamrelease` 并发；页面新增 `_releaseRemotePlayback`（同步、按 generation 去重、回看模式不发），只在退出（pop 前）、换集 / 自适应换档 / 手动换档 / 换线路（取新流与停止上报之前）、外链跳转确定关页之后调用；自然播完只报停止；两个 helper 恢复先落库后报停止。`0beb484f13d` 撤回误加在 `transcodeSegmentCount` / `transcodeSegmentRange` / `buildTranscodeHlsPlaylist` 上未使用的 `workKey` / `isAlive` 参数。
