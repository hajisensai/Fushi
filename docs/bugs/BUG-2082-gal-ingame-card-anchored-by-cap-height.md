## BUG-2082 · galgame 游戏内查词卡片翻到台词上方时按上限高度定位，实际卡片与台词之间留空隙
- **报告**：2026-09-03（用户：「查词和弹窗位置不一样」——SGRE 4K 全屏（视口 3840×2160）里点「夏の強烈な日射しを受けて。」的「夏」，卡片出现在画面上半部 y≈570，台词在 y≈1660，中间空 300 多 px；截图 `Temp/1368968b-….png`）
- **真实性**：✅ 真 bug。`hibiki_glookup.log` 记录 `present seq=7 anchor=(640,570) card=1346x773`，而 hook 报的字形是 (640,1660) 80×80、视口 3840×2160。根因 `fushi/lib/src/lookup/gal_ingame_lookup_controller.dart:1131-1136`（修前）：`_applyCardSizeCap` 用 8 MB 位图预算收出来的 **cap 尺寸**（4K 下 1933×1087）跑 `_resolveAnchor` 得到根卡左上角并冻结成 `_rootCardAnchor`，之后每次 present 都用这个左上角。台词贴底时 `computeFrameRect` 把 cap 卡翻到字形上方，`top = 1660 − 4 − 1087 = 569`；真正渲染出来的根卡只有 773 高，顶边仍钉在 569，底边停在 1342，与字形之间空出 314 px。视口越大（预算 cap 越高）、卡内容越短，空隙越大；1080p 窗口模式 cap 648 与内容接近，所以此前 E2E 没暴露。宿主 `global_lookup_host.js` 的 `measureAndReport` 只上报级联并集包围盒，Dart 侧拿不到根卡自身高度，也就没法按贴台词的边定位。
- **[x] ① 已修复** — 不动点改成「根卡贴字形的那条边」：① `_resolveRootPlacement` 仍用 cap 尺寸决定上/下方与水平 clamp，但记的是 `GalRootPlacement{x, edgeY, above}`（翻到上方 = cap 卡底边，放下方 = 顶边）；② 宿主 `measureAndReport` 在 overlaySize 的 box 里附带 `rootHeight`（根 shell 的实测高度，并入去重 key），`GlobalLookupController` 透传成 `onRoutedRevealed(..., physicalRootHeight)`；③ `_drainRecapture` 每次 present 用 `resolveGalRootTopLeft(placement, 根卡实际高度, viewH)` 推左上角（夹进 `[0, viewH − rootH]`）。cap 高度代入时落点与修前逐字节一致（布局原点不变）；宿主未上报 rootHeight 时退回首帧并集高度。**级联布局工作区的原点仍是 `_applyCardSizeCap` 用 cap 尺寸解出来的那个保守值，不随根卡实测高度改**——初版写过一个 `_syncCascadeOriginToRoot` 声称做这件事，实际是死代码（见「已知限制」），已删除（2026-09-03 审查后置补）。
- **[x] ③ 侧别不再从被夹过的坐标反推**（2026-09-03 审查后置补）：`computeFrameRect` 内部本来就算出了 `showBelow`，初版没往外传，`_resolveRootPlacement` 只好拿 `capAnchor.y < glyphY` 反推。但 `capAnchor.y` 经过 `[0, viewH − capH]` 夹取、`height` 又按锚侧空间收缩，中屏字形 + 大 cap 时会把「放下方」误判成 `above`、`edgeY` 变成视口底边（与字形脱钩），复现出同一段空隙的镜像形态（探针：字形 (300,300) 40×40、视口 1280×720、cap 600×560 → 反推得 `above:true, edgeY:720`，根卡 200 高时落到 y=520，离字形底边 340 空出 180 px）。现在 `GlobalLookupFrameRect` 带 `showBelow` 出参，`_resolveRootPlacement` 直接用它，`edgeY` 也改由字形算（`above ? glyphY − gap : glyphY + glyphH + gap`），顺带消掉「夹子没触发时才等于 glyphY − gap」的第二处漂移。SGRE 台词贴底所以真机没撞到，非贴底台词的引擎与 UI 文本查词会撞。
- **[x] ② 已加自动化测试** — `fushi/test/lookup/gal_ingame_lookup_contract_test.dart` 新增 group「BUG-2082 根卡以贴字形的那条边为不动点」：4K 实测数字（字形 (640,1660)、cap 1933×1087、实际 773）断言翻上方时底边 = 字形顶 − 间距、修前落点 569 只在代入 cap 高度时复现；下方放置顶边不随高度动；卡高过上方空间钉 0；下方溢出贴底。审查后补三条（2026-09-03）：同 group 加「中屏字形 + cap 远大于锚侧空间」象限（上面那组探针数字，反推实现在这里给 y=520）；`test/lookup/global_lookup_layout_test.dart` 加 `showBelow` 自报与竖排恒 true；`gal_ingame_lookup_contract_test.dart` 加**接线层**用例「reveal 报的根卡高度驱动 present anchor」（union 600×400 但 rootHeight 200 → anchorY 436），它同时堵住「忽略 host 上报的 rootHeight」与「_drainRecapture 退回按卡片 union 重解 anchor」两条变异；宿主侧 `fushi/test/lookup/global_lookup_host_test.mjs` 新增 11b（overlaySize 的 box.rootHeight = 根 shell 高度而非并集高度，且根卡变矮、并集不变时仍不被去重）。
- **真机复验**：2026-09-03 worktree 构建，SGRE 1920×1080 窗口：命中字形 (720,830) 40×40，卡片 1129×648、根卡高 648，present anchor=(720,178) → 卡片底边 826 = 字形顶 − 4，游戏内截图卡片紧贴台词行。
- **已知限制**（缺陷 B，2026-09-03 审查）：级联布局工作区原点（`GlobalLookupController._physicalLayoutWorkArea`）**一次查词只被读一次**：唯一读点在 `global_lookup_controller.dart` 的 `_lookupExternal` 里（拼 `showAt` 的 `capOrigin*`），而 `_applyCardSizeCap` 在 `lookupText` **之前**就把它写成了 cap 尺寸的保守值。初版在 reveal 之后又写一次（`_syncCascadeOriginToRoot`），那一次写入在本次查词内再也没人读、下次查词又被 cap 值覆回去——完全的死代码，已连同只服务它的 `_capPhysicalWidth/_capPhysicalHeight` 一并删除。真要让子卡按根卡**实测**左上角级联，需要的是一条能在查词中途把新原点推给 native/host 并重排已有子卡的通道（现在没有），不是在 Dart 侧多写一遍字段；在那条通道与其真机验证落地之前，原点就是保守的 cap 盒子。
- **备注**：悬浮高亮（鼠标停在字上给文字加背景）SGRE 侧目前**没有**实现——只有 KiriKiri 适配器在 TJS 里画选区高亮，`native/galgame_hook/hook/adapters/sgre_lookup.inc` 无任何 highlight 绘制；属于 hook 侧引擎缺口，按一引擎一任务另开。同一局还观察到线程记忆恢复成 UserHook1（此前误选被记住）导致资源音频不配对，这是记忆按用户选择恢复的既定行为，不在本条内。
