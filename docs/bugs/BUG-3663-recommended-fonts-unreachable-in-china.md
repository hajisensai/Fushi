## BUG-3663 · 中国大陆网络下推荐字体下载失败，且失败时不说原因
- **报告**：2026-10-23（用户：应用内反馈 f4ybrMM0mP，iOS 3.0.0+19763，「无法获取推荐字体——为什么，不可以直接下载吗，要自己配置，也没提醒」；同一份日志里 `raw.githubusercontent.com` 被 `Connection reset by peer`）
- **真实性**：✅ 真 bug。推荐字体清单是写死的（能显示），失败的是下载：`fushi/lib/src/pages/implementations/custom_fonts_page.dart` 的 `recommendedFontsCatalog` 每款只手写 `cdn.jsdelivr.net` + `raw.githubusercontent.com` + `fonts.google.com/download` 三条，raw 在大陆直连被重置、Google 打包接口早已只回网页 HTML（注释自承必败），Noto Serif SC 连 jsDelivr 都没有——实际只剩 jsDelivr 单节点；没有接入全仓已有的 GitHub 加速镜像名单 `kGitHubMirrorPrefixes`（更新检查 / 词典 / 着色器都在用）。失败后批量下载只弹「下载失败: N」（`_downloadRecommendedFonts`），不说哪款、不说原因、不给出路；`FontDownloadService.download` 全部源失败只 `debugPrint`，用户上传的日志里没有任何字体记录。
- **[x] ① 已修复** — `github_mirrors.dart` 新增 `kJsDelivrHosts` 与纯函数 `gitHubRepoFileUrls`（jsDelivr 四个独立 CDN 节点 → 镜像前缀套 raw → raw 直连，`viaJsDelivr: false` 跳过 jsDelivr 用于 >50MB 目录），Anime4K 着色器的 `anime4kMirrorUrls` 改为委托它；推荐字体每款改由 `_googleFontUrls(<仓库路径>)` 生成，删掉失效的 Google 接口。`FontDownloadService.download` 记录每个源的失败原因，全部失败时写 `ErrorLogService`（来源 `FontDownloadService.download`），结果新增 `unreachable`（所有源都败在传输层，判据 `isFontDownloadTransportFailure`：连接超时 / 连接错误 / 收发超时 / 证书，或底层 socket / TLS 异常；已答复的 4xx/5xx 不算）。字体页单链接与批量下载失败提示列出失败的字体名，`unreachable` 时追加「连不上字体下载源，可在设置里的『网络代理』配置后重试，或直接导入已有的字体文件」（`custom_fonts_download_unreachable_hint`）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/recommended_fonts_sources_test.dart`（每款都有全部镜像前缀与 raw 兜底、无 Google 接口、无重复；除 Noto Serif SC 外 jsDelivr 四节点排最前；`gitHubRepoFileUrls` 顺序与 `viaJsDelivr`）；`fushi/test/reader/font_download_service_test.dart` 新增「全部源连不上 → `unreachable` 并写错误日志」，原「全部源都不是字体」补断言 `unreachable == false`。
- **备注**：未在中国大陆网络 / iOS 真机实测各源连通性；公共镜像会轮换下线，统一由 `kGitHubMirrorPrefixes` 维护。若镜像档实测仍有明显失败率，可再考虑把推荐字体托管到自有 CDN（产品决策，未做）。
