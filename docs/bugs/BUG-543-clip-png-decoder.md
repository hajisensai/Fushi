## BUG-543 · 有声书片段导出移动端合成失败 ffmpeg-kit min 变体缺 png decoder
- **报告**：2026-07-04（用户：board 1134）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/media/audiobook/audiobook_clip_export.dart:156`（`buildFfmpegImageAudioToVideoArgs` 用 `-loop 1 -i <文本图>.png`）+ 落盘 `hibiki/lib/src/pages/implementations/reader_hibiki/audiobook.part.dart`（写 `$base.png`）。移动端走 `KitFfmpegBackend`（自编 ffmpeg-kit **min** 变体 AAR，`third_party/ffmpeg_kit_flutter/android/libs/ffmpeg-kit.aar`），其 libavcodec **无 png decoder**——解包 AAR arm64-v8a `libavcodec.so` 的 `.rodata` 探测：存在 `MJPEG decoder` / `gif decoder` / `BMP decoder` / `TIFF decoder`，**独缺 `PNG decoder`**（也无 `raw video decoder`）。喂 png → 运行时 `Decoder (codec png) not found` → 帧解不出 → `unspecified size` → 合成 exit 1。桌面 ffmpeg-min（`tool/ffmpeg-min/build-ffmpeg-min.sh:43` DECODERS 含 `mjpeg`+`png`、DEMUXERS 含 `image2`、**无 rawvideo**）有 png decoder 故不复现。
- **[x] ① 已修复** — 根因修法：把静止文本帧从 PNG 改喂 **JPEG**，两端 ffmpeg（桌面 ffmpeg-min / 移动 ffmpeg-kit min）都含 **mjpeg decoder**，绕开缺失的 png decoder。Flutter `Image.toByteData` 只支持 png/rawRgba（不支持直出 jpeg），且两端 min 均无 rawvideo demuxer/decoder（故排除 rawvideo 候选，它会同时弄坏桌面）。改动：① 新增纯函数 `encodeClipTextFrameAsJpg`（`package:image` 把渲出的 png bytes 解码后 encodeJpg，`audiobook_clip_export.dart`）；② `buildFfmpegImageAudioToVideoArgs` 增显式 `-f image2`（两端白名单都含 image2 demuxer）并明确输入为 jpeg；③ 管线 `audiobook.part.dart` 落盘从 `$base.png` 改 `$base.jpg`、写前经 `encodeClipTextFrameAsJpg`（解码失败记日志+toast 回退）。提交见分支 `todo1134-clip-png-menu`。
- **[x] ② 已加自动化测试** — `hibiki/test/media/audiobook/audiobook_clip_synth_test.dart` 新增两组守卫：`buildFfmpegImageAudioToVideoArgs image input (BUG-543 png-free)`（断言命令声明 `-f image2`、图片输入为 `.jpg`、任何输入 arg 都不是 `.png`）；`encodeClipTextFrameAsJpg (BUG-543 png->jpeg)`（png→jpeg 往返：输出带 JPEG SOI `0xFFD8`、可再解码回同尺寸；损坏字节返 null 让调用方回退）。
- **备注**：真机「移动端合成实际成功」需 Android 设备验收（当前无设备接入），由 owner 排期。桌面路径顺带核对无回归：桌面 ffmpeg-min 有 mjpeg decoder + image2 demuxer，改后桌面也走 mjpeg（此前走 png），两端统一。
