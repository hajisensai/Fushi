## BUG-3519 · reader-lazy-illustrations-premature-chapter-advance
- **报告**：2026-10-18（用户：手机小说跨章有问题，以《志乃と恋 Future》为例，从封面往后划进入一堆插图的章节，继续往后划，还没到插图末尾、连章尾都没到就跨到了下一章）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/pages/implementations/reader_fushi/webview.part.dart` `_buildSanitizedChapterHtmlBytes` 调 `ReaderResourceSanitizer.markImagesLazy`，给正文插图在 HTML 源码里写入 `loading="lazy"`（纯图片章与合并前导插图除外）。分页是横向多列排版：未加载的懒图尺寸为 0、不占列，而远列永远进不了 Chromium 懒加载视口，所以这些图一直不加载。`buildPaginationMetrics` 的 `maxScroll` 只算到已加载的图，`isAtEnd()`（`reader_pagination_scripts.dart`）提前为真，翻页越界走 `_handlePageTurnLimit` 直接跨章。「文字少 + 一串插图」的章既不是纯图片章，也不是合并前导插图，正好落进懒加载分支。
- **[x] ① 已修复** — 去掉正文图片懒加载：删 `markImagesLazy`，改为 `ReaderResourceSanitizer.stripImageLoadingAttributes`（连原书自带的 `loading` 也去掉），由阅读器统一按 eager 加载；图片在 `window.load` 前全部就位，初始化时章节几何即为完整。顺带删除围绕懒加载打的治标补丁：TODO-1349 纯图片章 eager 特判（`__fushiImageOnlyChapter` / `eagerAll` / `_isImageOnlyChapterCached`）、TODO-1339 合并前导图 eager 特判（`isMergedLeadImg` / 显式 `loading="eager"`）、`forceLoadPendingImages` 及其两个调用点、有声书跨图暂停与 VN `waitForImages` 里的「lazy 强制翻 eager」。迟到图片的 load 回调改为无条件失效 `paginationMetrics`（原先只有 >256px 的块图才失效）。首开读图开销由既有的 `_prefetchAdjacentChapterImages` 预热下一章承担。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_image_loading_strip_test.dart`（去属性的各种写法 + 引号内字样不误伤）、`fushi/test/reader/reader_image_pipeline_guard_test.dart`（章节 HTML 流水线确实调用它）；删除只钉补丁的守卫 `merged_image_eager_guard_test.dart`、`integration_test/merged_image_eager_load_test.dart`、`tool/reader_pitch_headless/sparse_chapter_landing_probe.mjs` 及其它文件里的 lazy/eager 断言。
- **备注**：未做真机复测（翻页 / 滚动 / VN 三模式），需在手机上用《志乃と恋 Future》复验：封面后插图章逐页划到最后一张插图，再划一下才进下一章。代价：带大插图的章首次打开会等图片读盘（原来懒加载省掉的那部分），下一章已有预热。
