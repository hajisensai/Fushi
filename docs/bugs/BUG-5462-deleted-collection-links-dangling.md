## BUG-5462 · 删掉的视频合集在作品图谱里留下「不在库中」的死连接
- **报告**：2026-11-25（用户真实库：合集被删后，12 条指向它的「同一作品」连接仍在，弹窗里显示一张「13 · 不在库中」的死卡）
- **真实性**：✅ 真 bug。`media_links` 的 `video_collection` 端点键是本机合集 id（`MediaLinkKind.videoCollection` 注释），没有外键；四条删合集路径只删成员、标签映射和合集行，从不碰以它为端点的连接：`deleteMediaCollection`（`packages/fushi_core/lib/src/database/database_library.part.dart:1134`）、移空自删（`:1899`）、删条目连带清空（`:2050`）、同步解散 `deleteMediaCollectionRaw`（`:2229`）。合集 id 自增不复用，端点删掉就再也解析不回来，这些行永远是死卡（作品图谱同步按自然键对齐，本机没有该合集的连接本来就不发出，留着也没有跨端用处）。
- **[x] ① 已修复**（2903203fcf）— 四条路径收进同一个 `_dropMediaCollectionRow`：删合集行时同事务清掉合集标签映射和以 `video_collection:<id>` 为端点的连接（两个方向）。**物理删除而不是写墓碑**：墓碑的语义是「用户否决了这一对」，用在这里会让推断永远不再提这一对、且端点已死墓碑本身也无意义；跨端不受影响——对端仍有该合集时它的连接照常存在，同名合集以后在本机再出现时会同步回来。AI 写入仍可撤销：整理器 / 库管家删合集前记的身份快照（BUG-5461）包含这些连接，撤销时随合集原 id 一起还原。
- **[x] ② 已加自动化测试** — `fushi/test/database/collection_identity_snapshot_test.dart`「删合集清掉以它为端点的作品图谱连接」组：用户删除、移空自删、删条目连带清空、同步解散四条路径都清掉两个方向的连接与标签，别的合集的连接不动。
- **备注**：与 [BUG-5457](BUG-5457-media-link-dangling-collection.md) 根因 1 的合集部分是同一个 bug，合流后共用 `_dropMediaCollectionRow`。存量死连接由 BUG-5457 的 schema v181 迁移（`purgeDanglingMediaLinks`）清掉——判据是「端点合集 id 在本机不存在」，不需要知道它原本属于谁；合并时败方连接改挂到胜方也由 BUG-5457 实现（`deleteMediaCollection(linksMovedTo:)`）。
