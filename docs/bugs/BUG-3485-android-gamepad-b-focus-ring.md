## BUG-3485 · Android 手柄 B 在触摸模式下变系统返回 + 屏幕外缘系统焦点框
- **报告**：2026-10-16（用户：应用内反馈 bxsTQRaamU，vivo V2339FA / Android 14 / Xbox 手柄）
- **真实性**：✅ 真 bug，模拟器 `hibiki_nav`（Android 15）+ uinput 虚拟 Xbox 手柄（vendor 045e，落 Generic.kl/kcm）两条都复现。
  - **现象 1（B = 系统返回）**：启动后处于触摸模式（`mInTouchMode=true`），`dumpsys activity top` 里 FlutterView 无 focused 标志（`VFE...... ........`）；按 B 后 logcat 出现 `AutofillManagerService: onBackKeyPressed()`（系统收到 BACK），更新弹窗被关掉 / 首页直接退回桌面。先按一次 A 后 `mInTouchMode=false`、FlutterView 变为 focused（`.F......`），再按 B 不再出现 `onBackKeyPressed`、app 留在前台。
  - **根因 1**：键事件只沿**聚焦 view 链**下发（`ViewGroup.dispatchKeyEvent` 只交给 `mFocused`）。API 28+ 在触摸模式下窗口不分配初始焦点，Flutter 也不主动给 FlutterView 要焦点 → 没有聚焦 view 时 `BUTTON_B` 根本到不了 FlutterView，Flutter 侧 BUG-1266 的吞键逻辑（`global_navigation.dart` `gamepadSystemFallbackMustBeSwallowed`）一次都轮不到；app 报「未处理」后 `Generic.kcm` 的 `fallback BACK` 合成返回键，绕过快捷键注册表，所以清空「返回」绑定也没用。A / Y 能「把焦点拉过来」是因为它们的兜底键 DPAD_CENTER / SPACE 属于导航 / 输入键，会让 ViewRootImpl 退出触摸模式并把默认焦点给 FlutterView（FlutterView 本身 focusableInTouchMode，拿到后点屏也不丢）；聚焦的平台视图被移除、切走再回来等丢焦路径之后又回到无焦点状态。修复点 `fushi/android/app/src/main/java/app/fushi/reader/MainActivity.java:214`（`ensureKeyFocusTarget`）+ `:352`（`dispatchKeyEvent` 在交给 super 前调用）。
  - **现象 2（外缘淡框）**：FlutterView 获焦且非触摸模式时，截图四边各有约 4px 的系统焦点高亮（模拟器上是绿色，用户机上是很淡的框）。
  - **根因 2**：`setDefaultFocusHighlightEnabled` 是**逐 view** 属性，BUG-195 / BUG-438 只设在 decorView 上，真正持焦的全屏 FlutterView 仍是默认 true，系统在它身上画默认焦点框 = 屏幕最外缘一圈。修复点 `MainActivity.java:177`（`disableSystemFocusHighlight` 改为同时设 FlutterView、当前焦点 view，并挂全局焦点监听给之后获焦的 view 关掉）。与「显示焦点框」设置无关（那是 Flutter 自绘焦点环）。
- **[x] ① 已修复** — `MainActivity.java`：`ensureKeyFocusTarget()`（无聚焦 view 时把焦点交给 FlutterView 再分发）+ `disableSystemFocusHighlight()` 覆盖 FlutterView 与后续获焦 view。提交见 PR。
- **[x] ② 已加自动化测试** — 源码守卫 `fushi/test/build/android_gamepad_key_focus_guard_test.dart`（Java 侧无单测宿主；钉死「super 之前补焦点」「只在无焦点时补」「FlutterView 关系统焦点框」）。
- **真机复现（修复前，小米平板 5 / MIUI，装机为现行发布版）**：冷启动后 `mInTouchMode=true`、FlutterView 无焦点；进统计页后 `input keyevent --source gamepad KEYCODE_BUTTON_B`，logcat `MIUIInput` 记录到投给 Fushi 窗口的 `KEYCODE_BACK`（`flags=0x400` = FLAG_FALLBACK），统计页被系统返回关掉；先注入 BUTTON_A 后 `mInTouchMode=false`、FlutterView 获焦，再按 B 不再出现兜底 BACK。MIUI 上 FlutterView 获焦后截图四边未见系统焦点框（该框随 ROM 而异，模拟器为绿色 4px，用户 vivo 为淡框）。
- **备注**：修复版**未在真机上装机验证**——真机装的是发布签名包，本机 debug 签名不同，覆盖安装需卸载清数据，不做；带 `applicationIdSuffix` 的并行测试包需要一次完整 APK 构建，本次两次整包构建都卡在原生 cmake 阶段（与本改动无关）。修复侧只验证了 `:app:compileDebugJavaWithJavac` 编译通过 + 源码守卫测试。
