## BUG-2258 · 打开带有声书的书不按有声书进度定位，按播放才跳
- **报告**：2026-09-08（用户：）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/pages/implementations/reader_fushi_page.dart:2371`（开书起点三选一 `if/else`：书签跳转 → **有阅读存档就按存档** → 只有无存档才 `_restoreFromCurrentAudioCue()`）。阅读进度（`ReaderPositions` 表）与有声书进度（偏好 `audiobook_pos_<key>` / `audiobook_pos_at_<key>`）是两份独立持久化：退书后台听书、书架小播放器听书只推进音频进度，重开书永远走存档分支 → 视口不在听到的地方；播放器其实已 seek 到保存毫秒（`audiobook_controller.dart:820`），但 `shouldRevealCurrentCue` 被 `_hasPlayedOnce` 门压着（`audiobook_controller.dart:1429`，刻意防暂停态 cue 拽走阅读位置，TODO-718），按播放那一刻门开、第一个 cue tick 才把视口拽到音频位置——即「按播放才跳」。
- **[x] ① 已修复** — 开书起点改为两份进度按写入时刻 LWW 仲裁（`audiobookResumeWinsOverReader`，`fushi/lib/src/media/audiobook/audiobook_resume_point.dart`，严格较新的音频才胜出，平局/老数据 0 仍走存档）。三处配套缺一不可：
  - **时间戳语义**：`AudiobookRepository.updatePositionMs` 位置没变就不写、不重盖时间戳——关书时 reader 先落阅读位置再 `flushPosition` 音频，若每次强制 flush 都重盖时间戳，音频永远比阅读「更新」，仲裁会被写入顺序而不是用户行为决定（暂停在第 3 章、静读到第 10 章关书，重开跳回第 3 章）。控制器三条强制路径（暂停 / 退后台 / stop）的 durability 契约不变，仍会调到仓库层。
  - **来源一致**：`AudiobookSessionLauncher.readPositionUpdatedAtMs` 与 `resolve()` 共用 `_pickSource`（Audiobook 行有可播放音频优先，否则 SrtBook 行），读的是**会真正启动的那个来源**的键；不取两键较大值（SRT 重导入会给 uid 键盖新时间戳，会话却加载 bookKey 键的旧位置）。与阅读存档并行取，不起 audio_service。
  - **起点落地**：音频胜出才 `await audioSlotFuture`（try/catch，槽失败正文照开、回退存档）；`_restoreFromCurrentAudioCue` 改返 bool，三条 cue 反查路径与存档 / 书签分支统一经 `_setOpenResumePoint` 一次写齐七个起点字段（cue 起点 charOffset 取 -1，否则存档分支先填的精确字符锚会在 `restoreToCharOffset` 里压过 cue 分数）；算不出（无 cue / 反查不到章）回退存档。不动 `_hasPlayedOnce` 门（TODO-718 被动高亮不覆盖阅读位置的契约不变）。
  - 多文件有声书的位置本身就恢复错文件，是独立的控制器缺陷，见 BUG-2263（同 PR 修）。
- **[x] ② 已加自动化测试** — `fushi/test/media/audiobook/audiobook_resume_point_test.dart`：仲裁纯函数四态；`readPositionUpdatedAtMs` 用内存 Drift 库验 无记录→0 / Audiobook 行（有音频）按 bookKey 键 / 配对 SrtBook 按 uid 键且 epub 键不算数 / 两行并存按 resolve 优先序取 bookKey / Audiobook 音频缺失回落 SrtBook；`updatePositionMs` 同位置不重盖时间戳、位置变了才推进、无时间戳老数据不变时保持无戳；reader 源码守卫锁「存档不再短路音频恢复、LWW 助手参与决策、`!restored` 后才落存档、槽 await 在 try 里、起点字段只经 `_setOpenResumePoint` 写」。
- **备注**：代价：音频胜出时首屏要等音频槽（audio_service 初始化 + 会话装配 + cue 预热）；这正是用户要跳到音频位置的场景，槽本来也要为底栏落定。可选后续：从持久化 positionMs + cuesForBook 在 Dart 侧直接推 cue 起点，不等播放器。`_hasPlayedOnce` 门与 BUG-882（歌词模式同族、已用位置驱动 `allBookCueIdxAtPosition` 修好）不动。
