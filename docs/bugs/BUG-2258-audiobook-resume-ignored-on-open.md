## BUG-2258 · 打开带有声书的书不按有声书进度定位，按播放才跳
- **报告**：2026-09-08（用户：）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/pages/implementations/reader_fushi_page.dart:2371`（开书起点三选一 `if/else`：书签跳转 → **有阅读存档就按存档** → 只有无存档才 `_restoreFromCurrentAudioCue()`）。阅读进度（`ReaderPositions` 表）与有声书进度（偏好 `audiobook_pos_<key>` / `audiobook_pos_at_<key>`）是两份独立持久化：退书后台听书、书架小播放器听书只推进音频进度，重开书永远走存档分支 → 视口不在听到的地方；播放器其实已 seek 到保存毫秒（`audiobook_controller.dart:820`），但 `shouldRevealCurrentCue` 被 `_hasPlayedOnce` 门压着（`audiobook_controller.dart:1429`，刻意防暂停态 cue 拽走阅读位置，TODO-718），按播放那一刻门开、第一个 cue tick 才把视口拽到音频位置——即「按播放才跳」。
- **[x] ① 已修复** — 开书起点改为两份进度按写入时刻 LWW 仲裁（`audiobookResumeWinsOverReader`，`fushi/lib/src/media/audiobook/audiobook_resume_point.dart`，严格较新的音频才胜出，平局/老数据 0 仍走存档）：`AudiobookSessionLauncher.readPositionUpdatedAtMs` 与阅读存档并行取（只查 Audiobook/SrtBook 两行 + 两偏好，不解析音频、不起 audio_service，两键都在取较大者），音频胜出时才 `await audioSlotFuture` 走 `_restoreFromCurrentAudioCue()`；该函数改返 bool，统一由 `_applyAudioCueResumePoint` 落起点并把 `_initialCharOffset/_initialCharOffsetEnd/_lastProgressCharOffset` 归 -1（否则存档分支先填的精确字符锚会在 `restoreToCharOffset` 里压过 cue 分数）；算不出（无 cue / 反查不到章）回退存档。不动 `_hasPlayedOnce` 门（TODO-718 的被动高亮不覆盖阅读位置契约不变）。
- **[x] ② 已加自动化测试** — `fushi/test/media/audiobook/audiobook_resume_point_test.dart`：仲裁纯函数四态；`readPositionUpdatedAtMs` 用内存 Drift 库验 无记录→0 / Audiobook 行按 bookKey 键 / 配对 SrtBook 按 uid 键 / 两行并存取较大；reader 源码守卫锁「存档不再短路音频恢复、LWW 助手参与决策、`!restored` 后才落存档」与「cue 起点清精确字符锚」。
- **备注**：`_hasPlayedOnce` 门与 BUG-882（歌词模式同族、已用位置驱动 `allBookCueIdxAtPosition` 修好）不动；正文模式此前没有等价物。
