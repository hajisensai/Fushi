## BUG-4073 · Windows flutter_windows.dll+0x133cb 访问冲突：UIA HitTestSync 打到失步的 AX 节点
- **报告**：2026-11-04（崩溃报告整批分诊：`HjB4IzCLFy`、`2LWk4y3pPw`，同一台 Windows 11 Home China build 26200，3.3.0-debug.23261——即当前 develop 尖端版本；两次间隔 20 分钟）。
- **真实性**：✅ 真原生崩溃，崩点已符号化；**触发它的那份失步语义更新没有定位到**。
  - 摘要：`code=0xc0000005 at=flutter_windows.dll+0x133cb av=read@0x8 frames=flutter_windows.dll+0x133cb, flutter_windows.dll+0x13426 ×9`（9 层同址递归）。
  - 构建用的是打过补丁的引擎（`ci/patches/flutter-engine/3.47.6/artifacts.json`：`flutter-engine-windows-3.47.6-hdr-output-2.zip`，sha256 `281b1147…085af`，本机下载后核对一致），**不是** SDK 缓存里的原版 dll（拿原版 PDB 符号化会落到指令中间，结果无效）。用补丁版 `windows-x64-release/flutter_windows.dll` + 同包 PDB，`llvm-symbolizer --inlines`：
    - `0x1800133cb` → `std::_Ref_count_base::_Incref_nz`（`memory:1136`）← `weak_ptr<FlutterPlatformNodeDelegate>::lock` ← `FlutterPlatformNodeDelegateWindows::HitTestSync(int,int)`，`shell/platform/windows/flutter_platform_node_delegate_windows.cc:69`
    - `0x180013426` → `FlutterPlatformNodeDelegateWindows::HitTestSync`，`flutter_platform_node_delegate_windows.cc:74`（对子节点递归）
  - 对应引擎源码（`engine/src/flutter/shell/platform/windows/flutter_platform_node_delegate_windows.cc:66-75`）：对 `GetAXNode()->children()` 的每个子节点取 `bridge->GetFlutterPlatformNodeDelegateFromID(child->id()).lock()`，只有 release 下不生效的 `FML_DCHECK(win_delegate)`，然后直接递归。外部 UIA 客户端（屏幕取词 / 翻译 / 输入法 / 讲述人等调用 `ElementFromPoint`→`accHitTest`）沿 AX 树往下命中测试时，子节点在 `AXTree` 里、bridge 的 `id_wrapper_map_` 里却没有 / 已失效，解引用即崩。这是 [BUG-2839](BUG-2839-windows-a11y-orphan-semantics-crash.md) 同一崩点、同一失步模型（`AXTree::Unserialize` 半应用失败后 bridge 不被通知，`accessibility_bridge.cc:108-116` 只 `FML_LOG(ERROR)` 后 return）。BUG-2839 修的是 OverlayPortal 孤儿节点那一个来源（`ci/patches/flutter-sdk/3.47.6/0001-semantics-no-orphan-traversal-child.patch` 在本版本仍在），23261 再次崩说明**还有别的失步来源**。
  - 崩溃进程的日志尾（`HjB4IzCLFy`，tid 33528 = 崩溃线程）：崩前 6 s（01:57:44Z）连续新建 4 个 961×94 的 WebView 纹理桥（`create-bridge` / `create-pool` / `pump-start`，`flutter_inappwebview_windows` 的 `custom_platform_view/texture_bridge.cc`），崩溃发生在 01:57:50Z。WGC 捕获本身不在崩溃栈上（崩溃线程是平台线程上的 UIA 回调），这些事件只说明崩溃时界面里有多个刚建好的 WebView 平台视图——平台视图节点进出语义树是一个待查的失步嫌疑来源，未证实。
- **[x] ① 已修复（框架层，已证实的失步来源）** — `ci/patches/flutter-sdk/3.47.6/0003-semantics-skip-children-of-merged-traversal-parent.patch` + `0002-semantics-no-merge-distinct-traversal-parents.patch`（来历、删除条件见 `ci/patches/flutter-sdk/README.md`）。**用户现场那一帧没有取到**（minidump 未上传、引擎报错不进日志），下面的来源是本机按引擎真实规则复现出来的，不能断言就是 23261 崩的那一帧；为此同时加了生产哨兵（见「失步取证」），下次失步会带节点信息进错误日志。
  - **来源 A（不依赖任何新补丁、当前 develop 就有）**：`MergeSemantics` 里两个带 tooltip 的 `IconButton`，鼠标悬停任一个。两个按钮的 tap 动作冲突，各自成节点后被并进合并祖先（`isMergedIntoParent`），Tooltip 的 `OverlayPortal` 锚点（traversal parent）因此从不单独下发；悬停时 overlay 子节点 graft 到它身上，`SemanticsNode._shouldSkipInHitTest`（`packages/flutter/lib/src/semantics/semantics.dart`，0001 补丁加的跳过逻辑只认「traversal parent 不存在」）不跳过它，于是它被下发、却没有任何节点在 `childrenInTraversalOrder` 里列它。实测下发帧：`1 traversal=[2] hitTest=[7, 2]`、`7 traversal=[]`——节点 7 是孤儿，引擎 `ax_tree.cc:1346` 报「7 will not be in the tree and is not the new root」整份拒收；框架以为已发过，下一帧增量更新在第 2 步撞「Nodes left pending by the update」（`ax_tree.cc:1781`，**改完树之后**才失败，`OnNodeCreated` / `OnNodeDeleted` 不发），bridge 的 `id_wrapper_map_` 与 AXTree 脱节：树里新建、映射里没有的子节点 → `HitTestSync` 里 `lock()` 拿空（本条）/ `ChildAtIndex` 空返回（BUG-2345）；树里已删、映射里还在的 delegate → 读已释放 `AXNodeData`（BUG-2337 的乱长度字符串、BUG-2839 的 `GetParent`）。
  - **来源 B（同族，a11y 内容丢失）**：`ListView` 条目（`IndexedSemantics` 把条目内不冲突的 configuration 并成一个节点）里并排两个 Tooltip / OverlayPortal：`SemanticsConfiguration.isCompatibleWith` 不拦两个不同的 `traversalParentIdentifier`，`absorb` 的 `??=` 丢掉第二个，第二个 overlay 被 0001 跳过，不进无障碍树（上游 issue #182444 / 未合入的 #190344）。0002 修它；但**只打 0002 会把来源 A 扩大到无冲突的锚点**（`MergeSemantics(Row(Tooltip, Tooltip))` 悬停即孤儿，实测），所以 0002 与 0003 必须一起打。
  - 0003 的修法：被并进祖先的 traversal parent 视同缺失，跳过 graft 到它身上的 traversal child（tooltip 文案本来已作为 `tooltip` 属性并进合并节点，不丢信息）；`isMergedIntoParent` 翻转时把 traversal child、其 hit-test parent 与未合并后代标脏重发，避免翻回时子树缺数据。
  - **WebView 平台视图不是来源**：`flutter_inappwebview_windows` 的 `CustomPlatformView`（`packages/flutter_inappwebview_windows/lib/src/in_app_webview/custom_platform_view.dart:582-612`）是 `Focus` + `Texture`，不建平台视图语义节点；4 个 Focus+Texture 磁贴在 1715 / 1075 宽之间反复改宽的场景按契约逐帧核对全绿（`semantics_update_ax_tree_contract_test.dart`「webview-like Focus+Texture tiles across width changes」）。
- **[x] ② 已加自动化测试** — `fushi/test/widgets/semantics_update_ax_tree_contract_test.dart`：截获每帧发往引擎的 `updateNode`，按 `AccessibilityBridge::CommitUpdates` 的两步提交 + `AXTree::Unserialize` 的判定（孤儿、重挂未重发、同一子节点两个父、新子节点缺数据、hit-test / traversal 两链同集）逐帧核对；场景含 Tooltip 悬停（ListView 条目 / MergeSemantics / MergeSemantics 内 IconButton / ListTile / 普通 Row）、两个 OverlayPortal 同条目、GlobalKey 搬子树、中间边界切换、类 WebView 磁贴改宽。「MergeSemantics IconButtons」在只有 0001 的 SDK 上红（上面的孤儿帧），打 0002+0003 后绿；「two shown OverlayPortals … both reach the engine tree」在没有 0002 的 SDK 上红。契约模型本身的判定对照测试：`fushi/test/utils/misc/semantics_ax_tree_contract_test.dart`（每条对应引擎一个失败点）。
- **失步取证（生产）**：`fushi/lib/src/utils/misc/semantics_ax_tree_contract.dart` 的 `AxTreeDesyncSentinel` 挂在主入口 binding（`FushiWidgetsBinding`，`fushi/lib/main.dart`）上：桌面端语义开着（有 UIA / AT-SPI / VoiceOver 客户端）时用同一份契约模型逐帧复核，违约帧记 `A11y.axTreeDesync`（违约项 + 节点 id 与截断 label），每个语义会话只记第一帧。没有改成 runner 抓引擎 stderr，原因：`flutter_windows.dll` 静态链接 CRT（`dumpbin /imports` 只有 KERNEL32 / USER32 等系统 DLL，没有 ucrtbase / `api-ms-win-crt-*`），它的 fd 2 在 DLL 初始化（早于 `wWinMain`）时按进程标准句柄定死；资源管理器拉起的 GUI 进程没有标准句柄，runner 再 `SetStdHandle` / `_dup2` 都够不着，`FlutterDesktopResyncOutputStreams` 只会重开 `CONOUT$`。要在 runner 层截获只能延迟加载 `flutter_windows.dll` 与全部插件 DLL（改加载顺序、影响崩溃 filter 链）或另起控制台，代价与风险都不值；框架出口的同一规则复核能在引擎之前认出违约帧，信息还更多。
- **引擎侧仍可加固（未做，需引擎构建，由用户决定）**：`FlutterPlatformNodeDelegateWindows::HitTestSync`（`flutter_platform_node_delegate_windows.cc:66-75`）、`FlutterPlatformNodeDelegate::ChildAtIndex`（`flutter_platform_node_delegate.cc:83-90`）、`GetParent` 对拿不到的 delegate / 空子节点返回失败而不是解引用；`AccessibilityBridge::CommitUpdates`（`accessibility_bridge.cc:108-116`）在 `Unserialize` 失败时丢弃整棵树并重建（新 `AXTree` + 清空 `id_wrapper_map_`，下一帧请框架整树重发），而不是半应用后 return；`CreateRemoveReparentedNodesUpdate` 的两处 `assert` 在 release 下改成显式校验。
- **备注**：符号化可复现：`llvm-symbolizer --obj=<hdr-output-2>/windows-x64-release/flutter_windows.dll --inlines 0x1800133cb 0x180013426`（基址按 PE 默认 0x180000000 + RVA）。
