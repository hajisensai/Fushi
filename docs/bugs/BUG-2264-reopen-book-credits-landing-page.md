## BUG-2264 · 重复开关书落地页整页入账且写出零时长段
- **报告**：2026-09-08（用户：「只要重复打开书，统计数值就会增加」+「有 0 分钟的误点会话」）
- **真实性**：✅ 真 bug。根因：EPUB / 漫画 / PDF 三域关书三条路都把「关书」当「翻走」结算当前单元——`reader_fushi_page.dart` dispose 的 `_studyClock?.detach(_readLedger.leave)` 与 `onSourcePagePop` 的 `_readLedger.leave()`、`navigation.part.dart` `_flushAllForProcessExit` 的 `_readLedger.settle()`；漫画 `manga_fushi_page.dart` / PDF `reader_pdf_page.dart` 同形三处。`ReadUnitLedger.leave()`（`read_unit_ledger.dart`）按**单元终点** reconcile，于是「开书落地、一个字没读、关掉」的那页整页入账；会话并集只活在一个 State 里，开关 10 次入 10 次。同时 `StudyClock._worthWriting`（`study_clock.dart`）只拦「0 字且 <1s」，这笔 chars>0 的结算让每次误点都写出一条时长≈0 的 `study_segments` 行——统计页里的「0 分钟会话」。
- **[x] ① 已修复** — 关书 / 退后台 / 进程退出**不碰账本**：一页只在「从它翻走」那一刻入账（`_beginNavigation` / 同章跳转 / 显式跳句 / 换章的 `leave()` 不变）。`StudyClock.detach()` 去掉结算回调只停表；`ReadUnitLedger.settle()` 随之删除（它唯一的用途就是退出 flush 结算当前页）。误点开书 = 0 字 + <1s，一行都不写。代价（已知、接受）：读完一页立刻关书，这页记到下次打开翻走的那天；读到全书末页关书不计末页。备选「落地页不计、翻到的页关书时计」被否：续读时上次关书那页会在「关书时」与「下次翻走时」各计一次，每次续读都双计。
- **[x] ② 已加自动化测试** — `test/stats/read_unit_ledger_test.dart`（只 arrive 不 leave × 10 次零入账）、`test/reader/reader_read_ledger_boundaries_test.dart`（开关 N 次不涨 / 拖进度条后关书全组改口径）、`test/reader/reader_pdf_read_ledger_test.dart`（落地第 5 页开关 5 次零页）、源码守卫 `test/reader/reader_read_ledger_wiring_guard_static_test.dart`（EPUB 关书三条路无 `_readLedger`、`settle` 标识符绝迹、leave 恰五处）/ `test/pages/reader_study_clock_gate_guard_static_test.dart`（PDF）/ `test/media/manga/manga_stats_dwell_guard_test.dart`（漫画）、`test/media/audiobook/study_clock_test.dart`（`detach()` 无回调）。
- **备注**：与 BUG-2227（关书结算的是上次采样单元）互斥——关书不再结算，那条的补刷仍保留给跳转 / 翻页路径。
