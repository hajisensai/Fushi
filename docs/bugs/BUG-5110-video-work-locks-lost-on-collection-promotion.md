## BUG-5110 · 单集作品长成多集合集后重刮，挂在那一集上的手填值 / 字段锁丢失
- **报告**：2026-11-22（BUG-5082 修复时沿代码路径发现）
- **真实性**：✅ 源码确认（未写复现测试）。合集只有 1 个视频时，计划器按单集刮（作品行挂在那一集的 `book_uid` 上，`video_source_work_planner.dart` 单成员合集不进 `primaryCollections`）。下到第二集后计划器改按合集刮，`VideoMetadataDatabaseStore.apply` 只按 `collection_id` 读旧行取字段锁（`video_metadata_database_store.dart` `existingWork`），随后 `_removeBookOwnedWorksForCollection` 把成员上的作品行整行删掉——用户在那一行上的手填值、v99 字段锁（含封面锁）、锁住的类型词条一起丢失。
- **[x] ① 已修复**（分支 `claude/dec-fmicnouu6v-manual-meta`）— `VideoMetadataDatabaseStore.apply` 在合集没有自己的行时先调 `_promoteSoleMemberWork`：视频成员里恰好一个挂着作品行就把它改归属（`book_uid` → `collection_id`，作品 id 不变），该作品起点的系列关系 `UPDATE OR IGNORE` 改挂合集（合集已有同 `(source, subject_id)` 的保留合集的）。之后的季 / 集 / 图 / 词条 / 身份整组替换就是「同一作品重刮」的语义：季集按合集刮削结果替换，锁住的标量 / 图种 / 词条按 v99 锁保留，身份按本次结果替换。多个成员各有作品行（各自独立的作品）不升格，照旧清掉。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/metadata/video_metadata_collection_promotion_test.dart`：单集行手填简介 + 锁简介 / 封面 + 一条成员起点关系 → 加第二集按合集刮 → 同一作品 id、手填简介、锁、旧封面、关系都在；多成员各有作品时不升格。
- **备注**：与 BUG-5082 手填资料同源的既有缺口（既有封面锁 / 字段锁同样受影响），非 BUG-5082 引入。BUG-5082 之后后果变重：丢的不再只是能重刮回来的刮削值，而是用户手打的资料。另一条更快触发的路径（#4076 审查发现）：多集合集还没有合集行、只有一个成员上挂着单集作品行时，合集页「编辑资料」按显示口径改的是那条成员行，而补刮会把这个未识别的合集按合集刮、随即删掉成员行——手填当场丢。
