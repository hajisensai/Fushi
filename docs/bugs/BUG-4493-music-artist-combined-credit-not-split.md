## BUG-4493 · 音乐艺人列表同一组人散成多条：扫描入库不拆合写的艺人署名
- **报告**：2026-11-11（用户：应用内反馈 AajkskmC-L；Windows）
- **真实性**：✅ 真 bug。截图里艺人分区并排出现「藤澤慶昌」「藤澤慶昌&加藤達也」「藤澤慶昌/加藤達也」「藤澤慶昌.加藤達也」等条目。根因：Rust 扫描 `native/fushi_music/src/scan.rs:560` `credits_of` 把标签字段整串当一个艺人名，`uid::artist_uid(整串)` 落成一位艺人，`music_track_credits` / `music_artists` 按它入库，艺人分区（`database_music.part.dart` `listMusicArtists`）就把每种合写拼法列成一个人。lofty 只按 ID3v2.4 的 NUL 拆多值（`tags.rs` `get_all`），`&` / `/` / `、` 这类人工合写不拆。Dart 侧 `music_metadata_text.dart:47` 的 `_artistSeparators` 只用于 MusicBrainz 比对，入库路径不经过它。
- **[x] ① 已修复** — 新增 `native/fushi_music/src/credit.rs` `split_artist_credit`（Rust 胖核心，Dart 不另写一份）：分隔符表与 Dart `_artistSeparators` 对齐（`,` `、` `，` `/` `／` `;` `；` `&` `＆` `×`，以及独立词 `x` / `feat(.)` / `ft(.)` / `with` / `vs(.)`）；入库是显示名，额外两条护栏——括号内不拆（`ノア(CV:A&B)` 整体一个署名），关键词分隔只认前后空白的独立词且两侧都有名字（`X JAPAN`、`Feather`、`Kid Within` 不拆）。`credits_of` 对 artist / album_artist / composer / lyricist / arranger 每个字段先拆再一人一个 `artist_uid`；显示用的 `artist_credit` 与专辑 uid 派生（`album_uid` 用原文 album_artist）不变。**存量曲库同修**（审查 PR #3419 指出：增量扫描对 mtime / size 没变的文件不重新解析，只修新入库数据等于用户看不到效果）：Rust 新增解析修订号 `scan::PARSER_REVISION`（=1，经 `ffm_scan_parser_revision` / Dart `musicScanParserRevision` 导出），`MusicLibraryScanner._ingest` 按来源记 `music_scan_parser_revision::<sourceId>`（设备本地前缀，进 `PrefRedactionPolicy.deviceLocalKeyPrefixes`），与当前修订号不一致就不传已知文件清单、整源重新解析，`writeMusicScanBatch` 按曲目重写 `music_track_credits`，旧合写 `artist_uid` 不再被任何在库曲目署名、从艺人分区消失；扫完才记新值。以后改解析结果的改动升这个修订号即可。
- **[x] ② 已加自动化测试** — `fushi/test/media/music/music_library_scanner_test.dart`「BUG-4493 存量」（旧修订号入库的合写艺人在修订号升级后被整源重新解析、艺人分区变成单人，修订号不变照常增量）+ 修订号偏好设备本地断言；`native/fushi_music/tests/scan.rs` `parser_revision_is_exported_and_covers_credit_split`；`native/fushi_music/src/credit.rs` 4 条单测（反馈三种拼法拆出同一组人、与 Dart 同一张分隔符表、括号 / 关键词护栏、去空去重）+ `src/scan.rs` `credits_split_combined_artist_fields_into_one_uid_per_person`（`credits_of` 端到端：合写拼法落同一组 uid）。`cargo test --profile quick --lib --test scan --test remote` 144+8+10 通过（golden 不变）。
- **备注**：已知取舍（按任务要求对齐 Dart 分隔规则）：名字本身带分隔符的组合（`Earth, Wind & Fire`、`AC/DC`）会被拆开；`.` 不是分隔符（要保住 `Mr.Children`），所以截图里「藤澤慶昌.加藤達也」这一条仍保持原样。存量曲库已由解析修订号机制覆盖（见 ①），升级后首次扫描每个来源会整源重新解析一次（远程来源会重新取一遍各文件头部字节）。**待所有者拍板**：「藤澤慶昌.加藤達也」这种半角点号合写不拆——`.` 加进分隔符会把 `Mr.Children`、`T.M.Revolution` 之类拆坏，要不要对「两侧都是 CJK 字符的 `.`」开特例由所有者决定；在拍板前这一条在艺人分区里仍是独立条目。
