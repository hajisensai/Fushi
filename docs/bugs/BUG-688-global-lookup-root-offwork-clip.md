## BUG-688 · app外查词根卡靠屏右下生成在工作区外被裁
- **报告**：2026-07-10（用户：「不止闪烁了，这个弹窗直接生成在窗口外面了可能」，TODO-1231 第六轮复诉·验收 BUG-670 修复时触发）
- **真实性**：✅ 真 bug（reserve-to-edge 地板引入的回归，develop 0aabf314c / BUG-670 起）。根因：根卡是级联里**唯一不经工作区 clamp 的卡**——`hibiki/lib/src/lookup/global_lookup_render.dart` `_frameRectMap` anchorless 分支恒返回 `{left:0, top:0}`（根卡钉在 window-local 原点 = 光标+8 的屏幕位置），历史上根卡「进屏」全靠 C++ `RevealStack`/`Reveal` 的右/下边 clamp（`hibiki/windows/runner/global_lookup_window.cpp:377-382`）滑动整个窗口兜底；BUG-670 的 reserve-to-edge 地板（`global_lookup_layout.dart` `computeCascadeHeadroomSeed` + `global_lookup_controller.dart` `_originFloorLeft/Top`）把窗口原点钉死在工作区左上角、宽高夹到工作区尺寸后，这两个 clamp 恒为 no-op（正是该修复的「绝无失配」证明），根卡失去唯一 fit-to-screen 机制。触发几何：`cursorWork.x + popupMaxWidth×uiScale > workW`（光标距右边 < 卡宽）或 `cursorWork.y + 内容高 > workH`（光标距底 < 卡高，默认 400×360）→ 根卡越出工作区的部分被窗口右/下边（= 工作区边）整条裁掉；右下角极端情形几乎整卡不可见（「弹窗直接生成在窗口外面」）。上一轮验收口径恰是「被查词靠屏右/下」，用户即在该几何撞上回归。
- **[x] ① 已修复** — 消除特殊情况：根卡与级联子卡同规则在 Dart 布局域钳进工作区。新增纯函数 `computeRootShellOffset`（`global_lookup_layout.dart`，单轴 `clampLikeIos(cursorWork, 0, screenWork - cardDim) - cursorWork`），`buildStackRenderScript` 算一次并作为 `_frameRectMap` anchorless 分支的基底（`global_lookup_render.dart`）。不变量：偏移恒 >= -cursorWork = reserve-to-edge 地板 → union-bbox 原点仍从首帧冻结，BUG-670「父卡任意层级零位移」不回退；根卡 local 为负时首帧走 v3 reveal-ready 门（held 到 commitLayerShift），不会先裁后跳；空间充足 / 无工作区上报 → 偏移 0 逐字节等于旧几何。host.js / C++ 零改动。提交：13b5f3342（分支 todo1231-popup-offscreen）。
- **[x] ② 已加自动化测试** — `hibiki/test/lookup/global_lookup_layout_test.dart`：`TODO-1231 computeRootShellOffset` 组（右边缘/底边缘/右下角验收几何/卡大于工作区/无工作区/负 cursorWork 左侧任务栏/越界 cursorWork + 全工作区扫掠不变量：偏移 >= 地板且钳后根卡完整在工作区内）+ `TODO-1231 root clamp render wiring guard` source guard（有人把 anchorless 分支改回恒 (0,0) 或断开 rootShellOffset 接线即转红）。
- **备注**：与 TODO-1345（「第二个弹窗出现导致第一个弹窗位置变动」，blocked）同属覆盖窗 origin/pin 体系但机理不同：1345 是子卡出现时 origin 外移的跨 DWM/WebView2 一帧位移（已由地板根治），本 bug 是地板让 C++ 窗口 clamp 失效后暴露的「根卡从未被布局域钳位」旧债。本修复不动地板与 origin 冻结语义，1345 的修复不受影响。
