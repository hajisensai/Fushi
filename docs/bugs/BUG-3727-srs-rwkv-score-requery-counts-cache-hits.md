## BUG-3727 · RWKV 分数表「每 50 次」刷新数的是部分命中的查询，不是作答
- **报告**：2026-10-23（来源：审查记录 HBK-AUDIT-019，`2026-10-23-rwkv-score-refresh-review.md`）
- **现象**：RWKV-Instant 排队用常驻分数表缓存每张候选卡的回忆率 R。答完一张卡后，其余卡的 R 会因共享状态（牌组 / 预设 / 全局流、今日复习数）变化而改变，但它们继续沿用旧分数。旧分数要等「50 次增量或 30 分钟」才整表刷新，而这个计数在一些作答路径上永远到不了 50。
- **真实性**：✅ 真 bug（代码路径确认，测试复现）。根因：`packages/fushi_engine/lib/srs/srs_rwkv_service.dart` 的 `instantRetrievability` 只在一次查询「既有命中又有缺失」（`missing.length < cards.length`）时 `_patchesSinceRequery++`。下面两种情况都不计数，模型推进再多次，别的牌组的旧分数也不刷新：
  - 全部缺失（同笔记候选全被作废）；
  - 连续直接评分、中间不排队。
  阈值 50 和 30 分钟都写死，没有依据。
- **[x] ① 已修复**：
  - `70c8ad022c`：计数改为模型状态真正推进的次数，在 `_appendNew` 里追加的评分与撤回各算一次，本机与同步来的都算。
  - 后续提交（用户 2026-10-23 拍板「上游默认就是 1，那就 1」）：
    - 阈值改成牌组设置「每答几题刷新一次 RWKV 队列」：`SrsRwkvQueueSettings.refreshEvery`，默认 1，范围 1–10000，对齐上游「Update the RWKV queue every」，在牌组设置的 RWKV 排队区可调。一次排队涉及多个牌组时取最小值。
    - 按次数触发的整表重查放到后台：本次排队先用现有分数（作答卡与同笔记卡已按最新状态补算），出完这张再在 worker 里重查，下一次排队生效。
    - 换日、牌组设置、同步合并、满 30 分钟仍当场重查，这几种情况旧分数可能整体失效。
- **实测**：`srs_rwkv_answer_bench_test`，6000 笔记 / 1.2 万候选卡，真模型 int4，测「作答 → 计数 → 出下一张」：

  | 方式 | 耗时 |
  |---|---|
  | 不整表重查 | 82–135 ms |
  | 每题同步整表重查 | 288–334 ms |
  | 每题后台重查，每题之间留 1 s 看卡时间 | 87–107 ms（第一题 142 ms） |
  | 每题后台重查，连续零间隔答题（后台重查排在下一次作答前面） | 128–203 ms |

- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/srs_rwkv_service_test.dart`「分数表整表重查按模型状态推进次数」组：
  - 默认每题后台重查、下一题起用新分数；
  - 牌组设置改了下一次排队按新值数；
  - N=3 时连续直接评分照样数满，撤回也算一次。

  变异实测：去掉计数后两条变红。
- **备注**：BUG-3718（原 50 次 / 30 分钟是为了躲开每题全量重算）的性能目标靠「后台、下一题生效」保住了。
