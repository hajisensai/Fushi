## BUG-2836 · 模型下载在劣化或卡死的连接上龟速或停住
- **报告**：2026-10-01（用户：截图）漫画 OCR 设置页下载 manga-ocr（NVIDIA GPU 加速）3.7 GB，「进度这么慢还中途自己停了」。
- **真实性**：✅ 真 bug。现场取证：`<数据根>/support/ocr_models/manga-cuda/torch-2.8.0+cu128-cp311-cp311-win_amd64.whl.part` 自 14:22 起 3 小时只到 222 MB，实测增长 50–93 KB/s；同一时刻同一代理（127.0.0.1:34151）新开连接 curl 10.8 MB/s、Dart `HttpClient` 带 Range 续传同一文件 11 MB/s——带宽、代理、Dart 栈都正常，坏的是 app 手上那一条用了几小时的长连接（代理出口劣化）。根因在共享下载器 `fushi_asr_core` 的 `ModelFileDownloader`（上游 hajisensai/fushi-subtitles `packages/asr_core/lib/src/onnx/model_file_downloader.dart`，旧钉版 `2168e85`）：`_downloadFileFrom` 的 `await for (chunk in response)` 无空闲超时（卡死即永远停着）、无吞吐感知（只能耗在坏连接上）、任何中途传输错误整条失败（用户只能手动「取消 → 继续」换连接）。另：用户跑的安装版 2.9.0-debug.16533 早于 `e65c31ad26`，离开设置页会取消下载（已由该提交修复，不在本条范围）。
- **[x] ① 已修复** — 上游 hajisensai/fushi-subtitles#20（合并 `308e236`）：`ModelDownloadResilience`——卡死（等头 / 两次数据间 >30s）、劣化（15s 测速窗 < 本次 downloadAll 最好窗口的 1/10；无参照时每文件试探换一次）、瞬时错误（IOException / 5xx / 429）均断开当前连接、从 `.part` 长度 Range 续传；只有无进度的重连计失败（4 次、指数退避）→ 换镜像 → 抛真实错误；404 等确定性错误照旧立即失败；状态错误改 `ModelDownloadStatusException extends HttpException`。本仓七处 git 依赖与 `ci/patches/git/fushi-subtitles-<sha>/` 目录钉到 `308e236`（两 sha 间上游只改了下载器两文件，补丁原样沿用）。`fushi/lib/src/media/manga/ocr/manga_ocr_model_downloads.dart` 下载失败补写 `ErrorLogService`（此前只弹 toast，事后日志为空）。
- **[x] ② 已加自动化测试** — 上游 `packages/asr_core/test/onnx/model_file_downloader_test.dart` 6 例（卡死续传 / 断线续传 / 劣化换连接 / 无参照只试探一次 / 503 重试 / 失败预算 + 404 不重试），变异实测：去掉劣化抛出 → 2 例红、去掉重试 → 6 例全红；本仓 `fushi/test/ocr/manga_ocr_model_downloader_test.dart` 等既有 46 例在新钉版下照绿。
