## BUG-1775 · 带clip的ASS事件按容器基线定位与帧空间裁剪几何脱节
- **报告**：2026-08-22（用户：截图，神稲ぼたん S01E08 外挂 .ja.ass，OP 1:04 处同句歌词拆成两处错位片段、底部片段字形被拦腰裁半）
- **真实性**：✅ 真 bug。片源真值：同句歌词由左右分屏两条 Dialogue 拼成（layer0 `{\blur4\clip(0,920,960,1080)}` + layer1 `{\blur4\clip(960,920,1920,1080)}`，样式 OP_JP/OP_JP2 均 \an2、MarginV 5/12）。mpv/libass 里排版与裁剪同在帧空间，两层同位叠画、左右 clip 无缝拼成一行。Hibiki 里 `\clip` 映射在 fit:contain 视频内容矩形（`_AssClipClipper`，`fushi/lib/src/media/video/video_subtitle_overlay.dart`），而无 \pos 的 cue 却按「用户 bottomPadding + 控制条避让」定位在**容器**坐标（`_paddingFor` / `_anchoredPadded`），且两条被 `_positionKey` 按 Layer 拆成两组后各自带独立 padding/避让动画状态——两套几何脱节：两半错位断开，clip 竖向边带把字形拦腰裁半。根因 `video_subtitle_overlay.dart` 的 `_positionCueGroup` 无 \pos 分支（修复前 ~1450-1487）不区分「带帧空间裁剪的事件」。
- **[x] ① 已修复** — 带静态 `\clip` 的无 \pos/\move cue 改按 libass 排版语义在帧空间合成锚点（`resolveClipCueAnchorFraction`：水平 左=MarginL/居中=帧中心+(L-R)/2/右=1-MarginR；竖直 顶=MarginV/中=0.5/底=1-MarginV），经 `mapPosFractionToContainer` 走与 \pos 相同的 `_absolutePositioned` 绝对定位（不做控制条 dodge——clip 窗固定在帧上，位移只会把文本推出窗）；`_positionKey` 把 clip 值指纹纳入键（不同裁剪窗绝不同组进 Column），`_mergeBottomBaselineGroups` 不再把 clip cue 折进底部基线桶；`_clipGroup` 的组内同裁剪判据从 identity 放宽到值指纹（`clipGroupFingerprint`）。提交见本分支。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_subtitle_clip_frame_anchor_test.dart`：纯函数钉 libass 锚点语义（\an2/\an8/\an5、Margin L/R/V、缺 PlayRes 兜底）+ 值指纹；widget 测试复现 E08 左右分屏形状（同文本异 clip 两层同位叠画、锚帧底缘不落用户基线、控制条可见不避让、视频未解码回退不炸）。
- **备注**：`respectAssStyle=false`（纯字幕模式）与 srt/vtt/无 clip ASS 路径零变化。带 \pos 的 clip cue 仍走原 \pos 分支（\pos 本就是帧空间，几何一致）。
