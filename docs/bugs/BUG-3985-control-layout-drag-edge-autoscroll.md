## BUG-3985 · control-layout-drag-edge-autoscroll
- **报告**：2026-11-02（用户：应用内反馈 Wn1SZdlyhl，Android 384x853）——手机上编辑视频控件布局，按钮往下 / 往上拖时画面不滚，靠下的槽位拖不到。
- **真实性**：✅ 真 bug。`fushi/lib/src/media/video/video_control_layout_edit_overlay.dart` 紧凑布局（:93-96 判定）把调色板固定在顶部、全部槽位放进一个 `SingleChildScrollView`（原 :228-249），横屏槽位视口只剩一百多像素；chip 是 `Draggable`（原 :545），拿起后指针被拖拽手势独占，滚动视口收不到手势，而全仓没有任何拖拽边缘自动滚动。设置页里的编辑器同构：`fushi/lib/src/controls/control_layout_editor.dart`（视频设置 / 沉浸 / 遥控按钮编辑器，嵌在设置 ListView 里，`_buildDraggableChip` 原 :1094-1125）以及**另外三份独立实现**（triage 说它们共用 ControlLayoutEditor，实际不是）：`reader/reader_control_layout_editor.dart`、`media/manga/reader/manga_control_layout_editor.dart`、`media/audiobook/lyrics_player/lyrics_control_layout_editor.dart`。
- **[x] ① 已修复** — 新共用组件 `fushi/lib/src/controls/drag_auto_scroll_region.dart`（`DragAutoScrollRegion` + `DragAutoScrollTarget`）：把 Draggable 的 `onDragUpdate` 指针位置接到 Flutter 自带的 `EdgeDraggingAutoScroller`，挑「包含指针、指针在边缘带、该方向还能滚」的视口（内层优先，再看区外竖向祖先如设置页 ListView），每走一步按指针当前位置重报矩形（否则只滚出边缘带几十像素就停——测试实测到的坑），拖拽结束 / 取消 / 指针抬起停止。五个编辑器全部接入。视频覆盖层紧凑布局另加横屏并排版式（宽 ≥600 且宽 > 高：调色板左侧整高一列、槽位右侧独立滚动），不再把槽位视口压到一百多像素。
- **[x] ② 已加自动化测试** — `fushi/test/controls/drag_auto_scroll_region_test.dart`：853x384 下用真实指针手势从调色板拖到槽位视口底边，断言视口自动滚、原本视口外的槽位滚进来并能落位、松手后停止；阅读器（独立实现）与视频设置（ControlLayoutEditor）嵌在 ListView 里拖到顶边断言外层列表回滚并在松手后停止。
- **备注**：Flutter 的 Draggable 只在指针移动时重新命中 DragTarget：自动滚动后手指完全不动直接松手，落点按最后一次移动时的目标算（框架限制）。未在真机复测。
