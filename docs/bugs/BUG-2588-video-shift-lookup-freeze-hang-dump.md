## BUG-2588 · 视频页 Shift 悬停换词到无词条字位时热槽 WebView 被同步拆掉（用户报整机卡死）+ 卡死零证据
- **报告**：2026-09-18（用户转述终端用户：Windows 看番，字幕 Shift 悬停查词「状況」已弹出，随后卡死、只能强杀；重启后错误日志只有一条 `Lookup.crashRecovered … 查词栈深度=1，栈顶词=「況に 一致しなくもないですね」`。报告人没有 dump、非本机，无法取证）
- **真实性**：✅ 真 bug（两条独立缺口叠加；卡死本体的 native 崩点**未 dump 坐实**，本条不断言已根治）。
  - **证据推理**：截图里字幕高亮仍是「状況」（`_lookupAt` 返回后才 `_rebuild` 高亮）、弹窗仍是「状況」的旧结果，但面包屑已记下从第二字「況」起的新词 → 用户按住 Shift 把鼠标右移一格触发**换词**（`_handleSubtitleHoverLookup` → `_lookupAt` → `pushNestedPopup(replaceStack: true, reuseWarmSlot: true)`），且卡死发生在换词后**第一帧之前 / 之中**。换词时 `DictionaryPopupController.beginTop(reuseWarmSlot)` 先把热槽置 `visible=false` → 面包屑被**删掉**（`error_log_service.dart` `markLookupStackDepth(0)`）；非空结果要等 `popupRendered`（或 1.8 s 兜底）才重新写；**唯一能在没画任何一帧的前提下写出新词面包屑的路径是空结果**：`dictionary_page_mixin.dart` 空结果分支立即 `controller.show(entry)` → `visible=true` → 面包屑同步写入。「況」单独作词头在报告人的词典集里没有条目完全合理（本机 62 本里也只有 5 条）。
  - **根因 ①（Dart，`fushi/lib/src/pages/implementations/dictionary_popup_layer.dart:1237-1262` 修前）**：`_buildBody` 只对 seed 空结果（`searchTerm.isEmpty`）保留热槽 WebView，**真实空结果**落到 Flutter「未找到」占位、把带 GlobalKey 的热槽 `DictionaryPopupWebView` 整个 unmount。下一帧 → `DictionaryPopupWebViewState.dispose` → fork `custom_platform_view.dart` `dispose()` → 原生 `in_app_webview_manager.cpp` `webViews.erase` → `~CustomPlatformView`（`texture_bridge_->Stop()` / `UnregisterTexture`）→ `~InAppWebView`（`webViewController->Close()` + `DestroyWindow`），全部在平台线程（= Dart UI 线程）**同步**执行，而此刻上一词的 `Runtime.evaluate`（`_pushResults` 未 await）可能还在 browser 进程里飞、60 Hz WGC 泵 `DispatcherQueueTimer` 仍在 Tick。`Close()` 是到 browser 进程的同步 IPC；本机 `wgc_capture.log` 已抓到一次换词缩高时平台线程在 WebView2 尺寸调用里停 196 ms（其余同类 1 ms）。这条路径与「按住 Shift 扫过字幕」的高频换词叠在一起，是目前唯一同时满足全部证据的卡死候选。即便不是卡死根因，它也**违反热槽契约**（BUG-092/BUG-094：热槽 WebView 活到 entry 生命周期结束）——每次空结果都把预热丢掉，下一次查词退化为冷建 WebView2。这一收窄来自 `17e822c9d04`（fix(mac): 别露出热槽空白壳），原始 BUG-092 挂载条件正是 `hasEntries || isSearching || keepWebViewWarm`。
  - **根因 ②（取证缺口，`fushi/windows/runner/crash_dump.cpp` + `error_log_service.dart:260-270` 修前）**：卡死不是崩溃——没有异常、`SetUnhandledExceptionFilter` 不触发、WER 不留 dump；查词面包屑下次启动只能报 `Lookup.crashRecovered` 且文案硬说成「native 崩溃、推断同 603-B」，既分不清崩溃与卡死，更看不到主线程当时卡在哪个 native 帧。BUG-2572（同家族：Windows 视频页键鼠失灵、小内存模式=不常驻热槽可规避）两轮离屏探针都没复现、报告人拿不出任何二进制证据，根因悬置至今。
  - **已排除**：① C++ 词典引擎对这串输入死循环——装机版 `fushidicts_ffi.dll` + 62 本真词典对该字幕**每个字位起**的查询全部正常返回（`況に…` 29 ms，最慢 `しなく` 1.7 s，同步 FFI 卡顿但不是卡死）；② Dart 侧 `pushNestedPopup` 链上没有会死等的 await（唯一 await 是同步 FFI），TTS/WebView 音频的 Completer 都有 5 s 超时；③ fork Windows C++ 侧没有任何显式跨线程同步等待（`SendMessage`/`WaitForSingleObject`/自旋 0 命中），唯一的锁是 `TextureBridge::mutex_`；runner 的低级鼠标钩子只 `PostMessage`、in-app 热槽弹窗根本不走它。
- **[x] ① 已修复** —
  - **①-a 热槽不拆**：`dictionary_popup_layer.dart` `_buildBody` 挂载条件恢复为 `hasRenderableResults || isSearching || keepWebViewWarm`；真实空结果（`isRealEmptyResult`）在热槽上改为不透明「未找到」盖板叠在 WebView 之上（与「搜索中」进度盖板同一手法，`ColoredBox` 命中行为 opaque），非热槽层仍渲染同一占位、不挂 WebView（行为不变）。Mac 那次「别露出空白壳」的诉求由盖板满足。
  - **①-b 主线程停泵看门狗（Windows）**：`fushi/windows/runner/hang_watchdog.{h,cpp}`（新）——旁路线程每秒 `IsHungAppWindow(主窗口)`，连续 ≥10 s（叠加系统自身 5 s 门槛）且无调试器时，从旁路线程 `WriteProcessMinidump(L"hang", 主线程 id, nullptr, …)` 抓全线程栈 minidump 到与崩溃 dump 同一目录（`crashdumps\hang-<pid>-<tick>.dmp`，诊断区「崩溃转储」页自动列出、可分享），并往同目录 `hang_watchdog.log` 追加「时间、卡了多久、dump 路径」；每进程最多一次。`crash_dump.cpp` 把 dump 写出抽成公共 `WriteProcessMinidump` / `ResolveCrashDumpDirectory`，崩溃 filter 与看门狗共用一条零堆分配路径（hang dump 不传 exception stream）。`main.cpp` 在 `CreateAndShow` 后启动、消息循环退出后停止；`CMakeLists.txt` 加源文件。
