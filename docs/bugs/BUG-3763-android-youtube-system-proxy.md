## BUG-3763 · Android 上 YouTube「用 Fushi 播放」报无法获取视频流（Dart 出站没走 Wi-Fi 系统代理）
- **报告**：2026-10-24（用户：浏览器 YouTube 观看页点「用 Fushi 播放」，Android 真机报「视频加载失败（无法获取视频流）」，错误日志里没原因）
- **真实性**：✅ 真 bug，且**不是浏览器入口特有**：浏览器入口与「视频库 › 粘贴 YouTube 网址」走同一条 `buildStreamVideoLaunch` → `resolveYoutubeSource`（`fushi/lib/src/media/video/stream_video_launch.dart`）。根因两层：
  1. **出口**：真机 43f8ed58 的 Wi-Fi 配了 HTTP 代理 `192.168.1.88:7890`（`dumpsys connectivity` 的 `HttpProxy`），本地 DNS 把 www.youtube.com 解析到不可达地址。`adb shell curl https://www.youtube.com/sw.js_data` 直连 `(28) Connection timed out`，`-x http://192.168.1.88:7890` 回 200。WebView 走系统代理所以网页能播；Dart `HttpClient` 不认 Android 系统代理，而出站代理层自动模式的系统代理读取 `resolveSystemProxyEnvironment`（`packages/fushi_engine/lib/utils/net/app_proxy.dart`）只覆盖 Windows / macOS / Linux，Android 恒为空 → DIRECT → 兜底链 5 个 client 各自 13 s 超时。同一台机器上 Windows 主机直连解析 `dQw4w9WgXcQ` 4 个 client 正常出流（只有 TVHTML5 unplayable），排除了 YouTube 风控 / 签名过期。
  2. **报错吞原因**：`_getManifestWithClientFallback` 把逐 client 失败拼成一句 `StateError('youtube manifest failed for all clients …')`，丢了异常类型；`VideoFushiPage._describeLoadFailure` 的子串判据见到 `manifest failed` 就报「视频不可用」（超时文本是 `TimeoutException after …`，不含 `timed out`，网络判据接不住）；而且起播失败的两个 catch（stream book launch build、remote episode load）只 `debugPrint`，不进错误日志。
- **[x] ① 已修复** — Android 新增 `SystemProxyChannel.java`（`ConnectivityManager.getDefaultProxy()`，回退 JVM `http.proxyHost`），主 engine 与 :popup 副 engine 都注册；Dart 门面 `fushi/lib/src/utils/net/android_system_proxy.dart`，`installAppNetworkBindings` 在 prime 前装进引擎新增的 `installPlatformSystemProxyReader`；纯函数 `androidSystemProxyEnvironment` 把 host/port/exclusionList 换成 environment。YouTube 兜底链全败改抛 `YoutubeManifestException`（逐 client 保留原始异常，`isTransportFailure` 判出口问题），播放页据此报「网络错误」而非「视频不可用」；两个起播 catch 改为 `ErrorLogService.log` 带堆栈。
- **[x] ② 已加自动化测试** — `fushi/test/utils/net/android_system_proxy_test.dart`（纯函数 + mock 平台通道 + `resolveAppProxyDirective` 走代理 / 排除项直连）、`fushi/test/media/video/youtube_manifest_failure_reason_test.dart`（SocketException / 超时判传输层、unplayable 不判、逐 client 原因带异常类型）；`youtube_watch_page_independence_test.dart` 两处断言跟随新异常类型。
- **备注**：真机复测（43f8ed58，测试包 `.webtest2` 已卸载）：浏览器 → `youtube.com/watch?v=dQw4w9WgXcQ`（跳到 m.youtube.com）→「用 Fushi 播放」→ mpv 起播 1080p、日文字幕轨自动上屏，播过 1:30 无中继 403。Windows 同一入口走视频页网页档（YouTube 网页播放器），正常播放，不经本修复的解析链。iOS 未接系统代理读取（无通道，行为与改前一致）；PAC 模式下 Android 的 `getDefaultProxy()` 给的是系统本地 PAC 代理端口，未实机验证。
