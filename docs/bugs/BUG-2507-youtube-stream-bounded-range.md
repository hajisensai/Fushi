## BUG-2507 · YouTube 直连流只接受有界 Range，libmpv/ffmpeg 无 Range 首请求 403 → 打不开
- **报告**：2026-09-12（用户：「添加youtube视频无法打开」）
- **真实性**：✅ 真 bug。真机复现：`integration_test/youtube_stream_playback_itest.dart`（FUSHI_YT_LIVE_ITEST=1，Windows 离屏 runner）解析成功后 libmpv 90 s 内 duration=0 / position=0，mpv 日志 `[curl] HTTP error 403` → `Failed to open <googlevideo>`。根因链：
  - youtube_explode 2.5.3 现在能签出流的只剩 `android` client（androidVr / tv 被 YouTube 判 unplayable、ios 首流 403），其 googlevideo 直链 query 带 `rqh=1`，**只接受有界区间** `Range: bytes=a-b`——同一 URL 同一 UA：`bytes=0-65535` → 206，无 `Range` → 403，开放区间 `bytes=0-` → 403（host 探针，UA 无关）。
  - libmpv 的 curl 后端首请求发 `bytes=0-`（`video_player_controller.dart:1628` 之后的 `player.open`），ffmpeg 制卡同样开放区间 → 一个字节都拿不到。解析阶段看不出：youtube_explode 的首流探测是 HEAD（不受此限），`youtube_stream_cache.dart` 的 liveness 用 `bytes=0-1` 有界探测。
  - 消费端：`fushi/lib/src/media/video/url_stream_video.dart` `UrlStreamVideoClient.remoteVideoStreamUrls`（播放页取流唯一出口）、`video_fushi/quality.part.dart` `_switchYoutubeVariant`、`mining/youtube_clip_miner.dart` `buildRequest`（ffmpeg）。
  - Windows 上 YouTube 分流到内置网页播放器（`web_video_bridge.dart` `shouldOpenInWebVideoPlayer`）不经此路，故桌面正常、**移动端 / 作品页预告片 / Windows mpv 路径全挂**。
- **[x] ① 已修复** — 新增本地有界分块中继 `fushi/lib/src/media/video/youtube_range_relay.dart`（`YoutubeRangeRelay`）：googlevideo 直链在交给播放内核 / ffmpeg 前换成 `http://127.0.0.1:<port>/yt/<token>`，内核任意 Range（无 / `bytes=X-` / `bytes=a-b`）翻成对上游的 2 MiB 有界分块顺序拉取（googlevideo 单区间 4 MiB 过、5 MiB 起 403，留余量），拼成带 `Content-Length` / `Content-Range` / `Accept-Ranges` 的响应，seek 天然支持；上游首块非 206 原样透传状态码。三处消费端接线；`YoutubeStreamCache` / liveness 继续持原始 URL。修后同一 itest：duration=564200、位置前进、全绿。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/youtube_range_relay_test.dart`：假 googlevideo（无 Range / 开放区间 403、有界 206 且单块封顶）下验证整流 / seek / 闭区间 / HEAD / 404 / 上游 403 透传，并断言上游全程只收到有界区间；`UrlStreamVideoClient.remoteVideoStreamUrls` 三条 googlevideo 流经中继换址、非 googlevideo 原样。真机：`integration_test/youtube_stream_playback_itest.dart`（既有，修前红修后绿）+ 新增 `integration_test/youtube_import_open_itest.dart`（导入 → 落库 → 网页播放器出标题）。
- **备注**：另有一层**不在本 bug 范围**的 YouTube 服务端限制：出口 IP 被 YouTube 判「Sign in to confirm you're not a bot」时（本机 Clash 出口即如此，`tv` / `android_vr` 的 player 响应直接 LOGIN_REQUIRED），所有无 PO token 的 client（android / ios / androidVr）签出的流只放**前 ~50 秒媒体**的字节区间，之后任何区间 403（同一 URL：`64K@0` 206、`64K@50%` 403；短于 50 s 的视频与未被标记的出口不受影响，`dQw4w9WgXcQ` 在 `android` 下全文件可拉）。这需要 BotGuard 生成 GVS PO token（yt-dlp PO-Token-Guide），youtube_explode 不支持，分块中继解不了；中继在中途撞到 403 会落 `error_log`（source `youtube_relay`）说明原因。桌面走网页播放器不受影响。
