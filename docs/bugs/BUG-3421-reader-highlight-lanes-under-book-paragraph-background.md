## BUG-3421 · 书自带段落底色盖住高亮窄条
- **报告**：2026-10-15（来源：PR #2203 合入后审查）
- **真实性**：✅ 真 bug。PR #2203 把所有高亮改由窄条层 `window.__fushiLanes` 画：`fushi/lib/src/reader/reader_selection_scripts.dart:630`（文件头说明）一个 body 下的 `fushi-hl-lanes`，CSS 在 `fushi/lib/src/reader/reader_content_styles.dart:975`（`z-index: -1`，body 用 `isolation: isolate` 当层叠上下文）。按 CSS 2.1 附录 E 的绘制顺序，同一层叠上下文里 z-index 为负的子层先画、随后才画流内块级后代的背景，所以书里 `p { background-color }` 之类的段落 / 块底色整片盖在窄条上——有声书当前句、查词、收藏、搜索在这种段落里全看不见。真 Chrome 截图实测（撤掉修复）：窄条范围里 59–73% 像素是裸段落底色。
- **[x] ① 已修复** — 待提交。窄条层按文本所在的「自带底色的最近祖先」分层（`reader_selection_scripts.dart` 的 `backdropOf` / `layerFor` / `pruneBackdrops`）：这种元素标 `data-fushi-hl-backdrop`，CSS 给 `isolation: isolate`（`reader_content_styles.dart` 新规则，自成层叠上下文、不改包含块与几何），在它末尾挂一个同样 `z-index:-1` 的 `fushi-hl-lanes`，于是窄条画在它的底色之上、它的字之下；底色元素不能挂层（ruby 内部、表格行 / 行组 / 列、`display: contents`）时挂到它下面最近的可挂元素。高亮撤掉后空层与标记一并撤。书的底色本身一律不动，不用 `!important` 去背景。几何（1em、居中、按行并条）沿用原逻辑，每层按自己的 `getBoundingClientRect` 取原点。
- **[x] ② 已加自动化测试** — `fushi/test/reader/highlight_lanes_test.dart` + `highlight_lanes_harness.mjs`：新增 6 张「带书底色」页（竖排 / 横排 × 分页 / 连续 / VN），真 Chrome 跑生产 CSS + 引擎 shell，断言段落被标记且 isolate、窄条在段落自己的层里、几何仍盖住文字，并对每条窄条真截图取像素：裸段落底色 ≤5%、字墨 ≥3%（字压在窄条上）；撤高亮后层与标记消失。`tool/reader_pitch_headless/cdp_client.mjs` 加 `evalHere` / `capture`（按 layout viewport 偏移把 client 坐标换成文档坐标——竖排文档比视口宽时两者差 22px）。变异实测：CSS 规则改成 `isolation: auto` → 6 种模式全部「lane is hidden under the book background」变红；`backdropOf` 短路成 null（等于修复前）→ 结构与像素断言全红；改回全绿。
- **备注**：已知缺口——**行内元素**（`display: inline`，如 `<span style="background">`）的底色压不住：Chromium 把行内盒的底色随行内容一起画，给它 `isolation` / `position+z-index` / `opacity` 都一样（单独探针实测 0% 窄条像素）。这种元素不挂层，里面的字归最近的块级底色层或 body 层，窄条在行内底色那一段仍被盖住；harness 只钉住「不给行内元素挂层」。WebKit（iOS / macOS WKWebView）未实测。在书 DOM 里插入层元素会影响书 CSS 的 `:last-child` 类选择器（只在高亮落在带底色元素里时插，用完即撤）。
