## BUG-2159 · 网飞扩展批量制卡期间扬声器出声
- **报告**：2026-09-05（用户：「浏览器的插件 Netflix 的，我想在“制卡”的时候不给用户播放声音」）
- **真实性**：✅ 真 bug — 根因 `tools/browser-extension/offscreen.js:45-49`（镜像 `fushi/assets/browser_extension/offscreen.js` 同源）。`chrome.tabCapture` 拿到带音轨的流后，标签页音频**已被 Chrome 改道进流、默认不对用户放音**；旧实现在 `startCapture` 里 `new AudioContext()` + `createMediaStreamSource(stream).connect(destination)` 把流**特意接回扬声器**（注释「回放时仍能听到」，TODO-1000 初版 `061da98777` 自带的设计，不是修 bug 加的）。而批量回放期间 `content.js` 的 `fushiRunNetflixBatch` 已藏字幕/控制条/光标（`content.js:606-627`），用户不是在看片——那段声音只是把整集台词对着房间放，且没有任何链路依赖它（录制走流里的音轨，与扬声器无关）。
- **[x] ① 已修复** — 提交 `<待填>`。删掉 `audioPlaybackCtx` 及其三处引用（接回 + 两处 `close()`）。录制不变：仍向 tabCapture 请求 `audio` 轨，MediaRecorder 照录；`stopCapture` 停轨后 Chrome 自动把标签页音频还给扬声器（批量结束/取消/跨集导航都会 stopCapture，`content.js:883/912`、`background.js:457`），用户看片声音不受影响。`node tools/browser-extension/scripts/sync-mirrors.mjs` 同步镜像。
- **[x] ② 已加自动化测试** — `fushi/test/mining/netflix_mining_robustness_guard_test.dart`「BUG-2159 offscreen … 录制期间不把 tabCapture 流接回扬声器」（两份镜像各一条）：正向断言 `startCapture` 仍请求 tab 音轨（静音不是靠丢音轨实现的），反向断言源码不再含 `createMediaStreamSource` / `.destination` / `audioPlaybackCtx`。
- **备注**：另一条「fushi 内嵌 WebView2 网页播放器制卡」（`web_mine_replay.dart`）走 WASAPI **端点** loopback 录扬声器混音，静音与录音在那条链路上不可分离，本 bug 不覆盖；要做需换进程级 loopback（`AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK`），另开任务。
