## BUG-4909 · 卡片片段回看下 Jellyfin/Emby 转码会话不释放
- **报告**：2026-11-20（来源：路线图 #3722 c31 的 video-11，代码审读复核成立）
- **真实性**：✅ 真 bug。根因（基准 `origin/develop@7745effa2e`）：卡片片段回看（BUG-3490）直接串流，取流时 `PlaybackInfo` 照常协商出会话（转码时服务器起 ffmpeg）；回看中退出 / 换集时 `fushi/lib/src/pages/implementations/video_fushi_page.dart:5763` `_reportRemotePlaybackStopped` 先 `if (_sourceReviewActive) return;`，`fushi/lib/src/media/video/source_review_remote_report_gate.dart:77` 闸门的 `stop` 回看中也直接返回 false。Jellyfin 的转码 ffmpeg 只在客户端 `DELETE /Videos/ActiveEncodings` 时才停（`fushi/lib/src/sync/jellyfin_video_client.dart:3876-3893` 只在 Stopped 之后做），于是回看那一程的转码在服务器上空转到它自己的超时；会话登记也一直留在客户端 `_sessions` 里。
- **[x] ① 已修复** — 新增可选能力 `RemoteVideoPlaybackDetach`（`fushi/lib/src/sync/remote_video_client.dart`），`JellyfinVideoClient.detachRemoteVideoPlayback` 与停止上报共用「先进先出摘最早会话 + 转码会话停 ActiveEncodings」，但不发 `/Sessions/Playing/Stopped`；闸门 `stop` 的回看分支对支持该能力的来源调它，仍返回 false、不发任何会改进度的上报；页面的停止上报不再在回看中提前返回，交给闸门判。提交 `6e3b58612c`（分支 `pr/video-page-load-failures`）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/source_review_remote_report_gate_test.dart`（回看中停止只摘会话、非回看照常 Stopped）；`fushi/test/sync/jellyfin_playback_negotiation_test.dart`（转码会话 detach 发 DELETE ActiveEncodings 且无任何 `/Sessions/` 请求、直播放 detach 不发请求只出队）；`fushi/test/pages/card_source_media_review_guard_test.dart` 守卫页面停止上报只经闸门、不在回看中提前返回。
- **备注**：计划要求的「真 Emby docker 回看一段转码内容后看服务器转码会话」没做（本轮所有者定不做设备 / 服务器实测）。Plex 回看的 transcode session 是否同样空转没有核实，未纳入。
