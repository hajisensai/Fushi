## BUG-4222 · Windows 自动更新后又弹「上次意外退出」闪退报告提示（旧的待报没人答就每次启动重问）
- **报告**：2026-11-07（应用内反馈 dCYn9_hix-，开发者自提，Windows 3.3.0-debug.24478：「自动更新的时候又弹错误退出提醒了，说要给开发者」）
- **真实性**：✅ 真 bug，但不在更新交接路径上。更新交接本身已正确处理：`fushi/lib/src/utils/misc/platform_updater.dart` 交接前 `AppExitCoordinator.begin('updateHandoff')` 落盘退出意图、`terminate('updateHandoff')` 标 clean（81aa1c223b）。反馈日志里 2026-11-07 12:31 更新后的那次运行**没有任何** `Process.previousExit*` 条目（错误段与诊断段都没有），即那次更新退出没有产生新判定。真正弹出的是旧待报：2026-11-06 14:58 那次启动记了一条真实的 `Process.previousExitUnclean`（v23866 停在前台时没了），30 秒后用户就点了更新（14:58:54 handoff）。首页提示条 15 秒自己收起、用户没选「发送」也没选「不用了」，这条待报就一直留在 `crash_report_state.json`：只有 `decline()`（`fushi/lib/src/feedback/crash_report.dart` 旧 `:477`）与 `submit()` 会清 `pending`，`currentOffer()` 每次启动都把它重新拿出来，`offerCrashReportAfterStartup`（`fushi/lib/src/pages/implementations/feedback/crash_report_prompt.dart` 旧 `:281`）于是每次启动都弹「Fushi 上次意外退出了」。用户只在自动更新时重启 app，看起来就是「每次更新都弹」，而提示里的「上次」其实是一次正常的更新交接。启动前卡片（`runCrashReportStartupGate`）停在卡片上被关掉也是同一个缺口。
- **[x] ① 已修复** — `CrashReportState.asked` 记下已经摆到用户面前的那批待报（`CrashReporter.markOfferShown`，`crash_report.dart:433`；首页提示条 `crash_report_prompt.dart:284`、启动前卡片 `:426` 显示时调用）；下次 `attach()`（`_dropAskedLastSession`，`crash_report.dart:410`，先于本次 `recordVerdict`）把问过没回答的那几次作废。用户点过「发送」的那批（`inFlight`）不受影响、照常重试；合并窗口里攒着、没给用户看过的待报也不受影响。
- **[x] ② 已加自动化测试** — `fushi/test/feedback/crash_report_test.dart` 组「问过没回答的待报不重问」：真 `offerCrashReportAfterStartup` 弹出提示条后不作答 → 下次 attach 无报告；启动前卡片没选就被杀 → 下次只剩新判出的那次；没给看过的不作废；点过发送但没交上去的照常重试。变异验证：去掉两处 `markOfferShown` 调用后该组 2 个用例变红。
- **备注**：Windows 真机未复验（需要「真实闪退 → 不理提示 → 自动更新」现场）；逻辑与平台无关，Android / macOS 同受益。
