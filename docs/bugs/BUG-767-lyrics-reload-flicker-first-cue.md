## BUG-767 · 歌词模式进入后一直闪烁 + 高亮恒第一句（不是正在听的那句）
- **报告**：2026-07-13（用户：现在进去一直在闪烁，并且高亮是第一句，不是我刚刚在听的）。BUG-757（歌词音频跟随）/ BUG-756（输入桥）落地 develop 后的回归。
- **真实性**：✅ **真 bug（两处叠加：重载死循环 + on-load 强夺焦）**。
  - **主根因（重载死循环）**：`reader_hibiki/audiobook.part.dart` `_onCueChanged` 歌词分支，`sourceIdx = usesAllBookCues ? allBookCueIdx : currentCueIdx`。当当前 cue **暂不可解析**（cue 间隙 / `AudiobookPlayerController.setChapterCues` 把 `_currentCue=null` 后 `notifyListeners`，`audiobook_controller.dart:632`）时 `sourceIdx==-1` → `idx<0`。旧码在 `idx<0` 分支**无条件**重开歌词页；重开又以 `allBookCueIdx>=0 ? ... : _lyricsEntryCueIndex`（-1<0 → 回退到过期 `_lyricsEntryCueIndex`≈0）生成 `currentIndex` → **高亮跳回第一句**；重载 onLoadStop 落定那帧 `sourceIdx` 仍 -1 → 再次重载 → **无限重载 = 一直闪烁 + 恒第一句**。此分支是既有代码，但 BUG-757/756 落地改了进入时序踩中了它。
  - **次根因（on-load 强夺焦）**：BUG-756 曾在 `reader_hibiki/webview.part.dart` `_onChapterLoadComplete` 歌词就绪分支加 on-load 焦点 reclaim，想让 ESC 从进入即可退。但桌面 `loadData` 后强夺 Flutter 焦点会顶焦原生 WebView2、重置其滚动到顶（→ 看似第一句），并与页面抢焦点抖动；叠加上面的重载路径（每次 loadData 都触发一次）放大成持续闪烁。
- **[x] ① 已修复** — `38d2ba1f3`。① `audiobook.part.dart`：`_onCueChanged` 歌词分支重载**加 `sourceIdx>=0` 守卫**——`sourceIdx<0`（cue 不可解析）时保位不跳、绝不重载；两条旧重载分支收敛为一条「cue 真移出已载窗口（sourceIdx>=0 但 idx 越界）→ 重开窗口居中当前 cue」的合法重载（currentIndex 用真实 index，不再回退第一句），从根上消除死循环特殊分支。② `webview.part.dart`：移除 `_onChapterLoadComplete` 歌词就绪分支的 on-load 焦点 reclaim（去掉桌面强夺焦的重置/抖动）。ESC 退出仍可用：点空白唤底栏走 `onLyricsTapEmpty`（内含焦点 reclaim）、查词弹窗关闭走 `onAllPopupsDismissed` reclaim——任一交互后焦点即回阅读内容。根因修，非绕过。
- **[x] ② 已加自动化测试** — `test/pages/reader_lyrics_input_bridge_guard_static_test.dart` 新增 2 条 BUG-767 用例：① `_onCueChanged` 歌词分支含 `if (sourceIdx >= 0) {` 守卫且重开歌词页调用只剩 1 处（旧码 2 处 = 死循环）；② `_onChapterLoadComplete` 歌词就绪分支**不再**含 on-load 焦点 reclaim。原 BUG-756 的「就绪即 reclaim」用例已改为反向守卫。WebView 行为无法 widget 挂载，最强可落地层是 reader 源码扫描守卫。
- **备注**：reader/WebView/有声书/桌面焦点类。代码 + 单测绿（audiobook/reader/pages 3615 全绿）、`flutter analyze` 0 issue、`dart format` 0 改动。**真机复测**（进歌词模式不再闪烁、高亮落在正在听的那句、cue 间隙/暂停态进入不闪；点空白仍唤底栏、交互后 ESC 仍退出）待用户后补——桌面 WebView2 焦点/重载时序是平台行为，必须真机验。
