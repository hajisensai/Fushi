## BUG-4849 · 查词 / 复习 tab 每次切入整页重挂（16～94 ms），查词页还要拆建一次预热的查词 WebView
- **报告**：2026-11-16（用户：转来群反馈录屏「切 tab 变卡了」；修完 BUG-4851 / BUG-4896 后列出的剩余项「非保活 tab 每次切入整页重挂」与「`home_dictionary_page.dart` 有同一个 inert 即 `SizedBox.shrink()` 的写法」，用户回「都做都做，能优化就优化」）
- **真实性**：✅ 真 bug（Windows profile 构建实测，探针 `fushi/integration_test/home_tab_switch_perf_itest.dart`）。回访切入首帧 build：查词 19～26 ms，之后 UI 线程还要被堵 35～60 ms（常驻热槽的查词 WebView 冷建）；复习 22～26 ms，第一次回访 94 ms。
  - 根因：`fushi/lib/src/pages/implementations/home_page.dart:2451`（修前行号）`_keepAliveTabs` 不含查词与复习，这两页挂在 `KeyedSubtree` 下、切走即销毁，每次切入从零 inflate + `initState` 重新取数。查词页开页即 seed 常驻热槽，于是每次切入冷建一个 WebView2 并装载 popup.html + JS + CSS、切走又销毁。
  - 同页第二处：`home_dictionary_page.dart:2236`、`:2244`（修前行号）浮层 inert 时返回 `SizedBox.shrink()`，把预热好的 WebView 整个卸载——与游戏工作台 BUG-4896 同一个坑，查词页不保活时只在「被不透明路由盖住再回来」触发，保活后每次切 tab 都会触发。
- **[x] ① 已修复** — 查词与复习加入 `_keepAliveTabs`。原先靠「切入即重挂」完成的事改成显式的「切入时做」：查词页藏着时不消费待查词（TODO-376）与聚焦请求，由藏转显后帧补消费；藏着时不参与系统返回；浮层 inert 时留在树上整棵 `Offstage` + `TickerMode(false)` + `ExcludeFocus`，页面被停用时才空渲染。复习页订阅 `homeShellTabNotifier`，切回时刷新配对主机列表，页内返回改用 `SectionPopScope`。设置与网页两页**刻意不保活**，见备注。提交见 PR #3534。
- **[x] ② 已加自动化测试** — `fushi/test/pages/home_hidden_tab_select_behavior_test.dart`「查词 tab 保活：藏着时不消费待查词，切回同一页才消费」「查词 tab 保活：藏着时有查询也不拦系统返回」；`fushi/test/pages/home_dictionary_nav_tap_focus_test.dart`「查词页保活：去别的 tab 再点回『查词』，是同一页、清空残留查询并聚焦」；源码守卫 `home_tab_keepalive_guard_test.dart`（保活集合、藏着时的早退、切入钩子、复习页的监听与 `SectionPopScope`）与 `home_dictionary_warm_popup_guard_test.dart`。
- **备注**：修后实测回访切入首帧（不开剖析的两轮）：查词 9.3 / 9.3 ms、没有随后的阻塞（修前 25.8 / 18.7 ms + 阻塞 35～60 ms）；复习 5.8 / 6.4 ms（修前 26.1 / 22.1 ms，第一次回访 94 → 16.2 ms）。行为变化：这两页现在跨 tab 保留页内状态（查词页的滚动位置、复习页的牌组列表），常驻内存里多一个预热的查词 WebView；从导航点「查词」仍会清空查询并聚焦搜索框（原有约定，`_selectTabFromNav` 发的 `clearQuery`），快捷键 / 程序化切入则保留上次查询。设置不保活：每次进入要从根页开始，页内有成串嵌套的页面与 `PopScope`，保活的收益只有一帧；网页 tab 重挂本来就在一帧以内（6～9 ms）。
