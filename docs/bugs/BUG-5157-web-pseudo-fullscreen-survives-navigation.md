## BUG-5157 · web-pseudo-fullscreen-survives-navigation
- **报告**：2026-11-22（审计 HBK-AUDIT-037，2026-11-21 项目审查；来自 PR #3798）
- **真实性**：✅ 真 bug。伪全屏状态只活在旧页面 JS 里（`fushi/lib/src/web_browser/tab_view/web_browser_page_scripts.dart` `webBrowserFullscreenScript` 的 `pseudo` 变量，只靠 MutationObserver 侦听当前 DOM 内的元素摘除）；整页导航后旧页面消失、不再报退出，新文档初始化也不发退出状态。Dart 加载入口 `fushi/lib/src/web_browser/tab_view/web_browser_tab_view.dart` `_onLoadStart` 只 `_fullscreenZoom.stop()`，不动 `_tab.fullscreen`，壳（`fushi_web_browser_page.dart` `_applyFullscreenDisplay`）因此留在沉浸模式 / 方向锁里；旧页面卸载前发出的迟到上报也照单全收。
- **[x] ① 已修复** — 页内全屏脚本每个顶层文档（含往返缓存恢复）生成代际号，初始化即报 `(false, '', doc, true)`（桥未就绪时在 `flutterInAppWebViewPlatformReady` 同号补报），之后每条上报带代际号；`pagehide` 先退自己的伪全屏。Dart 侧新增 `WebBrowserFullscreenDocumentGate`（`web_browser_fullscreen.dart`）：新代际通告 → `WebBrowserTabViewState.handlePageFullscreenReport` 重置缩放守卫（`WebBrowserFullscreenZoomGuard.reset`，旧页缩放不套到新页）并退标签页全屏、通知壳（退沉浸、还原方向集）；非当前代际的普通上报一律丢弃。子框架（无代际号）照常应用。
- **[x] ② 已加自动化测试** — `fushi/test/web_browser/tab_view/web_browser_tab_view_widgets_test.dart`「整页跳转（主文档换代）收尾伪全屏…」（桩 WebView 上走真实上报入口）；`fushi/test/web_browser/web_browser_fullscreen_test.dart`「文档代际闸」三条 + node 实跑脚本的「文档代际」一条；`web_browser_tab_view_logic_test.dart` 缩放守卫 reset 一条。
- **备注**：没有拿平台的 onLoadStart / onPageCommitVisible 当换代信号：前者是导航开始（可能被取消、iOS 是 provisional），后者各平台支持不一；顶层文档的 document-start 用户脚本就是「主文档提交」的五端一致信号。
