## BUG-1596 · release.yml 序号脚本在 working-directory: fushi 下解析成不存在路径，恢复自动发布首跑 exit 127
- **报告**：2026-08-13（用户：CI 红）
- **真实性**：✅ 真 bug。根因 `.github/workflows/release.yml:82`（修复前）：`Resolve Android release channel` step 设了 `working-directory: fushi`，而 BUG-1586（`21a191510b`）把序号算式改成根相对的 `RELEASE_SEQUENCE=$(bash tool/release_sequence.sh)`——在 `fushi/` 下解析成不存在的 `fushi/tool/release_sequence.sh`，bash 报 No such file or directory → exit 127，build job 首步即挂（run 31700342433）。六处调用点里只有这一处带 working-directory（release-desktop.yml×4 与 main.yml 都在仓库根跑）。落地当天没暴露：push 自动发布恰在改名过渡期停用、手动 dispatch 默认 `skip_tests=true` 且当日 dispatch 早于 BUG-1586 合入——2026-08-13 恢复 push 自动发布（用户指示）首跑即红。
- **[x] ① 已修复** — 去掉该 step 的 `working-directory: fushi`，`grep '^version:' pubspec.yaml` 改为 `fushi/pubspec.yaml`，与 release-desktop.yml 同名 step 对齐（step 内其余引用均为根相对字符串输出，不受 cwd 影响）。提交见本文件入库提交。
- **[x] ② 已加自动化测试** — `fushi/test/build/release_sequence_floor_guard_test.dart`「调用共享脚本的 step 不得设 working-directory（BUG-1596）」：枚举 `.github/workflows/*.yml` 全部 `bash tool/release_sequence.sh` 调用点，从调用行向上扫到所属 step 起始，任何 step 级 `working-directory:` 即红。已变异实测：临时加回 `working-directory: fushi` → 精确红在 `release.yml:85（调用点 105）`；反向替换还原 → 绿。
