## BUG-2488 · floating-dict-word-audio
- **报告**：2026-09-13（用户：「在 app 外查词和制卡没有单词音频吗」→ 追问「手机 app 外」）
- **真实性**：✅ 真 bug（仅 Android 悬浮词典；Windows WebView2 浮窗与 Android 文本选择/分享的 `PopupDictionaryPage` 都走 popup.js，本来就有）。根因：Android 悬浮词典是原生 TextView 窗口 `fushi/android/app/src/main/java/app/fushi/reader/FloatingDictService.java:255-277`，只持有 Dart 降维后的 `word / reading / meaning明文`，制卡时经 `notifyFloatingDictAnki` 把三个字符串原样送回 Dart，`AppModel._setupFloatingDictHandlers`（`fushi/lib/src/models/app_model.dart:7976`）再从它们拼 payload——整条路从未经过单词音频解析器 `resolveLookupAudioUrl`（app 内弹窗 / Creator / 扩展远端查词的唯一真相），`repo.mineEntry` 只认 `payload.audio`，于是 `{audio}` 字段恒空；窗口本身也没有播放按钮。
- **[x] ① 已修复** — Dart `FloatingDictChannel` 新增 `playAudio` native→Dart 调用与 `onPlayAudio` 处理器、制卡 payload 抽成纯函数 `buildFloatingDictMinePayload`；`AppModel` 制卡前经 `resolveLookupAudioUrl` 解析音频进 `fields['audio']`（本地路径 / http 由仓库层 `AnkiAudioRef.classify` 分流）、`onPlayAudio` 走 `playLookupAudio`（与 app 内自动发音同一函数）；Java 悬浮窗底栏加 ♪ 按钮 → `notifyFloatingDictEvent("playAudio")`。
- **[x] ② 已加自动化测试** — `fushi/test/media/floating_dict_channel_test.dart`（payload 带/不带 audio 的形状；native `playAudio` 分派到处理器；空词忽略）。
- **备注**：同一根因的其余症状本轮未动：悬浮词典制卡 `{sentence}` 恒空、只能制第一条词条、无音调/词频/glossary HTML——要根治得让原生窗口不再持有降维副本（改为按索引回 Dart 取真实 `DictionaryEntry`，或整窗换成 popup.js WebView），属独立任务。真机验证缺口：本轮只做了 `flutter analyze` + 定向测试 + `gradle :app:compileDebugJavaWithJavac`，没在 Android 真机/模拟器点过 ♪ 与制卡。
