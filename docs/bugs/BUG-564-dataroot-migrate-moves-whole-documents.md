## BUG-564 · Windows 数据根迁移整树搬移并删除用户整个 Documents（默认根）
- **报告**：2026-07-06（用户：TODO-1226，P0）
- **真实性**：✅ 真 bug。Windows 默认数据根 = 整个 `C:\Users\<user>\Documents`（`hibiki/lib/src/storage/app_paths.dart:124` 无 data_root pref 时 documentsRoot=getApplicationDocumentsDirectory()），是共享用户目录而非 Hibiki 私有目录。旧 `hibiki/lib/src/storage/data_root_migrator.dart` 对 documents 根的 `_MovePlan` 排除集为空 → `_moveTree` **整树搬移整个 Documents**：① 同盘 `src.rename` 撞其它进程句柄返回 ERROR_ACCESS_DENIED(5)，5 不在 `_shouldCopyAfterRenameFailure{17,18,1,13}` → 不走复制回退 → 回滚 + 确定性报「有文件被占用」；② 跨盘复制回退第一步 `_countFiles` 的 `listSync(recursive:true)` 默认 followLinks:true → 递归进 Documents 的 shell junction（My Music/My Pictures/My Videos，ACL 全拒）errno 5 硬炸；③ **「成功路径」把用户整个 Documents 搬进新根并 `_deleteOldRootAfterSwitch(oldDocumentsRoot)` 删源 = 删除用户整个 Documents 的数据事故**。
- **[x] ① 已修复** — 迁移引擎改为**共享根白名单选择性搬移**：`DataRootMigrationRequest` 新增必填 `documentsTopLevelIncludeNames`（null=Hibiki 专属根整树原行为；非 null=只搬白名单顶层项、绝不删源根本体），白名单单一真相源 `AppPaths.hibikiOwnedDocumentsEntries`（14 项，逐一对应仓库真实派生点）；UI 调用点 `hibiki/lib/src/sync/sync_settings_schema/data_root.part.dart` 以「旧 documents 根 == 平台 Documents 实路径」判共享（pref 存失效路径回退默认根时也判对），共享根传白名单；`_countFiles` / `_hasAnyFile` / `_dirExistsAndHasFiles` 等 `listSync` 全部补 `followLinks: false`。自定义专属根迁移行为逐字节不变。
- **[x] ② 已加自动化测试** — `hibiki/test/storage/documents_whitelist_guard_test.dart`：源码扫描守卫，`documentsSubdirectory('x')` / `appDirectory.path` join/插值派生点漏收白名单即红 + 生产入口必须引用白名单常量；`hibiki/test/storage/data_root_migrator_test.dart` 新增组「TODO-1226：共享默认根白名单迁移」：白名单模式只搬 Hibiki 项、用户文件/junction 不动、Documents 本体保留；pref 写失败回滚把白名单项合并搬回、用户文件无损；`_countFiles` followLinks:false 分母不计链接目标。既有 1182 回滚/安装目录拒绝测试全绿。
- **备注**：刻意**不**收进白名单：`error_log.txt` / `*_breadcrumb.txt`（`ErrorLogService` 直连 `getApplicationDocumentsDirectory()` 固定落平台 Documents、不随数据根走）、`video_clips`、桌面导出目录 `Hibiki`。另发现同类潜在缺陷（不在本 bug 范围）：`AudiobookStorage._documentsRoot`（packages/hibiki_audio）、`subtitle.part.dart:466/648`、`desktop_audio_clipper.dart:590`、`clip_export.part.dart:143` 直连 path_provider，自定义数据根生效后新写入会落回平台 Documents 而非新根，需后续统一接 AppPaths（TODO-935 遗留）。
