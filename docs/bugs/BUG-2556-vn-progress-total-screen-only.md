## BUG-2556 · 视觉小说模式翻屏后阅读位置不落库，重开书回到章首
- **报告**：2026-09-16（用户：「修复 vn 模式打不开的问题」+「vn 模式打开后有不少对应 vn 模式专属的开关的，参照 hoshi reader Android 也弄进来」）
- **真实性**：✅ 真 bug（「打不开」本身**未复现**，见备注；沿真实路径验出的是同一模式下的位置丢失）。Windows 离屏 runner 真 app（`fushi/integration_test/reader_vn_open_itest.dart`）：竖排 + `view_mode='vn'` 冷开书，键盘 PageDown 翻到第 3 屏（`firstChar=128`），关书重开落回第 0 屏、`initialCharOffset=0`；整个过程只有开书那一次 `[ReaderFushi] save position … charOffset=0`，翻屏后一次都没落库。临时探针实录：`fushiProgressDetails` 依次返回 `0,69,8,77` / `0,51,77,128` / `0,56,128,184`，另有两次返空串。根因链：宿主 `fushi/lib/src/pages/implementations/reader_fushi/webview.part.dart:1538-1556`（`fushiProgressDetails`）没有 `paginationMetrics` 时退到 `r.createWalker()` 数「章总字数」→ VN 的 `createWalker(rootNode)`（`fushi/lib/src/reader/reader_visual_novel_scripts.dart:874-882`）不传根时以 `this.screen`（当前屏克隆）为根——整章正文早被 `detachChapterSource` 搬进游离的 `sourceRoot`，document 里只剩这一屏——于是 `total` 是本屏几十字、`current = Math.round(p × total)` 中 `p` 是章级屏锚比例（0.008），恒取整成 0 → `progress = 0/total = 0.0` → Dart `navigation.part.dart` `_debouncedSaveReaderPosition` 的「同 section 且 `|progress − 上次| < 0.001` 不落库」把每一次翻屏都判成没动，第三段 `charOffset`（8/77/128，章内绝对偏移、本来是对的）随之一起丢弃；打字渐显（默认 45 字/秒）未完成时 walker 的 `isUnrevealed` 还会剔掉未揭示节点让 `total` 归 0，整段返空串被当纯图片章走 `_applyImagePageProgressFallback`，同样不落库。Chrome headless 直接调同一函数复现：VN 引擎 `totalChapterChars=648` 时它报 `14,54,108,162`。
- **[x] ① 已修复** — `b2cbcbf21d`（`pr/vn-mode-open`）：`fushiProgressDetails` 在没有 `paginationMetrics` 时优先取 VN 在 `initialize` 里算好的章级 `totalChapterChars`（`contentStream.totalMatchableChars`，与分页 shell 的 `paginationMetrics.totalChars` 同口径），walker 兜底只留给真没有章级计数的 shell（纯图片章语义不变）。修后同一真 app 路径：翻屏后落库 `charOffset=8/77/128`，重开落回第 3 屏。
- **[x] ② 已加自动化测试** — `fushi/test/reader/vn_progress_details_chapter_total_test.dart`（node 真跑生产引擎切出的 `fushiProgressDetails` 原文：VN 形态替身 reader 走查当前屏 54 字 / 0 字两种 walker，装配都必须是 `162,648,162,216`，末屏钳到 `648,648,600,648`；`paginationMetrics` 仍优先；无章级计数的纯图片章仍返空串）；真 app 证据 `fushi/integration_test/reader_vn_open_itest.dart`（竖排冷开 / 键盘翻屏落库 / 重开恢复 / 阅读中切 VN / 有声书 cue / VN 设置组随 view_mode 出现与消失，五路径全走真 WebView + 真引擎并抓像素）。
- **备注**：「VN 模式打不开」在上游 `cc1c858cca` 上**未复现**：真 app 冷开（横排 / 竖排）、带存档重开、分页中切 VN、有声书带 cue 四条路径都 content-ready 并渲染 stage（421 屏）；Chrome headless 给生产引擎喂封面 SVG / 纯 `<img>` / 空章 / ruby / 嵌套 section / `<br>` / 纯空白也全部建屏。用户本机日常开发版（本地 `develop`，2026-09-15 构建）**没有**上游 `8552f5cc4c`「feat(reader): complete VN mode settings and media semantics」（2026-09-09），VN 在那里仍是 M0：没有任何 VN 子设置、点空白翻页被强制开启、渐显被强制关闭——用户要的「VN 专属开关」上游已齐（渐显速度 / 每屏内容 / 每屏句数 / 保持对话 / 点空白前进 / 合并跨屏有声句，与 Hoshi-Reader-Android `ReaderSettings.kt` 的 6 项一一对应，无缺口），只是本地 develop 尚未同步。
