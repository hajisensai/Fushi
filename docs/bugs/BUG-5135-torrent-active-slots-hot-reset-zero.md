## BUG-5135 · 活跃下载 / 做种名额热更新回 0（引擎默认）不生效
- **报告**：2026-11-22（Codex 2026-11-21 PR 审查 HBK-AUDIT-020，PR #3996）
- **真实性**：✅ 真 bug。`native/fushi_torrent/fushi_torrent_ffi.cpp:795`（修复前）`ht_apply_session_settings` 只在 `active_downloads > 0` / `active_seeds > 0` 时写 settings_pack，`<= 0` 一律「不写」；而配置语义是「0 = libtorrent 默认」（`server_torrent_session_config.dart:9`、`anime_download_config.dart:180`、app 设置页同口径）。`EmbeddedTorrentHost.applySessionSettings`（`embedded_torrent_host.dart:544`）经 `libtorrentActiveLimitArg` 把 0 原样传下去，于是同一 session 从「不限（int32 最大值）」或自定义正数改回 0 时，native 什么都不写，旧名额一直用到重启。无头服务端 admin 保存走 `ServerDownloadHost.applyTorrentSessionSettings` 热重铺、显示成功；app 设置页（`torrent_settings_section.dart:1023`）改回 0 同样中招。头文件把 `<=0` 写成「保持默认」，实为「保持现值」——契约本身就是错的。
- **[x] ① 已修复** — 名额是**状态**不是增量：`ht_apply_session_settings` 每次都写全值，`>0` 原值、`0` 取 `lt::default_settings()` 的值（不在桥里抄 3 / 5 常量，与 `ht_set_unchoke_slots` 恢复默认的做法一致）、`<0` = 不限（-1）。`ht_session_status` 追加 `active_downloads` / `active_seeds` 现值（`FtSessionStatus.activeDownloads` / `activeSeeds`，老 DLL 为 null），热更新后能核对真正生效的值。Dart 侧 `libtorrentActiveLimitArg` 不变（不限仍下发 int32 最大值，老 DLL 也生效），只更新契约注释。修在 native 这一层，app 与服务端共用同一修复，不在服务端另做「0 → 3/5」的特例换算。
- **[x] ② 已增加自动化测试** — `packages/fushi_torrent/test/active_limits_hot_reset_test.dart`：真 DLL、同一 session 依次下发 默认 → 不限 → 0 → 自定义 → 0 → -1 → 0，每步读 `sessionStatus` 核对 native 现值。变异实测：撤掉 native 修复（恢复 `> 0` 才写）后「不限 → 0」一步读到 2147483647，测试红。
- **备注**：`max_upload_slots` 仍是 `<=0` 不写，但它随后由 `sweepUploadPolicy` 经 `ht_set_unchoke_slots` 重新裁决（`_appliedSessionUploadEnabled` 被置空），不存在同样的残留问题。
- **审查追修（PR #3996 复审）**：native 改成「每次写全值」后，`EmbeddedTorrentHost.reconcileNetworkDiscoveryState`（只切 DHT/LSD/UPnP/NAT-PMP）仍以缺省 `activeDownloads = 0` / `activeSeeds = 0` 调 `applySessionSettings`，每次 add / resume 唤醒或空闲收回都会把「不限 / 自定义」静默冲回 3/5——服务端默认不限（BUG-5160）跑一次唤醒就失效。修复：reconcile 带上 `_sessionConfig` 的名额；`EmbeddedTorrentSession.applySessionSettings` 的两个名额参数改 `required`（状态没有「不动」档，缺省 0 本身就是陷阱）。回归测试 `fushi/test/media/torrent/embedded_torrent_idle_discovery_test.dart`「发现协议开关不得把活跃名额冲回 libtorrent 默认」：伪 C ABI 记录每次下发的名额，修复前唤醒 / 收回两次下发为 `0/0`。
