## BUG-4958 · 互联/云聚合同步在 UI isolate 上同步跑整份快照折叠与指纹，慢设备 ANR
- **报告**：2026-11-21（用户：应用内反馈 c2voByEqPq，iReader Ocean 5 Pro 墨水屏 / Android 14 / 3.3.0；11-11～11-17 共 22 次 `reason=ANR`，全是 Input dispatching timed out，主线程 `state=R` 跑在 libapp 里）
- **真实性**：✅ 真 bug。3.3.0 release 包 libapp.so 已 strip（AGP 剥符号、Android 不出 split-debug-info），用 a2638e03 源码 + 同版 Flutter 3.47.6 重编出不 strip 的 arm64 AOT，再按掩码指令 k-gram 投票把反馈里 BuildId 8193417a…（= v3.3.0 release 资产）的 pc 对到符号：每次 ANR 的主线程栈都是 `AggregateSyncService.syncOverClient → unorderedSnapshotFingerprint → jsonEncode / List.sort(_StringBase.compareTo) / _stableHash`。根因 `packages/fushi_engine/lib/sync/aggregate_sync_service.dart:348`（develop 76811fc2 行号）：互联聚合同步在调用方（app 里 = UI isolate，Android 上与平台线程合并）同步跑整份统计 + 收藏快照的 `fromJson` / `mergeSnapshots` / `localDelta`（:334，逐条 jsonEncode 两遍）/ 两份 `unorderedSnapshotFingerprint`（逐条 jsonEncode + 排序 + 逐码元 FNV）；云通道同病（:184 增量、:206 整份 jsonEncode + 逐码元哈希）。数据随使用年头线性增长，慢 CPU 上一次跑满 5 秒即 ANR，且触发点在自动同步，所以集中出现在阅读器 / 历史页这些常驻页面。
- **[x] ① 已修复** — 折叠 + 写回增量判定 + host 指纹（`planFold`）、云通道上行编码 + 哈希（`encodeOutgoing`）、互联上行跳过判定（`liveOutgoingIfChanged`）抽成只吃纯数据的静态函数，经 `AggregatePureRunner`（默认 `Isolate.run`）在后台 isolate 执行；包装函数写成 static，闭包只捕获快照 / 原始 JSON，不带持 DB 连接的服务实例。DB 读写（materialize、墓碑裁剪、写回）与网络仍在原 isolate。
- **[x] ② 已加自动化测试** — `fushi/test/sync/aggregate_sync_off_ui_isolate_test.dart`：互联 / 云两条通道的纯计算都由真实 `Isolate.run` 在另一个 isolate 执行（记录执行 isolate 的 debugName，闭包不可发送会直接抛错）、结果照常落地 / 回传 / 跳过；`planFold` 与直接组合 merge / localDelta / 指纹逐项一致。既有 `aggregate_*_test.dart` 走默认 runner 覆盖回归。
- **备注**：反馈里另一份 BuildId 0c5011…（11-11～11-14 的更早一份 3.3.0 构建）拿不到对应包，未逐帧符号化，但其主线程帧形态与上面一致。仍留在 UI isolate 的线性步骤：`InterconnectSyncBackend.getRemoteAggregate` 的 `jsonDecode`、`putRemoteAggregate` 的 `jsonEncode`、发送给后台 isolate 时的消息深拷贝（VM 原生拷贝，比逐条编码 + 排序便宜一个量级以上）。真机复测未做（取消真机验证）。
