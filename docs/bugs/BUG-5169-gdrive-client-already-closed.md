## BUG-5169 · Google Drive 同步 / 比较数据全部报「Client is already closed」
- **报告**：2026-11-22（应用内反馈 #wnJNdQbYfw：「Can't Sync」，Windows + Android，Google Drive；手动同步、比较数据都报错）
- **真实性**：✅ 真 bug。日志 13:37:34 与 13:40:17 两轮 `SyncRunReport.errors` 里所有通道都是 `ClientException: HTTP request failed. Client is already closed., uri=https://www.googleapis.com/drive/v3/files…`，两轮完全一样，状态卡死。根因：桌面端 `GoogleDriveAuth.refreshAuth`（`fushi/lib/src/sync/google_drive_auth.dart:387-424`，修前）每次刷新都新建底层 HTTP client，并 `_desktopClient?.close()` 关掉旧 AuthClient（`closeUnderlyingClient: true`，连底层连接一起关）。同步的 tombstones / videos / aggregate / settings / collections 等通道是并行跑的，访问令牌过期后它们几乎同时吃 401，`GoogleDriveHandler._callOnce`（`fushi/lib/src/sync/google_drive_handler.dart:185-201`，修前）各自 `_cachedApi = null` 再各自 `refreshAuth()`：第一个刷新装上的新 client 被第二个刷新关掉，而先重试的通道已经把指向它的 `DriveApi` 缓存进 `_cachedApi`（`google_drive_handler.dart:136-141`，修前）。之后每个请求都用这个已关闭的 client，抛的是 `ClientException` 而不是 401，既不触发刷新也不算瞬时错误，于是直到重启每轮同步全部失败。
- **[x] ① 已修复** — HTTP 连接的生命周期与令牌刷新分开：`GoogleDriveAuth` 桌面会话只持有一个底层 client（`_desktopBaseClient`），只在换会话（登录 / 恢复，`_installDesktopSession`）和登出时关；刷新用这条连接换令牌，只换外层 `authenticatedClient` 包装（默认不拥有底层连接），旧包装不 close。`refreshAuth({rejected})` 单飞，并发 401 共用一次刷新；带上被拒的 client，若当前 client 已不是它（别人刷新过）就直接返回。handler 不再缓存 `DriveApi`，每次请求按 `getAuthClient()` 的当前 client 现建（只剩测试注入的 `_debugApi`）。移动端 `getAuthClient` 改为按令牌缓存 client（扩展的 `authenticatedClient()` 每次都新建一个），刷新 / 换账号 / 换 scope / 登出时丢弃，同样走单飞与被拒 client 判断。
- **[x] ② 已加自动化测试** — `fushi/test/sync/google_drive_token_refresh_concurrency_test.dart`：假 Google 服务端 + 关闭后抛 `Client is already closed` 的底层 client，走真实 `GoogleDriveHandler.listChildrenRaw → refreshAuth → refreshCredentials` 路径。①四个并行请求同时 401：token 端点只被请求一次、底层连接没关、四个都用新令牌成功、下一轮直接用新令牌；②迟到的 401（带旧 client）不再刷新，新令牌被拒才刷新；③底层连接只在换会话 / 登出时各关一次。变异实测：去掉单飞 → ① 红；handler 恢复长期缓存 DriveApi → ① 红（`GoogleDriveError(401)`）。
- **备注**：Android 端用户只说「也不行」，没附日志。Android 走 google_sign_in，修前不会出现「Client is already closed」（刷新不关 client），可能是同一份日志里 2026-11-20 的 `insufficient_scope` 重新授权，或者别的原因，需要 Android 日志才能确认。
