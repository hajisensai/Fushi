## BUG-809 · 有声书导出片段桌面仍用mjpeg/.mov无帧间压缩导致30秒200MB且非通用格式
- **报告**：2026-07-14（用户：视频大小200mb短短30秒，没缓存？而且格式也没换成常见格式）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/media/audiobook/audiobook_clip_export.dart`（改前 `buildFfmpegImageAudioToVideoArgs:349` / `buildFfmpegImageSeqAudioToVideoArgs:462`）硬编码 `-c:v mjpeg` + `-q:v 2` + `yuvj444p`，`audiobook.part.dart:1291/1402/1412`（改前）硬编码 `.mov` + `video/quicktime`。
  - **200MB / 「没缓存」**：Motion-JPEG 是 intra-only，每帧都是一张完整独立 JPEG，无任何 P/B 帧时域压缩。动态逐句高亮跟随把母帧按帧计划复制成大量**连续重复帧**（30s×24fps=720 帧），即便绝大多数帧字节完全相同，mjpeg 仍把每份重复帧重新编码成整张 JPEG（用户直觉的「没缓存」= 无帧间去重）→ 叠加 `-q:v 2`（近无损）+ `yuvj444p`（全彩不下采样）+ 1080×1920 → 数百 MB。这不是码率设错，是选错编码器。
  - **格式非通用**：输出 `.mov`（QuickTime）+ Motion-JPEG 组合，很多播放器/社交平台不接受或体积巨大，非通用 `.mp4`/h264。
  - **元根因**：桌面 ffmpeg-min build 自 `e039cf760`（2026-07-07，TODO-1257）已编入 `libx264`+`mp4` muxer（`tool/ffmpeg-min/build-ffmpeg-min.sh:50/60/96`），但有声书导出的 Dart 合成层从未迁移，仍停在旧 mjpeg/.mov 假设（文件顶部 D-CODEC 注释也过期）。桌面 CLI 后端有 libx264，移动端自编 ffmpeg-kit **min** 变体无外部 GPL 库（无 libx264，见 `ffmpeg_backend.dart:528-532`）。
- **[x] ① 已修复** — 按后端能力分流（新增纯函数 `_clipVideoCodecArgs`，`audiobook_clip_export.dart`）：桌面 `h264=true` → `-c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p -movflags +faststart` + `.mp4`（带帧间压缩，重复帧压到近零，30s 从 ~200MB 降到几 MB，且 .mp4 通用可直接播放/分享）；移动端 `h264=false` 保持 `-c:v mjpeg` + `.mov`（无 libx264）。caller `audiobook.part.dart`：`useH264 = isDesktop`、`videoExt = useH264 ? 'mp4' : 'mov'`，输出文件/保存对话框/分享 mime 全跟随；两条合成路径（静态单图 + 动态序列帧）都透传 `h264`。同时刷新过期的 D-CODEC 顶部注释。
- **[x] ② 已加自动化测试** — `hibiki/test/media/audiobook/audiobook_clip_synth_test.dart`：`h264=true switches to libx264 + crf + yuv420p + faststart (BUG-809)` 与 `seq h264=true uses libx264 (interframe compression) + faststart`（断言 libx264/crf/yuv420p/faststart 且不掺 mjpeg 的 qscale/yuvj*，序列帧仍走 -framerate 非 -loop 1）；默认路径原 mjpeg 守卫保持绿（=移动端）。`audiobook_clip_vertical_webview_guard_test.dart`：`BUG-809: caller wires desktop h264/.mp4, keeps mobile mjpeg/.mov` 源码守卫 caller 分流与透传。
- **备注**：移动端受 min AAR 限制仍 mjpeg/.mov；移动端也上 h264 需给自编 ffmpeg-kit 加 libx264（GPL）或 `h264_mediacodec`（另开 AAR 重建任务）。真机复测：桌面导出应得 `.mp4`、体积从数百 MB 降到几 MB、任意播放器可开。与 BUG-808 同批。
