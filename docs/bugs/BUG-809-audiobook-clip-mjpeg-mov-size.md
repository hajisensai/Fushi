## BUG-809 · 有声书导出片段桌面仍用mjpeg/.mov无帧间压缩导致30秒200MB且非通用格式
- **报告**：2026-07-14（用户：视频大小200mb短短30秒，没缓存？而且格式也没换成常见格式）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/media/audiobook/audiobook_clip_export.dart`（改前 `buildFfmpegImageAudioToVideoArgs:349` / `buildFfmpegImageSeqAudioToVideoArgs:462`）硬编码 `-c:v mjpeg` + `-q:v 2` + `yuvj444p`，`audiobook.part.dart:1291/1402/1412`（改前）硬编码 `.mov` + `video/quicktime`。
  - **200MB / 「没缓存」**：Motion-JPEG 是 intra-only，每帧都是一张完整独立 JPEG，无任何 P/B 帧时域压缩。动态逐句高亮跟随把母帧按帧计划复制成大量**连续重复帧**（30s×24fps=720 帧），即便绝大多数帧字节完全相同，mjpeg 仍把每份重复帧重新编码成整张 JPEG（用户直觉的「没缓存」= 无帧间去重）→ 叠加 `-q:v 2`（近无损）+ `yuvj444p`（全彩不下采样）+ 1080×1920 → 数百 MB。这不是码率设错，是选错编码器。
  - **格式非通用**：输出 `.mov`（QuickTime）+ Motion-JPEG 组合，很多播放器/社交平台不接受或体积巨大，非通用 `.mp4`/h264。
  - **元根因**：桌面 ffmpeg-min build 自 `e039cf760`（2026-07-07，TODO-1257）已编入 `libx264`+`mp4` muxer（`tool/ffmpeg-min/build-ffmpeg-min.sh:50/60/96`），但有声书导出的 Dart 合成层从未迁移，仍停在旧 mjpeg/.mov 假设（文件顶部 D-CODEC 注释也过期）。桌面 CLI 后端有 libx264，移动端自编 ffmpeg-kit **min** 变体无外部 GPL 库（无 libx264，见 `ffmpeg_backend.dart:528-532`）。
- **[x] ① 已修复** — 编码器新增纯函数 `_clipVideoCodecArgs`（`audiobook_clip_export.dart`）：`h264=true` → `-c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p -movflags +faststart`；`h264=false` → `-c:v mjpeg -q:v 2 -pix_fmt <pixFmt>`。caller 改**能力自适应「先试 h264/.mp4，失败回退 mjpeg/.mov」**（`_synthClipWithCodecFallback`，静态单图 + 动态序列帧共用；复用同一批已渲帧，回退只多跑一次快速失败的 ffmpeg）：容器/扩展名/分享 mime 跟随**实际产出**文件后缀，不再靠 `isDesktop` 假设。
  - **桌面**：捆绑 ffmpeg-min 有 libx264 → h264 一次成功 → `.mp4`，30s 从 ~200MB 降到几 MB、通用可直接播放/分享。
  - **移动端**：当前自编 ffmpeg-kit **min**（AAR 实测 configuration 无 `--enable-gpl/--enable-libx264/--enable-mediacodec`，只 `--enable-v4l2-m2m`，`libx264`/`h264_mediacodec` 符号=0，仅 `h264_v4l2m2m` 但 Android app 沙箱基本打不开 V4L2 M2M 节点、不可靠）→ h264 在编码器 init 即快速失败 → 回退 mjpeg/.mov（保持旧行为不破坏）。**重建带 libx264 的 AAR/xcframework 落地后，h264 自动成功切 .mp4，无需再改 Dart**（能力由「合成是否真成功」判定，绕开 ffmpeg-kit `-encoders` 输出捕获不可靠）。刷新过期 D-CODEC 顶部注释。
- **[x] ② 已加自动化测试** — `audiobook_clip_synth_test.dart`：`h264=true switches to libx264 + crf + yuv420p + faststart` 与 `seq h264=true uses libx264 (interframe compression) + faststart`（断言 libx264/crf/yuv420p/faststart，不掺 mjpeg qscale/yuvj*，序列帧仍 -framerate 非 -loop 1）；默认 mjpeg 守卫保持绿。`audiobook_clip_vertical_webview_guard_test.dart`：`BUG-809: caller tries h264/.mp4 then falls back to mjpeg/.mov`（守卫 mp4/mov 双候选 + `_synthClipWithCodecFallback` + h264:true 先于 h264:false + mime 跟随产出后缀）。
- **备注**：移动端要真正输出 h264/.mp4 需重建 ffmpeg-kit 二进制，**用户已定走 libx264（GPL）**；重建配置见 [docs/agent/build.md](../agent/build.md) 的「移动端 ffmpeg-kit h264 重建」。体积代价：vendored AAR 20.75MB→约 25~28MB，用户 APK 按 ABI split 实际增量约 +1.5~2.5MB。真机复测：桌面导出 `.mp4` 几 MB 任意播放器可开；重建后移动端导出也应为 `.mp4`。与 BUG-808 同批。
