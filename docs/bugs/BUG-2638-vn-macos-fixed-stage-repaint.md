## BUG-2638 · macOS VN 切屏后新屏文字只画在旧屏文字框内（竖排 fixed stage 重绘区域错误）
- **报告**：2026-09-23（用户：macOS 录屏 `iShot_2026-09-22_22.47.07.mp4`，「视觉小说显示模式还有 bug」——竖排 VN 翻到下一屏后，各列字形被竖着切掉半边、首尾列整列不见，鼠标划过/查词后才补全）
- **真实性**：✅ 真 bug。逐帧看录屏：切屏是瞬间完成的（无逐字渐显），新屏只在**上一屏文字框**那块区域里被画出来——「うまかった」」单列之后的两列新屏只剩夹在旧列框里的中段，框外一片黑；停留数秒不自愈，直到查词高亮等无关重绘。根因是 macOS WebKit 的重绘失效：VN 舞台 `.fushi-vn-stage` 是 `position: fixed`（`fushi/lib/src/reader/reader_content_styles.dart:1135` 修前），WebKit 把它单独合成一层；`renderScreen`（`fushi/lib/src/reader/reader_visual_novel_scripts.dart:2568` `replaceChildren` + 新 `.fushi-vn-content`）让竖排内容盒尺寸变化时，这一层只失效旧内容盒的矩形，新列落在旧框外的部分不重绘。真机 WKWebView 探针（生产引擎 `engineShell(vnMode:true)` + 生产 CSS 生成器输出，离屏渲染 `WKWebView.layer` 的真实后备存储 vs `takeSnapshot` 重新渲染，逐屏像素比对）稳定复现：fixed 舞台 8 屏里第 5、6 屏（「うまかった」」→ 两列新屏、→ 五列长屏）后备存储与真值差 1494 / 1621 像素，连跑三次数值一致。二分：横排、内容盒铺满屏、`.fushi-vn-screen` 单独 `will-change: transform`、舞台改 `absolute` 都 0/8；去掉 flex 居中、去掉 `max-*` 不影响。渐显速度 > 0 时逐字揭示本身每字都重绘，所以只在瞬间切屏的路径上显形（渐显 0、往回翻屏 `renderScreen(i, true)`、refit / 样式重锚落屏）。Windows WebView2 与 Playwright WebKit（WinCairo）不复现。
- **[x] ① 已修复** — `.fushi-vn-stage` 改 `position: absolute`（`inset: 0` 不变）。VN 文档从不滚动：初始化时 body 被清空只挂舞台（`reader_visual_novel_scripts.dart:1037` / `:1071`），整章在游离的 `sourceRoot` 里，`html, body` 为 `100vw × 100vh` + `overflow: hidden`，所以 absolute 的包含块就是视口，几何与 fixed 完全相同（探针里各屏 `.fushi-vn-content` 矩形逐屏一致）；量尺 `createScreenMeasurement` 仍是 fixed 子元素、按视口坐标放置，不受影响。改后用生产生成器重新产出的 CSS 在真 WKWebView 上两轮 0/8。提交 `fix(reader): stop macOS VN screen swaps painting only the old text box (BUG-2638)`（PR 分支 `pr/vn-reveal-repaint`）。
- **[x] ② 已加自动化测试** — `fushi/test/reader/vn_stage_positioning_bug2638_test.dart`：macOS / iOS / Android / Windows × 竖排 / 横排 8 例，锁生成器输出的 `.fushi-vn-stage` 为 `position: absolute !important`、不含 `position: fixed`，并锁 absolute≡fixed 的前提（`html, body` 100vw / 100vh / overflow hidden）。修前代码上 8 例全红。像素层行为只能在真 WKWebView 上验，CI 无 WebKit 合成。
- **备注**：真机探针是一个 Swift 小程序（`WKWebView` + 关掉 `_setWindowOcclusionDetectionEnabled:` 私有 SPI，否则 Mac 锁屏/熄屏时 `document.hidden=true` 不绘制），每屏 `layer.render(in:)` 取真实后备存储、`takeSnapshot` 取真值；ssh 下 `screencapture` 没有屏幕录制授权取不到像素，这是本机能拿到「屏上实际画了什么」的唯一办法。未在 Fushi app 本体里复测（app 内能用的 `captureReaderWebView` 走 `takeSnapshot`，本身就会重新渲染、看不到这类失效），由用户在 Mac 上确认。
