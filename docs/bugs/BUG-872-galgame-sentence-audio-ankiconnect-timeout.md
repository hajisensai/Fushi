## BUG-872 · Galgame SentenceAudio upload times out and creates an incomplete Anki card
- **报告**：2026-07-18（用户实测，note `1784350464159`）
- **真实性**：✅ 真 bug。日志显示音频捕获成功（`hasSentenceAudio=true`，导出约 0.68 秒），但 `AnkiConnectRepository._storeLocalMedia` 向 `localhost:8765` 上传时超时/被拒；代码捕获异常后返回 `null`，仍继续 `addNote`，因此 `Sentence` 正常而 `SentenceAudio` 为空（`packages/hibiki_anki/lib/src/ankiconnect/ankiconnect_repository.dart:399`）。WASAPI 原始导出为 48 kHz/32-bit float/双声道，6.55 秒 WAV 已达 2,515,268 bytes，单独 AnkiConnect 上传实测约 6.17 秒；同时发起查重、句音频、词音频和词典图片请求会突破 10 秒预算并挤满连接。
- **[x] ① 已修复** — `hibiki/windows/runner/process_audio_capture.cpp:83` 只在片段导出阶段把常见 WASAPI stereo float32 下混为 mono PCM16，再由 Windows Media Foundation 编码为 48 kbps MP3；系统编码器失败时写入同名 `.wav` 并返回真实回退路径。`packages/hibiki_anki/lib/src/ankiconnect/ankiconnect_service.dart:70` 将真实 AnkiConnect transport 限制为单连接排队；`packages/hibiki_anki/lib/src/ankiconnect/ankiconnect_repository.dart:407` 优先上传必需的句子音频，上传失败直接终止制卡/更新，不再生成缺音频的半成品卡。
- **[x] ② 已加自动化测试** — `packages/hibiki_anki/test/media_filename_guard_test.dart:159` 覆盖句子音频先于可选词音频上传，以及句子音频超时时不调用 `addNote`；`packages/hibiki_anki/test/ankiconnect_service_test.dart:324` 用本地 HTTP server 证明默认 transport 的并发请求实际串行。`hibiki_anki` 全量 175 项、主应用 Galgame/剪贴板定向 54 项均通过，`flutter analyze --no-pub` 零问题；Windows debug 构建成功，真实进程音频 smoke test 输出 48 kHz/mono/48 kbps MP3，1.512 秒文件为 9,503 bytes。该文件经真实 AnkiConnect 上传耗时 637 ms，读取回传字节一致，探测媒体随后删除。
- **备注**：失败卡 `1784350464159` 仅作为修复前证据；修复成功必须用后续新 note 验证 `SentenceAudio` 为 `[sound:hibiki_audio_....mp3]`（仅 Media Foundation 编码不可用时允许 `.wav` 回退）。
