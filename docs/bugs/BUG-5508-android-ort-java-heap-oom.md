## BUG-5508 · Android 跑 OCR / ASR 时 Java 堆 OOM 连环闪退
- **报告**：2026-11-26（反馈 U9mp42sAAL（主）/ GkWWJ02V3S / 2ML9ck1-Kj：3.4.0，Xiaomi 24129PN74C 一小时连崩 6 次、Samsung SM-S928U 2 次，全是 `java.lang.OutOfMemoryError`，growth limit 256 MB 用尽）
- **真实性**：✅ 真 bug。崩溃栈直接落在 vendored flutter_onnxruntime 的 Android 端：`OnnxTensor.createTensor → OrtUtil.prepareBuffer → ByteBuffer.allocateDirect`（9 MB）与 `onMethodCall → result.success → StandardMessageCodec.writeFloat → ByteArrayOutputStream.grow`（4 MB）；其余几次（主线程回包解码、inappwebview `invokeMethod`）是堆已被占满后的受害者。根因：插件经 MethodChannel 搬张量，每个张量在 Java 堆里存 2～5 份——`third_party/flutter_onnxruntime/android/src/main/kotlin/com/masicai/flutteronnxruntime/FlutterOnnxruntimePlugin.kt` 的 `createOrtValue`（codec 先把 Dart `Float32List` 解成 `FloatArray`，`OnnxTensor.createTensor(FloatBuffer.wrap(...))` 再拷进 direct buffer；**Android 上 `allocateDirect` 就是 Java 堆数组**（`VMRuntime.newNonMovableArray`），且存活到 `releaseOrtValue`），`getOrtValueData`（`tensor.floatBuffer` 是一份堆拷贝、再 `FloatArray` 一份、`StandardMessageCodec` 写进成倍扩容的 `ByteArrayOutputStream`、回包再 `allocateDirect` 一份）。消费方 `fushi/lib/src/onnx/onnx_inference_ort.dart` 的 `_toOrtValue` / `_readAsFloat32`（OCR 检测 / 识别、ASR 编解码每步都走）。
- **[x] ① 已修复** — 按「FFI 大块数据不逐元素、传指针」从结构上改数据通路（PATCHES.md delta 19）：Android 上数值张量只过地址。输入：`OrtValue.fromList`（float32 / int32 / int64 / uint8）在 Dart 侧 `malloc` 拷一份，调 `createOrtValueFromAddress`，插件经新 JNI 库 `libflutter_onnxruntime_jni.so` 的 `NewDirectByteBuffer` 包成 direct buffer，ORT 零拷贝读（`OrtUtil.prepareBuffer` 对 direct buffer 不再拷）；这块内存归 Dart 的 `OrtValue`，`releaseOrtValue` 返回后才 free。输出：`asFlattenedList` / `asList`（float32 / int32 / int64 / uint8 / int8）调 `getOrtValueAddress`，插件给出 ORT 张量自己的内存地址（私有 `OnnxTensor.getBuffer()` 反射 + JNI `GetDirectBufferAddress`，consumer ProGuard 规则保名），Dart 在 dispose 前直接拷进 typed list。Java 堆里不再有任何张量数据。float16 / bool / string 与 `convertOrtValue` 保留 codec 路径（没有调用方用它们搬大张量）；Linux / Windows 不受 Java 堆限制，保持原路径。
- **[x] ② 已加自动化测试** — `fushi/test/onnx/onnxruntime_android_native_tensor_memory_test.dart`：走真实 method channel（mock native 回包），Android 上 float32 / int64 / int32 / uint8 输入只发地址、插件按地址读到的就是原数据、`releaseOrtValue` 那一刻内存仍有效；`OrtOnnxSessionFactory` 建的 `OnnxSession.run` 整轮不出现 `createOrtValue` / `getOrtValueData`、输出值正确且输入输出全部释放；float16 回落 codec 路径；多维 `asList` 重排；非 Android 平台照旧走 list；Kotlin / JNI C / gradle / consumer 规则的源码守卫。
- **备注**：未在真机复测原始崩溃路径（需要同型号 + 同一批漫画 / 有声书负载）；Java 堆里若还有别的大户（崩溃日志里 inappwebview 的 2.4 MB 回包解码），本修复不覆盖，复发时先抓 hprof 看占用。`gradlew :app:assembleRelease` 需在合并前补跑一次以验证 JNI 库与 consumer 规则进包。
