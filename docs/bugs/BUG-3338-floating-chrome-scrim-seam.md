## BUG-3338 · 库页外壳页签胶囊下方横穿一条细线（浮动工具区两层遮罩接缝叠加）
- **报告**：2026-10-14（用户：视频 › 媒体服务器等 M3E 浮动顶栏库页，外壳页签胶囊正下方有一条贯穿的水平细线，暗色主题下明显）
- **真实性**：✅ 真 bug。根因在 `fushi/lib/src/utils/components/fushi_floating_chrome.dart`，修复前（upstream/develop `f82cd7d1e9`）的两处：
  1. `_FushiFloatingChromeOverlayState.build` 中外层遮罩在「下面还接着嵌套工具行」时传 `fadeExtent: 1`（原 :817–821），而 `FushiTopFadeScrim.build` 用 `math.max(1.0, fadeExtent)`（原 :914）把渐隐段下限钳在 1 px，所以外层在接缝处一定会多画一条 0.72 → 0 的渐变。这一条正好叠在嵌套层顶端 0.72 的薄纱上（嵌套层 `Positioned(top: outer * shown)` 从同一个 y 起画），合成后比上下都深。
  2. 接缝 y = 外壳页签实测高度 × 弹簧值，常常不在物理像素格上。两块渐变矩形的抗锯齿边会各盖半个像素，即使去掉第 1 条，接缝处仍会叠出一条比薄纱浅的亮缝。
  像素证据（widget 测试真实像素，暗色页面底 #121212、均匀白色内容，中线一列 G 通道）：薄纱区稳定在 84，修复前接缝处 DPR 1.0 第 56 行为 58、DPR 1.25 第 70/71 行为 60/80、DPR 1.5 第 84/85 行为 64/67（暗线）。只去掉 1 px 渐隐、不做像素对齐时，接缝处为 112/114/112（亮缝）。两处修改都做了之后，整列单调不减。
- **[x] ① 已修复** — `e7995fd4f7`：`FushiTopFadeScrim` 允许 `fadeExtent: 0`（在肩段末端硬停，见 :930–932）；下面还有嵌套工具行时外层传 0（:831）；外层终点与嵌套层起点用同一个 `snap` 对齐到物理像素格，两层恰好拼接，不叠也不留缝。BUG-3132 / BUG-3283 的约束保持不变：嵌套层只画自己那一段、收起时不画，外层不盖住嵌套工具行。
- **[x] ② 已加自动化测试** — `e7995fd4f7`：`fushi/test/widgets/fushi_floating_chrome_scrim_seam_test.dart`，DPR 1.0 / 1.25 / 1.5 各一条，外壳 + 嵌套工具区高度都取小数，用真实像素断言亮度自上而下单调不减；修复前 3 条全红，修复后全绿。
- **备注**：像素对齐是在本层局部坐标里做的，前提是两层 overlay 的原点重合且落在像素格上（库页里两层都铺满同一 body，原点是同一点）。如果将来 overlay 原点本身落在小数物理像素上，亮缝仍可能以亚像素强度出现。
