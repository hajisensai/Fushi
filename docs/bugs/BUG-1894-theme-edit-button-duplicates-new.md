## BUG-1894 · 主题行铅笔按钮在无活跃自定义主题时退化成第二个新建入口
- **报告**：2026-08-27（用户：截图圈出外观设置「主题」行末尾的「+」卡片和铅笔按钮，问「这俩玩意是不是功能重合了」）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/settings/settings_actions.dart:426`（修复前）——铅笔按钮的 `onTap` 取 `appModel.activeCustomThemeEntry?.id` 后**无条件** `pushSettingsPage(CustomThemePage(themeId: activeId))`。当前活跃主题不是自定义主题（系统主题 / 任一预设主题）时 `activeId == null`，该调用与右侧「+」卡片的 `CustomThemePage()` 空草稿路径逐字节等价：同一行里两个相邻按钮行为完全相同，其中一个还挂着 `Icons.edit_outlined`「编辑」图标去做新建，与 tooltip `t.edit_custom_theme` 直接矛盾。
- **[x] ① 已修复** — 承认「没有可编辑对象」这个状态而不是给它编一个回落目标：把活跃自定义主题 id 提到 `buildThemeSelector` 顶部算一次，铅笔按钮加 `enabled: activeCustomThemeId != null`。`FushiIconButton` 的禁用态三条路径齐全（图标走 `disabledColor`、`InkWell.onTap` 置 null、`FushiFocusTarget(enabled: false)` 把它摘出焦点/手柄遍历），于是无活跃自定义主题时它既点不动也走不到，新建入口唯一收敛回「+」卡片。提交 `<pending>`。
- **[x] ② 已加自动化测试** — 两层：
  - **行为层（主力）**：`fushi/test/pages/custom_theme_page_draft_no_persist_test.dart` 里原有用例 `edit button on a preset theme ... opens a draft, no upsert` 正是 BUG-1841 顺手把这个回落固化下来的地方，现改写为 `BUG-1894: edit button is disabled on a preset theme ...`：用既有的 `_RecordingAppModel`（`themeKey: 'light-theme'`）驱动真 swatch 行，断言编辑按钮的 `InkWell.onTap` 为 null、点击后 `CustomThemePage` **不被 push**、`upserts` 仍为空。BUG-1841 真正要守的「不得预先落库」不变式原样保留。
  - **源码扫描层**：`fushi/test/settings/multi_custom_theme_swatch_guard_test.dart` 新增 3 条：`enabled: activeCustomThemeId != null` 门存在、活跃 id 只在顶部解析一次（且旧的行内 `final String? activeId =` 不得回来）、**全文件 `const CustomThemePage()` 空草稿构造恰好出现一次**。最后一条覆盖行为测试够不到的面：防的是**别处**再长出第二个空草稿入口。
- **备注**：swatch 行的 widget 级测试需要整个 AppModel/InAppWebView 栈，故沿用该文件既有的源码扫描守卫形态（文件头注释已说明这一取舍）。鼠标/触摸用户编辑任意自定义主题仍走「长按该卡片」（`onLongPress` → `CustomThemePage(themeId: e.id)`，未改动）；焦点/手柄用户仍走「先切到某个自定义主题、再按铅笔」这条既有路径——本次只消除重合与图标语义矛盾，不改焦点模型（在 48px 卡片内嵌第二个焦点节点会污染 `FushiFocusController` 的几何方向导航，左右键会落到角标而非邻卡）。
