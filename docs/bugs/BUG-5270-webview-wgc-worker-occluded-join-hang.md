## BUG-5270 · 显示器关着时关掉带 WebView 的页面，Windows app 整个卡死（WGC 取帧线程 join 不回）
- **报告**：2026-11-23（代理：镜台 Flutter GPU 观察 itest `music_diorama_gpu_observe_itest.dart` 收尾 `nav.pop()` 后 `tester.pump` 永不返回，diorama-gpu-6/7/9 都卡在同一处，最长 1.5 h）
- **真实性**：✅ 真 bug，与歌词动画 / 镜台 / 音频分析无关。证据（复现 run `hang-wd-4`，夜间显示器已休眠）：
  - 看门狗打点：`pop` 后第 0～2 次 `pump` 正常返回，第 3 次（出栈转场结束、歌词页里查词弹窗的 WebView 被销毁）起 Dart 侧再无任何输出，连 3 s 周期 Timer 都不再触发——整条平台线程（与 Dart UI 线程合并）被同步阻塞。
  - cdb 线程栈：主线程 `InAppWebViewManager::HandleMethodCall`（dispose）→ `~CustomPlatformView` → `TextureBridge::Stop` → `StopFrameWorkerLocked` → `std::thread::join`（`packages/flutter_inappwebview_windows/windows/custom_platform_view/texture_bridge.cc` `StopFrameWorkerLocked` 里 `lifetime->worker.join()`）；取帧线程 `fushi-wgc-frames` 在 `RunFrameWorker` → `FrameClock::Wait` → `NtDCompositionWaitForCompositorClock`，`!runaway` 显示它已吃掉 16 s 用户态 CPU（在空转）。`wgc_capture.log` 有 `worker-stop-start`、没有 `worker-stop-joined`。
  - 根因：旧 `FrameClock::Wait`（原在 `texture_bridge.cc`，BUG-4114 引入）把 `DCompositionWaitForCompositorClock` 除 `WAIT_OBJECT_0` / `WAIT_FAILED` 以外的返回值一律当「节拍」。显示器关着（合成被遮挡）时这个函数**立刻**返回 NTSTATUS `STATUS_GRAPHICS_PRESENT_OCCLUDED`（0xC01E0006），**不等也不看传进去的停止事件**——独立探针实测：停止事件未置位 / 已置位两种情况都 0 ms 返回 0xC01E0006。于是取帧线程忙等占满一个核、永远看不到停止信号，平台线程 join 它就此卡死；Flutter 不再出帧，用户可见为整个 app 冻住（任何带 WebView 的页面在熄屏 / 锁屏后关闭都会中）。
- **[x] ① 已修复** — 节拍抽到 `packages/flutter_inappwebview_windows/windows/custom_platform_view/frame_clock.h`：`ClassifyCompositorWait` 把返回值分为停止 / 节拍（`WAIT_OBJECT_0 + count`、`WAIT_TIMEOUT`）/ 时钟没走（其它任何状态码）/ `WAIT_FAILED`；「时钟没走」时自己按一个 DWM 刷新间隔 `WaitForSingleObject(stop_event)`（`frame_clock.h` `case CompositorWaitOutcome::kClockUnavailable` → `WaitStopFor(IntervalMs())`），既不空转，停止请求也在一个刷新间隔内被看到；时钟恢复后照常用合成器时钟。进出「时钟没走」各记一行 `worker-clock-unavailable` / `worker-clock-resumed`。
- **[x] ② 已加自动化测试** — `packages/flutter_inappwebview_windows/windows/test/frame_clock_test.cpp`（`powershell -ExecutionPolicy Bypass -File tool/run_webview_frame_clock_test.ps1`）：替身合成器时钟恒返回 0xC01E0006，断言不空转、置位停止事件后 `Wait` 返回 false、与 `RunFrameWorker` 同形的线程在 2 s 内可 join；外加真实时钟置位停止后必须返回 false。旧行为下 4 项红（含 join 卡死）、修复后 13 项全绿。源码守卫 `fushi/test/widgets/wgc_pump_interval_guard_test.dart` 新增「时钟没走必须改等停止事件」一条，`texture_bridge_stop_guard_test.dart` 改读 `frame_clock.h`。端到端：`music_diorama_gpu_observe_itest.dart` 收尾不再吞超时 / 异常（任一步失败用例即失败）。
- **备注**：itest 收尾原本每步 `timeout` 后只打一行 `TIMEOUT` 就继续，用例照样算过，属掩盖；已改为收集失败并在收尾末尾 `expect(cleanupFailures, isEmpty)`。
