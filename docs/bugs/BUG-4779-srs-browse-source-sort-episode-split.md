## BUG-4779 · 复习卡浏览按出处列排序时同一部番的笔记被别作同名集拆散，与出处视图的集顺序不一致
- **报告**：2026-11-17（用户：PR #3574 合入后的只读核实遗留项「出处视图里同一系列各集的排序口径不一致」）
- **真实性**：✅ 真 bug。根因：`native/fushi_fsrs/src/store/browse.rs:2363-2367`（修前行号，origin/develop f25fcb3819）按出处列排序的行键 `Key::Source` 取的是**本条笔记自己**的 `source_title`，`cmp_keys`（修前 :1300-1312）先比系列键、再 `cmp_episode(标题, 作品键)`；而出处视图 `children`（修前 :2588-2601）用 `SourceGroup.data`（组里最近添加那条笔记）的标题排。`source_item_key` 对 `onlineVideo` 取 `sourceId`+`animeUrl`（:349-350），是整部番的身份，同一作品键下各笔记标题就是各自的集名，于是两部番的同名集（如都叫 `Ep 1`）在排序结果里挨在一起，同一部番的行被拆散，与出处视图里「同一集挨着」的顺序对不上。另外 `SourceGroup::add` 在添加时刻相同时取遍历中先到的那条，代表出处随行顺序变。
- **[x] ① 已修复** — 两边共用一个「集代表笔记」口径：新增 `newer_note`（`browse.rs:379`，最近添加优先、同刻按笔记 id 小者优先，与遍历先后无关），`SourceGroup::add` 改用它；新增 `episode_titles`（`browse.rs:390`），按出处列排序前对结果各行一次算出每个 (系列键, 作品键) 的代表标题（与 `children` 在各自系列里选代表一致；PR #3653 审查补上系列键，提交 38e982f011），`Key::Source` 增加 `own` 字段，行键改为 (系列键, 集代表标题, 作品键, 本条标题)（`browse.rs:2415` 起），同一作品键的行连在一起、作品之间的先后与 `children` 一致。提交 7c29004440。
- **[x] ② 已加自动化测试** — `native/fushi_fsrs/src/store/browse.rs` `browse_source_sort_keeps_item_rows_together_like_children`：同一在线视频作品下两条笔记标题不同（`Ep 2` / `Ep 1`），另一作品有一条 `Ep 1`，断言 `children` 顺序与升 / 降序排序结果一致、同作品的行挨着。把行键改回本条标题后该用例红（`left: [a4, a5, a3]`），另有 `browse_source_sort_episode_title_stays_within_its_series`（同一作品分在两个系列，代表标题不跨系列借用；只按作品键选代表时红）。修后 `cargo test --profile quick --lib store::browse` 23 条全绿。
- **备注**：纯内核排序逻辑，无设备相关路径；真机未复测。
