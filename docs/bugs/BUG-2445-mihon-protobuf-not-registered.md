## BUG-2445 · Injekt 未注册 ProtoBuf 导致 5 个 protobuf 漫画源整源不可用
- **报告**：2026-09-11（用户：很多扩展打不开，要求全量测试一遍扩展。127 个已装扩展逐个走 `sourcesManga → 各源 getPopularManga → search/filters → details → chapters → pages` 后归类得出。）
- **真实性**：✅ 真 bug。根因 `third_party/m_extension_server/upstream_src/server/src/main/kotlin/eu/kanade/tachiyomi/AppModule.kt:31`：上游 `AppModule` 只 `addSingletonFactory { Json { ... } }`，从未注册 `ProtoBuf`。扩展和取 `Json` 一样在静态初始化器里 `Injekt.get<ProtoBuf>()`，于是类初始化失败，桥上看到的是**不带原因**的 `ExceptionInInitializerError`（MangaMee 是后续调用的 `NoClassDefFoundError: Could not initialize class j0`），真凶只在 sidecar 日志里：`Caused by: uy.kohesive.injekt.api.InjektionException: No registered instance or factory for type class kotlinx.serialization.protobuf.ProtoBuf`。依赖本身早就在 classpath 上（`upstream_src/gradle/libs.versions.toml:25/135/162` 的 bundle），缺的只有注册这一行。
- **受影响扩展（实测，127 个中的 5 个）**：Zebrack、Manga One、Corocoro Online、Zerosum Online（四个在第一次 `getPopularManga` 就死，整源不可用）、MangaMee（`getDetailsManga` 死）。五份 sidecar 日志的 `Caused by` 完全一致。
- **[x] ① 已修复** — `d6f386a270`。新增 overlay `third_party/m_extension_server/overlay/server/src/main/kotlin/eu/kanade/tachiyomi/AppModule.kt`，在 `Json` 旁边 `addSingletonFactory<ProtoBuf> { ProtoBuf }`。**类型参数必须显式**：`ProtoBuf` 是 companion object，交给推断会注册成 `ProtoBuf.Default`，扩展按 `ProtoBuf` 取照样 `InjektionException`——新测试第一次跑就是这么红的。注册的是默认实例，与 Mihon 官方一致（扩展是按那个行为编译的）。
- **[x] ② 已加自动化测试** — `d6f386a270`，`third_party/m_extension_server/overlay/server/src/test/kotlin/eu/kanade/tachiyomi/AppModuleTest.kt`：用真实 `InjektScope(DefaultRegistrar())` 导入 `AppModule`，断言 `Json` 与 `ProtoBuf` 都能解析。该用例在未注册和「注册成 `ProtoBuf.Default`」两种形态下都会红（后者是实跑撞到的）。完整 JVM 套件 57 项 0 失败。
- **验收**：待新 jar 对这 5 个扩展重跑（见同批扫描 `sweep-retry`）。
- **备注**：`third_party/m_extension_server/UPSTREAM` 的 overlay 清单与修改说明已同步。`upstream_src` 保持 pristine。
