## BUG-686 · 互联同步书籍进度后书架不刷新(收端显示旧进度·观感=书籍没同步·有声书resume现读故正常)
- **报告**：2026-07-09（用户：「书籍进度是不是没同步，有声书进度倒是同步了」，TODO-1369）。
- **真实性**：✅ **真 bug（收端书架不刷新，非传输漏同步）**。沿真实代码路径逐层验真：
  - **传输链无漏同步（BUG-417 已修且在用户构建里）**：用户后端 `sync_backend_type=hibikiServer`（互联 LAN，非云）。互联书籍进度 live 端点 `_syncBookProgressLive`（`hibiki/lib/src/sync/sync_orchestrator.dart:572`）→ client `remoteBookProgress`/`putRemoteBookProgress`（`hibiki_client_sync_backend.dart:762/783`）→ server `/api/library/books/<key>/progress`（`hibiki_sync_server.dart:1163`，reqPath 经 `Uri.decodeFull` 解 CJK）→ host `getBookProgress`/`putBookProgress`（`app_model_library_host_service.dart:305/323`，直读写 host 自己的 `reader_positions`）四层全对；与有声书 `_syncAudiobookProgressLive` 结构对称、共用 bookKey 身份。现有测试 `sync_orchestrator_live_progress_test.dart` 12 例往返全绿。且 `git diff 2b2cf0b8b(用户 debug.6783/+513) origin/develop` 显示 `_syncBookProgressLive`/`putBookProgress` **函数体完全相同**——用户构建就含此修复、非晚落地。故**不是**书籍进度没进同步载荷。
  - **真根因＝收端书架 provider 不 invalidate**（airtight）：`_syncBookProgressLive` 把 host 更新的进度 upsert 进本地 `reader_positions`（`sync_orchestrator.dart:608-616` 的 host→local pull 块），但**不置任何 report 计数**；`SyncRunReport.needsLocalLibraryRefresh`（`sync_orchestrator.dart:123`）只看 `booksImported/dictionariesImported/audiobooksImported/localAudioImported`，**不含进度 pull**；`AppModel.refreshAfterSyncRun`（`hibiki/lib/src/models/app_model.dart:468`）在 `!needsLocalLibraryRefresh` 时**提前 return**，且刷新书架 tab（`ReaderMediaType.instance.refreshTab()` `:478`）只在 `booksImported||audiobooksImported` 时触发。书架 `hibikiBooksProvider` 是 **cached `FutureProvider.family`**（`reader_hibiki_source.dart:23`，非 Drift `.watch()`），只在 `ref.invalidate` 时重读 `reader_positions`→`computeBookProgress`→进度条。→ 进度只进了 DB，书架仍显同步前的旧进度条，直到 app 重启/tab 被别的原因 invalidate。用户观感＝「书籍进度没同步」。
  - **为何“有声书倒是同步了”**：有声书播放位置 `_syncAudiobookProgressLive` 同样不刷新书架，但用户是靠**打开书 resume 播放**来判断——resume 在起播时**现读** `audiobook_pos_<bookKey>` pref（不依赖书架缓存），故看着“同步了”。书籍阅读进度则主要由书架进度条呈现（缓存快照），于是同一份“进度只进 DB 不刷 UI”的缺口在两者上呈现为不对称观感。
  - **旁注（与 BUG-680 区分）**：用户最后安装仍是 debug.6783（`updates/…6783…install.log` mtime 07-06 21:22，无更新包），该旧包另有 BUG-680 的 `computeBookProgress` 显示缺陷；本 bug 是**当前 develop 仍存在**的书架刷新缺口（与旧包无关），用户升级后本修复才生效。
- **[x] ① 已修复** — 让「书籍进度 host→local pull」像内容导入一样标记书架刷新（根因修复，非补丁掩盖）：
  - `SyncRunReport` 新增 `int localBookProgressPulled`，`_syncBookProgressLive` 在 host-newer pull 的 upsert 后 `report.localBookProgressPulled++`（`sync_orchestrator.dart`）；纯 push（本地更新，无本地变更）不置位。
  - `SyncRunReport.needsLocalLibraryRefresh` 纳入 `localBookProgressPulled > 0`；`AppModel.refreshAfterSyncRun` 的书架 tab 刷新条件加 `|| report.localBookProgressPulled > 0`（`app_model.dart`）→ 收端拉到新书籍进度后 `hibikiBooksProvider` 被 invalidate、书架进度条即时更新。
  - 范围：只修书籍进度侧（用户报的书架进度条）；视频进度在独立视频 tab、有声书位置靠 resume 现读，本次不扩范围（同类缺口在别 tab，属独立 follow-up，避免风险与 gold-plating）。
- **[x] ② 已加自动化测试** — `hibiki/test/sync/sync_orchestrator_live_progress_test.dart` 新增组「book progress pull flags shelf refresh (BUG-686)」（真服务器/host DB/client backend/本地 DB 往返）：
  - host-newer pull → `report.localBookProgressPulled==1` 且 `report.needsLocalLibraryRefresh==true`（锁死「进度落 DB 且标记刷新」）；
  - 纯 push（本地更新）→ `localBookProgressPulled==0` 且 `needsLocalLibraryRefresh==false`（不做无谓刷新）。
  - `flutter analyze lib test` No issues；`flutter test test/sync/{orchestrator_live_progress,gating,orchestrator_conflict,host_service_book_progress,summary}` 全绿（无回归）。
