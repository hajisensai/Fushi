## BUG-4276 · Android controller D-pad reaches Dart as keyboard arrows (lookup mode / panel drive ignore it)
- **报告**：2026-11-08（双屏副屏真机巡检：AYN Thor，按住 L1 查词模式 / 按住 R1 驱动副屏时方向键照常翻页，L1 / R1 / A / B / Y 都正常被截获）
- **真实性**：✅ 真 bug，三处：
  - 设备类型丢失（develop 同样存在）：真机日志 `MainActivity.dispatchKeyEvent` 把手柄 source 0x501 收窄成 0x401（`ControllerKeySource`），引擎 `KeyEmbedderResponder` 也把 kGamepad 写进 key data 包，但 Flutter 3.47.6 dart:ui `PlatformDispatcher._unpackKeyData`（`bin/cache/pkg/sky_engine/lib/ui/platform_dispatcher.dart`，上游 master 2026-11 同样）根本不读这个字段，Dart 侧每个 `KeyEvent.deviceType` 都是 keyboard。`GamepadButton.fromKeyEvent`（`fushi/lib/src/shortcuts/input_binding.dart`）只在手柄类设备上认方向键 → `interceptNativeControllerLookupKey`（`gamepad_service.dart`）放行，页面的方向键绑定翻页。A / L1 等是 `gameButton*` 逻辑键、不看设备类型，所以正常。游戏串流页 `_isControllerSource(event.deviceType)` 同病。
  - 帽子键方向键（Thor 手柄的十字键是 `ABS_HAT0X/Y`）在副屏有焦点时：`SecondScreenActivity.dispatchGenericMotionEvent` 把摇杆事件转发给主进程并返回 true；主进程是直接调用 `dispatchGenericMotionEvent`、不经 ViewRootImpl，两边都没有「未消费摇杆事件 → 合成方向键」这一步，方向键整个丢失。
  - 触摸副屏后的第一个方向键被面板窗口的 ViewRootImpl「离开触摸模式」吞掉（`checkForLeavingTouchModeAndConsume`，面板 FlutterView 没有焦点），只剩抬起转发到主屏。
- **[x] ① 已修复** — `fushi/lib/src/shortcuts/key_event_device_type.dart`：外部不可控限制的临时兼容层，`RawKeyboard` 监听器记下同一次按键 raw 消息里的 Android source（框架先通知 raw 监听器、再把该消息的 KeyEvent 派给 HardwareKeyboard 与焦点树），`keyEventDeviceType(event)` 给 `GamepadButton.fromKeyEvent` 与游戏串流页用；清理条件：`_unpackKeyData` 读取设备类型后删除本文件。`SecondScreenActivity`：摇杆事件转发后返回 false，让面板窗口自己合成方向键再按键转发；窗口获得焦点即让 FlutterView 取得焦点。
- **[x] ② 已加自动化测试** — `fushi/test/shortcuts/key_event_device_type_test.dart`：按引擎真实顺序送 key data（设备类型 keyboard）+ raw 消息（source 0x401 / 0x1000010 / 0x301），焦点树早期处理器里手柄 / 帽子键方向键是 `GamepadButton.dpadDown`、键盘方向键不是；另有探测用例在 SDK 的 `_unpackKeyData` 开始读设备类型时变红，提示删兼容层。原生两处无 JVM 层可测（ViewRootImpl 行为），真机复测见双屏进度日志 S7e。
- **备注**：`MainActivity` 本身的「触摸后第一个方向键」同理只在主窗口 FlutterView 尚无焦点时出现（`ensureKeyFocusTarget` 在 `dispatchKeyEvent` 里调用，晚于 ViewRootImpl 的触摸模式阶段），本条未改主窗口。
