## BUG-4278 · 互联 live 进度 PUT 不回结果，client 无条件记基线
- **报告**：2026-11-10（用户：审计 sync-live 修复包 V-C2 / V-C3 / D10 / D11）
- **真实性**：✅ 真 bug。host 侧契约（本条前半，修复前）：
  - `packages/fushi_engine/lib/sync/fushi_sync_server/library.part.dart:285-299`（书进度 `PUT`）、`:615-630`（有声书位置 `PUT`）、`fushi_sync_server/video.part.dart:544-560`（视频位置 `PUT`）一律 `shelf.Response(200)` 空体；
  - `local_library_host_service/{books,audiobooks,videos}.part.dart` 的 `putBookProgress` / `putAudiobookPosition` / `putVideoPosition` 返回 `Future<void>`，被 LWW 拒收、书 / 有声书不在库都静默 no-op，也不接受「期望值」前置条件。
  - 后果：client 收到 200 就只能当作「写成功」记基线（被拒收的也记），且只能按判定时的旧快照盲写，覆盖判定之后第三台设备写下的进度。
  - client 侧（修复前）：`fushi/lib/src/sync/interconnect_playback_position_sync.dart:252-256` `reportLive` 是 `_recordPending → _putRemote → recordBaseline`，`:209-240` `pushLocal`、`interconnect_book_progress_sync.dart:311-350` `pushLocal` 与两处 `alignSynced` 都在 PUT 后无条件记基线；冲突弹窗「本机」（`playback_position_conflict_dialog.dart:98-100`）与对比弹窗（`sync_compare_dialog.dart:1116-1162`）经它们落地后直接计「已解决」。host 拒收（较新戳胜出，V-C3）或判定后被第三台设备改写（V-C2）时，基线照样推进到本机值，下一轮把 host 上别人的进度当成「只 host 动了」静默落回 / 覆盖。
- **[x] ① 修复** — f1cc1956cad（host 侧契约）：`fushi_library_host_service.dart` 新增 `LiveWriteResult`、`LivePositionWriteOutcome` / `LiveBookProgressWriteOutcome`（含 `tryParse`）、可选能力 `LivePositionWriteHost`、`kLiveWriteHeader`，以及 host 写入唯一判定口径 `resolveLivePositionWrite` / `resolveLiveBookProgressWrite`（带前置条件且命中时不按戳拒收、落库戳 = max(上报戳, 已存可信戳 + 1)、毒戳一定改写；无前置条件沿用 LWW 并区分 unchanged / stale）。`LocalLibraryHostService` 实现三个 `*Checked`，旧 `put*` 改为调它们并丢弃回执。三个位置 `PUT` 解析可选 `expectedPositionsMs` / `expected`（格式错 → 400），回 200 / 409 + 回执 JSON + `X-Fushi-Live-Write: 1`；三个位置 `GET` 与批量 `GET /api/library/book-progress` 加同一头。未实现能力的 host 行为不变。
  30d791656e7（client 侧）：`interconnect_sync_backend.dart` 新增 `putLiveVideoPosition` / `putLiveAudiobookPosition` / `putLiveBookProgress`（必带前置条件，返回 `LivePushStatus{confirmed, rejected, superseded}` + host 当前值），能力按 host 身份从位置端点响应头 `X-Fushi-Live-Write` 学习并缓存；未知 / 不支持时先 GET 核对前置条件（不符 → superseded、不发 PUT），旧 host 走兼容层 `PUT` 后再 `GET` 确认，降级（200 空体）清缓存后同样确认。兼容层是外部限制（旧 host 只有 LWW），前置 GET 与 PUT 之间仍有覆盖窗口；清理条件：最低支持的 host 版本都发 `X-Fushi-Live-Write` 后删除。旧 `putRemote*` 一字不改。`pushLocal`（视频 / 有声书 / 书）、`alignSynced`、`reportLive`（返回 `LiveReportResult{confirmed, held}`）只在 confirmed 时对齐本端戳（取 host 写后的戳）并记基线；rejected / superseded 删「待确认」行、不动本端；网络异常照旧保留待确认行（BUG-3528）。`BookProgressSyncStep` 加 `pushed`；冲突弹窗、对比弹窗只计 confirmed。
