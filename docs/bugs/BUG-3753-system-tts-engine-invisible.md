## BUG-3753 · system-tts-engine-invisible
- **报告**：2026-10-24（用户：「Fushi TTS 使用系统语音的时候不能读取系统 TTS 引擎，别的软件是正常的」；要求全平台都做）
- **真实性**：✅ 真 bug，沿真实代码路径确认：
  - Android：`fushi/android/app/src/main/AndroidManifest.xml` 的 `<queries>`（旧 354–378 行）没有 `android.intent.action.TTS_SERVICE`。targetSdk 35 受包可见性限制，第三方 TTS 引擎（讯飞、MultiTTS、商店版谷歌 / 微软……）对 Fushi 不可见；`TtsChannelHandler.java`（旧 83 行）只 `new TextToSpeech(context, listener)` 绑默认引擎——默认引擎恰是第三方引擎时绑不上、回落到别的引擎或初始化失败。别的 app 声明了这条查询，所以「别的软件正常」。
  - 系统语音没有任何引擎 / 声音选择：`system_tts_provider.dart`（旧）的 `params` 为空，`isAvailable` 只有 Android / Windows / Linux。
  - Windows：`desktop_tts.dart`（旧 `_sapiWindows`）每句起一个 PowerShell 调 `System.Speech`（SAPI 5），看不到 OneCore 声音（设置 › 语音里装的语言包声音大多只进 OneCore），且每句付一次 PowerShell 冷启动。
  - macOS：`say` 只出 AIFF（旧 `_sayMacOS`），缓存层只认 WAV / MP3，于是朗读声音体系里没开放 macOS。
  - iOS：没有合成到文件的实现。
- **[x] ① 已修复** —
  - Android：清单 `<queries>` 补 `TTS_SERVICE`；新 `SystemTtsController.java`（`TtsChannelHandler` 委托）：`getEngines`（PackageManager 查 `TTS_SERVICE`，标默认引擎）、`getVoices`（某引擎的已装声音，滤掉 `notInstalled`）、`ttsToFile` 收 `engine` / `voice`；请求排队一次一个，所需引擎不同就关旧实例按包名新建（`new TextToSpeech(ctx, l, engine)`），指定引擎没装直接报 `ENGINE_UNAVAILABLE`（不让 TextToSpeech 悄悄换默认引擎）；实例懒建（`:popup` 进程不常驻）；30 秒看门狗防引擎不回调卡死队列；`destroy` 释放实例并答复排队请求。
  - Windows：`windows_speech_worker.dart` 常驻 PowerShell 5.1 工作进程，WinRT `Windows.Media.SpeechSynthesis`（OneCore，`AsTask` 等待）+ SAPI 5 合并列声音（同名去重），按声音 / 语言合成，WinRT 不可用回落 SAPI。传输走 127.0.0.1 TCP + 随机口令：实测 Dart 写进 PowerShell stdin 的数据只有它首次阻塞读之前那部分能读到。宿主退出（连接断开 / 每秒查宿主 PID）进程自退，空闲 2 分钟发 `exit` 回收，经 `HelperProcessRegistry` 登记。
  - macOS：`say --file-format=WAVE --data-format=LEI16@22050` 直接出 WAV，`say -v ?` 列声音可选。
  - iOS：`ios/Runner/FushiSystemTts.swift`，`AVSpeechSynthesizer.write(_:toBufferCallback:)` 写 16-bit WAV，`speechVoices()` 列声音，错误码与 Android 一致。
  - Linux：列 Open JTalk `.htsvoice`（有辞书才列）与 `espeak-ng --voices`，可点名；espeak-ng 日语声音仍只读纯假名。
  - Dart：`SystemTtsDescriptor` 五端可用；参数「引擎」（仅 Android）+「声音」（都非必填，空 = 以前的按文字语言自动挑），进声音预设；`audioIdentity` 只在选了时带上它们（没选的旧缓存键不变）；点名的声音不在报新原因 `voiceUnavailable`（不悄悄换声音）。设置页声音行通用化：`TtsProvider.listParamOptions` 按参数 key 给选项、非必填参数多一个「自动 / 系统默认引擎」，换引擎清空声音。制卡兜底选一份系统语音预设即用所选声音。
- **[x] ② 已加自动化测试** — `fushi/test/utils/system_tts_voices_test.dart`（各平台原生输出解析、Windows 声音合并去重 / id 往返 / 协议编解码 / 工作进程脚本契约、假工作进程经真回环 socket 验「只起一次 + 按 id 配对 + 口令 + 失败码映射」、Linux 点名声音、预设参数与缓存身份）、`fushi/test/utils/system_tts_test.dart`（引擎 / 声音透传、`VOICE_UNAVAILABLE` 映射、Windows 请求体、`say` 参数）、`fushi/test/build/system_tts_native_guard_test.dart`（清单查询、Java 三条通道、iOS Swift 注册与 pbxproj 四处）、真引擎 `fushi/test/utils/system_tts_real_engine_test.dart`（`FUSHI_REAL_SYSTEM_TTS=1`，Windows / macOS）、设备探针 `fushi/integration_test/system_tts_native_probe_test.dart`（Android / iOS）。
  - 另：系统引擎点了念不了这段文字的声音时会「成功」写出空 WAV（实测 OneCore 英语声音念日文 = 46 字节），`hasAudibleWav` 把这种情况按合成失败报，不交给制卡 / 缓存（测试同文件）。
