## BUG-5156 · 重新生成存量漫画演出时复用旧响度片段（整形版本没进复用判据）
- **报告**：2026-11-22（审计 HBK-AUDIT-038，`docs/reviews/2026-11-21-project-review.md`，PR #3761 引入的裁静音 / 淡变 / 响度归一）
- **真实性**：✅ 真 bug。整卷生成的复用判断 `MangaRenderItem.canReuse`（`packages/fushi_engine/lib/tts/manga_audio/manga_audio_render_plan.dart:133`，调用处 `manga_audio_renderer.dart:253/281`）只比句 ID、文字、声音、种子，清单行也不记音频是按哪套整形参数出的。PR #3761 给合成句与有声书片段加了裁静音 + 淡变 + −18 LUFS 响度归一（`fushi/lib/src/media/manga/audio/manga_audio_render_backend.dart` `_mangaShapeChain`）后，存量演出重生成：旧的真人片段 / 合成句原样沿用（未归一），新出的句子用新处理，同一卷里音量忽大忽小。旁白参考音频（`.manga_narrator/<片段>.wav`）同样只按片段身份命名，整形参数再变时旧参考音频会一直沿用。
- **[x] ① 已修复** — 后端端口 `MangaRenderBackend.shapeVersion` 给出整形版本；app 后端取 `kMangaShapeVersion` = 三个 ffmpeg 参数构造器（合成句 `buildMangaLineEncodeArgs` / 有声书片段 `buildMangaClipArgs` / 旁白参考 `buildMangaNarratorRefArgs`）在固定取样输入下完整输出的 sha1 指纹（`mangaShapeFingerprint`；参数就是版本，拼接前统一采样、整形滤镜、编码改任一项自动变，不靠手动 bump）。清单行新增 `shape` 字段（`MangaRenderedLine.shape`，占位静音记 null），整卷生成、补回、换种子候选（`MangaRegenerateCandidate.shape`）都写入当时的版本；`canReuse` 要求 `old.shape == 当前版本`，历史清单没有该字段 → null → 按版本不符重出（有声书片段重剪、合成句的 TTS 片段还在缓存里时只重新编码、不重跑引擎）。旁白参考音频文件名带上整形版本（`mangaNarratorRefFileName`），版本变了重剪参考音频，Irodori 缓存键含参考路径，合成句随之重出。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/tts/manga_audio/manga_audio_renderer_test.dart`「整形版本（HBK-AUDIT-038）」组：历史清单（行里无 `shape`）有声书片段与合成句都重出并记新版本；现代清单同版本全部沿用、版本变了两种音源都重出；清单 JSON 往返、占位不记版本；补回 / 保留候选写当时版本。变异实测：去掉 `old.shape == shape` 后历史 / 现代两条用例变红。`fushi/test/media/manga/audio/manga_audio_render_app_test.dart` 断言版本指纹格式与旁白参考文件名带版本。
- **备注**：旧版本的旁白参考 WAV 在下次准备旁白时由 `_sweepStaleNarratorRefs` 删掉（TTS 缓存的 `clear` 不进 `.manga_narrator/` 子目录，不删就永远留着），判据 `isStaleMangaNarratorRef` 有单测。
