## BUG-1239 · 全角空格在视频页仍无法播放暂停
- **报告**：2026-07-29（用户：）
- **真实性**：✅ 真 bug —— BUG-853 / BUG-936 的 Dart 回退仍错误假设 IME 空格会以可识别的 `KeyEvent.physicalKey` 到达页面（`hibiki/lib/src/media/video/video_player_shortcuts.dart:254-265`）。Flutter Windows 引擎对 `VK_PROCESSKEY` 明确丢弃原物理/逻辑键身份，框架层只剩 `physicalKey=0 / logicalKey=0`；因此旧谓词要求 `PhysicalKeyboardKey.space` 永远无法命中。Win32 原消息的 `lParam` 仍保留 Space scan code `0x39`，真实可修复边界位于 runner 把消息交给 `HandleTopLevelWindowProc` 之前（`hibiki/windows/runner/flutter_window.cpp:360-376,2244-2260`）。
- **[x] ① 已修复** — runner 在 Flutter 消费消息前只识别「首次按下 + 无 Ctrl/Shift/Alt/Win 修饰 + `wParam==VK_PROCESSKEY` + scan code `0x39`」，经 `app.hibiki/windows_ime_space` 通道通知 Dart且不消费原 Win32 消息；视频页只在当前窗口/全屏视频路由、无文本框焦点时响应，词典浮层可见则只关闭浮层，其余经既有沉浸快捷键门控调用 `playOrPause`（`hibiki/lib/src/platform/windows_ime_space_channel.dart:1-44`；`hibiki/lib/src/pages/implementations/video_hibiki_page.dart:1665-1670,4259-4281`）。普通半角 Space、非 Windows 平台及其它 IME 键保持原路径。修复提交：`5786b2fff`。
- **[x] ② 已加自动化测试** — `hibiki/windows/runner/ime_space_dispatch.cpp` 抽出生产同源 native 谓词/派发缝；`hibiki/windows/runner/tests/ime_space_dispatch_test.cpp` 由 Windows runner 构建门直接编译执行，覆盖 `WM_KEYDOWN`/`WM_KEYUP`、普通 Space、`VK_PROCESSKEY + 0x39`、U+3000 后续 `WM_CHAR`、重复沿、Ctrl/Shift/Alt/LWin/RWin 与单次触发。`hibiki/lib/src/platform/windows_ime_space_dispatch.dart` + `hibiki/test/media/video/video_ime_space_playpause_test.dart` 可执行覆盖当前路由、IME composing/编辑焦点、浮层和沉浸门，定向 Flutter 测试共 13 条全绿。变异验证：`WM_KEYDOWN→WM_KEYUP` 与删除 Alt/Win 过滤均会令 native 门返回非零。测试提交：`f9abcb49d`。
- **备注**：按用户指示未等待 Windows 完整编译/真机验收；已执行 `flutter analyze --no-pub` 全量静态分析与上述定向回归。设备复测仍应覆盖 Windows 微软日文/中文 IME 的全角模式下，窗口与全屏视频各按一次 Space 可稳定暂停/继续。
