## BUG-4455 · 远端任务客户端不区分观测失败与任务失败：瞬时断网即删除 host 任务、清理失败当任务失败、观测可被卡住的响应体永久挂起
- **报告**：2026-11-10（互联远程长任务审查 V-D2、R13 client 侧、R8 job client 响应体无超时）
- **真实性**：✅ 真 bug。`fushi/lib/src/sync/interconnect_job_client.dart`（修复前，`1c136483d0c`）：`run()` `:232-406` 把 create→upload→start→poll→result 当成一个 try；`:316-318` 任一次状态 GET 抛出（超时、socket、TLS 抖动、移动端被挂起）都落到 `:390-396` 的 catch → `addError` + `cleanupRemote()` → DELETE，host 上跑了一小时的任务被 client 自己删掉；任务已不在 host（404）也照样补发 DELETE。`:341` 产物全部下载成功后用会抛异常的 `_send` 发 DELETE，DELETE 超时 / 4xx / 5xx 就把已落盘的结果报成任务失败。`:531-533` `.timeout` 只包 `client.send(req)`，`http.Response.fromStream` 在外面：对端发完响应头卡住响应体时 GET 永不返回；`_upload` `:558-567` 读错误体 / drain 同样无上界。修复前新测试实测四例全红：首个 `SocketException` 直接报错、404 后发了 DELETE、清理回 503 时以 `http_503` 报错、卡住的响应体让整条流 10 秒未结束。
  - **漫画 OCR client（同根，步骤 6）**：`fushi/lib/src/sync/interconnect_manga_ocr_client.dart`（修复前，`556b4a45b5c`）：`_send` `:557-568` 把所有传输异常压成 `MangaOcrRemoteException('http', '$e')`、丢掉「传输失败」这一类型，`.timeout` 只包到响应头（`:559-560`）；`run()` `:356-507` 同样一个 try 包到底，状态 GET 一次 `SocketException` 就以 `http` 报错并经关流触发的 `onCancel` 删掉 host 任务；create 在途取消时 `onCancel` 拿不到 jobId，create 回来后 `:396-397` `jobId = id; if (cancelled) return;` 不清理，host 留下 pending 孤儿。修复前实测三例红：create 在途取消后 `jobCount == 1`、前两次状态 GET 抛 `SocketException` 即以 `http` 收尾、卡住的响应体让整条流 10 秒未结束。「catch 只 addError 不清理」那一支未复现，见 [BUG-4456](BUG-4456-manga-ocr-client-error-orphan.md)。
