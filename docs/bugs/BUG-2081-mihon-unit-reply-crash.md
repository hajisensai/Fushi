## BUG-2081 · Mihon Android 通道 void 方法回 kotlin.Unit 触发 StandardMessageCodec 崩溃，Discover/Import 打开即崩
- **报告**：2026-09-03（用户：装过一个漫画扩展后，每次打开漫画 Discover / Import 页都崩；日志 `java.lang.IllegalArgumentException: Unsupported value: 'kotlin.Unit' of type 'class kotlin.Unit'`，栈顶 `StandardMessageCodec.writeValue` ← `MihonChannelHandler.register$lambda$0$1$0`）
- **真实性**：✅ 真 bug，自 `ee5f713133`（2026-07-29 Mihon 扩展生态首次提交）就在。基线 `develop@33d6caf51a` 的 `fushi/android/app/src/main/kotlin/app/fushi/reader/mihon/MihonChannelHandler.kt:127-151` `handle()` 是 `when` 表达式，`"uninstallPrivateExtension" -> uninstall(...)`（`:212`，无返回类型）和 `"clearSourceData" -> clearSourceData(...)`（`:361`，无返回类型）两条分支的值就是 `kotlin.Unit` 单例；`:89` 把它原样 `mainHandler.post { result.success(value) }`，StandardMessageCodec 不认 Unit，在主线程 Runnable 里抛未捕获异常（`:86-95` 的 catch 只包住同步的 `handle(call)`，包不住 post 出去的 lambda），进程直接死。同文件 `invalidateExtension` / `dispose` 两条分支手写了 `{ ...; null }` 才没中招——说明作者知道这个坑但没收口。
  用户看到的循环：`fushi/lib/src/media/manga/mihon/mihon_manager.dart:806-816` `_discardPreview`（预览失败 / 用户不保留时）→ `uninstallPrivateExtension` → 崩；`:744` 预览标记 `tmp/preview-pending` 已先于文件落地写下、崩溃前来不及清；之后每次进漫画 Discover / Import 触发 `MihonManager._initialise`（`:106`，`:117` 处调用）→ `_recoverAbandonedPreview`（`:838`）→ 再次 `uninstallPrivateExtension` → 再崩，Dart 侧 `on Object` 兜不住进程死亡，标记永远清不掉。`manga_sources_page.dart:567` 的「清除来源数据」按钮走 `clearSourceData` 是同一个崩点。
- **[x] ① 已修复** —（本提交）`MihonChannelHandler.kt`：新增通道唯一出口 `reply(result, value)`，`register()` 里 post 出去的回复改走它：`result.success(if (value === Unit) null else value)` 一处收口 void；编码抛 `IllegalArgumentException` 时转 `result.error("ENCODE_FAILED", …)` 带 cause 链——编码在发送之前整体完成，抛出时 reply 还没被消费，改回 error 是安全的，主线程 Runnable 不再裸奔。顺手删掉 `invalidateExtension` / `dispose` 分支手写的 `{ ...; null }`，四条 void 分支现在都是普通分支。Kotlin 侧 `flutter build apk --debug` 编译通过。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/mihon_channel_reply_codec_guard_test.dart`（仓库无 Android JVM 单测基建，可落地的最强层是源码守卫；用 `methodBody` 按签名取 `reply()` 体）：
  ① `reply()` 体内必须是 `result.success(if (value === Unit) null else value)`，且带 `catch (error: IllegalArgumentException)` → `result.error("ENCODE_FAILED"`；
  ② `reply()` 体之外，`register()` 必须 `mainHandler.post { reply(result, value) }`，且不允许出现任何带值的 `result.success(...)`（只放行 `cancelImageRequests` 的 `result.success(null)`）——任何绕过出口的新回复点都红。
  变异实测：收口改成裸 `result.success(value)` → ① 红；`reply(result, value)` 改回 `result.success(value)` → ② 红；两次都按原串还原并 sha256 核对一致。
- **备注**：用户设备上已经写下的 `preview-pending` 标记不需要手动清：修复后 `_recoverAbandonedPreview` 第一次成功 `uninstallPrivateExtension` 就会走到 `_clearPreviewMarker`。真机复测原始路径（预览扩展→不保留→重进 Discover）本轮未做，只有编译 + 源码守卫证据。
