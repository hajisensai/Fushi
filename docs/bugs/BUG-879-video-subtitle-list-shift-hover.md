## BUG-879 · 字幕列表单词无法 Shift 悬停查词
- **报告**：2026-07-18（用户：看 2 分钟动漫默认设置反馈，第 3 点）
- **真实性**：✅ 真 bug（设计缺口 + 命中过严）。根因 `hibiki/lib/src/media/video/video_subtitle_jump_panel.dart`：① 列表行文本只挂 `GestureDetector.onTapUp` 查词、行 `MouseRegion` 只做 hover 高亮，**没有 `onHover` 查词**；画面字幕 overlay 有完整 Shift-hover 链，两条不对称（用户报「按 Shift 探不出来」）。② **命中太严**：`hitAt` / `subtitleListCharHitFromParagraph` 的 `getBoxesForSelection` 用默认 `BoxHeightStyle.tight`（贴字形、1.25 行高的 leading 在盒外）+ 仅 1px 容差，点在行距 / 字缝就落空 → 退回 seek（作者实测「鼠标左键点也有时候不出词」的病因）；对比画面字幕 `resolveSubtitleCharHit` 有半字宽 + 描边级容差故宽容。
- **[x] ① 已修复** — **(a) 补 Shift-悬停**：面板级单一 `Listener(onPointerHover: _handleListShiftHover)`（不逐行挂 MouseRegion，避免每次 hover 新建 TextPainter 重排整行——那正是「列表比画面字幕卡」的结构性差异），复用 `_hitTestRows` 的 **RenderParagraph** 反查（不重排、与画面字幕几何反查一样轻），门控 / 8px / 去重与 overlay 同构。**(b) 放宽命中**：`hitAt`（tap）与 `subtitleListCharHitFromParagraph`（barrier/hover/keydown 共用）都改 `getBoxesForSelection(boxHeightStyle: BoxHeightStyle.max)`（盒覆盖整行视觉格含 leading）+ 容差 1px→`localRect.height*0.5`（半字格，与画面字幕半字宽兜底同量级）；tap 的 onTapUp 去掉多余 `charRect.contains` 二次收窄（会把容差内命中又误判空白退 seek）。四条列表查词路径（tap / Shift-hover / barrier / Shift-keydown）现共用同一宽容 RenderParagraph 反查。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_subtitle_jump_panel_test.dart`（BUG-879 widget：未按 Shift 悬停不查词、按住 Shift 悬停即对光标字符 `onLookupCue`；source guard：面板级 `_handleListShiftHover` 复用 `_hitTestRows` + `isShiftPressed`；命中盒 `BoxHeightStyle.max` + `height*0.5` 容差、无 `inflate(1)`）；`hibiki/test/media/video/video_subtitle_jump_panel_hit_tester_test.dart`（RenderParagraph 反查）。命中容差是真实 CJK 字体度量相关，Ahem 测试字体无 leading 复现不了，故行为层守卫命中源码（与画面字幕 `subtitle_char_hit_tolerance_test` 同思路，真机验收像素级手感）。
- **备注**：与 BUG-880/881 同一 PR（列表查词四点同源：列表原是查词体系二等公民——无 hover、命中过严、未登记 barrier、无 keydown）。修复提交 `96763ac23`（Shift-hover 骨架，PR#217 已合并 develop）+ 本轮补 tap 命中宽容 / 面板级 hover / RenderParagraph 复用。真机验收：列表左键点任意字都出词、Shift 悬停连续查、光标停着按 Shift 即出。
