## BUG-2465 · 页面隐藏时阅读器重锚旗永不清（rAF 冻结）位置与进度不落库
- **报告**：2026-09-12（有声书重开书对账集成测试在 Mac 跨机 runner 上追出：探针 `document.hidden=true / visibilityState=hidden`，武装 30 帧 rAF 一秒后 `raf=0`，`_reanchorPending` 恒真，阅读位置 20s 内从不落库；上一轮 `reader_live_settings_itest` 在 Mac 上四次探针也全是 `pending=true`，只是没断言位置所以绿）
- **真实性**：✅ 真 bug（触发条件是页面隐藏，日常可见时不发作）。根因 `fushi/lib/src/reader/reader_pagination_scripts.dart`：四条「置旗 → 下一帧落定 → finally 清旗」的重锚路径（分页 / 连续 × `restoreToCharOffset` / `updatePageSize`）都把落定排在 `requestAnimationFrame` 里；页面隐藏时（macOS 窗口不可见 / Cmd+H、Chromium 最小化、ssh 起的 GUI 进程）浏览器冻结 rAF，回调永不执行 → `_setReanchorPending(false)` 永不到 → `stableProgressInvocation` 恒 null → Dart `_refreshProgress` 早退：位置不落库、账本不 arrive、进度不刷新，直到页面重新可见 rAF 补发。开书时 WebKit 首帧 `innerW/innerH=0`（`[FushiInit]` 用 Dart 尺寸兜底），随后 `updatePageSize` 重锚就是隐藏页里第一处挂死的旗。
- **[x] ① 已修复** — 提交见合并记录。加 `_reanchorFrame(fn)`：`document.hidden === true` 走 `setTimeout(fn, 0)`（隐藏文档里布局照常可读，没有可见帧可等就立刻落定），否则原样 `requestAnimationFrame`；四处落定改经它调度。可见时零行为变化。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_reanchor_hidden_fallback_behavior_test.js`（node vm 原样执行 `_reanchorFrame`：可见 → rAF、hidden → setTimeout(0)、visibility 未知 → rAF）+ `fushi/test/reader/reader_reanchor_hidden_fallback_test.dart`（驱动 node + 源码守卫：四处都经 `_reanchorFrame`，「rAF 回调里 finally 清旗」的旧形状不得回潮）。真 app：`fushi/integration_test/audiobook_resume_align_itest.dart` 的 WebView 探针每段打印 `pending / raf / hidden`，Mac 隐藏 runner 下位置照常落库即为证。
- **备注**：`_progressScrollRaf`（scroll → 进度回传的 rAF 节流）在隐藏页里同样冻结，但隐藏页没有用户滚动，不改。
