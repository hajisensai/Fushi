## BUG-2925 · Android 视频退出后沉浸模式残留，启动状态栏被隐藏
- **报告**：2026-10-03（用户：Android 启动隐藏状态栏；视频退出后仍处于沉浸模式，拉出的状态栏自动收回。）
- **真实性**：✅ 真 bug。首页 helper `fushi/lib/src/utils/misc/platform_utils.dart:38` 在 Android 使用 manual + 仅 bottom overlay，主动隐藏状态栏。视频入口 `fushi/lib/src/pages/implementations/home_video_page.dart:153` 独立 `Navigator.push`，不经过 `AppModel.openMedia/closeMedia`；视频页 `fushi/lib/src/pages/implementations/video_fushi_page.dart:2550` 设置 immersiveSticky，退出 `:6165` 直接 pop；释放显示态 `:8420` 原本只清回调和还原方向，遗漏系统 UI 模式恢复。代码中「closeMedia 会恢复」的注释与实际路由不符。
- **[x] ① 已修复** — 首页 helper 先发送 manual + 全部 overlays，显式显示状态栏/导航栏，再发送 edgeToEdge 恢复布局。启动与阅读器退出共用此流程。真机发现 Flutter 3.44 的 Android `PlatformPlugin.enableEdgeToEdge()` 只调整 decor fitting，不清除旧的 FULLSCREEN / HIDE_NAVIGATION / IMMERSIVE_STICKY 标记；仅发送 edgeToEdge 虽可恢复 Flutter inset，仍会残留原生沉浸态，因此必须先清除隐藏标记。视频页在最后一个 `VideoDisplayClaim` owner 退出时调用同一 helper，覆盖正常退出与异常拆栈；换集时旧页释放不影响新页。沉浸重申和移动端全屏回调须仍持有当前 owner，防止已退出的页通过异步回调重新隐藏状态栏或锁横屏。2026-10-04 用户拍板 Android 首页改为显示状态栏（推翻 TODO-097 的隐藏决定），helper 不再按平台分支，五端同一流程。
- **[x] ② 已加自动化测试** — `fushi/test/utils/home_shell_system_ui_mode_test.dart` 拦截真实 SystemChrome 通道，验证先显示全部 overlays 再发送 edgeToEdge，以及从 immersiveSticky 恢复；`fushi/test/media/video/video_display_claim_test.dart` 验证退页后旧 owner 不再有权设置、新集仍持有；`fushi/test/media/video/video_lifecycle_static_test.dart` 验证最后一个 owner 释放后恢复首页模式；`fushi/test/pages/video_statusbar_immersive_guard_test.dart` / `video_orientation_fullscreen_guard_test.dart` 守住所有权检查和 await 后不重锁方向。另加 `fushi/integration_test/video_system_bars_restore_test.dart`：真实启动、生成测试视频、走本地视频入口、焦点驱动 Esc 退出、退出后 resumed，检查首页 inset 并提供 adb 采证阶段。inset 不能替代原生窗口标记检查。
- **验证**：9 个定向测试文件 63 条通过；全量 `flutter analyze --no-pub` 无问题。Android 17（API 37）实体设备集成测试 1 条通过，使用独立测试包 `app.fushi.reader.systembarprobe`。adb 检查该包窗口：启动、退出、退出后 resumed 均无 FULLSCREEN / HIDE_NAVIGATION / IMMERSIVE_STICKY，播放阶段三项标记存在；退出后实际展开/收起通知栏，标记仍未恢复。启动及退出截图确认状态栏可见。采证留在 PR 作者本机的不入库测试证据目录。
