## BUG-5090 · video-scrape-sourceless-scope-issue-blank-title
- **报告**：2026-11-22（PR #4018 审查遗留：无来源刮削范围的整批级错误 / 警告在界面上是空标题）
- **真实性**：✅ 真 bug。视频刮削协调器的范围级问题一律拿 `source.label` 当 `SourceScrapeIssue.workTitle`（`packages/fushi_engine/lib/media/video/metadata/video_source_scrape_coordinator.dart` 原 855「只允许刮削已登记的本地视频来源」、970「资料源整批不可用」、1288「AniDB 封禁跳过剩余作品」、1350 整批异常）。无来源本机视频范围 `sourcelessLocalVideoScrapeScope`（`video_scrape_scope.dart:30`）不落库、`label: ''`，于是任务面板（`video_source_scrape_dialog.dart` 结果行 `Text(issue.workTitle)`）与运行详情（`video_source_scrape_run_detail_dialog.dart` 时间线卡标题）显示空标题。engine 没有 i18n，不能在 engine 里填本地化名字；问题结构里也没有「这是范围级问题」的标识，界面无从区分。连带：运行详情给范围级问题也挂「手动指定」按钮（拿来源 label 当作品名去搜，必然找不到作品）；时间线节点按 `workTitle` 取 `ValueKey`，同一 run 的多条无来源范围级问题都是空串，会撞重复 key。
- **[x] ① 已修复** — `SourceScrapeIssue` 增加结构化范围标识 `scopeSourceId`（无来源范围为 `kSourcelessLocalVideoScrapeScopeId`）与 `isScopeLevel`，范围级问题统一经 `SourceScrapeIssue.scope(source, message:)` 构造（协调器 4 处全部改用）；run 摘要 JSON 增加 `scope` 字段往返保留（损坏值退化成作品级，不炸历史面板）。界面统一经 `videoScrapeIssueTitle`（`fushi/lib/src/media/video/metadata/video_scrape_issue_text.dart`）取标题：无来源范围映射 `t.video_scrape_scope_sourceless`，已登记来源显示其 label；运行详情对范围级问题不给「手动指定」，时间线节点改用 `ObjectKey(issue)`。ctl 刮削报告（`fushi/lib/src/ops/ctl_video_support.dart` `_issueJson`）同样给范围级问题带 `scope` 字段，AI / CLI 调用方不再把来源 label 当作品名去手动指定（审查补，`fushi/test/ops/ctl_video_routes_test.dart`「刮削报告 JSON 给范围级问题带结构化 scope，作品级问题不带」）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/metadata/video_source_scrape_coordinator_test.dart`「无来源范围的整批级错误带结构化范围 id，run 摘要往返保留」（真实协调器 + 内存库，无资料源走整批失败门）与「作品级问题解码后不是范围级；损坏的 scope 字段退化成作品级」；`fushi/test/pages/video_source_scrape_ui_test.dart`「scope-level issues show the localized scope name in run detail and the task panel」（两条无来源范围级错误显示本地化名、不撞 key、只有作品级问题有「手动指定」）。
- **备注**：修复前已落库的旧 run 摘要没有 `scope` 字段，其中无来源范围的整批级问题仍显示空标题（无法从旧记录可靠还原范围，不做猜测式回填）；新跑的批次不受影响。`fushi_server` 的 `video_scrape_host.dart` 用 `SourceScrapeIssue.toString()` 输出错误，范围级问题现在带 `scope <id>` 前缀。
