## BUG-2498 · 退出新手引导即向系统申请通知权限，MIUI 权限界面崩溃连坐杀掉 Fushi
- **报告**：2026-09-13（用户：MIUI 真机，退出新手引导那一刻 Fushi 被系统强制关闭；用 `adb pull` 取出 APK 再 `pm install -g` 预授全部权限绕开授权界面后不再闪退）
- **真实性**：✅ 真 bug。链路：向导关闭 → `fushi/lib/src/pages/implementations/home_page.dart:529` `appModel.startUpdateChecks()` → `fushi/lib/src/models/app_model.dart:1052` `feed.warmUpNotifier()` → `LocalUpdateNotifier.ensureReady()` → `_initialise()` 末尾直接 `_requestPermission()`（改前 `fushi/lib/src/updates/local_update_notifier.dart:175`）→ `ActivityCompat.requestPermissions([POST_NOTIFICATIONS])` → MIUI 的权限授予界面 `com.lbe.security.miui` 因字符串资源缺失崩溃 → 系统把发起请求的 Fushi 一起杀掉。
  - MIUI 那个崩溃本身是系统缺陷，Fushi 侧无法让别人的进程不崩；**Fushi 侧的根因**是 `ensureReady()` 把「初始化通知后端（挂点击回调、回放冷启动点击）」和「向系统申请运行时权限」焊成一件事，于是启动期、用户没做任何动作就弹系统权限框。Android 官方指南本就要求 `POST_NOTIFICATIONS` 在用户有明确意图的上下文里申请，不在启动即弹。
- **[x] ① 已修复** — `a1094d1e9a`：`UpdateNotifier` 契约拆成 `ensureReady()`（只初始化、永不申请）/ `hasPermission()`（只查询：Android `areNotificationsEnabled`、Apple `checkPermissions`、桌面恒 true）/ `requestPermission()`（显式申请）。`UpdateFeedService.warmUpNotifier()` 只初始化 + 查询并缓存权限状态；发通知前按 `hasPermission` 降级（没权限只出红点、不发系统通知，事件照常投递）。权限申请只剩一个入口 `enableSystemNotifications()`，由「设置 → 系统 → 系统通知」开关打开时触发；开关显示值 = 偏好开 && 系统已授权（`systemNotificationsActive`），被拒时开关显示为关、再打开即再申请。平台分派改用 `defaultTargetPlatform`（与插件自身分派同源，单测可用 override 走到 Android 分支）。 审查返工：冷启动点击回放从 `ensureReady()` 拆成 `replayLaunchResponse()`，只由 `warmUpNotifier` 调（否则用户几小时后打开开关会被旧点击莫名跳转）。
  - 行为变化（有意）：全新安装不再在退出向导时弹通知权限框；用户要收系统通知须主动打开那个开关。Android < 13、桌面、以及已授权的 Android 13+ 存量用户不受影响；此前拒过权限的 Android 13+ 用户，开关从「假开」变成如实显示为关。
- **[x] ② 已加自动化测试** — `fushi/test/updates/local_update_notifier_test.dart`「BUG-2498」组：method channel 级守卫，`ensureReady()` 只发 `initialize` + `getNotificationAppLaunchDetails`、绝不发 `requestNotificationsPermission`；`requestPermission()` 才发且只发一次。变异实测：把 `_initialise` 末尾的申请塞回去，两条即红。`fushi/test/updates/update_feed_service_test.dart`「BUG-2498」两条：warm-up / 发通知都不申请、开关显示值与申请入口的三态。
- **备注**：`READ_EXTERNAL_STORAGE` 在 API ≥ 33 / targetSdk 35 下是死权限，`android_permission_service.dart:48` 的兜底仍会把它送去弹窗（用户选真实路径目录时）；不在本次链路上，另开条目处理。
