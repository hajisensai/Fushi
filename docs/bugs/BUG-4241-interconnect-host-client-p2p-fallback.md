## BUG-4241 · 互联：主机能力探测 / GET 与选路缓存不走 P2P 隧道，直连不通时远程复习找不到主机
- **报告**：2026-11-08（agent：Linux Phase 4 互联验证，Windows host（带 fushi_p2p.dll）+ Linux 客户端，客户端到 host 直连端口全部拒绝，只剩 `p2p://`）
- **真实性**：✅ 真 bug，两处根因，症状同为「直连不通时 P2P 后备用不上」。
  - 实测：直连被挡后，同步（书进度双向）、远端查词、制卡到 host 都经 P2P 隧道正常（直连 UDP 打洞与强制 n0 中继两种路径都过）；但「复习 › 复习已配对设备的牌组」显示「没有已配对设备提供远程复习」。放开直连后同一页立刻列出 host；先经直连进入 host 牌组再挡直连，30 秒内点开牌组报「连不上已配对设备」，超过 30 秒重试即经隧道正常复习，评分落到 host。
  - 根因 1：`fushi/lib/src/sync/interconnect_host_client.dart:185-232` `InterconnectHostClient.getFromHost` 直接遍历库里存的候选（`:200-201` `interconnectEndpointUri(candidate.url, path)`），没有像 `postJson` 走的 `InterconnectPostTransport.post`（`fushi/lib/src/sync/interconnect_post_transport.dart:153`）那样先过 `rankInterconnectCandidates`，`p2p://` 候选从不经 `_resolveTransport` 换成本地转发口，拼出 `p2p://<nodeId>/api/capabilities` 交给 `http.Client`，抛错被 `catch (_) { continue; }` 吞掉。于是 `declaresCapability`（`:166`）在只有 P2P 可达时返回 null，所有按能力探测列主机的入口都把 host 判成不可用：远程复习 `fushi/lib/src/srs/srs_remote_store_client.dart:64`（经 `fushi/lib/src/sync/video_remote_targets.dart:78` `probeInterconnectHostTargets`）、视频遥控 `fushi/lib/src/sync/video_remote_client.dart:51`、AI 中继 `fushi/lib/src/ai/ai_interconnect_relay.dart:111`；同一个 GET 通道上的远程复习媒体 `srs_remote_store_client.dart:69` 与视频遥控快照 `video_remote_client.dart:58` 也只走直连。视频遥控与 AI 中继是按代码路径推断，未单独实测。
  - 根因 2：`fushi/lib/src/sync/interconnect_peer_addresses.dart:234-236` 选路缓存命中（30 秒 TTL）时只把缓存的胜出地址 resolve 后放组首，其余成员原样返回（`:262`），其中的 `p2p://` 没有换成转发口。缓存的直连地址一旦失效，消费方「顺序试组内其余地址」试到的是不可拨的 `p2p://`，请求整体失败；`:195` 注释写的「缓存的地址失效时消费方会顺序试组内其余地址，不会因为缓存而连不上」对 P2P 不成立。直连刚断的 30 秒内，远程复习的 `postJson` 与同步首个请求都会因此失败（同步那次只在 SyncRunReport 里记了一条 `prune root spill (list root)` 连接被拒，随后会话重选路恢复）。
- **[ ] ① 未修复** — 方向：`getFromHost` 与 `post` 共用同一份「过滤同 host 候选 → `rankInterconnectCandidates` → 逐个试」的候选来源，不在 GET 里另写一套；`_rankGroup` 缓存命中时整组都过 `_resolveTransport`（或缓存命中只做排序、仍保证组内 `p2p://` 可用），让「其余地址兜底」对 P2P 成立。
- **[ ] ② 未加自动化测试** — 建议：`fushi/test/sync/` 下注入假 P2P resolver（`setInterconnectP2pResolver`）与只认转发口的假 http client：① 只有 `p2p://` 可达时 `declaresCapability` 为 true、`probeInterconnectHostTargets` 列出该 host；② 选路缓存记着已失效的直连地址时，`postJson` 经组内 `p2p://` 成功。
- **备注**：P2P 隧道本身依赖 n0 公共基础设施（pkarr / DNS 发现、`*.relay.n0.iroh.link` 中继、QAD）；host 公布的 `p2p://` 带 `relay=` 与 `addr=` 拨号提示，所以有直连提示时可以不经发现直接打洞。
