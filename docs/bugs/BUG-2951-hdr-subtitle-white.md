## BUG-2951 · HDR直通下字幕比画面白更亮颜色发怪
- **报告**：2026-10-05（用户：「hdr下的字幕感觉颜色怪怪的」，附 HDR 片源截图）
- **真实性**：✅ 真 bug。用户机实测 Windows HDR 开、10-bit、「SDR 内容亮度」= 280 尼特；截图字幕填充 (224,224,224) 比画面里的白 (202,210,216) 还亮。根因是 HDR 直通（`fushi/lib/src/media/video/video_hdr_output.dart` `hdrHostMpvProperties`）下视频与字幕两套亮度基准：mpv gpu-next 输出 HDR10，参考白 = 203 尼特（BT.2408 / libplacebo `PL_COLOR_SDR_WHITE` / mpv `sub-hdr-peak` 默认）；字幕 / 弹幕是 Flutter 主窗里的 SDR 内容，DWM 把它的白映射到用户的 SDR 白电平（这里 280 尼特）。字幕于是比画面白亮约 1.4 倍、像贴上去的发光白。字幕层（`fushi/lib/src/pages/implementations/video_fushi/layout.part.dart` 的 `VideoSubtitleOverlay` / `VideoDanmakuOverlay`）此前不知道直通状态，runner `displayInfo` 也不回报 SDR 白电平。
- **[x] ① 已修复** — runner `QueryHdrDisplayInfo` 经 `DisplayConfigGetDeviceInfo(DISPLAYCONFIG_DEVICE_INFO_GET_SDR_WHITE_LEVEL)` 回报 `sdrWhiteNits`；主窗在宿主窗存在时重新激活也推 `onDisplayChanged`（改滑块无窗口消息）；控制器每次重判现读显示器信息存进 `hdrDisplayInfo`；纯函数 `hdrGraphicsWhiteScale` = min(1, 203 / SDR白)（仅直通 + HDR 显示器），`HdrGraphicsWhiteLevel` 在编码域按 sRGB OETF(系数) 套 ColorFiltered（GlobalKey 保子树 State），字幕与弹幕两层都包上。提交：见本分支 `fix(video): level subtitle layer to HDR graphics white (BUG-2951)`。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_hdr_output_test.dart`（「HDR 图形白归一」组：系数真值表 / 编码域乘数经 sRGB EOTF 回到系数 / 进出直通子树 State 不重建 / 通道解析 `sdrWhiteNits`）；`fushi/test/build/hdr_video_host_guard_test.dart`（runner 查 SDR 白、`"sdrWhiteNits"` 两侧同名、激活重读、两层图形都经 `_hdrGraphicsWhiteLevel`）。
- **备注**：SDR 白低于 203 尼特时 8-bit SDR 窗口无法更亮，系数取 1（字幕会略暗于画面白，属平台限制）。PGS 等图形字幕由 mpv 自己画，走 mpv 的 `sub-hdr-peak`，不受本修复影响。真机目视复验未做（需用户在 HDR 片源下看一眼）。
