## BUG-2709 · 词典在线更新：钉版本号的下载地址更新不到新版，旧版导入的词典被判不可更新
- **报告**：2026-09-26（用户：手动更新和 Yomitan / Hoshi 不一样，行尾「更新」按钮要自己下最新词典到本地再选文件；希望顶部一键更新所有词典，Pixiv Light 这种几百 MB 的大词典尤其需要）
- **真实性**：✅ 真 bug，两个根因 + 一个入口问题：
  1. **更新下载的是旧包**：见 BUG-2707（PR #1670）。三条更新链路（启动自动更新 `_autoRedownloadAndReimport`、单本、批量）已由 #1670 统一改为 `remote.resolveDownloadUrl(本地地址)` 下载、`remote.updatedSourceMetadata(...)` 回写（远端 index 的 `downloadUrl` / `indexUrl` 只采信 http(s) 绝对地址，缺省回落本地）。本条最初（PR #1672）自带的一套 `parseDownloadUrlFromIndexJson` / `resolveDownloadUrl` / `downloadUrl:` 参数与之重复且更弱（不限 scheme、不要求绝对地址），已在 #1670 之上重做时删除，统一用 #1670 的实现。
  2. **旧版导入的词典被判不可更新**：`Dictionary.isUpdatable` 只看 metadata；在线更新（TODO-609）之前导入的词典 metadata 里没有来源字段，即使词典目录下的 index.json 声明了 `isUpdatable:true`，行尾按钮也走 `_updateDictionaryFromFile`（让用户选本地文件）——这就是用户看到的「要我自己下一个最新的词典」。
  3. 顶部「检查更新」按钮只在存在 `isUpdatable` 词典时显示（`_buildActionBar`），2 发生时入口整个消失；且远端 index 拉取失败（`DictionaryRemoteIndexResult.succeeded == false`、`revision == null`）经 `needsUpdate` 返回 false，单本提示「已是最新」、批量计入「最新」——#1670 未修这一点。
- **[x] ① 已修复** — 根因 1 见 BUG-2707（#1670）。本条在 #1670 之上重做（分支 `fix/1672`）：启动期 `_backfillDictionarySourceMetadata`（`app_model.dart`）异步读词典目录 index.json 一次性回填来源字段（`kDictSourceProbeKey` 标记，`persistDictionaries` 批量落库只重载一次引擎；落库包 try/catch 记 `ErrorLogService`，调用方 unawaited 不再漏成 zone 错误）；动作栏首位常驻「更新全部词典」（Cupertino 桌面 / 移动动作栏同样有），无可更新词典时说明原因；检查失败单本提示 `dict_update_check_failed`、批量计入失败；不可在线更新词典的行尾 tooltip 改成「从本地文件更新」。
- **[x] ② 已加自动化测试** — `fushi/test/dictionary/dictionary_update_service_test.dart`（远端 downloadUrl 选址与 #1670 的 http(s) 绝对地址过滤、回填判定/合并、用真实 Pixiv index.json 回填后 `isUpdatable` 为真）、`dictionary_update_ui_guard_test.dart`（按钮常驻首位、单本/批量都把 `remote` 传进唯一选址漏斗、检查失败单本报失败/批量计失败）、`dictionary_auto_update_test.dart`（自动更新按远端地址下载与回写、回填接线、批量落库且落库异常被捕获）。
- **备注**：未在真 app 上跑一次完整的 Pixiv 大词典在线更新（需联网下载数百 MB）；逻辑由上述单测与源码守卫覆盖。
