## BUG-2891 · 64位游戏转区落空仍报已转日文区
- **报告**：2026-10-03（agent 在 クロノクロック 体験版v2 `cmvs64.exe`（x64）原始启动路径上发现：转区档位 `on`，会话记了 `launch.japanese_locale_applied`、状态卡亮「已转区」，但游戏的启动设置对话框片假名全是 `???`、`標準` 显示成 `[昗弨]`——进程实际跑在系统 CP936 下）
- **真实性**：✅ 真 bug。`fushi/lib/src/mining/galgame_audio_source.dart` 的 `start()` 把**命令行请求**（`resolveJapaneseLocale` 的结果，即是否带 `--japanese-locale`）直接记成 `_japaneseLocaleApplied`。injector 侧 `CreateJapaneseLocaleProcess`（`native/galgame_hook/injector/injector_main.cpp`）在 Locale Emulator 运行时缺失或 `LeCreateProcess` 失败时返回 false，`RunLaunch` 退回普通 `CreateProcessW`，并在 `LAUNCH pid=… locale=0` 里如实回报——Dart 已解析成 `GalHookLaunchObservation.localeLaunch`，却没人拿它定「转没转」。x64 helper 目录（暂存的 `voice_hook_runtime/<hash>/x64/`）本就只有 `fushi_voice_hook.dll` / `fushi_voice_injector.exe` / `LunaHook64.dll` / `LunaHost64.dll`，没有 `LoaderDll.dll` / `LocaleEmulator.dll`，所以 64 位游戏选 `on` 时必然落空、必然误报。`auto` 档有 64 位工程门不会请求，`on` 档没有。
- **[x] ① 已修复** — 拆开「请求」与「事实」：新增 `japaneseLocaleRequested`（命令行带没带）；`japaneseLocaleApplied` 改为只认 injector 回报（`requested && LAUNCH … locale=1`），没收到 LAUNCH 行时为 false。请求了却回报 `locale=0` 时 `japaneseLocaleSkipReason` 为新原因 `runtimeUnavailable`（key `runtime_unavailable`），会话控制器记 warning 事件 `launch.japanese_locale_unavailable`，状态卡显示新提示 `game_session_japanese_locale_skipped_hint_runtime_unavailable`（不再要求有 `auto` 判定才显示原因）。`GalHookSessionState.copyWith` 清判定时只丢旧原因、保留同次调用传入的新原因（`on` 档落空没有判定却有原因）。
- **[x] ② 已加自动化测试** — 变异实测：把 `japaneseLocaleApplied` 改回返回请求值，3 条用例变红。`fushi/test/mining/galgame_audio_test.dart`「转区事实只认 injector 回报」（`locale=1` ⇒ applied、`locale=0` ⇒ 未转 + `runtimeUnavailable`）；`fushi/test/mining/gal_japanese_locale_visibility_test.dart`「BUG-2891：on 档请求了转区却被 injector 退回普通启动」（warning 事件、不记 applied、状态带原因）；`galgame_japanese_locale_probe_test.dart` 改断言 `japaneseLocaleRequested`（命令行）并钉「进程没起来不算已转区」；`galgame_japanese_locale_test.dart` 稳定 key 清单加 `runtime_unavailable`。
- **备注**：没做的是「让 x64 也能转区」——Locale Emulator 只有 x86 版（`resolveJapaneseLocale` 注释已写明），这是外部工具限制。本修复只保证诊断说真话；x64 ANSI 引擎（如 CMVS x64）在中文系统上界面字符串仍会乱码，但游戏正文走引擎自带字形渲染、LunaHook 抽出的文本按 CP932 解码，实测正文与抽取文本都正常。
