## BUG-3062 · 移动端视频章节刻度没落在进度条轨道上
- **报告**：2026-10-07（用户：「移动端视频章节不是准确在播放条上」）
- **真实性**：✅ 真 bug。水平方向没问题（刻度层与 fork 进度条同用 `_videoSeekBarSideInset` 内缩、`fraction × 宽` 线性摆放，与 M3E 轨道手柄 `w × position` 同一坐标系），错在**竖直**：章节刻度层自带一套「轨道中线」近似公式，与 M3E 化后真实画出来的轨道不是同一个几何来源。
  - `fushi/lib/src/media/video/video_subtitle_style.dart:165`（修前）移动端轨道中线 = `seekBarBottom + seekBarTrackHeight / 2`，按旧 media_kit 贴底 5px 轨道算；但 M3E 化后轨道由宿主 `VideoM3eSeekTrack` 画，中线在热区容器底缘之上 `(6 + 4) × scale`（`fushi/lib/src/media/video/video_m3e_chrome.dart:1050`，修前）。full 档刻度带中线比轨道低 7.5×缩放、整条 13px 刻度几乎全落在轨道下方（截图上首章 / 中间章的刻度挂在轨道下面）。
  - `fushi/lib/src/pages/implementations/video_fushi/chapter.part.dart:93-94`（修前）喂给几何的按钮行高 / 进度条间距**没乘密度档** `_controlsDensityScale`，而主题里的 `seekBarMargin.bottom` 乘了：compact 档刻度带按未缩小的按钮行抬高。compact 下这项偏高恰好与上一项偏低部分抵消，误差随界面缩放与密度档变化，不是固定偏移。
  - 同一套近似公式还被缩略图预览层（`_buildThumbnailPreviewOverlay`）与自动连播倒计时卡（`episode.part.dart` `_buildAutoAdvanceOverlay`）共用；M3E 暗角与 Apple 玻璃胶囊则各自又写了一份。
- **[x] ① 已修复** — 轨道竖直几何收成唯一来源：`videoM3eSeekTrackCenterFromBottom`（M3E 轨道 widget 自己按它画中线）+ `videoSeekBarContainerBottom`（移动端主题的 `seekBarMargin.bottom` 也改用它）；页面新增 `_videoSeekBarContainerBottom` / `_videoSeekBarTrackCenter` 两个 getter（均乘密度档），章节刻度、缩略图预览、自动连播卡、M3E 暗角、Apple 胶囊全部改读 `_videoSeekBarTrackCenter`；`videoSeekBarTrackBand` 改为只接真实 `trackCenter` 展开刻度带；刻度高度乘密度档；mini 档（没有进度条）不再挂刻度层。提交 `0c084d57d22`。
- **[x] ② 已加自动化测试**（`0c084d57d22`）— `fushi/test/media/video/video_chapter_markers_track_alignment_test.dart`：按 fork 移动端布局搭控件区，用**真的** `VideoM3eSeekTrack` + `VideoChapterMarkers`，从拖动时间气泡反推轨道手柄 x / 轨道中线 y，断言 5 个时间点（含 0 与末尾 0.999）的章节刻度 x 与手柄 x 一致、刻度带中线与轨道中线一致且上下盖住轨道，覆盖 full / compact 两档 × 手机横屏宽度（844 / 915 / 740 / 667）× 界面缩放 × 手势栏 inset；另有纯函数测试与页面接线源码守卫（刻度 / 缩略图 / 连播卡都读 `_videoSeekBarTrackCenter`、M3E 轨道不得再内联第二份中线公式、mini 档不挂刻度、移动端主题走 `videoSeekBarContainerBottom`）。旧测试 `video_chapter_markers_test.dart` / `video_mobile_controls_margin_test.dart` 同步改到新签名。
- **备注**：真实像素对比（widget test 渲染，3× 像素比，手机横屏宽度）：`.codex-test/video-chapters/full_844x390_compare.png`、`compact_740x360_compare.png`（上半修前、下半修后）。**未在真机复测**：本机连着的 adb 设备是 HiBreak 墨水屏平板（装着用户的 app.fushi.reader），Android 端视频没有外部 VIEW 打开入口、也没有确定性开视频的调试钩子，真机复测需另编带 applicationIdSuffix 的测试包 + 集成驱动导入带章节的视频，本轮未做；证据只有 widget test 真实像素。桌面端也走同一 getter（M3E 桌面轨道中线 = 容器底缘 + overlap + 抬升，与修前 `buttonBarHeight + lift` 在 full 档数值一致；compact 档同样修正了未乘密度的偏差）。
