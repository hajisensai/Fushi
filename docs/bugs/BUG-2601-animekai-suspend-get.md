## BUG-2601 · 视频源扩展调 suspend OkHttpClient.get 在两端宿主都缺定义，AnimeKai 剧集列表 BRIDGE_HTTP_500
- **报告**：2026-09-19（用户：「animekai又出问题了，对齐一下mangayomi怎么解决的」，截图：AnimeKai (Unoriginal) 作品页 `MihonRuntimeException(BRIDGE_HTTP_500): 'java.lang.Object eu.kanade.tachiyomi.network.RequestsKt.get$default(okhttp3.OkHttpClient, java.lang.String, okhttp3.Headers, okhttp3.CacheControl, kotlin.coroutines.Continuation, int, java.lang.Object)'`，剧集列表空）
- **真实性**：✅ 真 bug（用本分支 overlay 构建的桌面 sidecar 直接打真实 yuzono APK 取证）
  - 报错串就是 `NoSuchMethodError` 的方法描述：AnimeKai（yuzono `aniyomi-en.kotokai-v16.8.apk`，dex 引用 `Leu/kanade/tachiyomi/network/RequestsKt;` + `get$default`）按 extensions-lib 16 写法 `client.get(url)` 取剧集，链接到 Kotlin 为「带默认参数的 suspend 扩展函数」生成的合成方法 `RequestsKt.get$default(OkHttpClient, String, Headers, CacheControl, Continuation, int, Object)`。两端宿主的 `Requests.kt`（sidecar `third_party/m_extension_server/upstream_src/server/src/main/kotlin/eu/kanade/tachiyomi/network/Requests.kt:17-56`、Android `fushi/android/app/src/main/kotlin/eu/kanade/tachiyomi/network/Requests.kt`）只有 `GET()` / `POST()` 请求构造器，没有 `OkHttpClient.get/post` 这组 suspend helper → 桌面端 `DalvikHandler.errorResponse` 把 `LinkageError` 包成 bridge/500 回给 Dart。
  - 同一批缺口：`rateLimit(permits, period: Duration)` / `rateLimitHost(httpUrl, permits, period: Duration)`（lib 16 扩展的写法，Kotlin value class 参数名字会被 mangle 成 `rateLimit-SxA4cEA`）两端都没有；Android 端连 `RateLimitInterceptor.kt` 整个文件都没有（Mihon 的 `source-api` 不含它，本仓 `prepareMihonSourceApi` 只拉 `source-api`）。
  - Mangayomi 的解法（`references/mangayomi` 桌面走 `kodjodevf/M-Extension-Server` release，本仓 vendored 钉在 `ee55c65` = v1.0.5.0）：镜像 v1.0.7 在 `Requests.kt` 加了三条 `suspend fun OkHttpClient.get/get/post`，在两个限流拦截器加了 `Duration` 重载，并用反射测试钉合成方法描述符（`RequestsTest.kt` / `RateLimitInterceptorTest.kt` / `SpecificHostRateLimitInterceptorTest.kt`）。本仓 overlay 逐字对齐这三处，其余 v1.0.7 改动（视频代理、YouTube、torrent 工具）不在本 bug 范围。
- **[x] ① 已修复** — sidecar overlay 新增 `overlay/.../network/Requests.kt`（三条 suspend helper，经 `awaitSuccess`）、`overlay/.../network/interceptor/RateLimitInterceptor.kt` / `SpecificHostRateLimitInterceptor.kt`（`Duration` 重载，TimeUnit 版保留）；Android 宿主 `Requests.kt` 加同样三条，新增同名两个拦截器文件。取证：`build_desktop_runtime.ps1` 构建的 sidecar 对真实 `aniyomi-en.kotokai-v16.8.apk` 走通 `sourcesAnime → getPopularAnime(30 条) → getDetailsAnime → getEpisodeList(13 集) → getVideoList(4 条 HD-1/Vidstream Sub/Dub 1080p，各 5 条字幕轨) → Range 拉流 200 application/vnd.apple.mpegurl`。提交见 PR。
- **[x] ② 已加自动化测试** — sidecar Kotlin 反射测试 `overlay/server/src/test/kotlin/eu/kanade/tachiyomi/network/RequestsTest.kt`（`get$default` 7 参 String / HttpUrl 两形、`post$default` 8 参）、`.../interceptor/RateLimitInterceptorTest.kt`（`rateLimit-SxA4cEA$default` 5 参 + 老 `rateLimit$default` 6 参）、`.../interceptor/SpecificHostRateLimitInterceptorTest.kt`（`rateLimitHost-Wn2Vu4Y` 4 参 / `$default` 6 参 + 老 7 参），随 `:server:test` 跑；Dart 源码守卫 `fushi/test/media/manga/mihon_host_network_abi_guard_test.dart`（两端 `Requests.kt` / 两个拦截器同形，Dart 桥的 `getMangaUrl` / `getAnimeUrl` 两端都分发）；`fushi/test/build/mihon_vendored_server_guard_test.dart` 登记三个新 overlay 覆盖文件。
- **备注**：同 PR 顺带给漫画 / 视频作品页各加「在网站打开」入口（`MangaSeriesPage` / `AnimeSourceDetailPage` AppBar，`Icons.open_in_new`）：先问扩展 `getMangaUrl` / `getAnimeUrl`（sidecar 上游本就分发，Android `MihonChannelHandler` 本次补上），拿不到再 `baseUrl + url` 兜底（Mangayomi 的做法）。lib 17 域（Aniyomi 主线 `HttpServer` 等）仍未 vendored。
