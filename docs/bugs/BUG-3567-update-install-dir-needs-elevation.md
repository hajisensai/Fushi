## BUG-3567 · update-install-dir-needs-elevation
- **报告**：2026-10-19（用户：所有者转述用户现场截图——Fushi 装在 `C:\Program Files\Fushi`，普通权限点更新弹「更新安装器未启动 / Cannot write to installation directory … errno = 5」，以管理员打开 Fushi 才能更新）
- **真实性**：✅ 真 bug（体验缺口）。安装器 `fushi.iss` 是 `PrivilegesRequired=lowest`，选目录页对不可写目录有拦截（BUG-1483），但用户以管理员身份运行安装器即可绕过、装进 Program Files。此后应用内更新的写预检（`fushi/lib/src/utils/misc/platform_updater.dart` 旧 `ensureWindowsInstallTargetWritable`）在普通权限下必然失败并抛错，唯一出路是「以管理员身份重开整个 app」——让 app 长期以管理员运行，且每次更新都要用户自己想到这一步。
- **[x] ① 已修复** — 写不进安装目录时不再报错，改为只把**安装器**经 UAC 提权：`runAndExit` 探针失败 → 给 launcher 下发 `--elevate`、给 Inno 加 `/FUSHINORELAUNCH`；`update_launcher.cpp` 的 `LaunchInstallerElevated` 用 `ShellExecuteExW` + `runas` + `SEE_MASK_NOCLOSEPROCESS` 拉起 Inno（拿句柄照常等它结束），用户在 UAC 里拒绝（`ERROR_CANCELLED`）按启动失败记 marker 并拉回 app；`fushi.iss` 的 `[Run]` 加 `Check: ShouldLaunchAppAfterInstall`，提权安装时跳过自启（外部 runas 提权下 Inno 不知道原用户，`runasoriginaluser` 不生效，自启的 app 会继承管理员令牌），改由仍是普通权限的 launcher 在安装结束后立即拉回 app（`EnsureAppBack` 提权路径不再白等 20 s）。没有 launcher 的直启路径无从提权，保留原报错。
- **[x] ② 已加自动化测试** — `fushi/test/utils/misc/update_installer_elevation_test.dart`（参数构造、`runAndExit` 不可写→提权交接 / 可写→普通交接 / 无 launcher→仍报错且不退出、`.iss` 与 launcher 两侧接线守卫）。本地另验：`cl /W4 /utf-8` 编译 `update_launcher.cpp` 零警告，`ISCC /O-` 编译 `fushi.iss`（含 `[Code]`）通过。
- **备注**：未做真机 UAC 端到端（需要一台装在 Program Files 的正式包 + 发布产物）。已知边界：以**另一个**管理员账户的凭据通过 UAC（标准用户机器的 over-the-shoulder 提权）时，提权的 Inno 写的 HKCU / `{userdesktop}` 属于那个管理员账户——这与用户手动以管理员运行安装器的既有行为相同，不是本修复引入。
- **审查补强（2026-10-19，PR #2369 第三方审查）**：初版有四处缺口，已在同一 PR 内按根因修掉——
  1. **提权执行未校验的文件（安全）**：安装包落在用户可写的 updates 目录，初版 launcher 直接 `ShellExecuteExW runas` 原始路径，校验（仅下载时、且哈希可缺省）与提权执行之间隔着「等 app 退出 + 等互斥体」的数秒乃至 CLI 下任意久，同用户任何进程都能换包拿到管理员权限。现在：下载层把「本进程按发布方公布哈希校验过的路径」登记进进程内 `UpdateDownloadTrust`（`.meta.json` 同样用户可写，不当凭据）；`runAndExit` 交接前按该哈希重算、不符即删包不交接；**提权只在有公布哈希时进行**，没有就保留旧报错；launcher 收 `--installer-sha256`，以 `FILE_SHARE_READ` 独占读打开安装包（他人写 / 删 / 改名及其上级目录改名都被拒，实测），握着句柄用 BCrypt 重算比对，再用 `GetFinalPathNameByHandleW` 解出的真实路径（穿过 junction，防校验后改指）提权启动，句柄一直握到 launcher 退出（`update_launcher.cpp` `LockAndVerifyInstaller`）。
  2. **Windows 构建门被打断**：`EnsureAppBack` 新引用的 `args.elevate_installer` / `SingleInstanceMutexHeld()` 在 `windows/runner/tests/update_launcher_completion_test.cpp` 的夹具里不存在，该夹具是 runner 的构建依赖（`fushi_windows_update_launcher_completion_gate`），`flutter build windows` 必红（本地 cl 复现 C2039 / C3861）；PR 上主 CI 没有跑所以没暴露。已补夹具并加 4 条提权用例（提权路径只看一眼互斥体、绝不进 20 s 观察窗口）。
  3. **任何写失败都弹 UAC**：初版把磁盘满 / 受控文件夹访问 / 路径无效也当成「需要提权」。现在探针返回三态 `WindowsInstallDirWriteProbe`，只有 `ERROR_ACCESS_DENIED` 才提权。
  4. **UAC 被拒 / 完整性失败只有一行原始错误**：重开后的「更新安装器未启动」对话框按 marker 的 `installerElevationDeclined` / `installerIntegrityCheckFailed` 给出可操作的说明（新增 i18n `update_install_elevation_declined` / `update_install_integrity_failed`）。
  - 测试：`fushi/test/utils/misc/update_installer_elevation_test.dart` 扩到参数绑定、哈希不符删包、无公布哈希不提权、非权限失败不提权、真实目录探针（Windows 下 System32 判 accessDenied）、launcher 锁定接线守卫；`update_launcher_completion_test.cpp` 11 例全过；launcher 实跑：错哈希 / 缺哈希都在弹 UAC 之前拒绝并写 marker。
  - **仍未验证 / 已知残留**：① 真机 UAC 端到端（含提权后 app 以普通权限回来、同意框是否直接前台弹出）仍未做；② 若安装目录的**上级**目录用户可写（非 Program Files 的自定义位置），用户可整体替换 `{app}`——这与提权安装本身的落点信任相同，不是日志独有的问题。
  5. **提权的安装器会结束别的登录用户的 Fushi**：`process_control.iss` 的 WM_CLOSE 目标 / 强杀主进程树 / 安装目录 helper 清扫都按镜像名或路径扫全机；普通权限下别人的进程打不开，但经 UAC 提权后管理员令牌能 `TerminateProcess` 快速切换用户 / 远程桌面其它会话里正开着的 Fushi（丢未落盘数据）。现在三处都过 `FushiInOwnSession`（`ProcessIdToSessionId` 与安装器同会话才碰），非提权安装行为不变；别的会话占着文件时安装按既有路径失败回滚。`ISCC /O-` 编译 `fushi.iss`（含 `[Code]`）通过。
  6. **提权 Inno 的 `/LOG` 写在用户可写的 updates 目录**：同用户进程可预置 junction / 符号链接把一次管理员写重定向。现在提权时日志写进安装目录本身 `{app}\fushi-update-install-<交接时刻毫秒>.log`（`windowsElevatedInstallerLogPath`）——探针刚证明当前用户在那里建不了文件，也就放不了链接；marker 记同一路径，reconcile 以普通权限照常读回（Users 对安装目录有读权限）。文件名按交接时刻区分，避免读到上一轮旧日志；`fushi.iss` 的 `CleanupStaleElevatedInstallLogs` 安装成功后只留本次这份，`[UninstallDelete]` 卸载时删除。非提权路径日志位置不变。
  7. **UAC 同意框不在前台**：consent 只在发起方 hwnd 处于前台时直接弹出，否则只在任务栏闪烁；launcher 在 app 退出后发起提权，原版传 `hwnd=nullptr`。按前台锁规则，有权让渡前台的只有当时的前台进程（用户刚点了更新的 app），所以 app 在 `exit` 前对 launcher pid 调 `AllowSetForegroundWindow`（定向，不用 `ASFW_ANY`）；launcher 发起提权前建 1x1 工具窗 `SetForegroundWindow` 后作为 `SHELLEXECUTEINFO.hwnd`，结果记进 marker `installerElevationForeground`。只在提权路径让渡前台。未做本机正向验证：需要一个持有前台的父进程，模拟它要往用户桌面注入按键抢前台，故未做。
