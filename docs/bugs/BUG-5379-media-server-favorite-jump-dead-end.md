## BUG-5379 · 媒体服务器直接串流（未入库）的收藏句在收藏夹点了没反应
- **报告**：2026-11-23（用户：从 Jellyfin 浏览页直接播一集、没「加入媒体库」，在播放器里 ★ 收藏句子；首页 → 收藏夹 → 句子 tab 点那一行没有任何反应）
- **真实性**：✅ 真 bug。媒体服务器浏览页直接串流走 `VideoFushiPage.remote`（`bookUid = info.id`，即服务器条目 id），只有 `MediaServerVideoLibrary.addMissing`（`fushi/lib/src/media/video/media_server/media_server_library.dart:209`）才建 `video_books` 行；收藏句因此记 bookKey = 条目 id、source = video，不带服务器身份。收藏夹 `_openVideoSentence`（`fushi/lib/src/pages/implementations/collections_page.dart:840-841`）`getByBookUid` 得 null 后直接 `return`——静默无反应。手机遥控跳收藏 `_openRemoteVideoFavorite`（`fushi/lib/src/pages/implementations/video_fushi/remote_control.part.dart:667-669`）同样在没有库行时回 `favorite_source_unavailable`，媒体服务器上明明还在。入库条目不受影响（`VideoFushiPage.neutralized` → `buildMediaServerLaunch`）。
- **[x] ① 已修复** — 新增唯一解析口 `resolveMediaServerItemLaunch`（`media_server_library.dart`）：没有本机库行时按条目 id 挨台问已登录的媒体服务器（`SyncRepository.getMediaServers` → `buildBrowser()` → `itemDetail(id, forLaunch: true)`），第一台给出可播放详情的胜出，没命中的现建客户端当场关掉；`loadConfigs` 自己抛出不吞。收藏夹与遥控跳收藏共用它，命中后以 `VideoFushiPage.neutralizedRemote(initialRemoteFavorite: …)` 打开、起播后按收藏起点 + 原文对到那一句。客户端所有权：远端页新增 `ownsRemoteClient`，真时退页与自建流客户端同一条收尾关闭（`RemoteClientTeardown`，BUG-5012 同款）；远端构造器补 `initialFullscreen`，遥控在全屏中跳到媒体服务器条目时照样接管原生全屏。哪台都没有 / 出错时收藏夹弹 `video_favorite_source_unavailable` 提示（来源不在库里，若是媒体服务器串流请登录那台服务器），不再静默；bookKey 为空同样提示。无 DB schema 变更。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/media_server/media_server_item_launch_test.dart`（解析器：多服务器取首个可播放命中、非叶子跳过、未命中关客户端、无服务器 / 空 id 回 null、配置源异常外抛）；`fushi/test/pages/collections_media_server_favorite_test.dart`（pump 真 CollectionsPage，点没有库行、无服务器可解析的视频收藏句 → 出现提示、不压新页）。
- **备注**：互联（Fushi host）远端播放的收藏同样只记 host 视频 id、不带 host 身份，本修复不覆盖：没有库行时会先问媒体服务器（不命中），收藏夹给出同一条提示（不再静默），遥控跳收藏回 `favorite_source_unavailable`；真要从收藏夹跳回互联 host 上的视频需要按 id 找 host 的解析口，未做（按委托不扩范围）。
