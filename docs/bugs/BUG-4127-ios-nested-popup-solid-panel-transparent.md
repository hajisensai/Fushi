## BUG-4127 · iOS 嵌套查词：透明度不被允许时子层实底压在正文上整块透明
- **报告**：2026-10-31（应用内反馈 hQpYQyWJNQ，iOS 26.3.1 / iPhone14,7，3.1.0-debug.22074，Apple 设计系统深色，reader_fushi：「cupertino 主题嵌套查词，子查词框背景透明，释义看不清」）
- **真实性**：✅ 真 bug。从反馈截图取色：父层面板正好是 `#1C1C1E`，是 Flutter `ColoredBox` 实底，不是 UIVisualEffectView 材质（材质会带上背景的色偏）。所以这台设备走的是「透明度不被允许 → 不透明实底」分支（`fushi/lib/src/utils/components/fushi_material_components.dart` `_ApplePopupGlassBackdrop._buildGlass` 原 `!realBlur` → `ColoredBox(opaque)`）。子层压在正文上的部分没有底色，正文原样透出来，只有和父层重叠的那段是实底。
  根因在 iOS 的平台视图合成规则：画在第 N 个平台视图之后的 Flutter 内容，引擎只把它跟第 N 个平台视图相交的部分合成进 overlay，其余部分落进最底层的 Flutter 画布，被更早的平台视图（阅读器 WKWebView）整块盖住。嵌套层的 Flutter 实底（还有同层 Flutter 画的描边和顶栏）画在父层查词 WebView 之后，所以只在和父层重叠的地方看得见。在 iOS 26.5 模拟器（Flutter 3.47.6）上用最小复现实测：一个阅读器 WKWebView 加父层、子层，子层用同一组 Positioned / Visibility / FadeTransition / Material clip / ClipRect 结构。背衬用 Flutter `ColoredBox` 实底时，子层压在正文上的部分整块透明，和反馈截图一致；换成原生 UIVisualEffectView 材质或原生实色视图都显示正常。入场淡入的 Opacity 和祖先 mask 都不是原因：dump 原生视图父链，alpha 全是 1，没有 mask。
- **[x] ① 已修复** — `a7e387901a`：iOS / macOS 上查词面板的背衬一律用原生平台视图。能真模糊就用系统材质；透明度不被允许时用原生实色面板（`fushi/apple/FushiNativeMaterialView.swift` 新增 `solid` 参数；`fushi/lib/src/utils/components/glass/fushi_native_material.dart` 新增 `fushiNativePopupBackdropHostAvailable` 和 `FushiNativeMaterialBackdrop.solidColor`）。判据只在 `_ApplePopupGlassBackdrop._buildGlass` 写了一处。
- **[x] ② 已加自动化测试** — `fushi/test/widgets/glass/fushi_popup_surface_nested_fill_test.dart`「iOS / macOS 原生系统材质」组：iOS / macOS × 三种情况（Apple 材质档 off、MD3 系统降低透明度、Apple 高对比度），断言背衬是带不透明 `solidColor` 的原生视图，且 surface 里没有 Flutter 画的不透明面板（改前 6 例红，改后绿）。另加一条，断言材质可用时不带 `solidColor`。
- **备注**：没有 iOS 真机，没在真机上按 paginated / continuous / vn 三种 view mode 复测原 app，证据只有模拟器上的最小复现（改前透明，改后实底）。iOS 墨水屏下 MD3 分支的底色仍由 Flutter `Material` 画，理论上嵌套层也会遇到同样的合成问题，这次没改（iOS 上开墨水屏极少）。
