## BUG-942 · 上/下一句字幕按钮太远时退化成 3 秒 seek
- **报告**：2026-07-20（用户：moonbeam / Student）——「视频播放器的『上一句 / 下一句』按钮只是前进 / 后退 3 秒」。
- **真实性**：✅ 真（行为符合当前实现，但与「跳句」按钮心智不符）。链路：屏上「上/下一句字幕」按钮 / 双击 / 手柄 / 控制项 → `_skipCueAndPokeControls`（`hibiki/lib/src/pages/implementations/video_hibiki_page.dart:5293`）与控制项分派（:4610）→ `controller.skipToPrevCueOrSeekBack` / `skipToNextCueOrSeekForward`。`skipToPrevCueOrSeekBack` 走 `prevSeekDecisionFor`（`video_player_controller.dart`），其中**上一句起点距当前 > seekSeconds(默认3) 秒时退化成回退 3 秒时间 seek**（TODO-085）。故字幕对话间隙常 >3s 时，「上一句」按钮就变成回退 3 秒；无字幕轨时前进/后退 3 秒（TODO-073/119）。moonbeam 大概率遇到「上一句太远」或「未加载字幕轨」两种退化。旧代码本意（`skipToPrevCueOrSeekBack` 旧 doc、`_replayPreviousCueAndPokeControls` :5339 注释）是「按钮不退化、只有键盘 Ctrl+← 退化」，但按钮接线已回归到退化路径 → 意图与接线漂移。
- **[x] ① 已修复** — 方案 B（用户确认）：**按钮 / 双击 / 手柄 / 控制项在有字幕时恒跳到相邻上/下一句，绝不因太远退化**；仅**键盘 Ctrl+←** 保留 TODO-085 退化。实现：`prevSeekDecisionFor` 加 `degradeFarCueToTimeSeek`（默认 `true` 保留键盘语义 + 既有单测），`skipToPrevCueOrSeekBack` 加同名参数**默认 `false`**（按钮语义 = 恒跳句）并透传；键盘 `previousSubtitle` 显式传 `degradeFarCueToTimeSeek: true`（`video_hibiki_page.dart` :3760 附近）。「下一句」`skipToNextCueOrSeekForward` 本就恒跳句（无字幕才 ±seek），无需改。无字幕时两侧仍 ±seekSeconds 秒（不 no-op 卡住，TODO-073/119 保留）。
- **[x] ② 已加自动化测试** — `test/media/video/video_player_controller_test.dart`：新增「BUG-942 按钮语义(degradeFarCueToTimeSeek:false)：上一句很远也跳句、不退化」——同「上一句距当前 ~31.5s」场景，默认(键盘)退化成 `timeSeek(-3000)`、按钮(`false`)则恒 `cue(0)`，两条对照钉死。既有 TODO-085 键盘退化用例（默认 true）保持绿。`flutter test --no-pub test/media/video/video_player_controller_test.dart test/media/video/video_player_keyboard_static_test.dart` 全绿（137）。
- **备注**：分支 worktree-prev-cue-button-always-jump。键盘另有裸 ←/→ = 纯时间 seek，故 Ctrl+← 退化不是唯一 seek 手段。真机复测：加载字幕轨、播放到对话间隙 >3s 处，点「上一句」应跳到上一句起点而非回退 3 秒。
