## BUG-4959 · 收藏句变更通知靠偏好表整表更新流，任何偏好写入都让播放页重读整串收藏
- **报告**：2026-11-21（拍板台 design-nmv-fyi-tail ④「根本性做完」；来源 #3831 c51 遗留取舍，代码审读，无用户报告）
- **真实性**：✅ 真问题（性能结构问题，无错误结果）。收藏句整份存在 `preferences` 表的一个键 `favorite_sentences`（JSON 列表，`packages/fushi_audio/lib/src/audiobook/favorite_sentence_repository.dart` `_key`）。`FavoriteSentenceRepository.watchChanges()` 委托 `FushiDatabase.watchPrefChanged`（`packages/fushi_core/lib/src/database/database_prefs_media.part.dart:23`），它订阅的是 `tableUpdates(preferences)` 整表：任何偏好写入（含播放进度定期保存等高频写）都会触发一次 `getPref('favorite_sentences')` 读出整串 JSON 再比较。收藏多时每次偏好写入都白读一遍大字符串。增删一条也是整串读出、解码、重写（`add` / `removeById` / `removeByContent` …）。
- **[ ] ① 未修复** — 根治是把收藏句迁成独立表（每句一行，id 主键 + 内容键索引），变更流改订该表，增删改逐行写。涉及：schema 版本 + 迁移（JSON → 行，迁完删偏好键）；`FavoriteSentenceRepository` 改为表读写；`backup_service.dart`（`_favoriteSentencesPrefKey` 的导出 / 恢复清理，旧备份里的偏好键要能恢复进表）；`backup_merge_engine.dart` `_mergeFavoriteSentencePrefs`（源库可能是旧 schema 的偏好键或新 schema 的表）；`aggregate_sync_service.dart` `_readFavoriteSentences` / `_writeFavoriteSentences`（wire 形状不变，读写源换成表）；`database_music_identity.part.dart` `_rewriteAliasedFavoriteSentences`（音乐身份别名改写）；`app_model.dart` 直查偏好键处。跨 schema / 备份 / 同步 / 音乐身份 ≥5 个模块，与 design-nmv-fyi-tail 的其余 5 条（纯局部修复）分开做一个 PR，避免一次评审里混入 schema 变更。
- **[ ] ② 未加自动化测试** — 需要：迁移测试（旧 JSON → 表，行数 / 字段 / 排序一致，偏好键删除）；旧备份恢复进表；merge engine 新旧源库两种形态；aggregate 快照往返；`watchChanges` 只在收藏表变化时发、写别的偏好不发。
- **备注**：拍板台 design-nmv-fyi-tail 其余 5 条已在分支 `claude/dec-design-nmv-fyi-tail` 的 PR 里做完；本条是那条事项唯一剩下的部分。
