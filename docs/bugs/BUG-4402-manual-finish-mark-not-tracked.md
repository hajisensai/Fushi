## BUG-4402 · Marked Finished / watched by hand is not sent to the tracking site
- **报告**：2026-11-10（用户：手动标「已读完」的 Ajin 第 1 卷已关联 MangaBaka（卷模式），`epub_books.completed_at` 已写，`media_tracking_outbox` 为空、没有同步）
- **真实性**：✅ 真 bug。手动标记只写 `EpubBooks.completedAt`，没有任何一处告诉追番：`fushi/lib/src/pages/implementations/reader_fushi_history_page.dart:3912`（`_toggleBookCompleted`）、`:2942`（合集批量标记）、`fushi/lib/src/ops/ctl_library_shelf.dart:917` / `:926`（CLI / AI）。阅读器路径走 `AppModel.reportPagedBookTrackingProgress`，手动标记没有。视频同样：`fushi/lib/src/media/video/video_watched_marks.dart:83` `setVideosWatched` 是手动标已看的唯一入口，只写库 + 回写媒体服务器，不碰追番。只有之后某次同步碰巧跑到补发（`_reconcilePersistedBookProgress` / `_reconcileCompletedVideoProgress`）才会发出去。
- **[x] ① 已修复** — 新增 `fushi/lib/src/media/library_finish_marks.dart`：`setBooksFinished` / `clearBooksFinished` 是手动设 / 清书「已读完」的唯一入口，设上时经 `LibraryFinishTracking.onBooksFinished` 报给追番（`AppModel.libraryFinishTracking` → `reportPagedBookTrackingProgress`，与阅读器读到卷末同一路径，含自动关联）；书架单本 / 批量、CLI、进度重置全部改走它。`setVideosWatched` 加必填 `tracking`，本地行标为已看后调 `onVideosWatched`（AppModel 起一次同步，补发按本地「看完」事实发出所有已关联视频，含合集级映射）；CLI 撤销恢复成已看同样上报。清除标记不上报：站点进度只增不减（`planTrackingEntryWrite` 也从不调低），所以没有可发的东西。
- **[x] ② 已加自动化测试** — `fushi/test/media/tracking/manual_finish_marks_tracking_test.dart`：已关联卷标记读完恰好发一条（卷号、completed）；未关联的什么都不发；取消标记不发更低进度；手动标已看的已关联视频发出；源码守卫：`lib/` 下除入口文件外不得直接调 `.setEpubBookCompleted(`。
- **备注**：手动标已看的**未关联**视频不会自动去站点搜索关联（播放到片尾才会）；批量标一整季时逐集搜索代价太大，按已关联的发。未在真实设备上复测。
