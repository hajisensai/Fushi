## BUG-606 · 油管首帧被字幕+title串行阻塞~28s
- **报告**：2026-07-07（用户：TODO-1307）
- **真实性**：✅ 真 bug。根因：YouTube 流媒体书开播前串行阻塞首帧——`buildStreamVideoLaunch`（`hibiki/lib/src/media/video/stream_video_launch.dart:32`）用默认 `withCaptions:true` 调 `resolveYoutubeSource`，其内部在 `getManifest`（首帧唯一必需，`youtube_source_resolver.dart` 取流）之外，还串行 ① `videos.get` 取被丢弃的 title（~9s，实际 title 用 `book.title`）+ ② `_resolveYoutubeCaptions`（~19s，WatchPage.get + getPlayerResponse + timedtext 3 次往返），全部返回才 `controller.load` 首帧（`video_hibiki_page.dart` `_applyLoad`）。首帧被字幕 + 重复 title 拉到 ~28s。
- **[x] ① 已修复** — 拆两段：**快解析 gate**（`buildStreamVideoLaunch` 改 `resolveYoutubeSource(url, withCaptions:false)`：跳过 videos.get + 字幕，只 getManifest 取流即起播）+ **字幕后置**（`UrlStreamVideoClient.youtubeCaptionsUrl` 存 watch URL；`_loadRemoteEpisode` 在 `_applyLoad` 返回后 `unawaited(_resolveDeferredYoutubeCaptions(client, seq))` 异步解析，cue 就绪回填 `client.setPreresolvedCues` + 灌 TODO-1302 的 YouTube 字幕轨 `_kYoutubeCaptionsSource`，不阻塞首帧、不绕过 1302 字幕轨模型）。附 **A2**（`_resolveYoutubeCaptions` 去掉多余 `WatchPage.get`，单次 `getPlayerResponse(androidVr)`——实测同 6 轨含 ja、省 ~1.3s）、**A1**（`kYoutubeManifestClientFallback` = androidVr → ios → tv 逐个兜底，androidVr 零回归）、**阶段反馈提前**（`_setLoadingPhase(connecting)` 移到 `buildStreamVideoLaunch` 之前）。提交 `b522c2797`。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/youtube_fast_load_guard_test.dart`（源码守卫：快解析 gate withCaptions:false / 字幕后置接 1302 哨兵 / A1 逐个兜底 / A2 无 WatchPage / 阶段反馈提前，删任一即红）+ `youtube_source_resolver_test.dart`（A1 兜底顺序 androidVr→ios→tv、`resolveYoutubeCaptions` best-effort 空 URL 返回空 cue 不联网）+ `url_stream_video_test.dart`（`setPreresolvedCues` 回填 + `youtubeCaptionsUrl` 数据模型）。提交 `b522c2797`。
