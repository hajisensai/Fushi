## BUG-3662 · 视频源扩展（Aniyomi extensions-lib 17）装不上：Unsupported extension-lib version
- **报告**：2026-10-21（用户：应用内反馈 gRSPNbJjqT，Windows 3.0.0+19763「下载仓库后视频源无法浏览」，弹窗 `MihonRuntimeException[BRIDGE_HTTP_400]: Unsupported extension-lib version`）
- **真实性**：✅ 真 bug。Aniyomi 主线 2026-09-14 发布 extensions-lib v17（aniyomiorg/extensions-lib `971ce96e`），仓库开始出 17 代 APK（实测 salmanbappi/extensions-repo 的 Anikoto 17.69 / AnimeSogo 17.37 / AnimeSuge 17.25，manifest `aniyomix.extensionLib = 17`）。宿主只并了 lib 14 + 16：sidecar 安装前的 `/inspect` 按 `third_party/m_extension_server/overlay/server/src/main/kotlin/mextensionserver/controller/InspectHandler.kt` 的 `supportedLibVersionLabel` 只认 14/15/16，17 → `IllegalArgumentException("Unsupported extension-lib version")` → HTTP 400 → Dart `desktop_mihon_runtime.dart` 拼成 `BRIDGE_HTTP_400`（Android `MihonExtensionLoader.supportedLibVersionLabel` 与 Dart `MihonMediaKind.supportedLibVersions` 同表同拒）。UPSTREAM 里原本就写着「lib 17 territory … refused at inspect time」的天花板。单放开门禁没用：lib 17 改了 `Video` / `Hoster` 构造（追加 `memo: JsonObject`）、把请求/解析 helper 从 abstract 改成 open、新增合并式 `getAnimeEpisodeUpdate` / `getAnimeSeasonUpdate`、`HttpServer` / `AnimeRelation` / `SAnimeEpisodeUpdate` / `ThumbnailInfo` / `torrentutils`，扩展按 JVM 描述符链接，缺一个就是 `NoSuchMethodError` / `AbstractMethodError`。
- **[x] ① 已修复** — 宿主 anime ABI 扩成 lib 14 + 16 + 17 并集（桌面 sidecar 与 Android 同一份 overlay 源码）：`Video` 改成手写类，同时保留 lib 16 的 14 参构造 / `copy$default`（47 个 yuzono lib16 APK 里 23 个在 `resolveVideo` 用它）与 lib 17 的 15 参构造 / `copy`；`Hoster` 两代构造；`SAnime` / `SEpisode` 加 `memo`；`AnimeSource` 加合并式调用（默认回落旧两步），`AnimeHttpSource` 的 `getAnimeDetails` / `getEpisodeList` / `getSeasonList` 对只实现合并式调用的 lib 17 扩展按反射改走合并式（与既有 hoster 判据同法，`super` 不回环）；helper 全改 open；新增 lib 17 模型类与 `torrentutils`（`TorrentUtils` 用 Java 同时给出 komikku 的普通版与 lib 17 的 suspend 版）；`HttpServer` 桌面绑 loopback，由 `AnimeVideoLoader` 把 `http://localhost:1` 改写到扩展本地服务、`ExtensionHttpServers` 管生命周期，Android 编自己的无 NanoHTTPD 版并把这类视频判不可播；三处安装门放到 17，并认 lib 17 的 `aniyomix.*` 元数据键。
- **[x] ② 已加自动化测试** — `third_party/m_extension_server/overlay/server/src/test/kotlin/mextensionserver/controller/AnimeExtensionAbiTest.kt`（真 APK dex 抽出的 170 条宿主引用逐条按描述符解析，夹具 `src/test/resources/anime-extension-abi-refs.txt`；变异实测追加一条不存在的描述符即红）、`AnimeVideoLoaderTest.kt`（两代 Video/Hoster 合成构造与 `copy$default`、lib16 copy 保 memo、memo 在 hoster→video→resolve 间传递、合并式路由与 `super` 不回环、旧扩展走合并式、本地服务改写/无服务时报因）、`AnimeResponseTest.kt`（门禁 14..17）、`fushi/test/media/manga/mihon_manager_media_kind_test.dart` / `mihon_anime_models_and_bridge_test.dart`（Dart 门禁装得下 17、拒 13）。sidecar `:server:test` 全绿；构建出的 sidecar JAR 对真 Anikoto 17.69 APK 调 `/inspect`（只读元数据、不跑扩展代码）返回 `libVersion: 17`、名字取自 `aniyomix.name`。
- **备注**：未做：① `SAnime.memo` / `SEpisode.memo` 不跨桥调用往返（宿主 wire 与库存储没有这个槽位；实测三个 lib 17 APK 都没用它，用了的扩展跨调用会拿到空 memo）；② Android 上 `HttpServer` 类扩展的视频不可播（App 不带 NanoHTTPD）；③ `TorrentUtils.getTorrentInfo` 一律报不支持；④ 未在真机跑过 lib 17 扩展的浏览/取流（规则禁止在本机执行第三方扩展代码，链接面由 ABI 夹具测试兜底）。
