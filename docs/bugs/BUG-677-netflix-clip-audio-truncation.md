## BUG-677 · Netflix 制卡句子音频尾段被截断（录制在字幕清空即停，无尾部余量）
- **报告**：2026-07-09（用户报：网飞制卡句子音频疑似少了后面一段/不准；并猜漏卡是否同因）
- **真实性**：✅ 真 bug。根因 `tools/browser-extension/content.js`（=镜像 `hibiki/assets/browser_extension/content.js`）`hibikiRunNetflixBatch` 逐句回放录制的停录判据。
- **[x] ① 已修复** — 根因：回放录制循环把「字幕文本变成别句/清空」当作停录点，检测到即 `v.pause()`+`endClip`（原 `content.js:452 if (nowText !== ref) break;`）。而字幕文本清空 = Netflix 字幕 **display end**，常早于本句 **语音 end**；录制侧只在头部保了 200ms 提前量（seek 到 `q.startV = cueStart-200`），**尾部从不补**——入队时算好的 200ms 尾部预留 `q.endV = cueEnd+200`（`content.js:275`）只被 YouTube 路径消费（`content.js:330 endMs: q.endV`），Netflix 回放路径按设计「用字幕变化重新定 end」（`hibikiCurrentCueWindowV` 注释 `content.js:126`）完全忽略它。结果句子音频尾段（字幕清空后的残余语音 + 本该保留的 200ms 尾部）被截。服务端 `transcodeClipToCapture`（`hibiki/lib/src/mining/immersion_capture_channel.dart:113`）整段转码 `[0, clipDurationMs]`、`clipDurationMs` 是墙钟上界（`offscreen.js:84`）→ **服务端不截断**，截断纯在录制停点过早。修复：句末检测到后不立即停，记录目标停录视频时间 `endAtSec = v.currentTime + kNfClipTailPadSec`（尾部余量 0.35s，与 200ms 头部提前量对称、略放宽以覆盖字幕清空后残余语音 + 120ms 轮询抖动），录到 `v.currentTime >= endAtSec` 才 pause+endClip。内容脚本版本标记 bump v42→v43 便于用户确认新版已加载。改动文件：`content.js`（两份镜像逐字节一致）。
- **[x] ② 已加自动化测试** — 源码扫描守卫 `hibiki/test/mining/netflix_todo1364_clip_tail_pad_guard_test.dart`：两份镜像都断言存在 `kNfClipTailPadSec>0`、句末记录 `endAtSec = v.currentTime + kNfClipTailPadSec`、停录门 `if (v.currentTime >= endAtSec) break;`、且旧的截尾写法 `if (nowText !== ref) break;` 不得残留（防回归）；并锁两份镜像逐字节一致。`netflix_mining_robustness_guard_test.dart` 的版本标记守卫同步 bump 到 v43。
- **备注**：用户第③问「漏卡（跳卡）是否同因」——**不同因**。跳卡是 DRM 回放录制概率失败（`v.paused` 重试仍失败 / `beginClip` 失败 / clip 无音轨转码失败 → `fail++`），已在 TODO-1361 处理为末尾清点未生成数；本 bug 只影响**已生成**卡的音频尾段完整性，两者独立。Netflix 运行时最终需用户真机复测（DRM 回放录制无法离屏自动化）。
