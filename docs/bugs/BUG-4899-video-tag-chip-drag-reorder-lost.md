## BUG-4899 · 视频库标签条拖动排序在桌面鼠标下失效
- **报告**：2026-11-15（用户：「我的标签拖动功能怎么没了」「这个没了不如删了」；拼贴改版评审设计稿 V3）
- **真实性**：✅ 真 bug（沿真实代码路径定位；未在真机复现，见备注）。
  - 先查是不是有提交删掉了拖动：`tag_filter_bar.dart` 的 `LongPressDraggable<BookTagRow>` + `DragTarget` 重排路径自 247fc429403（2026-09-09）起未改；视频页 `_buildTagFilterBar` 传 `onReorder: _reorderTags` 的接线自 497a2260900（2026-10-25）起只有缩进变化。**没有删除拖动的提交**，代码路径完整（本地是浅克隆，更早的历史经 GitHub API 逐提交核对 patch）。
  - 根因是手势竞技场：`fushi/lib/src/pages/implementations/tag_filter_bar.dart:289` 标签 chip 只有 `LongPressDraggable` 一条重排路径，它住在 `tag_filter_bar.dart:248` 的 `HorizontalDragScrollable` 横向 `ListView` 里（鼠标按住拖 = 横滚）。鼠标是精确指针，`computeHitSlop(mouse)` = `kPrecisePointerHitSlop` = 1 px：长按 500 ms 计时内手一抖超过 1 px，`DelayedMultiDragGestureRecognizer.checkForResolutionAfterMove` 自行 `rejected`，同一下位移让 Scrollable 的横向 drag recognizer（同为 1 px 门槛）胜出——桌面用户按住标签拖，看到的是标签条在滚、标签不动，表现为「拖动功能没了」。触屏 slop 是 18 px，不受影响。
- **[x] ① 已修复** — 现行实现（2026-11-22 改，见 BUG-5174）：所有指针都长按起拖，`FushiTagChipDraggable` 的长按识别与标签条 `HorizontalDragScrollable(mouseDragController:)` 的鼠标横滚共用 `longPressTolerantHitSlop`（鼠标取 `kTouchSlop`，不再是 1 px），从根上消除「手抖让长按输给横滚」；按下就拖仍归横滚。以下为 2026-11-21 的上一版（见 BUG-5066）：标签 chip 本身按指针类型分流起拖，`fushi/lib/src/media/tags/tag_chip_draggable.dart`（`FushiTagChipDraggable`）接入 `fushi/lib/src/pages/implementations/tag_filter_bar.dart`（书架 / 视频 / 游戏库共用）——鼠标 / 触控板走只认这两类设备的即时 `Draggable`（越过 slop 的同一帧先认领，比滚动区深、横滚抢不到；不动松开仍是单击筛选），触屏 / 触控笔走 `LongPressDraggable`，落点仍是 chip 上的 `DragTarget`。最初的修法是在每枚 chip 左侧加一个「⋮⋮」即时拖动柄（`tag_drag_handle.dart` / `FushiTagDragHandle`），开发者反馈（yC9PzmjPH2）要求删掉柄，BUG-5066 改成上述分流并删除了柄组件。
- **[x] ② 已加自动化测试** — `fushi/test/media/tags/tag_chip_draggable_test.dart`：复现根因（只有长按拖动 + 鼠标 2 px 抖动 → 拖动认输、列表被横滚）+ 鼠标在 chip 上按住即拖重排且列表不滚、鼠标单击仍是点选、触屏短滑归横滚、触屏长按拖重排；`fushi/test/pages/tag_filter_bar_chip_drag_test.dart`（接入层：无前置柄、多选不可拖；鼠标拖 chip 触发 `onReorder(0, 2)`、单击切换筛选、触屏长按拖触发重排）。替换了原柄方案的 `tag_drag_handle_test.dart` / `tag_filter_bar_drag_handle_test.dart`。
- **备注**：仍需桌面真机（Windows，鼠标）复测视频库 / 书架标签条拖动重排（收尾集成时未跑真机与测试）。
