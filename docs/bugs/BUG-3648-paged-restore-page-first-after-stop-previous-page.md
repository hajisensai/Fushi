## BUG-3648 · 页首字紧跟上一页末行的「。」时，存→取退回前一页（学习单位逆映射停在分隔符上）
- **报告**：2026-10-21（PR #2415 CI run 39401882521 `unit-tests (3/4)`：`paginated_page_first_fixed_point_test.dart:57` 的「vertical spread 20px」组每页 `first char N not on page` 且 `restores to <前一页>`；本机 Windows 绿）
- **真实性**：✅ 真 bug，生产代码，与平台 / 字体无关，只取决于页边界落在哪。
  - CI 与本机的差别只是视口：Linux 无头 Chrome 视口宽 1280（`pageSize 1272`），Windows 是 1258×646（`pageSize 1250`）。本机用 `Emulation.setDeviceMetricsOverride` 设 1280×556..572，默认字体 / MS Gothic / Yu Mincho 三种字体都**逐字**复现 CI 原文（`page 1: first char 551 ... restores to 0 not 1272` 直到 page 9 的 5087）。
  - 量到的几何（1280×560、对开 20px）：每个对开恰好装 9 段（每段 63 个学习单位，567 = 9×63），所以每页都从上一段末句「…文章文章。」的「。」之后开始。第 8 段末行「文章×8。」在本页右页首行（x 1220..1249），它前面的「。」（码元 50）在上一对开左页末行（x 1308..1337）。
  - 根因：单位索引 → 文本码元下标的逆映射。`fushi/lib/src/reader/reader_pagination_scripts.dart` 分页 `scrollToCharOffset`（修复前 :3317-3325）、`charOffsetOnCurrentPage`（修复前 :1700-1712）、连续 `collapsedRangeAtCharOffset`（修复前 :4072-4080）都用「数到第 k 个 `isUnitEnd` 就停，取下一个码元」。第 k 个单位结束后的下一码元不一定是第 k+1 个单位的首码点——句读 / 括号 / 空白都不算单位（`reader_study_unit_script.dart` 的 `classify` = 3）。`getFirstVisibleCharOffset` 报页首字 551（第 8 段码元 51「文」），逆映射却停在码元 50「。」：它画在前一页，于是页上校验判不在本页、`restoreToCharOffset` 落到前一页。`charOffsetOnCurrentPage` 原来只跳空白（`/\s/`），没跳句读。
  - 不是 `_spreadScrollContext` 取整：`pageSize` 1272 与 CSS 行周期一致，对开轴、网格、前进后退都对；也不是字体度量本身，字体只决定页边界是否恰好落在「。」之后。横排 / 竖排单条同样会中，只是本语料在那两种几何下没凑出这种页边界。
- **[x] ① 已修复** — `fushi/lib/src/reader/reader_study_unit_script.dart` 新增 `fushiStudyUnits.unitStartOffset(text, k)`：`isUnitEnd` 前缀计数的逆，数完 k 个单位后再跳过分隔符 / 透明码点，落在第 k 个单位的首码点。分页 `scrollToCharOffset`、`charOffsetOnCurrentPage`、连续 `collapsedRangeAtCharOffset`（句首锚）三处改用它。连续的句尾锚（收藏句 `endCharOffset` = 句首 + 句长，开区间）语义是「最后一个单位之后」，所以保留原来的「第 k 个单位结束后」，用 `collapsedRangeAtCharOffset(end, true)` 显式区分，免得句尾锚滑到下一句首字（可能已换到下一行）。
- **[x] ② 已加自动化测试** —
  - `fushi/test/reader/paginated_page_first_fixed_point_harness.mjs` 新增「vertical spread 20px @1280x560」：钉住视口，平台无关；另加 `requireAfterStop`，要求至少一页的页首单位紧跟「。」，防止字体度量变了以后这一例悄悄不再覆盖这个场景。变异实测：把 `unitStartOffset` 的分隔符跳过改成直接 `break`（等价于旧逻辑），本机 Windows 这一例逐字红出 CI 原文；修复版 9 组全绿（该例 10 页、9 页紧跟「。」）。
  - `fushi/test/stats/study_char_count_parity_test.dart` / `.js`：对全部语料的每个 k 断言 `unitStartOffset` 前恰有 k 个单位结束、落点是字母数字、不在词中间，k == count 时落在文本末尾。
- **备注**：
  - 未在真机复测：页边界要恰好落在「。」之后才触发，真机上无法稳定凑出；修复在真 Chrome 跑的生产 shell 上验证。
