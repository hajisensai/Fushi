## BUG-3741 · VN 模式有声书高亮推进时排版变化
- **报告**：2026-10-23（用户：Windows 录屏 `2026-10-23 17-44-22.mp4`，七つの魔剣が支配するII `p-002.xhtml` 段落「　<ruby>赤<rt>しやく</rt>銅<rt>どう</rt></ruby>色の髪をした彼の従兄が、…」，竖排 VN，Klee One 43px / 行高 1.65 / 字重 600）
- **真实性**：✅ 真 bug，真 app 复现。录屏逐帧：当前句从「赤銅…」换到同段下一句「その手前で…」那一刻，带注音的首列行宽少 6px，VN 居中随之整体平移（首列 −3px、其余各列 +3px），首列注音跟着挪。
  - 复现装置：离屏 Windows 集成测试（真 WebView2 155、生产 Dart 管线），原书重新打包成 EPUB + 用户库里该章真实 `audio_cues`（1300–1330 句、时间平移）+ 用户设置真播放。换句后段落 `<p>` 宽度 503.1 → 496.6px，首列与第二列间距 71.0 → 64.7px，88 个字形全部移动；视口 / 文档 / 屏盒 / 居中 margin / 样式表 / CSS 变量 / 计算样式 / 字体状态前后全部不变，强制整块重排宽度不变（不是增量排版过期）。时间线：宽度在 `highlightSentenceAudioCue` 后约 15ms 内变化，同一次调用里唯一的 DOM 改动是把「その手前で…」的文本节点切进新的 `.fushi-sentence-audio-cue` wrapper（另有旧句 wrapper 去掉只改字色的 active 类）。三段小样本、Chrome 无头探针都复现不出——需要整章真实内容拆出的那一屏。
- **根因**：`fushi/lib/src/reader/reader_visual_novel_scripts.dart:3042`（`wrapSentenceAudioCueRangesInBatch`）VN 是播放到哪句才处理哪句（`ensureSentenceAudioInlineTargetsForCue`），在 Blink 上走包裹：句子已经显示在屏上之后才切文本节点、插 wrapper。Blink 对含 ruby 的段落重新排版得到不同的行盒（首列 6.3px），整屏居中跟着平移。WebKit 早已因同类原因（BUG-3518 切开文本节点丢字距）改走 Range，Range 层的判据 `__fushiCueRanges.enabled()` 却只在 WebKit 上为真。分页 / 滚动开章即整章包裹、播放中不再改结构，不受影响。
- **[x] ① 已修复** — `fushi/lib/src/reader/reader_selection_scripts.dart:581` 新增 `__fushiCueRanges.availableForLiveText()`（引擎支持 CSS Highlight 即为真，`__fushiSentenceAudioRangeMode === false` 可强关），`reader_visual_novel_scripts.dart:3049` VN 改用它：任何支持 CSS Highlight 的引擎上当前句都登记成 live Range（`CSS.highlights('fushi-sentence-audio')`，字色走 `::highlight()`，底色窄条层读同一组 Range），屏上 DOM 不再被切；包裹只留给不支持 CSS Highlight 的旧 WebView。分页 / 滚动仍用 `enabled()`，行为不变；WebKit 上两个判据同为真，行为不变。
  - 真 app 复验：同一原场景、生产默认路径，换句前后段落宽度恒为 503.1px（= 不加高亮的原书排版），屏 HTML 是原书原样，零字形移动。
- **[x] ② 已加自动化测试** — `fushi/test/reader/vn_sentence_audio_live_text_test.dart`（跑手 `vn_sentence_audio_live_text_harness.mjs`）：生产 VN shell + 生产 VN CSS 在真 Chrome 里，用原书逐字配对 ruby 段落，断言高亮第一句、推进到第二句时屏上 `innerHTML` 一字不变、当前句由 CSS Highlight 承载且文本恰为该句（不含注音）、所有字形坐标不动。变异对照：VN 退回 `enabled()` 后报 `highlighting the first sentence must not touch the screen DOM`。随改：`highlight_lanes_test.dart` 非 Range 页显式关 Range 以继续覆盖包裹兜底；`favorite_removal_lookup_selection_harness.mjs` 的 VN 页同理；`vn_illustration_screen_harness.mjs` / `vn_lookup_audio_coordinates_harness.mjs` 读当前句改为两条路径都认。
- **三种 view mode**：改动只经 VN 分支生效；分页 / 滚动判据未动，`highlight_lanes_test.dart` 三种模式 × 两种书写方向 × 包裹 / Range 全绿。WebKit（iOS / macOS）上 VN 原本就走 Range，未变，未另上 Mac 复验。
