## BUG-2633 · 视频页查词弹窗内滚轮穿透到画面——词典翻页时音量跟着变
- **报告**：2026-09-22（用户：「现在查词框滚轮穿透了，词典翻页视频音量会跟着动」；Windows 桌面，视频页查词弹窗开着时在弹窗里滚滚轮）
- **真实性**：✅ 真 bug，Windows 离屏 runner 真机复现（`integration_test/video_ctx_mine_confirm_itest.dart`：弹窗上滚 4 格，词典 `scrollTop 0 → 14.5` 的同时播放器音量 `100 → 80` 并刷出音量 HUD；连 barrier 区的滚轮也 `80 → 60`）。根因是 `41fd58c1f2c`（2026-09-22 01:17，悬停查词离开自动续播）给查词浮层加的两个悬停探针：
  - `fushi/lib/src/pages/implementations/video_fushi_page.dart` `_wrapPopupHoverProbe`（浮层内容外）与 `_buildPopupOverlay` 里 barrier 外那层，都是 `MouseRegion(opaque: false)`，注释以为它「只订阅 enter/exit，不改变命中语义」。
  - 实际 Flutter 的 `RenderMouseRegion.hitTest` 是 `super.hitTest(result, position) && _opaque`（`flutter/src/rendering/proxy_box.dart:3339`）：`opaque: false` 时**无条件返回 false**——子树里弹窗矩形的 TODO-805 opaque 吸收层、barrier 的 opaque `ColoredBox` 认领的命中一到这层就被丢掉，父 `Stack` 继续测下一个子项，根 Overlay 的 `_RenderTheater` 继续测下面的视频路由。真机逐层 `hitTest` 取证：`Semantics=true → MouseRegion=false → FadeTransition=false → … → Stack(overlay)=false → _Theater=true`。
  - 于是整个查词 overlay entry 对命中测试透明：`layout.part.dart:375` 视频画面 Listener 的 `onPointerSignal: _handleVideoWheelSignal`（`video_fushi_page.dart:9256`）在弹窗 / barrier 上的滚轮命中路径上，`_onVolumeWheel` 照常改音量；它的门控只排除侧栏与控制条 chrome，不知道浮层存在（`test/shortcuts/video_pointer_channel_reachability_test.dart` 的复刻没有这两层 MouseRegion，所以照样绿）。
- **[x] ① 已修复** — `dictionary_popup_layer.dart` 新增 `lookupOverlayHitClaim({child})`（opaque `Listener` 壳），视频页两处探针都改成「认领壳在外、`MouseRegion(opaque: false)` 在内」：命中重新由 overlay entry 认领，MouseTracker 的 hover 归属一字不改（探针仍非 opaque，指针移到浮层上时 barrier 仍算 hover 中、不误报 exit）。真机复测：弹窗上滚 4 格音量 `100 → 100`、无 HUD、词典 `scrollTop` 照常增加；barrier 区滚轮音量不变。提交见本文件所在修复提交。
- **[x] ② 已加自动化测试** — `fushi/test/pages/lookup_overlay_hit_claim_guard_test.dart`：① 与真页面同形的最小复刻钉住 Flutter 几何事实（裸 `MouseRegion(opaque:false)` 探针让页面 Listener 收到弹窗矩形与 barrier 上的 2 次滚轮）；② 同结构外包 `lookupOverlayHitClaim` 后页面收到 0 次、探针 enter 照常回报；③ 源码守卫钉两处探针都包了且认领层在 MouseRegion 外面。`integration_test/video_ctx_mine_confirm_itest.dart` 真机断言弹窗 / barrier 上滚轮音量不变、弹窗内容照常滚动。
- **备注**：同一根因意味着 09-22 01:17 之后弹窗期间**所有**指针事件都穿到了视频页（不止滚轮）：pointer down / up / hover 也进了页面命中路径（单击靠手势竞技场先到者赢暂未外显；hover 会让 media_kit 控制条在弹窗开着时也被唤起）。media_kit 自带的 `modifyVolumeOnScroll` Listener 判的是 `e.delta`（滚轮事件恒为零）实际不触发，本轮不动它。
