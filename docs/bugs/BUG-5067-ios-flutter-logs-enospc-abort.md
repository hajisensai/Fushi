## BUG-5067 · ios-flutter-logs-enospc-abort
- **报告**：2026-11-21（用户：应用内反馈 AwX7bUtymI，iPad16,2 / iOS 26.6.2 / 3.3.0-debug.28434，启动闪退 x2）
- **真实性**：✅ 真 bug。设备存储写满（日志里大量 `errno = 28`），崩溃栈 signal 6：`flutter_logs` → `Foundation` → `libobjc` 抛 ObjC 异常 → `libc++abi` → `abort`，跑在 flutter_logs 的串行队列上。根因 `flutter_logs-2.2.8/ios/Classes/Logger.swift:50-51`（`FileOutput.process`）与 `:87-88`（`URLOutput.process`）用旧 API `FileHandle.seekToEndOfFile()` / `write(_:)`，I/O 出错（ENOSPC）时抛 `NSFileHandleOperationException`，Swift 接不住 → SIGABRT。触发点是 Dart 侧任何一次 `FlutterLogs.initLogs` / `FlutterLogs.logError`（`fushi/lib/main.dart:759`、`:1061`）。
- **[x] ① 已修复** — `ci/patches/hosted/flutter_logs-2.2.8/ios/Classes/Logger.swift` 整份覆盖进 pub cache（`ci/apply-patches.sh`）：追加改走可抛错 API `do { try seekToEnd(); try write(contentsOf:); try close() } catch { 丢弃本条 }`，建文件 / 打开失败返回 nil，删掉从未赋值的 `fileHandle` 字段与 `deinit` 里的旧 `closeFile()`。iOS 13.4+ API，`fushi/ios/Podfile` post_install 已把所有 pod 钉到 15.1。说明见同目录 `PATCHES.md`。
- **[x] ② 已加自动化测试** — `fushi/test/build/flutter_logs_enospc_patch_guard_test.dart`：补丁目录版本 == `pubspec.lock`、无旧 FileHandle API / `try!`、`appendLine` 的 do/try 顺序与 catch 不碰句柄、两个 Output 都经 `appendLine`、打开失败返回 nil、Podfile pod 部署目标 ≥ 13.4。把上游原件拷回补丁目录时 5 条里 3 条红（变异实测）。Swift 本身不在测试编译面，未在真机上复现磁盘满。
- **备注**：磁盘满时 DB 打不开走的是专屏而非闪退（核实）：`AppModel.initialise` 捕获 `FushiDatabaseUnrecoverableException` 置 `_unrecoverableDbError`（`fushi/lib/src/models/app_model.dart:5994`），`main.dart:2851` 起渲染「数据库无法恢复 / 无法打开」专屏；反馈日志里 01:26:36 已记 `AppModel.initialise.unrecoverableDb`，随后的闪退来自 flutter_logs 写盘，即本 bug。另：该专屏把 ENOSPC 下 sqlite 报的 malformed(11) 当「损坏」提示用户恢复备份 / 清数据，没提示「存储空间不足」——是否区分属另一问题，已另登记 BUG-5076。
