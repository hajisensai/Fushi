## BUG-2890 · 启动会话绑定启动设置对话框后永不改绑主窗口
- **报告**：2026-10-03（agent 在 CatSystem2 / CMVS 官方体验版上跑原始启动路径时发现：会话状态一直是 `window=<对话框 hwnd>/画面モードを選択してください`（CMVS 是 `起動時の設定`），对话框关掉、主窗口 `CoreSystem2` / `cmvs_ctrl_base_app` 出现后也不变，`shot game` 报 `window handle invalid`，CMVS 引擎精确查词因 attached 目标不对停在 `evaluate_calibration_manual_only`，点字直接推进剧情）
- **真实性**：✅ 真 bug，与引擎无关。`fushi/lib/src/mining/gal_hook_session_controller.dart` 的 launch 路径按 pid 取 Z 序第一个顶层窗口当 `boundWindow`；这类引擎进程的第一个可见窗口是启动设置对话框。窗口重绑监视 `_startWindowRebindWatch` / `_tryRebindWindow` 只在**还没绑上**时运行、绑上即自停，之后再没有任何地方核对绑定的窗口是否还活着——对话框一销毁，`boundWindow` 就永远指着死 hwnd，而 attached 查词面、截图、制卡取窗口都从它派生。
- **[x] ① 已修复** — 重绑监视改成跟随整条 launch 会话：首次找到窗口后也启动，不再因已绑定而自停；已绑定时若该 hwnd 不在同 pid 的存活窗口里、而同进程已有别的窗口，就改绑过去并记 `window.rebound` 事件（`_replaceDeadBoundWindow`）。没有替代窗口时保留原绑定（不清空），主窗口切显示模式短暂不可见时不会在 null 与原窗口之间来回跳；主窗口活着时同进程再冒出的窗口（退出确认框等）不会抢走绑定。
- **[x] ② 已加自动化测试** — `fushi/test/mining/gal_hook_session_controller_test.dart`「BUG-2890：启动设置对话框关掉后改绑到随后出现的主窗口」：先绑对话框 → 对话框消失且无替代时保留 → 主窗口出现后改绑并发 `window.rebound` → 主窗口在时冒出的确认框不抢绑定。变异实测：去掉 `_replaceDeadBoundWindow` 调用，该用例变红（Expected 34 / Actual 21）。
- **备注**：真机复测（修复后的 Debug 宿主，原始启动路径，リアライブ体験版v2 `cmvs32.exe`）：会话先 `window.auto_bound` 到「起動時の設定」对话框（hwnd 33693126），点「設定を中止してゲーム起動」后记录 `window.rebound {from: 33693126, to: 33758662}`，33758662 即主窗口 `cmvs_ctrl_base_app`；native 侧 `gal-shield … targetReady/ready request_target=0x2031dc6 surface_target=0x2031dc6`，attached 面跟到了主窗口。（该体验版的引擎精确查词仍不可用，原因另记：现有 CMVS provider 只认 ChronoClock x64 的 exe 哈希，与本 bug 无关。）
