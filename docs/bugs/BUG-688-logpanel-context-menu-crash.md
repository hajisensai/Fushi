## BUG-688 · 日志面板选中文本弹右键菜单崩溃（选区端点空断言）
- **报告**：2026-07-10（用户日志 01:21:05.554/.571 两条同栈连发：`FlutterError: Null check operator used on a null value`，#0 `SelectableRegionState.startGlyphHeight` → #1 `contextMenuAnchors` → #2 `_HibikiLogPanelState._buildContextMenu` → `ContextMenuController.show` → `_LayoutBuilderElement._rebuildWithConstraints` 重建链；TODO-1380）
- **真实性**：✅ 真 bug — 根因 `hibiki/lib/src/utils/components/hibiki_material_components.dart:2362`（修复前）：`_buildContextMenu` 每次 toolbar 重建都读 `selectableRegionState.contextMenuAnchors`。框架链（Flutter 3.44 `selectable_region.dart`）：`contextMenuAnchors`（:1596-1611）只在首次求值用右键位置 `_lastSecondaryTapDownPosition` 当锚点且**用一次即清空**（:1600-1602），之后重建一律退回 glyph 路径 → `startGlyphHeight`（:1777-1779）对 `_selectionDelegate.value.startSelectionPoint!` 空断言；而 `getSelectionGeometry`（:2653-2692）明说 selectable detached/off-screen 时 transform 为 NaN → `if (start.isFinite)` 不成立 → 端点为 null，同时 `_hasSelectionOverlayGeometry`（:408-410，OR 语义）在另一端点仍在时保持为真 → SelectionOverlay 不销毁、菜单不被框架收走，`markNeedsBuild`（`text_selection.dart:1684`，post-frame）触发 overlay entry 重建即崩。日志面板恰好是高危组合：懒加载 `ListView.builder`（离屏行 Selectable 被回收/detach）+ 持续追加的日志流（内容更新触发几何变化 → toolbar 重建），菜单挂着的每一帧都可能踩中部分几何。两条错误相隔 17ms（≈逐帧重建）与机理吻合。
- **[x] ① 已修复** — 锚点自持，消除对选区几何的依赖：面板外层 `Listener.onPointerDown` 先于 SelectionArea 记下**面板内最近一次 pointer down 的全局坐标**（右键/长按召菜单前必然先有一次面板内 pointer down，首帧框架本来就锚在这个位置），`_buildContextMenu` 改用 `TextSelectionToolbarAnchors(primaryAnchor: _lastPointerDownGlobalPosition ?? Offset.zero)`，不再读 `contextMenuAnchors`。每次重建幂等（菜单钉在召出位置不跳动），`startGlyphHeight` 空断言路径从本面板彻底不可达；选区整体消亡时框架仍照常 dispose SelectionOverlay 收走菜单（行为不变）。日志流追加期间菜单保持打开——用户正选中复制日志时新行进来不打断（不采用「内容一变就关菜单」的补丁式绕过）。提交哈希：见分支 `todo1380-logpanel-menu`。
- **[x] ② 已加自动化测试** — `hibiki/test/widgets/log_panel_context_menu_crash_guard_test.dart`：① 行为守卫——右键呼出菜单后经真实重建路径（滚动令选区几何变化 → `SelectionOverlay.markNeedsBuild` → 菜单 post-frame 重建）断言锚点仍钉在右键位置（修复前退回 glyph 路径锚点跳走，即真机上的崩溃点）、无异常、菜单项「复制全部」仍真写穿剪贴板；② 选区整体被回收时菜单被框架优雅收走（无异常）；③ 日志持续追加 5 轮菜单保持打开、锚点不动、无异常；④ 源码守卫——剥注释后禁止 `_HibikiLogPanelState` 出现 `.contextMenuAnchors`/`.startGlyphHeight`/`.endGlyphHeight`/`.selectionEndpoints`，并要求自持锚点在场。headless 复现边界：flutter_test 里 Selectable 回收是同步簿记，起点被回收时选区索引清成 -1、几何整体 none → 框架自己收菜单，「起点 null 终点仍在」的部分几何来自真渲染 detach/NaN 瞬态，headless 打不出那次空断言本身，故守卫钉在同一条重建代码路径的锚点不变式上（与 BUG-119/423/448 同类限制，测试文件头有完整说明）。
- **备注**：行为差异——修复后菜单**始终**锚在召出它的 pointer down 位置：桌面右键与修复前首帧一致；移动端长按菜单从「选区起点上方」变为「按压点上方」（差距一行内，可用性不变）；拖动选区手柄后重新弹出的菜单锚在最初长按点（手柄在 overlay 里，pointer down 不经过面板 Listener）——换取的是崩溃类整体消除，日志面板以桌面排障为主用途，可接受。真机原始失败路径（Windows 桌面日志页选中+右键+日志流追加）建议下次真机值班顺手复测留证。
