## BUG-2742 · 制卡词典图片只声明一维时尺寸与 Yomitan 不一致（小、居中、竖排）
- **报告**：2026-09-27（用户：两张 Anki 预览截图——同一条「語彙力・熟語の百科事典」词条（コンコン），「这种字典含图片的，fushi 和 yomitan 导出的不一样，图二是 yomitan 的，做成一样」。Fushi 卡片上狐狸 / 敲门两张插图缩成小块、居中、上下各占一行；Yomitan 卡片上按原比例、约 10 行高、左对齐并排）
- **真实性**：✅ **真 bug（沿真实代码路径 + 用户本机 Anki 真卡逐条比对 + 上游源码逐行比对）**。截图那张卡不在本机，但本机 Anki 里同一系列词典（語彙力・二字熟語の百科事典）有 Fushi 做的卡 34 张、Yomitan 做的 436 张：Fushi 导出一律是 `width:100em` + sizer `padding-top:10%`（`<img width="8400" height="840">`）；Yomitan 导出是 `font-size:1px;font-size:1em;width:8.57143em` + `padding-top:116.667%`（`<img width="480" height="560">`）。两边的数字互相印证：这本词典的 img 只声明 `height:10, sizeUnits:'em'`、没有 width（该卡的图在 Anki 媒体库里实为 180×210，`<img>` 的 480×560 是 em 图按 `usedWidth×14×2×dpr` 放大后的属性值）。
  - **Yomitan 的语义**：导入器 `dictionary-importer.js` `_createImageData` 把词典 JSON 的 `width`/`height` 存成 `preferredWidth`/`preferredHeight`，`width`/`height` 换成**媒体文件的真实像素尺寸**；生成器 `structured-content-generator.js` `createDefinitionImage` 再算 `invAspectRatio = (pw&&ph) ? ph/pw : 真实高/真实宽`、`usedWidth = pw ?? (ph ? ph/invAspectRatio : 真实宽)`，容器写 `width:${usedWidth}em`；Anki 导出内联 `ext/data/structured-content-style.json`：`.gloss-image-container{font-size:1px}`，仅 `.gloss-image-link[data-size-units=em] .gloss-image-container{font-size:1em}`（`sizeUnits` 只在有 preferred 值时生效）。于是 10 ÷ (210/180) = **8.5714em**。
  - **本仓的根因**：hoshidicts 库里只有词典原始 JSON，没有真实尺寸。`fushi/assets/popup/popup.js:1712`（修复前）`createDefinitionImage` 的解构兜底 `width = 100` 把缺的宽度补成 100，`invAspectRatio = 10/100`、`usedWidth = 100`，导出 100em × 10em 的扁盒子；`max-width:100%` 把它压到卡片宽，`object-fit:contain` 把图缩进这条扁带并水平居中——每张图独占一整行，正是截图症状。
  - **同源的第二处偏差**：`fushi/assets/popup/popup.js:1025`（修复前）`applyImageStyles` 对所有导出图片内联 `font-size:1em`，`:1829` 一律 `${usedWidth}em`。这是 BUG-1062 的改法，它当时认定「Yomitan 卡片上没有 CSS、em 按卡片字号解析」，但 Yomitan 其实把上面的样式表内联进了卡片：非 em 图是 `font-size:1px`（本机真卡：明鏡 `font-size:1px;width:150em` = 150px）。于是非 em 图在 Fushi 卡片上被放大到 150 × 卡片字号、压成满宽。回看 BUG-1062 修复**前**的代码（非 em `Npx`+`1px`、em `Nem`+`1em`），它与 Yomitan 本就同形；当时用户报的「图片小了很多」大概率就是本条的单维声明问题，被误诊成字号问题，所以今天又被报一次。
- **[x] ① 已修复** — 提交 `6fc0a30118a`。根因修（对齐上游数据语义，不是事后 CSS 兜底）：
  - `buildMinePayload`（async）制卡前 `await probeExportImageSizes(idx)`：遍历本词条各义项 structured-content 里的图片（判据同 `renderStructuredContent`：`tag==='img' || type==='image'`），只量「没有同时声明宽高、且不是无尺寸 SVG 外字」的图，用弹窗显示同一个 `rewriteDictionaryMediaPath` URL 起 `new Image()` 取 `naturalWidth/naturalHeight`（弹窗刚显示过，基本命中缓存；单张 3 秒超时，缺图 / 宿主慢就放弃这张）。结果放进 `currentExportImageSizes`，与 `currentDictionaryMedia` 同款由 `buildMinePayload` 开关、不跨制卡存活。
  - `resolveExportImageGeometry` 逐行移植 Yomitan 的尺寸算法（原始 JSON 的 width/height 当 preferred*，量到的当真实尺寸）；导出分支据此写容器 `${usedWidth}em`、sizer 宽高比、`<img>` 的 width/height 属性（em 图 `usedWidth*14*2*dpr`，与 Yomitan 同式）、`data-size-units` 只在有声明尺寸时打。
  - 容器字号恢复 Yomitan 规则：em 图 `1em`、其余 `1px`；无尺寸 SVG 外字的 1.2em 行内框仍是 `1em`（否则会被压成 1.2px；Anki 侧 `_ankiGaijiImageStyle` 的 `font-size:1em!important` 也兜着）。
  - 量不到尺寸时不再回落到 100：沿用 BUG-1676 的「交给 `<img>` 自己定宽高比」，只把词典声明的那一维落到 `<img>`（`height:10em` / `width:Nem`，按容器字号解析）。
  - 弹窗（非导出）路径一行未动。三份 popup.js 镜像同步。
- **[x] ② 已加自动化测试** — `fushi/test/pages/popup_glossary_export_parity_test.js`（Node 真执行 popup.js，沙箱 `Image` 按 path 回真实尺寸，**走真 `buildMinePayload`** 截获导出的图片节点）：(1/4) 用户这张卡的形状（`height:10` em，真实 180×210 / 200×280）→ 容器 `8.5714em` / `7.1429em`、sizer `116.667%` / `140%`、`font-size:1em`、`<img>` 480×560 / 400×560（dpr 2，与 Yomitan 真卡同值）；(2/4) 只声明宽的非 em 图 → `200em` + 真实宽高比 75% + `font-size:1px`；(3/4) 无声明但量到 → `320em` + `1px`（= 真实像素）；(4/4) 量不到 → 容器 `auto`、`<img>` `height:10em`、绝无 `100em`。并纠正 BUG-1062 (1/3)：非 em 图应为 `150em` + `font-size:1px`、`<img>` 150×100；em 图补 `font-size:1em` 断言；无尺寸 SVG 外字容器仍 `1em`。Dart driver `fushi/test/pages/popup_glossary_export_parity_test.dart` 源码守卫改为钉「制卡前先量尺寸且早于 `constructGlossaryHtml`」「导出走 `resolveExportImageGeometry`」「容器字号 `useEmUnits || svgWithoutDimensions ? - **备注**：真 Chromium 取证（headless，真 popup.js + Anki 媒体库里的真图 180×210 / 180×180 喂 `buildMinePayload`）：修复后导出 `width: 8.57143em` / `10em`，与 Yomitan 真卡逐字一致；修复前三张全是 `width: 100em`，渲染出来正是用户截图的「小、居中、竖排」，修复后与 Yomitan 卡并排同尺寸。真机肉眼复测待用户：桌面 Anki（AnkiConnect）用「語彙力・熟語の百科事典」查コンコン制卡，卡片插图应与 Yomitan 卡一致（约 10 行高、按原比例、左对齐并排）。未改的已知差异：Yomitan 导出还内联了 `.gloss-image-link[data-collapsed=true] .gloss-image-container{display:none}`（`collapsed:true` 的图在 Yomitan 卡片上不显示），Fushi 仍显示——与本条尺寸问题无关，改动会让现有卡片少图，留给用户决定。
