## BUG-4285 · 互联主机停止或启动失败回滚时绕过 P2P 串行队列，隧道转发残留
- **报告**：2026-11-10（用户：互联 host 安全审查 H8）
- **真实性**：✅ 真 bug。（行号按 94317ab6295）app 端 P2P 挂载有两个所有者：`fushi/lib/src/sync/fushi_server_controller.dart:992` 的 `stop()` 直接 `currentAppInterconnectP2pRuntime?.current?.hostStop()`，不经 `_serializeP2p`；`:758-768` 的 `_rollbackFailedStart` 根本不 `hostStop`；`:1027-1045` 的 `_attachP2p` 最后一道检查写成 `if (!stillWanted() || !await _repo.isInterconnectP2pEnabled())`，先求 `stillWanted()` 再 await 偏好，await 回来直接 `node.hostListen(port)`。`setP2pEnabled(true)` 发起的 attach 不归 `_starting` 管，stop 落在这次偏好读取里时序列是 `[hostStop, hostListen]`——host 已停、隧道仍对公网转发到已关的端口；启动时广播抛出走回滚，`hostListen` 残留。修复前测试实测两条都红（`[hostStop, hostListen]` / 回滚后序列末项是 `hostListen`）。无头端（`headless_host.dart:744-756`）已是单一序列，不受影响。
- **[x] ① 已修复**（`876dfab85d4`）— 新增测试缝接口 `InterconnectP2pHostPort`（available / ensure / hostListen / hostStop / hostPeer / hostAddresses / restart，默认实现走本进程运行时），控制器的挂载、卸载、换中继全部经它并在 `_serializeP2p` 里调用；`stop()` 摘下 `_server` 后 `await _detachP2p(server)`（排在所有在飞 attach 之后），删掉直连 `hostStop()`；`_rollbackFailedStart` 在 `server.stop()` 之前 `await _detachP2p(server)`；`_attachP2p` 每次 await 之后都先拿到偏好值、最后再求 `stillWanted()`，最后一道检查到 `hostListen` 之间没有 await。构造参数 `broadcastFactory` 原样透传给 `LanBroadcastService`。
- **[x] ② 已加自动化测试** — `fushi/test/sync/server_p2p_lifecycle_test.dart`（真控制器 + 真 server，假隧道端口记调用序列）：用 drift `QueryInterceptor` 与假端口的 `ensure` 把 stop 精确插在 attach 的每个 await 上（偏好读 #1 / ensure / 偏好读 #2 / 偏好读 #3），断言最后一次 hostListen 之后必有 hostStop 且 stop 完成后不再有隧道调用——修复前「偏好读 #3」红（`[hostStop, hostListen]`）；另有 0..40 个事件循环轮次的扫描；启动时 `broadcastFactory` 抛出 → `FushiServerStartError` 且序列末项为 hostStop——修复前红（末项 hostListen）。
- **备注**：取舍 T8：`stop()` 现在会等在飞的 P2P 挂载落地（最长一次 `runtime.ensure()`）再卸下。
