## BUG-4230 · 查词弹窗按住时子弹窗就位导致平台视图丢指针：滑不动、点词失效、选区菜单关不掉
- **报告**：2026-11-06（用户：应用内反馈 5hnsRtTrQj，Android 3.3.0-debug.23880 vivo 手机；看视频查词时常带出选区和「搜索 / 复制 / 分享 / 网页搜索」菜单，之后点别处关不掉、查词框滑不动、二级查词失效，关掉重查仍坏，只能退出视频重进）
- **真实性**：✅ 真 bug，两半：
  - 菜单关不掉（fork 插件自画的 floatingContextMenu 只能靠 WebView 自己收到单击关闭）——已由 BUG-4180（`30b763e7d4`）修好，用户的 23880 包不含该提交。
  - 滑不动 / 点词失效 / 重开仍坏——develop 仍在。`fushi/lib/src/pages/implementations/dictionary_popup_layer.dart:661`（旧）`parkedPopupLayer` 用 `visible && occluders.isNotEmpty ? PopupOccluderClip(...) : child` 按条件增删一层包装，`PopupOccluderClip.build`（旧 `:707-719`）在 Android / 无遮挡时又直接 `return child`。父层的 `occluders` 由子弹窗入场就位（`dictionary_page_mixin.dart` `entranceSettled`）/ 关闭在空与非空之间翻转，父层里带 GlobalKey 的查词 WebView 随之搬家：Flutter `PlatformViewRenderBox.detach` → `_PlatformViewGestureRecognizer.reset()`（`flutter/lib/src/rendering/platform_view.dart:668-674,841`）直接丢掉正在转发的指针、不补 cancel。手指按住时撞上这一刻，这根手指的 UP 永远到不了 Android 平台视图，controller 的 MotionEvent 指针表里留下幽灵手指；此后每次触摸都被当成第二根手指（捏合，`supportZoom: false`）——不滚动、不产生 click（JS 点词与点击清选区都不触发）、插件 `onSingleTapUp` 不来、菜单不关；静止的幽灵手指满长按时长还会自己触发选词（用户说的「不小心的选中」）。视频页第 0 层是常驻热槽（`video_fushi_page.dart` 关闭只隐藏），坏 controller 一直复用到退出视频页。
- **[x] ① 已修复** — 平台视图上方的祖先结构在层的生命周期内恒定：`parkedPopupLayer` 恒包 `PopupOccluderClip`（隐藏时传空遮挡），`PopupOccluderClip` 恒返回同一个 `ClipPath`，不裁时 `clipper: null` + `Clip.none`（命中不受限、不推裁剪层，iOS / macOS 原生材质不受影响）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/popup_layer_platform_view_pointer_test.dart`：真 `parkedPopupLayer`，Android / Windows 两种平台下 occluders / visible 反复翻转，带 GlobalKey 的探针 RenderObject 零 detach；真 `PlatformViewSurface` + 竖滑手势组，手指按住期间 occluders 翻转后，平台视图 controller 仍收到这根手指的抬起。改前三条均红（detach 4 次；抬起 0 次）。
- **备注**：未在真机复测（按约定不做）；缺口是「弹窗里点词出子窗、子窗淡入期间按住父窗」之后父窗是否还能滑。Flutter 上游 `reset()` 不给已转发指针补 cancel 的行为本仓不改 SDK。
