## BUG-5590 · 点开视频字幕侧栏，滑入动画卡住大半秒：字幕源枚举两次整页重建
- **报告**：2026-11-27（用户：视频点出字幕侧边栏掉帧，录屏里半透明的中间帧停住约 0.8 秒后一帧跳到终态）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/pages/implementations/video_fushi/subtitle.part.dart:855`（修前）：字幕面板挂载后的帧回调（`video_quick_settings_sheet.dart` `_notifySubtitleCategoryShownAfterFrame`）调 `_ensureSubtitleMenuSourcesLoaded`，它在枚举开始（`_rebuild(() => _subtitleMenuLoading = true)`）与结束（`:880` 写入结果）各做一次**整页 setState**。侧栏挂在整页 build 的 `ValueListenableBuilder` 里，页面一重建，builder 闭包换新，整块面板（几百个 widget）从头 build / layout 一遍；`Video` 同时拿到新参数，`VideoViewParameters` 变化，media_kit 控件层也整层重建。两次大帧正压在滑入动画中间。字幕源按视频路径缓存，所以是「每集首次点开字幕面板」必现，同一集再开不会。
  - 证据（Windows 离屏真 app，debug，2864×1766 @144 Hz，`integration_test/video_side_panel_raster_perf_itest.dart`）：首开逐帧 build 544 / 193 / 177 ms，帧间空档 572 ms；脏根探针在面板祖先链上抓到 `VideoFushiPage(_VideoFushiPageState)`（打开后约 44 ms，调用栈 `_rebuild` ← `_ensureSubtitleMenuSourcesLoaded` ← `_notifySubtitleCategoryShownAfterFrame`）与 `ValueListenableBuilder<VideoViewParameters>`。
  - 排除项：一开始怀疑厚材质面板在 premium 玻璃档逐帧跑液态玻璃全管线着色器，同一次运行里交替量 premium / standard / minimal：面板开着的稳态 raster p50 2.0–2.9 ms，三档无差别，raster 不是瓶颈，该方向作废。
- **[x] ① 已修复** — 字幕轨菜单的「源列表 + 加载中」改由 `_subtitleMenu`（`ValueNotifier`）承载（`video_fushi_page.dart`，保留同名 getter / setter），枚举流程与 YouTube 字幕轨懒加载只改 notifier、不再整页 `_rebuild`；唯一显示它们的字幕轨区 `_buildSubtitleTrackSettingsSection` 用 `ValueListenableBuilder` 监听、只重建本区。
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_side_panel_open_rebuild_guard_test.dart`（源码守卫：枚举 / YouTube 懒加载不调 `_rebuild`，字幕轨区监听 `_subtitleMenu`，不退回裸字段；media_kit 无法 headless，整页 widget 测试驱不动真播放器）；真 app 行为由 `fushi/integration_test/video_side_panel_raster_perf_itest.dart` 断言（首开 / 重复打开期间面板祖先链上不再出现整页或 `VideoViewParameters` 脏根），同时输出各阶段帧时。BUG-1329 的两条守卫（`video_subtitle_menu_refresh_guard_test.dart`）按新写法更新字面匹配，不变量不变。
- **备注**：同一集重复打开仍有面板首次挂载本身的成本（debug 下单帧 build 约 240 ms，release 小得多），不在本条范围；本机离屏 runner 只有 debug 构建，release 观感待用户在真机复测。
