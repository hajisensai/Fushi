## BUG-4102 · 查词弹窗词头元数据列 ResizeObserver 同步写布局：每次弹窗变宽都报 loop 错误灌满错误日志，且逐词条强制回流
- **报告**：2026-11-05（应用内反馈 `3op205DyWN`「阅读时卡住」：Android 16 Xiaomi 23116PN5BC，3.3.0-debug.23469。点词后卡住，再点一次屏幕弹窗才出来，关掉弹窗后又卡住，退出小说恢复；「检查发现出现了 200 条错误报告」）。
- **真实性**：✅ 真 bug（错误日志那一半）；「卡住」本身的根因**未从日志定位**。
  - 日志本次运行段正好 200 条（`ErrorLogService._maxEntries`，`fushi/lib/src/utils/misc/error_log_service.dart:41`），**全部**是 `PopupJs.window.onerror: ResizeObserver loop completed with undelivered notifications.`（`popup.html:0:0`）；整份日志里同一句共 1489 条，按查词节奏一秒 3–4 条地来。
  - 来源：`fushi/assets/popup/popup.js` 的词头元数据列布局（旧 `updateEntryHeaderMetaLayout` / `observeEntryHeaderMetaLayout`，修前约 `:6849-6884`）。ResizeObserver 回调里**同步** `header.classList.toggle('meta-stacked', …)`，叠放与否改的是被观察的 `.entry-header` 自身的高；它是该轮投递里最浅的目标，规范规定这种变化只能推到下一帧，Chrome 于是每次都抛这条错。弹窗宽度一变（竖排按选区两侧空间定宽、每次查词宽度都不同、拖尺寸）就触发一次，经 `popup.js:131` 的 `__fushiReportJsError` → `reportJsError` 桥 → `logPopupJsError`（`dictionary_popup_webview.dart:4475`）落进错误日志，把 200 条上限整页挤满——卡住那段时间里真正的报错全被挤掉。
  - 同一回调里逐个 header「读 `clientWidth` / `getComputedStyle` / `scrollWidth` → 写类」交替，后一个 header 的读把前一个的写强制同步回流（layout thrashing）。headless Chrome 实测（桌面，30 / 100 / 300 个词条、每条约 200 个释义节点）：回调耗时 11 / 43 / 119 ms，修后 1 / 3 / 8 ms。手机慢数倍；Android 上同一应用的所有 WebView 共用一个渲染进程主线程，弹窗这段阻塞同样压在正文 WebView 上。
  - 未定位的部分：日志只有错误日志与诊断段，没有帧耗时 / JS 长任务 / 主线程栈，`00:31:59` 之后再无弹窗错误，`00:32:38` 有一次系统内存压力（rss 1387 MB，`00:33:52` 降到 717 MB，与「退出小说后恢复」吻合）。上面的回流量级（百 ms 级）解释不了「关掉弹窗后一直卡到退出小说」的持续卡死，不能据此宣称卡住已修。
- **[x] ① 已修复（错误灌满日志 + 回流）** — `popup.js` 拆成只读的 `measureEntryHeaderMetaStacked` 与批量的 `updateEntryHeaderMetaLayouts`（先把整批 header 量完、再只给真变了的写类）；ResizeObserver 回调只把 header 登记进 `__fushiHeaderMetaDirty`，在下一帧 `requestAnimationFrame` 里统一 flush，写布局不再发生在投递期间；换代渲染时连同 observer 一起清掉脏集合。判据逐字不变。浏览器扩展两份镜像（`fushi/assets/browser_extension/vendor/popup.js`、`tools/browser-extension/vendor/popup.js`）同步。
- **[x] ② 已加自动化测试** —
  - `fushi/test/dictionary/popup_header_meta_resize_observer_test.dart`（`chrome` tag）驱动 `popup_header_meta_ro_harness.mjs`：真 Chrome 加载生产 `popup.css` + `popup.js` 这一段，30 个同构词头先观察、再拖宽、再拖回窄，断言叠放结果 30 / 0 / 30 且 ResizeObserver 报错为 0。修前红（`errors: ["ResizeObserver loop completed with undelivered notifications."]`），修后绿。
  - `fushi/test/dictionary/popup_header_meta_stacked_test.js`（经同名 `.dart` 驱动 node）新增：整批里没有任何一次读落在写之后、状态没变不再写；ResizeObserver 回调里不写类、同一帧只排一次 rAF、rAF 里统一写。
- **备注**：代价是窗口尺寸变化后叠放切换晚一帧落地（首次渲染时弹窗还在挂起显示 / 入场淡入，看不出）。卡住的真因需要设备侧证据（帧耗时、正文 / 弹窗 WebView 的 JS 长任务）；修掉这条噪音后错误日志不再被挤满，下一次复现的日志才有用。未做真机验证。
