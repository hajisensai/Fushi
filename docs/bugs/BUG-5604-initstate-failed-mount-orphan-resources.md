## BUG-5604 · State 的 initState 半途抛错后，已挂上的订阅 / 监听 / Timer 成孤儿（全页面通用）
- **报告**：2026-11-28（用户：BUG-5602 查出的通用生命周期缺陷要根治，不只挪视频库页的代码顺序）
- **真实性**：✅ 真 bug。Flutter 3.50 `Element.inflateWidget` 在 `newChild.mount` 抛错时走 `_deactivateFailedChildSilently`（`packages/flutter/lib/src/widgets/framework.dart:4612/:4665`）：只 `deactivate`，元素不进 inactive 列表、**永不 unmount**，所以 `State.dispose` 永不调用、`State.mounted`（`_element != null`，:975）一直是 true。initState 里在抛错点之前挂上的流订阅、监听、Timer、观察者于是既不会被 dispose 撤掉、`mounted` 闸门也挡不住；之后它们的回调在停用的元素上读 `ref` / `context` 即断言「Looking up a deactivated widget's ancestor is unsafe」，同时泄漏。修复前在视频库页复现：initState 在 `libraryRefreshSignal.addListener` 处抛错后，再往库里写一条视频，孤儿 uid 订阅走 `_refreshAfterVideoUidsChanged` → `_loadLibraryMapsInner`（`home_video_page.dart:1961`）、孤儿观看进度订阅走 `_onWatchProgressChanged` → `_loadWatchRecency`（:1938），都撞这条断言；导入落点 `VideoLibraryDropPort` 也一直挂着孤儿页。所有页面基类（`BaseModuleTabPageState` 的 shell tab 监听、`BaseTabPageState` 的 tab 刷新监听、`BaseSourcePageState` 的外部导航注册与标题栏单击监听）同样在子类 initState 之前就挂上，子类任何一处抛错都会把它们留成孤儿。
- **[x] ① 已修复** — 新增仓库级资源登记器 `StateResourceScope`（`fushi/lib/src/utils/state_resource_scope.dart`）：`ownSubscription` / `listenTo` / `ownTimer` / `onTeardown` 把 initState 挂的外部资源登记进一份撤销清单，dispose 与挂载失败两条退场路径共用、按登记逆序撤、每条隔离（抛错经 `FlutterError.reportError` 上报，不挡其余）。
  - 挂载失败的判据：框架在 `_firstBuild` 里 initState 返回后紧接着调第一次 `didChangeDependencies`；走到 `deactivate` 时还没见过它 = initState 半途抛错。另在 initState 里排一个微任务兜底（同步挂载结束后仍没见过 `didChangeDependencies` 即判失败）：子类 `deactivate` 覆写在调 super 之前抛错时框架吞掉异常、走不到本 mixin 的 `deactivate`，靠这条照样撤。GlobalKey 移位（deactivate → activate）不误判。
  - 清单撤过之后再登记的资源当场撤销；`schedulePostFrame` 代替 initState 里的 `addPostFrameCallback`，挂载失败 / 已 dispose 后不回调（失败那一帧框架照样跑 post-frame 回调，孤儿 State 的 `mounted` 恒为 true 挡不住）；`resourcesReleased` 给撤不回来的异步任务当代次闸门（`main.dart` 的 ctl 服务起好时据此当场停掉）。
  - 顺序有依赖的进程级注册（`ExitFlushRegistry`、`readerSessionRemotes`、`videoPlaybackRemotes`、`VideoDisplayClaim`、控制器查词、PiP / 全屏交接、`SharedLookupPopupHost.attach`）同样在 initState 登记，`onTeardown` 返回 `ScopedRelease` 句柄，dispose 在原来的位置逐条 `release()`（幂等，清单收尾时跳过）；`releaseResources()` 让 dispose 在指定位置一次撤完。词典页 / Texthooker 先登记私有宿主的 `dispose`、再 `attach` + 登记 `detach`，逆序撤销保证总是先 detach 后销毁宿主。
  - `BasePageState` 直接 mix 它，整个页面家族自带；基类自己的监听 / 注册改为登记。`lib/` 全部 initState 的裸挂资源已迁完（含 `MediaServerUserDataRefresh` 等 mixin，要求使用方先 `with StateResourceScope`）。dispose 里与之重复的手工撤销删除。
  - 音乐库、互联配置、仪表盘、视频 / 漫画 / 小说阅读器、`main.dart` 的 initState 里先于挂资源起跑的 `unawaited` 任务移到 initState 末尾；首页的网页制卡后台调度器（同步起跑）登记撤销。
  - **不覆写 `mounted`**：覆写后 `use_build_context_synchronously` 不再认它是 `State.mounted`，全仓 async 闸门都会报警（实测视频库页一文件 13 条）。
- **第三轮：`didChangeDependencies` / `didUpdateWidget` 同样会留孤儿，已纳入**（框架 `framework.dart`）：
  - 首次 `didChangeDependencies` 抛错与 initState 抛错走同一条 `_deactivateFailedChildSilently`，但 mixin 已经在 `super` 里记下「见过 dCD」，旧判据漏掉它；
  - `didUpdateWidget` 抛错由父级 `ComponentElement.performRebuild` 的 catch（:5828-5876）接住：只对旧子元素做一次非递归 `deactivate`、换成 ErrorWidget，旧子树永不 dispose，子孙连 deactivate 都没有；
  - 之后的 dCD 抛错走 `buildScope` 的 catch，不留孤儿。
  - 判据改为「帧后仍处于停用态」：正常停用在同一帧的 `finalizeTree` 里就 unmount → dispose 或被 GlobalKey 重新 activate，post-frame 回调时还停着且没撤过 = 孤儿。`deactivate` 时没见过 dCD 当场撤；见过的排一个帧后检查（并 `ensureVisualUpdate`），孤儿时连同子孙里的 `StateResourceScope` 一起撤。
  - 新增 `slot:`：同一槽位再登记先撤上一条，`didUpdateWidget` 换对象重挂、helper 里反复重排的 Timer / 订阅不再越攒越长；`listenTo` 接受 null（只摘旧的）；`scheduleScopedMicrotask` 代替构建期内的裸 `scheduleMicrotask`。
  - 守卫升级为 `package:analyzer` 语法树扫描（`fushi/test/build/initstate_resource_scan.dart`，不走分析器插件）：从 initState / dCD / dUW 出发顺着本类私有方法展开（异步 helper 只扫到第一个挂起点），报出裸挂的订阅 / 监听 / Timer / 观察者 / handler / `AppLifecycleListener` / post-frame / 微任务 / 赋给别的对象的回调（`other.onX = …`）；本类自建对象上的监听不计；撤销登记须在挂之前或紧跟其后、且源码对得上同一接收者与回调。首次扫出 377 处（initState 143 / dCD 58 / dUW 176；监听约 190、post-frame 52、Timer 34、流订阅约 20、回调赋值 / 观察者 / handler 等其余），全部迁完，零容忍。迁移中顺带修掉多处 `onTeardown(() => widget.x?.removeListener(...))`：撤销时读的是当时的 `widget`，换过 widget 后摘错对象。
- **[x] ② 已加自动化测试** — `fushi/test/utils/state_resource_scope_test.dart`：失败路径回滚订阅 / 监听 / Timer / 自定义撤销且只撤一次、失败后才登记的资源当场撤；正常 dispose、GlobalKey 移位不撤；一条撤销抛错不影响其余；`deactivate` 覆写在 super 前抛错由微任务兜底撤销（去掉兜底即红）；`releaseResources` 与 `ScopedRelease` 提前撤的顺序；`schedulePostFrame` 挂载失败不回调。`fushi/test/pages/home_video_failed_mount_background_work_test.dart` 第二条（视频库页 initState 半途抛错后导入落点已撤、之后写库与切回视频 tab 不再触达孤儿 State）——修复前红（`dropPort.attached` 仍为 true；去掉该断言后异步区抛出上述两条 deactivated 断言），修复后绿。`fushi/test/pages/shared_lookup_popup_host_teardown_order_test.dart` 锁定词典页 / Texthooker 的 attach / detach / 宿主 dispose 顺序（源码范式 + 同范式在正常退场、挂载失败、共享宿主三种情形的行为）。守卫 `fushi/test/build/initstate_resource_rollback_guard_test.dart` 零容忍（语法树扫描，见上），另有扫描器自检锁定各类裸挂逐条报出、已登记 / 自建对象 / 先登记的撤销不计。第三轮在 `state_resource_scope_test.dart` 补：首次 dCD 抛错、dUW 抛错（本 State 与子孙一并撤）、槽位替换、正常停用 + dispose 不被帧后检查重复撤。
- **备注**：仍未覆盖：已经起跑的 Future 撤不回来，只能靠「放 initState 末尾」+ `mounted` / `resourcesReleased` 闸门；守卫只展开本类私有方法，跨类 helper / 基类方法里挂的资源靠基类自己登记。
