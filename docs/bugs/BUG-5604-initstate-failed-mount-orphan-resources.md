## BUG-5604 · State 的 initState 半途抛错后，已挂上的订阅 / 监听 / Timer 成孤儿（全页面通用）
- **报告**：2026-11-28（用户：BUG-5602 查出的通用生命周期缺陷要根治，不只挪视频库页的代码顺序）
- **真实性**：✅ 真 bug。Flutter 3.50 `Element.inflateWidget` 在 `newChild.mount` 抛错时走 `_deactivateFailedChildSilently`（`packages/flutter/lib/src/widgets/framework.dart:4612/:4665`）：只 `deactivate`，元素不进 inactive 列表、**永不 unmount**，所以 `State.dispose` 永不调用、`State.mounted`（`_element != null`，:975）一直是 true。initState 里在抛错点之前挂上的流订阅、监听、Timer、观察者于是既不会被 dispose 撤掉、`mounted` 闸门也挡不住；之后它们的回调在停用的元素上读 `ref` / `context` 即断言「Looking up a deactivated widget's ancestor is unsafe」，同时泄漏。修复前在视频库页复现：initState 在 `libraryRefreshSignal.addListener` 处抛错后，再往库里写一条视频，孤儿 uid 订阅走 `_refreshAfterVideoUidsChanged` → `_loadLibraryMapsInner`（`home_video_page.dart:1961`）、孤儿观看进度订阅走 `_onWatchProgressChanged` → `_loadWatchRecency`（:1938），都撞这条断言；导入落点 `VideoLibraryDropPort` 也一直挂着孤儿页。所有页面基类（`BaseModuleTabPageState` 的 shell tab 监听、`BaseTabPageState` 的 tab 刷新监听、`BaseSourcePageState` 的外部导航注册与标题栏单击监听）同样在子类 initState 之前就挂上，子类任何一处抛错都会把它们留成孤儿。
- **[x] ① 已修复** — 新增仓库级资源登记器 `StateResourceScope`（`fushi/lib/src/utils/state_resource_scope.dart`）：`ownSubscription` / `listenTo` / `ownTimer` / `onTeardown` 把 initState 挂的外部资源登记进一份撤销清单，dispose 与挂载失败两条退场路径共用。挂载失败的判据：框架在 `_firstBuild` 里 initState 返回后紧接着调第一次 `didChangeDependencies`，走到 `deactivate` 时还没见过它 = initState 半途抛错，此时逆序撤销全部登记；清单撤过之后再登记的资源（initState 排的 postFrame 回调在失败后那一帧仍会跑）当场撤销。GlobalKey 移位（deactivate → activate）不误判。`BasePageState` 直接 mix 它，整个页面家族自带；基类自己的监听 / 注册改为登记。迁移了视频库页与盘点出的高风险 State（裸挂 ≥4 个）：`main.dart` 应用根、悬浮球宿主、首页、仪表盘、词典页 / 查词对话框、书库 / 音乐 / 游戏库、视频 / 网页视频 / 漫画 / 小说阅读器、Texthooker、游戏串流、图形字幕遮挡层、互联服务配置、媒体源视图。dispose 里与之重复的手工撤销删除，同一份清单只写一次。**不覆写 `mounted`**：覆写后 `use_build_context_synchronously` 不再认它是 `State.mounted`，全仓 async 闸门都会报警（实测视频库页一文件 13 条）；所以已经起跑的 Future 撤不回来，仍按 BUG-5602 的做法把首帧取数 / 后台任务放在 initState 最后一步。
- **[x] ② 已加自动化测试** — `fushi/test/utils/state_resource_scope_test.dart`（最小 State：失败路径回滚订阅 / 监听 / Timer / 自定义撤销且只撤一次、挂失败的监听不登记、失败后才登记的 postFrame 订阅当场取消；正常 dispose 撤销、GlobalKey 移位不撤；一条撤销抛错不影响其余且照常上报）；`fushi/test/pages/home_video_failed_mount_background_work_test.dart` 第二条（视频库页 initState 半途抛错后导入落点已撤、之后写库与切回视频 tab 不再触达孤儿 State）——修复前红（`dropPort.attached` 仍为 true；去掉该断言后异步区抛出上述两条 deactivated 断言），修复后绿；守卫 `fushi/test/build/initstate_resource_rollback_guard_test.dart` 扫 `lib/` 每个 initState 的裸挂资源，存量按「文件::类 → 个数」冻结在 `initstate_resource_rollback_baseline.txt`，只减不增，新写的 State 必须走登记。
- **备注**：存量还有约 176 个 State 在基线里（多为每个 1～3 个裸挂的组件级 State），按守卫只减不增逐步迁。未覆盖：① 已经起跑的 Future（`unawaited(_load())`）撤不回来，部分页面（音乐库、互联配置、仪表盘、首页、`main.dart`、视频播放页）的 initState 里仍有先于挂资源起跑的异步任务，只能靠「后台任务放最后」的约定；② 非 Listenable 的进程级注册（`ExitFlushRegistry` / `readerSessionRemotes` / `videoPlaybackRemotes` / `VideoDisplayClaim` / `PopupHost.attach` 等）因 dispose 里撤销顺序有依赖暂未登记；③ 子类 `deactivate` 覆写若在调 super 之前抛错，框架吞掉异常、撤销不会执行。
