## BUG-568 · 竖排跳章落点错误(章界输入穿透+图片late-load冻结)
- **报告**：2026-07-06（用户：看板 TODO-1229，headless Chrome 实证 + 4 截图法证）
- **真实性**：✅ 真 bug。双缺陷协同（1179 的 +1px 容差盖不住）：
  - **根因①（输入穿透·首要）**：`hibiki/lib/src/pages/implementations/reader_hibiki/chrome.part.dart:35` `_paginate` 及 `hibiki/lib/src/pages/implementations/reader_hibiki/webview.part.dart:1622` `onBoundarySwipe` 无「导航/恢复在飞」守卫。滚轮惯性节流(450ms) < 换章加载(数百 ms restore)，跨章那一下之后排队的翻页 tick 在新章 restore 未落定时立即再翻 → 章首插图页/首页整页被越过；更糟 `hoshiReader` 未就绪时 `evaluateJavascript` 返 null → `_didScroll(null)=false` → 再 `_handlePageTurnLimit` → **跳两章**。
  - **根因②（落点冻结快照）**：`hibiki/lib/src/reader/reader_pagination_scripts.dart` `_sharedInitImages` 图片 late-load 回调（原 1569-1574）只失效 `paginationMetrics` 不重锚。backward 跳章 `restoreProgress(0.99)` 落 `contentLastPageScroll`（restore 瞬间布局）后，章首懒加载 block 图 load → 整章几何后移 → 冻结 scrollTop 错一行（Chromium 只在 scrollTop=0 自愈）。
- **[x] ① 已修复** — 案A：`_paginate` 入口 + `onBoundarySwipe` 加 `_paginationInFlight`（`_restoreInFlight || !_readerContentReady || _isNavigatingToChapter`）守卫丢弃瞬态窗口输入（`chrome.part.dart` 新增 getter + 入口守卫；`webview.part.dart` onBoundarySwipe 收口）。案B：`reader_pagination_scripts.dart` paginated `restoreProgress` 记录章首(0)/章末(≥0.99)重锚资格 `__imgReanchorProgress`，`paginate` 入口清资格（用户翻页放弃），图片 load 回调命中资格时重放 `scrollToProgressPaged` 语义重锚（程序化滚动，不污染 TODO-798 userDriven 因果门）。提交见本轮。
- **[x] ② 已加自动化测试** — `hibiki/test/pages/chapter_jump_pagination_in_flight_guard_test.dart`（案A 源码守卫：`_paginate`/`onBoundarySwipe` 均含 `_paginationInFlight` 且守卫先于 paginator 调用/跨章）+ `hibiki/test/reader/chapter_jump_late_load_reanchor_test.dart`（案B JS 守卫：restoreProgress 记录资格·paginate 清资格·图片 load 回调重放·连续 shell 不误触）。
- **备注**：红线遵守——未动 `window.hoshiReader` 符号；未破 BUG-162/1179 的 +1px 容差/floor；未引入 IntersectionObserver（BUG-007 教训）；TODO-798 userDriven 因果门不被案B重放污染。每章加载重建 `window.hoshiReader`，`__imgReanchorProgress` 无跨章残留。1179 的 ±1 行 overhang 残留按原 decision 单独立项，不混本 bug。
