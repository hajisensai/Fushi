## BUG-1423 · 阅读器悬浮控制栏快捷键未驱动临时显隐状态
- **报告**：2026-08-02（用户：）
- **真实性**：✅ 真 bug。根因在 `hibiki/lib/src/pages/implementations/reader_hibiki/caret.part.dart:530`：`ShortcutAction.readerToggleChrome`（键盘 + 手柄同一入口）无条件调挤压模式旧入口 `_toggleChrome()`（`reader_hibiki/chrome.part.dart:965`），只翻 `_showChrome`。而 TODO-975 之后底栏默认是**悬浮**形态：`_showChrome` 退化成不可见的「底栏功能是否启用」持久开关，真正决定画不画栏的是 `_chromeTransientVisible`，自动收起由 `_chromeAutoHideTimer` 驱动（`chrome.part.dart:1090` `_handleFloatingChromeReveal`）。指针路径（点空白 `webview.part.dart:2016/2053/2080`、点顶部进度 `chrome.part.dart:1884`）走的是那台状态机，快捷键既不改真实可见态也不续期计时器 → 表现为「按键没反应，必须先用鼠标点空白唤栏」，且旧计时器到点仍会在操作中途收栏。
- **[x] ① 已修复** — 新增 `_toggleChromeFromShortcut()`（`reader_hibiki/chrome.part.dart`，紧邻 `_toggleChrome`）：底栏悬浮时复用指针路径同一台状态机 `_handleFloatingChromeReveal()`（可见→取消计时并收起，隐藏→唤出并重新武装计时），再经 `FocusReclaimCause.chromeToggled` 把焦点确认回正文（与 `_toggleChrome` 同一 cause）；底栏仍是挤压模式（含「只顶部进度悬浮」的混合形态）时保留 `_toggleChrome()` 旧语义。`readerToggleChrome` 分支改走这个唯一入口，键盘与手柄同时受益。
- **[x] ② 已加自动化测试** — 新增 `hibiki/test/reader/reader_floating_chrome_shortcut_guard_test.dart`（读 `reader_hibiki_page_source_corpus.dart` 合并语料，切片前剔除整行注释防注释真空通过）：锁 `readerToggleChrome → _toggleChromeFromShortcut()` 接线 + **负向**断言该分支不再直调 `_toggleChrome();`、helper 的悬浮/挤压分流与统一焦点回收、以及 `_handleFloatingChromeReveal` 显隐两侧对同一自动隐藏计时器的取消/重武装。
- **顺带消掉的连锁陷阱**：旧路径在悬浮态把 `_showChrome` 翻成 false，而它同时是 JS 侧 `__hoshiTapGate.chrome` 的镜像（`reader_hibiki/lookup.part.dart:54`）——于是按一次快捷键之后，**下一次点正文变成「把栏叫回来」而不是查词**（`reader_hibiki/webview.part.dart:1959` 的 `if (!_showChrome && !shiftKey)`），且 `bottomBarVisible` 因 `chromeExpanded == false` 直接返回 false（`reader_chrome_floating.dart:155`），底栏连临时可见都唤不出来。改后悬浮态 `_showChrome` 恒 true，这条连锁一并消失。
- **影响面**：`_executeShortcutAction` 是键盘与手柄共用入口（`reader_hibiki/caret.part.dart:497`），所以手柄的 toggleChrome 一并改到新路径——这是意图内的（用户报的就是「手柄/键盘按了没反应」）。
- **备注**：没有改鼠标空白点击、VN 空白推进（`_revealFloatingChromeForVnAdvance` 仍是「只唤出不 toggle」）或顶部进度条的既有语义；只把快捷键/手柄从错误的旧状态层挪回正确那层。悬浮态 `_showChrome` 不变 → 预留高恒 0，故无需重下 chrome insets / 重锚，与指针路径一致。
