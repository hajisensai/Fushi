## BUG-2605 · 「卡已在 Anki」对话框点「新增为重复卡」仍被两后端当重复拒绝
- **报告**：2026-09-20（用户：「even when i manually select "Add as a new card", Fushi won't export the new card because it's recognized as a duplicate」，截图：查词弹窗 `掛かる` ✓ → 「Card already in Anki」对话框 → 点「Add as a new card」）
- **真实性**：✅ 真 bug
  - 对话框的「新增为重复卡」（`fushi/lib/src/anki/anki_mined_card_action_sheet.dart` `_runMineNew`）直接调宿主传进来的 `mineNew`，两条车道（`fushi/lib/src/pages/base_source_page.dart` `onMinedCardActionFromPopup` / `fushi/lib/src/pages/implementations/dictionary_page_mixin.dart` `onMinedCardAction`）里的 `mineNew` 就是普通制卡回调 `onMineFromPopup(fields)` / `onMineEntry(fields)`，一路到 `repo.mineEntry` 没有任何「用户已裁决」的信号。
  - 三个后端的 `addNote` 只看全局偏好：AnkiConnect `packages/fushi_anki/lib/src/ankiconnect/ankiconnect_repository.dart` `_mineEntryInner` 发 `allowDuplicate: settings.allowDupes` → Anki 回 `cannot create note because it is a duplicate` → `MineOutcome.duplicate()`；AnkiDroid `packages/fushi_anki/lib/src/ankidroid/anki_repository.dart` `_mineEntryInner` 在 `!settings.allowDupes` 时先 `checkForDuplicates` 命中即返回 duplicate；AnkiMobile `fushi/lib/src/anki/ankimobile_repository.dart` 同样 `allowDuplicate: settings.allowDupes`。「允许重复」默认关 → 对话框按钮等于没有。
- **[x] ① 已修复** — 裁决走 payload 位 `AnkiMiningPayload.allowDuplicate`（`packages/fushi_anki/lib/src/anki_models.dart`，wire 键 `allowDuplicate`，与 `glossarySelectionHighlighted` 同一套「布尔 / 全字符串」两线解析；`AnkiMiningPayload.withAllowDuplicate(fields)` 给弹窗字段拍位）。两条车道的 `mineNew` 构造请求时拍位；三个后端按 `settings.allowDupes || payload.allowDuplicate` 放行（AnkiDroid 跳过 `checkForDuplicates`）。选 payload 而非改 `mineEntry` 签名：制卡请求本来就以这份 map 为唯一载体，互联「制卡到服务端」转发的也是 `rawPayloadJson`，主机侧原样认得；45 个测试替身的 `mineEntry` 覆写一个不用动。不改全局「允许重复」偏好——只放行这一次。
- **[x] ② 已加自动化测试** — `packages/fushi_anki/test/add_as_duplicate_override_test.dart`（payload 两线解析 + 缺省 false；AnkiConnect `allowDupes=false` 时带位请求 `options.allowDuplicate` 为 true、不带位仍 false；AnkiDroid 带位不发 `checkForDuplicates` 直接 `addNote`、不带位仍被拦成 duplicate）；`fushi/test/pages/anki_mined_card_action_wiring_static_test.dart` 新增源码守卫：两条车道的 `mineNew` 必须带 `AnkiMiningPayload.withAllowDuplicate(fields)`。
- **备注**：`mineNew` 的三条触发路径（「新增为重复卡」/ AnkiMobile「再加一张」/ 反查为空后重制）都在用户已被告知「卡已有」并选择继续之后，统一拍位；反查为空那条本来就不会撞重复，位是无害的。未在真机 Anki 上复测（本机无 AnkiConnect 环境），契约由 MockClient / MethodChannel 测试钉死。
