## BUG-4128 · asr-video-model-variant-flips-on-gpu-budget
- **报告**：2026-11-06（用户：应用内反馈 Pjuq2vMmhc，Windows 3.3.0-debug.23880）——前一晚下好了视频字幕识别模型，第二天「整季生成日语字幕」显示「视频用的日语识别模型还没下载」。
- **真实性**：✅ 真 bug，根因在上游算法包，本仓未修。模型不在 temp / 更新清理目录：附带日志的 `Storage.footprint` 显示 `asr_models/parakeet-tdt-ctc-0.6b-ja/model.int8.onnx` 625 MB（= 清单 655542604 字节）仍在 app support 下，文件没丢。「已下载」判据随机器状态变：弹层 `video_subtitle_generate_sheet.dart:328` → `AppVideoSubtitleAsrModelPort.isReady`（`fushi/lib/src/media/video/subtitle/video_subtitle_model_ports.dart:62`）→ 上游 `fushi_asr_core` `AsrTranscriptionService.plan`（`packages/asr_core/lib/src/asr/asr_transcription_service.dart:274-330`，sha 680c0a1）每次现探 GPU EP 与 DXGI 显存预算（本仓 `fushi/lib/src/onnx/onnx_inference_ort.dart:125` 返回的是**随系统负载浮动**的 `budget`），经 `recommendAsrEncoderVariant`（`asr_engine.dart:198-219`）选变体，只查**该变体**的文件是否齐（`asr_model_store.dart:105`）。Parakeet 包 `fp32GpuMinBudgetBytes` = 4 GiB：下载那次预算 < 4 GiB → int8（只下了 int8）；第二天预算 ≥ 4 GiB → fp32，要 `model.onnx` + 2.48 GB `model.onnx_data` → 判「没下载」。按钮再点会再下 2.5 GB 的 fp32。录制器（`video_subtitle_recognizer.dart:200-214`、`moss_video_subtitle_recognizer.dart:251-280`）与有声书 / 远端 host 也都按同一 plan 走，同病。
- **[ ] ① 未修复** — 变体选择是 `fushi_asr_core` 的规划逻辑，按仓库规则须在上游 `hajisensai/fushi-subtitles` 改：plan 在推荐变体未就绪而另一变体已完整在盘时应规划已就绪的那个（并据此重算 EP），而不是把已下好的模型判成「没下载」；之后本仓按 asr-assembly.md 七处钉同一新 sha。本仓 app 层不能只改 `isReady`（改成「任一变体就绪」会让识别器照 plan.variant 去加载缺失的 fp32 文件）。
- **[ ] ② 未加自动化测试** — 随上游修复在 asr_core 加 plan 单测（int8 已就绪 + 预算 ≥ 门槛 → 仍规划 int8 / modelReady=true）。
- **备注**：日志里没有 ASR 规划日志，「下载时预算 < 4 GiB」是由盘上只有 int8 反推的（若当时就是 fp32 规划，下载器会下 fp32 那套）。
