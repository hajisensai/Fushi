## BUG-926 · 词典弹窗触屏无法复制释义(撤回BUG-762全量禁选)
- **报告**：2026-07-19（用户报「查词界面文字更新 1.2.0 版本无法复制」）
- **真实性**：✅ 真 bug（回归自 BUG-762，随 `cc6484e87` 进入 1.2.0）。根因 `hibiki/lib/src/pages/implementations/popup_settings_injection.dart` 的 `_touchNoSelectStyleJs`（BUG-762 引入，注入进 `buildPopupStaticSettingsJs` 的 head）：`@media (pointer: coarse){html,body,body *{-webkit-user-select:none !important;user-select:none !important;-webkit-touch-callout:none !important;}}`。它用 `body *` `!important` 全量碾平了 `assets/popup/popup.css` 已精细分区的选区设计（正文 `-webkit-user-select:text` @`:43/:510/:1263/:1270`，交互 chrome=按钮/标签/音高行逐元素 `none`）。触屏（粗指针，所有 Android/iOS 手机平板）上词典释义正文因此**无法被原生选区选中 → 安卓 ActionMode「复制」与 iOS 长按 callout「拷贝」都无从触发 → 无法复制**。桌面细指针（`pointer:coarse` 不命中）幸免，故只在触屏 1.2.0 暴露。BUG-762 担心的「长按释义→系统 ActionMode 接管→弹窗关不掉」其实已被 `assets/popup/popup.js:3616-3620` 的 document click 处理器优雅化解（有选区先 `removeAllRanges()` 再 `return`，点一下取消选择、再点才关窗），加上弹窗 chrome 的关闭按钮/横拖关都在 WebView 之外不受 ActionMode 阻挡，始终有退路——用整块 CSS 全量禁选去修一个已被 JS 处理的标准选中态，是修在了错误的层，代价是牺牲了词典核心能力「复制释义」。
- **[x] ① 已修复** — 撤回 `_touchNoSelectStyleJs`：删除该常量及其在 `buildPopupStaticSettingsJs` head 的拼接，回落到 popup.css 的跨平台逐元素选区分区（正文可选、chrome 不可选，无平台门控，触屏同样生效）。阅读器 `reader_content_styles.dart` TODO-1279 的同款抑制**保留不动**——阅读器复制本就桌面门控（Ctrl+C / 右键均 `isWindowsPlatform`），触屏确无原生选区消费者，正当性成立；弹窗恰相反（核心用途就是复制释义）。提交：<待填>
- **[x] ② 已加自动化测试** — `hibiki/test/dictionary/popup_touch_native_selection_guard_test.dart`（原 BUG-762 守卫**反转重写**）：源码扫描钉死①注入体不得复活 `hoshi-popup-touch-noselect` / `body *{` 全量禁选 / `$_touchNoSelectStyleJs` 拼接；②popup.css 正文保持 `-webkit-user-select: text` 且不含 `pointer: coarse` 抑制；③popup.js click 仍含 `removeAllRanges()`（BUG-762 卡死的真实化解，防两头回归）。
- **备注**：真机验证待用户（Android/iOS 词典弹窗长按释义→可选中→系统菜单「复制/拷贝」→粘贴校验）。与 BUG-762 同一元素双向张力：本修复选择「复制可用」优先，卡死侧由 popup.js 既有 click 清选区 + chrome 关闭退路兜底。
