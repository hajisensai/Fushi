## BUG-1128 · 无语音台词误配 BGM：捕获工作台补排除音轨入口
- **报告**：2026-07-26（用户：截图反馈——KiriKiriZ 游戏，一句没有语音时被读进 BGM）
- **真实性**：✅ 真 bug。根因在自动选源无绝对能量门限：`hibiki/windows/runner/voice_hook_reader.cpp:476` 起 `GrabUtterance` 以 `best_delta = -1e18` 为初值、按「文本时刻能量 − 说话前能量」的**相对最大者**选源（`:486-490`），只要窗口内有任一 16-bit 源有片段就必选出一条；BGM 稳态播放时 `delta≈0` 仍胜出，被当作这句的语音。唯一兜底 `sel_src == 0 → return {}`（`:492-497`）只在**所有源都被排除**时触发，不在「能量太低」时触发。`_attachLineAudio`（`hibiki/lib/src/mining/gal_hook_session_controller.dart:2853`）对每条台词无条件 `grabUtterance`，不传 sourcePtr/exclude → 用默认空排除集。PR#434（BUG-1109）的增长收敛（`_settleLineUtterance:2787` 只看「变长」）会把无语音行的 BGM 一路拼到 6s 上限，加剧问题。
- **[x] ① 已修复** — 把已存在的「逐轨排除（标记为 BGM）」入口从诊断页搬到捕获工作台：工具栏溢出菜单新增 `manageTracks` → `_showTrackManagerDialog`（`hibiki/lib/src/pages/implementations/texthooker_page.dart`），逐轨试听 + 标记为 BGM / 恢复，复用会话既有的 `GalHookSessionController.setTrackExcluded`。排除某条 BGM 轨后，`grabUtterance` 的 exclude 集合会滤掉它——没有语音的台词也就不会再选到 BGM（`voice_hook_reader.cpp:492-497` 全部源被排除即返回空）。排除只在引擎 PCM 后端参与取音，故对话框按 `galTrackSelectionAffectsCapture` 门控，与诊断页口径一致。提交哈希：见 PR。
- **[x] ② 已加自动化测试** — `hibiki/test/tools/gal_workbench_track_manager_guard_test.dart`（3 条源码守卫：溢出菜单动作分发、对话框刷新快照+逐轨 setTrackExcluded+后端门控、新 i18n key）+ `hibiki/test/pages/texthooker_page_test.dart` 新增 widget 用例「workbench overflow menu opens the exclude-tracks dialog」（真开菜单→开对话框→关闭）。
- **备注**：本轮只做**用户可控的排除**（无需改 native、可在纯 Dart CI 验证）。更彻底的「自动」根治是给 `voice_hook_reader.cpp:476` 的选源加**绝对能量门限**（低于阈值返回空），或启用设计已有但从未落地的 `SharedHeader::calibrating` 校准模式（`hibiki-hook/include/voice_hook_ipc.h:227`、`docs/specs/galgame-mining/handoff.md:181`）；二者都要改 Windows runner / hibiki-hook 并在真机标定阈值，属独立后续项，本轮未做。真机验收（Windows + 引擎 PCM 会话确认排除后无语音行不再收 BGM）未在本环境完成，能力标 `implemented_unverified`。
