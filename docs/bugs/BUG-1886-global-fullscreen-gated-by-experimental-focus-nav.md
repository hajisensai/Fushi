## BUG-1886 · F11 窗口全屏被实验性焦点导航开关门控，默认安装上按 F11 无反应
- **报告**：2026-08-27（用户：「小说和漫画都缺少全屏模式」）
- **真实性**：✅ 真 bug。`fushi/lib/src/shortcuts/global_navigation.dart:474-482`（修前）：`_handleGlobalToggleFullscreen(registry, event)` 的调用点整块压在 `if (focusNavigationEnabled) { ... }` 内，而 `focusNavigationEnabled` = `AppModel.experimentalFocusNavigationEnabled`，其偏好 `experimental_focus_navigation_enabled` 在 `fushi/lib/src/models/preferences_repository.dart:419-421` **默认 false**。于是默认安装上按 F11 完全没反应——`ShortcutAction.globalToggleFullscreen`（`shortcut_action.dart:280`）与 F11 默认绑定（`shortcut_defaults.dart:175-177`）、执行体 `_toggleWindowFullscreen`（`global_navigation.dart:369-385`，Windows/Linux 走 `windowManager.setFullScreen`、macOS 走 `WindowManipulator`）全都在，唯独运行时永不解析。快捷键设置页照常把 F11 显示给用户，属于「配了键却永不生效」。
  与 **BUG-1266 完全同构**：同一个函数的注释（`global_navigation.dart:395-398`）已经写明「手柄按钮分发与注册表 globalBack **不再受它门控**……把正式功能挂在一个默认关闭的实验开关上，等于在默认安装上『配了绑定却永不解析』」。那次修了 globalBack 与手柄分发，漏了全屏这一支。窗口级全屏与「方向键/摇杆移焦」这套实验能力本就正交，不该共用开关。
- **[x] ① 已修复** — 把 `_handleGlobalToggleFullscreen` 的调用移出 `if (focusNavigationEnabled)`，与 `_handleGlobalBack` 同层（`global_navigation.dart:474-483`），并在注释里写明它与 BUG-1266 是同一条理由。这是小说 / 漫画 / 任意页面「桌面端全屏」的共同入口，修完即三端可用。
- **[x] ② 已加自动化测试** — `fushi/test/shortcuts/global_fullscreen_not_gated_test.dart`：widget 行为测试（不是源码守卫），断言 `KeyEventResult`。三条：焦点导航**关闭**时 F11 仍被全局层认领 / 开启时照常认领（不回归）/ 改绑 F10 后 F10 生效且 F11 不再认领。
  变异实测：把调用点改回 `focusNavigationEnabled ? _handleGlobalToggleFullscreen(...) : KeyEventResult.ignored` → 「关闭时仍认领」与「改绑 F10」两条红、「开启时照常认领」仍绿，与预期完全一致；还原后源文件 sha256 与变异前逐字节一致（`c481ad1f5a5018a3…`）。
- **备注**：本条只恢复**桌面窗口级**全屏。移动端 F11 无意义（`_isDesktopWindow` 门控，移动端消费按键但不动作）；漫画的移动端沉浸式全屏在 [BUG-1888](BUG-1888-manga-top-chrome-no-hide.md) 里随「隐藏界面」一起做。小说阅读器移动端仍保持 `navigation.part.dart:135` 的 edgeToEdge（刻意设计，未改）。真机验证未做（用户已取消该环节）。
