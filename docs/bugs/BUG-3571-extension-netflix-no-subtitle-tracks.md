## BUG-3571 · 浏览器扩展：网飞播放页「字幕轨」显示「这个视频还没有字幕轨」，同页 asbplayer 能拿到轨
- **报告**：2026-10-19（用户：截图，网飞《氷の城壁》E02，播放器菜单「字幕轨 · 这个视频还没有字幕轨」，同页 asbplayer 列出 `ja - 日本語[CC].nfimsc`）
- **真实性**：✅ 真 bug。扩展取网飞整轨只有两条通道：`tools/browser-extension/netflix-bridge.js` 的 `JSON.parse` 清单钩子（MSL 解密后的清单不经主世界 `JSON.parse`，文件注释早已记录零命中）和 XHR / `Response` 原型上的字幕正文嗅探（当前播放器的字幕下载也不经主世界原型）。两条都拿不到 → `fushiEpisodeCues` 空 → `player-controls.js` 的 `renderTracksPage` 走 `pc_track_none`。asbplayer 现行做法（`extension/src/entrypoints/netflix-page.ts`）是：轨清单取播放器 API `getTimedTextTrackList()`，下载地址从 `playerApp.getState().videoPlayer.cadmiumPlayerRepository.playersById[会话]` 里按结构找 `type==='timedtext'` 且带 `urls[]` 的对象，没地址的轨临时 `setTimedTextTrack` 让播放器下发再切回。
- **[x] ① 已修复** — `a5c7c6358e`：`netflix-bridge.js` 新增播放器状态通道（`harvestPlayerState` 每 2 s 一拍，清单 / 当前轨变化后连扫 5 拍、平时约 16 s 扫一次状态树）：全部文字轨投成 `{__fushiNf:'tracks'}` 占位，状态里已有地址的轨直接整轨下载；`{__fushiNf:'fetchTrack'}` 按需取无地址的轨（临时切轨 → 计次封顶等地址 → 切回原轨，失败投 `cuesFailed`）。`subtitle-providers.js` 登记占位轨（key 同整轨 `vid|lang~trackId`、带显示名），选中时 `fushiRequestLazyTrack` 发 `fetchTrack`；cue 到即清占位。`d97bb0864d`：app 内置网页视频的 `web_video_glue.js` 不把空 cue 占位轨投给 Dart（app 有自己的站点轨清单与加载态）。
- **[x] ② 已加自动化测试** — `tools/browser-extension/netflix-bridge.test.js`（状态通道三条：列轨 + 有地址直接下载 + replay 重放轨清单；fetchTrack 切过去再切回；地址不来时切回并投 cuesFailed）、`tools/browser-extension/lazy-tracks.test.js`（网飞占位轨登记 / fetchTrack / 清占位）。
- **备注**：未在真网飞页面复测（需要登录的真实浏览器会话）；`playersById` 的结构判据与 asbplayer 线上版本一致。若网飞自己的字幕是关着的，默认活动轨会是字典序第一条占位轨，选中它会触发一次临时切轨（YouTube 占位轨同一行为）。
