## BUG-5167 · music-backdrop-pixi-default
- **报告**：2026-11-22（用户：应用内反馈 l1ERGmWxjF）
- **真实性**：✅ 真 bug。开发者要求歌词页流体背景默认用 Pixi 渲染器，但默认值从 88712fbf45 引入起一直是 `mesh`：`fushi/lib/src/models/preferences_repository.dart:6221-6224`（`getPref(..., defaultValue: 'mesh')`）、`fushi/lib/src/pages/implementations/music/music_lyrics_backdrop.dart:52-57`（`fromPref` 回落 `meshGradient`）、`fushi/lib/src/settings/settings_schema_music.dart:507`（schema `defaultValue: meshGradient`）、widget 构造默认 `music_lyrics_backdrop.dart:675`。偏好只在设置页手选时落库，所以没手选过的老用户库里没有这一行。另：schema 的「恢复默认」走 `onChanged(defaultValue)`（`settings_kit.dart` segmented 分支），会把当时的默认值 `mesh` 显式写进库，和「手选 mesh」分不清，改了出厂默认后这批用户也跟不过去。
- **[x] ① 已修复** — 出厂默认改 `pixi`（`MusicLyricsBackdropStyle.defaultStyle` 一处定义，getter / `fromPref` 回落 / schema / widget 默认都指向它）；没有行 = 跟默认走，老用户自动迁移，显式存了 `mesh` 的（手选）保持不变；键名冻结不改。新增 `PreferencesRepository.clearMusicLyricsBackdropStyle()`，schema 用 `resetToDefault` 把「恢复默认」改成删行，以后再改默认也分得清手选与默认。顺带修 pixi 成默认后暴露的多余离屏渲染：`_BackdropPainter.shouldRepaint` 把 pixi 着色器 / 小贴图身份变化也当作离屏图内容变化去作废缓存，着色器异步加载完那次 setState 让静态模式把同一帧离屏渲染两遍；二者不进离屏图，现在只触发重绘不作废缓存。
- **[x] ② 已加自动化测试** — `fushi/test/pages/music_lyrics_backdrop_test.dart`：`fromPref(null/bogus)` 与 widget 默认为 pixi；空库默认 pixi；老库无行 → pixi、显式 `mesh` → 保持 mesh；`clear` 后行被删且读回 pixi；schema 默认 pixi 且带 `resetToDefault`；静态 pixi 只离屏渲染一次。变异实测：还原四处修复后 5 个用例变红，恢复后全绿。
- **备注**：已显式存 `mesh` 的存量行（手选或旧版「恢复默认」写入）无法区分，一律按用户选择保留。
