## BUG-4305 · srs-sync2-device-trust
- **报告**：2026-11-10（用户：SRS 同步 v2 安全加固——设计 §9 写的是「不认识的设备公钥需要已有设备确认」，实现却是首次信任；能往同步位置写文件的任何人都能删 / 彻底清除整个库）
- **真实性**：✅ 真缺陷。`native/fushi_fsrs/src/store/sync2/transport.rs` `trust_head`（原 342–349 行）第一次见到的设备直接 `INSERT … sync2_devices` 记下公钥、当作可信；之后它的 `deleted` 写入与 `Purge` 在 `store/sync2/mod.rs` `project_edit_noted` / `project_body` 照常落投影，`Purge` 还经 `semantics.rs` `purge_entity` 把本机日志里的内容换成哈希、重写本机的段（不可逆）。`docs/specs/2026-10-25-srs-sync-v2-plan.md` §4 自己承认是 TOFU。
- **[x] ① 已修复** — 所有者拍板的方案：新设备普通操作照收，删除与彻底清除扣到本机确认之后。srs.db v29（`store/schema.rs`、`store/sync2/schema.rs` `V29_TRUST`）加 `sync2_trust`（只记还没信任的设备：待确认 / 已拒绝；没行 = 可信，升级时已认识的设备天然可信）与 `sync2_trust_held`（扣着的操作）。`store/sync2/trust.rs`：`trust_head` 插入新设备时本机库已有用户内容（`library_fresh`：有复习日志 / 修改记录 / 非内置身份记录）就记待确认；`project_edit_noted` 开头 `hold_edit`、`project_body` 的 `Purge` 分支 `hold_purge`：不可信设备的删除 / 清除只记账、不投影、不进实体索引（操作照常进日志，链 / 因果 / 版本向量 / 转发 / 段回收不变）；`sync2_trust` 命令信任时按 seq 交回生产投影（晚投与一开始就投逐表相同）、拒绝时继续扣着；摘要的版本向量部分在扣着时带扣住集合指纹（`digest_vv_tag`），扣着期间与信任它的设备互不比较、不误报确定性 bug。界面：冲突中心顶部「待确认的设备」卡片（设备名 / ID / 首次出现 / 扣着几条删除与清除，信任要确认框、拒绝），同步页设备列表标「待确认 / 已拒绝」并跳冲突中心，牌组列表冲突角标把待确认设备计入。
- **[x] ② 已加自动化测试** — Rust `native/fushi_fsrs/src/store/sync2/tests_trust.rs`（新设备普通操作生效、删除与清除扣住且不进冲突中心、不卡投递、双方不报摘要不一致；信任后与全新库一开始就信任的对照设备投影 / 冲突 / 清除标记 / 日志清除位逐表相同、与作者收敛；拒绝后新删除继续扣、改信任后收敛；v28 → v29 升级时已认识的设备不扣；只有内置实体的全新库首轮不扣、之后的新设备扣）。端到端助手 `tests.rs` `AUTO_TRUST`（默认开，模拟用户每次都点信任）让既有同步语义测试照旧按全部互信跑。Dart `fushi/test/srs/srs_device_trust_test.dart`（MD3 + Apple：冲突中心信任 / 拒绝、同步页「待确认」标签）。
- **备注**：信任是纯本机状态（不能新增操作种类），每台设备各自确认；新设备首轮同步时同步位置上已经有的设备一律可信（无法区分）；互联配对不携带 sync2 公钥（host 只按上传路径猜设备，`srs_app_runtime.dart` `_onHostClientUpload` 只补名字），不作信任依据；普通操作（改字段、清空内容、撤销复习、改身份记录）仍不扣；远程复习作用域不提供确认（冲突中心不在可达页面里），无头服务端没有确认入口。
