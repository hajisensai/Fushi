## BUG-4361 · 答卡后的去抖推送不覆盖云盘通道，背完卡云盘不自动同步
- **报告**：2026-11-07（用户：开发者自提，Windows，反馈 O4MSorhpie「背完卡没有自动触发同步」）
- **真实性**：✅ 真 bug（读代码验证；反馈日志末尾全被 gal-ingame 诊断挤满，没有 SRS 推送记录可对照）。根因：本机写入后的推送 `SrsLocalPush → SrsSyncScheduler.autoPush`（`fushi/lib/src/srs/srs_sync_scheduler.dart:795-812`，改前）只接收「此刻可用的互联后端」一个参数，只推互联通道和本机 host 目录；app 侧 `_pushInterconnect` / `_interconnectReady`（`fushi/lib/src/srs/srs_app_runtime.dart:251-283`，改前）只取 `InterconnectSyncBackend.instance`。云盘通道（OneDrive / WebDAV / Google Drive 等）只在进复习 tab 的节流同步、常规同步的通道后置步骤和「立即同步」里跑——背完卡留在 app 里不动，云盘就一直收不到答卡记录。另外这条推送不经「同步与备份 + 互联」模块门（BUG-4305 / #3143 漏掉的一处自动入口），没推出去时也不留任何原因。
- **[x] ① 已修复** — 推送按通道分两条（`srs_app_runtime.dart` 的 `localPush` = 互联 + 本机目录，`cloudPush` = 云盘），各自一个 `SrsLocalPush`（去抖 10 s / 复习中最长攒 45 s / 离开复习页与进后台立即推 / 失败指数退避 30 s→10 min，两条各退各的，host 不可达不拖住云盘）。`SrsSyncScheduler.autoPush` 改成接收通道运行器（`SrsChannelRunner`，与「立即同步」/ 进复习 tab 同一个通道抽象），生产传 `runOnAuthenticatedSyncChannels(where: 互联 / 非互联)`——`where` 在认证之前筛，不为用不到的通道刷新令牌；推送领 `syncModuleGate` 的票，模块关着不推、途中关门下一条通道不再开跑；没推出去（模块关着 / 不在前台 / 没配对或没登录 / 推送失败）记进 `autoPushSkipReason` 并记诊断日志（稳定原因只在变化时记，失败按 10 min 限流）。`kSrsLocalPushMaxWait`（45 s）语义不变。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_sync_scheduler_test.dart`：「答卡 → 去抖到期 → 云盘通道推送；失败指数退避，成功后清零」（fakeAsync）、「同步模块关着不推、不算失败；途中关门，下一条通道不再开跑」、「ready 为 false 不跑通道、不退避，记下原因；本机目录照跑」、「通道一轮在通道运行器（互斥锁）里跑，本机目录在锁外；失败报 false」、`runOnAuthenticatedSyncChannels`「where 筛掉的通道不认证、不跑」，接线守卫改为断言两条推送与 `notifyLocalWrite`。测试未在本分支运行，统一在合并后验证。
- **备注**：反馈日志被 `gal-ingame` / `gal-overlay` 高频诊断淹没（10485 行），属于另一个问题（诊断限流），本条不处理。应用里没有「计量网络」的概念（全仓无 metered / 仅 Wi-Fi 判据），推送不另造一个。
