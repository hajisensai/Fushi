## BUG-2946 · YouTube 制卡/播放：watch 页被降级时 5 个 client 全部报「视频不可用」
- **报告**：2026-10-04（用户：贴出 `Anki.mineImmersion.youtube` 连续三条错误日志，20:10:03 / :14 / :24，视频 `N2uQWfV6Jr4`）
- **真实性**：✅ 真 bug。视频本身公开可播（oEmbed 200，TED-Ed「4 ways to fix your attention span」），报错文案「视频不存在 / 私有 / 已删除」是误导。根因 `packages/fushi_engine/lib/media/video/youtube_source_resolver.dart` `_getManifestWithClientFallback`：每个 client 都以 youtube_explode 默认的 `requireWatchPage: true` 调 `getManifest`，先拉 watch page HTML；youtube_explode `watch_page.dart:168` 在页面缺 `og:url` 时直接抛 `VideoUnavailableException.unavailable`，**发生在任何 player 请求之前**。YouTube 间歇对某个出口下发降级 watch page（有 `#player`、无 `og:url`），于是 visionos / androidVr / android / ios / tv 五个 client 全部死在同一张页面上——兜底链形同虚设。3 分钟后同一机器直连与代理拉 watch page 都已恢复正常（有 `og:url`、playability OK），符合「间歇降级」。
  - watch page 在链里唯一的作用是给 visionOS 提供 visitor 身份（其 player 请求不带身份会被判 bot）。实测不拉 watch page 时其余 client 结果逐个与拉时相同（android 出流；androidVr/tv unplayable；ios 首流 403），visionOS 改带 `sw.js_data` 的 visitorData（youtube_explode 给 IOS 用的同一端点，JSON、不经 HTML 结构判定）即 OK，直链无 `n` 参数、尾部 Range 206（不是 android 的 60 秒窗口流）。
- **[x] ① 已修复** — `d29950b22b`：兜底链一律 `requireWatchPage: false`；`kYoutubeVisitorIdentityClients`（= visionOS）经 `fetchYoutubeVisitorData` + `youtubeClientWithVisitorData` 派生带 `context.client.visitorData` 与 `X-Goog-Visitor-Id` 的副本，身份每次解析只取一次、算进该 client 自己的超时，取身份失败只算该 client 失败；全部失败时报错逐 client 列出各自原因（旧报错只列 5 个几乎相同的 apiUrl + 最后一个异常）。联网实测生产入口 `resolveYoutubeSource(withCaptions:false)`：`N2uQWfV6Jr4` / `D8uACXBAqkE` / `dQw4w9WgXcQ` 全部由 VISIONOS 出流（2.3~3.2s），音频尾部 Range 206。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/youtube_watch_page_independence_test.dart`：MockClient 离线重现「watch page 降级」驱动真实兜底链，断言出流且全程不请求 `/watch`、`sw.js_data` 只取一次；全部失败时报错含每个 client 名；取身份失败时链继续且 VISIONOS 不发 player 请求；visitorData 解析 / 派生纯函数。变异实测：把实现改回 `requireWatchPage: true`，主用例精确重现原始日志（5 个 client 全为 `VideoUnavailableException: Video 'N2uQWfV6Jr4' is unavailable`）。
- **备注**：字幕轨链（`kYoutubeCaptionClientFallback`）仍剔除 visionOS，本次未动。另：选流时的「isThrottled=true（异常，缓冲可能慢）」日志对 visionOS 流是误报——该 client 直链从不带 `ratebypass`，修复前（经 watch page）同样为 true，尾部 Range 实测 206，非本次引入。
