## BUG-1172 · 漫画 Lens 旋转命中区在非方形页上算错
- **报告**：2026-07-27（用户：PR#474 只读审查）
- **真实性**：✅ 真 bug。`hibiki/lib/src/media/manga/ocr/google_lens_protocol.dart:287-294`（`_orientedCharacterBounds`）与 `:317-320`（`_readGeometry` 的行级 AABB）在**归一化空间**里做旋转三角运算：Lens 的 `width` 按图宽归一、`height` 按图高归一，而 `rotation` 是真实像素空间的角度——把两个不同尺度的量直接混进同一组 sin/cos，只有正方形页（W == H）成立。1200×1700 的漫画页在 90° 上行的 X 半宽偏小 **1.4167 倍**（本仓实测：应 102px，旧算法给 72px），字符沿基线的 Y 位移同样偏大同一倍数 ⇒ BUG-1152 声称根治的斜排/竖排点词错位在非方形页上仍在。
- **[x] ① 已修复** — 新增 `_rotatedAabb`：先把 X 轴乘 `aspect = imageWidth / imageHeight` 拉进各向同性空间（单位＝图高像素）再做三角投影，最后把 X 半宽除回归一化尺度；`_orientedCharacterBounds` 的基线 Y 位移补上同一个 `aspect` 因子。`decodeResponse` 增加 `required int imageWidth / imageHeight`（`GoogleLensOcrService._recognizePage` 传送检图的 `prepared.width/height`），零维度时抛 `GoogleLensProtocolException`。`aspect == 1` 时与旧式完全一致，方形页无行为变化。
- **[x] ② 已加自动化测试** — `hibiki/test/media/manga/ocr/google_lens_protocol_test.dart` 新增两条，判据一律落在**像素空间**（旋转矩形的像素 AABB 与归一化口径无关）：①「45 度斜行在非方形页上的命中区按像素几何还原」1200×1700 + π/4，断言字符 AABB 的像素宽高等于解析值、且两字符像素位移斜率 == tan(45°)；②「90 度竖行在非方形页上的 X 半宽按页宽高比还原」断言行像素宽 == 未旋转的像素高。原有 5 条用例补齐 1000×1000 维持方形口径。负向验证：把 `_rotatedAabb` 改回归一化混算 → 两条新用例转红（102.0 vs 72.0，正是 1.4167 倍），还原后绿。
- **备注**：BUG-1152 的残留面。旧测试唯一的非 0 角是 π/2（cos = 0 的**退化值**），缺 W/H 修正时断言照样通过，所以没抓到。仍未处理：`_LensGeometry.isVertical` 的 `rect.height > rect.width * 1.25` 也在归一化空间比，竖长页上偏向判竖排——是启发式不是数学错，改动会影响竖排检测与句序，未纳入本次范围。
