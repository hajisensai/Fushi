## BUG-1270 · YouTube 实时字幕回跳后重复且累积成长段
- **报告**：2026-07-29（用户：YouTube 字幕列表回跳后，同一时间点出现超长旧行和重复短行）
- **真实性**：✅ 真 bug —— `tools/browser-extension/content.js:186-237` 把 YouTube 字幕 DOM 的任意前缀增长都当作同一 cue 就地扩写，没有时长边界；播放数分钟后可把整段累积进一行。seek 分支又直接以回跳后的短快照调用 `hibikiLiveCueStart`，而旧去重只认「文本完全相同 + 句首相近」（`content.js:344-367`），所以同一 3:13 的较短前缀会再插一行。
- **[x] ① 已修复** — PR #590（整支内容以单提交重放进 develop）：DOM 原始累积快照与当前 live cue 文本分离；前缀增长最多连续写入 12 秒，超时只把新增后缀切到下一 cue，阻止一行无限增长。seek 前先定格当前 cue；目标时间窗内若已有相同或前缀相关文本，则进入只读 replay 状态，后续逐字增长只跟踪页面、不再修改或重复插入旧轨。live 采样状态收进每代 `hibikiSamplerState`，并删掉单槽「上一个 key」记忆 `hibikiLastSamplerKey`，改由 `hibikiHasRecordedLiveTrack(key)` 从权威数据（`hibikiEpisodeCues[key+'|live']` 是否已有内容）推导「这个 key 见过没有」——单槽记忆在 A→B→A 回访时已被 B 覆盖，会把回访误判成新轨而重复追加。工具版与 `hibiki/assets/browser_extension/content.js` 内置镜像同步。
- **[x] ② 已加自动化测试** — `tools/browser-extension/universal-subtitle-providers.test.js` 新增 BUG-1270 回归：模拟 YouTube DOM 连续 14 秒累积，断言按新增后缀切成两条有界 cue；再从 3:26 回跳 3:13 并重放短前缀，断言轨道条数不变且 3:13 只有一条。另加两条 `SPA A→B→A` 回归，覆盖回访已有轨时短前缀与长前缀两个方向都只读 replay、不追加重复 cue。重放后在 develop 上复跑：该文件 17/17，扩展 Node 全套 190/190，Dart 侧镜像与 BUG 守卫 `FLUTTER TEST VERDICT: PASSED - 227 tests ran`；两个 `content.js` blob 逐字节一致（`cc307a451c2466440f6fe36c00a0775274d4ef7a`）。变异复验：把 `hibikiHasRecordedLiveTrack` 改回恒 false（等价单槽语义）后两条 A→B→A 立即转红（退出码 1），确认断言真绑定本修复。
- **备注**：YouTube 有可下载字幕轨时仍由 Hibiki server 一次返回整轨并自动替换 live 兜底；直播/尚未生成完整轨的视频只能边播边采，本修复约束的是这条兜底。按用户要求未等待 Flutter 编译/构建验收。
