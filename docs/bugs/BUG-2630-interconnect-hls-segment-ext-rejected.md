## BUG-2630 · 互联转码 HLS 分段 URL 无扩展名被 FFmpeg 6.1 白名单拒开
- **报告**：2026-09-22（用户：「iOS 的 Fushi 互联又没办法播放远端 Fushi 的视频了」；追问后补充「其他平台切换画质就会直接播放不了」）
- **真实性**：✅ 真 bug（iOS 模拟器 / macOS / Android 真机 + Mac 真 host 复现，非推断）。两段根因：
  - **第一段（起播就黑屏）**：先排除直传——iOS 模拟器进程内起自签 `FushiSyncServer` 播互联视频（`fushi/integration_test/interconnect_remote_video_ios_itest.dart`），交给 native 的是降级中继形态 `http://127.0.0.1:<port>/…/stream?token=`，libmpv 起播到 1.7 s、时长 6046 ms、中继零错误——**LAN 直传没坏**。再打转码：Mac 上用 `packages/fushi_engine/tool/interconnect_video_host_probe.dart`（真 ffmpeg）起 host，同一条 itest 以 `FUSHI_REMOTE_QUALITY=2` 强制画质档 → host 回 `hls.m3u8`，libmpv 位置/时长恒 0；中继日志里每个 `hlsseg?n=1..4` 只写了 40–57 KB 就被播放器掐断。绕开中继与播放器 curl 直取 host 产物，`init+seg0` 拼起来 ffprobe 能解、解码零错误——**产物合法**；但 `ffprobe -tls_verify 0 <playlist url>` 报 `URL https://…/hlsseg?token=…&n=0 is not in allowed_segment_extensions … Invalid data found`。根因：FFmpeg 6.1.3+ / 7.1.1+ / 8.0（2025 年安全加固回移到维护分支；6.1.0～6.1.2 与 7.0.x / 7.1.0 没有这道门）的 `libavformat/hls.c` `test_segment()`（`extension_picky` 默认开）对 playlist 里每个分段 URL 先查 `allowed_segment_extensions` 白名单，扩展名取 **query 之前**的路径尾（`format.c` `ff_match_url_ext`），不在名单上直接 `AVERROR_INVALIDDATA`。host 首版把分段 URI 拼成裸 `hlsseg?token=&n=`（`packages/fushi_engine/lib/sync/fushi_sync_server/video.part.dart`，随 09-21 的 `96d7a5be096` 引入），没有扩展名；Android / iOS / macOS 随包 libmpv 是 FFmpeg 6.1.6、Windows 随包是 2026-08 的 master 构建，都在门内（Linux 走系统库，发行版 6.1.1 / 7.0.x 不复现），所以**随包四端一选画质档（或「自动」档在非局域网地址下起播）就黑屏**。
  - **第二段（seek / 恢复断点就黑屏）**：扩展名补上后从 0 起播五端都好，但 iOS 模拟器 / macOS / Android **只要 seek**（含恢复上次位置）立刻位置钉死、随后跳到片尾；Windows 客户端没事。mpv 日志：seek 后 hls demuxer 重新拉了 init + 目标段，但 mov demuxer 没报「duplicated MOOV」，随后 `[ffmpeg] NULL: Invalid NAL unit size (…) / missing picture in access unit` 成串。用 Windows 随包 libmpv（python-mpv 加载 `libmpv-2.dll`）对同一批产物做四组对照——静态文件、A/B 交替两份不同编码、活 host 明文直连、活 host 经中继——「打开 → seek 到 15 s」**全部正常**，排除分段格式 / host 动态出段 / 中继。差异只剩 FFmpeg 版本：Windows 随包 libmpv 是 2026-08 master 构建，Apple / Android 是 6.1.6。对照源码：master 的 `mov_read_packet` 开头有「`s->pb->pos == 0` 就丢弃 fragment index / 样本游标 / index entries 并重新 `mov_switch_root`」，专门配合 `hls_read_seek` 里的 `pb->pos = 0`；**6.1 的 mov.c 没有这段**，`mov_switch_root` 沿 seek 前的绝对 `next_root_atom` 向前跳过新数据再当 moof 解析，整条流从第一个样本起错位。6.1 的 hls.c 连 `EXT-X-DISCONTINUITY` 都不处理（子 demuxer 只在 `hls_read_header` 建一次），fMP4 在 6.1 客户端上无路可走。（中途怀疑过分段尾部 `mfra` 的 `tfra` 偏移失真——它确实与交付字节不一致，但剥掉后 macOS 照样坏，不是原因。）
- **[x] ① 已修复** — 见提交列表：① 分段端点带扩展名（`kTranscodeSegmentPathSuffix`，路由 / 鉴权豁免 / playlist 三处同一常量）；② 分段改成 **MPEG-TS**（`live_transcode.dart`：`-f mpegts` + `-output_ts_offset` 直接给绝对时间轴，`fmp4_rewriter.dart` 与 `hlsinit.mp4` 端点整个删除），ffmpeg-min 配方 `MUXERS` 补 `mpegts`、fork 上 `ffmpeg-min.yml` 重编后 vendor 到 `third_party/ffmpeg-min/{windows,macos}`，smoke-test 加了同形状的 TS 探针。修后真机（Mac 真 host 转码，画质档 2）：iOS 模拟器起播 1604 ms → seek 15 s → 16604 ms；macOS 从恢复位置 17313 ms 起播 → seek 15 s → 18063 ms，mpv 日志零 NAL 错；Android 见备注；Windows 随包 libmpv 经 python-mpv 直连 TS host seek 正常。
- **[x] ② 已加自动化测试** — `fushi/test/sync/fushi_sync_server_hls_segment_ext_guard_test.dart`：把 hls.c `test_segment` + `ff_match_url_ext` + `av_match_name` 与 6.1 白名单逐字移植成 Dart，用真 `FushiSyncServer` 签发 playlist、按 hls.c 的方式先解析成绝对 URL 再验每个分段（按探得 mpegts 的表；含裸 `hlsseg?token=` 必拒的负向自检、playlist 出现 `EXT-X-MAP` 即 fail、分段路由在新路径上真能到达 handler）；`live_transcode_test.dart` 钉 `-f mpegts` / `-output_ts_offset` / 不再有 `-movflags`、playlist 无 MAP；`fushi_sync_server_transcode_test.dart` 钉分段原样透传 + `video/mp2t`；`tool/ffmpeg-min/smoke-test.sh` 在 CI 重编时跑真 ffmpeg-min 出 TS 段并验起始时间戳。真机门：`fushi/integration_test/interconnect_remote_video_ios_itest.dart`（进程内直传 + 外部 host 画质档模式 + ≥20 s 样片时的 seek 阶段 + `--dart-define=FUSHI_TEST_MPV_LOG_FILE` 收尾回读 mpv 日志）。
- **备注**：
  - 不改 client：mpv 虽可用 `demuxer-lavf-o=allowed_segment_extensions=ALL` 放宽第一段，但 6.1 的 mov seek 问题客户端无解（换随包 libmpv 的 FFmpeg 是另一个量级的活）；协议错在 host，就在 host 修。
  - 新老组合：老 client + 新 host 无影响（client 从不自己拼 hls 子路径，只跟 playlist 走）；新 client + 老 host 仍是老 playlist、仍坏——host 升级才好，这是 host 侧协议 bug 的必然。
  - 取证装置：`packages/fushi_engine/tool/interconnect_video_host_probe.dart`（`--plain` 走明文，用来把 TLS / 中继从链里摘掉）；`VideoPlayerController` 的 `FUSHI_TEST_MPV_LOG_FILE` 钩子现在也认同名 `--dart-define`（Android / iOS 真机的进程环境从外面投不进来）。
  - 取证过程中一次失误：对用户平板 `flutter drive` 时测试包 versionCode 低于装机版，flutter 按默认回退卸载重装，平板上原装 Fushi 的应用数据被清；`flutter drive` 收尾还会卸掉 app，平板现在没有 Fushi，需用户重装。
