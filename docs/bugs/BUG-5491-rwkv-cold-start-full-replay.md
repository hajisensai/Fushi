## BUG-5491 · RWKV 冷启动逐卡重放全部历史，复习页首开等十几二十秒
- **报告**：2026-11-26（用户：iPhone 每次冷启动后第一次打开复习都要加载十多二十秒）
- **真实性**：✅ 真 bug。iPhone 真库取证（session_marker 重活账本）：冷启动后 `core:rwkv_cards 60x 28882ms`。根因：RWKV 分数表只在内存里（`native/fushi_rwkv/src/sched/machine.rs` `align_scores` 冷启动时 clear key 为空 → 整表清空），排队打分把所有候选卡都当缺失、统计 `current()` 又每次整表重查，两条路径都经 `_queryRows`（`packages/fushi_engine/lib/srs/srs_rwkv_service.dart`）调逐卡模式 `rwkv_cards`（`native/fushi_fsrs/src/store/gen4/cmd/training.rs`）。它只为取每张卡**最后一条**保留评分，却把每张卡按血统整个重放一遍：`logs_by_card` → `Index::replayed_logs` 对每条日志解码操作、拼投影 JSON、归一、重放（PC 真库副本实测 1.49 万张卡 36.5 秒，其中取日志 32.5 秒、投影 0.3 秒；约 20 万条日志，每条约 150 µs）。
- **[x] ① 已修复** — 「最后一条保留评分」本是卡行同一份重放的副产品：缓存层新增派生表 `rwkv_last`（`native/fushi_fsrs/src/store/gen4/cache.rs` 的 `DDL`，与 `cards` 同一次物化，`LogsByCard::rwkv_last` = `projection::rwkv_kept` 的最后一条；卡行删除由触发器连带删），进 `DERIVED_TABLES`（重建清空、增量与重建对拍都覆盖它）。新代 schema 40027 → 40028（用户 2026-11-26 拍板）：新代库第一次升号，新增就地升级名单 `schema.rs` `ADDITIVE_FROM`（只加对象的旧号，`check_kind` 认，每次开库的 `install` 用 `CREATE … IF NOT EXISTS` 补齐后写下新号）；`CACHE_RULES` 6 → 7 让升级后的库整层重建一次填上数据。升级后的库旧版本 app 打不开（报 schema 比本版本新）。新增读命令 `rwkv_rows` 模式 2（`cmd/training.rs` `rwkv_last`，一次按主键表读）→ Dart `SrsCore.rwkvLastRatings` / `SrsDbStore.rwkvLastRatings`（账本 `core:rwkv_last`），`_queryRows` 改读它。真库副本：1.49 万张卡 292 ms（原 35.4 秒），14913 张逐卡与逐卡重放的 last 完全一致。逐卡模式 `rwkv_cards` 仍给追加行（`_appendRows`，只涉及刚作答的几张卡）用。
- **[x] ② 已加自动化测试** — Rust：`store/gen4/derive.rs` `assert_rwkv_last_matches_replay`（挂在 `assert_rebuild_is_identity` 上，所有缓存场景——血统、重置、撤销、别名、Anki 副本——逐卡核 `rwkv_last` == 逐卡重放的 last；`rwkv_last` 也进了增量 vs 重建的派生表对拍）；`cache.rs` `cache_rules_matches_the_pinned_derivation_table` 记修订 7；`guards_tests.rs` `every_additive_schema_upgrades_in_place_to_the_frozen_shape`（40027 形状的库 = 新建库去掉登记的增量，指纹等于冻结的 40027；开一次后指纹等于 40028、号写成 40028）与 `schema.rs` `check_kind_*`（能就地升级的旧号被认并升号）。Dart：`packages/fushi_engine/test/srs/srs_rwkv_service_test.dart`「日志 → 回放行」核末条与逐卡重放在撤销前后一致；对拍夹具 `srs_rwkv_orchestration.json` 重写（只有 60 处 `cards` → `last` 取数记录替换，卡与 lastAt 逐条相同，后端调用 / 分数 / 状态不变，脚本核过）。
- **备注**：升级后首次开库有一次整层重建（与以往升 `CACHE_RULES` 相同）。iPhone 真机的冷启动复测待 develop 推送后的 TestFlight 包（不往用户手机覆盖装开发包）。冷启动时 `dart:load_stats` 约 15 秒：统计的 RWKV 整表重查走的就是本条修掉的那条路径（账本 60 次 = 两条路径各 30 块），TestFlight 复测时再看剩下多少。
