## BUG-2470 · 阅读器状态行坐进系统底部安全区
- **报告**：2026-09-12（用户：「没底栏的情况下，安全区依旧很高无法显示完所有文本」「iOS 端需要做到最底部都能显示阅读进度」，附 Hoshi Reader iOS 截图——进度读数直接画在 home indicator 那一带里）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/pages/implementations/reader_fushi_page.dart` 的 `_readerBottomReserve = _bottomChromeReserve + _statusFooterReserve + _stableBottomInset`（状态行高与系统底 inset **相加**）与 `chrome.part.dart` `_buildStatusFooter` 的 `bottom: _statusFooterBottomOffset`（= 系统 inset，状态行画在安全区**之上**）。
  - 机制：iPhone `viewPadding.bottom` = 34pt（home indicator）。正文底部预留 = 28（状态行）+ 34 = 62pt，其中 34pt 是一条纯背景色空带，谁也不画；状态行浮在它上面。用户看到的就是「没底栏也有一大条安全区」。home indicator 本身只是叠在内容上的一条 5pt 细线（离底 8pt），Apple 自家与 Hoshi Reader 都把内容画进去。
  - 桌面 / Android（阅读器进沉浸模式，系统栏隐藏）inset 为 0，两式相等，此前看不出来；只有 iOS 有这 34pt。
- **[x] ① 已修复** — 提交见合并记录。`readerStatusFooterBandHeight(footerReserve, bottomInset) = max(两者)`（`reader_status_footer.dart`）作单一真相源：页面 `_statusFooterBand` 取代「状态行 + inset」两段相加，`_readerBottomReserve = _bottomChromeReserve + _statusFooterBand`；状态行 `Positioned(bottom: 0)`，组件按 `bottomInset` 画整条带（带高 = max(28, inset)，读数行贴带顶、多出的在读数之下，落在 home indicator 细线之上）；挤压态窄屏底栏改坐在 `_statusFooterBand` 之上。iPhone 底部总扣除 62 → 34pt；桌面 / Android 带高 = 28，零变化。状态行不在场（歌词 / 被底栏吸收）时带高 = inset，与旧行为一致。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_status_footer_test.dart`：纯函数 `band: footer sits inside the system bottom inset`（28/34 → 34、28/0 → 28、28/16 → 28、0/34 → 34）+ 源码守卫（`_readerBottomReserve` 必须经 `_statusFooterBand`、状态行 `bottom: 0` + `bottomInset: _stableBottomInset`、旧 `_statusFooterBottomOffset` 不得回来）；`reader_chrome_floating_test.dart` / `reader_desktop_chrome_test.dart` 同步钉新式。真 app：`fushi/integration_test/reader_live_settings_itest.dart` 段 B 断言 `fushi_status_footer` 底边 == 窗口底边、带高 == max(28, viewPadding.bottom)——Windows / Mac 上 inset 0，iOS 模拟器上量 34。
- **备注**：Android 3 键导航（48dp 不透明导航栏）不受影响：阅读器进 `immersiveSticky`，导航栏隐藏、inset 为 0；若日后阅读器不再沉浸，48dp 的带会把读数画到按钮下面，届时要按 `systemGestureInsets` 或阈值区分手势条与按钮栏。
