## BUG-4472 · DPI-unaware 游戏在缩放屏上 WGC 失败后 PrintWindow 兜底把逻辑尺寸整帧误判为 partial，制卡无图失败
- **报告**：2026-11-12（志愿者机 Windows 11、显示缩放 300%；经典 KiriKiri2 游戏，窗口化，经 Locale Emulator 启动，32 位）
- **真实性**：✅ 真 bug（PrintWindow 判据部分）。宿主 `error_log.txt` 每次制卡都是 `CreateForWindow returned no item hr=0x80070057; PrintWindow produced partial client pixels; source WGC item rejected and no verified Magpie presentation mapping was found`，同机 KiriKiriZ 游戏 WGC 正常。被绑定窗口是被同进程 Delphi `TApplication`（可见、零尺寸 `WS_POPUP`）owned 的顶层 VCL 窗体，`dpi_awareness=0(unaware)`。
  - 根因：`fushi/windows/runner/window_capture.cpp` 旧 `TryCapturePrintWindow`（develop `:877-896`）用本进程（PerMonitorV2）读到的**物理**客户区尺寸分配 DIB 并预填哨兵；DPI-unaware 窗口在缩放屏上由 DWM 位图拉伸，PrintWindow 只按窗口**自身（逻辑）**客户区尺寸画到 DIB 左上角（300% 时约 1/9 面积），其余像素保持哨兵（**推断**：本机单显示器 96 DPI 无法实测缩放屏；与诊断是 `partial` 而非 `no pixels` 一致，新增诊断字段用于真机证实）。旧 `ValidatePrintWindowPixels`（develop `:636-676`，判据 `:665` `untouched_pixels != 0`）只要有任何哨兵残留就判 `kPartialPixels`——坐标系错配，不是画面不完整。
  - 为什么整张卡失败：`fushi/lib/src/mining/gal_hook_mining_coordinator.dart:563/605/656` 截图失败一律 `return done(captureFailed(still))`；这是现有设计（BUG-1227 曾把「无图仍建卡」当 bug 修掉），本条不改，是否降级为无图卡列为待决策。
  - **未定位**：WGC `CreateForWindow` 对该 HWND 返回 `E_INVALIDARG` 的原因。传入的就是被绑定窗口本身（`CaptureWindowPng` → `CaptureCore(source_hwnd)`，只有 `Magpie.SrcHWND` 属性才会换 HWND，`window_capture.cpp` `ResolveScalingSourceWindow`），没有换成 owner / 根窗口，没有任何坐标参与该调用。离线在 96 DPI 本机建「可见零尺寸 `WS_POPUP` owner + 同 style/ex-style 的 DPI-unaware / GDI-scaled / PMv2 owned 顶层窗」六种组合，WGC 与 PrintWindow 全部成功——owner 结构本身不触发 E_INVALIDARG；缩放屏条件本机无法构造（单显示器 96 DPI），不改用户显示缩放。
- **[x] ① 已修复** — `fushi/windows/runner/window_capture.cpp`：新增 `ReadNativeClientSize`（在目标窗口自身的 DPI awareness context 下 `GetClientRect`）；`ValidatePrintWindowPixels` 只接受两种完整布局——整张物理 DIB 都被画、或「原生客户区严格小于物理客户区，且左上角原生矩形内全画、矩形外全未画」——其余混合仍是 `kPartialPixels`；后者用 WIC 高质量插值拉伸到物理客户区（与 DWM 显示、WGC 交付的同一坐标系，`image == client` 不变量保持），捕获前后各读一次原生尺寸，变了按 client identity changed 拒绝。所有 PrintWindow 结论诊断追加 `(physical_client=WxH native_client=WxH dpi_awareness=N painted=[l,t,r,b])`，真机日志可直接证伪 / 证实本根因。
- **[x] ② 已加自动化测试** — `fushi/windows/runner/tests/window_capture_printwindow_helper_test.cpp` `CheckDpiVirtualizedPixelLayouts`：36x27 物理 / 12x9 原生——全画→完整物理帧；只画原生左上块→完整、区域 12x9；同一左上块但原生 == 物理→仍 partial（修前行为在非虚拟化窗口上保持）；原生块外漏一像素 / 原生块缺一行→partial；全未画→no pixels；原生块全黑→透明黑帧拒绝；原生块拉伸到 36x27 后像素全为原生颜色、alpha 255。
- **备注**：缩放屏真机复验待补（本机单显示器 96 DPI）。修好后同一游戏的期望日志：`PrintWindow fallback captured the DPI-virtualized client at its native size and scaled it to the physical client (physical_client=… native_client=… dpi_awareness=0 …)`。若真机仍是 `PrintWindow produced partial client pixels (…)`，按其中 `painted=` 与 `native_client=` 的实际关系再判，本条根因假设即被证伪。
