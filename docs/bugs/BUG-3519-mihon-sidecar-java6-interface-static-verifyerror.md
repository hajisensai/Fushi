## BUG-3519 · 桌面 sidecar 加载 keiyoushi Komga 扩展 VerifyError（dex2jar 产出 Java 6 类不能 invokestatic 接口方法），整个扩展装不上
- **报告**：2026-10-19（用户：桌面端装 keiyoushi Komga 1.6.73 失败，sidecar 栈 `java.lang.VerifyError: Illegal type at constant pool entry 552 in class eu.kanade.tachiyomi.extension.all.komga.Komga`，`Komga.r(MultiSelectListPreference;Komga;)V @61: invokestatic`）
- **真实性**：✅ 真 bug。dex2jar 把每个类都写成 major 50（Java 6），`third_party/m_extension_server/upstream_src/server/src/main/kotlin/mextensionserver/util/BytecodeEditor.kt:195` 的 `visit(version, …)` 原样透传。DEX 没有这条上限，当下扩展编出的两类东西在 52 以下非法：
  - 对 InterfaceMethodref 的 invokestatic / invokespecial（JVMS 4.9.1）——宿主 kotlinx-coroutines 1.11 把 `Job.cancel$default` 编成接口静态方法，Komga 常量池 #552 正是它；同形的还有一批扩展的 `invokeSuspend` 续体；
  - 接口里的非抽象（default）方法——`ClassFormatError: Method x in class y has illegal modifiers: 0x1`。
  HotSpot 拒掉整个类；Komga 的类在 `SourceFactory.createSources()` 就被链接，`fushi/lib/src/media/manga/mihon/mihon_manager.dart:686` 的 `_listSources` 抛错，安装回滚。加 `-Xverify:none` 诊断后 Komga 整条链路全通，说明没有第二个阻断。
  - 波及面实测（keiyoushi 索引 1400 个 APK + yuzono 动画仓库 250 个，逐个用 sidecar 自己的 `PackageTools.dex2jar` 转换、对每个类 `Class.getDeclaredMethods()` 强制链接校验、不初始化）：修复前 13 个扩展有被拒的类——常量池型 10 个：keiyoushi Komga 1.6.73、MangaFire 1.6.34、BatCave 1.6.13、InfinityScans 1.6.14、MangaCloud 1.6.0、SpyFakku 1.6.1、Ono 1.6.0、SoftKomik 1.6.0、ComX 1.6.42、yuzono Hanime 14.24（Hanime 两型都有）；接口修饰符型：yuzono Jellyfin 16.32、Stremio 16.11、YFantasy 16.3、Hanime 14.24。
- **[x] ① 已修复** — `BytecodeEditor.transform` 把低于 52 的版本写成恰好 52（`convertedClassVersion`，经 `server-build.gradle.patch`）。不高于 52：53 起 putfield/putstatic final 字段只许在初始化器里，DEX 代码不守这条。升到 52 后 JVM 不再回退到推断式校验器，靠的是已有的 `ClassWriter.COMPUTE_FRAMES` + `ClassReader.SKIP_FRAMES` + 基于 ClassHierarchy 的 `getCommonSuperClass`（只读类字节、不加载类）重建每个方法的 StackMapTable——全量语料验证 1650/1650 个 APK 的所有类在 52 下链接通过，修复前在 50 下能过的类没有一个在 52 下失败。提交见 PR。
- **[x] ② 已加自动化测试** — `third_party/m_extension_server/overlay/server/src/test/kotlin/mextensionserver/util/ConvertedClassVersionTest.kt`（构建脚本的 `:server:test` 跑，CI 两个桌面 job 都会跑）：Java 6 夹具先自证会被 HotSpot 拒（invokestatic 接口静态、invokespecial 接口 default）；转换后版本为 52、可链接可调用；final 字段在构造器外赋值仍可用（钉死不超过 52）；版本只升不降。
