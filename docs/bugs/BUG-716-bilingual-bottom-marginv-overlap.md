## BUG-716 · 双语底部对白 MarginV 塌陷重叠
- **报告**：2026-07-10（用户：提供真实 fansub「双语.ass」，要求「尽量尊重原字幕自带样式、多轨字幕完美支持」）
- **真实性**：✅ 真 bug。用当前 develop(+627) 代码离屏渲染该文件的重叠 JP/CH 对白对，两条 `\an2` 底部字幕塌陷到同一 75px 基线、盒相交叠印，且逐字查词把上面 CH 的字误判成下面 JP（hit-test 命中错 cue）。根因 `hibiki/lib/src/media/video/video_subtitle_overlay.dart:576` `_positionKey` 与 `:1201` `_paddingFor` 的交互。
- **[x] ① 已修复** — 根因：`_positionKey`（`video_subtitle_overlay.dart:576`）把底部锚点 cue 按**原始** MarginV 拆成不同分组，但 `_paddingFor`（`:1201`）底部基线 = `max(bottomPadding=75, scaledMarginV)` 单调抬升不越用户基线——故 MarginV 缩放后都 <= 75 的两条（典型 `Dial_JP` MarginV=4 + `Dial_CH` MarginV=30）被 `max` 夹回同一基线，两组各自定位却落同一 y、互相压字。修复：`_positionKey` 底部锚点改按**渲染后基线是否真的不同**归键——缩放后 `<= bottomPadding`（会被 `max` 夹回）的 MarginV 折进基线桶（key mv=-1），使它们同组、走 `_syncGroupSlots` 竖排堆叠（libass 碰撞下推同效果），不再叠印；真正超出基线的标题（MarginV=400 等）仍各自 authored 高度（TODO-1341 不回归）。并在 `_groupMainCuesByPosition`（`:552`）对组内按 MarginV 升序稳定排序（小的贴底、大的在上），复现 libass「MarginV 越大离底越远」的次序、不依赖字幕书写先后。提交 e765fe181。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_subtitle_bilingual_marginv_overlap_test.dart`：① 复现真实布局（`\an2` MarginV 4 + 30、均 < bottomPadding）断言两条盒**不重叠**（CH 底缘 ≤ JP 顶缘）+ CH 在上 + 跨 cue 查词各归各句；② 守卫大 MarginV（400 > 75）标题仍在 authored 高位、不被折叠（TODO-1341 不回归）。既有 dual_position / multicue / slot_snap / multi_full / overlay / markup 全套 72 测试无回归。
- **备注**：仅静态 MarginV 定位（本文件招牌 `Scr` 用的 `\frz` 旋转 / `\move` / `\fscy`+`\t` 缩放动画仍不支持，属独立 gap，不在本 bug）。离屏 flutter_test 无系统字体（字形显示为盒），字号/颜色/描边/上下分层几何真实；真机字形保真度待用户设备复测。
