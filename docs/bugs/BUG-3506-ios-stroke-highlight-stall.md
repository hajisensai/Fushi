## BUG-3506 · iOS 笔触样式高亮停住不跟随、查词无高亮
- **报告**：2026-10-17（用户：iOS 有声书跟读，高亮样式选了笔触样式后——开不开落笔动画都一样——当前句高亮画到一半停住，cue 往前走了高亮不跟；翻页再翻回来又显示完整高亮；查词时被查的词没有高亮）
- **真实性**：✅ 真 bug，iOS 26.5 模拟器 Safari + 生产引擎页（iOS 平台 `ReaderContentStyles.css` + `ReaderSelectionScripts.source()` + `engineShell` + `__fushiInstallShell`）复现，两个独立根因：
  1. **笔触高亮停住（重绘失效，DOM 是对的）**：`fushi/lib/src/reader/reader_selection_scripts.dart:1339`（修前）每组写一张 1×1、`overflow:visible` 的 `<svg class="fushi-mark-ink">` 定在窄条层原点，笔划全画在盒外的溢出区（CSS `reader_content_styles.dart:1021` 修前把它钉成 1px）。WebKit 竖排下算不对这块溢出区的重绘范围：每步 DOM 里的路径都随 cue 正确更新，屏上却停在上一次整层重建时的样子（翻页重建才补上）；竖排滚动模式宿主层在屏外，整张 svg 从来不画。对照（9 对「动作 / 真值」不一致数）：经典 0/9；马克笔、荧光笔竖排翻页 7/9，马克笔 + 落笔动画 8/9；横排不复现。macOS 27 WKWebView 的极简页面不复现。
  2. **查词无高亮（钩子丢失，DOM 没更新）**：`reader_selection_scripts.dart:1467`（修前）把 `CSS.highlights.set/delete/clear` 的钩子装在顶层局部变量 `reg` 指向的对象上，之后没有任何闭包引用它。WebKit 的 `CSS.highlights` 包装对象没人引用时会被回收，下次读到的是新对象，钩子随之消失（实测：GC 后 expando 属性消失；先用全局变量拿住就保留）。查词 / 搜索写进注册表后窄条层收不到通知、不重画；而 `::highlight(fushi-selection)` 底色早已清空、可见底色只靠窄条层（BUG-3369），于是被查词无高亮。与笔触样式无关，经典样式同样中招。
- **[x] ① 已修复** —（提交见本分支 `fix(reader): BUG-3506 …`）改法：① `markSvg` 由行几何算出笔划包围盒（沿行 ±2em、跨行 ±3.5em，覆盖粗细上限 + 盖住振假名 + 滤镜外扩），svg 盒子 = 包围盒（内联 `left/top/width/height !important` + 同位同大的 `viewBox`），路径坐标不变，不再靠溢出区；CSS 去掉 1px 钉死。② `hookRegistry()` 用闭包变量 `hookedRegistry` 强引用装了钩子的注册表，`flush` 每次重画前调它（对象换了就补装）。
- **[x] ② 已加自动化测试** — `fushi/test/reader/highlight_stroke_marker_harness.mjs`（真 Chrome 跑生产 CSS + 引擎：六种笔触在最粗 + 盖住振假名时每一笔都落在自己的 svg 盒内、svg 盒不是 1×1；修前代码上红在 `the stroke svg box is the stroke bounds (1.0x1.0)`）；`fushi/test/reader/highlight_lanes_registry_hook_guard_test.dart`（源码守卫：注册表被存活闭包强引用、flush 先 hookRegistry 再画、旧的局部变量写法不得回来——WebKit 包装回收 Chrome 测不出来）。
- **复验**（iOS 26.5 模拟器 Safari，修复版生产页，10 对「动作 / 真值」：cue×3 → 热替换样式表 → cue → 查词 → 撤查词 → cue → 翻页 → cue）：经典 / 马克笔 / 马克笔 + 落笔动画 / 荧光笔 × 竖排翻页 / 竖排滚动 / 横排翻页 / VN 竖排，16 组中 13 组 0/10；余下 3 处都只是笔划边缘 1 CSS px 竖线（约 3.6k 设备像素，修前是整句级 10 万+），疑为重绘矩形取整，未定位。查词后 400ms 选区层已画出、屏上与真值一致，`__fushiLanesHooked` 始终为 true；所有路径都在各自 svg 盒内，真值红像素数与修前逐步相同（无裁切 / 偏移）。未在真机 / 真 app WKWebView 上验。
- **备注**：`highlight_lanes_test.dart` 的「竖排有声书窄条与振假名墨迹重叠约 1px」在未改动的 upstream/develop 上同样失败，与本修复无关。
