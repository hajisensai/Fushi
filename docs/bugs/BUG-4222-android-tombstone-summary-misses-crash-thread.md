## BUG-4222 · Android 原生崩溃摘要抽不到崩溃线程栈
- **报告**：2026-11-07（崩溃报告 `#MdVKlfPOWD`：Xiaomi 2311DRK48C，Android 15，3.3.0，`CRASH_NATIVE status=6`）
- **真实性**：✅ 真 bug（取证端）。报告里的 `trace summary` 只有 `SIGABRT` / `SI_QUEUE`、abort message `FORTIFY: pthread_mutex_lock called on a destroyed mutex (0xb400007b25adc2f0)`，之后是 `hwuiTask1`、`mali-compiler`、`CookieMonsterBa`（WebView）几条线程的 `futex/pthread_cond_wait` 帧，**没有崩溃线程**，无法定位。
  - 根因：`fushi/android/app/src/main/java/app/fushi/reader/ProcessExitChannel.java` `readTraceSummary` 对 API 31+ 的 tombstone protobuf 只读前 64 KB、抽长度 ≥ 6 的可打印串、截 3000 字（`printableRuns`）。tombstone 的线程表是 `map<uint32, Thread>`，序列化顺序与崩溃线程无关，一百多条线程（这份 thr=108）各带寄存器与栈内存片段，崩溃线程常在 64 KB 之外；即使读到了，可打印串里也不标哪条是崩溃线程。
- **[x] ① 已修复** — 新 `TombstoneSummary.java`（同目录）：按 AOSP `tombstone.proto` 线格式解出 pid / tid / uptime、signal（号、名、code、fault addr）、abort message、causes、线程表；按 `tid` 找出**崩溃线程**列 40 帧（`#NN pc rel_pc  file (offset 0x…) (func+off) (BuildId: …)`，与 debuggerd 文本格式同读法，apk 内 so 带 offset + BuildId 可直接对符号），崩溃线程不是主线程时再列主线程 12 帧，按整行截到 3400 字。tombstone 读取上限 64 KB → 8 MB（后台单线程执行器上读）。解不开时标 `tombstone unparsed (原因, 字节数)` 再退回可打印串。
- **[x] ② 已加自动化测试** — `fushi/android/app/src/test/kotlin/app/fushi/reader/TombstoneSummaryTest.kt`（4 例，`gradlew :app:testDebugUnitTest --tests app.fushi.reader.TombstoneSummaryTest` 4/4 过）：手搓 > 64 KB 的 tombstone（107 条带 4 KB 栈内存的无关线程在前、崩溃线程在后、另有 registers / memory_mappings / 未知 fixed64 字段），摘要点名崩溃线程并逐帧列出、apk 路径折成 `base.apk (offset 0x…)`、无关线程不出现；崩溃在主线程时只列一次；按整行截断；截断的 proto 抛错不误读。
- **备注**：
  - `#MdVKlfPOWD` 本身**仍无法定位**：现有材料只有 abort message。`pthread_mutex_lock called on a destroyed mutex` 是「某线程锁了已被析构的互斥量」——常见于进程退出时静态析构与仍在跑的线程赛跑，或某个原生对象释放后仍有线程用它。该进程 08:03:49 进后台（`lastLifecycle=paused`）、08:05:18 崩溃（importance=125），首个采样 `cpu=299.5s[DartWorker×9 236.3s …]`、`srs=2/2`（两份 SRS 内核同时开着）。崩溃线程是谁要等带本修复的版本再报一次。
  - ANR（`REASON_ANR`）走文本 trace，原样保留 "main" 线程段；其中 libflutter 帧可用 Flutter 引擎公开符号（`flutter_infra_release/flutter/<engine>/android-arm64-release/symbols.zip`）对，libapp（Dart AOT）帧 release 包无符号，对不了。
