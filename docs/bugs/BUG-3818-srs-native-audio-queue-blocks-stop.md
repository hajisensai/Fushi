## BUG-3818 · 复习换卡后上一张音频不停（原生 just_audio play() 占住串行队列）
- **报告**：2026-10-27（用户：应用内反馈 N-JACNGS-K Android 3.0.1-debug.21417、MljlXfzZzL macOS 3.0.1-debug.20797；1o9Oe8GuDR 同机「音频播放不了」疑同类）
- **真实性**：✅ 真 bug（沿代码路径 + 上游源码确认，非设备复现）。
  - `fushi/lib/src/utils/misc/desktop_audio_playback.dart:280`（修前）`_play` 的串行 body 里 `await _player.play()`。注释假设它「native play 请求被接受就返回」——只对 media_kit 后端（Windows / Linux，`main.dart` `JustAudioMediaKit.ensureInitialized()` 缺省参数）成立。Android / iOS / macOS 走 just_audio 原生实现：`just_audio-0.9.42/android/.../AudioPlayer.java:938-952` 把 `play` 的 `Result` 存进 `playResult`，直到暂停 / 播完 / 释放才回复（darwin `AudioPlayer.m:1027-1031` 的 `_playResult` 同理）；just_audio 的 `play()`（`just_audio.dart:933-971`）等的就是它。
  - 于是在这些平台上一段音频**整段播放期间占着 `_activation` 队列**：换卡 / 翻面时 `SrsCardAudioSequencer`（`srs_card_autoplay.dart:349-386`）发出的 `DesktopAudioPlayback.stop()` 排在它后面跑不了，上一张卡的音频播到结束；下一张卡的 `playFile` 也排在后面，要么等旧音频播完才开播（「挤压下一张卡的音频」），要么被那次 stop 的 preempt 作废——N-JACNGS-K 日志里成串的 `DesktopAudioPlayback.playFile: preempted by stop() before/after load — playback dropped` 就是这条。
  - 页内通道：卡面 WebView 里页面自己开播的媒体（脱离文档的 `new Audio()`、shadow root 里的）换卡时不归 `__fushiSrsSetCard` 的 `stopMedia(root)` 管，会响到播完（`srs_card_face.dart` 外壳脚本修前只停卡面根下的 `<audio>/<video>`）。
- **[x] ① 已修复** —
  - `desktop_audio_playback.dart`：新增 `justAudioUsesMediaKitBackend`（`:75`，与 `main.dart` 的 media_kit 接管平台同一口径）。串行 body 里 media_kit 后端照旧 `await play`（BUG-342 的激活边界不变）；原生后端 `play()` 的 Future 覆盖整段播放，只发出不等（`:320` 起，`load()` 已完成平台激活，这里只剩 `_sendPlayRequest`，失败照常进错误日志），播完由 `playFileToEnd` 读 `playerStateStream` 判定。`stop()` 在队列里排超过 750 ms 留一条 `DesktopAudioPlayback.stop` 诊断（取证，不改行为）。
  - 页内通道：自动播放闸门（`srs_card_autoplay.dart` `kSrsCardAutoplayGateScript`）记下页面里开过播的媒体（`play()` 包装 + `play` 事件），暴露 `__fushiSrsStopAllMedia`；外壳换卡（`srs_card_face.dart` `__fushiSrsSetCard`）在换内容前调用它。换卡 / 翻面 / 离开页面（WebView 销毁）三条路都确定性停下所有页内媒体。
- **[x] ② 已加自动化测试** — `fushi/test/utils/misc/desktop_audio_playback_native_play_future_test.dart`（假播放器模拟原生 / media_kit 两种 `play()` 语义：stop 立即打断在播片段、下一段立即替换、自然播完仍报完成、media_kit 仍在 body 内等 play）；`fushi/test/utils/misc/desktop_audio_playback_serial_guard_test.dart` 守卫随新结构更新；`fushi/test/srs/srs_card_autoplay_gate_test.dart` + `srs_card_autoplay_gate_harness.mjs` 真 Chrome 新增「换卡停掉文档内 / 脱离文档 / shadow root 三路在响的媒体」。变异：把原生分支改回 `await play` → 新测试 2 条红（stop 打断、下一段替换）；去掉换卡时的 `__fushiSrsStopAllMedia()` → Chrome 检查红（脱离文档的那段换卡后仍在播：`after:[true,false,true]`）；均还原后绿。
- **备注**：未在 Android / macOS 真机复测（缺设备）。1o9Oe8GuDR「音频播放不了」只有标题无正文，日志只有一条 warmUp 诊断，归同类是推测：原生后端下任何一段卡住不结束的播放都会把此后所有排队播放钉死，这次修复同样解掉；若复发，新加的 `DesktopAudioPlayback.stop` 排队诊断会出现在日志里。
