## BUG-3291 · 片段导出烧字幕丢失原字幕颜色与加粗
- **报告**：2026-10-12（用户反馈 #ZsUlsXebWm，Windows，2.10.0-debug.18749：片段导出时字幕缺少原字幕的颜色、加粗等样式）
- **真实性**：✅ 真 bug — 烧录链路只传纯文本：`packages/fushi_engine/lib/media/video/video_clip_subtitle.dart` `buildClipSubtitleCues` 产出的 `ClipSubtitleCue` 只有 `text`，丢掉了 `AudioCue.markup`；`fushi/lib/src/media/video/video_clip_subtitle_image.dart` `renderClipSubtitlePng` 用一个统一 `TextStyle` 画整句。屏幕 overlay 在「尊重字幕自带样式」开着时会按 markup 上色 / 加粗，导出件却一律用户外观。随包 `ffmpeg-min` 刻意不带 libass（`tool/ffmpeg-min/build-ffmpeg-min.sh` 注释：选 overlay 而非 subtitles filter，避免 libass+freetype+fribidi+fontconfig 四个原生依赖），所以修法是把样式传进 Dart 侧渲染，而不是改用 libass 烧录。
- **[x] ① 已修复** — `ClipSubtitleCue` 新增 `markup`（透传源 cue 的 `SubtitleMarkup`）；`video_clip_subtitle_image.dart` 新增 `clipCueStyledMarkup`（只有真带样式的 cue 才走富文本，纯文本 cue 导出逐字节不变）与 `buildClipSubtitleStyledSpan`（与 overlay 同源：样式表 `PrimaryColour` / `Bold` / `Italic` / 下划线 / 删除线为基线，行内主色、`\1a` 填充透明度、粗斜体覆盖，描边色作投影色，`\N` 还原换行）；`clip_export.part.dart` 按 `appModel.videoRespectAssStyle` 门控（与屏幕同一开关）。提交：c6b9a6d90d。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_clip_subtitle_image_test.dart` `styled cue export` 组（真 ASS 经 `AssParser` → `buildClipSubtitleCues` → 富文本：样式表红色 + 粗体 + 蓝描边、行内绿色、`\N` 换行；纯 SRT 走旧路径；带样式渲染出整帧 PNG）。
- **备注**：范围只到颜色 / 粗体 / 斜体 / 下划线 / 删除线 / 描边色。ASS 的字号、字体、`\pos` / `\an` 定位、旋转、`\t` 动画、卡拉 OK 不跟随（导出排版仍按用户统一外观换算，保证大小与位置可预期）；多层特效字幕的叠层去重沿用旧行为。
- **审查返工（PR #2081）**：烧录 overlay 链与截图合成都是「后画的在上」，原先按 cue 列表（文件）顺序叠；改为每层带自己颜色后，多层叠字的底层（黑字 + 白描边）若在文件里排在上层之后会盖住上层、烧出黑字。新增纯函数 `orderClipCuesForBurn`（`packages/fushi_engine/lib/media/video/video_clip_subtitle.dart`，按 `SubtitleMarkup.layer` 升序稳定排序，与 libass / 屏幕 overlay 的 z 序一致），`video_clip_exporter.dart` 烧录与 `clip_export.part.dart` 截图合成两处都经它；SRT 不受影响。测试：`fushi/test/media/video/video_clip_subtitle_test.dart` `orderClipCuesForBurn` 组。
