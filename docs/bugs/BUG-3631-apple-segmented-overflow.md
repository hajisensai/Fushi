## BUG-3631 · iPhone 上 Apple 分段条放不下时右侧被裁、横拖滚不动
- **报告**：2026-10-20（用户：应用内反馈 sJPo20DIsj，iOS 27.0.1 / iPhone 402x874@3 / 英文界面 / Apple 设计系统；漫画阅读器设置面板顶部「Mode / General / Filters / OCR」最右段被裁一截，「Dictionaries」页「Term 5 / Kanji dictionaries 1 / Frequency…」第三段几乎整段被裁，原话「被裁掉而不是滚动」）
- **真实性**：✅ 真 bug。两处宿主其实都已经放进了横向滚动区（漫画设置 `fushi/lib/src/media/manga/reader/manga_reader_settings_sheet.dart:1223`，宽 < 384 时 `HorizontalDragScrollable` + `SingleChildScrollView`；词典页 `fushi/lib/src/pages/implementations/dictionary_dialog_page.dart:1798`，一律横向滚动），截图里的「裁切」就是滚动视口的边缘——问题在于**滚不动**。根因在组件层：Apple 分段控件 `FushiAppleSegmentedControl` 整条控件挂着一个滑块横拖识别器（upstream/develop `fushi/lib/src/utils/components/glass/fushi_glass_toggles.dart:4184-4206`，`GestureDetector` + `onHorizontalDragStart` + `DragStartBehavior.down`）。它和外层 `Scrollable` 的横拖识别器在同一个手势竞技场里比；内层先收到移动事件、先过 slop，必胜，所以在分段条上的任何横拖都变成了「拖滑块」，外层滚动永远拿不到手势。分段条本身就是这一行的全部可触区域，视口外的段因此既看不到也点不到。词典页更严重，是因为 Apple 分段按「最宽段 × 段数」等宽取宽（`fushi_glass_toggles.dart:3914`），「Kanji dictionaries 1」把四段都撑到约 170 pt。Material（M3E）分支（`FushiPillSegmentedButton` / `FushiConnectedButtonGroup`）没有横拖识别器，同宽度下横拖正常滚动，不受影响（有测试钉住）。
- **[x] ① 已修复** — `fushi_glass_toggles.dart`：滑块横拖改用 `RawGestureDetector` + `_SegmentThumbDragRecognizer`（`isPointerAllowed` 按按下点过滤，`:4385`）；`allowsThumbDragFrom`（`:4194`）判据：控件比最近的横向滚动视口还宽时（`_segmentedControlOverflowsHorizontalScrollable`，`:4373`），只有从选中滑块上起手的横拖才拖滑块（iOS `UISegmentedControl` 同语义），其余横拖不参与竞技、交给外层滚动；放得下或不在横向滚动区时（含 PageView 的一页）判据恒真，手势分工与外观不变。改在组件层，所有放进横向滚动宿主的 Apple 分段（漫画设置、词典页、`FushiSegmentedStrip` 等）一起受益。提交：本 PR。
- **[x] ② 已加自动化测试** — `fushi/test/widgets/apple_segmented_overflow_scroll_test.dart`（402x874@3 + Apple 设计系统 + 词典页同形态宿主）：溢出时从非滑块处横拖会滚动且不改选中、末段可滚到并点选；溢出时从滑块起手仍拖滑块；宽度够时无滚动距离、任意处横拖照旧拖滑块；不在滚动区时照旧；M3E 同宽度可滚。去掉修复后第一条红（`Expected: <2> Actual: <0>`，横拖被滑块吃掉改了选中）。
- **备注**：未在 iPhone 真机 / 模拟器复测（本批按要求只用代码路径 + widget 测试证明），需真机复测两处原始路径：漫画阅读器设置面板顶栏、设置 › 词典页类型分段，在非选中段上横拖应滚动、从选中段起手应拖滑块。待拍板：等宽段在词典页仍很宽（约 680 pt 需滚两屏），是否改为 Apple 的按内容分配段宽（`apportionsSegmentWidthsByContent`）未在本次改动，保持既有设计。
