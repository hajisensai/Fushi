## BUG-2496 · 封面/图片文件非空但不可解码：写侧无校验、非原子直写，渲染侧无兜底当致命错误落盘
- **报告**：2026-09-13（用户贴错误日志：两条同毫秒 `FlutterError: resolving an image codec / Exception: Invalid image data`，栈只到 `FileImage._loadAsync`）
- **真实性**：✅ 真 bug。不是 0 字节文件（那会报 `StateError ... is empty and cannot be loaded as an image`），是**非空但不可解码**的文件：HTML 错误页存成 `.jpg`、连接中断 / ffmpeg 写一半的半截 JPEG（头部合法、无 EOI）。两条同毫秒 = 两个不同 completer = 同一帧两张不同坏图；且只有 completer 上没有任何带 onError 监听者时错误才会走 `FlutterError.reportError`，所以一定来自无 `errorBuilder` 的渲染点。三层根因：
  1. **写侧无「是不是图片」判据**：`packages/fushi_engine/lib/media/cover_file_writer.dart` 的 `writeCoverBytesAtomically` / `copyCoverFileAtomically` 只管原子写与驱逐，任何字节都收；ffmpeg 两条路（`desktop_audio_clipper.dart:788-811` 抽帧、`video_cover_extractor.dart:103-125` 内嵌封面）让 ffmpeg **直写最终路径**，后者非零退出只要文件非空就当成功（损坏的 attached_pic 解码到一半退出留下半截 JPEG 照样当封面）；书架/更新中心在写到一半时重建就读到半截文件。
  2. **四处绕过收口的直写**：`media_source.dart:780` 书 override 缩略图 `copySync`；`book_import_dialog.dart:1073` SRT 封面 `copy`；`pdf_importer.dart:87` PDF 封面 `writeAsBytes`；`online_manga_library_service.dart:129` 在线漫画封面 `writeAsBytes`，其 `_imageExtension` 对未知魔数一律回落 `.jpg`——`fetchCover` 返回的 HTML 错误页就这样成了 `cover.jpg`。
  3. **渲染侧**：`updates_center_page.dart:205`、`reader_gallery_page.dart:280/391`、`media_collection_detail_page.dart:1947/2045`、`media_item_edit_dialog_page.dart:328`、`manga_series_page.dart:1523`、`reader_fushi/chrome.part.dart:972`、`crop_image_dialog_page.dart:90` 的 `Image.file` / `Image(image: FileImage)` 无 `errorBuilder`；`main.dart:625` 的 `FlutterError.onError` 不看 `details.silent`（Flutter 把图片解码失败标为 `silent: true`，`image_stream.dart:910/985/998`），当致命错误同步 flush 落盘，且坏文件每次重建都重复解码重复报。
