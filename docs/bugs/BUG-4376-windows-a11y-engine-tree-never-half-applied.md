## BUG-4376 · Windows 无障碍树：引擎在语义更新被 AXTree 拒收后不自愈（半应用、委托悬空），且框架违约更新直接交给 AXTree
- **报告**：2026-11-10（崩溃报告 `GUbS2C2ukc`，Windows 3.3.0+24434，同一进程 02:32 连续两次 native AV；用户拍板「改自维护引擎加固 Windows 无障碍树，应该怎么做就怎么做」）。
- **真实性**：✅ 真原生崩溃，根因在引擎（`flutter_windows.dll`），框架侧失步来源只是触发条件。
  - 现场：`GUbS2C2ukc` 的日志先记到生产哨兵 `A11y.axTreeDesync`「Nodes left pending by the update: 5824 / 5825 / 5826 (child of 5563)」（与 [BUG-4333](BUG-4333-windows-axtree-desync-pending-children-recur.md) 同一形态：父节点列出从未下发的子节点），几分钟后平台线程崩在 `flutter_windows.dll+0x1001334` = `memmove ← vector::erase ← AccessibilityBridge::CreateRemoveReparentedNodesUpdate`（与 [BUG-3796](BUG-3796-windows-nav-switch-freeze-a11y-reparent.md) 同崩点），光栅线程随后在 `ContainerLayer` 析构里写 AV（堆已被前一次越界 memmove 写坏）。
  - 引擎根因（Flutter 3.47.6 引擎 `engine/src/flutter/shell/platform/common/accessibility_bridge.cc`，打补丁前）：
    1. **拒收即永久失步**：`CommitUpdates` 把框架的增量更新原样交给 `ui::AXTree::Unserialize`（:108）。`AXTree` 在「Nodes left pending」「would be reparented」等检查失败时**已经改完一部分树**（建了 / 删了 `AXNode`）才返回 false，且不发 `OnNodeCreated` / `OnNodeDeleted`；bridge 只 `FML_LOG(ERROR)` 后 return（:65-67、:113-116），`id_wrapper_map_` 从此与树脱节：树里新建、映射里没有的节点 → `HitTestSync` / `ChildAtIndex` 解引用空委托（BUG-4073 / [BUG-2345](BUG-2345-flutter-child-at-index-null.md)）；树里已删、映射里还在的委托 → 读已释放的 `AXNodeData`（[BUG-2337](BUG-2337-windows-uia-flutter-host-crash.md)）；失败更新留在 `event_generator_` 里的事件指向已删节点，下一帧事件循环读它们。
    2. **重挂校验只在 debug 生效**：`CreateRemoveReparentedNodesUpdate` 用 `assert` 保证「子节点有父」「被重挂的子节点本帧重发了」「旧父节点的 child_ids 里有它」（:226、:235、:248），release 下全是空操作；树已失步时 `std::find` 返回 `end()`，`child_ids.erase(end())`（:249）越界 memmove——本次崩点。
    3. **框架违约的更新不先处理**：框架只发变化的节点，bridge 却只拿「本帧 pending」建更新，所以「父节点列出没下发过的子节点」（BUG-4333）、「节点下发时没有父节点列它」（[BUG-2839](BUG-2839-windows-a11y-orphan-semantics-crash.md) / BUG-4073 的孤儿）、「子节点换父节点却没重发」都直接成了 AXTree 拒收；bridge 也不保留以前下发过的节点数据，后续帧无法补齐。
    4. 其它悬空点：`OnNodeReparented`（:158）是空函数——AXTree 在同一份更新里销毁并重建同 id 节点时只发这个回调，委托继续指着已销毁的 `AXNode`；`FromFlutterSemanticsNode` 存的是指向 embedder 更新缓冲区的 `flags` 指针（:594）；自定义动作描述按「本帧 pending」表查找、找不到时 release 下解引用 `end()`（:517-520）。
  - Windows 节点委托（`shell/platform/windows/flutter_platform_node_delegate_windows.cc:66-75`、`shell/platform/common/flutter_platform_node_delegate.cc:90`）对拿不到的子委托 / 越界子节点只有 `FML_DCHECK`，release 下直接解引用。
- **[x] ① 已修复（引擎补丁，待重编引擎产物后随包生效）** — 新补丁 `ci/patches/flutter-engine/3.47.6/engine-a11y-tree-hardening.patch`（`tool/flutter_engine/build_patched_engine.ps1` 的 patch 步骤按序打，来历与删除条件见同目录 `README.md`）：
  - `AccessibilityBridge` 保留框架下发过的每个节点的最新数据（`semantics_nodes_`，flags 按值存）与自定义动作（`custom_actions_`）；每次提交先把 pending 合并进去，再从根节点按「子节点必须有数据、每个节点只挂一个父节点（本帧重发的父节点优先）、先父后子」推出目标树（`PlanTree`），然后与当前 AXTree 比对生成两步更新（`ApplyTreePlan`：先把换父节点的节点从旧父节点摘掉，再发新增 / 变化 / 子节点列表变化的节点，被摘掉子树里的节点用保留的数据重建；第一步按 AXTree 现有数据摘过子节点的旧父节点在第二步一律按保留数据重新序列化，否则框架没重发它时它的 role / `kClipsChildren` 还停在「有子节点」）。BUG-4333 那种「列出未下发子节点」的帧不再交给 AXTree，那几个子节点等数据到了自动挂上；孤儿节点留到有父节点列它时再挂；没重发的换父节点按保留数据重建子树。
  - AXTree 仍拒收（按构造不应发生）时 `RebuildTree`：先清事件、销毁全部委托（平台节点随之 `Destroy`，持有它的 UIA / MSAA 客户端拿到「元素不可用」而不是读野指针），再用同一个 tree id 新建 AXTree 从目标树整树重建；连重建都失败就留空树，保证树与委托映射始终一致，绝不半应用。
  - `CreateRemoveReparentedNodesUpdate` 与其中的 `assert` 删除（由 `ApplyTreePlan` 的显式计算取代），`OnNodeReparented` 改为重建该节点的委托，自定义动作缺失时补空描述保持与 id 列表对齐。
  - 委托：`ChildAtIndex` 越界 / 子节点为空返回 `nullptr`；`HitTestSync` 跳过拿不到委托的子节点（记 ERROR）并在 bridge 已释放时返回自身。
  - 框架侧的取证哨兵（`A11y.axTreeDesync`，`fushi/lib/src/utils/misc/semantics_ax_tree_contract.dart`）保留不动：它报的是框架违约本身，引擎现在能吸收这些违约，但框架来源（BUG-4333）仍应定位修掉。
- **[x] ② 已加自动化测试** — 引擎单测随补丁加进 `engine/src/flutter/shell/platform/common/accessibility_bridge_unittests.cc`：`ChildWithoutDataIsNotLeftPending`（BUG-4333 现场形态 + 数据后到自动挂上 + 越界 `ChildAtIndex`）、`NodeSentBeforeAnyParentListsItAttachesLater`（孤儿）、`MovedChildThatIsNotResentKeepsItsSubtree`（本次崩点：换父节点不重发，含子树，委托指向当前 `AXNode`）、`ChildListedByTwoParentsIsPlacedOnce`、`NodeDataOutlivesTheUpdateBuffer`（flags 指针悬空）、`CustomActionDescriptionSurvivesLaterUpdates`；原有 `CanReparentNode*` 等用例不改。本仓源码守卫 `fushi/test/build/windows_a11y_engine_hardening_guard_test.dart` 咬住补丁存在、LF、被构建脚本打上、关键改动（整树重建、`OnNodeReparented` 换委托、委托判空、删掉 release 下无效的 `assert`、flags 按值存）。
