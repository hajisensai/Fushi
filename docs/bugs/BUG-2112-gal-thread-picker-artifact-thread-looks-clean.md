## BUG-2112 · 游戏文本线程选择器把全伪影线程当干净线程展示，选中后永远 0 行且无提示
- **报告**：2026-09-04（ceshi 批量适配 · KiriKiri Z `tenshi_sz.exe`（天使☆騒々 RE-BOOT! 官方多语言版 ver1.12，x86）真机会话，worktree 构建 + 隔离实例）
- **现象**：工作台线程下拉里出现 `KiriKiriZ · 0xe1c450 · #fc19 · 10`，副标题预览是干净整句「暗闇の中で燃え盛る炎。」，看起来比 EmbedKrkrZ（日中双语混出）更干净；选中后「实时台词 · 0」「尚未收到台词」，下拉里该线程行数继续涨（6→10），浮窗不更新，会话事件里只有 `text.thread_selected`，**没有** `thread_history_recovered` 也没有任何警告。切走再切回、推进多句均无效。
- **真实性**：✅ 真 bug（消费端呈现/判据缺口，native 行为正确）。探针 `fushi_voice_ring_probe <pid> --dump-thread-previews`（本轮新增）读预览槽：该线程 `line_count=10, artifact_count=10, flags=1`，原文是逐字 ×3 伪影「徐徐徐々々々ににに汗汗汗ばばばむむむ…」（兄弟线程 `#b7b3` 是 ×2）；`--dump-text-events` 读文本环：该 thread_id 只有 1 条 `ThreadDiscovered`、**0 条 line**。链路：`native/galgame_hook/injector/injector_main.cpp:957` 预览写在门控**之前**（含伪影行）→ `:970 LunaShouldWriteLine` 对伪影返回 false → 行从未进文本道（正确）；Dart 侧 `fushi/lib/src/sync/texthooker_service.dart` `collapseTexthookerPreview` 把预览折叠成干净句子供下拉展示，`_compareTextThreads` 里虽有 `observedArtifactCount * 2 > observedLineCount` 的「脏线程」判据但**只用于排序**——UI 不标、记忆恢复 `_maybeRestoreTextThread`/自动选 `_maybeAutoSelectEngineExactThread` 不跳、`selectTextThread` 不报，用户按预览选中即静默死态。
- **[x] ① 已修复** — `TexthookerTextThread.isArtifactDominated` 成为唯一判据：排序复用；`texthookerThreadSubtitle(artifactLabel:)` 在下拉与选线程弹窗副标题最前显示「逐字重复伪影线程，不会有可用台词」（i18n `game_text_thread_artifact_hint`）；记忆恢复与引擎精确线程自动选跳过伪影主导线程（同 hook 面的逐字兄弟线程指纹相同、行数更多，否则会被优先恢复）；`selectTextThread` 选中伪影主导线程时记 `text.thread_selection_artifact_dominated` 警告事件。探针加 `--dump-thread-previews`（`native/galgame_hook/tools/ring_probe.cpp`）作为以后分型「预览有字、选进去没字」的第一步。
- **[x] ② 已加自动化测试** — `fushi/test/sync/texthooker_service_test.dart`：`isArtifactDominated` 阈值、副标题伪影提示置首、排序把伪影主导线程排后。
- **备注**：tenshi_sz 上真正可用的是 `EmbedKrkrZ · 0xd22188`（KiriKiri Z 官方多语言版会把日文与中文两份都吐出来，日文行可配到 `game_resource` 语音，中文重复行走 loopback），`KiriKiriZ · 0xe1c450` 的所有 ctx 子线程都是逐字重绘伪影。与 BUG-1470（采集/发布判据分叉）同一族：都是「预览区不受门控、正文受门控」两套口径没有向用户解释。
