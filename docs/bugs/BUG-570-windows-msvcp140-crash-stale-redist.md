## BUG-570 · Windows app crashes at launch (MSVCP140.dll c0000005) on machines with stale VC++ Redistributable
- **报告**：2026-07-06（用户：）
- **真实性**：✅ 真 bug。根因不在 Dart 层，在打包链路：`.github/workflows/release-desktop.yml` 的 Windows job 从头到尾没有把 MSVC CRT 运行库（msvcp140.dll / vcruntime140.dll / vcruntime140_1.dll）拷进 `hibiki/build/windows/x64/runner/Release/`，`hibiki/windows/installer/hibiki.iss:39` 的 `Source: "{#SourceDir}\*"` 只能打包 Release 目录里已有的文件，所以安装包里根本没有 CRT。hibiki 的 C++ 模块（inappwebview_windows / hoshidicts / media_kit 等）用较新的 MSVC 工具链 `/MD` 动态链接 CRT，引用了较新的 STL/EH 符号（`VCRUNTIME140_1!__CxxFrameHandler4`）。当目标机器系统 VC++ Redistributable 停在 2019 旧版（14.24）时，System32 里的 `vcruntime140_1.dll` 缺这些导出符号 → 加载器解析失败 → `hibiki.exe` 启动即以 faulting module `MSVCP140.dll`、异常码 `c0000005`（访问违例）闪退。
- **[x] ① 已修复** — `.github/workflows/release-desktop.yml:311` 新增「Bundle VC++ CRT runtime into Windows bundle」步骤（在 ffmpeg 安装之后、Compile installer/ISCC 之前）：用 `vswhere` 定位 VS2022 安装路径 → 在 `VC\Redist\MSVC\<version>\x64\Microsoft.VC<NNN>.CRT\`（版本目录通配、不硬编码）里取含 `msvcp140.dll` 的最新 CRT 目录 → 强制拷贝 `msvcp140.dll`/`vcruntime140.dll`/`vcruntime140_1.dll`（缺任一 `throw` 失败，不静默跳过）+ 按存在拷可选伴生 DLL（`msvcp140_1/2`、`msvcp140_codecvt_ids`、`concrt140`）到 Release 目录。DLL 落在 `hibiki.iss` 的 `Source: {#SourceDir}\*` 打包范围内，随安装包分发；app 目录 DLL 载入优先于 System32，无需提权，与目标机器系统 redist 版本无关。标准 Flutter Windows 自包含分发做法。提交：b2a0e4df4
- **[x] ② 已加自动化测试** — `hibiki/test/tools/release_desktop_crt_bundle_guard_test.dart`：源码扫描守卫，断言 release-desktop.yml 含 CRT 打包步骤、拷贝根因所需三个 DLL 名、用 vswhere 稳健定位、且该步骤排在 Compile installer(ISCC) 之前（否则打包时 DLL 未落地等于没修）。5 项全过。提交：b2a0e4df4
- **备注**：CI/打包链路修复，未改任何发布通道触发/条件/channel 逻辑；`tool/check_release_policy.ps1` PASS。真机验收口径：在一台**只装旧版（≤14.24 或全无）VC++ Redistributable**的 Windows 机器上安装新包，`hibiki.exe` 能正常启动进主界面（不再 MSVCP140.dll c0000005 闪退）；或用 Dependencies/dumpbin 确认安装目录下已随包出现 msvcp140.dll + vcruntime140_1.dll。
