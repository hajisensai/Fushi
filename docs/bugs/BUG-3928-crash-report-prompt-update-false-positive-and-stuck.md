## BUG-3928 · 闪退报告提示：自动更新也弹、点「不用了」关不掉、点「发送」发不出去
- **报告**：2026-11-01（用户：反馈 msySECp2Cy（Windows）、jmgMk1gHG2（Android））
- **真实性**：✅ 真 bug，三处根因：
  1. **自动更新被判成闪退（Windows / macOS）**：`fushi/lib/src/utils/misc/platform_updater.dart` 把进程交给更新安装器 / 替换脚本后直接 `exit(0)`，没调 `PreviousExitLog.markCleanExit()`；下次启动会话标记读到「没标 clean、停在前台」→ `describeUncleanPreviousSession` 判 `unexpected`（反馈 msySECp2Cy 日志：`WindowsInstaller.handoff` 后 18 秒即 `Process.previousExitUnclean … 疑似闪退`）。
  2. **自动更新被判成闪退（Android）**：`fushi/lib/src/diagnostics/previous_exit_log.dart` 的 `androidExitKind` 把 `PACKAGE_UPDATED` 归 null 交给会话标记，而安装器杀进程时 app 常在前台（反馈 jmgMk1gHG2：`reason=PACKAGE_UPDATED importance=100 … installPackageLI`）→ 同样判 `unexpected`。
  3. **关不掉 / 发不出去**：`fushi/lib/src/pages/implementations/feedback/crash_report_prompt.dart` 首页出来后的提示用 SnackBar，回调里捕获了当时的 `ScaffoldMessengerState`。根 MaterialApp 被整树重挂（`main.dart` 按界面语言变 key 的 `KeyedSubtree` 等）后旧 messenger 被 dispose，首页 Scaffold 带 GlobalKey 被搬进新树、还画着旧提示条；点「不用了」/「发送」都在已 dispose 的动画控制器上 `reverse()` → 抛空指针（用户日志 `Null check … ScaffoldMessengerState.hideCurrentSnackBar … crash_report_prompt.dart:290`），条不收起；「发送」的 `onSend` 抛出后卡片切到失败态显示「闪退日志没发出去」——其实根本没提交。已用一次性 widget 复现确认：重挂后旧条仍可见，点按抛 `reverse() called after dispose()` 且不消失。另外它画在首页 Scaffold 里，被推上来的页面盖住（反馈 jmgMk1gHG2「rendered below most elements」）。
- **[x] ① 已修复** — ① `platform_updater.dart` Windows 安装器交接与 macOS 替换脚本两处 `exit(0)` 前 `PreviousExitLog.markCleanExit()`；② 新增 `PreviousExitKind.appUpdated`（`PACKAGE_UPDATED`，不值得报，优先级压过会话标记推断）；③ 首页出来后的提示改成 app 级浮层：状态放在 `crashReportHomePrompt`（`ValueNotifier`，不挂在任何 widget / messenger 上），`CrashReportPromptHost` 挂在 MaterialApp builder 的全局浮层 Stack、导航之上，与启动前提示共用同一张浮动卡片（滑入 + 淡入），15 秒不点收起。
- **[x] ② 已加自动化测试** — `fushi/test/feedback/crash_report_test.dart`（Android `PACKAGE_UPDATED` 前台也不报；根 MaterialApp 按 locale key 重挂后「不用了」收起并作废、「发送」收起并真的提交；不点按时收起、这批留着）；`fushi/test/utils/misc/update_handoff_test.dart`（Windows 安装器交接退出时会话标记已 clean）。
- **备注**：Windows 关机 / 注销被判「疑似闪退」的同类缺口另记 BUG-3929 并已修。
