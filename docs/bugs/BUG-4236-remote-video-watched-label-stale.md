## BUG-4236 · 视频页远端卡「看到 X」只显示 host 清单快照：同步拉到新断点 / 播完返回后不刷新
- **报告**：2026-11-07（Linux Phase 4 互联测试，Docker 客户端 + Windows host；实测截图与日志（未入库）：客户端库里已是 host 的 50 s，视频页继续观看卡仍是「Watched to 0:40」）
- **真实性**：✅ 真 bug。
  - 根因①：卡片断点只认 host 清单条目的 `RemoteVideoInfo.positionMs`（`fushi/lib/src/pages/implementations/home_video_page.dart:2024-2025` `_loadRemoteVideos` 把清单原样交给卡片，`:6720` 等处直接 `formatVideoPosition(video.positionMs)`；合集详情的远端上下文 `:10241` 同样）。清单经 `RemoteLibraryCache` 取（`:2077`，TTL 60 s，`fushi/lib/src/sync/remote_library_cache.dart:45`），视频页又是保活 tab，快照可以是几分钟前的。本机库里的远端断点（互联 sweep / 冲突弹窗 / 播放页 / 本机作为 host 收到的对端 PUT 写入）完全不参与显示，而开播位置早已认它（BUG-4231 `resolveRemoteVideoResumeMs`）——卡片和实际续播对不上。
  - 根因②：没有任何刷新触发。`_refresh` 刻意不重拉远端（`:1184`），`_openRemote` 不等播放页返回（`:3403`），sweep 落地断点也不通知本页（本机断点在偏好表，BUG-3610 的观看进度信号只看 `video_books`）。
- **[x] ① 已修复** — 一份判定、两处使用：`fushi/lib/src/media/video/remote_video_resume.dart` 抽出 `newestRemoteVideoPosition`（本机库断点 vs 已知 host 断点取较新），开播判定与卡片都走它；`withLocalRemoteVideoPositions` 一条前缀查询读齐本机断点（`localRemoteVideoPositionFromPrefs`，与 `readLocalRemoteVideoPosition` 同口径），把清单条目换成取较新后的副本（`RemoteVideoInfo.withPosition`，host 播放列表按 host 当前集比较）。视频页 `_loadRemoteVideos` 与合集详情远端上下文都套上它。刷新：新增数据层信号 `watchLocalRemoteVideoPositionsChanged`（偏好表表级更新 + `video_remote_position_*` 键族快照比较，别的偏好写入不发），视频页订阅，前台防抖重算（清单仍走缓存，不多打 host），被播放页 / 详情页盖住时记一笔、露出来再算——覆盖 sweep 落地与播完返回两条路径。提交见 git log（fix/interconnect-video-resume-stale）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/home_video_remote_watched_label_test.dart`（真 `HomeVideoPage` widget）：本机库断点较新时卡片显示本机断点、较旧时显示清单；页面常驻时本机库断点被写新（sweep 同款直接写库）→ 卡片就地变成新值且不重新列 host 清单。`fushi/test/sync/remote_video_watched_label_stale_test.dart`（真 host + 真 sweep）：sweep 后缓存的旧清单条目显示 host 新断点，且等于离线开播的续播位置；清单较新 / 本机无记录原样返回；播放列表按当前集比较；断点信号对 sweep 写库与偏好仓库写入都发、对无关偏好不发。
- **备注**：未在设备上复测（下一轮 Phase 4 补）：客户端看过 host_long → host 上接着看 → 客户端停在视频页手动同步 → 继续观看卡应立刻变成 host 新位置；客户端播放后返回视频页，卡片应是刚看到的位置。首页 dashboard 的远端「继续」卡（`home_dashboard_page.dart` `remoteContinueCandidates`）与合集详情页自身的刷新时机未改，仍按清单快照，需要时另开。
