## BUG-2560 · iOS 制卡后「已制卡 ✓」不刷新，要重新点词才出现
- **报告**：2026-09-16（用户：「ios添加完卡片并没有出现打勾弹框还是没变得重新点击词才出现」）
- **真实性**：✅ 真 bug，而且是**时序上的结构性错配**，不是偶发竞态。AnkiMobile 的 `mineEntry` 在 `_openUrl` 返回 true 后就回 `MineOutcome.success`（`fushi/lib/src/anki/ankimobile_repository.dart:541-555`）——那一刻 AnkiMobile 才刚被拉起，卡还没进库；真正的「卡进去了」要等 `x-success` 回跳才落账（`fushi/lib/main.dart:1258-1263` → `fushi/lib/src/anki/ankimobile_mined_ledger.dart` 的 `record`），那已经是用户从 AnkiMobile 切回来之后。而 popup.js 制卡成功后**立刻**回问一次 `duplicateCheck`（`fushi/assets/popup/popup.js` 的 `refreshFromAnki`），必然问在落账之前 → 拿到 `false` → 画「+」。落账之后没有任何机制回头刷新已经打开的弹窗，所以 ✓ 只能等用户重新查一次这个词才出现。
- **[x] ① 已修复** — 由落账那一侧回头通知界面（延迟重试是掩盖，不是修复）：新增进程内广播 `MinedStateSignal`（`fushi/lib/src/anki/mined_state_signal.dart`），`AnkiMobileMinedLedger.record` / `forget` 内部发（发在账本里而不是调用点，任何新的落账路径都不会漏）；`DictionaryPopupWebViewState` 订阅它并 `evaluateJavascript` 调 popup.js 新入口 `window.fushiRefreshMineStates({expression})` 重问 `duplicateCheck` + 重画按钮。popup.js 三镜像同步。提交 `e54a6ab593`
- **[x] ② 已加自动化测试** — `fushi/test/anki/ankimobile_mined_ledger_test.dart`（落账与 `forget` 都广播、没有状态变化时不广播）；`fushi/test/utils/misc/popup_asset_behavior_test.js` 的 `testHostRefreshPaintsMinedStateAfterLateLedgerWrite`（制卡返回时仍画「+」，落账后宿主刷新才亮 ✓，指名别的词不连坐），由 `fushi/test/pages/popup_mine_audio_fresh_resolve_static_test.dart` 驱动进 CI。
- **备注**：同一次用户报告里「卡片删掉也不会检测是否还存在」那半见 BUG-2561；「其他平台是否也有一样的问题」的答案是有一条同症状路径，见 BUG-2562。
