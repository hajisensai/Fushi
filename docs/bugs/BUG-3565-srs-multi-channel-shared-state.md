## BUG-3565 · 云盘 + 互联同时开着时复习同步状态全局一份：批次只到先跑的目录、另一个目录每轮换化身
- **报告**：2026-10-19（排查 BUG-3566 时发现）
- **真实性**：✅ 真 bug。`SrsSyncLocalState`（写入者身份、批次号、冻结批次、cursor、起步 / 快照进度）每个 profile 只存一份，而 app 对每条已认证通道各跑一轮 `SrsSyncEngine.syncOnce`（`fushi/lib/src/sync/sync_auto_trigger.dart` 的通道后置步骤与 `runOnAuthenticatedSyncChannels`）。修复前 `packages/fushi_srs/lib/src/sync/sync_engine.dart`：`_publish` 在第一个目录确认后就清掉冻结批次、事件已 `markPublished`，批次只到先跑的目录；第二个目录里列不到本写入者目录，`syncOnce` 开头的「`everPublished && listFiles(writerId) == null` → 换新化身」把它误判成「已被当作退役清理」，每轮换一次化身（旧化身目录堆积）。另外 `bootstrapped` / `lastSnapshotBatch` 全局一份，第二个目录永远不起步、快照节奏错位。
- **[x] ① 已修复**（fd34aeda59 + 9913660568）— 目录只是传输介质：写入者身份 / 批次号 / cursor 全局一份（批次冻结后逐字节不变），按目录记进度（`SrsDirectoryState`，键为稳定目录身份 `fushi/lib/src/srs/srs_directory_key.dart`）；冻结批次留存在本机（schema v121 `srs_sent_batches`），每个目录各自按序补传，留存到最近同步过的目录都确认；落后太久的目录用快照补齐、读方遇缺口改读覆盖快照；只有「出现过本写入者目录、现在不见了」才换化身。多目录拓扑下补上转发（另一个目录里写入者不活着时把新落地 / S 变小的事件带过去，批次头 `fs` 带原 S）与「缺就全量重新发布」核对。设计见 `docs/specs/2026-10-14-fushi-srs-design.md`「多目录传输」。
- **[x] ② 已加自动化测试** — `packages/fushi_srs/test/simulator_test.dart`「多目录（云盘 + 互联 host）」固定用例（同一批次到每个目录且不换化身、桥接互通含桥接前历史、快照补齐、留存逐批补传、未传过的目录不换化身、被清理的目录照旧换化身、旧版本状态）+ 桥接 / 双目录两种拓扑各 60 个随机种子（收敛 / 事件一致 / 修改不丢）；`fushi/test/srs/srs_sync_scheduler_test.dart`「同一批次传到每个目录；再同步不换化身」（真 SrsDbStore + 两个目录）与「同时触发的几轮依次跑」；`fushi/test/database/migration_v121_srs_sent_batches_test.dart`（建表）。
- **[x] 审查后续（d2ba14fe1e）** — ① 目录身份不稳：Google Drive / OneDrive / Dropbox 账户没认出来（`currentEmail` 为空）时身份原是 `googleDrive:`，认出来后变 `googleDrive:<账户>`，同一个物理目录被当成两个目录（重新起步、可能全量重发；两个不同账户都落成 `googleDrive:` 还会互相套用进度、误判换化身）。改为拿不到稳定身份时 `srsDirectoryKeyOf` 返回 null，调度器这一轮跳过该后端（`kSrsSyncDirectoryIdentityUnavailable`），不建目录状态（`srs_directory_key.dart` 的 `srsAccountDirectoryKey` / `srsServerDirectoryKey`，WebDAV / FTP / SFTP 地址为空同理）。测试 `fushi/test/srs/srs_directory_key_test.dart`、`srs_sync_scheduler_test.dart`「目录身份拿不到」。② 大发件箱切批：`SrsSyncOptions.maxEventsPerBatch`（5000）——全量重新发布 / 大包导入不再冻结成一个巨型批次，单个文件有界、中断时已确认的批次不重传；测试 `simulator_test.dart`「发件箱按 maxEventsPerBatch 切批」（固定用例 + 每批 1 条的单目录 / 双目录各 30 个随机种子）。
- **取舍（保留，不改）**：
  - 新目录起步时，本机持有、而该目录里不活着的写入者的数据要「全部事件重新发布一次」：引擎只按写入者记进度，而身份记录（牌组 / 笔记类型 / 笔记）不带写入者，无法只挑缺的那几个写入者的事件；只重发一部分会让 `relayed` 记账失真，之后的转发判据跟着错。代价是新加目录时整库多传一份（切批后单个文件有界）。
  - `legacyDirectories`（旧版本升级上来、没有按目录记账）只在换化身时清除：旧状态不知道升级前用过哪些目录，第一次在某个目录里找不到本写入者时分不清「从没传过」与「被当作退役清理过」，按后者换一次化身是安全侧；之后新化身没有旧账、标记清除。代价是升级后最多一次全量重发。
- **备注**：真机（云盘 + 互联同时开）复测待补。批次头新增可选键 `fs`，旧版本照常解码、只对转发 / 重新发布事件的 S 取值不同（多目录此前本来不工作）。
