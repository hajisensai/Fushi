## BUG-3605 · 漫画远程 OCR 右上角进度走两遍（上传段与识别段共用一条进度）
- **报告**：2026-10-19（用户：Android，反馈 uTsfcZodup「ocr的右上角提示会走两遍进度条。第一次走完会从0继续」，截图为漫画阅读器右上角「OCR 17/169」浮标；日志里同期整卷 OCR 走的是 `MangaOcrJobRegistry.pairedHost` / `MangaFushiPage.wholeVolumeOcr`，即已配对主机引擎）
- **真实性**：✅ 真 bug，不是真跑了两遍，是两个阶段共用一条进度。已配对主机整卷 OCR 分两段：先逐页上传页图（`fushi/lib/src/sync/interconnect_manga_ocr_client.dart:407` 发 `MangaOcrRemoteEvent.uploading(done, total)`），再轮询 host 识别进度（同文件 `:441` 发 `MangaOcrRemoteEvent.running(done, total)`），两段各自从 0 数到总页数。转成统一后台事件的 `mangaOcrRemoteEvents`（`fushi/lib/src/media/manga/manga_ocr_job_stream.dart:449`）把 `uploading` 丢了，两段都变成同形的 `MangaOcrBackgroundEvent.progress`；阅读器 HUD（`fushi/lib/src/media/manga/reader/manga_fushi_page.dart:6396`）只拼 `OCR done/total`，于是上传走完一遍、识别又从 0 走一遍。导入向导自己直连远程流、区分了上传文案，所以只有走任务注册表的入口（阅读器浮标、作品页横幅、章节列表、桌面控制通道）中招。顺带：远程 finished 事件不带页数（`total` 恒 0），映射后整卷完成事件的 `pagesTotal` 也是 0。
- **[x] ① 已修复** — `MangaOcrBackgroundEvent.progress` 新增 `uploading` 阶段位（默认 false，其它引擎不变），`mangaOcrRemoteEvents` 原样带出并让 finished 沿用进度报过的总页数；注册表跟随步骤转发保持阶段；阅读器浮标上传段显示「OCR · 正在上传页面 x / y…」、识别段仍是「OCR x/y」；作品页 OCR 横幅与章节列表副标题上传段同样换成既有的上传文案（`manga_remote_ocr_uploading`，不新增 i18n）；桌面控制通道任务 JSON 上传段多带 `phase: uploading`，`fushi_cli` 显示为「上传 x/y 页」。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_ocr_job_stream_remote_phase_test.dart`（远程事件映射：上传段标 uploading、识别段不标、finished 带总页数）；`fushi/test/pages/manga_fushi_page_test.dart`「BUG-3605」（注册表里的远程任务：上传段浮标显示上传文案、不出现「OCR 1/2」，识别段才显示「OCR 1/2」）。
- **备注**：未在真机复测（本批不使用真机），待真机复测：已配对主机跑整卷 OCR 时浮标先显示上传、再显示识别进度。是否把两段合成一条 0→100% 的进度属于展示取舍，本修复沿用导入向导既有的「上传 / 识别分开显示」口径。
