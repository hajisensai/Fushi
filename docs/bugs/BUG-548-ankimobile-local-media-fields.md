## BUG-548 · iOS AnkiMobile 制卡本地音频图片未嵌入
- **报告**：2026-07-05（用户：APKG 对比：`/Users/wight/Downloads/1.apkg` 为 iOS 制卡，`/Users/wight/Downloads/2.apkg` 为 Windows 正常制卡）
- **真实性**：✅ 真 bug。沿真实 APKG 与代码路径定位：iOS 导出的 `media` 索引为空，note 字段里的 `ExpressionAudio` / `SentenceAudio` / `Picture` 仍是 `/var/mobile/Containers/.../Library/Caches/...` 沙盒绝对路径；Windows 正常包则有 `hibiki_audio_*` / `hibiki_cover_*` 媒体文件，字段为 `[sound:...]` 与 `<img src="...">`。根因在 `hibiki/lib/src/anki/ankimobile_repository.dart:185` 旧路径直接 `buildMinedFields(... dictionaryMediaTags: const {})`，没有像 AnkiConnect / AnkiDroid 那样先把本地封面、句音频、词音频和词典媒体转成 Anki 可导入的媒体引用。AnkiMobile URL Scheme 又没有 `storeMediaFile` API；官方手册要求字段里提供可下载的图片/音频链接才会由 AnkiMobile 接管媒体，因此裸本地路径必然无法随卡片进入 collection media。
- **[x] ① 已修复** — 本提交：`AnkiMobileRepository` 新增 `_renderMinedFieldsForAnkiMobile`，在字段渲染前并发读取本地封面、句音频、本地词音频与词典媒体缓存，转成 `data:<mime>;base64,...`；远程词音频 URL 保持原样交给 AnkiMobile 下载；再复用 `buildMinedFields` 做模板渲染和词典媒体占位符替换。这样 iOS addnote URL 不再暴露沙盒路径或 `hoshi_dict_*` 占位符。
- **[x] ② 已加自动化测试** — `hibiki/test/anki/ankimobile_repository_test.dart` 新增回归用例：先用临时 GIF/AAC/MP3 与词典 SVG 缓存复现旧 URL 里出现本地路径的失败，再守住 `ExpressionAudio` / `SentenceAudio` / `Picture` / `Glossary` 都输出 data URL，且不包含临时路径和 `hoshi_dict_0.svg`。验证：`/Users/wight/fvm/versions/3.44.0/bin/flutter test test/anki/ankimobile_repository_test.dart`。
- **备注**：APKG 1 里的大量 `+` 属于已记录的 [BUG-547](BUG-547-ankimobile-query-plus-encoding.md)；当前分支已有 `%20` 回归测试通过。本次修复覆盖独立的媒体缺失问题。最终 AnkiMobile 是否把 data URL 落成 collection media 仍需真机创建并导出 APKG 复看，因为第三方 AnkiMobile 确认界面无法在本地单元测试里自动驱动。
