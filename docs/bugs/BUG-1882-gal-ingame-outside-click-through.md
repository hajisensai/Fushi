## BUG-1882 · 游戏内查词点外关闭时同一点击穿透到游戏推进台词
- **报告**：2026-08-25（用户：Windows / STEINS;GATE RE:BOOT 内嵌查词）
- **真实性**：✅ 真 bug，且首版修复边界不足 — direct galCard 的 `WH_MOUSE_LL` 已在真机确认绑定正确并能关闭 popup，但 SGRE 不靠 Win32 mouse message 推进：精确 exe（SHA-256 `75A83A0E…C404B9D8`）创建 `GUID_SysMouse` / `c_dfDIMouse2`，以 `DISCL_FOREGROUND | DISCL_NONEXCLUSIVE` 获取设备，并在每帧调用 `IDirectInputDevice8::GetDeviceState(20)` 直接读取 `rgbButtons[0..7]`。因此 HHOOK `return 1` 只能挡窗口消息，挡不住物理 DirectInput state；这正是“框消失但游戏仍下一句”的首个失败边界。
- **[x] ① host 点击事务** — `global_lookup_window.cpp` 只在 direct galCard 的 Reveal 事务中同步确认 HHOOK；`low_level_mouse_hook.cpp` 以真实窗口 region / 绑定游戏客户区区分卡内外，异步通知 Hide 并成对吞掉点外 down/up。桌面/global route 使用独立 HWND，仍保持原点击穿透语义。
- **[x] ② SGRE 专用 DirectInput 输入盾** — `sgre_lookup.h/.inc` 只在既有精确 SGRE profile 内读取已证实的 mouse device slot `module+0xA96E18`，detour vtable slot 9；先调用原 `GetDeviceState`，再仅对同一个 mouse `self` 且 `cbData==20` 清 `[12,20)` 的八个按钮字节，绝不改 lX/lY/lZ。注入侧 button latch 在 popup 隐藏后继续屏蔽已经见过的 down，直到 raw state 真正报告 up，杜绝半个点击泄漏。
- **[x] ③ 跨进程生命周期 / fail-closed** — 精确 SGRE 先在游戏 HWND 发布 `Required`，detour 安装且 trampoline 非空后才以 `Ready` 作最后 commit；Fushi 看到 Required-without-Ready 时拒绝 direct 上屏，写入 popup HWND 后还会重读 Required/Ready/Window，封住 health worker 的撤销竞态。helper 在 live popup publication 存在时推迟例行主窗迁移；`SetPropW` 被 UIPI 拒绝仍 fail closed。Fushi 崩溃后 popup HWND 自动失效，helper 的 `IsWindow + GW_OWNER + class` 校验使输入盾失效。Hide 撤 property 前通过 hook-thread callback barrier，旧 up 只投递 popup-thread finalizer，并按具体 direct HWND（不是任意 desktop/global target）判断，避免 ABA 与永久残留。
- **[x] ④ 定向自动化** — native `sgre_adapter_test.cpp` 钉死 exact RVA/vtable/DIMOUSESTATE2 ABI、轴不变、八按钮 active→held→up latch 和未知布局 no-op；Dart 守卫钉死 direct-only publication、Required→Ready/UIPI fail-closed、二次提交校验、HHOOK down/up、callback barrier、跨实例撤销以及 desktop 负边界。45 条相关 Flutter 守卫通过；x64/x86 的 `fushi_sgre_adapter_test` 与 `fushi_voice_hook` 定向构建通过；Windows Debug runner 已重新编译并安装同哈希 helper。按开发约定未跑全量测试。
- **备注**：不新增铺满游戏的透明遮罩窗。它仍挡不住 DirectInput，还会额外引入 DPI、Z 序、全屏与截图副作用。
