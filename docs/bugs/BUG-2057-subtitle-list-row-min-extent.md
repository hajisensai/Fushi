## BUG-2057 · 字幕列表行高被历史固定行高 56×字号档钉死，单行（尤其英文译文）上下留白特别大
- **报告**：2026-09-03（用户：视频页字幕列表截图，罗马音行与英文译文行交替，「英语的上下间距特别高」）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/media/video/video_subtitle_jump_panel.dart:658`（`_minRowExtent => 56 * _fontScaleSteps`）+ `:764`（`_measureRowExtent` 末尾按它取下界）。

  56 是 asbplayer 版字幕列表最初的**固定**行高（`b98370fb75`：`static const double _itemExtent = 56`）。BUG-1034 把行高改成按 `TextPainter` 真实测量的自适应值时，把这个固定值留成了保底下界，注释写作「TODO-340 的历史视觉密度」。结果它不是「下界」而是**几乎所有行的实际行高**：默认字号 14 下 1 行需要 `16 + 17.5 = 33.5`、2 行需要 `16 + 35 = 51`，两者都低于 56，于是**一行的行和两行的行一样高**，单行行里 60%+ 是空白。字号档越大越离谱——1.5× 档实测内容只要 45、行高却是 84（多 87%）。

  为什么用户说是「英语」：一条字幕的英文译文通常只占 1 行，而同一条的日文/罗马音更常换到 2 行。2 行的行把 56 填满了、1 行的行没填满，所以视觉上只有英文行「上下间距特别高」。

  照片取证（去斜 + 像素测量，比例尺由图标间距 `3×(字号+2)` 与行内 padding 16 双向交叉验证）：截图里 7 个可测行的归一化行高全部落在 443~509 px 的同一档，与它们是 1 行还是 2 行**无关** —— 即每一行都被钉在保底下界上，正是本 bug 的指纹。

- **[x] ① 已修复** — 删掉 `_minRowExtent` 与那次取下界，行高改为纯 `kSubtitleRowPaddingVertical + max(文本, 时间戳单行, 动作图标)`。行内可点内容（时间戳、3 个动作图标）本来就已经进了这个取最大值，保底那一档不提供任何功能保证，纯属遗留特例。默认字号下 1 行 56→36（−36%）、2 行 56→52。提交见本分支。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_subtitle_row_extent_guard_test.dart` 新增 group `BUG-2057 行高只由内容决定（无保底下界）`，在 0.85× / 1.0× / 1.5× 三个字号档上断言几何契约 `行高 == kSubtitleRowPaddingVertical + max(文本, 时间戳, 动作图标)`，三个分量**全部取自真实渲染**（不复刻实现常量），并额外断言 1 行 < 2 行 < 3 行严格递增。变异实测：把 `56 * _fontScaleSteps` 下界加回去，三个档位全红（33.9 vs 47.6 / 36.0 vs 56.0 / 45.0 vs 84.0）。
- **备注**：行高变矮属于视觉密度变化，字号档 A+/A− 仍照常整体缩放。`kSubtitleRowPaddingVertical = 16` 是固定值、不随字号档缩放，本次未动（与本 bug 无关，改它会再动一次密度）。
