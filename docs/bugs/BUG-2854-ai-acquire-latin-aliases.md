## BUG-2854 · AI 下视频只用搜索列表项身份搜资源，漏掉详情里的罗马字/英文名致 Nyaa 0 条
- **报告**：2026-10-02（用户：截图）「AI 下视频」输入「fx战士」→ 已选「FX戦士くるみちゃん」→ 放送中 → 字幕日本語 → 「失败：这部作品没搜到任何资源。」（构建 2.9.0-debug.16720，已含 BUG-2818 修复）。
- **真实性**：✅ 真 bug。实测 nyaa.si（2026-10-02）：`FX Senshi KURUMICHAN` 0 条、`FX戦士くるみちゃん` 0 条、`FX Senshi Kurumi-chan` 17 条、`FX Fighter Kurumi-chan` 9 条。TMDB 搜索列表项的身份只有日文原名 + JP 区风格化别名 `KURUMICHAN`。资源搜索页打开前经 `home_page.dart` `_videoDiscoveryItemWithSearchAliases`（BUG-2794）用 `loadDetails` 把详情的罗马字 / 英文名前置进别名；AI 流程也调了 `loadDetails`，但 `video_acquisition_reducer.dart` `_onDetailsLoaded` 只把 work 存进 `state.work`，`state.reference`（= `chosenItem.reference`，`video_acquisition_models.dart:836`）仍是搜索项那份，`_searchResources` 拿它发 `VideoAcquisitionSearchResourcesEffect` → Nyaa 只查到两个 0 条的拼写 → `filterResourceGroups` 空组 → `no_candidates`。整套路径同病：`video_acquisition_service.dart` `_resolveFranchiseEntry` 只给剧集取详情、且取到后仍用原身份搜，没有拉丁标题的电影条目永远只拿原名去搜。
- **[x] ① 已修复** — `a36c3d48be`：`_onDetailsLoaded` 用与资源页同一判据 `withWorkLatinTitles(work)` 补齐 `chosenItem`（搜资源、下载入队、订阅行都用这份身份）；`_resolveFranchiseEntry` 对剧集或 `!hasLatinTitle` 的条目取详情并用补齐后的身份搜资源，`planFranchiseEntry` 把补齐写回条目（`VideoAcquisitionFranchiseEntry.copyWith` 新增 `item`）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/acquisition/video_acquisition_latin_aliases_test.dart`（以实测形状构造：前提 / 单作品搜资源与提交身份带英文名且 Nyaa 查询词含它 / 无详情原样 / 整套计划写回 / 整套 service 纯日文电影取详情并按补齐身份搜）；变异实测：回退 reducer + service → 3 条红。
- **备注**：修前绕行：发现页 → 资源搜索页手动搜。
