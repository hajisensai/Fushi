## BUG-3502 · 复习牌组列表：父牌组新卡/到期数没按子牌组截断后自底向上汇总
- **报告**：2026-10-16（用户：Windows 截图，牌组树 蓝宝书 → 例文カード{N1..N5} / 文法カード{N1..N5}：例文カード 显示新卡 0、其子 N1..N5 各 50，顶层 蓝宝书 却显示 50；「子卡组都没新卡了，但是父卡组设置了新卡就有明显不合理，anki 好像不是这样的」）
- **真实性**：✅ 真 bug。根因 `packages/fushi_engine/lib/srs/srs_db_store.dart:1212`（upstream/develop 的 `_summarize`）：每个牌组各自拿**整棵子树的原始卡数**去比**自己的**每日上限（`newCount: min(newAvail, max(0, budget.allowed - newDone))`，:1249；到期同理 :1251），子牌组的上限 / 已截断的数从不往上传。于是父牌组的数只受自己的上限约束：子牌组（或中间层）上限已满 / 为 0 时，顶层仍按子树原始卡数显示 50。复习页 `nextCard`（:1357 起）也只看所点牌组的 `sum.newCount > 0`，随后在整棵子树里按创建时刻取新卡，不检查卡所在牌组到所点牌组这一路上各层的上限——点顶层能出的卡数与子牌组行的数字对不上。截图里 例文カード 为 0 是它自己剩余上限为 0（上限 0 或今天子树已学满）的结果，按 Anki v3 也是 0；不合理的是 蓝宝书 在两个子牌组都为 0 时仍显示 50。
- **[x] ① 已修复** — 新增 `_countTree`（对齐 Anki v3 limit tree，rslib scheduler/queue/limits.rs）：每层剩余上限 = 自己的上限（新卡仍经 `srsComputeNewCardBudget` 按复习量缩减）− 今天整棵子树已学 / 已复习量；新卡与到期数自底向上 `min(本层剩余上限, 本层自己的卡 + Σ 子牌组截断后的数)`；学习中不截断、逐层求和；只看所点牌组的子树（点子牌组时祖先上限不参与，与 Anki deck list 一致）。`nextCard` 取复习卡 / 新卡时要求卡所在牌组到所点牌组一路每层都还有剩余上限（层状拟阵，贪心按任何顺序都恰好取到该行显示的数）。顺带：牌组列表改按 `::`→`\x1f` 的先序排序（原先按全名字符串排，「Lang2」会插进「Lang」与「Lang::JP」之间）。提交见本分支 `pr/srs-deck-collapse`。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/srs_deck_tree_counts_test.dart`：三层树、各层不同上限（Root 10 / A 3 / A1·A2 50 / B·B1 20）、已学部分配额（从 A1 学 2 张后 A1=3、A=1、Root=8）、子牌组全 0 时父不再显示新卡、点父 / 点子牌组时实际出卡数 = 该行显示数且各层上限守住、学习中逐层求和不截断。
- **备注**：未实现 Anki「新卡也受复习上限约束」（`new_cards_ignore_review_limit` 默认 false 时新卡上限再与剩余复习上限取小）——Fushi 用自己的「按复习量缩减新卡」预算承担这一角色，没有对应设置。另发现 `srs_anki_package.dart` 新格式预设 `c.intOf(9, 20)`：proto3 里 new_per_day = 0 会被省略、读成 20（旧格式 JSON 正常），未在本条修。
