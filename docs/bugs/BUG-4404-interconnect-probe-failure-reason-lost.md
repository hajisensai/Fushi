## BUG-4404 · 互联能力探测把凭据失效、证书不符、老版本、连不上都折成『没有可用主机』
- **报告**：2026-11-10（用户：互联审查 R9 / R8 / C13 订阅 client）
- **真实性**：✅ 真 bug（代码路径核实；核心断言修复前确认红）。行号指基准 94317ab6295：
  - `fushi/lib/src/sync/interconnect_subscription_client.dart:237`（`statusCode != 200 → null`）与 `:252`（`catch (_) → null`）：订阅能力探测把 401、证书不符、5xx、超时、老 host 全部折成 null，`probeAll()` 只剩「有 / 没有」；`:317-416` 另有一份自带的传输实现（`_tokenForBaseUrl` / `_clientFor`，`fromStream` 不受超时约束，`http.Client()` 无关闭路径），`probeAll()` 按存储顺序逐条探测。
  - `fushi/lib/src/sync/interconnect_download_client.dart:190` / `:213`：代下载能力探测同样折成 null（步骤 7 已把探测换成 outcome，但消费方仍只取 `probeAll()` / `probeUrl()`）。
  - `fushi/lib/src/media/downloads/download_execution_target.dart:70-77`：`probeUrl` 返回 null 或抛异常一律 `DownloadExecutionUnreachable(url, deviceName)`，没有原因字段。
  - 消费方因此只能笼统提示：`home_page.dart:2825`（发现页下载）/ `:2937`（发现页订阅）只看列表空不空就弹「去配置下载后端」；`home_page.dart:3065`、`download_actions.dart:127`、`ctl_download_support.dart` 的 Unreachable 一律「连不上」；`home_page.dart:2937` 的订阅 client 与 `remote_subscriptions_section.dart:54` 的 client 永不关闭。
- **[x] ① 已修复** — `dc30049890c`：
  - `interconnect_subscription_client.dart` 按步骤 7 的方式迁到 `InterconnectHostChannel`：`HostSubscriptionTarget` 加可选 `host` / `hostRef`（client 产出的 target 带 host、`baseUrl` 取持久代表地址）；`probeHost` / `probeAllOutcomes`（并发、保持组序）；`probeAll()` 签名不变；`close()`；错误体沿用 `{message, reason}` 字段；调用方直接构造的老形状 target 按地址在配对清单里认 host。
  - 新文件 `fushi/lib/src/sync/interconnect_host_failure_text.dart`：`interconnectHostFailureText` / `interconnectHostFailureLine` / `interconnectHostFailureWorthTelling` / `interconnectFirstTellableFailureLine`。
  - `download_execution_target.dart`：`DownloadExecutionUnreachable` 加 `failure`（缺省 unreachable）与 `statusCode`，由 `probeHost` 的 outcome 填；本体拆成 `resolveDownloadExecutionFor(url:, repo:, client:)`（`createClient` 测试缝）；`downloadExecutionUnreachableMessage`。
  - 消费方：首页发现页下载 / 订阅在没有可用 host 时先 toast 第一条值得说的原因（authRejected / certificateMismatch / unsupported / notPaired）再走原逻辑，订阅 client 用完关闭；「AI 下视频」、通用磁链（`pushGenericMagnet` 经 `onRemoteUnreachable` 回调交回原因，`genericPushMessage` 与 `anime_download_dialog` 用它）、添加任务对话框、ctl `--device` 缺省解析都说出具体原因；`RemoteSubscriptionsSection` dispose 时关 client，cancelled 在 dispose 路径静默。
