## BUG-4737 · 内置浏览器广告拦截在联网刷新过期列表期间整页失效
- **报告**：2026-11-15（应用内反馈 h4xK2GRAl7，维护者自提：hitomi.la 首页横幅广告与伪通知广告都没被拦）
- **真实性**：✅ 真 bug。本机 `web_adblock/state.json` 显示开关开、四份列表在反馈前一分钟（12:57:07→12:57:12）刚联网重下完、`engine/*.dat` 同秒生成——即那次打开浏览器时列表已过期（>4 天），正在联网刷新。
  根因：`AdblockCore::open`（`native/fushi_web_core/src/adblock/mod.rs:254`，`engine: RwLock::new(None)`）打开时内存引擎是空的，唯一装引擎的入口是联网之后的 `finish_sync`（旧 `mod.rs:497`）；`WebAdblockService.ensureLoaded`（旧 `fushi/lib/src/web_adblock/web_adblock_service.dart:114`）直接 `begin_sync` → 逐份下载 → `finish_sync`，所以列表过期那次，磁盘上明明有可用的 `.dat` 缓存，整个下载期间（数秒）`check` 一律放行、`cosmetic` 一律返回空。逐请求平台的标签页又不等引擎就建 WebView（旧 `fushi/lib/src/web_browser/tab_view/web_browser_tab_view.dart:395` 只有 contentBlockers 平台 await），首页的子资源请求全放行，documentStart 的 cosmetic 引导脚本只取一次、拿到空就再也不取（`fushi/lib/src/web_adblock/web_adblock_wiring.dart:153-154` 唯一一次 `call('fushiAdblockCosmetic')`，`if (!raw) return;`，连通用隐藏的 `startGeneric()`（`:165`）也不再启动）——引擎就绪后这一页也不会补拦。在线视频源页（`fushi/lib/src/pages/implementations/video_fushi/web_source.part.dart`）同一个服务只 `unawaited(ensureLoaded())` 就建 `WebVideoSession`，同一根因。
- **[x] ① 已修复** — 把「把磁盘缓存装进内存」从「联网刷新」里拆出来：Rust 新增 `AdblockCore::load_cached`（`mod.rs:584`，不联网、反序列化 / 按缓存列表编译，借用 `syncing` 互斥）+ C ABI `fwc_adblock_load_cached`；Dart `AdblockCore.loadCachedInBackground`；`WebAdblockService.ensureEngineWarm`（每个服务暖一次、总开关重开时复位，不排在联网同步后面），`ensureLoaded` 先暖机再同步；浏览器标签页与在线视频源页建 WebView 前都 await 暖机（本地反序列化，不等网络）；contentBlockers 平台（iOS / macOS）暖机时已按缓存装好 WebKit 规则列表，只在没有缓存可暖（`contentRuleListIdentifier == null`）时才等联网同步。`setListEnabled` / `updateNow` 也先暖机再联网，暖机不会排到一次未暖的联网同步后面。
- **[x] ② 已加自动化测试** — `native/fushi_web_core/src/adblock/tests.rs`（`load_cached_warms_engine_before_stale_lists_are_refetched`、`load_cached_is_a_no_op_without_cache_or_when_disabled`）；`fushi/test/web_adblock/web_adblock_service_test.dart`（`BUG-4737: cached engine blocks while stale lists are re-fetched`——列表过期、下载卡住期间断言 `check` 拦截且 cosmetic 含站点规则，修复前红；`ensureEngineWarm completes without network when nothing is cached`；`BUG-4737: updateNow / setListEnabled from a cold service does not queue warm-up behind its network sync`——修复前暖机排在联网同步后、红；`BUG-4737: content-blocker warm-up installs the cached rule list without network`）。
- **备注**：未做真机 / 桌面实机复测（hitomi.la 实页）。首装（磁盘上一份缓存都没有）时仍要等首次下载完才有引擎，那之前已打开的页面不会补下发 cosmetic——无缓存可暖，不在本修复范围。反馈里「加订阅列表」属范围变化，未做。
