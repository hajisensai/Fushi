## BUG-4003 · 游戏串流制卡无视主机挖词目标、一律发往 Anki
- **报告**：2026-11-02（用户：samutw，AYN Thor 接收端串流 Windows 主机，制卡提示「The host failed to add the card; check Anki on the host」）
- **真实性**：✅ 真 bug。主机挖词目标是 Fushi 复习（`srs_mining_target_install_default = srs`）、未配 Anki 牌组；AnkiConnect 本身在线。根因 `fushi/lib/src/models/app_model.dart` `createGameStreamMiningAdapter` 用裸 `platformServices.createAnkiRepository()`，不像互联转发 / 浏览器扩展那样走遵守挖词目标的 `hostMiningAnkiRepository`，于是每张串流卡都发往没配置的 Anki 而失败。叠加 `fushi/lib/src/sync/game_stream_mining.dart` 只在 `failureReason` 非空时记日志，后端拒卡（原因在 `MineOutcome.errorDetail`）时主机日志一片空白。
- **[x] ① 已修复** — 适配器改用 `hostMiningAnkiRepository`；后端拒卡时经 BUG-089 的同一诊断入口 `logMineOutcomeDiagnostics`（`error_log_service.dart`，`logMineFailure` 也走它）记进 `GameStream.mine` 日志，原始异常 `MineOutcome.error` 优先、其次 `errorDetail`（分支 `fix/game-stream-mining-target`，审查后移植到 `port/tp-game-stream-mining-target`）。
- **[x] ② 已加自动化测试** — `fushi/test/sync/game_stream_mining_test.dart`（拒卡记日志带原因；只有原始异常、errorDetail 是通用文案时日志里有原始异常）+ `fushi/test/srs/host_mining_target_test.dart`（真 ProviderContainer 装配下 `AppModel.createGameStreamMiningAdapter()` 的仓库：目标=复习时落复习不写 Anki，目标=Anki 时就是本机 Anki 后端；替换了原来的源码子串守卫）。
- **备注**：接收端仍把后端拒卡显示成通用 `host_error` 文案；主机日志现在有真实原因。
