## BUG-4333 · Windows 3.3.0 AXTree 失步复发：父节点列出从未下发的子节点（BUG-4073 未覆盖的来源）
- **报告**：2026-11-10（崩溃报告分诊：`6w4NCIxzoR`、`T--XrKRrZ8`、`lGXdQ_RHiN`，三台不同 Windows 机器，都是 3.3.0+24434——已含 [BUG-4073](BUG-4073-windows-uia-hittest-av.md) 的 0002 / 0003 框架补丁）。
- **真实性**：✅ 真原生崩溃；**框架侧来源未定位**，本条只交付取证。
  - 崩点与 BUG-4073 / [BUG-3796](BUG-3796-windows-nav-switch-freeze-a11y-reparent.md) 同族：`6w4NCIxzoR` 是 `flutter_windows.dll+0x13b23` 同址递归（UIA `HitTestSync` 解引用空 delegate，`flutter_platform_node_delegate_windows.cc:66-75`）；`T--XrKRrZ8` 符号化为 `memmove ← vector::erase ← AccessibilityBridge::CreateRemoveReparentedNodesUpdate`（`accessibility_bridge.cc:249`，`child_ids.erase(end())`）；`lGXdQ_RHiN` 两次 AV 都在 OLEACC / UIAutomationCore 回调里。
  - 三份日志里生产哨兵 `A11y.axTreeDesync` 记到的是**同一个形态**：一帧只下发 2 个（或 33 个）节点，其中某个父节点的 `childrenInTraversalOrder` 多出连续三个从未下发过的新 id——`27872-27874 (child of 8543)`、`5932-5934 (child of 7)`（`page=[HomePage>SrsDeckListPage]`）、`3175-3177 (child of 2170)`（`page=[HomePage>SettingsHomePage]`）。日志里的 `"?"` 是哨兵模型里**没有这几个 id 的数据**（从未下发），不代表框架节点本身没有 label。
  - 框架里「列进父节点、却不下发」只有三条路径（`packages/flutter/lib/src/semantics/semantics.dart`，打过 0001-0003 的 3.47.6）：① `SemanticsOwner.sendSemanticsUpdate` 对「自己 `isPartOfNodeMerging` 且父节点也 `isPartOfNodeMerging`」的脏节点只标父节点脏、`_dirty = false` 不下发（:5064-5070），而父节点只要不是合并根就照样把它列进 `childrenInTraversalOrder`（`_addToUpdate`，:4173）——两边一致的前提是合并标记与父节点一致；② 0001 的 `_isSkippedInHitTestTree` 跳过（:5190）；③ 节点未 attach。头号嫌疑是 ①：`_RenderObjectSemantics._produceSemanticsNode`（`rendering/object.dart:6313`）按 render 侧 `parentData.mergeIntoParent` 直接改 `isMergedIntoParent`，而 setter 不向下递归、`_updateChildMergeFlagRecursively`（`semantics.dart:3218`）在本节点标记已相等时早退——缓存未重建的子孙节点可能留着过期标记，造成「父节点不是合并根、子节点却被当成合并节点压掉」。**未证实**：没有本机复现，现场也取不到框架状态。
  - 复核补充（PR #3158 审查）：上面「只有三条路径」漏了第四条——④ **新节点从未被标脏**：`SemanticsNode` 新建时 `_dirty = false`（`semantics.dart:3346`），只有 `rect` / `transform` 等 setter（:2837、:2856）与 `updateWith` 里注解有变化（:3761）才标脏，`attach` 只在已脏时补登记（:3284）；父节点 `_replaceChildren` 发现新子节点只标父节点自己脏（:3109）。所以一个「注解全是默认值、`rect == Rect.zero`、无 transform」的新节点不会进 `_dirtyNodes`、永不下发，父节点却把它列进子节点——与「只下发父节点等两个节点、父节点多出连续几个新 id」的形态吻合。常规路径上这种零面积节点会在父 fragment 被 `shouldDrop`（`isInvisible`，:2912）滤掉，但 `_mergeSiblingGroup`（`rendering/object.dart:6361-6365`）把 explicit 子节点直接交给 `node.updateWith(childrenInInversePaintOrder: childrenNodes)`、没过 `shouldDrop`；`isMergedIntoParent = true` 的零面积节点也不算 invisible。**同样未证实**；取证里 `rect=0x0@(0,0)` 且无 flags / actions / label 指向 ④，合并标记判定（`!!`）指向 ①。
