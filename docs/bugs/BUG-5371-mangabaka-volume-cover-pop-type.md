## BUG-5371 · mangabaka-volume-cover-pop-type
- **报告**：2026-11-23（用户：Windows 上「在线匹配封面」选 MangaBaka → 点某一卷封面，转圈不停；点取消后背后页面变灰、弹窗仍在）
- **真实性**：✅ 真 bug。不是网络慢（实测 MangaBaka 搜索 0.3 s、卷列表 0.1 s、43 张缩略图并发 1.6 s、单卷原图约 200 KB），是弹窗关不掉：弹窗结果类型是 `BookCoverScrapeSelection`（`(cover, candidate)` 记录，`fushi/lib/src/media/metadata/book_cover_scrape_dialog.dart:112`），而卷封面出口 `_useVolume` 与「使用系列封面」按钮仍是 `Navigator.of(context).pop(file)`（原 `:391`、`:557`）。`pop` 按实参推断类型，编译期不报；运行时 `Route<BookCoverScrapeSelection?>.didPop(File)` 抛类型错误，发生在 try/catch 之外——无 toast、不进错误日志、`_applyingVolume` 不复位，转圈永不结束，导航栈半弹出（取消后背景页消失）。起因：1540ccb4c8（2026-11-15）加卷网格时结果还是 `File`，b376816344（2026-11-16）把结果改成记录时只改了普通候选出口，漏了这两个 MangaBaka 出口。
- **[x] ① 已修复** — 弹窗所有「选中」出口收口到唯一的 `_finish(BookCoverScrapeSelection)`（签名钉死结果类型，再传错类型编译期就报）；卷封面返回 `series.forVolume(cover)`（新增 `BookScrapeCandidate.forVolume`：封面地址 / 卷号取那一卷，简介 / 评分 / 标签 / 背景沿用系列），「使用系列封面」改为复用 `_use(series)`（原来是逐行复制的下载流程）。弹窗加 `downloaderOverride` 供测试注入下载器。
- **[x] ② 已加自动化测试** — `fushi/test/media/metadata/book_cover_scrape_dialog_test.dart`「BUG-5371 点卷封面：弹窗关闭并返回该卷封面 + 系列资料（不卡转圈）」「BUG-5371「使用系列封面」：弹窗关闭并返回系列候选」：经真实路由 `showDialog<BookCoverScrapeSelection>` 打开，断言弹窗关闭、无异常、返回的封面文件与候选（卷封面地址、卷号、系列 id）。把旧 `pop(file)` 放回时前者以 Flutter「type provided to Navigator.pop() is not a subtype」失败。
- **备注**：书架卡菜单（`reader_fushi_history_page.dart` `_scrapeBookItem`）与编辑信息弹窗（`media_item_edit_dialog_page.dart`）两个调用方都受影响，修复后都能拿到卷封面。
