## BUG-4794 · SRS 卡面视频片段加载不了时不落占位，等它播完的复习音频序列永远不返回
- **报告**：2026-11-17（小说 / 漫画 / 视频优化清单复核 gap-vidmisc-7）
- **真实性**：✅ 真 bug（代码路径确证，未在真机上用坏文件复现）。根因 `fushi/lib/src/pages/implementations/srs/srs_card_video_clip.dart:45-74`（修前）：`SrsCardVideoPlayer` 抽象只有 `playingStream` / `completedStream` / `videoSizeStream`，没有错误出口；`_open`（修前 `:445-461`）只在 `player.open` **抛异常**时才落「视频未同步」占位，`_startRun`（修前 `:504-525`）起播后只等 `completedStream` 发 true。而 media_kit 对加载不了的文件（0 字节、没有 moov、认不出格式）既不让 `open` 抛、也不发 `completed`——`completed=true` 只来自 `eof-reached`（`ci/patches/hosted/media_kit-1.2.6/lib/src/player/native/player/real.dart:2204-2218`），错误只进 `errorController`（同文件 `:2372-2407`）。结果：卡面是一块黑框，`SrsCardVideoChannel.playToEnd` / `playToEndOrElse`（无超时）等这段片段播完的那一步永远不返回，后面的音频不播，直到用户手动点一下或翻卡。触发面：同步没传完的媒体、写了一半的片段；尾部截断但还能解码的文件会正常走到结尾，不受影响。
- **[x] ① 已修复**（912ca5eb8c5）— `SrsCardVideoPlayer` 加 `errorStream`（生产实现 = `Player.stream.error`）；卡面片段订阅它，`_onPlayerError` 只在**还没拿到画面尺寸**（`_videoSize == null`）时判加载失败：`_failLoad` 作废进行中的序列播放（等待中的以 false 结束）、释放播放器并撤销登记（之后的序列退回只播音频）、画「视频未同步」占位。已出画面后的错误只记诊断日志——media_kit 的错误流同时带 `vd` / `ad` 解码器的非致命日志，一出错就判失败会误伤能放的片段。`open` 抛异常的旧分支并到同一个 `_failLoad`。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_card_video_clip_test.dart`：「BUG-4794 还没出画面就报错 = 加载失败：序列以 false 结束、落「视频未同步」占位、释放播放器」「BUG-4794 没起序列时报加载错误：同样落占位，之后的序列退回只播音频」「BUG-4794 已出画面后的错误（解码器单帧报错等）不算加载失败：照常播完 = true」（真 widget + 假播放器发错误事件）。
- **备注**：待真机验证——往 SRS 媒体库放一张引用 0 字节 / 截断到没有 moov 的片段的卡，确认卡面落「视频未同步」占位、音频序列继续往下播；再用正常片段确认没有被误判（硬解回退之类的 `error` 级日志若早于画面尺寸到达会被当成加载失败，代码上按 mpv 的属性语义不应发生，没有真机证据）。纯音频、没有画面轨的「片段」永远拿不到画面尺寸，播放中任何一条错误日志都会被判成加载失败；视频制卡产出的片段都带画面轨，不在正常路径上。
