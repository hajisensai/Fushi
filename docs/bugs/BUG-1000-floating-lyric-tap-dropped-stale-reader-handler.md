## BUG-1000 · 桌面悬浮字幕点词后台听书时静默丢弃(reader卸载后channel残留!mounted handler)
- **报告**：2026-07-11（用户：Windows 桌面听有声书时点悬浮字幕条上的词，查词「完全没反应」；时好时坏。用带诊断日志的构建实测确认。）
- **真实性**：✅ 真 bug（生命周期/状态同步）。根因 `hibiki/lib/src/media/audiobook/audiobook_session.dart` 的 `installReaderSurfaces` / `restoreDefaultSurfaces`：二者把 channel 点词 handler 的重接线 `_setupFloatingLyricHandlers()`（内部 `FloatingLyricChannel.setEventHandlers(onLookupText: _onFloatingLyricLookup)`）**门控在 `if (_showFloatingLyric())`**。
  - reader attach 时 `_onFloatingLyricLookup` 被换成 reader 页的 `_lookupFromFloatingLyric`（`lyrics.part.dart:399`，首行 `if (!mounted) return;` 在 `tryFloatingLyricGlobalLookup` 之前）。
  - 用户偏好 `show_floating_lyric=false`（悬浮条经手动 toggle / `showFloatingLyricOverlay` 临时拉起，此路径不受该 pref 门控）。此时退出阅读器 = reader 页 unmount → `detachReader` → `restoreDefaultSurfaces`：`_onFloatingLyricLookup` 虽还原成 app 级默认，但 `if (_showFloatingLyric())` 为假 → **跳过 `_setupFloatingLyricHandlers()`** → `FloatingLyricChannel._onLookupText` 残留为已卸载 reader 的 `_lookupFromFloatingLyric`。
  - 之后每次原生点词 → `_handleNativeCall('lookupText')` → 残留 handler → `if (!mounted) return;` **静默吞掉**（`tryFloatingLyricGlobalLookup`→`GlobalLookupController.lookupText` 永不触发，查词/自动朗读/覆盖窗全无）。诊断日志实测：11 次 `floatlyric: native lookupText recv handlerSet=true` 后**零** `tryFLGL:` / `lookupText:`；修复后每次点词稳定 `tryFLGL→lookupText→showAt`。控制按钮走同一 channel 的 `_handleNativeCall` 但无 mount 门，故按钮一直能用（与「只有点字不行」现象吻合）。
- **[x] ① 已修复** — 提交 <PENDING>。`audiobook_session.dart`：把 `_setupFloatingLyricHandlers()`（channel 点词路由重接线）移出 `installReaderSurfaces` / `restoreDefaultSurfaces` 的 `if (_showFloatingLyric())` 门——handler 接线必须始终反映当前 `_onFloatingLyricLookup`，与偏好开关无关；只有「样式应用」`applyFloatingLyricStyle()` 才门控在条真在显示。app 级默认 handler 无 mount 门（用 session 持有的 AppModel + `tryFloatingLyricGlobalLookup`），故 detach 后点词稳走全局查词覆盖窗。
- **[x] ② 已加自动化测试** — `hibiki/test/media/audiobook/floating_lyric_handler_rewire_test.dart`：构造 `show_floating_lyric=false` 的会话，`installReaderSurfaces` 后经 channel 二进制消息模拟原生点词断言路由到 reader handler、`restoreDefaultSurfaces` 后断言路由到 app 级默认 handler。撤掉重接线（回门控）即红（handler 不接线 → 点词无人消费）。
- **备注**：仅修「点词是否到达查词」这一层（reader 生命周期 / channel 接线）。用户另报的覆盖窗几何（卡片不按 `popup_max_height` 截断、渲染满屏、未锚在词上方；热键/悬浮条通用）是独立问题、由他人在覆盖窗子系统修复，本卷不碰。
