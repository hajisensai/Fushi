## BUG-2902 · 漫画本地 OCR 漏识别：稀疏装饰标题整块没检出、斜体并排两列丢一列
- **报告**：2026-10-02（用户：两张截图「漏掉识别了，修复完提交pr」——横排标题「モテる女子の / オキテ」没有任何框；「パステルカラーで / 女子力アップ♡」点「パ」查出「バス」。用户安装版设置：本地 ONNX + 逐列 CTC 模型 `manga_ctc`）
- **真实性**：✅ 真 bug，两个独立根因。原图在用户机器上找不到（在线源直读），用截图裁出右页、`max(R,G,B)` 洗掉覆盖层后喂真实 Dart 管线（用户安装版同一套模型、FFI ORT）复现：
  1. **标题整块没检出**：页面检测器（comic-text-and-bubble-detector）给「モテる女子の」0.125、「オキテ」0.02 分（洗图后整块 0.057），低于 `TextDetector.scoreThreshold = 0.3`（`packages/fushi_engine/lib/ocr/text_detector.dart`）整块丢掉；同一区域交 PP-OCR 行检测 + 逐列 CTC，两行一字不差。识别没问题，问题在检测器对字距稀疏的装饰字不自信。
  2. **斜体并排两列被并成一列**：行检测正确检出两列（`[449..525]` / `[484..566]`），但字是斜着写的，轴对齐列框横向重叠 41 px（较窄者的 54%）；`mergeOcrLineFragments`（`packages/fushi_engine/lib/ocr/ocr_line_layout.dart`）只看跨轴重叠 ≥ 0.5，把并排两列当「同一列被切断的碎片」合并成一条宽列——覆盖层上一层框包住两列，逐列 CTC 只读出一列（`メステルカラーで` / 生产里是 `バステル…`），「女子力アップ♡」整列丢失。
- **[x] ① 已修复**（提交见 PR）—
  - `ocr_line_layout.dart` `mergeOcrLineFragments`：同列碎片沿阅读方向首尾相接；沿阅读方向重叠超过较短者一半的两段是并排的两列 / 两行，只有跨轴也重叠到 0.8（同一列被检出两次）才合并。修后该块读成 `パステルカラーで` + `女子カアッ…`（第二列个别字错是截图画质）。
  - 补检（新 `packages/fushi_engine/lib/ocr/page_text_sweep.dart` `PpOcrPageTextSweeper`）：检测器加弱档（`kDetWeakScoreThreshold = 0.02`，低于正式阈值的文字框进 `PageDetections.weakTextRegions`，正式结果不变）；流水线识别完正式块后把弱候选交补检器：去掉落在已有块里的 → 按「交叠最深 / 间距最小」聚团（团面积 ≤ 页面 8%）→ 团最高分 ≥ 0.05、按分数花每页 10% 面积预算 → 外扩 0.15 倍短边在原分辨率检行，行被区域截断就沿阅读方向延长（最多两轮）→ 先合并碎片再去振假名、只认碰到本团候选的行 → 逐行识别（竖列转向，同逐列 CTC）→ 平均 CTC 置信度 ≥ 0.85 且日文字 ≥ 2 个、占 ≥ 60% 才收（水印 `DL-Raw.Se` 被挡）。补回的块按全部块重排阅读序。
  - 装配：`manga_ocr_service_impl.dart` 用已有的行检测器 + 逐列 CTC 的漫画 rec 建补检器（不另开会话），经 `runMangaOcrFolderJob(sweeper:)` 进流水线。**只在逐列 CTC 模式下启用**：经典 manga-ocr / Baberu 模式的横排行识别器是通用 PP rec，同一页把「オキテ」以高置信度读成「才半元」，置信度门槛挡不住，这些模式保持原行为。旧缓存只补排版的路径不跑检测器，不补检。
  - 管线版本 `v5-line-geometry` → `v6-weak-text-sweep`（识别文本变了，v5 逐页缓存不复用；已识别的卷要「重新识别本卷」才生效，不会自动重跑）。
  - 实测（真实 Dart 管线 + 用户安装版模型，FFI，机器重负载）：
    - 用户截图页（带覆盖层，最接近生产检测结果）：补回 `モテる女子の` + `オキテ` 与 `モテコーデ`，补检 2.0 秒。
