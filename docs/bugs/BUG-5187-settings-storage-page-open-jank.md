- **报告**：2026-11-22（用户：应用内反馈 2ZkXmroj-C，开发者自报，Windows 3.4.0-debug.31044：打开 设置 › 存储 时界面卡一会）
- **真实性**：✅ 真 bug（附带日志无对应时刻记录；沿真实代码路径定位 + 测量）。开页 `_rescan`（`fushi/lib/src/pages/implementations/storage_usage_view.dart:209`）先在 UI isolate 上取书 / 视频清单：`loadStorageBookRefs` 整行读 `epub_books`（`fushi/lib/src/settings/storage_usage_actions.dart:353` 原 `db.getAllEpubBooks()`），每本带几十 KB 的 `chaptersJson` / `tocJson`；`loadStorageVideoRefs` 整行读 `video_books`（原 `db.allVideoBooks()`，含 `playlistJson` 等几十列）。drift 的 SQL 在后台 isolate 跑，但结果行要整份拷回 UI isolate 解码 + 映射成行对象，而存储页只用 bookKey / title / extractDir 与 uid / title / videoPath。实测（内存库，500 本书 × 约 52 KB 大列 + 1500 条视频）：书清单 200～600 ms、视频清单 30～200 ms，同一份书清单改走瘦投影 `getEpubBookMetas()` 约 27 ms。另：开页并行跑的 `anime4kInstalledBytes`（`fushi/lib/src/media/video/video_shader_downloader.dart`）在 UI isolate 上逐文件 `existsSync` / `lengthSync`。类目目录求和本来就在 `Isolate.run` 里，不是卡点。
- **[x] ① 已修复** — 书清单改读瘦投影 `FushiDatabase.getEpubBookMetas()`；视频清单改读新增的 `FushiDatabase.allVideoBookPaths()`（`selectOnly` 三列，`packages/fushi_core/lib/src/database/database_prefs_media.part.dart`）；`srt_books` / `audiobooks` / 合集表本来就是窄表、音频路径列确实要用，保持整行。`anime4kInstalledBytes` / `deleteAnime4kShaderFiles` 的同步 stat / 删除搬进 `Isolate.run`（只把目录路径字符串送过去）。
- **[x] ② 已加自动化测试** — `fushi/test/storage/storage_usage_main_isolate_io_test.dart`：drift `QueryInterceptor` 记录 SQL，断言书 / 视频清单不读 `chapters_json` / `toc_json` / `source_metadata` / `playlist_json`、`epub_books` / `video_books` 不出现 `SELECT *`，且结果正确；`IOOverrides` 探针把调用方 zone 里的 File / Directory 换成「`*Sync` 即记录并抛」的包装，跑完整类目扫描 + 随包组件 + Anime4K 占用，断言零违规且量到真实字节（另有探针自检用例）。
