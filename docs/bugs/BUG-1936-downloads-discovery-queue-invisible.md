## BUG-1936 · 发现页直链下载（游戏等）提示已加入下载，下载页任务 tab 却不显示
- **报告**：2026-08-29（用户：「游戏的下载，点击以后显示加入下载队列，但是没有」）
- **真实性**：✅ 真 bug。发现页 HTTP 直链条目走 `fushi/lib/src/pages/implementations/media_discovery_page.dart:355`（`appModel.discoveryDownloadQueue.enqueue` → toast `discovery_download_queued`「已加入下载」），而 `DiscoveryDownloadQueue`（`fushi/lib/src/media/discovery/discovery_download_queue.dart`，内存队列、app 生命周期常驻）在整个 app 里**只有**游戏库占位卡（BUG-1911，`games_library_page.dart:125`）在读；下载页任务 tab（`downloads_page.dart:318-330`）只渲染 `MokuroMoeTasksSection`（漫画目录队列）+ `VideoDownloadJobsPanel`（`video_download_jobs` 表）+ 旧 `AnimeDownloadDialog` 番剧计划。全历史 `git log -S discoveryDownloadQueue -- downloads_page.dart` 为空——这条队列从来没接过任务视图。torrent 条目走 `pushGenericMagnet`（落旧计划 JSON，任务 tab 的旧计划区能看到），所以只有 shinnku / AList 这类直链源（游戏为主，也含小说/有声书）中招。
- **[x] ① 已修复** — `2e25d45775`：新增 `fushi/lib/src/media/discovery/discovery_download_tasks_section.dart`（`DiscoveryDownloadTasksSection`，范式同 `MokuroMoeTasksSection`：`ListenableBuilder` 直接监听队列不另存副本；行 = 状态图标 + 标题 + 「域标签 · 状态」副标题，下载中给「已收 / 总 (百分比)」、完成给入库摘要、失败给错误原文；行内取消/重试，头部批量重试/清除已完成；高度策略同 BUG-1184）挂进 `downloads_page.dart` 任务 tab、紧随漫画目录区。发现页私有 `_formatBytes` 提成 `discovery_labels.dart#formatDiscoveryBytes` 两处共用。
- **[x] ② 已加自动化测试** — `fushi/test/media/discovery/discovery_download_tasks_section_test.dart`：接线守卫（`downloads_page.dart` 源码必须含 `const DiscoveryDownloadTasksSection(),` 且在 Mokuro 区之后）+ 空队列不占位 + 真队列驱动（永不完成的 resolver = running / queued；非瞬时错 = failed）断言计数、域标签、状态文案、取消移出、行内重试就地复活同一对象 + 360 宽不溢出 + `discoveryDownloadStatusLabel` / `discoveryDownloadProgress` 纯函数。
