## BUG-669 · YouTube 分离流回放 UA 残缺致 googlevideo tarpit 超时打不开
- **报告**：2026-07-09（用户：谷歌视频打不开 + VIDEO-DIAG 日志）
- **真实性**：✅ 真 bug（代码级根因）。根因 `hibiki/lib/src/media/video/youtube_source_resolver.dart:372`（`httpHeaders: const {'User-Agent': 'Mozilla/5.0'}`）。
  - 现象：libmpv 打开 YouTube ANDROID_VR 分离流（video itag137 + audio-add itag251）两条 `videoplayback` 请求全 `[curl] error: Timeout was reached` 挂死超时（非 403）。
  - 数据流：`resolveYoutubeSource` 用 `youtube_explode` 的 `androidVr` client 铸流；`androidVr` 的 innertube context **不带 userAgent**（youtube_api_client.dart:78-92），故 youtube_explode 全程用其 `YoutubeHttpClient.defaultHeaders['user-agent']`＝**完整 Chrome UA**（`Mozilla/5.0 (Windows NT 10.0; Win64; x64) ... Chrome/96...`）发 innertube player 请求铸出 googlevideo 直链、并对首流做 HEAD 403 探测（stream_client.dart:97，探测通过＝流被选中）。但 Hibiki 把回放 UA 硬编码成**残缺**的裸 `Mozilla/5.0`（非任何真实浏览器会发的完整 UA），经 `resolved.httpHeaders → UrlStreamVideoClient.httpHeaderFields → load() → Media.httpHeaders`（video 主流）+ 全局 `http-header-fields`（audio-add 副音轨继承）下发。googlevideo 的 svpuc 服务端校验对残缺/可疑 UA 往往不是干脆 403 而是**吊住连接（tarpit）**→ libmpv/ffmpeg curl 一路挂到 `network-timeout=30s` 超时。故「HEAD 探测（完整 UA）通过、回放 GET（残缺 UA）超时」这一非对称正是铁证。
  - 同一残缺 UA 还硬编码在制卡 ffmpeg 路径 `desktop_audio_clipper.dart:54`（`-user_agent Mozilla/5.0`）与 `:139`（range 下载 header），注释明写「与 libmpv 侧一致」——同一系统性缺陷。
- **[x] ① 已修复** — 新增单一真相 `kYoutubeStreamReplayUserAgent`（运行时取 `yt.YoutubeHttpClient.defaultHeaders['user-agent']`，兜底完整 Chrome UA），令回放 UA 与 youtube_explode 铸流 UA 一致（yt-dlp 同原则）。三处 googlevideo 回放点（resolver httpHeaders、clipper `-user_agent`、range 下载 header）统一引用。提交 <PENDING>。file:line：`youtube_source_resolver.dart`（常量+`youtubeStreamReplayHeaders()`+line 372 改用 helper）、`desktop_audio_clipper.dart:54/139`。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/youtube_stream_replay_ua_test.dart`：守卫回放 UA＝youtube_explode 铸流 UA、非残缺裸 `Mozilla/5.0`、为完整浏览器 UA（含平台+浏览器 token）；`youtubeStreamReplayHeaders()` 携该 UA；clipper `buildFfmpegRemoteInputArgs` 的 `-user_agent` 值＝同一常量（三处一致性不回归）。
- **备注**：YouTube 是活的外部服务，bg 无法真机验证 live 播放。本修为**代码级根因**（回放 UA 与铸流 UA 的确定性不对称），完整验证需真机重放原始失败视频（ANDROID_VR itag137+251）确认起播出画面出声。若真机仍超时，需继续排查 googlevideo 是否新加 PO Token 门槛（androidVr 需 proof-of-origin），那属外部契约变化、非本仓可单测层。修不破坏既有：完整 Chrome UA 是「浏览器性」严格超集，youtube_explode HEAD 探测已用它并通过，旧能用裸 UA 的流对更完整 UA 只会更宽松。
