## BUG-2629 · 浏览器扩展 YouTube 制卡音频多录下一行——自动字幕滚动双行的 cue 时长跨到下下行
- **报告**：2026-09-22（用户：「浏览器扩展 youtube 制卡时音频还会附带下一行的句子，导致有两行句子的音频被录制但是 anki 只有第一行的句子」）
- **真实性**：✅ 真 bug（沿真实数据 + 代码路径验证，未拿到用户那条视频）。制卡的音频窗就是 cue 窗（`tools/browser-extension/content.js` 的 `fushiMineContext` → `fushiEnqueue` / `bridge-shim.js` 立即制卡 → `fushiClipWindowWithMargin(startV, endV)` ±200ms → 服务端 `resolveYoutubeSource` 按 `clipStartMs/clipEndMs` 用 ffmpeg 裁真实流），句子字段取的是同一条 cue 的文本；所以「字只有一行、声音有两行」= **那条 cue 的 endMs 越过了下一行的 startMs**。用 innertube ANDROID 端点实拉 `dQw4w9WgXcQ` 的 `en (asr)` 轨证实 YouTube 自动字幕就是这个形状（滚动双行显示，每行要停留到被顶出去为止）：`t=18800 d=7160`「We're no strangers to」→ 25960，而下一行「love. You know the rules…」`t=21800` 就开始了，中间只靠一条 `t=21790 a=1` 的 `\n` 追加行截断。
  - `tools/browser-extension/youtube-bridge.js:139` `parseSrv3`：只在「紧随其后那一行的 textContent 恰好是 `\n`」时把时长截到追加行开头；没有追加行的变体（正文行背靠背）不截。
  - `tools/browser-extension/youtube-bridge.js:161` `parseJson3`（srv3 取不到 / 解析为空时的回落路径）：`\n` 事件因文本为空被跳过，`dDurationMs` 原样保留 → 每行 cue 都跨到下下行开头，任何一行制卡都会把下一行整句录进音频。
- **[x] ① 已修复** — `youtube-bridge.js` 新增 `clampRollingCues`：两条解析路径出来的 cue 统一按 startMs 排序后，任何一条的 endMs 不得越过下一条的 startMs（`fetchTrack` 两处出口都过它）。srv3 带 `\n` 行的既有截断结果不变（止于追加行，差 10ms），没有 `\n` 行与 json3 回落路径也收到下一行开始。不重叠的手工轨原样不动。镜像 `fushi/assets/browser_extension/youtube-bridge.js` 已同步。提交见本文件所在修复提交。
- **[x] ② 已加自动化测试** — `tools/browser-extension/youtube-bridge-rolling-cues.test.js`：受控 vm 真加载 `youtube-bridge.js`，用实拉的自动字幕形状分别走 json3 / srv3（带 `\n` 行）/ srv3（无 `\n` 行）取轨，断言发布出去的 cue 两两不重叠、「We're no strangers to」止于 21800（原来 25960）、`[Music]` 等本就不重叠的 cue 时长原样、乱序手工轨只排序不改动。
- **备注**：**未在用户的原始视频上复演**——用户没给视频链接与使用的字幕轨，本轮是「实拉一条自动字幕轨证实形状 + 代码路径推导 + 单测钉死」，按 docs/agent/integration-testing.md 口径算 `implemented_unverified`。若用户那条是 srv3 带 `\n` 行的自动轨（理论上原逻辑已截断），则还有别的来源没查到，请回报视频链接与「字幕列表里选的是哪条轨」再追。
