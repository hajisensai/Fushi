## BUG-2583 · 媒体服务器播放卡顿 / 有时无法重播：无 PlaybackInfo 协商与会话、中继逐请求握手、原生拆建竞态
- **报告**：2026-09-18（用户：「emby 播放好卡而且有时候无法重新播放」，要求参照成熟客户端优化）
- **真实性**：✅ 真 bug（沿真实代码路径定位，四处独立根因）
  1. **中继一请求一握手**：`fushi/lib/src/utils/net/app_native_proxy.dart` `_forward` 对非钉扎上游「每请求 `createAppHttpClient()` + 结束 `close(force: true)`」。libmpv 取流是一串 Range / seek / 缓存回填请求，每个都重新 TCP（https 再加 TLS）握手；128 MiB 预读要靠一连串这样的请求填满，局域网直播放也卡。钉扎分支早为此做了客户端复用（`_pinnedClientFor`），普通分支没有。
  2. **没有起播协商与会话**：`fushi/lib/src/sync/jellyfin_video_client.dart` 手拼 `/Videos/{id}/stream?static=true`，全仓零处 `PlaybackInfo` / `DeviceProfile` / `PlaySessionId` / `/Sessions/Playing`（起播）/ `/Videos/ActiveEncodings`。后果：服务器侧码率限制与用户策略全被绕过，永远全码率直出（远程访问直接卡）；Progress / Stopped 无会话身份，仪表盘看不到本客户端；`DeviceId` 是所有安装共用的常量 `hibiki-app`，两台设备（或同一台退出再进）在服务器眼里互相顶掉会话。
  3. **原生拆建竞态（BUG-2441 触发侧，此前未修）**：`fushi/lib/src/media/video/video_player_controller.dart` `dispose()` 是同步签名，`unawaited(_player?.dispose())` 就返回；退出播放页再进同一集，新页 `Player()` / `VideoController()` 与上一个 Player 的原生拆除在 vendored media_kit 里并发（`third_party/media_kit_video/windows/video_output.cc:131-171` 析构持锁等 promise、`native_video_controller/real.dart:127-128` controller 表按 mpv 句柄地址索引、`angle_surface_manager.cc` 静态 EGL/D3D 拆了重建）→ 第二次 open 失败。
  4. **网络流打不开永远无提示**：`fushi/lib/src/pages/implementations/video_fushi_page.dart` `_promoteVideoReadyOrDiagnose` 对 `videoPath == null`（所有远端流）直接 promote、不做任何「压根没打开」判定；`shouldDiagnoseMediaNeverOpened` 对非本地文件恒 false。于是 3 的失败在 Emby 条目上表现为黑屏 `00:00 / 00:00`、无错误、无重试入口——「有时候无法重新播放」。
- **[x] ① 已修复** — `23fad6468d4`（中继复用）+ `6bfd32e292b`（协商 / 会话 / DeviceId / 画质档 / 拆建串行 / 网络流判死）：
  - 1：中继非钉扎上游按 `scheme://host:port` 复用 `HttpClient`（keep-alive 池），`close()` 统一关；`Host` 头不再照抄给上游（`23fad6468d4`）。
  - 2：`JellyfinApi.playbackInfo`（POST `/Items/{id}/PlaybackInfo` + `buildDeviceProfile`：libmpv 直播放不限容器编码、转码 HLS h264/aac、文本字幕外挂 / 图形字幕烧录、可选码率 + 宽度上限）；`JellyfinVideoClient._negotiatePlayback` 按服务器裁决出直出 URL（带 `PlaySessionId` / `DeviceId`）或 `TranscodingUrl`；兼容层（飞牛等）无该端点（404 / 回 HTML）时**记日志回落**手拼直出（外部系统缺功能的兼容层，影响只限该服务器，服务器补上端点即自动恢复）。会话生命周期新增能力接口 `RemoteVideoPlaybackSession`（`fushi/lib/src/sync/remote_video_client.dart`）：`/Sessions/Playing` 起播、Progress 带 `PlaySessionId` / `MediaSourceId` / `PlayMethod` / `EventName`、暂停 / 继续即时上报（不受 10s 节流）、Stopped 后转码会话 `DELETE /Videos/ActiveEncodings`；同条目会话 FIFO（退出→立刻重开时旧页的 Stopped 不会拿新会话报停）。`DeviceId` 改为 per-install（`SyncRepository.getOrCreateDeviceId`），随 `JellyfinServerConfig` 持久化（令牌与它绑定，旧配置继续用旧常量不逼重登）。画质档：`RemoteVideoQualityLimit` + `JellyfinVideoClient.kQualityPresets`（自动 / 1080p 20 / 1080p 10 / 720p 6 / 720p 3 / 480p 1.5 Mbps），播放页画质菜单第三来源（`video_fushi/quality.part.dart` `_switchMediaServerQuality`：偏好落库 → 关旧会话 → 重新协商起播回到当前位置），偏好键 `video_media_server_quality_preset`。页面 `_startRemotePlaybackSession` / `_syncRemotePlaybackPausedState` 接起播与暂停上报。
  - 3：`VideoPlayerController` 记下上一份原生释放 Future（`_pendingNativeDisposal`），`load()` 建新 Player 前 `awaitPendingNativeDisposal()`（有界 `kNativeDisposalWait` 5s，超时记日志照常放行，不把新页一起卡死）。
  - 4：`shouldDiagnoseMediaNeverOpened` 增 `networkGraceElapsed`；页面对网络流在 promote 后另武装 `_armNetworkOpenDiagnosis`（宽限 = mpv `network-timeout` 30s + 本地档 12.5s，常量 `kMpvNetworkTimeoutSeconds` 从 `video_mpv_config.dart` 导出），用尽仍未打开 → 失败页 + 重试 + 日志，可自愈；新一次 load / dispose 取消。
- **[x] ② 已加自动化测试** — `fushi/test/sync/jellyfin_playback_negotiation_test.dart`（PlaybackInfo 请求体 / DeviceProfile / 直播放 URL 带会话 / 转码 URL / 画质档上限与宽度条件 / 兼容层 404 与 HTML 回落 / Start→Progress→暂停继续→Stopped 全带会话 / 转码 Stopped 后 DELETE ActiveEncodings / 同条目 FIFO / DeviceId 认证头与配置往返）；`fushi/test/utils/net/app_native_proxy_tls_origin_test.dart`（同原点一串请求只建一个上游客户端）；`fushi/test/media/video/video_player_controller_test.dart` 新增「上一个 Player 的原生释放先于下一个建立」3 条（等待 / 无在途 / 有界超时）与 `shouldDiagnoseMediaNeverOpened` 网络宽限真值表；既有 `jellyfin_video_client_test.dart` 的直出 URL 用例改走兼容层回落路径。
