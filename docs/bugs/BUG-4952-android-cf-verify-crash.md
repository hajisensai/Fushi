## BUG-4952 · Android 点「网站验证」主进程立即闪退
- **报告**：2026-11-21（用户：应用内反馈 ckLhL3V7tf，OPPO OPD2409 / Android 16 / 3.3.0，崩溃 x2）
- **真实性**：✅ 真 bug。两次崩溃都在浏览页报 `CLOUDFLARE_CHALLENGE_REQUIRED` 后约 1.5 秒（用户点「网站验证」），`lastLifecycle=inactive` 比崩溃早约 70 ms（验证 Activity 刚盖上来），ExitInfo `reason=CRASH process=app.fushi.reader`（主进程，不是 `:network_challenge`）。根因：`fushi/android/app/src/main/kotlin/app/fushi/reader/mihon/CloudflareChallengeActivity.kt:72` 在验证进程里把匿名 `object : ResultReceiver(main)` 直接 `putParcelable("control", …)` 回发；Parcel 写的是运行时类名 `CloudflareChallengeActivity$onCreate$1`。主进程 `CloudflareChallengeCoordinator.kt:68` 的 `data?.getParcelable("control")` 解这个 Bundle 时没有 app classloader（`ResultReceiver.send` 送来的 Bundle classLoader 为空，退回 boot classloader），找不到该类 → `BadParcelableException` 在主线程 Handler 里抛出 → 主进程崩。该消息在验证 Activity `onCreate` 一开始就发，所以 Android 上每次点验证都会崩，与机型无关。
- **[x] ① 已修复** — 新增 `IpcResultReceiver.kt` 的 `ResultReceiver.forIpc()`：经一次 Parcel 往返换成 `android.os.ResultReceiver` 基类实例（binder 仍指向原对象），跨进程只出现框架类名；协调器 → 验证进程的 `receiver`、验证进程 → 协调器的 `control` 两处都改走 `forIpc()`。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/android_cloudflare_proxy_boundary_test.dart`「ResultReceivers cross process boundaries only as the framework type」：扫描 `android/app/src/main` 下所有 Kotlin/Java，凡 `putExtra` / `putParcelable` 传出 `object : ResultReceiver` 声明的变量或内联匿名对象而未 `.forIpc()` 即红，并要求至少命中两处已包装的发送点防空守卫。
- **备注**：JVM 单测里 `android.os.Parcel` 是 not-mocked 桩、仓库没有 Robolectric / androidTest，Parcel 往返行为本身只能真机验证；按本轮约定未做真机复测（缺口：在 Android 上对需 Cloudflare 验证的 Mihon 源点「网站验证」确认不再闪退）。
