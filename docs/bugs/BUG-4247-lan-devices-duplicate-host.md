## BUG-4247 · 互联「局域网设备」列表把同一台 host 列两遍，配对后红屏 `_dependents.isEmpty`
- **报告**：2026-11-08（用户：Android 模拟器端到端跑互联配对，配对后红屏）
- **真实性**：✅ 真 bug。错误日志里红屏前反复出现 `Duplicate keys found`（building FushiGroupedList，`Column has multiple children with key [<[<'https://<host>:38765'>]>]`），随后路由切换时 `InheritedElement.debugDeactivated` 断言 `_dependents.isEmpty`、`Duplicate GlobalKeys`（Overlay 的 `_OverlayEntryWidgetState`）、`Looking up a deactivated widget's ancestor is unsafe`。BUG-4220（对话框释放调用方的 TextEditingController）的修复已在出事构建里，不是同一机制。
  - 根因 `fushi/lib/src/sync/lan_discovery_service.dart:303`（修复前 :302，resolved 分支 `_discoveredDevices[device.deviceId] = device`）：发现结果以 TXT `id`（缺失时回落 service name）为键，而这个键对同一台 host 并不稳定——host 换了 deviceId / 以新实例名重新注册、旧记录的 lost 事件没到，或某次 resolve 丢了 TXT 回落成 name 键——于是同一个 `host:port` 存成两条。
  - 列表行 `fushi/lib/src/sync/sync_settings_schema/interconnect.part.dart:2169` 以 `ValueKey(device.webDavUrl)` 为键（`FushiGroupedList` 再包一层 `ValueKey<Key?>`），两条同 URL 的设备 → 同级重复 LocalKey；重复键下 `updateChildren` 的结果未定义，元素树被弄坏，配对后路由切换停用子树时就撞上 `_dependents.isEmpty`。
- **[x] ① 已修复** — 数据层保证「一个 `host:port` 只有一条」：resolved 时 `_evictSupersededBy` 先删掉同一 service name 之前登记的旧键条目、以及同一 endpoint 的其它条目，并去掉指向被删条目 / 指向本条目的其它 name 映射（旧实例名迟到的 lost 不会删掉活着的条目）。一个 `host:port` 同时只可能有一个服务在监听，最新一次 resolve 拥有它；发现结果的 `deviceId` 在 UI 不参与任何逻辑，配对全程按 URL 走。
- **[x] ② 已加自动化测试** — `fushi/test/sync/lan_discovery_dedupe_test.dart`：数据层（丢 TXT 的重复 resolve、换实例名重注册、同名不同 id、被取代名的 lost 不删活条目、不同 host / 端口仍分开）+ widget 层（按生产同样的键把列表建出来，第二条同 endpoint 记录到来后无 `Duplicate keys` 异常、只剩一行）。
- **备注**：Android 模拟器（x86_64 debug）复测：PC 上用 zeroconf 广播两条 `_fushi-sync._tcp` 记录（不同实例名 / 不同 `id`、同一 `host:port`、都带 `tls=1`），不需要真 host、不需要配对。修复前的构建：进「互联 → 配对与设备」，局域网设备区直接红屏 `Duplicate keys found`（键 `https://<ip>:<port>`），返回再进再返回时出现 `_dependents.isEmpty`（与原始日志同一条链）。修复后的构建：同一页只列一行、停 20 s 不变，进出页面多次，error_log 里没有新的 FlutterError。
