## BUG-751 · 剪贴板半透明面板顶部按钮(制卡/音频/收藏)几乎不可见
- **报告**：2026-07-11（用户：「我没看见制卡按钮」+「顶上的几个按钮太难看清了，感觉和完全透明一样」）
- **真实性**：✅ 真 bug。不是没渲染——`popup.js createEntryHeader` 对每个词条恒渲 `.mine-button`（+ `.audio-button`/`.favorite-button`）。根因是**对比度**：`popup.css:236-246` 这三个头部按钮静息 `opacity:0.5` + `background:transparent` + `color:inherit`。app 内弹窗卡背景实心，0.5 仍清晰；但**剪贴板面板是半透明的**（整窗 `WS_EX_LAYERED`+`LWA_ALPHA` ≈0.85–0.95 叠上卡片 `cardBgAlpha`=`clipboardPanelOpacity`），0.5 的字形逐层相乘后有效不透明度≈0.4，叠在透出游戏画面的半透明卡上→近乎不可见，用户读成「没有按钮/全透明」。两外部查词面（剪贴板面板 + 瞬态窗）都带 `<html class="global-lookup">`。
- **[x] ① 已修复** — `hibiki/assets/popup/popup.css`：新增 scoped 规则把 `html.global-lookup` 下**可点**的三个头部按钮提到 `opacity:1`（与正文一样清晰）。`:not(:disabled)` 保留禁用态 0.15；只覆写 opacity 不动颜色，故金色收藏 `.favorited` / 绿色 ✓↩ `.latest` 特例色不变。app 内弹窗无 `.global-lookup` 类→保持低调 0.5，零回归。`generate-content-css.mjs` 整条丢弃 `html.global-lookup` 选择器（扩展 `#entries-container` 永不带该类）→不进扩展 content.css。popup.css 三副本（源 + 扩展 vendor ×2）已同步字节一致（md5 `e374e57a…`）。提交：分支 worktree-bug751-panel-button-opacity（PR 见下）
- **[x] ② 已加自动化测试** — `hibiki/test/lookup/global_lookup_button_visibility_guard_test.dart`：①源码守卫 popup.css 三个 `html.global-lookup .X-button:not(:disabled)` 规则存在且整体 `opacity:1`；②反向守卫两份扩展 content.css **不含**该 global-lookup 专属规则（证明生成器正确丢弃）。TODO-1267 三副本字节 parity 守卫仍绿。像素级「按钮在半透明面板上清晰可见」需可见窗真机目视。提交：分支 worktree-bug751-panel-button-opacity（PR 见下）
