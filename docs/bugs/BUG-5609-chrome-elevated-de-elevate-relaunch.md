## BUG-5609 · 提权 shell 下真 Chrome 测试秒退：Chrome 降权自重启，spawn 的进程 exit 0
- **报告**：2026-11-28（用户：本机 Windows 上 `test/reader/continuous_*`、`srs_card_*`、`srs_defs_illustration_chrome` 在 develop 基线也红，报 `chrome exited before DevTools was ready`）
- **真实性**：✅ 真 bug。本机复现：`dart tool/heavy.dart -- flutter test test/srs/srs_card_clamp_toggle_test.dart --no-pub` → exit 1，`Error: chrome exited before DevTools was ready (code 0, signal null, after 67ms) (chrome wrote no stderr)`。根因在各处 Chrome 启动参数表，CDP 驱动是 `tool/reader_pitch_headless/cdp_client.mjs:418`（`launchChromeDriver` 的 `spawn`，`resolveChrome` 在 `:18`，退出判定在 `waitForDevToolsPort` `:284` / `:309`）；`--dump-dom` 型启动点在 `fushi/test/srs/srs_defs_illustration_chrome_test.dart:65` 等 9 个测试文件与 `tools/browser-extension/embedded-frame-lookup.test.js`。
  - 证据：本机 Chrome 158.0.8127.37（`C:/Program Files/Google/Chrome/Application/chrome.exe`），agent shell 是管理员令牌（`whoami /groups` → `High Mandatory Level`）。直接用驱动的参数起 Chrome（加 `--enable-logging=stderr --v=1`）：60 ms 内 exit 0、stderr 一个字都没有；但临时 profile 仍被占用，`Win32_Process` 里能找到一个新的浏览器进程，命令行就是原参数后面多了 `--noerrdialogs --no-first-run --do-not-de-elevate`，父进程不是我们——这是 Chrome 检测到提权后经 shell 降权自重启。重启出来的进程 stderr 不再接到我们的管道，`DevTools listening on ws://…` 永远等不到，而且它成了孤儿。对照：同样参数只加 `--do-not-de-elevate`，189 ms 打出 `DevTools listening on ws://127.0.0.1:17689/…`。`--headless` / `--headless=new` / `--headless=old` 三种都一样，与 headless 模式、版本号、沙箱、用户数据目录无关。
  - CI 为什么不受影响：GitHub Windows runner 以关了 UAC 的管理员账户运行，进程没有拆分令牌（没有可降到的受限令牌），Chrome 不走降权重启；Linux / macOS 没有这条路径；这些测试在 CI 上一直绿即是实证。所以只有「本机开了 UAC、agent 以管理员跑」时红。
- **[x] ① 已修复** — 所有真 Chrome 启动点（`cdp_client.mjs`、`srs_card_autoplay_gate_harness.mjs`、8 个 `--dump-dom` / `--screenshot` 型 Dart 测试、浏览器扩展的 node 测试）紧挨 headless 参数加 `--do-not-de-elevate`（Chrome 给自己的重启加的就是这个，非 Windows / 未提权时是 no-op）。本机环境不用改。
- **[x] ② 已加自动化测试** — `fushi/test/build/chrome_launch_do_not_de_elevate_guard_test.dart`：扫 `fushi/test`、`tool/`、`tools/` 下的 `.dart/.mjs/.js/.cjs`，凡出现 headless 启动参数字面量的文件，`--do-not-de-elevate` 参数字面量个数必须不少于它（带扫描规模哨兵 ≥10 个文件）。提权行为本身在 CI 上造不出来，守卫是能落地的最强一层。
- **备注**：排查经验写进 `docs/agent/fast-workflow.md`「并发伪红判别」。清孤儿浏览器只按命令行里自己的临时 profile 路径找 PID，不按名字杀 `chrome.exe`。
