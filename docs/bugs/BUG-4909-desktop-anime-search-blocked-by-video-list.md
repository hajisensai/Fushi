## BUG-4909 · 桌面端动画在线源面板被同扩展的慢取流卡住数分钟
- **报告**：2026-11-20（应用内反馈 igLsy_gcWz，macOS 3.4.0-debug.29190）
- **真实性**：✅ 真 bug。用户实测 sidecar 日志：Anikoto 一次 `getVideoList` 跑了 5 分 2 秒（hoster 403 → WebView 回退逐个 30 s 超时），期间详情页「在线源」面板发出的 `getSearchAnime` 在 sidecar 里排到它结束才开始，App 侧已 `BRIDGE_TIMEOUT` 4 次；无阻塞时同一搜索约 0.3 s。
  根因：`third_party/m_extension_server/upstream_src/server/src/main/kotlin/mextensionserver/impl/ExtensionInstanceCache.kt:40` 每个缓存的扩展实例只有一把 `invocationLock`，`DalvikHandler` / `SourceImageHandler` / `SourceDataHandler` 的所有调用都在这把锁下串行——几秒级的目录查询（搜索 / 详情 / 封面）被分钟级的取流整段堵住。上游加锁的理由是保护来源对象上的分页游标等目录状态，取流调用只拿传入的那一集，不碰这些状态；Android 宿主（`MihonChannelHandler` 共享 2 线程池、无按来源锁）本来就让同一来源的调用并发。
- **[x] ① 已修复** — 锁粒度改成「按调用通道」：overlay 版 `ExtensionInstanceCache` 引入 `InvocationLane`（`CATALOGUE` / `PLAYBACK`，`getVideoList` 与 `getPageList` 走 `PLAYBACK`），每个实例每个通道一把锁，同通道仍串行（分页游标照旧受保护），跨通道可并行；`SourceDataHandler` 清偏好 / cookie 走 `invokeExclusively`，等两条通道都空再动。`DalvikHandler` 按 `dataBody.method` 选通道。改动在 overlay（`ExtensionInstanceCache.kt` / `MExtensionServerLoader.kt` / `DalvikHandler.kt` / `SourceDataHandler.kt`），`UPSTREAM` / `NOTICE` 同步记录。
- **[x] ② 已加自动化测试** — `third_party/m_extension_server/overlay/server/src/test/kotlin/mextensionserver/impl/ExtensionInstanceCacheTest.kt`：取流通道被占住时同实例的目录调用 2 s 内完成；独占调用等在途取流结束；方法到通道的映射；原有同通道串行 / 实例复用 / 失败不缓存用例保留。`fushi/test/build/mihon_vendored_server_guard_test.dart` 把三份新 overlay 加进「覆盖上游已有文件」清单。
- **备注**：反馈里另一半——面板等所有来源都回来才一次性出结果（`fushi/lib/src/media/video/discovery/video_work_acquisition_backends.dart` `searchVideoAcquisitionTargets`），改成按来源逐个出结果属于面板交互改变，未在本修复里动，交拍板。真机复测未做（桌面 sidecar 慢取流场景需能稳定复现 403 + WebView 回退的扩展）。
