## BUG-3730 · 从 Anki 迁移 / 导入不带新卡位置，新卡按笔记创建时刻出、丢了 Anki 里排好的顺序
- **报告**：2026-10-23（来源：用户反馈「lapis 的排序也没有继承，刷了几张新卡，都是我很久以前看高木同学制的十几万词频的词」；srs_followup_tasks A）
- **现象**：迁移后新卡不按 Anki 里的顺序出（用户在 Anki 里按词频重排过），而是最早建的笔记先出。
- **真实性**：✅ 真 bug。用用户本机 Anki 集合副本复现：
  - 导入后 11737 张可见新卡没有一张带 `new_position`。
  - Lapis 牌组的 1189 张新卡按旧规则出卡，前 50 张里只有 5 张和 Anki 的前 50 张相同。
- **根因**：`packages/fushi_engine/lib/srs/apkg/srs_apkg_import.dart` 导入排程时没有读 Anki 新卡的 `due`（新卡序号；在筛选牌组里时原值在 `odue`），所以卡片没有 `newPos`。`nextCard` 对没排过的新卡按（笔记创建时刻, cardId）出。
  - 词频排序本身是通的：`frequencyRankOf` 取显示值的前导数字，「㋕」后缀、「2857, 252030」这类多值都能取到 2857。「按词频重排新卡」写的就是这个 `newPos`。
- **[x] ① 已修复**：
  - 含排程导入时，来源新卡的序号写成 `newPos`：新建卡随卡片草稿一起落库；旧 Lapis 迁到 Fushi 卡片时，新卡按血统继承这个位置。
  - 补救已迁移用户：本机已有、从没排过位置的新卡补上来源位置（`SrsImportReport.newPositionsRepaired`）。被换成别的卡的旧卡（隐藏的前身），补到继承它的可见卡上。本机排过的不覆盖。
  - 笔记在本机换过类型（旧 Lapis 已迁成 Fushi 卡片）时，导入照旧记为「笔记类型冲突」、不动内容与日志，但新卡位置照样补。
  - 用户集合实测：Lapis 牌组 1189 张新卡的出卡顺序与 Anki 完全一致。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/apkg/srs_apkg_import_test.dart`「从 Anki 迁移的复习数据与新卡顺序」组：
  - 新卡按 Anki 位置出，而不是按创建时刻；
  - 旧版迁移结果（无位置、换过笔记类型）再迁一次补上位置，第二次不再写。
- **备注**：已迁移的用户要重新跑一次「从 Anki 迁移」才会补上位置。笔记按「较新时更新」不会被覆盖，复习日志按稳定 ID 不会重复写。
