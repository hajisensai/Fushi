## BUG-3930 · gal-lookup-card-middle-button-and-left-click-leak
- **报告**：2026-11-01（用户：应用内反馈 -AynHxzwNe、3-hTDB25CZ（日志），魔法使之夜 Steam 版 / HUNEX 引擎）
- **真实性**：✅ 真 bug（沿代码路径确认，两层）：① `fushi/windows/runner/low_level_mouse_hook.cpp` `HookProc`：落在登记覆盖窗口（游戏内查词卡 / hook 台词浮窗 / 穿透工具条）上的按键只有左键会发布 v19 护盾请求（`BeginOverlayClickShieldTransaction` 只挂在 `WM_LBUTTONDOWN`），中键 / 侧键原样放行——查词卡是 WS_EX_NOACTIVATE 置顶窗，游戏仍是前台，HUNEX 等采样型引擎每帧 `GetAsyncKeyState` 读到物理中键就快进；② 左键「偶发」穿透：`fushi/windows/runner/voice_hook_reader.cpp` `TryPublishOverlayClickShieldTransaction`（:2348）用 `try_lock` 抢 reader 的 `st.mutex`，而这把锁在 PCM 抓取（GrabRecent/GrabClipNear/GrabUtterance）、写查词帧、PollText 期间整段持有——恰好在卡片刚弹出 / 正在拉音频时点击，发布失败按 fail-open 放行，左键被引擎看见
- **[x] ① 已修复** — 中键 / X1 / X2：LL 钩子在 `g_target` 闸门之前对落在登记覆盖窗口上的 down 直接吞掉（记入 `g_swallowed_buttons`，配对 up 同样吞），并以客户区坐标把 down/up 改投给该点的我方窗口（`OverlayButtonRelayWindowAt` / `PostRelayedButton`），卡片自己的中键 / 侧键行为不变。被 LL 钩子吞掉的事件不进任何输入队列、不更新异步键态，对消息型、GetAsyncKeyState、RawInput 读法同时生效，所以不需要扩 IPC 位、也不需要改 HUNEX 注入侧（左键仍走 v19 护盾，因为左键要真正落到卡片 WebView 上）。右键刻意不吞：卡片的原生右键菜单需要真实右键到达 WebView2。左键竞态：映射生命周期改由独立的 `SRWLOCK mapping_lifetime`（Open 赋 header / CloseLocked 解映射时独占），覆盖窗口事务发布只取共享锁（`MappingLifetimeShared`），不再与 PCM / 查词帧 / PollText 争 `st.mutex`。分支 fix/feedback-galgame
- **[x] ② 已加自动化测试** — `fushi/test/lookup/gal_overlay_click_shield_guard_test.dart` 新组「中键 / 侧键改投与键盘护盾」：锁住改投在 `g_target` 闸门之前、down 吞掉时记位、up 成对改投、左 / 右键不进改投槽（源码守卫；系统级 WH_MOUSE_LL 与真实游戏在单测里伪造不了）
