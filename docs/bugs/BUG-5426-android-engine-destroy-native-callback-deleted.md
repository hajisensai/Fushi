## BUG-5426 · Android 退出界面后引擎被销毁，原生线程回调已删的 NativeCallable 整进程 SIGABRT
- **报告**：2026-11-25（应用内反馈 Wgbo462Sfc：Android 3.3.0，OnePlus PKG110 / Android 16。`onTrimMemory` BACKGROUND / UI_HIDDEN 后约 1 秒 `CRASH_NATIVE status=6`，abort 信息 `runtime_entry.cc: 5380: error: Callback invoked after it has been deleted.`，tombstone 只有主线程 Looper 栈、没有出事线程栈）
- **真实性**：✅ 真 bug（沿依赖与 Flutter 源码确认路径，未在真机复现）。`fushi/android/app/src/main/java/app/fushi/reader/MainActivity.java:66` 继承 `AudioServiceActivity`，主引擎是 audio_service 缓存的引擎（`pubspec.lock` 解析为 audio_service 0.18.18）。根页返回 → `FlutterActivity.finish` → `AudioServicePlugin.onDetachedFromActivity`（`AudioServicePlugin.java:350-363`）断开 MediaBrowser → 没在前台播放时 `AudioService.onDestroy` → `disposeFlutterEngine`（`:116-130`、`:828-829`）`flutterEngine.destroy()`：主 isolate 关闭，VM 删掉它所有 `NativeCallable` 跳板。进程（缓存进程、前台服务）和原生侧都还活着：没 dispose 的 media_kit 播放器（发布构建每个注册一个 `NativeCallable.listener` 当 libmpv 唤醒回调，pub cache `media_kit-1.2.6/lib/src/player/native/core/initializer_native_callable.dart:50-55`）、进程级 Rust 引擎音频分析 / 漫画超分（`native/fushi_compute/src/music_analysis.rs` `emit`、`upscale.rs` `emit`，回调由 `packages/fushi_compute/lib/src/music_analysis/fushi_compute_music_analysis.dart:232`、`upscale/fushi_compute_upscale.dart:276` 的 `NativeCallable.listener` 交给它们）。它们的线程下一次回调就落进已删的跳板 → VM `FATAL` → SIGABRT，出事线程是 mpv / Rust 工作线程，所以 trace 摘要里只有主线程。销毁由 Java 同步完成，Dart 收到的 `detached` 是排队消息、跑不到，所以 BUG-4730 那种「Dart 侧先摘回调」在这条路径上没有可挂的同步点。与 BUG-3003（热重启）、BUG-4730（macOS 退出）同一机制：原生回调持有者活得比注册它的 isolate 久。
- **[x] ① 已修复** — 不再把 Dart 函数指针交给活得比 isolate 久的原生代码，原生 → Dart 的异步事件一律投 Dart 原生端口：`Dart_PostCObject` 任意线程可调，端口随 isolate 关闭后只返回 false，不会 abort。新模块 `native/fushi_compute/src/dart_port.rs`（`Dart_CObject` 的 kNull / kInt64 / kArray 布局 + `DartPort`）；`ffc_mana_start` / `ffc_upscale_start` 改收 `(post, port)`（Dart 传 `NativeApi.postCObject` 与 `RawReceivePort` 的 `nativePort`），事件改投 `[kind, token(, value)]`，ABI 升 v4。libmpv 只收 `void(*)(void*)`，所以 fushi_compute 新增常驻的唤醒跳板 `ffc_port_signal_new` / `ffc_port_signal_fire` / `ffc_port_signal_free`；media_kit 覆盖补丁新增 `lib/native_wakeup.dart` 的 `installMpvPortWakeup`，`InitializerNativeCallable.create` 装了它就用「跳板 + 端口」代替 `NativeCallable.listener`（dispose 在 `mpv_set_wakeup_callback(NULL)` 之后释放目标，`quiesceForProcessExit` 两种句柄都摘）。app 在 `main.dart` 紧跟 `MediaKit.ensureInitialized()` 调 `installFushiMpvPortWakeup()`（`fushi/lib/src/platform/mpv_port_wakeup.dart`）。修的是机制本身，所以 Android 引擎销毁、热重启、桌面退出都不再依赖「来得及先摘回调」；BUG-4730 的退出摘回调保留（对端口方式同样有效）。
- **[x] ② 已加自动化测试** — Rust：`dart_port::tests`（布局、投递、已关端口返回 false 不崩、唤醒目标），`music_analysis::tests::engine_runs_queue_and_reports_events` 先接已关端口跑一首再换端口，`upscale` 测试改用端口收事件并断言没给投递函数时拒绝启动。Dart（真原生库）：`packages/fushi_compute/test/dart_port_test.dart` 让目标 isolate 真的退出后再唤醒 100 次、别的 isolate 启动音频分析后退出再让工作线程投事件——退回函数指针回调时测试进程会直接 abort。真 libmpv：`fushi/test/third_party/media_kit_hot_restart_test.dart` 新增 `port` 模式（探针 `fixtures/media_kit_isolate_exit_probe.dart`）：装 app 的端口唤醒、**不摘回调**就杀掉 owner isolate，再 wakeup / quit；同一流程换成 `NativeCallable`（不摘）就是 BUG-4730 记录的 `Callback invoked after it has been deleted` 崩溃。结构守卫 `fushi/test/platform/native_event_port_guard_test.dart`：`main.dart` 必须在 `MediaKit.ensureInitialized()` 之后装 `installFushiMpvPortWakeup()`（不装时 media_kit 静默回落 `NativeCallable`、功能测试照绿），fushi_compute 的 Rust 导出不得再有 `extern "C" fn` 回调形参 / 别名（`PostCObject` 除外）、Dart 绑定不得再建 `NativeCallable` / `Pointer.fromFunction`。
- **备注**：真机未复测（需要 Android 设备走「根页返回 → 服务解绑销毁引擎 → 原生回调」）。依赖里另有 `pdfrx_engine` 用 `NativeCallable.listener` 做 PDFium 文件读写回调（只在文档操作进行中被调），`flutter_local_notifications_windows` 只在 Windows；本修复未动它们。旧引擎被销毁后没 dispose 的 mpv 句柄仍然泄漏到进程结束（只是不再崩），新 Activity 起的是新引擎，不会接管它们。
