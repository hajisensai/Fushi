## BUG-710 · 字体路径自愈测试硬编码Windows分隔符在Linux CI挂(Release APK阻断)
- **报告**：2026-07-10（用户：报「apk编译失败」）
- **真实性**：✅ 真 bug（测试 bug，非生产代码 bug）。「Build Release APK」workflow 的 `Run unit tests (main app)` step 连续 failure（+624 `156b8793a`、+625 `44041323b`），失败测试 `hibiki/test/reader/font_path_relocation_test.dart`：
  - line 54 `relocateMissingFontCatalogPaths relocates a missing path onto the same-basename file in the new dir` → Expected:<1> Actual:<0>
  - line 170 `relocateMissingFontListPaths relocates missing shadow-list paths and keeps other fields` → Expected:<1> Actual:<0>
  - 根因 `file:line`：`hibiki/test/reader/font_path_relocation_test.dart:37` 与 `:161`（修复前）——两例把期望路径 `newPath` **硬编码成 Windows 风格** `r'D:\data\documents\custom_fonts\Klee_1.ttf'`，并塞进 fake filesystem `existsIn({newPath})`。
  - 被测 helper `hibiki/lib/src/reader/font_catalog.dart` 的 `_relocatedFontPath`（约 line 300）用 `p.join(currentFontsDir, fontPathBasename(rawPath))` 构造候选路径；`package:path` 的 `p.join` 用**宿主平台分隔符**。Windows CI/本地用 `\` → 候选 == 硬编码 newPath → `fileExists(candidate)` true → relocated 1（本地 10658 全过）。Linux/Android CI 用 `/` → 候选 `D:\data\documents\custom_fonts/Klee_1.ttf` ≠ 硬编码 `\` 风格 newPath → `fileExists(candidate)` false → relocated 0 → Expected 1 Actual 0。
  - 复现证据（真跑，最小 path-only 项目）：`p.windows.join(newDir,base)=D:\data\documents\custom_fonts\Klee_1.ttf match=true`；`p.posix.join(newDir,base)=D:\data\documents\custom_fonts/Klee_1.ttf match=false`。
  - **注意**：生产代码 `_relocatedFontPath` / `relocateMissingFontCatalogPaths` 正确、无需改。真机上 `currentFontsDir` 永远来自 path_provider 的宿主原生分隔符，`p.join` 也用宿主原生分隔符，两者永远一致；`fontPathBasename` 同时切 `/` 和 `\`，连跨平台 profile 导入路径也能恢复。故 TODO-1393 字体自愈在 Android 上**是生效的**，本 bug 不影响生产功能，仅阻断 Release APK CI 的单元测试 step（从 TODO-1393 落地 +621 起一直红）。
