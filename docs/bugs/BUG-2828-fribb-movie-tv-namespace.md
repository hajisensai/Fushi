## BUG-2828 · 剧场版的 Fribb TMDB tv id 被当成 movie id 拉取，TMDB 补充绑成无关电影
- **报告**：2026-10-01（用户：视频首页「1 部作品还没确认身份」，リズと青い鳥 被刮成挪威电影）
- **真实性**：✅ 真 bug。Fribb 对挂在电视剧特典季下的剧场版给出 `type: MOVIE` + `themoviedb_id: {tv: N}`（实测 715 行；リズと青い鳥 = anidb 13491 → tv 62564 吹响！上低音号），而 `anime_identity_mapping.dart:52` 的 `isMovie` 把「作品形态」和「TMDB id 所在命名空间」混成一个布尔，`anime_offline_identity_resolver.dart` / `video_source_scrape_coordinator.dart` 的 `_planAnidbGroup` / `_tmdbLookupFromMapping` / `_resolvedFromOffline` 据此拼 `/movie/62564`，命中同号的无关电影（tt1650407）并覆盖 NFO。另：`_tmdbSupplement` 在 AniDB HTTP 详情不可用（主源无年份）时年份门整个放行，同名异片只凭标题即判精确命中。连带问题：挂起原因只落一段「需要人工确认」，事后分不出分支、看不出 AI 问没问。
- **[x] ① 已修复** — `e0188aea20`：`AnimeIdentityMappingEntry.tmdbMediaKind` / `tmdbIdFor(kind)` 把命名空间与形态分开，所有拼 TMDB lookup 的地方只认它；`_tmdbSupplement` 主源无年份时用本地目录 / NFO 年份。`8370d04203`：挂起原因结构化标记 `pending:<cause> ai=<outcome> candidates=N key=…`（`video_scrape_pending_note.dart`），运行记录详情与待确认清单显示「原因 · AI 结果」，无记录显示「尚无刮削记录」。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/anime_identity_mapping_test.dart`、`fushi/test/media/video/metadata/anime_offline_identity_resolver_test.dart`、`fushi/test/media/video/metadata/offline_identity_coordinator_test.dart`（从不拉 `/movie/<tv id>`、年份门用本地年份）、`fushi/test/media/video/metadata/video_scrape_pending_note_test.dart`、`video_source_scrape_coordinator_test.dart`「挂起原因」五条、`video_library_scrape_sweep_test.dart`、`fushi/test/pages/video_task_center_ui_test.dart`；均做过变异实测（回退修复即红）。
- **备注**：已被错绑的存量作品（如 リズと青い鳥 work 75：tmdb 62564 / imdb tt1650407）需在修复版里手动重刮一次才会改绑到正确的 tmdb movie 482150 / tt7089878。AniDB HTTP 302（client 未登记）另走 BUG-2623 的 HTTP/UDP 身份拆分。
