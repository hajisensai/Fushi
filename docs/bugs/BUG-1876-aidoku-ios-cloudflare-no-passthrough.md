## BUG-1876 · iOS Aidoku 源遇 Cloudflare 挑战无过盾能力只报 JsonParseError
- **报告**：2026-08-25（用户：）
- **真实性**：✅ 真 bug。iPhone 上打开 Aidoku 的 MangaFire 源报 `AidokuRuntimeException(RUNTIME_FAILED): Aidoku source returned error code -1: Error: JsonParseError(Error("expected value", line: 1, column: 1))`。本机 curl `mangafire.to/filter?...` 实测 `403` + `Cf-Mitigated: challenge` + `Server: cloudflare`，返回的是 Cloudflare 挑战页 HTML，源按 JSON 解析必炸。根因两层：① iOS 的 Aidoku wasm host 是 Rust `reqwest` 直发（`native/aidoku_runtime/src/embedded.rs:733` 改前的 `send_request`，改前每请求 `reqwest::blocking::Client::builder().build()`）：默认 UA 是 `Aidoku/1 CFNetwork/...`、**无 cookie jar、每个请求新建 Client、`js.webview_*` 全部硬编码 -1**——`cf_clearance` 无处落地，结构上永远过不了盾；Android 端 Mihon 有 `CloudflareInterceptor`（WebView 解题 + CookieJar + UA 对齐），iOS 侧无等价物。② host 对非 2xx 响应零日志，CF 识别（`is_cloudflare_challenge`，8-15 加的，用户包 v2.1.1 是 8-14 的、不含）一旦漏判就只剩一句 `JsonParseError`。
- **[x] ① 已修复** — `91e5076a6c`。Rust host：reqwest 加 `cookies` feature；请求 JSON 新增 `network:{userAgent, cookies[]}`（`NetworkSession`），`HostState` 持有**一次调用共享**的 Client（cookie jar + 调用方 UA），CF 命中时记录被挑战的 URL 并以结构化 `CloudflareChallenge` 错误穿透到 `error_response`，信封带 `challengeUrl`；每次网络往返进 `net_log`（去 query，截尾 12 条）附在 `error code -1` 类错误后面。Swift：`FlutterError.details` 透传整个错误信封。Dart：新 `aidoku_network_session.dart`（`kAidokuUserAgent` 单一身份 + 文件持久化 `AidokuCookieJar` + `AidokuCloudflareGate`）；`IosAidokuRuntime` 每次调用附 `network`，收到 `CLOUDFLARE_CHALLENGE`+https `challengeUrl` 时调 resolver 解题后**重试一次**；`aidoku_cloudflare_challenge_page.dart` 用**同一 UA** 的 `InAppWebView` 加载挑战页、轮询 `cf_clearance` 落到 WKHTTPCookieStore 后整站 cookie 回存 jar；图片下载改用同一 UA 并带 jar cookie；`main.dart` 启动时装 resolver。
- **[x] ② 已加自动化测试** — Rust `embedded.rs` tests：`network_session_is_optional_and_defaults_to_no_cookies` / `network_session_takes_the_caller_identity_and_cookies` / `cloudflare_error_keeps_its_challenge_url_through_context_layers` / `network_log_keeps_a_bounded_tail_and_strips_query_tokens`（`cargo test --no-default-features --features embedded`）；Dart `fushi/test/media/manga/aidoku_network_session_test.dart`（域匹配 / 持久化 / 按站替换 / 过期 / 坏文件）+ `fushi/test/media/manga/aidoku_runtime_cloudflare_test.dart`（每次调用带身份与 cookie、挑战→解题→带新 cookie 重试一次、拒绝解题不重试、二次挑战不循环、全局 gate 回退、非 https challengeUrl 不开 resolver）。
- **备注**：未在 iOS 真机/模拟器上跑过端到端（本机是 Windows，Rust 侧只做了 Windows 主机编译+单测；远程 Mac 构建 iOS 需重编 `build_aidoku_runtime.sh` 的 staticlib）。已知边界：macOS 的 `DesktopAidokuRuntime` 是另一套 host（aidoku-test-runner），本轮未接 cookie/UA。
- **审查修复（合入前 code review，8 条 CONFIRMED 全修）**：① 过盾页判据改为「`cf_clearance` 值 ≠ jar 现存条目」——WebView 共享 cookie 存储里的陈旧 cookie 不再被秒判成功；② 持久化成功后才置完成态/停轮询，失败下轮重试、关闭按钮始终可退出；③ `AidokuCookieJar.ensureLoaded` 失败不再被 `??=` 备忘（一次启动期 IO 抖动曾会毒化所有 iOS Aidoku 调用直到重启），非 UTF-8 文件按空 jar 降级；④ resolver 按 host 单飞去重，并发扇出同站只弹一页，重试前先比对 jar 的 clearance 值、已被并发解掉就静默重试；⑤ pop 前查 `ModalRoute.isCurrent`，关闭过渡期的轮询不再误弹下层页面；⑥ 后台流（全局搜索 6 路扇出、发现页自动匹配）走 `AidokuCloudflareGate.runSuppressed`，被拦只按 `CLOUDFLARE_CHALLENGE` 码分类成徽标，不再无操作弹全屏 WebView；⑦ 挑战信封带 `challengeUserAgent`（被拦请求实际发出的 UA，源可自设），解题 WebView 用它而非固定默认 UA——对齐上游 Mihon 的 per-request UA 解题，消除「源自设 UA 永远过不了盾」边界；⑧ Rust host 的 HTTP client 惰性构建，`inspect` 不再白付构建成本。测试补齐于 `aidoku_cloudflare_challenge_page_test.dart`（新）/ `aidoku_runtime_cloudflare_test.dart` / `aidoku_network_session_test.dart` / Rust `cloudflare_envelope_carries_the_effective_user_agent_only_when_known`。
