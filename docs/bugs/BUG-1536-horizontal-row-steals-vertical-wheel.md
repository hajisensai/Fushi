## BUG-1536 · 视频首页横滚行抢走整页纵向滚动（应 Shift+滚轮才横滚）
- **报告**：2026-08-11（用户：「视频主页的横向滚动要按住 shift+滚轮才行。不然会把上下滚动行为抢走。包括其他系列也要这样改」）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/utils/misc/platform_utils.dart:128`（`WheelToHorizontalScroll`）被用在**嵌于纵向滚动页面**的横滚行上：`fushi/lib/src/pages/implementations/home_video_page.dart:3121`（`_buildHorizontalCardRow`，继续观看 / 接着看 / 最近添加三行共用）与 `fushi/lib/src/pages/implementations/collection_relations_section.dart:295`（合集详情页「相关作品」）。该件把滚轮的 `dy` 投到横轴并向 `PointerSignalResolver` 登记，只要横向内容还有余量就一直登记，指针停在行上时外层 `CustomScrollView` 永远拿不到滚轮 → 整页纵滚被这一行吃掉。
- **[x] ① 已修复** — 撤掉这两处的 `WheelToHorizontalScroll`（BUG-1214 引入时只考虑了「横滚行裸滚轮没反应」，没考虑它嵌在纵滚页面里的代价）。撤掉后：未按 Shift 时横向 `Scrollable` 只取 `scrollDelta.dx`（物理滚轮恒 0）→ 不登记 → 滚轮冒泡给外层纵滚；按住 Shift 时 Flutter 内建对物理鼠标翻轴（`ScrollBehavior.pointerAxisModifiers` 默认 Shift，见 SDK `scrollable.dart` 的 `_pointerSignalEventDelta`）→ 横滚，无需自有代码。鼠标拖动横滚（`HorizontalDragScrollable`）与触屏行为不变。`WheelToHorizontalScroll` 保留给**外面没有纵滚可抢**的横向面板（字幕波形对轴弹窗的时间轴，BUG-1214 的原始诉求），其文档补了「什么时候不要用」。
- **[x] ② 已加自动化测试** — `fushi/test/pages/collection_relations_section_test.dart`：把本区放进真的能纵滚的页面后钉两条行为——裸滚轮 → 横向 `pixels == 0` 且外层纵向 `pixels > 0`；Shift + 滚轮 → 横向 `pixels > 0` 且外层不动（前置断言两个方向都有滚动余量，防假绿）。变异实测：把 `WheelToHorizontalScroll` 包回去，第一条即红。源码守卫 `fushi/test/pages/unified_collections_architecture_guard_test.dart` 由「横滚行必须包桥件」反转为「不得包桥件」。
- **备注**：与 BUG-1214 是同一处代码的两种诉求，边界定在「该横向区外面有没有纵向滚动可抢」。
