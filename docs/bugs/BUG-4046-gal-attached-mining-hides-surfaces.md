## BUG-4046 · 游戏制卡期间查词卡消失、点不了别的词、hook 文本不更新；制卡后主界面打不开
- **报告**：2026-11-03（应用内反馈 U9k4hlYaNZ「游戏制卡卡顿且界面消失」：制卡慢；制卡未完成时不能点其它单词查询，hook 文本卡住不更新；制完卡后 Fushi 主界面打不开，只有任务栏在。未附日志、截图）
- **真实性**：反馈里四个症状拆开验：
  1. **「制卡未完成时不能点别的词 / hook 文本卡住」——✅ 真 bug（attached 表面路径）**。attached（游戏文字上的 1/255 alpha 字形捕获窗）点词打开的桌面查词卡，制卡时把 `_acquireAttachedMiningCaptureLease` 作为 capture lease 传给协调器（改前 `fushi/lib/src/lookup/gal_hook_text_overlay_controller.dart:2643`）。这把 lease 先 `GalAttachedTextController.acquireMiningCaptureLease`（`gal_attached_text_controller.dart:1858`：native 隐藏字形表面、状态转 suspended，期间点击不再命中；`_pushLatestTextIfActive` `:2150` 起把新台词压到 release 才同步），再 `GlobalLookupChannel.suspendForCapture`（`windows/runner/global_lookup_window.cpp:2092`：`ShowWindow(hwnd_, SW_HIDE)` 藏掉查词卡）。动图模式下 lease 包住整个采样循环，时长未定时最坏 8 s（`galgame_window_gif.dart` `kGalAnimatedMaxDuration`，原注释自己写着「已知代价」）。这两个表面都是独立顶层 HWND（字形窗 `attached_text_surface_window.cpp:1516` `WS_POPUP`；查词卡是 `GlobalLookupWindow`），而游戏截图只走按窗口的捕获（`window_capture.cpp:1851` `CaptureWindowPng`：WGC `CreateForWindow` → PrintWindow → Magpie 呈现窗），BUG-2922 的独立探针已实测 owned 顶层弹窗不会进 `CreateForWindow` 帧——这把 lease 是不必要的屏障，BUG-2922 当时在备注里点名留下了这条路径未改。台词浮窗点词打开的是同一张桌面查词卡，从不传 lease，截图里也从没出现过卡片，是同一判据的对照。
  2. **「下一张卡要等上一张卡做完」——✅ 真 bug，同批 BUG-4045**（整张卡一个串行作业）。
  3. **「制卡慢」——部分是设计行为**：整句音频要等语音播完（引擎 PCM 收敛）、动图按整句时长采样（≤ 8 s）、ffmpeg 编码。BUG-4045 之后这些不再挡下一张卡的采样，但单张卡的端到端时长本身不变。
  4. **「制完卡后主界面打不开，只有任务栏」——❌ 未复现 / 根因未定位**：无日志无截图。沿代码查过制卡链上所有窗口操作：capture lease 只 `SW_HIDE` 查词卡 / 字形表面，release 只 `SW_SHOWNOACTIVATE` 恢复它们自己（`global_lookup_window.cpp:2129`），整条制卡链没有任何对主窗的 hide / minimize；窗口截图在独立线程（`flutter_window.cpp:3908`）、回包走 UI 定时器，不阻塞平台线程。没有证据能把它归到某一行代码，**不硬改**。需要用户下次出现时在「设置 → 反馈」附带日志（`ErrorLogService` 的 `gal-click` / `lookup hide` / `captureWindowGifBytes` 记录）与主窗所在显示器 / 是否全屏信息再查。
- **[x] ① 已修复**（症状 1）— 提交 `f53e2ca643`。attached 点词入口 `_onAttachedLookupText`（`gal_hook_text_overlay_controller.dart:2629-2652`）制卡不再带 capture lease：查词卡留在屏上、字形表面照常接点击、新台词实时同步。`_acquireAttachedMiningCaptureLease` 只剩校准样本截图在用（`_acquireCalibrationCaptureLease`），那条未改。游戏内查词卡（hook 画在游戏渲染树里的位图卡与词高亮）那把 lease 是必要的，保留。
- **[x] ② 已加自动化测试** — `fushi/test/lookup/gal_attached_capture_suppression_contract_test.dart`：「attached mining does not suspend the attached surfaces」源码守卫（`_onAttachedLookupText` 体内不得出现 `captureLeaseFactory`，全文件不得再把 `_acquireAttachedMiningCaptureLease` 当制卡 lease 传）；原有的 fence 顺序 / 补偿恢复守卫改挂到校准路径上继续生效。`gal_attached_text_controller_test.dart`、`gal_ingame_lookup_contract_test.dart` 同批 123 个测试 exit 0。只能做到源码守卫这一层：`GalHookTextOverlayController` 依赖 native 通道与真实 hook 会话，无法在单测里构造出 attached 命中 → 制卡的行为链。
