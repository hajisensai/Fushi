## BUG-3606 · 竖排引号方向不一致（有的竖有的横）
- **报告**：2026-10-19 应用内反馈 #mTof77pMTe（Android 华为 XYAO-W00 / HarmonyOS 4.2：更新到最新版后仍然有的引号纵向、有的横向）；同一用户 10-10 反馈 #vbsmSBAx5q 的截图是同一现象
- **真实性**：✅ 真 bug。两张截图都是**正文阅读器**竖排：「」是横排字形（┌ ┘），。、落在字格左下（横排位置），而同页 ー、…… 是竖的。竖排 `text-orientation: mixed` 下，UAX #50 里 Tu / Tr 类标点（「」、。（）等）由 Blink 保持直立、靠字体的 OpenType `vert` / `vrt2` 换成竖排字形；**提供该字符的字体没有 `vert` 时 Blink 不退回旋转，直接画横排字形**（Gecko 会旋转）。ー …… —— 走旋转、与字体无关，所以总是竖的——同一页方向混杂。正文字体链 `fushi/lib/src/reader/reader_content_styles.dart:515`（`_bodyFontFamily`）把标点完全交给用户字体 / 书自带字体 / 系统回退字体，其中任一款缺 `vert` 就出这个现象。本机 Chromium 实测：带 `vert` 的字体在阅读器全部排版选项（mixed / upright、vpal、kerning、悬挂标点、两端对齐、字重）下都正确出竖排「，故不是阅读器 CSS 关掉了 `vert`。上一次修复 BUG-3281（`9880325ff1`）只改了歌词模式的回退链（拉丁系统字体打头），没有覆盖正文；具体是用户哪款字体缺 `vert` 无法从截图 / 日志确定。
