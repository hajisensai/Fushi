## BUG-3855 · Windows 应用内浏览器点网页会把焦点抢回 Flutter，YouTube 设置菜单的二级项打不开
- **报告**：2026-10-28（用户：Windows 版应用内浏览器打开 YouTube 视频页，齿轮菜单能开，带「>」的音轨 / 字幕 / 休眠定时器 / 播放速度 / 画质点了打不开；普通 Chrome 正常）
- **真实性**：✅ 真 bug，真 app 复现（Windows 离屏 runner，Flutter 层 mouse 指针经真实 `SendMouseInput` 链路）。根因 `packages/flutter_inappwebview_windows/lib/src/in_app_webview/custom_platform_view.dart:601-608`（修复前）：`onPointerDown` 在 `!_focusNode.hasFocus` 时 `_focusNode.requestFocus()`，50 ms 后再补一次。
  - 链路：WebView2 收到 LEFT_BUTTON_DOWN 自己 SetFocus 到 Chromium 子窗 → Flutter 视图 WM_KILLFOCUS → 引擎报 `ViewFocusState.unfocused`，框架把焦点停到根作用域（Flutter 3.47 `widgets/view.dart` `_ViewState.didChangeViewFocus`）。下一次点网页时上面那行让 View 作用域重新得焦 → `_scopeFocusChangeListener` 发 `requestViewFocusChange(focused)` → 引擎 SetFocus 回 Flutter 视图，与 Chromium 来回抢。
  - 证据（`fushi/.codex-test/windows-itest/ytprobe3/yt-probe.log`）：齿轮那一下 Flutter 主焦点还在 WebView 节点上，没有抢夺，菜单正常打开；随后视图焦点事件 `unfocused`，主焦点落到 `Root Focus Scope`。点「字幕」这一下出现 7 次 `focused/unfocused` 交替（viewFocus #2–#8），页内捕获到 mousedown 后约 50 ms 的 `window blur` + 菜单项 `focusout`（ytprobe2 的事件记录），YouTube 的弹层随之关闭：click 已送达、子面板 `ytp-panel-animate-forward` 已挂上，20–40 ms 后整个 `.ytp-settings-menu` 变 `display:none`、`activeElement` 回到 BODY。Playwright Chromium 同样的鼠标序列（`D:\temp-user\ytprobe\chromeseq.out`）没有这次 blur，子菜单「画质」正常打开。排除了点击未送达 / 坐标漂移 / 缺 hover / pointerType / buttons 异常 / 纹理未刷新（down/up/click 齐全、isTrusted、坐标一致；CDP 截图与合成帧一致）。
- **[x] ① 已修复** — 删掉 `onPointerDown` 里的 `requestFocus` 与 50 ms 重试：点进网页时键盘就归 WebView2（与浏览器一致，app 快捷键本来就走宿主页的键盘桥），Flutter 侧焦点由引擎的 view focus 事件自然停到根作用域，不再与 Chromium 抢。差异记在 `packages/flutter_inappwebview_windows/PATCHES.md`。
- **[x] ② 已加自动化测试** — `packages/flutter_inappwebview_windows/test/pointer_down_view_focus_test.dart`：模拟引擎报 unfocused 后再点 WebView，断言框架没有向引擎发 `ViewFocusState.focused` 请求（`testFocusEvents`，即会变成原生 SetFocus 的那一条）、焦点仍停根作用域、按下 / 抬起照常转发 native；换回旧实现时该测试红（Expected empty, Actual 有 focused 请求）。真 app 诊断探针 `fushi/integration_test/web_browser_youtube_menu_probe_itest.dart`（联网，打开 YouTube 逐个点二级项）：修复前四个二级项全部 FAIL，修复后（`ytprobe4`）字幕 / 休眠定时器 / 播放速度 / 画质四个子菜单都打开，截图 `yt-05-item-6-flutter.png` 可见画质子菜单。
- **备注**：同一探针还碰到另一个问题，本条未修：首次打开 YouTube 时页面会改址到 `&themeRefresh=1`，被中止的首个主框架导航以 `Indicates that the connection was stopped.` 报 `onReceivedError`，app 的「无法连接到该网站」失败页就盖在已加载成功的新文档上并吞掉所有指针（ytprobe1 / 2 / 4 出现，ytprobe3 没出现）。修复前探针先把这层失败页清掉才继续取证。该现象需另开 bug。用户真实桌面输入（真鼠标 WM_* 到 Flutter 视图）未在本机复测，结论基于同一转发链路的 Flutter 层指针。
