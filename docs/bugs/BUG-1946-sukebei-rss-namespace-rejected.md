## BUG-1946 · Sukebei 发现源结果恒空：NyaaClient 严格解析硬编码 nyaa.si 命名空间，sukebei RSS 的 sukebei.nyaa.si/xmlns/nyaa 被判 invalidNamespace
- **报告**：2026-08-29（用户：「接入 sukebei 有问题 全是空的」）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/media/torrent/nyaa_client.dart:13`（旧）`const String _nyaaNamespace = 'https://nyaa.si/xmlns/nyaa'`，`_parseNyaaDocumentStrict` → `requiredNyaaField('infoHash')` 用 `element.name.namespaceUri != _nyaaNamespace` 做精确比对。上游 nyaa 软件把 RSS 命名空间拼成 `<站点 origin>/xmlns/nyaa`（实抓 2026-08-29：`https://sukebei.nyaa.si/?page=rss&c=1_3` 根元素 `xmlns:nyaa="https://sukebei.nyaa.si/xmlns/nyaa"`，75 条 item），所以 sukebei 首屏每一条 item 都在 `nyaa:infoHash` 上抛 `NyaaFeedFormatException(invalidNamespace)`，`NyaaDiscoverySource.search` 整次失败，游戏发现页 Sukebei 源恒空。nyaa.si 本站不受影响，因此之前没暴露。翻页（HTML `?p=N`）路径不看命名空间，本来就能过。
- **[x] ① 已修复** — 命名空间判据从「== 硬编码 nyaa.si」改成「http(s) 且路径 == `/xmlns/nyaa`」（`isNyaaNamespace`），nyaa.si / sukebei.nyaa.si / 镜像站一条规则覆盖；`https://invalid.example/ns`、路径不同的仍判 invalidNamespace。所有 `nyaa:` 扩展字段（seeders/size/categoryId/trusted/remake）统一走 `_nyaaChildText`，不再按硬编码命名空间取值。提交：见本分支。
- **[x] ② 已加自动化测试** — `fushi/test/torrent/nyaa_client_test.dart`「BUG-1946：sukebei / 镜像站 <site>/xmlns/nyaa 命名空间被接受，路径不同才拒」（4 个接受 + 4 个拒绝命名空间矩阵 + `isNyaaNamespace` 边界）；`fushi/test/media/discovery/sources/nyaa_discovery_source_test.dart`「BUG-1946：Sukebei 源用站点自身命名空间的 RSS 也能产出条目」（原始失败路径：sukebei 形状 RSS → `DiscoveryResourceItem`）。修复前两条均红（invalidNamespace），修复后绿。另用真实抓包（RSS 首屏 75 条 + HTML 第 2 页 75 条）一次性喂 `NyaaClient` 验证通过，抓包不入库。
- **备注**：`test/torrent/nyaa_client_test.dart` 里「真实本地 HTTP」用例本地服务器 baseUrl 是 `127.0.0.1` 但声明 nyaa.si 命名空间——所以判据**不能**从 `baseUrl` 推导（镜像/反代也会转发源站命名空间），只能按路径判。
