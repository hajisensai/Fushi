## BUG-1525 · 浏览器侧边栏查词存在可感知延迟
- **报告**：2026-08-11（用户：）
- **真实性**：✅ 真 bug。旧版 650ms 固定等待虽已移除，但真实热路径仍有四层额外成本：`tools/browser-extension/side-panel.js` 用自定义抽屉并重复解析 `popupJson`；`tools/browser-extension/background.js:cfg()` 每次查词都读扩展存储；旧 `_AppModelRemoteLookupService.searchDictionary` 会把同一份 FFI 结果先构造成每 glossary 一条的完整 `DictionaryEntry.extra`，再第二遍生成 `popupJson`；`content.js:fushiRender` 还强制回流并等待 200ms opacity 动画。真实本机 API 冷查询约 100–300ms，复杂结果可达 0.8–1.23 MB。
- **[x] ① 已修复** — 改为 Yomitan 式主动扫描：Side Panel 的 Shadow host 随面板常驻，按下 Shift 立即复用最后指针位置；相同词复用在途 Promise 与已解析 LRU，cue 准备继续并行。连接配置在 service worker 内缓存并随 storage 变更失效；`popupOnly && !record` 走可选 `FushiRemotePopupLookupService`，直接从完整缓存或原始 FFI 缓存生成 `popupJson + bestLength`，跳过 `buildResultFromLookup/buildLookupEntryExtra`，并由 DictionaryRepository 的 8 MB 紧凑 LRU 统一随词典变更失效。完整查询、同步与写历史仍走兼容旧路径。Side Panel 与主界面 Shift 弹框都去掉 200ms 强制淡入；`popup.js` 首词条只同步建立第一个可见词典块就撤掉加载层，首条余块与后续词条均按“每宏任务一个词典块”渐进补齐，旧代结果可取消。Side Panel 的解析结果缓存也从 48 条无界大对象改为 12 条/8 MiB 原始 JSON 估算双门槛，避免连续查询复杂词后因堆膨胀触发秒级 GC。提交：本提交。
- **[x] ② 已加自动化测试** — `tools/browser-extension/side-panel-performance.test.js` 守卫常驻 Shadow host、Shift keydown 即查、在途/LRU 复用、配置缓存失效、无 200ms fade 与逐词条 yield；`fushi/test/sync/browser_extension_lookup_cache_guard_test.dart` 守卫远端查询命中 AppModel 缓存且不共享可变滚动位置。按用户要求本轮跳过执行自动化测试。提交：本提交。
- **[x] ③ 已加真实链路性能日志** — service worker 为每次 lookup 分配随机关联 ID，用同一时钟域的 epoch 区分扩展唤醒/派发、localhost 请求和大响应交付；持久记录请求开始、1/3 秒仍在等待时的当前阶段、配置读取、响应头、响应体、外层 JSON 解析及错误。服务端通过 `Server-Timing` 继续拆分规范化、popup/full/FFI 三级缓存、原生 FFI 查询、`popupJson` 构造、响应 map 与最终 `jsonEncode`，并回报真实缓存来源。网页弹框和原生 Side Panel 再记录内层 JSON 解析、词条数、首词条 DOM、尾批完成/取消，以及容器显示后的下一帧；失败诊断有 750ms 上限，不会反过来把查词请求永久挂住。最近 80 个阶段只保存在 `chrome.storage.local`，仅记录词长、不记录原始查词内容；扩展设置页“查词性能日志”可刷新、复制完整 JSON 或可靠清空。日志 IPC 被推迟到首条渲染之后，不进入同步首显关键路径。提交：本提交。
- **备注**：`YomitanApiServer` 只是 localhost API 外壳，并未调用外部 Yomitan 服务；实际词典查询已经在 Fushi 进程内直达 FushiDicts/HoshiDicts。MV3 无法直接加载本地 DLL；Native Messaging/WASM 会引入浏览器注册、1 MB 消息分块或整套词典复制及第二份引擎状态，不能解决大结果的解析与 DOM 成本，因此保留 localhost 单一词典状态。Yomitan 的 `text-scanner.js` 在修饰键按下时复用最后指针事件直接搜索；`popup.js`/`display.js` 复用既有 popup surface，并让后续词条逐项让出事件循环。
