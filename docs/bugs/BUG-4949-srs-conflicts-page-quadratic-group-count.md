## BUG-4949 · iOS 同步冲突页扣住的删除上万条时 build 占住主线程数秒，被看门狗 0x8BADF00D 杀掉
- **报告**：2026-11-21（应用内反馈 3sGnx0FYRr，同设备另见 jpAhsYUXLG；iPhone14,8 / iOS 27.2 / 3.3.0-debug.28434）
- **真实性**：✅ 真 bug。三次 `RBSTerminateContext 0x8BADF00D「Failed to terminate gracefully after 5.0s」`（WatchdogVisibility=Background）的崩溃线程用 `ios-dart-symbols-testflight-28434`（build id `7d114500…`，`llvm-symbolizer`）还原后**全部**停在 `_SrsConflictsPageState._sameCount` → `_heldGroup` 的字符串插值（`fushi/lib/src/pages/implementations/srs/srs_conflicts_page.dart:341-345` 旧行号），调用方是 `_buildBody` 里给每条扣住的删除卡片算 `sameCount`（旧 :714）。根因：`_sameCount` 每次都对 `_held` / `_conflicts` 整表 `where(...).length`，而 `_buildBody` 对每条卡片各调一次 → 每次 build O(N²)。该设备 SRS 库 2.1 GB、`read:conflict_edits` 19 万行，扣住的删除数以万计，一次 build 就是上亿次插值；Flutter 3.29+ iOS 的 UI 与平台线程合并，Dart 占住的就是主线程，系统要求退出时 5 秒内收不到响应即杀进程。
  - 分诊里「workmanager 后台周期任务拉起进程跑互联同步」不成立：日志的线程名 `dev.fluttercommunity.workmanager.BackgroundPeriodicTask.N.ui` 与另一进程里的 `io.flutter.1.ui` 是同一个 tid（8813488256，主线程），只是合并线程模式下主线程被最后建的引擎改了名；那几条 `runOnAuthenticatedSyncChannels(interconnect=true)` 是主引擎前台的推送（`SrsLocalPush._run → SrsAppRuntime._push`，栈已还原），失败原因是 host 不可达，与看门狗无关。
- **[x] ① 已修复** — 组条数是加载结果的派生状态：新增 `srsCountByGroup`，`_load` 里对 `_conflicts` 的 `group` 与扣住删除的 `held/<kind>` 一趟数完存进 `_sameCounts`，与列表在同一个 `setState` 里换；`_sameCount` 只查表。build 从 O(N²) 降到 O(N)。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_conflicts_group_count_test.dart`：计数正确；2 万条用计数 Iterable 断言只遍历一趟；守卫 `_sameCount` / `_buildBody` 里不再出现 `.where(`。
- **备注**：没在 iOS 真机复测（真机验证按本机规则不做）。页面仍一次性构建全部卡片的 widget 对象（O(N)，每次 build 上万个轻量对象），加载阶段 `_entityLabel` 对每条扣住的删除各读一次库（日志里 `read:cards 13271x`）；这两处是线性开销、不在三份崩溃栈上，未改。
