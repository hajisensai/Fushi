## BUG-5189 · shortcut-inline-record-esc-pops-page
- **报告**：2026-11-22（应用内反馈 KhJG0swJKT，开发者自报，Windows 3.4.0-debug.31044）：设置 › 快捷键 › 视频，在某个动作上开始行内录制（「按下新的组合键… Esc 取消」），按 Esc 整页被退出，没有取消录制。
- **真实性**：✅ 真 bug（widget 测试复现）。触发条件：开着「键盘 / 手柄焦点导航」（`FushiFocusRoot` 启用）+ 桌面鼠标。录制条 `_InlineRecorder` 挂在整行 `FushiListItem` 的 `FushiFocusTarget` 子树里；录制中鼠标在行内任何位置（含录制条本身）按下，`FushiFocusTarget._handleMousePointerDown`（`fushi/lib/src/focus/fushi_focus_target.dart:209`）无条件 `requestById(行)`，把主焦点从录制器（`shortcut-record`）拽回整行。之后的 Esc 不再经过录制器的 `_onRecordKey`（`shortcut_browser.part.dart:526` 的取消分支），冒泡到 `wrapWithGlobalNavigation` 的 `_handleGlobalBack`（`global_navigation.dart:414` `nav.maybePop()`），整页被弹出；其它键同理冒泡到全局快捷键而不是录进录制器。焦点导航关着时没有 click-to-focus Listener，不复现。
- **[x] ① 已修复** — `FushiFocusTarget` 的鼠标 click-to-focus 在焦点已落在本目标**子孙**上时不改焦点（`node.hasFocus && !node.hasPrimaryFocus` 直接返回）：子孙此刻是键盘所有者，点击就落在它所在的这块里。通用修复，卡片里的输入框等同类子孙焦点一并不再被外层目标抢走；不在全局返回里特判。
- **[x] ② 已加自动化测试** — `fushi/test/shortcuts/shortcut_inline_record_esc_test.dart`（真实层级：`wrapWithGlobalNavigation` + 启用的 `FushiFocusRoot` + push 出的设置路由；鼠标点行开始录制 → 点录制条 → 断言主焦点是 `shortcut-record`；Esc 后路由仍在、录制器消失、绑定未改；J 键录进动作）；`fushi/test/focus/mouse_click_to_focus_test.dart` 新增「目标内按下不抢聚焦子孙」单测（含点击确实命中的前置断言）。修复前探针在「焦点导航开 + 点录制条」组合下复现：主焦点落在 `shortcut-row-videoScreenshot`，Esc 后浏览器路由被弹出。
- **备注**：既有 `shortcut_browser_test.dart` 只挂裸 MaterialApp（无全局导航层、无焦点根），测不出这条。
