## BUG-4115 · Windows 音乐歌词页 / 有声书歌词模式 / 小说阅读器里拖不动窗口
- **报告**：2026-11-04（用户：Windows，音乐播放器、有声书歌词模式、小说阅读器里无法拖动整个 Fushi 窗口，其它页面可以）
- **真实性**：✅ 真 bug，与 BUG-3929（视频页）同一根因，当时只修了视频页。这几页都上报了 `FushiTitleBarColorScope`（沉浸页）：`fushi/lib/src/pages/implementations/reader_fushi_page.dart:4289`（阅读器）、`fushi/lib/src/media/audiobook/lyrics_player/lyrics_player_overlay.dart:458`（有声书歌词模式覆盖层，挂在阅读器里）、`fushi/lib/src/pages/implementations/music/music_lyrics_page.dart:2165`（音乐歌词页 `_TitleBarScope`），同样受影响的还有 `fushi/lib/src/media/manga/reader/manga_fushi_page.dart:6689`（漫画）与 `fushi/lib/src/pages/implementations/game_stream_page.dart:1871`（游戏串流）。沉浸页的自绘标题行（唯一的 `DragToMoveArea` + 窗口按钮）由 `fushi/lib/src/utils/components/fushi_desktop_title_bar.dart:531` 的 `_ImmersiveCaptionReveal(enabled: immersive)` 包住，`:955` `_shown` 为假时 `:987` `IgnorePointer(ignoring: !shown)` 整条不吃指针——「拖动区可命中」与「按钮可见」绑成了一个状态；`_shown` 只认顶边停留（`:1002` `_kImmersiveRevealEdge = 8` + 400ms）/ 键盘焦点 / 触摸 / 原生最大化键悬停 / 页面浮出请求。这些页都没有页面级表态，于是只剩「顶边 8px 停留」一个入口，而 Windows 窗口化时那 8px 正压着顶边 resize 把手（`:755` `ResizeEdge.top`，光标是缩放箭头），实际等于拖不动。不是 WebView 平台视图吃指针：标题行在 Navigator 之上的 Stack 里，浮出时照常先命中。
- **[x] ① 已修复** —
  - 标题栏（`fushi_desktop_title_bar.dart`）：新增「隐形拖动条」模式（`setCaptionDragBand` + `FushiTitleBarDragBandScope`）。把「拖动区可命中」与「按钮可见」拆成两个状态：拖动区始终可命中（仍是同一份 `DragToMoveArea`，拖动 / 双击最大化不变），窗口按钮隐去时 `IgnorePointer`，指针进入整条带子停留 `FushiMotion.short`（经 `fushiMotionDuration`）后淡入、离开淡出，不再依赖顶边 8px + 400ms。`FushiTitleBarRevealScope` 改成 `bool revealed`，与拖动条 scope 共用「被整页盖住即撤回」骨架。新增 `FushiWindowDragArea`：空白背景鼠标按住拖动（越过 pan 阈值）→ `windowManager.startDragging`，单击照旧交给背景回调，无双击回调，不认触摸，未装自绘顶栏 / 内容全屏时不挂识别器。
  - 音乐歌词页、有声书歌词覆盖层：顶栏常驻、标题行那一条只有背景 → 隐形拖动条；背景层包 `FushiWindowDragArea`（覆盖层的 `onTapBackground` 保留；歌词 WebView 在背景之上，不覆盖）。
  - 小说阅读器：`revealed: _bottomBarShouldPaint`（顶栏贴边 / 悬浮同一判据），栏收起时标题行隐去、顶部正文照常点词。
  - 漫画阅读页：`revealed: mangaChromeBarPainted(...)`（与顶栏 `MangaChromeReveal` 同源）。
  - 游戏串流：返回 / 动作工具栏常驻、画面经 SafeArea 排在标题行之下 → 隐形拖动条。
  - 视频页：保持跟随控制条（改为 `ValueListenableBuilder` 喂 bool，行为不变）。调查画面上「鼠标按住拖动 = 拖窗口」：与长按倍速（`video_fushi/layout.part.dart:492` `VideoLongPressSessionDetector`，桌面鼠标按住约 500ms 后横拖连续调速，`speed.part.dart:112`）在同一区域同一拖动语义冲突，另与字幕按字点击查词（`video_subtitle_overlay.dart:2184`，按在字上拖会被 pan 抢走）、字幕位置拖拽调整模式（`:2260` `_wrapDragAdjust`）重叠 → 按拍板「有冲突就不加」，未加。
  - 提交：未提交（交回待审）。
- **[x] ② 已加自动化测试** — `fushi/test/desktop/immersive_pages_window_drag_test.dart`：真 `ReaderLyricsPlayerOverlay` 挂在 `FushiDesktopTitleBar` 下，按钮隐去时拖动 → `startDragging`、双击 → `maximize`、隐去的关闭键点击无效、指针进入带子按钮淡入 / 离开淡出 / 划过不浮出；`FushiWindowDragArea` 拖动 → `startDragging`、单击走原回调、双击不最大化、触摸不拖、未装顶栏不拖；阅读器 / 漫画式页面栏收起时顶部归页面、栏唤出后可拖；拖动条 scope 被整页盖住撤回；源码守卫钉住阅读器 / 漫画 / 音乐 / 歌词覆盖层 / 游戏串流的表态，以及棘轮「所有上报配色的页面必须挂 `FushiTitleBarRevealScope` 或 `FushiTitleBarDragBandScope`」。`fushi/test/desktop/fushi_title_bar_page_colors_test.dart` 两条 BUG-3929 用例改用新 API。
