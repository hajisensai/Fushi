## BUG-3874 · srs-webview-card-lookup-gate-never-sent
- **报告**：2026-10-29（用户：iOS 上复习「JLPT N1」「Eggrolls」「蓝宝书」等导入的 Anki 牌组时，点卡面空白唤不出 / 收不起悬浮顶栏胶囊，点词也不查词）
- **真实性**：✅ 真 bug。iOS 27.0 模拟器 + 安装版库里抽出的三套真模板（JLPT N1 Exam Question / eggrolls-JLPT10k-v3.5 / 双语 N2 笔记类型）+ XCUITest 真实触摸复现。整面 WebView 卡面（`SrsWebCardFace`）的页内取词脚本在抬起时先读门控 `window.__fushiSrsLookup`（`fushi/lib/src/pages/implementations/srs/srs_card_lookup.dart:638` `if (!g.tap || g.open) return;`），点词（`onTextSelected`）与点空白（`onTapEmpty`）都排在它后面；门控从没下发——页内读到 `{"lookupInstalled":true,"gate":null}`。根因 `fushi/lib/src/pages/implementations/srs/srs_card_face.dart` `onLoadStop` 把回调参数 controller 传给 `_installLookup`，而 `_installLookup` 用 `identical(_controller, controller)` 判「注入期间视图没换」：flutter_inappwebview 每次回调都经 `controllerFromPlatform` 给同一平台控制器新包一只 `InAppWebViewController`，与 `onWebViewCreated` 存下的 `_controller` 永远不 identical，于是装完取词脚本就返回、门控与弹窗状态同步全部跳过。由 `10894f1d9b`（2026-10-27）引入；controller 包装方式各平台一致，含该提交的构建在 Android / Windows 上照理同样受影响（未实测）。内置 Fushi 卡片的原生区与释义 WebView 不受影响（后者经 `didChangeDependencies` 传的是 `_controller` 本身）。
- **[x] ① 已修复** — `onLoadStop` 改用存下的 `_controller`（并按 `.platform` 核对是同一平台视图），`_installLookup` 的视图更替判断恢复原意。iOS 模拟器真实触摸验证用的是等价探针改法（`_installLookup` 内按 `.platform` 比较）：点空白顶栏出 / 收、点「諸問題」弹查词；本提交的最终写法未再上模拟器复跑。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_web_card_face_lookup_gate_test.dart`：假平台与真插件同形（每次回调新包 controller），断言外壳加载后取词脚本与门控都下发。
- **备注**：`flutter test` 集成测试绑定下嵌入的 WKWebView 收不到真实触摸（最小 InAppWebView app 正常启动可收到、放进 integration_test 就收不到），WebView 真实点按要「灌数据 + 正常启动 + XCUITest」验。
