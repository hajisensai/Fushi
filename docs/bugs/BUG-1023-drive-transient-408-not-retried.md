## BUG-1023 · Google Drive 瞬时故障(408/429/5xx)被判非重试整本skip
- **报告**：2026-07-23（用户：日志 `SyncRunReport ... SyncBackendError: HTTP status was: 408`）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/sync/google_drive_sync_backend.dart:34`（`mapDriveError`）配合 `hibiki/lib/src/sync/google_drive_handler.dart:23`（`isStaleCacheError => statusCode == 404`）。Drive 错误映射时 `isRetryable` 只取 `isStaleCacheError`，即**唯一可重试类别是 404 陈旧缓存**；408（Request Timeout，教科书级瞬时故障）以及 429/500/502/503/504 全部落到 `isRetryable:false`。于是在 `sync_manager.dart:172` 的 retry-once 分支（`if (e.isRetryable)`）进不去，直接落到 skip 分支：该书本轮不同步、错误记进报告，要等下一轮同步才重试。`isStaleCacheError` 把"该重试"和"404 陈旧 ID"两个正交语义混成了一个。
- **[x] ① 已修复** — 给 `GoogleDriveError` 增正交 getter `isTransientError`（`google_drive_handler.dart`，覆盖 408/429/500/502/503/504，**显式排除 507 Insufficient Storage** 配额耗尽——重试无益仍走 skip）；`mapDriveError` 改为 `isRetryable: e.isStaleCacheError || e.isTransientError`（`google_drive_sync_backend.dart`）。未新增/改动重试机制（沿用 sync_manager 现有 retry-once），未动 404 幂等语义（`isStaleCacheError` 消费点逐字不变），向后兼容。提交哈希：<PENDING>。
- **[x] ② 已加自动化测试** — `hibiki/test/sync/google_drive_scope_signout_test.dart` 新增 group `BUG-1023 transient Drive failures are retryable`：参数化断言 408/429/500/502/503/504 → `SyncBackendError.isRetryable == true`；并守住 **507 与未分类 4xx（400）→ isRetryable == false**，防回退成"全 5xx 一刀切重试"误伤配额。`mapDriveError` 本就 `@visibleForTesting`，纯单测无需真机。
- **备注**：与旧记忆里"Drive 瞬时超时整轮放弃 / 逐轨回退"同族——per-book skip 已保证一本超时不拖垮整轮，本修复补上"这一本本可轮内重试一次就成功"的缺口。单次立即重试对 429 非最优（理想是指数退避），但已远好于跳过；退避机制属独立后续，不在本 bug 范围。原始失败路径（真机 Drive 同步遇 408）需在有真值密钥的 worktree 真机验证。
