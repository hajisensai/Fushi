## BUG-3618 · 在线源视频往回跳（上一句 / 固定秒数后退）有时跳不动
- **报告**：2026-10-19（用户：应用内反馈 _ukmWVA9HN，Android vivo V2339FA，3.0.0-debug.19739，Aniyomi 在线源，附录屏）。原话：大部分时候正常，有时上一句硬是跳不过去；按固定秒数往回跳也会跳不动，得多往前跳一点让它从前面播到现在，之后原先有问题的点就好了；从头看下去时不常发生。
- **真实性**：✅ 真 bug（播放器层，用随包 libmpv 复现了同一组症状；用户的真实源本机没有，未在原始路径复现）。
  - 录屏：停在「というわけで…」这句，连按上一句，字幕先换成上一句、约 1 秒后弹回原句，画面不动，反复五次；多往前跳一大段后从前面播过来就正常了。字幕弹回是 BUG-3488 的在途快照在播放态有界放弃——说明 mpv 那边落点根本没到目标，Fushi 的 seek 封装（`seekMs` / `_rawSeekMs` → `player.seek` → mpv `seek <t> absolute`，hr-seek=yes）本身没吞、没改目标。
  - 根因在 demuxer：在线源的 HLS 分片常常**不是从关键帧切开**的（分片 4～6 s，GOP 10 s 上下）。往 demuxer 缓冲**外**的位置 seek 时，ffmpeg hls demuxer（随包 FFmpeg 9.0.1）按播放列表时长找到「包含目标的那一片」从片头读起；片头不是关键帧，解码只能从片内 / 下一片的第一个关键帧开始，它可能在目标**之后**——hr-seek 只会往后丢帧、不会往回找，于是落点比目标晚最多一个 GOP。往回跳几秒时晚落点常落回原位置附近 =「跳不动」。缓冲**内**的 seek 由 mpv 按缓冲里真实的关键帧定位、是精确的，所以「从前面播过来之后就好了」「从头看很少遇到」（从头看时往回跳多在后向缓冲里；续播 / 往前跳过后，起点之前的段不在缓冲里）。
  - 复现（本机 `D:\hibiki-tmp\seekrig`，app 随包 `libmpv-2.dll` mpv 0.41 / ffmpeg N-126123，属性按 media_kit + `buildNetworkCacheProperties(isMobile:true)`）：240 s 片源 GOP 10 s，`-hls_time 4 -hls_flags split_by_time` 切片，本地限速服务器提供。续播到 150 s 播 10 s 后 seek 到 147 → 实际落在 ~150（`execute seek (to 148.462) … join ranges 151.48-…`，伴随 `non-existing PPS 0 referenced`）；seek 到 135 → 落在 ~140。同片源的关键帧对齐 HLS、带 Range 的 mp4 直链都精确；缓冲内 seek 都精确。
- **[x] ① 已修复** — `fushi/lib/src/media/video/mpv_cache_snapshot.dart` `hrSeekDemuxerOffsetForSeek`：HLS 且目标不在 `demuxer-cache-state.seekable-ranges`（离段起点留 2 s 余量）时下发 mpv 为「demuxer 做不到精确 seek」提供的 `hr-seek-demuxer-offset` = 12 s（一个 GOP 的上界：x264 默认 keyint 250 @23.976 ≈10.4 s），demuxer 从目标前读起、目标之前必有关键帧，hr-seek 再精确解到目标；缓冲内 / 非 HLS 下发 0（缓冲内照样精确，不白解帧拖慢句子跳转）。`fushi/lib/src/media/video/video_player_controller.dart`：网络流采样（`_startCacheSpeedSampling`）读 `file-format` / `demuxer-cache-state`；`seekMs` / `_rawSeekMs`（句子跳转、±秒、章节）在 `player.seek` 之前、`notifyExternalSeek`（进度条 / 横滑，fork 在它之后才 seek）调 `_applyHrSeekDemuxerOffsetFor`，值不变不重发，换源复位。同一复现装置下 offset=12：147 → 落在 ≈147、135 → ≈135（seek 后 3 s 读 149.2 / 137.1）；缓冲内 seek 延迟不变（offset 不下发）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/mpv_cache_snapshot_test.dart`「hrSeekDemuxerOffsetForSeek」组（非 HLS / 缓冲内 / 缓冲外 / 贴起点 / 未采样 / 多段）；`fushi/test/media/video/hls_seek_demuxer_offset_wiring_guard_test.dart` 钉三个 seek 入口在 `player.seek` 之前下发、采样读两条属性（无真 libmpv 的单测覆盖不到接线）。
- **备注**：待真机复测（用户的在线源 + Android）。12 s 是经验上界，GOP 更长的片源仍可能晚落点（但比修前近得多）；缓冲外 seek 多拉一两个分片。缓冲外 HLS seek 若超过 2 s 才落地，句子跳转的字幕快照仍会先弹回原句再随落地更新（BUG-3488 播放态有界放弃，未改）。kGkpsMzkpZ（暂停态跳句弹回，BUG-3488 / PR #2275）是另一条机制，已在 upstream/develop。
