## BUG-5253 · 色块布局 sliver 每个滚动帧重建视口内全部卡片（媒体库页滚动卡顿）
- **报告**：2026-11-22（用户：媒体页滚动的时候好卡，该丢后台的就丢后台，不要在主线程同步卡顿）
- **真实性**：✅ 真 bug（沿代码路径与 Flutter SDK 源码验证）。视频库「系列 / 全部视频」在色块 / 拼贴布局下走 `SliverFushiCoverBlocks`（`fushi/lib/src/pages/implementations/home_video_page.dart` `_buildVideoBlockSliver`）。旧实现 `fushi/lib/src/utils/components/fushi_cover_block_layout.dart` `SliverFushiCoverBlocks.build` 在 `SliverLayoutBuilder` 里算整库排布并返回新的 `SliverList.builder`。`SliverLayoutBuilder` 只要 `SliverConstraints` 变了就重跑 builder（SDK `widgets/layout_builder.dart:267` `layoutInfo != _previousLayoutInfo`），而 `scrollOffset` 每个滚动帧都在变；`SliverChildBuilderDelegate.shouldRebuild` 又恒为 true（`widgets/scroll_delegate.dart:579`）。结果是每个滚动帧都要在 UI 线程上重算整库的 `computeFushiCoverBlockPlacement`，还要把视口和缓存区里每一格的 `itemBuilder` 重跑一遍。视频库每格就是整张卡的 build：`_buildCollectionCoverCard`、`videoSeriesMeta`（排序刮削图组、`jsonDecode` 标签）、`_collectionProgress`（逐集解析集号）、`FushiCoverBlock.didUpdateWidget`（取色 / 宽高比探针）等。书、游戏、音乐等 21 处色块布局调用点也有同样问题。
- **[x] ① 已修复** — `SliverFushiCoverBlocks` 改成 StatefulWidget，按「widget 实例 + 横轴宽度 + 摆放姿态」记住上次交出的 sliver。只有滚动位置变化时原样交回同一个实例，框架会整棵跳过更新；宽度、参数或父级重建（新的 itemBuilder 闭包）变化时照常重建。
- **[x] ② 已加自动化测试** — `fushi/test/utils/components/sliver_fushi_cover_blocks_scroll_rebuild_test.dart`：小步滚动 30 帧，已建好的格子一次都不许重建；改宽度或父级换新 itemBuilder 时必须重建并生效。
- **备注**：同类 `SliverLayoutBuilder` 每帧重建还有 `audiobookshelf_library_view.dart:506`、`discovery_layout.dart:839`、`media_server_grid_view.dart:518`、`media_server_detail_view.dart:1105`、`music_plugin_pages.dart:1168/3149`、`extension_store_list.dart:48`、`extension_management_tile.dart:496`，不在本次范围，未改。没有在 profile 包上实测帧耗时（本 worktree 没有 Windows profile 构建，另有代理同时在改）；可用 `fushi/integration_test/video_collection_perf_itest.dart` 的 library 滚动段复测。
