## BUG-5253 · 色块布局 sliver 每个滚动帧重建视口内全部卡片（媒体库页滚动卡顿）
- **报告**：2026-11-22（用户：媒体页滚动的时候好卡，该丢后台的就丢后台，不要在主线程同步卡顿）
- **真实性**：✅ 真 bug（沿代码路径与 Flutter SDK 源码验证）。视频库「系列 / 全部视频」在色块 / 拼贴布局下走 `SliverFushiCoverBlocks`（`fushi/lib/src/pages/implementations/home_video_page.dart` `_buildVideoBlockSliver`）。旧实现 `fushi/lib/src/utils/components/fushi_cover_block_layout.dart` `SliverFushiCoverBlocks.build` 在 `SliverLayoutBuilder` 里算整库排布并返回新的 `SliverList.builder`。`SliverLayoutBuilder` 只要 `SliverConstraints` 变了就重跑 builder（SDK `widgets/layout_builder.dart:267` `layoutInfo != _previousLayoutInfo`），而 `scrollOffset` 每个滚动帧都在变；`SliverChildBuilderDelegate.shouldRebuild` 又恒为 true（`widgets/scroll_delegate.dart:579`）。结果是每个滚动帧都要在 UI 线程上重算整库的 `computeFushiCoverBlockPlacement`，还要把视口和缓存区里每一格的 `itemBuilder` 重跑一遍。视频库每格就是整张卡的 build：`_buildCollectionCoverCard`、`videoSeriesMeta`（排序刮削图组、`jsonDecode` 标签）、`_collectionProgress`（逐集解析集号）、`FushiCoverBlock.didUpdateWidget`（取色 / 宽高比探针）等。书、游戏、音乐等 21 处色块布局调用点也有同样问题。
- **[x] ① 已修复** — 新增共用组件 `fushi/lib/src/utils/components/fushi_sliver_width_builder.dart` `FushiSliverWidthBuilder`：继承 SDK `AbstractLayoutBuilder<double>`，render object 把 `layoutInfo` 收窄成 `constraints.crossAxisExtent`，框架只在横轴宽度变、widget 换新实例或 builder 依赖的 InheritedWidget 变时重跑 builder，只滚动时子树原样保留（不靠手写缓存，依赖追踪仍归框架管）。`SliverFushiCoverBlocks` 改回 StatelessWidget 走它；同类 builder 只依赖横轴宽度的 8 处一并换掉：`audiobookshelf_library_view.dart` `_grid`、`discovery_layout.dart` `DiscoveryCoverGrid`、`media_server_grid_view.dart` 海报网格、`media_server_detail_view.dart` 分集网格、`music_plugin_pages.dart` `SliverMusicRecommendBlocks` 与最近播放行（这两处每帧交出新的 `SliverFushiCoverBlocks` 实例，会把上面的修复整个打穿）、`extension_management_tile.dart` `ExtensionCatalogSliver`、`extension_store_list.dart` `ExtensionStorePageSliver`（后者子 sliver 是父级传入的同一批实例、不会逐帧重建格子，只省掉每帧重跑 builder 的小开销）。
- **[x] ② 已加自动化测试** — `fushi/test/utils/components/sliver_fushi_cover_blocks_scroll_rebuild_test.dart`：小步滚动 30 帧，已建好的格子一次都不许重建；改宽度或父级换新 itemBuilder 时必须重建并生效。`fushi/test/utils/components/fushi_sliver_width_builder_test.dart`：滚动 30 帧 builder 与格子都不重跑；宽度变、父级换新实例、同一实例只改 builder 读的 MediaQuery 时必须重建。
- **备注**：`fushi/lib` 里已无 `SliverLayoutBuilder`；以后新写的 sliver 若 builder 只看横轴宽度，用 `FushiSliverWidthBuilder`。没有在 profile 包上实测帧耗时（本 worktree 没有 Windows profile 构建，另有代理同时在改）；可用 `fushi/integration_test/video_collection_perf_itest.dart` 的 library 滚动段复测。
