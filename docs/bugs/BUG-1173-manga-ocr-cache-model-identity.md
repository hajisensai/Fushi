## BUG-1173 · 漫画本地 OCR 缓存不含模型身份
- **报告**：2026-07-27（用户：PR#474 只读审查）
- **真实性**：✅ 真 bug。逐页缓存目录 `manga_ocr_out/_pages/<签名>/` 的签名是 `hibiki/lib/src/ocr/manga_ocr_folder_job.dart:32` 的**手维护常量** `local-onnx-v2-oriented`，只描述坐标口径版本；而 `hibiki/lib/src/ocr/manga_ocr_model_manifest.dart:43-72` 的下载直链指向 HuggingFace 的 **`main` 可变 ref** 且清单里没有 sha256（只有 `expectedBytes`）。上游一旦重新导出模型，新装用户拿到的是另一份权重，目录名却纹丝不动 ⇒ ①断点续跑把新旧模型的结果混进同一卷；②向导 `manga_ocr_wizard_dialog.dart:294-343` 的「整卷已缓存 → 直接产出」探测会**跳过 OCR** 直接输出旧模型结果；③重开恢复 `manga_ocr_cache_recovery.dart:47` 把旧模型结果贴回当前 payload。全程无任何信号。（换**引擎**不会串——引擎编在目录名里，物理隔离；缺的只有模型版本。）
- **[x] ① 已修复** — 新增 `hibiki/lib/src/ocr/manga_ocr_model_fingerprint.dart`：`resolveMangaOcrModelFingerprint` 对清单里全部模型文件做流式 sha256、折成 12 位短指纹，缓存签名变为 `local-onnx-v2-oriented-<fp>`；模型文件缺失时返回 null，签名退回基线常量。指纹按 `(size, mtime)` 记忆化到模型目录旁的 `model_fingerprint.json`（同 git/rsync/ninja 的判定；11MB~343MB 的整文件下载不可能同尺寸同毫秒换内容），常态只做几次 stat，重下同一份模型不会误伤缓存。`runMangaOcrFolderJob` 改为 **required** `engineSignature`（不给默认值，免得新调用方漏传又混卷）；isolate（`manga_ocr_service_impl.dart`）、向导探测、重开恢复三处消费方统一走同一解析。
- **[x] ② 已加自动化测试** — ①`hibiki/test/ocr/manga_ocr_model_fingerprint_test.dart`：同名同长度不同内容 → 指纹不同；上游换模型重下 → 签名变；重下同一份模型 → 签名不变；记忆化 sidecar 命中与损坏容错；模型缺失退回基线。②`hibiki/test/ocr/manga_ocr_folder_job_test.dart`「引擎签名不同（换模型）时不复用旧页缓存」：同签名重跑识别器零调用，换签名后每页重新检测、两个缓存目录并存、产物元数据记录真正产出它的签名。③`hibiki/test/media/manga/manga_ocr_cache_recovery_test.dart`「local cache from a different model signature is not recovered」：不同签名零恢复，同签名同一份缓存能恢复（证明为空不是因为没写成功）。
- **备注**：PR#474 新增面审查产物。同批顺带修掉 `ocr_inference_ort.dart:87-91` 的**不可达死代码**——单输入模型「按 session 元数据回退」排在按名匹配之后，循环里任一未命中就已 `return inputs`、走完又保证 `resolved` 非空，doc 宣称的鲁棒性从未生效；已把该分支提到匹配之前并补 `ocr_inference_ort_test.dart`「single-input model accepts any exported input name」（`input` / `x` / `pixel_values` 三种导出名）。另给 `manga_ocr_recognizer_test.dart` 的 fake encoder/decoder 补上逐维形状断言，堵住「元素数相同 ⇒ NCHW 写成 NHWC、beam tiling 写错都不会红」的口子。
