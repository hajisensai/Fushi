## BUG-757 · 歌词模式音频跟随失效（followAudio 门控 + snap 回中不生效）
- **报告**：2026-07-12（用户：歌词模式音频跟随失效）。
- **真实性**：✅ **真 bug（跟随语义 + snap 回中丢失）**，且**主因常是 BUG-756 的下游**。跟随驱动链没断：`controller.notify → onReaderCueChanged → _onCueChanged`（`reader_hibiki/audiobook.part.dart:509`）→ `__lyricsSetCue(idx, followAudio.value)`。高亮无条件更新，自动滚动被双门控 `scroll!==false && !__lyricsCaretActive`（`lyrics_mode_html.dart:319`）。① **最广覆盖面**：`followAudio` 是与正文共享、按书持久化的开关（默认 true）；用户此前在正文关过「跟随音频」→ 进歌词沿用 OFF → 高亮跟随但**不自动滚动** = 用户感知的「跟随失效」——而「跟随开关」就在 BUG-756 里**唤不出的底栏**，用户改不到，两症状闭环。② **真 snap bug**：切 follow OFF→ON 的 `snapReaderToAudio`（`audiobook_controller.dart` `_forceNextReveal=true` + notify）在歌词模式失效——歌词分支**从不调 `consumeForceReveal()`**（正文分支 `audiobook.part.dart:596` 调），且 `setCue` 有 `if(index===_currentIdx)return`（`lyrics_mode_html.dart:305`）→ snap 那刻 cue 没变、早退吞掉回中，打开跟随画面也不动；副作用是 force-reveal 一次性旗泄漏到之后退回正文的 `_onCueChanged`，凭空多滚一次。
- **[x] ① 已修复** — `c41330804`。`audiobook.part.dart` 歌词分支：① **无条件** `final bool forceReveal = controller.consumeForceReveal();`（哪怕本帧未就绪/越界也消费一次，堵住泄漏到正文路径）；② scroll 形参由 `controller.followAudio.value` 改成 `followAudio.value || forceReveal`（snap 也放行滚动）；③ `forceReveal` 下在 `__lyricsSetCue` 之后再显式 `__lyricsScrollToCue($idx)`，绕过 `index===_currentIdx` 早退强制把当前句居中。跟随开关本身沿用共享持久化语义（用户可唤出底栏后自行开关，见 BUG-756）。根因修（补齐 force-reveal 语义 + 绕开早退），非绕过。
- **[x] ② 已加自动化测试** — `test/media/audiobook/lyrics_follow_audio_guard_test.dart`（更新旧用例适配 `$scroll` 派生 + 新增 BUG-757 用例：全语料 `consumeForceReveal()` ≥2 处证明歌词分支独立消费；歌词分支含 `window.__lyricsScrollToCue($idx)` 强制回中）。`_onCueChanged` 含真 WebView 无法 widget 挂载，最强可落地层是 reader 源码扫描 + HTML 生成器契约。
- **备注**：reader/有声书/歌词类。代码 + 单测绿、`flutter analyze` 0 issue、`dart format` 0 改动。**真机复测**（歌词模式播放中当前句自动居中跟随；切「跟随音频」OFF 只高亮不滚、再 ON 立刻回中）待用户后补。与 BUG-756 同批修（唤出底栏后才够到跟随开关）。
