## BUG-5463 · 「同一作品」打开只在 Jellyfin 上有集的动画合集显示「合集为空」
- **报告**：2026-11-25（用户：书卡的作品种类角标 →「同一作品」弹窗 → 点改编动画的视频合集卡，打开后显示「合集为空」；这部动画的集只在 Jellyfin 服务器上（视频库混排开着，视频库里点同一个合集是有集的）。卡片也只有占位图，没有服务器海报）
- **真实性**：✅ 真 bug。视频合集的成员清单是跨端 union：Jellyfin / Emby 混排或互联 host 上的集在本机只有 `media_collection_items` 行，`entryKey` 是远端视频 id、没有 `video_books` 行（`fushi/lib/src/media/collections/collection_episode_slot.dart` 文件头）。只有视频库页持有解析这些成员的远端上下文（远端来源 + 清单缓存）。根因在 `fushi/lib/src/media/links/media_link_opener.dart:111`（修复前）：「同一作品」的打开器自己 push 了一个 `MediaCollectionDetailPage`，`loadEpisodes` 只给 `loadCollectionEpisodeSlots(repository:, collectionId:)`、不带 `loadRemoteVideos`，远端成员全部被丢弃，详情页判空。卡片没有海报同理：`MediaLinksSection._cover` 只认本地封面，远端合集没有本地封面。
- **[x] ① 已修复** —
  - `73a1801b9d`：视频合集不再由打开器自建详情页。`media_link_opener.dart` 回到首页壳、切到视频 tab、发打开请求（`fushi/lib/src/models/video_collection_open_request.dart`）；`HomeVideoPage` 接请求（`_onVideoCollectionOpenRequested` / `_openRequestedVideoCollection`），用视频库合集卡同一个出口 `_openCollectionDetail` 打开，详情页因此带着远端上下文；请求先于首轮远端取数到达时只解析远端来源、不等整份清单。卡片在合集有远端成员时画云图标（`MediaLinkEntry.hasRemoteMembers` → `ShelfCardMeta.leadingIcon`），与视频库合集卡同一提示。
  - 远端海报（同一 PR 第二个提交）：远端来源链（互联 → Jellyfin → 云盘）从视频库页的三个私有方法收进共享解析器 `fushi/lib/src/media/video/remote_video_source_resolver.dart`（`resolveRemoteVideoSource`，页面的 widget 测试钩子作为注入点转进去；`resolveVisibleRemoteVideoSource` 再套「显示远端条目」开关）。新增可选能力 `RemoteVideoLookup.remoteVideosByIds`（`fushi/lib/src/sync/remote_video_client.dart`），`JellyfinVideoClient` 用 `/Users/{uid}/Items?Ids=...` 实现（`JellyfinApi.items` 加 `ids` 参数，每 100 个一发，只留可播叶子，映射同 `infoFromItem`），不枚举整库。`MediaLinkEntry` 改带远端成员键（`remoteMemberKeys`，成员序前 5 个）；`MediaLinksSection` / `showMediaLinksDialog` 加 `remoteVideoSource`，没有本地封面的远端合集卡在区块加载时一次性按成员 id 查远端，取第一个剧海报（否则第一个成员封面），用与视频库相同的 `RemoteCoverImage` + 缓存键（剧海报 = 不含令牌的 URL 路径，单集封面 = 视频 id），共用磁盘缓存；来源整段生命周期只解析一次，没有远端成员的卡不触发任何网络。各调用点经 `mediaLinkRemoteVideoSource(ref:)` 传入。
