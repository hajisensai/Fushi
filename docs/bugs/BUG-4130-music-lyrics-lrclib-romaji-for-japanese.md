## BUG-4130 · 音乐歌词：日文歌拿到 LRCLIB 罗马音版（不检查歌词书写系统）
- **报告**：2026-10-28（用户：开发者本人，应用内反馈 zl9Nmfldfr，「文字位置不对，而且文本是英文的，应该默认对应的语言才对」；截图是 Windows 歌词页播放 うさぎとかめ / 平沢唯(CV:豊崎愛生)，整页罗马音纯文本）
- **真实性**：✅ 真 bug（语言部分）。日志里同曲 sidecar / 内嵌都没有（`resolve` 的 ②③ 早返回没触发），罗马音来自 LRCLIB。根因：
  - `fushi/lib/src/media/music/lyrics/music_lyrics_service.dart` `_resolveLrclib`（修前 574-608）：`/api/get` 命中的 `bestLyrics` 不看正文书写系统直接落库、返回，罗马音 / 翻译版与原文版一视同仁；缓存命中同样直接返回。
  - `fushi/lib/src/media/music/lyrics/lyrics_candidate_scoring.dart` `pickBestLyricsCandidate`（修前 145-185）只按标题 / 艺人 / 时长评分，分不出同名的原文版与罗马音版。
  - `resolve`（修前 531-553）LRCLIB 固定第一，罗马音命中直接 return，带原文的歌词插件没机会。
  - 位置部分：截图是旧版 `music_lyrics_page.dart` 固定 `width: 380` 左栏布局，88712fbf45（2026-10-29）已重写为 split / stage / disc 三种布局，非本条代码修复范围。
- **[x] ① 已修复** — 新增纯函数 `lyricsScriptProfile` / `expectedLyricsScript` / `lyricsScriptFit` / `lyricsScriptMismatches`（按元数据推断期望书写系统：有假名→日文、谚文→韩文、汉字→汉字系，全拉丁字母不推断；假名 / 汉字 / 谚文按字、拉丁字母按词计数，夹大量英文的原文版不会被字母数压成「拉丁字母」）；`_resolveLrclib` 对不上时按 `lyricsQueries` 走 `/api/search`（LRCLIB 客户端新增 `q` 参数）挑同名、同录音时长（±2 s）且书写系统对得上的记录；挑不到就留着但只当兜底；歌词插件的结果（缓存命中与新取）同样过书写系统检查，对不上的落库但只当兜底、继续问下一个插件，全部在线来源都没有对得上的才按 LRCLIB → 插件顺序用兜底；缓存的对不上行按 `updated_at` 每 `kLrclibNegativeCacheTtl` 重挑一次——改版前落库、更新时间已早于 TTL 的旧行首次解析即重挑，TTL（7 天）内落库的旧行要等到期（表里无「搜过原文版」标记），重挑保留用户偏移。`pickBestLyricsCandidate` 对带正文的候选加书写系统权重并可要求必须对得上；在线搜索结果原文版排前，选来源 / 在线搜索列表副标题标出书写系统。
  - 审查补修（PR #2989）：`expectedLyricsScript` 改成返回 `LyricsScriptExpectation`（书写系统 + `fromTitle`）。去括注后的标题有假名 / 谚文 / 汉字才是强推断；标题全拉丁字母、只有艺人 / 专辑带 CJK（『桜高軽音部 - Don't say "lazy"』、中文歌手的英文歌）是弱推断，只有正文是罗马音 / 拼音（`lyricsLooksRomanized`：≥ 80% 的拉丁字母词能拆成罗马字音节）才算对不上，英文原文不再被 `/api/search` 换成翻译版。歌词插件：`_searchAndFetch` 按 `rankLyricsCandidates` 名次逐条取（最多 `kPluginLyricsScriptProbeLimit` = 3 条），取到书写系统对得上的就用；缓存里对不上的插件行按 `updated_at` 每 `kPluginLyricsNegativeCacheTtl` 重挑一次，挑到原文版换掉并保留偏移，挑不到只刷新更新时间。
- **[x] ② 已加自动化测试** — `fushi/test/media/music/lyrics/music_lyrics_script_selection_test.dart`（离线 LrclibTransport fixture：罗马音 get + 原文 search → 选原文；拉丁字母曲目不额外搜索；同名原文按时长裁决；搜不到原文时插件胜出；无插件仍用罗马音且 TTL 内不重挑；搜索失败不落库；旧缓存罗马音行重挑保留偏移；在线搜索排序与书写系统标注；日英 / 中英混排原文不判错；插件拿到罗马音 / 只有中文翻译时继续问下一个插件、二次解析走缓存同样跳过；LRCLIB 与插件都对不上时 LRCLIB 兜底在前；只有插件的对不上版本时仍用它；TTL 内落库的旧罗马音行到期前不重挑、到期后重挑）。把 `_resolveLrclib` 的期望书写系统变异成 null 时其中 5 条变红。
