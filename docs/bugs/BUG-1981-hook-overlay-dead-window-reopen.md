## BUG-1981 · Hook 浮窗 HWND 失效后自动与手动打开都无窗口
- **报告**：2026-08-31（用户：「游戏的hook浮窗打不开了，点击hook浮窗按钮也打不开」）
- **真实性**：✅ 真 bug。`fushi/windows/runner/floating_lyric_window.cpp:398` 的 `Show()` 只判 `hwnd_ == nullptr`，没有像 `GlobalLookupWindow` 一样核对 `IsWindow + GWLP_USERDATA`；HWND 被 `WM_CLOSE`/外部 teardown 销毁后，成员仍非空，`ShowWindow`/`SetWindowPos` 对死句柄失败但函数无条件回 `true`。同时 `fushi/lib/src/lookup/gal_hook_text_overlay_controller.dart:716` 只信上次 `show=true` 的 `_visible` 镜像，后续自动同步只发 `updateText`，手动入口也可能再次接受假成功，故屏幕始终没有窗口。
- **[x] ① 已修复** — `ad52944d70`：Win32 侧新增 `FloatingLyricWindow::OwnsLiveWindow()`（`IsWindow` + `GWLP_USERDATA` back-pointer 双判据，防 HWND 被系统回收）、把两条死窗路径的复位表收成唯一的 `ResetWindowInteractionState()` + `ForgetDeadWindow()`、`Show()` 先丢死句柄再重建并在 `SetWindowPos` 失败时回 `false`、`IsShowing()` 改用 `OwnsLiveWindow()`。
  同 PR 后续提交把同一 bug 家族的另外三处一并根治：
  1. **`hook_toolbar::SlotTooltipHost` 的死句柄**（`hook_toolbar_window.cpp`）——提示窗以宿主浮窗为 owner 创建（`WS_POPUP` + `hWndParent=owner`），宿主被销毁时系统连带销毁它，而 `EnsureWindow()` 的 `if (hwnd_ != nullptr) return true;` 幂等守卫从此**永久短路**，浮窗重建后槽位提示整会话再也不出。补 `OwnsLiveWindow()` / `ForgetDeadWindow()`，在幂等守卫**之前**调用，建窗后立刻打 back-pointer，析构也先忘死句柄再 `DestroyWindow`（否则可能去拆被系统回收给别人的窗口）。`pass_through_toolbar_` 自身是 `nullptr` owner，不在本形状内，未动。
  2. **`HandleMessage` 用成员 `hwnd_` 冒充消息宿主**——`WM_NCDESTROY` 分支原本 `HWND destroyed = hwnd_;`。一旦出现「旧窗口的 NCDESTROY 晚于新窗口创建」的排列，`SetWindowLongPtr(destroyed, GWLP_USERDATA, 0)` 就打在活着的新窗口上并把 `hwnd_` 清成 null。改为由 `WndProc` 把消息自带的 `hwnd` 透传进 `HandleMessage`，函数体全部改读它；成员句柄与复位表只在 `hwnd_ == destroyed` 时才动。
  3. **每行一次 `isShowing()` 往返是轮询，不是派生状态**——native 在 `WM_NCDESTROY` 里推新事件 `overlayDestroyed`（`FloatingLyricWindow::DestroyedCallback` → `flutter_window.cpp` → `gal_hook_text` 通道），Dart 的 `_visible` 镜像由它**被动**复位。按行的 MethodChannel 往返因此去掉（Zato 那种逐字重绘一句台词就是十几次）；`isShowing()` 保留为兜底，但只在**每局会话开始**打一次，且 `_visible` 为 false 时直接早退。`overlayDestroyed` 与用户按关闭的 `close` 严格分开：后者置 `_suppressedForSession`，前者不能。
- **[x] ② 已加自动化测试** — `fushi/test/lookup/gal_hook_overlay_window_lifetime_guard_test.dart`（源码扫描，剥注释后逐函数体）钉死：`OwnsLiveWindow` 的双判据、唯一复位表、`Show()` 的先后序、`IsShowing()` 不得退回裸 `hwnd_ != nullptr`、`WM_NCDESTROY` 只认消息自带 hwnd 且条件清零、`HandleMessage` 函数体不得再读成员 `hwnd_`，以及 `SlotTooltipHost` 的同四条契约。`fushi/test/lookup/gal_hook_text_overlay_controller_test.dart` 覆盖：native 推 `overlayDestroyed` 后镜像被动复位且**不**置 `_suppressedForSession`、下一条台词重建窗口、每条台词都不再打 `isShowing` 轮询、会话开始的兜底对账仍在。全部新断言做过变异实测（改坏被守代码 → 对应断言变红 → 按唯一锚点还原并核 sha256）。
- **备注**：聚焦 Flutter 测试在执行任何 case 前被 `pdfium_dart` 下载 `pdfium-win-x64.tgz` 的 GitHub release-assets 超时阻塞；未做 Windows 构建、真实游戏/设备 E2E，不能把本条记为真机已验证。
