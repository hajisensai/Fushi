## BUG-5611 · web-video-builtin-white
- **报告**：2026-11-28（BUG-5591 前台验证时发现；同日用户现场反馈「浏览器视频用 fushi 播放，视频直接都是白的」，当时系统里唯一的实例正是 develop 分叉点 `e18ab28f1c8` 的 Release 构建）
- **真实性**：✅ 真 bug，既有问题。Windows Release 前台复现：app 内浏览器打开 YouTube 观看页 → 工具栏「用 Fushi 播放」→ 播放页（「制卡优先」档）进度在走、字幕在出，视频区整片白。BUG-5591 分支与 develop 分叉点表现一致，与全屏改动无关。
- **根因**：`fushi/lib/src/media/video/web_video_session.dart`（修前第 88–96 行 `webVideoCapturableEnvironment`）给可捕获档环境传了 `--disable-direct-composition`。「制卡优先」档是 composition 宿主：WebView2 把画面交进 fork 自建的 visual（`packages/flutter_inappwebview_windows/windows/in_app_webview/in_app_webview.cpp` `createSurface`），纹理桥用 `CreateGraphicsCaptureItemFromVisual` 从这个 visual 截进 Flutter 纹理（`custom_platform_view/texture_bridge.cc:535`）。在 WebView2 158 运行时上，关掉 DirectComposition 后浏览器进程根本不往宿主 visual 出画面，WGC 截不到任何帧，Flutter 纹理是空的，露出底下的白底；网页本身照常播放（JS 状态上报照走，所以进度、字幕都正常）。这个参数是 2026-08 在旧运行时上为 Widevine 软件解密视频可截取加的（`docs/plans/2026-08-29-web-video-player-anime4k.md` §5），当时实测能出画面；现在运行时行为变了。app 内浏览器页用的共享环境不带该参数，同一条 WGC 链路一直正常，这就是「浏览器里能看、交给播放页就白」的原因。
  - 逐层取证（本机 Release + 临时诊断补丁，已撤）：纹理桥 `TextureBridgeGpu::CopyIntoSurface` 每 120 帧回读 3 个像素落盘。修前：只有浏览器页那一路桥（3840×1900）有帧，播放页那一路桥**一帧都没进来**；修后：播放页桥（3840×2160）持续有帧、像素是视频内容，屏幕截图里画面正常。CDP 读页面：修前 `visibilityState=visible`、`<video>` 在播、只留画面样式已套上——网页层没问题，断在「浏览器进程 → 宿主 visual」这一步。
- **[x] ① 已修复** — 可捕获档环境参数改为 `kWebVideoCapturableBrowserArguments`（`--autoplay-policy=no-user-gesture-required --disable-direct-composition-video-overlays`）：保留 DirectComposition 出画面，只关视频 overlay。真机复测（Windows Release，YouTube `HrTvMpjmmsA`）：交给播放页后画面正常；播放页上 F11 进 / 出全屏画面都正常。
- **[x] ② 自动化测试** — `fushi/test/media/video/web_video_capturable_env_args_test.dart`：可捕获环境参数整词不含 `--disable-direct-composition`（及 `--disable-gpu` / `--disable-gpu-compositing`）、保留自动播放与只关视频 overlay，且环境单例确实用这份常量。像素级（WGC 纹理是否有帧）目前没有 Dart 可读的出口，只能真机截图 / 纹理桥回读兜底，未做成集成测试。
- **备注（遗留）**：Widevine 软件解密的视频（dash.js Widevine 样例，`mediaKeys` 在、`videoWidth=1920`、在播）在 composition 宿主下仍是黑的——修前（整片白）修后都看不到，浏览器页共享环境也是黑的；再加 `--disable-features=UseDCOverlaysForSoftwareProtectedVideo` 也无效。即「制卡优先」档在当前运行时上截不到加密站点画面（Netflix 等在 1080p 显示器上默认走这一档），需另立项查（候选：换 Chromium 开关组合、或 DRM 站点默认改走「画质优先」档——后者改变默认行为，要先拍板）。Windows 专属；复现素材：`https://www.youtube.com/watch?v=HrTvMpjmmsA`，开发数据根 `D:\hibiki-dev-data`。
