## BUG-5611 · web-video-builtin-white
- **报告**：2026-11-28（BUG-5591 前台验证时发现；同日用户现场反馈「浏览器视频用 fushi 播放，视频直接都是白的」，当时系统里唯一的实例正是 develop 分叉点 `e18ab28f1c8` 的 Release 构建）
- **真实性**：✅ 真 bug，既有问题。Windows Release 前台复现：app 内浏览器打开 YouTube 观看页 → 工具栏「用 Fushi 播放」→ 播放页（「制卡优先」档）进度在走、字幕在出，视频区整片白。BUG-5591 分支与 develop 分叉点表现一致，与全屏改动无关。
- **根因**：`fushi/lib/src/media/video/web_video_session.dart`（修前第 88–96 行 `webVideoCapturableEnvironment`）给可捕获档环境传了 `--disable-direct-composition`。「制卡优先」档是 composition 宿主：WebView2 把画面交进 fork 自建的 visual（`packages/flutter_inappwebview_windows/windows/in_app_webview/in_app_webview.cpp` `createSurface`），纹理桥用 `CreateGraphicsCaptureItemFromVisual` 从这个 visual 截进 Flutter 纹理（`custom_platform_view/texture_bridge.cc:535`）。在 WebView2 158 运行时上，关掉 DirectComposition 后浏览器进程根本不往宿主 visual 出画面，WGC 截不到任何帧，Flutter 纹理是空的，露出底下的白底；网页本身照常播放（JS 状态上报照走，所以进度、字幕都正常）。这个参数是 2026-08 在旧运行时上为 Widevine 软件解密视频可截取加的（`docs/plans/2026-08-29-web-video-player-anime4k.md` §5），当时实测能出画面；现在运行时行为变了。app 内浏览器页用的共享环境不带该参数，同一条 WGC 链路一直正常，这就是「浏览器里能看、交给播放页就白」的原因。
  - 逐层取证（本机 Release + 临时诊断补丁，已撤）：纹理桥 `TextureBridgeGpu::CopyIntoSurface` 每 120 帧回读 3 个像素落盘。修前：只有浏览器页那一路桥（3840×1900）有帧，播放页那一路桥**一帧都没进来**；修后：播放页桥（3840×2160）持续有帧、像素是视频内容，屏幕截图里画面正常。CDP 读页面：修前 `visibilityState=visible`、`<video>` 在播、只留画面样式已套上——网页层没问题，断在「浏览器进程 → 宿主 visual」这一步。
- **根因（第二层：加密视频截到黑）**：Chromium 把受保护视频（含 Widevine 软件解密）一律放进 DirectComposition overlay——`components/viz/service/display/dc_layer_overlay.cc` `IsOverlayRequiredForQuad`（"Hardware protected video always requires overlays, and for software protected video we prefer it"）；这类 overlay 的交换链带 `DXGI_SWAP_CHAIN_FLAG_DISPLAY_ONLY`（`ui/gl/swap_chain_presenter.cc` `IsProtectedVideo(...)` 分支），只上屏、不可截，WGC 截到的是黑。第一版修复里写的 `--disable-direct-composition-video-overlays` 在 Chromium 里**不存在**（`ui/gl/gl_switches.cc` 只有 `disable-direct-composition` / `enable-direct-composition-video-overlays`），是空操作，先前「只关视频 overlay」的说法不对。能用的是 GPU 驱动 workaround 的命令行开关 `--disable_direct_composition_video_overlays`（下划线，`gpu/config/gpu_driver_bug_list.cc` `AppendWorkaroundsFromCommandLine`），置位后 `DirectCompositionOverlaysSupported()` 为 false（`ui/gl/direct_composition_support.cc`），`dc_layer_overlay.cc` 在保护判断之前就返回 unsupported，加密视频改走普通合成、可被截取。所以这是开关组合问题，不是绕不过的内容保护。
  - 实测（WebView2 158，`integration_test/web_video_builtin_capture_itest.dart` 离屏跑，同一会话先 YouTube 再把页面换到 dash.js Widevine 样例并把 `<video>` 铺满页面）：
    - 只带 `--autoplay-policy`：YouTube 有画面；Widevine 样例 `mediaKeys` 在、在播，纹理 5 个采样点全是不透明黑 `[0,0,0,255]`。
    - 加 `--disable_direct_composition_video_overlays`：浏览器与 GPU 进程命令行都带上该开关；YouTube 照常；Widevine 样例采样点是随时间变化的画面像素（如 `[43,65,75]`→`[188,123,98]`）。
    - 修复前参数 `--disable-direct-composition`：纹理桥整段只进 1 帧、全透明 `[0,0,0,0]`，测试红（`frames` 增量 0 < 30）。
- **[x] ① 已修复** — 可捕获档环境参数 `kWebVideoCapturableBrowserArguments` = `--autoplay-policy=no-user-gesture-required --disable_direct_composition_video_overlays`：保留 DirectComposition 出画面，用 GPU workaround 开关关掉视频 overlay，加密视频（Widevine 软件解密）也截得到。真机复测（Windows Release，YouTube `HrTvMpjmmsA`）：交给播放页后画面正常；播放页上 F11 进 / 出全屏画面都正常。
- **[x] ② 自动化测试**

  - 纹理桥只读体检出口：fork `TextureBridge::GetCaptureStats`（累计 WGC 帧数 + 最近一帧 5 个采样点）经 `getCaptureStats` 通道方法暴露，Dart `fushi/lib/src/media/video/web_video_capture_stats.dart`；`fushi/test/media/video/web_video_capture_stats_test.dart` 测解析与判据，并守卫 C++ 方法名 / 字段名与 Dart 一致。
  - `fushi/integration_test/web_video_builtin_capture_itest.dart`（`FUSHI_WEB_VIDEO_BUILTIN_CAPTURE_ITEST=1`；`FUSHI_WEB_VIDEO_PROBE_URL` 再测加密样例）：「制卡优先」档交给播放页后 5 s 内纹理进 ≥30 帧、非纯白、有变化；加密样例截到有变化的画面。修复前参数下红（见上）。
