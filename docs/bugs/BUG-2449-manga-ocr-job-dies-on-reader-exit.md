## BUG-2449 · 退出漫画阅读页会真停掉正在跑的整卷 OCR 任务
- **报告**：2026-09-11（用户：「感觉退出漫画的时候会把 OCR 停掉」）
- **真实性**：✅ 真 bug。整卷/点击即识别 OCR 任务的唯一持有者是阅读页 State：`fushi/lib/src/media/manga/reader/manga_fushi_page.dart:920` 的 `_wholeVolumeOcrSubscription`（唯一 `listen()` 点在 `:3181-3215` `_attachWholeVolumeOcrJob`），`dispose()` 在 `:1090-1091` 无条件 `cancel()`。而 `MangaOcrBackgroundJob`（`manga_ocr_background_job.dart:7-19`）是冷流，五个执行器的 `onCancel` 全是真中止：本地 ONNX 发 cancel token 到推理 isolate（`packages/fushi_engine/lib/ocr/manga_ocr_service_impl.dart:746-749` → `:512-514` → `:266-270`）、系统 OCR `system_ocr_manga_service.dart:100-102`、Google Lens `google_lens_ocr_service.dart:175-177`、外部 mokuro `external_mokuro_runner.dart:173-178`（SIGKILL 子进程 `:351`）、互联主机 `sync/interconnect_manga_ocr_client.dart:411-413`（向 host 发 `DELETE /api/ocr/job/<id>`）、在线 Lens `mihon/mihon_online_ocr.dart:206-208`。所以「退出阅读页 == 取消订阅 == 任务被杀」，返回书架、切章、系统回收 State 都会把一个设计上要跑 17–33 分钟（`docs/specs/2026-07-24-manga-ocr-design.md:111`）的批处理砍在半路；在线章节还会连带 `_closePageSession`（`:1094-1096`）关掉取图会话。已完成页保留在逐页缓存，但整章 `manga.json` 只在全扫完才写（`mihon_online_ocr.dart:307-332`），退出即本轮白跑。作品页 `library/manga_series_page.dart` 与 `manga_module.dart` 不持有任务，与本 bug 无关。两份设计文档都没约定「退出阅读器后整卷任务是否存活」，属规格空白而非规格违反。
- **[x] ① 已修复** — `1940dedeb7`。新增 `fushi/lib/src/media/manga/ocr/manga_ocr_job_registry.dart`：`MangaOcrJobRegistry`（Riverpod `mangaOcrJobRegistryProvider`，app 级、按 `bookKey` 索引）唯一持有底层事件流订阅，把事件广播给观察者、记录进度快照 `lastEvent`，**finished 先落盘再转发**（落盘经 `runExclusiveOnMangaJson` + `writeMangaJsonAtomically`，写侧清单与锁覆盖守卫同步登记）。阅读页 `manga_fushi_page.dart`：`_attachWholeVolumeOcrJob` 改为 `registry.start` + 观察；`dispose` 只取消观察者订阅；HUD 取消按钮走 `registry.cancel`（唯一真停入口）；三条装书路径末尾 `_reattachRunningOcrJob(imageRoot)` 按受管目录一致才接回（A 章任务不会热替换到 B 章页面）；在线阅读会话交给任务持有，页面 `dispose` / 换章先问 `ownsSession` 再关。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/ocr/manga_ocr_job_registry_test.dart`（6 条：观察者取消不停任务且晚到观察者拿快照、`cancel` 才真停并关会话、零观察者完成仍落盘、finished 在落盘后转发、报错移除并关会话、同书重复启动不并发）；`fushi/test/pages/manga_fushi_page_test.dart` 新增「BUG-2449」widget 用例：预置运行中任务 → 装书 HUD 接回 `1/2` → 退出页面断言底层流未收到 cancel → `registry.cancel` 才 cancel。变异实测：把 `dispose` 改回取消任务，该用例翻红（Expected false / Actual true）。
- **备注**：导入向导的 `launchInBackground=false` 分支（`manga_ocr_wizard_dialog.dart:129`）是模态进度页，关掉即取消属于模态语义，未纳入注册表。`mihon_online_ocr.dart:149` 物化阶段 `isCancelled: () => false` 仍不可取消（HUD 取消要等物化完才生效），随「强制下载后才能看」删除在线懒 OCR 路径一并消失，不单独修。widget 测试里真异步的 `registry.cancel` 必须放进 `tester.runAsync`：fake zone 下 await 一个 async 函数的完成微任务不会被冲刷（第一版测试因此挂满 10 分钟）。
