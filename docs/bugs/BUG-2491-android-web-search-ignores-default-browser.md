## BUG-2491 · 安卓选区「网页搜索」无视默认浏览器跳自带浏览器
- **报告**：2026-09-13（用户：QQ 群反馈截图——阅读器选区工具条点「网页搜索」，默认浏览器不是手机自带的，却跳到自带浏览器）
- **真实性**：✅ 真 bug。根因 `fushi/android/app/src/main/java/app/fushi/reader/SelectionActionChannel.java:43`（修前）发的是裸 `Intent.ACTION_WEB_SEARCH`。Android 的「默认浏览器」角色只覆盖 `ACTION_VIEW http/https`，`ACTION_WEB_SEARCH` 走的是另一套独立的 intent 解析——OEM ROM 上注册了该 action 的往往只有自带浏览器/系统搜索，所以用户把默认浏览器改成谁都不影响落点。阅读器工具条（`chrome.part.dart` `case 'webSearch'`）、WebView 原生菜单（`webview.part.dart` id 5）、查词弹窗（`dictionary_popup_webview.dart:1702`）三个入口都经 `SelectionExternalActions.searchWeb` → 同一条原生通道，一处根因三处症状。
- **[x] ① 已修复** — `launchWebSearch` 先用 `ACTION_VIEW https` + `MATCH_DEFAULT_ONLY` 解析出默认浏览器包名（解析到 `android` 即系统 resolver 视作「没设默认」），把 `ACTION_WEB_SEARCH` `setPackage` 定向给它——Chrome/Firefox/Edge/Brave 等都注册了该 action，会用浏览器自己的搜索引擎搜；定向抛 `ActivityNotFoundException`（浏览器没注册）则退回原来的裸 intent，零破坏。不硬编码任何搜索引擎 URL、不新增偏好。`AndroidManifest.xml` `<queries>` 补 `VIEW + BROWSABLE + https` 声明——Android 11+ 包可见性没有它 `resolveActivity` 恒 null（`5605f5f2b1` 当年删 preflight 就是踩的这个，那次没加 queries）。
- **[x] ② 已加自动化测试** — `fushi/test/platform/android_selection_action_channel_guard_test.dart` 改钉新契约：探针 intent 形状 + `MATCH_DEFAULT_ONLY` + `android` 包排除 + `setPackage(browser)` 定向 + 两层 `ActivityNotFoundException` 兜底 + 探针 URL 永不 `startActivity` + manifest `<queries>` 含 VIEW-https。变异实测：去掉 `.setPackage(browser)` 守卫转红（exit 1），还原 6/6 绿。
- **备注**：Java 层没有 JVM 单测基建覆盖 `PackageManager`（现有 kotlin 测试只有 mihon 代理两条），所以最强可落地层是源码守卫 + `assembleRelease` 编译门。真机行为（Chrome 设默认后定向成功）未在本机验证——Windows 机没有 Android 真机接入，模拟器默认浏览器就是 Chrome 无法复现「自带浏览器」差异；待用户回访。
