## BUG-2874 · 漫画顶栏窄屏翻页方向按钮压住页码胶囊
- **报告**：2026-10-02（用户：Android 竖屏手机 ~412dp，在线 Mihon 源章节，顶栏「翻页方向」按钮（`Icons.arrow_back`）画在页码胶囊「4 / 37」上面）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/media/manga/reader/manga_reader_chrome.dart:171`（修前）：顶栏只拿与内容无关的固定阈值 `readerHeaderCompact`（`fushi/lib/src/reader/reader_desktop_chrome.dart:97-100`，760）决定折叠，折叠后 `:196` 把**全部** pinned 按钮照画，从不检查真实宽度放不放得下。漫画页给的 pinned 有 返回 + 章节目录 + 翻页方向 + 回到开头（`fushi/lib/src/media/manga/reader/manga_fushi_page.dart:5661/5678`）+（整卷 OCR 运行中）取消 + 设置 + 隐藏 + ⋮，412dp 上 7~8 颗 48dp 按钮把 `:192` 的 `Expanded` 标题槽挤到 ~68dp（OCR 运行中只剩 ~20dp），胶囊取自然宽画出槽外，Row 不裁剪，紧随其后的方向按钮盖在胶囊上；加大系统字号更糟。EPUB 顶栏早已按真实按钮数判（`readerHeaderCompactForActions`），漫画顶栏没跟上。
- **[x] ① 已修复** — `manga_reader_chrome.dart` 新增纯函数 `planMangaTopBarActions`：按**真实宽度 + 页码胶囊实测宽**（`TextPainter` 带 `MediaQuery.textScalerOf`）排布——宽窗放不下也转紧凑；紧凑态仍放不下胶囊时，把 `MangaChromeAction.secondary` 的 pinned（翻页方向、回到开头）从后往前降进 ⋮；胶囊再用 `ConstrainedBox(maxWidth: 标题槽剩余宽)` + 单行省略兜底，极端字号下收缩而不被按钮压住。整栏随 `pageListenable` 重建（只是这条栏，页面本体不 setState），胶囊文案变宽时排布跟着变。`manga_fushi_page.dart` 给方向 / 回到开头两颗标 `secondary: true`。提交：见 `fix(manga): demote secondary top-bar actions so the page chip never overlaps`。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_reader_chrome_test.dart`：「MangaReaderTopBar 窄屏排布」组按漫画页真实动作组形态，在 412dp × 字号 1.0 / 1.3（各含整卷 OCR 运行中多一颗 pinned）与 360dp × 2.0 下比较胶囊与栏内每颗 `IconButton` 的 rect 不相交、胶囊文字未被省略（Ahem 字体下 1.3 + OCR 运行档只钉不相交），并验证方向按钮降进 ⋮ 后在菜单里可点；`planMangaTopBarActions` 两条纯函数用例。修前代码（不降级、胶囊不限宽）跑新增 7 条里 6 条红。
- **备注**：真机 HiBreak（Android 14）装修复后的探针包（独立 applicationId，未动用户装机），`wm size 772x1544` 临时模拟 412dp（已 `reset`）：本地卷顶栏「返回 · 8 / 37 · 方向 · 回到开头 · 设置 · 隐藏 · ⋮」排布正常、胶囊未被压。本地卷没有章节目录按钮、截图时整卷 OCR 已跑完，用户那一档（8 颗 pinned）的真机像素未取到，由 widget 测试覆盖。
