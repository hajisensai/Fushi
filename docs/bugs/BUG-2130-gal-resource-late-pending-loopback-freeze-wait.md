## BUG-2130 · game_resource 行先 pending 后被资源匹配，制卡仍白等一个被丢弃的 loopback 冻结窗
- **报告**：2026-09-03（代理适配 WoH/HUNEX 真机制卡「完整句子音频」时定位；BUG-2127 §2.4 的遗留缺口）
- **真实性**：✅ 真 bug（沿真实代码路径定位）。HUNEX（WoH，`audio=game_resource`）等「资源原件」引擎里，HFA/HW 解包常比文本晚落盘：一行台词到达时 `engine.rawVoiceReady=true` 但 `findPairedVoiceResourceId` 还返回 null（`fushi/lib/src/mining/gal_hook_session_controller.dart:4644-4676`）。此时行被标 `pending` 并仍调 `_scheduleLineAudioAttach`（`:4682`）→ `_attachLineAudio`（`:5056`）在 `resourceReady=true` 下跳过 `grabUtterance`，但 `_audioSource` 是 loopback（资源模式带 loopback 兜底），于是给这一行排了一个 4s 的 `_scheduleLoopbackFreeze`（`:5100`）。资源随后落盘时 `_refreshPendingResourceMatches`（`:5276`）把行提升为 `matched` 并把源资源 id 固化到本行，但**没有撤那个已无意义的冻结定时器**。制卡时 `_lineAudioSettleWait`（`:3019`）看到该行的冻结定时器还在、且「快到点」，就让制卡在入队前 `await _awaitLineAudioSettled`（`:3036`）干等 `剩余 + 1.5s`——而 `_captureAudioBytesNow` 的资源原件分支（`_waitForPairedResourceAudio`，`:3288`）会在首轮直接返回整段源 Ogg，那份 loopback 冻结片段**注定被丢弃**。净效果：用户「台词一出就制卡」白等一个用不上的兜底窗（≤4s+1.5s），且到点的冻结还会抓一段纯 BGM 混音写进本行缓存。BUG-2127 文档 §① 声称「资源原件行零等待」，实际只在「行到达即 matched」时成立；「先 pending 后匹配」这条支路未被覆盖。
- **[x] ① 已修复** — 两处：① `_lineAudioSettleWait`（`fushi/lib/src/mining/gal_hook_session_controller.dart:3019`）在用户裁决判定之后、settle/freeze 判定之前加一条短路：`if (_resourceIdForLine(lineId) != null) return null;`——资源已固化到本行即零等待放行，因为制卡走整段源 Ogg 分支并在首轮返回，冻结片段用不上。② `_refreshPendingResourceMatches`（`:5276`）把 pending 行提升为 matched 时，顺手 `_loopbackFreezeTimers.remove(pending.key)?.cancel()` + 清 `_loopbackFreezeStartedAt`，从根上撤掉这段无意义的兜底定时器（避免到点抓纯 BGM，也让状态干净）。未改资源配对判据、未动 loopback 兜底在「资源始终没落盘」时的正常降级路径（那时 `_resourceIdForLine` 仍为 null，照旧等冻结窗）。
- **[x] ② 已加自动化测试** — `fushi/test/mining/gal_attach_pchooks_loopback_settle_test.dart` 新增用例「BUG-2127 §2.4 game_resource 行先 pending 排了冻结、后被资源匹配提升」：新引擎替身 `_LateResourceEngine`（`rawVoiceReady=true`，配对 id 先 null、`revealResource()` 后返回）驱动「pending → matched」提升，断言制卡零等待（`elapsed < 1500ms`，冻结窗设 4s）、`loopback.backMsCalls` 为空（不回取混音）、行 backend 为 `game_resource`。变异实测：临时回退两处修复 → 该用例等到 4056ms 触发 `elapsed < 1500` 断言红。同文件原 BUG-2127/1287 两例仍绿。
- **备注**：与 BUG-2127 同一「台词一出就制卡拿完整句音频」主题，但归属不同支路：BUG-2127 收口 loopback/引擎 PCM 会话的收敛，本条收口 game_resource 会话里「先 pending 后匹配」时残留的冻结兜底。真机复测随 WoH/HUNEX 制卡 E2E 一并进行（见 BUG-2129）。
