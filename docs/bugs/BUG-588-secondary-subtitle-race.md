## BUG-588 · 副字幕轨就绪竞态致有时不显示
- **报告**：2026-07-07（用户：）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/media/video/video_player_controller.dart:820` `selectSecondarySubtitleTrack`（TODO-857 双字幕 Path A：libmpv `secondary-sid` 自渲染，仅本地内嵌轨）。选副字幕（ffmpeg `0:s:N` 第 N 条内嵌字幕轨）前 `await _waitUntilSubtitleTracksReady(player)`，旧 helper 只要「任意一条」真实轨就绪就早退；随后 `real = tracks.subtitle.where(id!=auto/no)`，`if (streamIndex >= real.length) return false;`。容器多条内嵌字幕轨在 `player.open` 后**逐条异步**解析——选第 2 条（`streamIndex=1`）时若这一刻只解析出第 1 条即早退 → `real.length==1` → `1 >= 1` → 一次性 `return false` 放弃下发，且 `_restoreSecondarySubtitle`（`video_hibiki_page.dart:2459`）是 `unawaited` 一次性调用，失败彻底放弃 → 表现为「副字幕有时候不显示」。手机端 IO 慢更易命中。同款竞态也存在于按 index 选轨的 `selectEmbeddedGraphicTrack:761`。
- **[x] ① 已修复** — 就绪判据从「任意一条真实轨」改为「**目标 `streamIndex` 对应的轨真正就绪**」：`_waitUntilSubtitleTracksReady` 加 `minTrackCount` 参数（默认 1，保持文本字幕默认加载 `_loadEmbeddedSubtitleIfNeeded` 的旧「任意一条」行为不变），按 index 选轨路径（`selectSecondarySubtitleTrack` / `selectEmbeddedGraphicTrack`）传 `minTrackCount: streamIndex + 1`。等待内核抽成可单测的 `waitForSubtitleTrackCount`：事件驱动订阅轨列表变化流，每次醒来复读**当前**真实轨数直到 `>= minTrackCount` 立即完成，最多等 5s（明确超时上界，非硬延迟）；`listen` 之后立即复读一次闭合 check-then-subscribe 竞态。附诊断回读 `secondary-sid` / `secondary-sub-visibility`（仅 `onDiagLog` 非空时，best-effort 不吞新异常）。提交 `__FIXSHA__`（`hibiki/lib/src/media/video/video_player_controller.dart`）。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_secondary_subtitle_track_ready_test.dart`：注入「真实轨数」读取器 + 轨列表变化事件流，验证「只解析出第 1 条时选第 2 条不早退、等第 2 条就绪才完成」「目标轨永不出现时超时返回 false（有界）」「check-then-subscribe 竞态闭合」「到达阈值即停（更高目标轨数需更多轨）」。不依赖真 libmpv。
- **备注**：TODO-1295。副字幕仍是 Path A 纯 libmpv 自渲染（不进 Dart cue 流、不可查词），本修复只解决「按序号选轨越界早退」竞态，不改双字幕架构。未碰 TODO-1246 正在改的 `video_hibiki_page.dart` / `subtitle.part.dart` / `video_subtitle_source.dart`。
