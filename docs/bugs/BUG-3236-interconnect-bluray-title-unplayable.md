## BUG-3236 · 互联客户端打不开蓝光标题（host 把 .mpls 当视频直传）
- **报告**：2026-10-10（用户：互联客户端播放蓝光标题与打开光盘菜单是否可用）
- **真实性**：✅ 真 bug。库里蓝光标题的 `videoPath` 是几 KB 的 `BDMV/PLAYLIST/*.mpls`，本地播放由 `video_player_controller.dart` 的 `resolveBluraySource` + `AacsMediaSession` 变成 `edl://`；互联 host 整条链路没有任何蓝光处理：`packages/fushi_engine/lib/sync/fushi_sync_server/video.part.dart` 的 `/stream` 用 `serveFileWithRange` 把 `.mpls` 本身发出去，播放器一打开就报错；弱网转码的分段命令（`live_transcode.dart` `buildTranscodeSegmentArgs` → `_runSegment`）自己起 ffmpeg 进程，绕开了进程单例外层的 `BlurayFfmpegBackend` 输入改写，同样把 `.mpls` 交给 ffmpeg（`Invalid data found when processing input`）。光盘菜单要 libbluray 读盘目录，远端只有 HTTP 流，属方案的硬限制，入口本就按本地路径形状门控、远端不显示。
- **[x] ① 已修复** — `a930b1459a`：`/streamurl` 对蓝光标题下发段表 `discTitle`（`bluray_remote_title.dart`）+ `edl://` url；新增 token 门控、豁免 Basic 的 `bdclip.m2ts` 分段端点（Range；加密盘经按播放复用的 `BlurayClipRelayPool` 解密回环转发）；client 控制器 `load(remoteDiscTitle:)` 用与本地同一份 `buildBlurayEdlUri` 拼 EDL、逐段过 `nativePlaybackUri`、带 MPLS 章节并按网络源配置；转码分段改走共享的 `runWithBlurayFfmpegInput`（`BlurayFfmpegBackend` 也改用它），`-to` 换成改写器认的 `-t`，时长取 MPLS；能转码的 host 另附低清 HLS 作制卡抽帧源；下载入口明确拒绝光盘标题。
- **[x] ② 已加自动化测试** — `fushi/test/sync/fushi_sync_server_bluray_test.dart`（段表 / Range 直出 / 加密段转发 / 门 / 转码命令经改写 / 制卡流）、`fushi/test/sync/bluray_clip_relay_pool_test.dart`（在途请求不被空闲回收，变异实测会红）；opt-in 原生：`fushi/test/media/video/live_transcode_bluray_native_test.dart`（分段时间轴跨接缝，去掉改写即复现原始报错）、`fushi/test/sync/fushi_sync_server_bluray_native_test.dart`（真 host + 真 mpv 播 EDL 与转码 HLS 并 seek）。
- **备注**：旧 host 的视频清单里没有可认出光盘标题的字段（无路径、bookUid 无标记），client 侧做不到「旧 host 隐藏光盘标题」，修复随 host 升级生效；旧 client 收到的 `url` 是 EDL，明文 http host 下也能直接播。没有做两台真机（host + client）的完整 app 验证：本机验证到「真 FushiSyncServer + 合成盘 + 真 libmpv 当 client」，AACS 加密盘只做了替身转发测试（无可入库的加密盘夹具）。转码 seek 的通用问题拆到 BUG-3237。
