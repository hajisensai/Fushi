## BUG-3609 · 简日内封双语 ASS 重叠、纯日字幕字宽不对（缺原片未定根因）
- **报告**：2026-10-19（用户：应用内反馈 aDMPpG_2eq，Windows 3.0.0；「简日内封字幕重叠，繁日内封大致正常，纯日字幕字宽不对」，片源 [MingY] Romelia Senki [01][WebRip][JPCN].mkv，5 条内封 ASS：JPSC / JPTC / SC / TC / JPN）
- **真实性**：⏳ 未确定。附带日志里没有任何字幕 / ASS 相关记录，没有原片字幕文件（反馈里的磁力链接按规定不打开）。截图只能看出：JPTC 时中文在上、日文在下正常竖排；JPSC 时中文落在日文那一行的位置（与日文叠在同一基线）；JPN 时日文字形明显横向压窄。重叠只会发生在「尊重字幕自带样式」开（纯字幕模式整层折一个堆叠组、按文本去重，结构上不会叠印）。
  - 已查到的**候选机制**（都只是候选，未用原片证实是用户这条）：
    1. `_mergeBottomBaselineGroups`（`fushi/lib/src/media/video/video_subtitle_overlay.dart:1590` 起）只在桶内文本两两互异时合并底部基线组；桶里出现任何重复文本（例如中文对白另有一条同文本的光晕 / 阴影层）就 `if (!distinct) return;`（`:1631`）整桶不合并，日文组与中文组各自锚到同一底基线 → 叠印。JPTC 若没有这层重复就正常，能解释「简日叠、繁日不叠」。
    2. 底部组归入基线桶的判据比原始 MarginV（`isBaselineBucketMarginV`，`:3639`），渲染基线用缩放后的 MarginV（`resolveBottomBaseline`，`:3621`）。原始 MarginV 略大于用户基线、但缩放后（窗口高 < PlayResY）又不超过用户基线的那条样式，会单独成组却画在同一基线上 → 叠印。这条与简繁无关，除非两份字幕的 MarginV 不同。
    3. 纯日「字宽不对」：渲染层按样式 ScaleX / `\fscx` 横向缩放（`:2425`、`:2528`），与 libass 同语义；若原字幕样式本就 ScaleX<100 则 mpv 下同样窄，若字体缺失回退到别的字体也会显得不同。没有样式表无法判断是否偏离 libass。
