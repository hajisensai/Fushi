## BUG-873 · Galgame 制卡缺少绑定游戏窗口截图 Picture
- **报告**：2026-07-18（用户：希望 Galgame 制卡时截取当前绑定游戏窗口，并把图片写入新卡 `Picture` 字段）
- **真实性**：✅ 真 bug。已有 Windows Graphics Capture 单帧能力，但 Galgame occurrence 在 `hibiki/lib/src/mining/galgame_audio_capture_controller.dart:177` 原本只导出进程音频；主查词页、桌面浮层与覆写路径构造 `AnkiMiningContext` 时也只注入 `sasayakiAudioPath`，没有 `coverPath`，因此默认 `Picture -> {card-image}` 必然为空。
- **[x] ① 已修复** — 同一 occurrence 在 Luna 剪贴板文本到达、游戏仍在前台时即对已绑定 `HWND` 发起窗口截图，制卡时复用该结果并与 650ms 音频后摇/导出并行；仅保留最近 8 个截图 Future，避免积压大图。Windows native 先尝试 `PrintWindow(PW_RENDERFULLCONTENT)` 并检查客户区黑帧，失败后用 UI `DispatcherQueueTimer` 主动轮询 FreeThreaded WGC 帧池（不注册 `FrameArrived`），300ms 无帧则裁取当前可见桌面中的窗口区域。截图沿既有制卡压缩设置输出 PNG 或 JPEG。`dictionary_page_mixin.dart`、`home_dictionary_page.dart`、`overlay_bridge_handlers.dart` 的新卡与覆写路径都把截图注入 `coverPath`。Galgame 图片和句音频均为必需媒体：任一路失败则中止制卡并清理另一条临时文件；AnkiConnect 在 `addNote/updateNoteFields` 前严格上传截图，成功后通过 `{card-image}` 写入 `Picture`。
- **[x] ② 已加自动化测试** — `hibiki/test/mining/galgame_audio_capture_controller_test.dart` 覆盖绑定 `HWND`、文本 occurrence 即开始截图、音图并行导出、WAV 回退、截图失败与临时文件清理；`hibiki/test/mining/window_capture_channel_test.dart` 钉住客户区黑帧检查、300ms WGC 上限、桌面回退和禁用 `FrameArrived`；`hibiki/test/lookup/overlay_mine_sentence_behavior_test.dart` 和 `hibiki/test/pages/home_dictionary_galgame_mining_context_test.dart` 分别走真实浮层/主查词页制卡路径，断言仓库调用时截图存在且 `requireCover=true`；`packages/hibiki_anki/test/media_filename_guard_test.dart` 覆盖 Picture 上传顺序、字段渲染与上传失败不建卡。
- **验证证据**：Windows debug runner 对真实外部 File Explorer `HWND` 输出 276×45 非黑 PNG，像素与该窗口当时仅标题栏的真实状态一致；该 PNG 经本机 AnkiConnect `storeMediaFile` 上传、`retrieveMediaFile` 取回后字节数均为 1640 且 SHA-256 一致，随后已 `deleteMediaFile`，未创建测试卡。本机 programmatic WGC 对 Explorer 持续无帧，故三层回退不是理论分支而是必要兼容。
- **备注**：实际 Galgame 的 `PrintWindow` / WGC 行为依赖渲染器与进程权限；桌面裁剪只保证当前可见像素。已把截图前移到文本 occurrence 以降低 Hibiki 遮挡概率，发布前仍应以 LunaTranslator + 实际游戏做一次原始流程 smoke test；若游戏以管理员权限运行，Hibiki 也应使用相同权限。
