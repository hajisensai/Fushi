## BUG-2487 · Windows 更新 toast 无应用图标，app 新版本条目跳浏览器而非应用内更新
- **报告**：2026-09-12（用户：「这个更新提醒，缺少图标，而且更新应该直接在app内更新啊，哪有跳转到外面的说法」）
- **真实性**：✅ 真 bug，两条根因：
  - 图标：v101 更新中心投出的 Windows toast（`LocalUpdateNotifier._windowsDetails`）XML 里没有任何 `<image>`（`ToastNotificationManager.History` 实查），头部图标全靠注册表 `HKCU\Software\Classes\AppUserModelId\com.hibiki.fushi\IconUri`。`local_update_notifier.dart:106` 的 `bundledAssetPath` 用 `p.join` 拼 `assets/meta/icon.png`，asset 名里的 `/` 原样混进 Windows 路径，注册表里实际是 `D:\APP\Hibiki\data\flutter_assets\assets/meta/icon.png`；文件存在但 toast 头部为空。
  - 跳外部：`updates_center_open.dart:74` 对 `UpdateFeedKind.appRelease` 硬写 `launchUrl(releaseUrl, externalApplication)`；更新中心条目、toast 本体、toast「打开」按钮（`AppModel._onUpdateNotificationResponse` → `openUpdateFeedEntry`）三个入口都落到它。而设置页「立即检查更新」（`settings_schema_system.dart` 的 `_checkUpdateNow`）早就是完整应用内链路（检查 → `UpdateAvailableDialog` → `_downloadAndInstall`），更新中心没接它。
- **[x] ① 已修复** — `0746ffcd30`：`bundledAssetPath` 按 `/` 拆段 `joinAll`；每条 toast 追加 `WindowsImage(appLogoOverride)` 指向同一张随包图标（文档保证的显示位，不再赌 shell 对注册表值的解析）。手动检查编排抽成 `fushi/lib/src/updates/app_update_check.dart` 的 `checkAppUpdateNow(context, appModel)`，设置页与更新中心 appRelease 共用；`updates_center_open.dart` 不再 import `url_launcher`。iOS/Linux 不能自装的情况由 `UpdateChecker` 既有的 `_showFallbackDialog`（TestFlight / App Store / 发布页）处理，无特例。
- **[x] ② 已加自动化测试** — `fushi/test/updates/local_update_notifier_test.dart`（`bundledAssetPath` 无 `/`；toast 带 `appLogoOverride`；图标文件不在不挂）；`fushi/test/settings/manual_update_check_guard_test.dart`（编排守卫改指新文件 + 「更新中心 appRelease 走 `checkAppUpdateNow`、文件内无 `launchUrl(`」不变式）。
- **备注**：真机 toast 头部图标未在本轮实测（用户桌面正在使用，未开通知中心；PowerShell 探针 toast 未出现在截图里，疑专注助手）。注册表 `IconUri` 路径修正在下次 `initialize()` 时重写。
