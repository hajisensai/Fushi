## BUG-5520 · SSH 传输断开后 SFTP 请求永远挂起：同步卡死、「本地 vs 远端」对比弹窗一直转圈
- **报告**：2026-11-25（GitHub issue #4331，Android S25 Ultra，Debug 31327：对比弹窗只有转圈；日志成对的 `UncaughtZone SSHStateError(Transport is closed)` 与 `SyncBackendError: Connection failed: Software caused connection abort`）
- **真实性**：✅ 真 bug。Android 掐掉 SFTP 的 socket（切后台 / 换网）时，dartssh2 2.11.0 两处缺陷：
  1. `SftpClient` 构造里 `_channel.stream.listen(_handleData)`（pub cache `dartssh2-2.11.0/lib/src/sftp/sftp_client.dart:31`）没有 `onDone` / `onError`：频道结束后 `_replyWaiters` 与未完成的握手永不完成，在途请求永远挂起。`SftpSyncBackend._guarded`（`fushi/lib/src/sync/sftp_sync_backend.dart` 的 `_opLock.withLock`）被这个请求一直占着，后面所有 SFTP 操作排在它后面；`_ensureConnected` 本来会因 `isClosed` 重连，但轮不到它。对比弹窗 `loadSyncCompareData` 在 `runExclusiveWithSync` 下跑，排在卡死的同步后面，只能转圈到重启。
  2. 传输关闭时 `SSHClient._handleTransportClosed` → `_closeChannels` → `SSHChannelController.destroy()`（`ssh_client.dart:458`、`ssh_channel.dart:217`）往已关闭的传输发 EOF，`SSHTransport.sendPacket` 抛 `SSHStateError`：`_done` 没完成、`_closeChannels` 循环中断、`_channels` 不清；上传循环随后 `close()` 再抛一次（`ssh_channel.dart:344`）。这就是日志里那对未捕获错误。
- **[x] ① 已修复** — `ci/patches/hosted/dartssh2-2.11.0/` 补丁：`SftpClient` 频道流加 `onDone: close` / `onError: _closeError`，关闭时失败握手与全部等待者（`SftpAbortError`），关闭后发出的请求立即失败，无人监听的 `_done` completer 换成布尔标记；`SSHChannelController.abandon()` 只在本地拆频道不发消息，`_closeChannels` 在传输已断时走它。请求能及时失败后，`_guarded` 原有路径把它译成可重试的 `SyncBackendError` 并断开，下一次操作自动重连。不加超时。
- **[x] ② 已加自动化测试** — `fushi/test/sync/sftp_dead_transport_test.dart`：真 `SSHChannelController` + 打补丁的 `SftpClient`，传输「关闭」后发送即抛（与 `sendPacket` 相同）：在途请求 / 未完成握手 / 关闭后新请求都以 `SftpAbortError` 失败，`close()` 重复调用不抛，`SftpSyncBackend` 的操作以可重试错误失败并释放 op 锁、下一次操作拿新连接发出请求。未打补丁时 5 条全红（挂起超时 / close 抛错）。
- **备注**：`SSHClient._closeChannels` 那一处没有单测（要假 SSH 握手），由补丁说明与 `abandon()` 单测覆盖语义；待 Android 真机上 SFTP 同步中切后台复测（本机没有 SFTP 同步配置的真机环境）。
