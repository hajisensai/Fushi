## BUG-3003 · Windows 视频页热重启调用已销毁的 Dart 回调导致原生崩溃
- **报告**：2026-10-06（用户：视频页开着时热重启必现；CC 提供三个进程崩溃记录）
- **真实性**：✅ 真 bug。media_kit 1.2.6 的 `lib/src/player/native/core/initializer_native_callable.dart:50` 注册 isolate 所属 `NativeCallable.listener`；正常 dispose 才在该文件第 67 行解除。Flutter 热重启销毁 isolate，却保留 libmpv handle；`lib/src/player/native/player/real.dart:45` 在新 isolate 中回收旧 handle 时直接发 `quit`。旧播放器的后台事件或回收命令均可能调用已失效函数地址；仅在新 isolate 回收前解绑仍留下重启间隙。
- **[x] ① 已修复** — 本 BUG 同一修复提交：`ci/patches/hosted/media_kit-1.2.6/lib/src/player/native/core/initializer.dart` 在 Windows debug 复用上游 `InitializerIsolate`，create/dispose 共用一个选择条件。以 `mpv_wait_event` + SendPort 消费事件，不再向 libmpv 注册 Dart 函数地址。profile/release、其他平台保持原选择。经现有 bootstrap/apply-patches 分发，清理条件见补丁 `PATCHES.md`。
- **[x] ② 已加自动化测试** — `fushi/test/third_party/media_kit_hot_restart_test.dart` 与 `fixtures/media_kit_isolate_exit_probe.dart`。真实子进程/真实 libmpv：等 owner 与 worker 全部退出，排空合并通知后再 wakeup/quit；正常 dispose 同样验证。检查子进程退出码和必经标记，缺 Windows DLL 时明确 skip，另守卫精确版本与 create/dispose 一致性。
- **根因证据**：17:06 / 17:24 / 17:47 三份 WER dump 的异常线程均在 `libmpv-2.dll+0x100e9a7: call rax` 调用 wakeup callback 时发生执行 AV。PE unwind 与逐层 callsite 校验定位到 libmpv 后台线程；callback/userdata 字段与同 DLL 的 `mpv_set_wakeup_callback` setter 一致。独立原始依赖探针报 `Callback invoked after it has been deleted`，退出 `-1073740791`；补丁版 kill/dispose 均退出 0。
- **真实修前复现**：同 worktree 的 Windows Debug 视频页首次热重启即触发执行 AV；watchdog dump 保存的原始异常为 `0xc0000005`，旧 handle `552085171232` 与 `NativeReferenceHolder Disposing` 日志一致。调用点为该 DLL 的 `libmpv+0x100d693: call rax`，callback/userdata 字段同样为 `+0xa8/+0xb0`。CrashRpt 的异常消息框留住进程，外观为卡死；确认 dump 后仅终止自启 PID 26004，不能把随后 Lost connection 当作自然退出。
- **真实修后验收**：Flutter 3.47.6，实际 app main/VideoFushiPage、真实 libmpv、120 秒本地 H.264 视频。视频页保持打开连续 **9 次 full hot restart**，每轮解码尺寸 320×180、playing=true、播放位置推进，并保存视频截图；无新增 crash/hang dump。测试 harness 曾尝试 Esc 退出，但状态和截图表明页面仍在，因此只计为视频打开时的 9 轮，不声称验证了正常关闭页面。定向测试 **3/3 通过、无 skip**（首轮测试启动器使用不受支持的 `Isolate.packageConfig`，改用 workspace 根配置后通过）。全量 analyze 返回 1：4 个 warning、1 个 info，均在与基线 `685c4eb059c` 内容一致的其他文件，本次改动无诊断；详情见本地 `analyze.log` 与 `analyze-baseline-verification.txt`，不宣称全库分析通过。
- **本地证据**：`.codex-test/crash-1006/` 下 `dump-analysis.md`、`baseline-hang-analysis.md`、`baseline.log`、`fixed.log`、`fixed-result.json`、`data-fixed/video-*.png` 与探针日志。验证使用本 worktree 的依赖副本，未把新补丁写入共享 pub cache；接收提交后须 bootstrap 应用补丁并冷启动一次。
- **边界**：Windows debug 每个播放器使用额外事件 isolate；热重启由 Flutter 工具关闭其 worker。原生视频 render-context 析构顺序/异步 Dispose 的独立风险仍待修，本提交不宣称解释交接中的 16:11 堆损坏事件。
