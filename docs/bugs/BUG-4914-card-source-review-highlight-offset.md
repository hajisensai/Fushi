## BUG-4914 · 小说卡片「来源」回看高亮整体错位（落到后面的词上）
- **报告**：2026-11-20（用户：应用内反馈 -zZGX0tQL2，Android，3.3.0-debug.28910）。制卡词「真っ当な」，例句「真っ当な理由」，从卡片跳回来源后高亮落在「理由」」上。日志：`restore from bookmark ... charOffset=847`、`jump target mark chapter=39 [847,853)`——长度 6 正是整句「真っ当な理由」，起点却偏后。
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/pages/implementations/reader_fushi/mining.part.dart:64`（修前）：制卡写 `CardSourceLink.charOffset/charLength` 用的是 `_miningSpanRange()`（`audiobook.part.dart:1291`），它返回 `_cachedMatchableSentenceRange`——JS `getMatchableOffset` 的**音频匹配坐标**（`readerRegex` 白名单 UTF-16 码元数，拉丁 / 数字逐字母计、全角字母数字逐码元计）。而回看端 `fushi/lib/src/anki/card_source_router.dart:505` 把它原样当 `Bookmark.charAnchor`，`scrollToCharOffset` 与落点句标记（`_jumpTargetSpan`）按**学习单位坐标**（`getNormalizedOffset` / `nodeStartOffsets`，`countStudyChars` 口径）落位，`validateReaderSourceLocator` 也按学习单位校验。两把尺子不同：句前每多一个拉丁词 / 数字串等，匹配坐标就比学习单位多出若干，回看高亮整体往后偏。同一个值还经 `_recordMinedSentence` 写进了制卡历史 `mined_sentences.norm_char_offset`，制卡历史跳转同样偏。三种 view mode（paginated / continuous / vn）共用这一组坐标，问题与模式无关。
- **[x] ① 已修复** — 新增 `readerSourceStudySpan`（`fushi/lib/src/reader/reader_source_locator.dart`）作为来源锚点的唯一口径：学习单位、句级优先、退到选区；`mining.part.dart` 的 `_miningStudySpan()` 统一供 `CardSourceLink`、制卡历史与制卡位置使用。音频区间（`startMs/endMs`）仍走 `_miningSentenceAudioClip` 的匹配坐标，不受影响。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_source_study_span_test.dart`：helper 句级优先 / 选区回退 / 匹配坐标与学习单位不同的 payload 取学习单位；源码守卫钉住 `_prepareMiningContext` 的来源范围取 `_miningStudySpan()`、不再取 `_miningSpanRange()`，且制卡历史与制卡位置共用同一口径。
- **备注**：修复前已写进 Anki 卡片 / 制卡历史的旧来源链接仍是匹配坐标，无法事后换算（卡里没存原文位置的另一口径），这些旧卡回看仍会偏；新制的卡正确。WebView 真机三种 view mode 复测未做（JS 端两套坐标函数本次未改，修复只换了 Dart 侧选用的那一组）。
