## BUG-2604 · AV1 视频制卡截帧/动图/片段导出恒 ffmpeg exit 69：捆绑 ffmpeg-min 只有 hwaccel 空壳的原生 av1 解码器
- **报告**：2026-09-19（用户：「i just tried to export a clip and it gave me an "ffmpeg conversion failed" error」；日志 `extractVideoFrameViaFfmpeg` / `extractClipGifViaFfmpeg` 各一条 `ffmpeg exit 69; executable=…\AppData\Local\Hibiki\ffmpeg.exe; stderr=Conversion failed!`，句子音频那条没报错）
- **真实性**：✅ 真 bug。本地「复现不了」只是因为测试视频不是 AV1 编码。
  - 根因 `tool/ffmpeg-min/build-ffmpeg-min.sh:201`（`DECODERS=`）列的是 FFmpeg **原生 `av1`** 解码器，没有 `libdav1d`。原生 `av1` 只是 hwaccel 挂钩壳（libavcodec/av1dec.c；allcodecs.c 注明 "hwaccel hooks only, so prefer external decoders"），而配方 `--disable-everything` 后 `ffmpeg -hwaccels` 为空 → 任何 AV1 源每一帧都是 `Your platform doesn't support hardware accelerated AV1 decoding. / Failed to get pixel format.` → `Decode error rate 1 exceeds maximum 0.666667` → **exit 69**（fftools 对解码错误率超限的专用退出码）。凡解视频流的链路全挂（截帧、GIF/WebP/AVIF 动图、片段导出、书架封面），只解音频的句子音频正常——与用户日志形态一致。
  - 实证：用入库 `third_party/ffmpeg-min/windows/ffmpeg.exe`（n7.1.5）对 libsvtav1 编的 3 秒样本跑 app 的截帧 / 动图参数，两条都 exit 69 + `Conversion failed!`，音频裁剪 exit 0。
  - 并发症 `packages/fushi_engine/lib/media/video/ffmpeg_backend.dart:127`（`extractFfmpegFailureReason`）：从尾向首取第一条含错误关键词的行，而 ffmpeg 任何非零退出都以 `Conversion failed!` 收尾（命中 `failed`），于是摘要永远只有这句零信息量的尾行，真因整个被吞——用户和日志都无从看出「是 AV1」。
- **[x] ① 已修复** — 配方 `DECODERS` 改 `libdav1d` + `--enable-libdav1d`（三平台装依赖；macOS 走 `build_darwin_static_deps` 用 meson cross file 静态自编 dav1d 1.5.1），`.github/workflows/ffmpeg-min.yml` 重编后 Windows/macOS 二进制重新 vendor；`extractFfmpegFailureReason` 跳过泛用尾行，并在有 `Stream mapping:` 锚点时把锚点后第一条错误行（根因）与尾部错误行（后果）一起给出。提交见本 PR。
- **[x] ② 已加自动化测试** — `tool/ffmpeg-min/smoke-test.sh`「decoding an AV1 source (libdav1d)」：断言 `-decoders` 含 libdav1d，再用 fixture ffmpeg 编 AV1 样本、按 app 的截帧与 GIF 参数真解一遍（旧 exe 上实测红在 `MISSING DECODER`）；`fushi/test/tools/ffmpeg_min_vendored_recipe_guard_test.dart` 的 `_requiredStandaloneFlags` 加 `--enable-libdav1d`（漏 vendor 直接红）；`fushi/test/media/video/video_clip_exporter_test.dart` 新增 BUG-2604 逐字 stderr 用例，摘要必须以 `Your platform doesn't support hardware accelerated AV1 decoding.` 开头而非 `Conversion failed!`。
- **备注**：用户机上若 PATH 有全量 ffmpeg 也救不了——`_runCliFfmpeg` 只在捆绑 exe 根本没跑起来（无 stderr / STATUS_INVALID_IMAGE_FORMAT）时回退 PATH，exit 69 带完整 stderr 不回退；这是有意的（避免把「捆绑 exe 能力不足」静默换成机器相关行为），修法就是让捆绑 exe 具备能力。
  **移动端同型缺口未修**：入库的 `third_party/ffmpeg_kit_flutter` Android AAR 与 iOS xcframework 的 configure 串都没有 `--enable-libdav1d`（也没有 `--enable-mediacodec` / videotoolbox hwaccel），libavcodec 里只有原生 av1 壳（含 "support hardware accelerated AV1 decoding" 字串、无 `libdav1d` 符号）——AV1 视频在移动端制卡截帧/动图应同样失败。移动端二进制是 Mac 上用 ffmpeg-kit 的 `android.sh` / `ios.sh` 手工编的（配方不在本仓），需要单独一轮 `--enable-dav1d` 重编 + 重 vendor，并给 `ffmpeg_kit_mobile_recipe_guard_test.dart` 补 `--enable-libdav1d` 断言。
