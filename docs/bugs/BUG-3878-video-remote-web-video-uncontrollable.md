## BUG-3878 · video-remote-web-video-uncontrollable
- **报告**：2026-10-29（用户：「遥控器如果打开的是浏览器的视频会无法控制」；追加「全部能力补齐」）
- **真实性**：✅ 真 bug。手机视频遥控器只认 `VideoRemoteHost.register` 登记过的绑定（`fushi/lib/src/sync/video_remote_host.dart` `register`），全仓只有原生播放器页本地 / 远端片源在 `_applyLoad` 里登记（`fushi/lib/src/pages/implementations/video_fushi_page.dart` `_registerVideoRemote(controller)`）。网页视频的三种形态都没登记：原生播放器页网页档 `_initWebSource`（`video_fushi/web_source.part.dart`）、内置网页播放器页 `WebVideoFushiPage`、app 内浏览器 `FushiWebBrowserPage`（扩展宿主），手机一直停在「等待电脑打开视频」。
- **[x] ① 已修复** — 三种形态都登记遥控绑定，能力与原生播放器对齐（播放 / 暂停 / 跳转 / 句子列表 / 试听 / 音量 / 字幕轨 / 在线字幕 / 收藏 / 制卡 / 关闭；网页没有的选集与选词光标不报能力）。共用件抽到 `fushi/lib/src/media/video/video_remote_binding_support.dart`（句子行缓存、制卡请求解析、收藏匹配、留白时间窗、下载字幕解析）。网页档字幕按「站点视频 → 轨」管：手机下载的在线字幕登记成一条轨再选中；制卡 YouTube 走服务端按时间窗裁剪，其它站点进网页制卡队列。app 内浏览器：新控制器 `fushi/lib/src/web_browser/features/extension_host/web_browser_video_remote.dart` 跟前台标签页的正片登记 / 注销，经扩展宿主向页内 `subtitle-panel.js` 新增的 `fushiRemoteState` / `fushiRemoteControl` / `fushiRemoteMineContext` 取状态、下命令（真扩展不发这三条，零影响）；制卡 YouTube / B 站服务端裁剪，其它站点当前帧 + 句子（无句子音频），Netflix 回 `video_extraction_unavailable`。宿主 `VideoRemoteHost` 改为按登记顺序保留仍开着的播放器，当前的关掉后回落到压在下面的那个（浏览页开在视频页上面、或反过来，关掉上层后手机不再变成「没有视频」）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_remote_binding_support_test.dart`（共用件）、`fushi/test/sync/video_remote_web_playback_wiring_test.dart`（两个网页播放页的登记与分流接线；页面依赖 WebView2，无可注入缝）；`fushi/test/web_browser/features/extension_host/web_browser_video_remote_test.dart`（接真 `VideoRemoteHost`：登记 / 切标签 / 换视频 / 命令 / 查词续播 / 试听 / 字幕 / 收藏 / 制卡分流 / 上下层回落）、`tools/browser-extension/video-remote.test.js`（页内消息）。
- **备注**：未在真机上用手机遥控实测（需 Windows 端 WebView2 + 已配对手机）；非 YouTube 站点的遥控制卡进队列，手机显示「已在电脑制卡」，实际要等电脑端跑队列才落卡。
