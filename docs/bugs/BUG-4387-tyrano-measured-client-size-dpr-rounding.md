## BUG-4387 · TyranoScript 内嵌查词在 Electron 全屏 + 小数缩放下永远不出卡：DOM 推算的客户区与真实客户区差 1px 被逐像素拒收
- **报告**：2026-11-11（用户：「内嵌查词好像失效了」，截图为 ユリアリス 窗口；Windows 3.3.0-debug.26444，经 Fushi 启动）
- **真实性**：✅ 真 bug（本机原始路径实测）。DOM 会话正常（台词进 texthooker、`tyrano_dom.voice_stored` 逐句在记），查词面也已武装（`gal-overlay: attachedReady=true … status=waitingForBodyThread/measured_waiting_complete_line`），但 `%TEMP%\hibiki_glookup.log` 里每一句都是 `gal-attached-measured: update_rejected reason=measured_client_size_mismatch measured=3840x2160`。实测游戏窗口客户区（per-monitor DPI aware）为 **3840x2159**，页面 `innerWidth/innerHeight = 2560x1440`、`devicePixelRatio = 1.5`、`document.fullscreenElement` 非空——Electron 全屏在 Windows 上窗口比屏幕矮 1px，而 Chromium 把 2159/1.5 = 1439.33 向上取整成 1440 CSS px，Dart 侧 `round(1440 × 1.5) = 2160`（`fushi/lib/src/mining/tyrano_dom/tyrano_dom_frame.dart:308-309`）。runner 的判据 `ClientSizeMatches`（`fushi/windows/runner/attached_measured_layout.h:136`，原实现）要求两者逐像素相等，于是每份测量都被拒收、旧框撤掉、卡永远不出。根因是判据本身：DOM 给的客户区尺寸是「整数 CSS 视口 × 小数 dpr」推出来的，天然带不到一个 CSS 像素的量化误差，逐像素相等在任何非整数缩放下都站不住。
- **[x] ① 已修复** — 量化容差随测量一起上 wire：Dart 端 `galAttachedMeasuredClientSizeTolerance(dpr)`（`fushi/lib/src/lookup/gal_attached_measured_frame.dart`；整数 dpr 容 `dpr−1`，dpr=1 时仍逐像素相等；小数 dpr 容 `ceil(dpr)`）写进 `GalAttachedMeasuredPayload.clientSizeTolerance`，经 `attachedUpdateMeasuredText` 的 `clientSizeTolerance` 参数传给 runner；`ClientSizeMatches` 改为在容差内一致即可，容差夹到 `kMaxClientSizeTolerance = 4`，Electron 菜单栏 / 真实重排（几十 px）照旧拒收。三处判定（`UpdateMeasuredText`、`SyncToTarget`、`RebuildMeasuredClusters`）共用同一份已存容差。
- **[x] ② 已加自动化测试** — C++ `fushi/windows/runner/tests/attached_measured_layout_test.cpp` `TestClientSizeMatches`：3840x2160 对 3840x2159 在容差 0 时拒、容差 2 时收，2127（菜单栏量级）与超大容差（被夹）仍拒；Dart `test/lookup/gal_attached_measured_route_test.dart` 覆盖容差公式与 2560x1440@1.5 帧的载荷，`test/platform/gal_attached_measured_channel_test.dart` 断言 wire 参数。
- **备注**：修复后未在原始路径（重建 fushi.exe → Fushi 启动 ユリアリス 全屏 150%）复测弹卡与「点击查词不推进」，TyranoScript 仍是 `implemented_unverified`，`engine-support.yaml` 不升级。
