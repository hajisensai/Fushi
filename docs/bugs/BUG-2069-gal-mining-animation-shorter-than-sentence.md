## BUG-2069 · galgame 制卡动图固定 1.25 秒不覆盖整句语音
- **报告**：2026-09-03（用户要求「制卡要有视频、完整句子音频」；SGRE 真机 E2E 制出的卡：SentenceAudio 3.19 s AAC 是整句，Picture 却是 10 帧 / 8 fps = 1.25 s 的 AVIF 动图，比语音短一大截）
- **真实性**：✅ 真 bug（与需求不符）。`fushi/lib/src/mining/galgame_window_gif.dart` `captureWindowGifBytes` 的帧数是常量 `frames = 10`，与本句时长无关；`fushi/lib/src/mining/gal_hook_mining_coordinator.dart:300` 音频与动图并行采集，但两者之间没有任何数据流，动图不知道语音多长。资源音频路径（`gal_hook_session_controller.dart` `game_resource` 分支）也从不写 `durationMs`，条目上没有时长可用（PCM 路径在 `_encodeLineSlice` 里写了）。Lapis 模板的 `Picture` 字段是 `<img>`，卡片里的「视频」就是这张动图（`{video-clip}` 只是 `{card-image}` 的旧别名），所以动图时长 = 卡片视频时长。
- **[x] ① 已修复** — ① `galgame_window_gif.dart`：新增 `targetDuration: Future<Duration?>`，采样循环至少抓基线 10 帧，之后按 `galAnimatedFrameBudget`（回放 fps 下覆盖整句、上限 `kGalAnimatedMaxDuration` 8 s）收口；时长尚未到达（引擎 PCM 要等语音播完）期间继续采样——语音在播的正是这句的画面。② `gal_hook_session_controller.dart` 资源音频路径用 `adts_duration.dart`（纯 Dart 读 ADTS 帧头）把 `durationMs` 写到行条目。③ `gal_hook_mining_coordinator.dart` 生产路径把「音频字节回来后从条目读 `audioDurationMs`」作为异步目标喂给采样循环；注入捕获器的测试路径不变。**审查补 ④（B4，同一 PR 内）**：原实现里 budget 只决定**何时停止**、不裁剪已落盘的帧 —— `pending` 期间 budget 直接是 8 s 上限（64 帧），等 `targetDuration` 解析出 null 时 budget 掉回基线，但 `i` 可能已到 30~60，那 30~60 帧仍会**原样进 ffmpeg**，所以「null 退回 `frames` 帧的旧行为」这句话原本不成立（纯函数测的是文档语义、循环跑的是另一套）。新增 `trimSurplusAnimationFrames`：编码前把落盘帧裁到最终预算（image2 从 `frame_000` 连读到第一个缺号为止，删尾部即截断序列），帧名/输入模式收成 `galAnimationFrameName` + `kGalAnimationFramePattern` 同一处真相源。
- **[x] ② 已加自动化测试** — 分两层。**纯函数层**：`fushi/test/mining/gal_animated_frame_budget_test.dart`（3.19 s → 26 帧、未知时长维持基线、未到达期间维持采样、8 s 上限）、`fushi/test/mining/adts_duration_test.dart`（帧头求和、截断尾帧不计、非 ADTS/保留采样率返回 null，**审查补** `frame_length < 7` 判损坏 —— 缺这道守卫 offset 不前进、`adtsDurationMs` 死循环，变异实测是 300 s 无输出挂死而不是普通红）。**生产接线层（审查补；此前三处全部零覆盖、三条变异全存活）**：① `fushi/test/mining/gal_window_gif_duration_wiring_test.dart` —— mock `window_capture` MethodChannel + `setFfmpegBackendForTesting` 注入假编码器（编码时数目录里真实存在的帧文件），直接观测「采样了几次」和「几帧交给了 ffmpeg」；钉住无时长 = 基线帧数、时长未定期间继续采样、定下来后按预算收口且落盘帧被裁到预算、解析为 null 时多抓的帧被裁回基线。② `fushi/test/mining/gal_hook_session_controller_test.dart`「BUG-2069：配对到的资源语音必须把整句时长写回行条目」—— 喂 43 帧合成 ADTS，断言行条目 `audioDurationMs == 998`。③ `fushi/test/mining/gal_mining_animation_duration_wiring_guard_test.dart`（源码守卫）—— 编排里那段接线**结构上测不到**：`_captureGifUsesDefault` 只有在不注入捕获器时为真，而注入捕获器正是所有编排测试造替身的方式，生产分支在测试里永远不执行；守卫钉「生产调用点带 `targetDuration:`」且「该实参由 `audioFuture` + `audioDurationMs` 派生」，不只是钉参数名。变异实测（改坏 → 确认真红 → 按唯一锚点还原 → sha256 对基线）：采样循环预算换成常量 → 2 条红；去掉裁帧 → 「Expected <4> Actual <12>」；`durationMs` 置 null → 「Expected <998> Actual <null>」且同文件其余 50 条仍绿；编排整行删 `targetDuration:` → 守卫红，且**关掉该守卫后 `test/mining` + `test/pages` 共 4476 条全绿**（即此前确实零覆盖）。
- **备注**：动图在制卡时刻开始抓，不是回放式的「这句期间」录像；用户在语音播完很久后再制卡，画面就是当时的静止画面。要做到真正按台词时间窗回放，需要会话期间常驻环形抓帧（WGC 连续采样 + 卡片可见期间剔帧），本轮未做。**已知代价（审查记录）**：capture lease 的持有窗口从固定 ~1.2 s 拉长到最多 8~12 s 墙钟——lease 期间游戏内查词卡与高亮是隐藏的，用户会看到它消失更久；这是「动图覆盖整句」这条需求的直接代价，不是回归，要缩短只能靠上面那个常驻环形抓帧方案。**真机复验仍未做**（待新构建）：上面的自动化只证明三段接线与裁帧在单测层成立，不证明真机 E2E 动图确实与语音等长。
