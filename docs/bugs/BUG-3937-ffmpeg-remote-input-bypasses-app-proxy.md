## BUG-3937 · ffmpeg-remote-input-bypasses-app-proxy
- **报告**：2026-11-01（用户：反馈 vhW6OpRy2H，Windows，App 3.0.0，香港网络：「chrome 插件看 youtube 无法制卡：网页插件生成卡片后全消失了，anki 没有」）
- **真实性**：✅ 真 bug。浏览器扩展 YouTube 制卡的句子音频先由 Dart range 物化（`materializeRemoteAudioViaRangeDownload`，经 `createAppHttpIoClient` 走 app 代理）——日志里 `HandshakeException: Connection terminated during handshake`；失败回退 ffmpeg 直读 googlevideo，而 `packages/fushi_engine/lib/utils/misc/desktop_audio_clipper.dart` 的 `buildFfmpegRemoteInputArgs` 只在宿主中继路由时传 `-http_proxy`，直连远端时**完全不带用户在 app 里设的代理**（手动地址 / 自动模式下的系统代理）→ `ffmpeg exit -138`（Windows ETIMEDOUT）。requireAudio=true（有意设计，不出无声卡）→ 整张卡中止；扩展 toast 只给出 `required audio missing (HandshakeException…)`，普通用户读不懂。
- **[x] ① 已修复** — ffmpeg 远端输入与 Dart 出站共用同一份代理裁决：`app_proxy.dart` 新增 `resolveAppProxyUrlForExternalClient`（地址取 `resolveAppProxyDirective`，凭据取 `resolveAppProxyCredentials`，百分号编码 userinfo；自动模式下环境变量给的是 SOCKS 时如实返回 `socksUnsupported`、不冒充），`buildFfmpegRemoteInputArgs` 在没有中继端点时用它填 `-http_proxy`（中继优先；直连裁决不传）。网络类中止原因由 `isRemoteFetchNetworkFailure` 判定，`youtubeMineAbortMessage`（app_model.dart）回给扩展一句「连不上 YouTube 视频服务器（网络或代理问题），请在网络代理里配置」+ 原因。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/ffmpeg_app_proxy_args_test.dart`（手动代理 / 凭据编码 / 直连 / 本机目标 / 中继优先 / SOCKS 判定 / 网络失败判定 / 用户消息）；`ffmpeg_remote_input_route_args_test.dart` 钉直连模式免受跑测机器环境变量影响。
- **备注**：直连裁决下 ffmpeg 仍按自身规则读继承的 `http_proxy` 环境变量（与改动前一致）。用户侧的临时办法：在 app 设置「网络代理」里配置能访问 YouTube 的 HTTP 代理。
