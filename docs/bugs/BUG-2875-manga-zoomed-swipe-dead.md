## BUG-2875 · 漫画放大态（含捏合残留 101%~105%）左右滑永远翻不了页
- **报告**：2026-10-02（用户：Android 竖屏手机，在线 Mihon 源章节，阅读模式「自动」、从右到左、适应屏幕、有 OCR 识别框；录屏里页面看起来是贴合未放大，在下半页反复左右滑，始终停在 3/37，顶栏处于唤出态）
- **真实性**：⚠️ 用户的原始触发条件**未直接复现**；可证实的根因只有一条，已修。根因 `fushi/lib/src/media/manga/manga_overlay_html.dart:1743`（修前）：swipe 判定硬性要求 `ZOOM <= 1`，放大态的一切横向拖动都只交给 `_panBy` 平移。`_clampPan` 把平移限制在 `[vw·(1−ZOOM), 0]`，捏合缩回「看起来贴合」时很容易停在 101%~105%，此时可平移余量只有几像素，画面与贴合无从分辨，左右滑永远只是挪几像素、一页也翻不动（点边缘热区不看 ZOOM，仍能翻）；该倍率还经 `onMangaZoomChanged` 记进 `_zoomPercent`，换章 / 重建窗口文档后照样带着。
  - 真机证据（HiBreak，Android 14，WebView 152，独立 applicationId 的探针包、本地 37 页 CBZ，设置与用户一致：自动 / 从右到左 / 适应屏幕）：ZOOM=1 时顶栏唤出 / 隐藏、整卷 OCR 运行中、注入 OCR 框后从框上起手、慢速（按住 0.6s 再拖）各种左右滑**都能翻页**——这些候选均排除；经 CDP 把 ZOOM 设为 1.03 后画面与贴合目测无异，`adb input swipe` 右滑 450px 只把画布从 `translate(-6.585px…)` 挪到 `translate(0px…)`，页码停在 3/37，复现「划不动」。
  - 已沿代码排除：分镜导航（`manga_panel_navigation` 默认关）、`_navigating` 卡死（`_loadInitialWindow` 有 10s 超时且 finally 解锁并续 drain）、宽页拆分 / 自动放大（默认关）。在线直读的占位几何 / 页级识别路径未能在真机上走（探针包无 Mihon 源）。
- **[x] ① 已修复** — `manga_overlay_html.dart` 的 `_start` 记下按下时的 `PAN_X`（`spx`），`_end` 用「手指横移 − 画布实际横移」= 平移**贴边后没吃掉**的余量判 swipe（同向、过 72px 或 36px+900px/s）。未放大时 `_panBy` 不动 `PAN_X`，余量 = 整段位移，判据与修前逐字一致；明显放大时平移区间内照旧只平移，拖到边缘再继续才翻页——与 Mihon、与滚轮的「能平移就平移、贴边才翻页」（BUG-1760）同一口径。宽页拆分态的 swipe 也因此能翻半页。提交：见 `fix(manga): turn pages from the unconsumed pan of a zoomed swipe`。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_zoomed_swipe_edge_js_test.dart`：node 跑生成文档里真实的 `_clampPan` / `_panBy` / `_start` / `_end`，覆盖未放大判据不变、103% 残留能翻、明显放大时区间内只平移、贴边余量过阈才翻、反向拖全被平移吃掉；修前代码跑这组有 2 条红。`manga_overlay_html_test.dart` 的「放大态拖动」字面守卫同步改为钉余量判据、禁止回到硬性 `ZOOM <= 1` 门。
- **备注**：修复后的探针包真机复测：ZOOM=1.03 时右滑 450px 画布贴边后翻到下一页；ZOOM=2 居中时右滑 200px 只平移（`translate(-219.5px…)`→`(-112.833px…)`、页未变），紧接着再右滑 450px 贴边后翻页。在线 Mihon 源直读章节没有在真机上走过；若用户确认当时没有捏合过、修复后仍划不动，需要拿到当时页内 ZOOM 再查。
