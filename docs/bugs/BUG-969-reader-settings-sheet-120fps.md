## BUG-969 · 阅读设置抽屉滚动与拖动跑不满120fps
- **报告**：2026-07-21（用户：120Hz Android 真机、最新 debug/rolling 包——已含 PR#187 RepaintBoundary 与 PR#229 弹窗高刷，抽屉滚动/交互仍掉帧）
- **真实性**：✅ 真 bug。三个叠加根因，均沿真实代码路径验证：
  1. **拖 slider 每 tick 全表 setState + HCT 风暴**：schema slider 渲染层每个 `onChanged` tick 收尾 `settingsContext.refresh()`（`hibiki/lib/src/settings/settings_schema_widgets.dart:199-201`）→ 整张 sheet `setState`（`hibiki/lib/src/media/audiobook/reader_quick_settings_sheet.dart:578-581`）；字号/行距 slider 与主题选择器同页，每次 rebuild 对每张色卡（系统+预设7+自定义N）各调一次 `buildHibikiColorScheme` = `ColorScheme.fromSeed` HCT 色调板生成、无缓存（`hibiki/lib/src/settings/settings_actions.dart:320-431`、`hibiki/lib/src/models/theme_notifier.dart:65`）。
  2. **实时预览无合并**：每 tick 还触发 `onSettingsChangedLive` → `_applyStylesLive`（重算整段 CSS + evaluateJavascript 换入 + `_reanchorForStyleChange` 样式重锚）+ `_syncTapGateJs` + **整个 ~7300 行阅读器页 `setState`**，一次拖动上百趟 WebView 往返叠加（`hibiki/lib/src/pages/implementations/reader_hibiki_page.dart:1479-1492`、`2471-2537`）。
  3. **scrim 下的 BackdropFilter 每帧白付**：悬浮顶部进度 pill 的 `BackdropFilter(ImageFilter.blur 12)`（`hibiki/lib/src/pages/implementations/reader_hibiki/chrome.part.dart:1703`，悬浮 chrome 默认开启）每个栅格化帧都重采背景+重跑高斯，与内容变化无关；抽屉开着时 pill 压在 modal scrim 下 blur 不可见，抽屉滚动的每一帧（120Hz）却仍付 saveLayer+回读。
  （PR#187 的 RepaintBoundary 包法正确、对纯滚动的重绘有效，但覆盖不了以上三条：①②是 build/JS 成本，③是逐帧 backdrop 采样，均不受重绘缓存层保护。）
- **[x] ① 已修复** — commit `64a129309`：① `buildHibikiColorScheme` 加纯函数有界 memo（同参返回缓存实例，`theme_notifier.dart`）；② `onSettingsChangedLive` 改经 `CoalescedAsyncRunner` 合并（在飞只置脏标记、收尾补跑一趟，last-write-wins 最终状态不丢，`coalesced_async_runner.dart` + `reader_hibiki_page.dart`）；③ 抽屉打开期间（复用 `_appearanceSheetOpen` 旗）pill 保留半透明底、跳过 blur（`topProgressPillShowsBlur`，`reader_chrome_floating.dart` + `chrome.part.dart`）。
- **[x] ② 已加自动化测试** — `hibiki/test/utils/misc/coalesced_async_runner_test.dart`（合并语义：风暴 N 触发 → 2 趟；异常不卡死）、`hibiki/test/models/theme_scheme_cache_test.dart`（同参 identical 命中缓存 / 异参独立）、`hibiki/test/reader/reader_chrome_floating_test.dart`「BUG-969」组（blur 门控真值表 + 源码守卫：pill blur 必须经 `topProgressPillShowsBlur(obscured: _appearanceSheetOpen)`、`onSettingsChangedLive` 必须经 runner 合并）。
- **备注**：待 120Hz 真机复测抽屉滚动/拖动帧率。若纯滚动仍不满 120，下一嫌疑是 WebView 平台视图（hybrid composition）之上叠 Flutter 内容的合成代价（`InAppWebViewSettings` 未显式配置渲染模式）；另阅读正文连续滚动路径存在每 50ms 全章 DOM 遍历的进度刷新（`navigation.part.dart:271-308` + `stableProgressInvocation`），本轮未动，如报正文滚动卡再立案。
