## BUG-5102 · aggregate-live-codec-merge-on-caller-isolate
- **报告**：2026-11-22（外部审计 Codex 2026-11-21 PR 审查 HBK-AUDIT-028，PR #3902）
- **真实性**：✅ 真问题（性能 / UI 卡顿）。BUG-4958 已把折叠、指纹、上行判定挪进 `AggregatePureRunner`，但互联聚合同步仍有三段整份快照的 O(N) 计算落在调用方 isolate（app 里即 UI isolate）：① client GET 的 UTF-8 + JSON 解码——`fushi/lib/src/sync/interconnect_sync_backend.dart` `getRemoteAggregate`（develop cbdc2a45ed 第 2141～2145 行，`_readBodyBounded` 的 `utf8.decoder` + `jsonDecode`）；② client PUT 的编码——同文件 `putRemoteAggregate` 的 `utf8.encode(jsonEncode(json))`（第 2159 行）；③ 写锁内的重读合并 / 差集——`packages/fushi_engine/lib/sync/aggregate_sync_service.dart` `foldIntoLocal`（第 1780～1786 行，`mergeSnapshots` + `localDelta` 同步执行），本机出站同步的锁内写回（`_applyMergedLocally`）与 host 的 PUT 折叠（`LocalLibraryHostService.applyAggregateSnapshot`）都走这里。host 端点 `fushi_sync_server/sync_state.part.dart` 的 GET `jsonEncode` / PUT `readJsonObjectBody` 是同形问题（app 内 host 与 UI 同一 isolate）。实测（`packages/fushi_engine/test/bench/aggregate_live_sync_isolate_bench.dart`，每族 4 万行、报文 9.8 MiB，桌面机 5 次中位数）：修前调用方最大停顿 GET 解码 337 ms、锁内合并 / 差集 286 ms、PUT 编码 48 ms。
- **[x] ① 已修复** — 传输层只搬字节、编解码与合并进同一个后台执行器：新增 `packages/fushi_engine/lib/sync/aggregate_wire_codec.dart`（UTF-8 JSON 字节 ⇄ 快照的纯函数，fused 解码器、`JsonUtf8Encoder` 一步编码）；`syncOverClient` 契约改为 `fetchRemote → Uint8List?` / `pushMerged(Uint8List)`，报文体解码与折叠在同一次后台计算（`planLiveFold`）里做，上行判定直接回编码好的字节（`liveOutgoingIfChanged`）；`foldIntoLocal` 的合并 / 差集经 `_runPure` 在后台算（`foldDelta`），调用方写锁照旧包住「重读 → 合并 → 写回」，后台计算期间不释放，事务内一致性不变。client 端 `getRemoteAggregateBody` / `putRemoteAggregateBody` 只读写原始字节；对比弹窗用 `decodeWireSnapshotOff`；host 端点 GET / PUT 用 `encodeWireSnapshotOff` / `decodeWireSnapshotOff`（坏 JSON / 非 object / 空体仍回 400）；无头 CLI `AggregateRemote` 同契约。修后调用方最大停顿：GET 37 ms、锁内合并 47 ms、PUT 44 ms（剩下的是把快照拷进后台 isolate 的消息复制开销，见备注）。
- **[x] ② 已加自动化测试** — `fushi/test/sync/aggregate_sync_off_ui_isolate_test.dart`：互联一轮的三段（解码 + 折叠、锁内合并 / 差集、上行判定 + 编码）都在真后台 isolate 执行；锁内那一段确实在 `localApplyLock` 持有期间执行；host 侧 `foldIntoLocal` 经 runner 且 MAX 落库正确；`planLiveFold` 坏 JSON 抛 `FormatException`、非 object 当空快照、`liveOutgoingIfChanged` 回的字节解码后等于合并结果。`fushi/test/sync/sync_orchestrator_live_aggregate_test.dart`：真 host 端点坏 JSON / 非 object / 空体回 400 不落库，GET 回 UTF-8 JSON（含 CJK 书名）。变异实测：把 `foldIntoLocal` 撤回在调用方同步算合并 / 差集后，`aggregate_sync_off_ui_isolate_test.dart` 7 条里 4 条变红（互联 / 云通道 hop 数 3→2、锁内 hop 记录 `[false, true, false]`→`[false, false]`、host fold runner 调用数 1→0），exit 1。
- **备注**：未覆盖的残余（已登记，不在本条范围）：① 每次后台计算都要把快照（本地 materialize 结果 / 合并结果）以消息复制拷进后台 isolate，4 万行 / 族时约 35～50 ms 停在调用方；`materializeLocalSnapshot` 把 DB 行组装成快照本身也在调用方。根治要把聚合同步整体（DB 读取 + 折叠 + 编码）交给常驻后台所有者（drift 后台 isolate 或 Rust 胖核心），属架构改动。② 云通道（`SyncAssetStore.getJsonAsset` / `putJsonAsset`）各后端的快照 JSON 编解码同样在调用方，未改。
