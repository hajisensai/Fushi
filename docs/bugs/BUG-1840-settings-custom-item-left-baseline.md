## BUG-1840 · 视频设置页 Jimaku/OpenSubtitles 块贴边，比标准设置行更靠左
- **报告**：2026-08-25（用户：截图，设置 → 视频 → 字幕，Jimaku / OpenSubtitles 整块的标题、开关、输入框都贴到分组卡片左沿，比上一行「刮削后自动补字幕」的图标还靠左）
- **真实性**：✅ 真 bug。根因是**水平基线没有拥有者**：设置 schema 渲染器对 `SettingsCustomItem` 是裸渲染、不给任何内边距（`fushi/lib/src/settings/settings_schema_widgets.dart:119`，`custom.builder(settingsContext)` 直接返回），仓库里其余四个整段自绘的 custom 分区（`DiscoverySourceSettingsSection` / `MangaOcrSettingsSection` / `TorrentSettingsSection` / `JellyfinConfigWidget`）都是组件自己补 `rowHorizontal`；唯独 `VideoExternalProviderSettingsSection`（`fushi/lib/src/pages/implementations/video_external_provider_settings_section.dart:905` 的 `_constrainSectionWidth`）没有——它原本只被下载页的 `TorrentSettingsSection` 嵌套托管、由宿主补边距（`torrent_settings_section.dart:685`），BUG-1712 把它以 `onlySubtitleSources: true` 内联进视频 schema（`settings_schema_video.dart:1160`）后就整块贴边。同一现象的更深一层：BUG-1712 用「同一组件双挂载」修「一个能力两个家」，把症状固化成了结构——Jimaku/OpenSubtitles/Torznab/Jellyfin/AniDB/TMDB 等第三方凭据散在视频与下载两页，没有唯一的家。
- **[x] ① 已修复** — 本 PR（`worktree-settings-online-services`）：① 组件自己承接 `rowHorizontal` 基线（`_constrainSectionWidth` 外包一层 `Padding`），与其它自绘分区同一条线；② `onlySubtitleSources` 布尔换成三值 `VideoExternalProviderScope`（字幕来源 / 资源索引器 / 下载落盘管道），从 `TorrentSettingsSection` 里拆出来当平级兄弟，避免双重缩进；③ 新建「在线服务」一级分区 `settings_schema_services.dart` 作第三方凭据唯一的家（Jimaku、OpenSubtitles、内置索引器、Torznab、发现来源、AniDB、TMDB、Jellyfin/Emby、Dandanplay 服务器），视频·字幕与下载各留一条跳转行；持久化键零改动。
- **[x] ② 已加自动化测试** — `fushi/test/settings/video_external_provider_settings_section_test.dart`：`section content sits on the shared row baseline`（内容左沿 == `FushiDesignTokens.spacing.rowHorizontal`）、`scopes render disjoint content`（三段互斥，不再「同一能力两个家」）、`subtitle sources scope lists both providers side by side`（BUG-1712 不变式改钉到单一家）；`fushi/test/settings/settings_destination_order_guard_test.dart`（侧栏顺序含 `buildServicesDestination()`）；`fushi/test/settings/video_source_scrape_global_settings_test.dart`（AniDB/TMDB 迁到 `services.metadata.*` 后仍可达、共用 `commitVideoMetadataRuntimePreference`）。
- **备注**：`SettingsCustomItem` 的契约是「builder 自带行布局与内边距」，渲染器不补——这一点此前只是各组件的默契，没写在任何地方；本次在 `_constrainSectionWidth` 的注释里写明。若以后再有 custom 分区贴边，先查它有没有自己的 `rowHorizontal`。
