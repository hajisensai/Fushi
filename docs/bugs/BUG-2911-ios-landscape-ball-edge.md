## BUG-2911 · iOS 横屏应用内悬浮球不吸附屏幕侧边
- **报告**：2026-10-03（用户：fushi 的 iOS 端横屏状态下视频不会吸附侧边）
- **真实性**：✅ 真 bug。iPhone 17 Pro 模拟器打开视频（视频页锁横屏），应用内悬浮球收起后停在离屏幕右缘约 45pt 的黑边中间，没有贴边。实测 `MediaQuery.viewPadding = (61.6, 0, 61.6, 19.9)`：iOS 横屏左右安全区**对称**上报灵动岛深度，`displayFeatures` 为空。根因在宿主 `fushi/lib/src/floating_ball/app_floating_ball_host.dart:782-788`（修复前基线 `3a3109708d`，`build` 里 `final EdgeInsets padding = MediaQuery.viewPaddingOf(context); final Rect viewport = Rect.fromLTRB(padding.left, padding.top, window.width - padding.right, …)`）：左右 inset 全部扣掉，球的停靠边 = 安全区内缘，没有灵动岛的那一侧也贴不到屏幕边。Android（`shortEdges`）只在刘海侧上报 inset，所以不受影响；竖屏左右 inset 为 0，所以只在横屏出现。
- **[x] ① 已修复** — iOS 原生 `FushiFloatingBall.swift` 在 `app.fushi.reader/floating_ball` 上新增 `sensorHousingEdge`，按 `UIWindowScene.interfaceOrientation` 换算外壳所在边（`landscapeRight` → 左，`landscapeLeft` → 右）。视口抽成纯函数 `appFloatingBallViewport`：外壳在左 / 右时，对侧的水平 inset 归零；未知时保持两侧都避让。模拟器复验：灵动岛在左时，右停靠球的包围盒右缘为 889.9（大于屏宽 869，外缩贴边）；灵动岛在右时仍避让右侧（827.9）。
  - **审查返工（外壳边改为原生推送）**：初版宿主只在 `initState` 与 `didChangeMetrics` 时重查外壳边。横屏左 ↔ 右翻转 180° 时窗口尺寸与（左右对称的）安全区都不变，`didChangeMetrics` 不一定触发，`_sensorHousingEdge` 停在旧值，球会停到灵动岛底下（视频页同时允许两个横屏方向）。改为由原生主动推：`SceneDelegate.swift` override `windowScene(_:didUpdate:interfaceOrientation:traitCollection:)`（FlutterSceneDelegate 已实现它转发插件，先调 super），界面方向变了就经 `FushiFloatingBall.interfaceOrientationDidChange` 在同一通道推 `sensorHousingEdgeChanged`（参数与查询回话同一套字符串）；Dart `FloatingBallChannel.installHandler` 新增 `onSensorHousingEdgeChanged`，宿主 `_onSensorHousingEdge` 收到即 setState。查询保留为首次取值与尺寸变化时的兜底，且处理器先于首次查询装上（两条消息按原生发出顺序到达，后到者即真值）。时机取舍：`viewWillTransition(to:with:)` 开头 `interfaceOrientation` 还是旧值，在那里推只会推旧边；scene 回调在界面方向更新之后才来，推的一定是新值，代价是可能比新 inset 晚一两帧（左 ↔ 右翻转时球随后挪正）。竖 ↔ 横那一帧即便新 inset 先于新外壳边到达也无害（旧值 up/down → 两侧照扣；left/right 遇竖屏 → 左右 inset 本为 0），只有左 ↔ 右翻转会错侧，正由推送覆盖。平台门抽成测试缝 `debugSensorHousingEdgePlatformOverride`。初版写成 `@objc func` 被 Swift 编译器拒（Overriding declaration requires an override keyword），已改 override + super，由 PR CI 的 ios job 编译验证。
- **[x] ② 已加自动化测试** — `fushi/test/floating_ball/app_floating_ball_viewport_test.dart`：用实测横屏数值钉住外壳在左 / 在右 / 未知 / 旋转那帧旧值 up 四种视口；mock 通道钉住查询的字符串 → `AxisDirection` 映射（含 null / 未知值 / 非字符串）与非 iOS 不打扰原生；`sensorHousingEdgeChanged` 推送经 `installHandler` 回调；原生「scene 方向回调 → 推送」结构守卫。`fushi/test/floating_ball/app_floating_ball_host_test.dart` 的「BUG-2911 iOS 横屏外壳边」组：真宿主 + 横屏窗口与对称安全区，外壳在左时右停靠收起球右缘超出窗口、左停靠仍避让 inset；推来 `right` 后（不经重查）布局翻转，推来 null 两侧都避让。
- **备注**：没有灵动岛的那一侧，球拖到最上 / 最下端时可能被屏幕圆角轻微裁到。Android 本来就不避让圆角，两端行为一致。
