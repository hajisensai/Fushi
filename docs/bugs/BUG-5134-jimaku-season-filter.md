## BUG-5134 · 合集字幕只点第二季批量下载仍可能写入第一季字幕（Jimaku 把请求季号抄成候选季号）
- **报告**：2026-11-22（外部审计 HBK-AUDIT-049，Codex 2026-11-21 PR 审查，来源 PR #3763）
- **真实性**：✅ 真 bug，在 develop `8b8e6acd28` 上沿源码路径复现（`fushi/test/media/video/subtitle/subtitle_season_fact_test.dart` 与面板 widget 测试在撤掉修复后变红）。三处根因叠在一起：
  1. **请求意图被当成来源事实**：`packages/fushi_engine/lib/media/video/jimaku_subtitle_provider.dart:119`（AJATT 同形：`fushi/lib/src/media/video/subtitle/ajatt_subtitle_provider.dart:94`）把 `request.effectiveSeason` 原样写进每个候选的 `season`。请求第二季、按 AniList id 落空后退到文本搜索时，拿回的第一季条目连同文件名写着 `S01E02` 的字幕全被标成第二季。
  2. **标签压过文件名**：`fushi/lib/src/media/video/subtitle/subtitle_batch.dart:187` 的 `subtitleCandidateSeason` 先信声明的季号、文件名只作兜底，于是上面那份错标签让 `S01E02` 也配给第二季。
  3. **只点一季时执行器把多季合集当成单季**：面板只把选中那一季的成员传给批量（`fushi/lib/src/pages/implementations/subtitle_collection_panel.dart:1293` 的 `_targetAt`），`runSubtitleBatch` 只看目标算 `allowUnseasoned = !hasMultipleTargetSeasons`（`subtitle_batch.dart:542`），季号未知的字幕照收；面板的来源过滤（`subtitle_collection_panel.dart:1174`）同样默认收。
  4. **（审查补）身份确认只证明「条目 = 请求的 AniList 作品」，证明不了它是请求的那一季**：`fushi/lib/src/media/video/subtitle/subtitle_series_season.dart` 的 `pickAniListSeriesForSeason` 挑不出对应季的 AniList 条目时回退相关度首条（通常是第一季），面板把第一季的 id 连同 `season: 2` 一起发给 Jimaku，命中第一季条目、id 对上，`jimakuEntrySeason` 就把它自报成第二季——修复前后都能让第一季字幕成为第二季的来源（审查时在 PR 头上加 widget 测试复现：「下载全部」按钮可用）。
- **[x] ① 已修复** — 新增 `packages/fushi_engine/lib/media/video/subtitle/subtitle_source_season.dart`：候选季号只认来源能证明的事实——文件名里的季号优先，其次条目层面的季号（条目 AniList id 与请求作品对上时才采信请求季号；否则只认条目名里唯一的季度记号），都没有就是 null。Jimaku（`jimakuEntrySeason`）与 AJATT 都改走它；`subtitleCandidateSeason` 改为文件名优先。`runSubtitleBatch` 新增 `collectionSpansSeasons`，面板传 `_hasMultipleSeasons`；面板来源过滤与批量共用 `subtitleSeasonAllowsUnseasoned`（合集跨季且目标有季号时不收季号未知的字幕，PV·特典节不受影响）。`pickAniListSeriesForSeason` 给了季号却没有对得上的条目时返回 null（不回退首条），合集面板 / 单集面板随即退回纯文本检索，季号交给条目名 / 文件名证明。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/subtitle/subtitle_season_fact_test.dart`（真 `JimakuVideoSubtitleProvider` + 伪 Jimaku HTTP：回退条目不再标第二季、AniList 对上才采信请求季号、文件名压过标签、合集跨季只配第二季时第一季条目的字幕一个都写不进去、单季合集照旧）；`fushi/test/pages/subtitle_collection_panel_test.dart`「HBK-AUDIT-049 多季合集只点第二季…」（面板 + 真 Jimaku provider：第二季没有可用来源、四集都没写入；切到第一季按 AniList 确认后照常写入两集）；同文件「HBK-AUDIT-049 多季合集只点第二季、AniList 没有第二季条目…」（AniList 只回第一季条目时不按第一季 id 搜、第二季无可用来源）；`subtitle_series_season_test.dart` 挑不出对应季返回 null。变异实测：撤掉来源事实或撤掉合集跨季判据，对应用例变红。
- **备注**：行为变化——合集跨季时，季号既不在文件名、来源也无法确认身份的字幕不再配给任何一季（会显示「字幕季号与目标季不符」），这与 #3763 对多季混跑既定的「拒绝静默跨季套用」一致。SubDL 的 `record.season ?? request.effectiveSeason`（服务端已按 `season_number` 过滤）未在本次改动范围内。**未修遗留**：刮削后自动补字幕（`packages/fushi_engine/lib/media/video/subtitle/library_video_subtitle_backfill.dart` / `scraped_subtitle_targets.dart`）发的是作品级 anilist id + 文件解析出的季号；作品跨季（TMDB 一部剧含多季）时那个 id 只对应其中一季，`jimakuEntrySeason` 同样会把它的条目自报成请求季——与修复前行为相同（不是回归），要根治需让身份按季解析或给请求补「id 已按季核实」的契约，待单独处理。未做真机复测。
