## BUG-4387 · flatpak-x11-mesa-crash
- **报告**：2026-11-10（用户：外部测试者，Flatpak 3.3.0，Ubuntu GNOME Wayland，Intel 13 代核显 + RTX 4060 Laptop 混合显卡，NVIDIA 595.99.02 按需模式；应用内崩溃报告两份）
- **真实性**：✅ 真 bug。默认启动窗口出现不到 1 秒即崩溃，测试者五组对照：默认（Flatpak 钉的 X11）崩；`FLATPAK_GL_DRIVERS=default`（只剩 Mesa，跑 Intel 核显）崩；`LIBGL_ALWAYS_SOFTWARE=1`（Mesa llvmpipe）能用但卡；`GDK_BACKEND=wayland`（Intel）流畅；PRIME 卸载到 NVIDIA（EGL + GLX 都走 NVIDIA）正常。崩溃只出现在「X11 + Mesa 硬件驱动」组合，与 NVIDIA 无关（先前怀疑的 Flutter `glBlitFramebuffer` NVIDIA 问题已排除）。触发条件在本仓：`tool/linux/flatpak/app.fushi.reader.yml:25`（`--env=GDK_BACKEND=x11`，为应用外悬浮球钉 X11）。崩溃点在图形栈内：Flutter 3.47.6 Linux 嵌入层在 X11 上用 EGL 渲染、GTK 用 GLX 呈现，帧不可共享（`engine/src/flutter/shell/platform/linux/fl_view_renderer.cc:100-106`），每帧 `glReadPixels`（`fl_compositor_opengl.cc:199`）后 `gdk_cairo_draw_from_gl`（`fl_compositor_opengl.cc:295`）；崩在首帧前后，具体出错调用无栈未定位（崩溃报告进了上游反馈后端，只有 Dart 侧日志）。
- **[x] ① 已修复（临时兼容层）** — 新增 Flatpak 入口 `tool/linux/flatpak/fushi_launcher.sh`（装成 `/app/bin/fushi`，`command: fushi` 不变，权限 / finish-args 不变，自更新契约不受影响）：仅当 `GDK_BACKEND` 恰为清单默认的 `x11`、有 Wayland 显示、且不是 Steam 游戏模式时介入；X11 运行在 20 秒内死于崩溃信号（SIGSEGV / SIGABRT / SIGBUS / SIGILL / SIGFPE / SIGTRAP，不含 SIGTERM / SIGINT）就用同一参数在 Wayland 上重启，并在 `$XDG_CONFIG_HOME/fushi/x11-fallback` 记下当前构建（`/.flatpak-info` 的 `app-commit`），此后同一构建直接走 Wayland；换构建（更新）自动重试 X11；Wayland 也同样早崩则删记录（不是 X11 的问题）。用户自设的 `GDK_BACKEND`（`flatpak override --env=...`）原样尊重。代价：落到 Wayland 的机器没有应用外悬浮球（Wayland 不许摆放自身窗口，`floating_ball_channel.cc:400`、`floating_ball_config.dart` 的 `linuxSessionIsX11` 已有降级）。`flatpak_build.sh` 把启动器随清单拷入并钉 sha256（flatpak-builder 只按清单文本缓存）。**清理条件**：X11 + Mesa 崩溃根因定位并在上游（Flutter 嵌入层 / Mesa）修复后删掉启动器，恢复符号链接。
- **[x] ② 已加自动化测试** — `fushi/test/build/flatpak_launcher_x11_fallback_test.dart`（`@TestOn('linux')`，CI 单测在 ubuntu-latest）：用 bash 真跑启动器 + 桩程序，覆盖 X11 崩溃→Wayland 重启且参数不丢、同构建直接 Wayland、换构建重试 X11、两端都崩不归咎 X11、SIGTERM 不算崩溃、用户覆盖 / 无 Wayland / 游戏模式不介入（exec，无外壳）、SIGTERM 转发给应用、清单与打包脚本装配。Linux 容器（Flutter 3.47.6）10/10 通过、连跑 3 次；红→绿：启动器换成直接 exec（等同原符号链接）4 条失败。
- **备注**：真机 Flatpak 端到端未验（本机无法复现：WSL / 虚拟机都拿不到 Linux 原生 Intel / NVIDIA 驱动；BaseApp 本地缓存过期，重建 WebKit 需数小时）。测试者那台机器在新包发出前可用 `flatpak override --user --env=GDK_BACKEND=wayland app.fushi.reader` 绕过。
