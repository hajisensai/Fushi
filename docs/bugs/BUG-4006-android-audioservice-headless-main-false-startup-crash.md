## BUG-4006 · 无界面拉起的进程跑 main()，被判「启动即闪退」（Android audio_service / iOS 后台拉起）
- **报告**：2026-11-04（崩溃报告整批分诊）。Android：`0B-NDKFxfS`、`SGge0zu1FY`、`ajMNnjGlhY`（x2）、`bZbeHh8l36`（x2）、`Xpkq6jDjzr`（同一台 moto g55 5G，3.3.0-debug.23025）、`RgaeV2JF62`（moto g 5G 2023，3.2.0-debug.22643）、`UeCVNnw7Jx`（同机，memoryKill x4，23025）；iOS：`d3SS3FJIOH`、`vHHHx7AvCY`（23025）。共 9 份，最新出现版本 3.3.0-debug.23025（Android）/ 23025（iOS）。
- **真实性**：⚠️ 闪退报告是误报，但背后的「无界面跑完整 main()」是真问题，修法需要拍板。证据：
  1. 标记 `lastLifecycle=launching@<started>` 与 `started` 同一毫秒，之后**再没有任何生命周期写入**，而进程活了 15 分钟到 3.5 小时（`SGge0zu1FY` 的 pid 31774 10:15:53 启动，`0B-NDKFxfS` 13:48 才报它没了；`ajMN` 15:16→15:31；`bZbe` 14:44→15:00）。只要 MainActivity 上过屏，`_ExitEvidenceObserver` 就会记到 resumed，所以这些进程从来没有界面。
  2. 这些进程启动 1–2 s 内都记了 `TtsChannel.setLocalAudioDbs: MissingPluginException(No implementation found for method setLocalAudioDb on channel app.fushi.reader/tts)`：该通道只在 `MainActivity.configureFlutterEngine`（`fushi/android/app/src/main/java/app/fushi/reader/MainActivity.java:645`）注册，进程退出记录通道同样只在那里注册（`:623` `ProcessExitChannel.registerWith`），对应 Dart `previous_exit_log.dart:1213` 的 `on MissingPluginException` 静默分支——所以这些进程的 Android 退出记录也收不到。跑 `main()` 却没有 MainActivity 配置过引擎。
  3. 谁会无界面跑 `main()`：`MainActivity extends AudioServiceActivity`（`MainActivity.java:60`），AndroidManifest 把 `com.ryanheise.audioservice.AudioService` 以 `exported=true` + `android.media.browse.MediaBrowserService` 暴露（`AndroidManifest.xml:212-218`）。系统媒体续播（Android 11+ 开机 / 媒体卡片）、蓝牙 / 车机、`MediaButtonReceiver` 绑这个服务时，`AudioService.onCreate`（`audio_service-0.18.18/android/.../AudioService.java:345`）调 `AudioServicePlugin.getFlutterEngine`（`AudioServicePlugin.java:70-111`），新建 FlutterEngine 并 `executeDartEntrypoint(DartEntrypoint.createDefault())`——完整的 app `main()` 在没有 Activity 的引擎里跑起来。
  4. 会话标记把 `launching` 算前台（`fushi/lib/src/diagnostics/previous_exit_log.dart:207-210`），无界面进程后来被系统回收（`UeCVNnw7Jx`：标记 pid 31262 的退出记录 `LOW_MEMORY importance=400`）就成了「启动初始化未完成（停在前台时没了，疑似闪退）」。
  5. iOS 同形：`Info.plist` 声明了 `UIBackgroundModes = audio, fetch` 和 BGTask（`app.fushi.feedback-reply-check`），系统在后台拉起 app 时 Flutter 引擎跑 `main()` 但不会收到前台生命周期，标记同样停在 `launching`（`d3SS3FJIOH`：pid 18758 启动 3 分钟内没了，无任何生命周期）。
  - `SGge0zu1FY` 里另有 `FlutterLogs.initLogs: MissingPluginException(flutter_logs)`：`flutter_logs-2.1.11` 的 `FlutterLogsPlugin` 把 `channel` 存在 companion 静态字段里（`FlutterLogsPlugin.kt:30`），任一引擎 `onDetachedFromEngine` 都会把**最后一个**引擎的 handler 置空（`:347`）；同进程多引擎（audio_service 引擎 + Activity）时互相踩。属同一「一进程多引擎」结构问题，未单独处理。
- **[ ] ① 未修复** — 需要拍板（产品行为与原生边界取舍）：
  - **选项 A（只修判定）**：启动时由原生如实告诉 Dart「这次进程是不是带界面启动的」（Android：引擎是否由 Activity 配置 / 进程启动时的 importance；iOS：`UIApplication.applicationState == .background`），标记初始状态记 `headless` 而不是 `launching`，无界面会话不算前台。需要一个对**所有**引擎都注册的原生通道（不能挂在 `configureFlutterEngine`）。只消除误报，无界面 `main()` 照跑。
  - **选项 B（不让系统冷启动整个 app）**：去掉 AudioService 的 `MediaBrowserService` 暴露 / 关掉媒体续播，系统与外设就不会在没打开 Fushi 时拉起引擎。代价：锁屏/通知栏「继续播放上次的有声书」、车机浏览不可用。
  - **选项 C（无界面时走瘦入口）**：`main()` 识别无界面启动，只装 audio handler、不做数据库 / 同步 / 迁移等全量初始化，界面接上后再补完整初始化。改动面最大，但同时解决「无界面进程后台吃内存 / 跑同步」与通道缺失（MainActivity 接管缓存引擎时 Dart 侧早期调用已失败、不会重试）。
- **[ ] ② 未加自动化测试** — 待方案选定。可落地层：A 为 `previous_exit_log_test.dart` 的标记状态机 + 原生通道契约守卫；C 为入口分流单测。
- **备注**：同 pid 有 Android 退出记录时的误报已由 BUG-4005 修掉（`UeCVNnw7Jx` 的标记那条因此降为后台回收；它仍会因 pid 26422 `LOW_MEMORY importance=125`——前台服务期间被 LMK 杀——按 memoryKill 上报，那一条是真实的内存回收）。`Xpkq6jDjzr` 同机、停在 `inactive`、无平台记录，证据不足以单独定性。
