## BUG-1988 · SGRE 游戏内查词命中被原生提供者准入门静默丢弃
- **报告**：2026-09-01（用户：音频正常，但游戏区域文字点击没有反应）
- **真实性**：✅ 真 bug。真机共享内存已累计 15 个 SGRE `submit` hit，且 provider `kind=2/id=5`、文本跨度和字形矩形均有效，但 host 没有写入任何 card frame。`nativeOnly` 切换会按设计 Detach 可选的桌面 attached surface；SGRE 原生 provider 仍是 registry 的 Ready owner，事件却带来 attached surface 的 `detached` token。`fushi/lib/src/lookup/gal_attached_text_controller.dart:_nativeProviderReady` 错把这个独立 surface token 当成原生 provider 生命周期，无法进入 `activeNative`；中央仲裁因此保持 `_providerAdmission=false`，所有命中在 `gal_ingame_lookup_controller.dart:handleHit` 入口静默返回。runner 还会在未完成真机验证的输入盾上返回 `riskAcceptanceRequired`，原实现同样没有把它识别为独立的“provider ready、等待授权”状态。另有一个独立的首次恢复竞态：SGRE 在 `OfferReady` 之前先消费 queued up，registry 可拒绝 payload，但事件游标已经推进。修复准入后第二轮真机日志进一步证明点击已查到“整理”（63 条词典结果），但 galCard 的 READY-SAFETY 在权威 `overlaySize(epoch=1)` 前 127ms 抢先提交 legacy epoch 0；游戏卡要求精确 `overlaySize → captureReady`，两代几何互相拒绝后没有 `gal-ingame: rendered/present`，用户仍看不到卡片。
- **[x] ① 已修复** — 原生就绪判定改以 registry 的 production kind/id pair 与 Ready/Active provider 生命周期为唯一权威，不再依赖可选桌面 attached surface 的 `ready/detached/riskAcceptanceRequired` token；未授权仍停在 `needsRiskAcceptance`，只有 shield verified 或当前 exe 已显式授权才进入 `activeNative`，不降低输入安全门。工作台把原先藏在更多菜单里的授权操作改为状态旁的常驻按钮。SGRE worker 同时改为先 `OfferReady`、再消费并发布 queued click，与 Siglus/Leaf 的生命周期顺序一致；submit hit 被准入门拒绝时也记录明确原因。IPC v21 再把“允许发现 Ready provider”和“允许 native owner 吞点击”拆成两个独立位：风险确认前继续采集/发现几何但 DirectInput 不拦截，正边沿先打开 Dart route 再发布 native input 位，反边沿先退役 route；`not_open` 的正边沿不会缓存到下一块 mapping 重放。越界 glyph 必须完整落在 client viewport，弹窗查词失败也会把真实 `false` 返回原生 dismiss 链，不再把失败伪装成已接管。galCard 的 READY-SAFETY 现在即使 WebView 已 ready 也继续等待权威 versioned `overlaySize`，只在既有有界重试耗尽后才用 epoch-0 最后兜底；桌面浮窗仍保留 ready 即 reveal 的快速路径。（本提交）
- **[x] ② 已加自动化测试** — `fushi/test/lookup/gal_attached_text_controller_test.dart` 使用真实 nativeOnly 后 `detached` surface token、SGRE production pair 和 partial shield，锁定“确认前需要授权、确认后 activeNative 且不要求 attached 校准 variant”；`fushi/test/pages/gal_attached_lookup_workbench_test.dart` 锁定授权入口无需展开菜单即可看见；`native/galgame_hook/tests/adapter_structure_test.py` 锁定 `OfferReady < ReadLatestSgreLookupClickSubmit < PublishSgreLookupClickPayload`；`global_lookup_flaky_popup_guard_test.dart` 锁定 galCard 不得用 WebView-ready 抢跑权威几何且仍保留有界 fallback。（按用户要求本轮不执行测试）
- **实机回归**：2026-09-01 使用本分支最新 Windows Debug 包启动 `sgre_steam.exe`。风险确认前工作台保持 `needsRiskAcceptance`，正文与音频继续采集但点击不被 native 消费；用户显式确认后状态切换为 `activeNative`、几何来源显示 `SGRE · active`，游戏内正文点击成功弹出查词卡，用户确认问题已修复。随后关闭 Fushi、injector 与 SGRE，未遗留调试进程。
- **备注**：generic shield 的 partial 不能冒充 verified；修复只让已存在的逐 exe 显式授权真正生效。真机日志中普通 `lookupText/showAt` 来自 attached 台词表面，不能证明 galCard 路由运行；本 bug 修复的是 `onGalLookupHit` 后的中央准入死路。
