## BUG-5201 · 媒体服务器网格 / 首页在标记未看后仍显示旧的已看状态
- **报告**：2026-11-22（用户：Jellyfin 条目「标记未看」后刷新仍显示已看，过一阵才消失）
- **真实性**：✅ 真 bug。媒体服务器首页行（`fushi/lib/src/pages/implementations/media_server/media_server_home_view.dart`）、库网格（`media_server_grid_view.dart`）、详情集清单各自持有一份 `MediaServerItem` 快照（`played` / `positionMs` / `unplayedChildCount`），只有详情页在「自己标记 / 自己的播放页退回」后重拉自己（修前 `media_server_detail_view.dart` `_markEpisodes` 末尾与 `_playEpisode` 里的 `_refreshEpisodesInPlace`）；从详情页退回网格 / 首页，剧卡仍是进详情前那份快照，要等整页重建才对。服务器侧没有延迟：一次性 Jellyfin 12.4 容器上 `DELETE /Users/{uid}/PlayedItems/{id}` 返回后立刻查 `Played=false`、断点 0、`LastPlayedDate=null`。真 app 复现（`fushi/integration_test/media_server_mark_unwatched_itest.dart`，修前）：详情页集卡立即变未看、服务器 `played=false`，退回网格剧卡仍是「2 unwatched · 3 eps」，70 s 后依旧。
- **[x] ① 已修复** — 新增进程内信号 `MediaServerUserDataChanges`（`fushi/lib/src/media/video/media_server/media_server_user_data_changes.dart`，按服务器身份派发），收口在真正改服务器状态的两处：`JellyfinVideoClient.setRemoteVideoPlayed` 写成功后（所有「标记已看 / 未看」入口——视频库卡菜单、合集详情、媒体服务器详情、CLI / AI 操作——最终都走它），`MediaServerSession.playItem` 的播放页退回后。读者：`MediaServerUserDataRefresh` 混入首页 / 网格 / 详情，原地重拉已加载条目（不出骨架、不回顶、不重放进场），突发通知合并成「在途一次 + 结束后再一次」；网格在首页 / 追加页在途时记 stale，那页结束后补拉，重拉期间挡住追加页；`remoteLibraryCacheProvider` 订阅同一信号失效该服务器的清单槽。详情页原来的两处手动重拉与手动 `invalidateSource` 去掉，只留一条机制。
- **[x] ② 已加自动化测试** — `fushi/test/pages/media_server/media_server_grid_view_test.dart`「服务器用户数据变更：已加载的页原地重拉…」（别的服务器不理；从 0 按页重拉到已加载条数；不出骨架、滚动位置不变；新状态可见）；`media_server_home_view_test.dart`「服务器用户数据变更：继续观看与库行原地重拉…」；既有 BUG-3491 用例（播放页退回原地重拉）改由信号驱动后仍绿。真 app：`media_server_mark_unwatched_itest.dart` 对本地一次性 Jellyfin（`FUSHI_JF_URL` / `FUSHI_JF_USER` / `FUSHI_JF_PASS`）断言退回网格后剧卡为「3 unwatched」，修后通过（截图 ju-01 修前「2 unwatched · 3 eps」+ 进度条 / ju-05 修后「3 unwatched · 3 eps」）。
- **备注**：只有 Jellyfin / Emby 有「已播放」协议（Plex 不回写，不发信号）。聚合搜索结果页是一次性结果，没接信号。
