## BUG-4140 · 内置浏览器把 canvas / 跨页翻页式漫画试读页认不成漫画
- **报告**：2026-11-04（用户：开发者自报，应用内反馈 tNQr1gO6_2，Windows；BookWalker 试读 viewer.html）
- **真实性**：✅ 真 bug。页面内容探针 `fushi/lib/src/web_browser/features/open_in_fushi/web_page_content.dart` 只数 `document.images` 里渲染高 ≥ 400、**宽 ≥ 四成视口**、原图高 ≥ 600 的 `<img>`（脚本第 165 行），分类要求至少 `kWebPageComicMinImages = 3` 张（第 92 / 140 行）。翻页式阅读器一屏只有一两页：页画在 `<canvas>` 上或贴成背景图根本不在 `document.images` 里；即使是 `<img>`，桌面跨页里每页约三分之一屏宽，也过不了四成宽的门。所以这类页面永远到不了「漫画」。
- **[x] ① 已修复** — 探针在视口 5×3 取样点下（`elementsFromPoint`，每点前 6 层）收大块图面：`<canvas>` 位图高 ≥ 600 / `<img>` 原图高 ≥ 600 / 背景图是 `url(...)` 的元素，连同视口尺寸、文档是否长滚动一起回报；分类新增「翻页大图 + 少正文」规则：不长滚动、`<p>` 正文 < 300 字、且至少一张图面够高（≥ 六成视口且 ≥ 400）够宽（≥ 两成视口）、形状像书页（单页高宽比 1.25–1.65 或跨页 0.66–0.825）→ 漫画。只看形状和页面结构，不看域名；整屏地图 / 游戏画布（16:9、16:10、平板横屏、手机竖长全屏）落不进书页比例。
- **[x] ② 已加自动化测试** — `fushi/test/web_browser/web_open_in_fushi_test.dart`「翻页式阅读器」组：跨页两张 canvas / 单张跨页图面 / 手机单页判漫画；长滚动、正文多、图面太矮、16:9 / 平板横屏 / 手机全屏画布、缺视口读数都不判；读数解析；探针脚本在 node 假 DOM 上收到 canvas 与背景图页面、跳过位图太小的 canvas 与无背景图的容器。
- **备注**：没有在真实 BookWalker 页面上验证（反馈里的链接按规定不打开）。两个未验证的风险：① 探针在 `onLoadStop` / 换地址 / 回到前台时跑，若阅读器在 loadStop 之后才异步画出页面，这一次探测仍会落空，需要在真实页面上确认；② 判成漫画后「用 Fushi 阅读」走的扫图器 `assets/web_comic/web_comic_scanner.js` 不读 canvas，canvas 绘页的阅读器能否真正接管阅读是另一件事。
