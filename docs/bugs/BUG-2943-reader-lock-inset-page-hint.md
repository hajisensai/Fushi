## BUG-2943 · 阅读器 inset 往返重锚丢失原字符锚
- **背景**：PR [#1955](https://github.com/hajisensai/Fushi/pull/1955) 修正了分页 hint 的页距口径，但没有验证多个独立落定的几何事件往返之后，最终正文是否仍在原处。
- **真实性**：✅ 生产方法上的算法级位置保持失败。可公开复现的合成夹具使用 400×824 视口、20px 字号、零页边距和 `0→24→0` 顶部 inset；DOM 采用理想多列几何，不能视作真实 WebView 或物理设备复现。
- **根因**：`fushi/lib/src/reader/reader_pagination_scripts.dart` 的分页 `setChromeInsets` 在每个已完成的几何事件前重新采页首。首个重排为了不跳过旧锚会落到含锚的前一页；第二次把那个临时页首当成新锚，再量化一次，原始落点永久丢失。高度变化的 `updatePageSize` 还走粗节点进度，必须与 inset 共用精确锚。PR #1955 的像素 hint 按新页距换算有必要，但只能解决页距口径，不能保住跨事件的语义锚。
- **[x] ① 已修复** — 分页几何重锚在明确导航之前保留字符锚及原逻辑页；inset 与尺寸共用捕获/提交入口。独立 token 标识在飞回调，翻页、恢复、fragment、跟读/搜索揭示、迟到图片目标更新会撤销旧回调，旧回调不能覆盖新导航或清新回调的旗。相对翻页先落定自己的几何补偿，显式样式变更开启新的基线。保留 BUG-2205 的防跳字检查、无变化早退、图片尺寸更新、metrics 失效和物理章尾夹取，不使用任意延时。
- **[x] ② 已加自动化测试** — `geometry_reanchor_roundtrip_behavior_test.dart/js` 用 Dart 生成真实分页 shell，再由 Node 执行原生产方法，DOM 边界采用明确标注的理想多列几何；断言最终页首字符、页号及导航落点，不能用桩替 `scrollToCharOffset` 后只验参数。包含双向多轮往返、同帧合并/分帧、同容量变页距、尺寸/inset 交错、旧回调不能覆盖明确导航、尾部插图、隐藏文档、迟到图片、样式失效及防跳字边界。
- **PR #1955 清理审计**：移除并替换每次事件单独捕获/提交 hint 的实现，换算本身保留到统一 helper；删除已被最终页首/页号行为回归覆盖的旧调用参数桩测试。该 PR 的 audiobook/video 鼠标拖动测试对应上游已经保留的独立修复，删除它们只会损失有效覆盖，因此不回滚。metrics 失效和图片盒更新早于该 PR，不属于可随意撤销的代码。
- **验证**：相同新 Dart 驱动对未修改的 `c59d631` 产生真实位置断言失败，对修复版本通过；移除 BUG-2205 的临时变体也由专门断言拒绝。Flutter 3.44 的 7 个定向文件共 27 测试通过、无跳过，全量 `flutter analyze --no-pub` 无问题。最终合成夹具复跑：修复版 33/33 场景通过，旧源码 26 失败/7 对照通过；防跳字变体 32 通过/1 失败。以上 Flutter 测试与 analyze 均已重新执行；CI 结果待补。
- **边界**：合成 DOM 不证明浏览器字体塑形、多列碎片、Android 电源键或持久化行为。真实 WebView 与设备验收仍待补。`continuous` 与 `vn` 不改变几何重锚策略；既有行为测试及实际设备验收分别记录，不把“未改动”视作已验证。
