## BUG-1828 · 阅读器大图两侧留白被判成点中图片，底栏永远唤不出来
- **报告**：2026-08-24（用户：「点击空白的地方，进入到图片里面了，而没有出现底栏」；现场是 `安達としまむら` 第 1 卷最后一章 `p-bookwalker.xhtml`，整章只有一张固定版式 `<svg><image>`，Windows 桌面版 2.2.1-debug.12170）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/pages/implementations/reader_fushi/webview.part.dart:983-1000` `_fushiBlockImageUrl`：判「点中图片」用的是 `target.closest('.block-img-wrapper')`，即**命中元素在不在那个居中容器里**，而不是**有没有点在图片上**。`.block-img-wrapper`（`fushi/lib/src/reader/reader_content_styles.dart:498-504`）是 `display:flex` + 居中的**纯布局盒**，横向撑满整列；图片只是 `margin:auto` 居中在里面。离线复现实测（1364×812 CSS 视口 + 用户真实设置）：wrapper 横跨 `0→1364`，`svg.block-img` `34.5→1329.5`，真正画出来的 `<image>` 只有 `407→957`（549px）——**整页 40% 是图、60% 是留白，却全部算「点中图片」**。于是每一次点击都走 `onImageTap`（`webview.part.dart:1105-1107`）弹图片查看器，`onTapEmpty`（`webview.part.dart:2012`）永远触发不到 → 底栏唤不出来。大图两侧留白在任何章都有这个问题，只是「整章只有一张图」的章（封面 / 插图页 / BOOK☆WALKER 尾页）全页无一处例外，用户被关死在页内。
- **[x] ① 已修复** — 不给 5 个命中点各补坐标参数，而是让**纯布局盒不参与命中**，一条 CSS 不变量同时管住 tap / touch / contextmenu / 右键四条路径（`reader_content_styles.dart`）：`.block-img-wrapper` 与 `svg.block-img` 置 `pointer-events: none !important`，`img.block-img` 与 `svg.block-img image` 置 `pointer-events: auto !important`。`svg` 之所以要拆到内部 `<image>`：`img.block-img` 用 `max-width/max-height + width/height:auto`，盒子等于图片、不 letterbox；`svg.block-img` 是**定值**盒（为了让内部 `<image>` 能 meet-fit，见该规则原注释），内部按 `xMidYMid meet` letterbox，盒子远宽于画面。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_image_tap_hit_area_guard_test.dart`（4 条：wrapper 不可命中 / `img.block-img` 可命中且盒=图 / `svg.block-img` 不可命中且内部 `<image>` 可命中 / CSS 不变量与 JS 判据保持耦合）。**已变异实测**：删掉新增的 `pointer-events` 声明后 3 条 CSS 断言全部转红，非恒真断言。
- **备注**：落地前用离线 Edge+CDP 复现环境做过真浏览器前后对照（同一份 engine.js/boot.js、只换样式表）：修复前 `<image>` 中心与四个留白点 `closest('.block-img-wrapper')` **全为 true**、`_fushiBlockImageUrl` 在五个点都解析出图片 URL；修复后中心点不变（仍可点、仍解析出 URL，`pointer-events:none` 只挡命中测试、不影响 `closest()` 上溯），四个留白点全部落回 `DIV.main`、`inWrapper=false`、URL 为 `null`。缺口：`img.block-img { pointer-events: auto }` 这条**未被真浏览器实测**（复现用的那一章没有走 `block-img` 路径的栅格 `<img>`），它只是把默认值写死，风险低但按证据纪律不算已验证。同一轮用户报告里的「ESC 退不出阅读器」经查**不是代码 bug**：该用户的 `src:reader_fushi:shortcut_bindings_json` 里 `global_back` 只剩 `Alt+ArrowLeft`（代码默认是 `[Escape, Alt+←]`），`Escape` 被 `reader_dismiss_dict` 占着、没有词典浮窗时是空操作；「←/→ 不翻页」同理——那两个键绑的是有声书上/下一句，翻页键是 `PageUp/PageDown`（实测可翻）。滚轮相关的另一个真 bug 见 [BUG-1829](BUG-1829-reader-wheel-chapter-cooldown-starvation.md)。
