## BUG-5414 · browser-page-fullscreen-caption-buttons
- **报告**：2026-11-24（用户：应用内反馈 WtYMwfPjpe，Windows「顶栏右上角的缩小放大关闭好像不会隐藏」，截图是内置浏览器里 YouTube 自己的全屏播放界面）
- **真实性**：✅ 真 bug。内置浏览器的网页全屏（站点全屏键被 `webBrowserFullscreenScript` 截成页内伪全屏）在 `fushi/lib/src/pages/implementations/fushi_web_browser_page.dart` `_applyFullscreenDisplay` → `_applySystemUi` 只调 `SystemChrome.setEnabledSystemUIMode(immersiveSticky)`，这在桌面是 no-op；浏览页从没告诉桌面自绘顶栏（`FushiDesktopTitleBar.setContentFullscreen`），浏览页又不是沉浸页（没上报 `FushiTitleBarColorScope`），所以标题行常显、窗口按钮组一直浮在全屏画面右上角。分诊初判指向的视频播放页（`video_fushi/fullscreen.part.dart` 的 runner 全屏、网页档 `_toggleWebWindowFullscreen`）都已登记 `setContentFullscreen`，不是这条路径。
- **[x] ① 已修复** — `fushi_desktop_title_bar.dart` 新增声明式 `FushiTitleBarContentFullscreenScope`（与 Reveal / DragBand scope 同一套「被整页盖住 / dispose 即撤回」骨架），浏览页 build 外层按前台标签页的 `fullscreen` 登记；`setContentFullscreen` 在构建期调用时把 notifier 发布推到帧尾（顶栏是页面祖先，构建中不能标脏它），命令式调用方不受影响。
- **[x] ② 已加自动化测试** — `fushi/test/pages/fushi_web_browser_shell_test.dart`「桌面自绘标题栏：网页全屏时窗口按钮随顶栏一起收起，退出 / 离开浏览页还原」（真浏览页接线）；`fushi/test/desktop/title_bar_content_fullscreen_scope_test.dart`（scope 本身：收起时页面顶部不再让位、被整页盖住撤回、回前台再收起、卸载归还）。
- **备注**：网页全屏仍只铺满窗口、不把 OS 窗口切成真全屏（与现有设计「伪全屏五端一致」相同）；要不要像 Chrome 那样顺带窗口全屏是另一个取舍，未改。另：`web_video_fushi_page.dart` 有同类问题（`_onState` 用页面上报的 `fs` 直接覆盖 `_fullscreen`：网站自己进全屏只藏 app bar、不藏顶栏；Fushi 全屏键进窗口全屏后 250 ms 内又被轮询改回 false）。PR #4400 正把该页收成制卡重放的后台宿主，为免冲突本次不动，交该 PR 合并后复核（重复 PR #4412 / BUG-5425 并入本条）。2026-11-25 在 PR #4400 里复核：统一后用户看的播放器只有原生播放器页（网页档全屏走 `_toggleWebWindowFullscreen` → `_enterVideoNativeFullscreen`，已登记顶栏），但 `WebVideoFushiPage` 仍作为制卡重放宿主可见（交接途中用户可回来），同类问题没有自行消失，已按根因修：全屏态拆成 `WebVideoHostFullscreen`（`fushi/lib/src/media/video/web_video_host_fullscreen.dart`）——Fushi 切的窗口全屏只由 `_toggleFullscreen` 改，页面快照只报站点 DOM 全屏、不再覆盖窗口全屏；站点自己进全屏时用 `FushiTitleBarContentFullscreenScope(enabled: site)` 收起桌面顶栏；Esc 按来源退（窗口全屏退 runner，站点全屏让页面 `exitFullscreen`）。测试 `fushi/test/media/video/web_video_host_fullscreen_test.dart`。
