## BUG-2454 · 刮削图片语言写死中文，不看资料语言偏好
- **报告**：2026-09-11（用户：截图《お兄ちゃんはおしまい！》卡片，标题日文、封面却是中文版海报「不当哥哥了!」，问「这个为什么是中文的」）
- **真实性**：✅ 真 bug。用户偏好 `video_metadata_locale = ja`，文字确实按日语走了（TMDB `language` 参数经 `packages/fushi_engine/lib/media/video/metadata/video_metadata_resolver.dart:99` 拿到 `ja`，作品行 title/overview 均为日文），但图片语言在两端都写死中文、根本不看这个偏好：
  - 请求端 `packages/fushi_engine/lib/media/video/metadata/tmdb_video_metadata_provider.dart:149/183/219/409` 四处 `include_image_language: 'zh,en,null'`——向 TMDB 要图只要 zh/en/null，**日文海报连请求都没发**；
  - 选择端 `packages/fushi_engine/lib/media/video/metadata/video_metadata_merge.dart:426` `languageOrder` 默认 `['zh','en','']`，唯一调用点 `video_source_scrape_coordinator.dart:1930` 从不传值；且排序评分先于语言，一张 8.0 分的中文海报天然赢；
  - 配置端 `video_source_scrape_config.dart:84/105` 的 `imageLanguages` 字段声明了从没被任何地方读过（死字段）；同文件 `:83/118/136` 与 `settings_schema_video.dart:806/810` 把 `zh-CN` 写成全局默认，`tmdb_video_metadata_provider.dart:57` 搜索列表无条件追加 `zh-CN`（非中文用户每次搜索白搭一次请求）。
  - 用户库里证据（`video_metadata_works` id 102，主源 TMDB 198152）：`video_metadata_images` 行 2301 cover provider=tmdb language=zh rating=8.03，即卡片上那张。
  - 同病曾在分支 `worktree-video-metadata-locale-root-fix`（4f83afe6a2 / 907581d98e，无 PR）修过一次，但改的是 `fushi/lib/src/media/video/metadata/` 旧路径，09-08 引擎搬家后未合入、落后 develop 526 提交；本条按 `packages/fushi_engine/` 新路径重放其语言派生部分（不含「优先原文标题」显示偏好与 AniDB 客户端设置项两块无关改动）。
- **[x] ① 已修复** — 新增 `packages/fushi_engine/lib/media/video/metadata/video_metadata_languages.dart`（`VideoMetadataLanguages`）作刮削语言唯一真相源：从一个 BCP-47 资料语言派生 `imageLanguages` / `tmdbIncludeImageLanguage` / `searchLocalesForQuery`。请求端四处、选择端（`languageOrder` 改必填）、配置端（删死字段、默认跟随界面语言 `uiLocaleTag`）、设置页（显示实际生效语言、重置回跟随界面语言）全部改成消费派生值；海报/logo 语言优先于评分（背景图维持评分优先）。三个生产装配点 `app_model.dart` / `home_page.dart`×2 传界面语言。`zh-CN` 派生出的请求参数与修复前逐字相同。提交 66e0de270a，PR #1420。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/metadata/video_metadata_languages_test.dart`（派生表：ja/de/en/zh-CN/空白/搜索别名去重）、`video_metadata_merge_test.dart`（同一批候选换 ja/zh-CN/de-DE 三种语言序选出三张不同海报；背景图评分优先）、`video_metadata_provider_contract_test.dart`（de-DE 真到 wire 上且 `include_image_language=de,en,null`）、源码守卫 `video_metadata_language_wiring_guard_test.dart`（请求端四处同源、选择端必填、配置端无 zh-CN/无死字段、三个装配点都传 `uiLocaleTag`、设置页默认来自界面语言）。
- **备注**：已入库的条目**不会自动换图**，用户需对该作品手动重刮。存量非中文界面且从没设过资料语言的用户，此前恒 `zh-CN`，现在跟界面语言走，库里会出现新旧条目语言混合态——不迁移偏好是刻意的，迁了等于把 bug 冻住。MAL 主源把 `title_japanese` 写进 `title` 的阶梯问题（「优先原文标题」对动画无感）不在本条范围。
- **Code review 返工（8 条全采纳）**：① 语言优先只对印片名的图种（`kLanguageFirstImageKinds`：cover/logo/banner/disc/clearart），分集剧照 `thumb` / 横版 `landscape` / 背景图仍评分优先（否则 0 票 `en` 剧照压住 8.5 分无标签剧照）；② 桌面端 `setAppLocale` 补 `reloadVideoDownloadPipelineRuntime()`，否则下载导入那条刮削链冻结旧语言直到重启；③ 无头服务端加 `metadata_locale` 配置项（YAML / admin API / WebUI，默认 `zh-CN` 延续既有行为，是可见可改的配置默认不是隐含常量）喂 `uiLocaleTag`；④ 设置页输入框显示**存的值**（空 = 跟随界面语言，占位 `video_source_scrape_locale_follow_ui`），不再预填界面语言具体串——预填后没动过的框上按回车会把 `en-US` 钉死且界面看不出区别；⑤ 删掉「含汉字就并入 zh-CN」的搜索别名表——resolver 在详情阶段用含全部 translations 的 aliases 再判一次 exact，搜索阶段投影语言不影响判定，那张表只让日文目录名的用户每次多发一次请求；⑥ 删无人读的 `config.languages` getter（会成为无视来源级覆盖的第二入口）；⑦ `fromPreferences(uiLocaleTag:)` 改**必填**，漏传是编译错误，守卫不再数字面量出现次数；⑧ `primarySubtag` 对 `-DE` 这种首段为空的手填值取第一个非空段，兜底 `en` 子标签而非整串 `en-US`。
