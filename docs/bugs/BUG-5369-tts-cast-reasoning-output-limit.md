## BUG-5369 · tts-cast-reasoning-output-limit
- **报告**：2026-11-23（用户：有声书制作台「用 AI 标注说话人」用 gpt-5-mini 报「模型没有返回内容」，整本失败）
- **真实性**：✅ 真 bug。用 Fushi 的原样请求（台词遍一块 ≤100 句 / 6000 字，`max_completion_tokens` = 8192）直接重放全书四块：gpt-5-mini 默认推理强度下思考 token 依次 5632 / 5696 / 6272 / **8192**，最后一块 `finish_reason=length`、`reasoning_tokens=8192`、正文为空；可见的标注本身只要约 1.5k token。
  - 根因一 `packages/fushi_engine/lib/ai/ai_chat_client.dart:597,615,652,683`（修复前行号）：`completeWithUsage` / `chat`（含互联主机转发）只要正文为空就抛 `empty_response`，不看停止原因——「思考把输出额度用光」被报成「模型没回」，而 `AiChatCompletion.truncated` 的文档早已写明这种情况原样重发只会再截一次、调用方要缩小这次要的输出。
  - 根因二 `fushi/lib/src/media/audiobook/tts/studio/tts_cast_annotator.dart` 的 `ask` 用 `client.complete` 只拿回字符串，`tts_cast_passes.dart` 的两遍主循环完全不知道回复被截断：空正文 → `ai_failed / empty_response` 整本失败；非空但被截断的回复按 BUG-5366 的补救收下前半截，缺的行悄悄记成旁白 / 不明。
- **[x] ① 已修复** —
  - 引擎：新短码 `kAiOutputLimitCode = 'output_limit'`，`aiChatEmptyReplyFailure(stopReason)`（`ai_chat_client.dart:203`）统一判：正文为空且停止原因是截断（OpenAI `length` / Anthropic `max_tokens` / Gemini `MAX_TOKENS`）抛 `output_limit`，否则仍是 `empty_response`；`completeWithUsage` 与 `chat` 的直连和互联主机两条路径都走它（`:614,633,670,701`）。不是临时性失败、不换 key。
  - 引擎消费方保持原口径：字幕校对 `ai_text_completer.dart` 把 `output_limit` 与 `empty_response` 一样当一次不合格回复交给各阶段重试循环；漫画标注 `manga_audio_annotate_runner.dart` 两者都只记这一页失败、不中止整卷。界面短码映射 `fushi/lib/src/ai/ai_failure_text.dart` 加 `output_limit` → `ai_error_output_limit`（提示调低推理强度）。
  - 选角：`TtsCastAsk` 改回 `TtsCastReply = ({String text, bool truncated})`，`annotateTtsCast` 用 `completeWithUsage`，`output_limit` 转成 `truncated: true`（`tts_cast_annotator.dart:108`）。主循环（`tts_cast_passes.dart:101` `splitTruncated`、`:122` `rosterChunk`、`:189` `linesChunk`）遇到截断（空或半截）就把这块按字数拆两半依次重问（`tts_cast_prompt.dart:184` `splitTtsCastChunk`，前后文从原块与另一半里取），递归到 `kTtsCastSplitMinSentences` = 8 句（`:178`）；第一遍拆开的后一半用最新角色表，第二遍后一半的滚动上下文 = 进来的 recent 接上前一半刚归属的台词，章末 recent 与不拆时一致。截断的前半截不拿来补救。拆到下限仍截断抛 `TtsCastAnnotateFailure('output_limit', '<遍>, section N: K sentences', 半截回复)`，界面文案 `audiobook_studio_cast_failure_output_limit`（提示到 AI 提供商设置调低推理强度或换不思考的模型）。
  - 不调大 8192 上限（gpt-4o-mini 等拒收 >16384），不加盲目重试：缩小这次要的输出才是对症。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/ai/ai_chat_output_limit_test.dart`（三种协议空正文 + 截断 → `output_limit`，complete / completeWithUsage / chat 同口径；正常结束仍是 `empty_response`；互联主机转发的空正文截断与主机带回的短码）；`fushi/test/media/audiobook/tts/studio/tts_cast_passes_test.dart`（100 句一块空正文截断拆半到装得下、按序标全、后一块看得到前一块的台词与前文；半截回复不补救同样拆；第一遍截断拆半且后一半看得到新角色；两遍拆到下限报 `output_limit`；`splitTtsCastChunk` 的上下文与台词标记）；`tts_studio_page_test.dart`（`output_limit` 文案）；`fushi/test/settings/ai_provider_settings_test.dart`（短码映射不漏 `output_limit`）。
- **备注**：拆块只缓解「思考量随输入增长」的情况；思考本身就要吃满 8192 的模型（推理强度开到最高）在 8 句一块时仍会报 `output_limit`，那时只能调低推理强度。
