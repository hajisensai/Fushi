## BUG-5017 · v3.0.x 复习同步写入者目录迁移完也永远留在位置上
- **报告**：2026-11-21（用户：开发者本人，Windows 安装版当互联 host）。`sync-data/fushi-data/fushi-srs/<profile>/2RIr94DPav6kxb5RWSGciWgE4LNKvGBCRtT4wT2iGSc=#1/` 占 569 MB；用户拍板放弃 v3.0.x 客户端，迁移完成后清掉。
- **真实性**：✅ 真 bug（磁盘泄漏）。`<44 字符>#<n>/` 是协议 1 之前 v3.0.x 旧事件同步的写入者目录（`native/fushi_fsrs/src/gen4/location.rs:30-31`）。全仓唯一删写入者目录的 `srsRemoveOwnProfileFolder`（`packages/fushi_engine/lib/srs/srs_profile_link.dart`）只删本设备在旧 uid 下的，别的写入者目录（`batch-*` / `snapshot-*` / `profile.json`）永不删。旧事件同步早已删除（守卫 `srs_sync_v1_removed_guard_test.dart`），现版本不读 `batch-*` / `snapshot-*`。
- **根因**：协议 1 → 3 的旧根迁移（v3.3.0 `srs_location_migration.dart`）只把写入者目录的 `media/` 搬走，目录本身与旧事件同步的 `batch-*` / `snapshot-*` / `cursor` / `probe` / `profile.json` 没有任何代码删；gen4 删掉该迁移后连 PR #3874 的删除闸门也没有落点。现版本唯一还读写入者目录的只有 `srsListRemoteProfiles` 的最低优先级回退（`packages/fushi_engine/lib/srs/srs_profile_link.dart` 写入者目录分支 `readInfo(w.name, w.id, _kSrsInfoRankLegacy)`）：位置迁到 `v4/` 后同一批设备已在 `v3/devices/` / `v4/devices/` 下，删掉只是不再把 v3.0.x 时代的旧名字 / 旧笔记数算进候选。
- **[x] ① 已修复** — 清理挂在生产入口 `srsRunLocationRound`（`packages/fushi_engine/lib/srs/sync2/srs_location_runner.dart:83-106`，互联 host / 云盘 / 无头服务端共用）：只有本轮内核 `location_root` 认过根（`onLocationRoot`：新根 `v4/` 在用、`v3/` 与 `v2/` 围栏已立）才调 `srsSweepLegacyWriters`（同文件 :139、:177）；协议 1 位置、需要更新、密钥不对、meta 读不到时一个不碰。判据不放 Rust：「位置的代」已经是内核 `location_root` 的结论，剩下的是按名字列 / 删 `SyncAssetStore` 目录，与 `srsRemoveOwnProfileFolder` 同层。删的范围：只认 `<设备>#<化身号>` 形状的目录；里面只有死文件 + 空 `media/` 整目录删，`media/` 里还有 v3.3.0 没搬完的媒体或有认不出的文件时只删死文件、目录和那些文件留着（没有证据说明那些媒体在集合里有副本）；`v2` / `v3` / `v4` 与别的目录不碰。删失败记 `SrsSync2Report.legacyWriterErrors`，调度器 `_logFormerSweep`（`fushi/lib/src/srs/srs_sync_scheduler.dart:468`）记日志、不算本轮失败，下一轮再清。本机 host 实测位置 `01a13df4-…/pzzCeD9X…=#2/`（393 MB，`media/` 为空，只有 batch/snapshot/cursor/probe/profile.json）落在整目录删的分支里。提交 e942c3b798。
