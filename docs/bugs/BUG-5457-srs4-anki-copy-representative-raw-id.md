## BUG-5457 · gen4 迁移对拍：同一次 Anki 复习的副本新代按规范 ID 选代表、与协议 3 选的不是同一份，卡的到期日 / 间隔判不同、回滚
- **报告**：2026-11-25（应用内反馈 iNWSgqE7_Z：Windows，3.4.0+32563 正式版，复习库升级「核对新库时发现了差异，已全部撤回」，`verdict: aborted` / `profileVerdict: fail`）
- **真实性**：✅ 真 bug（新代算的卡状态与协议 3 不同；对拍的基准没错，旧库与操作都没坏）。报告签名：导入、闭包、规范计数全对（卡 2428、日志 64639，`merged` 0）；`knownDifferences.total` 0、`oldSideStaleResults` 0、`oldSidePending` 0；`parity` 里 `cards` 228/228 只差 `due_day` / `scheduled_days`（`00c121f8… 20767 -> 20786, 68 -> 87`、`023ba8bc… 20782 -> 20764, 64 -> 46`，有大有小，稳定度 / 难度 / `last_log_id` / `reps` 都相同），`stats` 10 行同 ID 只差 `kind` 2↔3 与 `maturity_delta` 0↔-1、另有 94/87 行只在一侧（成熟变化行跟着间隔跨 21 天出现 / 消失）；`knownDifferences.cacheCardRepresentativeSwaps` 525、`cacheStatRepresentativeSwaps` 6307。
  - **根因**：同一事件的多份副本只算一份，代表取日志 ID 最小的那份（`native/fushi_fsrs/src/history.rs:265`，v3.4.0 `select`：`cmp_utf16(&l.id, …)`）。协议 3 的投影行里是原值 ID；新代读日志时把 ID 归一成规范 ID（`store/gen4/cache.rs:1043` `log_at` → `canonical_json`），再交给同一个 `select`（卡行 `cache.rs:1971` `Material::of`、统计 `cache.rs:2052` `stats_from_stored`、重放 `sync2/replay.rs` `fold`）。带盐的原值与规范值先后可以相反，于是两侧挑了不同的那份副本。BUG-5063 当时只认了「两侧代表不同、日志 ID 那一格不同」（`store/gen4/compare.rs:1141` 的注释写的是「两边算的是同一次复习」，`card_representative_swaps` / `stat_representative_swaps` 只换日志 ID 那一格，其余列照比），前提是副本内容一样。可同一条 Anki 复习按血统里两张卡各导入一次时，两份的结果可以不一样（推定：导入锚点的结果取导入那一刻来源卡的到期日与间隔，`packages/fushi_engine/lib/srs/apkg/srs_apkg_import.dart` `_cardState`；Anki 那边在两次导入之间重排过就是记忆状态不变、间隔与到期日变），代表换了，卡的结果就换了：`due_day` / `scheduled_days` 不同、稳定度相同，方向随机；之后本机作答时前一间隔不同，统计的「年轻 / 成熟」与成熟变化跟着不同。
  - 报告里的佐证：例子卡的 `idTrace` 里，卡行的最后一条日志 `c56cbd8c…` / `90397e2b…` 是 v5 UUID（导入派生的日志 ID），挂在另一张卡上（`newLogCard` `da9f93c8…` ≠ 卡 `00c121f8…`），即血统里前身卡上的 Anki 副本；`cacheCardRepresentativeSwaps` 525 张卡里正是代表不同的那些，其中结果不同的 228 张判出差异。同形合成库（下面的测试）复现出逐列相同的签名：`cards` 只差 `due_day` / `scheduled_days`，`stats` 差 `kind` / `maturity_delta`（合成库的作答正按到期日排，多一格 `prev_due_day`）。
  - 3.4.0 之后的 develop 没有修过（`git log v3.4.0..upstream/develop` 在 `native/fushi_fsrs` 下没有提交）。
- **[x] ① 已修复** — 不加容差、不盖列：新代选副本代表时按作者记下的原值日志 ID 比，与协议 3 同一份（与 C1 的 fuzz 种子用原值卡同一个口径）。
  - `history.rs`：`Log` 加 `rank`（选代表比的原值 ID，`None` = `id`），`select` 按 `rank_id()` 比；加 `state_from_stored_ranked` / `stats_from_stored_ranked`。协议 3、Dart 列模式都传 `None`，行为不变。
  - `sync2/replay.rs`：`Row` 加 `raw_id`，`fold` 把它设成解析出的日志的 `rank`（重放里副本的有效与否决定之后作答的前一状态）。
  - `store/gen4/cache.rs`：`LogIn` 加 `raw_id`（操作里的原值日志 ID），重放、卡行（`Material::of_ranked`）、统计（`stats_from_stored_ranked`）、`group_rows` 都带上；`cmd/preview.rs`、`cmd/writes_intent.rs`（`sched`）的头状态同用。
  - `store/mod.rs` `LogRow` 加第 4 格原值 ID，`history_states_of` / `stat_projection_of` 按它选代表（新代 `cmd/training.rs` 的 `history_states` / `stat_projection` 读命令给原值）；`store/projections.rs` `LogsByCard::push` 加 `rank`（新代训练集 / 校准 / RWKV 给原值）。读侧与缓存层选同一份。
  - 行为：迁移后这些卡的到期日与协议 3 一致（不再随规范 ID 的先后换成另一份副本的结果）；`cacheCardRepresentativeSwaps` / `cacheStatRepresentativeSwaps` 在这类库上变成 0。
- **[x] ② 已增加自动化测试** — `store/gen4/migrate_tests.rs` `anki_copies_with_different_results_keep_the_protocol_3_representative`：两条血统、各一对带盐与规范先后相反的 Anki 副本，结果间隔 15 / 30、记忆状态相同，第二条之后本机作答一次；跑真实迁移判 committed、`parity` / `canonical` 空、两类代表交换 0。去掉修复（`rank_id` 退回 `id`）即红，报告签名与用户的相同：`cards` `due_day: 19705 -> 19690, scheduled_days: 30 -> 15`，`stats` `kind: 2 -> 3`、`maturity_delta`。`history.rs` `copies_pick_their_representative_by_the_raw_id_when_one_is_given`：内核层按原值选代表、不给原值时与原规则相同、条数不符报错。BUG-5063 的 `anki_copies_across_a_lineage_whose_salted_and_canonical_order_differ_migrate_cleanly` 期望改成两类交换 0（两侧本来就该选同一份）。
