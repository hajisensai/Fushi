## BUG-2607 · iOS 触屏阅读器查词/划选/收藏高亮全部不画：WebKit 不绘制 user-select:none 文字上的 ::highlight
- **报告**：2026-09-20（用户：「ios书籍（有声书）划句子会没有高光」，附 iOS 截图：有声书里长按划选「朝の満員電車…気持ちになる。」，两枚选区手柄 + 搜索/复制/收藏/导出片段视频菜单都在，选区本身零高亮；页顶有声书当前句的绿色高亮正常）
- **真实性**：✅ 真 bug，且比报告的范围大：**不限有声书，iOS 触屏上阅读器所有走 CSS Custom Highlight 的层都不可见**。根因 `fushi/lib/src/reader/reader_content_styles.dart` TODO-1279 的触屏规则 `@media (pointer: coarse) { html, body, body * { user-select: none !important } }`（为消除「原生蓝选区 + app 查词高亮」双选区而全量禁原生选区）——**WebKit 对 `user-select: none` 的文字不绘制任何 `::highlight()`**。本机 Playwright WebKit 探针（同一条 Range、同一条 `::highlight(fushi-selection){background-color}` 规则、priority=1，截图采样 Range 矩形内命中高亮色的像素比）：裸段落 0.559；包 `.fushi-sentence-audio-cue` span 0.559（有声书 DOM 无关）；`user-select:none` 带/不带 `-webkit-` 前缀、写在元素上或由祖先继承 **全部 0.000**；祖先 none 但元素 `user-select:text` 回到 0.559；只有 `-webkit-touch-callout:none` 不受影响。iOS 主指针是 coarse，规则一落地，查词 `fushi-selection`、长按划选、收藏句 `fushi-hl-*`、搜索 `fushi-search` 在 iOS 上一律不画；有声书当前句（`.fushi-sentence-audio-active` 元素 class 背景）与 `<ruby>` 分流 class 不走 ::highlight 所以照常，用户才看成「只有划选坏了」。手柄由 `reader_selection_scripts.dart` 自绘 DOM 元素定位，与绘制无关，所以手柄在、高亮不在。BUG-609/624 两次改动都写着「iOS 待用户验收」——这条规则从没在 WebKit 上验过。Blink 绘制 ::highlight 不看 user-select，Android/Windows 无此问题。
- **[x] ① 已修复** — 按渲染引擎分流：`ReaderContentStyles._touchNativeSelectionCss()` 在 iOS 只发 `-webkit-touch-callout: none`（链接/图片长按气泡），不再发 `user-select: none`；「触屏不建原生选区」改由 WKWebView 原生真值承担——阅读器 `InAppWebViewSettings.isTextInteractionEnabled: !isIOSPlatform`（`WKPreferences.isTextInteractionEnabled`，iOS 14.5+，关掉文本选择手势/放大镜，与 CSS 无关，不影响 ::highlight 绘制，也不影响 app 自绘选区用的 caretRangeFromPoint / Range）。其它平台 CSS 一字不改。提交 `7057a7bbd37`。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_ios_highlight_user_select_bug2607_test.dart`：`debugDefaultTargetPlatformOverride` 钉 iOS 时 `@media (pointer: coarse)` 块不含 `user-select`、仍含 `-webkit-touch-callout`；钉 Android 时仍含两种前缀的 `user-select: none !important`（1279 不回归）；源码守卫 `webview.part.dart` 含 `isTextInteractionEnabled: !isIOSPlatform`。既有 `reader_longpress_drag_select_guard_test.dart` 的「user-select:none 仍在」断言显式钉到 Android。真机证据 `fushi/integration_test/reader_ios_highlight_user_select_probe_itest.dart`（iOS 模拟器真 WKWebView + 阅读器同款 `isTextInteractionEnabled:false` + 本仓真实生成的 iOS 阅读器 CSS，三段各注册一条 Highlight 后 `takeScreenshot` 采样）：裸段落 / 有声书 cue span 必须画出，手动补 `user-select:none` 的对照段必须不画。
- **备注**：iOS 模拟器（iPhone 17 Pro / iOS 26.5，dpr 3）真 WKWebView 实测 2026-09-20：`highlightPixelRatio={a: 0.733, b: 0.0, c: 0.733}`——修复后 CSS 裸段落与有声书 cue span 都画出高亮，`user-select:none` 对照段 0（根因坐实），`CSS.highlights` supported=true，`isTextInteractionEnabled:false` 不影响 ::highlight 绘制。「长按不再起原生选区」这一半只能靠 `isTextInteractionEnabled=false` 的 Apple 文档语义（WKWebView 关掉文本选择手势），模拟器测试投不了 UIKit 长按手势，待用户真机验收（同 BUG-609/624）。
