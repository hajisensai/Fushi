## BUG-5308 · manga-read-aloud-highlight-not-rotated
- **报告**：2026-11-23（用户：应用内反馈 3ERe-0Q4q8，开发者本人）漫画朗读的当前句高亮（黄底橙框）在斜着的文字上仍是水平的正框，没跟文字一起转。
- **真实性**：✅ 真 bug。朗读高亮 `.ocr-box.manga-speaking`（`fushi/lib/src/media/manga/manga_overlay_html.dart` 修前 :1065-1066）画在块级 `<p class="ocr-box">` 上，而块框按 `block.rectangle`（轴对齐外接框）定位、不带任何旋转（`mangaOcrBoxesHtml`，修前 :49-95）；字级 `.ocr-char` 早已按 `region.rotation` 做 `transform:rotate`（:531-533），所以命中区是斜的，块框和高亮是正的。「显示识别范围」（BUG-2481）的块框、文字条当前块 / 悬停描边同理。
- **[x] ① 已修复** — 新增 `mangaBlockOrientedFrame`：由块内字格（转角取面积加权的 4θ 圆周均值，避开 ±45° 折叠跳变；边长与中心取全部字格四角在该坐标系里的投影范围）拟合出整块的有向矩形。斜块的 `.ocr-box` 加 `data-ocr-frame` 与 `--ocr-frame-l/t/w/h/r` 变量，`::before` 伪元素按它定位并 `rotate`；朗读高亮、识别范围框、`manga-ts-current` / `manga-ts-hover` 描边在斜块上改画到 `::before`，块框本身不再画正框。块几何与命中区不变（伪元素 `pointer-events:none`），全正立的块输出逐字节不变；文字条里块是 static 排版，不画斜框。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_tilted_block_frame_bug5308_test.dart`（拟合出的转角 / 边长 / 中心、正立块无外框、±45° 折叠、overlay 输出 `data-ocr-frame` 与转角变量）；`fushi/test/media/manga/manga_tilted_block_frame_bug5308_chrome_test.dart`（真 headless Chromium 跑生产 `__mangaSetSpeaking`，量计算样式：斜块高亮在 `::before` 上转 -20° 且与字格转角一致、宽高比是 1:3 的列而非外接框、块框无正框；正立块照旧；识别范围视图同理）。
