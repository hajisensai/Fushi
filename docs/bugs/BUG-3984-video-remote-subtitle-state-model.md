## BUG-3984 · video-remote-subtitle-state-model
- **报告**：2026-11-02（用户：应用内反馈 Xt3RCTPKhX，Android vivo V2339FA）——在线下载的字幕被归到「Fushi 互联服务端字幕」且删不掉；退出重进 / 切集再切回，之前下载 / 导入的字幕全部消失，再下载落成带 (x) 序号的副本；互联一直关着也显示「互联服务端字幕」。
- **真实性**：✅ 真 bug。远端（互联 / Jellyfin·Emby·Plex / 在线源扩展 / 直链）字幕状态把两种语义混在两个字段里：`fushi/lib/src/pages/implementations/video_fushi_page.dart` `_loadRemoteEpisode` 重放上次选中的本机档时写进后端默认槽 `_remoteSubtitlePath`（原 :4687），菜单把该槽画成固定文案「Fushi 互联服务端字幕」且不包删除菜单（`video_fushi/subtitle.part.dart` 原 :323-334），再按路径去重把同一文件可删的「本机导入」行藏掉（原 :394-421，副字幕 :507-581、手机遥控 `playback_remote.part.dart` :244-320 同一逻辑）；换集一开头把 `_importedSubtitleSources` 清空（原 :4633）且无任何持久化可重建；`_remoteSubtitlePath` 每集也从不复位；内嵌轨重放也写这个槽（原 :4732）；重放失败（文件不在 / cue 为空）静默落回默认分支。
- **[x] ① 已修复** — 拆成两份互不覆盖的真相：`_remoteSubtitlePath` 只放后端默认字幕（每集起播先清空，内嵌轨 / 本机档重放不再写它）；本机落盘字幕档按集持久化（`PreferencesRepository.remoteSubtitleFiles` / `setRemoteSubtitleFiles`，键同 `remoteSubtitleKey`），`_registerImportedSubtitleSource` / `_deleteSubtitleFile` 同步写，`_loadRemoteEpisode` 据此重建 `_importedSubtitleSources`；上次选中的本机档重放成本机行的选中态（旧数据补登记）；重放失败打日志 + 提示一次（新 i18n `video_subtitle_restore_failed`）。主 / 副字幕菜单与手机遥控字幕列表统一经新纯模型 `video_fushi/remote_subtitle_catalog.dart` 的 `remoteSubtitleFileEntries` 拼行（本机档总是成行且可删，与后端默认同路径时留本机行）；后端默认行文案按后端类型给（互联 / 媒体服务器 / 扩展源 / 视频源，新 i18n `video_subtitle_remote_default_*`）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_remote_subtitle_catalog_test.dart`（行模型、按集持久化跨实例 reload、重建过滤缺失文件、播放页接线源码守卫）。
