## BUG-2485 · Windows 来源链接规范化后被错误判无效
- **报告**：2026-09-10，用户新制“結果”卡片，点击 MiscInfo 来源链接后提示“来源链接无效或版本暂不支持”。
- **真实性**：✅ 真 bug。`packages/fushi_anki/lib/src/card_source_link.dart:239` 原先拒绝任何非空 `uri.path`。卡片保存 `fushi://source?v=1&…`，Windows 系统协议启动链会将它规范化为 `fushi://source/?v=1&…`，因此合法链接在书籍查找之前就被拒绝。只读核对真卡字段参数完整；隔离的临时协议捕获程序实际收到新增根路径 `/`、其余参数原样保留。Anki 自带 Qt 的 QUrl 独立探针没有改写 URL。此前集成测试从 `toUri()` 直接解析，遗漏系统规范化。
- **[x] ① 已修复** — 解析器仅接受空路径或单个 `/`，HTML 来源识别也兼容这两种形式；其他路径、未知参数、重复参数等拒绝规则保持。已有卡无需改写。
- **[x] ② 已加自动化测试** — `packages/fushi_anki/test/card_source_link_test.dart` 新增系统规范化形式解析、HTML 读回与非根路径拒绝断言；修复前实际 1 条失败，修复后整个文件 17 条通过（退出码 0）。真实阅读器集成用例改用系统规范化后的根路径链接，Windows 运行 `win-itest-20260910-094614-e8952b6b` 实际执行 1 条并退出 0，覆盖定位、进度保护及单层弹窗。改动文件静态分析通过；分析器 Windows 可选性能服务清理异常通过进程级隔离排除，正常与错误夹具分别验证退出码 0 / 3，未忽略代码诊断。
- **备注**：本机隔离传递证据为 `.codex-test/probe-source-shell.ps1` 及其捕获文件；该脚本只注册随机命名临时协议，finally 删除自身键，没有改动 Fushi 协议关联或 Anki 卡片。Qt 证据在 `.codex-test/anki-qurl-probe/`。
