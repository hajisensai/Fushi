## BUG-5612 · video-web-parentdata-conflict
- **报告**：2026-11-28（BUG-5611 集成测试 `fushi/integration_test/web_video_builtin_capture_itest.dart` 在 Debug 构建里发现，非用户报告）
- **真实性**：✅ 真问题（Debug 断言）。`develop`（`4d853cf7919`）上同样存在，不是 #4603 引入的，只是 #4603 的集成测试第一次在 Debug 下把它暴露出来。网页站流媒体书在 `VideoFushiPage` 以「制卡优先」档打开时，框架报两次 `Incorrect use of ParentDataWidget`：同一个 RenderObject 上叠了两层 `Positioned`——外层 `Positioned(left: 0, top: 0, right: 0, bottom: 0)`（即 `Positioned.fill`），内层 `Positioned(left: 0, top: 84, right: 0, bottom: 0)`。所有权链：`Padding ← SafeArea ← Positioned ← Positioned ← Stack ← Positioned ← Stack ← SizedBox ← Row ← AnimatedBuilder ← ⋯`。说明某个返回 `Positioned` 的叠层 builder 又被调用方包了一层 `Positioned.fill`。Release 里断言不跑，但内层的 `top` 偏移会被外层覆盖或丢掉，该叠层的位置可能不对。app 的 `FlutterError.onError` 会把它吞进错误日志，所以平时看不到。
- **根因**：`fushi/lib/src/pages/implementations/video_fushi/web_source.part.dart:1882`（修前）网页档视频槽 Stack 的最后一层写成 `Positioned(left: 0, right: 0, bottom: 0, top: barExtent, child: _buildOsdOverlay())`，而 `_buildOsdOverlay()`（`video_fushi/volume_osd.part.dart:371`，修前）自己返回 `Positioned.fill(child: SafeArea(...))`。外层 `top: 84` = 自绘标题行 32 + 返回条一行 52（`webVideoReturnBarExtent`）。两层 `Positioned` 落在同一个 RenderObject（OSD 的 `SafeArea` 底下那个 `Padding`）上，框架断言；Release 里两层先后写同一份 `StackParentData`，偏移取决于应用顺序。另外外层的 `top` 已含顶部系统让位，内层 `SafeArea` 又让一次，OSD 比返回条低 32。
- **[x] ① 已修复** — 结构上让「定位」只发生一次：`_buildOsdOverlay()` 改为返回未定位子树，两个 controls Stack 的挂载点（`layout.part.dart` 盘菜单态与 `_buildVideoControlsInner`）自己包 `Positioned.fill`；网页档视频槽的整套叠层抽成纯布局组件 `WebVideoSurfaceLayers`（`fushi/lib/src/media/video/web_video_surface_layers.dart`），所有入参都是未定位子树，由它统一摆放，OSD 放在返回条下面并 `MediaQuery.removePadding(removeTop: true)`（返回条已吃掉顶部让位）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/web_video_surface_layers_test.dart`：露出站点页面 / 有站点视频两种布局各 pump 一次，断言 `tester.takeException()` 为 null，返回条高 = 顶部让位 + 52、站点页面与 OSD 卡片都从返回条底边开始（OSD 不再多让 32）、有视频时画面铺满且返回条与 OSD 不挂。
- **备注**：复现：`$env:FUSHI_WEB_VIDEO_BUILTIN_CAPTURE_ITEST=1; .\tool\run_windows_itest.ps1 integration_test\web_video_builtin_capture_itest.dart`，在 FlutterError.onError 交还给测试 binding 的情况下即可看到。
