## BUG-5190 · gen4 迁移对拍：同一张卡的行只差继承来的卡片标志，整体回滚（多前身按卡 ID 排先后）
- **报告**：2026-11-22（应用内反馈 eZJEGqEt7K：macOS 3.4.0-debug.31044 复习库升级核对失败并回滚；hok7g7rPDx：Android 同版本 `migrationFailed`，没附报告，疑似同签名）
- **真实性**：✅ 真 bug（同一份历史在协议 3 与新代算出不同的卡片标志；旧库没受影响）。报告签名：`parity` 只有 `cards` 104/104，两侧例子是同一批卡 ID；`notes` / `stats` / `canonical` 无差异，`knownDifferences` 全 0（不是 BUG-5063 的换代表）；带盐 profile（`salts` 1，`aliases.salted` 30498）。用最小库复现出同一签名（下面的迁移测试，修复前 `cards` 1/1，列差异 `flag: 2 -> 1, new_position: 2 -> 1`）。
  - **根因**：卡片标志（`deck` / `suspended` / `buried` / `flag` / `newPos`）按 `historyFrom` 血统继承：自己没记的键取「血统里第一张有记录的前身」，血统按广度优先、同一层的前身按**卡 ID** 的 UTF-16 序排（修复前 `native/fushi_fsrs/src/registers.rs:1027` `cards_group` 的 `preds.sort_by(cmp_utf16)`，继承在 :1035-1046）。一张卡有两个以上前身（并入重复笔记、删光重导……）且前身记的值不同时，后继卡继承谁的由卡 ID 的先后决定。协议 3 的卡 ID 是原值（带 profile 盐），新代缓存层（`store/gen4/cache.rs` `cache_lineage` → `registers::card_lineage_flags`）用规范 ID，两种 ID 的先后约一半相反，于是同一张卡在两边继承到不同前身的 `newPos` / `flag` / 牌组……；`canonical` 只比调度状态（队列 / 到期 / 次数 / 记忆），这几列不在里面，所以只在 `cards` 行对拍里露出来。同一规则还在新代恢复（`store/gen4/cmd/writes_restore.rs` `card_inherited_at`）与协议 3 恢复的测试参照（`store/sync2/timeline.rs`）各写了一份，同样按 ID 排。
  - 现有报告只给行身份（`dryrun.rs` `diff_json` 默认 `ident()`），看不出是哪一列不同，这次靠复现定位。
- **[x] ① 已修复** — 继承规则改成与 ID 的写法无关：离这张卡最近、有记录的一层里，几张前身都有时取**生效写入最新**的（排序键 = 寄存器胜者同一把 `SortKey`：HLC 物理时刻、计数、写入者、修改记录 ID；`registers::later` / `WriteOrder`）。三处同一规则一起改：`registers.rs` `cards_group`（协议 3 与新代缓存层共用）、新代恢复 `writes_restore.rs` `card_inherited_at`（排序键取自这条写入按类拼出的落库行，`class.rs` `Index::class_winner_in`）、协议 3 恢复参照 `timeline.rs` `card_inherited_at`（`winner_at`）。不加已知差异：两边规则相同后对拍本来就该相同。另外，对拍报告的 `cards` / `stats` 差异默认带「同一身份两侧都有的行按列名的差异计数」与前几行「列: 旧 -> 新」（`compare.rs` `column_diffs`，`dryrun.rs` `diff_json` 的 `sameIdRows` / `columns` / `columnExamples`；这两类的列只有调度数值与 ID，不含笔记内容），对拍装置（`parity.rs`）的差异详情同样带上。
  - 行为变化：只在「同一层两张以上前身对同一个键记了不同的值」时，后继卡继承的值从「卡 ID 序在前的那张」变成「最近写的那张」。旧 Dart 生成的 300 个血统用例里只有 1 个落在这一类（`registers.rs` `RETIED_VECTORS`），其余逐字不变。
- **[x] ② 已增加自动化测试** — `store/gen4/migrate_tests.rs` `a_card_inheriting_from_two_predecessors_whose_salted_and_canonical_order_differ_migrates_cleanly`：带盐小库，一张卡 `historyFrom` 两张前身（挑带盐与规范先后相反的一对），前身记了不同的 `newPos` / `flag` / `deck` / `suspended`，跑真实迁移判 committed、`parity` / `canonical` 为空；撤掉修复即红（`cards` 1/1，与用户报告同签名）。`store/gen4/cmd/writes_tests.rs` `restore_writes_back_the_flag_of_the_latest_written_predecessor_of_a_layer`：恢复到后继卡自己还没记 `flag` 的时刻，两侧预览与状态相同、写回的是最新写的前身的值（ID 序在前的那张先写）。`registers.rs` `card_lineage_vectors_match_the_old_dart_implementation` 加独立参照 `latest_inherited`（只用寄存器公开读法）逐例比新规则，旧 Dart 期望在不受影响的 299 例上仍逐字比。
- **缺口**：
  - 没拿到用户的库，104 张卡是否全是这一类只能由用户「重新升级」复核；若还有别的列不同，新报告会带上 `columns` / `columnExamples` 直接指出列名。Android hok7g7rPDx 没附报告，未确证同签名。
  - 对拍装置（`parity.rs` `imported_from`）仍不写 profile 的盐（BUG-5063 缺口），本次临时让它写盐把全部协议 3 场景跑了一遍，除一个本就故意制造差异的干跑测试外没有新差异；固定成常设覆盖仍单独做。
- **备注**：同一层前身的血统列表（`l`，日志拼接顺序）仍按 ID 排；调度状态由日志按发生时刻重放得出，本次对拍的 `canonical` / `stats` 也一致，未见依赖这一顺序的列。
