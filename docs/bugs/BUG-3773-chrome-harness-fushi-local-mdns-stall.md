## BUG-3773 · chrome-harness-fushi-local-mdns-stall
- **报告**：2026-10-25（用户：dist_test 全量实跑时发现 Windows 本机 5 个 chrome 标签阅读器 suite 稳定红，Mac 不红）
- **真实性**：✅ 真问题（测试环境层，非阅读器 JS/CSS 回归、非 Chrome / node 版本问题）。竖排阅读器 CSS 的 `@font-face` 指向 app 虚拟域名 `https://fushi.local/fushi-assets/FushiVerticalPunctuation.woff2`（`fushi/lib/src/reader/reader_vertical_punctuation_font.dart:28`，`font-display: block`），生产里由 WebView 拦截器供给；headless Chrome harness（`tool/reader_pitch_headless/cdp_client.mjs` 的 `launchChromeDriver`）没有拦截，Chrome 去问系统解析器，Windows 对 `.local` 走 mDNS/LLMNR，实测 `curl https://fushi.local/...` 14 s 后才解析失败。分页 / VN shell 在 `await document.fonts.ready` 之后才 `applySentenceAudioCues`（`fushi/lib/src/reader/reader_pagination_scripts.dart:3268` 等），于是竖排页 cue 迟迟不挂（实测 ~20 s），harness 在 `evalOnPage` 里读到 `cueWrappers.size == 0` → 「cue wrapped into several pieces (0)」「has lanes」等断言红；30 个页面每页多等十几秒，整段 harness 108 s 超过 Dart 侧 100 s 预算 → `Expected: <0> Actual: <-1>`。横排页不引用该字体故不受影响；macOS 上 `.local` 解析失败快，所以 Mac 不红。CI 无 Chrome 自跳过，不暴露。
- **[x] ① 已修复** — `tool/reader_pitch_headless/cdp_client.mjs:359` 启动 Chrome 时加 `--host-resolver-rules=MAP fushi.local ~NOTFOUND`，虚拟域名在所有平台上立即解析失败（与 Mac 上原有行为一致：字体回退、`fonts.ready` 立即 resolve），不再依赖系统解析器时序。highlight_lanes harness 从 108 s（红）降到 41 s（绿）。生产路径不变。
- **[x] ② 自动化测试** — 回归即这 5 个起真 Chrome 的 suite 本身（Windows 本机修复前必红、修复后绿）：`fushi/test/reader/highlight_lanes_test.dart`、`highlight_stroke_marker_test.dart`、`vn_illustration_screen_test.dart`、`vn_pointer_seek_cue_hit_test.dart`、`vn_sentence_audio_live_text_test.dart`；本机定向跑 exit 0、7 个测试全过、0 skip。
- **备注**：其它走 `launchChromeDriver` 的 harness 同样受益。未额外加源码扫描守卫——flag 被删时这 5 个 suite 在 Windows 上会直接变红。
