## BUG-1841 · 自定义主题「+新建」和「编辑」图标进编辑页前就落库空主题
- **报告**：2026-08-25（用户：点击主题的两个编辑图标任意一个就会自动增加一个主题，即使什么都没改；一般设计应该不保存就不会自动增加）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/settings/settings_actions.dart`（修前）：`createBlankCustomTheme()` 先 `appModel.upsertCustomTheme(entry)` 把一条空主题写进列表、再 push `CustomThemePage(themeId: created.id)`。「+新建」圈无条件走这条路；「编辑」按钮在当前不是自定义主题时（`activeCustomThemeEntry == null`，即用户停在系统/预设主题上）也走这条路。所以只是点开编辑页看一眼、什么都不改、直接返回，swatch 行已经多了一个「Custom N」。编辑页 `custom_theme_page.dart` 的 `_applyAndClose` 才是用户意义上的「保存」，但入口层已经抢先写库。
- **[x] ① 已修复** — `settings_actions.dart`：删掉 `createBlankCustomTheme` / `blankCustomThemeSeed`，「+」push `CustomThemePage()`（无 id），「编辑」push `CustomThemePage(themeId: activeCustomThemeEntry?.id)`，两个入口都不再写库。`custom_theme_page.dart`：`themeId == null`（或 id 不在列表）= 草稿——用品牌默认种子 `kCustomThemeDefaultSeed`、无角色色、只活在 State 里，只有「应用」才 `upsertCustomTheme`；同时删掉了 null-id 时回退到旧扁平偏好 `customThemeSeed/customThemeFontColor…` 的死路径（三个调用点都传 id，从没走过）。草稿不渲染「删除」按钮：列表里没它、`deleteCustomTheme` 是空操作，但 `_resolveThemeKeyAfterDelete` 会顺手把全局主题键改到别的主题，属于同类副作用。
- **[x] ② 已加自动化测试** — `fushi/test/pages/custom_theme_page_draft_no_persist_test.dart`（widget 行为：记录型 AppModel 断言「+」/「编辑」两入口 push 的是 `themeId: null` 且零 upsert；草稿页 initState 零 upsert、无删除按钮、默认名 hint = 长度+1、点「应用」恰一次 upsert 且种子为品牌默认；不应用直接离开零写入；已有条目仍可编辑且有删除按钮）+ `fushi/test/settings/multi_custom_theme_swatch_guard_test.dart`（源码守卫：swatch 行不得出现 `upsertCustomTheme(` / `createBlankCustomTheme`）。变异实测：把预落库塞回「+」入口，两套测试各红一条。
- **备注**：测试里第一个 `Scrollable` 是 AppBar 动作区的横向滚动条，拖它正文列表纹丝不动（`maxScrollExtent` 恒 0）；要滚正文必须按 `AxisDirection.down` 挑。相邻但未动的既有行为：编辑已落库主题时点「删除」无论它是否是当前活跃主题都会把全局主题键改到「第一个剩余自定义主题/系统主题」——用户在预设主题上删一个自定义主题也会被切走，与本 bug 同形，未在本轮处理。
