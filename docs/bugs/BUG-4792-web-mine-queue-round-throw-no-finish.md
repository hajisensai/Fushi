## BUG-4792 · 网页视频制卡队列一轮中途抛异常时不收尾：交接页回不去、后台制卡页不关、调度器停在「在跑」
- **报告**：2026-11-17（网页视频只读补查 gap-webvideo-2，复核 confirmed）
- **真实性**：✅ 真 bug（控制流确证）。`fushi/lib/src/pages/implementations/web_video_fushi_page.dart:1588-1695`（修前）`_runMineQueue` 只有 `try {…} finally {…}`，整轮收尾 `_finishMining(...)` 写在 finally **之后**。try 里没被各自 catch 包住的 await：`getTemporaryDirectory`、`resolveTargetMiningImageMode`（只吞 `Exception`）、`_navigateForMining` 的 `loadUrl`、`_mineQueue.markFailed` / `markDone` 的 DB 写、`runner.capture`（`encodeAudio`、截帧）、`_resolveCardMedia`。任何一处抛出 → `_finishMining` 被跳过：交接页不 `_reopen` 回原档；后台制卡页不关页，`WebMineBackgroundRunner` 的 `openMiningPage` 永不完成，后台自动制卡到重启前不再跑（`_autoRunTriggered` 已为 true，开跑截止也不再兜底）；空闲调度器不 `runFinished()`，停在高频轮询。finally 里 `loopback.stop()` 自己抛出时连 `_mineRunning` 都不复位。出错那一行还留在待办，下一轮原样再撞。
- **[x] ① 已修复**（`e40b885fc55`）— 一轮的编排抽到 `fushi/lib/src/mining/web_mine_queue_run.dart`：`runWebMineQueueRows` 对每一行 try/catch——记日志、标这一行失败、接着跑下一行（抛出时已在让位 / 页面已卸载的不标失败，留待办）；`runWebMineQueueRound` 保证 body 抛不抛、某一步还原抛不抛，后面的还原步骤都执行且不向外抛，`_finishMining` 在它返回后无条件调用。行内抛过错时收尾先暂停站点（否则还原会话音量后会外放）。整轮准备步骤抛出且是自动制卡时本页置 `_autoGaveUp`，不让空闲调度每几秒原样重撞。
- **[x] ② 已加自动化测试** — `fushi/test/mining/web_mine_queue_run_test.dart`（一行抛出后面照跑、导航抛出、标失败自己抛出、让位后抛出留待办；「runWebMineQueueRound」组：body 抛出 / 某步收尾抛出 / 同步抛出时其余收尾照常执行）；`fushi/test/media/video/web_video_mine_queue_guard_test.dart`「BUG-4792 / BUG-4793」组钉页面确实走这套骨架、`_finishMining` 在骨架之后。
