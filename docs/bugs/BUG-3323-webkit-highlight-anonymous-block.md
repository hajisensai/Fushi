## BUG-3323 · iOS/macOS 分页阅读器拖选与查词高亮不可见（页顶注音预留的块级 p::after 让正文进匿名块）
- **报告**：2026-10-13（用户：hajisensai/Fushi#2108「最近出现的，现在的复制框看不到范围了」，iPhone 截图：长按拖选后只有两个选区手柄与「搜索 / 复制 / 收藏」操作条，选中的文字没有任何底色）
- **真实性**：✅ 真 bug（WebKit 专属，分页模式；09-28 BUG-2761 引入）。根因两段：
  - `fushi/lib/src/reader/reader_content_styles.dart` 的 `_webKitPaginatedRubyReserveCss`（BUG-2761 / BUG-2799）在 iOS / macOS / Linux(WPE) 分页模式给每个 `p` 发 `p::after { content:""; display:block; margin-block-end:-R }`。块级伪元素让 `p` 的直属文字被包进**匿名块**。
  - WebKit 对布局父级是匿名块的文本节点**不绘制任何 `::highlight()`**。Playwright WebKit 探针：同一 Range 红色高亮像素命中——裸段落 0.77、`p::after{display:block}` 0.00、`::before` 块级 0.00、`<div>文字<div></div></div>` 0.00、`display:flow-root/table` 的 `::after` 0.00；`::after` 行内 / 行内块 / 绝对定位 0.77；文字包在 `<span>` 里 0.77；`p::highlight()` / `*::highlight()` / `:root::highlight()` 写法全部 0.00。Blink 全部正常。iOS 26.5 模拟器 WKWebView（swiftc 直编探针）同样：无 `::after` 0.688、有块级 `::after` 0.000（与 `isTextInteractionEnabled` 开关无关）。
  - 用户截图像素佐证：选区那一列与纸色完全一致（253,253,255），不是高亮色太淡。
  - 受影响的是所有 CSS Custom Highlight 层：拖选 / 查词 `fushi-selection`、收藏 `fushi-hl-*`、搜索 `fushi-search`。有声书当前句、ruby 内的字走元素 class 背景，不受影响——所以看起来是「只有手柄没有选区」。
- **[x] ① 已修复** — `2b8fe16539`：不动 BUG-2761 的预留（负边距只能挂在块级盒上才参与折叠与分栏截断；改段落 margin 的方案 BUG-2761 已排除：章首不截断、覆盖书自带边距；WebKit 也不支持块级 `box-decoration-break: clone`，实测第二栏顶 0 vs Blink 40）。改在高亮侧：`ReaderSelectionScripts.source()` 新增幂等全局 `window.__fushiEnsureHighlightPaintable(textNode)`——文本节点的父元素是块容器且有在流块级子盒（真实子元素，或带 content 的块级 `::before/::after`），或父元素是 flex/grid 容器时，把该文本节点**原样移进**无样式行内元素 `<fushi-hl-text>`（节点身份与偏移不变，包装不产生盒子）。四个写入点在**建 Range 之前**调用它（建好再搬会让活 Range 塌缩）：`highlightSelection`（拖选 / 查词）、`HighlightBridge` CSS 分支（收藏）、分页 / 连续 shell 的 `scrollToSearchMatch`、VN 的 `highlightSearchMatchOnScreen`（搜索）。
  - 验证：Playwright WebKit 用真实 iOS 阅读器 CSS + 生产选区脚本跑 begin/update/endRangeSelection，选区内纯纸色像素占比修复前 0.673 → 修复后 0.000；iOS 26.5 模拟器同法 0.737 → 0.144（剩余是字形间隙外的行距），截图左右对照与用户截图一致 / 恢复正常。三种 view mode：翻页修复前不画、修复后画；滚动与 VN 不发预留 CSS，修复前后都正常且不做任何包装（wrapped=0）。包装前后每个文本节点的字形矩形逐一相等（排版零变化）。Blink（Chromium）修复前后都正常。
- **[x] ② 已加自动化测试** — `2b8fe16539`：`fushi/test/reader/reader_highlight_paintable_bug3277_test.dart`（+ 同名 `.js`）：node 真跑生产安装器，钉「块级 `::after` / 块级子元素 / flex 容器 → 包装且节点身份不变、幂等」「纯块段落 / 行内子元素 / 行内或绝对定位或无 content 的 `::after` / 浮动或 display:none 子元素 / 行内父级 → 不动」；Dart 侧钉四个写入点都在 `document.createRange()` 之前调助手、助手在 `fushiSelection` 之前安装。WebKit 真绘制只能在 WebKit 里验，像素证据见上。
- **审查补丁**（合并前）：助手在 Blink（UA 含 `Chrome/`：Android WebView / WebView2）上直接 no-op——Blink 本就能在匿名块里画高亮，搬节点只剩副作用（拖选每帧的 computed-style 探测、结构选择器翻转、可能截断同节点上的原生选区）；文本父元素唯一的元素子节点是 `<img>` 时不搬（搬了会让阅读器的 `p > img:only-child { display:block }` 失配、插图变行内、段落在查词瞬间重排），这类段落在 WebKit 上保持修复前的不画状态。`.js` 守卫加了对应用例。
