## BUG-5302 · 互联音乐库：客户端歌词页 / 卡拉 OK 页放 host 的 MV（依赖 #4249）
- **报告**：2026-11-23（拍板台 design-imusic-q0..q12 实现分期，PR 分支 `claude/imusic-impl`）
- **真实性**：✅ 真缺口（分期待办）。host 侧已下发 MV 绑定（`GET /api/library/music/tracks/<uid>/videos`，含 YouTube 绑定的 `youtubeRef`，design-imusic-q7「做」）并能签 `musicVideo` 流票；客户端 `fushi/lib/src/media/music/server/interconnect_music_client.dart` 已实现 `MusicServerVideoSource`（`videosFor` / `openVideo` / `setVideoOffset` 写回）。但歌词页 MV 背景控制器 `MusicMvBackdropController` 与自动匹配都在**未合并**的 PR #4249，develop 上没有消费端，所以客户端还看不到 host 的 MV。
- **[x] ① 已修复** — #4249 合入后：歌词页背景控制器 `MusicMvBackdropController` 改成只管播放与对齐，画面来源由解析器（`MusicMvSourceResolver`）按曲目来源给（`fushi/lib/src/pages/implementations/music/music_lyrics_mv_backdrop.dart`）：本机曲目 `watchLocalMusicMvBackdrop`，互联 host 曲目 `watchFushiHostMusicMvBackdrop` → `resolveFushiHostMusicMvBackdrop`（host 上第一条有字节的绑定签 `musicVideo` 票；YouTube 绑定不当背景，与本机一致）；曲目本身是 MV 视频时 `InterconnectMusicBrowser.openTrackPicture` 另签一条原样画面流、偏移 = CUE 起点（design-imusic-q8 a：两条连接）。`MusicMvBackdropSource.release` 在换曲 / 换画面 / dispose / 迟到结果时还票（幂等）。卡拉 OK / MV 页（`music_mv_page.dart`）抽出 `MusicKaraokeMvBinding`：`MusicKaraokeLocalBinding`（本机行）与 `MusicKaraokeHostBinding`（画面签票、离页 release；YouTube 绑定由本机 YouTube 音源取，受 `isYoutubeMusicSourceAvailable` 门，iOS 不出；「曲库音轨」请 host 截好这一首（`forDownload` = 原样 + `segment`）；±100 ms 微调 `setVideoOffset` 写回 host）。host 曲目的服务器菜单加「MV」入口打开 host MV 列表页（`MusicHostMvPage`，同文件）。DTO 加 `label`（文件名 / YouTube id）供列表显示。
- **[x] ② 已加自动化测试** — `fushi/test/media/music/server/interconnect_music_mv_test.dart`（背景取第一条非 YouTube 绑定签票、release 只还一次；MV 视频曲目另签原样画面流且偏移 = CUE 起点；host 绑定的画面 / 曲库音轨 `segment` 票 / 微调 PUT；iOS 过滤 YouTube）；`fushi/test/pages/music_lyrics_mv_backdrop_test.dart` 回归；视频构造点守卫登记歌词页背景。两台真机对齐（蓝光 m2ts）未做，留给合并后真机验收。
