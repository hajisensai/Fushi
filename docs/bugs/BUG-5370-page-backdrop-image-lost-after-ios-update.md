## BUG-5370 · page-backdrop-image-lost-after-ios-update
- **报告**：2026-11-24（用户：应用内反馈 nvX37PiR_l）iOS 更新后自定义页面背景图丢失，回落默认样式。
- **真实性**：✅ 真 bug。`fushi/lib/src/models/theme_notifier.dart` 的 `importPageBackdropImage` / `importPageBackdropModuleImage`（修前 :1415 一带）把复制件的**绝对路径** `<support>/page_backdrop/<slot>-<ms>.<ext>` 写进 `page_backdrop_image_landscape` / `_portrait`、模块 JSON `page_backdrop_module_images` 以及各配置停放的 `<键>::<uid>`（键定义在 `fushi/lib/src/utils/adaptive/page_backdrop_style.dart:111-144`）。iOS 每次安装 / 更新换容器 UUID（桌面换数据根时 support 根也整体搬走），启动对账 `SandboxRelocation.reconcile` 只按 `fushi/lib/src/storage/path_rebase_coverage.dart` 的 `kPathRebasePrefs` 重基偏好，而这份清单没有任何 page_backdrop 键——守卫只扫 `getPref/setPref('字面量')` 且按 path|dir|root|file 认键名，`page_backdrop_image_landscape` 既是 const 声明、名字也不像路径，两头都漏。旧路径悬空，`_verifyPageBackdropImages`（修前 :1337）`File.exists` 判不存在，回落默认样式；文件其实还在新容器的 page_backdrop 目录里。修前的清扫 `_sweepUnreferencedPageBackdropImages` 还按整条绝对路径比对引用，旧路径悬空时下一次换图会把目录里仍被引用（停放配置 / 模块）的文件当孤儿删掉。
- **[x] ① 已修复** — 偏好只存背景图目录里的**文件名**，读时按当前目录拼成绝对路径（`resolvePageBackdropImagePath`，与容器根 / 数据根无关）；`ThemeNotifier` 持有解析好的目录（`AppModel` 构造前先解析并 `usePageBackdropImageDirectory`，首帧不闪默认背景）。存量绝对路径在载入时按文件名改写一次（`_healStoredPageBackdropImagePaths`：live 两张、模块 JSON、各配置停放值，文件在当前目录里才改，与 `healMissingFontFilePaths` 同法，串在背景图写操作队列里）。清扫与取色缓存都按文件名比对。四个设备本地键在 `kPathRebasePrefs` 登记为非路径（写明理由），守卫新增「`kPageBackdropDeviceLocalPrefKeys` 每个都要登记」。
- **[x] ② 已加自动化测试** — `fushi/test/models/theme_page_backdrop_accent_test.dart`：导入只存文件名、目录整体搬到新根后重建 notifier 仍解析到新位置（全局横竖屏 + 模块 + 取色缓存命中）；存量旧容器绝对路径载入后 live / 模块 / 停放键都改写成文件名、目录里没有的不改、随后换图的清扫不误删停放引用的文件；纯函数用例。`fushi/test/storage/path_rebase_coverage_guard_test.dart`：页面背景设备本地键必须登记。
- **备注**：iOS 真机复测（装新 TestFlight 后背景仍在）未做，需真机；单测已模拟容器根换掉。
