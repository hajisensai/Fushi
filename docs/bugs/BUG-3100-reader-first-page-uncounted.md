## BUG-3100 · 翻页后开始计时模式下打开时那一页不计字数
- **报告**：2026-10-09（用户：群反馈 10-08「发现翻的第一页居然没有计字数」「我看完一页发现字数是 0」「我说为什么阅读速度这么慢」；开发者确认「你的是翻页后开始计数，不把你这页算进去，那得改一下」）
- **真实性**：✅ 真 bug。阅读计时开始方式 = 「翻页后开始」（`on_page_turn`）时，打开书后时钟停着；首次向前翻页的那次落定里，`fushi/lib/src/pages/implementations/reader_fushi/navigation.part.dart` 的 `_refreshProgress` **先** `_readLedger.arrive(unitStart, unitEnd)`——账本把刚翻走的第一页（打开时停着读的那页）结算成 `onCredit` → `StudyClock.addChars`，而此刻时钟还没起（`isRunning == false`），`addChars` 按停表丢弃（BUG-2210 规则）；**之后**才 `_noteStudyClockUnitArrival` 让开始方式门起表。于是第一页字数永久丢失：读完一页统计为 0，整次会话的字/时系统性偏低。代码注释里写的「先 arrive 再起表，打开时停着读的那页按停表丢弃」正是这个口径，开发者已改判。
- **[x] ① 已修复** — 新增 `arriveReadUnitThroughStartGate`（`fushi/lib/src/stats/reader_study_clock_start_mode.dart`）把顺序钉成「先喂门（首次翻页即起表）、再 arrive」，阅读器 `_refreshProgress` 只经它落定；起表回调 `_onStudyClockAutoStartOnTurn` 仍只走 `_startStudyClockFromGate`（`studyClockMayRun` 统一判据，面板压正文 / 切后台时照旧不起表、字数照旧丢弃）。只补字数，不补打开到首次翻页之间的时长（「翻页后开始」的本意）。打开即开始 / 手动两种模式口径不变。提交见 PR `pr/stats-slim`。
- **[x] ② 已加自动化测试** — `fushi/test/stats/reader_study_clock_start_mode_test.dart`「BUG-3100 首次翻页时打开那页的字数」（真 `ReadUnitLedger` + 真开始方式门 + 「停表即丢」替身时钟：翻页后开始下第一页 500 字在首次翻走时计入；旧顺序这里是 0；打开即开始 / 手动口径不变）；接线守卫 `fushi/test/pages/reader_study_clock_start_mode_wiring_guard_static_test.dart` 钉 `_refreshProgress` 只经 `arriveReadUnitThroughStartGate`、不许裸 `_readLedger.arrive`。
- **备注**：真机未验（阅读器 WebView 路径，本次只在纯逻辑层 + 源码接线层验证）。同一群聊里另一条「翻页开始计时只在第一次翻页生效，中途手动暂停后再翻页不会重新开始」群友自己也说「各有利弊」，开发者未表态，属产品取舍，**未改**，记为待定。
