## BUG-1607 · 弹幕退场时其余弹幕整屏重排
- **报告**：2026-08-14（用户：让弹幕改成出屏幕再消失，并且消失不会重排。现在弹幕消失逻辑有问题）
- **真实性**：✅ 真 bug。三个独立根因，都在「谁占哪一行」这条链上：
  - **A｜行号是活动集的纯函数，不是弹幕自己的属性（主因）**：`fushi/lib/src/media/video/video_danmaku_layout.dart:109`（旧 `nextFreeMs` 局部数组）+ `:154`（旧 `_pickLane`）。`layout` 是静态纯函数，每帧拿**当前活动集**从零跑一遍贪心分配。任何一条弹幕过期离开活动集，排在它后面的弹幕全部重新分配行号——整屏弹幕在同一帧集体换行。实测（视口 400×200 / maxLanes=4 / 8 条每 500ms 一条）：`positionMs=8100` 第一条过期的那一帧，第二条的 `Positioned.top` 从 50.0 跳到 0.0。用户说的「消失逻辑有问题」就是这个：真正扎眼的不是那条走掉的，是剩下的全体抖一下。
  - **B｜密度上限中途放行，被挡下的弹幕会凭空冒到画面中间**：旧 `capped = active.sublist(0, allowed)` 每帧按当前活动集截断。超出 `maxActive` 的弹幕这一帧不画，等前面的过期后又落进窗口，于是它从画面**中间**凭空出现（它的 `progress` 已经走了一半）。这是 A 的镜像：不该发生的可见性变化。
  - **C｜同一行的「空出时刻」是拍脑袋常数**：旧 `nextFreeMs[lane] = item.startMs + 900`。900ms 与「上一条尾巴是否已经完全进屏」毫无关系。实测同一样本 `positionMs=1000`：第 0 行上一条的右边缘还在 x=444.5（视口宽 400），新一条已被放进同一行的 x=400，头尾直接叠住。旧实现之所以看着还行，是因为缺陷 A 每帧重排，把重叠洗掉了——A 一修，C 就会暴露成常驻重叠，两者必须同一批改。
  - **附带**：`videoDanmakuTextStyle` 的描边阴影（`offset:(1,1)` + `blurRadius:3`）会画到文本框外 4px，而位移几何只按文本框宽算。BUG-1297 修好「文本框出屏」之后，过期那一帧屏幕左缘仍留着 4.0px 阴影跟着被抹掉——「出屏幕再消失」最后这一截。
- **[x] ① 已修复** — 提交 `<pending>`。
  - 新增 `fushi/lib/src/media/video/video_danmaku_lane_board.dart`（`VideoDanmakuLaneBoard`）：**行号是弹幕自身的属性，出生那一刻定下、终身不变**；密度上限同样在出生那一刻裁决（挤不下就永久不出现，`rowFor` 返回 null）。于是一条弹幕的整个生命周期只有两件事——挑一行、滑出去，「消失」只剩「它自己走出去了」这一种原因。
  - `VideoDanmakuLayout` 从静态纯函数改为**有状态、按播放会话长期持有**（`VideoDanmakuOverlay._layout` 是 final 字段）。仅在换视频 / 改样式 / 改视口 / seek 时整板重置——那几次重排是用户动作的必然结果，与自然退场无关。
  - 行可用判据换成真实几何：两条都是滚动弹幕时 `dt >= D * max(w前, w新) / (视口宽 + max(w前, w新))`。`f(w前)` 是「前一条尾巴完全进屏」，`f(w新)` 是「更快的新条不追尾」（同一时长下行程 = 视口宽 + 自身宽，所以越宽越快）；两个约束都是时间的线性函数、`f` 单调递增，于是合并成对 `max` 求一次 `f`——没有分支，也没有 900 这种常数。任一方是固定弹幕则整行占满，等它自己离场。
  - 全行占满时的兜底从 `index % maxLanes`（每帧可能在两条分支间跳）换成「最早空出的那一行」，且同样 sticky。
  - 位移几何与行占用统一按**占地宽**（文本框 + 两侧阴影，`kVideoDanmakuShadowOverflow`）计算，退场真正发生在屏幕之外。
  - 顺带消掉两个 clamp 特例：行号统一自上而下（底部弹幕改为从最后一行往上挑，不再镜像 y），行数按「这条带真放得下几行」发放而不是靠 clamp 把越界行压回带内（那等于多个行号落在同一个 y 上互相覆盖）；行高下限改用 `VideoDanmakuTextMetrics.lineHeight` 实测值，不再是与 20px 字号对不上的 `18 * fontScale`。
- **[x] ② 已加自动化测试** — 几何层 `fushi/test/media/video/video_danmaku_exit_stability_test.dart`（退场不牵动幸存者：逐帧比对每条弹幕**自己出生那一帧**的 lane/dy；被密度上限挡下的不得凭空出现；过期帧文本+阴影整体越过左边界；同一行相邻两条的阴影框全程不叠边）+ 真实渲染层 `fushi/test/media/video/video_danmaku_overlay_test.dart::a danmaku leaving the screen never re-rows the survivors`（逐帧 pump，断言每条弹幕的 `Positioned.top` 终身不变）。
- **备注**：三组守卫均已**变异实测**，且转红位置与手算一致：① 分配板每帧强制重置 → 几何层「コメント1 在 positionMs=8100 换了行」+ 渲染层「top 从 50.0 变 0.0」+ 密度层「4 条变 12 条」三处同时红；② 行空出时刻退回 `startMs + 900` → 「第 0 行在 positionMs=1000 出现叠边（444.5 > 400）」红；③ 去掉阴影溢出 → 「过期那一帧仍留 4.0px 在屏内」红。断言基准刻意用**弹幕自己出生那一帧的落位**和**独立测得的宽度 / 独立的阴影常量**，不用本帧其它字段推导，避免几何一退化基准跟着偏（BUG-1297 第一版踩过的自洽陷阱）。未做真机复测。
