## BUG-2972 · 歌词模式高亮颜色无法修改
- **报告**：2026-10-05（用户：shishamo 反馈「歌词模式高亮颜色无法修改」）
- **真实性**：✅ 真 bug。歌词页是覆盖层主题架构，当前行色只认 CSS 变量 `--ly-current`（`fushi/lib/src/media/audiobook/lyrics_mode_html.dart:310` `.cue.current { color: var(--ly-current, $accentColor) }`；逐字扫过 `:350` 同样读它），而该变量由设计系统的 `LyricsHtmlTheme.currentColor` 写入（`lyrics_mode_html.dart:44`，取值来自 `lyrics_player_md3.dart:199` `cs.primary` / `lyrics_player_apple.dart:83` `Colors.white`）。Dart 侧传给 `generate` / `__lyricsUpdateStyle` 的 `accentColor`（`fushi/lib/src/pages/implementations/reader_fushi/lyrics.part.dart:303` `_readerLyricAccentColor()`，只取 scheme.primary、不读任何偏好）被变量回落值盖掉，`__lyricsUpdateStyle` 在 themed 态下还显式跳过字面色改写（`lyrics_mode_html.dart:973`）。全局「当前句高亮」主题角色 `audio_highlight_color` 也从不进歌词页。结果：歌词模式没有任何用户可控的高亮色通路，改哪个设置都不生效。
- **[x] ① 已修复** — 新增歌词专属偏好 `lyrics_highlight_color`（int ARGB，哨兵 0 = 跟随播放器主题；`ReaderSettings` / `ReaderFushiSource.lyricsHighlightColor` / `setLyricsHighlightColor` / `clearLyricsHighlightColor`，写后走 `onSettingsChangedLive` → `_applyStylesLive` → 歌词态 `_updateLyricsStyleLive` 热更）。`LyricsModeHtml.themeVars` / `applyThemeInvocation` / `generate` 增加 `currentColorOverride`，覆盖 `--ly-current` 及派生的 `--ly-upcoming`（×0.4）、`--ly-pill-bg/fg`；查词选区 `--ly-hl` 语义不变。`lyrics.part.dart` 全部四个主题发射点（首屏 generate、页面就绪注入、`_updateLyricsStyleLive`、`_applyLyricsHtmlTheme`）都带 `_lyricsCustomHighlightColor()`。设置入口（阅读设置「歌词模式」分组的高亮色行）由侧板重设计同分支提供。提交：见 claude/sh-reader-panels 分支 `fix(lyrics): user-controllable lyrics current-line highlight color (BUG-2972)`。
- **[x] ② 已加自动化测试** — `fushi/test/reader/lyrics_highlight_color_test.dart`：themeVars 有 / 无 override 的 `--ly-current` 与派生变量、`--ly-hl` 不变；generate 的 `:root` 内联含 override；applyThemeInvocation JSON 携带 override；偏好默认 0、持久化往返、setter 触发 live hook 且 clear 回 0；源码守卫——`lyrics.part.dart` 每个 `LyricsModeHtml.generate(` / `applyThemeInvocation(` 调用都传 `currentColorOverride: _lyricsCustomHighlightColor()`。
- **备注**：未在真机复测（UI 行由同分支侧板重设计接入后由用户在 Windows / Mac 热重载验证）。歌词页是独立文档，与正文三种 view mode 无关，不适用三模式验证。
