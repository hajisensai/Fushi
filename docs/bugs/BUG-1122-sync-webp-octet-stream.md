## BUG-1122 · sync-webp-octet-stream
- **报告**：2026-07-26（用户：）
- **真实性**：✅ 真 bug——sync server 的扩展名→Content-Type 推断副本缺 `.webp`：修复前 `hibiki/lib/src/sync/hibiki_sync_server.dart:2517` 的 `_guessContentType` switch 只认 png/jpg 等，`.webp` 落 default `application/octet-stream`（:2574）。封面/文件统一经 `serveFileWithRange`（同文件，Content-Type 取自 `_guessContentType`）下发，故 `/api/library/books`、`/api/library/videos` 的 `coverUrl` 指向 webp 封面时按 `application/octet-stream` 发送，对端 WebView/浏览器面（浏览器扩展、远端书卡等标准 UA 消费面）可拒绝内联渲染而当附件处理。webp 封面真实存在（视频海报刮削与游戏封面下载均可落 webp）。根因属「6 份扩展名→MIME switch 副本各自漂移」的一例：词典媒体/查词浮窗/anki 三份认 webp，sync server / EPUB fallback / 云上传三份不认。
- **[x] ① 已修复** — ``0db1c8d60``：根因修复 = 消灭漂移源头，6 份副本收敛到单一映射表 `packages/hibiki_core/lib/src/utils/mime_types.dart`（`kMimeTypeByExtension` + `mimeTypeForFilePath`，覆盖面取 6 份并集，含 `.webp → image/webp`）。`hibiki_sync_server.dart` `_guessContentType`、`sync_utils.dart` `guessSyncContentType`、`epub_book.dart` `fallbackMimeType`、`dictionary_media_types.dart` `dictionaryMediaMimeType`、`global_lookup_controller.dart` `_globalLookupImageMime` 改为查该表；`packages/hibiki_anki/lib/src/anki_models.dart`（独立模块，无 hibiki_core 依赖）持逐项镜像 `kAnkiMimeTypeByExtension`，由守卫测试锁定一致。
- **[x] ② 已加自动化测试** — `hibiki/test/sync/hibiki_sync_server_books_test.dart`（HTTP 层回归：`.webp` 封面经 coverUrl 下发必须 `image/webp`）+ `hibiki/test/sync/mime_types_test.dart`（webp 全入口断言、各历史分歧扩展名断言、anki 镜像逐项一致守卫、源码扫描守卫：lib 下不得再新增扩展名→image MIME 的 switch 副本）。
- **备注**：命名统一轮 G8 顺带审计出的真 bug。6 份副本之间无互相矛盾的映射（并集无冲突）；audio 语境的两份专用推断（`remote_audio_lookup_bytes.dart`：`.mp4/.aac→audio/mp4`、`.webm→audio/webm`、兜底 octet-stream；`lookup_audio_playback.dart` `audioMimeForPath`：`.opus→audio/ogg`、兜底 audio/mpeg）是查词音频播放语境的刻意映射，不并入共享表，但两者之间存在 `.opus`（audio/opus vs audio/ogg）与兜底值的分歧，留作后续独立收敛项。漫画页 `manga_hibiki_page.dart` `_mangaMimeForPath`（jpeg 兜底的图片服务）同样刻意保留，已进源码扫描守卫白名单。
