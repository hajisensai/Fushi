## BUG-3673 · 漫画 chrome 开着时查词，chrome 被「画进」查词弹窗（iOS）且弹窗开着仍能点到 chrome
- **报告**：2026-10-21（用户：应用内反馈 8HcJchWAcr，iOS 3.0.0+19763 iPhone 402x874@3；「Manga Overlay Invades Popup Dictionary」，3 张截图：快捷设置面板 / 页面网格 / 滑块+底部工具栏全部恰好被裁在弹窗圆角矩形里，弹窗外看不到 chrome）
- **真实性**：✅ 真 bug。漫画页主 Stack 把查词弹窗层（`manga_dictionary_host`）排在顶栏 / 底栏 chrome **之前**（develop 329a739431 `fushi/lib/src/media/manga/reader/manga_fushi_page.dart:6215`），chrome 画在弹窗之上：① 全平台——弹窗的全屏 dismiss barrier 盖不住 chrome，弹窗开着时点底栏按钮直接打开快捷设置 / 页面网格（截图 s0 / s1）；② iOS——正文与弹窗都是 WKWebView 平台视图，弹窗外壳 `FushiPopupSurface` 带圆角裁剪（`dictionary_popup_layer.dart` `clipBehavior: Clip.antiAlias`）。engine 对排在最后一个平台视图之后的 Flutter 内容，把它与**所有**更早平台视图的交集并成一个矩形挂到**最后那个**平台视图的 overlay 上（`flutter_3.47.6/engine/src/flutter/flow/view_slicer.cc:45-123` SliceViews 的 `for (int j = i; j >= 0; j--)` 并集 + 背景 `kDifference` 挖掉），overlay 再按该平台视图的非矩形裁剪裁（`FlutterPlatformViewsController.mm:893-895` `ApplyNonRectClipToOverlayCanvas`）。于是 chrome 及其打开的面板只在弹窗圆角形状里露出，弹窗外整块消失。初判「查词时 chrome 没收起」不是根因：EPUB 的悬浮 chrome 同样不随查词收起（设计如此），问题是 z 序。
- **[x] ① 已修复** — 查词弹窗层挪成主 Stack 的**最后一个**孩子（`manga_fushi_page.dart` `manga_dictionary_host`）：弹窗是模态浮层，barrier 盖住 chrome（点弹窗外照常走 `onDismissBarrierTap` 换词 / 关栈）；iOS 上 chrome 只叠在正文 WebView（无非矩形裁剪）之上，弹窗之后不再有 Flutter 内容。chrome 在弹窗以外的区域照常显示。
- **[x] ② 已加自动化测试** — `fushi/test/pages/manga_fushi_page_test.dart`「无 DB 行时页面安全降级」追加断言：词典宿主必须是页面主 Stack 的最后一个孩子。
- **备注**：iOS 合成行为只能在真机上目视验证，未在 iOS 真机复测。EPUB 阅读器（BUG-3292）刻意让 chrome 画在弹窗之上、弹窗避让 chrome；按上面的 engine 机制，iOS 上悬浮 chrome 被唤出时开弹窗可能同样整块消失 / 被裁进弹窗形状——本次不在改动范围内，未验证。
