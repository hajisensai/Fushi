## BUG-2800 · iOS 翻进新章节后振假名词突然撑开（有声书跟随高亮把 ruby 移进 span，WebKit 取消注音悬挂）
- **报告**：2026-09-30（用户：「翻页后自嘲这种有振假名的词突然岔开了 ios 端」，附录屏：竖排有声书播放中翻页，过场后「そう自嘲気味に」先正常显示，约 0.1 秒后「嘲」与「気」之间撑开一段空隙）
- **真实性**：✅ 真 bug。录屏逐帧：过场帧近全黑（跨章节快照过场，翻进了新章节文件）；撑开前注音「じちょう」尾部悬挂在「気」上方 3 视频像素，撑开后「自」「嘲」与注音都不动、「気」及其后整体下移 11 视频像素（≈7.5 CSS px）——即注音悬挂（ruby overhang）被取消。根因 `fushi/lib/src/reader/reader_pagination_scripts.dart` 的 `applySentenceAudioCues`：BUG-2780 为了让整句高亮连续，把整颗 `<ruby>` 用 `setStartBefore/setEndAfter` 移进 `span.fushi-sentence-audio-cue`。WebKit 对处在行内 span 里的 ruby 不再让长注音悬挂到邻字上（iOS 26.5 模拟器 Safari 实测：ruby 进 span 后前侧 +2.0px，ruby 与后文分属两个 span 时后侧再 +1.4px；ruby 作为段落直接子节点、两侧文字各自包 span 则与原书逐像素相同；pull 变量 / 高亮背景 / splitText 都不影响）。包裹在章节初始化的 `Promise.all(imagePromises).then(...)` 里异步执行，新章节首屏已经画出，于是用户看到正文「突然岔开」；包裹也会让已算好的分页几何失真。用从源码切出的真 `applySentenceAudioCues` 在模拟器上跑 6 个样例（Klee One / Hiragino）：旧实现 4 段字符位移（「俺は会釈をする。」8 字动 5 个、「大喝采を浴びた」7 字动 6 个）。
- **[x] ① 已修复** — ruby 永远不再被移动：`sentenceAudioWrapItems` 让 ruby 内的基字片段各自单独成组（wrapper 就地落在 ruby / rb 内、不跨 rt），ruby 外的文字仍按同父并组，但 `sentenceAudioInlineGap` 遇到 `<ruby>`（或含 ruby 的行内元素）就断开，不再把它吞进 wrapper。注音不能悬挂（邻字是汉字、注音远长于基字）时基字 wrapper 与邻 wrapper 之间会露出 ruby 撑出的间距（BUG-2780 的原始症状），新增 `fillSentenceAudioRubyGaps` 在高亮时量同一行相邻 wrapper 的缝，由 ruby 内那个 wrapper 用 `box-shadow`（只画在边框盒外、不参与排版）伸过去补色，`clearSentenceAudioCue` / `resetSentenceAudioCues` 撤掉。基字 wrapper 不再包住 rt，`cueIdAtDomPoint` 对落在注音上的点改按「同一颗 ruby 里的基字 wrapper」归属 cue（中键 seek / 查词句子身份不丢）。`reader_ruby_metrics_script.dart` 的 `probeRuby` 原先假定 `ruby.firstChild` 是基字文本，改为按文档序找首个不在 rt/rp 里的文本节点（否则有声书书里的 BUG-2779 度量会找不到基字）。模拟器真函数复测：6 段全部 0 位移，「漢/かんじかんじ」13.75px、「喝/かっさい」3.85px 的缝被补上，整句高亮连续、无叠色。
- **[x] ② 已加自动化测试** — `fushi/test/reader/sentence_audio_ruby_wrap_behavior_test.js`（node 真执行切出的 `applySentenceAudioCues` / `sentenceAudioWrapItems` / `sentenceAudioInlineGap` / `rubyForNode` / `fillSentenceAudioRubyGaps` / `clearSentenceAudioRubyGaps`：ruby 永远留在原父节点、基字 wrapper 在 ruby 内、rt 不被跨越、文字组遇 ruby 断开、含 ruby 的 `<em>` 不被吞、同列缝按实测补阴影且只给 ruby 侧、跨列与无缝不补、取消高亮清空），由 `sentence_audio_ruby_wrap_behavior_test.dart` 驱动；`fushi/test/reader/reader_ruby_metrics_behavior_test.js` 加「基字包在 wrapper 里仍能量到」用例；`fushi/test/reader/reader_audio_cue_identity_harness.mjs`（真 Chrome 跑生产 shell）改为从 ruby 内 wrapper 取基字并断言 ruby 留在原位，注音指针归属照旧由它钉住。换回旧实现即红。
