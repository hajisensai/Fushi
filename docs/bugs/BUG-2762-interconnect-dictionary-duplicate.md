## BUG-2762 · 互联页「上传到互联对端」里词典出现两次
- **报告**：2026-09-28（用户：设置 → Fushi 互联截图，「上传词典」开关与「词典 · 传输 ▾」并排，「词典重复了，把上传词典那个删掉」）
- **真实性**：✅ 真 bug。`fushi/lib/src/sync/sync_settings_schema.dart` 的 `interconnect.upload.section` 里同时有 `interconnect.upload_dictionary`（`SettingsSwitchItem`，驱动 `resolveChannelSyncFlags` → 互联通道自动双向 union）与 BUG-2494 加的 `interconnect.dictionary_transfer`（显式上传 / 下载）。两行都叫「词典」，开关文案是「上传」、实际却是双向 union；云备份那侧早已只剩显式动作，互联侧是唯一残留的自动词典同步。
- **[x] ① 已修复** — 删开关与它驱动的整条自动路径：设置项 + `_SyncSettingsState.interconnectSyncDictionary` + `SyncRepository.is/setInterconnectSyncDictionaryEnabled`（偏好键 `interconnect_sync_dictionary` 不再有读写方，旧行留库无害）+ `ChannelSyncFlags.syncDictionary`（自动 sweep 恒传 `syncDictionary: false`）+ i18n `interconnect_upload_dictionary(_hint)`。只藏 UI 不够：开过开关的存量用户库里那行仍是 true，会永远关不掉。随之退役的是删词典的远端传播（`AppModel._propagateDictionaryDeleteToRemote` / `deleteRemoteDictionaryAsset`，BUG-086 / BUG-1566）：没有自动并集就没有「下轮又被拉回来」的幽灵词典，远端那份是用户显式传上去的备份，本地删除不该连坐。`InterconnectSyncBackend.deleteRemoteDictionary`（host DELETE 端点客户端）保留。
- **[x] ② 已加自动化测试** — `fushi/test/sync/sync_settings_visibility_test.dart`（互联上传区只剩 `interconnect.dictionary_transfer` 一个词典行、`upload_dictionary` 不得回来）；`fushi/test/sync/interconnect_upload_toggles_test.dart`（自动 sweep 恒 `syncDictionary: false`、开关读取方与偏好键不得回来）；`fushi/test/sync/interconnect_channel_consumers_test.dart`（AppModel 删词典不再传播到远端）。
- **备注**：互联页词典现在与云备份页同形——只由「词典 · 传输 ▾」显式上传 / 下载。
