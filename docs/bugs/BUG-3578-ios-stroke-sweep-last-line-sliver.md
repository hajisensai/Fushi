## BUG-3578 · iOS 竖排笔触高亮落笔动画：跨三栏的句子最后一栏只剩右侧一窄条
- **报告**：2026-10-19（用户：iOS TestFlight，深色主题竖排，有声书当前句用马克笔样式 + 落笔动画，三张截图里每句的最后一栏「ら？」」「校舎で」」「い相手と見た証のはずだ。」高亮都只剩贴在文字右侧的一窄条；「ios 的自定义高亮，并且动画还是渲染有问题」）
- **真实性**：✅ 真 bug，iOS 26.5 模拟器 Safari + 当前 develop 生产引擎页（iOS 平台 `ReaderContentStyles.css` 马克笔 + 落笔动画 + `ReaderSelectionScripts.source()` + `engineShell`，Range 模式，正文 48px 让句子跨三栏）复现：竖排翻页切句 6 次里 4 次动画播完后与「窄条层 display:none 两帧重建」的真值不一致（最多 9.7 万设备像素），最后一栏只画出右侧一窄条，与用户截图同形；竖排滚动、VN 同样复现；跨两栏的句子（34px）与横排不复现。
  - 根因：`fushi/lib/src/reader/reader_selection_scripts.dart` 的 `markSvg`（修前 :1504–1518）把一组笔划画进**一张** svg，盒子包住整句所有行；每行的落笔动画是 SMIL `<animate>` 驱动的 clipPath 矩形。WebKit 竖排下这类动画的重绘区按 svg 盒子左右镜像：三栏时第一栏与第三栏的重绘互换，第三栏最后播，它的重绘落到第一栏上，自己只有与镜像区重叠的那一窄条被画出；之后没有别的东西再触发重绘，一直停在那里，翻页 / 整层重建才补全。BUG-3506 把 svg 从 1×1 溢出改成包围盒时，这条镜像问题被两栏的常见情形掩盖了（两栏时镜像大致落回句子自身）。
  - 排除的修法（同一装置实测）：给窄条层 `writing-mode: horizontal-tb` 整层排版错乱；只给 svg 改 writing-mode 无效；`will-change: transform`（svg 或窄条层）看似「0 差异」，实为整层高亮被提升到 body 背景之下、两边都没画出来的假修复。
- **[x] ① 已修复** — `markSvg` 改为**一行一张 svg**（`markOpen`：盒子 = 该行笔划包围盒，沿行 ±2em、跨行 ±3.5em，viewBox 同位同大），盒子以本行为中心，镜像后仍落在本行上；滤镜 / 纹理等共享 defs 只写进第一张（按 id 全文档引用），每行自己的 defs 与落笔 clip 跟着自己那张；`still` / `ink` 两串同样逐行拼，「形状没变不重建 DOM」的比较不受影响。复验（同一装置，修复版脚本）：竖排翻页 6 次切句差异 [0,0,0,0,0,268]、竖排滚动 ≤739、横排 0、VN 一处 6481（肉眼一致，文字边缘抗锯齿级），修前对应为 9.7 万 / 4.8 万 / 2.9 万级的整栏缺失。
- **[x] ② 已加自动化测试** — `fushi/test/reader/highlight_stroke_marker_harness.mjs`（经 `highlight_stroke_marker_test.dart` 跑真 Chrome）：`contained` 新增「每张笔触 svg 的跨行尺寸 ≤ 单行笔划带 7em」，跨多行的收藏句断言「一行一张 svg」并过 `contained`。WebKit 的镜像重绘 Chrome 复现不了，测试钉的是结构；把脚本换回修前版本实跑，红在「long favourite paints one svg per line」与「each stroke svg holds a single line (191.0 vs 154)」。
- **备注**：验证在 iOS 模拟器 Safari 生产引擎页，未在真机 TestFlight 包上复验；用户是深色主题，模拟器用的是默认浅色，机制与配色无关。取证装置：本机 `D:\hibiki-tmp\ioshlcue\pages4`（生成器 `assemble4.py` 在会话临时目录、dumper 同 BUG-3518 的 `dump_rig_test.dart` 加马克笔 + 动画配置），Mac `~/ioshlcue/pages4`，结果 `r7_*`（修前与假修复）/ `r10_*_pl`（修复）。
