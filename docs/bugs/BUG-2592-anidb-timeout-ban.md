## BUG-2592 · AniDB UDP 一次超时就全局封禁 90 分钟，整批文件全报限流
- **报告**：2026-09-19（用户：「很多刮削给干限流了」+ 后台任务截图；要求对齐 Shoko）
- **真实性**：✅ 真 bug（安装版库 `video_source_scrape_runs` 115/116 两次 sweep 的 summary 复盘 + 真实代码路径）
  - run 115（10:43）：BLEACH S17E41–44 哈希识别成功，E45 一次 FILE 无应答报「AniDB UDP 连接失败，请检查 UDP 9000 网络与防火墙」，之后**同一 run 内剩下 4 个作品 30 多个文件全部**「AniDB 当前限流或维护，已暂停请求」。app 重启后 run 116（11:38）同样剧本：E45–48 成功 → Re:Zero S04E13 一次超时 → 其余全「限流」。链路明明通着，一次丢包就整批报限流。
  - 根因 `packages/fushi_engine/lib/media/video/metadata/anidb_udp_file_client.dart:277-279`（改前）：同 tag 重发一次仍无应答 → `_block(AnidbUdpFailure.banned, 90 min)`，而 `_blockedUntilMs` 是**进程级静态**，此后每个客户端每个文件在 `_exchangeOnce` 入口直接抛 `banned`（`:303`），设置页「测试登录」同样被拒。把「无应答」当「服务端 ban」是误判：Shoko `AniDBUDPConnectionHandler.SendInternal` 对超时只 `Retry(1)`，第二次仍超时按 `SocketException` 原样抛、**不标 ban**；`IsBanned` 只由 `555 BANNED`（或全 0 应答）置位，任何其它响应码把它写回 false；600/601/602/604 只启动 300 s backoff。
  - 放大因素：`config.timeout` 15 s（Shoko 收发各 30 s），AniDB 高峰期 FILE 十几秒才回，容易被判丢包。
- **[x] ① 已修复** — 对齐 Shoko：① 超时默认 30 s；② 双超时只抛 `timeout`（本文件跳过、下次 sweep 由 `_hashBacklog` 重试）并进入**指数退避** 30 s × 2ⁿ⁻¹（封顶 10 min，Shoko 队列 `RetryPolicy` 30 s × 2ⁿ），窗口内报新原因 `backoff`（文案带剩余秒数）而不是「限流或维护」；③ 任何一条应答清零退避；④ 真 ban 只认 555 / 504（90 min = Shoko `BanTimerResetLength` 1.5 h），600/601/602/604 归 `maintenance` 退避 5 min（Shoko 300 s backoff）；⑤ 节流 / 退避 / 封禁状态改为可注入假时钟与假睡眠（`resetSharedState`），测试能覆盖。PR #1550（`f264f396926`）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/metadata/anidb_udp_file_client_test.dart` group「shared rate gate: timeout is not a ban (BUG-2592, Shoko parity)」：双超时只退避 30 s 不封 90 min、窗口内报 backoff 不发包、收到应答后退避从头算；连续静默 30→60→120→240→480→600→600 s；555 封 90 min / 602 退避 5 min 且对另一个客户端同样生效、到期恢复发包。
- **[x] ③ 第二轮继续对齐 Shoko**（同 PR 第 3 个提交）— 节流改 Shoko `UDPRateLimiter`（2 s / 连续活跃 >10 s 后 6 s / 空闲 120 s 重置，原平 4 s）；505 按 Shoko 视为会话无效（清会话、重登、同一条 FILE 重发一次），598 归会话错误并清会话，555/504 封禁时清会话；空闲 5 min 自动 LOGOUT（`idleLogout`，下一条请求重新 AUTH）。测试同文件：「rate limiter: 2 s per packet, 6 s once active…」「idle session is logged out…」、501/505/506 重登循环、598 分类。逐项对照与有意差异见 `docs/specs/2026-09-19-shoko-anidb-tmdb-parity.md`。
- **[x] ④ 第三轮**（同 PR）— AUTH 双超时 → 重建 socket 再登一次（Shoko `LoginWithFallbacks`/`ForceReconnection`，第一轮登录超时不进退避）；320 未收录文件改每日复查、连续 15 次不再自动问（`anidb_file_identities.miss_attempts`，schema v108，`migration_v108_anidb_miss_attempts_test.dart`），报告文案带复查次数。测试：UDP「AUTH that times out twice rebuilds the socket…」、`anidb_hash_identity_service_test.dart` 每日复查 / 15 次用尽 / 命中归零。
- **备注**：`_terminalFailure`（500/503/504/555 本客户端永久失败）语义不变。设置页「测试登录」新增 `video_anidb_login_test_failed_backoff` 文案。同一批还修了 Jikan 429（BUG-2595）。
