## BUG-5040 · 触屏在查词弹窗正文里拖选文字时弹窗被本体横滑关掉
- **报告**：2026-11-20（用户：应用内反馈 DrV7fPpWD2，iPad13,16 / iOS 27.0.1 / 3.3.0-debug.28434，漫画阅读器里「想选中弹窗里的一段释义做卡片，弹窗每次都消失」）
- **真实性**：✅ 真 bug（沿代码路径定位，未在 iOS 真机 / 模拟器复现）。根因 `fushi/lib/src/pages/implementations/dictionary_popup_layer.dart:2429`（`_BodySwipeDismissDetectorState._onPointerUp`）：本体横滑关闭检测器自 BUG-1242 起是**不进手势竞技场的 raw `Listener`**，包住整张弹窗 surface（含正文 WebView）。TODO-896 给弹窗 WebView 声明 LongPress / 横拖 / 竖拖识别器（`dictionary_popup_webview.dart` 的 `gestureRecognizers`），前提是「WebView 赢下竞技场 → 正文框选到不了检测器」，但 Listener 不参与竞技场，这个前提已不成立。触屏上长按选字后横拖扩选、或拖选区把手，轨迹都是明确横向，抬手时位移过阈（默认灵敏度约 94px）就 `onDismiss`。检测器是五个表面共用的，漫画阅读器只是用户当时所在的表面；桌面鼠标拖选不受影响（检测器只认触摸类指针）。
- **[x] ① 已修复** — 与 BUG-4925（PR #3867，同一检测器、Android 拖选区柄）合流为一套机制：弹窗 WebView 注入 `kPopupSelectionChangeReportJs`（文档选区每变成一段新的非空选区就经 `popupSelectionChanged` 冒泡 `PopupSelectionChangedNotification`），`_BodySwipeDismissDetector` 接住后把**这一划**作废、抬手不关；下拉关闭脚本同样在选区于本划内改变时不上报。iOS 上长按选字与拖选区柄都会触发 WebKit 的 `selectionchange`，覆盖本条现场。划之前留下的旧选区不挡滑关，与覆盖窗（BUG-2770）口径一致。合流时撤掉了本条最初的实现（抬手时经平台通道异步问 WebView「有没有选区」的 `touchOnNativeSelection` 探针，PR #3851）：它让「有任何旧选区」就挡住正文横滑，与 BUG-4925 的口径矛盾，且抬手后还要等一次跨通道往返。
- **[x] ② 已加自动化测试** — `fushi/test/pages/dictionary_popup_selection_swipe_guard_test.dart`（真实 `DictionaryPopupLayer`：划中选区变了不关、选区没变照常关、旧选区不挡且作废标记不漏到下一划；两段 JS 用 node 实际运行；注入与派发接线守卫）。
- **备注**：iOS 真机肉眼复测未做（本机 Windows，无 iOS 设备 / 模拟器）。假定 iOS 在 WKWebView 原生选区手势期间仍把 move/up 交给 Flutter 的 Listener、且 WebKit 在拖选区柄时派发 `selectionchange`——均为代码与规范推断，未实测；若 iOS 实际发 PointerCancel，根因另有所在，需设备日志。
