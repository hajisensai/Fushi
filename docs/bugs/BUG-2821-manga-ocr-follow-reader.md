## BUG-2821 · 移动端整卷 OCR 不跟读者翻页，翻到的页要等整卷识别完
- **报告**：2026-10-01（用户：移动端还不能边 OCR 边看，识别出来的结果不能马上用，要等 OCR 跑完）
- **真实性**：✅ 真 bug。逐页热替换链路本身是通的（执行器先写逐页缓存再发进度 → 注册表透传 → 阅读器 `__mangaReplaceOcr`），问题在处理顺序：整卷任务的起点只在开跑那一刻按当前页定一次，之后按固定顺序线性往后跑——`packages/fushi_engine/lib/ocr/manga_ocr_pipeline.dart:177`（本地 ONNX）、`fushi/lib/src/media/manga/ocr/google_lens_ocr_service.dart:220`（Lens）、`fushi/lib/src/media/manga/ocr/system_ocr_manga_service.dart:147`（系统 OCR）都是 `for (... in order)`，运行中没有任何改道入口。桌面上本地模型一页几秒，读者跟得上；手机上一页几十秒，读者翻得比识别快，翻到的页永远还没轮到，体感就是「要等整卷识别完才能查」。下载钩子 / 作品页排的任务更是从第 0 页起，阅读器接回后也改不了。
- **[x] ① 已修复** — 新增 `MangaOcrPageScheduler`（运行中可改道、每页恰好一次，不改道时与 `mangaOcrPageOrder` 逐项相同）+ `MangaOcrPageFocus`（读者当前页的改道通道）。本地 ONNX 经整卷 isolate 控制端口的 `_JobFocusMessage` 送进去（`MangaOcrVolumeJob.focus`），Lens / 系统 OCR 在各自循环里取；三者的逐页事件都如实带页号。所有起任务的入口（阅读器、下载钩子、作品页「识别本章」、OCR 向导后台任务）都带改道通道，阅读器每翻一页 `MangaOcrRunningJob.focusPage`，接回别处排的任务时先把读者当前页送过去。提交见 PR。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_ocr_follow_reader_test.dart`（调度器 / 改道通道 / 流水线中途改道顺序 `[0,4,5,1,2,3]`）、`fushi/test/ocr/manga_ocr_service_impl_test.dart`「读者翻页：焦点页实时转给在跑的任务」、`fushi/test/media/manga/ocr/manga_ocr_job_registry_test.dart`「focusPage」组、`fushi/test/pages/manga_fushi_page_test.dart` BUG-2449 接回任务时断言焦点 = 当前页。
- **备注**：远端主机 / 外部 mokuro CLI 不按页序处理，不跟随（`MangaOcrFocusableService` 是可选能力）。未在手机真机上复测（本机无 adb 设备）。直读章不识别是另一条根因，见 BUG-2822。
