## BUG-5555 · Windows 触控板滑条漫不跟手（慢、滑不动、偶尔反向），鼠标滚轮正常
- **报告**：2026-11-24（应用内反馈 AmYIZcxlKr，Redmi G 笔记本：触控板滑条漫时有时太慢、有时滑不动、甚至往反方向滑；鼠标滚轮正常；只有条漫阅读页，首页 / 设置页正常）
- **真实性**：✅ 真 bug（代码路径推断，本机无精密触控板）。触控板两指平移经 `packages/flutter_inappwebview_windows/lib/src/in_app_webview/custom_platform_view.dart` 的 `onPointerPanZoomUpdate` → `setScrollDelta`，原生侧 `in_app_webview.cpp` `sendScroll` 把每帧几像素的 panDelta 换算成**普通 WHEEL 鼠标事件**发给 WebView2（composition 托管下 WebView2 只有 `SendMouseInput` 这一个滚轮入口，没有精确滚动 / 手势相位）。条漫页（`fushi/lib/src/media/manga/manga_overlay_html.dart`，webtoon 模式不挂滚轮监听，`if (!IS_WEBTOON)` 那段只给跨页）把滚动交给原生：Chromium 对每个普通滚轮都起一段平滑滚动动画，碎 delta 连发时后一个不断改前一个的目标，手指和内容脱钩。鼠标一格是单个大 delta，动画正是想要的，所以只有触控板坏；Flutter 页面自己滚动不经 WebView，所以正常。同一仓里查词弹窗（`popup.js` BUG-870 / BUG-2834）与正文连续模式早已页内接管细粒度滚轮、1:1 同步滚动，条漫是漏掉的那一处。
- **[x] ① 已修复** — `manga_overlay_html.dart` webtoon 模式新增滚轮监听：像素模式且 |deltaY| < 60 判为细粒度设备并锁定到本次手势（200 ms 空闲后重判，甩动中途的大帧不被误判成鼠标），`preventDefault` 后 `window.scrollBy` 同步 1:1（亚像素余量跨帧累计），并让页内触摸惯性让位；放大态横向照旧走 `_panBy`。鼠标一格（大 delta / 行 / 页模式）、Ctrl+滚轮缩放不动。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_webtoon_trackpad_wheel_js_test.dart`：node 执行生成文档里真实的监听，5 例（碎 delta 被接管且 1:1 + 余量不丢 + 反向跟手、同手势大帧仍同步、鼠标一格 / 行模式交给原生、空闲后重判、Ctrl 留给缩放 + 放大态横向走 `_panBy`）。修前文档里没有这段监听，用例全红。
- **备注**：未在精密触控板真机上复测。「偶尔反向」没有找到独立机制：页内 1:1 之后内容位移 = 手指位移 + 宿主补的惯性（`TrackpadFling`，速度采样与 Flutter 自家 Scrollable 同一个 VelocityTracker），若真机上仍见反向，下一步查 `TrackpadFling` 的抬手采样。别的原生滚动的 WebView 页面（浏览模块里的网页等）走的是同一条「碎普通滚轮 → 原生平滑动画」链路，同样可能不跟手；WebView2 没有精确滚动输入口，插件层无法通用修，要逐页接管。
