## BUG-583 · app 外查词第一个弹窗出现/嵌套子弹窗打开或消失时父卡残留闪烁 + 子弹窗出现被裁一帧再跳进来

- **报告**：2026-07-07（用户：TODO-1231 复诉；+499/BUG-567 修过内容闪烁 + 大幅减轻几何跳动后残留）
- **真实性**：✅ 真 bug（三处独立根因，均沿真实代码路径定位；Windows app 外全局查词覆盖窗 = WebView2 裸窗）
  - 根因 A（**第一个弹窗出现时闪** · 每次根卡片出现）：`hibiki/lib/src/lookup/global_lookup_controller.dart` `_lookupExternal` 在 `showAt`（把窗口移到离屏）**之前**先发 `buildBeginLookupScript` → host `beginLookup`（`hibiki/assets/popup/global_lookup_host.js` 旧 :824-841）。`beginLookup` 把 `contentReady` 重置为 false 后**又调 `observeContent`**；而根 iframe 是 TODO-1095 复用的，里面还留着上一次查词的 `.glossary-content`，`observeContent` 的同步 `hasContent` 短路当场把 `contentReady` 重新标为 true → `scheduleMeasure` → `measureAndReport` → `postToHost('overlaySize')` → Dart `_applyOverlayBox`（`_revealed` 刚被重置为 false）→ `revealStack` **把窗口移到光标处按旧卡尺寸显示出来**。紧接着 `showAt` 又把窗口移回离屏、`renderStack` 渲染新卡再 reveal —— 用户看到的是**旧卡在光标处闪一帧**（re-gate 被陈旧内容击穿，产生早于新渲染的 premature reveal）。
  - 根因 B（**消失第二个弹窗时闪** · 向左/上级联的子弹窗关闭）：子弹窗向左/上级联时窗口最小角（union bbox 原点）变负，根卡片靠 host `commitLayerShift` 反向平移钉在光标处（+499 P2）。子弹窗**消失**时最小角要从负值回到 0：`_applyOverlayBox` → `revealStack` → C++ `RevealStack` 先 `SetWindowPos` 把窗口左上角移回光标、再经 `ExecuteScript` 调 `commitLayerShift(0,0)` 复位图层。跨 DWM 窗口 / WebView2 合成面无法同帧原子提交，两笔补偿位移落在相邻两帧 → 根卡片先向右下跳、约 1 帧后弹回。+499 的因果排序把它压到 ~1 帧但没消除；向右/下级联恒为 0，不闪（与用户「第二个弹窗出现不闪、消失才闪」一致——出现时新子卡吸引注意力掩盖了同类残留，关闭时视线落在根卡片上，位移更刺眼）。
  - 根因 C（**父弹窗打开子弹窗瞬间闪** · 每次嵌套子卡出现，含向右/下常见级联 · 用户第二轮复诉「第一个父弹窗出现子弹窗的时候还是会闪一下」）：`global_lookup_host.js` `measureAndReport` 过去用**全部** shell（含刚创建、仍被 D1 门挡住不可见的子卡）算 union bbox 的最小角（origin）。子卡一 `renderStack` 落地（还没渲染、`contentReady=false`），最小角就被它拉动：向左/上级联时 origin 变负 → Dart `revealStack` → C++ `SetWindowPos` 先移窗、`commitLayerShift` 经 `ExecuteScript` 慢约 1 帧补偿 → 钉住的父卡先跳后弹（同根因 B 的跨 DWM/WebView2 去同步，只是发生在**打开**方向）。且子卡从「按 descriptor 尺寸占位」到「真渲染尺寸」还会二次改 bbox，父卡被一个**看不见的**占位子卡扰动两次。shell 屏幕位置 = 窗口原点 + 图层平移 + shell 本地 = 光标 + shell 本地（与 origin 无关，仅当两笔补偿同帧时成立），故那 1 帧去同步就是父卡位移的唯一来源。

  - 根因 D（**子弹窗自身出现时先被裁一帧再跳进来** · 向左/上级联子卡 · 用户第四轮复诉「不一定父弹窗闪，可能子弹窗闪，反正还是会闪」）：根因 C 让 origin 只跟随 content-ready 的 shell，副作用是**向左/上级联的子卡在其 content-ready 那刻就打开 D1 reveal 门上屏，但此时窗口还没移到覆盖它的位置**（窗口原点仍在父卡 0，子卡本地坐标为负 = 落在窗口视口左/上边界外）。子卡 content-ready → `measureAndReport` 发 origin=-40 的 `overlaySize` → Dart→C++ `RevealStack` 移窗 + `commitLayerShift` 要经一整个 round-trip（多帧）才到位。于是子卡从「content-ready 上屏」到「窗口移到位」之间的若干帧被窗口边缘**裁掉左/上一条**，然后窗口移到、图层平移补上，子卡才「跳」成完整——用户看到子卡先缺角闪现再跳进来（`global_lookup_host.js` `renderPayload` 旧 `setGateFlag(record, ATTR_REVEAL_READY, 'revealReady')` 在几何一落地就无条件放行，不管窗口是否已覆盖）。向右/下级联子卡本地坐标为正、恒在窗口内，故不裁不闪（与用户「向右/下常见级联本就不闪、边缘向左/上才闪」一致；harness `#40`/`#41` 已证 origin 移动时机，本轮补齐可见性时机）。

- **[x] ① 已修复** — 第一轮（根因 A/B）commit `2d5b575f5`；第二轮（根因 C）commit `042ae229d`；第四轮（根因 D）commit `b1b1b5b92`
  - 根因 A（结构性根治）：`global_lookup_host.js` `beginLookup` 改为**只**重置 `contentReady=false` + 拆掉上一轮的 observer / safety timer，**不再** `observeContent`（不接受陈旧卡、不触发 premature measure）。新卡的 content-ready 改由随后的 `renderStack` 提供：body 变了走 `injectContent`+`observeContent`（观测新卡）；body 没变（同词复查 / 嵌套重发父卡同一 body）走 `renderPayload` 新增的 `else if (hasContent(record)) markContentReady(record)`（当前已渲染的卡就是本次正确内容，直接满足门；`hasContent` 门控保证全新空 frame 仍走 observeContent 门，不早标）。`beginLookup` 因此不再发早于新渲染的 `overlaySize`，旧卡不再在光标处闪一帧。
  - 根因 B（结构性根治）：新增纯函数 `ratchetOverlayOrigin`（`hibiki/lib/src/lookup/global_lookup_layout.dart`，CSS px、不含 dpr），`_applyOverlayBox` 用它把窗口最小角**棘轮**成「本会话见过的最外值」——只向外（左/上）移，绝不回内。子弹窗关闭时最小角保持在外、`dx/dy`（窗口左上角）与 `commitLayerShift` 的图层平移都不变，只有右下（远端）边收缩，根卡片零位移 → 关闭不再跳。棘轮每次新热键查词（`_lookupExternal`）+ 真实 dismiss（`_onOverlayHidden`）复位为 `double.infinity`（无约束），新根卡重新以光标为原点 (0,0)。向右/下级联恒 (0,0)，棘轮 no-op，与旧行为逐字节一致。代价：关子弹窗后窗口在左/上侧多留一块透明区（点击该区经 host 命中 gap → dismiss，功能无碍），会话结束即复位。
  - 说明：这是 +499（BUG-567）之后的**残留**闪烁，非其回归；+499 已根治内容重绘闪烁并缓解几何跳动，本次进一步消除 premature-reveal（A）与关闭时的窗口/图层跨边界去同步（B）。
  - 根因 C（结构性根治，第二轮）：`measureAndReport` 把 union bbox 拆成两个独立来源——**最小角/origin**（决定窗口位置 + `commitLayerShift` 的钉根平移）只取**已 content-ready（用户已能看见）**的 shell；**最大角/远端边**（只决定窗口尺寸、绝不移动父卡）仍取**全部** shell，使窗口提前长大覆盖尚未渲染的子卡（子卡真渲染时不被裁）。于是：向右/下级联父卡**全程零位移**（origin 恒为根卡 0,0，只右下长大，无图层平移、无跨边界竞争）；向左/上级联父卡在子卡隐藏期不动，直到子卡 content-ready（即将上屏）才发生**唯一一次** origin 外移——与子卡自身出现同帧，残留被掩盖。无任何 shell content-ready 时（首个根卡 reveal，此刻屏上没有父卡可跳）origin 回退到全部 shell，首帧几何与修前逐字节一致（Never break userspace，既有 harness #11/#15 仍绿）。剩余不可消除项：向左/上级联那唯一一帧跨 DWM/WebView2 去同步是平台边界（`SetWindowPos` 与 `ExecuteScript` 无法同帧原子提交），现已与子卡出现同帧、被新卡吸引注意力掩盖，非本轮可再压。
  - 根因 D（结构性根治，第四轮）commit `b1b1b5b92`：给 D1 reveal 门加「**已被提交的窗口原点覆盖**」这一条件。`global_lookup_host.js` 新增 `shellCoveredByOrigin(record)`（shell 本地左上角 ≥ 当前已提交原点 `layerOffsetLeft/Top`，即落在窗口视口内）与 `maybeFlipRevealReady(record)`：`renderPayload` 不再无条件放行 reveal-ready，改为**仅当窗口原点已覆盖该 shell 时**才放行（根卡 / 向右/下子卡恒被覆盖，逐字节等价旧行为，立即放行）；向左/上子卡在窗口移到覆盖它之前**保持隐藏**，直到 C++ `RevealStack` 移窗后调 `commitLayerShift(newOrigin)`——其末尾遍历所有 frame `maybeFlipRevealReady`，把刚被新原点覆盖的子卡放行 → 子卡**首帧就出现在最终位置**（不再先缺角再跳）。origin 计算（`measureAndReport` 仍用 `contentReady`）完全不动，故父卡残留（那唯一 1 帧跨 DWM 去同步）与根因 C 一致、不回退；仅把子卡的**视觉上屏**推迟到窗口覆盖它之后。`beginLookup` 复位 `layerOffsetLeft/Top = 0`（对齐 Dart 棘轮 per-lookup 复位），防上一次左/上级联留下的负原点把下次查词的子卡误判为「已覆盖」而放行成缺角。安全兜底：held 的 shell 若迟迟等不到 `commitLayerShift`，`REVEAL_READY_SAFETY_MS`（450ms）一次性 timer 仍放行（最坏退回修前的缺角，绝不卡成永久隐藏）。剩余不可消除项同根因 B/C：向左/上级联那唯一 1 帧父卡跨 DWM/WebView2 去同步是平台边界，本轮不动它，但子卡不再叠加缺角 + 跳，用户看到的子卡出现已干净。

- **备注**：WebView2 覆盖窗渲染无法离屏自动化，最终验收是**真机**（见下口径）。根因 B 的棘轮在纯 helper + Dart 状态层完全可守卫；C++ `RevealStack`/`commitLayerShift` 排序不经 flutter test 编译。真机验收口径：Windows 竖排书（或让被查词靠近卡片左/下边）→ app 外划词弹出根卡（**根卡出现不再有旧卡闪一帧**，根因 A）→ 卡内嵌套查词**开**子卡（**父卡不向右下跳、不闪**，根因 C；尤其向右/下级联应全程零位移）→ 关子卡（**父卡不向右下跳、不闪**，根因 B）→ 反复开/关，父卡不整卡重绘/不丢滚动位置（+499 保留）。**根因 D 专项**：让被查词靠近屏幕右/下边、卡内嵌套查词使子卡**向左/上级联**，子卡出现应**首帧就完整、无缺角/无先缺一条再跳**（对比修前：子卡先缺左/上一条闪现再跳进来）；向右/下常见级联子卡出现照旧干净。剩余可见的向左/上那 1 帧父卡跨 DWM 去同步是平台边界，非本轮目标。
