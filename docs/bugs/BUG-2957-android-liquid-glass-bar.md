## BUG-2957 · Android 设计系统 Apple（液态玻璃）底栏渲染成灰色矩形
- **报告**：2026-10-05（协作者 shishamo 转述：Android 选 Apple + 液态玻璃，底栏是两块灰色矩形，磨砂正常；随后 iOS 同症状，Windows 3.47 debug 侧栏红屏 `liquid_glass_render_scope.dart:28 'scope != null': No liquid glass renderer found in context`）
- **真实性**：✅ 真 bug。`fushi/lib/src/utils/components/glass/fushi_glass_scope.dart` `fushiGlassQuality(prominent: true)` 在液态档给 `GlassQuality.premium`；`liquid_glass_widgets` 的 `GlassContainer` 默认 `useOwnLayer: false`，premium 走 `LiquidGlass.grouped` → `LiquidGlassBlendGroup` 从祖先取 `LiquidGlassRenderScope`（库 `src/engine/liquid_glass_blend_group.dart:127`，断言在 `liquid_glass_render_scope.dart:28`），Fushi 全树没有任何 `LiquidGlassLayer`，构建期抛错：debug 红屏、release 是灰色 ErrorWidget（主胶囊 + 搜索圆钮 = 「两块灰矩形」）。这条路径只在引擎支持着色器 ImageFilter（`ImageFilter.isShaderFilterSupported`，即 Impeller）时进入：Android / iOS（Metal）恒 Impeller 必现，Windows / Linux 在 3.44 默认 Skia 时库直接 pass-through 看不出，升 3.47（桌面默认 Impeller）后同样炸。磨砂档是 minimal，不走分组路径，所以正常。出事的调用点：`adaptive_navigation.dart:384`（搜索圆钮）/ `:829`（Tab 胶囊）/ `:931`（侧栏 / 底栏背衬 `_NavSurfaceBackdrop`）、`adaptive_widgets.dart:534`（液态 sheet）、`fushi_material_components.dart:98`（`FushiGlassBackdrop`）/ `:4817`（`FushiPopupSurface`）。
- **[x] ① 已修复** — 上述 6 处 premium `GlassContainer` 显式 `useOwnLayer: true`（自带 `LiquidGlassLayer`，与仓库里其它 premium 调用点同一写法）；判据维持「按实际渲染后端」：液态 → 磨砂的降级只看 `ImageFilter.isShaderFilterSupported`（`adaptive_platform.dart` `glassMaterialOf`），不按平台名写死，3.44 / 3.47、移动 / 桌面同一判据。真机：Android（B651…，Impeller）Apple + 液态底栏修前两块灰块（`android-shots/08-apple-liquid-before.png`）→ 修后完整胶囊 + 搜索圆钮（`12-apple-liquid-after.png`、`34-apple-settings.png`、`36-browse-rest-bar.png`）。
- **[x] ② 已加自动化测试** — `fushi/test/widgets/glass/glass_premium_own_layer_guard_test.dart`：源码扫描 `lib/` 全部 `GlassContainer(`，`quality:` 可能为 premium（`prominent:` / `GlassQuality.premium` / 由它们赋值的局部变量）的必须写 `useOwnLayer:`；反向自检（导航文件至少认出 3 处 premium，防正则空转——初版正则把 `fushiGlassQuality(context, prominent: true)` 截在逗号处、内联写法全漏判，已改为括号配平取实参）；另钉「液态降级只按引擎能力、不得出现平台判断」。widget 测试层做不了：flutter_tester 恒 `isShaderFilterSupported == false`、`flutter test` 没有 Impeller 开关，库在测试里永远走 pass-through，所以守卫落在源码层。
- **备注**：iOS 未在模拟器复测（见报告）；判据与修法与平台无关。
