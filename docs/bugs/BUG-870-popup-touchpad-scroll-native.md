## BUG-870 · 查词弹窗触控板滚不动 / 很难滚：native sendScroll 无残差截断 + JS 0.24 过度降速
- **报告**：2026-07-17（用户：触控板没办法滚动查词弹窗，或者很难滚动，问题还在）
- **真实性**：✅ 真 bug。BUG-701/TODO-1387 的所有修复都只动 `popup.js`（JS 层子像素残差），从未触碰真正的上游截断点，所以「修过还在」。桌面 in-app 弹窗滚动链路：触控板两指 → Flutter `PointerScrollEvent`（精密触控板每帧小 delta）→ `custom_platform_view.dart:471 onPointerSignal` → `_setScrollDelta` → method channel → native `in_app_webview.cpp sendScroll` → WebView2 `SendMouseInput(WHEEL)` → DOM `wheel` → `popup.js:3506` 接管。两处根因：
  - **主因（滚不动）** `packages/flutter_inappwebview_windows/windows/in_app_webview/in_app_webview.cpp:1961`（原）：`auto offset = static_cast<short>(delta * kScrollMultiplier);`（`kScrollMultiplier=6`）向零截断且**无跨帧余量累加**。精密触控板慢滑时 Flutter 的 `delta` 很小，`delta*6 < 1` 时 `offset` 直接为 **0** → 根本不发 wheel 给 WebView2 → JS 的 TODO-1387 残差逻辑压根没机会跑（wheel 还没进 DOM 就没了）。鼠标一档 `delta≈20 → 120` 每帧即过整单位，正常——精确对上「鼠标能滚、触控板滚不动」。
  - **次因（很难滚）** `hibiki/assets/popup/popup.js` wheel 处理器：`POPUP_WHEEL_PIXEL_FACTOR=0.24` 是为**鼠标粗档位**（deltaY≈100-120 → 24px）调的降速系数，被无差别施加到精密触控板的细 delta 上 → 每帧再压小 4 倍 → 侥幸过了 native 截断的也「很难滚动」。
- **[x] ① 已修复** —
  - Native（主）：`in_app_webview.cpp sendScroll` 按轴累加被截小数余量——`scrollResidualX_/Y_`（`in_app_webview.h`）；`scaled = delta*6 + residual` → `offset = static_cast<short>(scaled)` → `residual = scaled - offset`；`offset==0` 时 `return`（本帧不足一个 wheel 单位，余量已累加，等下帧凑够再发，绝不丢触控板慢滑）。加 short 溢出夹取防极快甩动环绕。鼠标一档 `20*6=120` 行为不变。
  - JS（次）：区分设备类——`POPUP_WHEEL_MOUSE_NOTCH_PX=60`（pixel-mode `|deltaY|` 阈值）+ `POPUP_WHEEL_TRACKPAD_FACTOR=1.0`。小 pixel-mode 帧标记 `_popupWheelFineDevice`（手势内 latch，随 residual 一同在 surface 切换/空闲重置），细设备走因子 1.0（自然 1:1，仍除 zoom）；`deltaMode!==0` 或 `|deltaY|>=60` 的粗档位仍走 0.24。latch 防一次大的甩动帧被误当鼠标降速。三份 popup.js 镜像逐字节同步（sha256 af30d40c…）：`assets/popup/popup.js` + `assets/browser_extension/vendor/popup.js` + `tools/browser-extension/vendor/popup.js`。popup.css 未改，content.css 不重生成。
- **[x] ② 已加自动化测试** —
  - 行为级（真滚动位移）：`hibiki/test/reader/popup_wheel_scroll_behavior_test.js`（node vm 载真 popup.js 派发合成 wheel）——改断言：细触控板帧走 1:1（12×deltaY=2 → 24px，pre-fix 只 5px）；zoom 下细设备残差无损（30×deltaY=1 @zoom3 → 10px）；**latch**（先小帧后 80px 大甩帧仍 84px 不被降速）；鼠标一档 deltaY=100 → 24px 不回归；横向抖动/相等帧/ctrl/空闲重置全保留。
  - 源码级 native 守卫：`hibiki/test/build/popup_wheel_native_residual_guard_test.dart`——读 vendored `in_app_webview.cpp`，断言 `scrollResidualX_/Y_` + `residual = scaled - offset` + `if (offset == 0)` 存在、旧 `static_cast<short>(delta * kScrollMultiplier)` 消失、`static_cast<short>(scaled)` 存在（native 窗口无法在测试宿主跑，钉死防 re-vendor 回归）。
  - 源码级 JS 守卫：`hibiki/test/reader/popup_wheel_scroll_asset_test.dart` 新增 `POPUP_WHEEL_TRACKPAD_FACTOR`（≥0.9）/ `POPUP_WHEEL_MOUSE_NOTCH_PX`（30~100）/ `_popupWheelFineDevice` / `deltaPx * factor` / 因子三元选择守卫。
  - 镜像守卫 `browser_extension_popup_parity_guard_test.dart` + `browser_extension_popup_wheel_surface_guard_test.dart` 全绿（三镜像逐字节一致、表面感知路由保留）。
- **备注**：native C++ 改动隔离在 Windows fork（`flutter_inappwebview_windows`），需 `flutter build windows` 真机方能编译验证；本机代理可下 media_kit/ANGLE。真手感（慢滑/快甩/斜滑、词典大字号 zoom>1）待用户真触控板终验——这正是 BUG-701 备注遗留的「待真触控板终验」项。修复不影响鼠标滚轮路径（native+JS 双层均有鼠标不回归守卫）。次嫌未改：`custom_platform_view.dart:477 onPointerPanZoomUpdate` 转发 panDelta 未取负（与 :471 onPointerSignal 取负相反），若某配置下 Windows 投递触控板为 PointerPanZoom 会方向反——但用户报的是「滚不动」非「方向反」，且两路径同汇入已修的 native 截断，故本次不动符号以免把某条正常路径方向弄反。
