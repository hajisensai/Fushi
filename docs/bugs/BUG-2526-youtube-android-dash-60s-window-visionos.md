## BUG-2526 · YouTube 花絮/流媒体打不开或无声：android client DASH 流无 PO token 只放前 60 秒
- **报告**：2026-09-13（用户：作品详情页点「花絮」（MAL/TMDB 的 OP/ED 影片，YouTube）加载好久且没声音，问是不是一次开太多导致）
- **真实性**：✅ 真 bug，与并发无关。`Documents/error_log.txt` 22:36 三次点击成对出现 `Failed to open http://127.0.0.1:10053/yt/…`（视频）+ `Can not open external file http://127.0.0.1:10053/yt/…`（`audio-add` 音轨）。沿 `video_work_detail_page.dart:_playExtra` → `stream_video_launch.dart:buildOnlineVideoExtraLaunch` → `youtube_source_resolver.dart:resolveYoutubeSource` → `youtube_range_relay.dart:_stream` 复现：
  - youtube_explode 2.5.3 自带 client 里只剩 `android` 能签流（androidVr/tv/webCreator/tvSimplyEmbedded unplayable，ios 探测挂满超时，mweb 解析崩，safari 无流）。
  - YouTube 对**无 PO token** 的 ANDROID client 签发的 DASH 分离流（`c=ANDROID&rqh=1`）只放**前 ~60 秒**：固定窗口（1:30 的 OP 音频 251 总 1.41MB 只放到 ~1.01MB，视频 137 总 32.7MB 只放到 ~21MB），与 Range 顺序 / 回放 UA / `&range=` query 写法无关，窗口外 1 字节也 403；全部 6 条音频、所有 ≥480p 视频流尾部一律 403，只有 muxed itag 18（360p）不受限。yt-dlp 原话「android client https formats require a GVS PO Token … may yield HTTP Error 403」，其 2025.12 版 `-f 251` 下载同样 403。
  - 根因落点 `packages/fushi_engine/lib/media/video/youtube_source_resolver.dart:kYoutubeManifestClientFallback`（链里没有不受窗口限制的 client）。表现：`youtube_range_relay.dart:_stream` 首块 `bytes=0-2097151` 对 1.4MB 音频越窗 → 上游 403 原样透传 → libmpv 挂不上音轨 = 无声；解析 5~8s + 打开失败 = 「加载好久」。
  - 诊断盲点：中继首块非 206 不落 error_log（只记中途失败），从日志看不出上游状态码。
- **[x] ① 已修复** — `5554723bd0` + 审查返工 `68e42cf561`（`YoutubeStreamCache` schema v1→v2、加载时版本不符整份丢弃：v1 条目全是 android 签的限窗直链，liveness `bytes=0-1` 探不出、升级后最长 ~6h 仍会喂旧 URL；字幕链改用去掉 visionos 的派生列表 `kYoutubeCaptionClientFallback`，免每次字幕解析白付一次被判 bot 的往返）：照 yt-dlp 2026.08.19 `INNERTUBE_CLIENTS['visionos']`（`_DEFAULT_JSLESS_CLIENTS`，`REQUIRE_JS_PLAYER: False`、无 PO token 策略）新增 `kYoutubeVisionOsClient` 放到 `kYoutubeManifestClientFallback` 链首，其余 client 原样兜底；回放 UA 不变。中继首块非 206 落 `error_log`（`youtube_relay`，带状态码/区间/上游 host）。实测（同一出口）：visionos 的 itag137/251 尾部 Range 206、`bytes=0-` 整文件 206、越 EOF 首块被裁成 206；生产 `resolveYoutubeSource` 默认链 + 真实 `YoutubeRangeRelay` 对两条花絮整流读取字节数与总长完全一致（1,414,393 / 1,459,680），1080p 视频头尾 206，ffmpeg `-ss 60 -t 3` 经中继裁 audio-only 段 exit 0（旧流 60s 处必 403），解析 2.8~6.7s。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/youtube_client_fallback_test.dart`（`BUG-2526 visionos client` 组：innertube context 与 yt-dlp 逐字一致、链首 identical、回放 UA 不随 visionos 走；链顺序/短路用例同步）、`fushi/test/media/video/youtube_source_resolver_test.dart`（链长 5、首位 visionos）、`fushi/test/media/video/youtube_range_relay_test.dart`（首块 403 落 error_log 含状态码/区间/host；首块 206 不落）、`fushi/test/media/video/youtube_stream_cache_test.dart`（v1/缺 version/非法 version 的整份文件被丢弃，当前版本照常读写且 ≥2）、`youtube_client_fallback_test.dart`（`BUG-2526 字幕链` 组：字幕链 = 取流链去掉 visionos 且派生一致）。
- **备注**：不是本地网络、不是并发开太多、不是中继分块 bug。visionos 必须走 watch page（默认 `requireWatchPage: true`），裸 innertube 请求被判「Sign in to confirm you're not a bot」。字幕链不含 visionos（审查返工前复用同一份列表时实测 3~6s，多出的一跳就是 visionos 被判 bot 的空转）。visionos 无 muxed 流 → `miningVideoHasAudio=false`，制卡音频改从 audio-only 经中继抽（已实测）。yt-dlp 的 client 表会漂，YouTube 再封 visionos 时按同法换 `_DEFAULT_JSLESS_CLIENTS` 里的下一个。遗留（另开）：`buildOnlineVideoExtraLaunch` 不走 `YoutubeStreamCache`、不传画质设置。
