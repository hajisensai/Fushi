## BUG-2339 · Siglus原生文本适配与Luna自动扫描争抢入口
- **报告**：2026-09-07（扩大 Siglus 原版体验版覆盖时发现）
- **真实性**：✅ 真 bug。`native/galgame_hook/hook/dll_main.cpp:663` 的 Ready 及其后的 loopback ACK 早于 `adapter_registry.inc:550` 的 Siglus 文本安装；`injector/injector_main.cpp:2059` 消费 ACK 后即可独立启动 Luna。两者缺少文本入口归属契约，Luna 先修改入口会使原生完整 profile 的原始指令校验失败。
- **[x] ① 已修复** — IPC v24 在尾部追加单写者文本归属；Ready 前初始化，原生完整安装或 fallback 成功才发布 NativeOwned，并禁止本会话 Luna 扫描。LunaScenario / 确定安装失败放行 Luna，Pending 由 worker 推进，注入器只尝试一次。Ready 失败清除 hooked 并终结 Pending。最终正常宿主附着原版 PID 35760（无 --no-luna）已确认 owner=NativeOwned、完整 profile、原生正文及实际词典释义；实际 DLL SHA-256 `eef92ede7c8c10cb88ad7a68e67784c9ad335f729713def14b3213f517743488`。
- **[x] ② 已加自动化测试** — `native/galgame_hook/tests/siglus_text_owner_test.cpp` 验证未决、发布顺序、Native/fallback 独占、失败一次性放行和重附着终态；`adapter_structure_test.py` 钉生产接线与 Ready 失败顺序；两份 native IPC 契约测试钉 v24 尾追加与版本一致性。最终 x86/x64 构建、CTest 各 72/72，宿主 IPC 定向 10/10，Windows Release 构建退出 0。正常实机查词关闭不推进、再次点击推进通过；不代表音频/制卡 E2E 或所有异常组合的运行验证。
- **备注**：官方 LOOPERS PLUS 体验版 x86 1.1.140.8，原版 EXE SHA-256 `49bac0ac8d3520554220f7cd7dd289d3f740fb3b1740bc108138f253a77de1c7`。正常启动并通过 host 附着的 PID 28384 使用 DLL `485a90ee79613bcaa5a869e6a3800616112593cd25a8bf1307c692fa7ce396de`，入口已被修改，始终未匹配完整 profile。随后重新沿原始 Start.exe 启动 PID 50588，仅以同 DLL 的 `--hold --no-luna` 做对照，完整 profile 匹配且第一句产生一条正文。该诊断参数不是面向用户的修复。终拒绝后本 DLL 的文本 fallback 也可能修改入口，因此晚期观察到指向本 DLL 的 E9 不能证明完整 profile 成功。对照没有接 host、没有启用几何，也没有证明真实词条或制卡。
