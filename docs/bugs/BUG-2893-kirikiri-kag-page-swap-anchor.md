## BUG-2893 · KiriKiri KAG 换页 backlay+trans 后查词锚点失效
- **报告**：2026-10-03（agent 在测试目录 `ceshi` 的 KiriKiri Z / KAG 作品（x86）原始启动路径上发现：选中 Luna `EmbedKrkrZ` 正文线程后，点击当前台词查词，12 次只有 7 次出卡，其余点击直接推进剧情；`fushi_galhook.log` 的 `capture.shape` 显示 23 次捕获里 17 次因锚点校验失败被丢弃）
- **真实性**：✅ 真 bug。KAG 的 `backlay` + `trans` 换页会对调表/里两页的 MessageLayer 对象：屏上 (page,index) 位置换成了另一个对象，原对象挪到另一页同一 index。`native/galgame_hook/hook/adapters/kirikiri_adapter.inc` 的 `fushiLookupCapture` 候选循环在 `fushiLookupBindGroupAnchorValid`（:3562）里拿绑定组记下的 `anchorIdentity` 与当前槽位对象做身份比较，换页后恒不相等，于是整组被当作陈旧锚点拒掉，没有几何发布，点击穿透到游戏。
- **[x] ① 已修复** — 新增 `fushiLookupBindGroupFollowSwap`（:3527）：只在「锚点 page 是 1/2、本页同 index 已不是锚点对象、另一页同 index 恰好是锚点对象」这一个换页形态成立时，把锚点改绑到本页同 index 的后继对象（再经 `fushiLookupResolveCurrentSlot` 核对才提到强锚点）；其余情况一律不动，原拒绝语义保留。候选循环在锚点校验前先调它，并在 `capture.shape` 里追加 `rj=`（版本/锚点/槽位三类拒绝计数）与 `fs=`（跟随换页次数）诊断。真机复测（同一游戏、新 hook）：查词 7/12 → 13/14、11/12；锚点拒绝 17/23 → 0/25。剩下的失败全是 `lookup.submit reject=1`（text_generation=0：Luna 正文线程漏掉该句或用说话人名顶替正文），属于文本通道问题，不在本修复范围（见备注）。
- **[x] ② 已加自动化测试** — `native/galgame_hook/tests/kirikiri_lookup_source_guard_test.py::BindGroupSwapFollowTest`：钉 FollowSwap 的「另一页同 index 必须是锚点」判据与改绑语句，以及候选循环里 FollowSwap 必须在 AnchorValid 之前调用。变异实测：删掉 `if(there[group.anchorIndex] !== anchor) return false;`、删掉循环里的 FollowSwap 调用，两条用例都变红。Python 守卫 392 OK；CTest x64 127 / x86 131 全过。
- **备注**：模式 B（未修）：同一作品里 Luna `EmbedKrkrZ` 文本线程会整句漏掉部分正文，或用说话人名（如「彩ちゃん？」）顶替正文，查词提交因 text_generation=0 被按设计拒绝、点击推进剧情。根治需要 KiriKiri 侧 TJS 精确文本通道（新功能）或修 Luna 侧，作为下一道门单独立项。
