## BUG-4180 · Android 查词弹窗 search/copy 浮动菜单选区结束后不关，盖住制卡按钮
- **报告**：2026-11-06（应用内反馈 5Sj-bzv_rm：Android TV / 盒子 Hisense HITV205N，Android 11，3.0.1-debug.20797）
- **真实性**：✅ 真 bug（代码路径确认，无 TV 设备未实机复现）。
  - 弹窗带自定义 `ContextMenu` 项（`fushi/lib/src/pages/implementations/dictionary_popup_webview.dart:2708` 的「查词」，BUG-1237 后 Android 隐藏系统默认项、复制由 Dart 补），于是 fork 的 `startActionMode`（`third_party/flutter_inappwebview_android/.../in_app_webview/InAppWebView.java:1589/1598`）即使在 Hybrid Composition 下也走 `rebuildActionMode`（`:1604`）：`finish()` 系统 ActionMode，自己 inflate 一个 `floatingContextMenu` 子 View（`:1636`）。系统「选区清空 → finish ActionMode」从此够不到这个菜单。
  - 菜单的关闭路径只有：触屏单击（`:472` `onSingleTapUp`）、点菜单项、以及两条**仅 texture 模式**的路径——轮询 `checkContextMenuShouldBeClosedTask`（`:494` 被 `!useHybridComposition` 门住）与页内 keydown 脚本（`:605` 同样门住）。主进程弹窗是 HC（`dictionaryPopupWebViewUsesHybridComposition = true`），TV 没有触屏、D-pad 键事件归 Flutter 焦点，四条路径一条都触发不了。
  - 弹窗 WebView 是常驻热槽（关窗只停到屏外、换词只重注入词条），关窗时 `base_source_page.dart:1494/2030` 已 `clearSelection()`（`removeAllRanges`），但没人把「选区没了」接到菜单上，菜单就一直挂在这个 WebView 上，每次查词都盖住右侧按钮（制卡），只能重启。先前 AI 的分析成立。
- **[x] ① 已修复** — fork 新增事件驱动的关闭路径：`PluginScriptsUtil.FUSHI_HIDE_CONTEXT_MENU_ON_SELECTION_END_JS_PLUGIN_SCRIPT`（所有合成模式都装）在顶层文档及每个同源子 frame 文档上监听 `selectionchange`，整页（顶层 + 可达同源子 frame）都无选区且焦点不在可编辑元素时调 token 感知的 `_fushiHideContextMenuCall()`（native 无菜单时为 no-op）；`InAppWebViewClient` / `InAppWebViewClientCompat` 的 `onPageStarted` 在新顶层文档开始时关菜单（旧文档的选区消失不发 `selectionchange`）。无延迟 / 重试 / 轮询。弹窗关窗时既有的 `clearSelection()` 因此会顺带关菜单。说明见 `third_party/flutter_inappwebview_android/PATCHES.md`「Floating context menu closes when the selection ends」。
- **[x] ② 已加自动化测试** — `fushi/test/build/inappwebview_android_context_menu_close_guard_test.dart`（fork 无 Java 单测基建，按 BUG-3762 守卫范式做源码守卫）：锁住 selectionchange 监听（含同源子 frame）、「整页无选区才关」先于 hide 调用、可编辑元素例外、无定时器、脚本不在 texture-only 分支里、native hide 无菜单 no-op、两个 client 的 `onPageStarted` 关菜单。
- **备注**：无 Android TV / 物理机，D-pad 长按选词 → 关弹窗 / 换词菜单消失尚待设备复测。已知限制：opaque-origin（沙箱）iframe 内的选区顶层看不见，顶层选区结束仍可能关掉它的菜单（与上游 texture 模式轮询一致）。
