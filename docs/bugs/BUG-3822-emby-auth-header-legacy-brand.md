## BUG-3822 · Emby/Jellyfin 认证头仍报旧品牌 Hibiki，添加服务器失败日志无请求轨迹
- **报告**：2026-10-23（应用内反馈 AL8qJr6yr-，macOS 3.0.1-debug.20797：某 Emby 服务器「依旧 404、添加仍被拦」，SenPlayer / Hills / Yamby 均能添加；服务器有防扫库的客户端黑白名单）
- **真实性**：⚠️ 部分确认。确认的两点：① `fushi/lib/src/sync/jellyfin_video_client.dart` `JellyfinApi.authHeaderFor` 写死 `Client="Hibiki", Device="Hibiki", Version="1.0"`（改名 Fushi 后的旧品牌、假设备名、假版本），DeviceProfile 名也是 `Hibiki`；按 `Client` 放行 / 拦截的服务器（BUG-2848 同类）认不出本应用。② 添加失败时（`fushi/lib/src/sync/jellyfin_settings_widget.dart` `signInJellyfinServer` / `addJellyfinRoute`）日志里没有任何请求记录——反馈附带的日志只有更新检查与词典弹窗条目，探测各端点、`/emby` 前缀、登录请求各回了什么全无。**未确认**：该服务器拦截的判据是否就是 `Client` 名（反馈说「404」而 BUG-2848 那类白名单回 403；也可能按 UA / 请求序列判扫库）。
- **[x] ① 已修复** — 新增 `packages/fushi_engine/lib/media/video/media_server/media_server_client_identity.dart`：产品名常量 `kMediaServerClientProduct = 'Fushi'`（Plex 的 `kPlexProduct` 改为引用它）、`MediaServerClientIdentity`（产品 / 设备名 / 版本）与进程级装配点 `mediaServerClientIdentity`；`AppModel._initialiseOnce` 读完 PackageInfo 后按 `PlatformDeviceInfoService.deviceModel`（桌面主机名 / 移动端型号，无意义值回落产品名）与应用版本装配；头值收成可打印 ASCII 并去引号（非 Latin-1 主机名会让 `HttpHeaders` 抛）。`authHeaderFor` 改报 `Client="Fushi", Device="<本机>", Version="<应用版本>"`，DeviceProfile 名同改。添加服务器 / 线路包一层 `JellyfinConnectTrace`（`fushi/lib/src/sync/jellyfin_connect_trace.dart`）：每条请求记 `方法 路径 → 状态码 [content-type] [server]`，失败时连同本机身份与最终错误写进 `ErrorLogService.log('JellyfinConnect.signIn|addRoute')`（落盘、随反馈上传）；不记主机名、查询串、请求体、响应体。
- **[x] ② 已加自动化测试** — `fushi/test/sync/jellyfin_client_identity_test.dart`（8 条：认证头新身份且无 Hibiki、缺省读进程级身份、登录请求两个头名都带新身份且成功不记日志、设备名解析与回落、头值清洗、全 404 时日志列出 6 条请求与状态码且不含密码与主机名、登录 401 记认证响应码、空地址不记）；`fushi/test/sync/jellyfin_playback_negotiation_test.dart` DeviceProfile 名断言改为 `Fushi`。
- **备注**：没有那台服务器，未真机复测，**不保证**改名后就能添加——下次同类反馈带日志即可看到每条请求的状态码与前置网关（`server` 头）。风险：若有服务器管理员按 BUG-2848 的指引把 `Client="Hibiki"` 加进了白名单，这些服务器会改为拦截 `Fushi`，需要管理员改放行名；令牌按 DeviceId 归属，已登录的服务器不需要重登。刻意不冒充其他客户端名（同 BUG-2848 备注）。
