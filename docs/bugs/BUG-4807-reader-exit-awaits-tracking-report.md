## BUG-4807 · 阅读器关书（返回键）等着追踪上报，未映射的书会等一次站点搜索
- **报告**：2026-11-17（用户：小说优化清单 novel-12，代码复核确认）
- **真实性**：✅ 真 bug（沿代码路径确认，未做慢网复现）。根因是「一段没有延迟上界的网络调用被压在返回键的等待链上」：
  - `fushi/lib/src/pages/implementations/reader_fushi_page.dart` `onSourcePagePop` → `await _syncAndFlushPosition()` → `_flushPosition` → `_persistPosition`；修复前 `fushi/lib/src/pages/implementations/reader_fushi/navigation.part.dart:1708-1713`（基准 4c347287835）在 `_persistPosition` 末尾 `await appModel.mediaTrackingService.recordBookProgress(...)`。
  - `packages/fushi_engine/lib/media/tracking/media_tracking_service.dart:2185-2207` `recordBookProgress` 先 `await _ensureAutoBookMapping`（无映射且已配置时内联一次 Bangumi 搜索，`searchSubjects` 没有请求级超时），再 `await _sendBookProgress`（卷号 > 1 时还会内联 `readEntry`）。
  - 窗口不只是「搜索在途时按返回」：打开一本未映射的书、没翻页就按返回，退出 flush 自己就是第一次 `_persistPosition`，搜索直接在退出路径上发起并被等待。慢网下返回键表现为按了没反应。
  - 附带：每次位置落库（500 ms 防抖，每翻一页一次）都调一次 `recordBookProgress`，其中 `_isIgnored` / `findMapping` / `loadBookTrackingSnapshot` 等库查询都在「没前进就跳过」的短路之前，章内翻页也照跑。
- **[x] ① 已修复** — `recordBookProgress` 挪出等待链：`_persistPosition`（`navigation.part.dart`）改经 `ReaderTrackingProgressReporter.report` 只发起、不等；同一份「完成章数 + 是否读完」**落定**后不再报、在途时不重复发起（去重键含 `progress >= 0.999` 的 +1，不是章号）。「落定」取自服务：`recordBookProgress` 改为返回 `Future<bool>`——进了至少一个站点的队列、且没有还在等映射的站点（Bangumi 自动映射未命中 / 搜索失败、会自己关联书的站点还没关联上、卷的章节伴随映射没建出来）也没有入队失败，才是 `true`。服务把搜索的网络错误、未命中、入队失败都吞成正常返回（`_singleFlightAutoMapping`、`_enqueueAndSync`），所以不能拿「没抛错」当已报：没落定的不记，下次落库照常再调服务（搜索频率由服务的 10 分钟未命中窗限制，与修复前一致）。抛错记 `ErrorLogService`（`ReaderFushi.recordBookProgress`），同样不算已报。「读完」写库（`markEpubBookCompletedIfUnset`）仍在被等待的那一段。进程退出（`_flushAllForProcessExit`）在本地写穿之后把在途上报等完，仍受 `ExitFlushRegistry` 的单回调超时约束；关书后页面自己的退出回调已注销，所以 dispose 交给 `ExitFlushRegistry.defer` 的那一笔改成 `_flushPositionAndTrackingReport`（位置落库 → 等在途上报），「读完最后一章 → 返回 → 立刻关 app」时在途的那次仍有人等。新文件 `fushi/lib/src/reader/reader_tracking_progress_reporter.dart`。提交见本分支 `pr/reader-nav-lookup-state`。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_tracking_progress_reporter_test.dart`：上报口真行为（send 挂着时 `report` 已返回、落定后去重、在途不重复发起、**服务回「没落定」下次再报**、只有「读完」变也报、抛错后再报、同步抛错走 onError、`whenSettled`）+ 接线守卫（`_persistPosition` 不 await `recordBookProgress`、读完写库在前且被等待、追踪关着不发起、退出等完且排在本地写穿之后、dispose 交出去的那一笔带着在途上报、返回键链不等上报）。`fushi/test/media/tracking/media_tracking_service_test.dart` 新增一组钉返回值：搜索抛错 / 无结果 → `false`（未命中窗内再调仍 `false` 且不再搜），映射建好后同一份进度 → `true` 并入队，已在队列里再调仍 `true`，追踪关着 → `false`。
- **备注**：去重只对「所有能报的站点都已入队」的书生效；有站点一直关联不上的书（如 Bangumi 搜不到唯一结果）每次位置落库仍会进一次服务（只有本地库查询，不在返回键等待链上），频率与修复前相同。待真机复测原始失败路径——开追踪 + 未映射的书，限速 / 断网下翻一页立刻按返回，应立即退出；恢复网络后 Bangumi 进度仍应报上去。未做的原因：本轮多组并发共用设备，不做真机。
