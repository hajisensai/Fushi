## BUG-4323 · 复习卡上明鏡的外字 SVG（［参考］菱形）画成 150px 方块
- **报告**：2026-11-10（开发者自提，反馈 Hm3asDcb8b，iOS 深色：「あざとい」背面明鏡释义里的红色双菱形图标占了半个卡面）
- **真实性**：✅ **真 bug（截图量尺 + 真词典数据 + headless Chrome 排版取证）**。
  - 那个图标是明鏡的外字 `gaiji/参考2.svg`：词典 JSON 里 `{"tag":"img","path":"gaiji/参考2.svg","data":{"class":"gaiji",…}}`，**没有** width / height / sizeUnits，外层包一个 `span[data-sc-img][data-sc-class="gaiji"]`；SVG 本身只有 `viewBox="0 0 1024 1024"`，没有固有尺寸。
  - 截图（736px 宽 ≙ 402 css px）里菱形外框约 257px → 约 140 css px；SVG 的菱形占 viewBox 的 94%，图片盒 ≈ **150×150 css px**。
  - **派单时的推测不成立**：这张图没有 `preferredWidth/Height` / `sizeUnits:'em'`，与弹窗 `declaredImageSize` 无关；现行 Fushi 导出（`fushi/assets/popup/popup.js` `createDefinitionImage` 的 `svgWithoutDimensions` 分支）对它产出 `width:auto!important;min-width:1.2em;height:1.2em` 的字大盒子，用真 popup.js + 真词条导出、套 Fushi 卡片 styling.css 在 headless Chrome 里排版，量得 16×16——Fushi 自己制的卡不会这样。
  - **150×150 的来源是 Yomitan 导出的字段**：Yomitan 导入时把媒体文件的真实尺寸写进 width/height，没有固有尺寸的 SVG 拿到的是浏览器给的默认尺寸 150×150（推断，未逐行核 Yomitan 媒体加载器），导出 `font-size:1px;width:150em` + sizer `padding-top:100%`（BUG-2742 记录过本机 Yomitan 真卡里明鏡就是 `font-size:1px;width:150em`）。Fushi SRS 自带 AnkiConnect 端点（`packages/fushi_engine/lib/srs/ankiconnect/`），Yomitan 直接往 Fushi 卡片笔记类型制卡，字段原样存下。把这个形态喂给同一份卡片 CSS，Chrome 量得 **150×150**，与截图一致。
  - **根因（卡面这一层）**：`packages/fushi_anki/templates/fushi_card/styling.css:1260-1275`（修复前）对词典图片只兜 `max-width:100%`，外字图片盒的几何完全听字段里制卡端写死的内联样式。导出（Yomitan 与现行 Fushi 一样）把 `gloss-*` class 剥掉，词典 CSS 里给外字定尺寸的规则在卡面上命中不到；卡面上能认出外字的只剩 `data-sc-class="gaiji"`，而模板没按它收口。旧版 Fushi 导出（BUG-2825 之前，还带 class）反过来会被明鏡 CSS 的 `span[data-sc-img][data-sc-class="gaiji"] .gloss-image-container{width:15em!important}`（特异度 0,5,1）命中，靠字段尾部追加的 `_ankiGaijiImageStyle` 才压住。
- **[x] ① 已修复** — Fushi 卡片 styling.css 新增两条规则，按 `data-sc-class="gaiji"` 把外字图片盒压成一个字大（取值与 `anki_models.dart` 的 `_ankiGaijiImageStyle` 一致）：图片链接 `max-width:1.2em; vertical-align:text-bottom`，图片盒（现行 / Yomitan 形态是 `<a>` 下第一个 span，旧版是 `.gloss-image-link > .gloss-image-container`）`width / min-width / height / max-width / max-height / font-size` 全 `1em!important`。sizer 与 img 在各种导出形态里都是内联绝对定位铺满盒子，跟着变小，不用单独改。`min-width` 必须是 1em：Fushi 导出的外字盒内联 `width:auto!important`，内联 !important 压不动，写 0 会塌成 0 宽（取证时踩到过）。特异度 (0,5,3) / (0,6,1) 压过词典规则 (0,5,1)。没嵌媒体时外字退化成 alt 文字（不是链接），不受影响。重新生成 `fushi_card_template_data.dart`。
  - 升级路径：内置「Fushi 卡片」笔记类型用户没改过 CSS 时跟随代码（`packages/fushi_engine/lib/srs/srs_builtin.dart`），库里已有的卡直接生效，原生卡面「CSS 与内置模板逐字一致」的判据也随之一致；改过 CSS 的笔记类型、以及已导出到 Anki 的笔记类型拿不到这条（与其它模板改动同口径）。
  - 没有改制卡导出：Fushi 的导出已经产出字大外字盒；Yomitan 的字段不归我们改，卡面是 Fushi 能控制的那一层。
- **[x] ② 已加自动化测试** — `packages/fushi_anki/test/fushi_card_gaiji_image_style_test.dart`：解析 `kFushiCardStylingCss`，断言两种导出形态的图片盒规则都在、取值全是 `1em !important`（含 `min-width` 不得为 0）、图片链接限宽 1.2em，并计算特异度必须高于明鏡规则 (0,5,1)；另守规则都限定在 `data-sc-class="gaiji"` 下，不碰别的图片。**测试未在本分支运行，统一在合并后验证。**
