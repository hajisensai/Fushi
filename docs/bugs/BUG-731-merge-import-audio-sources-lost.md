## BUG-731 · 合并导入不恢复音频来源(音频源配置/本地音频库被当设备设置丢弃)
- **报告**：2026-07-11（用户：导入 14GB 备份后「音频来源等也没有恢复」）
- **真实性**：✅ 真 bug（离屏 export→merge 往返复现）— 根因 `hibiki/lib/src/sync/backup_merge_engine.dart:652-663`：`merge()` 里注释「Preferences are device settings → kept (non-merge by default)」，唯一例外是 `audiobook_pos_*`。因此 `audio_source_configs` / `local_audio_dbs` 这两个 pref **从不参与合并**——即使目标设备一条音频来源都没有也不恢复。而它们引用的 `local_audio_*.db` 文件其实随备份走（`localAudio/` 前缀，`mergeImportBackupFiles` 步骤5 已 copy-if-absent 拷进来）→ 文件到了、注册配置没到 = 音频来源静默丢失。覆盖导入不受影响（整库 blob 替换，且这两个 key 不在 `SyncRepository.deviceLocalPrefKeys`，不会被本地层保留覆盖）。
- **[x] ① 已修复** — `backup_merge_engine.dart` 新增 `_mergeAudioSourcePrefs()`（在 `merge()` 事务末尾调用）：把 `local_audio_dbs` / `audio_source_configs` 当**内容配置**合并——目标为空/空列表时采用备份值（原样复制保留 `s:`/`j:` 类型前缀），目标已有非空列表则保留本设备（merge 从不 clobber）。判空 `_isEmptyListPref` 从首个 `[` 解析 JSON 容忍类型前缀（一个新装 app 会写 `[]` 占位，仅靠 NOT-EXISTS-on-key 不够）。合并后由既有 `BackupService._rebaseLocalAudioPaths`（merge 步骤6）按文件名把路径 re-home 到本机 support 目录。
- **[x] ② 已加自动化测试** — `hibiki/test/sync/backup_merge_audio_source_restore_test.dart`：真实 export→merge 往返，断言①空占位设备合并后音频来源 pref 恢复 + 路径 re-home 到本机 support（不含源目录名）+ `local_audio_*.db` 文件已拷入；②本设备已有非空列表时保留自身、不被备份覆盖。
- **备注（未解决/需用户信息）**：用户同轮还报「进度结束非常快、点重启没重启、空书籍」。离屏 export→import 往返（fresh merge / overwrite / 同路径 re-merge 三态）**均无法复现空书籍**——书行+内容+路径 re-base 都正确落地，所以空书籍是**环境/状态相关**（最可能是导入所用 app 的 data_root 与「手动打开的 hibiki」不一致，或导入进了另一个数据根）。需用户确认：导入用的是哪个 hibiki（正式版还是测试版）、其数据位置、导入前书库是空还是已有书、以及选的是「覆盖整库」还是「合并到现有库」。另：桌面端「立即重启」按钮 `backupImportRestart()` 走 `exit(0)`，只退出不自动重启（`sync_settings_schema/backup.part.dart:83-89`），与「点重启没重启」相符——属既有行为，是否改成真正重启另议。
