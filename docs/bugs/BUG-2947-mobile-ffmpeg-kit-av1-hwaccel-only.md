## BUG-2947 · 移动端 AV1 视频制卡截帧/动图失败：ffmpeg-kit 缺 libdav1d
- **报告**：2026-10-05（用户贴 Android 错误日志：`extractVideoFrameViaFfmpeg` / `extractClipGifViaFfmpeg` 各一条 `ffmpeg exit 1; executable=ffmpeg-kit; stderr=[av1 @ 0x…] Your platform doesn't support hardware accelerated AV1 decoding. | Error marking filters as finished`，调用栈 `ImmersionMiningEngine._mineNow.runAnimatedLadder` → `tryGif` / `tryStartFrame`）
- **真实性**：✅ 真 bug，即 BUG-2604 备注里记下的「移动端同型缺口未修」。
  - 根因 `third_party/ffmpeg_kit_flutter/patches/build_x264_android.sh` / `build_x264_ios.sh` 的配方只有 `--enable-gpl --enable-x264 --enable-openssl --enable-libvpx --enable-opus`，没有 `--enable-dav1d`。FFmpeg n6.0 原生 `av1` 解码器只是 hwaccel 挂钩壳（allcodecs.c:833 "hwaccel hooks only, so prefer external decoders"），而移动端配方 `--disable-mediacodec` / `--disable-videotoolbox` 后没有任何 hwaccel → 任何 AV1 源每一帧都失败。凡解视频流的制卡链路（截帧、GIF/WebP/AVIF 动图、音画同步片段）全挂，只解音频的句子音频正常；封面最终只能退到 `controller.screenshot` 当前帧。
  - 实证（2026-10-05，扫入库二进制字节）：Android arm64-v8a / armeabi-v7a 与 iOS 两个切片的 libavcodec 里都含用户日志那句 `Your platform doesn't support hardware accelerated AV1 decoding`，`libdav1d` 与 `--enable-libdav1d` 四个切片全无。
- **[x] ① 已修复** — 配方两端加 `--enable-dav1d`（ffmpeg-kit v6.0 自带 dav1d 1.2.1，meson + ninja 构建，CI 两个 job 补装 meson/ninja）；`verify_mobile_outputs.py` 加 `--enable-libdav1d`、`libdav1d`、dav1d 自身日志串与 `license_dav1d.txt` 判据（旧 AAR 上实测恰好红这 7 条、其余全绿）。n6.0 的 allcodecs.c 把 `ff_libdav1d_decoder`（:766）排在原生 `ff_av1_decoder`（:834）之前，两者并存时按 codec id 默认选 libdav1d，app 侧 ffmpeg 参数无需改。CI run 37216513850 重编（两端 verify 通过）后重新 vendor `android/libs/ffmpeg-kit.aar` 与 `ios/Frameworks/*.xcframework`（文件集不变，仅新增 `LICENSE.DAV1D`；Info.plist 仅条目顺序变化，切片/架构一致）。提交见本 PR。
- **[x] ② 已加自动化测试** — `fushi/test/tools/ffmpeg_kit_mobile_recipe_guard_test.dart`：`_requiredMobileFlags` 加 `--enable-libdav1d`，新增 `_requiredAv1DecoderStrings`（`libdav1d` 封装名 + dav1d 自身日志串，Android 两 ABI 与 iOS 两切片同证），AAR 许可加 `license_dav1d.txt`。新二进制 12/12 通过；换回旧 AAR 时 Android 能力用例与许可用例变红（变异实测）。
- **备注**：dav1d 在 ffmpeg-kit 里按 `-Denable_asm=false` 编（上游脚本写死），解码比带 SIMD 的慢，但制卡只解一帧或一句长度的片段，可接受。
  未做真机解码实测（AAR 只有 arm ABI，x86_64 模拟器跑不了 ffmpeg-kit）；能力证据是四个切片的 configure 串 + libavcodec 中 dav1d 封装与库自身串的静态扫描。
