- **报告**：2026-11-21（用户：所有者本人，「srs 升级后，一背卡为什么马上就开始卡」）
- **真实性**：✅ 真 bug，两个叠加根因（真库副本：45,971 卡 / 355,321 行 `log_ix`，作答连带排下一张 3.3–3.7 s，单独排队 1.7 s）：
  - 出卡常驻会话没接进新代命令层：`native/fushi_fsrs/src/store/gen4/dispatch.rs:405-407`（作答顺带排队，写事务里）与 `:544` 直接调无状态的 `cmd::study::study`（`cmd/study.rs:85`）；每次都 `deck_tree` + 读 30 天 `log_ix` 逐条解操作体 + 今天每张学习卡逐张 `replayed_card_logs` 重放整个连通分量（随今天学卡数 O(N²)）。协议 3 的常驻会话 `store/queue.rs` `StudyHub` 只在 `store/mod.rs:506` 装配，gen4 没有对应物——`cmd/study.rs` 文件头写明「留到接线（规划 §2.2 S1）」，#3838 接线时没补。
