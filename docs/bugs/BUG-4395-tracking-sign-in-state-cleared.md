## BUG-4395 · A rejected sign-in looked fixed after any sync, and signing in again did not send what waited
- **报告**：2026-11-11（T1 F3 item 1b, found by tests: the hands-on test could not reach the sign-in-needed state）
- **真实性**：✅ 真 bug. (1) `packages/fushi_engine/lib/media/tracking/media_tracking_service.dart` `_persistSyncOutcome` wrote every provider's `lastSyncUnauthorized` from each sync, also for a provider that was asked nothing that round (its rows backed off after the rejection, so `_syncProvider` returned `unauthorized: false`): any later sync, e.g. another site sending, cleared "Sign in again" on the Tracking page, the Home strip and the settings row while the site still refused. Only the last round of `_syncUntilSettled` was persisted, so a rejection in an earlier round could be lost the same way. (2) Signing in again (plugin row, AniList, MangaBaka sections) started a plain `syncNow()`: the rows that waited stayed backed off (30 s doubling to 6 h), so nothing was sent until the backoff ran out.
- **[x] ① 已修复** — "sign-in needed" changes only when the site answered that round (line ~3345), every round's outcome is persisted; new `MediaTrackingService.resumeAfterSignIn(providerId)` clears the state, makes that site's rows due and syncs; the three sign-in paths call it (T1 F3 item 1b commit).
- **[x] ② 已加自动化测试** — `fushi/test/media/tracking/tracking_sign_in_needed_test.dart`.
- **备注**：a still-signed-in site that keeps answering 401 is retried on the normal backoff (30 s .. 6 h), not in a loop; a plugin whose account reads "signed out" stops being active, so it is not retried at all.
