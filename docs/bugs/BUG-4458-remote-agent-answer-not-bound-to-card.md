## BUG-4458 · 远端 AI 助手的确认 / 候选作答不绑定卡片，晚到的作答会落到下一张卡上
- **报告**：2026-11-10（互联远程长任务审查 V-D5、R14）
- **真实性**：✅ 真 bug。协议是「回答当前那张」，动作不带卡片身份：`packages/fushi_engine/lib/sync/assistant/agent_assistant_host.dart:584-589`（修复前）`act` 的 `answerConfirm` 只校验 `approve` 是 bool 就调 `_host.answerConfirm(approve)`，`:431-439` 直接完成**当前** `_confirm`；`answerChoice`（`:441-453`）只校验 id 属于当前 `_choiceIds`，前后两张候选卡选项 id 重叠时晚到的作答落到新卡上，`choice == null` 完全不校验。手机端 `fushi/lib/src/ai/agent/remote_ai_agent_session.dart:259-266` 只发 `{type, approve}` / `{type, choice}`，快照里已有的 `pending.entryId` 没用上；页面 `ai_agent_page.dart` 按钮也不传卡片 id。修复前新 engine 测试实测：对卡片 A 的重复同意晚到后，卡片 B 被同意、第二个不可逆工具被执行。
- **[x] ① 已修复** — `7efbaff8348` 作答动作加可选 `entryId`（缺省或非空字符串，否则 400）：`AgentCompleterHost` 开卡时经会话注入的 `pendingEntryOf` 记下卡片条目 id，带 `entryId` 且与待答卡片不符即原样忽略（先于候选选项校验，旧卡晚到不回 400）；`AiAgentConversationController.answerConfirm/answerChoice` 加 `{String? entryId}`，页面传 `entry.id`；`RemoteAiAgentSession` 发 `entryId ?? 快照 pending.entryId`；本机 `AiAgentController` 按最后一张同类卡片且仍待答比对。不带 `entryId` 的旧客户端照旧答当前那张，旧 host 忽略未知键。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/sync/assistant/agent_assistant_host_test.dart` group「answers bind to the card」（确认 / 候选晚到作答不落新卡、兼容无 entryId、entryId 形状 400）；`fushi/test/sync/app_agent_assistant_host_test.dart`「BUG-4458」真 host 端到端（经接口作答带上快照卡片 id、晚到旧卡作答不同意新卡）；`fushi/test/ai/agent/ai_agent_controller_test.dart`「BUG-4458」本机控制器。
- **[x] ② 补页面接线测试** — `7f13b168526` `fushi/test/pages/ai_agent_answer_binds_entry_test.dart`：记录型假控制器，点确认卡「执行 / 拒绝」、候选卡选项与「取消」，断言作答带上各自卡片 id（把页面四处 `entryId: entry.id` 去掉时实测红：收到 null）。
- **[x] ③ ctl 管理路由也绑定卡片** — `62b92572fa9`（用户 2026-11-11 按建议拍板做）`POST /api/admin/ai/agent/sessions/:id/answer` 收可选 `entryId`（取自 `GET sessions/:id` 的 `pending.entryId`）：与此刻待答卡片不符回 409「这张卡片已经不在等待回答」，不落到下一张；不带时照旧答当前那张（旧脚本不受影响）。作答收进 `answerAiAgentCtlCard`，经 `AiAgentController.answerConfirm/answerChoice(entryId:)`；`fushi_cli ai ask` 作答时带上它看到的那张卡片的 id。测试：`fushi/test/ai/agent/ai_agent_controller_test.dart`「BUG-4458：ctl 作答带卡片 id 只答那一张，卡片换了回 409；不带 id 照旧答当前那张」。
