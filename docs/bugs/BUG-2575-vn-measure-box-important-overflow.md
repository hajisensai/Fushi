## BUG-2575 · VN 量尺盒被 .fushi-vn-screen 的 !important 尺寸覆盖，每屏按整视口切、真实屏溢出裁切
- **报告**：2026-09-18（用户：iOS 竖排 VN 模式「屏幕包不住字体、最左列被裁切」「靠语音推进显示不全」截图）
- **真实性**：✅ 真 bug。`fushi/lib/src/reader/reader_visual_novel_scripts.dart` `createScreenMeasurement` 把真实屏盒的宽高写进量尺的**普通**内联样式 `root.style.width/height`，而量尺与真实屏共用 `.fushi-vn-screen` class，`reader_content_styles.dart` `_vnLayoutCss` 里该 class 是 `width: 100% !important; height: 100% !important`——样式表 important 压过普通内联值，BUG-1688 那次「量尺镜像真实屏盒」从没生效。量尺是 `position: fixed`，100% 解析成整视口（393×852），真实屏盒是视口减 chrome 预留带与用户上下边距（例 393×702 / 393×792）。竖排下量尺列更长、`splitScreenToViewport` 以为一屏装得下更多字，真屏列更短就多出一列贴左边被 `overflow:hidden` 裁掉（用户截图：最左列切半）；横排则末行落进底栏。headless Chrome（iPhone 393×852、top inset 60 / bottom 90）复现：修前竖排拆分屏每屏 2/9 个字形矩形落在屏盒外，量尺 `root.clientHeight` 读到 852 而真屏 702；修后全部 0/N，屏切分收敛到真实容量（[54,124] → [54,109]）。
- **[x] ① 已修复** — `createScreenMeasurement` 改用 `root.style.setProperty('width'/'height', …, 'important')`（含无真实盒时的 `--page-width/--page-height` 兜底分支），内联 important 优先级高于样式表 important，量尺真正等于真实屏盒。提交 `86ded222acf`（PR 分支 `pr/vn-ios-screen-fit`）。
- **[x] ② 已加自动化测试** — `fushi/test/reader/vn_measure_box_restore_progress_behavior_test.dart`（+ 同名 `.js` node 跑手）：把生成物里的 `window.fushiReader` 对象字面量丢进 node 求值，在 CSSStyleDeclaration 替身上跑真实 `createScreenMeasurement`，断言宽高值等于真实屏盒且 `getPropertyPriority` 为 `important`（含兜底分支）。
- **备注**：VN 屏切分只在 `buildScreens` / `refitScreensToCurrentViewport` 时量一次，量尺错一次就整章错；此前 iOS 上凡 chrome 预留带或上下边距非零，每个「刚好装满」的屏都会溢出一截。与 BUG-1688（量尺曾固定 100vw/100vh）同源不同层：那次改了值，这次改的是优先级。
