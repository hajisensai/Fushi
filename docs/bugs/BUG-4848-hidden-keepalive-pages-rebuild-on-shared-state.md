## BUG-4848 · 回首页卡 100 ms：首页失效书列表 provider，藏着的书架与漫画书架各跟着整页重建四次
- **报告**：2026-11-16（用户：转来群反馈录屏「切 tab 变卡了」；修完 BUG-4851 / BUG-4896 后列出的剩余项「回首页时延后的刷新偶发到 90 ms」，用户回「都做都做，能优化就优化」）
- **真实性**：✅ 真 bug（Windows profile 构建实测，探针 `fushi/integration_test/home_tab_switch_perf_itest.dart`）。逛过别的 tab 再回首页：首帧 build 103 ms，随后 +130 ms / +210 ms / +405 ms 处再各来一帧 57 / 36 / 37 ms。timeline 拆开看，首页自己的构建只有 12.7 ms，其余全是**藏着的**书架与漫画书架：`FutureBuilder<_RemoteBookState?>` 往下整棵网格，每帧两份。
  - 根因：保活 tab 用 `Offstage` 藏着，但页面 State 仍订阅着全局状态，被动标脏照样整页 `build`。触发方是 `fushi/lib/src/pages/implementations/home_dashboard_page.dart:990-1000`（修前行号）`_reloadNow`：首页被藏着时到达的数据变更只记一笔（`_reloadDeferredWhileHidden`），切回时（`:895` `onTabActivated`）补做，其中无条件失效 `fushiBooksProvider` / `bookLastReadAtProvider` / `completedEpubBookKeysProvider`。两个书架实例在 `build` 里 `ref.watch` 前两个（`reader_fushi_history_page.dart:1005`、`:1662`），每个 provider 先通知一次 loading、算完再通知一次 data——两个实例 × 两个 provider × 两次通知，藏着的页面白白重建 8 遍，分摊在四帧里。外壳的 `_hiddenTabContent`（BUG-2976）只挡得住自上而下的 widget 更新，挡不住页面自己被标脏。
  - 触发面不止测速：读一会儿书 / 看一会儿视频再回首页就是这条路径（阅读位置写入 → 首页记欠账 → 回首页补做）。
- **[x] ① 已修复** — 新增 `fushi/lib/src/utils/components/section_deferred_build.dart`：页面 widget 混入 `SectionDeferredBuild` 后，所在分区（`SectionVisibilityScope`）藏着时 `build` 原样交回上一次的产物（子树因 widget 同一而整棵跳过）并记一笔欠账，重新可见时欠着才真构建一次，没欠就继续交回旧产物——只因可见性翻转被叫起来不算构建理由。订阅全程不断（`ref.watch` / `ref.listen` 原样留着、`ref.listen` 回调照常触发），`State.didChangeDependencies` 照常被调用。接到书架（`ReaderFushiHistoryPage`，书与漫画两个实例）与首页（`HomeDashboardPage`）上；首页原先用 `TickerMode.valuesOf(context)` 读开关，会让它每次切走 / 切回都被标脏，改成订阅 `TickerMode.getValuesNotifier`。提交见 PR #3534。
- **[x] ② 已加自动化测试** — `fushi/test/utils/components/section_deferred_build_test.dart` 八条（真 provider、真 InheritedWidget、真 `setState`，数页面 State 被调 `build` 的次数）：对照组（没混入的页面藏着时照样重建）、藏着时 provider 连变三次不重建且 `ref.listen` 逐次收到、切回只补一次、没欠账来回藏显不重建、`setState` / 父级换 widget / 其它依赖变化都记欠账、可见性翻转与别的依赖同帧一起变照样重建、可见时逐帧兑现、不在分区里行为不变、嵌套分区。`fushi/test/pages/reader_remote_interconnect_test.dart`「藏着的书架不跟着书列表 provider 失效重建，切回才补一次」挂真书架页验接线（把书架上的 `with SectionDeferredBuild` 拿掉，这条红）。
- **备注**：修后实测回首页（第一次回访，开着 build 剖析，数值偏高）：首帧 32.5 ms、+58 ms 处 23.7 ms、+405 ms 处 22.1 ms，三帧都只剩首页自己补做的重载；藏着的书架不再出现在 timeline 里。书架欠着的那一次构建落在随后第一次切回书架的那一帧（47.6 ms，同样开着剖析，只此一次）；不开剖析的回访轮里回首页 19.0 / 11.7 ms、书架 6.2 / 3.9 ms、漫画 8.0 / 4.6 ms，全程没有 UI 线程阻塞。用了 `SectionDeferredBuild` 的页面要守一条：State 的 `build` 产物不能直接依赖 `SectionVisibility`（可见性翻转不触发它重建），要按可见性换内容的地方放进子 widget（`SectionPopScope`、`Builder`）。视频页 / 游戏页 / 查词页 / 复习页没接：查词页的 State 在 `didChangeDependencies` 与 `build` 里直接读可见性；其余三页没量到这类被动重建，未动。
