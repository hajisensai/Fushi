## BUG-5112 · 漫画超分：旧档迟到的模型加载失败能关掉新档、清掉新档的队列
- **报告**：2026-11-22（Codex 2026-11-21 PR 审查 HBK-AUDIT-006，PR #3951）
- **真实性**：✅ 真 bug（沿当前 develop cbdc2a45ed 代码路径复现）。`native/fushi_compute/src/upscale.rs` 工作线程模型加载失败分支（修前 `worker_loop` 约 256–271 行）：只有 `models_failed` 的写入按代际判了，`state.queue.clear()` 不判——加载期间调用方已 `ffc_upscale_configure` 换到新一代并提交了新页时，旧代失败把新一代的任务全清掉（发 `EVENT_CANCELLED`），而新一代并没加载过；随后发的 `EVENT_MODELS_FAILED` token 固定为 0，`fushi/lib/src/media/manga/reader/manga_upscale_controller.dart` 的 `_onEvent`（修前 470 行）收到就 `_active = null` 并提示「不可用」，不分是哪一代的失败——新档的阅读器被旧档迟到的失败关掉。另一处同源缺口：换代时队列里旧一代的任务不丢，工作线程会用新模型算旧键（键里带档位标签）并写进缓存，内容与键不符。
- **[x] ① 已修复** — 失败结果归属发起加载的那一代配置，Rust 与 Dart 按同一代际判：`ffc_upscale_configure` 加 `out_generation` 出参交出生效代际（ABI 升 3）；工作线程只在失败代仍是当前代时记 `models_failed`、清队列，`EVENT_MODELS_FAILED` 的 token 改为失败的那一代；`Engine::configure` 换代时丢掉旧一代排队的任务。Dart `MangaUpscaleActivation.generation` 记下启用时的代际，`MangaUpscaleController.handleEvent` 只认本代的 `modelsFailed`。
- **[x] ② 已加自动化测试** — Rust `upscale::tests::old_generation_model_failure_cannot_disable_the_new_configuration`（注入可卡住的模型加载：g2 加载中换到 g3 并提交新页，再让 g2 失败——断言新页仍在、g3 未被记失败、工作线程接着加载 g3、失败事件带 g2；换代丢旧一代排队任务）；`packages/fushi_compute/test/upscale_binding_test.dart` `configure hands out the engine generation`（真库过 FFI：同配置不换代、换配置加一）；`fushi/test/media/manga/manga_upscale_controller_test.dart` `a late model failure of an older engine generation keeps the active tier`。变异实测：恢复「无条件清队列」后 Rust 用例红。
- **备注**：真机未复测（需要 ORT + 模型 + 换档时序）。
