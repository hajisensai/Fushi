## BUG-2335 · 同版本数据库缺词典显式展开列导致启动空值崩溃
- **报告**：2026-09-07，Windows 原版 Siglus 游戏内嵌查词验收时，新宿主在附着游戏前显示 `Initialisation failed / Null check operator used on a null value`，旧宿主此前可正常启动。
- **真实性**：✅ 真 bug。`C:\文档\error_log.txt` 在 13:51:07.805703 记录完整堆栈：`$DictionaryMetadataTable.map`（`packages/fushi_core/lib/src/database/database.g.dart:5902`，`expanded_languages_json` 被非空映射）→ `DictionaryRepository.loadFromDb:99` → `AppModel._initialiseOnce:2552`。磁盘库 `PRAGMA user_version=97`，但 `PRAGMA table_info(dictionary_metadata)` 缺该列；代码也为 schema 97，Drift 不调用 `onUpgrade`，上游 v96 的加列分支因此永远不会执行。这是并行迁移史的版本号与实际结构不一致，不是 galgame Hook 或 theme prewarm 异常。
- **[x] ① 已修复** — `packages/fushi_core/lib/src/database/database.dart:733` 提取 `_ensureDictionaryExpandedLanguagesColumn`，复用原 v96 的 `Migrator.addColumn` 定义与表/列存在守卫；`beforeOpen:3052` 在降级拒绝之后、任何生成查询之前执行这一个已证实缺列的结构修复。同版本漂移库添加 `TEXT NOT NULL DEFAULT '[]'`，原有行保持继承语义；正常库短路。保持 `schemaVersion=97`，不降版本、不删数据、不重放其它迁移、不修改生成 mapper。提交由集成任务单独记录。
- **[x] ② 已加自动化测试** — `fushi/test/database/migration_same_version_dictionary_expanded_languages_test.dart` 使用独立临时 SQLite 文件，保留当前 `user_version` 但删除该列，修复前准确复现 `database.g.dart:5902` 空值断言，修复后证明生成 mapper 可读、新列默认 `[]`、原有词典所有字段及额外列不变；重复打开正常库保留显式展开值且不产生 DDL；未来版本库拒绝发生在补列前，结构和数据不变。新文件 3 条，连同现有 v96、v97 和降级保护三个文件最终 **12/12** 通过。`flutter analyze --no-pub` 对生产文件及新测试定向检查通过（No issues found）。
