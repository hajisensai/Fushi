## BUG-3451 · 视频控制条「⋯」只有一项仍弹菜单、点开菜单时控制条消失
- **报告**：2026-10-16（用户：应用内反馈 eeWvjG93_d，Windows）
- **真实性**：✅ 真 bug，两处根因：
  1. 菜单打开时控制条消失：`⋯` 菜单是 popup 路由，modal barrier 盖满整页；`MouseTracker` 帧尾对静止鼠标重新命中，media_kit 桌面控制条的 `MouseRegion` 不再在命中链上 → `onExit` → `onExit()` 把 `visible` 置 false（`third_party/media_kit_video/lib/media_kit_video_controls/src/controls/material_desktop.dart:980` 改前的 `onExit: (_) => onExit(),`）。移动端则是自动隐藏 Timer 在菜单开着时照样到点（`material.dart` 的四个 hide Timer）。页面侧 `_videoBarMoreButton` 只 `_pokeControlsVisible()` 续一次命，挡不住 barrier 引起的 exit。
  2. 只有一项仍弹菜单：`VideoBarPlan.overflowing => hidden.isNotEmpty`（`fushi/lib/src/media/video/video_control_bar.dart:182`）只要有一项被收起就画「⋯」，`_openOverflowMenu`（同文件约 500 行）对一项也弹菜单；默认精简布局把「倍速」作为常驻菜单项（`_foldedBarEntries`，`video_fushi_page.dart`）塞进右下「⋯」，于是底栏常驻一个只有一行的菜单。
- **[x] ① 已修复** — fork 两端加 `holdVisible`（`ValueListenable<bool>`，为 true 时 MouseRegion onExit 与所有自动隐藏 Timer 不收控制条，放开时按 hover 重新倒计时；见 `third_party/media_kit_video/PATCHES.md`「Host-held controls while a bar popup is open」）；`VideoControlBar` 新增 `onMenuOpenChanged`（菜单开 / 关回调，页面接到 `_controlsHeldByMenu` 再装进两端 theme）与 `singleActionButtonBuilder`（「⋯」里只剩一项时在「⋯」位置直接画那一项的按钮，点一下即执行，不再弹一行菜单；与仓库「工具栏放得下就平铺」规则一致）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_control_bar_test.dart`（group「VideoControlBar「⋯」只有一项 / 菜单开关」：单项直接画按钮且首帧不闪「⋯」、两项仍是菜单、菜单开关回调 true/false 配对）；`fushi/test/pages/video_controls_menu_hold_guard_test.dart`（机制复现：从按钮弹 popup 菜单 → 底下 MouseRegion onExit；fork 源码守卫：holdVisible 字段 / 绑定 / onExit 与每个 hide Timer 都看 `_held`；页面守卫：两端 theme 装配、每条 VideoControlBar 接线）；真 app：`fushi/integration_test/video_bar_overflow_shortcuts_itest.dart`。
- **备注**：同批反馈 tMFIoEr0me（找不到视频快捷键列表）在播放器设置面板「控制按钮」分类加了「快捷键设置」入口，进入后预选「视频」分域（`ShortcutSettingsPage.initialScope`）。mpv.net 式表格编辑器未做，待拍板。
