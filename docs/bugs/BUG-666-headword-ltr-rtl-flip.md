## BUG-666 · 查词卡 headword 在 RTL UI 语言下被甩到最右
- **报告**：2026-07-09（用户：TODO-1354，续 BUG-664）
- **真实性**：✅ 真 bug — 根因不在 `.entry-header` 顺序（`hibiki/assets/popup/popup.js:1920` `createEntryHeader` 里 expression 恒在前、`.header-buttons` 靠 `margin-left:auto` 靠右，DOM 顺序正确），而在**文档方向**。查词弹窗 WebView（`dictionary_popup_webview.dart` / `popup.html` / inline HTML `_buildInlinePopupHtml`）**都没有显式声明 `dir`**；宿主平台视图把 Flutter 环境 `Directionality` 作为 `layoutDirection` 传入，当用户把 UI 语言设为**阿拉伯语**（`hibiki/lib/i18n/strings_ar.i18n.json`，17 语言里唯一 RTL）时，`Directionality = rtl` → WebView 文档根默认方向 `rtl`。RTL 下 `.entry-header`（`popup.css:127` `display:flex`）这个 flex 行主轴翻转：`.expression-scroll`（`popup.css:155` `flex:1 1 auto`）落到**右端**、`.header-buttons`（`popup.css:213` `margin-left:auto`）被挤到**左端**——headword「以内」被甩到最右，按钮 + `.entry-current .entry-header::before`（`popup.css:142` 焦点蓝三角 #1a73e8）挤到左（即用户截图「左侧符号 + 以内浮右」）。同时 RTL 还会把例句 `ol{padding-left:1.8em}`、glossary 文字缩进翻到错误一侧。Chrome 无头渲染 `<html dir="rtl">` + 真实 popup.css 精确复现该截图；加 `html,body{direction:ltr}` 后 headword 回到左端紧贴蓝三角、按钮回右、例句缩进回正（与 Niratan 一致；Niratan `Features/Popup/popup.css` 的 entry-header/expression-scroll/header-buttons 与 Hibiki 同构，本身也是 LTR）。
- **[x] ① 已修复** — `hibiki/assets/popup/popup.css` 的 `html, body` 块加 `direction: ltr;`：查词卡是日文/CJK 词典内容，永远 LTR 阅读，作者层 `direction:ltr` 覆盖 UA 的 `[dir=rtl]` 继承（作者源优先于 UA 源），把整卡钉死 LTR，一并修正 headword 位置、音高行、glossary 文字与例句缩进；对 LTR 语言用户零变化（本就是 LTR，只是显式化）。popup.css 在 `<head>` 里 render-blocking（inline HTML 直接 `<style>` 内联、file:// 走 `<link>`），首帧前即生效，无 RTL 闪烁。改后已 **re-vendor**：字节拷 popup.css 到 `hibiki/assets/browser_extension/vendor/popup.css` + `tools/browser-extension/vendor/popup.css`（`cmp` 验字节一致），并 `node tools/browser-extension/scripts/generate-content-css.mjs` 重生成两份 `content.css`——生成器把该 `html,body` 规则 re-root 成 `#entries-container`，故浏览器扩展里 `direction:ltr` 只作用于弹窗容器、**绝不翻转宿主页面方向**（含 RTL 宿主站，零泄漏）。
- **[x] ② 已加自动化测试** — `hibiki/test/pages/popup_layout_width_columns_test.dart` 新增组「TODO-1354 查词卡钉死 LTR」：源码守卫 popup.css 的 `html, body` 块含 `direction: ltr`（正则定位块 + 断言），并断言 `strings_ar.i18n.json` 存在（RTL 触发前提的真实性佐证，保持根因链可追溯）。既有 `hibiki/test/build/browser_extension_popup_parity_guard_test.dart` 兜住 re-vendor 字节一致 + content.css 与 popup.css 同步（含新 `direction:ltr` 已 re-root 到 `#entries-container`）。
- **备注**：纯 CSS 方向修复，不改 DOM/JS，不影响查词/制卡/嵌套导航/音高行内化（BUG-664）。最终「与 Niratan 一样 headword 左对齐」的视觉验收需真机：把 UI 语言切阿拉伯语、查一个带振假名的词，确认 headword 在左、按钮在右、例句缩进在左。
