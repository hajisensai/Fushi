## BUG-2606 · 覆盖已有卡不清未映射字段（SentenceFurigana 露旧句）也不补 fushi 标签
- **报告**：2026-09-20（用户：「when using fushi to overwrite an existing card in anki with data in the SentenceFurigana field, because Fushi doesn't use that field, overwritten cards will still display the old sentence until the data is manually cleared. it would be nice to have an auto-furigana function, or the ability to clear the field when overwriting! the associated fushi tags currently aren't added either (fushi tag + metadata tag)」，截图：Anki 编辑器 `Sentence` 已是新句、`SentenceFurigana` 仍是别的工具填的旧句）
- **真实性**：✅ 真 bug
  - 两后端 `updateMinedNote`（AnkiConnect `packages/fushi_anki/lib/src/ankiconnect/ankiconnect_repository.dart`、AnkiDroid `packages/fushi_anki/lib/src/ankidroid/anki_repository.dart`）只把 `fieldMappings` 渲染出的字段发给 `updateNoteFields`；AnkiConnect 服务端与 AnkiDroid native（`fushi/android/app/src/main/java/app/fushi/reader/AnkiChannelHandler.java` `updateNoteFields` 按位置合并）都「未给出的字段保留旧值」。Lapis 模板 `{{#SentenceFurigana}} {{furigana:SentenceFurigana}} {{/SentenceFurigana}}{{^SentenceFurigana}} {{furigana:Sentence}} {{/SentenceFurigana}}`（`packages/fushi_anki/lib/src/lapis_note_type.dart`）优先读 `SentenceFurigana`，Fushi 默认映射刻意不填它 → 覆盖后卡面照旧是老句子。
  - 两处 doc 都写明「不改 tag」——覆盖路径根本不调 `buildNoteTags`，`fushi` / 分类 / 书名标签一个都不补。
- **[x] ① 已修复** — 覆盖 = 这张卡变成「此刻新制会得到的那张」（字段与标签都是），沿用 BUG-858 定下的「覆盖=整体替换」语义：
  - AnkiConnect：先 `notesInfo` 读现有字段名（顺手喂给 `contextForExistingSourceNote`，不再二读），`BaseAnkiRepository.fieldsForOverwrite` 给没映射的字段补空串后 `updateNoteFields`；随后新增的 `AnkiConnectService.addTags` 把 `buildNoteTags(...)` 那组并进去（用户原有其它标签保留）。note 读不到（已删 / 不可达）明确失败、不发半覆盖。
  - AnkiDroid：通道 `updateNoteFields` 多带 `clearUnspecified: true` + `tags`；native 按位置把没点名的字段写空，`AnkiProvider.updateNoteTags`（`AddContentApi.updateNoteTags` / ContentProvider `Note.TAGS` 两个实现）写并集。
- **[x] ② 已加自动化测试** — `packages/fushi_anki/test/overwrite_whole_card_test.dart`（AnkiConnect：没映射的 `SentenceFurigana` / `Hint` 送空、映射字段送渲染值、随后 `addTags` 带 `用户tag fushi book 书名`、note 读不到不发更新、全映射字段皆空仍拒绝；AnkiDroid：单次通道调用带 `clearUnspecified:true` + 同组 `tags`）。既有 `note_id_and_update_test.dart` / `ankidroid_overwrite_test.dart` / `card_source_link_test.dart` 全绿。
- **备注**：用户提的「自动生成句子假名」没做——仓库里没有句级形态分析器接进 Anki 包，Lapis 官方也建议 `SentenceFurigana` 留空由模板 `furigana:Sentence` 现算；清空未映射字段后卡面就走这条路。代价：用户在 Anki 里手填过、Fushi 又没映射的字段（Lapis 的 `IsSentenceCard` 等卡型开关、`Hint`）覆盖时会一并清空——这是「整体替换」的字面含义，若上游想留活口可再加「覆盖时清空未映射字段」开关。Android native 改动在本机 `:app:compileDebugJavaWithJavac` 通过编译，未真机复测。
