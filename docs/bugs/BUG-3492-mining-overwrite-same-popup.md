## BUG-3492 · 在线视频后台制卡后，同一查词弹窗里点 ✓ / 高级制卡确认没反应、不覆盖
- **报告**：2026-10-17（用户反馈 cqlujSVuxg，Android vivo，2.10.0-debug.19358；扩展里在线看的视频：制卡后马上想加上下句，在同一弹窗里再进「高级制卡」确认、或点已制卡的 ✓ 都没反应，不覆盖、不弹「已覆盖」，要划掉弹窗重新查词才能覆盖成功）
- **真实性**：✅ 真 bug。在线视频（网络流）制卡默认走后台模式（`VideoOnlineMiningMode.background`，`fushi/lib/src/mining/video_online_mining_mode.dart:30`）：`_mineVideoCard` 不等落卡、直接回 `MinePopupResult.queued()`（`fushi/lib/src/pages/implementations/video_fushi/lookup_mining.part.dart` 后台分支 `_trackBackgroundMine` 之后）。popup.js 收到 `result.queued` 把本按钮的闭包标记 `queuedLocally = true`（`fushi/assets/popup/popup.js` mine 按钮 onclick 的 `if (result.queued)` 分支），而 app 内没有宿主队列（`window.fushiIsEntryQueued` 只有浏览器扩展定义），这个标记**此后再也没有任何东西撤掉**：卡落地后宿主不通知弹窗，查重刷新 `setMineState` 也不清它。onclick 开头 `if (isEntryQueued()) { setMineState(...); return; }` 于是对这颗按钮永远成立——再点 ✓ 直接 return；「高级制卡」确认经 `fushiPopupMineEntryByIndex` 回点的是同一个 onclick，同样 return，且 promise 正常 resolve，对话框按「点到了」关窗，没有任何提示。新弹窗重新渲染按钮、没有这个标记，查重得到 ✓ → `minedCardAction` 操作单 → 覆盖成功，所以「换个弹窗就好」。
  - 本地视频（等待模式，不回 queued）与阅读器（只有 Anki 不可达进待发队列时才回 queued）走的都是已制卡的正常路径，不受影响；只有回 queued 的表面会踩到。
  - 「恢复为一键制卡的默认」：对话框控制器的 `resetToDefaults`（`fushi/lib/src/mining/advanced_mining/advanced_mining_controller.dart:734`）在同一弹窗里没有找到独立失效的代码路径——它恢复的是对话框打开时的选择，之后确认仍回点那颗被标记卡死的按钮，所以表现为「恢复默认后也制不了」。按同一根因处理，未单独改它。
- **[x] ① 已修复** — popup.js：`setMineState(true)`（Anki 里已有这张卡）一律撤掉本弹窗的「已加入」标记；app 车道点击已加入的按钮时先问一次 Anki，已落地就撤标记、落到已制卡的正常路径（操作单 / 覆盖），未落地就用页内提示 `popup_mine_still_queued` 说明，不再静默 return；浏览器扩展（宿主持有队列）行为不变。视频页后台落卡成功后经 `MinedStateSignal.instance.notifyWord(expression)` 通知正在显示这个词的弹窗重问，✓ 自动换成真已制卡态。三份 popup.js 镜像同步；`popup_settings_injection.dart` 注入 `window.i18nMineStillQueued`。
- **[x] ② 已加自动化测试** — `fushi/test/utils/misc/popup_asset_behavior_test.js`：`testAppQueuedMarkAnswersClicksAndYieldsToOverwriteOnceLanded`（未落地再点：不重复制卡、有页内提示、不卡死；落地后同一弹窗点 ✓ 交给宿主 `minedCardAction` 覆盖）、`testHostRefreshAfterBackgroundLandingClearsAppQueuedMark`（宿主刷新后标记撤掉、点 ✓ 直接走覆盖）；还原修复后两条均红。宿主接线守卫 `fushi/test/pages/video_background_mine_refreshes_popup_guard_test.dart`。
- **备注**：未在 Android 真机 + 在线视频源复现/复验（本机无对应在线源环境）；结论来自代码路径与 popup.js 真跑行为测试。
