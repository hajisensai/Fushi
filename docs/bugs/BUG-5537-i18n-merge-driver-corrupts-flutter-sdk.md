## BUG-5537 · i18n-merge-driver-corrupts-flutter-sdk
- **报告**：2026-11-27（批量合并时自查发现）
- **真实性**：✅ 真 bug。在 linked worktree 里合并一条碰了 i18n json 的 PR 之后，本机 Flutter 3.50.0 的 `bin/cache/flutter.version.json` 被改写成 `frameworkVersion: 2.9.1`、`frameworkRevision` = 刚做的合并提交（`2b3ab780de2`），`tool/bootstrap.ps1` 随即报「找不到 Flutter 3.50.0」，拒用这份 SDK。根因：`tool/setup_worktree.ps1:124` 把驱动注册成 `dart fushi/tool/i18n_merge_driver.dart %O %A %B`；git 在 linked worktree 里会把 `GIT_DIR` 传给合并驱动（普通仓库不传，已实测），PATH 上的 `dart` 是 Flutter 的包装脚本，`bin/internal/shared.sh:124` / `shared.bat:75` 跑 `git -C "$FLUTTER_ROOT" rev-parse HEAD` 时继承了 `GIT_DIR`，读到的是本仓 HEAD，于是判定 SDK 变了：删掉 `flutter.version.json`、重建 flutter_tools，再按本仓的 tag 算出版本号。
- **[x] ① 已修复** — 新增入口 `tool/git_hooks/i18n_merge_driver.sh`：先 unset `GIT_DIR` / `GIT_WORK_TREE` / `GIT_INDEX_FILE` 等仓库定位变量（驱动本身唯一的 git 调用是对三个临时文件跑 `git merge-file`，用不到仓库），再用 `.dart_tool/package_config.json` 里 `flutterRoot` 那份 SDK 的 `dart-sdk/bin/dart(.exe)`（不经包装脚本），没有时才退回 PATH 上的 `dart`。`setup_worktree.ps1` 改注册 `sh tool/git_hooks/i18n_merge_driver.sh %O %A %B`，守卫 `i18n_keys_sorted_guard_test.dart` 跟着改，`rules-detail.md` 写明不要配成直接 `dart`。
- **[x] ② 已加自动化测试** — `fushi/test/tools/i18n_sync_ops_test.dart`「linked worktree 里合并：入口脚本起的 dart 看不到 GIT_DIR」：建临时仓库 + linked worktree，对照组（sh 探针直接当驱动）证明 git 确实传了 `GIT_DIR`，实验组走真入口脚本、探针 dart 必须看到 `<unset>`。对照组刻意不用 `dart`，免得测试本身在跑测试的机器上把 SDK 写坏。
- **备注**：修复只在重新跑过 `tool/setup_worktree.ps1`（写仓库级 git config，主 checkout 与所有 worktree 共用）之后生效；SDK 已被写坏的机器在 SDK 目录、去掉 `GIT_DIR` 后跑一次 `bin/flutter --version` 即可恢复（本机已恢复）。
