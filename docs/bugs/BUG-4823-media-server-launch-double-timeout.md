## BUG-4823 · 媒体服务器从库行起播：服务器不可达时条目详情连等两轮超时才进失败页，可达时同一份详情串行取三次
- **报告**：2026-11-17（优化计划第一波 c20 / video-7 + gap-remote-1，代码审查发现）
- **真实性**：✅ 真 bug。从媒体库重开一条 Jellyfin / Emby / Plex 条目时，同一份条目详情在首帧前串行取三次，彼此不共享：① `fushi/lib/src/media/video/media_server/media_server_library.dart:484` `buildMediaServerLaunch` 的 `browser.itemDetail`（取服务器端断点与带令牌的封面，失败只打日志）；② 取流 `fushi/lib/src/sync/jellyfin_video_client.dart:3637` / `fushi/lib/src/sync/plex_video_client.dart:848`；③ 下后端默认字幕 `jellyfin_video_client.dart:3735` / `plex_video_client.dart:896`（行号均为修前）。服务器不可达时 ① 先等满一轮请求超时（15 秒）被吞掉，② 再等一轮才进失败页，用户约 30 秒才看到「打不开」。
- **[x] ① 已修复** — 提交 `287026754cf`。新增 `fushi/lib/src/sync/launch_item_detail_memo.dart`（`LaunchItemDetailMemo`）：客户端内只留一格的短复用（窗口 10 秒，从请求落定起算）。`itemDetail` 取到的详情留给随后的取流 / 取字幕；失败只有重开入口那一次才留（`MediaServerBrowser.itemDetail(..., forLaunch: true)`，只有 `buildMediaServerLaunch` 这样调），且只交给一个读取方一次——取流已经接上在途那一发并当场拿到错的，不再留给下一次；之后重试照常重新请求；详情页取详情失败、取流自己请求失败都不留记录（审查后补，提交 `98a71be9c34`）。存的是服务器原样详情，Jellyfin 的版本选择在读出时重新过 `_withChosenVersion`，所以取流后换了版本再取字幕仍是当下选中的版本。`remoteVideoPosition`（LWW 要最新断点）、`remoteVideoDetail`、下载不走复用。`buildMediaServerLaunch` 不新增失败分型。
- **[x] ② 已加自动化测试** — `fushi/test/sync/launch_item_detail_memo_test.dart`（窗口 / 在途共用 / 失败只交一次 / 在途共用后失败不留 / 非重开入口的失败不留，时钟注入）；`fushi/test/sync/plex_video_client_test.dart` [D] 组与 `fushi/test/media/video/media_server/jellyfin_media_versions_test.dart`「一次起播内条目详情短复用」组：假服务器数同一条目详情端点的命中次数（重开入口 → 取流 → 取字幕 = 1 次；读断点、下一次重开各 +1），重开入口失败后取流抛同一个错且不发第二次请求，详情页取详情失败后取流照常重新请求，换版本后取字幕下的是新版本的轨，`playbackClient` 就是浏览器本身；`fushi/test/media/video/media_server/media_server_library_test.dart` 钉住重开入口带 `forLaunch`。
- **备注**：未在真 Emby / Plex 上实测请求次数与不可达时的等待时长（见 PR 说明的待真机验证）；播放页 `_initRemote` 之后的失败态与重试流程没有改。
