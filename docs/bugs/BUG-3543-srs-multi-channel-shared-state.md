## BUG-3543 · 云盘 + 互联同时开着时复习同步状态全局一份：批次只到先跑的目录、另一个目录每轮换化身
- **报告**：2026-10-19（排查 BUG-3542 时发现）
- **真实性**：✅ 真 bug。`SrsSyncLocalState`（写入者身份、批次号、冻结批次、cursor、起步 / 快照进度）每个 profile 只存一份，而 app 对每条已认证通道各跑一轮 `SrsSyncEngine.syncOnce`（`fushi/lib/src/sync/sync_auto_trigger.dart` 的通道后置步骤与 `runOnAuthenticatedSyncChannels`）。修复前 `packages/fushi_srs/lib/src/sync/sync_engine.dart`：`_publish` 在第一个目录确认后就清掉冻结批次、事件已 `markPublished`，批次只到先跑的目录；第二个目录里列不到本写入者目录，`syncOnce` 开头的「`everPublished && listFiles(writerId) == null` → 换新化身」把它误判成「已被当作退役清理」，每轮换一次化身（旧化身目录堆积）。另外 `bootstrapped` / `lastSnapshotBatch` 全局一份，第二个目录永远不起步、快照节奏错位。
- **[x] ① 已修复**（fd34aeda59 + 9913660568）— 目录只是传输介质：写入者身份 / 批次号 / cursor 全局一份（批次冻结后逐字节不变），按目录记进度（`SrsDirectoryState`，键为稳定目录身份 `fushi/lib/src/srs/srs_directory_key.dart`）；冻结批次留存在本机（schema v119 `srs_sent_batches`），每个目录各自按序补传，留存到最近同步过的目录都确认；落后太久的目录用快照补齐、读方遇缺口改读覆盖快照；只有「出现过本写入者目录、现在不见了」才换化身。多目录拓扑下补上转发（另一个目录里写入者不活着时把新落地 / S 变小的事件带过去，批次头 `fs` 带原 S）与「缺就全量重新发布」核对。设计见 `docs/specs/2026-10-14-fushi-srs-design.md`「多目录传输」。
- **[x] ② 已加自动化测试** — `packages/fushi_srs/test/simulator_test.dart`「多目录（云盘 + 互联 host）」固定用例（同一批次到每个目录且不换化身、桥接互通含桥接前历史、快照补齐、留存逐批补传、未传过的目录不换化身、被清理的目录照旧换化身、旧版本状态）+ 桥接 / 双目录两种拓扑各 60 个随机种子（收敛 / 事件一致 / 修改不丢）；`fushi/test/srs/srs_sync_scheduler_test.dart`「同一批次传到每个目录；再同步不换化身」（真 SrsDbStore + 两个目录）与「同时触发的几轮依次跑」；`fushi/test/database/migration_v119_srs_sent_batches_test.dart`（建表）。
- **备注**：真机（云盘 + 互联同时开）复测待补。批次头新增可选键 `fs`，旧版本照常解码、只对转发 / 重新发布事件的 S 取值不同（多目录此前本来不工作）。
