## BUG-1735 · 伪影文本线程在选择器里与健康线程无法区分，预览还被折叠成干净句子
- **报告**：2026-08-19（用户：真机验证游戏内查词制卡时发现）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/sync/texthooker_service.dart:551-553`（数据采到了但只用于排序，一处都不渲染）
- **[ ] ① 未修复** —
- **[ ] ② 未加自动化测试** —
- **备注**：见下

### 现象（真机，2026-08-19）

《天使☆嚣嚣 RE-BOOT!》（KiriKiri Z）的文本线程选择器里同时列着：

```
EmbedKrkrZ · 0x452188 · 13      在寂静的黑暗中，亮起了一束火光。
KiriKiriZ  · 0x54c450 · #0a47 · 5   在寂静的黑暗中，亮起了一束火光。   ← 100% 伪影，选它永远拿不到台词
KiriKiriZ  · 0x54c450 · #524d · 5   在在寂寂静静的的黑黑暗暗中中，，亮亮起起了了一一束束火火光光。。
```

`#0a47` 那条的**计数在涨、预览句子干净**，看起来比 `#524d` 健康得多——但它才是死线程
（台词全被伪影门丢掉，见 BUG-1733）。UI 主动把用户往这条上引：我本人就是照着"预览最干净"选中它的，
随后花了一整轮才发现制卡失败的上游在这里。

这三条线程的**原始串**（`FUSHI_LUNA_DIAG=1` 实测，同一句话）：

```
EmbedKrkrZ  raw_len=26 normalized_len=13  「聞いたことくらいはある」「聞いたことくらいはある」
KiriKiriZ   raw_len=26 normalized_len=26  「「聞聞いいたたここととくくららいいははああるる」」
KiriKiriZ   raw_len=39 normalized_len=39  「「「聞聞聞いいいたたたここことととくくくらららいいいはははあああるるる」」」
```

也就是说 `#0a47` 那条预览里的干净句子**完全是 UI 折叠出来的假象**，它的真实输出是逐字重复串。

### 根因

伪影信号**已经采到并送到 Dart 了**，但全 app 只拿它排序、一处都不渲染：

- native 采集：`observedArtifactCount` / `previewIsArtifact`
- 传到 Dart：`gal_hook_session_controller.dart:3638`、`texthooker_service.dart:254` / `:257`
- 唯一用途：`texthooker_service.dart:551-553` **只用于排序**

而副标题的预览文本还被 `collapseTexthookerPreview`（`texthooker_service.dart:45-51`）**折叠成干净句子**，
等于把"这条线程输出的是逐字重复串"这个唯一的肉眼线索也抹掉了。

### 修复方向

1. 选择器行上显示伪影比例（如 `伪影 5/5`）或直接标记「不推荐 / 该线程输出逐字重绘串」。
2. 预览折叠要么不做，要么在折叠时保留一个"已折叠"标记，别让折叠后的干净句子冒充健康输出。
3. 排序之外，把 100% 伪影的线程降级或默认过滤（但仍可展开查看，别直接隐藏——诊断时要看得见）。
