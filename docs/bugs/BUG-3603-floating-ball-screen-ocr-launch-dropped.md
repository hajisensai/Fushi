## BUG-3603 · Android 应用外悬浮球截屏查词点了没反应（宿主 Activity 被 ROM 静默拦下）
- **报告**：2026-10-19（用户反馈 `LHyeNKyYjH`「悬浮球应用外无法截屏查词」，附录屏；vivo V1901A / Android 9；同一会话另报 BUG-3602）
- **真实性**：✅ 真 bug（录屏 + 代码路径；未在真机复现）。录屏：桌面上展开应用外球点「Screen OCR」，菜单收起后球仍在原处、没有任何截屏确认框，之后桌面照常响应长按。对照代码：系统球 `runAction(ACTION_SCREEN_OCR)` → `ScreenCaptureRequestActivity.launch` → `BackgroundActivityLauncher.start`（API < 34 直接 `startActivity`）。宿主 Activity 只要 `onCreate` 跑过，首件事就是 `FloatingBallService.setCaptureHidden(true)` 把球藏掉；`launch` 若因「流程进行中」被挡，那个状态同样伴随 `captureHidden == true`（两者只在 `onCreate` / `onFlowFinished` 成对改）。录屏里球没藏，说明 `launch` 返回了 true 而 Activity 根本没起来；进程也没重启（日志 23:30 之后无 `init`）。Android 9 没有 AOSP 后台启动限制，能无声吞掉这次 startActivity 的只有 ROM 自己的「后台弹出界面」类权限（vivo / MIUI 等，默认关）。根因 `fushi/android/app/src/main/java/app/fushi/reader/ScreenCaptureRequestActivity.java:60-61`：交给系统就当成功，丢没丢没人知道，每点一次都是同样的「没反应」，没有任何提示。与 BUG-3602 同源（同一处「发起被丢没人知道」），BUG-3602 是它在应用内球上的后果之一。
- **[x] ① 已修复** — 平台限制本身（ROM 权限）代码绕不过去，本修复让它不再静默：`ScreenOcrFlowLatch`（见 BUG-3602）记下「已发起、宿主未 onCreate」，下一次点「截屏识字」时 `launch` 发现上一次被丢，先弹 Toast 说明原因（文案 `floating_ball_ocr_launch_blocked`，经 `floatingBallNativeLabels` 下发，键 `ocr_launch_blocked`，缺省英文）再照常发起；Fushi 回到前台时同样按「被丢」收尾，不留脏状态。
- **[x] ② 已加自动化测试** — 同 BUG-3602：`fushi/android/app/src/test/kotlin/app/fushi/reader/ScreenOcrFlowLatchTest.kt` + `fushi/test/floating_ball/screen_ocr_launch_latch_guard_test.dart`（含「被丢后下一次发起给出原因提示」与文案下发）。
- **备注**：待真机复测。Android 9 拿不到「启动被丢」的同步信号，所以**第一次**点击仍然没有反应，第二次起才有提示；要从根上消除只能让用户在系统设置里给 Fushi 开「后台弹出界面」。是否再加「点提示直接跳到应用详情页」等引导属于产品取舍，未做（从后台起设置页同样会被同一权限拦下）。同一权限也会让应用外球的「应用外查词 / 剪贴板查词 / 打开 Fushi」等经 `BackgroundActivityLauncher` 的入口失效，本修复只给截屏识字加了提示。
- **后续（2026-10-23，用户拍板）**：新增「保持截屏会话」开关（设置 → 悬浮球，Android，默认关；`ScreenOcrOptions` / `ScreenOcrService.captureWithKeptSession`）。开启后只要同意过一次（可以在 Fushi 前台用应用内球发起，不受后台弹窗管控），之后截屏识字直接复用常驻的 MediaProjection 取帧，不再从后台起确认框 Activity——这条被 ROM 拦下的路径整个绕开；会话被系统停掉时回到每次申请。守卫 `fushi/test/floating_ball/screen_ocr_session_and_card_image_guard_test.dart`。
