## BUG-4790 · Android 截屏识字交给 Dart 识别期间没有取消出口，识别慢时悬浮球一直藏着
- **报告**：2026-11-17（用户：PR #3615 合入后的遗留缺陷复核——「截屏识字时原生侧等 Dart 回话没有出口」中「Lens 网络卡住 / 本机模型初始化卡住、用户没有可以取消的界面」这一部分）
- **真实性**：✅ 设计缺口（代码路径确认，未复现卡死）。现状：
  - `fushi/android/app/src/main/java/app/fushi/reader/ScreenOcrService.java:628` `recognize` 把帧交给 Dart 识别期间，选取层还没画出来，流程锁（`ScreenCaptureRequestActivity` 的 `flowActive`）持有、悬浮球 `setCaptureHidden(true)`。非保持会话时 `releaseCapture`（`:583`，`:608` `stopForeground(STOP_FOREGROUND_REMOVE)`）已撤掉前台通知，此刻**没有任何通知或界面**能取消；保持会话时通知里的「停止」走 `stopSessionNow`（`:464`），流程未结束时只清 `keepSession`、不收尾。
  - Dart 侧 `fushi/lib/src/floating_ball/app_floating_ball_host.dart` `_androidRecognizeScreenOcrFrame` 对 `target.recognize`（本机模型 / Lens）没有取消令牌。Lens（`fushi/lib/src/media/manga/ocr/google_lens_ocr_service.dart:49`）各阶段有 60 秒超时，不会无限挂；本机模型首次加载 / 推理没有上限，但也是有限时间。所以实际是「可能等一两分钟、期间无法取消」，不是永久卡死（永久卡死的引擎销毁路径已在 BUG-4789 修掉）。
- **[x] ① 已修复**（2026-11-21，拍板台 left3659 选方案 A：识别中的通知上加「取消」）— 根因是识别阶段既没有出口、原生也没有区分「这次流程」与「下一次流程」的身份。修法：
  - 原生新增纯状态类 `fushi/android/app/src/main/java/app/fushi/reader/ScreenOcrRecognitionGate.java`：每次流程一个编号 + 「识别中」阶段。`ScreenOcrService.recognize` 进识别时挂上带「取消」的「正在识别」通知（`buildRecognizingNotification`，PendingIntent 带流程编号 `EXTRA_FLOW`）；选取层画出来（`showRecognized` → `endRecognition`）或流程收尾（`finishFlow`）时撤掉，保持会话时换回会话通知。
  - 点「取消」→ `onStartCommand` 的 `ACTION_CANCEL_RECOGNITION` → `cancelRecognition`：只接受当前流程且正在识别的取消（`takeCancel`），先 `FloatingBallChannel.cancelScreenOcrRecognition(flow)` 让 Dart 放弃，再 `finishFlow`（解流程锁、放回悬浮球）。过期取消把被冷启动 / 重新 start 的空服务停掉。
  - 所有识别回调（引擎询问、ML Kit、PNG 编码、Dart 回话）带发起时的流程编号回来，`stale(flow)`（流程已收尾或编号不是当前的）一律丢弃——取消后停不下来的识别（本机模型推理、ML Kit）晚到的结果落不进用户紧接着发起的下一次流程。
  - Dart 侧 `fushi/lib/src/floating_ball/screen_ocr_recognition_cancellation.dart` 取消令牌；`app_floating_ball_host.dart` `_androidRecognizeScreenOcrFrame` 用它包住识别，收到 `cancelScreenOcrRecognition {flow}`（`_cancelAndroidScreenOcrRecognition`，编号对不上不动）立刻回 `{cancelled: true}`；Lens 在取消时断开连接（`GoogleLensMangaOcrService.close`，下次重建），本机模型的结果到了丢掉。
- **[x] ② 已加自动化测试** — JVM `fushi/android/app/src/test/kotlin/app/fushi/reader/ScreenOcrRecognitionGateTest.kt`（取消只在识别中接受一次、残留通知取消不碰下一次流程、取消后晚到的结果判过期、冷启动实例不接受任何编号）；Dart `fushi/test/floating_ball/screen_ocr_recognition_cancellation_test.dart`（令牌）与 `fushi/test/floating_ball/app_floating_ball_host_test.dart`「BUG-4790：识别中原生按流程编号取消」（经真实通道：别的编号不取消、同编号立刻回 cancelled）；源码守卫 `fushi/test/build/screen_ocr_reusable_selection_guard_test.dart` 改为钉 `stale(flow)`。真机验证未做（通知按钮点击路径未在设备上复测）。
- **备注**：不靠原生侧加超时掩盖（会把慢但正常的本机模型首次加载误判成失败）。
