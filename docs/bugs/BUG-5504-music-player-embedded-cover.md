## BUG-5504 · music-player-embedded-cover
- **报告**：2026-11-24（反馈 qGNRXaXNEv，Windows 10；反馈 EMjx7gJftH / GitHub #3352 追加回复，Windows 11）：音乐播放页大封面与底部迷你播放条是占位音符，曲目列表 / 「继续收听」却有封面。
- **真实性**：✅ 真 bug。曲目行用 `musicLocalTrackCoverOf`（`fushi/lib/src/pages/implementations/music/music_track_list.dart:1182`，目录封面优先、否则内嵌封面），而播放项 `musicPlayItemOf`（`fushi/lib/src/media/music/music_library_data.dart:371`）只带 `album.coverPath`，`MusicPlayItem` 没有内嵌封面来源；播放页 `music_lyrics_page.dart` `_PlayerCover`、Apple 版 `music_lyrics_page_apple.part.dart`、播放条 `music_now_playing_bar.dart`、队列 `music_queue_panel.dart` 都只传 `coverPath`。只有内嵌封面、没有目录封面的专辑在这些地方永远是占位。
- **[x] ① 已修复** — `MusicPlayItem` 加 `embeddedCoverPath`；`musicPlayItemOf` 按引擎同一条规则 `musicCoverSourceOf` 算封面来源（目录封面优先；否则专辑选定的封面曲目 / 这首自己的内嵌封面）。播放页大封面、唱片标签、Apple 播放页、播放条（含取色）、队列两处 `MusicCover` 传 `embeddedFromPath`；只认 `ImageProvider` 的歌词页流体背景与封面取色经新的 `MusicEmbeddedCoverImage`（字节来自 `MusicEmbeddedCoverCache`）接上，`musicCoverImageProvider` / `musicLyricsBackdropCoverProvider` 加 `embeddedFromPath` 回落。
- **[x] ② 已加自动化测试** — `fushi/test/media/music/music_play_item_embedded_cover_bug5504_test.dart`（播放项封面来源六种情形、provider 回落、四个消费文件接线守卫）。
- **备注**：未做的同类消费方：全屏歌词动画（visualizer 各样式按 `coverPath` 字符串走自己的封面加载）、系统媒体会话 / 通知封面、桌面小组件 / Live Activity、第二屏伴屏，这些仍只认目录封面文件（要么需要文件路径，要么跨模块的字符串契约），没改。EMjx7gJftH 的第②点（部分 MP3 元数据全空，`native/fushi_music/src/tags.rs` `read_lofty` 不带扩展名提示）需用户样本文件验证，本条未处理。
