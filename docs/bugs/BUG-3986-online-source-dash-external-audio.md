## BUG-3986 · online-source-dash-external-audio
- **报告**：2026-11-01（用户：GitHub #2773 经 fushi-bot 转，反馈 EXlaIL2eKQ，Windows）——自建 Aniyomi 扩展返回 DASH 分离候选（纯画面流 + `Video.audioTracks` 放音频）时起播无声；`mpvArgs` 无消费端。
- **真实性**：✅ 真 bug。`fushi/lib/src/media/video/online/anime_source_video_client.dart` `remoteVideoStreamUrls`（原 :372-376）把 `audioStreamUrl` 恒置 null、`MihonVideo.audioTracks` 整份丢弃；`mpvArgs` 全仓无读取点（`media/manga/mihon/mihon_models.dart:768` 注释「只透传记录」）；`downloadRemoteVideo` 只下画面流，分离流会下成无声视频。报告里「wire 格式无法区分两种语义」的前提不成立：上游 Aniyomi 对 audioTracks 一律 `audio-add <url> auto`，由 mpv 默认选轨决定。
- **[x] ① 已修复** — `RemoteVideoStreamUrls` 新增 `externalAudioTracks`（`RemoteVideoExternalAudioTrack`：url / label / language，与「必须选中」的 `audioStreamUrl` 区分）；在线源 client 填入 audioTracks + mpvArgs 的 `audio-file(s)`；`VideoPlayerController.load` 在恢复 seek / play 之前逐条 `audio-add <url> auto <title> [lang]`（新纯函数 `media/video/video_external_audio_tracks.dart`），制卡音频源跟着当前实际选中的外挂音轨走（auto 且真实音轨全是外挂 = 纯视频流时取第一条），选中外挂音轨时不再按播放器轨序号 `-map`。`mpvArgs` 白名单（新 `online/anime_source_mpv_args.dart`）：`http-header-fields` / `referrer` / `user-agent` 并入取流头（Video.headers 优先），`audio-file(s)` 作外挂音轨，其余记日志忽略、不注入 mpv。下载器新增 `downloadWithExternalAudio`：画面与外挂音轨各自下载后 `ffmpeg -c copy` 合成 Matroska（映射 `0:v`、`0:a?`、各外挂 `N:a`），合成失败如实抛错。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/online/anime_source_mpv_args_test.dart`（白名单解析、audio-add 命令构造、制卡音频源判定）、`anime_source_video_client_test.dart`（externalAudioTracks / 合并请求头 / 下载走合成）、`anime_episode_downloader_test.dart`（回环服务器下两路 + 假 ffmpeg 断言合成参数、失败抛错不留成品）。
- **备注**：未用假 native player 断言 controller 发出 audio-add 的时序（放在既有 `externalAudioTrackUrl` 外挂之后、play 之前，同一代码块）；未用真实 DASH 扩展端到端验证。外挂音轨不会出现在 `RemoteVideoStreamUrls.fromJson` 之外的互联 wire 上（互联 host 不发此字段）。
