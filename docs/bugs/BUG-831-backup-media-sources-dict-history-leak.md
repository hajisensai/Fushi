## BUG-831 · 备份导出泄漏 media_sources 本地路径与 dictionary_history 查词记录
- **报告**：2026-07-15（用户：BUG-828 修复后精查真实备份 v44/v45，发现同类漏洞两处仍随主库导出）
- **真实性**：✅ 真 bug（BUG-828 的漏网表）。根因 `hibiki/lib/src/sync/backup_service.dart` `_stripOrphanUserDataTables`：BUG-828 覆盖了合集/标签/书架/搜索/墓碑，但漏了 `media_sources`（本地库根路径 `D:/书/…`、`D:/video/…`，泄漏设备目录结构）和 `dictionary_history`（最近查词记录，含 searchTerm + 渲染后的完整结果 JSON，单条可达数百 KB，是私人痕迹且体积大）。实测真实备份 `media_sources=2`（book+video 各一，含 D:/ 绝对路径）、`dictionary_history=4`（か いらんこと言ったなとか 等）。
- **[x] ① 已修复** — `_stripOrphanUserDataTables` 扩展：`dictionary_history` 加入无条件清空组（与 `search_history_items` 同列，私人痕迹永不导出，即便勾了词典也清）；`media_sources` 按内容类别 gating，`media_kind='book'` 随 `!includeBooks` 清、`media_kind='video'` 随 `!includeVideos` 清（`media_kind` 值域仅 book/video）。`epub_books`/`video_books.source_id → media_sources` 是 `onDelete:setNull` 且内容排除时这两表已被 `_retainBooks/_retainVideos` 清空，故删 media_sources FK 安全。真实备份 dry-run：`media_sources 2→0`、`dictionary_history 4→0`，`foreign_key_check` 无违反。
- **[x] ② 已加自动化测试** — `hibiki/test/sync/backup_categories_test.dart` 新增 3 例：full 导出清 dictionary_history + 留 media_sources；content-excluding 导出清 media_sources 两 kind；仅排除 videos 只删 video 源、留 book 源。并更新 `backup_service_test.dart` 既有断言（原断言 full 往返保留 dictionary_history=1，改为 `isEmpty`——反映「查词历史永不导出」的新语义）。全部 backup_* 测试单跑绿。
- **备注**：基于 origin/develop（含已合并的 BUG-828）新开分支修，非在旧分支叠。`dictionary_metadata`（词典本体元数据）与 `preferences` 的 `audio_source_configs`/`local_audio_dbs`（音频恢复必需）属正当数据，保留。
