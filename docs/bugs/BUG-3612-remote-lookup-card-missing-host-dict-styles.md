## BUG-3612 · 瘦客户端经远端查词制卡缺少 host 词典自带样式（看电脑媒体库视频）
- **报告**：2026-10-19（用户：反馈 embI7TO9xs，iPad 看 PC 媒体库视频制卡，iPad 未导入任何词典、查词由 PC 完成，卡片 Glossary / MainDefinition 里没有任何词典自带 `<style>`；BUG-3425 只修了游戏串流）
- **真实性**：✅ 真 bug，就是 BUG-3425 备注里点名的遗留路径。视频页（及阅读器 / 首页查词等所有 `DictionaryPageMixin` 表面）查词走 `AppModel.searchDictionary` 的 remote-first 分支，`_searchRemoteDictionary`（`fushi/lib/src/models/app_model.dart:7407`）**每次查词新建** `FushiRemoteLookupClient`、且没开 `trackDictionaryStyles`，请求不带 `stylesRevision`，host 一个字节的样式都不下发；结果交给弹窗时宿主也没有注入 `resourceSource`（`DictionaryPageMixin.popupResourceSource` 默认 null，`dictionary_page_mixin.dart:502`），`DictionaryPopupWebView` 于是只注入本机 `FushiDicts.dictionaryStyles`（`dictionary_popup_webview.dart:1759`，iPad 上为空表）。`popup.js` 渲染与导出 Glossary 都读 `window.dictionaryStyles?.[dictName]`，卡里自然没有样式。附件日志是 PC 侧日志，与该路径无关。不能照搬串流的「宿主注入资源源」：`popupResourceSource` 非 null 还意味着「卡片落在那台设备」（隐藏卡组 / 制卡目标切换、不收本机词典媒体），而这里卡片写在 iPad 本机 Anki，且同一表面下一次可能就是本机结果。
- **[x] ① 已修复** — 复用 BUG-3425 的 `stylesRevision` 门控：`DictionarySearchResult` 新增仅内存的 `remoteDictionaryStyles`（`withKanjiResults` 拷贝保留，不进 `toJson`）；`FushiRemoteLookupClient` 开着 `trackDictionaryStyles` 时把 host 样式挂到返回的结果上（指纹不变期间同一实例）；`AppModel` 改为复用一个开着 `trackDictionaryStyles` 的客户端（数据库或 http client 换了才重建），样式按指纹只整表下发一次；`DictionaryPopupWebView` 的远端样式来源改为 `resourceSource?.dictionaryStyles ?? result.remoteDictionaryStyles`，沿用既有的「整表替换 / 换回本机结果时重发静态段」逻辑。制卡目标、卡组选择等本机制卡行为不变。
- **[x] ② 已加自动化测试** — `fushi/test/sync/game_stream_host_dictionary_styles_test.dart`「BUG-3612」组（不钉候选的跟踪客户端结果带 host 样式且指纹不变时同一实例 / 拷贝不丢 / 未跟踪与老 host 结果为 null / `AppModel` 远端查词复用开着 `trackDictionaryStyles` 的客户端的源码守卫）；`fushi/test/pages/dictionary_popup_result_host_styles_test.dart`（真实推送链：带 host 样式的结果在静态段之后整表覆盖 `window.dictionaryStyles`、同实例不重注入、换回本机结果重发本机样式）。
- **备注**：待真机复测（iPad + Windows host 看媒体库视频制卡，核对卡片 Glossary 带 `<style>`）。老 host（不认 `stylesRevision`）仍回落本机样式，与修复前相同。未覆盖：host 词典媒体（外字 / 图片）在瘦客户端本机弹窗仍问本机引擎；桌面全局查词窗与 galgame 覆盖窗走各自渲染路径，未改。
