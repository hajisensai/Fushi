## BUG-5147 · 专辑补归组后丢失原始归属，后续增量扫描无法纠正；收尾零变化也整源重读
- **报告**：2026-11-22（外部审计 HBK-AUDIT-027，Codex 2026-11-21 PR 审查，针对 PR #4033 的 BUG-5080 修法）
- **真实性**：✅ 真 bug（PR #4033 head `3cd192de6a` 合 develop 后复现）。BUG-5080 的 `mergeSplitMusicAlbumsOfSource`（`packages/fushi_core/lib/src/database/database_music.part.dart:181`，PR head）把没写专辑艺人的曲目 `album_uid` 直接改写成带艺人那张的 uid，按标签算出的原值从此不在库里；增量扫描对没变的文件只报 `Unchanged`、不重新解析（`fushi/lib/src/media/music/music_library_scanner.dart:430`），归组器下次只看到「已经在带艺人那张里」的曲目。同目录后来加进第二位艺人的同名专辑（或带艺人的文件被删），被并过去的曲目永远退不回自己的专辑。另外收尾每次扫描都对整源做 曲目 ⋈ 专辑 全读 + 分组，零变化也一样（200 首的源零变化扫描读 200 行）；身份改写（`database_music_identity.part.dart` `_remapScannedMusicTracks`）也拿旧行的生效专辑当改写目标，会把新解析的曲目连原始归属一起钉在被并入的那张上。
- **[x] ① 已修复** — 原始归属单独成列、归组随写入在受影响目录上重算：schema v167 加 `music_tracks.scan_album_uid`（`music_tables.dart`，扫描落库写按标签算的 uid，归组从不改它；迁移回填为当前 `album_uid` 后整库归组一次，存量 BUG-5080 拆分也并回）。`writeMusicScanBatch` / `softDeleteMissingMusicTracks` 在各自事务末尾只对本批写入 / 本次软删曲目所在的（来源, 目录）调 `_regroupMusicAlbumDirs`：按 `path_key` 区间（`idx_music_tracks_path_key`）读该目录、按原始归属算——同目录同名、带专辑艺人的恰好一位时没写艺人的指向那张，否则一律退回原始归属，只写与现值不同的行。扫描器收尾不再整源归组。判据算上「从音乐库移除」的墓碑行（文件仍在，隐藏不该让同盘其它曲目换专辑）。身份改写目标改用旧行的 `scan_album_uid`。新增 `musicTrackDirPrefix`（`media_source_util.dart`）。
- **[x] ② 已加自动化测试** — `fushi/test/media/music/music_library_scanner_test.dart`「HBK-AUDIT-027」两条（增量加第二位艺人 → 退回、再删 → 并回、带艺人的全删 → 退回；零变化扫描归组读 0 行（修前 200 行）、只有一个目录新增一首时只读该目录 11 行；变异实测：退回修前代码两条都红——h2 停在 x-uid、零变化读 200 行）；`fushi/test/database/migration_v167_music_scan_album_uid_test.dart`（v166→v167 回填 + 整库归组 + 重跑幂等；单批落库即已归组；重新解析不被生效专辑钉死；隐藏带艺人曲目不换组）。
- **备注**：未做真机验证（音乐库真实目录增量扫描），缺口仅此。schema 号 v167 与同期其它分支可能撞号，合并时按惯例顺延。
