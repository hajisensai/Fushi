## BUG-4243 · 资源搜索漏掉高种整季包：贴合度只认单一查询词、S01 季包给不出下载计划
- **报告**：2026-11-08（用户：AI 下视频 / `fushi_cli aidl` 搜《BanG Dream! Ave Mujica》只给出 ToonsHub 7 集 2 种，nyaa 上 cappybara BD 54 种、DBD-Raws、SubsPlease Batch 全没给）
- **真实性**：✅ 真 bug。nyaa 请求本身没问题（HTML 搜索、`s=seeders&o=desc`，`!` 不影响结果），高种发布都已返回到 app，丢在下游两处：
  - A：AniList 169295 的 title=native=romaji=`BanG Dream! Ave Mujica`，英文名 `Ave Mujica - The Die is Cast -` 进别名并被选成首选查询词；provider 用全部叫法各查一次，但 `VideoResourceRegistry.search` 重排时只拿 `request.effectiveQuery` 一个词算标题贴合度（`packages/fushi_engine/lib/media/video/download/video_resource_registry.dart:131` → `packages/fushi_engine/lib/media/torrent/video_resource_relevance.dart:117`），写正式名的 cappybara / LoftMoon / SubsPlease / DBD 被当成「不相关」沉到十名开外；版本卡把相关度名次当组间主键（`video_resource_version_groups.dart:237`）。
  - B：`[cappybara] … - S01 (BD 1080p …)` / `… S01 VOSTFR …` 这种只写季号的季包，`looksLikeBatchVideoRelease`（`packages/fushi_engine/lib/media/video/download/subscription_release_scope.dart:36`）不认，下载规划「全集」分支只认它（`video_acquisition_resource_picker.dart:501`），整张卡给不出计划被 `_firstPlannable` 静默跳过。
- **[x] ① 已修复** — A：`rankVideoResourcesByRelevance` 新增 `workTitles`，查询身份的标题集合 = 查询词 ∪ 作品全部已知标题（季号仍只认查询词 / 显式季号），registry 有 `media` 时传 `title + originalTitle + aliases`；同分回到上游做种次序。B：`looksLikeBatchVideoRelease` 认「季包记号（`S01` / `Season 2` / `2nd Season` / `第2季`）且解析不出集号」，订阅端 `subscriptionReleaseIsBatch` 本来就把它们算整包，答案不变；没有季号的无集号单条（`Show Special`）仍不当全集。实测离线复现（121 条真实 nyaa 结果）首推从 ToonsHub 7 集 2 种变为 cappybara BD 季包 54 种，其后 LoftMoon / SubsPlease / DBD / SubsPlease Batch。
- **[x] ② 已加自动化测试** — `fushi/test/torrent/video_resource_relevance_test.dart`、`fushi/test/media/video/download/video_resource_registry_work_titles_test.dart`、`fushi/test/media/video/download/subscription_release_scope_test.dart`、`fushi/test/media/video/acquisition/video_acquisition_resource_picker_test.dart`
- **备注**：`_nyaaWorkQueries` 把英文副标题排在 title 前、成为订阅行默认 searchQuery 的取词顺序问题未动（修 A 后只影响默认查询词展示，不再影响排序）。`[Moozzi2] … - TV + SP` 这种既无季号也无集号的 BD 包仍给不出「全集」计划（与一集特典无法区分，按 BUG-4241 的取舍保守处理）。
