## BUG-2775 · 有声书下载导入失败只显示 import failed
- **报告**：2026-09-29（用户：下载「[新海誠] 小説 秒速5センチメートル」有声书后任务行只显示红字 `import failed`；有声书目前不能精确定位/附着到已有 EPUB，报错却让人摸不着头脑）
- **真实性**：✅ 真 bug。界面显示的是裸 `import failed`（不带 `discovery import failed:` 前缀），说明导入器没抛异常、只返回了 0 条。有声书自动入库（`fushi/lib/src/media/discovery/import/discovery_import_production.dart` `importAudiobook`）遇到包内 EPUB 与库中已有书同名时 `return null`（v1 刻意不把音频自动附着到既有书），执行器把 null 记成 0 条 → `AnimeDownloadService._finishDiscoveryPlan`（`fushi/lib/src/media/torrent/anime_download_service.dart`）落兜底 `failReason: 'import failed'`，任务行（`anime_download_dialog.dart` `_buildPlanRow`）原样显示。另外 `DiscoveryImportBlocker` 注释声称「UI 层负责翻译」，实际上没有翻译层：缺字幕 / 缺音频 / 解压失败等被挡下的原因也只会以 `DiscoveryImportBlockedException(...)` 的 toString 原样露给用户。
- **[x] ① 已修复** — `daac1196fb2`：新增原因码 `DiscoveryImportBlocker.audiobookBookAlreadyInLibrary`，同名书分支改抛 `DiscoveryImportBlockedException`；service 捕获被挡下异常时落稳定原因码 `blocked:<name>`（`animeDownloadBlockedFailReason`，换界面语言后旧任务也跟着变）；任务行经 `describeAnimeDownloadFailReason` 把每个原因码翻译成可照做的文案（同名书：「库中已有同名书。有声书暂时不能自动关联到已有的 EPUB，请打开这本书手动导入有声书」），非原因码的旧任务 / 诊断文本原样显示。
- **[x] ② 已加自动化测试** — `fushi/test/media/discovery/import/discovery_import_production_test.dart`（内存库 + 最小 EPUB 真跑生产导入器：先入库，再以同一本书走有声书导入，断言抛新原因码）；`fushi/test/torrent/anime_download_service_discovery_kind_test.dart`（被挡下 → failReason 可解析并翻译成同名书文案；每个原因码都有专门文案；非原因码原样透传）。
- **备注**：手动「添加任务」的下载管线（`packages/fushi_engine/.../video_download_pipeline_service.dart` `_importDiscoveryMedia`）仍把被挡下异常的 toString 塞进 ActionRequired，本次未动；游戏包 exe 已全部在库（登记 0 条）同样会落兜底 `import failed`，非本 bug 范围。
