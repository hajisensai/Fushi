## BUG-874 · 竖排有声书读到「句首是行尾单字」的句子时凭空前翻一页、下一句又翻回
- **报告**：2026-07-18（用户：）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/reader/reader_pagination_scripts.dart` `scrollToRange`（cue-follow + search-highlight 共用落页原语，旧行 1975）用起始边 `rect.top`（竖排）`alignToPage`(floor) 落页，但 `pageStep`（列周期 = N×(used 列宽+gap)）因 chrome inset / body padding 可比 client 视口 `viewportExtent` 小最多半页（见同文件 `getScrollContext` 的 `physicalMaxScroll` 注释「两者因此可相差半页」）。
  - 现象：竖排（vertical-rl）有声书跟读时，遇到某句 **句首恰是一行行尾的单字**（竖排=列底只容下一个字、其余绕到下一行/列）时，读到该句 WebView 凭空**前翻一页**（用户看不到当前句也看不到高亮标记），读到下一句又**翻回**正确页。可靠复现。
  - 链路：`audiobook.part.dart _onCueChanged` → `AudiobookBridge.highlight(reveal:true)` → JS `window.__hoshiRevealTarget(t)` → 分页模式走 `hoshiReader.scrollToRange(rng)`（`rng.selectNode(高亮元素)`）。
  - 根因：`scrollToRange` 只按 pitch 网格 `floor((rect.top+currentScroll)/pageStep)*pageStep` 落页，**缺「句首已在 client 视口内即不翻页」的短路**（`scrollToTarget` 有 `已可见 return false`，`scrollToRange` 没有）。句首行尾单字的 `rect.top` 落在 `[pageStep, viewportExtent)` 这条「视觉仍在本页底部、却已越过 pitch 网格边界」的失配带内 → floor 判进下一 pitch 页 → 前翻；下一句句首起始边回落 `[0, pageStep)` → floor 落本页 → 翻回 = 抖动。单字最大化句首 `rect.top`（把句首顶到列最底），故只在「行尾单字起句」这一几何下触发；多字起句时句首 `rect.top` 更靠上、落在 `[0,pageStep)` 不触发。TODO-881（中点锚→起始边锚）修的是同路径的另一抖动，未覆盖本页底失配。
  - 判据：句首视觉在本页底部（用户截图为正确页，绿色高亮句首「ホ」在最右列底可见）⟺ 句首在 client 视口内 ⟺ reveal 不该翻页；却前翻 ⟺ floor 用 pageStep 网格把页底可见句首误判进下一页。
- **[x] ① 已修复** — `reader_pagination_scripts.dart`：`getScrollContext` 返回对象新增 `viewportExtent`（真实 client 视口 extent，此前只本地算给 `physicalMaxScroll` 用）；`scrollToRange` 在 floor 落页前加可见短路 `if (startEdge >= 0 && startEdge < context.viewportExtent) return false;`——句首起始边落在真实视口 `[0, viewportExtent)` 内即「已在本页可见」不翻页（`startEdge<0` 句首滚出视口首边、`>=viewportExtent` 句首真在下一页时不短路、照常 floor 落页）。分页整页对齐无需 `scrollToTarget` 的 15% 安全边距（句子落本页任意位置都是合法阅读位）。从根上消除 pitch 网格与 client 视口在页底的坐标失配，不引入延迟/重试/特例分支。提交：`29f5873042`。
- **[x] ② 已加自动化测试** — `hibiki/test/reader/reveal_viewport_visible_no_flip_test.dart`：纯函数影子 `ReaderPaginationScripts.revealScrollTargetForTesting`（pageSize<viewportExtent 半页失配）断言句首 `rect.top∈[pageStep,viewportExtent)` 返 `null`（不翻页），旧 `revealAnchorTargetScrollForTesting` 同输入返 3000（前翻，坐实症状）；`rect.top>=viewportExtent`/`<0` 仍照常 floor 落页；源码守卫断言 `getScrollContext` 暴露 `viewportExtent` 且 `scrollToRange` 含 `startEdge < context.viewportExtent` 短路（回退即红）。headless WebView 不可用，沿用项目「纯函数单测 + 源码扫描守卫」范式。
- **备注**：真机复测（竖排 + 有声书跟读）：构造一句句首恰是行尾单字的 cue（或找到复现书位），播放读到该句时正文**不前翻**、当前句与高亮标记保持可见；读下一句不翻回。相邻普通句跟读翻页仍正常（句首真移出本页时照常翻页）。横排（horizontal-tb）不受影响（同短路对横排用 `rect.left`/`clientWidth`，行为一致）。
