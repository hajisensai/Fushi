## BUG-2597 · 歌词模式听书字数不入账、自动恢复歌词时可能零时长
- **报告**：2026-09-19（用户：「歌词模式统计有问题怎么回事」）
- **真实性**：✅ 真 bug（真实代码路径）。**字数**：`ReadUnitLedger.arrive` 的唯一调用点是 `_refreshProgress`（`fushi/lib/src/pages/implementations/reader_fushi/navigation.part.dart:1264`），它在歌词模式三处早返回（`:1156 / :1191 / :1211`）；歌词文档没有滚动回传（`lyrics_mode_html.dart` 只回 `onLyricsReady/onLyricsTapEmpty/onShiftHover/onLyricsPointerSeek`），`_onCueChanged` 歌词分支（`audiobook.part.dart:693-735`）只 `touch()` 空闲门 + `_syncPositionFromCurrentCue`（只写落库位置，不进账本）。于是整段听书账本零推进；进歌词经 `_loadLyricsPage → loadData` 不过 `_beginNavigation`，退出时 `_exitLyricsMode → _navigateToChapter → _beginNavigation.leave()` 结算的还是**进歌词前站着那一页**，听一小时字数 0、「字/时」一路下跌，统计页出现大量「有时长 0 字」的会话。**时长**：`_studyClock` 只在 `_onRestoreComplete` / 内容就绪兜底 / 账本回调 / 手动暂停键里 `_ensureStudyClock()`；开书自动恢复歌词模式（BUG-785，`webview.part.dart` `_onChapterLoadComplete` 尾部触发）可能抢在正文 `notifyRestoreComplete` 之前，歌词 `loadData` 换掉文档后那次回调永远不来 → 时钟为 null → `touch()` 与 `_syncStudyClockRunState` 全部 no-op → 整段歌词会话零时长。
- **[x] ① 已修复** — `_onCueChanged` 歌词分支新增 `_arriveLyricsCueUnit`：播放态下把**当前句**当阅读单元 `arrive(start, end)`（cue 推进 = 翻走上一句，翻走即计 + 会话并集去重，与正文同一本账）；区间经 `_studyUnitForLyricsCue`：`fushi-cue://` 走 `_studyRangeForAudioFragment`（BUG-2333 口径），独立 SRT / SMIL 走 `_srtCueChapterMap` / `chapterHref` 定章 + `ReaderAudioPositionIndex.studyRangeForUniqueText` 唯一命中，解不出不计。进歌词模式 `_readLedger.leave()`（与 `_beginNavigation` 对称）；歌词文档就绪（`_lyricsPageReady = true`）处 `_ensureStudyClock()`。暂停态被动高亮 / 显式跳句不 arrive（后者已 `leave()`，BUG-1107）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/reader_lyrics_chapter_nav_and_stats_static_test.dart`（BUG-2597 组：歌词分支调 `_arriveLyricsCueUnit`、只在播放态、走学习单位映射、先 `_traceArrive` 再入账、进歌词 `leave()`、歌词就绪建时钟）；真机门 `fushi/integration_test/reader_lyrics_settings_and_chapter_nav_itest.dart` ③：歌词模式从章首播到第 3 句后退出歌词，`study_segments` 该书 `chars` 必须增长。
- **备注**：暂停后不停表、只靠空闲门（默认 10 分钟）拒窗，以及歌词页滚动 / 点句 / 查词不喂门，是既定语义（BUG-2558 / 查词不喂门），本条不动。
