## BUG-3522 · 出站同步落地无条件写本地进度，盖掉刚到的互联对端 PUT（进度倒退）
- **报告**：2026-10-19（PR #2335 / BUG-3519 审查：host 进度 PUT 改拿窄锁后，本机出站写口不再与它互斥）
- **真实性**：✅ 真 bug（沿代码路径验证）。BUG-3519 让 host 端 `putBookProgress`（`packages/fushi_engine/lib/sync/local_library_host_service/books.part.dart:425`）与视频 / 有声书位置 PUT 只持同步状态窄锁 `runExclusiveWithSyncStateApply`，不再排在整轮同步锁 `runExclusiveWithSync` 后；而本机落 `reader_positions` / 断点偏好的出站写口既不拿这把窄锁、又是无条件写：
  - 云导入：`fushi/lib/src/sync/sync_manager.dart` `_syncBookOnce` 在第 317 行读本地并判方向，`_handleImport` 先 `await _backend.getProgressFile(...)`（第 581 行，网络），再在第 603 行无条件 `upsertReaderPosition`（写云端旧 `updatedAt`）并记基线；有声书断点同形，第 634 行 `getAudioBookFile` 后第 636 行无条件 `setAudiobookPosition`。
  - 互联 client：`fushi/lib/src/sync/interconnect_book_progress_sync.dart` 的 `applyRemote` / `pushLocal` / `alignSynced` 都经 `_upsertLocal`（第 170 行）无条件写；`pushLocal` / `alignSynced` 的本地写夹在一次网络 PUT 之后。`interconnect_playback_position_sync.dart` 的 `applyRemote` / `alignSynced` / `pushLocal` 对断点偏好同形（sweep 先读本地再网络读 host，`_writeLocal` 无条件写）。
  - 时序：电脑既是互联 host 又跑云同步 → 云导入判定后在等网络 → 手机 PUT 新进度 Y，host 落库、手机记基线 → 云导入用旧值 X 覆盖 → 手机下一轮判「只 host 动了」→ applyRemote，手机进度也倒退到 X。变异实测（去掉比较 = 修前的无条件写）：云导入后 host 回给对端的是第 50 页 @5000，而不是对端刚 PUT 的第 120 页。
- **[x] ① 已修复** — 仓储层加两个「比较后写入」原语，重读与写入同一 DB 事务：`FushiDatabase.upsertReaderPositionIfUnchanged(pos, expectedUpdatedAt:)`（`database_library.part.dart`，无行按 0 比较）与 `runIfIntPrefUnchanged(stampKey:, expectedStamp:, write:)`（`database_prefs_media.part.dart`）。云导入用判定时读到的本地时间戳 / 有声书 `_at_` 戳做 CAS，失败即返回 skipped、不记基线；互联书进度与播放断点的全部本地落地改走 CAS，`applyRemote` 返回是否落地（失败不记基线、sweep 不计「已拉取」、冲突弹窗不计已解决）。host 三个 PUT 的读-比较-写在窄锁内再包一层 `_db.transaction`，与出站 CAS 互不插队。没把整轮锁加回来。提交 `fix(sync): outbound progress landing compares before writing (BUG-3522)`。
- **[x] ② 已加自动化测试** — `fushi/test/sync/outbound_progress_landing_cas_test.dart`（13 条）：仓储层 CAS 原语 4 条；`SyncManager` 云导入在 `getProgressFile` / `getAudioBookFile` 网络读期间让生产接线的真 `LocalLibraryHostService` 收对端 PUT，断言对端新值保留、基线不推进；`InterconnectBookProgressSync` 判定后 / PUT 期间本地被对端 PUT 改写、`InterconnectPlaybackPositionSync` 判定后断点被改写各一条，每组带「无插队照常落地」对照。变异实测：去掉两个原语里的比较，8 条竞态用例全红、5 条对照仍绿。
- **备注**：无头服务端（`fushi_server`）不跑本机出站同步，只受益于 host PUT 的事务化，无行为变化。
