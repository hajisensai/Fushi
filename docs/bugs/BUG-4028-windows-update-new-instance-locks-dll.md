## BUG-4028 · Windows 应用内更新：安装期间新启动的 Fushi 占用 DLL 致整包回滚
- **报告**：2026-11-03（反馈 umcyzpaebn，Windows 10.0.26200，3.3.0-debug.23025 → 23080：`update-handoff.json` 记 `installerExitCode=5` / `installer_incomplete` / `appAliveAfterInstaller=true`；Inno 日志 10:31:30.440 旧实例退出、.457 launcher 拉起安装器、10:31:31 一个父进程为 explorer.exe 的新 fushi.exe（PID 17896）启动、10:31:31.395 起 `DeleteFile fbdaom.dll` code 5 重试 4 次后 Abort 回滚；事后模块枚举确认 fbdaom.dll 映射在 17896 里。结果是「新 exe 资源版本 + 旧 data\app.so」半更新态）
- **真实性**：✅ 真 bug（结构性缺口，按日志与代码路径确认；新实例**为什么**被拉起未能归因，见备注）。沿真实交接路径：`platform_updater.dart` 拉起 launcher 后 `exit` → `update_launcher.cpp` 等父进程退出、等 `FushiSingleInstanceMutex` 释放后启动安装器 → `fushi.iss` `InitializeSetup`（WM_CLOSE / 结束持有单实例互斥量的 fushi.exe）→ `PrepareToInstall`（`KillProcessesUnderDir({app})` 按镜像路径清场）→ 复制。两次清场都是**一次性快照**，之后启动的 fushi.exe 没有任何东西拦。根因在 `fushi/windows/installer/fushi.iss` `PrepareToInstall`（清场后再无门）+ `fushi/windows/runner/main.cpp` `wWinMain`（启动时不知道安装目录正在被替换，照常抢单实例互斥量、建引擎）。launcher 自己拉 app 走 `CreateProcessW`（父进程会是 launcher），`[Run]` 走安装器——父进程 explorer.exe 说明这次启动来自 shell（任务栏 / 开始菜单 / 文件关联等），不在 Fushi 自己的交接代码里。
- **[x] ① 已修复** — 加一道两侧共享的「请勿启动」门 `FushiInstallInProgressMutex`：`fushi.iss` 在 `PrepareToInstall` **先** `OpenFushiInstallGate()`（`CreateMutexW`）**再**清场，`CurStepChanged(ssPostInstall)`（全部文件已落地）第一件事 `CloseFushiInstallGate()`；`LockedGalHookComponent` 命中而中止时也放门；回滚 / 取消时安装器退出、句柄随之关闭。`main.cpp` 新增 `InstallInProgress()`，启动第一步（抢单实例互斥量之前）与「等完退出中的旧实例」之后、建引擎之前各判一次，门在就立即 `return EXIT_SUCCESS`（不等待：等待期间 exe 与静态插件 DLL 一直被映射，正好把安装卡死；安装器 `DeleteFile` 自带重试，瞬时映射不影响）。提权安装建的门对普通权限进程 `OpenMutexW` 返回 `ERROR_ACCESS_DENIED`，同样视为门在。于是：门建好之前启动的进程一定在清场快照里被结束；之后启动的自己退出。`[Run]` / launcher 的 `EnsureAppBack` 都在门放开之后，安装成功后新版照常被拉起。
- **[x] ② 已加自动化测试** — `fushi/test/build/windows_installer_launch_gate_guard_test.dart`（源码守卫：两侧门名一致；`PrepareToInstall` 中建门先于 `KillProcessesUnderDir`；`ssPostInstall` 才放门、`[Run]` 仍在；runner 在单实例互斥量之前与等完旧实例之后各判一次门、门在即 `return EXIT_SUCCESS` 且不 `Wait`；`ERROR_ACCESS_DENIED` 算门在）。Inno 脚本与 C++ runner 没有可跑的单测框架，沿用 `update_launcher_relaunch_guard_test.dart` 同款源码扫描。`tool/preview_installer.ps1 -CompileOnly` 编译通过。
- **备注**：未做真机应用内更新复测（需要发两版安装包走完整交接）；runner 改动未做 `flutter build windows` 编译验证（见交接报告）。反馈里的另两条期望未做：② 复制前对 `{app}` 下全部 dll/exe 写锁预检——有了门之后 Fushi 自身不再是占用来源，外部占用仍由既有 `LockedGalHookComponent` 覆盖 voice_hook；③ 识别半更新态并提示——属于另一层兜底，未在本条范围。17896 为什么在那一刻被 shell 拉起（用户点击 / 文件关联 / 其它工具）无日志可证，未归因。
