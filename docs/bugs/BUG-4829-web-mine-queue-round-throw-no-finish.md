## BUG-4829 · 网页视频制卡队列一轮中途抛异常时不收尾：交接页回不去、后台制卡页不关、调度器停在「在跑」
- **报告**：2026-11-17（网页视频只读补查 gap-webvideo-2，复核 confirmed）
- **真实性**：✅ 真 bug（控制流确证）。`fushi/lib/src/pages/implementations/web_video_fushi_page.dart:1588-1695`（修前）`_runMineQueue` 只有 `try {…} finally {…}`，整轮收尾 `_finishMining(...)` 写在 finally **之后**。try 里没被各自 catch 包住的 await：`getTemporaryDirectory`、`resolveTargetMiningImageMode`（只吞 `Exception`）、`_navigateForMining` 的 `loadUrl`、`_mineQueue.markFailed` / `markDone` 的 DB 写、`runner.capture`（`encodeAudio`、截帧）、`_resolveCardMedia`。任何一处抛出 → `_finishMining` 被跳过：交接页不 `_reopen` 回原档；后台制卡页不关页，`WebMineBackgroundRunner` 的 `openMiningPage` 永不完成，后台自动制卡到重启前不再跑（`_autoRunTriggered` 已为 true，开跑截止也不再兜底）；空闲调度器不 `runFinished()`，停在高频轮询。finally 里 `loopback.stop()` 自己抛出时连 `_mineRunning` 都不复位。出错那一行还留在待办，下一轮原样再撞。
- **[x] ① 已修复**（`e40b885fc55`）— 一轮的编排抽到 `fushi/lib/src/mining/web_mine_queue_run.dart`：`runWebMineQueueRows` 对每一行 try/catch——记日志、标这一行失败、**结束本轮**，其余行留在待办（抛出时已在让位 / 页面已卸载的不标失败，留待办）。标失败是为了必抛的行不会每次重跑到同一处；不接着跑是因为抛出的原因分不清是这一行的还是环境的（临时目录写不进去时每一行都会抛），而网页队列的失败行没有重试入口，接着跑会把整条队列逐行标成失败（独立审查指出，取代最初「标失败并继续」的写法）；`runWebMineQueueRound` 保证 body 抛不抛、某一步还原抛不抛，后面的还原步骤都执行且不向外抛，`_finishMining` 在它返回后无条件调用。行内抛过错时收尾先暂停站点（否则还原会话音量后会外放）。自动制卡出错（准备步骤抛出 / 某一行抛出）时把这本书记进进程级的 `WebMineIdleGiveUps`（同文件）：本次空闲不再自动开跑，用户有过输入才作废——不让空闲调度每几秒原样重撞；记在进程级而不是页面字段，是因为窗口宿主档的空闲交接每轮都换页面实例。
- **[x] ② 已加自动化测试** — `fushi/test/mining/web_mine_queue_run_test.dart`（一行抛出只损失这一行并结束本轮、每行都抛的环境故障一轮只损失一行、导航抛出、标失败自己抛出、让位后抛出留待办；「WebMineIdleGiveUps」组；「runWebMineQueueRound」组：body 抛出 / 某步收尾抛出 / 同步抛出时其余收尾照常执行）；`fushi/test/media/video/web_video_mine_queue_guard_test.dart`「BUG-4829 / BUG-4800」组钉页面确实走这套骨架、`_finishMining` 在骨架之后且是方法体顶层语句（没被条件分支包住）、空闲开跑前查 `WebMineIdleGiveUps`。
- **备注**：整轮准备步骤抛出时给用户看的仍是「成功 0 / 失败 0」（原因只在 error_log），「出错」状态要加文案，留给失败行重试入口（gap-webvideo-6）拍板时一起做。待真机复测——桌面与 Android 各跑一次「看完再制卡」，含中途抛错（例如重放途中断开 Anki / 让临时目录不可写）后交接页仍换回原档、后台制卡页仍关页。同批改动：队列按视频归组（gap-webvideo-5，A、B、A 从导航三次降到至多两次，落卡顺序随之按视频聚合）。
