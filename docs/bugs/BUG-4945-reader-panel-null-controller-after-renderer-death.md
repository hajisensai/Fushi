## BUG-4945 · reader-panel-null-controller-after-renderer-death
- **报告**：2026-11-21（用户：应用内反馈 b8ODOAKcMX，Redmi Note 8 / Android 11 / 3.3.0；同机同签名 gnw0KuIdfg）
- **真实性**：✅ 真 bug（次生的 Dart 空断言）。日志 `Null check operator used on a null value @ _ReaderChrome._buildQuickSettingsSheet (chrome.part.dart:2778)`，经 `_openReaderPanel` 的 `ValueListenableBuilder` 重建触发；同期 MIUI MemoryService 杀掉 WebView 沙箱进程。根因：`fushi/lib/src/pages/implementations/reader_fushi_page.dart:2409` 的 `WebViewDeathGuard.flushBeforeRebuild` 在 renderer 死后把 `_controller` 置 null，而已经打开的侧板重建时走 `fushi/lib/src/pages/implementations/reader_fushi/chrome.part.dart:2876` 的 `webViewController: _controller!`。该参数在小说阅读器里根本没被用：`ReaderQuickSettingsSheet` 只在 `!isFushiReader` 时把它交给 `AudiobookBridge.setReaderSetting`，而唯一调用点固定传 `isFushiReader: true`，`setReaderSetting` 本身也是空实现——侧板对正文 controller 的依赖是死依赖，却在构建期做了非空断言。
- **[x] ① 已修复** — 删掉 `ReaderQuickSettingsSheet.webViewController` 参数、`_updateSetting` 里的 TTU 死分支和空实现的 `AudiobookBridge.setReaderSetting`，`_buildQuickSettingsSheet` 不再读 `_controller`。侧板构建路径与正文 WebView 生命周期解耦，renderer 死亡后侧板照常重建。
- **[x] ② 已加自动化测试** — `fushi/test/pages/reader_panel_controller_independence_static_test.dart`（源码扫描守卫：侧板构建路径不得读 `_controller`，sheet 不得再持有 `InAppWebViewController`）；`fushi/test/media/audiobook/audiobook_play_bar_theme_chip_test.dart` 的 widget 测试改为不传 controller 构建 sheet。
- **备注**：同一反馈里的主崩溃是原生 `CRASH_NATIVE status=6 (SIGABRT)`（低内存 `RUNNING_CRITICAL`、srs_sync `start:migrate:meta` 阶段），无 tombstone 线程栈，证据不足以定位代码根因，本条不处理，需要带 tombstone 的复现。renderer 死后正文 WebView 不重建（`afterRebuild` 未接，见 reader_fushi_page.dart 的注释）以及侧板里导航类回调点击时仍会走 `_controller!`（异步报错、不崩构建）属于既有设计，未在本条改动。设备肉眼复测（杀 renderer 时侧板开着）未做。
