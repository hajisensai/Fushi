## BUG-1646 · 漫画页选文件夹导入：目录内是 epub 卷时报 Manga image folder has no pages
- **报告**：2026-08-14（用户：漫画界面导入 `銀河英雄伝説01 (ヤングジャンプコミックスDIGITAL).epub` 相关的文件夹，报「导入失败: MangaImportException: Manga image folder has no pages」）
- **真实性**：✅ 真 bug — 根因 `fushi/lib/src/media/import/import_carrier.dart:55`（修复前）：`if (isDirectory(path)) return ImportCarrier.mangaFolder;`——**目录只有「一卷页图目录」一种解释**。用户选的是一个装着多卷 `.epub` 的文件夹，于是走 `MangaImporter.importFromImageFolder` → `enumerateMangaPages`（`fushi/lib/src/ocr/manga_ocr_folder_job.dart:124-133` 只收 `kMangaOcrImageExtensions` 的图片扩展名）→ 0 页 → `manga_importer.dart:109` 抛 `Manga image folder has no pages`。那句话描述的是判定结果，不是用户做错了什么。
- **不是**「漫画被认成小说」：用户给的样本 EPUB 走**单文件**路径判定完全正确。实测（临时诊断测试，已删）：`looksLikeImageArchive = true`、`isPureImageEpub = true`、194 个 spine 章全是纯图页；该包是 Open Manga Format（`omf:version omf.1.0` + `rendition:layout pre-paginated`，页面用 SVG `<image xlink:href>` 包 JPEG，TODO-1174 起已被 `_chapterImageRefs` 认出）。单文件路径无需改动。
- **[x] ① 已修复** — 给 `ImportCarrier` 补上缺失的目录形态 `mangaBatchFolder`，而不是给旧分支加特例：目录里装什么是**数据的形状**。`classifyImportCarrier` 的目录分支改为「有页图 → `mangaFolder`（与改动前逐字节一致）；无页图但直接子层有整卷文件 → `mangaBatchFolder`；都没有 → 仍 `mangaFolder`，让导入器抛那句更准确的『没有页』」。新增 `fushi/lib/src/media/manga/import/manga_folder_batch.dart` 逐卷导入（一卷失败不中断整批、标题取各自文件名、`DuplicatePolicy.skip` 使重跑幂等），对话框在批量时把标题框换成「这批有几卷」的说明并汇报「成功/跳过/失败各几卷」。文件选择器白名单改为从新的唯一真相源 `kMangaCarrierFileExtensions` 派生，不再手抄。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_folder_batch_test.dart`（13 条：目录两种形态的生产实参判定、候选枚举只看直接子层 + 自然序、逐卷各成一本、一卷坏包不中断整批、带插图的 Yomitan 词典 zip 不落库、重跑幂等、`isEmpty`、进度回报）+ `fushi/test/media/import/import_carrier_test.dart` 新增「目录的两种形状（BUG-1646）」4 条。两条关键守卫做过变异实测：把批量分支阈值改成 `> 999999` → 2 红；把逐卷 `catch` 改成 `rethrow` → 1 红；回滚后 sha256 与变异前一致。
- **备注**：来源扫描那条路（漫画库「来源」tab 的本地扫描根）仍只认 `.mokuro`（`fushi/lib/src/media/source_library/source_library_scanner.dart:60` 的 `kScanMangaExtensions`），`mediaKind == 'manga'` 的来源里 `.epub`/`.cbz` 会被归进 `plan.books` 后整桶丢弃且**不报错**。那是有意为之的首版边界（`:592-595` 注释：重扫去重要按身份 key，CBZ/裸图没有那层契约），不在本次范围内——本次只修「导入对话框选文件夹」这条用户真实走的路。
