## BUG-752 · 扩展查词弹窗与app内完全不一样：content.css生成器把通用reset抬到ID特异性压死低特异性margin/padding
- **报告**：2026-07-12（用户：浏览器查词弹窗完全不一样，和正常弹窗。附截图：注音（振假名）直接印在词条正文汉字上、排版间距整体塌掉）
- **真实性**：✅ 真 bug。根因 `tools/browser-extension/scripts/generate-content-css.mjs:104`（修复前 `transformSelectorList`）：popup.css 的通用 reset `* { margin:0; padding:0; box-sizing:border-box }`（特异性 0,0,0）被生成器改写成 `#entries-container, #entries-container *`（特异性 1,0,0），反超 popup.css 里**特意用 `:where()` 压低特异性**的规则——最扎眼的是 `:where(.glossary-group,.glossary-content) .ruby-unit { padding-top:0.55em }`（0,1,0；BUG-722/732/733 的注音预留空间）被压死，`rt`（`position:absolute; top:0`）失去预留直接印在基字上。同理弹窗内**所有**类选择器声明的 margin/padding 在扩展里全部归零，与 app 内 popup.css 级联完全分叉 →「完全不一样」。
  - 排除项（验伪记录）：已安装扩展副本与用户 app build 7561 打包资产逐字节一致（BUG-726 指纹刷新链路正常）；三镜像（assets/popup ↔ assets/browser_extension/vendor ↔ tools/browser-extension/vendor）在 origin/develop 无漂移；app_model.dart BUG-688 注释归因的「Blink CSS zoom + rt 绝对定位错位」经无头 Chrome 对照实验证伪——zoom=1 也重叠、修复后 zoom=1.75 也不重叠，与 zoom 无关。
  - 复现证据：无头 Chrome harness（shadow DOM + content.css `<link>` + postProcessRuby 同构 DOM）zoom=1 即复现注音塌陷；诊断显示 `.ruby-unit` 计算样式 `paddingTop=0px` 而同块 `line-height:1` 生效 = 单属性被更高特异性规则压制。
- **[x] ① 已修复** — `generate-content-css.mjs` 所有 re-root 前缀改为特异性中性的 `:where()`：`*` → `:where(#entries-container, #entries-container *)`（精确保持 0,0,0），`body`/`html*` → `:where(#entries-container)…`，`hr`/`a`/`::selection`/`::-webkit-scrollbar*` → `:where(#entries-container) …`（精确保持 0,0,x）；重新生成两份 content.css（仅 15 个 re-root 选择器变化）。修复后 harness 复测：zoom=1 与 zoom=1.75 注音均正确悬浮于基字上方（`paddingTop=8.25px` 生效）。提交：见本分支。
- **[x] ② 已加自动化测试** — `hibiki/test/build/browser_extension_popup_parity_guard_test.dart`：新增「re-root 必须特异性中性」守卫（禁止任何 `#entries-container`/`#entries-container *` 裸 ID 前缀 re-root 选择器重新出现，`:where` reset 必须存在），并同步更新 scoped 断言字符串。
- **备注**：用户已装副本（app build 7561 解压）仍是旧 content.css；落地进 app 后随 BUG-726 指纹链路自动刷新磁盘副本，但浏览器里仍需在 `chrome://extensions` 手动「重新加载」一次扩展才吃到新样式。BUG-688 在 `app_model.dart`/`content.js` 里关于「扩展嵌套 zoom 触发假名重叠」的注释是误诊（真凶即本 bug），不影响其「浮动弹窗不叠加 appUiScale」的尺寸决策本身，注释未改。
