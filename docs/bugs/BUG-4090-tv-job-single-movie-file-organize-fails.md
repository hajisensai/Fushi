## BUG-4090 · 剧集身份的下载任务下到单文件剧场版，整理报 unable to determine episode number
- **报告**：2026-11-04（用户：应用内反馈 9Fpg5zXriP，Windows）
- **真实性**：✅ 真 bug。任务身份是 TV 版（tv · 2015），种子是单文件剧场版 `[FFF-Kantai] Hibike! Euphonium - Chikai no Finale [BD][1080p-FLAC].mkv`。整理形态只看任务身份（`packages/fushi_engine/lib/media/video/download/video_download_pipeline_service.dart` `_organizeDownload` 里 `mediaKind != movie` 一律 episodic）；organizer 只有「电影身份 + 多集包 → 剧集」一个方向的纠正（BUG-2760），反方向两趟都认不出集号就抛 `unable to determine episode number`（`packages/fushi_engine/lib/media/video/download/video_download_organizer.dart` `plan()`），下到 100% 的任务卡在 needsAttention。反馈里「系统播放器打不开」是 Windows 播放器不支持 MKV 内 FLAC 音轨（0x80004005），与 Fushi 无关。
- **[x] ① 已修复** — 与 BUG-2760 对称：剧集请求两趟都认不出集号、且除显式特典外只剩**一部**正片（并且是全种子最大的视频）时，organizer 改判为电影整理，作品名按文件本身取（`standaloneFeatureTitleOf`：只剥方括号发布标签，不走会把 ` - Chikai no Finale` 当集标题丢掉的文件名解析器）。管线随之把任务改成 movie、标题改成该名、清空年份 / 季号，并**整份清掉**剧集身份（`identity_json` / `metadata_provider` / `external_id`）：剧场版在 AniDB / MAL / TMDB 都是独立条目，留下任何一个 TV 版 id 都会让 scrape 阶段或库内补刮把它绑回 TV 版；刮削交给媒体库自动识别。不选「放进 Season 00 / Specials」：那要凭空编一个 S00E01，并把另一部作品挂到 TV 版身份下。多个无集号视频 / 只有特典 / 特典比唯一正片大时仍显式失败。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/download/video_download_organizer_test.dart`（group `a tv request holding a single standalone feature (9Fpg5zXriP)`：改判电影与目标路径、改判后以电影请求重放同路径、纯特典 / 特典更大仍失败、标题提取）；`fushi/test/media/video/download/video_download_pipeline_service_test.dart`（`a tv job holding a single standalone feature is reclassified to a movie ...`：端到端走到 completed，任务形态 / 标题 / 身份清空 / 入库标题）。
- **备注**：真机未复测（本轮不做）。
