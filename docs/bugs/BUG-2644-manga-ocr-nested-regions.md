## BUG-2644 · 漫画目录段落与内嵌行框重复识别和显示
- **报告**：2026-09-23（用户：Windows 本地 ONNX 漫画识别慢且不准）
- **真实性**：✅ 真 bug。真实漫画目录页 page_000003 的高分整段（0.669）与内部两条低分横行（0.329/0.319）同时输出，文字和识别耗时重复。`packages/fushi_engine/lib/ocr/text_detector.dart:280` 仅按 IoU 去重，段落与内部单行 IoU 低于 0.1，无法命中 0.7 的去重条件。
- **[x] ① 已修复** — 初版 `6b333442ac8` 在检测阶段按几何包含删除子框。PR #1626 审查发现父段 PP 振假名过滤可能同时漏掉小字号正文，因此最终改为识别后同时检查较高父框分数、横排几何包含与完整文本覆盖才删除重复结果。NMS 保留低 IoU 内框的独立识别机会，同分、竖排、部分相交、父框漏字或识别为空时均保留子块。
- **[x] ② 已加自动化测试** — `fushi/test/ocr/text_detector_test.dart` 保证低 IoU 包含框不提前消失；`manga_ocr_pipeline_test.dart` 与 `routing_ocr_recognizer_test.dart` 覆盖标题/小字正文组合回归、文本覆盖去重、单框/批处理与负向边界。
- **验证**：OCR 及相邻缓存/目录流程 236 项测试通过。使用 Windows 随包 ORT 1.22 DLL 的真实 Dart 管线，目录页从 5 块变 3 块，5 条目录及页码全部保留，重复子行消失；旧版 13628ms，新版两轮 7519/4947ms（有并发编译/用户应用负载，不视为空闲机基准）。整段原有的「裏方→里方」错字仍在，不能把去重等同逐字识别全对。
- **审查后的测量边界**：上面的真实页计时属于检测阶段去重的初版；最终方案会识别嵌套子框后再确认文本重复，不能沿用该计时宣称最终速度。最终回归证据见 `docs/reviews/2026-09-24-project-review.md`。
