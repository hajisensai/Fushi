## BUG-859 · 全局查词嵌套弹窗弹出位置不对
- **报告**：2026-07-16（用户：全局查词嵌套弹窗弹出位置不对，估计其他地方也有问题）
- **真实性**：✅ 真 bug（三层审计确认 4 处定位域缺陷 + 1 处面板语义缺陷，主根因如下）。
  1. **竖排级联错套嵌套卡（主根因，竖排书用户必现）** — `hibiki/lib/src/lookup/global_lookup_controller.dart:1106`（修复前）把「最近阅读器 writingMode 是竖排」喂给整条覆盖窗级联。但覆盖窗里有锚点的帧**全部**是弹窗卡片内的词（卡片内容恒横排），root 无锚点（光标定位）——`isVertical` 的唯一消费者恰是嵌套卡。in-app 参照语义 `hibiki/lib/src/pages/base_source_page.dart:957` `_layerVerticalWriting => index == 0 && …`（2026-06-08 起）明确嵌套层**永不**继承书的竖排。BUG-453（2026-06-28）以「与 app 内一致」为由接入 writingMode，前提当时就已不成立：竖排书用户每次点卡内词，子卡被放到词左/右且恒 maxHeight 高（`global_lookup_layout.dart:119` 竖排 height 恒 maxHeight），位置观感完全错。本修复废除该接线（级联恒横排），**取代 BUG-453**。
  2. **多显示器混缩放 dpr 域错配** — `global_lookup_controller.dart:536-541`（修复前）把 native 上报的光标显示器物理 px 工作区/原点偏移 ÷ **主窗口 dpr**；覆盖窗 WebView2 按**它自己所在显示器**的缩放光栅化（`global_lookup_window.cpp` windowed 分支不设 RasterizationScale，跟随显示器）。混缩放多屏时级联布局域整体错标度，嵌套卡错位且破坏 reserve-to-edge 防钳位不变量。修复：native showAt 应答新增 `monitorDpr`（`FlutterDesktopGetDpiForMonitor(monitor)/96`，`flutter_window.cpp`），Dart 优先用它换算（0 回退主窗口 dpr，行为同修复前）。
  3. **RevealStack 工作区钳位静默平移整层** — `global_lookup_window.cpp:464-467` 钳位可移动窗口原点，但 `commitLayerShift` 仍按**意图原点**的 bbox 下发 → 钳位触发时根卡+嵌套卡整体平移钳位差量（正常被 reserve-to-edge 地板掩盖为 no-op，但地板不变量恰被根因 2 破坏）。修复：钳位差量（÷ 本窗 dpr 转 CSS px）折进 commitLayerShift 实参。
  4. **beginLookup 影子偏移与 DOM 平移脱同步** — `hibiki/assets/popup/global_lookup_host.js:1179-1180`（修复前）新查词只重置 `layerOffsetLeft/Top` 变量，不重置 `layer.style.left/top`：上一轮向左/上级联的残留平移使 `shellCoveredByOrigin` 门失效，且绕过 commitLayerShift 的 reveal 路径（legacy Reveal / ready-safety 兜底）把新根卡按旧平移错位画出。修复：beginLookup 同步归零 layer DOM 平移。
  5. **（伴随）handleGlobalClick 缺 panel 守卫** — `global_lookup_host.js` 底层鼠标钩子转发的空白点击在 panel 模式仍会 `dismissPopupAt(0)`（常驻面板「空白点击永不关闭」语义被破坏；且 panel root 的 `100%`/`calc()` 尺寸在 `frameIdAtPoint` 里 parseFloat 成 100×0 盒，面板上任何点击都会误判为空白）。修复：panel 模式直接吞掉全局点击。
- **[x] ① 已修复** — ①级联恒横排：`global_lookup_controller.dart` `_renderStack` 移除 writingMode 接线；`global_lookup_render.dart` 删除 `isVerticalFromWritingMode` 与 payload `isVertical` 字段，`computeFrameRect` 恒 `isVertical: false`，anchorless fan-out 恒向下（纯函数 `computeFrameRect` 的竖排分支保留未动）。②`flutter_window.cpp` showAt 应答新增 `monitorDpr`；`overlay_window_channel.dart` 解析；controller 用 `workDpr = monitorDpr > 0 ? monitorDpr : 主窗dpr` 换算工作区域。③`global_lookup_window.cpp` RevealStack 把钳位差量折进 commitLayerShift。④⑤`global_lookup_host.js` beginLookup 归零 layer 平移；handleGlobalClick 加 panel 守卫。提交哈希：见 commit。
- **[x] ② 已加自动化测试** — `hibiki/test/lookup/global_lookup_popup_style_guard_test.dart` `group('BUG-859 …')`：controller 不读 writingMode / render 恒横排 / controller 用 monitor dpr 换算 / native 上报 monitorDpr / RevealStack 折算钳位差量（5 条源码守卫，翻转并取代原 TODO-938 组）；`overlay_window_channel_test.dart` 新增 monitorDpr 解析 + 旧回复回退 0 两用例；`global_lookup_host_test.mjs` 新增 B1（beginLookup 归零 layer DOM 平移）/ B2（panel 模式不因全局点击 dismiss）；`global_lookup_layout_test.dart` fan-out 源码守卫更新为横排-only。
- **备注**：仅 Windows 覆盖窗路径；剪贴板常驻面板控制器本就不传 isVertical，不受根因 1 影响。根因 3 的 C++ 行为无法单测，靠 `flutter build windows` 编译验证 + 源码守卫锁形。真机复测清单：竖排书开着 → 热键查词 → 点卡内词，子卡应出现在被点词正下/上方（不再左右+全高）；混缩放双屏在副屏查词复测嵌套位置。取代 BUG-453（其守卫测试已翻转）。
