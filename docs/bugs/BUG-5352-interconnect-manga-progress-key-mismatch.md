## BUG-5352 · interconnect-manga-progress-key-mismatch
- **报告**：2026-11-24（用户：应用内反馈 2bNEiehLgw）PC 当 host 时读到第 44 页，安卓经互联接过来的同一卷漫画总从第 1 页开始；统计页里同一卷有两个键（安卓 `interconnect-…`、PC `mihon-…`）。
- **真实性**：✅ 真 bug，两处根因叠在一起：
  1. **键对不上**：经互联收进本机的漫画行 bookKey 是 `InterconnectMangaCatalog.localBookKeyFor(对端键)` 推出的单向哈希（`fushi/lib/src/media/manga/interconnect/interconnect_manga_source.dart` `localBookKeyFor`），而互联书级进度的 live 读写直接拿本机 `book.bookKey` 去问 host（`fushi/lib/src/sync/interconnect_book_progress_sync.dart` 修复前 `remoteProgress` / `readRemoteForSweep` 的 `all[book.bookKey]` / `pushLocal` 与 `alignSynced` 的 `putLiveBookProgress(book.bookKey…)`）。host 只认对端键：GET 永远回空，PUT 判 missing，进度两个方向都过不去。删除墓碑那条路早已用 `peerBookKeyOf` 换算（`reader_fushi_source.dart` deleteBook），进度这条漏了。
  2. **落了书级那行阅读器也不看**：书架在线条目（互联单卷也是，唯一一章 key = 对端键）开章时起始页只认 `manga_chapter_states`（`fushi/lib/src/media/manga/reader/manga_fushi_page.dart` 书架开章路径 `getMangaChapterState` → `resolveMangaChapterResumePoint`），不读书级 `reader_positions`。只修键、只落 `reader_positions`，安卓照样从第 1 页开始。
- **[x] ① 已修复** — `InterconnectBookProgressSync.hostBookKeyOf`：互联单卷漫画行用描述符里的对端键读写 host（GET / 批量快照 / PUT 全部换算；位置基线是本机状态，仍按本机键）；落到本端时（`_upsertLocalIfUnchanged`）同步写那唯一一章的章级进度，阅读器开章就落到 host 的那一页。章节式互联漫画（`chaptered`）的 `reader_positions` 只装「当前章第几页」、不带章身份，两端当前章互不相干，拿它对齐会把 A 章页码落到 B 章，所以 sweep / 退出书同步 / 对比弹窗都把它排除（`syncsBookProgress`），不再发注定无效的请求。
- **[x] ② 已加自动化测试** — `fushi/test/sync/interconnect_manga_progress_key_test.dart`：真 `FushiSyncServer` + `LocalLibraryHostService` + 真 `InterconnectSyncBackend`，host 单卷漫画读到第 44 页 → client 书架行（`interconnect-…` 键）拉下来，`reader_positions` 与章级进度都是第 44 页；批量快照按对端键取到；client 往后读 → 推到 host 对端那一行；章节式行不参与、普通书 wire 键不变。
- **备注**：未尽事项——**章节式**互联漫画（host 端是 Mihon 等分章条目，反馈里 `mihon-…` 很可能就是这种）的章级进度（`manga_chapter_states`：每章页码 / 已读 / 继续阅读落点）目前没有任何互联同步通道，要新开 host 端点 + client sweep（按章 key LWW，两端章 key 逐字相同）。属于新协议 / 跨端「已读」行为变化，已登记拍板台待用户定。统计页两个键是统计按本机书键各记各的，与进度无关，不在本条范围。
