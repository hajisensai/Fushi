## BUG-2535 · 有声书章尾：最后一句匹配播完、下一句未匹配时不进入下一章
- **报告**：2026-09-14（用户：小说章尾需要优化——最后一句匹配上了、播完之后下一句没匹配上，也要进入下一章）
- **真实性**：✅ 真 bug。沿 `AudiobookPlayerController._updateCurrentCue` → `_maybeEmitCrossChapter` 复现：cue 推进到章尾之后那条**未匹配** cue（`textFragmentId == ''`，`SubtitleRematchCodec.tryDecode` 返回 null，常是下一章章名 / 无正文的过场）时，`packages/fushi_audio/lib/src/audiobook/audiobook_controller.dart:_maybeEmitCrossChapter` 的 `if (frag == null) return;` 无条件早退，没有任何「本章已读完」判断；文字要等到下一章第一条**匹配** cue 到来才跨章，期间用户听着下一章、屏幕停在上一章章尾。reader 侧 `fushi/lib/src/pages/implementations/reader_fushi/audiobook.part.dart:_handleCueCrossChapter` 还要求当前 cue 解得出学习单元锚（`studyOffset == null` 即取消），未匹配 cue 即使发了跨章也会被拦下。
- **[x] ① 已修复** — 本提交（自含修复+测试+本条目；并发抢号致哈希随 rebase 变动故不内联记录）：① 控制器新增按播放顺序（audioFileIndex → startMs）排的 `_playbackOrderedCues` 视图（`_chapterCues` 只按 startMs 排，多文件时各文件时间轴穿插、不能当播放邻居用）；② `_maybeEmitCrossChapter` 对未匹配 cue 改经纯判据 `unmatchedCueCrossChapterTargetForTesting`：上一条匹配 cue 属于当前章、之后再无本章匹配 cue（下一条匹配 cue 属于更晚的章或不存在）→ 目标 = 当前章 + 1；章中间一句没匹配上 / 上一条匹配 cue 不在当前章（用户手动翻走或已跨过去）/ 乱序数据 / 全书解不出 section（SRT、SMIL 路径）一律保位，与旧行为一致；目标再经既有 `shouldCrossChapterForTesting`（follow 开、已按过 play）门控。③ reader `_handleCueCrossChapter` 放行未匹配 cue（`unmatchedChapterEnd`）：没有字符锚就落目标章章首，目录页 / 越界照旧保位。
- **[x] ② 已加自动化测试** — `fushi/test/media/audiobook/unmatched_cue_chapter_end_cross_test.dart`：纯判据 10 条用例（章尾未匹配进下一章、全书末尾、章中间未匹配保位、连续多条未匹配只跨一次、手动翻走保位、开头未匹配段保位、乱序保位、reader 未就绪 / cue 不在表保位、SRT 路径恒保位、跨音频文件按播放序）+ 源码守卫（播放序视图、`if (frag == null) return;` 不得回退、reader 放行未匹配 cue）。
- **备注**：目标选「下一章」而不是「下一条匹配 cue 所在章」——中间若有整章没匹配上（图片章 / 后记），音频此刻读的是它，文字跟到它才同步，之后的匹配 cue 到来照旧再跨。落章首后章首插图的暂停 / 揭遮罩见 BUG-2536。未真机复测（无现成带章尾未匹配 cue 的对齐书），行为由纯判据单测 + 源码守卫锁定。
