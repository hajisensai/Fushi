## BUG-3229 · 汉字假名混写的惯用句（棚にあげる）查不到
- **报告**：2026-10-10（用户：「棚に上げる 这种惯用句查不出来」，并要求排查其它惯用句是否同类）
- **真实性**：✅ 真 bug。用真引擎（clang 编的 `fushidicts_ffi.dll`）+ 用户安装版的 61 本真词典逐条探针：
  - 原样表记「棚に上げる」与它的变形（棚に上げて / 棚に上げた / 棚に上げられる…）**能**查到（12 本词典有词条），引擎扫描、变形还原、排序与弹窗组装都不是问题。
  - **汉字 + 假名混写**「棚にあげる」「棚にあげて」只出「棚」。根因 `native/fushidicts/fushidicts_src/query.cpp` `DictionaryQuery::query_raw`：词典哈希索引只有**完整表记**与**完整读音**两种键（`expr != expression && reading != expression` 即跳过），混写串两种键都对不上；`lookup.cpp` 的候选 → 还原 → 查库链路里没有任何一步能把「あげる」对回「上げる」。
  - 同类排查（同一探针、同一批真词典）：手をやく / 足をあらう / 腹がたつ / 顔がひろい / 口をはさむ / 耳をかたむける / 気がおけない / 首をながくして / 猫の手もかりたい / 胸をはる / 油をうる / 水にながす / 足がでる / 気にいる / 目をさました / 顔をあらう / 口をあけた / 花がさいた / 子供がなく 共 22 例，修复前**全部**只查到开头的单字（或「花がさ」这种错切），说明是所有混写惯用句 / 复合词的通病，不是「棚に上げる」个例。原样表记写法的惯用句（目をつける、腹をくくる、猫をかぶる…）本就正常。
- **[x] ① 根因修复** — 引擎加一条「混写 → 读音」通路（`native/fushidicts/fushidicts_src/scan/mixed_orthography.{hpp,cpp}` + `lookup.cpp` 接线）：
  - 还原形同时含汉字和假名时，把每段汉字换成它单独查得到的读音（按词典列出次数排序、段多时每段少取，组合 ≤64），拼出候选**完整读音**查读音索引（bloom 过滤，未命中几乎零成本；每次查词内对汉字段读音与候选读音的查库结果做缓存）。
  - 查回的词条必须过 `matches_mixed_orthography`：词头里的假名逐字一致；**一段连续汉字要么整段原样、要么整段写成读音里对应的假名**（不许拆半——实测拆半会出「足がいた → 足掻く」「水を → 水脈」这类助词误命中）；查询里的汉字必须原样出现在词头里（「日が」不命中「僻」）。过了才经 `filter_by_pos` 并入结果。
  - `deinflected` 记查询里的混写形，排序比较器因此把混写命中排在同长度的表记精确命中之后。
  - 真词典 A/B（修复前 DLL vs 修复后 DLL，同一批 61 本词典）：上面 22 例全部命中正确词头且排第一（棚にあげる → 棚に上げる、子供がなく → 子供が泣く…）；21 条普通句子（今日は天気がいい、雨がふっている、水をのむ、足がいたい…）首条结果与修复前**逐条一致**；单次查词 2–10ms，未变慢。
- **[x] ② 自动化测试** — `native/fushidicts/tests/ja_mixed_orthography_lookup_test.cpp`（ctest，真 `ja.json` + 带词性的 Yomitan 词典跑真实 `Lookup`）：正向覆盖原形、て形 / た形还原、片假名写法、整段汉字词换写；反向覆盖查询汉字不在词头里、一段汉字拆半换写（足がいた / 水を）、假名与读音对不上（棚にあがる），并钉表记精确命中仍排第一。本机 clang + Ninja 跑全部 38 条 ctest 全绿。
- **备注**：Yomitan 同样只按表记 / 读音精确查，这条通路是有意超出上游的增强。已知不覆盖：汉字段单独查不到读音的串（罕见字、只在词组里出现的训读）、汉字段超过 3 段的长串；「たなに上げる」这种前段假名、后段汉字的写法仍靠词典是否收录该形。真 app 弹窗未单独复测（改动只在引擎查库层，弹窗 / 高亮长度消费的是同一个 `lookup` 结果）。
