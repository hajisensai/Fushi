## BUG-3875 · interconnect-lists-unstreamable-videos
- **报告**：2026-10-28（应用内反馈 `_xEjClqXTQ`，Android OnePlus：「无法加载该视频 网飞的」，截图《The Wild Robot》「视频加载失败 / 无法加载该视频。」）
- **真实性**：✅ 真 bug。日志连续 10 条 `VideoFushi.remoteEpisode` `SyncBackendError: Not found: GET /api/library/videos/video/stream/3944feb5541d/streamurl`：手机在电脑的互联媒体库里点开一本 Netflix 网页视频书。host 清单 `listVideos`（`packages/fushi_engine/lib/sync/local_library_host_service/videos.part.dart`）只滤掉了在线视频源与媒体服务器条目，网络流书（Netflix / YouTube 页、直链、rtsp）与 `.strm` 照常下发；而 `/streamurl` 靠 `resolveVideoFile` 找媒体文件，这类行恒 null → 404，对端只能显示泛化的「无法加载该视频」。
- **根因**：清单条目缺「对端能否经 host 播放」这一属性，展示层只能把 host 列出的每一条都当可播的远端占位卡。
- **首版修法的回归（已撤）**：首版（`15e7532630`）让 `listVideos` 直接不下发网络流书与 `.strm`。但这份清单同时是同步编排眼里「host 有哪些视频」的集合——`fushi/lib/src/sync/sync_orchestrator/videos.part.dart` 的 `_syncVideoProgressLive` 用它取交集（进度 / 播放偏好 sweep），首页 / 视频库页还用它做合集收养——于是两台机器都有的同一条网页视频 / `.strm`，进度、调轴等播放偏好、合集归属静默停止同步。「可不可以远程播放」是展示 / 播放层的属性，「host 有哪些条目」是同步层的事实，两者不能共用一份被过滤过的清单。
- **[x] ① 已修复** — `RemoteVideoInfo` 新增 `peerPlayable`（wire 键 `peerPlayable`，只在 false 时写出；缺省 true）。host `listVideos` 恢复只滤在线源 / 媒体服务器，网络流书与 `.strm` 照常列出但标 `peerPlayable: false`（`_hostServesVideoBytes`）。展示 / 播放层经 `peerPlayableRemoteVideos` 过滤：视频库页远端占位卡与合集详情成员（`home_video_page.dart`）、首页继续观看（`home_dashboard_page.dart`）、卡片来源跳转（`card_source_router.dart` 的 `findRemoteVideoForCardSource`）；同步 sweep 与合集收养仍读整份清单。wire 兼容：新 host + 旧 client → 旧 client 不认识该键，按首版之前的行为照常列出（点开仍是 404，与修复前相同，同步不受影响）；旧 host + 新 client → 无该键按可播处理，与改动前逐字节同行为。
- **[x] ② 已加自动化测试** — `fushi/test/sync/fushi_library_host_service_video_test.dart`「网络流书（Netflix 页 / 直链 / 频道）与 .strm 照常列出但标 peerPlayable=false」+「RemoteVideoInfo.peerPlayable wire 兼容」组；`fushi/test/sync/sync_orchestrator_live_progress_test.dart`「BUG-3875: 网络流书 / .strm 两端都有时进度与偏好仍同步」（真实 server + host + client，经 wire 断言清单带标志、host 较新的进度 / 调轴回灌本地、本地较新的调轴推到 host）；`fushi/test/anki/card_source_remote_video_test.dart` 不可播条目不当卡片来源。
- **备注**：Netflix 本身只能在 Windows 的网页播放器里播，手机上本来就放不了。进度推回 host 的缺口（修复前就存在）已一并修：`/api/library/videos/<id>/position` 端点原用 `resolveVideoFile` 当存在性闸门（`packages/fushi_engine/lib/sync/fushi_sync_server/video.part.dart` position 分支），网络流书 / `.strm` 行恒 404，进度只能 host→client 拉、client→host 推必失败（host 网络盘掉线时本地文件行同样被误拒）。现改与 `/playback` 同口径只认 DB：`videoExists(id, episodeIndex:)`（行存在 + 集下标落在 `playlistJson` 内），不要求媒体字节。测试 `sync_orchestrator_live_progress_test.dart`「本地较新的进度推回 host（网络流书 / .strm，report 无错误）」「/position 闸门：未知 id 与越界集下标仍 404，界内集下标可写」。
