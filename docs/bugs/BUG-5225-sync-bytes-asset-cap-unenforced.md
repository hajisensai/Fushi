## BUG-5225 · 同步字节资产 256 MiB 读取上限在 OneDrive / Dropbox / SFTP / FTP / 本机目录上没生效
- **报告**：2026-11-22（第三方审查 HBK-AUDIT-223，[#4133](https://github.com/hajisensai/Fushi/pull/4133) 引入）
- **真实性**：✅ 真 bug。`packages/fushi_engine/lib/sync/sync_asset_store.dart:105` 的 `getBytesAsset` 约定超过 `kSyncBytesAssetMaxBytes`（256 MiB）就抛错，防坏 / 恶意远端把进程撑爆；但 `fushi/lib/src/sync/onedrive_sync_backend.dart:515`（`.bodyBytes` 整份收）、`dropbox_sync_backend.dart:635`（同）、`sftp_sync_backend.dart:697`（`handle.readBytes()` 按 stat 大小整份收）、`ftp_sync_backend.dart:866`（临时文件 `readAsBytes()`）、`packages/fushi_engine/lib/sync/local_directory_asset_store.dart:119`（`readAsBytes()`）都直接整份读进内存。SFTP 另把任何 `SyncBackendError` 映射成 null，上限错误即便有也会被当成「不存在」。
- **[x] ① 已修复** — 上限计数只写一次：`sync_asset_store.dart` 新增 `readSyncAssetBytesCapped`（声明长度已超就不收；逐块计数，超了抛 `SyncAssetTooLarge` 并取消上游）。HTTP 后端经 `sync_http.dart` 的 `downloadSyncAssetBytesCapped` 流式收（看 `Content-Length` + 计数）；SFTP 先 `stat` 再按大小流式读；FTP 先 `SIZE` 预检、读临时文件时计数；本机目录先看长度再流式读。SFTP 的 `_guarded`、FTP 的错误翻译原样放行 `SyncAssetTooLarge`，不包成可重试传输错误、不吞成 null。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/sync/sync_asset_bytes_cap_test.dart`（计数器：上限内整份、超限即取消上游、声明超限不订阅、声明撒谎照拒；本机目录超限文件抛错）；`fushi/test/sync/sync_asset_bytes_cap_backends_test.dart`（OneDrive / Dropbox 声明超限不订阅响应体、SFTP 超限零读字节且抛错而非 null）。
- **备注**：FTP 没有可注入的客户端，未单独加后端级测试，走的是同一个计数器。OneDrive / Dropbox 的 `getJsonAsset` 仍整份收（不在本条契约内）。
