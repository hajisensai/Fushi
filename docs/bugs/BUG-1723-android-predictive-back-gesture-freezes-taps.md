## BUG-1723 · 安卓侧滑返回后全屏点击失效
- **报告**：2026-08-18（用户：群反馈）安卓平板，设置 → 外观 → 语言（次级页面）返回后「点击任意处都无反应」；竖屏下进设置任意次级页面再返回同样复现。用户补充的关键分型：**点左上角返回箭头不复现，侧滑（手势）返回才复现**。
- **真实性**：✅ 真 bug。根因在 Flutter 3.44 预测性返回（predictive back）的手势记账：`TransitionRoute.handleStartBackGesture` → `NavigatorState.didStartUserGesture()`（`flutter/lib/src/widgets/routes.dart:566`）与 `_handleDragEnd` 里的 `didStopUserGesture()`（同文件 `:594-622`）是一对**无状态机保护**的全局计数增减；计数一旦失配卡在 >0，`_ModalScope` 会把**每一层路由**都 `IgnorePointer` 掉、并把 `focusScopeNode.canRequestFocus` 置假（`routes.dart:1154-1157` 的 `_shouldIgnoreFocusRequest`，消费点 `:1215-1222`）。表现正是「画面完全正常、动画照跑，但点哪都没反应」，只能杀进程。点返回箭头走 `Navigator.pop`，完全不碰这条链，故不复现。
  - 为什么是平板竖屏：设置页宽窄判据读的是界面缩放后的画布宽（`fushi/lib/src/settings/settings_home_page.dart:86` 的 `>= 720`），800dp 平板竖屏经移动端自动缩放（上限 1.12，`fushi/lib/src/utils/app_ui_scale.dart:64-76`）后 ≈714 → 落进窄分支，点分类才 push 次级页面；横屏是左右主从、不 push，所以只有竖屏才走得到这条路径。
  - 三条会让计数失配的平台事件序列（`fushi/test/utils/adaptive/predictive_back_gesture_accounting_test.dart` 全部固化为用例，也用它们实测过自带实现必挂）：① 平台对同一次手势**重发起始事件**（start→start→commit）→ 加两次减一次，永久 >0；② **手势进行中路由被程序化 pop** → 框架把那次减法挂在路由动画的 status listener 上，路由随即销毁、`AnimationController` 一并 dispose，回调永不触发 → 永久 >0；③ **commit 之后重发 cancel** → 二次减法，debug 踩 `assert(_userGesturesInProgress > 0)`（`navigator.dart:5849`），release 静默变负、此后一次合法手势被整段吞掉。三者都由 Android 平台层发出，序列在不同 OEM / 手势识别路径上并不保证配对，app 侧无法约束。
- **[x] ① 根因修复** — 不再让平台事件直接驱动全局手势计数，先过一个显式状态机：新增 `fushi/lib/src/utils/adaptive/predictive_back_page_transitions.dart` 的 `FushiPredictiveBackPageTransitionsBuilder`——一次手势只认一次开始（重复起始事件只接进度、不再计一次）、一次结束（未持有手势时的 commit/cancel 直接丢弃），并在 detector `dispose` 时对「手势中途路由被销毁」补齐那次结束（延到帧末 + `ensureVisualUpdate`，因为 element unmount 期树是锁定的，直接调用会踩 markNeedsBuild）。在 `fushi/lib/src/models/theme_notifier.dart:964` 的 `_buildThemeData` 里把 Android 转场换成它，其余五个平台逐个显式列出（`PageTransitionsTheme.builders` 是全量替换而非合并，漏平台会静默回落 `ZoomPageTransitionsBuilder`，iOS/macOS 会因此丢掉 Cupertino 边缘滑动返回）。首页设置 tab 的返回拦截语义不变：栈底路由 `popGestureEnabled` 为假时本 detector 不接管，事件回落框架普通 pop 路径，仍由 `PopScope(canPop:false)` 消费并切回来源 tab（BUG-236）。观感代价：手势期间仍随进度跟手，但转场从 Android 16 的 shared-element 退化为公开的 `FadeForwardsPageTransitionsBuilder`（自带实现的 shared-element 转场是私有类，复用不了）。提交：本修复提交。
- **[x] ② 加自动化测试** — `fushi/test/utils/adaptive/predictive_back_gesture_accounting_test.dart`（5 例：正常侧滑返回真的 pop 且计数归零、界面仍可点；上述三条失配序列各一例，断言计数恒回零且首页按钮仍能点开子页；栈底 + `PopScope(canPop:false)` 侧滑仍走拦截回调）。`fushi/test/models/theme_page_transitions_guard_test.dart`（2 例：Android 必须用 `FushiPredictiveBackPageTransitionsBuilder`；六个平台必须全部显式配置且 iOS/macOS 仍是 Cupertino 转场）。**变异实测**：分别去掉「重复起始事件的幂等分支」「dispose 兜底释放」「多余 commit/cancel 的丢弃」，三次各自只打红对应那一条用例、其余保持绿，还原后源文件 sha256 与变异前逐字节一致（`4e6011ab00694a9b568a46d3be94f36d5ae08cb93c4d1dfa58b458eeeaed91c9`）。
- **备注**：这是对上游缺陷的兼容层，清理条件写在实现文件类注释里——Flutter 把这三条序列的配对修进 `TransitionRoute`（自带幂等 + dispose 兜底）之后，本文件可整体删除、`pageTransitionsTheme` 不再指定 Android builder 即恢复自带观感。验证口径：`dart analyze` / `flutter analyze` 均无 issue；`dart run tool/flutter_test_failures.dart --no-pub test/utils/adaptive/ test/models/ test/settings/ test/pages/home_settings_back_intercept_test.dart test/pages/home_settings_exit_sync_warning_test.dart` 全绿（22 + 937 条）。**未做真机复测**：用户叫停了模拟器复现，这条修复的证据全部来自在真实平台 channel（`SystemChannels.backGesture`）上驱动 framework 状态机的 widget 测试，安卓平板上的原始失败路径待用户实机回归。
