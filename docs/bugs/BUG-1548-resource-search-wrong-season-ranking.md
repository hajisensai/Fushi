## BUG-1548 · 资源搜索结果错季混排：结果只按 seeders 排序，无标题/季号相关度
- **报告**：2026-08-11（用户截图：下载-资源搜索 `Hibike! Euphonium 2`，返回结果混着 S3、S1、剧场版、Ensemble Contest OVA，「感觉出现了好多不对劲的玩意」）
- **真实性**：✅ 真 bug。三处叠加：
  1. **查询词只是子串**：`fushi/lib/src/media/torrent/nyaa_resource_provider.dart:106-138` 把季号原样跟在标题串里发给 Nyaa（`nyaa_client.dart:420` → `?page=rss&q=<query>&c=1_0&f=0`，无排序参数），Nyaa 只做站内模糊词匹配，S1/S3/剧场版/OVA 天然全中。
  2. **季号从不传**：`video_discovery_acquisition_dialogs.dart:558-576` 构造 `VideoResourceSearchRequest` 时 `season`/`episode` 永远为 null，`VideoMediaReference.season` 在发现链路也从不赋值（`video_discovery_provider.dart:141`），于是 Torznab 的 `season=` 参数（`torznab_client.dart:614-624`）恒不生效。
  3. **根因——唯一排序没有相关度**：`fushi/lib/src/media/torrent/video_resource_provider.dart:112-115` 的 `deduplicateVideoResources` 排序 = `providerPriority` 升序 → `seeders` 降序，**零标题匹配度、零季号校验**；Nyaa 源内 priority 同值（`nyaa_resource_provider.dart:12`）⇒ 实际就是纯做种数降序，老季种子做种多必然压在正确季前面。UI（`video_discovery_acquisition_dialogs.dart:946-1004`）按 `result.items` 原序渲染，自己不排不筛。
  仓库里 `NyaaTorrent.season`（`nyaa_client.dart:125`）、`jimakuEntrySeasonConflicts`（`anime_download_matching.dart:447`）、`MatchScorer` 的季度加罚（`match_scorer.dart:141-165`）三套现成能力，没有一套接进资源搜索链路。
- **[x] ① 已修复** — 新增 `fushi/lib/src/media/torrent/video_resource_relevance.dart`：`parseVideoResourceIdentity(String)` 复用刮削侧同一套识别件解出「基础标题集合 + 季号」，季号三级取值 —— `FilenameParser.parse().season`（位置化，认 `S3` / `第三季` / `2nd Season`）→ `MatchScorer.detectSeasonsInText()`（归一化后全串扫描，补上被当噪音丢掉的括号块 `(Season 3)` / `[S3]`）→ 并列标题一致的裸尾数（番剧的 `Title 2` 写法，`FilenameParser` **有意**保留在标题里不能动）。后两级都只在唯一时才认，避免「S1+S2 合集」被随便挑一个。
  `rankVideoResourcesByRelevance()` 在 `VideoResourceRegistry.search()` 去重之后重排：季号契合度（正是这一季 2 / 该条没写季号 1 / 明确是别的季 0）→ 标题贴合度（`TitleNormalizer.similarity` 取最大）→ 同档保持上游次序（providerPriority → seeders，稳定排序）。**只重排不丢弃**：Nyaa 命名太脏，过滤会误伤合集/特典。
  为避免抄第二份季号正则，把 `MatchScorer._detectSeasonsInText` 提升为公开的 `detectSeasonsInText`（唯一内部调用点同步改名，行为不变）。`deduplicateVideoResources` 本身没动，订阅链路（`nyaa_resource_provider.dart:76`、`torznab_client.dart:482`）行为不变。
- **[x] ② 已加自动化测试** — `fushi/test/torrent/video_resource_relevance_test.dart`（8 条）：身份解析 4 条（裸尾数当季号并剥出基础标题、`S3`/`Season 3`/裸数字三种写法读出同一季号、并列中日英标题、无季号标记必须是 null 不能当第一季）；排序 4 条，其中主用例**照抄用户截图的 6 条真实标题与做种数**（错季的做种数刻意更高），断言第 2 季的两条冒到最前、S3 的三条落到最后、一条都不少；另有「季号未知不被惩罚到错季之下」「调用方显式给季号时以它为准」「查询词不带季号时保持上游次序」。`flutter test test/media/video/metadata test/torrent test/media/video/scraper --no-pub` → 689 passed（含原有 `provider_dedup_test.dart`）。
- **备注**：与 BUG-1547 同一「moviepilot 式识别 / 刮削分离」方向：识别件（`FilenameParser` + `TitleNormalizer` + `MatchScorer`）现在同时服务刮削链路与资源搜索排序。仍未做的：查询词本身没有做季号变体扩展（不给 Nyaa 发 `S2` / `第2期` 等别写法），也没把 `season` 从 UI 传进 `VideoResourceSearchRequest`——两者都属于「让服务端少返垃圾」，本次只治「返回来的排对」。
