## BUG-2201 · 待确认身份的作品在视频页零提示用户无从知道要去确认
- **报告**：2026-09-07（用户：「匹配结果存在歧义，需要人工确认 每次打开视频页的时候提醒一下吧」）
- **真实性**：✅ 真 bug。刮不出规范身份**没有任何可见症状**：封面照样有（`documents/video_covers/*.jpg` 抽帧兜底那张）、卡片照样进库、下载任务显示「已完成」、`last_error` 为空，用户只会觉得「封面怎么是视频截图」。待确认队列此前唯一的出口是刮削任务面板里的一段 section（`fushi/lib/src/media/video/metadata/video_source_scrape_dialog.dart:169-183`），要先知道它存在才点得到；视频页页头那个 Badge（`home_video_page.dart:5209-5220`）只反映 `scrapeTaskController.isBusy`，不反映待确认数量。生产库实证：最近 7 次 sweep 全是 `succeeded_works=0 / pending_confirmations=2`、警告「匹配结果存在歧义，需要人工确认」，全堆着没人点。
- **[x] ① 已修复** — 视频页顶部常驻待确认提醒条：`home_video_page.dart` 的 `_buildPendingScrapeBanner()`，插在 `SyncProgressBanner` 之后、正文 `Expanded` 之前（页面顶层 `Column` 里唯一不受 `section` 门控、且不随列表滚走的插槽），数量为 0 时 `SizedBox.shrink()` 零高度。数据来自新端口 `loadPendingScrapeWorks`（`home_page.dart` → `video_library_shell.dart` → `home_video_page.dart`，与既有 `onOpenScrapeTasks` 同形），实现是 `VideoLibraryScrapeSweep.sweepAndListPending()`——一个端口两件事是有意的：提醒和补刮读的是同一份「哪些作品还没刮出规范身份」，拆两个端口就要查两遍全库。重算时机：进页面 / 切回页面 / 库里多出条目 / 刮削结果落库（`watchVideoScrapePresentationChanged` 监听的正是 `videoMetadataWorks` + `videoMetadataProviderIdentities` 两张表，确认完数字当场掉下去）。点提醒条上的按钮直接走既有 `onOpenScrapeTasks` 进待确认队列。新增 i18n `video_library_scrape_pending_banner` / `_action`（17 语言经 `i18n_sync` 补齐）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/home_video_pending_scrape_banner_test.dart` 四条：有作品没身份时提醒条常驻且按钮能进确认队列、全部有身份时零高度、端口未接线时不显示、库里多出条目就地重算（BUG-2199 的 UI 侧接线，已变异实测）。用例走真链路（真 db → `VideoSourceWorkPlanner` → 待确认判据 → 提醒条），不是对着假数据断言。
- **备注**：与 [[BUG-2199]] 同批。提醒条按用户要求**每次进视频页都显示**、不提供「不再提醒」——它反映的是一个仍未处理的真实待办，清空队列即自然消失。
