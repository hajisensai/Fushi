## BUG-5114 · local-audio-identity-ignores-recordings
- **报告**：2026-11-22（外部审计 HBK-AUDIT-001，2026-11-21 Codex PR 审查，来源 PR #3968）
- **真实性**：✅ 真 bug。本地音频库内容身份 `la1` 只哈希 `entries` 元数据与 `android` 行数，不读音频 BLOB（`packages/fushi_engine/lib/models/local_audio_content_id.dart:73,95` @ cbdc2a45ed）。两份录音不同、元数据与条数相同的库身份相同，于是：服务端启动整理 `LocalAudioLibraryStore.normalizeContentIdentities`（`local_audio_library_store.dart:151`）把后一份当重复、删内部副本；app `normalizeLocalAudioLibraries` 收掉其登记并经孤儿回收删文件；`importPackage` / `importSyncedLocalAudioDb` / 同步 union 把另一份当「已有」跳过。复现：新测试「元数据与条数相同、录音不同 → 身份不同」在旧算法下两库身份相等（变异实测见下）。
- **[x] ① 已修复** — 身份换成 `la2`：`entries` 按全列排序、`android` 先把 (source, file, rowid) 小键排进 TEMP 表，再经一条 rowid 连接查询顺序取 (source, file, data)，每个值带类型 + 长度前缀，喂给 native/fushi_compute 的流式 SHA-256（1 MiB 原生缓冲区满了才跨一次 FFI）。前缀换成 `la2-`、旧 `la1-` 不再被认作身份：已存的旧身份由启动回填 / 服务端整理自动重算；互联能力位改名 `localAudioContentIdV2`，只发 la1 的旧 host 会按「对端版本过旧」报出，而不是静默按名匹配。耗时（本机真实 1.26 GB 库，Dart JIT）：la1 0.15–0.5 s，la2 首版逐行回 Dart 取数 31 s → 改 TEMP 表连接 + 类型化拷贝后 1.9–2.0 s；身份算一次就存进登记，之后不再扫。
- **[x] ② 已加自动化测试** — `fushi/test/sync/local_audio_content_identity_test.dart`（录音不同身份不同；超 1 MiB 录音跨多次 FFI 稳定且与行序无关；服务端整理保留两份、不删文件；推来的同元数据不同录音另起名登记）、`fushi/test/models/app_model_synced_local_audio_test.dart`（app 启动整理保留两份；同步拉到的同元数据不同录音登记）、`packages/fushi_server/test/local_audio_host_test.dart`（两份同元数据不同录音的真库身份不同）。
- **备注**：同键（source, file 完全相同）的重复行按 rowid 定序，顺序不同只会多留一份、不会误删。真机未验。
