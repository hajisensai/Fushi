## BUG-689 · 桌面剪贴板自动查词跨窗口尺寸断点后失效
- **报告**：2026-07-10（用户：小窗没法自动查、恢复大窗才能查、缩回有概率又行）
- **真实性**：✅ 真 bug（监听生命周期竞态）。根因 `hibiki/lib/src/sync/desktop_lookup_service.dart:68`（原 `bool _running`）。`DesktopLookupService` 是 app 级单例（clipboard_watcher + Ctrl+Shift+D 热键），但 `start()`/`stop()` 只由 `HomeDictionaryPage` 的 mount/dispose 调用（`home_dictionary_page.dart:112` initState→`_startDesktopLookupIfEnabled`→`start`；`:225` dispose→`stop`）。窗口物理宽跨 600px 断点时（`home_page.dart:632-635`，`windowSizeClassReal` compact↔medium 在 `_buildMobileLayout` 底栏 Scaffold ↔ `_buildDesktopLayout` Row+侧栏 Scaffold 间切换，`buildBody` 是 `switch` 非 IndexedStack，`:828`），`HomeDictionaryPage` 祖先链变、类型不可 reconcile → 被 dispose+重建。Flutter 先挂新元素（initState→`start`）、帧末才卸旧元素（dispose→`stop`）：新页 `start()` 在 `:155 if (_running)` 处因旧页未 dispose、`_running` 仍 true 而**短路 no-op**（不重挂 `clipboardWatcher.addListener`）；随后旧页 `stop()`（`:176-179`）执行 `_running=false`+`removeListener`+`clipboardWatcher.stop()` → 净结果 watcher 被停、监听器被摘、`_running=false`，新页虽挂了 pending 消费回调但底层 OS watcher 已死 → 静默不查。「缩回有概率又行」= start/stop 均 `unawaited` 异步穿插、单例只有裸 `bool _running` 无并发 owner 计数 → 非确定性。
- **[x] ① 已修复** — 把裸 `bool _running` 换成**引用计数** `int _startRefCount`（`desktop_lookup_service.dart`），正确建模「N 个并发持有者」：`start()` 计数 +1（只有 0→1 才真正挂 watcher+热键，>1 只重配窗口模式、绝不重挂监听）；`stop()` 计数 -1（只有 1→0 才真正拆，>0 早退、计数已 0 钳制成 no-op 防下溢）。断点期计数 1→2→1 恒 >0，OS watcher 始终存活；计数自增/分支判定都在首个 `await` 之前同步完成，故与 start/stop 的 `unawaited` 异步穿插无关、结果确定。**未解耦到 app 级 owner**（那样会破坏 i18n 文案对用户的明确承诺「仅在查词界面监听剪贴板和全局热键」，`desktop_clipboard_window_mode_hint`）——引用计数既根因修复竞态、又保留「仅查词 tab 期间监听」的既定契约与所有既有守卫（`desktop_lookup_to_dictionary_tab_test.dart` 页面仍是 owner）。页面/设置/AppModel 零改动。分支 `todo1385-clipboard-watcher`，提交 `14d50243c`。
- **[x] ② 已加自动化测试** — `hibiki/test/pages/home_dictionary_clipboard_watcher_breakpoint_test.dart`：① 引用计数单元语义（首个 owner 0→1 真启 OS watcher；双 start 后单 stop 仍 `isRunning` 且 OS watcher 未 `stop`；1→0 才真拆；计数已 0 再 stop 钳制 no-op）；② **行为守卫**：真 `HomeDictionaryPage` 从底栏 Scaffold 布局切到 Row+Expanded 侧栏布局（强制 dispose+重建，复现 600px 断点），断言重建后 `svc.isRunning` 仍 true、clipboard_watcher 通道**无** `stop` 调用，且模拟外部复制日文经 `onClipboardChanged` 仍驱动重建后页面自动查词（`searchedTerms` 命中）。修前（裸 bool）断点后 `isRunning=false`+通道 `stop`，测试红。
- **备注**：✅ Windows 桌面离屏真机验收已过（`tool/run_windows_itest.ps1 integration_test/clipboard_lookup_breakpoint_itest.dart`，evidence `.codex-test/windows-itest/win-itest-20260710-114645-27cd1561/`）：真 Windows 引擎构建 `hibiki.exe`，真 app 开 desktopClipboardEnabled→词典 tab→经真 `home_page` 把窗口拖到 <600 再拖回 ≥600（两次跨断点、真 `HomeDictionaryPage` dispose+重建）→断言 `DesktopLookupService.isRunning` 仍 true，`All tests passed!`（exit 0）。为不打断用户未在离屏用例里写系统剪贴板，端到端剪贴板→查词由 widget 守卫覆盖。桌面剪贴板/热键查词是桌面专属（`DesktopLookupService.isDesktop` 门控），移动端无此 watcher、不受影响。
