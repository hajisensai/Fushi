## BUG-4004 · 安卓应用内浏览器看油管时找不到换字幕的 Fushi 播放器按钮
- **报告**：2026-11-03（应用内反馈 Mb6qKIhwEm，Android 平板 HUAWEI DBY-W09，app 3.3.0-debug.23213；截图是 Fushi 应用内浏览器开 `m.youtube.com/watch`）
- **真实性**：✅ 真 bug。桌面 `www.youtube.com` 上 Fushi 按钮插进 `.ytp-right-controls`（`tools/browser-extension/player-controls.js` `controlAnchor`），菜单里有「选字幕轨」子页；`m.youtube.com` 的 plasma 播放器根本没有这个控制栏（实测下载 `player-plasma-es6-*.vflset/base.js`：`ytp-right-controls` 出现 0 次，只有 `html5-video-container`），于是退回通用悬浮按钮。悬浮按钮默认 `opacity:0; pointer-events:none`，只在 `data-visible="1"` 时出现（`vendor/content.css` `#fushi-player-btn.is-floating`），而显隐判据是 DOM 包含——旧 `player-controls.js` 的 `pointerover` 处理器（修复前约 1176 行）要求事件目标是 `<video>` 本身或 `video.parentNode` 的后代。plasma 播放器的 `<video>` 独占 `.html5-video-container`，触控 / 控件层全是容器的**兄弟**，手指永远点不到「容器里」，`hoverVideo` 永远为假，按钮在安卓上永远隐身——用户只能看到字幕却找不到换轨入口。同一缺陷也落在任何「控件层盖在 video 父容器之外」的通用站点（桌面鼠标同样不出按钮）。
- **[x] ① 已修复** — 显隐判据改成几何：指针视口坐标落在正片矩形内（`pointInVideo`，`player-controls.js:251`）或落在按钮本身即显示；`pointerover` + `pointermove`（capture，passive）共用 `onPointer`（`player-controls.js:1191`），同层控件里移动也能判；触屏 `pointerover` 在按下时带坐标触发，点画面即出、点画面外即淡出。不依赖任何站点 DOM。提交见下。
- **[x] ② 已加自动化测试** — `tools/browser-extension/player-controls.test.js`：「悬浮按钮：指针落在画面上就出现——盖在 <video> 上的控件层也算」（m.youtube.com 结构：video 在 `.html5-video-container`、控件层是兄弟；旧判据实测红：`点到画面上的控件层：按钮出现` 断言失败）+「pointInVideo：只认画面矩形内的有限坐标」。
- **备注**：未在真机 / 模拟器上肉眼复测 m.youtube.com（本轮无设备）；按钮出现后菜单与桌面同一份（选字幕轨 / 偏移 / 外观）。
