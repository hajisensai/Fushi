## BUG-4078 · 歌词覆盖层 ⋯ 菜单的 -10s / +10s 与播放器上的 ±10 键重复
- **报告**：2026-11-04（应用内反馈 MnVAGO_nry，Android，有声书歌词模式截图）
- **真实性**：✅ 真 bug。覆盖层 ⋯ 菜单由 `_showLyricsMoreMenu`（`fushi/lib/src/pages/implementations/reader_fushi/lyrics.part.dart`，修前 `:874`）把 `kLyricsOverlayMenuItems`（修前 `:128-138`）原样追加进来，表里含 `audiobookSeekBack` / `audiobookSeekForward`；注释说「不含三颗传输键（覆盖层自己有播放控件）」，但新版 MD3 / Apple 展开卡与宽屏中岛、经典 MD3 都在屏上摆着 ±10 键（`lyrics_player_md3_modern.part.dart` `_modernTransportButtons`、`lyrics_player_apple_modern.part.dart` `_appleModernTransport`、`lyrics_player_md3.dart` `_TransportGroup` / 进度条两侧）。另一面，经典 Apple 布局与新版窄屏收起的迷你条（`relativeSeek: false`）屏上没有 ±10 键，直接删菜单项会让这些形态在触屏上失去入口——菜单需要知道「按下 ⋯ 的那套布局此刻有没有 ±10 键」，而 `LyricsMenuAnchor` 修前不带这条信息。
- **[x] ① 已修复** — `LyricsMenuAnchor` 新增 `relativeSeekOnScreen`（`lyrics_player_contract.dart`），由每颗 ⋯ 按它所在形态如实填写：MD3 工具条 / 新版宽屏中岛 = 给了 `onSeekRelative` 即 true；经典 Apple = false；Apple 新版窄屏页眉 ⋯ = 卡片展开且有回调。页面改用 `lyricsOverlayMenuItems(relativeSeekOnScreen:)`（`lyrics.part.dart`）在 true 时去掉两项。提交 `65fd9bd59d`。
- **[x] ② 已加自动化测试** — `fushi/test/media/audiobook/lyrics_more_menu_relative_seek_test.dart`：纯函数去重；MD3 / Apple × 新版 / 经典 × 窄 / 宽 × 收起 / 展开全组合按 ⋯，断言锚点的 `relativeSeekOnScreen` 等于屏上 ±10 键是否可点；反馈现场（MD3 新版窄屏展开卡）为 true，Apple 迷你条 / 经典 Apple 为 false。
- **备注**：未在真机复测（本轮只做 widget 测试）。
