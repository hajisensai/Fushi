## BUG-430 · Windows IME 激活时全表面快捷键失效
- **报告**：2026-06-26（用户：）
- **真实性**：✅ 真 bug。**根因在平台边界，不在快捷键解析层**（2026-11-05 本机真 Windows app 真机取证定案）：Flutter 的 Windows view（`FLUTTERVIEW` 子窗口）在没有文本框聚焦时仍关联着 IME input context，输入法于是按自己的状态吃键，以 `WM_KEYDOWN wParam=VK_PROCESSKEY(0xE5)` 投递；Flutter 嵌入层对 `VK_PROCESSKEY` 直接 `callback(true); return;`（`D:/flutter_sdk/flutter_3.47.6/engine/src/flutter/shell/platform/windows/keyboard_key_embedder_handler.cc:177-183`），Dart 侧一个 KeyEvent 都收不到。修复点是 `fushi/windows/runner/ime_association_guard.cpp:5-14`（`ApplyImeAssociation`，`ImmAssociateContextEx`）+ `fushi/lib/src/platform/windows_ime_guard.dart`（无可编辑焦点时解除关联），即 BUG-1450（`7a99dbf2ee6`，PR #761）已合入的那套；本条此前三轮以 `logicalKey == LogicalKeyboardKey.process` 为入口的「修复」全是死代码（`process` 是 Flutter Web 专有值，原生端不可达，守卫 `fushi/test/shortcuts/ime_process_key_reachability_guard_test.dart`）。
  - **真机证据**（2026-11-05，Release 构建带 `FUSHI_TEST_ROOT=D:\hibiki-dev-data`，`FUSHI_TEST_HIDDEN` 离屏实例；临时诊断在 runner 消息循环记 `WM_KEYDOWN` 的 wParam / scan / `ImmGetContext`，Dart 侧 `HardwareKeyboard` 记 KeyEvent 与 `resolveKeyboard` 命中；`SendInput` 发真实按键，`WM_INPUTLANGCHANGEREQUEST` + `WM_IME_CONTROL` 切输入法，测完还原 0x08040804 / open=1 / conv=1025 与前台窗口。诊断代码未入库）：
    | 场景 | 关联（himc） | 按键序列 → `WM_KEYDOWN` wParam | Flutter 侧 |
    |---|---|---|---|
    | 微软拼音中文态，无守卫 | 1 | Space 0x20、Ctrl+1 0x31、Ctrl+2 0x32、PageDown 0x22、**M 0xE5、A 0xE5、Esc 0xE5** | 前四个正常到达并命中 `homeTabBooks` / `homeTabDict`；M 之后全无事件 |
    | 微软拼音，无守卫，先按 M 起组字 | 1 | **M、Space、M、Ctrl、Ctrl+1、PageDown、Esc 全 0xE5**；Esc 取消组字后 Ctrl+2 恢复 0x32 | 组字期间零事件，Ctrl+1 丢失 |
    | MS-IME 日文平假名态（conv=0x19），无守卫 | 1 | **Space 0xE5**；Ctrl+1 0x31、PageDown 0x22 正常；**M 起组字后 Space / Ctrl / Ctrl+1 / PageDown / Esc×2 全 0xE5** | 空格永远到不了；组字期间全部快捷键丢失 |
    | MS-IME 日文平假名态，**有守卫（现状）** | **0** | 13 次按键全是真实 VK（0x20/0x11/0x31/0x22/0x4D/0x1B/0x32），无一 0xE5 | 全部到达，Ctrl+1/2 命中 tab 切换，Esc 命中 `globalBack` |
    | 微软拼音，**有守卫** | **0** | 全部真实 VK | 全部到达 |
    | 视频页（argv 打开 ffmpeg 生成的测试视频），MS-IME 平假名，**有守卫** | **0** | Space×4、M、Esc 全真实 VK | 每次 Space 命中 `videoTogglePlayPause`，M 命中 `videoToggleMute` |
  - **「Ctrl+数字 / PageDown 按吞键理论不该失效」的矛盾已解释**：这两个键在空闲态确实不被吃，但只要先按过一个会起组字的键（拼音下任何字母、日文下任何假名键——包括字母快捷键本身或误触），输入法就进入组字态；Flutter 剥掉了 `ISC_SHOWUICOMPOSITIONWINDOW` 且无文本客户端，**组字是不可见的**，此后 Space / Ctrl / Ctrl+数字 / PageDown / Esc 全部变 `VK_PROCESSKEY` 被吞，直到组字被提交或取消。用户看到的就是「全表面快捷键时灵时不灵」。
  - 键盘消息只投到持焦的 `FLUTTERVIEW` 子窗口，顶层 `FlutterWindow::MessageHandler` 一条键盘消息都收不到（诊断里顶层探针零输出，无守卫且 Space=0xE5 时也是零）——这就是 BUG-1239 在顶层拦 `VK_PROCESSKEY` 的 Space 通道同样从未触发过的原因。
- **[x] ① 已修复** — 真修复是 BUG-1450 的平台边界守卫（`7a99dbf2ee6`，见上），本轮真机证实有效。本轮提交 `aa1a2415f89` 删除不可达的兼容层：`InputBinding.normalizeCapturedKey` 的 `process` 判据、`resolveReaderSpaceOverride` / `resolveReaderArrowPageTurn` 的 `process` 分支与 `physicalKey` 参数、视频页 `isVideoImeSpacePlayPause` / `_handleVideoImeSpacePlayPause`、BUG-1239 的 runner `app.fushi/windows_ime_space` 通道（`ime_space_dispatch.{h,cpp}`、`windows_ime_space_channel.dart`、`windows_ime_space_dispatch.dart`），并更正注释里「IME 把 logicalKey 改写成 process」的错误事实。`resolveKeyboard` 的物理键回退保留，它服务的是 BUG-2948（macOS 表外符号键），与 IME 无关。
- **[x] ② 已加自动化测试** — 最强可落地层是 native：`fushi/windows/runner/tests/ime_association_guard_test.cpp` 新增真 HWND 用例，对生产 `ApplyImeAssociation` 断言「disable 后 `ImmGetContext` 为 null、enable 后恢复」——正是真机上 himc=1 吞键 / himc=0 不吞的分界（随每次 Windows runner 构建由 `fushi_windows_ime_association_gate` 执行）。变异实测：disable 改成 `IACE_DEFAULT` → 「disable must leave the window without an input context」转红；enable 改成 `0` → 「enable must restore the input context」转红。Dart：`fushi/test/shortcuts/ime_process_key_reachability_guard_test.dart` 加两条源码守卫（`lib/` 不得再以 `LogicalKeyboardKey.process` 作判据；`main.dart` 必须在 `runApp` 前 `WindowsImeGuard.install()`）；焦点驱动开关见既有 `fushi/test/platform/windows_ime_guard_test.dart`。删除只喂合成 `process` 事件的假绿测试 `shortcut_registry_ime_test.dart`、`video_ime_space_playpause_test.dart` 与 `input_binding_test` / `reader_space_pause_test` 中的对应用例。
