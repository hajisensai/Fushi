## BUG-430 · Windows IME 激活时全表面快捷键失效
- **报告**：2026-06-26（用户：）
- **真实性**：✅ 真 bug（症状真实），但 ⚠️ **下面这条根因已于 2026-08-02 被引擎源码证伪，当前真凶待定**——见「根因证伪」栏。以下保留原始记录以存档：根因：Windows 微软 IME 激活时，Flutter 引擎把 `KeyDownEvent.logicalKey` 改写成 `LogicalKeyboardKey.process`（输入法占用逻辑键），而快捷键解析 `HibikiShortcutRegistry.resolveKeyboard`（`hibiki/lib/src/shortcuts/shortcut_registry.dart:241`）用 `InputBinding.==`（`hibiki/lib/src/shortcuts/input_binding.dart:233`，只比 logicalKey+modifiers）做精确相等 → 与任何 binding 的 logicalKey 都不等 → 恒返回 null → 阅读器/首页/全局所有键盘快捷键全部失效。`physicalKey`（USB HID 扫描码）不受 IME 改写，是唯一可靠的回退判据。两个直读 `event.logicalKey` 的纯函数 `resolveReaderSpaceOverride` / `resolveReaderArrowPageTurn`（`hibiki/lib/src/shortcuts/reader_space_override.dart:14/40`）同样失效：IME 下有声书裸 Space 不再播放/暂停、RTL 书裸左右键翻页方向反转（落回注册表写死的 Right=前进）。
- **根因证伪（2026-08-02，引擎源码级）**：上面那条「引擎把 logicalKey 改写成 `process`」的前提**不成立**，本 bug 的真凶**待定**。证据：
  - `LogicalKeyboardKey.process` 是 **Flutter Web 专有**值。其裸 keyId `0x0010000070f` 在整棵 engine 树只出现 3 处：web 引擎 `lib/web_ui/lib/src/engine/key_map.g.dart:237`（唯一生产用），以及 Android / embedder 两个 **test util**。Windows / Android / iOS / macOS / Linux-GTK 的**生产键表全都没有该条目**；框架侧同理，`packages/flutter/lib/src/services/keyboard_maps.g.dart` 里它只在 `kWebToLogicalKey`（:2398）出现，`kWindowsToLogicalKey`（:2862）等原生表均无。
  - Windows 上被 IME 消费的键，由嵌入层 `shell/platform/windows/keyboard_key_embedder_handler.cc:177-183` 在 `VK_PROCESSKEY` 时直接 `callback(true); return;`（注释原文 "not sent to Flutter"）——**一个 `FlutterKeyEvent` 都不发**；对应的 keyup 因无按下记录，也在 `:255-260` 被丢弃。（BUG-1432 记录的行号为 `:174-181` / `:254-259`，属 engine 版本行号微差，同一段逻辑。）
  - ⇒ **引擎在本仓 5 个出包平台上永不产生 `logicalKey == LogicalKeyboardKey.process`**。IME 吃掉的键在 Flutter 侧根本不存在（既无 down 也无 up）；IME 不吃的键则逻辑键完全正常。两种情况都到不了 `== process` 判据。
  - 该事实已由守卫测试钉住：`hibiki/test/shortcuts/ime_process_key_reachability_guard_test.dart`（BUG-1432）。
  - ⚠️ **真机确认率 0/3**：本条至今标「真机门禁待验」，同族的 BUG-853 标「待用户验收」，BUG-936 则由**用户真机证实 `.process` 修复无效**。三轮修复的测试全部是合成 `(process, physicalKey)` 事件，因而恒绿、不可证伪。
- **🔴 一个未被新理论解释的矛盾（不许抹平）**：`VK_PROCESSKEY` 吞键理论**只**预测「被 IME 消费的那些键」消失——大致是可打印键与空格。但本 bug 报的是**全表面快捷键失效，明确含 `Ctrl+数字`（首页切 tab）与 `PageDown`（阅读器翻页）**，而这些键微软 IME 通常**不**消费、按吞键理论应当正常抵达 Flutter 并正常命中 binding。若用户报告属实，**吞键不足以解释全部症状，很可能还存在第三个根因**（尚未定位；候选方向仅供后续排查参考：IME 激活期的焦点/键盘所有权变化、composing 状态改写 `Shortcuts`/`Focus` 链、窗口级 IME 关联导致的事件路由变化）。**在真机抓到 IME 激活时按 `Ctrl+数字` / `PageDown` 的真实 KeyEvent 之前，本条不得按「症状已解释」结案。**
- **[ ] ① 未修复（原「已修复」作废：前提被证伪）** — ⚠️ 下述实现虽已合入 develop，但按「根因证伪」栏，其唯一入口条件 `key == LogicalKeyboardKey.process` 在 5 个出包平台上永不成立，整条回退是**死代码**，本 bug 因而**未获真正修复**。且即便该前提成立，也解释不了上面「矛盾」栏里的 `Ctrl+数字` / `PageDown` 失效。存量兼容层本轮**不删**（Never break userspace；且两张映射表与 `normalizeCapturedKey` 的「捕获侧与运行时共用同一契约」恰是将来真修复所需的零件）。以下为原始记录，存档用：`resolveKeyboard` 加可选参数 `PhysicalKeyboardKey? physicalKey`；正常路径（精确相等遍历）逐字不变，仅当 `key == LogicalKeyboardKey.process && physicalKey != null` 时启用物理键回退分支（在 modifiers 完全相同前提下按 `InputBinding.physicalKey` 比对）。`InputBinding` 新增 `static final Map<LogicalKeyboardKey,PhysicalKeyboardKey> _logicalToPhysical`（覆盖与 `_knownKeys` 相同的非 game* 键集）+ 派生 getter `physicalKey`；`==`/`hashCode`/`serialize` 不动。两个 override 纯函数也加 `physicalKey` 参数，`key==process` 时按物理键还原 Space/方向键语义。四调用点透传，门控 `physicalKey: focusedEditableText() == null ? event.physicalKey : null`（文本框 composing 时传 null 关回退，保证 IME 打字不被吞）：`reader_hibiki/caret.part.dart`（directReaderAction + reader/audiobook scope chain + spaceOverride + arrowOverride）、`home_page.dart`（home + global scope）、`global_navigation.dart`（`_handleGlobalBack` global scope）。`home_page.dart` 的 `arrowTraversalDirection`（焦点方向导航降级，非数据破坏）列为 follow-up 未纳入本轮。**已知限制：physical↔logical 一一对应仅在 US-QWERTY 物理布局下成立**；非美式物理键盘（AZERTY / 德语 QWERTZ）上字母/符号键的物理位与逻辑键不一致，回退可能错绑到相邻键。因回退仅在 `key==process`（IME 激活，本就全失效）时启用，最坏只是“按某键触发了相邻快捷键”，绝不会比现状（全部失效）更糟；Space/方向键物理位在所有常见布局一致，实际不受布局影响。提交哈希：见下。
