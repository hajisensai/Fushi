## BUG-677 · 导入选字幕文件的选择器变了 回退系统文件选择器 (board 1360)
- **报告**：2026-07-09（用户：TODO-1360）
- **真实性**：✅ 真 bug（体验回归）。根因 `hibiki/lib/src/media/import/real_path_directory_picker.dart:83`（`pickRealFilePath`）被三个导入对话框的字幕/对齐选择器调用：`hibiki/lib/src/media/video/video_import_dialog.dart:283`（`_pickSubtitle`）、`hibiki/lib/src/media/audiobook/book_import_dialog.dart:483`（`_pickSubtitle`）、`hibiki/lib/src/media/audiobook/audiobook_import_dialog.dart:531`（`_pickAlignment`）。board 1112（commit `a2897b429`）为「安卓单文件视频导入不复制到 cache（避免 videoPath 悬空、no video found）」新增真实路径文件浏览器 `pickRealFilePath`，并把**字幕选择器一起**改走它；随后又扩到有声书/书籍导入的字幕/对齐选择器。于是安卓上「导入选字幕文件」从熟悉的系统文件选择器（SAF）变成 app 内自建的真实路径目录/文件浏览器（只能浏览默认根集下的真实路径，触达不到 Downloads / 云盘 / 最近文件），用户不适应。
- **[x] ① 已修复** — 字幕/对齐文件在导入时**当场被解析消费**（字幕→cues→`CuesToEpub` 生成 EPUB；对齐→跑 matcher），不以绝对路径长期引用，SAF 复制到 cache 的临时副本读完即弃，不存在 `pickRealFilePath` 要解决的「清缓存路径悬空」问题——所以对字幕而言真实路径浏览器**无收益、只有回归代价**。新增 `pickSystemFilePath`（`real_path_directory_picker.dart`，走系统文件选择器 = 复用既有 `_fallbackPickFile`，安卓 SAF / iOS Files / 桌面原生），三个字幕/对齐选择器改用它、并删掉多余的 `MANAGE_EXTERNAL_STORAGE` 请求。**视频本体 `_pickVideo` 保留 `pickRealFilePath`**（它以绝对路径引用、不复制，SAF cache 路径会悬空——board 1112/TODO-949 的真实修复，不能回退）。桌面/iOS 行为不变（本就走 `_fallbackPickFile`）。提交：见分支 `todo1360-subtitle-picker-revert`。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/subtitle_import_system_picker_guard_test.dart`：源码扫描守卫，断言三个导入字幕/对齐选择器（video `_pickSubtitle` / book `_pickSubtitle` / audiobook `_pickAlignment`）走 `pickSystemFilePath` 且不再走 `pickRealFilePath`，同时 `_pickVideo` 仍走 `pickRealFilePath`（防止把视频也误回退重引 no-video-found）。并同步更新既有守卫 `hibiki/test/media/video/real_path_directory_picker_test.dart`（原断言字幕走 `pickRealFilePath` 已按本回退改写）。
- **备注**：post-import 的字幕挂载选择器（`reader_history/video.part.dart`、`video_hibiki/subtitle.part.dart`）本就用系统 `FilePicker.platform.pickFiles`，不受本次影响。DB schema 零改动，无版本 bump。
