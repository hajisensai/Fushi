## BUG-4081 · linux-lan-scan-without-avahi
- **报告**：2026-11-04（用户：Steam Deck 游戏模式，互联「局域网设备」显示 "Scan failed — check network permissions or firewall."）
- **真实性**：✅ 真 bug。Linux 上 bonsoir 只是 Avahi 的 D-Bus 客户端，SteamOS 自带 Avahi 但 `avahi-daemon.service` 默认 disabled（WSL / 精简安装干脆没有）；`AvahiBonsoirDiscovery.initialize` 抛 `NameHasNoOwner: Could not activate remote peer 'org.freedesktop.Avahi': activation request failed: unknown unit`，`fushi/lib/src/sync/lan_discovery_service.dart` `startDiscovery` 原样 rethrow → `interconnect.part.dart` `_startScan` 置 `_scanFailed`；广播端 `LanBroadcastService.start` 同因失败（只记日志），别的设备也扫不到 Deck。BUG-4078 只修了「未初始化的 discovery 被 stop 时空检查崩溃」，扫描本身仍依赖 Avahi。
- **[x] ① 已修复** — 新增纯 Dart 的 mDNS / DNS-SD 兜底 `fushi/lib/src/sync/mdns_fallback.dart`（标准 224.0.0.251:5353 报文编解码、SO_REUSEADDR 与 systemd-resolved 共享端口、Responder 应答 PTR/SRV/TXT/A + 上线两次通告 + 下线 goodbye + 旧式单播查询回单播、Browser 按 TTL 缓存并补问缺失记录、过期即判离线）。`LanDiscoveryService` / `LanBroadcastService` 在 Linux 上 bonsoir 初始化失败时切到兜底（事件翻译成同一套 Bonsoir resolved/lost 事件，复用既有映射与去重）；非 Linux 行为不变，兜底的 socket 也绑不上才报扫描失败。
- **[x] ② 已加自动化测试** — `fushi/test/sync/mdns_fallback_test.dart`：报文往返（UTF-8 / 含点实例名）、他家压缩指针解码、畸形包拒收不抛、Responder↔Browser 解析 + 同网段地址优先 + goodbye 判离线、无 goodbye 时 TTL 过期判离线、只有 PTR 时补问 SRV/TXT 且不半解析上报、旧式单播查询回单播并回显 id、Avahi 失败时 LanDiscoveryService 经兜底拿到对端 FushiDevice（含 https）、非 Linux 仍抛错、绑定期间 stop 不留残留。
- **备注**：真机验证（Deck ↔ Windows Bonjour 对端）见提交说明；Deck 侧另有 Avahi 可用时仍走 Avahi。
