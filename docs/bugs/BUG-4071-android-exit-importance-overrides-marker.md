## BUG-4071 · Android 后台被厂商杀进程仍被判「停在前台时没了」弹闪退报告
- **报告**：2026-11-04（崩溃报告整批分诊，反馈 `e1_jaKAeiF`：realme RMX3888，3.3.0-debug.23025，「闪退报告：意外退出」）。
- **真实性**：✅ 真 bug（闪退误报）。报告正文里三条证据自相矛盾：会话标记 `pid=19104 … lastLifecycle=inactive@10:01:46.305 memoryPressure=1x`（判「停在前台时没了，疑似闪退」）；`onTrimMemory UI_HIDDEN@10:01:44.326 pid=19104`（界面已进后台）；`ApplicationExitInfo reason=OTHER pid=19104 importance=400 … description: [UNKNOWN] stop app.fushi.reader due to o-stop(40)`（ColorOS/realme 后台管理在后台把进程杀了，`importance=400` = `IMPORTANCE_CACHED`）。根因：`fushi/lib/src/diagnostics/previous_exit_log.dart:1163`（旧）`collect` 在取 Android 退出记录**之前**就用 `describeUncleanPreviousSession(previous)` 定了标记那条的前后台，只看 `PreviousSession.diedInForeground`（`:207-210`，`inactive` / `launching` 都算前台）；Android 给的 `reason=OTHER` 映射不出 kind（`androidExitKind` 返回 null），于是 `classifyPreviousExit` 选中标记推断的 `unexpected`、`worthReporting` 为真。平台对**同一 pid** 记下的死时重要性是事实，标记的生命周期只是推断，旧实现让推断压过了事实。
  - 同一类误报还覆盖无界面引擎：`UeCVNnw7Jx` 里标记 pid=31262 停在 `launching`，Android 记录同 pid `LOW_MEMORY importance=400`。
- **[x] ① 已修复** — `previous_exit_log.dart`：新增 `androidImportanceAtDeath(payload, pid:, startedAtMs:)`（按 pid 找记录、跳过早于本会话启动的同号记录——pid 会复用）；`describeUncleanPreviousSession` 增加 `androidImportanceAtDeath` 参数，有值时以 `importance <= kAndroidForegroundImportance(125)` 判前后台并写进摘要（`androidImportanceAtDeath=400`）；`PreviousExitLog.collect` 改为先取 `consumeExitReports`，再生成会话标记那条摘要。原生崩溃 / ANR 等平台明确原因的优先级不变（后台原生崩溃照样上报）。
- **[x] ② 已加自动化测试** — `fushi/test/diagnostics/previous_exit_log_test.dart` 组 `Android：同一 pid 的死时重要性压过会话标记的前后台推断`：经真实 MethodChannel 假通道走 `PreviousExitLog.collect` + `classifyPreviousExit`，四例：importance=400 → `backgroundReclaim` 不上报；importance=100 → 仍 `unexpected`；别的 pid / 早于会话启动的同号记录 → 回落标记推断；后台 `CRASH_NATIVE` → 仍 `nativeCrash` 上报。旧实现下第一例红；修复后与 `crash_report_test` / `app_exit_coordinator_test` / `update_handoff_test` 合跑 88 例全绿（exit 0）。
- **备注**：只修「平台已经给了同 pid 重要性」的情况。没有同 pid 退出记录、标记又停在 `launching` 的那类（audio_service 无界面拉起 `main()`）见 BUG-4072，需要拍板。
