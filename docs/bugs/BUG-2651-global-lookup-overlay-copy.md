## BUG-2651 · 应用外查词弹窗无法复制：Ctrl+C 复制到前台应用、右键菜单被弹窗盖住（issue #1581）
- **报告**：2026-09-25（用户：GitHub issue #1581 @Luoyur0。Windows 用应用外查词 Ctrl+Alt+D，在弹窗里选中文字按 Ctrl+C，复制到的是弹窗外原本选中的文字；右键选「复制」，菜单被弹窗盖在下面点不到）
- **真实性**：✅ 真 bug，两个症状同一个根：瞬态覆盖窗 `GlobalLookupWindow` 是 `WS_EX_TOPMOST | WS_EX_NOACTIVATE`（`fushi/windows/runner/global_lookup_window.cpp:2098` `OverlayCreateExStyle`），按设计**永不拿键盘焦点**（前台应用始终留着焦点，gal 卡片依赖这一点）。① 卡片里划选后按 Ctrl+C，按键投给的是前台应用，它复制自己的选区——popup.js 的键盘监听注释早写明「app 外瞬态覆盖窗永不接收键盘焦点、runner 无键盘转发」；② WebView2 自带的右键菜单没有被接管（整个 runner 对 `ContextMenuRequested` 零引用），Chromium 菜单窗弹在这个置顶卡片**下面**，菜单里的「复制」永远点不到。在 app 内弹窗与已获得焦点的剪贴板面板上都没有这个问题，只有 app 外瞬态覆盖窗（与共用同一个类的 gal 桌面卡片）中招。
- **[x] ① 已修复** — 不改「卡片不抢焦点」的设计，改为只在确有需要时接管：
  - host（`fushi/assets/popup/global_lookup_host.js:3768` `selectedText` / `:3811` `watchFrameSelection`）给每个卡片 iframe realm 挂 `selectionchange`（load 与 realm 复用两条路都紧跟 `wrapFrameBridge`），汇总成「有无非空选区」一个布尔、**变化时**才 `postToHost('overlaySelection')`；`selectedText()` 优先取最近一次产生选区的 realm（在子卡里划选不会清掉父卡的旧选区）。
  - native（`global_lookup_window.cpp:3026`）在 `WebMessageReceived` 就地消费 `overlaySelection`、不转发 Dart；`UpdateCopyHotkey`（`:3586`）只在「有选区 && `IsShowing()`」时 `RegisterHotKey(MOD_CONTROL | MOD_NOREPEAT, 'C')`，`Hide()` 清 `visible_` 后立刻注销（`:1868` 附近）——点卡外、前台切走、程序化重置都经 Hide，隐藏的卡片绝不会截走用户在别的应用里的 Ctrl+C；三处上屏点补调一次。`WM_HOTKEY`（`:3780`）经 `ExecuteScript(selectedText())` 取文本，native 以 `CF_UNICODETEXT` 写剪贴板（卡片没焦点，页面内 `execCommand('copy')` / `navigator.clipboard` 不可靠）；取回空串说明上报过期，以现场为准交还热键。
  - 右键菜单：`ConfigureWebView` 经 `ICoreWebView2_11::add_ContextMenuRequested`（`:2778`）接管，`HandleContextMenuRequested`（`:3641`）`put_Handled(TRUE)` + deferral 后 `PostMessage` 出 COM 回调栈（模态菜单直接在回调里跑会挂住 WebView2 派发，同 beginWindowResize 的教训）；`ShowPendingContextMenu`（`:3662`）用 Win32 `TrackPopupMenuEx` 弹「复制 / 全选」（文案取 WebView2 自己的本地化标签；复制文本取菜单目标的 `SelectionText`，native 写剪贴板；全选交回 WebView2 原生命令）。`#32768` 菜单窗天然在置顶带之上。按 TrackPopupMenu 契约弹菜单期间临时 `SetForegroundWindow(hwnd_)`（否则点菜单外不收、Esc 到不了菜单），菜单结束若前台仍在我们手里就还给原窗口；`HandleGlobalClick` 在菜单模态期间不把点菜单那一下当点卡外（`:813`），`ForegroundHookProc` 放过「把前台还回去」那一次（`:799`），其余前台切换照常关卡。
- **[x] ② 已加自动化测试** — `fushi/test/lookup/global_lookup_overlay_copy_guard_test.dart`（4 条源码守卫：host 只在变化时上报并导出 `selectedText`、两处 `wrapFrameBridge` 都紧跟 `watchFrameSelection`；native 在 `message_cb_` 之前拦截 `overlaySelection`；热键条件 `selection_present_ && IsShowing()` + `MOD_CONTROL | MOD_NOREPEAT` + Hide 在清 `visible_` 后注销 + `WM_HOTKEY` 走复制；右键菜单 `put_Handled` + deferral + PostMessage、回调里无 `TrackPopupMenu`、前台→武装→Track→解除的顺序、点击钩子与前台钩子的放行）；`fushi/test/lookup/global_lookup_host_test.mjs` 末段行为测试（两张卡片 realm 的选区汇总：首次选中报 true、扩选不重报、最近 realm 优先、回落到剩余选区、全部清空只报一次 false；watcher 按 realm 幂等），反例对照（去掉去重）确认会红。runner C++ 用 MSVC `cl /W4 /WX`（与工程同参）单编 `global_lookup_window.cpp` 通过，并做了编译反例对照。
- **备注**：⚠️ 真机未复验（本轮没有在 Windows 上起真 app 走 Ctrl+Alt+D 原始路径）。已知边界：① 若别的进程已全局注册 Ctrl+C 热键，`RegisterHotKey` 会失败（报 overlay error），退回旧行为，右键复制不受影响；② 右键菜单弹出期间前台临时切到卡片，对焦点敏感的 galgame 会短暂失焦一次，菜单关闭即还回；③ 右键空白处（无选区）最多只剩「全选」一项（WebView2 没给就不弹菜单），WebView2 页面菜单里的刷新 / 检查等项不再出现（它们原本也弹在卡片下面够不着）。
