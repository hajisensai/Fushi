## BUG-3664 · 翻页模式当前句高亮只亮第一行，折行部分全丢
- **报告**：2026-10-23（用户：应用内反馈 DEHOXVOYVQ，Android 3.0.0-debug.20679，荣耀平板横屏 1047x698@2.91，横排翻页、有声书跟读；「小说书籍模式，当前的字幕高亮条显示不全，歌词模式能显示齐全」。附带录屏抽帧：「途端——あらゆる角度から飛来した針が、毛糸 / 玉をハリネズミに変える。」只有第一行「途端……毛糸」有高亮条，折到下一行的「玉を……変える。」没有；另一句「よくよく観察すると、壁・床・天井の全て / に、小指の……」同样只亮第一行）
- **真实性**：✅ 真 bug。窄条层 `__fushiLanes` 的分栏收边（BUG-3503 / BUG-3518 引入，`fushi/lib/src/reader/reader_selection_scripts.dart` `lanes()`）按片段起点用 `floor((a + 0.5 − start) / step)` 归栏，再把片段收进该栏。栏网格 `start + k·step` 由计算样式 `column-width` / `column-gap` 与 `scrollLeft` 算出，但 Blink 排栏用 1/64px 定点数、`scrollLeft` 按设备像素取整，每栏有亚像素误差，翻到第 k 页累积 k 倍；几十页后每行行首（恰在真实栏起点）落到算出的栏起点左侧超过 0.5px，被归进前一栏、收到前一栏栏尾后宽度归零被滤掉。所以折行后的每一行都丢，只有行中起头的第一段留下。整数 DPR / 第 0 页（现有测试场景）看不出来。真机漂移量是推断（无安卓真机复现）；在真 Chrome 里给网格注入每栏 0.3px 漂移，旧判据复现出同一现象（第 1、2 行无窄条），修复后通过。
- **[x] ① 已修复** — 归栏容差放宽到半个列间距（`max(0.5, min(gap/2, step/4))`）：正文片段起点永远在某一栏内（悬挂标点只从栏尾往外伸），网格误差远小于半个列间距；栏头不再收（片段不会从栏头之前开始，收它只会把漂移削进字里），栏尾照旧收（BUG-3518 不回退）。滚动 / VN 没有分栏（`columnFrame` 为 null），三种模式共用同一函数，只有翻页受影响也只改翻页。
- **[x] ② 已加自动化测试** — `fushi/test/reader/highlight_lanes_harness.mjs`（经 `highlight_lanes_test.dart` 真 Chrome 跑 分页/滚动/VN × 横竖排 × 默认/Apple CSS）：翻到第 4 页、选一段折行三行的文字，每行都要有完整窄条；再把 `column-width` 读数加 0.3px/栏模拟定点漂移重画，每行仍要有窄条。变异实测：容差改回 0.5 时 4 种分页组合的「drifted grid」第 1、2 行全部失败，修复后通过。
- **备注**：本机 `highlight_lanes_test` 在默认 CSS 竖排上有与本改动无关的既有失败（`cue wrapped into several pieces (0)`，HEAD 版 harness 同样失败，疑本机字体环境），CI 判绿。未在安卓真机复测。
