## BUG-4907 · 视频导入 / 来源扫描 / 互联收字幕在 UI isolate 上同步解析整份字幕，特效重的 ASS 冻住 UI 上百毫秒
- **报告**：2026-11-20（路线图 #3722 c33，审查条目 video-36g）
- **真实性**：✅ 真 bug。根因 `packages/fushi_engine/lib/media/video/video_library_import.dart:66`：`parseSubtitleCues` 是同步函数，四个调用点都在 UI isolate 上——`fushi/lib/src/media/source_library/source_library_scanner.dart:3069`（来源扫描逐个视频）、`fushi/lib/src/media/video/video_import_dialog.dart:640`（导入对话框）、`fushi/lib/src/pages/implementations/home_video_page.dart:4508`（远端视频下载落字幕）、`packages/fushi_engine/lib/sync/local_library_host_service/videos.part.dart:1425`（互联 host 收上传字幕，host 跑在 app 的 UI isolate）。实测（`dart run`，JIT，本机）：1500 条 SRT（86K 字符）约 3 ms、1500 条带特效标签的 ASS（155K）约 6 ms、8000 行特效 ASS（830K）约 33 ms、30000 行（3.1M，卡拉 OK / 招牌特效很重的字幕组 ASS）约 124 ms；扫一个满是这类字幕的库就是一串掉帧 / 冻结。
- **[x] ① 已修复** — `parseSubtitleCues` 改成 `Future<List<AudioCue>>`：格式在起 isolate 前校验（不支持的格式仍以 `ArgumentError` 失败）；内容超过 `kSubtitleParseInlineMaxChars`（64K 字符，就地解析约 2 ms 以内，起 isolate 的固定开销反而更大）的交给 `Isolate.run` 解析，小内容就地解析。只搬解析、不搬判编码：`readTextWithEncoding` 在移动端可能走平台通道（只在根 isolate 可用），调用方仍先读文本再交进来。四个调用点改为 `await`。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/media/video/parse_subtitle_cues_test.dart`「a large ASS is parsed off the calling isolate」：解析 30000 行 ASS 的同时跑 1 ms 周期定时器，断言解析期间事件循环照常走拍（≥3 拍）且结果按开始时间升序、条数完整。变异实测：把分流条件改成恒就地解析后该用例红（`Expected: a value greater than or equal to <3>  Actual: <0>`）。`fushi/test/media/video/parse_subtitle_test.dart` 随签名改为 await。
- **备注**：耗时是 JIT 下的数；release AOT 的绝对值会低一些，但 30000 行量级仍远超一帧预算。没在真机上量扫描期间的帧时（所有者定本轮不做设备验证）。
