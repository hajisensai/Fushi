## BUG-5510 · 同步 sweep 补拉有声书不进下载任务表、不与手动任务互斥
- **报告**：2026-11-19（开发者应用内反馈 B5trcDxSnf：「自动同步补拉有声书时不经过下载管理器，所以书架上看不到它的进度；它和手动下载也不互斥，同一个有声书包可能被拉两次」）
- **真实性**：✅ 真 bug。`fushi/lib/src/sync/sync_orchestrator/audiobooks.part.dart`（修前 `:211-214` / `:309` 起）`toPullAudioOnly` 只按 `localBookKeys` 过滤，逐本 `getRemoteAudiobook` + `importAudioDatabasePackage` 自己闷头拉：不登记 `InterconnectDownloadManager`（书架本地卡遮罩、首页后台任务环都读它），也不看书架上正在跑的「从对端下载有声书 / 重新下载有声书」任务；反过来手动入口（`reader_history/remote.part.dart` `_downloadRemoteAudiobookOnly` / `_refetchRemoteAudiobook`）只按 `bookTaskId(downloadId)` 判重，也看不到 sweep。两条可以并跑，同一个包拉两遍、并发解包写同一本书。
- **[x] ① 已修复** — 新端口 `fushi/lib/src/sync/sync_audiobook_pull_tasks.dart`（`SyncAudiobookPullTasks`：`isBookDownloadRunning` / `runAudiobookPull`），`InterconnectDownloadManager` 实现它并在 provider 创建时注册到 `syncAudiobookPullTasks`（销毁注销）；`sync_auto_trigger.dart` 的完整 sweep 把它交给 `SyncOrchestrator.audiobookPullTasks`。sweep 补拉前按落地书键跳过已有在跑任务的书，自己拉的登记成任务（键 `sync-audiobook:<bookKey>`、kind audiobook、阶段 [audiobook]、`landedBookKey` = 本书，字节口径与手动补拉相同），书架遮罩与后台任务环据此显示进度；`runAudiobookPull` 自己再判一次忙，判忙到登记之间被手动任务抢先也让开。手动补拉 / 重拉入口加 `isBookDownloadRunning(localBookKey)` 判重，与 sweep 双向互斥。失败的 sweep 任务留在下载中心可重试（本体自包含；本轮同步结束后不再往同步进度行报进度）。
- **[x] ② 已加自动化测试** — `fushi/test/sync/sync_orchestrator_live_audio_test.dart`（真 server + 真 `InterconnectDownloadManager`：sweep 补拉登记成 completed 的有声书任务、落地书键 / 标题 / 阶段正确、跑的过程中书架判据看得到；手动任务在跑时 sweep 不拉、不另起任务，且 `runAudiobookPull` 对忙的书不跑本体）。
- **备注**：反馈里顺带提的「按话下载漫画的第 k/N 话逐话进度」是另一件功能诉求，不在本条范围。无界面宿主 / 测试不注册端口时 sweep 行为与从前一致。
