## BUG-4997 · Plex 连接探测在核对服务器身份之前就把 X-Plex-Token 发给被探测地址
- **报告**：2026-11-20（PR #3793 c42 审查未解决项）
- **真实性**：✅ 真 bug。`probePlexConnection`（`fushi/lib/src/sync/plex_settings_widget.dart:127`）用带 token 的 `PlexApi` 调 `identity()`，而 `PlexApi._send` 对每个请求都加 `X-Plex-Token` 头（`packages/fushi_engine/lib/media/video/media_server/plex/plex_api.dart:383` `headers` → `:408`），所以 token 在比对 machineIdentifier **之前**就到了被探测地址；`PlexServerConfig.rerouteAfterFailure` 的注释（`fushi/lib/src/sync/plex_video_client.dart:186`）却声称核对能防止把 token 发给别的服务器。BUG-4980 让这条探测在任何传输失败后自动对全部已存连接（含 http 明文局域网地址）发起，旧局域网地址被别人的设备 / 别的 PMS 占了时 token 直接泄给对方。账号登录挑线路（`savePlexAccountServers`）与 `fushi_server` 的 `media-server plex` 选连接（`packages/fushi_server/lib/src/commands/media_server_commands.dart:550`，后者连 machineIdentifier 都没比对，只看非空）同一问题。
- **[x] ① 已修复** — `PlexApi.identity()` 改为不带 token（`/identity` 无需认证：官方 https://developer.plex.tv/pms/ 「Get PMS identity」标 Authorizations: None，社区规范 lukasparke/plex-api-spec 记 `Auth: none`）；新增引擎侧唯一入口 `verifyPlexServerIdentity(uri, machineIdentifier, clientInfo)`，内部构造的 `PlexApi` 不持有 token。`probePlexConnection` 与 `savePlexAccountServers` 的 probe 签名去掉 token 参数（探测阶段结构上拿不到凭据），登录挑线路、自动换线路、CLI 选连接都走它；CLI 同时补上 machineIdentifier 比对。核对通过、被选为当前线路的地址之后才会收到带 token 的请求。注释改准确。
- **[x] ② 已加自动化测试** — `fushi/test/sync/plex_identity_probe_no_token_test.dart`（假 PMS：`identity()` 不带 token、自动换线路时身份不符的局域网地址从未收到 token 且切换后鉴权请求只去核对通过的地址、账号登录挑线路同样、期望 id 为空不发请求）；`packages/fushi_server/test/media_server_commands_test.dart`「局域网地址被别的服务器占了」；`fushi/test/sync/plex_account_servers_probe_test.dart` 随签名调整。
- **备注**：核对与之后的鉴权请求之间对面换机器（TOCTOU）不在防护范围。手动连接（用户亲手填地址 + token）没有预期 id 可比，`/identity` 同样不带 token，随后的 `/library/sections` 照常带。若有 PMS 配置对无凭据 `/identity` 回 401，探测会判该线路不可用（与官方文档不符，未遇到，未做真 PMS 验证）。
