## BUG-4714 · 网页播放器窗口宿主档 DOM 字幕点词制卡丢失锚点 cue，静默出无画面无音频的纯字段卡
- **报告**：2026-11-10（应用内反馈 J8oImZq3Is，Windows 3.3.0-debug.25034：网页播放器制卡时画面与原句音频静默缺失；字幕轨列表为空但能取到 cue）
- **真实性**：✅ 真 bug（沿代码路径定位，日志无直接证据）。根因 `fushi/lib/src/pages/implementations/web_video_fushi_page.dart:2013-2020`（`_onDomLookup`）：窗口宿主档的 DOM 字幕层（`assets/web_video/web_video_dom_subtitles.js:160-166`）直接读页面 store `window.fushiEpisodeCues` 里的活对象，而 Dart 侧 `_controller.cues` 是 glue 每 250ms 节流投过来的轨快照（`assets/web_video/web_video_glue.js:80-107`），解析时还会 trim 文本（`fushi/lib/src/media/video/web_video_bridge.dart:423`）。live 轨在 store 里被原地改写（`assets/browser_extension/subtitle-providers.js:930-965,1000-1003`：文本逐字变长、起点往前并、终点从 `startV+1500` 往后延），所以 `_onDomLookup` 拿载荷的 (cueStart, sentence) 按「起点 + 全文相等」去快照里找经常落空；落空后退回 `_controller.currentCue`，它按快照里的旧短终点算，此刻往往是 null。`_lastLookupCue == null` 之后，`onMineEntry`（:1196-1198）与 `_mineFromGlobalLookup`（:2036-2040）都退回 mixin 的纯字段制卡：不入重放队列、不截帧不录音，也没有任何提示。载荷本身已带被点那句的完整时间窗与文本，却被丢掉了。
- **[x] ① 已修复** — 新增 `webVideoDomLookupAnchorCue`（`fushi/lib/src/media/video/web_video_hosting.dart`）：DOM 点词的锚点就是被点的那一句，Dart 快照里有时间窗与文本都相同的那条就返回它本身（`cueStreamOwning` 按 identical 认流），否则按载荷建一条；永不为 null。`_onDomLookup` 改用它，不再退回 `currentCue`，DOM 点词后的制卡一律走入队重放。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/web_video_dom_lookup_anchor_test.dart`（快照命中返回同一对象、首尾空白、live 轨快照滞后、Dart 侧还没有轨四种情形，加 `_onDomLookup` 源码守卫）。
- **备注**：真机复测（Windows 窗口宿主档 + live 轨站点点词制卡、等重放落卡）未做。另发现 DOM 字幕层的延迟方向与 Dart 相反（JS `cueAt(videoTime + delayMs)`，Dart `posMs - delayMs`），不在本条范围，未改。
