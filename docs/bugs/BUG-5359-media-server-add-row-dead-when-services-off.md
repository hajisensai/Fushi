## BUG-5359 · 媒体服务器列表「去设置添加服务器」在线服务模块关着时点了没反应
- **报告**：2026-11-24（用户：Cupertino 主题 Windows 宽窗，视频 › 媒体服务器，组下「去设置添加服务器」点了没反应，日志无异常）
- **真实性**：✅ 真 bug。与设计系统 / 宽窗壳无关（M3E 同样中招）。点按确实触发（运行实例只读 hitTest：命中路径落到该行 `FushiAppleRow` 的 GestureDetector），`openMediaServerSettings` 也确实往根 Navigator push 了 `SettingsDetailPage(services)`；但用户关着「在线服务」模块（运行实例 `moduleVisibility.enabled` 不含 `services`），`SettingsDetailPage.build` 判 `!destination.isVisible` → `_popInvisibleDestination()`（`fushi/lib/src/settings/settings_detail_page.dart:94`）当帧自 pop，屏幕上什么也没发生。病根在入口：`fushi/lib/src/pages/implementations/media_server/media_server_server_list_view.dart` 的添加行 / 空态按钮（及书 / 漫画导入页「连接服务器」块）不看模块门，无条件挂着一条通往已被关掉分类的路；同仓的浏览 › 下载设置（`browse_page.dart` `servicesEnabled`）、发现页「管理来源」（`discovery_manage_sources_action.dart`）都按模块门不渲染。
- **[x] ① 已修复** — 新增 `mediaServerSettingsAction(context, ref)`（`media_server_server_list_view.dart:439`），判据与设置分类自己的 `visible` 同一条 `isSettingsDestinationVisible(SettingsDestinationId.services, …)`、`ref.watch` 跟随开关；不可达时返回 null，`MediaServerListView` / `MediaServerGroupedList` / `MediaServerListEmpty` 的 `onOpenSettings` 改可空，null 时添加行 / 空态按钮不渲染。视频分区（`media_server_browse_page.dart`，外部注入的回调仍优先）、书 / 漫画媒体服务器页签（`user_media_servers_view.dart`）、漫画 / 书导入页「连接服务器」块（`manga_sources_page.dart` / `book_import_page.dart`）都改经它取。
- **[x] ② 已加自动化测试** — `fushi/test/pages/media_server/media_server_settings_entry_test.dart`：MD3 / Apple 各验 模块开着时点击、Enter、空态按钮都停在 设置 › 在线服务；模块关着时添加行与空态按钮不渲染、服务器行照常；另钉病根（模块关着直接推服务设置页当帧自 pop）。
- **备注**：同类未改（不在本单范围，未验证）：`home_page.dart` 媒体服务器获取后端的 `configure`、`home_video_page.dart` `VideoOnlineServicesBanner.onOpenSettings`、`music_sources_page.dart` `_openServerSettings`（子页 `buildMusicServersDestination` 是否受同一门待查）也直接推服务设置页。
