## BUG-5413 · Android 引擎被销毁、进程留在后台时，原生线程回调已删的 NativeCallable，VM abort 整个进程
- **报告**：2026-11-24（应用内反馈 Wgbo462Sfc：Android 3.3.0，OnePlus PKG110 / Android 16。`onTrimMemory` 依次 BACKGROUND@47.135、UI_HIDDEN@47.190、BACKGROUND@47.313，约 0.9 s 后 `CRASH_NATIVE status=6`，importance=400（cached），SIGABRT `runtime_entry.cc:5380: error: Callback invoked after it has been deleted.`，trace 只有主线程 Looper 栈、没有出事线程）
- **真实性**：✅ 真 bug。MainActivity 继承 `AudioServiceActivity`，引擎来自 audio_service 的 `FlutterEngineCache`（不随 Activity 销毁）；但 Activity 走后（划掉最近任务 / 系统回收）`AudioServicePlugin.onDetachedFromActivity` 断开 MediaBrowser，没在前台播放时 `AudioService.onDestroy` → `AudioServicePlugin.disposeFlutterEngine()`（pub cache `audio_service-0.18.18/android/src/main/java/com/ryanheise/audioservice/AudioServicePlugin.java:116-130`，经 `:828-830`）`flutterEngine.destroy()`：root isolate 关停，进程留在后台（cached）。VM 随 isolate 删掉它创建的 `NativeCallable.listener`，而这些回调交给了活得比 isolate 久的原生线程：
  - libmpv 唤醒回调：补丁版 `ci/patches/hosted/media_kit-1.2.6/lib/src/player/native/core/initializer_native_callable.dart:50`（每个播放器一个，只有 `Player.dispose` 才解绑；引擎销毁不 dispose）；
  - fushi_compute 进程级引擎：音乐分析 `native/fushi_compute/src/music_analysis.rs:105`（`emit` 调 `ffc_mana_start` 登记的回调，Dart 侧 `fushi_compute_music_analysis.dart:232` 建的 listener）、漫画超分 `native/fushi_compute/src/upscale.rs:182`（`fushi_compute_upscale.dart:276`）。工作线程报下一个进度 / 完成事件、或 mpv 核心线程派发下一个事件，就进到已删回调，VM `FATAL` → SIGABRT。
  桌面同一机制此前只在「有意退出」路径上处理（BUG-3003 Windows 热重启改事件 isolate 后端、BUG-4730 `AppExitCoordinator.begin` 摘 libmpv 回调）；引擎销毁不经任何退出链，Android 上这条路径没有任何保护，也不可能在 Java 销毁引擎前同步跑 Dart 去摘。
- **[x] ① 已修复** — 不再把随 isolate 失效的函数指针交给原生线程，改成 Dart 原生端口（端口随 isolate 关闭，`Dart_PostCObject` 发往已关端口只是返回 false、丢消息）：
  - `native/fushi_compute/src/dart_port.rs`（新）：`DartPort`（`NativeApi.postCObject` + `SendPort.nativePort`，消息是 `int` 列表）与 `ffc_port_wakeup(void *d)` 跳板（给只认 `void (*)(void*)` 的 C 库，`d` = `{post, port, value}`）。
  - `ffc_mana_start(post, port)` / `ffc_upscale_start(..., post, port)` 改收端口（ABI 3 → 4，`lib.rs` 与 `kFushiComputeAbiVersion` 同步）；Dart 绑定改用 `NativeEventPort`（`packages/fushi_compute/lib/src/native_events/native_event_port.dart`），同一进程里下一个 isolate 再 `start()` 就换成自己的端口。
  - media_kit 补丁新增 `useNativePortWakeup()`（`lib/native_wakeup.dart`）：之后建的播放器把 `ffc_port_wakeup` + 各自的 `PortWakeupData` 交给 `mpv_set_wakeup_callback`，`ReceivePort` 驱动原来的事件排空；`dispose` 先解绑再关端口、释放数据。`fushi/lib/main.dart` 在 `MediaKit.ensureInitialized()` 后、建任何播放器前装上。BUG-4730 的退出摘回调保留（两种唤醒都适用）。
- **[x] ② 已加自动化测试** —
  - `fushi/test/third_party/media_kit_hot_restart_test.dart` 新增 `port` 模式（探针 `fixtures/media_kit_isolate_exit_probe.dart`）：真实子进程 + 真实 libmpv，发布构建的 NativeCallable 后端装上端口唤醒，既不 quiesce 也不 dispose 就杀掉 owner isolate，再 wakeup / quit → PASS。去掉 `useNativePortWakeup` 的同一探针本地实测 abort：`runtime_entry.cc: 6222: error: Callback invoked after it has been deleted.`（需 `FUSHI_TEST_LIBMPV` 或 Windows Debug 构建，否则 skip）。
  - `packages/fushi_compute/test/music_analysis_binding_test.dart`「events after the registering isolate died are dropped, not fatal」：真原生库，短命 isolate 登记端口并提交一首后 `Isolate.exit`，工作线程把事件发往已关端口；主 isolate 再 `start()` 后照常收到下一首的 done。
  - Rust：`dart_port.rs` 单测（`Dart_CObject` 布局、已关端口、跳板）；`music_analysis.rs` 引擎测试先在已关端口上跑完一首再换端口；`upscale.rs` 代际测试改用假端口。
  - 守卫：`packages/fushi_compute/test/native_lifetime_guard_test.dart` 禁止 `lib/` 再出现 `NativeCallable`。
- **备注**：Android 真机未复测「划掉任务 → 引擎销毁 → 后台事件」的原始路径（需要在引擎销毁后恰好有 mpv / 分析 / 超分事件）；复测方法：播放过视频或开着音乐分析队列时把 app 从最近任务划掉，`adb logcat` 不应再出现 `Callback invoked after it has been deleted`。引擎销毁后 Dart 侧状态（库连接、播放器）随 isolate 一起丢弃、原生侧句柄泄漏到进程结束，这是 audio_service 销毁引擎本身的语义，本修复只保证原生侧不再把进程带崩。
