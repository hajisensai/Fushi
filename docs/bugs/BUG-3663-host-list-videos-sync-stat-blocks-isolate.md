## BUG-3663 · 网络盘上的视频让 Fushi 主 isolate 卡数秒（互联 host 列表与 UI 一起冻结）
- **报告**：2026-10-23（用户：读有声书期间互联 host 的 `/api/library/books`、`/api/library/videos` 同时卡 4–16.7 s，平时 60–160 ms）
- **真实性**：✅ 真 bug，但根因不在 DB。现场实测：卡顿期间无鉴权、零 DB 的 `/api/ping`（`packages/fushi_engine/lib/sync/fushi_sync_server/pairing.part.dart:465`，同步返回）与 videos **同起同落**卡 13.5 s / 5.6 s / 3.7 s（2026-10-23 17:28–17:29，并发轮询），进程 CPU 低于空闲基线（probe.txt 17:25:57 那次 4.0 s，cpu 9% < 空闲 15–22%）——是主 isolate 被同步调用堵住，不是 DB 队列在排。每次卡顿都与 rclone→OpenList（夸克网盘，`--dir-cache-time 1m`）日志里一串串行 PROPFIND 精确对齐（每级 0.15–4.4 s）。库里 99 个视频有 64 个在 rclone 挂载盘 `Z:` 上，两部合集的海报 / 附加图也在 `Z:`。只轮询 ping、不碰 videos 的 4 分钟对照组：最长 0.99 s，无秒级卡顿。互联 host 跑在 app 主 isolate 上（服务端无 isolate），主 isolate 上任何对网络盘的同步 stat 都会冻结全部端点和 UI。
