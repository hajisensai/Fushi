## BUG-3663 · 视频页查词浮层压在之后推入的页面之上，点击被 barrier 吃掉并续播
- **报告**：2026-10-23（用户：反馈 5yWS2o6U6q「进入反馈的时候查词取消了，导致视频继续播放了。视频继续播放的时候进入下一级，会把反馈压住」，Windows 3.0.0-debug.20677，反馈入口是应用内悬浮球）
- **真实性**：✅ 真 bug（代码路径 + Flutter 源码 + widget harness 复现）。视频页把查词浮层子树（整屏 dismiss barrier + 弹窗层）手动 `insert` 到**根 Overlay**（`fushi/lib/src/pages/implementations/video_fushi_page.dart:7250-7252` `_syncPopupOverlay`），这个 entry 不属于任何路由，也从不看本页路由是否还在栈顶。`Navigator` push 时走 `Overlay.rearrange`，把不在路由列表里的 entry 原样插回**最顶**（Flutter 3.47.6 `packages/flutter/lib/src/widgets/overlay.dart:840-845`，`_insertionIndex(null, null) == _entries.length`）。于是查词浮层开着时从悬浮球打开反馈中心（`openFeedbackCenter` → 根导航整页路由）：① 反馈页被弹窗与 barrier 压住（「会把反馈压住」）；② 在反馈页上点任何地方先落到 barrier（`video_fushi_page.dart:7303` 起的 `Positioned.fill` barrier），被判成「点浮层外面」→ `_popNestedPopupAt(0)` → 关栈汇聚点按 `_pausedForLookup` 恢复播放（`video_fushi_page.dart:7122`，「查词取消了、视频继续播放」）；③（推测，未实测）浮层可见时 barrier 的 hover / 点击换词按**被盖住的视频页**的字幕几何反查（`_subtitleHitTester` 读登记字符的 RenderBox，离屏页面仍挂着），落在原字幕位置时可在反馈页上再起一次查词——即用户说的「进入下一级」的一种可能。BUG-797/1040/1327/1364 只给「本页自己弹的对话框」接了让位计数（`dictionary_page_mixin.dart` `_popupHidingDialogDepth`），别处推上来的路由完全没覆盖。
- **[x] ① 已修复** — `DictionaryPageMixin` 新增 `lookupOwnerRoute` / `lookupOwnerRouteCovered`（`fushi/lib/src/pages/implementations/dictionary_page_mixin.dart:261-279`）：宿主声明浮层跟随的路由，它不是栈顶时并进既有让位门 `lookupPopupHiddenByDialog`——弹窗层停靠屏外（`:985`）、搜索占位卡不画、barrier 不挂（`shouldShowLookupDismissBarrier` 已接这道门）、悬停离开自动续播不触发（`shouldAutoResumeOnHoverLeave(hiddenByDialog:)` 已接）；**不关栈**，查词会话与「因查词暂停」原样保留，视频保持暂停，回到视频页浮层复原。视频页覆写 `lookupOwnerRoute`（`video_fushi_page.dart:7209`，窗口 = 本页路由、全屏 = 全屏路由，与键盘所有者同口径）；新增 `LookupOwnerRouteProbe`（`fushi/lib/src/pages/implementations/dictionary_popup_layer.dart:425`）经 `ModalRoute.isCurrentOf` 订阅栈顶状态，挂在窗口侧（`video_fushi/layout.part.dart:99`）与全屏路由（`video_fushi/fullscreen.part.dart:227`，在悬浮球场景之内、`VideoFullscreenBackScope` 之外），变化时帧后刷新根 Overlay entry；`_lookupAt` 入口在被盖住时不起新查词（`video_fushi/lookup_favorite.part.dart:42`）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/lookup_overlay_owner_route_cover_test.dart`：与宿主同构的根 Overlay harness，「不跟随路由（修复前）」钉死旧层序（后推整页上的按钮点不到、点击落到 barrier）；「跟随路由」断言被整页盖住时 barrier 不挂、弹窗停到屏外、新页面按钮可点、会话保留，pop 后复原（把 mixin 门里的 `lookupOwnerRouteCovered` 去掉变异实测变红）；另有三条源码守卫钉视频页接线；`advanced_mining_dialog_zorder_guard_test.dart` 钉的 mixin 弹窗层门字面量随之改成 `!lookupPopupHiddenByDialog`，并断言计数仍在门里（owner route 取法、两处探针、`_lookupAt` 门控在暂停之前）。
- **备注**：未修的同族入口——悬停发起的查词会话里，指针从画面移到悬浮球上：悬浮球挂在导航之上（`fushi/lib/main.dart` 的根 `Stack`），barrier 的 `MouseRegion` 收到 exit → `_handlePointerLeftLookupSurface` 起 320 ms 意图确认表 → `_fireHoverLeaveResume` 判「指针离开查词面」关栈续播。这发生在推反馈路由**之前**，本修复挡不住；「指针移到全局悬浮球算不算离开查词面」是产品取舍，未改，见反馈处理回报。首页词典页 / texthooker 也把浮层挂在根 Overlay，同样不跟随路由，但它们没有「暂停 / 续播」副作用，本次未接（覆写 `lookupOwnerRoute` + 挂探针即可）。
