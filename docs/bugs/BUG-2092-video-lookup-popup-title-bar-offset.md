## BUG-2092 · 视频页查词弹窗在 Windows 窗口模式整栈下移一个标题栏高压住被查词
- **报告**：2026-09-03（用户：视频字幕查词「弹窗出来的时候就已经压到文字上面了」，截图：Komi-san NF 内嵌 .ass 英字，弹窗底边切掉字幕上半截）；2026-09-04 用户从**字幕列表**再报一次（「字幕列表查词框不应该挡住词」），同一根因、另一入口（`_handleSubtitleListLookup` → `_lookupAt` 走同一条 `_calcMixinPopupPosition` 收口）。像素复核：弹窗渲染底边 1999 物理，减 32 逻辑（=64 物理）得算出底边 1935，对应被查词行盒顶 ≈1943 —— 整行落在弹窗底边之下；「上方」分支的选取条件（roomBelow 不足、roomAbove 充足）亦自洽。此前修复只躺在 `worktree-video-subtitle-lookup-rect` 分支、从未开 PR，故用户仍在复现
- **真实性**：✅ 真 bug。根因 `fushi/lib/main.dart:1966`——Windows 上 `FushiWindowsTitleBar` 把 `FushiAppUiScale(导航器)`（含根 Overlay）放在一条 32 逻辑像素、**不随界面缩放**的自绘标题栏之下，根 Overlay 原点比屏幕原点低 32px。四个根 Overlay 查词宿主（video / 首页词典 / texthooker / 网页视频）走同一条 `DictionaryPageMixin._calcMixinPopupPosition`（`dictionary_page_mixin.dart:226`），把被点字符 `localToGlobal` 的**屏幕 rect** 直接当 Overlay 坐标交给 `resolvePopupRect`，浮层整栈下移 32px；「贴在被查词上方」的弹窗底边正好压进词里。全屏（`FushiWindowsTitleBar` hideFrame）时标题栏消失、偏移归零，故只有窗口模式中招。阅读器家族早已用 `overlayBox.globalToLocal` 换算（`reader_fushi/chrome.part.dart:498`，BUG-1438），mixin 家族漏了。像素复核：截图 DPR 1.5、`popup_max_width/height`=865/591 × `app_ui_scale` 1.4，弹窗宽高/左右缘与设置严丝合缝，底边比字符行盒顶边低 ≈35±3 逻辑像素 ≈ 标题栏 32。
- **[x] ① 已修复** — `dictionary_popup_layer.dart` 新增 `rootOverlayScreenOrigin(context)`（根 Overlay 左上角的屏幕坐标；无根 Overlay / 未布局返回零）；`_calcMixinPopupPosition` 在唯一收口处 `selectionRect.shift(-origin)` 后再交给 `resolvePopupRect`，首层 / 嵌套 / 搜索占位三条入口一并归正，无偏移时零位移、历史行为不变。提交 `24785b3f2c`。
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_lookup_popup_overlay_test.dart`：① harness 用例——导航器上方压 32px 标题栏、缩放 1.0/1.4 下裸屏幕 rect 恰偏 32px、减去 `rootOverlayScreenOrigin` 后贴回字符；② 无标题栏时原点为零；③ 源码守卫——`_calcMixinPopupPosition` 函数体必须含 `selectionRect.shift(-rootOverlayScreenOrigin(context))` 且 `resolvePopupRect` 吃换算后的 `layerSelection`；④「上方分支重叠判据」用例（2026-09-04 补）——被查词贴画布底部使下方装不下弹窗、走 `calcPopupPosition` 的**上方**分支，断言未换算时弹窗底边压进词里（恰深 `标题栏 - gap`）、换算后 `popup.bottom <= char.top` 零重叠。①②只覆盖下方分支（那里下移只是留出空隙、看不出压词），而用户可见症状恰是上方分支，故单独钉死。变异实测：把该用例里的 `shift(-rootOverlayScreenOrigin(...))` 撤成裸 `charScreen` 即红。
- **备注**：Phase B 拖拽尺寸的冻结左上角 `_popupResizeAnchorTopLeft` 只在拖拽被取消时清空，注释写的「换词/关窗即失效」实际靠 `_popupResizeAnchorSelection == selectionRect` 近似——同一字符重复查词时冻结原点仍生效，弹窗从冻结点向下长可能再次压词；本条未改，另议。
