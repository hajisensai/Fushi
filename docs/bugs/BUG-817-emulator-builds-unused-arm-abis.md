## BUG-817 · 手机模拟器集成构建误编ARM导致SQLite下载超时
- **报告**：2026-07-15（用户：修复手机模拟器问题）
- **真实性**：✅ 真 bug。仓库规定的 `ci/integration-test.sh --only=app_smoke` 能正常启动 `hibiki_gpu_test` AVD，但原脚本在 `ci/integration-test.sh:116` 用未限定目标平台的 `flutter build apk --debug` 构建模拟器 APK，Flutter native-assets 因而同时处理 ARM 与 x86_64，随后 sqlite3 3.3.3 的 native hook 尝试从 GitHub 下载模拟器根本不会使用的 `libsqlite3.arm.android.so` 并超时。把 Flutter 构建限定为 `android-x64` 后，第二层问题随即暴露：vendored `third_party/media_kit_libs_android_video/android/build.gradle` 虽收到 Flutter 的 `-Ptarget-platform=android-x64`，仍会遍历四种 ABI 的 libmpv JAR，先下载无关的 `full-arm64-v8a.jar` 并同样超时。两处共同根因都是“模拟器专用构建没有把依赖准备范围收窄到 AVD 的 x86_64 ABI”，不是 AVD 启动故障。
- **[x] ① 已修复** — `ci/integration-test.sh:115-116` 将模拟器总编排改为 `flutter build apk --debug --target-platform android-x64`；`third_party/media_kit_libs_android_video/android/build.gradle:70-94` 为每个 JAR 标注 ABI，读取 Flutter `target-platform` 并只下载目标 ABI，未传/无法识别目标平台时仍保留原有全 ABI 回退，避免改变普通 fat/release 构建语义。
- **[x] ② 已加自动化测试** — `hibiki/test/tools/integration_test_runner_android_abi_guard_test.dart:30` 守卫模拟器总编排必须传 `android-x64`；`hibiki/test/build/libmpv_truehd_guard_test.dart:116` 守卫 vendored downloader 读取 Flutter 目标平台并把 `android-x64` 映射为 `x86_64`。两文件合跑 6/6 通过。
- **备注**：真实回归使用版本 `1.2.0`（debug `versionCode=1000072300`）与 `emulator-5554`：`ci/integration-test.sh --only=app_smoke` 完成 x86_64 Flutter 构建、安装、权限准备及启动检查，`app_smoke` 1/1 通过，日志在 `.codex-test/itest-logs/app_smoke.log`。Gradle 打包门禁 `hibiki/android/gradlew.bat :app:assembleRelease` 亦通过；首次运行命中 BUG-146 已知的陈旧 `GeneratedPluginRegistrant.java`，按既有构建前清理策略删除该生成物后重跑成功。外网仍不稳定，验证复用了主工作区内 MD5 已匹配上游固定值的 sqlite/libmpv 本地缓存；fresh worktree 的失败日志已证明修复后只需 `full-x86_64.jar`，不再请求 ARM libmpv JAR。
