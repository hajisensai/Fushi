## BUG-4392 · 吊销已配对设备后，它签出的视频流 / 原盘 / 音频链接仍可用，老客户端拿到的共享 token 也无法单独吊销
- **报告**：2026-11-10（用户：互联 host 安全审查 H5）
- **真实性**：✅ 真 bug。（行号按 94317ab6295）派生凭据不记签发者：`packages/fushi_engine/lib/sync/fushi_sync_server.dart:1762-1800` 的 `_VideoStreamToken` 没有签发者字段，签发于 `fushi_sync_server/video.part.dart:105-117,151`，校验于 `:245,:1080,:1156` 只看 videoId / TTL；`disc_share_routes.dart:37-50` 的 `DiscShareSession`（签发于 `video.part.dart:53`）与 `remote_lookup_routes.dart:174,229` 的 `RemoteAudioTokenStore.mint` 同样不记。`invalidatePeerTokenCache` 碰不到这三张表，吊销后最长 6 h / 12 h / 5 min 内仍可用。共享 token 仍被下发：`fushi_sync_server/pairing.part.dart:46` v1 `/api/pair` 返回 `_token`；`:406-416` 的 `_issuePeerTokenOrFallback` 在会话没有 `clientDeviceId` 时回退 `_token`，不落库、不能单独吊销。修复前实测：新测试里 peer 签出的流 URL / 原盘 manifest / 音频 URL 吊销后均仍 200；v1 与无 deviceId 的 v2 confirm 都返回共享 token。
- **[x] ① 已修复**（`a92a3d26c58`）— 引擎：auth.part 加 `_requestCredentialFingerprint`（Basic 密码 → 凭据指纹）与 `_issuerStillValid`（指纹在当前凭据快照里）；`_VideoStreamToken` 加必填 `issuer`，`/streamurl` 两处签发填本请求凭据指纹（取不到回 401），`/stream`、HLS、蓝光分段三处校验在 videoId 检查后核对签发者，失效即删 token 回 403；`DiscShareSession` / `DiscShareTokenStore.issue` 加 `issuer`，`handleDiscShareRequest` 加可选 `issuerValid`，失效删会话回 403；`RemoteAudioToken` / `mint` 加 `issuer`，`RemoteLookupRoutes` 加 `issuerOf` / `issuerValid`，`handleAudioFile` 改为 async、失效作废 id 回 403（`FushiApiServer` 不接，行为不变）。新常量 `kFushiLegacyPeerIdPrefix = 'legacy-'`；`_issuePeerTokenOrFallback` 改为 `_issueAccessToken`：接了 `onPeerPaired` 时无 deviceId 的配对（v1 `/api/pair` 审批通过后、不带 deviceId 的 v2 confirm）落一行 `legacy-<随机>` 的 per-peer token（恒非「我的设备」、不记设备钥匙），落库失败抛出不回退共享 token；未接线仍回共享 token。新 provider `pairedPeerCredentialsProvider`（peerId → token），`legacy-` 行进快照的 `legacyPeerTokens`：`_validateAuth` 认、`_validatePeerAuth`（敏感服务门）不认，权限同共享 token；没接新 provider 时退回 `pairedPeerTokensProvider`。app `fushi_server_controller.dart` 与无头 `headless_host.dart` 改接新 provider。
- **[x] ② 已加自动化测试** — 新 `fushi/test/sync/fushi_sync_server_derived_token_revoke_test.dart`（真 server：peer 签出的流 URL 吊销后 403 且再次仍 403；共享 token 签出的流 URL 不受株连；原盘 manifest 吊销后 403；查词音频 URL 吊销后 403）；`fushi/test/sync/fushi_sync_server_peer_token_test.dart`（无 deviceId 的 v2 confirm 与 v1 `/api/pair` 都发 `legacy-` 行 token、能鉴权、删行后 401；legacy token 与共享 token 一样被 `/api/host/update` 的已配对设备门拒、带 deviceId 的 peer token 通过；原「回退共享 token」用例按新契约改写）；`fushi/test/sync/remote_lookup_routes_test.dart` 跟随 `handleAudioFile` 改 async。
- **评审修正（2026-11-11，`e24e2b98b24`，仅测试）**：`fushi_sync_server_derived_token_revoke_test.dart` 吊销后两次请求改比响应体（第一次 `Token revoked`、第二次 `Invalid or expired token`，证明作废的 token 已从表里删除）；补 HLS playlist（`hls.m3u8`）、HLS 分段（`hlsseg.ts`）与蓝光分段（`bdclip.m2ts`）三条路径的吊销用例（吊销前 token 被认落 404、吊销后 403 `Token revoked`）。制卡用转码 token（`video.part.dart` 光盘标题 + 转码开启时签发）与主 token 共用同一个 `issuer` 变量，取用走同一个 HLS handler；它的签发需要本机 ffmpeg 与转码偏好，未单独加用例。
- **备注**：wire 形状不变（契约 F）。已持共享 token 的老设备照旧可用、仍不能单独吊销（取舍 T5）；同一老客户端每重配一次多一行 `legacy-`。吊销不切断正在发送的单个直传响应，下一次 Range / 下一个 HLS 分段才 403（取舍 T4）。
