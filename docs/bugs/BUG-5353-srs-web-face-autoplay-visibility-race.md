## BUG-5353 · srs-web-face-autoplay-visibility-race
- **报告**：2026-11-24（用户：应用内反馈 FJXqvneRRp，Android 3.4.0-debug.31707）
- **真实性**：✅ 真 bug。复习时翻面常常不自动播单词 / 例句音频（自动播放开着，AnkiDroid 正常）。日志 `SrsCardFace.webFallback noteType=Kuzuma✨ tpl=Recognition reason=html: <script>`：卡面走整面 WebView。录屏 v0：答案面整块从透明淡入（约 150 ms），三次翻面只有一次有声。根因在 `fushi/lib/src/pages/implementations/srs/srs_card_face.dart` 的 `reportSounds`（旧版在 `finish()` 里同步调用）+ `fushi/lib/src/srs/srs_card_autoplay.dart` 的 `shown()`（旧 `parseFloat(cs.opacity) === 0` 直接判隐藏）：页面判「哪些发音键看得见」是在换卡同一个任务里、卡片脚本刚跑完时同步取的，页面一帧都没画，模板的入场效果停在第 0 帧 opacity:0，整面发音键被判成看不见，宿主自动播放清单（`srs_review_page.dart` `_autoplayAudio` / `_onVisibleSounds`）为空。真实 headless Chrome 复现：CSS 关键帧淡入与「脚本下一拍加类名触发过渡」两种写法修前都报 `[]`。
- **[x] ① 已修复** — `srs_card_autoplay.dart` `fadingOpacity()`：祖先上有一条还在跑、且动的是 opacity 的动画 / 过渡时，这一层的 opacity:0 是过渡态，不当隐藏；`srs_card_face.dart` `afterFirstFrame()`：可见发音等这一面第一帧画出（两次 rAF）再判并上报，页面转入后台立刻报、1 秒兜底只防「声称可见却不出帧」的 WebView 让宿主一直等；`shownSeq`：换主题赶在慢卡外部脚本加载期间时不报半成品。静态隐藏（display:none、定住的 opacity:0、收起的 details）判定不变（HrB0STYm3E 不回退）。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_card_visible_sounds_entrance_test.dart` + `srs_card_visible_sounds_entrance_harness.mjs`：真实 headless Chrome 跑生产外壳，CSS 关键帧淡入 / 脚本触发过渡的答案面发音键报成可见、每面只报一次、带对面标记；静态隐藏副本仍不报。修前红（两种淡入都报 `[]`），修后绿。`srs_card_anki_dom_contract_harness.mjs` 改为等上报到达再断言。
- **备注**：Kuzuma 模板原文拿不到，按录屏里的淡入现象与代码路径复现；若模板用的是 `window.onload` / 字体加载完才去掉 opacity:0 这类晚于首帧的揭示方式，本修复覆盖不到，需拿到模板再看。
