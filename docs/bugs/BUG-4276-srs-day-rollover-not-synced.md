## BUG-4276 · 复习的「今天」日界不随同步、profile 时区字段从没有写入方
- **报告**：2026-11-10（所有者：SRS 多设备「今天」口径审查）
- **真实性**：✅ 真 bug。`SrsDbStore.dayContext()`（`packages/fushi_engine/lib/srs/srs_db_store.dart` 修复前 961–980 行）读 profile 实体的 `dayRolloverHour` / `utcOffsetMin`（`packages/fushi_srs/lib/src/field_edit.dart:154-155`），缺失时回落本机统计日界与本机偏移；但 `fushi/lib`、`packages/*/lib`、`native/fushi_fsrs/src` 里没有任何写入方（`git log -G` 查到这两个键在 lib 里只在 61da4d35d5f / f341d8ec74f 出现过读取与显示名，从没写过）。结果：两台设备统计日界不同时各算各的「今天」（每日上限、到期、今日计数各不相同），「随同步」只是注释里的设计；`utcOffsetMin` 是一条永远读不到值的死分支，按固定偏移同步时区还会在夏令时 / 换时区时出错（`day.dart` 文件头）。
- **[x] ① 已修复** — 翻日时刻接上写入方：用户在统计设置里改日界走 `AppModel.setStatDayResetHourByUser`，本机偏好之外写一条 profile `dayRolloverHour` 字段修改（`SrsDbStore.setDayRolloverHour` → `editField`，随同步 v2 传播）；同步拉入后 `SrsAppRuntime.adoptSyncedDayRollover` 把显式值单向跟到本机统计日界（`AppModel.adoptSyncedDayRolloverHour`，不写回复习）。时区恒用本机：`dayContext` 不再读 profile `utcOffsetMin`，`SrsDbStore.open` 新增 `localOffsetMin`（缺省系统时区）；删掉死常量 `SrsFieldKeys.utcOffsetMin`。首次开复习补 4 点的默认值路径仍只改本机偏好，单设备用户行为不变。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/srs_day_rollover_synced_test.dart`（回落值不变 / 写入即生效 / 经同步另一份库取到同值 / 存量 `utcOffsetMin` 不再生效 / 改日界后内核每日新卡上限按新「今天」重算）；`fushi/test/srs/srs_day_rollover_user_write_test.dart`（用户写入两处都落、默认值路径不写复习、同步值单向跟到本机、复习不可用时只改偏好）。
- **备注**：未在真 app 里看过统计设置弹窗（文案未改，只换了写入入口）。复习模块关着时改的日界不写复习字段，之后再开复习、若复习里留着更早的同步值，两者会不一致，直到下次在设置里改日界。
