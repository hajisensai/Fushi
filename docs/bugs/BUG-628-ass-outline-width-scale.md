## BUG-628 · 外挂ASS描边宽未随PlayResY缩放（尊重自带样式仍不够忠实）
- **报告**：2026-07-08（用户：ASSx2 外挂 .ass「尊重字幕自带样式」启用没用、没什么很大区别、还是没颜色之类的。文件 `[Nekomoe kissaten&LoliHouse] Shunkashuutou Daikousha - Haru no Mai - 06 [WebRip 1080p HEVC-10bit AAC ASSx2][JPN].ass`，TODO-1246 续 BUG-571/591/604）
- **真实性**：✅ 真 bug（描边宽缩放缺失）+ 澄清「没颜色」多为观感等价。沿真实代码路径全链复核并用用户真文件实测：
  - **架构确认**：Hibiki 视频文本字幕**不经 libmpv/libass 渲染**——`video_player_controller.dart:1364-1372` 对文本轨恒 `setSubtitleTrack(no())` + `sub-visibility=no`，字幕只由 Flutter 自绘 `VideoSubtitleOverlay` 渲染（为逐字查词）。故「尊重自带样式」只能在 overlay 里**复刻** ASS 样式，与 mpv `sub-ass-override` 无关；切 libass 原生渲染会毁掉查词，非正解。
  - **管线本已通（实测用户真文件）**：`AssParser.parseString` 正确把 `[V4+ Styles]` 解析成 `SubtitleCueStyle`（本文件所有 Style 的 `PrimaryColour=&H00FFFFFF` 白、`OutlineColour` 黑/褐、`Fontsize=65`、`Outline=2.5`）；`setCues` 保留 markup；单视频重开由 `_loadSingle` 的 `_rehydratableExternalSubtitlePath`→重解析恢复 markup（BUG-571，`video_hibiki_page.dart:2223`）；overlay `_styleForGrapheme`/`_resolveStroke` 在 respectAssStyle 开时把主色→填充、描边色→描边层。widget 级实测：respect 开 → 填充白、描边褐(Text_JP)/黑(Text_JP2)、字号 65×显示高/1080≈36。
  - **「没颜色」根因＝观感等价，非渲染 bug**：本文件正文主色**全部是白**（无一条 `\c` 行内色，180/373 条 Text_JP2 描边色**黑**），恰与 Hibiki 默认字幕外观（白字黑描边，`video_subtitle_style.dart:224` defaults）像素级一致 → 尊重后视觉几乎无变化，用户如实观察。**唯一**真正的忠实度缺陷是描边宽：
  - **描边宽缩放缺失（本 bug 的真根因）**：`hibiki/lib/src/media/video/video_subtitle_overlay.dart:699` `_resolveStroke` 返回 `outlineWidthPx` 的**裸 PlayRes 像素**（2.5），而字号已在 BUG-604 按 `显示区高/PlayResY` 缩放。ASS `Outline`/`\bord` 与字号同为相对 PlayResY 的绝对像素（本文件 `ScaledBorderAndShadow: yes`，描边本应随画面缩放）；小于 PlayResY 的显示区里，描边相对**已缩放**的字号偏粗——大制作字幕设计的细描边被渲成一圈过重黑边，与真播放器/ASS 设计不符，尊重开关名不副实。实测：显示高 360 / PlayResY 720 时字号 48→24（缩放 0.5），但描边 4→仍 4（未缩放）。
- **[x] ① 已修复** — `video_subtitle_overlay.dart` `_resolveStroke`：ASS 来源的描边宽（`span.\bord ?? cueStyle.Outline`）乘 `_assFontScale(markup)`（=显示区高/PlayResY，与字号同源）再夹 `[0.5, 24]`（防 PlayResY 缺失/异常时描边消失或撑爆，与 `_resolveAssShadows` 深度夹同量级）；回退用户统一描边宽（`baseWidth`，已逻辑像素）时不缩放，respect 关时恒统一宽——历史像素级不变。前次颜色/描边色/字号/阴影/`\r`（BUG-571/591/604）未回退。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_subtitle_overlay_markup_test.dart` 新增 3 例：① ASS 描边宽 `4 @ PlayResY720 在 360px` → `2.0`（描边层 `foreground.strokeWidth`，与已有字号 48→24 缩放同构）+ 描边色蓝仍生效；② 无 PlayResY → 裸 4.0（向后兼容）；③ respect 关 → 恒用户统一宽 5.0，不吃 ASS 的 4。overlay markup 全组 15 例绿；`ass_parser_test`/`subtitle_markup_test`/`video_subtitle_ass_style_rehydrate_test` 复跑绿。
- **备注**：真机验收口径：装本 develop 版设备，用**含彩色/细描边设计**的外挂 .ass（如具名 Sign 橙色、或描边宽≠默认的字幕）验证开关开时字幕呈现 .ass 自带颜色 + 忠实（缩放后）描边粗细、关时回统一外观。**对本文件（白字黑描边）尊重前后仍近似等价属预期**——文件本身无彩色正文，overlay 不可能凭空造色；若用户要「字幕更花」需换含彩色主色/描边的 .ass 或双语轨。ASS 自带**字体**（FOT-Matisse ProN B / HYXuanSong）未安装时仍走 CJK 回退链（无法内置商用字体，超范围）。
