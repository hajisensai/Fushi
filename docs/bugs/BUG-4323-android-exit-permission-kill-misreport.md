## BUG-4323 · Android 权限变更导致的系统杀进程被误报为闪退
- **报告**：2026-11-10（应用内崩溃报告：反馈 DyamYE6bPL、g8AEGUyQBU）
- **真实性**：✅ 真 bug，已在 origin/develop 704f8c6bd9 沿代码路径确认。DyamYE6bPL（小米，SDK 34）：同一 pid 的 `ApplicationExitInfo` 是 `reason=PERMISSION_CHANGE importance=100 description: permissions revoked`（用户撤销运行时权限）；g8AEGUyQBU（OPPO，SDK 37）：`reason=OTHER importance=100 description: [KILL UID] MANAGE_EXTERNAL_STORAGE changed.`（在系统设置里改「所有文件访问权限」，AOSP `StorageManagerService` 调 `killUid(..., opToName(op) + " changed.")`，`AppExitInfoTracker` 加子原因前缀 `[KILL UID]`）。两条都是系统对用户权限操作的标准反应，却都弹了闪退报告。
  - 根因：`fushi/lib/src/diagnostics/previous_exit_log.dart:561`（修复前）`androidExitKind` 的 switch 没有 `PERMISSION_CHANGE` 分支，`OTHER` 一律返回 null 且不看 description；条目没有种类 → `classifyPreviousExit` 只剩会话标记的推断（resumed / importance 100）→ `PreviousExitKind.unexpected` → `worthReporting` 为 true → 上报。原生侧 `ProcessExitChannel.java:267` 已把 `REASON_PERMISSION_CHANGE` 转成字符串、description 也已传上来，缺的只是 Dart 侧分类。
- **[x] ① 已修复** — 新增 `PreviousExitKind.permissionChanged`（排在 `userStopped` 之后、压过会话标记推断，`worthReporting` 恒 false；提示文案沿用既有 unexpected 标签，因为该种类不会弹提示，无新 i18n key）。`androidExitKind(reason, {description})`：`PERMISSION_CHANGE` → `permissionChanged`；`OTHER` 仅当 description 整串匹配 AOSP 形态 `^\[KILL UID\] [A-Z][A-Z0-9_]* changed\.?$` 时 → `permissionChanged`，其它 `OTHER`（`OneKeyClean`、ColorOS `o-stop(40)` 等厂商文本）照旧 null。`formatAndroidExitReports` 把条目的 description 传进去。ColorOS `o-stop` 不在本修复范围（待用户拍板）。
- **[x] ② 已加自动化测试** — `fushi/test/diagnostics/previous_exit_log_test.dart`「Android：同一 pid 的死时重要性压过会话标记的前后台推断」组：经真 `PreviousExitLog.collect` + `classifyPreviousExit`，`PERMISSION_CHANGE` 与 `OTHER + [KILL UID] MANAGE_EXTERNAL_STORAGE changed.` 两例判 `permissionChanged` 不上报，`OTHER + 无关描述` 仍判 unexpected 上报；`androidExitKind` 单测钉住锚定（前缀夹杂、非 `<OP> changed` 形态、非 OTHER 原因码均不改判）。测试未在本分支运行，统一在合并后验证。
