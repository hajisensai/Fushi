## BUG-4906 · 互联 host 同步根堆积已无人读取的客户端文件箱书文件夹
- **报告**：2026-11-21（用户：开发者本人，Windows 安装版当互联 host）。`%APPDATA%\Fushi\Fushi\sync-data\fushi-data\` 占 8.2 GB：四十多个以书名命名的文件夹（`.epub`、有声书 `.m4b`、`progress_*.json`、`audioBook_*.json`）合计约 6.7 GB，其中 m4b 与 host 本机书库里的同名文件字节数完全一致；`fushi-srs/<profile>/` 另占 1.4 GB（见备注）。
- **真实性**：✅ 真 bug（磁盘泄漏，行号为修复前 upstream/develop 76811fc25da）。
  - 写入方：互联客户端的 `SyncManager` 书阶段经 `InterconnectSyncBackend`（`WebDavPathBackendMixin.ensureBookFolder`，`fushi/lib/src/sync/webdav_path_backend_mixin.dart:40`）把每本书的文件箱写进 host 的 WebDAV 根 `<sync-data>/fushi-data/<书名>/`。书内容（epub / 音频）只有很老的版本会传（v2.7.0 起 `managerSyncContent = isInterconnect ? false : …`，v2.9.1 起 `_fileBoxIsClientOwned` 门），进度 / 统计 / 有声书断点 JSON 一直写到 d2b6d0966ff（2026-11-07）才停（`fushi/lib/src/sync/sync_orchestrator.dart:1051` 互联不跑书阶段；`sync_manager.dart:700`、`:1262` 的 `_fileBoxIsClientOwned` 门）。截至报告日最新正式版 v3.3.0（11-06）仍会写 JSON。
  - 读取方：host 从不读这些书文件夹。host 读同步根的只有保留命名空间——`fushi-srs`（`fushi/lib/src/srs/srs_app_runtime.dart:400`、`packages/fushi_server/lib/src/server_srs.dart:352`）与 `__pending_mines__`（`packages/fushi_engine/lib/anki_sync/anki_box_landing.dart:45`）；其余 `__x__` 命名空间是客户端之间经 host 交换的共享数据（字典 / 本地音源 / 聚合 / 合集 / 视频 / 墓碑 / 字体 / 设置）。新客户端对比弹窗也不再列文件箱（`sync_compare_dialog.dart:272-282`）。
  - 根因：去掉写入端（d2b6d0966ff 及更早的内容门）时没有任何一处收走已经写下的数据；全仓没有清理 `<sync-data>/fushi-data/<书名>/` 的代码（host 启动 `fushi_server_controller.dart:925` 只做 `hibiki-data` 改名迁移，headless `headless_host.dart:631` 直接 `server.start()`）。于是旧版本写下的 GB 级 epub / 音频永久留在 host 上，存储页只能显示成一整块「sync-data」。
- **[x] ① 已修复** — 新增引擎函数 `pruneDeadInterconnectFileBox`（`packages/fushi_engine/lib/sync/interconnect_file_box_prune.dart`），app host（`FushiServerController`）与 headless host（`HeadlessHost`）都在绑端口前调用：删 `<sync-data>/fushi-data/` 下「名字不是保留命名空间、且目录是平的（只有文件）」的一级目录。保留判据 `isInterconnectFileBoxReservedName` = `__` 前缀或 `fushi-srs`，覆盖全部现存命名空间；带子目录的、根下直接放的文件一律不碰。单目录删失败只记日志，不挡启动，下次启动重试。
  - 旧客户端兼容：v2.7～v3.3 的客户端读到书文件夹没了按「远端缺失 → 导出本机」（`resolveProgressSync(remote: null)`）重写几 KB 的 JSON / 封面，不删本机任何东西；这些残余下次 host 启动再收。早于 v2.7、仍会往文件箱传 epub 的客户端，每次 host 重启后会重传一次书内容（未核实这类版本是否还能连上现在的 host）。
  - 云后端不受影响：改动只在 host 侧本地磁盘，云通道的书文件夹路径一行未改。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/sync/interconnect_file_box_prune_test.dart`（真 `FushiSyncServer` 经 WebDAV PUT 写入旧客户端文件箱 + 全部保留命名空间 → 清理后文件箱没了、保留命名空间 / 带子目录的目录 / 根下文件都在、幂等）；`fushi/test/sync/interconnect_file_box_prune_reserved_guard_test.dart`（扫源码里声明的全部同步命名空间常量都落在保留判据里；两个 host 装配点都在 `server.start()` 前调用清理）。
- **备注**：`fushi-srs/<profile>/` 下 `<44 字符>#<n>/`（v3.0.x 旧事件同步的写入者目录，不是协议 1）与 `v2/`（协议 1 旧根，即围栏）本 PR 不动：`v2/meta.json` 是新版本每轮重立的围栏；写入者目录里的 `media/` 与 `profile.json` 现版本仍在读，`batch-*` / `snapshot-*` 是否可删取决于「是否放弃仍在跑的 v3.0.x 客户端」，属设计取舍，已交用户决定（用户 2026-11-21 拍板放弃 v3.0.x；gen4 下的清理见 BUG-4908，未修复）。
