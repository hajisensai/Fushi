## BUG-5145 · manga-review-stale-session-overwrite
- **报告**：2026-11-22（外部审计 HBK-AUDIT-016，Codex 2026-11-21 PR 审查，PR #4031）
- **真实性**：✅ 真 bug。① `fushi/lib/src/media/manga/audio/manga_audio_review_page.dart`（PR head a771ab0d86）`_syncTask` 在任务结束时先 `setState(() => _task = null)` 解锁、再 `unawaited(_load(...))` 异步重读；读盘窗口里 `_session` 仍是任务前的旧会话，`_commit` 只查 `_busy`（= `_task != null`）就放行，`saveAll()` 把整份旧稿连同旧账本写回，盖掉任务刚写的结果；且两次 `_load` 没有代号，晚到的旧读盘结果也会装上。② `packages/fushi_engine/lib/tts/manga_audio/manga_audio_script.dart` `MangaAudioScriptStore.save` 固定临时名 `<file>.tmp`，同卷两次并发存盘在 Windows 上实测抛 `PathAccessException: Cannot rename file ... (errno = 32)`（8 路并发最小复现）。③ 累积成本：`mangaReviewStartIndex` 对队列每项调 `lineById`（线性扫全卷、每行现拼 `lineId` 字符串），从卷末打开 3000 行卷实测拼 4,474,536 次字符串、886 ms；每确认一句整稿 `jsonEncode(toJson())` 重编全部行，整卷逐句复核 3000 句共 9,000,000 次行 `toJson`、11.8 s。
- **[x] ① 已修复** — 店：`MangaAudioScriptStore` 按规范化路径在进程级静态表上排队读写（排队在调用当下同步发生，按调用顺序执行），并记本进程修订；`load` 给稿子盖 `storeRevision`，新增 `saveIfCurrent` 只在修订未变时写，写后修订前进。会话：新增 `MangaAudioAnnotateSession.saveReviewEdits`（`fushi/lib/src/ai/ai_manga_audio_assistant.dart`）按修订写演出稿、只重做系列档案改动，不再写复核不改的账本。页面：新增 `MangaReviewEditGate`，解锁挂在「最近一次请求的会话装上」而不是「任务结束」；任务结束同一拍先 `beginLoad` 再改状态，读盘按代号认领，旧结果丢弃；`saveReviewEdits` 返回 false 时重开会话并提示 `manga_audio_review_conflict`。成本：`MangaScriptLine.lineId` / `jsonText` 改为 `late final` 缓存（行不可变）；`MangaAudioScript.lineById` / `replaceLine` 改自校验位置索引；`MangaAudioScript.encode` 复用行 JSON；复核队列改 `MangaReviewQueue`（带页号二分 + 身份→位置表），待复核数改增量维护。修后同样样本：卷末定位 0 次拼串、12 次比较、8 µs；整卷逐句复核每句只编码 1 行，共 3000 次、339 ms。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/tts/manga_audio/manga_audio_script_store_revision_test.dart`（旧会话 `saveIfCurrent` 拒写且盘上保留任务结果；8 路并发存同卷都成功按调用序落盘不留临时文件；排队期间读盘看到先排的写；增量序列化与 `toJson` 等价；外部直接改 `lines` 后查行仍准）；`fushi/test/media/manga/audio/manga_audio_review_test.dart` group「编辑锁（HBK-AUDIT-016）」（任务结束到新会话装上前不可改；晚到旧读盘不装不解锁）与改写后的队列用例。变异实测：去掉修订校验、去掉排队、`editable` 去掉 `sessionPending` 三处各自变红。
- **备注**：同构隐患登记——`fushi/lib/src/media/manga/audio/manga_audio_script_page.dart` `_syncTasks`（develop 既有代码，非 #4031 引入）也是任务结束即解锁、异步 `_load()`，读盘窗口里的编辑经 `saveAll()` 整份写回（含账本）。该页编辑入口多，改成按修订写需逐个审，未在本 PR 内改。
