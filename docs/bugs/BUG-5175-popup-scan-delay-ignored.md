## BUG-5175 · 浏览器扩展词典弹窗内悬停扫词不认扫描延迟（侧栏 / 嵌套弹窗连触发键也不认）
- **报告**：2026-11-22（用户：应用内反馈 #r4tpeIzVuD「浏览器扩展悬停查词给词典内部扫描也添加延迟」）
- **真实性**：✅ 真 bug。扫描延迟（反馈 L4Vhk0hOjM，提交 74c36a07379c）只接进网页侧 `tools/browser-extension/content.js:2620`（document mousemove 走 `fushiEffectiveScanDelay`）；查词弹窗内部的悬停扫词走共享的 `fushi/assets/popup/popup.js:10217` `__fushiPopupMouseMove`，只问 `__fushiScanModifierHeld`，「不按键」模式下恒为真，指针每动 8px 就立刻 `selectText`，完全不看 scanDelay——同一个设置在弹窗里失效。另：侧栏（`side-panel.js`）与嵌套弹窗（`nested-popup.js`，独立 realm）都没注入 `__fushiScanModifierHeld`，弹窗内扫词在这两处退回「Shift」，连触发键设置（反馈 ulS75hVkAK）都不认。
- **[x] ① 已修复** — popup.js 认可选钩子 `window.__fushiScanDelayMs`：> 0 时「停稳后扫」（每次 mousemove 重新计时，到点按最后坐标扫；松开触发键 / mouseout 到弹窗外作废，`__fushiPopupMouseMove` / `__fushiPopupMouseOut`，popup.js:10223-10267）；app 内无钩子 = 立即扫，行为不变。审查补：指针从网页滑进弹窗时网页侧排着的待扫没撤（host 截住 mousemove，document 侧收不到后续移动），到点会按弹窗边上的网页坐标再查、换掉正在读的词条；content.js host `mouseenter` 里 `fushiCancelScanDelay()`。三个扩展 realm 各注入同一判据的钩子：content.js:616、side-panel.js:217-218（同时补上触发键钩子）、nested-popup.js:22-61（扩展页，直接读 storage.scanModifier / scanDelay，函数副本受交叉比对守卫）。源头改 `fushi/assets/popup/popup.js` 后 cp 到 `tools/browser-extension/vendor/popup.js`，`node tools/browser-extension/scripts/sync-mirrors.mjs` 同步 assets 镜像。
- **[x] ② 已加自动化测试** — `tools/browser-extension/popup-scan-delay.test.js`（真加载 vendor/popup.js：none+300ms 连续划过只在停稳后按最后坐标扫一次、延迟 0 立即扫、app 无钩子 Shift 立即扫、松开键 / 移出弹窗作废；真加载 nested-popup.js 验钩子随 storage 热更新；侧栏钩子源码守卫）；`shift-hover.test.js` 新增 content.js 钩子用例，并把 nested-popup.js 的四个函数副本纳入逐例交叉比对。变异实测：还原 popup.js 修复 → 2 例红；还原 content.js 钩子 → 1 例红；恢复后全绿。审查补 `hover-leave-resume.test.js`「scanDelay：指针进弹窗撤掉网页侧待扫」，去掉 mouseenter 里的撤销即红。
- **备注**：嵌套弹窗副本是 content.js / side-panel.js 之后第三份同名函数副本（扩展页不装 content.js），漂移由 shift-hover.test.js 交叉比对兜住。
