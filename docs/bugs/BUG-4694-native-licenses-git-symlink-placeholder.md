## BUG-4694 · 原生许可生成器在 core.symlinks=false 的 git 检出里把符号链接许可文件读成目标路径文本，产物随机器而变
- **报告**：2026-11-15（SRS 换代工程线 A 在 #3392 上发现：Windows 上跑 `tool/native_licenses.dart` 后 `percent-encoding-iri` 的许可换了文本，并删掉 `fushi/assets/licenses/native/` 下两份已入库文件）
- **真实性**：✅ 真 bug，但方向与现象描述相反——**入库产物才是错的**。`percent-encoding-iri@2.2.0` 是 cargo git 依赖（ankitects/rust-url@bb930b8），子目录 `percent_encoding/LICENSE-{MIT,APACHE}` 在 git 里是指向 `../LICENSE-*` 的符号链接（模式 `120000`）。在 `core.symlinks=false` 的环境（Windows 无建链权限时 git / libgit2 的默认）检出时链接被写成内容为 `../LICENSE-MIT` 的普通文本，`fushi/tool/native_licenses.dart:522`（`_rustLicenseFiles` → `_licenseFilesIn`）把它当许可原文读入，于是入库的 `4201a739d99186cf.txt` / `71430174df61bd45.txt` 内容就是 `../LICENSE-APACHE` / `../LICENSE-MIT` 这一行路径。能建真链接的机器（Linux / macOS、开了开发者模式的 Windows）读到真原文，产物就变成「删两份、加 `76e972ac0f4ddb11.txt`、Apache 归入已有的 `143368af9701a24e.txt`」——线 A 看到的就是正确产物。复现：把 cargo 检出里的链接换成占位文本，旧工具重跑与入库产物逐字节一致（index.json 零差异）；恢复真链接重跑即得上述差异。
- **[x] ① 已修复** — `resolveNativeLicenseSymlink`（`fushi/tool/native_licenses.dart`）：非 registry 依赖的许可文件按 git 索引模式 `120000` 判定符号链接，目标取自 git 对象（与检出成真链接还是占位文本无关），相对链接所在目录逐跳解析；越出检出根 / 目标不存在直接报错，不退回占位文本。registry crate 不受影响（`cargo package` 打包时已解引用）。同时用修好的工具重新生成产物。验证：真链接检出与占位文本检出两种环境下重跑，`index.json` 的 git blob 都是 `6cd8def951f`，许可文本 548 份一致。
- **[x] ② 已加自动化测试** — `fushi/test/build/native_license_symlink_test.dart`：真 git 仓库按 `core.symlinks=false` 检出符号链接条目（占位、链式、反斜杠目标、普通文件、非 git 文件、越界、目标缺失）。
