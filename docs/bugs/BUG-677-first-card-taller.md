## BUG-677 · 查词弹窗首个词典卡片比其他卡片高
- **报告**：2026-07-09（用户：查词弹窗「卡片没抄到 Niratan 精髓·第一个卡片会比其他卡片高」）
- **真实性**：✅ 真 bug — 根因 `hibiki/assets/popup/popup.css:913`（`.glossary-section > .category-body` 缺 `align-items`，走 CSS grid 默认 `align-items:stretch`）。多词典查词时每部词典渲染成一枚 `.glossary-group` 玻璃卡片，作为 `repeat(var(--dict-columns,1), minmax(0,1fr))` 网格项（桌面 TODO-1357 默认 2 列）。grid 默认 `align-items:stretch` 把同一行的卡片全部拉伸到该行最高卡片的高度：首行常含义项最多的词典（idx 0），被拉高后同行义项少的卡片下方留出大片空白玻璃盒，读作「第一个卡片特别高」。对照 Niratan（`W1ght/Niratan` `Features/Popup/popup.css` `.glossary-group` + `popup.js` `layoutMasonry`）：其卡片是自然内容高度（单词典 `display:block` 单列；多词典 JS masonry 按最短列打包），从不等高拉伸——这正是用户说的「没抄到精髓」。
- **[x] ① 已修复** — `hibiki/assets/popup/popup.css` 在锁死的多列 grid 上把纵轴对齐从默认 `stretch` 改成 `align-items:start`：每张卡片贴其网格单元顶部、取自身内容高度，首卡不再被行内最高卡片拉伸出特殊高度，观感回到 Niratan 的自然高度玻璃卡片。不改 DOM/JS、不引 JS masonry（避免过度设计，且 `--dict-columns` 多列 + 源码守卫 TODO-776/1357 是已交付的受保护功能）。列间距仍只走 `column-gap`，卡片间纵向间距仍由 `.glossary-group` 的 `margin-top` 提供（grid 不折叠 item margin），零双倍间距。Parity re-vendor：popup.css 字节拷 `hibiki/assets/browser_extension/vendor/` + `tools/browser-extension/vendor/`，`content.css` 经 `generate-content-css.mjs` 重生成。提交哈希：见分支 `todo1325-card-layout-niratan`。
- **[x] ② 已加自动化测试** — `hibiki/test/reader/popup_dict_card_guard_test.dart` 新增「首卡不被等高拉伸」守卫：断言 `.glossary-section > .category-body` grid 显式 `align-items: start`（非默认/`stretch`），且卡片不设固定 `height`/`min-height` 等强制高度；并复核 grid 仍只用 `column-gap`（无 `row-gap`/裸 `gap`）。CSS 选择器层守卫，CI 真跑。
- **备注**：视觉最终需用户真机/桌面看图确认（首卡与其余卡片等自然高度、无空白玻璃盒）。真 masonry 瀑布流（Niratan 的最短列打包）是 JS 引擎，超出本次「以真实 CSS 为准·别过度设计」范围，且与现有 `--dict-columns`「一行 N 个词典」grid 功能（TODO-776/1357 + 源码守卫）冲突，未纳入本次修复。
