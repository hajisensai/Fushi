## BUG-1987 · WoH/HUNEX 单击文字无法查词且点击穿透到游戏
- **报告**：2026-08-31（用户：Wight）
- **真实性**：✅ 真 bug。用户在原始 WoH 1.0 / HUNEX GGE x64 路径中反复确认：实时台词与语音已经可用，但单击画面中文字仍不呼出内嵌查词，同时该次点击继续落给游戏。预期契约是“点文字只触发查词，同一个物理 down/up 不得推进游戏”；这与已修复的通用穿透态命中 BUG-1480、弹窗点外关闭穿透 BUG-1882 都不是同一条失败路径。
- **根因（已定位）**：不是一个坐标偏移，也不是某个 exe SHA 未命中，而是三条边界同时不成立：
  1. **输入拦截晚于游戏语义提交。** 原始 WoH 调用链先在 input pump 内调用 semantic hit-test/submit，之后才直接调用 `GetAsyncKeyState(VK_LBUTTON)`；因此旧 `GetAsyncKeyState` detour 即使清掉按键位，也已来不及阻止游戏推进。当前实现改在结构扫描出的 semantic submitter 入口接管 bit 0，并保留 `GetAsyncKeyState` 仅作物理边沿/尾部观测（`native/galgame_hook/hook/adapters/hunex_gge_adapter.inc:2347`、`:2435`、`:3566`）。
  2. **字形局部坐标缺少到客户区的可证投影链。** renderer glyph 只给出 source descriptor 内的局部矩形；旧路径把它近似成窗口坐标，既不能稳定命中文字，也不能作为输入所有权依据。当前实现只接受同一语义行、同一 render thread 的唯一链：glyph/source descriptor → surface compose destination → texture upload identity → XYZRHW sprite quad → client physical pixels；任一 identity、代数约束、时序或窗口尺寸不唯一即 fail closed（`native/galgame_hook/hook/adapters/hunex_gge_adapter.inc:881`、`:1597`、`:1684`、`:1747`、`:1928`）。
  3. **Dart admission 与注入端输入所有权分裂。** 旧 Dart 在 provider admission 为 false 时丢弃 hit，而注入端只看到 `lookup_enabled`，仍可能消费/发布，造成“没有查词结果但点击已被另一侧处理”的 split-brain。共享契约已升为 v21，并复用 `lookup_geometry_admission_flags` 的 `0x2` 作为 host-owned `NativeInputAllowed`；只有该 request 已被同序列 applied、HUNEX exact provider 仍为 active owner 时，semantic hook 才可消费并发布 hit（`native/galgame_hook/include/voice_hook_ipc.h:111`、`:715`、`:1327`，`native/galgame_hook/hook/geometry_provider_registry.h:267`，`fushi/lib/src/lookup/gal_ingame_lookup_controller.dart:442`，`fushi/windows/runner/voice_hook_reader.cpp:2138`）。
- **[ ] ① 已实现，未验收（`implemented_unverified`）** — HUNEX 准入不钉 exe SHA：只以标题/资源角色作候选边界，再对当前 PE 可执行段做唯一 masked-pattern 与调用图/数据流结构校验；semantic submit、poller、surface compose、texture upload、quad 和 sprite draw 任一缺失或多解都拒绝安装（`native/galgame_hook/hook/adapters/hunex_gge_adapter.inc:2227`）。命中事务冻结语义行 generation、投影 evidence 与 token；单击、Shift 触发与 popup 点外关闭均有独立状态机，只有 lookup/popup owner 才允许吞 bit 0，miss 保持透传。该设计仍须真机证明 Shift 按住后移动到另一字形时会按产品语义重新命中，且 down/hold/up 尾部不会泄漏给游戏；在这项证据出现前不得写成“Shift 悬浮已完成”。admission 关闭时先撤销 native 输入许可，再退本地 provider；已有事务仍排完尾部，禁止新事务起闩，避免半次点击泄漏给游戏。
