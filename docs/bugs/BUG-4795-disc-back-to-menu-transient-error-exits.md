## BUG-4795 · 原盘正片按返回回盘菜单时，任何暂时性错误都会让整个原盘会话退出
- **报告**：2026-11-17（维护者自提：PR #3511（BUG-4755）合入后只读核实的遗留缺陷）
- **真实性**：✅ 真 bug。PR #3511 后 `fushi/lib/src/pages/implementations/video_fushi/disc_menu.part.dart:241-253` 的 `_returnToDiscMenu` 用 `catch (error, stack)` 接住 `discMenuKey(VideoDiscMenuKey.topMenu)` 抛出的**所有**异常后一律 `_exitDiscSession()`。而 `fushi/lib/src/media/video/video_disc_menu.part.dart:373-384` 的 `_sendDiscCommand` 会抛 `navigation-not-active` / `navigation-initializing`（初始菜单仍在等待），`fushi/lib/src/media/video/video_disc_menu.dart:654` 的 `runCheckedVideoDiscCommand` 在 media_kit 桥接拿不到整数结果时记 -1 也抛——这些都不是盘的回答。只有盘按 UO 掩码拒绝 `bd_menu_call`（补丁回 `STREAM_ERROR` → mpv `MPV_ERROR_COMMAND` = -12）才意味着「没有菜单这一级」。于是正片里按返回偶发直接退回详情页、丢掉原盘会话，与 BUG-4755 定的层级（正片 → 盘菜单）相反。
- **[x] ① 已修复** — 新增纯判据 `isVideoDiscMenuCallRefusal`（`fushi/lib/src/media/video/video_disc_menu.dart:678`，只认 `command-failed:-12`），回菜单这一级的执行收进 `DiscMenuReturn`（`fushi/lib/src/media/video/disc/disc_session_controls.dart:151`）：盘拒绝 → `onRefused` 退会话；其他失败 → `onFailed` 记 ErrorLog、留在正片、提示一次 `video_disc_navigation_failed`。页面 `_discSessionReturnToMenuOnBack`（`disc_menu.part.dart:234`）委托给它。提交 67249dab0b。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_disc_menu_test.dart`「only the disc refusing a menu call counts as a refusal」（-12 是拒绝；-1 / -4 / navigation-initializing / navigation-not-active 不是）；`fushi/test/media/video/disc/disc_session_controls_test.dart` 的 `DiscMenuReturn` 组（暂时性失败不退会话、只有拒绝才退）；`fushi/test/pages/video_disc_session_wiring_guard_test.dart` 钉页面接线（`isRefusal: isVideoDiscMenuCallRefusal`）。撤掉判据（改成任何异常都算拒绝）时这几条变红，已实测。
- **备注**：实盘复测未做（本轮不做真机验证）。页面级 Esc 按键链没有可执行测试：`VideoPlayerController` 是具体类、原盘会话要真 libmpv，widget 测试里起不来，仍由源码接线守卫覆盖。
