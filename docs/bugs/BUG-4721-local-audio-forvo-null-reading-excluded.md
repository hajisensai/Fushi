## BUG-4721 · 本地发音库精确读音查询排除 reading 为 NULL 的行，日语 Forvo 发音不显示
- **报告**：2026-11-16（用户：应用内反馈 Dd9HikrfRx，安卓和 PC 端）
- **真实性**：✅ 真 bug。现象：查词长按发音键，菜单里没有日语 Forvo，设置里却能看到 forvo 子来源；同一个 android.db 在别的阅读器里能出 Forvo；英语 Forvo 正常。根因：「读音精确优先 / 回落」查询写成 `WHERE expression = ? AND reading = ?`，只有结果为空才回落到 `WHERE expression = ?`（`fushi/lib/src/utils/misc/local_audio_db.dart:377-387`，Android 原生 `fushi/android/app/src/main/java/app/fushi/reader/TtsChannelHandler.java:537,581` 同写法）。local-audio-yomichan 生成的库里 forvo（以及 forvo_ext2）行的 reading 全是 NULL：本机真库实测 forvo 85791 行全 NULL，nhk16 / jpod / shinmeikai8 等多数带读音。日语词只要别的子来源有一行读音精确命中，forvo 的 NULL 行就被 `reading = ?` 整体排除，回落也不触发。英语库（oald10）没有读音能对上的行，总走回落，所以英语正常。BUG-3740 只修了「每个库只回一条」，没动这个过滤条件。
- **[x] ① 已修复** — 「读音命中」改成读音相同**或该行没有读音**（与 Yomitan 本地音频服务器同一语义）：`WHERE expression = ? AND (reading = ? OR reading IS NULL) ORDER BY reading IS NULL, rowid`，精确读音行排在无读音行前，同级按库内顺序；一行都没命中才回落到只按 expression 查。Dart `LocalAudioDb._queryMetas`（`fushi/lib/src/utils/misc/local_audio_db.dart:385`）和 Android 原生（`TtsChannelHandler.LOCAL_AUDIO_READING_MATCH_SQL`，单条查询与「选择音频源」全量查询共用这一条）逐字相同。子来源优先级排序不变，用户把 forvo 排在前面时单击 ♪ 会播 forvo。传入读音为空时（制卡增强取卡片读音字段可能为空）不按读音过滤，直接只按 expression 查，与上游 reading 为 None 的分支一致，避免只剩 NULL 读音行把带读音的子来源挤掉。
- **[x] ② 已加自动化测试** — `fushi/test/utils/local_audio_db_test.dart` 的「rows without a reading (forvo) still match an exact-reading lookup」组（真 sqlite 库：nhk16 读音精确、forvo reading=NULL、jpod 读音不符；断言全量列表含 forvo、按优先级挑 forvo / nhk16、无 order 时精确行在前、只有 NULL 行时不回落到读音不符的行、读音为空时不按读音过滤），修复前 4 条全红；`fushi/test/android/local_audio_null_reading_query_guard_test.dart` 逐字比对 Dart 与 Java 两端 SQL，并要求 Java 两处 rawQuery 都用这条常量（Android 原生 SQLiteDatabase 在单测里跑不了）。
- **备注**：真机 / 模拟器未复测。
