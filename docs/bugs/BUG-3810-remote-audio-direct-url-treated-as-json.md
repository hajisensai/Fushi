## BUG-3810 · 英语查词时直接返回音频的自定义 URL 音源（uapis.cn / GPT-SoVITS /tts）没有声音
- **报告**：2026-10-27（用户反馈 0-jh-OH5_0，Windows 3.0.0+19763：`https://uapis.cn/api/v1/dictionary/audio?word={term}` 与本机 GPT-SoVITS `http://127.0.0.1:9880/tts?text={term}&…&media_type=aac` 在 Yomitan 里能播，Fushi 提示无可用发音；错误日志 `Audio source error: FormatException: Unexpected character (at character 1) ID3…`）
- **真实性**：✅ 真 bug。Yomitan 的自定义 URL 音源分两种：「Custom URL」（URL 本身回音频）与「Custom URL (JSON)」（回 `audioSourceList`）。Fushi 的 `AudioSourceConfig`（`fushi/lib/src/models/audio_source_config.dart`）只有一种 `remoteAudio`、不记响应类型，设置页也只有一个 URL 输入框，仓库里没有导入 Yomitan 音源设置的路径（无 `custom` / `custom-json` 处理），所以不存在「导入时类型被丢掉」——是解析端只认 JSON：
  - 根因 `fushi/lib/src/utils/misc/word_audio_resolver.dart:597`（修复前）`defaultFetchAudioSourceEntries` 把任何 2xx 响应体一律 `jsonDecode`，直返的 mp3（`ID3` 开头）/ ADTS aac 抛 `FormatException`；
  - `:647` catch-all 把它当网络错误记日志并 `rethrow`，`:218-222` `resolveConfigured` 据此把该 host 计入 45 s 失败冷却（BUG-488 / TODO-1057 的「死源」机制）——格式判错被当成服务器故障，这个源每次查词都失败或被短路。
  - 反馈里的「sovits」指 GPT-SoVITS 的 HTTP `/tts` 接口（`media_type=aac` → `Content-Type: audio/aac`、裸 ADTS 帧），同属「URL 直接回音频」，同一根因。
- **[x] ① 已修复**（提交 1860ca5731）— 远端响应按确定性判据分型（`fushi/lib/src/utils/misc/word_audio_cache.dart` `sniffWordAudioExtension`：音频魔数 ID3/MPEG 帧/ADTS/OggS/fLaC/RIFF-WAVE/ftyp/EBML，或 `Content-Type: audio/*`）：是音频就把这次请求的字节按内容寻址落盘（`cacheWordAudioBytes`，与弹窗 `data:` 落盘共用同一缓存目录与淘汰逻辑，从 `lookup_audio_playback.dart` 抽出），返回本地路径——播放端不再请求第二遍（GPT-SoVITS 不会合成两次）；否则按 `audioSourceList` JSON 解析（`parseAudioSourceListBody`）；两者都不是（可达、2xx、格式不认识）记一条新的 `audio_source_unrecognized_response` 日志（载荷带 Content-Type 与开头 16 字节）并当空结果返回，**不** rethrow、不计 host 冷却。try/catch 只包网络请求本身，只有连接级失败才进冷却。
- **[x] ② 已加自动化测试** — `fushi/test/utils/misc/word_audio_direct_url_source_test.dart`：真实 `defaultFetchAudioSourceEntries` + 假 `HttpClientAdapter` 回 ID3 mp3（audio/mpeg 与 octet-stream）、ADTS aac（audio/aac）、`audioSourceList` JSON、不认识的 text/html；`resolveConfigured` 端到端断言返回落盘文件、字节一致、host 不冷却、第二次查词仍真打源；`sniffWordAudioExtension` 判据表。9 条全过；把 `sniffWordAudioExtension` 变异成恒返回 null（等价旧的「只认 JSON」）后 6 条变红。
- **备注**：未在真机 / 真实 uapis.cn、GPT-SoVITS 服务上复测原始失败路径（待补）。没有给 `AudioSourceConfig` 加「直返音频 / JSON」类型字段：Fushi 本来就先请求再解析，响应自身的 Content-Type / 魔数是权威判据，用户照 Yomitan 两种 URL 直接粘进同一个输入框都能用，无需迁移存量配置。ADTS aac 文件在弹窗里以 `data:audio/mp4` 交给 WebView（沿用 `audio_mime.dart` 的 `aac → audio/mp4` 既定映射），WebView2 能否解码裸 ADTS 未实测。
