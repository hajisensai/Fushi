## BUG-5136 · loopback 一路被多方共用时，任何一方 stop（含失败 start 后的兜底 stop）都会停掉别人的环
- **报告**：2026-11-22（实现拍板台 design-cross-app-audio-desktop 时沿代码路径发现：电脑端跨应用语音缓存要与 galgame 会话共用系统混音 loopback）
- **真实性**：✅ 真 bug（潜伏）。`fushi/windows/runner/audio_loopback_capture.cpp:569`（origin/develop cbdc2a45ed）`AudioLoopbackCapture::Stop()` 无条件停掉全进程唯一的那一路采集；`Start` 只做「同来源幂等、异来源 busy」（`:528`），没有持有者计数。于是 `fushi/lib/src/mining/gal_hook_session_controller.dart:5809` `_startLoopbackIfAllowed` 在 start 失败（例如网页视频制卡的静音进程树正在录 → `busy`）之后照样 `await loopback.stop()`，会把网页视频那一路停掉；galgame 补录的临时源、网页视频预起作废时的 stop 同理。跨应用语音缓存常驻系统混音之后，galgame 会话一结束就会把它的环停掉，且常驻的系统混音会让网页视频静音进程树一律 `busy`（自动制卡整轮放弃）。
- **[x] ① 已修复** — loopback 采集改成「每个来源一路、各路可并存、每路按租约计数」：新增纯数据结构 `fushi/windows/runner/audio_loopback_leases.h`（`LoopbackLeaseTable`：每次 Start 发一张永不复用的租约，Release 只交回自己那张，某一路最后一张交回才真停；未知 / 已交回 / 缺省租约无操作；采集线程意外退出后同来源重起把旧租约迁过去）；`audio_loopback_capture.cpp` 的全局单一 `g_state` 拆成按来源的会话注册表，`Stop()` 换成 `Release(lease)` / `StopAll()`；通道 `start` 回包带 `lease`，`stop` / `grabRecent` 带 `lease`。Dart `LoopbackGalAudioSource` 持有自己的租约，没持有时 `stop()` 不发通道调用。同一进程树 silent 设置相反仍互斥（busy）。
- **[x] ② 已加自动化测试** — 原生：`fushi/windows/runner/tests/audio_loopback_leases_test.cpp`（随每次 Windows runner 构建跑的 gate：共用一路时只有最后一张租约交回才停、缺省 / 重复 stop 无操作、租约不复用、重起迁移、来源键规范化）；变异实测：把 `Release` 的 `*last` 改回恒 true（旧语义），测试 2 条断言转红。Dart：`fushi/test/mining/galgame_audio_test.dart`（租约协议）、`fushi/test/mining/cross_app_audio_capture_test.dart`「desktop (Windows loopback)」组（galgame 停不影响跨应用缓存、反之亦然、失败 start 的兜底 stop 不误伤），替身 `fushi/test/mining/fake_loopback_native.dart` 按 native 语义实现。
- **备注**：runner 未在真机上复测「galgame 会话 + 跨应用缓存 + 网页视频静音采集」三路并存（本轮不做真机验证）；C++ 改动已用 MSVC `/W4 /WX` 编译通过 `audio_loopback_capture.cpp` 与租约单测。
