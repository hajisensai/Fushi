## BUG-5238 · 章下载续跑账本只记已落地页：共享页地址的旧页被当成新页表里的另一页复用
- **报告**：2026-11-22（代码审查 HBK-AUDIT-206，`docs/reviews/2026-11-22-project-review.md`，针对 PR #4139）
- **真实性**：✅ 真 bug。`fushi/lib/src/media/manga/download/manga_download_page_ledger.dart:196`（develop 283a920286）判身份唯一用的是「账本里已落地的页」的计数，不是落盘时那份完整页表。Mihon 懒解析的源会给几页报同一个页地址：旧页表 A、B 同身份、只落了 A 时，账本里只有一条，看着唯一；新页表删了 A 只剩 B（同身份），A 的旧图就被留作 B。198 行的「页序 + 身份都对上就原地留用」对重复身份同样不成立（同一例里 A 也在第 0 页）。
- **[x] ① 已修复** — 账本升到 v2，多记这些页所属的整份页表 `table`。续跑时：新页表与账本页表整份相同（页数相同、逐页身份都在且相等，与 `OnlineMangaChapterPageRefs.sameSourcePages` 同一判据）才按页序原地留用；否则只认在旧页表和新页表里都唯一的身份（页序变了就挪），重复身份一律删掉重下。账本项必须真是账本页表里那一页，对不上当坏项。v1 账本没有页表、判不出当时是否唯一，按空账本处理（升级后那一次续跑整章重下）。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_download_page_ledger_test.dart`：旧表 A、B 同身份只落 A、新表只剩 B 不复用；旧表唯一新表重复不复用；页数变了时重复身份不再按页序留用；账本项与页表对不上不认；v1 账本当空账本。
- **备注**：与 BUG-5237 同属 audit-035（PR #4139）的页身份链。
