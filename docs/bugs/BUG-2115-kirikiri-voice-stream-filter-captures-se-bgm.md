## BUG-2115 · KiriKiri 资源流语音过滤按裸 .ogg/.opus 后缀把 SE/BGM/脚本当语音并配给旁白
- **报告**：2026-09-04（ceshi 批量适配 · KiriKiri Z `tenshi_sz.exe` 真机：序章无配音旁白「静まり返った闇の中に、紅蓮の明かりが点った。」被标「音频就绪 · game_resource · `★炎９(Loop).ogg`」——那是火焰环境音效循环（403 KB）；`%TEMP%\fushi_gal_voice` 里同时躺着 `【システム】決定１.ogg`（系统 SE）、`bgm24.opus`（3.5 MB BGM）、`voice.tjs` / `charvoice.csv` / `voicebar.pbd`（脚本与 UI 资源）。制卡会把音效当「整句语音」写进卡）
- **真实性**：✅ 真 bug，但**真正的用户可见缺口是落盘文件名丢了扩展名**，不是「采集面过宽」。根因：`dll_main.cpp` 的 `VoiceBaseName` 生成落盘名时只切 `/`、`\`，没切 KiriKiri 归档放置路径的分隔符 `>`。放置路径 `…voice.xp3>坒`（条目名被哈希、无扩展名）→ base=`voice.xp3>坒` → 里头 `.xp3` 的点骗过「无点补 .ogg」→ 落盘名 `..._voice.xp3_坒`（**无音频扩展名**）。host 的资源索引按扩展名扫，看不见它，于是明明 6.86 s 的源资源已落盘，制卡却退回 5 s loopback（真机：由月「そうね…」→ 源 `yuz_001_0008.ogg` 6.86 s vs 卡里 5.00 s aac）。SE/BGM 被一并 dump 是次要现象——host 按 textseq/时间戳配对，多几个 SE 文件不影响配对结果。
- **修复弯路（诚实记录）**：第一版把 `IsVoiceStorageName` 收窄成「必须含 voice/koe 目录段」并在两处 detour 加容器魔数门。真机复验立刻暴露它**把整局语音全杀了**：天音有声台词（画面 VOICE 指示灯亮）一条都不 dump，`reserved_luna` 的 `VoiceStreamDumped`(0x80000) 位恒清——因为该游戏语音逻辑名是裸 `yuz_001_0004.ogg`（无 voice 段、无 voice 子串），被新过滤误杀。已回退这两处。
- **[x] ① 已修复** — 只保留证明正确的那半：`VoiceBaseName` 切分符加 `>`；扩展名按**载荷容器魔数**补（`hook/kirikiri_voice_storage_name.h::KirikiriVoicePayloadExtension`，Ogg/RIFF-WAVE），不按名字猜——落盘名恢复带 `.ogg`，host 索引得到，制卡取整句资源。粗筛 `IsVoiceStorageName` 保持宽（含 voice/koe 或 .ogg/.opus/.wav 后缀），SE/BGM 的收敛交给下游 textseq 反查 + 整句匹配。
- **[x] ② 已加自动化测试** — `native/galgame_hook/tests/kirikiri_voice_storage_name_test.cpp`（`>` 分隔符 + 载荷魔数：Ogg/WAVE 正例、RIFF-非WAVE/sidecar/截断/nullptr 负例，双架构 CTest）。
- **真机复验（2026-09-04，修正版构建）**：落盘名恢复带扩展名（`..._坒.ogg`，旧版是无扩展名 `..._坒`）；`reserved_luna` 的 VoiceStreamDumped(0x80000) 位置位；工作台女主由月有声句现标 `game_resource · yuz_001_00NN.ogg`（旧版恒 `system_loopback · 5.00s`）。**未采到**的一项：制卡后卡内 SentenceAudio 时长与源资源逐字节/时长一致——测试模式隔离 Fushi 每 ~1.25s 抢回前台使卡片不发布（[[reference_test_hidden_fushi_steals_foreground_from_game.md]] 的 harness 局限，真机前台稳定不复现），留待用户真机或后续会话补。
- **备注**：教训——真机不复验就动采集面的正向判据必翻车（第一版收窄 IsVoiceStorageName 把整局语音杀光）。与 BUG-2070（ATRI wuopus 恒降级）是否同源待 ATRI 复验；本样本 opus 只被 BGM 触发、语音走 vorbis 资源。
