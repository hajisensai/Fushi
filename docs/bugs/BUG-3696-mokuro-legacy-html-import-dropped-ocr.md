## BUG-3696 · mokuro-legacy-html-import-dropped-ocr
- **报告**：2026-10-23（用户：应用内反馈 NdpewUzW1C，Android 3.0.0 / Galaxy Tab S7 FE，从 jidoujisho 迁来；截图里阅读器在跑 `OCR 6/853 · CPU`）
- **真实性**：✅ 真 bug。mokuro 0.1.x 的产物是 `<卷名>.html` + `<卷名>/` 页图 + `_ocr/<卷名>/<页>.json`（没有 `.mokuro`，jidoujisho 的 mokuro 阅读器吃的就是这个 html），Fushi 只认 `.mokuro`：
  - 选装着它的文件夹：`classifyImportCarrier` 目录分支（`fushi/lib/src/media/import/import_carrier.dart` 的 `directoryMokuroFileCount`）数的 `mangaMokuroFilesIn`（`fushi/lib/src/media/manga/import/manga_folder_batch.dart:48`）只认 `.mokuro` → 计 0 → 落到 `directoryHasPageImages`（递归）→ `mangaFolder`，把整个目录（多卷时所有卷）压平成一本**没字**的纯页图漫画；
  - 选 `.html`：同函数文件分支只有 `ext == '.mokuro'` 早退，html 落进 `ImportCarrier.text` 被转成 EPUB（漫画框直接拒收）；
  - 来源库：`planMangaFolders`（`packages/fushi_engine/lib/media/manga/manga_folder_plan.dart:103`）只把 `.mokuro` 当 manifest，`<卷名>/` 被计成纯页图卷导入，无头服务端同一份口径同病；
  - 结果三条路都把 mokuro 的文字层丢掉，阅读器 `mangaVolumeOcrSettled` 为 false → 自动排整卷本地 OCR（截图里的 853 页就是被压平的多卷）。
  - 另：Android 单选 `.mokuro` 时 SAF provider 给不出真实路径（「下载」「最近」入口、云盘）会只交回 `cache/saf_pick/` 的单文件副本，同级页图不在；选中时的「孤立 mokuro」提示此前只对 iOS 生效（`manga_import_dialog.dart` 的 `_isOrphanedIosMokuro`），Android 要到点导入才报一串缓存路径的缺图错误。
- **[x] ① 已修复** — 新增 `packages/fushi_engine/lib/media/manga/mokuro_legacy_html.dart`（旧版产物判据：本地 `isLegacyMokuroHtmlVolume`、纯路径 `legacyMokuroHtmlPathsIn`，同级同名 `.mokuro` 在时让位）；`MangaImporter.importFromMokuroPath` 遇 `.html` 先由 `legacyMokuroJson` 把逐页 JSON 按 mokuro 页序拼回 `.mokuro` 形状（`img_path` = `<卷名>/<页>`，缺 JSON 的页文字层空、宽高探测页图），之后与 `.mokuro` 同一条管线；`planMangaFolders` 把旧版 html 计入 manifest（app 来源库 / 无头服务端 / prune 对账同一口径）；`classifyImportCarrier` 认旧版 html 为 `mangaMokuro`，`mangaCarrierFilesIn` / `mangaMokuroFilesIn` 认目录里的旧版 html（单卷 / 多卷批量）；app 来源库远端卷镜像页图 + `_ocr` JSON 后交本地导入器；漫画框文件选择器收 `.html`，孤立 manifest 提示改为不分平台（i18n `manga_import_ios_mokuro_needs_folder` → `manga_import_mokuro_needs_folder`）。提交见本分支 `fix(manga): import legacy mokuro html volumes with their OCR`。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/mokuro_legacy_html_test.dart`（纯路径判据含 `p.url` 远端、来源库归卷、导入后文字层 + `mangaVolumeOcrSettled` 为真、文件 / 目录载体判定、多卷批量、本地来源库扫描）。
- **备注**：`.mokuro`（mokuro 0.2+）在 Android 上原本就走得通：来源库本地目录与漫画框「选文件夹」都经 SAF tree → 真实路径（需全文件访问），导入后 `mangaVolumeOcrSettled` 为真，阅读器不排本地 OCR。远端旧版卷的导入函数没有单测（需要假 NetworkSourceFileSystem），只测了它的归卷规划。
