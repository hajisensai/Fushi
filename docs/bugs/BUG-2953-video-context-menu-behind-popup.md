## BUG-2953 · 视频页右键菜单被查词弹窗遮挡
- **报告**：2026-10-05（用户：「就是视频里面复制这个词的时候，右键复制，选项会跑到这个查词框后面去」）
- **真实性**：✅ 真 bug。视频页在查词弹窗里右键选词 → Windows 宿主菜单「查词 / 复制」（`fushi/lib/src/pages/implementations/dictionary_popup_webview.dart:3149` `showFushiMenu(context: 弹窗 context)`）推进**根 Navigator**；而查词浮层是视频页用 `overlay.insert(entry)` 手动挂进根 Navigator Overlay 的外来 entry（`video_fushi_page.dart:6168`，同形的还有 `web_video_fushi_page.dart:1421`、`home_dictionary_page.dart` `_syncPopupOverlay`、`texthooker_page.dart:2546`）。Navigator 每次 push 都 `overlay.rearrange(路由 entries)`（Flutter `navigator.dart:4585`），`OverlayState.rearrange` 把不在列表里的旧 entry `insertAll(_entries.length, old)`（`overlay.dart:844`）——外来 entry 永远排到所有路由**之上**，菜单 route 于是画在浮层之下、点不到。窄顶栏「⋯」溢出 `PopupMenuButton`（`dictionary_popup_layer.dart` `_buildOverflowMenuButton`）同根，且不限 Windows。书内阅读器 / 漫画（`BaseSourcePage`）浮层在页面 Stack 里、低于菜单路由，不受影响。
- **[x] ① 已修复** — 新增共享组件 `LookupOverlayNavigator`（现位于 `fushi/lib/src/lookup/lookup_overlay_navigator.dart`，经 `dictionary_popup_layer.dart` re-export）：浮层子树作为自带 `Navigator` 的初始路由（无 barrier 的 `OverlayRoute`、`requestFocus: false`、`Clip.none`），浮层内 `Navigator.of(context)` 找到的就是它，菜单落在同一 entry 里、浮层之上；四个根 Overlay 宿主（视频 / 网页视频 / 首页词典 / texthooker）的 `_buildPopupOverlay` 都包上它，放在 `FushiAppUiScaleNeutralizer` 之外（菜单坐标空间与改前一致）。未用重新 insert / 延时。（工作区未提交，哈希待提交后补）
- **[x] ② 已加自动化测试** — `fushi/test/pages/lookup_overlay_navigator_menu_layer_test.dart`：复刻根 Overlay 手动 insert 的浮层 + `showFushiMenu`，断言菜单项命中链不含弹窗盒、点「COPY」能选中；对照组（不包装）钉住「菜单沉到弹窗下、点击落在弹窗上」的根因；另验导航层对弹窗外命中透明、挂载不抢页面焦点、Esc 关菜单后焦点回页面、外层 markNeedsBuild 能刷新子树；源码守卫要求四个宿主都在中和器外包 `LookupOverlayNavigator`。
- **[x] ③ 返回先关菜单（同 bug 第二段）** — 菜单进了内层 Navigator 后，所有「返回」入口仍只认根 Navigator：系统返回 `WidgetsApp.didPopRoute` → 根 `maybePop()` → 页面 `PopScope`（视频页 `_dismissTopForegroundLayer`），把浮层连同菜单一起关掉；Alt+← / 手柄 B / 鼠标返回键的根兜底（`global_navigation.dart` `_handleGlobalBack` / `_executeGlobalMouseAction`、`gamepad_service.dart` B 分支）同样直接根 `maybePop()`。修法：`LookupOverlayNavigator` 迁到 `fushi/lib/src/lookup/lookup_overlay_navigator.dart`（`dictionary_popup_layer.dart` re-export），给出唯一判据 `activeMenuNavigator` / `popActiveMenu()`（最内层、栈上有可弹路由的查词导航器）；①系统返回键：`installSystemBackInterceptor()` 在 `main.dart` 的 `runApp` 之前注册 observer，`handlePopRoute` 按注册顺序先问它，菜单开着只 pop 菜单并认领，页面 `PopScope` 不触发；②预测性返回：菜单开着时在根栈顶路由挂 `canPop: false` 的 `PopEntry`（内层 `NavigatorObserver` 驱动，菜单关闭即摘），`popGestureEnabled` 为假、页面不跟手滑走，提交后框架退化为 `handlePopRoute` 被①接住；③Esc / Alt+← / 手柄 B / 鼠标返回键：`_handleGlobalBack`、`_handleEscapeWithoutRegistry`、`_executeGlobalMouseAction`、gamepad B 兜底在根 `maybePop()` 之前先 `popActiveMenu()`。结果：返回 = 先关最内层菜单 → 再关浮层 → 再退页。测试 `fushi/test/pages/lookup_overlay_navigator_back_test.dart`（`handlePopRoute` 菜单开着只关菜单、第二次才关浮层；无菜单时页面逻辑不变；无 PopScope 页面菜单开着 `popGestureEnabled` 为假且返回只关菜单；全局导航层 Alt+← / Esc 先关菜单；源码守卫：main 在 runApp 前安装、四个根兜底先问菜单）。变异验证：去掉拦截与守卫后两条行为用例变红。（工作区未提交）
- **备注**：悬浮歌词 host（`floating_lyric_lookup_host.dart`，挂在 `MaterialApp.builder`）不在本次范围。`activeMenuNavigator` 只认查词导航层，不改变 app 里其它嵌套 Navigator 的返回语义。
