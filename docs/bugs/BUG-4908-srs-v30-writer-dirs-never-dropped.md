## BUG-4908 · v3.0.x 复习同步写入者目录迁移完也永远留在位置上
- **报告**：2026-11-21（用户：开发者本人，Windows 安装版当互联 host）。`sync-data/fushi-data/fushi-srs/<profile>/2RIr94DPav6kxb5RWSGciWgE4LNKvGBCRtT4wT2iGSc=#1/` 占 569 MB；用户拍板放弃 v3.0.x 客户端，迁移完成后清掉。
- **真实性**：✅ 真 bug（磁盘泄漏，行号为修复前 upstream/develop 76811fc25da）。`<44 字符>#<n>/` 是协议 1 之前 v3.0.x 旧事件同步的写入者目录（`native/fushi_fsrs/src/gen4/location.rs:30-31`）。旧根迁移 `srsMigrateV1Media`（`packages/fushi_engine/lib/srs/sync2/srs_location_migration.dart:790` 起）只逐个搬、删写入者目录里的 `media/`（`:126-127` 注释「目录本身与别的内容不动」，`SrsV1Writers` 也只有 `deleteMedia`），`batch-*` / `snapshot-*` / `profile.json` 永不删；全仓唯一删写入者目录的 `srsRemoveOwnProfileFolder`（`srs_profile_link.dart:399-424`）只删本设备在旧 uid 下的。旧事件同步早已删除（守卫 `srs_sync_v1_removed_guard_test.dart`），现版本不读 `batch-*` / `snapshot-*`；写入者的 `profile.json` 只在还没迁移的位置上被 `srsListRemoteProfiles` 读（迁移过的位置由每台现版本设备每轮发布的 `v3/devices/<设备>/profile.json` 代替）。
- **[x] ① 已修复** — `SrsV1Writers` 新增 `deleteWriter`（`SrsAssetV1Writers` 整目录 `deleteAsset(isFolder: true)`）；`srsMigrateV1Media` 在四个条件同时成立时删掉全部写入者目录：旧根 `v2/meta.json` 是围栏、新根 `v3/meta.json` 在用（原有入口检查）、旧根完成标记 `v2/migrated.json` 的指纹等于当前清单（含写入者媒体）、每个写入者的 `media/` 都已为空。只在「标记与清单一致」那条分支里删——写下标记的那一次不删，下一个进程比过指纹才删；归档位置不删；删失败记 `cleanupErrors`，下次再试。`v2/` 围栏永不删。仍在运行的 v3.0.x 客户端会丢掉还没收的批次并换化身号重写（已拍板放弃）。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/sync2/srs_v1_writer_drop_test.dart`（真 `LocalDirectoryAssetStore` 位置 + 真迁移：条件齐备时两个写入者目录整删、围栏与新根逐字节不变、幂等；新根 meta 不在 / 围栏被换成普通 meta / 旧根多了文件导致指纹不符 / 完成标记不在 / 写入者 media 里还有晚到文件，五种情况各一条，一个都不删）。
