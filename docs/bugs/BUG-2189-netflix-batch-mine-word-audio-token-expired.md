## BUG-2189 · 网飞批量制卡单词音频落空：入队冻结的短命 token URL 生成时已过期
- **报告**：2026-09-06（用户：「网飞制卡少了单词音频」；真卡取证 AnkiConnect note 1788020800232，`ExpressionAudio` 空、`MiscInfo`=Netflix）
- **真实性**：✅ 真 bug。扩展弹窗制卡时 `popup.js buildMinePayload` 把 `resolveWordAudio` 拿到的 URL 冻进 `fields.audio`；扩展侧那个 URL 是本机 server 签发的 5 分钟短命 token（`fushi/lib/src/sync/yomitan_api_server.dart` `_handleAudioLookup` / `_pruneAudioTokens`，`fushi_sync_server.dart` 同款）。Netflix/YouTube 走批量队列（`tools/browser-extension/content.js` `fushiEnqueue` → `chrome.storage.local`，看完一集才「生成全部」），几十分钟后发 `/api/mine` 时 token 早被 prune → `_storeRemoteAudio` 抓 404 → 卡建好但 `[sound:]` 空。`/api/mine` 全链路（`buildRemoteMineResponse` → `mineImmersion` / `mineEntry`）此前从不重解析单词音频。
- **[x] ① 已修复** — `fushi/lib/src/sync/fushi_remote_api_handlers.dart` 新增 `resolveRemoteMineWordAudio`：`fields.audio` 是本机 token 引用（`remoteAudioTokenIdFromRef`）时，token 仍活取字节、已过期按 `expression+reading` 重走同一条 `lookupAudio`，一律改写成自包含 `data:<mime>;base64,` URI（与 app 内本地音频库制卡同形，`AnkiAudioRef.dataUri`）；两个 server 的 `_handleMine` 注入 `_resolveMineWordAudio`。取不到时保留原引用让既有 404 → `audioWarning` 诊断照常浮出。
- **[x] ② 已加自动化测试** — `fushi/test/sync/yomitan_api_server_extension_endpoints_test.dart` group「BUG-2189」5 例：过期 token → 重解析 data URI；活 token → 直接取字节不打后端；过期且库无此词 → 原引用保留；外部 http / data: 原样透传；clip 沉浸路径同样改写。
- **备注**：真机（Chrome + Netflix DRM）批量生成一张卡的端到端复测本机无法自动化，待用户复测；`implemented_unverified`。
