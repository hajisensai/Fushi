## BUG-2453 · 视频播放页合成 hover 设备退出后不注销，库页中心卡片被幽灵指针悬停放大
- **报告**：2026-09-11（用户：「我在进入视频页的时候，中间附近的卡片会显示鼠标放上去的效果，也就是放大。但是我鼠标明明没放上去」）
- **真实性**：✅ 真 bug。库页卡片放大只由 `fushi/lib/src/utils/components/fushi_hover_lift.dart:221-225` 的 `MouseRegion.onEnter/onExit` 驱动（`home_video_page.dart` 四处 `FushiHoverLift` 的 builder 都无视 hover 参数），即 Flutter `MouseTracker` 认定「有一个指针停在那张卡上」。这个指针不是用户的鼠标：播放页 `video_fushi/controls_visibility.part.dart` 的 `_pokeControlsVisible` 为了唤醒 media_kit 控制条，用固定设备号 `_syntheticHoverDevice = 0x6869626B`、`kind: mouse`、位置 = 视频区几何中心，经 `GestureBinding.handlePointerEvent` 派合成 `PointerHoverEvent`（`_dispatchPokeHover`）。Flutter `MouseTracker.updateWithEvent` 对未知设备的 hover 会新建一条 `_MouseState`，**只有收到同设备的 `PointerRemovedEvent` 才删**（SDK `rendering/mouse_tracker.dart:324-331`）；全仓没有任何地方派过这个 remove。于是只要本次会话打开过播放器，幽灵指针就永远停在屏幕中心；退出播放器后每帧帧末 `updateAllDevices` 都在那一点命中测试，库页中心那张卡的 `MouseRegion` 收到 `onEnter`，`FushiHoverLift` 放大。用户描述的「中间附近」「鼠标明明没放上去」与此完全吻合（同一幽灵指针也会让此后落在屏幕中心的任何 `MouseRegion`——按钮 hover 高亮、tooltip、弹窗按钮——被当成悬停）。
- **[x] ① 已修复** — **删掉合成设备，改走显式唤醒信号**。media_kit 桌面 fork `third_party/media_kit_video/lib/media_kit_video_controls/src/controls/material_desktop.dart` 新增 theme 字段 `Listenable? wakeSignal`（构造 + `copyWith`，全屏路由经 normal/fullscreen 复制 theme 自然透传），State 在 `didChangeDependencies` 绑定 / `dispose` 解绑，收到即调它自己的 `onHover()`——唤起 + 重排隐藏 Timer，正是合成 hover 唯一想触发的那条路径；宿主若在 build/layout 阶段发信号则延到帧末（`setState` 不合法）。与移动端 `restartHideTimerSignal`（TODO-1059）同构，区别只在桌面要唤起（键盘 seek / 关面板本就该露出控制条，「只在可见时续命」由页面 `_keepControlsAliveIfVisible` 自己门控）。页面 `_desktopControlsTheme` 传 `wakeSignal: _restartHideTimerSignal,`（与移动端共用同一个信号对象），`_pokeControlsVisible` 两端都只 `_restartHideTimerSignal.poke()`（桌面顺带显式 `_pokeLockButton()`——合成 hover 时代它经页面根 Listener 的 `_handleVideoControlsHover` 顺带续命侧边锁按钮）。随之整删：`_syntheticHoverDevice`、BUG-215 的 `_pokeParity` ±1px 抖动、BUG-425 的 `_pendingPokeHover`/`_pokeDispatchScheduled`/`_dispatchPokeHover` 微任务延迟、BUG-1798 的 `_isSyntheticControlsHover` 三处按设备号过滤；页面不再合成任何指针事件。fork 补丁登记在 `third_party/media_kit_video/PATCHES.md`（BUG-2453 节）。**三版「注销时机」修法均被 code review 逐条证伪、已废弃**：(a) `dispose()` 同步注销（首版 8dd895ccf8 / PR #1419，审查前已被并发会话合入 develop，合并提交 df57354836）——dispose 跑在 `finalizeTree` 锁态内，pop 反向过渡期间幽灵指针早已进到下层库页卡上，remove 让那张卡 `onExit → setState` 撞「widget tree was locked」断言；`pushReplacement` 换集还会把新页刚露出的控制条藏掉；(b) 路由动画状态监听 + post-frame 注销（c5377504f6）、(c) `RouteTopListener` 叶子按 `isCurrent` 边沿注销（b9fa111219）——注销是边沿一次性，poke 随输入无限次，注销后再 poke 即复发；全屏接管换集走 `removeRoute` 不 pop、只靠 SDK `_updateSecondaryAnimation` 一个相等分支才碰巧收到 `forward`；弹窗 / `fullscreenDialog` / 零时长路由根本不驱动次动画；切换显示语言的 `KeyedSubtree` 整树重挂不经任何路由动画。合成指针设备本身就是错的抽象，任何注销时机都是补丁。提交：见 PR #1424 本轮 commit。
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_controls_wake_signal_guard_test.dart`。① 机制层（真 Navigator + 真 `FushiHoverLift` + 真实 `MouseTracker`）：派过合成 hover 而不派 remove → pop 后 `mouseIsConnected` 仍真、下层中心卡 builder 拿到 `hovering == true`（症状本体）；不合成任何指针事件 → 退页后设备表为空、中心卡从未被判 hover，真实鼠标移到同一位置仍能悬停（正向对照）。② 页面源码守卫（`containsCodeLine` 剥注释）：视频页语料无 `handlePointerEvent(` / `PointerHoverEvent(` / `PointerRemovedEvent(` / `PointerAddedEvent(` / `_syntheticHoverDevice` / `0x6869626B`；`_pokeControlsVisible` 五条门控俱在、唯一出口 `_restartHideTimerSignal.poke();`、桌面显式 `_pokeLockButton();`、无 `scheduleMicrotask(`；`_desktopControlsTheme` 传 `wakeSignal: _restartHideTimerSignal,`、移动端仍传 `restartHideTimerSignal:`；`_isSyntheticControlsHover` 不复存在。③ fork 源码守卫：`wakeSignal` 字段 / 构造 / `copyWith` 透传、State 绑定与解绑、`_onWakeSignal` 调 `onHover()` 且 `mounted` 早退。原本钉住合成机制内部（抖动 / 微任务 / 设备号过滤 / 派发锚点）的七份守卫（`video_controls_poke_guard_test` 等）同步改为钉新契约。
