## BUG-2453 · 视频播放页合成 hover 设备退出后不注销，库页中心卡片被幽灵指针悬停放大
- **报告**：2026-09-11（用户：「我在进入视频页的时候，中间附近的卡片会显示鼠标放上去的效果，也就是放大。但是我鼠标明明没放上去」）
- **真实性**：✅ 真 bug。库页卡片放大只由 `fushi/lib/src/utils/components/fushi_hover_lift.dart:221-225` 的 `MouseRegion.onEnter/onExit` 驱动（`home_video_page.dart` 四处 `FushiHoverLift` 的 builder 都无视 hover 参数），即 Flutter `MouseTracker` 认定「有一个指针停在那张卡上」。这个指针不是用户的鼠标：播放页 `fushi/lib/src/pages/implementations/video_fushi/controls_visibility.part.dart:70-75` 的 `_pokeControlsVisible` 为了唤醒 media_kit 控制条，用固定设备号 `_syntheticHoverDevice = 0x6869626B`（`video_fushi_page.dart:924`）、`kind: mouse`、位置 = 视频区几何中心，经 `GestureBinding.handlePointerEvent` 派合成 `PointerHoverEvent`（`:127-133` `_dispatchPokeHover`）。Flutter `MouseTracker.updateWithEvent` 对未知设备的 hover 会新建一条 `_MouseState`，**只有收到同设备的 `PointerRemovedEvent` 才删**（SDK `rendering/mouse_tracker.dart:324-331`）；全仓没有任何地方派过这个 remove。于是只要本次会话打开过播放器，幽灵指针就永远停在屏幕中心；退出播放器后每帧帧末 `updateAllDevices` 都在那一点命中测试，库页中心那张卡的 `MouseRegion` 收到 `onEnter`，`FushiHoverLift` 放大。用户描述的「中间附近」「鼠标明明没放上去」与此完全吻合（同一幽灵指针也会让此后落在屏幕中心的任何 `MouseRegion`——按钮 hover 高亮、tooltip——被当成悬停）。
- **[x] ① 已修复** — 合成设备与播放页 State 同生共死：`_VideoFushiPageState.dispose()`（`video_fushi_page.dart:4055`）调新增的 `_retireSyntheticHoverDevice()`（`controls_visibility.part.dart`），派同设备、同 kind 的 `PointerRemovedEvent` 让 MouseTracker 删掉那条设备状态，并丢弃待派发的 `_pendingPokeHover`。`_dispatchPokeHover` 真派发前置 `_syntheticHoverDeviceLive`，从没造过设备（移动端 / 从未 poke）时 dispose 不往指针管线塞任何事件。**不能**在每次 hover 后立刻注销：media_kit fork 的 `onExit`（`third_party/media_kit_video/.../material_desktop.dart:633-640`）无条件 `visible = false` 并取消隐藏 Timer，remove 会触发它，poke 就白派了；退页时控制条子树已随本页 deactivate 从渲染树摘下，MouseTracker 对已摘下的 region 不回调 `onExit`（`validForMouseTracker` 为假），注销零副作用。提交：见本轮 commit。
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_synthetic_hover_device_retire_guard_test.dart`（6 条）。① 行为层用纯框架部件 + 真 `FushiHoverLift` 在 Flutter 真实 `MouseTracker` 上复现：派一条与生产同构的合成 hover 到「播放页桩」中心 → 整页换成「库页桩」——不注销时 `mouseIsConnected` 仍真且中心卡 builder 拿到 `hovering == true`（症状本身）；随页 dispose 注销后设备表清空、卡片不再被判 hover，且真实鼠标移到同一位置仍能悬停（正向对照，证明探针没失灵）。② 源码守卫钉住 `dispose()` 调 `_retireSyntheticHoverDevice()`、后者派同设备 `PointerRemovedEvent`（device / kind / 经 GestureBinding / 清 `_pendingPokeHover`）、`_dispatchPokeHover` 在派发**之前**登记在册、测试复刻的设备号与生产常量同值。变异实测：删掉 dispose 里那一行调用，仅「dispose 调用」守卫变红（+5 -1），还原后全绿。
- **备注**：残留面：播放页**打开期间**幽灵指针仍停在视频区中心（poke 语义所需，与之前一致），落在那一点的其它 `MouseRegion`（例如盖在中心的浮层按钮）依旧会被当成悬停——这是「用合成指针事件驱动 media_kit 私有 Timer」这条设计本身的代价；彻底消除要给桌面 fork 加与移动端 `restartHideTimerSignal` 同构的唤醒信号、删掉合成设备（连带 BUG-215 抖动、BUG-425 微任务、BUG-1798 过滤三处补丁一起删），另开任务。
