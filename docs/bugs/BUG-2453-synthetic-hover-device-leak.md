## BUG-2453 · 视频播放页合成 hover 设备退出后不注销，库页中心卡片被幽灵指针悬停放大
- **报告**：2026-09-11（用户：「我在进入视频页的时候，中间附近的卡片会显示鼠标放上去的效果，也就是放大。但是我鼠标明明没放上去」）
- **真实性**：✅ 真 bug。库页卡片放大只由 `fushi/lib/src/utils/components/fushi_hover_lift.dart:221-225` 的 `MouseRegion.onEnter/onExit` 驱动（`home_video_page.dart` 四处 `FushiHoverLift` 的 builder 都无视 hover 参数），即 Flutter `MouseTracker` 认定「有一个指针停在那张卡上」。这个指针不是用户的鼠标：播放页 `fushi/lib/src/pages/implementations/video_fushi/controls_visibility.part.dart:70-75` 的 `_pokeControlsVisible` 为了唤醒 media_kit 控制条，用固定设备号 `_syntheticHoverDevice = 0x6869626B`（`video_fushi_page.dart:924`）、`kind: mouse`、位置 = 视频区几何中心，经 `GestureBinding.handlePointerEvent` 派合成 `PointerHoverEvent`（`:127-135` `_dispatchPokeHover`）。Flutter `MouseTracker.updateWithEvent` 对未知设备的 hover 会新建一条 `_MouseState`，**只有收到同设备的 `PointerRemovedEvent` 才删**（SDK `rendering/mouse_tracker.dart:324-331`）；全仓没有任何地方派过这个 remove。于是只要本次会话打开过播放器，幽灵指针就永远停在屏幕中心；退出播放器后每帧帧末 `updateAllDevices` 都在那一点命中测试，库页中心那张卡的 `MouseRegion` 收到 `onEnter`，`FushiHoverLift` 放大。用户描述的「中间附近」「鼠标明明没放上去」与此完全吻合（同一幽灵指针也会让此后落在屏幕中心的任何 `MouseRegion`——按钮 hover 高亮、tooltip——被当成悬停）。
- **[x] ① 已修复** — 合成设备随播放页**失去栈顶**注销：`_VideoFushiPageState.didChangeDependencies` 给本页路由的主动画（进入 `reverse` = 被 pop）与次动画（进入 `forward` = 新路由压上来 / `pushReplacement` 换集替换本页）各挂一个状态监听（`_attachSyntheticHoverRouteListeners`，`controls_visibility.part.dart`），任一触发即 `_retireSyntheticHoverDevice`：清 `_pendingPokeHover`，并排一个 **post-frame** 派同设备、同 kind 的 `PointerRemovedEvent`；「在册」旗 `_syntheticHoverDeviceLive` 由 `_dispatchPokeHover` 真派发前置真、在 post-frame 真正派发那一刻清零（排队到派发之间再 poke 的那条 hover 同样被删）。`dispose()` 只摘监听，**不派任何指针事件**。三条否决过的写法：(a) 每次 hover 后立刻注销——media_kit fork 的 `onExit`（`third_party/media_kit_video/.../material_desktop.dart:633-640`）无条件 `visible = false`，remove 会触发它，poke 白派；(b) `dispose()` 里同步注销（第一版，code review 打回）——dispose 跑在 `finalizeTree` 锁态内，pop 反向过渡期间本页 `IgnorePointer`、幽灵指针早已进到下层库页中心那张卡上，remove 让那张仍挂树的卡 `onExit → setState` 撞「setState() or markNeedsBuild() called when widget tree was locked」，dispose 后半段整段跳过；`pushReplacement` 换集时旧页 dispose 晚于新页入场，还会把新页 media_kit 全画面 region 刚露出的控制条和光标一起藏掉；(c) `RouteAware`——`AppModel.routeObserver` 从未挂到任何 Navigator；`ModalRoute.isCurrent` 也不行，pop 不重建 `_ModalScope`，那个值在被 pop 的路由上是陈旧的。post-frame 派发不在 build / finalize 锁内，且早于 `RendererBinding` 在 `drawFrame` 之后才登记的 MouseTracker 帧末重命中，所以幽灵指针来不及进入下层页 / 新页的任何 region，onExit 只落在本页自己正在退场的控制条上。提交：见本轮 commit（首版 8dd895ccf8，返工见后续 commit）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_synthetic_hover_device_retire_guard_test.dart`（10 条）。① 行为层用真 Navigator（`MaterialPageRoute` 带过渡的 push / pop / pushReplacement）+ 真 `FushiHoverLift` 在 Flutter 真实 `MouseTracker` 上复现四态：不注销 → pop 后 `mouseIsConnected` 仍真、下层中心卡 builder 拿到 `hovering == true`（症状本身）；失去栈顶时注销（修复同构）→ pop 全程逐帧采样下层卡从未被判 hover、设备表清空、无任何 FlutterError、真实鼠标移到同一位置仍能悬停（正向对照）；第一版 dispose 同步注销 → 自管 `FlutterError.onError` 收到含 `locked` 的断言（审查指出的失败形态钉成回归，用例收尾要 `initMouseTracker()` 换新追踪器，因为锁态断言把 `_debugDuringDeviceUpdate` 卡在 true）；pushReplacement 到第二个播放页 → 新页 region 既没收到幽灵 onEnter 也没收到 onExit。② 源码守卫全部用 `containsCodeLine`（剥注释）钉：`didChangeDependencies` 挂路由监听、两条监听各看 `reverse` / `forward`、注销走 `addPostFrameCallback` 且旗在派发时清零、`dispose` 只摘监听不含 `handlePointerEvent(` / `_retireSyntheticHoverDevice();`、`_dispatchPokeHover` 派发前登记在册、测试复刻设备号与生产常量同值。
- **备注**：残留面：播放页**打开期间**幽灵指针仍停在视频区中心（poke 语义所需，与之前一致），落在那一点的其它 `MouseRegion`（例如盖在中心的浮层按钮）依旧会被当成悬停；hot reload 把本页 State 整个卸载（不经 pop）时不注销，只在 debug 出现、下一次 poke/退页即修正。彻底消除要给桌面 fork 加与移动端 `restartHideTimerSignal` 同构的唤醒信号、删掉合成设备（连带 BUG-215 抖动、BUG-425 微任务、BUG-1798 过滤三处补丁一起删），另开任务。未做真机复测（本机 Windows itest 受 ATL 阻塞，见记忆），原始失败路径（库页开视频 → ESC 退出）由上述真 Navigator widget 测试覆盖。
