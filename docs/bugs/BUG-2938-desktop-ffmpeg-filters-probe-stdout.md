## BUG-2938 · 桌面端片段导出滤镜探测丢 stdout，硬字幕恒不烧
- **报告**：2026-10-04（用户：qqbotxiaoxiao；读代码推出，agent 复现确认）
- **真实性**：✅ 真 bug。根因 `packages/fushi_engine/lib/media/video/video_clip_exporter.dart:404`（`_probeFfmpegFilters` 用 `backend.run(['-hide_banner','-filters'])` 的 `.output` 解析滤镜表）+ `packages/fushi_engine/lib/media/video/ffmpeg_backend.dart:410`（桌面 CLI 后端的 `runFfmpegProcess` 执行 `process.stdout.drain()`、只把 stderr 作 output）。ffmpeg 把 `-filters` 表写到 **stdout**，所以桌面三端探测恒为空集 → `ffmpegCanBurnClipSubtitles` 恒 false → app 视频片段导出的硬字幕烧录（BUG-2202）**静默退化为无字幕导出**，从未真正生效。
  - 复现（Linux，ffmpeg 6.1）：`ffmpeg -hide_banner -filters 2>/dev/null` 能列出 `overlay` / `subtitles`，`2>&1 >/dev/null` 为空；最小 Dart 复现 `const CliFfmpegBackend().run(['-hide_banner','-filters'])` → `rc=0 outputLen=0`、`filters=0 canBurn=false`。
  - 影响面：**桌面 Windows / macOS / Linux**（`CliFfmpegBackend`，含显式 `FUSHI_FFMPEG` / 服务端 `ffmpeg:` 覆盖的任何平台）。移动端 Android / iOS 的 `KitFfmpegBackend` 不受影响：ffmpeg-kit 的 fftools 把 `printf` 换成了 `av_log(NULL, AV_LOG_STDERR, …)`（`AV_LOG_STDERR` 定义见 vendored `ffmpegkit.framework/Headers/fftools_cmdutils.h:82`），查询表落在 `session.getOutput()` 里。
  - 无头服务端 `video clip --burn-subs` 之前已知此问题，在 `packages/fushi_server/lib/src/commands/video_commands.dart` 里另起 `Process.start` 自己收 stdout 绕过（重复实现）。
  - 同类排查：仓库里其余经 `backend.run` 的 `-version` 调用（`subs_commands.dart` 的 `ffmpegUnavailableReason`）只看退出码，不受影响；hls demuxer 能力探测（`desktop_audio_clipper.dart` 的 `-h demuxer=hls`）走 `runProbe`（ffprobe，收 stdout），不受影响；`lib/` 内没有其它 `-encoders` / `-codecs` / `-hwaccels` 查询。
- **[x] ① 根因修复** — 提交 `ce91224e8b`：`FfmpegBackend` 新增查询原语 `runQuery`（output = stdout + stderr），`run` 契约不变（仍 drain stdout，保护 `pipe:1` 二进制输出与错误摘要）。CLI 后端经同一套「覆盖 > 捆绑 > PATH」回退走新的 `runFfmpegQueryProcess`；`BlurayFfmpegBackend` 直传；`KitFfmpegBackend` 复用 `run` 的会话路径。三个顶层 runner（ffmpeg / 查询 / ffprobe）收敛到唯一的 `_runToolProcess`（一处 drain/超时/SIGKILL）。引擎公开 `queryFfmpegFilterNames(backend, timeout)`（非零退出按探测失败），app 片段导出与 fushi_server `probeFfmpegFilterNames()` 共用，删除服务端单独的 `Process.start` 探测。
- **[x] ② 自动化测试** — `packages/fushi_engine/test/ffmpeg_query_contract_test.dart`：假后端证明探测只走 `runQuery`、不走 `run`，非零退出判空，蓝光包装直传；本机有 ffmpeg 时真跑 `runFfmpegQueryProcess` / `CliFfmpegBackend` 探测，断言与 ffmpeg 自己打印的表一致且含 `overlay`（有 libass 时含 `subtitles`），并钉住 `run` 仍不收 stdout。`fushi/test/media/video/ffmpeg_backend_selection_test.dart` 守卫改为「三个 runner 共用唯一一处 sigkill」。
- **备注**：`FfmpegBackend` 是接口，加原语后所有测试假件都补了 `runQuery`（委托 `run`）。
