## BUG-4730 · 桌面退出时引擎先于 libmpv 回调收尾，mpv 核心线程回调进已释放跳板崩溃
- **报告**：2026-11-16（应用内反馈 H6Vou-6uYX：macOS 3.3.0-debug.24478 闪退 2 次，两份 .ips 同签名 `EXC_BAD_ACCESS SIGSEGV`，出错线程 `? ← mp_client_send_property_changes ← mp_wait_events ← run_playloop ← core_thread`；出事前在 MusicLyricsPage 放音乐，会话标记 `exitRequested=windowClose`，阶段停在退出链的并行步骤）
- **真实性**：✅ 真 bug。发布构建的 media_kit 给每个播放器注册 `NativeCallable.listener` 当 libmpv 唤醒回调（pub cache `media_kit-1.2.6/lib/src/player/native/core/initializer_native_callable.dart:50-55`），只有逐个 `Player.dispose` 才先 `mpv_set_wakeup_callback(null)`（同文件 `:64-68`）。退出链 `fushi/lib/main.dart` `_flushAndExitForWindowClose`（:1655 起）从不 dispose 播放器，也没有任何一步解绑回调。进程却可能不经链尾 `exit(0)` 结束：会话标记只在「进入」阶段时落盘，停在并行步骤、没进 `book-exit sync drain` 说明进程死在并行阶段、链没走到 `exitApp`。macOS 上链在跑时再来一次退出请求（Dock 退出、再按 ⌘Q、注销），`_handleExitRequested`（main.dart:1607）见 `_shutdownStarted` 立即答 `AppExitResponse.exit`；Flutter 引擎的 `FlutterEngineTerminationHandler` 在第一次请求时就把 `_shouldTerminate` 置 YES，第二次 `applicationShouldTerminate:` 直接 `NSTerminateNow`。两条都进 `NSApp terminate`，`FlutterEngine applicationWillTerminate:` 调 `shutDownEngine` 拆掉 isolate、释放回调跳板，而 libmpv 核心线程仍在派发属性变更 → 跳进已释放地址（栈顶 `?`）。与 BUG-3003（Windows 热重启）同一机制：libmpv 活得比注册回调的 isolate 久。
- **[x] ① 已修复** — 「开始退出」与「libmpv 不再回调 Dart」改成同一个同步点：`fushi/lib/src/platform/app_exit_coordinator.dart` 的 `begin()`（所有有意退出的第一步，`terminate` / `terminateVia` 也经它）在写意图之前先同步调 `quiesceNativeCallbacksForProcessExit()`。该入口是 media_kit 覆盖补丁新增的公开库 `ci/patches/hosted/media_kit-1.2.6/lib/native_exit.dart`，实现在补丁版 `initializer_native_callable.dart` 的 `quiesceForProcessExit()`：对所有在世句柄 `mpv_set_wakeup_callback(ctx, null, null)`（与 libmpv 调回调时持同一把锁，返回后核心线程不可能再进 Dart），并让之后新建的句柄不再注册回调。不 dispose、不 close：之后的命令 / 属性写仍可用，后来的 `Player.dispose` 照常安全。事件 isolate 后端（Windows debug / execmem 受限）本就不给 libmpv Dart 函数指针，无需处理。
- **[x] ② 已加自动化测试** — `fushi/test/third_party/media_kit_hot_restart_test.dart` 新增 `quiesce` 模式（探针 `fixtures/media_kit_isolate_exit_probe.dart`）：真实子进程 + 真实 libmpv，直接用发布构建的 NativeCallable 后端建句柄，调退出摘回调入口后不 dispose 就杀掉 owner isolate（等同引擎关停），再 wakeup / quit。修前（入口为空实现）子进程报 `Callback invoked after it has been deleted`、退出码 `-1073740791`；修后退出 0。`fushi/test/platform/app_exit_coordinator_test.dart` 断言 `begin` 在第一个 await 之前、写意图之前摘回调，`terminate` / `terminateVia` 直达路径同样先摘。
- **备注**：libmpv 测试需要 Windows libmpv（`FUSHI_TEST_LIBMPV` 或本 worktree 的 Windows Debug 构建），否则 skip。macOS 真机退出路径未复测。「链在跑时第二次退出请求立即放行终止」本身会跳过关库（WAL 下次启动回放，不丢已提交数据），是否让第二次请求等第一条链跑完属另一项改动，未在本修复里动。
