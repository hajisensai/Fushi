## BUG-2918 · 首页继续面板仍显示已读完的书
- **报告**：2026-10-03（用户：QQ 群反馈，首页「続きから」里挂着一本显示 100% 的书；打开确认「已经最后力」——滚轮到底、已读到最后一页。另一本之前读完的书则不在面板里。）
- **真实性**：✅ 真 bug。首页「继续」区判在读只看进度 `item.position > 0 && item.position < item.duration`（`fushi/lib/src/pages/implementations/home_dashboard_page.dart` `_buildContinueSection` 书循环条件），完全不看读完标记 `EpubBooks.completedAt`。阅读器落库的位置是末页**首个可见字符**，读到最后一页 position 也永远 < duration，百分比四舍五入显示 100%，于是读完（completedAt 已由阅读器自动或手动写入）的书照样留在「继续」。「之前那本不在」是因为它的位置恰好等于 duration（或从头开始读完），落进了旧判据的排除分支——两本书走的是同一条错判据，只是数值不同。书架读完筛选 / hero 计数早已用 `classifyShelfReadStatus`（`packages/fushi_engine/lib/media/collections/shelf_sort.dart`，completed 优先于进度），首页是唯一没接上的消费方。
- **[x] ① 已修复** — 首页判据收敛到同一条 `classifyShelfReadStatus`：新增 `isDashboardContinueBook(item, completedBookKeys)`（`home_dashboard_page.dart`），完成集合由新的 `completedEpubBookKeysProvider`（`reader_fushi_source.dart`，读 `getCompletedEpubBookKeys()`）提供；关书 `onSourceExit` 与首页表级重载 `_scheduleReload` 同点失效它；`watchDashboardDataChanges()`（`database_statistics.part.dart`）的表集补上 `epubBooks`，书架标记完成 / 同步回灌完成标记后首页同一条通道重算。提交见 PR。
- **[x] ② 已加自动化测试** — `fushi/test/pages/home_dashboard_continue_book_test.dart`（用户原样形态 9960/10000 + 已完成 → 不进；在读 / 未开读 / 位置到 duration / 前缀 key 不误中）；`fushi/test/database/epub_books_test.dart`「watchDashboardDataChanges 在写入完成标记时 emit」（表集漏 `epubBooks` 时红）。
- **备注**：standalone SRT 等无 bookKey 的条目回退 mediaIdentifier 查完成集合，查不到即按进度判，与旧行为一致。
