## BUG-4370 · 音乐 WASAPI 独占输出暂停时不交还设备
- **报告**：2026-11-08（应用内反馈 WY8uvL1Vfy：「独占输出开启时，音乐暂停没有释放独占设备的占用」；Windows，3.3.0-debug.23880）
- **真实性**：✅ 真 bug。`fushi/lib/src/media/music/mpv_music_output_backend.dart:1363`（修前）`pause()` 只是 `_player.pause()`（mpv `pause=yes`）。mpv 暂停只让 AO 停止消耗缓冲（`player/audio.c` `ao_set_paused`），WASAPI 独占流 / macOS `coreaudio_exclusive` 的 hog mode 一直开着；后端只在停止 / 播完 / 出错时经 `_releaseAudioDevice`（`stop` + `ao-reload`，同文件 :1189）卸 AO。所以独占模式下暂停期间别的程序放不出声。
- **[x] ① 已修复** — 维护者拍板「怎么做对就怎么做，可参照 foobar2000 等」：暂停即交还独占设备、恢复时重新获取。实现：独占（`audio-exclusive=yes` 已下发、没退回共享）时，暂停后对**已初始化好的当前文件**写 `file-local-options/aid=no`——mpv `mp_switch_track_n` 没有音轨时 `uninit_audio_chain` + `uninit_audio_out`（`player/loadfile.c`），设备立刻关闭；文件不卸载、位置不动，两条链都没有时 `handle_eof` 不结束文件（`player/playloop.c`），不会误判播完。恢复播放先写 `file-local-options/aid=auto` 选回音轨（mpv 按当前位置重建音频链、重开设备；设备此时被别人独占则走既有 `_recoverOutput` 退共享），再取消暂停。用逐文件选项而不是全局 `aid`：全局值会带进下一次 loadfile 让下一个文件「没有可播的流」；逐文件值随文件卸载由 mpv 还原。「要不要交还」做成状态（`_pauseWanted` 且独占），由 `_syncPausedDevice` 在暂停、`current-ao` / `current-tracks/audio/id` 变化时收敛，覆盖不起播的打开（暂停态换曲 / 恢复会话）与暂停早于加载完成；读 mpv 状态到下发之间用 `on_unload` 钩子计数作废换了文件的那次。播放 / 暂停用代次防止选回音轨途中又暂停时被旧的 `play` 起播。
- **[x] ② 已加自动化测试** — `fushi/test/media/music/music_mpv_backend_real_test.dart`（真 libmpv，`ao=null`，平台按 Windows 下发 `audio-exclusive=yes`）：「独占输出：暂停即交还设备…恢复后原位接着放」（暂停后 `current-ao` 为空、`aid=no`、`time-pos` 不动、文件未卸载、不报播完；恢复后 AO 重开、从暂停处接着放直到播完、无失败事件）；「共享输出：暂停不动音轨与设备」；「独占输出：不起播的打开 / 暂停早于文件加载完成——加载完成后照样不占设备，按播放后正常出声且不报错」（同时钉住上一首的取消选中不会带进下一次 loadfile）。
- **备注**：测试未在本分支运行，统一在合并后验证。真机（真 WASAPI 独占设备被其他程序抢用）未验证。
