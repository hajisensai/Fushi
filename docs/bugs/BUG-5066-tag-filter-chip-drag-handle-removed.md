## BUG-5066 · 库页标签 chip 左侧的拖动柄删除，拖动改由 chip 按指针类型分流
- **报告**：2026-11-21（应用内反馈 yC9PzmjPH2，开发者本人：「标签左边的东西给我删掉」；截图为库页标签条，每枚标签 chip 左侧一个「⋮⋮」）
- **真实性**：✅ 真问题（UI 回归，沿代码定位）。截图里的「⋮⋮」是 BUG-4899 加的 `FushiTagDragHandle`：`fushi/lib/src/pages/implementations/tag_filter_bar.dart:337-345`（修复前）在每枚非多选 chip 前用 `Row` 塞一个柄，组件在 `fushi/lib/src/media/tags/tag_drag_handle.dart`，全仓只此一处使用。柄是对 BUG-4899（鼠标长按拖动输给 `HorizontalDragScrollable` 横滚，见该文件根因）的绕行：拖动入口仍只有 `LongPressDraggable`（`tag_filter_bar.dart:301`，修复前）一条，鼠标只好另开一个即时拖的柄，代价是每枚标签前多一个视觉噪音元素。只删柄会让 BUG-4899 复发。
- **[x] ① 已修复** — 删 `tag_drag_handle.dart` 与柄的接入；新增 `fushi/lib/src/media/tags/tag_chip_draggable.dart`（`FushiTagChipDraggable`）：chip 本身按指针类型分流起拖——鼠标 / 触控板走只认这两类设备的即时 `Draggable`（`ImmediateMultiDragGestureRecognizer(supportedDevices:)`，越过 hit slop 才起拖，比滚动区深、同一帧先认领，横滚抢不到；不动松开仍是单击筛选），触屏 / 触控笔走只认这几类设备的 `LongPressDraggable`（短滑仍归横滚）。两套设备集不重叠，不进同一竞技场。`tag_filter_bar.dart` 直接返回 `FushiTagChipDraggable` 包 `DragTarget` 的 chip，不再有 `Row` + 柄。代价：鼠标在 chip 上拖不再横滚标签条（修复前柄以外的 chip 区域按住拖是横滚），鼠标横滚改走 Shift+滚轮（标签条没包 `WheelToHorizontalScroll`，裸滚轮不横滚；横向 `Scrollable` 只取滚轮 dx，见 BUG-1214）、触控板横扫与 chip 间空白处拖动。标签很多的鼠标用户横滚入口变窄，若要恢复裸滚轮横滚需另评估 BUG-1536（嵌在纵向页面里的横向区包滚轮映射会抢走整页纵滚）。
- **[x] ② 已加自动化测试** — `fushi/test/media/tags/tag_chip_draggable_test.dart`（横向 `HorizontalDragScrollable` 列表里：根因复现「只有长按拖动 + 鼠标 2 px 抖动 → 拖动认输、列表被横滚」；鼠标在 chip 上按住即拖并重排、列表不滚；鼠标单击仍是点选不起拖；触屏短滑归横滚不起拖；触屏长按后拖动重排）+ `fushi/test/pages/tag_filter_bar_chip_drag_test.dart`（接入层 `FushiTagFilterBar`：可拖区域左缘就是 chip、没有前置柄，多选模式不可拖；鼠标按住 chip 拖到另一枚触发 `onReorder(0, 2)` 且不触发筛选；鼠标单击切换筛选；触屏长按拖触发 `onReorder(2, 0)`）。替换了 BUG-4899 的 `tag_drag_handle_test.dart` / `tag_filter_bar_drag_handle_test.dart`。
- **后续（BUG-5174，2026-11-22）**：上面「鼠标即时拖、chip 上拖不再横滚」的代价开发者不接受（应用内反馈 tJxhjzEQbi）。现行实现：所有指针都长按才起拖，长按识别与标签条的鼠标横滚共用容忍手抖的门槛 `longPressTolerantHitSlop`（鼠标 `kTouchSlop`），按下就拖 = 横滚、长按后拖 = 重排、不动松开 = 单击；柄仍然没有。详见 BUG-5174。
- **备注**：未在 Windows 真机用鼠标复测（按仓库现行约定真机验证不做），手势行为由上面的 widget 测试按真实竞技场覆盖。
