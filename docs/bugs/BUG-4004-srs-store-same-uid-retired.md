## BUG-4004 · srs-store-same-uid-retired
- **报告**：2026-11-03（用户：两位用户反馈日志，iOS + Android，3.3.0-debug.23213）——复习同步 v2 收段、`srsPurgeExpiredTombstones`、`compactStoredStyles` 反复报 `Bad state: SRS store is unusable: profile <当前 uid> is no longer the active SRS profile`，常在启动后几秒；整轮收段作废、下次从头再来。用户没切过配置。
- **真实性**：✅ 真 bug（沿真实代码路径验证，未在用户设备上复现）。`fushi/lib/src/srs/srs_profile_stores.dart` `_handOver` 只要旧激活副本还能写就 `retire` 它，不比较 uid；`activate` 每次都走交接。`srsStoreProvider`（`fushi/lib/src/srs/srs_providers.dart`）watch `activeProfileId`，而 `ProfileUiState.activeProfileId` 初值 -1、`ProfileViewModel._load()` 异步写入真实 id（`fushi/lib/src/profile/profile_view_model.dart`）：启动时 provider 先按 -1 自己解析一次打开副本 A 并起样式去重 / 媒体回收 / 同步，装载完成 id 变成真实值时 provider 重建，同一 uid 再 `activate` → A 被作废，在跑的写入全部抛错。另一处缺陷：收段那一轮的 finally 调 `sync2IngestEnd`，它也要进独占区，副本已作废时直接抛，`ingest_end` 没发到内核，会话（含预处理好的段）留在内核里。
- **[x] ① 已修复** — ① `SrsProfileStores.activate` 同 uid、副本可写且未在作废时复用原副本，`reuse` 回调就地换参数（`SrsDbStore.rebind`），连接 / 设备 ID 变了才交接；② `ProfileViewModel.loaded` + `srsStoreProvider` 先等配置装载完再读激活 id，消除 -1 → N 重建；③ `SrsDbStore.retire` 一调用就置 `isWindingDown`，最后一段独占区里先放掉收段会话（`ingest_end`）再跑交接体，作废错误改为带副本的 `SrsStoreRetiredError`；`sync2IngestEnd` 在会话已被作废放掉时不再进独占区；样式去重 / 媒体回收（`srsPurgeExpiredTombstones` 新增 `shouldStop`）/ 同步一轮的 `shouldStop` 都看 `isWindingDown`；④ `SrsSyncScheduler._runRoundOn` 把「本轮副本被作废」按收手（`kSrsSync2Stopped`，不计失败）交回，`_syncWithBackend` 用新副本马上重排一轮（只一次，读到的仍是旧副本则按副本不可用交回）。提交见分支 `pr/srs-store-same-uid-handover`。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_store_same_uid_handover_test.dart`（同 uid 两次 activate 复用 + 换 uid 仍作废；provider 容器在配置装载期间不打开、装载完只开一次、配置视图重建沿用同一副本；调度器副本被换掉按收手结束并用新副本重排、读到旧副本不打转）；`packages/fushi_engine/test/srs/sync2/srs_sync2_retire_mid_ingest_test.dart`（真实内核：收段途中作废，内核无残留会话，新副本下一轮收完结果与一次收完相同）。
- **备注**：同一轮里已提交的片保留在库里，下一轮 `finishPending` 收尾；作废时内核会话随即放掉，不再滞留预处理段占内存。旧副本的检查点收手依赖已有的 `ingest_yield`（排队写入请内核当场收片）。
