## BUG-2554 · 漫画查词命中字不高亮
- **报告**：2026-09-15（用户：Windows 桌面版漫画阅读器，「选中的文本不会高亮显示」）
- **真实性**：✅ 真 bug。高亮机制是 JS `fushiSelection.highlightSelection(n)` 用 CSS Custom Highlight `fushi-selection` 画（`fushi/lib/src/reader/reader_selection_scripts.dart:1717-1792`），**由 Dart 在查词后主动 eval**（`:1431` 注释明说 tap 路径自己不渲染）。小说页在 `_highlightAndShowPopup` 里 eval `highlightInvocation(count)`（`reader_fushi/lookup.part.dart:113-116`）且正文样式有 `::highlight(fushi-selection)` 规则（`reader_content_styles.dart:723,855`）。漫画页修复前：`processMangaSelection` 把 `searchDictionaryResult` 返回的 `highlightCount` 直接丢弃（原 `manga_fushi_page.dart:3795-3798` 不接返回值），全文件没有任何 `highlightInvocation` 调用；覆盖层文档 `mangaWindowDocument` 的 `<style>` 只有 `.ocr-box/.ocr-char` 规则、没有 `::highlight(...)`（原 `manga_overlay_html.dart:693-713`）——两处缺一样都画不出来，实际两处都缺。
- **[x] ① 已修复** — `manga_overlay_html.dart:717` 加 `::highlight(fushi-selection){background-color:rgba(255,196,0,0.45);}`（半透明，不盖页图原字）；`manga_fushi_page.dart:3848` 接住 `highlightCount` 交给新 `_highlightMangaSelection`（`:2781`，与阅读器同一「弹窗先显、高亮异步一跳」解耦范式）；`onAllPopupsDismissed` 追加 `_clearMangaSelectionHighlight`（`:2768`，eval `clearInvocation()`，fire-and-forget 不阻断焦点归还）。提交：`44a9937c03`。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_lookup_barrier_relookup_test.dart`：文档契约（`::highlight(fushi-selection)` 规则存在）+ 页面源码守卫（`highlightCount` 必须接住并喂 `highlightInvocation`；整栈关闭必须 eval `clearInvocation`）。
- **备注**：命中层字符是逐字绝对定位的 `.ocr-char`（`color:transparent`），`::highlight` 只画背景不受影响。**真机复测未做**（同 BUG-2553 原因）：Windows 上点字后预期该词（去屈折后的命中长度）底下出现黄色半透明高亮，关弹窗后消失。
