## BUG-1119 · remote-continue-kind-downcast
- **报告**：2026-07-26（用户：）
- **真实性**：✅ 真 bug——`RemoteContinueCandidate` 用 `bool isVideo` 把媒体种类二元降维（`hibiki/lib/src/utils/misc/dashboard_remote_merge.dart:16,25`），首页消费点把非视频候选一律硬编码成 epub（`hibiki/lib/src/pages/implementations/home_dashboard_page.dart:808`：`c.isVideo ? MediaKind.video : MediaKind.epub`）。这是 BUG-1111（commit 344b058a6，本地 `_ContinueEntry.isVideo` 枚举化）的漏网消费点：远端 SRT 书一旦进清单会被抹成 epub，游戏等第三种媒体结构上进不了远端「继续」。
- **[x] ① 已修复** — `72ada8505`：wire 端 `RemoteBookInfo` additive 加 `kind` 字段（`hibiki/lib/src/sync/hibiki_library_host_service.dart`：toJson 在 epub 缺省**不写键**→旧书清单 wire 字节完全不变；fromJson 缺失/未知一律 `MediaKind.tryParse ?? epub` 回落，旧 host 兼容；copyWith 透传）；host 侧 `listBooks` 显式标 `kind: MediaKind.epub`（`hibiki/lib/src/sync/app_model_library_host_service.dart`，EpubBooks 行都是 EPUB 卡，与本地 `_bookMediaKind` 按 `hoshi://book/` 身份判 epub 一致）；`RemoteContinueCandidate` 改携带 `MediaKind kind`（保留派生 getter `isVideo`，旧消费点零改动），书循环取 `b.kind`、视频循环恒 `MediaKind.video`；`home_dashboard_page.dart` 消费点改直读 `c.kind`。注：standalone SRT 书（`hoshi://srtbook/<uid>`，无 EpubBooks 行）今天不在 host 书清单里，「远端 SRT 书真正进清单」是独立 follow-up，本条只拆结构降维。
- **[x] ② 已加自动化测试** — `hibiki/test/sync/interconnect_dashboard_feed_test.dart`：wire 回环（无 `kind` 键→epub 旧 host 兼容、`'srt'`→srt、未知串容忍回落 epub、epub 缺省不写键的 wire 字节守卫、copyWith 保 kind）+ `remoteContinueCandidates` 种类管道（SRT 书候选 kind==srt 不被抹成 epub、默认书 epub、视频 video）+ 候选结构装得下 `MediaKind.game`。
- **备注**：审计 bug#5。档案原路径口径修正：`dashboard_remote_merge.dart` 实际在 `hibiki/lib/src/utils/misc/`（非 `sync/`）；`RemoteContinueCandidate` 是 client 端内存混排模型而非 wire DTO，additive 字段落在真正的 wire 类型 `RemoteBookInfo` 上（视频走独立 `/api/library/videos` 清单天然 video，无需字段）。「远端游戏进继续列表」还需游戏 wire 导出（BUG-1111 已明文设计游戏为本机局域身份，不参与互联远端补位），本条只拆掉结构性障碍不承诺可达。
