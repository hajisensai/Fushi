## BUG-1116 · reader-settings-prefcodec-one-way
- **报告**：2026-07-26（用户：审计 bug#2）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/reader/reader_settings.dart:129`（修复前 `_parseValue` 只做 true/false/int/double/string 裸值启发式，不识别 PrefCodec 类型标签）。同一 `src:reader_ttu:*` DB key 有两个写入方：ReaderSettings `_set`（reader_settings.dart:122，裸 `toString()`）与 MediaSource `setPreference`（media_source.dart:164，`PrefCodec.encode` 标签值）；`ReaderHibikiSource.readerSettings` 为 static、在 `AppModel.initialise` 完成前为 null（reader_hibiki_source.dart:930），此窗口内 46 处 `?? setPreference(...)` 回退全部落标签值（'b:false' / 'd:22.0'）到同一 key。ReaderSettings 重启加载读到标签值：bool/int/double 解析成 String → `_get<T>` 类型不符 → 静默回落默认（用户偏好丢失）；String 型更糟——整串 's:vertical-rl' 被当值直接采纳（污染值）。单向不兼容：MediaSource 读侧早已用 `PrefCodec.decodeUntyped` 双格式兼容（media_source.dart:139）。
- **[x] ① 已修复** — `51c8c30c9`：`_parseValue` 改为委托 `PrefCodec.decodeUntyped`（严格超集：`decodeUntyped` 的非标签分支与旧启发式逐行等价，旧裸值行为逐字节不变）。刻意**不改写侧 `_set`**：写侧改标签编码会破坏既有裸值断言且引入降级不兼容（旧版本读不懂标签），留作可选后续。
- **[x] ② 已加自动化测试** — `hibiki/test/reader/reader_settings_pref_codec_compat_test.dart`：(a) 回退路径真实双写复现（`setTtuFontSize` 落 'd:30.0' 后新 ReaderSettings 实例必须读回 30）；(b) 'b:false' → bool；(c) 'i:600' → int；(d) 's:horizontal-tb' → String 不吃进污染串；(e) 旧裸值 '26.5'/'false'/'vertical-rl' 行为不回归；(f) 'z:' → 回落默认不崩。相邻爆炸半径全绿：`test/settings/top_progress_toggle_guard_test.dart`、`test/reader/reader_content_styles_test.dart`、`test/reader/reader_chrome_floating_test.dart`、`test/database/pref_codec_test.dart`。
- **备注**：`top_progress_toggle_guard_test.dart` 74-77 行注释「decode 端两者皆兼容」修复前不成立（只有 MediaSource 侧兼容），已随修复更正为现实描述。key 名（`ttu_*` / `src:reader_ttu:` 前缀）零变更，不触审计 §0 红线。
