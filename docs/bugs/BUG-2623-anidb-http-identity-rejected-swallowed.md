## BUG-2623 · AniDB HTTP API 拒绝内置客户端身份（302）被吞成「详情不可用」且每作品重试
- **报告**：2026-09-22（用户：刮削日志截图，高木同学 2 每集一条「AniDB HTTP 详情不可用，已保留标题目录摘要且不会把分集标记为完整。」）
- **真实性**：✅ 真 bug。直接用内置身份请求 `http://api.anidb.net:9001/httpapi?client=fushiplayer&clientver=1&protover=1&request=anime&aid=14591`，AniDB 回 HTTP 200 + gzip `<error code="302">client version missing or invalid</error>`——`anidb_app_client.dart` 里登记的是 **UDP** 客户端（29913），HTTP API 客户端是另一条登记、从未登记过，所以 2026-09-20 起装配的 anime XML 资料链在生产**从没成功过**（本机两套数据根都没有 `anidb_anime/AnimeDoc_*.xml`，安装版最近 5 次运行每个作品都有这条）。代码侧根因：
  - `packages/fushi_engine/lib/media/video/metadata/anidb_video_metadata_provider.dart:508-525` `_parseAnime` 只认 `not found` / `banned`，302 当普通网络异常抛出；`fetchWork` / `fetchSeasons`（`:177-216`）吞掉异常退成 catalog-only，`episodeInfo`（`:437`）吞成 null → 全部集信息退回 UDP `EPISODE`；
  - `_loadAnime`（`:288`）失败后 `_animeCache` 条目被移除，`isHttpApiAvailable`（`:127`）只看本地配置不看服务端拒绝 → 一批 N 个作品发 N 次注定失败的请求，各占 3s 限流闸；
  - `video_source_scrape_coordinator.dart:3230-3238` `_hydrateWork` 打的是不带原因的固定文案，用户/开发者都看不出是身份被拒、封禁、没配身份还是网络故障。
- **[x] ① 已修复** — provider：请求闸按「client/version」记住 302 拒绝（`_AniDbRequestGate.latchIdentityRejection`），`isHttpApiAvailable` 吃这个闩（本进程后续直接 catalog-only + UDP，不再撞 httpapi；用户换自定义 client 键不同自然解闩），新增 `httpIdentityRejection` / `httpDetailUnavailableReason`（302 / 封禁 / 未配身份 / 最近一次传输失败四种原因分开说）；协调器 `_hydrateWork` 把原因写进日志：「AniDB HTTP 详情不可用（AniDB 拒绝了客户端身份 fushiplayer/1：client version missing or invalid（code 302）（HTTP API 客户端未登记或版本无效，与 UDP 客户端是两条登记）），已保留标题目录摘要…」。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/metadata/anidb_provider_shoko_chain_test.dart`：`a 302 client identity rejection latches the identity and is reported`（一次 302 后 fetchWork / fetchSeasons / fetchEpisodes / episodeInfo 都不再发请求，原因外显）、`a transport failure is reported as the detail-unavailable reason`（网络故障不当身份问题）。
- **备注**：代码只能把事实说清楚 + 止损，**根治要所有者在 AniDB 项目 20715 下登记 HTTP API 客户端**（或给现有客户端启用 HTTP）。若 AniDB 给的 HTTP 客户端名与 UDP 不同，`VideoSourceScrapeGlobalConfig` 现在 UDP/HTTP 共用一对 `anidbClientName/Version`，届时要拆成两组身份。
