## BUG-584 · 退出图1重进回图2·恢复位置错误
- **报告**：2026-07-07（用户：「图1退出·但是重进回到图2的地方」，退出位置与重进恢复位置不一致，恢复到更早的位置）
- **真实性**：✅ 真 bug（EPUB 阅读器 reader_hibiki 位置恢复）。根因 `packages/hibiki_audio/lib/src/audiobook/reader_position_repository.dart:25`。阅读位置有两套坐标：精确锚 `char_offset`（`getFirstVisibleCharOffset`→`restoreToCharOffset`，恢复不动点）与粗粒度分数 `norm_char_offset`（`calculateProgress`→`restoreProgress`）。恢复时 shell 在 `initialCharOffset>=0` 时**优先精确锚**（`hibiki/lib/src/reader/reader_pagination_scripts.dart:1522`、`:2374`；`reader_hibiki_page.dart:1412` `_initialCharOffset = saved.charOffset ?? -1`）。落库路径 `reader_hibiki/navigation.part.dart:866 _persistPosition` 在 WebView 当帧算不出精确偏移时传 `charOffset:null`（竖排/ruby 下 `caretRangeFromPoint` 失败、或有声书 cue 派生位置经 `_syncPositionFromCurrentCue` 恒传 -1）。旧 `repo.save`：同 section 且 `charOffset==null` 一律 `Value.absent()` **保留旧精确锚**，却照常把 `norm_char_offset` 更新成推进后的分数。于是滚动/播放推进了分数、精确锚仍停在上次能测到的旧位置；退出再进恢复优先精确锚 → 落回旧位置（图2），而非退出时的当前位置（图1）。属 BUG-155/BUG-162 症状类的残留（当年只补了退出前重读 WebView，没堵住「分数已推进但无新精确锚时精确锚陈旧」这条）。
- **[x] ① 已修复** — `packages/hibiki_audio/lib/src/audiobook/reader_position_repository.dart:25-46`：修正不变量「精确锚绝不能比分数陈旧」。同 section 无新精确锚时，仅当 `norm_char_offset` **不变**（当帧只是测不到、位置没动的瞬态）才 `Value.absent()` 保留旧锚；一旦分数变化说明位置真推进了但没有对应新精确锚 → 置 `Value(-1)` 失效，恢复回退到始终最新的分数。跨 section 照旧 -1 失效。瞬态 reflow 归零由上游 `stableProgressInvocation` 的 `_reanchorPending` 门控 + `_syncPositionFromWebViewProgress` 的 transientZero 守卫拦在落库前，不会以「分数归零 + 无精确锚」形式到达仓库。提交：见本轮 commit。
- **[x] ② 已加自动化测试** — `hibiki/test/media/audiobook/reader_position_repository_test.dart`：新增 `same-section null save with moved fraction invalidates stale charOffset`（分数推进→旧精确锚必须失效为 null，恢复走最新分数）与 `same-section null save with unchanged fraction preserves charOffset`（分数不变→保留旧锚，守住 BUG-162 瞬态测量失败保护）。原 `save with charOffset then same-section null preserves it` 断言已按修正不变量重写。
- **备注**：真机验收口径——EPUB 书内滚动/翻页（尤其竖排日文）到某位置后退出，回书架再重进，应停在退出那一刻的位置，不回到更早的位置；有声书跟随播放推进到某句后退出重进，应恢复到该句附近（分数粒度 ≈0.5 字符），不回到章首/旧精确锚。恢复分数粒度较精确锚略粗（章内 1/10000 ≈ 0.5 字符），肉眼阅读无感，远胜落到完全错误的旧位置。
