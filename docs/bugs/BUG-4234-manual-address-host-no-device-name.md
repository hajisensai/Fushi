## BUG-4234 · 手动地址添加的 host 没有设备名：peer ls 不列出、远端复习标题显示 host.docker.internal
- **报告**：2026-11-07（Linux Phase 4 互联测试，第 2 / 6 行；证据为实测截图，未入库）
- **真实性**：✅ 真 bug，已沿代码路径确认。用手动地址 `https://host.docker.internal:38765` 配对的 host（与配对链接不同）没有 deviceName：`fushi_cli peer ls` 里看不到它的设备名，复习 ›「复习已配对设备的卡组」页标题显示的是 URL 主机名 `host.docker.internal`（`video_remote_targets.dart` `_displayNameOf`：没名字就用 URL 主机名）。
  - 根因：host 在无鉴权的 `/api/ping` 里本来就报展示名（`packages/fushi_engine/lib/sync/fushi_sync_server/pairing.part.dart` `_handlePing` 的 `deviceName`），设置页手动地址配对也读到了它（`_attemptManualPair` → `_runPairingV2(deviceName: ping.deviceName)`，LAN 发现同样传入），但配对成功收尾把它丢掉：`fushi/lib/src/sync/sync_settings_schema/interconnect.part.dart:1074` `_onPairSuccess(baseUrl, token, fingerprint, hostId:)` 不带名字，`:1219` 写死 `addFushiClientUrl(..., deviceName: null)`。扫码 / 深链路径（`fushi/lib/src/sync/interconnect_link_pairing.dart`）自己写了一份落库并带上链接里的名字，两份落库逻辑因此分叉。已经这样配过的条目没有任何途径补名：`/api/host/addresses` 只回 hostId + 地址，学到的地址继承锚点的（空）名字。
- **[x] ① 已修复** — 提交见下方备注。
  - 配对落库收成一份：`interconnect_link_pairing.dart` `recordInterconnectPairing`（地址 + TOFU 指纹 + host 展示名 + per-peer token 落到全组地址），设置页 `_onPairSuccess`（手动地址 / LAN 发现）与扫码 / 深链共用；`_runPairingV2` 把 ping 的展示名交给 `_onPairSuccess`。
  - 老条目补名：host 在已鉴权的 `/api/host/addresses` 回包里加 `deviceName`（与 ping 同一个值）；客户端地址学习器（配对成功 + 同步选路成功后台，按锚点 10 分钟节流）把它交给 `mergeLearnedHostAddresses(deviceName:)`，同组里没名字的条目（含锚点、学到的地址）补上，已有名字不改写；老 host 不带该字段时不动。学习器只从经 TLS 钉扎的 https 锚点学（原有规则），明文 http 手动地址的老条目不会被补名（新配对不受影响）。
- **[x] ② 已加自动化测试** — `fushi/test/sync/interconnect_host_device_name_test.dart`：真 host（FushiSyncServer，TLS 自签 + per-peer token + deviceName）+ 真 `probeFushiPing` + 真 v2 配对 + `recordInterconnectPairing` → 条目带名字、`peerHostUrlToWire` 列出；源码切片守卫钉住 `_runPairingV2` → `_onPairSuccess` → `recordInterconnectPairing` 传名字、不再写死 null；没名字的老条目经真 `InterconnectAddressLearner.refresh`（`/api/host/addresses`）补名；`mergeLearnedHostAddresses` 不改写已有名字、老 host 不带名字时不动。`interconnect_settings_bug1693_guard_test.dart` 改为断言 v2 成功点经 `recordInterconnectPairing` 落凭据（否则 indexOf == -1 会让顺序断言真空通过）。
- **备注**：修复见 PR #3075。真机观察：客户端设置 › 同步 › 互联用手动地址 `https://<host>:38765` 新配对后，`fushi_cli peer ls` 的该 host 行带 `deviceName`（host 的设备名），复习 ›「复习已配对设备的卡组」标题为设备名而非 `host.docker.internal`。修复前配对的老条目：客户端跑一次同步（`fushi_cli sync`，选路成功触发后台学地址）或重启后等学习器跑过，`peer ls` 补出名字；需要 host 也是本修复之后的版本（`curl -u hibiki:<token> https://<host>:38765/api/host/addresses` 回包含 `deviceName`）。
