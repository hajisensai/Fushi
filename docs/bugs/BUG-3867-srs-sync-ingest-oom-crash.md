## BUG-3867 · srs-sync-ingest-oom-crash
- **报告**：2026-10-28（用户：开了「制卡后 30 秒自动重排」后复习页转圈闪退；另一用户打开牌组即闪退。两份日志 3.0.1-debug.21804 / 21885，小米 Android 16）
- **真实性**：✅ 真 bug。日志里十余次 `Process.activityCrashRecovered` 全部停在 `srs_sync stage=downloading`，`androidExitInfo` = `CRASH_NATIVE SIGABRT`、`Scudo ERROR: internal map failure (error desc=Out of memory)`，RSS 1–4.5 GB。根因：收段（`sync2_ingest_batch` / `ingest_finish` / `ingest`，以及 `apply` 等同一 `Touched`）把**每条落进投影的操作的事件全文**（实体记录 `d`、笔记字段值 `v`、日志行）塞进返回 JSON `events`（`native/fushi_fsrs/src/store/sync2/mod.rs` `project_entity` / `land_edit` / `project_log`、`semantics.rs` `refresh_tags_row`）。一批 8 MiB 压缩段解开是几万条操作、几百 MB JSON：Rust 侧 `Vec<Value>` + 字符串、`Isolate.run` 跨 isolate 拷一份 Map、再在 UI isolate 上逐条 `SrsEvent.fromJson`（`packages/fushi_engine/lib/srs/srs_db_store.dart` `_absorbProjection`）——同步时 UI 卡顿，内存冲顶被 Scudo 杀。而 Dart 侧只用其中的种类 / ID / 字段键 / 卡 ID 标脏缓存。重排一次整组重铺（`srsMinimalMovePositions` relayout）就是 O(N) 条位置修改，正好把对端一批收段撑大。
- **[x] ① 已修复** — 内核只交回落库**标记**：`Touched::landed_entity/landed_edit/landed_log`（`{"t","id","k","e","f"}` / `{"t","id","card"}`），Dart `_absorbProjection` 改读标记（`_SrsLanded`），不再解析事件全文。
- **[x] ② 已加自动化测试** — `native/fushi_fsrs/src/store/sync2/tests.rs` `ingest_returns_compact_landed_markers_not_event_bodies`（64 KiB 字段值的笔记修改经收段后返回 < 4 KiB、无 `x` 全文、标记字段齐全）；Dart 侧 `packages/fushi_engine/test/srs/sync2/` + `srs_db_store_test.dart` 73 条回归通过。
- **备注**：「Lapis 卡仍没按词频排」本单未定根因：日志里没有任何 `AnkiAutoReposition[...]` 失败记录；自动路径在「词典来源下一张都没查到词频」（`anki_auto_reposition.dart` `plan.ranked == 0`）时静默跳过，需要用户的牌组 / 词频设置才能判断。闪退循环本身也会让每轮同步收不完。
