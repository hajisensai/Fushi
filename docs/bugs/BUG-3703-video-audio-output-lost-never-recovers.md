## BUG-3703 · 播放中音频设备失效后视频永久没声音，只能重启 app
- **报告**：2026-10-24（用户：「刚刚视频好卡，而且音频还没了。重启以后恢复了」）
- **真实性**：✅ 真 bug。用户 `Documents/video_diag_log.txt` 现场：15:19:06 `[mpv/ao/wasapi] Error feeding audio: AUDCLNT_E_DEVICE_INVALIDATED` → 重试连撞 5 次 `AUDCLNT_E_DEVICE_IN_USE` → `[fatal] Bad device retry failed` → `[cplayer] Could not open/initialize audio device -> no sound.`，此后整段 `abitrate=-` / `avsync=-`、视频零丢帧照放。mpv 在 ao 初始化失败后 `error_on_track` 取消选中音轨（`aid=no`），**之后再也不会自己选回来**；Fushi 侧 `fushi/lib/src/pages/implementations/video_fushi_page.dart` 的 `_handlePlaybackError` 只落日志，全仓没有任何音频输出恢复（无 `ao-reload`、无设备列表监听）。真 libmpv 实测：设备恢复后不会自愈、`ao-reload` 无效（无 ao 时直接 return）、播放中写 `aid=auto` 也是 no-op，只有写回**具体轨号**的 `aid` 才重建音频链。卡顿另查：日志里只有起播 2 秒 vo-drop 与 15:15:55 一秒 UI jank，音频丢失后 mpv 零丢帧，不属本条。
- **[x] ① 已修复** — 新增 `fushi/lib/src/media/video/video_audio_output_recovery.dart`（`VideoAudioOutputRecovery`：识别丢失 → 按 1/2/4/8/15/30s 退避重选音轨、不设上限，`audio-device-list` 变化时立即重试并重置退避，load 重置、Player 销毁停止）；`video_player_controller.dart` 把 `stream.error` / `stream.audioDevices` 接给它，`reselectAudioAfterOutputLoss` 只在 mpv `aid=no` 时写回丢失前的具体轨（`auto` 落到容器默认轨 / 第一条真实轨），以 `current-ao` 非空判定恢复，每个 await 后按 player identity + loadToken 双判据校验。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_audio_output_recovery_test.dart`：fake_async 状态机（退避节奏、封顶不放弃、不重复排期、设备变化立即重试、reset 作废在途结果）、目标轨判定、控制器接线守卫，以及真 libmpv 端到端（指向不存在的 wasapi 设备复现「音轨被取消选中、视频照放」→ 设备不在时持续退避 → 设备回来后自动恢复 `current-ao` 与 aac 解码；需 `FUSHI_TEST_LIBMPV` + `FUSHI_TEST_FFMPEG`）。
- **备注**：真机未在用户原始路径（真实拔插 / 切换输出设备）复测；真 libmpv 用例走的是同一条 ao 初始化失败 → `error_on_track` 路径。
