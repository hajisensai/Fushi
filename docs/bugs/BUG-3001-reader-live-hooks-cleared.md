## BUG-3001 · 阅读器按钮布局等实时设置在切卷/叠开阅读器后改了不生效，须退出重进
- **报告**：2026-10-05（用户转述协作者 shishamo：「自定义按钮位置改完无法马上生效需要退出后才重新打开才生效」）
- **真实性**：✅ 真 bug（沿代码路径确认，未在真机复现）。「自定义按钮位置」= 阅读器顶栏 / 底栏按钮拖拽编辑器（`settings_schema_reading.dart` 的 `buildReaderControlLayoutEditor`，设置页与书内快捷设置共用）。编辑器每次落位都写穿偏好 `reader_control_layout`，再经 `notifyReaderChromeReanchored`（`settings_actions.dart:136`）调静态 hook `ReaderFushiSource.onChromeReanchorLive` 让阅读器重建；阅读器 chrome 每次 build 都现读偏好（`reader_fushi/chrome.part.dart:1643`），本身没有缓存。根因在 hook 的生命周期：`reader_fushi_page.dart` 旧 dispose（上游 c7932af5419 的 `:3173-3176`）**无条件**把四个实时 hook（`onSettingsChangedLive` / `onLayoutReloadLive` / `onChromeReloadLive` / `onChromeReanchorLive`）置 null。切卷走 `openMedia(pushReplacement: true)`（`reader_fushi/chrome.part.dart:2581`），新阅读器 initState 先注册 hook、旧阅读器等转场结束才 dispose，于是把仍在显示的新阅读器的 hook 一起抹掉；卡片来源（`card_source_router.dart:220`）在阅读器上再叠开一个阅读器、关掉上层时同理。之后改按钮布局（以及反转底栏、顶栏进度、字号等所有经这四个 hook 实时生效的阅读器设置）偏好照写、阅读器收不到通知，退出重开时 initState 重新注册才生效。视频播放器的按钮布局编辑器只在播放器内出现、经 notifier 实时生效，无此问题。
- **[x] ① 已修复** — `ReaderFushiSource` 改为持有者栈：`attachLiveHooks` / `detachLiveHooks`（`reader_fushi_source.dart`，`ReaderLiveHooks` 一组四个回调），hook 恒指向栈顶仍存活的阅读器；阅读器页 initState 登记自己那组、dispose 只按身份注销自己那组（`reader_fushi_page.dart` `_liveHooks`）。切卷后新页 hook 不再被旧页抹掉，叠开阅读器关闭上层后 hook 回落到下层。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_live_hooks_owner_test.dart`（切卷顺序 / 叠开回落 / 单页注销置空 / 重复注销）；源码守卫 `fushi/test/reader/reader_live_settings_guard_test.dart` 改为钉「经 attach/detach 登记、dispose 不得无条件置 null」，`reader_chrome_floating_test.dart` / `reader_hide_toolbars_guard_test.dart` / `tap_gate_mirror_guard_test.dart` 跟随新登记形态。
- **备注**：未在真机复现原始失败路径；需要在 Windows / Mac 上验证：打开合集里的一卷 → 切到下一卷 → 书内快捷设置 → 按钮布局里拖一个按钮到底栏，阅读器应立即出现该按钮。
