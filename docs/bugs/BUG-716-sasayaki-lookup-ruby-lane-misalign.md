## BUG-716 · 有声书/查词注音高亮 narrow-lane 错位
- **报告**：2026-07-10（用户：有声书音频高亮被改坏了；补报：查词的有注音的也有问题）
- **真实性**：✅ 真 bug，根因 `hibiki/lib/src/reader/reader_content_styles.dart` 的 `_highlightLaneCss`（narrow-lane）+ 各 `-ruby-active` / `.hoshi-sasayaki-cue.hoshi-sasayaki-active` 改用 lane 变量的规则。
  - Jul 7 起 `6f9796f7b`(narrow ruby highlight lane) + `7674ae703`(narrow sasayaki text lane) 把有声书/查词/收藏的 ruby 高亮与普通正文 sasayaki cue 从整句 `background-color` 填充改成 `_highlightLaneCss` 的 1em 窄条：`background-image: linear-gradient(var(--hoshi-highlight-lane-color,...))` + `background-size: 1em 100%`(竖)/`100% 1em`(横) + `background-position: left center`(竖)/`left bottom`(横)。
  - 窄条按 `background-position: left` 钉在**元素背景盒的左缘**，而不是基字中心。书籍行距≠字号（行盒宽 > 1em）时字居中→条偏左；`<ruby>` 盒含注音轨、宽度与普通 span 不同→同为 `left` 落点不一致→**有无振假名两种高亮宽度/位置不一**。`TODO-1308` 后续又改了 `ruby-position`（furigana 侧），进一步让 lane 的 `left` 假设失配。
  - 离屏 Blink 探针（`$CLAUDE_JOB_DIR/tmp/sasayaki_*.mjs`，真 Chrome 渲染逐张核对）复现：narrow-lane 下竖排细条往基字左侧偏移、ruby 列与非 ruby 列绿条位置/宽度不一致、注音字戳出绿条；整句填充下两者同宽、字居中、注音在绿块外。
  - 附带：`91296349b`(TODO-1371) 去掉 active 态 `line-height:1` 只在「竖排 + 书籍行距<字号」边界有 ~3px 取舍，普通场景改前后渲染完全一致，**不是**本 bug 主因；回到整句填充后该维度一并消失（填充不依赖 line-height）。
