## BUG-4925 · 查词弹窗拖选区柄时横滑被当成滑动关闭
- **报告**：2026-11-17（应用内反馈 vUJ0k5kEn6，Android 3.3.0-debug.27576，Hisense HNR320T）
- **真实性**：✅ 真 bug。用户在查词弹窗里长按选字后拖选区柄调整范围，横向位移过滑关阈值，抬手弹窗就关了。根因 `fushi/lib/src/pages/implementations/dictionary_popup_layer.dart:2400-2408`（`_BodySwipeDismissDetectorState._onPointerUp`）：应用内弹窗的正文横滑检测器只看 Flutter raw 指针轨迹（`_pointerIsHorizontal` + 累计 dx），完全不知道 WebView 里的选区；而覆盖窗的横滑脚本 `kPopupTouchSideSwipeReleaseJs`（`fushi/lib/src/reader/popup_swipe_close_script.dart`，BUG-2770）早有「这一划改动了选区就不上报」的防线，两边口径不一致。同一缺口也在下拉关闭脚本 `kPopupTopPullReleaseJs` 的 `fire()`（同文件 :29）里：长按选字后往下拖也会被当成下拉关闭。
- **[x] ① 已修复** — 把选区判据交给 Dart：新增 `kPopupSelectionChangeReportJs`，文档选区每变成一段新的非空选区就 `callHandler('popupSelectionChanged')`（只挂 `selectionchange`，Android 拖选区柄由 Chromium 原生处理、页面不一定有 touchmove）；`DictionaryPopupWebView` 收到后在自身 context 冒泡 `PopupSelectionChangedNotification`，`_BodySwipeDismissDetector` 用 `NotificationListener` 接住，若有正在跟踪的指针就把这一划标为作废，抬手不关。划之前留着的旧选区（折叠不上报、两划之间的通知不计）不挡滑关，与覆盖窗口径一致。下拉关闭脚本在 touchstart / pointerdown 记起手选区，`fire()` 时选区变成新的非空选区就不上报。
- **[x] ② 已加自动化测试** — `fushi/test/pages/dictionary_popup_selection_swipe_guard_test.dart`：真 `DictionaryPopupLayer` widget 行为（选区未变照关 / 划中选区变了不关 / 旧选区不挡、作废标记不漏到下一划）+ 两段 JS 经 node 真跑（上报只在新的非空选区；下拉在选区变化时不上报，鼠标同理）+ WebView 注入与通知派发的接线守卫。
- **备注**：未在真机上复测原始失败路径（拖选区柄的触摸是否经 Flutter 指针树、`selectionchange` 先于抬手到达 Dart）；Android 设备复测待补。脚本型词典的沙箱 iframe（不透明源）里的选区看不到，不在本修复范围。
