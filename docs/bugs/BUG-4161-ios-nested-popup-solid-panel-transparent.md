## BUG-4161 · iOS 嵌套查词：透明度不被允许时子层实底压在正文上整块透明
- **报告**：2026-10-31（应用内反馈 hQpYQyWJNQ，iOS 26.3.1 / iPhone14,7，3.1.0-debug.22074，Apple 设计系统深色，reader_fushi：「cupertino 主题嵌套查词，子查词框背景透明，释义看不清」）
- **真实性**：✅ 真 bug。从反馈截图取色：父层面板正好是 `#1C1C1E`，是 Flutter `ColoredBox` 实底，不是 UIVisualEffectView 材质（材质会带上背景的色偏）。所以这台设备走的是「透明度不被允许 → 不透明实底」分支（`fushi/lib/src/utils/components/fushi_material_components.dart` `_ApplePopupGlassBackdrop._buildGlass` 原 `!realBlur` → `ColoredBox(opaque)`）。子层压在正文上的部分没有底色，正文原样透出来，只有和父层重叠的那段是实底。
  根因在 iOS 的平台视图合成规则（Flutter 3.47.6 engine，已对照源码）：父层查词 WebView 被 `fushi/lib/src/pages/implementations/dictionary_popup_layer.dart:1675` 的 `clipBehavior: Clip.antiAlias` 圆角裁剪（外加 `FushiPopupSurface._borderInsetChild` 的 `ClipRRect`），平台视图带上 kClipRRect mutator，`engine/src/flutter/shell/platform/darwin/ios/framework/Source/FlutterPlatformViewsController.mm:94` `HasNonRectClipForUnderlayCutout` 为真，这个视图进了 `viewsWithUnderlayPreserved`。结果是紧跟在父层 WebView 之后绘制的那段 Flutter 内容：① overlay 层在 `:895` `ApplyNonRectClipToOverlayCanvas` 被裁成父层的圆角形状；② `engine/src/flutter/flow/view_slicer.cc:121-130` 的 `preserve_underlay` 分支不在底层画布上挖掉这块，内容整段画进**所有平台视图之下**的底层画布，形状外的部分被阅读器 WKWebView 整块盖住。注意 `view_slicer.cc:43` 的 `for (int j = i; j >= 0; j--)` 会拿每段内容和它之前的**所有**平台视图（含阅读器 WebView）求交并进 overlay，所以判据不是「和哪个视图相不相交」，而是「紧挨着的前一个平台视图带非矩形裁剪」。嵌套层的 Flutter 实底正好画在这一段里，所以只在和父层圆角形状重叠的地方看得见。同一段里的其它内容同样受影响：嵌套层原生背衬之前画的外侧投影（`_PopupOuterShadowPainter`，原先排在 `FushiNativeMaterialBackdrop` 之前）压在正文上的部分也不显示。嵌套层自己的描边和顶栏画在本层原生背衬**之后**（背衬是 `_ApplePopupGlassBackdrop` Stack 的第一个子项，描边 / 顶栏在后面的 `Material` 里），而原生背衬没有非矩形裁剪（`parkedPopupLayer` 链上只有 Positioned / Visibility / FadeTransition；`PopupOccluderClip` 的 `ClipPath` 只在 Windows / Linux 挂），所以不受影响。右下角尺寸把手画在本层 WebView 之后，但按几何算整笔落在本层 WebView 的内圈圆角里（离圆心最远 ≈12.8px < 内圈半径 13px），也不受影响。在 iOS 26.5 模拟器（Flutter 3.47.6）上用最小复现实测：一个阅读器 WKWebView 加父层、子层，子层用同一组 Positioned / Visibility / FadeTransition / Material clip / ClipRect 结构。背衬用 Flutter `ColoredBox` 实底时，子层压在正文上的部分整块透明，和反馈截图一致；换成原生 UIVisualEffectView 材质或原生实色视图都显示正常。入场淡入的 Opacity 和祖先 mask 都不是原因：dump 原生视图父链，alpha 全是 1，没有 mask。
- **[x] ① 已修复** — `a7e387901a`：iOS / macOS 上查词面板的背衬一律用原生平台视图。能真模糊就用系统材质；透明度不被允许时用原生实色面板（`fushi/apple/FushiNativeMaterialView.swift` 新增 `solid` 参数；`fushi/lib/src/utils/components/glass/fushi_native_material.dart` 新增 `fushiNativePopupBackdropHostAvailable` 和 `FushiNativeMaterialBackdrop.solidColor`）。判据只在 `_ApplePopupGlassBackdrop._buildGlass` 写了一处。`984de24669`：嵌套层在父层 WebView 之后、自己的原生背衬之前不再画任何 Flutter 内容——`_ApplePopupGlassBackdrop._buildNativeMaterial` 把 `FushiNativeMaterialBackdrop` 排到 Stack 第一个，外侧投影 `_PopupOuterShadowPainter` 挪到其后，挖掉的内侧与原生背衬同形（Apple 连续圆角用 superellipse，MD3 用圆角矩形），不压暗面板；同时更正 Swift 文件头、`fushiNativePopupBackdropHostAvailable` doc 里写错的合成规则。
- **[x] ② 已加自动化测试** — `fushi/test/widgets/glass/fushi_popup_surface_nested_fill_test.dart`「iOS / macOS 原生系统材质」组：iOS / macOS × 三种情况（Apple 材质档 off、MD3 系统降低透明度、Apple 高对比度），断言背衬是带不透明 `solidColor` 的原生视图，且 surface 里没有 Flutter 画的不透明面板（改前 6 例红，改后绿）。另加一条，断言材质可用时不带 `solidColor`。`984de24669` 加两组：iOS / macOS × 三种背衬（Apple 系统材质、Apple 原生实底、MD3 系统材质），按渲染树绘制顺序断言 surface 里原生背衬之前没有任何会出像素的 Flutter 绘制（投影排回背衬之前时 6 例红，改后绿）；Apple / MD3 各一条像素断言：投影不进面板内侧、面板外侧有投影。
- **备注**：没有 iOS 真机，没在真机上按 paginated / continuous / vn 三种 view mode 复测原 app，证据只有模拟器上的最小复现（改前透明，改后实底）。墨水屏（`isGlassDesignTheme` 在墨水屏下恒为 false，选 Apple 设计系统也走 MD3 分支）原先不挂原生背衬，底色由 Flutter `Material` 画，同样落在父层 WebView 之后那一段；`75f93c13a5` 补上：iOS / macOS 上原生背衬宿主可用时，墨水屏也把 `Material` 改透明、由背衬槽画原生实色面板（颜色 = 原墨水屏卡面色，不带主色淡染），并且墨水屏不画外侧投影。测试加「墨水屏：实底是原生视图」与「MD3 墨水屏原生实底 / 墨水屏选 Apple 设计系统：原生背衬是 surface 里第一个绘制的东西」（iOS / macOS 各一，改前 6 例红，改后绿）。合成规则本身来自父层 WebView 的圆角裁剪；改成矩形裁剪能整个消掉这条规则，但会让 WebView 内容在圆角弧外露出，且无 iOS 真机可验，这次不动。
