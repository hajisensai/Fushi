## BUG-3874 · android-debug-apk-extra-abis
- **报告**：2026-10-29（用户：官网 / App 内更新的安卓调试版 459 MB，为什么不只出 arm64）
- **真实性**：✅ 真 bug。调试通道已是 `flutter build apk --release --target-platform android-arm64`（`.github/workflows/release.yml` 「Build release-signed debug-channel APK」），但该参数只让 `libflutter.so` / `libapp.so` 按 ABI 出；而 Flutter 插件不分包时会把 `abiFilters` 清空后固定写回三个 ABI、无视 target-platform（`FlutterPlugin.kt` 的 `configureAbiWithoutSplits`），插件与本仓 jniLibs（onnxruntime、ffmpeg、libmpv、WebRTC、fushi_p2p / fsrs / compute / web_core 等）照样三 ABI 进包。实测 `fushi-3.0.1-debug.21966-476c6b3-debug.apk`（481 MB）：`lib/arm64-v8a` 239 MB、`lib/x86_64` 140 MB、`lib/armeabi-v7a` 88 MB，后两者没有 `libflutter.so`，纯死重。正式 / 测试版走 `--split-per-abi`，各 ABI 包正常（v3.0.0 三包约 200 MB），不受影响。
- **[x] ① 已修复** — `fushi/android/gradle.properties` 用 Flutter 官方开关 `disable-abi-filtering=true` 关掉插件那份，`fushi/android/app/build.gradle` 的 `ndk {}` 在不分包时按 `target-platform` 收 `abiFilters`（没传时同 Flutter 默认三个）；`--split-per-abi` 时让给 `splits.abi`（AGP 不许两者并存）。本机 `flutter build apk --debug --target-platform android-arm64` 实测：改前 511 MB / 三个 ABI，改后 332 MB / 仅 `arm64-v8a`。
- **[x] ② 已加自动化测试** — `release.yml` 新增出包后门「Verify debug-channel APK is arm64-only」（解包核对 `lib/` 下只有 `arm64-v8a`，否则 CI 红）；`fushi/test/build/release_workflow_diagnostics_guard_test.dart` 钉住 gradle 过滤与该门的存在 / 顺序。
- **备注**：CI 里各 Rust 内核仍对调试通道编三 ABI（缓存命中各约 1 分钟，不影响包体积），未在本次收窄。官网「通用包，含全部架构」文案在官网仓库，需另改。预计调试包降到约 250 MB，其中 `libapp.so` 约 90 MB。
