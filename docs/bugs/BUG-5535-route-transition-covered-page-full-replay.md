## BUG-5535 · 打开 / 返回二级页（视频合集等）转场掉帧：被盖住的那一页每帧整页重放绘制
- **报告**：2026-11-27（用户：打开视频系列这种二级页面会掉帧）
- **真实性**：✅ 真 bug。用安装版真实库的只读拷贝（`design_system=glass`，4K、dpr 2、165 Hz、RTX 4070 Ti）跑 profile `video_collection_perf_itest`，从视频库页推入 29 集的合集：转场 600 ms 内每帧 raster 均值 9.6–11.1 ms（返回 10.0–12.7 ms），超 6 ms（165 Hz 每帧预算）的帧 44–54 / 600 ms。拆开：视频库页静止一帧 raster 5.5–6.4 ms、合集页约 2 ms，转场时两页都在场。被盖住的页在 UI 侧并不重画（路由 RepaintBoundary 的层复用），但桌面 Impeller 没有 raster cache，每帧都把它整页的绘制命令重放一遍。逐项对照：关掉玻璃材质、关掉页面背景各只降 1–2 ms；`RenderBakedSurface` 帧末检查每帧只有约 0.3 ms（视频库页只有 22 个烘焙面），不是原因。根因位置：路由转场层 `fushi/lib/src/utils/adaptive/fushi_page_backdrop.dart` `FushiBackdropPageTransitionsBuilder.buildTransitions`（所有设计系统的推页都经过它）对被盖住的页没有任何缓存。
- **[x] ① 已修复** — `FushiBackdropPageTransitionsBuilder` 给每页包一层 `FushiCoveredPageSnapshot`（同文件）：本页的 `secondaryAnimation` 在动（新页推入 / 弹出 / 侧滑返回跟手）时用 Flutter `SnapshotWidget` 把整页（含页面背景）画成一张快照，之后每帧贴图、随转场位移 / 压暗，转场落定立刻回实时绘制——与 Flutter Zoom 转场的 `allowSnapshotting` 同一机制，特效一个不少。转场开始后隔两帧才开拍：`Hero` 在第一帧画完后才起飞、起点第二帧才换成占位，`isCurrent` / `didPushNext` 的重建也在第一帧，拍早了快照里会留下重影。延迟计时只在转场状态变化时重来（转场途中页面每帧重建，曾把计时一直作废、快照从没开起来）。`SnapshotMode.permissive`：含平台视图的页照常实时画；路由 `allowSnapshotting` 为 false 时不拍。同一次运行交替对照（各 3 次）：推入 raster 均值 9.6–11.1 → 4.5–4.9 ms、超 6 ms 帧 44–54 → 13–23；返回 10.0–12.7 → 3.4–4.5 ms、38–43 → 5–7。
- **[x] ② 已加自动化测试** — `fushi/test/widgets/covered_page_snapshot_test.dart`（Apple 设计系统主题）：推入第 1 帧不拍、第 2 帧后开拍，开拍后被盖住的页至多为快照完整画一次，落定回实时绘制；返回途中重新露出的页同样画快照；开拍那一帧起点 `Hero` 已是占位（快照里没有重影）。真机测速探针 `fushi/integration_test/video_collection_perf_itest.dart` 改为从视频库页推入、glass 设计系统下也能等到首页，并按 600 ms 转场窗口汇总 raster / build 与慢帧清单。
- **备注**：转场途中被盖住的页内若有东西在动（加载圈、视频画面），快照里它停在拍下那一帧，落定后恢复（与 Flutter Zoom 转场同取舍）。推入首帧 build 仍有 10–30 ms 的尖峰（合集页首次构建 + 数据加载），这次没动。静止时整页仍以 140 帧/秒左右持续出帧，另记 BUG-5536。
