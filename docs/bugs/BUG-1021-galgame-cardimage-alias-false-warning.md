## BUG-1021 · galgame 场景制卡误报缺少 {card-image}（旧别名瞎眼）
- **报告**：2026-07-23（用户：截图 toast「Anki 字段映射缺少游戏卡片字段: {card-image}」）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/mining/gal_hook_mining_coordinator.dart:267`（`_unmappedTokens`）。该处对 card-image 用裸 token 校验 `AnkiHandlebarOptions.anyFieldConsumesToken(mappings, '{card-image}')`。提交 `63b0685f9`（TODO-1298，2026-07-07）把默认映射 `Picture` 从旧名 `{book-cover}` 改成 `{card-image}`，`{book-cover}`/`{video-clip}` 保留为向后兼容别名（三者都渲染同一 `context.coverPath`，见 `packages/hibiki_anki/lib/src/anki_models.dart:463-470`）。改名前建过 Lapis 卡组的用户，持久化 `fieldMappings` 里 `Picture` 仍是 `{book-cover}`；`LapisPreset.applyDefaults = {...defaults, ...current}` 让 current 覆盖，保持旧别名。裸 token 校验只认字面 `{card-image}` → 认不出 `{book-cover}` → 误报缺失，尽管画面/GIF 其实已通过别名正常落卡。对比 `{sentence-audio}` 走 `anyFieldConsumesSentenceAudio` 能同时认 `{sasayaki-audio}` 别名——唯独 card-image 校验漏做别名。`{sentence}` / `{audio}` 未改过名，不受影响。
- **[x] ① 已修复** — 新增别名感知 helper `AnkiHandlebarOptions.anyFieldConsumesCardImage`（认 `{card-image}` / `{book-cover}` / `{video-clip}` 三别名，镜像 `anyFieldConsumesSentenceAudio` 写法，`packages/hibiki_anki/lib/src/anki_models.dart`）；`_unmappedTokens` 的 card-image 检查改用该 helper（`hibiki/lib/src/mining/gal_hook_mining_coordinator.dart`）。消除特例，向后兼容旧配置且不再误报。提交见 PR。
- **[x] ② 已加自动化测试** — `hibiki/test/anki/anki_field_consumes_token_test.dart` 新增 `anyFieldConsumesCardImage` 三别名守卫组；`hibiki/test/mining/gal_hook_mining_coordinator_test.dart` 新增回归「legacy {book-cover}/{sasayaki-audio} aliases are not reported missing」——旧别名映射的卡组 `unmappedTokens` 为空。
- **备注**：默认值 `LapisNoteType.defaultFieldMappings` 本就含 `{card-image}`/`{sentence-audio}`/`{audio}`，全新卡组已补全，无需再加；真正没适配的是校验对旧别名瞎眼。用户报「加到默认值」的直觉源于误报 toast，实为校验缺陷。
