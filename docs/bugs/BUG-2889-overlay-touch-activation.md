## BUG-2889 · 悬浮划词条与工具条被触摸点按抢走游戏前台
- **报告**：2026-10-03（agent 在 Fate/stay night[Realta Nua] 触摸验收第④条时发现：手指点在盖着游戏上沿的「Fushi Hook Text」划词条上，前台从游戏变成 `FushiFloatingLyricWindow`）
- **真实性**：✅ 真 bug，BUG-2788 的同类遗漏。`WS_EX_NOACTIVATE` 只挡**鼠标**点击激活；触摸 / 触控笔按下另发 `WM_POINTERACTIVATE`，落 `DefWindowProc` 回 `PA_ACTIVATE`，窗口照样变前台。BUG-2788 只给查词卡、BUG-2793 只给悬浮球补了这条，以下窗口的窗口过程都没有：`fushi/windows/runner/floating_lyric_window.cpp`（`FloatingLyricWindow::HandleMessage`，一条都没处理）、`hook_toolbar_window.cpp`（`HookToolbarWindow::HandleMessage`，一条都没处理）、`attached_text_surface_window.cpp` 与 `hdr_video_host_window.cpp`（只回 `MA_NOACTIVATE`）。游戏一失去前台，宿主「前台必须是游戏」的点卡外吞点击就失效，下一下触摸会推进剧情。
- **[x] ① 已修复** — 四个窗口过程统一 `case WM_POINTERACTIVATE: case WM_MOUSEACTIVATE: return OverlayNoActivateReply(message);`（`window_activation_policy.h` 的共用策略），runner 里不再有裸 `return MA_NOACTIVATE;`。
- **[x] ② 已加自动化测试** — `fushi/test/build/noactivate_overlay_pointer_activation_guard_test.dart`：不按文件点名，扫 runner 里**每个** `CreateWindowEx` 调用（扩展样式是同文件无参 helper 时换成函数体再判），凡扩展样式含 `WS_EX_NOACTIVATE` 且非 `WS_EX_TRANSPARENT`、非系统 tooltip 的窗口，所在文件必须 include 共用策略并把两条激活请求一起交给它；另钉扫描面非空（划词条 / 工具条 / 查词卡 / 悬浮球 / 贴附文字面都在）与「无裸 MA_NOACTIVATE」。变异实测：删掉划词条那两行 case，测试变红并点名 `floating_lyric_window.cpp`。
- **备注**：真机复测（同一 Fate 样本，修复后的 Debug 宿主，`InjectTouchInput` 真实触摸）：触摸点划词条 (1150,300) 后前台仍是 `TTVPWindowForm`（修复前变成 `FushiFloatingLyricWindow`），台词不推进。同一会话其余触摸步骤：点字弹卡、卡内竖滑、卡内点按、卡外点按（`global click … consumed=1` 关卡）、卡上横滑（关卡）、卡外滑动、长按（无卡时按系统右键弹出游戏菜单，与鼠标右键一致），每步台词都不推进、前台都是游戏。
