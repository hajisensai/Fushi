## BUG-2936 · AI下视频「全部哆啦A梦大电影」MAL系列遍历静默截断丢新剧场版·失败时静默降级成下单部TV·短片混进剧场版
- **报告**：2026-10-04（用户：「还有比如我希望下载全部的哆啦a梦大电影，你试着交互一下」——沿「AI 下视频」整套下载链路走一遍真实交互）
- **真实性**：✅ 真 bug，三处：
  1. **MAL 关联遍历静默截断**：`packages/fushi_engine/lib/media/video/discovery/video_franchise.dart` 的 `resolveMalFranchise`（修前 :200 `while (queue.isNotEmpty && visited.length < maxWorks)`，`kVideoFranchiseMaxMalWorks = 60`）预算按「取过的节点」算，特别篇 / OVA / 同映短片不进清单也占预算；到上限时队列非空却不标记、不记日志。MAL 实测（myanimelist.net/anime/2471）：1979 版 Side story 一层就 ~50 部（37 部剧场版夹特别篇与短片），广度优先走完这层才轮到 2005 版（8687）挂的 22 部剧场版——60 在这里耗尽，丢的恰好是 2018 年以后最新的剧场版，用户拿到的「全部剧场版」静默缺一大截。
  2. **取不到清单时静默降级**：`video_acquisition_reducer.dart` 的 `_onFranchiseLoaded`（修前 :2019-2033）只要成员为空或只剩锚点，就说「没找到同系列，按这一部继续」并把 scope 改成 `work`。用户要「全部剧场版」而锚点是 TV（1979 版 1700+ 集），或资料源出错 / 不可用（`loadFranchise` 的 `_guardFranchise` 把异常吞成 null，与「没有数据」不可区分；MAL 第一个请求就失败时返回空清单而非 null），都会替用户下错东西，且提示「没有同系列作品」本身是假话。
  3. **同映短片混进剧场版**：`_malFranchiseKind`（修前 :180）只看 MAL `type`，而 MAL 把哆啦A梦剧场版同映的 15–30 分钟短片、The☆Doraemons 短片、天象馆片也标 `Movie`，默认勾选进「全部剧场版」。
- **[x] ① 已修复** — `VideoFranchise.incomplete`：预算耗尽 / 中途请求失败 / 某来源整个失败时置真（`resolveMalFranchise`、`loadFranchise` 的 `_FranchiseAttempt`、联网补全的资料源缺席占位），`mergeVideoFranchises` 取并；预算 60 → 150（按请求数计，Jikan 闸门下 ≈ 2.75 分钟上限）。reducer `_franchiseHasNothingMore`：只有清单完整且锚点本身属于用户要的范围才自动按单部继续，否则说 `franchiseUnavailable`（取不到时）并问新槽位 `franchiseFallback`（只下这一部 / 取消）；有作品但不全时在 `franchiseFound` 后补一句 `franchiseIncomplete`。MAL `Movie` 片长 < 40 分钟（AMPAS / BFI 长片定义，`kVideoFranchiseMinFeatureMinutes`）的不算剧场版，片长未知照收。3 条 i18n。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/discovery/video_franchise_test.dart`（哆啦A梦形态图 109 节点收全 59 部剧场版且不含短片、短片判据、上限 / 中途失败 / 首请求失败标不全、合并取并）；`fushi/test/media/video/acquisition/video_acquisition_franchise_test.dart`（null / 要剧场版却只有 TV / 不全只剩锚点 → 问 `franchiseFallback` 不静默改单部；继续 / 取消；不全但有作品 → 出清单并说明；完整时不说）。原测试「没有系列来源（null）同样退回单部」钉的正是本 bug，已改为新行为。
- **备注**：未改——交互式选作品时 AI 身份判定不知道 scope（整套模式下哆啦A梦多个候选会问用户选哪一部，选哪部作锚点都能串起系列，只是多一问）；150 部预算下柯南这类更大的图仍可能走不完，此时会如实提示「可能不全」。
