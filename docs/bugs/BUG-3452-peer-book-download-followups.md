## BUG-3452 · 对端书下载后多出未下载卡、合集册数翻倍、跳回顶部、最近阅读排序错位
- **报告**：2026-10-16（用户：反馈 FvgH1f3vZ_ 追加，Android 手机从互联对端下载书；BUG-3328 修完并发崩溃 / 合集内进度 / 多选合集下载之后仍存在的四个问题）
- **真实性**：✅ 真 bug（①②④ 沿代码路径确认并有测试钉住；③ 的「滚回顶部」本身未在测试里复现，见备注）。根因（行号均为基线 `fe266bc780`）：
  1. **占位卡的去重 / 折叠只在整个下载任务结束后才重算**：`reader_history/remote.part.dart:802`（`_downloadRemoteBook` 尾部 `_refreshSrtBooks()` → `_refreshRemoteBooks()`），而本地卡在 `remote.part.dart:897` 入库那一刻就经书集合流（`_epubBookKeysProvider`）冒出来。中间这段（拉对端进度、下有声书包，后者可以很久）旧占位卡还在：合集归属已由 `adoptBook` 提升成本地 uid、折叠映射经合集表监听重载后，占位卡掉出合集，以散卡挂在合集外，任务一结束角标变回下载按钮 =「未下载」卡；在此之前合集里本地卡与占位卡并存。
  2. **清单收养拿过期身份快照把占位成员插回合集**：`packages/fushi_engine/lib/sync/remote_collection_adoption_service.dart:80`（`_findLocalBook` 只查 `adoptBooks` 开头装载的 `CollectionBookIdentityIndex`）。一轮目录刷新逐本收养期间（批量下载时上一本的收尾刷新与下一本的落地正好重叠），刚落地、已提升成本地 uid 的书在快照里查不到，被当成「本机没有」，`adoptRemoteCollectionMember` 把对端键的占位成员行重新插回：合集里同一本书两行（本地成员 + 对端键占位成员），占位卡只要还在清单结果里就折进合集一起计数；下一轮刷新（切 tab、TTL、重启）按新身份收养时才删掉那行，与「过很久或重启恢复」的现象一致。
  3. **去重只按书名派生键比**：`packages/fushi_engine/lib/sync/fushi_library_host_service.dart:1359`。上游 #2207 起下载时把对端键（`downloadId` = host bookKey）记进别名并并入本地键集合，但这里只拿 `sanitizeTtuFilename(title)` 去比；host bookKey 与书名不同源时（对端同名书带后缀、无 dc:title 的 EPUB…）下载完的占位卡永远去不掉。
  4. **最近阅读排序**：`reader_fushi_history_page.dart:1291` 本地书没有阅读记录时回落到 `importedAt`；下载入库的 `importedAt` 是下载那一刻（`remote.part.dart:897` 新建行），而对端读过的书虽然 `remote.part.dart:1075` 写回了对端的阅读时刻，但 `bookLastReadAtProvider` 平时只在关书时失效，书架拿到的映射里没有这本书 → 同样回落到下载时刻。两种情况都让刚下载的书顶到「最近阅读」最前，与下载前占位卡（按 host 的阅读时刻 / 入库时刻排）的位置不一致。
- **[x] ① 已修复** — （提交见 PR）

  - `remote_collection_adoption_service.dart` `_findLocalBook`：预载快照落空时在本事务里按对端键再精确查一次（本机键 = 对端键，或别名），不再把已提升的占位成员插回。
  - `fushi_library_host_service.dart` `dedupeRemoteBooks`：host 显式下发的 bookKey 命中本地键集合（含别名）同样算已在本机（没带 bookKey 时不拿原始书名当键，保持 BUG-2274 的值域区分）。

- **[x] ② 已加自动化测试** — `fushi/test/pages/reader_remote_download_followups_test.dart`：去重按对端键（纯函数）；过期快照收养不插回占位行（真 DB）；合集成员落地后、任务收尾前占位卡不再出现且册数不变（真书列表 provider + 拉进度挂起的假对端）；散本下载后滚动位置不动、书留在占位卡原格；「最近阅读」下按对端阅读时刻 / 未读按对端入库时刻排。
- **备注**：
  - ③「跳回顶部」：BUG-3328 已修掉书列表重算换转圈导致的滚动归零。本轮测试里（「最近阅读」排序、书架已滚下去、点一张散本占位卡下载）基线上滚动偏移**没有**被重置，但下载完那本书从用户眼前消失、被排到书架最顶上（入库时刻 = 下载时刻）——合集外弹出「已下载对端书籍」正是这一刻，与反馈描述吻合；修复后它留在占位卡原来的格子（测试 ③ 钉住偏移不变 + 位置不变）。若反馈人更新后仍看到滚动位置本身回到顶部，需要录屏或说明当时的排序方式再查。
  - 产品取向（派发方给定）：下载下来的书沿用对端阅读时间；对端没读过的按未读处理（沿用对端入库时刻，不按下载时刻排最前）。副作用：「导入时间」排序下这本书同样按对端入库时刻排（与下载前占位卡一致）。
  - 审查补记（**已修**，见下一条）：`epub_books.importedAt` 同时是删除墓碑仲裁的「本机存在起始时刻」（`fushi/lib/src/sync/sync_orchestrator/tombstones.part.dart:23` → `tombstoneAppliesTo`，BUG-2044 语义：删后重加的条目不再弹删除确认）。改写成对端入库时刻后，若某条 book 墓碑的 `deletedAt` 落在「对端入库 < deletedAt < 本机下载」之间且高于该通道的消费基线（例：第三台设备经云通道「从所有设备删除」、互联 host 没删），本机刚下载的书会弹一次「其他设备已删除，本地也删？」——修复前因入库时刻 = 下载时刻被压下。只多一次需用户确认的提示，不会静默删除；根治要把「排序用的入库时刻」与「本机存在起始时刻」拆成两个事实（新列，schema bump），另行处理。同类副作用：宽屏 dashboard「最近添加」按 `importedAt` 取书，刚下载的旧书不会进那一行。
