## BUG-2466 · 连续模式听书长距离平滑跟随滚动把途中视口计入阅读账本
- **报告**：2026-09-12（用户 2026-09-12：「书重新打开…一旦播放就会跨了很多页导致阅读速度和阅读量异常」；重开书起点上游已按 BUG-2390「音频位置为主」处理，本条是沿账本路径追出的跟随滚动根因）
- **真实性**：✅ 真 bug。`fushi/lib/src/reader/reader_pagination_scripts.dart` `scrollToTarget`（cue reveal → `revealElement` → 本函数）在连续模式对任意距离都用 `scrollBy({behavior:'smooth'})`；Dart 侧 reveal 前只武装 B-3 settle 窗（`kReaderReanchorSettleMs` = 250ms，`audiobook.part.dart` `_onCueChanged`），窗关了之后 smooth 补间还在多帧滚动，每一次 scroll 回传都走 `_handleReaderScroll` → `_refreshProgressFromScroll` → `_refreshProgress` → `_readLedger.arrive(途中视口)`（`navigation.part.dart`），同一处的 `_studyClock?.touch()` 还把空闲门喂开。账本语义是「翻走的单元并集 ∩ [0, 当前位置)」：途中每个视口都成了「翻过的单元」，随后位置越过它们即 `addChars` 入账——从没读过的几十页整段计成已读，字数虚增、字/时爆表。分页模式的 reveal 走 `scrollToRange`（瞬时翻页）不受影响；一个视口之内的逐句跟读也只可能多采到相邻一页。
- **[x] ① 已修复** — 提交见合并记录。`scrollToTarget` 加 `followBehavior(位移, 视口)`：位移绝对值超过一个视口（不是「跟」是「跳」：重开书音频在几十页外 / 跨章落地 / 手动 seek）用 `'auto'` 瞬时落地——单次 scroll 落在 250ms settle 窗内被吞、窗关后 `_scheduleReanchorSettleProgressRefresh` 只 arrive 落点一个单元；一个视口之内仍回落到共享 `behavior` 变量（默认 smooth，墨水屏 auto），TODO-825 用户点名要的跟读动画一根毛不动（TODO-803 无条件砍成 instant 的修法仍是被驳回的）。竖排 rl / lr 两条 scrollBy 收成一条位移算式，横排一条，都经 `followBehavior`。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_follow_scroll_jump_behavior_test.js`（node vm 从 `reader_pagination_scripts.dart` 原样切出 `scrollToTarget` 执行：横排下一屏 smooth / 几十页外 auto / 往回几十页 auto / 安全区内不滚 / 墨水屏短距离 auto / 竖排 rl、lr 各一远一近）+ `fushi/test/reader/reader_follow_scroll_jump_test.dart`（驱动 node + 源码形状）；既有守卫 `audiobook_follow_scroll_settle_guard_test.dart` 改钉新不变式：scrollBy 必须经 `followBehavior(`，阈值必须是「超过一个视口」且短距离回落到 `behavior` 变量，仍禁写死 `behavior:'auto'|'instant'`。
- **备注**：一个视口之内的 smooth 仍可能把相邻一页采进并集（上界一页，与真翻页无异），有意保留动画不治；settle 窗长度不动。
