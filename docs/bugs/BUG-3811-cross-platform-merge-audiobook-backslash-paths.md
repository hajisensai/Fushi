## BUG-3811 · Windows 备份合并到 Android 后，EPUB 配对有声书不跟字幕、进度归零
- **报告**：2026-10-27（用户：应用内反馈 XDtB1kYT0C，Windows 3.0.1-debug.20797 导出 → Android 3.0.0-debug.20677 合并导入）
- **真实性**：✅ 真 bug（读代码沿真实路径确认，手机端数据库未取到）。三段链路：
  1. **根因**：`fushi/lib/src/sync/backup_service.dart:165-180`（修前）`rebasePath` 把源路径的子路径原样切下来（`:179` `oldPath.substring(nrOld.length)`），保留了 Windows 的 `\`。合并导入第 6 步（`backup_service/restore.part.dart` `_rebaseAllPaths` → `path_rebase.part.dart:139-178`）把 `audiobooks` 行与配对的 `srtbook_epub_<bookKey>` 行都换成 `/data/.../audiobooks\d4515d05\x.m4b`——POSIX 上 `\` 是普通文件名字符，这是一个不存在的文件名；而随包文件按归档相对路径落在 `<audiobooks>/d4515d05/x.m4b`。两行全部断链。
  2. **两表分叉**：`packages/fushi_audio/lib/src/audiobook/srt_book_repository.dart:42,66-117`（修前）书架 `listAll()` 的读取侧自愈 `repairMovedPaths` 只遍历 `srt_books`（`AudiobookPathRelocator.segmentsOf` 本就分隔符无关，能把它修好），同一份路径的 `audiobooks` 行没人修。
  3. **症状落点**：`fushi/lib/src/media/audiobook/audiobook_session_launcher.dart:47-60` `audiobooks` 行解析不到音频 → `:62-95` 退到配对 srt 行，按 `srtBook.uid` 身份起播（`:80`/`:93`/`:155`）。音频能放；但这本书的 cue（`audio_cues.book_key = bookKey`）与进度（`audiobook_pos_<bookKey>`）都挂在 bookKey 上，uid 下为空 → 不高亮、进度归零。
  - 反馈人的「原因 1（launcher 用错 key）」不是根因：配对 srt 行自己持有音频与 uid 下 cue 是合法状态（audioOnly 重新定位后 `_healDirtyAudiobookRow` 删掉 audiobooks 行，见 `audiobook_session_launcher_heal_test.dart`），改 launcher 的回退 key 会打坏那条路径；问题在于两张表本该同步的路径被修成了一张好一张坏。「原因 2（合并不替换本机已有行）」是合并引擎刻意的 push-only UNION 语义，本机已有且有效的行保持不动是对的；本机旧行坏掉的情形由下面的两表同修覆盖。
- **[x] ① 已修复** — `rebasePath`：目标根是 POSIX 形态（不含 `\`）时子路径一律换成 `/`；Windows 目标保持原字节（两种分隔符 Windows 都认，`DataRootMigrator` 等同机调用方零变化）。判据取自目标根而非 `Platform`，保持纯函数。`SrtBookRepository.repairMovedPaths` 改为同一个 relocator 一起修 `audiobooks` 行（`audio_root` / `audio_paths_json` / `alignment_path`），健康库照旧在解析数据根前短路——救已经导入坏了的用户库（重新合并导入修不了：本机坏行不在源根下，rebase 不碰它）。提交见本分支 `fix(backup): ...`。
- **[x] ② 已加自动化测试** — `fushi/test/media/audiobook/audiobook_cross_platform_merge_heal_test.dart`（临时 DB：两表同指 Windows 源路径、cue/进度挂 bookKey → 书架 `listAll()` 后 `AudiobookSessionLauncher.resolve` 必须落在 audiobooks 行、拿到 3 条 cue 与 1500ms 进度；健康行不改写不扫目录）；`fushi/test/sync/backup_rebase_path_test.dart` 新增 Windows→POSIX、混合分隔符、Windows 目标保持原字节三例。
- **备注**：未在 Android 真机复测原始失败路径（Windows 导出 → Android 合并导入 → 开书听）；测试在 Windows 主机上跑，POSIX 目标分隔符由纯函数用例覆盖。
