## BUG-4127 · macOS 小说阅读器选中正文后 ⌘C 无法复制
- **报告**：2026-11-06（用户：QQ 群「/星尘///」经 fushi-bot 应用内反馈 `p7TdfQeivq`，macOS，3.0.1-debug.21966）
- **真实性**：✅ 真 bug（沿代码路径确认，本机无 Mac 未真机复现）。根因 `fushi/lib/src/shortcuts/reader_space_override.dart:174`（旧 `readerShouldHandleDesktopCopy` 第一行 `if (!isWindows) return false;`）：桌面复制兼容层只在 Windows 生效，依据是 BUG-402 写下的「macOS 的 WebView 自带原生 copy」——这个前提从没在 Mac 上验证过，而且是错的。BUG-2948 真机取证「点击阅读器正文后 first responder 仍是 `FlutterView`（不是 WKWebView）」；机制见 BUG-2508（desktop_drop 的 DropTarget 压在窗口最上层，点击由引擎转发给平台视图）与 BUG-3131（`flutter_inappwebview_macos` 不调 `makeFirstResponder`）。所以这一情形下 Flutter 对 ⌘C 返回 ignored 后，Runner 菜单 Edit > Copy（`MainMenu.xib` 的 `copy:`）发给 first responder = FlutterView，它不在文本输入态、不实现 `copy:`，WebKit 收不到 copy：能选中、⌘C 没反应。first responder 并非始终是 FlutterView：DOM 节点获焦时 WebKit 会把 WKWebView 交成 first responder（BUG-2447、BUG-3828，`reader_fushi/caret.part.dart:63` 注释同一事实），那时原生 copy 本身可用、⌘C 不进 Flutter，接管谓词不会被调到，不会重复处理，所以修复对两种情形都成立。两个调用点都把 macOS 排除在外：阅读器正文 `fushi/lib/src/pages/implementations/reader_fushi/caret.part.dart:178`（谓词只传 `isWindows`）、查词弹窗 `fushi/lib/src/pages/implementations/dictionary_popup_webview.dart:4101`（修复前：谓词同样只传 `isWindows`，且复制拦截 `Focus(onKeyEvent: _handleDesktopCopyKey)` 整个包在 `if (isWindowsPlatform)` 分支里，macOS 弹窗根本没有这层）。
- **[x] ① 已修复** — 谓词改名 `desktopShouldHandleCopyGesture({key, modifiers, isWindows, isMacOS})`，按平台取主修饰键：Windows 只认 {Ctrl}+C，macOS 只认 {Meta}+C，混入 Shift/Alt/另一修饰键、Linux、移动端一律 false。阅读器正文与查词弹窗继续共用这一个谓词，复用两边已有的 `_copyNativeSelectionToClipboard`（取 `window.getSelection()` 写 `Clipboard.setData`），不另写 macOS 逻辑。弹窗把复制拦截 `Focus` 从 Windows 分支挪出，所有平台都挂、是否接管只由谓词决定；右键 `ContextMenuTrigger` 仍只在 Windows 包。已核对 `shortcut_defaults.dart`：`keyC` 只有视频 scope 的裸 C（`videoToggleShaderCompare`），没有任何 Ctrl+C 绑定，`_macOS` 的 Ctrl→Meta 映射不会产生 ⌘C 冲突；复制拦截本来就在快捷键解析之前。同时改正 `reader_space_override.dart` 注释与 BUG-402 文档里「macOS 自带原生 copy」的错误说法。提交哈希：`e30b55cfa6`。
- **[x] ② 已加自动化测试** — 谓词真值表 `fushi/test/shortcuts/reader_desktop_copy_test.dart`（macOS ⌘C 命中；macOS Ctrl+C / ⌘⇧C / ⌘⌥C / 裸 C / ⌘V 不命中；Windows Meta+C 不命中；Linux/移动端 Ctrl+C 与 Meta+C 都不命中）；源码守卫 `fushi/test/reader/reader_desktop_copy_guard_test.dart`（阅读器调用必须同时传 `isWindows: isWindowsPlatform` 与 `isMacOS: isMacOSPlatform`，改前红）、`fushi/test/pages/popup_copy_shortcut_and_menu_guard_test.dart`（弹窗复制拦截层不得包在 `isWindowsPlatform` 分支里，`_handleDesktopCopyKey` 必须传两个平台事实）。
- **备注**：
  - 真机缺口：本机没有 Mac，「选中正文 → ⌘C → 系统剪贴板拿到文字」这条链路没实测；弹窗内 ⌘C 还依赖弹窗 WebView 的 Flutter FocusNode 在焦点链上（Windows 已验证此路径，macOS 未验证）——若 macOS 上焦点停在阅读器正文，⌘C 会走阅读器那条、取阅读器正文选区。
  - 残余待查：macOS 右键「拷贝」是否可用未知（反馈人未回答开发者 10-31 的追问）。macOS 走非 Windows 的 `ContextMenu` 自定义「复制」项（`fushi/lib/src/pages/implementations/reader_fushi/webview.part.dart:2147` 附近），能否弹出未验证。
