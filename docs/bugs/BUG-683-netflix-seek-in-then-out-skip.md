## BUG-683 · 网飞批量制卡 seek 过去马上跳走没录制（seek-in-then-out）
- **报告**：2026-07-09（用户：网飞批量制卡「有概率跳过某几张卡」；关键复现诊断：「跳转过去以后马上跳转走了，根本没制卡」/ TODO-1361 ⑤ 续）
- **真实性**：✅ 真 bug（seek→录制交接时序缺陷，非 BUG-675 归因的「DRM 回放概率性失败」）。根因 `tools/browser-extension/content.js`（两镜像）`hibikiRunNetflixBatch` 逐句 seek 后的「就绪判据」：
  - 旧实现 `seek → v.pause() → hibikiWaitForBuffered → v.play() → for(let i=0;i<8&&v.paused;i++){play();sleep(60)} → if(v.paused){fail++;continue}`（原 content.js:429-431）。它在**固定 480ms（8×60ms）后只看一次 `v.paused`** 就决定「跳过本句」。
  - 两处判据错误：① `v.paused === false` **不等于视频在播/在前进**——seek 后 `<video>` 元素可能仍处于 `seeking`（currentTime 冻结）却已 `paused=false`；② Netflix seek→恢复播放的耗时**多变**（DRM/缓冲/MSE 段喂入），480ms 常不够。二者叠加 → **本可录的句被误判「暂停」，立刻 `continue` 进下一句 `seekTo`**——用户肉眼看到「跳过去→马上跳走、根本没停下来录」。这属 seek 时序误跳，被 BUG-675 归到「DRM 概率失败」类里（都进 `fail++`），但根因是时序不是 DRM。
  - 另一隐患：`seekTo` 的 `seekDone` 只据 Netflix 播放器 API `getCurrentTime`（netflix-bridge.js:98-104）判定，MSE 下 `<video>` 元素层可能滞后仍 `seeking`/停旧位；旧代码没在 `<video>` 层再确认落定就 pause/play → 可能停在旧位录错内容/空录。
- **[x] ① 根因修复** — 提交 `<PENDING>`。`tools/browser-extension/content.js` + `hibiki/assets/browser_extension/content.js`（两镜像逐字节一致，byte-identity 由 `browser_extension_dict_media_mirror_guard_test.dart` 守）。把「固定 480ms 后单看 `v.paused`」换成**两道条件驱动的有界就绪门**（非盲目延迟，条件满足即刻返回，正常句零/极小额外延迟）：
  - `hibikiWaitForSeekSettled(v, targetSec, 4000)`：暂停态有界等 `!v.seeking && |currentTime-target|<0.5s`，确认 seek 真落到 `<video>` 元素层再开录（不吃入队预留的 200ms 头部提前量；上界 4s 兜底不卡死）。
  - `hibikiWaitForPlaying(v, 4000)`：以**「currentTime 相对开录基线是否前进」**为唯一判据有界等视频真在播，期间反复补 `play()` 抗自动播放拦截/播放器暂态回暂停；真前进了才 `beginClip`。到 4s 上界仍推不动才 `fail++`（真 DRM/网络/自动播放失败，**留队可重试，BUG-675 清点不变**），不再因 seek→播放时序把本可录的句误跳。顺带修好 seek 后 `seeking` 冻结帧被录进 clip（TODO-1335 ④ 只以 readyState 门控、未覆盖 `seeking`）的隐患。内容脚本版本 `v43→v44`。**未碰** BUG-674/675/676（隐藏下一集/残留清点/documentTitle）、BUG-681（`kNfClipTailPadSec` 尾部补时）逻辑。
- **[x] ② 已加自动化测试** — `hibiki/test/mining/netflix_bug683_seek_gate_guard_test.dart`（两镜像各守）：断言 ① 旧 `for (let i = 0; i < 8 && v.paused` 480ms 快照跳过已删除、不得复活；② `hibikiWaitForSeekSettled` 存在且在录制前 await、判据含 `!v.seeking`；③ `hibikiWaitForPlaying` 存在、`const advancing = await hibikiWaitForPlaying`、判据为 `v.currentTime > base + 0.02`（前进）而非 `v.paused`；④ advancing 门在 `beginClip` **之前**；⑤ `if (!advancing) { fail++;` 仍走失败清点（不静默丢卡，BUG-675 契约不破）；⑥ 版本 `v44`；⑦ `kNfClipTailPadSec`（BUG-681）仍在。`flutter test`（本 guard + `netflix_todo1361_fixes_guard_test.dart` + `browser_extension_dict_media_mirror_guard_test.dart`）57 全绿；两镜像 `node --check` 通过、`cmp` 逐字节一致。
