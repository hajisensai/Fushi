## BUG-4165 · macOS 小说阅读器选中正文后 ⌘C 无法复制
- **报告**：2026-11-06（用户：QQ 群「/星尘///」经 fushi-bot 应用内反馈 `p7TdfQeivq`，macOS，3.0.1-debug.21966）
- **真实性**：✅ 真 bug（沿代码路径确认，本机无 Mac 未真机复现）。根因 `fushi/lib/src/shortcuts/reader_space_override.dart:174`（旧 `readerShouldHandleDesktopCopy` 第一行 `if (!isWindows) return false;`）：桌面复制兼容层只在 Windows 生效，依据是 BUG-402 写下的「macOS 的 WebView 自带原生 copy」——这个前提从没在 Mac 上验证过，而且是错的。BUG-2948 真机取证「点击阅读器正文后 first responder 仍是 `FlutterView`（不是 WKWebView）」；机制见 BUG-2508（desktop_drop 的 DropTarget 压在窗口最上层，点击由引擎转发给平台视图）与 BUG-3131（`flutter_inappwebview_macos` 不调 `makeFirstResponder`）。所以这一情形下 Flutter 对 ⌘C 返回 ignored 后，Runner 菜单 Edit > Copy（`MainMenu.xib` 的 `copy:`）发给 first responder = FlutterView，它不在文本输入态、不实现 `copy:`，WebKit 收不到 copy：能选中、⌘C 没反应。first responder 并非始终是 FlutterView：DOM 节点获焦时 WebKit 会把 WKWebView 交成 first responder（BUG-2447、BUG-3828，`reader_fushi/caret.part.dart:63` 注释同一事实），那时原生 copy 本身可用、⌘C 不进 Flutter，接管谓词不会被调到，不会重复处理，所以修复对两种情形都成立。两个调用点都把 macOS 排除在外：阅读器正文 `fushi/lib/src/pages/implementations/reader_fushi/caret.part.dart:178`（谓词只传 `isWindows`）、查词弹窗 `fushi/lib/src/pages/implementations/dictionary_popup_webview.dart:4101`（修复前：谓词同样只传 `isWindows`，且复制拦截 `Focus(onKeyEvent: _handleDesktopCopyKey)` 整个包在 `if (isWindowsPlatform)` 分支里，macOS 弹窗根本没有这层）。
- **[x] ① 已修复** — 谓词改名 `desktopShouldHandleCopyGesture({key, modifiers, isWindows, isMacOS})`，按平台取主修饰键：Windows 只认 {Ctrl}+C，macOS 只认 {Meta}+C，混入 Shift/Alt/另一修饰键、Linux、移动端一律 false。阅读器正文与查词弹窗继续共用这一个谓词，复用两边已有的 `_copyNativeSelectionToClipboard`（取 `window.getSelection()` 写 `Clipboard.setData`），不另写 macOS 逻辑。弹窗把复制拦截 `Focus` 从 Windows 分支挪出，所有平台都挂、是否接管只由谓词决定；右键 `ContextMenuTrigger` 仍只在 Windows 包。已核对 `shortcut_defaults.dart`：`keyC` 只有视频 scope 的裸 C（`videoToggleShaderCompare`），没有任何 Ctrl+C 绑定，`_macOS` 的 Ctrl→Meta 映射不会产生 ⌘C 冲突；复制拦截本来就在快捷键解析之前。同时改正 `reader_space_override.dart` 注释与 BUG-402 文档里「macOS 自带原生 copy」的错误说法。提交哈希：`e30b55cfa6`。
  - **审查补修（弹窗 / 歌词两面）**：只挪弹窗的 `Focus` 在 macOS 上走不到——`AppKitView` 只在引擎回调 `onFocus` 时 requestFocus（Flutter 3.47.6 `packages/flutter/lib/src/widgets/platform_view.dart:1045-1047`），macOS 引擎不发 viewFocused（BUG-3131 排除路径里的真机事实），弹窗 WebView 的 FocusNode 永远不进焦点链；阅读器 `Focus(_focusNode)` 是正文 + 弹层的共同祖先（`reader_fushi_page.dart` 的 `onKeyEvent: _handleKeyEvent` 那层），所以弹窗里拖选后 ⌘C 落进阅读器的复制分支，旧实现只读正文 `_controller` 的选区并吞键：正文无选区时静默无效，正文残留旧选区（Shift 悬停查词不清选区）时复制出错误文字。有声书歌词覆盖层同理（Windows 上原本也错）：复制固定读正文，没跟着屏上的歌词 WebView 走。根因是「复制键的目标面」只有一个硬编码的正文 controller，而阅读器页上有多个各持独立原生选区的 WebView。改为由阅读器按**可见层叠顺序**分派：`_copyNativeSelectionToClipboard` 经纯函数 `copyFromTopmostSurfaceWithSelection`（`fushi/lib/src/shortcuts/reader_space_override.dart`）自顶向下尝试——可见弹窗各层（`BaseSourcePageState.visiblePopupStatesTopDown`，最上层在前，每层调 `DictionaryPopupWebViewState.copyNativeSelectionForHost`：穿透 iframe 取选区，非空写剪贴板 + 成功提示，空则返回 false 不提示）→ 阅读面（歌词覆盖层显示时 `_lyricsController`、否则正文 `_controller`；被盖住的正文不进候选）。第一个有选区的面胜出，后面不再读；全部为空不写剪贴板。弹窗自己的 `Focus` 层保留（Flutter 焦点确实进了弹窗子树的平台 / 宿主上仍就地接住），注释改为如实说明 macOS 上它收不到键。
- **[x] ② 已加自动化测试** — 谓词真值表 `fushi/test/shortcuts/reader_desktop_copy_test.dart`（macOS ⌘C 命中；macOS Ctrl+C / ⌘⇧C / ⌘⌥C / 裸 C / ⌘V 不命中；Windows Meta+C 不命中；Linux/移动端 Ctrl+C 与 Meta+C 都不命中）；源码守卫 `fushi/test/reader/reader_desktop_copy_guard_test.dart`（阅读器调用必须同时传 `isWindows: isWindowsPlatform` 与 `isMacOS: isMacOSPlatform`，改前红）、`fushi/test/pages/popup_copy_shortcut_and_menu_guard_test.dart`（弹窗复制拦截层不得包在 `isWindowsPlatform` 分支里，`_handleDesktopCopyKey` 必须传两个平台事实）。审查补修追加：`reader_desktop_copy_test.dart` 的 `copyFromTopmostSurfaceWithSelection` 组（顶层有选区时下层——含残留旧选区的正文——一次都不读；顶层空时落到下一层；全空返回 false；无候选返回 false）；`reader_desktop_copy_guard_test.dart` 断言阅读器复制先走 `_caretVisiblePopupStatesTopDown` / `copyNativeSelectionForHost`、阅读面按 `_lyricsOverlayShown` 在 `_lyricsController` 与 `_controller` 间选，且不再直接读 `_controller` 当唯一来源；弹窗守卫断言 `copyNativeSelectionForHost` 空选区不提示。注：弹窗守卫「Focus 不包平台分支」只证明结构，**证明不了** macOS 上能收到键——macOS 能用靠的是阅读器分派那条。
- **备注**：
  - 真机缺口：本机没有 Mac，「选中正文 → ⌘C → 系统剪贴板拿到文字」这条链路没实测；弹窗 / 歌词里 ⌘C 走阅读器分派，同样没在 Mac 上实测。
  - 残余范围：阅读器以外挂词典弹窗的宿主（视频页、texthooker、首页查词等）在 macOS 上 ⌘C 仍到不了弹窗——同一焦点事实，弹窗自己的 `Focus` 收不到键、这些宿主也没有分派。本次只修反馈所在的阅读器页；要覆盖它们需在各宿主键盘处理里同样调 `visiblePopupStatesTopDown` / `copyNativeSelectionForHost`。
  - 残余待查：macOS 右键「拷贝」是否可用未知（反馈人未回答开发者 10-31 的追问）。macOS 走非 Windows 的 `ContextMenu` 自定义「复制」项（`fushi/lib/src/pages/implementations/reader_fushi/webview.part.dart:2147` 附近），能否弹出未验证。
