## BUG-907 · 弹幕两项性能缺陷：布局每帧 O(N) 全量扫描 + 20MB sidecar 主 isolate 同步解析
- **报告**：2026-07-19（守卫审计批：弹幕子系统性能）
- **真实性**：✅ 真 bug（两项，同属弹幕子系统，一并根修）。
  - **缺陷 A（每帧 O(N) 全量扫描）**：`hibiki/lib/src/media/video/video_danmaku_layout.dart:59` `VideoDanmakuLayout.layout()` 每帧从 `i=0` 扫到 `items.length`，`:61-65` 用 `elapsed = positionMs - item.startMs` + `if (elapsed<0 || elapsed>durationMs) continue` 筛活动窗口。`items` 已按 `startMs` 升序（来源 `video_danmaku_source.dart:93/:137` 解析后 sort），但布局层没利用有序性——弹幕全集可达数千~上万条，每帧全量遍历是纯浪费（活动窗口只占极小切片）。
  - **缺陷 B（主 isolate 同步解析）**：`hibiki/lib/src/media/video/video_danmaku_source.dart:67` `readTextWithEncoding` 异步读盘 OK，但 `:69-71` 紧接着**在当前（主）isolate 同步**调 `parseBilibiliDanmakuXml`（`:82` 内部 `XmlDocument.parse` + `findAllElements` 遍历 + sort）/ `parseDandanplayDanmakuJson`（`:101` 内部 `jsonDecode` + 遍历 + sort）。sidecar 上限 `kVideoDanmakuLocalMaxBytes = 20MB`，20MB XML/JSON 的解析会阻塞 UI 线程数百 ms 卡帧。调用点 `hibiki/lib/src/pages/implementations/video_hibiki/danmaku.part.dart:29` `await loadDanmakuSidecarFile(...)`。
- **[x] ① 已修复**
  - **A 根修**：`video_danmaku_layout.dart` 新增静态二分 `_lowerBoundByStartMs(items, target)`（lowerBound，返回首个 `startMs >= target` 下标）。`layout()` 改用二分定位活动窗口 `startMs ∈ [positionMs - maxDurationMs, positionMs]`（`maxDurationMs = max(scrollMs, fixedMs)`）：`loIndex = _lowerBoundByStartMs(items, positionMs - maxDurationMs)`、`hiIndex = _lowerBoundByStartMs(items, positionMs + 1)`，只遍历 `[loIndex, hiIndex)` 切片。切片内仍对每条按其**自身模式**的 `durationMs` 做原精确判定（`elapsed<0 || elapsed>durationMs`），故 fixed（4s）模式窗口比 scroll（8s）短的差异由切片内精确判定兜住——与原全量筛选**逐条等价**，只是每帧从 O(N) 降到 O(log N + 活动数)。二分依赖 `items` 升序契约（已由 source 层 sort 保证，代码注释注明）。
  - **B 根修**：`video_danmaku_source.dart` 新增顶层纯函数 `_parseDanmakuContent((String, bool) request)`（按 `isJson` 分派到 JSON/XML 解析器，无闭包捕获）。`loadDanmakuSidecarFile` 的解析改为 `await compute(_parseDanmakuContent, (content, ext == '.json'))`：IO（`readTextWithEncoding` 读盘 + 编码探测）留在主 isolate，CPU 密集解析搬到后台 isolate。入参 `(String, bool)` 记录、出参 `List<VideoDanmakuItem>`（纯 `int/String/enum` 不可变数据类）均可跨 isolate 传输。`loadDanmakuSidecarFile` 签名不变（本就 `Future`），调用点 `danmaku.part.dart:29` 无需改动。
  - 提交见本轮 commit（`git log`）。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_danmaku_layout_test.dart`（扩充）
  - **A 等价性**：新增参考实现 `_referenceActive`（逐条复刻优化前全量扫描逻辑），`binary-search active set equals full-scan reference across sweep` 用混合模式（scroll/top/bottom）升序 items + `positionMs` 从 -500 到 30000 步进 250 全扫，断言二分 `layout` 的活动集 identity（`startMs|mode|text` 键集）逐点等于参考全量筛选。`binary-search equivalence holds on edge inputs` 覆盖空列表 / 单条（窗口内外、边界 elapsed==durationMs）/ 全在窗口内 / 全部过期 / 全部未出现。用超大 `maxActive/maxLanes` 关掉截断丢帧，让 entries 集合 == 内部活动集。
  - **B 正确性 + 守卫**：`parseBilibiliDanmakuXml maps p-attr and mode correctly`（scroll/top/bottom 模式 + 升序）、`parseDandanplayDanmakuJson maps comments correctly`（升序排序 + 字段映射）直测纯函数；`loadDanmakuSidecarFile parses off the main isolate via compute` 源码扫描守卫断言 `video_danmaku_source.dart` 含 `await compute(` + `_parseDanmakuContent`，且旧同步分派 `items = ext ==` 已消失（后台解析无法在 headless widget 测试直接驱动帧时，用源码守卫钉住不变式）。
