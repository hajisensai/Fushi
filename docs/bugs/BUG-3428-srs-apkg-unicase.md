## BUG-3428 · 安卓导入新格式 Anki 包报 no such collation sequence: unicase
- **报告**：2026-10-15（用户：安卓真机，复习页 ⋯ → 导入 → 选 Anki 包，弹「导入失败：SqliteException(257): while preparing statement, no such collation sequence: unicase … Causing statement: SELECT ntid, ord, name, config FROM fields」）
- **真实性**：✅ 真 bug。Anki 2.1.28+ 的新 schema（`collection.anki21b` / 新 `collection.anki21`）里 `notetypes` / `fields` / `templates` / `decks` / `tags` 的 name 列与唯一索引是 `COLLATE unicase`，这是 rslib 打开库时现注册的自定义排序规则，标准 SQLite 没有。`packages/fushi_engine/lib/srs/apkg/srs_anki_package.dart:332`（修前；修后 :334）`SrsAnkiCollection.open` 用裸 `sqlite3.open` 打开解出的集合，没注册 `unicase`，于是 `_loadNoteTypesProto` 的第一条 `SELECT … FROM fields`（`srs_anki_package.dart:527`）在 prepare 阶段就失败。测试夹具 `apkg_test_support.dart` 的 `schema18Extra` 没写 `COLLATE unicase`，所以既有测试一直覆盖不到。旧格式 `collection.anki2`（JSON 列模型，无这些表）不受影响。已用忠实 DDL 的夹具在单测里复现出与用户逐字相同的报错。
- **[x] ① 已修复** — 新增 `packages/fushi_engine/lib/srs/apkg/anki_collection_db.dart`：`openAnkiCollectionDb` / `registerAnkiCollations` 在第一条查询前用 `Database.createCollation(name: 'unicase', …)` 注册大小写折叠比较（`toUpperCase().toLowerCase()` + `ß`→`ss`，近似 rslib 的 `UniCase::cmp`）。所有打开 Anki 集合库的地方都走它：`SrsAnkiCollection.open`（apkg 导入）与 `fushi/lib/src/anki/anki_backup_word_reader.dart`（iOS 读 Anki 备份第一字段；只查 `notes` 本不受影响，统一入口防后续查配置表再踩）。`srs_apkg_export.dart` 写的是自建的 schema 11 库（无 unicase），不需要。提交见 PR。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/apkg/anki_collection_db_test.dart`：夹具改成 Anki rslib 的真实 DDL（`COLLATE unicase` + `WITHOUT ROWID` + 唯一索引 + `tags` 表）；断言裸 `sqlite3.open` 读 `fields` 报 no such collation（夹具忠实）、`SrsAnkiCollection.open` 读出笔记类型/字段/模板/牌组/预设（修前逐字复现用户报错、修后通过）、unicase 比较语义与唯一索引按大小写不敏感判重。
- **备注**：unicase 语义与 Anki 的差异：Dart 无 Unicode case-fold API，除 `ß` 外的一对多折叠（如 `ﬁ` 连字）、土耳其无点 i、希腊词尾 σ/ς 与 rslib 不完全一致；Dart 按 UTF-16 码元定序、Rust 按码点定序，BMP 外字符相对顺序可能不同。导入只读这些表、不依赖排序结果，差异不影响能否读出。
