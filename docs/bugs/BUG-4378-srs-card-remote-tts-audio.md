## BUG-4378 · eggrolls 卡组例句在线 TTS 键点了没声音（WebKit 播不了不支持 Range 的远程音频）
- **报告**：2026-10-28（应用内反馈 `Feedback: ffWC0TPq1I`，macOS 3.0.1-debug：导入的蛋卷（eggrolls-JLPT10k）卡组，例句右侧的播放键点了无效；同一牌组在 Anki 里能出声。反馈人后续补充：笔记里没有句子音频，模板见反馈时间线）
- **真实性**：✅ 真。截图里例句右侧是紫色描边的键，对应模板 CSS 的 `.tts.replay-button`——不是 `[sound:]` 渲染出的键，而是模板 `setEdgeTTS()` 在例句音频字段为空时自造的在线 TTS 键（v26.06.13 模板 `tts.enable` 默认 `'fallback'`）：`<audio preload="none">` 下挂两个 `<source>`，指向 `ms-ra-forwarder-…vercel.app/api/aiyue?…` 与 `anki.0w0.live/api/aiyue?…`，点键 `audio.play()`。实测这两个服务：前者 200 `audio/mpeg`，但**不支持 Range**（带 `Range: bytes=0-1` 仍回整份 200）；后者 502。Anki 桌面是 Chromium，照播；Fushi 的 macOS / iOS 卡面是 WKWebView，HTTP 媒体走 AVFoundation，要求服务器支持字节范围请求（拿不到 206 就播不出），所以点了没有声音。Fushi 侧的缺口在卡面页面让媒体开播的唯一入口——自动播放闸门的 `play()` 包装（`fushi/lib/src/srs/srs_card_autoplay.dart:384`，修复前）直接把远程源交给 WebView 自己的媒体管线，没有任何一端替页面把远程音频变成本平台能播的形态；卡面 WebView 的网络也不走 Fushi 的代理设置。（AI 总结里的「异步取音频后 play() 被闸门当无手势拒绝」不成立：模板是在同一次点按里同步 `play()`，闸门放行。）
- **[x] ① 已修复** — 卡面页面里源是公网 http(s) 的 `<audio>` 开播时（闸门 `play()` 包装，`srs_card_autoplay.dart` 的 `playRemote`），候选地址（`src`，或按文档顺序的各 `<source src>`）经 JS 桥 `onSrsFetchRemoteAudio` 交给宿主；宿主走应用代理出口（`createAppHttpClient`）按顺序取（前一个失败才试下一个，与浏览器选源一致），只收音频（`Content-Type` 为 `audio/*` / `application/ogg`，否则按文件头认），32 MiB 上限；页面拿到字节做成 `blob:` 换上再播（`blob:` 由浏览器内存供数，天然支持范围请求，五端同一条路）。手势里就记下许可，取回后的开播不再看手势；取回期间 `pause()` / 换卡 / 翻面作废这次开播（`AbortError`），宿主取不到以 `NotSupportedError` 拒绝并记诊断日志。卡面媒体虚拟域、`blob:` / `data:` 等本地源不经宿主；视频不搬。新文件 `fushi/lib/src/srs/srs_card_remote_audio.dart`，外壳装 `kSrsCardRemoteAudioScript`，`SrsWebCardFace` 注册桥。提交见 PR。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_card_remote_audio_test.dart`（真 HttpServer：不支持 Range 的音频服务、502 后换下一个、octet-stream 的 mp3、网页 / 超限 / 非 http(s) 拒收；桥应答形态；外壳装载顺序）+ `srs_card_remote_audio_harness.mjs`（真 headless Chrome 跑生产外壳 + eggrolls 模板 `setEdgeTTS` 原样：点 TTS 键 → 两个候选按序交给宿主 → `blob:` 播放、二次点击不重取；宿主失败 `NotSupportedError`；取回中 `pause()` / 换卡 → `AbortError`；本地媒体不经宿主）。测试未在本分支运行，统一在合并后验证。
- **备注**：macOS / iOS 真机上点 eggrolls 在线 TTS 键出声未复测（WebKit 的 Range 要求是按 Apple 文档与常见现象判断，本机无 Apple 设备）；`<audio autoplay>` 直接写远程地址、不经 `play()` 的开播不在本次范围。
