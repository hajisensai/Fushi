## BUG-3694 · 首页「继续」远端合集每集一张同名卡
- **报告**：2026-10-23（用户：应用内反馈 GonyeE75Kd，Android 3.0.0-debug.20644「一堆kon播放列表」）
- **真实性**：✅ 真 bug。互联子设备首页「继续」区主卡是「K-ON! 播放列表 · 观看 · 卒業式！· 远端」，下面一排完全相同的「K-ON! 播放列表 · 远端」卡。根因 `fushi/lib/src/utils/misc/dashboard_remote_merge.dart:83-94`（修复前）：`remoteContinueCandidates` 对 host 视频清单**逐行**出候选（`positionMs > 0` 即一张），不看 `RemoteVideoInfo.collection`；host 上同一播放列表每看过一集就有一行带断点（BUG-3491 起播放不再自动打勾，看完的集也保留断点），于是 N 集 = N 张卡。小卡标题按显示名规则取合集名（`home_dashboard_page.dart` `_continueDisplayTitle` 的 `entry.collectionName ?? entry.title`），所以 N 张卡同名同封面。本地视频在 `home_dashboard_page.dart:1741-1793` 早已按主合集收敛成「一合集一卡」（`_collectionResumeTarget` → `continueMemberIndex`），远端路径没走同一判据。不是键不一致或同步重复写 history：每张卡是不同 episode 的 `RemoteVideoInfo.id`。书侧同病（远端分卷各在读就各一张）。
- **[x] ① 已修复** — `remoteContinueCandidates` 对带主合集归属的远端书 / 视频按 host 合集自然键（类型 + 名）归组，组内按 host sortIndex 排序后跑与本地合集同一个 `continueMemberIndex`（锚点 = 最近播放 / 阅读的成员，看完就推进下一个），一合集最多一张卡；整组没开始 / 整组看完不出卡；单元活跃时刻取组内最大 `positionUpdatedAtMs` / `progressUpdatedAtMs`。远端视频散卡补上与本地散卡同口径的「未看完」（`completedAt == null`）。另加 `withoutLocallyCoveredCollections`：本地已出同名合集卡（host 合集按名收养进本地同名合集，本地 / 远端成员可同在一个合集）时去掉远端那张，dashboard 在混排前调用。
- **[x] ② 已加自动化测试** — `fushi/test/sync/interconnect_dashboard_feed_test.dart` 组「反馈 GonyeE75Kd：远端合集在「继续」区一合集一卡」（6 条：多集一卡且落最近集、片尾推进下一集、整组看完 / 未开始不出卡、不同合集各一张 + 看完散卡不进、书合集同判据、本地同名合集卡去重）。
- **备注**：远端「继续」卡点击仍只切到视频 / 书架 tab（远端占位卡承接播放），本次未改。
