## BUG-4373 · 漫画：WebView2 持键盘焦点时切换界面 / 统计 / 计时（及新书签）快捷键收不到，改键也不生效
- **报告**：2026-11-10（实现反馈 FhspOXxPl_「漫画添加当前页为书签快捷键」时沿代码路径发现）
- **真实性**：✅ 真 bug（代码路径定位，未在设备上复现）。漫画正文是原生 WebView，Windows 上 WebView2 持键盘焦点期间按键只存在于 DOM，只有页内键桥键表里的 token 会回传 Dart。原有两座键桥的键表都是硬编码默认 token：翻页桥只有 `ArrowLeft/ArrowRight/Escape/Esc/F11`、平移桥只有 `Ctrl+Arrow*`（`fushi/lib/src/media/manga/reader/manga_fushi_page.dart` 原 `navigationKeyBridgeScript` / `panKeyBridgeScript` 的 `keys:` 字面量，现为 `_kNavigationBridgeKeys` / `_kPanBridgeKeys`，见 `:777` / `:799` 附近）。`mangaToggleChrome`(M) / `mangaOpenStatistics`(I) / `mangaToggleStudyClock`(P) 以及新增的 `mangaToggleBookmark`(B) 的键都不在表里，WebView 持焦时按下去无响应；在设置里改键同样到不了 WebView 持焦路径。
- **[x] ① 已修复** — 新增第四座「命令键桥」`onMangaCommandKey`（`MangaFushiPage.commandKeyActions` / `commandKeyBridgeTokens` / `commandKeyBridgeScript`）：键表按注册表**当前**绑定以 `InputBinding.bridgeToken` 生成，每次换窗注入时重算（与鼠标桥同一范式），剔除与翻页 / 平移桥重叠的 token 防止一次按键执行两遍；回调汇进 `_handleNativeNavigationKey`，后者改用 `InputBinding.fromBridgeToken` 反解析（小键盘 DOM code）。命令键动作在 `inputActionForShortcut` 中都排在翻页门控之前、任何模式都执行，截获它们不会抢走 webtoon 原生滚动键。翻页 / 平移桥仍是硬编码表（按绑定生成会截走 webtoon 让给原生滚动的 ↑/↓/Space），不在本条范围。提交见分支 `claude/manga-bookmark-shortcut`。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_bookmark_shortcut_test.dart`（命令键桥 token 默认含 B/M/I/P、改键后跟随、与翻页 / 平移桥重叠剔除、生成脚本形状、handler 注册与注入的源码守卫、`fromBridgeToken` 反解析守卫）。
- **备注**：Windows 真机 WebView2 持焦路径未复测（本批不做真机验证），待补。测试未在本分支运行，统一在合并后验证。
