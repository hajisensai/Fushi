## BUG-3437 · 远端代下载任务删除时「同时删除已下载文件」勾选被丢弃
- **报告**：2026-10-16（CLI 全覆盖审查中发现，主代理确认按字面生效修）
- **真实性**：✅ 真 bug。下载页「远端任务」卡（`fushi/lib/src/pages/implementations/remote_download_tasks_section.dart`）以 `deletesFiles: true` 摆出「同时删除已下载文件」勾选框，但删除回调忽略勾选直接 `client.delete(target, jobId)`；协议层 `DELETE /api/downloads/<id>` 不带任何删文件参数（`fushi/lib/src/sync/interconnect_download_client.dart:254`、`packages/fushi_engine/lib/sync/downloads/host_download_routes.dart:62-65`、`packages/fushi_engine/lib/sync/downloads/host_download_host.dart:59`），能力位也不声明删除语义，于是删不删由 host 写死且两种 host 相反：app 当 host `fushi/lib/src/sync/app_download_host.dart:147-153` 恒 `deleteFiles: false`（勾了也不删），无头服务端 `packages/fushi_server/lib/src/download_host.dart:415-416` 恒 `deleteFiles: true`（不勾照样连整份种子数据一起删，见 `video_download_pipeline_service.dart` `deleteJob` 的 `removeTorrent(deleteFiles: …)`）。
- **[x] ① 已修复** — 协议加 `DELETE /api/downloads/<id>?deleteFiles=true|false`（路由解析，非法值 400）；`HostDownloadHost.deleteJob(jobId, {bool? deleteFiles})`，两种 host 给了参数按参数执行、缺省（旧客户端）保持各自历史行为；`/api/capabilities` 的 downloads 段加 `deleteFilesParam: true`（`kHostDownloadDeleteFilesParamCapability`）。客户端 `HostDownloadTarget.deleteFilesParam` 读能力位，`InterconnectDownloadClient.delete(..., deleteFiles:)` 只在 host 支持时发参数、否则拒绝而非静默丢弃。远端任务卡：host 支持 → 勾选框按字面生效；老 host → 不摆勾选框，卡片详情如实提示历史缺省（新增 i18n `download_remote_delete_files_host_default`）。CLI `dl rm --device` 支持 `--delete-files`，老 host 明确报错。提交：b970aaf5da。
- **[x] ② 已加自动化测试** — `fushi/test/sync/host_download_routes_test.dart`（路由：参数原样到达 host / 缺省 null / 非法 400）；`fushi/test/sync/app_download_host_test.dart`（真实 FushiSyncServer + InterconnectDownloadClient：能力位宣告、勾选真删 / 不勾保留、老客户端缺省保留、老 host 拒绝带参数）；`packages/fushi_server/test/download_host_discovery_test.dart`（服务端：显式 false 保留、true 删除、缺省连文件删）。
- **备注**：老 host（未升级）上的行为不变，只是界面不再给出兑现不了的勾选框。
