## BUG-5468 · ai-reasoning-effort-unsupported-model
- **报告**：2026-11-23（用户：沙盒 Fushi 实测）
- **真实性**：✅ 真 bug。OpenAI 提供商（`https://api.openai.com/v1`）模型 `gpt-5-mini`、推理档位「低」，把模型改成 `gpt-4o-mini` 后存着的 `"reasoningEffort":"low"` 不变，此后每个请求都是「服务返回错误（400）」。根因 `packages/fushi_engine/lib/ai/ai_chat_client.dart` `_openAiPayload`（原 :1137）：只要 `provider.reasoningEffort != none` 就发 `reasoning_effort`，不看所配模型收不收——OpenAI 对非推理模型（gpt-4o / gpt-4o-mini / gpt-4.1 / `*-chat-latest` …）回 400 `unsupported_parameter`。配置界面 `fushi/lib/src/pages/implementations/ai_provider_settings_section.dart`（原 :701）的推理档位行对任何模型、任何协议都显示（Anthropic / Gemini 载荷根本不用这个字段），而 OpenAI 预设的建议模型就是 gpt-4o-mini，开箱选「低」即坏。`classifyAiHttpFailure` 把这种 400 归成无信息的 `http_400`，用户看不出原因。
- **[x] ① 已修复** — `ai_chat_client.dart` 新增唯一判据 `aiModelAcceptsReasoningEffort`（非 OpenAI 兼容协议 → 不收；OpenAI 官方 host 上按模型名，封闭的旧非推理族 gpt-3.5 / gpt-4* / chatgpt-* / `*-chat-latest` / gpt-5-search 不收，`ft:` 微调按基座判；其余兼容端点信用户的显式选择）与 `effectiveAiReasoningEffort`；载荷构造只发生效档位，配置界面在所配模型不收时隐藏推理档位行。存着的档位不清，换回推理模型原样回来。兼容端点 / 认不出的模型不收时，400/422 体里带 `reasoning_effort` 的归成新短码 `reasoning_unsupported`（`kAiReasoningUnsupportedCode`，不重试），界面文案 `ai_error_reasoning_unsupported` 提示把「推理」改成关闭；仍不回显响应体原文。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/ai/ai_reasoning_effort_test.dart`：判据表（旧族 / 推理族 / 未知新模型 / 微调 / 兼容端点 / Anthropic·Gemini）、复现路径 gpt-4o-mini + 「低」不发字段且请求成功、gpt-5-mini 照发、兼容端点 400 归 `reasoning_unsupported` 且只发一次、兼容层其他措辞也认；`fushi/test/settings/ai_provider_settings_test.dart`：wire 形状正反两例、编辑页推理档位行随模型显隐的 widget 测试、短码文案映射。
- **备注**：判据是「非推理旧族黑名单」而不是「推理模型白名单」：OpenAI 新出的对话模型都是推理模型，白名单会让每个新模型在 Fushi 更新前都调不了档位。`*-chat-latest` 5.1 起只收 `medium`，同样按不可调处理。
