## BUG-1634 · 游戏内查词制卡截图包含查词框
- **报告**：2026-08-13（用户：Windows / KiriKiri 游戏内查词）
- **真实性**：✅ 真 bug。制卡从 popup 的 `mineEntry` 发起（`fushi/assets/popup/popup.js:1391-1394`），经 lookup bridge 和游戏内 mining handler 到达 `GalHookMiningCoordinator`（`fushi/lib/src/lookup/overlay_bridge_handlers.dart:72-80,308-350`、`fushi/lib/src/lookup/gal_ingame_lookup_controller.dart:517-524`、`fushi/lib/src/lookup/gal_hook_text_overlay_controller.dart:723-757`）。coordinator 在点击制卡后读取当前绑定窗口，并直接对该 HWND 做静态图或 GIF 采样（`fushi/lib/src/mining/gal_hook_mining_coordinator.dart:193-205,227-306`、`fushi/lib/src/mining/galgame_window_gif.dart:50-86`）；Windows 原生端使用 WGC `CreateForWindow(hwnd)` 捕获整个游戏窗口（`fushi/windows/runner/window_capture.cpp:338-340`）。游戏内 popup 此时已由 KiriKiri adapter 合成为游戏自身 Layer（`native/galgame_hook/hook/adapters/kirikiri_adapter.inc:1240-1346`），因此它必然进入同一窗口截图；这不是桌面或全局 screenshot provider 误选来源。
- **[x] ① 已修复并通过真实游戏 E2E** — v15 新增 exact `kLookupFrameCaptureSuppress` 与 hook→host 的 `lookup_frame_applied_seq`。Dart 获取截图租约后先冻结输入/重抓；hook 在游戏线程隐藏 card 与选词高亮，直到下一次 continuous callback 才确认 applied seq；静态图只包单次 WGC，GIF 只包多帧采样，`finally` 恢复当前离屏 popup 的最新位图。PID 35872 的真机会话中，制卡前后 `lookup_frame_applied_seq` 从 `0` 前进到 `76`，随后普通恢复帧推进到 `80`；新 Anki note `1786565255084` / card `1786565255085` 的 Picture 为 480×286 AVIF，SHA-256 `D5B259449D508EA7D233D8A5F8AF8CC5970C0EA72AC31D29BA8105ADDFD5B710`。原分辨率目视确认图片仅含游戏画面、原生对话框与游戏 UI，不含 Fushi popup 或选词高亮；popup 随后正常恢复并显示制卡成功状态。
