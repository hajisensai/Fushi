## BUG-2576 · VN 往前翻章 restoreProgress(0.99) 落到 99% 字数所在屏而非末屏，fragment 失效不回退进度
- **报告**：2026-09-18（用户：iOS VN 模式「跳转会跳到奇奇怪怪的位置，章节跳转有问题」）
- **真实性**：✅ 真 bug。宿主往前翻到上一章走 `_navigateToChapter(prev, progress: 0.99)`（`reader_fushi/navigation.part.dart`），`>= 0.99` 是「章末」的约定值：分页 shell `scrollToProgressPaged` 与连续 shell 都专门分流到 `scrollToChapterEnd`（`reader_pagination_scripts.dart`）。VN 的 `restoreProgress` / `renderInitialScreen`（`reader_visual_novel_scripts.dart`）只调 `screenIndexForProgress`，即「第一个尾锚 >= 0.99 的屏」——屏进度锚按字数线性分布，200 屏的章落到第 198 屏、距真正章末还差两屏，用户感知是「往前翻章落到奇怪的位置」。同函数里 fragment（目录/内链 `#id`）在屏表查无时直接硬落第 0 屏，也不回退到进度锚。
- **[x] ① 已修复** — 新增 `screenIndexForRestoreProgress(progress)`：`>= 0.99` 直接取末屏，否则沿用进度锚查找；`restoreProgress` 与 `renderInitialScreen` 两条宿主恢复入口统一走它，`calculateProgress` 往返（`refitScreensToCurrentViewport` / 样式重锚）仍走 `screenIndexForProgress` 不受阈值影响。`renderInitialScreen` 在 fragment 查无时退回进度锚（同为 restore 口径）。提交 `86ded222acf`（PR 分支 `pr/vn-ios-screen-fit`）。
- **[x] ② 已加自动化测试** — `fushi/test/reader/vn_measure_box_restore_progress_behavior_test.dart`（+ 同名 `.js`）：200 屏线性锚下 `screenIndexForProgress(0.99)` 落 197 而 `screenIndexForRestoreProgress(0.99)` 落 199（末屏）、0.5 仍走锚、空屏表退 0；`restoreProgress(0.99)` 真渲染末屏并 notify；`renderInitialScreen` 已知 fragment 优先、未知 fragment 回退进度锚、`initialProgress: 0.99` 开在末屏。另有源码断言：两条 restore 入口不再裸调 `screenIndexForProgress`。
- **备注**：搜索/收藏句「跳回原文」走 `scrollToSearchMatch` / `restoreToCharOffset`（字符偏移口径，与本条无关）；BUG-2556（`fushiProgressDetails` 在 VN 下分母取本屏字数）上游已合，本地 develop 未同步，未同步的开发版重开位置仍会偏。
