## BUG-3855 · 部分 Emby 服务器的 CDN/WAF 前置按 UA 拦 Dart 默认 UA，全站回裸 404，添加服务器与登录必失败
- **报告**：2026-10-28（用户：某台 Emby 4.9.5 服务器添加失败，报 `/System/Info/Public` 404、登录不了；同一台服其它第三方 Emby 客户端添加使用正常，只有本应用不行。macOS / Apple Silicon）。
- **真实性**：✅ 真 bug（**客户端没报自己的 UA**，服务器的 CDN/WAF 前置按 UA 拦，属客户端缺陷——不是服务器缺端点）。对该服 `/System/Info/Public` 实测（curl 逐 UA 定性）：`Dart/3.5 (dart:io)` → **`404`，响应体纯文本「404」**（正是用户看到的 404）；`Dart/1.0` / `DartFoo/1.0` / `Fushi/3.0.0 (Dart/3.5)` 同样 404；`Fushi/3.0.0` / `Emby/4.8.0.0` / `Dalvik/2.1.0 …` / 全小写 `dart` → 200；浏览器 / curl / okhttp UA → 403。即规则是「UA 含 `Dart` 子串（大小写敏感）→ 404」，与认证头 `Client=` 无关（`-A "Fushi/3.0.0"` + `Client="Hibiki"` → 200；`-A "Dart/3.5 (dart:io)"` + `Client="Emby Theater"` → 404）。同服 `/System/Ping`、`/emby/…` 前缀、`/Users/AuthenticateByName` 表现完全一致：`Dart` UA 一律裸 404，`Fushi` UA 分别回 `200 Emby Server` 与 `401 用户名或密码无效`——**登录失败也是同一个原因，不是账号问题**。根因在 `fushi/lib/src/sync/jellyfin_video_client.dart` 的 `JellyfinApi._headers`：只发 `Authorization` / `X-Emby-Authorization` / `Content-Type`，**从不设 `User-Agent`**，于是 `package:http` 底层的 dart:io `HttpClient` 自报默认 UA `Dart/<SDK 版本> (dart:io)`，撞上这类反代规则后探测、登录、封面、下载全 404。BUG-3137 / WMxpfrPXJp 的探测回退与「全 404 转认证请求定案」本身在工作——只是每条请求都被 UA 拦掉，探测拿真请求也定不了案，最终只能报「连不上」。
- **[x] ① 已修复** — 根因修：新增 `mediaServerUserAgent()`（`packages/fushi_engine/lib/media/video/media_server/media_server_client_identity.dart`），UA 报 `Fushi/<应用版本>`，与认证头 `Client="Fushi"` 同源（服务器后台看到的是同一个身份，不引入第二套身份字面量）；`JellyfinApi._headers` 加上 `'User-Agent': userAgentFor()`（`jellyfin_video_client.dart`），探测 / 登录 / 读媒体库 / 封面 `fetchBytes` / `downloadToFile` 全走这一份头，一次覆盖。`jellyfin_connect_trace.dart` 的诊断轨迹补一行 `user-agent: …`——此前「全站 404」与「服务器真没这条路由」在日志里一模一样，无从区分。**刻意不做**（同 BUG-2848 的取舍）：不冒充别的客户端名 / UA；本次只报自己的产品名与版本，而该服对任意非 `Dart` UA 一律放行，说明这是通用反爬规则而非客户端白名单，报自己的名字即可通过。
- **[x] ② 已加自动化测试** — `fushi/test/sync/jellyfin_client_identity_test.dart`：①「每个请求自报 User-Agent：产品名/版本，不含 Dart」——`JellyfinApi.userAgentFor()` 等于 `Fushi/3.0.1` 且不含 `Dart`，并断言登录流程里 `signInJellyfinServer` 发出的**每一条**请求（探测 + 登录）都带 `user-agent`；② 既有「公开端点与登录全 404」轨迹用例补断言 `user-agent: Fushi/` 进错误日志。
- **备注**：macOS debug 实跑真机复测**已做**：用真实代码路径打该服，`probeServer()` 回 `name=<服务器名>`（修复后 200），假账号 `authenticateByName` 回 401「用户名或密码无效」（修复前是 404），随后真账号登录成功、媒体库与封面正常。同类风险面（本条未改）：① `streamUrl` / `imageUrl` / `subtitleUrl` 是自带 `api_key` 的 URL，交给 flutter 图片解码器或 libmpv 请求，UA 由它们自己决定；② Plex 走另一套传输（`packages/fushi_engine/lib/media/video/media_server/plex/plex_api.dart` 的 `headers`，同样只有 `X-Plex-*` 身份头、不设 `User-Agent`），遇到同一类反爬前置的 Plex 服会是同一个病，需要时用同一个 `mediaServerUserAgent()` 补一行。
