## BUG-3273 · Preserve Jellyfin pause state in delayed position heartbeats
- **Report**: 2026-10-12, investigating premature completion after leaving playback.
- **Verification**: Protocol defect reproduced with the production client/API: unchanged develop fails 7 of the 10 regression cases; the fixed targeted batch passes 133 tests. The reported end-to-end incident has not been reproduced.
- **Root cause**: `fushi/lib/src/pages/implementations/video_fushi_page.dart:2992` starts background position flushes without awaiting them, while `_persistRemotePosition` (`:4334`) waits for database writes. The native pause listener (`:4424`) can therefore report `IsPaused: true` before the flush reaches `JellyfinVideoClient.putRemoteVideoPosition`. That heartbeat (`fushi/lib/src/sync/jellyfin_video_client.dart:3311`) previously omitted `isPaused`, so `JellyfinApi.reportProgress` (`:1733`) serialized its default `false`. The overwrite occurs only when the existing heartbeat throttle permits the later request.
- **[x] ① Fix** ([commit 608b407](https://github.com/MarvNC/Fushi/commit/608b4075b3b02566873b8fb889a7c46e7a8f783c)): Keep each item's last local pause intent, update it before pause/unpause HTTP, use it in position heartbeats, and reset it when playback starts (including the no-session compatibility path). Preserve intent across Stop because another disposal flush may still be pending.
- **[x] ② Automated regression** ([commit 608b407](https://github.com/MarvNC/Fushi/commit/608b4075b3b02566873b8fb889a7c46e7a8f783c)): `fushi/test/sync/jellyfin_paused_heartbeat_test.dart`, using the production client/API with an HTTP mock. Covers delayed, pending, and failed pause reports; playing/resume; item isolation; Start resets; and both late FIFO Stop and final-session Stop.
- **Validation**: The final formatted targeted batch passes 133 tests; full Flutter analysis reports no issues; independent source/test review approved. No device build or live-account test was performed.
- **Limits**:
  - No lifecycle changes, new Stop calls, threshold changes, or server/account changes.
  - Existing in-flight HTTP requests may arrive out of order; this fix corrects heartbeat payloads constructed after the local pause intent changes.
  - Hard process termination before any lifecycle/pause delivery remains outside the client's guarantee. Android device and live Jellyfin/Ani-Sync end-to-end verification are pending.
  - Jellyfin's separate stale-session extrapolation bug is documented in upstream [PR #17631](https://github.com/jellyfin/jellyfin/pull/17631). This report does not claim that mechanism occurred in the original incident.
