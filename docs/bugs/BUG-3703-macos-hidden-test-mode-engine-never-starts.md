## BUG-3703 · macOS 设了 FUSHI_TEST_HIDDEN 后主窗口从不入屏，Flutter 引擎不启动
- **报告**：2026-10-24（Mac 跨机冒烟时发现：`FUSHI_TEST_HIDDEN=1` 冷启进程只剩 AppKit 事件循环）
- **真实性**：✅ 真 bug，两层，前一层把后一层盖住了。
  1. 引擎不启动：`a0410792d8`（2026-10-03 启动外观）把 `MainMenu.xib` 主窗口改成 `visibleAtLaunch="NO"`，入屏只靠 `applicationDidFinishLaunching` → `MainFlutterWindow.hideForStartupPresentation()` 的 `orderFront`；但它开头 `guard !hiddenTestMode else { return }`（`fushi/macos/Runner/MainFlutterWindow.swift:19`，`a0410792d8` 版），`AppDelegate` 的 `showStartupWindow` 在隐藏模式下也不动窗口——窗口从未入屏，Flutter view 不挂载、引擎不启动。实测（develop `459d2af220`，M4 Mac，隔离 home）：7 线程、无 `io.flutter.*` / DartWorker 线程、RSS 98MB、零数据文件；同条件去掉 `FUSHI_TEST_HIDDEN` 正常建库。macOS 隐藏模式 itest 自 10-03 起全部起不来，CI 不跑 macOS itest 所以没暴露。
  2. 入屏后暴露：`awakeFromNib` 只在创建时把窗口停到 (-32000, -32000)，之后谁都能把它挪回屏内。`setFrame` 打点抓到三处：AppKit `orderFront` 的屏幕约束（`_reallyDoOrderWindow`）、窗口状态恢复（`restoreStateWithCoder`）、`window_manager.setBounds`（Dart `DesktopWindowPlacement.applyInitialPlacement`）；另有 AppKit 「标题栏至少一截在屏内」约束（`constrainFrameRect`）不经 `setFrame`。实测窗口先后停在 (132, 92) 1206x727 整块可见、只拦 setFrame 后仍剩左下角 261x110 一条可见。
- **[x] ① 已修复** — 全在 `fushi/macos/Runner/MainFlutterWindow.swift`，只作用于隐藏模式：`hideForStartupPresentation` 隐藏分支 `orderFront(nil)` 后返回（不碰 `alphaValue`）；重写 `setFrame(_:display:)` / `setFrame(_:display:animate:)` / `setFrameOrigin` 把 origin 钉在 `hiddenTestOrigin`（-32000, -32000，与 Windows `kOffscreenOrigin` 同值），尺寸照收；重写 `constrainFrameRect(_:to:)` 原样返回；`awakeFromNib` 隐藏分支 `isRestorable = false`。窗口位置归原生层管，Dart 启动定位不改。
- **[x] ② 已加自动化测试** — `fushi/test/native/macos_hidden_test_mode_window_guard_test.dart`：xib `visibleAtLaunch="NO"` 前提 + 启动调用；隐藏分支 orderFront 在 return 前、禁 `guard !hiddenTestMode`；三个 setFrame 族重写都钉 `hiddenTestOrigin`、`constrainFrameRect` 隐藏模式原样返回、`isRestorable = false`。变异实测：还原旧 `hideForStartupPresentation` / 去掉 `setFrameOrigin` 钉点，对应用例变红。
- **备注**：Mac 真机复测（M4 MacBook Air，macOS 26.6.2，release 包，独立 bundle id `app.fushi.reader.smoke` + `CFFIXED_USER_HOME` 隔离，`lsof` 全量文件清单真实 home 零命中）：修复后 `FUSHI_TEST_HIDDEN=1` 冷启 60 秒存活、19 线程、RSS 370MB、建库 v124 / 104 表，主窗口 1182x713 停在 (-31992, 32235) 完全屏外，`activationPolicy=accessory`、`isActive=false`、前台进程不变。非隐藏模式下 develop 基线与修复包窗口几何、线程数一致（无回归）。Windows 隐藏模式下 Dart `applyInitialPlacement` 的 `setBounds` 是否同样把窗口拉回屏内未复测（Windows runner 只在创建时停屏外、之后不拦截挪窗），不在本条范围。
