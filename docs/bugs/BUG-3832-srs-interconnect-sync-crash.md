## BUG-3832 · 小米设备 SRS 互联同步 / 复习记录 / 导入卡片时闪退（Dart 日志无栈）
- **报告**：2026-10-26（应用内反馈 XDV7Mzc2gw「同步 srs 数据时闪退」、kB2ltk0u9F「查看复习记录时崩溃，在页面待了一会儿」、U37Aku3oeL「导入卡片崩溃」；同一台小米 23116PN5BC，构建 21417 / 21568）
- **真实性**：⚠️ **闪退根因未能定位**（三份日志都没有任何崩溃栈；崩溃窗口前最后的 Dart 记录都是复习同步失败）。沿代码路径逐条核验：
  - 「不可达时紧循环重试」**不成立**（已验证）：`SyncBackendError: No reachable Fushi server address` 在 `srs_sync_scheduler.dart` `_syncWithBackend` 第一步算目录身份（`_directoryKeyOf` → `InterconnectSyncBackend.connectedHostIdentity`）时就抛出，走不到 `_onDataChanged`，失败不会自我触发下一轮。日志里每 ~8 s 一条是「本机推送 5 s 去抖（`srs_interconnect_watch.dart` `SrsLocalPush`）+ 一轮探测死地址约 3 s」，跟着用户答卡走。
  - **队列不合并（已验证，真缺陷）**：`syncWithBackend` 每次触发都往 `_serially` 的 FIFO 追加一轮；kB2ltk0u9F 16:53:23 / :37 / :44 / :51 四条 `syncThrottled` 失败间隔 7 s——60 s 节流下只能是它们早已放行、排在一轮长常规同步之后被连续重放。
  - **发件一次性全量进内存（已验证，结构风险，未证实是闪退原因）**：Rust `sync2_outbox`（`native/fushi_fsrs/src/store/sync2/transport.rs:648-692`）把 `uploaded` 之后的全部段一次打包返回，Dart 侧再复制一份（`srs_core.dart:551-557, 816-835`）；`uploaded` 只在写 head 时前进（`transport.rs:733-738`），上传中途断一次下一轮就整份重来。日志里本机设备目录失败段的 seq 一天内从 277661 涨到 427227，说明 ~43 万条操作的历史在局域网 host 时断时续时反复从头补传；同一设备 10-25 的旧日志里出现过 `FSRS-SNAP: OutOfMemoryError`。三次闪退都落在这个时期、且崩前无 Dart 错误——**推测**是补传 / 导入时内存峰值被系统按低内存杀掉，但没有证据坐实（没有退出原因记录，见 BUG-3831）。
  - 并发：本机推送与长轮询的 `syncWithBackend(InterconnectSyncBackend.instance)`（`srs_app_runtime.dart:163-194`）不拿常规同步的 `_autoSyncMutex`，可能与常规同步并发改同一单例后端的会话 / 选路缓存（已验证存在；`close()` 不带 force，推测不是闪退直接原因）。
- **[x] ① 已修复（可确定的缺陷 + 取证）** —
  - `fushi/lib/src/srs/srs_sync_scheduler.dart` `syncWithBackend`：同一后端 + 同一 `directoryKey` 已有一轮**排着还没开跑**时复用它的 future（开跑时会看到此前全部本机改动，合并不丢数据）；已开跑的不复用。排队不再随触发次数线性增长。
  - 同文件 `_trackRound`：每轮开跑**同步**写活动面包屑 `activity_srs_sync.breadcrumb`（后端、阶段、排队 / 在跑 / 合并数、连续失败数、RSS / maxRSS），阶段变化覆写，跑完删除；进程死在同步里，下次启动 `PreviousExitLog` 报 `Process.activityCrashRecovered`。失败轮次把同一组计数 + 上次失败时刻写进诊断段（`SrsSyncScheduler.roundFailed`）。配合 BUG-3831 的 Android `ApplicationExitInfo`（LOW_MEMORY / CRASH_NATIVE + pss / rss），下一次反馈就能区分「同步中被系统按内存杀」与「原生崩溃」。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_sync_scheduler_test.dart`「轮次合并与取证」组：排队中的三次触发合并成一轮、已开跑的不复用、跑时有面包屑跑完删除；失败累计连续失败数、成功清零；残留面包屑下次启动折成 `activityCrashRecovered`（带阶段与内存）。
- **备注**：**闪退根因仍待下一次带退出原因的反馈确认**。若证实是补传期内存峰值，根因修复是把发件改成按字节预算分批（`sync2_outbox` 加 `max_bytes` 并返回 `more`，`srsSync2Round` 第 3 步循环取批上传）并按批持久化上传进度（中断后续传而不是整份重来），与收段的 `kSrsSync2IngestBudgetBytes` 同口径——涉及 Rust 存储不变量（head 之前 `uploaded` 先前进），本批未做。`SrsLocalPush` 失败后无退避、推送 / 长轮询不走 `_autoSyncMutex` 两点也留待后续。**→ 三点均已在 BUG-3849 修复**（分批发件 + 水位续传、推送指数退避、推送 / 长轮询轮次进 `runExclusiveWithSync`）。未在真机验证。
