## BUG-4049 · 制卡字段 popup-selection-text 拍平成纯文本
- **报告**：2026-11-03（应用内反馈 aBgKMjhfut，Windows 3.2.0-debug.22671：「字典的选中内容 popup-selection-text 制卡到 anki 卡片里变纯文本了，非常不好读。能像 glossary 一样保有原本显示样式吗，或者 fushi 有其它统一的方便阅读的样式都可以」）
- **真实性**：⚠️ 现状属实，但是**设计如此**，不是数据通道丢样式的 bug；要不要改是产品取舍，待拍板。
  - `{popup-selection-text}` 从源头就是纯文本：`fushi/assets/popup/popup.js:1787` `snapshotSelection()` 取 `__fushiSel()?.toString()`（DOM `Selection.toString()`），作为 `popupSelectionText` 进制卡 payload；`packages/fushi_anki/lib/src/anki_models.dart:1133-1137` 原样代入字段。中途没有任何一层「先有 HTML 再拍平」——没有被丢掉的样式可以恢复。这与 Yomitan 同名占位符语义一致（推测：依据对 Yomitan `popup-selection-text` 取 `getSelection().toString()` 的记忆，本轮未对照其源码）。
  - 「保留样式」的那一路**已经存在**：同一次选区还会作为 `<mark class="fushi-selection">` 高亮落进导出的释义树（`applyGlossarySelectionHighlight`，`AnkiMiningPayload.glossarySelectionHighlighted`），也就是 `{glossary}` / `{selected-glossary}` 等释义字段里带原词典样式、选中段被高亮；Lapis 下 `SelectionText` 还会为它让位（`BaseAnkiRepository.shouldYieldSelectionText`）。
  - 一个确实存在的可读性损失：`Selection.toString()` 里的换行（跨义项 / 跨 `<li>` 选择时）原样写进 HTML 字段，Anki 渲染时折叠成空格，多义项选区会挤成一行。另外纯文本未做 HTML 转义，选区里含 `<` 时会被当成标签解析。这两点改了会改变所有现存卡片模板的输出，同样需要拍板。
- **[x] ① 已修（用户拍板方案 B，2026-11-04）** — 新增占位符 `{popup-selection-html}`，`{popup-selection-text}` 语义不变（仍是纯文本）。`popup.js` `snapshotSelection()` 同一时刻对同一 Selection 取 `snapshotSelectionHtml()`：逐 Range `cloneContents()`，按公共祖先最近的 `[data-dictionary]` 认词典并外包作用域，`sanitizeSelectionHtmlTree()` 去掉弹窗交互件（按钮 / 媒体 / 本地图片 / `<style>`）、DICT_HTML_BLOCKED_SELECTOR 元素、事件 / href / id / data-fushi-* 属性、inline style 的外链 url()，外包 `.yomitan-glossary` 并附所属词典的 scoped CSS（与 `{glossary}` 共用 `exportedDictStyleTag`，BUG-3762 的 `</style` 转义同一处）。`buildMinePayload` 只在纯文本正是这次快照时才上报 `popupSelectionHtml`。Dart：`AnkiMiningPayload.popupSelectionHtml` + `anki_models.dart` `{popup-selection-html}` 渲染（让位判据与纯文本版相同）、两处媒体二次重建透传、`AnkiHandlebarOptions.coreOptions` 与 picker 标签 `handlebar_popup_selection_html`、互联 host 白名单 `kGameStreamHostMineFieldKeys`。出厂预设（Lapis `SelectionText`、Fushi 卡型 `LookupSelection`、Senren）**不改映射**，需要样式的用户手动选新占位符。
  - 原选项（存档）：
  - **A 维持现状**：`{popup-selection-text}` 保持 Yomitan 兼容的纯文本；需要样式的用户映射 `{glossary}` / `{selected-glossary}`，选中段已带高亮。可在制卡设置的占位符说明里写明这一点。
  - **B 新增占位符**（如 `{popup-selection-html}`）：在 `snapshotSelection` 时 `Range.cloneContents()` 取选区 HTML 片段，带上所属词典的 scoped CSS（与 `{selected-glossary}` 同一套 `anki_glossary_css` 管线）。不动现有占位符语义；需要新 payload 字段 + 守卫 + 各预设（Lapis `SelectionText`、Fushi 卡型 `LookupSelection`）是否改映射的决定。
  - **C 只修纯文本的可读性**：`popupSelectionText` 写入字段前 HTML 转义并把换行转 `<br>`。改的是所有用户现有卡片的输出格式。
- **[x] ② 已加测试** — `fushi/test/anki/popup_selection_html_test.{js,dart}`（node 执行 popup.js：作用域 + scoped CSS、净化、跨词典 / 多 Range、快照生命周期、payload 源级）；`packages/fushi_anki/test/popup_selection_html_test.dart`（wire 解析、渲染、媒体二次重建透传、让位、picker）。真 WebView 里 `Range.cloneContents()` 的端到端未跑（本轮不做设备验证）。
