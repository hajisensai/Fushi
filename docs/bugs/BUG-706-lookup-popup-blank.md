## BUG-706 · 查词弹窗全空白: __hibikiRoot 函数名与 window.__hibikiRoot marker 冲突
- **报告**：2026-07-10（用户：TODO-1392 严重回归，查词弹窗完全空白，退 1.0.1+614 可恢复）
- **真实性**：✅ 真 bug。根因 `hibiki/assets/popup/popup.js:5`（PR#12 / BUG-688 引入，1.0.1+615）。
  - PR#12（BUG-688）把查词弹窗 DOM 放进 Shadow DOM，用 `window.__hibikiRoot` 作为「shadow 根」marker（仅浏览器扩展 content.js 会把它设为 shadow root；in-app 恒 undefined）。popup.js 顶层却声明了同名**辅助函数** `function __hibikiRoot(){ return window.__hibikiRoot || document; }`。
  - JS 经典脚本里顶层 `function __hibikiRoot(){}` 声明会**同时**在全局对象上创建同名属性 `window.__hibikiRoot = 该函数`。于是 in-app（扩展从不覆盖它）`window.__hibikiRoot` 恒为**真值（那个函数）**，`__hibikiContainer()` 里 `var r = window.__hibikiRoot; r.querySelector('#entries-container')` 在**函数对象**上调 `.querySelector` → `TypeError: r.querySelector is not a function` → `renderPopup()` 抛异常中止 → 词条永不渲染进 `#entries-container` → 弹窗全空白（FFI 查词其实返回了词条）。
  - 四个 in-app 宿主（reader base_source_page / video dictionary_page_mixin / 首页 home_dictionary_page / app 外 popup_dictionary_page）都加载同一份 popup.js，全部空白；浏览器扩展 vendor/popup.js 同源同 bug（content.js 把 `window.__hibikiRoot` 改写成 shadow 后，同名标识符 `__hibikiRoot()` 变成 `shadow()` 也抛错）。
  - Windows 离屏真机复现（WebView2）：reader 单击「猫」→ FFI lookup entries=1 + pushPopup，但 `[PopupWebView] Uncaught` + 探针 `TypeError: root.querySelector is not a function`，`#entries-container` 无 `.entry`、innerText 空 = 空白。
- **[x] ① 已修复** — 根因修复：把内部辅助函数从 `__hibikiRoot()` 改名为 `__hibikiRootNode()`（定义 + 8 处调用点），消除与 `window.__hibikiRoot` marker 的命名冲突；marker 读取（`window.__hibikiRoot`）原样保留，shadow-DOM 契约不变。三份 popup.js 同步修改：`hibiki/assets/popup/popup.js`、`hibiki/assets/browser_extension/vendor/popup.js`、`tools/browser-extension/vendor/popup.js`。提交 895c89cdf。
  - 真机复验（Windows 离屏 WebView2，同一条 reader 查词路径）：探针 hasHibikiRoot=false, entryCount=1, innerTextLen=88, innerTextSample="猫[ねこ]…HibikiGeneratedTestDict", containerHeight=197.98，弹窗真实出词条，非空白。证据 `.codex-test/windows-itest/win-itest-20260710-161834-7e0db1b2/`（修前证据 `win-itest-20260710-160557-82d5cc01`）。
- **[x] ② 已加自动化测试** — 源码扫描守卫 `fushi/test/reader/popup_fushi_root_marker_collision_guard_test.dart`：对三份 popup.js 断言「仍读 window.__fushiRoot marker」+「禁止 function __fushiRoot( 声明（同名会把 marker 重新发布成函数、in-app 弹窗空白）」+「存在并使用 __fushiRootNode()」。改回旧名即转红。（符号名 W9-2 由 `__hibiki*` 改名而来，目录名 W8 由 `hibiki/` 改名而来。）
- **备注**：静态审查易漏——`window.__hibikiRoot || document` 表面看是安全回退，真正的坑是**函数声明的副作用**把 marker 变量填成了函数。与 in-app 无关的 parkedPopupLayer / entry.visible 区分（那些在本批次零改动，已排除）。
