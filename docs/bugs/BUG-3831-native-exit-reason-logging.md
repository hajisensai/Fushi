## BUG-3831 · 原生崩溃 / 被系统杀的进程没有任何日志（反馈分诊约一半闪退卡在 Dart 日志无栈）
- **报告**：2026-10-27（反馈分诊 `docs/reviews/2026-10-27-feedback-triage.md`：WkL9BvD7Z9、XDV7Mzc2gw / kB2ltk0u9F / U37Aku3oeL、mA1DXdQruP、zhmmH5G4Hq、EQp4haAnV4、O2eI1Bewe_、B3HfY5HRWi / CuYJSpmM_2 等闪退反馈，附的日志只有一次冷启动）
- **真实性**：✅ 结构缺口（已验证）。错误日志只收 Dart 能接住的异常（`FlutterError.onError` / `runZonedGuarded` / `PlatformDispatcher.onError`，`fushi/lib/main.dart`），原生崩溃、裸 Java 线程未捕获异常、被系统按内存杀、ANR 都不过这些钩子。系统本来记着这些：Android 11+ 有 `ApplicationExitInfo`，Windows runner 已经在 `fushi/windows/runner/crash_dump.cpp` 的 `WriteDumpFilter` 写 minidump 但没有任何文字摘要进日志（dump 也不随反馈上传），macOS 有 `DiagnosticReports/*.ips`，iOS 有 MetricKit——但 app 一样都没读（`grep getHistoricalProcessExitReasons|DiagnosticReports|MXCrashDiagnostic` 在本仓为零）。另外 Android 9（API 28，WkL9BvD7Z9 的设备）没有 ApplicationExitInfo，也没有任何「上次是否正常退出」的标记。
- **[x] ① 已修复** — 新模块 `fushi/lib/src/diagnostics/previous_exit_log.dart`（`PreviousExitLog.foldIntoErrorLog`，`main.dart` 在 `ErrorLogService.init` 之后与其它取证折入并发跑），摘要按严重程度走 `log`（落盘）或 `logDiagnostic`，都在 `getFullLog` 里，随反馈日志上传（`feedback_diagnostics.dart:collectFeedbackLogText`）；所有摘要过 `redactExitReportPaths`（路径里的用户名换 `<user>`），只带有限长度摘要：
  - 全平台：会话标记 `session_marker.json`（启动写、生命周期变化 / 内存压力同步覆写、`exitApp` / 重启 / `detached` 标 clean）；上次没标 clean → `Process.previousExitUnclean`（最后的生命周期状态、内存压力次数；停在前台算严重，后台算诊断）。API < 30 的 Android 靠它。
  - Android：`ProcessExitChannel.java`（新通道 `app.fushi.reader/process_exit`）在后台线程读 `getHistoricalProcessExitReasons`（reason / status / description / importance / pss / rss / 时间 / 进程名，时间戳游标去重；CRASH_NATIVE 抽 tombstone 可打印串、ANR 取 main 线程段，各 ≤ 3000 字符），并进程级登记 `onTrimMemory` / `onLowMemory`（最近 8 次级别 + 时间 + pid，`commit()` 同步落盘）。
  - Windows：`crash_dump.cpp` 的 `WriteDumpFilter` 在写 minidump 后追加一行 `crashdumps\crash_summary.log`（异常码、模块+偏移、AV 读写地址、线程、x64 从异常上下文 `RtlVirtualUnwind` 前 10 帧、dump 文件名；静态缓冲零堆分配），下次启动读出清空。不上传 minidump。
  - macOS：扫 `~/Library/Logs/DiagnosticReports/<进程名>-*.ips`（app 已去沙盒），摘异常 / 信号 / 终止原因 / 崩溃线程前 12 帧，`previous_exit_state.json` 记已读到的修改时间。
  - iOS：`AppDelegate.swift` 的 `FushiCrashDiagnostics` 订阅 MetricKit，`MXCrashDiagnostic` JSON 落 `Documents/metrickit/`（单条 > 256 KB 只留元数据，目录最多 10 条），Dart 摘要元数据与归属线程调用链后删除。
  - 另加通用活动面包屑 `ActivityBreadcrumb`（同模块）：长活动开始同步写 `activity_<名>.breadcrumb`、结束删除，下次启动残留 → `Process.activityCrashRecovered`（复习同步一轮已接入，见 BUG-3832）。
- **[x] ② 已加自动化测试** — `fushi/test/diagnostics/previous_exit_log_test.dart`：路径脱敏；会话标记前台 / 后台 / clean / detached 四态；Android 退出原因分级、trace 摘要脱敏、trim 级别命名；经真实 `MethodChannel`（mock 消息处理器）取数；Windows 摘要读出并清空；macOS `.ips` 解析（异常、帧、只认本进程、二次启动不重复）；iOS MetricKit 解析并删除；折入后的摘要确实出现在 `collectFeedbackLogText()` 里。原生侧（Java / C++ / Swift）CI 不跑：C++ 已本机 `cl /W4 /WX /utf-8` 单独编译通过；`ProcessExitChannel.java` 已用 `javac` 对 android-36 `android.jar` + flutter embedding jar 单独编译通过（未跑 Gradle 全量构建）；Swift 未编译验证。
- **备注**：**未在真机验证**：Android 11+ 设备上制造一次 native crash / 低内存杀，确认下次启动日志里有 `Process.androidExitInfo`；Android 9 上确认 `Process.previousExitUnclean`；Windows 制造一次 AV 确认 `crash_summary.log` 与帧；macOS / iOS 同理。Swift 用到的 `MXCrashDiagnostic` 属性（`exceptionType` / `exceptionCode` / `signal` / `terminationReason` / `virtualMemoryRegionInfo`）按 iOS 14 SDK 文档书写，未在 Xcode 下编译。
