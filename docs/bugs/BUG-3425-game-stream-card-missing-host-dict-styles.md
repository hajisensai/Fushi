## BUG-3425 · game-stream-card-missing-host-dict-styles
- **报告**：2026-10-16（用户：反馈 ZRMBBl25qV，iPad 串流 PC 游戏制卡，卡片 Glossary / MainDefinition 无任何词典自带 `<style>`；PC 本机制卡正常）
- **真实性**：✅ 真 bug。串流页查词弹窗 `DictionaryPopupLayer` 没有注入 `resourceSource`（`fushi/lib/src/pages/implementations/game_stream_page.dart:1592`），WebView 于是走本机 `FushiDicts.dictionaryStyles`（iPad 没装词典 ⇒ 空表），渲染与 Glossary 导出（`assets/popup/popup.js` 的 `window.dictionaryStyles?.[dictName]`）都拿不到样式；串流查词客户端 `InterconnectGameStreamDictionaryLookup`（`fushi/lib/src/sync/game_stream_client.dart:397`）只转发 `searchDictionary`，从不取 host 样式。反馈人的排查**部分不准**：`FushiRemoteLookupClient` 并非「从不请求样式」——它有 `dictionaryStyles()`（`/api/lookup/dictionary/styles`），手机字幕遥控器在用，只是串流路径没接；`stylesRevision` 门控当时只在浏览器扩展走的 `FushiApiServer` 上生效，互联 host（`FushiSyncServer` 的 `/api/lookup/dictionary`，`packages/fushi_engine/lib/sync/fushi_sync_server/lookup.part.dart:38`）没接 `popupDictionaryCssProvider`。
- **[x] ① 已修复** — host：`/api/lookup/dictionary` 接上只含词典自带 CSS 的 `popupDictionaryCssProvider`（按 provider map 身份缓存快照），与扩展同一套 `stylesRevision` 门控，请求不带该字段的老客户端回包不变；client：`FushiRemoteLookupClient(trackDictionaryStyles: true)` 首查发空指纹、之后发缓存指纹，指纹不变沿用同一不可变实例；串流：`InterconnectGameStreamDictionaryLookup` 持有 `RemoteDictionaryPopupResources`（样式 / 媒体 / 发音都问 host），查词后采用 host 样式，老 host（回包无指纹）回落样式端点；`GameStreamPage` 把 `controller.popupResources` 作为 `resourceSource` 传给弹窗。
- **[x] ② 已加自动化测试** — `fushi/test/sync/game_stream_host_dictionary_styles_test.dart`（请求带 revision / 指纹不变不重下且同实例 / 新指纹替换 / 未开启时请求体不变 / 老 host 回落样式端点 / host 端门控契约）、`fushi/test/pages/game_stream_popup_resources_test.dart`（串流页弹窗拿到 host 资源源，删掉接线即红）。
- **备注**：未在 iPad 真机 + Windows host 上端到端复测制卡。`AppModel` 的 remote-first 查词（每次新建 `FushiRemoteLookupClient`）在瘦客户端本机弹窗渲染时同样用本机样式，不在本修复范围。
