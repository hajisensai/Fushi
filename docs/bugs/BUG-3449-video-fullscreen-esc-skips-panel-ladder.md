## BUG-3449 · video-fullscreen-esc-skips-panel-ladder
- **报告**：2026-10-15（用户：Windows 视频全屏时打开底部剧集列表，按 Esc 先退出了全屏，应该先关掉底部剧集列表；反馈 `_oQPV1HPqX`，重复 `2XRS7o4YJ8`）
- **真实性**：✅ 真 bug。全屏是推到根 navigator 的独立路由（`fushi/lib/src/pages/implementations/video_fushi/fullscreen.part.dart` `_pushNeutralizedVideoFullscreen`），逐级退出层级表（`_dismissTopForegroundLayer`，`video_fushi_page.dart`）只接在两处：页面键盘通道（焦点在本页子树里才收得到）与视频页的 `PopScope`（`video_fushi_page.dart` `build()`）。焦点不在本页子树里时（焦点导航开着时的 app 兜底节点等），Esc 冒泡到全局「返回上一级」→ `Navigator.maybePop`——栈顶是全屏路由，视频页的 `PopScope` 轮不到，全屏路由直接被 pop，media_kit 的 `_FullscreenInheritedWidgetPopScope` 随之退原生全屏，剧集轨 / 字幕列表 / 侧栏 / 查词浮层原样留着。手柄 B 兜底、鼠标侧键 app 根兜底、media_kit 自带的退全屏同样走 `maybePop`，同一个缺口。Windows 真窗 itest 复现：焦点在兜底节点、横轨开着按 Esc → `isFullscreen=false`（改前红）。焦点停在横轨卡片上时由页面键盘通道接住，改前就是对的（同 itest 实测）。
- **[x] ① 已修复** — 新增 `fushi/lib/src/media/video/video_fullscreen_back_scope.dart`（`VideoFullscreenBackScope`，`canPop: false`，拦下的返回先走 `_dismissTopForegroundLayer`，一层都没开才退全屏），挂进全屏路由（`fullscreen.part.dart` pageBuilder）；所有前台层（查词浮层 / 控制布局编辑 / 控件 popover / 字幕列表 / 剧集轨 / 侧栏 / 沉浸锁）共用同一份层序。显式退全屏（F 键 / 全屏按钮 / 外部导航收尾）改为直接 `Navigator.pop` 全屏路由（`_exitVideoFullscreen`），不被面板吃掉。vendored media_kit `fullscreen_inherited_widget.dart` 的 PopScope 改为只在 `didPop` 为真时退原生全屏（否则被否决的 pop 也会退掉原生全屏，见 `third_party/media_kit_video/PATCHES.md`）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_fullscreen_back_scope_test.dart`（真 Navigator + 真 PopScope：剧集轨开着第一次 maybePop 只关剧集轨、全屏路由保留，第二次才退全屏；六层同时开着按层级表逐层关；显式 pop 不经层级表；外加全屏路由接线与 media_kit `didPop` 补丁的源码守卫）；`fushi/integration_test/video_fullscreen_episode_list_open_test.dart` 加 Esc 段（Windows 真窗：焦点落在 app 兜底节点，第一次 Esc 关横轨且仍全屏，第二次 Esc 退全屏且仍在视频页；改前红、改后绿）。
- **备注**：Feedback `_oQPV1HPqX` / `2XRS7o4YJ8`。用户现场焦点为何落到页面子树外未能从日志确认（日志无焦点信息、截图未上传）；修复不依赖焦点落点，覆盖所有经 `maybePop` 到达的返回。
