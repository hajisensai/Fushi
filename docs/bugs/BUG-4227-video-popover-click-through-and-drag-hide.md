## BUG-4227 · 视频音量 / 倍速浮层点空白处下穿到进度条；拖浮层滑条时控制条照样自动隐藏
- **报告**：2026-11-07（用户：应用内反馈 vskVvFumuG，Windows 3.3.0-debug.24478）
- **真实性**：✅ 真 bug（两条都沿真实代码路径确认）。
  - ① 点浮层空白底下穿：浮层外框 `VideoControlPopoverFrame`（`fushi/lib/src/media/video/video_volume_overlays.dart`）在 Apple 设计系统下是 `VideoGlassHud` → `VideoGlassSurface`，玻璃底是 `IgnorePointer` 兄弟层（`fushi/lib/src/media/video/video_apple_chrome.dart:119`），内容 Row 的内边距 / 控件间缝都不命中；点按于是落到下面的 dismiss 层（`fushi/lib/src/pages/implementations/video_fushi/controls_popover.part.dart:410`，修前行号，`HitTestBehavior.translucent`，命中后继续往下）与 media_kit 进度条的原始 Listener → 点浮层空白处 = 关浮层 + 跳进度。MD3E 外框是 `DecoratedBox`，`RenderDecoratedBox.hitTestSelf` 按装饰命中，浮层内本就不下穿（测试在修前对 MD3E 即为绿，对 Apple 为红，见下）。
  - ② 拖滑条控制条照样隐藏：控制条的自动隐藏只靠 hover 续命——media_kit 桌面 fork 的 `MouseRegion.onHover`（`third_party/media_kit_video/lib/media_kit_video_controls/src/controls/material_desktop.dart:1034`）与浮层自己的 hover keep-alive（`controls_popover.part.dart:337`，修前行号）都只收 `PointerHoverEvent`；按住拖滑条发的是 `PointerMoveEvent`，没有任何东西重排隐藏计时 → 到点 `visible=false`，`_applyControlsVisibilityFromMediaKit`（`fushi/lib/src/pages/implementations/video_fushi/controls_visibility.part.dart:115`）随之关掉浮层。分诊所指 `volume_osd.part.dart:104`（`_setVolumeFromSlider` 不 poke）是同一现象的一处症状点，倍速滑条同样中招；修在「按住」这条输入通道上，两个滑条一起覆盖。
  - 分诊 ① 里「dismiss 层改 opaque」**未采纳**：dismiss 层铺满播放区，改 opaque 后 media_kit 控制条的 `MouseRegion` 立刻收到 `onExit`（`material_desktop.dart:1038`，非 hold 时直接 `visible=false`）→ 浮层被连带关掉；hover 打开的浮层还会挡住锚点按钮的 `MouseRegion` → 锚点 `onExit` → 180 ms 后关 → 锚点再 `onEnter` 重开，形成闪烁环。用户报的是「点浮层黑色背景」下穿，浮层外框吃命中即根治；浮层外点进度条 = 关浮层 + 跳进度保持现状。
- **[x] ① 已修复** — `VideoControlPopoverFrame.build` 外包 `Listener(behavior: HitTestBehavior.opaque)`，外框整块是命中面（两套设计系统同一声明，不依赖底色实现）；新增 `VideoControlPopoverPressHold`（同文件），浮层内有指针按着报 true、最后一个指针抬起 / 取消报 false，只旁听不进手势竞技。页面在 `_controlPopoverHoverKeepAlive` 两端都包上它，回调 `_setControlPopoverPressed` 写新来源 `_controlsHoldPopoverPress` 并经 `_syncControlsHold` 并进 `_controlsHeld`（fork `holdVisible`：按住期间指针离开与隐藏计时都不收控制条，松开后按 hover 重新倒计时）；`_hideControlPopover` 收尾放开按住（按住中被 Esc / 门控关掉时组件卸载收不到抬起）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_control_popover_hit_test.dart`：按真实层序（进度条原始 Listener → translucent dismiss 层 → 浮层外框）真实渲染 MD3E / Apple × 音量 / 倍速，点外框内边距断言进度条与 dismiss 都没收到；`VideoControlPopoverPressHold` 拖动全程只报一次 true、抬起报 false、不抢子树拖动手势，多指 / cancel 语义。`fushi/test/pages/video_popover_press_hold_guard_test.dart`：源码守卫钉页面三处接线（播放页 headless 跑不了）。红→绿：去掉外框 Listener + 回退页面接线后 `+10 -5`（Apple 音量 / 倍速两例 `seekBarDowns` 实际 1，守卫三例红；MD3E 两例修前即绿），恢复后 `+15` 全绿。
- **[x] ③ 复核补修（按住只护住了控制条，没护住浮层本身）** — 悬停打开的浮层是非固定的，收起只看锚点 / 浮层悬停；Flutter 在 `PointerMoveEvent` 时重做鼠标命中测试（`flutter/lib/src/rendering/binding.dart:466-471`），按住拖滑条拖出浮层边界照样触发浮层 `MouseRegion.onExit`（修前 `fushi/lib/src/pages/implementations/video_fushi/controls_popover.part.dart:364-367`）→ `_scheduleControlPopoverHide`（修前同文件 `:330`）180 ms 后 `_hideControlPopover` → 浮层与滑条在拖动中途卸载、按住一并被放开。修复：把固定 / 悬停 / 按住三条保持来源收进唯一收起判据 `VideoControlPopoverHoverDismiss`（`fushi/lib/src/media/video/video_control_popover_hover_dismiss.dart`），按住期间不排、不执行 hover 收起，按下撤掉排队中的收起，松手时若已不在锚点 / 浮层上按 hover 规则补一次延迟收起；页面的锚点 / 浮层 `onExit`、`_setControlPopoverPressed`、`_hideControlPopover` 都经它，删掉页面自建的只看悬停的计时器。测试：`fushi/test/media/video/video_control_popover_hover_dismiss_test.dart`（fake_async 状态机 8 例），`fushi/test/pages/video_popover_press_hold_guard_test.dart` 改钉页面全经判据。红→绿：判据去掉按住检查后 `+5 -3`（拖出浮层被收 / 松手不补收起 / 按下不撤排队收起），恢复后 `+8`。
