## BUG-3796 · windows-nav-switch-freeze-a11y-reparent
- **报告**：2026-10-26（用户：Windows 侧栏切换容易卡死、要重启；「很多人都有」；先悬停弹一次速览卡再切换能稳定触发）
- **真实性**：✅ 真 bug。全局悬浮球的语义标注没有自成节点（`fushi/lib/src/reader/reader_floating_ball.dart` `_buildBall` 的 `Semantics(button, label)` 缺 `container: true`），标注冒进 `main.dart` 根 builder Stack 上包住整个 Navigator 的祖先节点：语义树里凭空出现一个铺满整窗、标签「悬浮球」的节点，整个 app 挂在它下面；球随场景显隐 / 换状态时整棵 app 语义子树在两个父节点间搬家。Windows 引擎 `AccessibilityBridge`（`shell/platform/common/accessibility_bridge.cc`）处理不了这种搬家——`Unserialize` 报 `Node N is not marked for destruction, would be reparented to <球节点>` / `Nodes left pending by the update`，失败后引擎侧 AXTree 与框架永久分叉，后续更新一路在坏树上改，最终 `CreateRemoveReparentedNodesUpdate` 的 `child_ids.erase(end)`（:249，release 无 assert）越界 memcpy、或堆损坏后渲染线程释放图层时崩（`~DlTextImpeller` / `DisplayList::DisposeOps`），表现为卡死 / 闪退。semantics 只在有 UIA 客户端（输入法、划词工具等，Windows 上很常见）时开启，所以只有 Windows 中招、且很多人都有；侧栏切换 + 速览卡是语义树变动最剧烈的操作，最容易引爆。
  - 取证：用户装机 3.0.1-debug.21417 当天 6 次崩溃 dump 用同版引擎 pdb（`flutter-engine-3.47.6-hdr-output-2`，时间戳 `0x6add7801`）符号化，栈落在 `AccessibilityBridge::CommitUpdates` → `:249`；崩溃自 21002 版（10-24）开始，早于 10-25 Windows 切 Impeller，与 Impeller 无关。
  - 复现：调试版（旧代码）干净启动零操作即 215 条 `Failed to update ui::AXTree`，悬停「书架」弹出速览卡后切换，实例直接崩（`Lost connection to device`）。
- **[x] ① 已修复** — 球的 `Semantics` 加 `container: true`，标注只落在球自己（31.7×48）。验收（调试版、干净启动）：启动 0 条；速览卡 → 切换 5 轮共 30 步、全部 11 个 tab 逐个切、侧栏快速连点 30 次、悬浮球 / 侧栏展开收起各 2 轮，`Failed to update ui::AXTree` 全程 0 条，实例存活。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_floating_ball_semantics_test.dart`：按 `main.dart` 根 Stack + `Overlay.wrap` 的真实装配形状，钉住「球标签不得落在页面祖先上」（旧代码下失败）与「球显隐不改变页面节点的父节点」。
- **备注**：引擎侧「子树换父节点即失败、失败后不自愈」本身仍是 Flutter Windows 的缺陷，本修复只消除了 Fushi 这一处整棵 app 搬家的来源；以后在根 Stack / 全局浮层上加带标注的组件，同样必须 `container: true`。调试时顺带看到 `home_dashboard_widgets.dart:634` 的 Column 溢出 4.2px，与本 bug 无关。
