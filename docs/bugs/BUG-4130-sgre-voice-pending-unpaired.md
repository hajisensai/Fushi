## BUG-4130 · 命运石之门（SGRE）制卡音频一直「匹配中」，未配上的行仍显示 game_resource 与播放键
- **报告**：2026-11-06（应用内反馈 3drXfc4GFk，Windows 3.0.1-debug.21889，STEINS;GATE RE:BOOT）
- **真实性**：✅ 真 bug，两处根因（沿 origin/develop 4c4c7505a3 代码路径确认）：
  1. 配对契约：SGRE 精确文本通道只在打字机把整句显示完之后才发布（`native/galgame_hook/hook/adapters/sgre_lookup.inc` `CaptureSgreLookupDrawState` 的 `IsSgreScenarioLineFullyRevealed` 门），文本时间戳是写入时刻（`include/voice_hook_ipc.h` `WriteTextLaneEvent` 的 `GetTickCount64()`）；语音随页开播，资源名 `sgre-voicebody-*.xwma` 不带事件 ID（`hook/adapters/sgre_adapter.inc` `HandleSgreCompressedResource`）。宿主只能走无标记窗 `[T-330, T-130]`（`fushi/lib/src/mining/galgame_audio_source.dart` `pickPairedVoiceOggs`），打字越慢差得越远，补配路径（`_refreshPendingResourceMatches` / `_waitForPairedResourceAudio`）用的是同一时间戳同一窗口，永远配不上。
  2. UI：资源通道就绪但未配上时 `gal_hook_session_controller.dart` 给行写了 `backend='game_resource'`（无 resourceId）；`texthooker_page.dart` `_pickLineTrack` 只凭 backend 弹出带播放键的资源弹窗，「本句音轨」面板与选中句条优先显示 backend。另核实：资源模式（非 Loopback 音源）下 pending 没有任何收束出口——`_attachLineAudio` 只在 `!resourceReady` 时写 missing，`_refreshPendingResourceMatches` 只会升格成 matched，`_trimCache` 只是把待匹配项挤出 map，行状态永远停在 pending（无配音的旁白句同样如此）。
- **[x] ① 已修复** —
  - native（主修）：新增 `hook/adapters/sgre_voice_binding.h`（`SgreScenarioPageTracker` + `ResolveSgreVoicePage`，纯函数）。精确通道逐帧记录场景页（首字形时刻、发布后的 seq）；文本时间戳改为该页首字形出现时刻（`TextLaneWrite.timestamp_ms` 可选覆盖，不得晚于写入时刻）；语音在 HookWorker 上有界等待所属页（首字形不晚于语音 +500 ms、不早于语音 -1500 ms 的最新页）发布后以 `fushi_textseq<seq>` 命名，宿主走事件 ID 精确层。无归属 / 所属页未发布即被替换 / 无精确通道 / 60 s 截止一律写回无标记旧名；队列上限 8，满了把最旧的按无标记写出，不丢。Dart 时间窗未放宽。
  - Dart：待配对行不再写 backend，并清掉折叠进来的旧事件 resourceId；资源弹窗只给 `backend=game_resource` 且 matched / encoded 的行（`texthookerLineHasResourceAudio`）；面板与选中句条无音频时报状态（`texthookerLineAudioSummary`）；pending 收束：后续已有一句开始时刻超出本句配对容差（`kGalVoicePairingWindowMs`）时行状态收束成 missing（`game_resource_not_paired`），不撤出待匹配集合，资源晚落盘仍升格成 matched。
- **[x] ② 已加自动化测试** — `native/galgame_hook/tests/sgre_adapter_test.cpp`（`TestScenarioPageVoiceBinding`：页识别、首字形时刻、按页绑定 seq、带 seq 的资源文件名、等待 / 过期 / 无通道分支）；`native/galgame_hook/tests/adapter_structure_test.py`（`.inc` 调用点守卫：发布用首字形时刻、语音经绑定再落盘、HookWorker 推进）；`fushi/test/mining/galgame_sgre_voice_pairing_test.dart`（**特征测试**，不是回归测试：本 PR 没改 Dart 配对，修复前同样全绿；只锁宿主对带 textseq 的 SGRE xwma 的契约，「native 确实生成带 textseq 资源」只由上面两项 native 测试锁住）；`fushi/test/mining/gal_resource_pending_convergence_test.dart`（待配对不带 game_resource、越过容差收束 missing、晚到资源升格）；`fushi/test/pages/texthooker_page_test.dart`（pending 行面板显示 Matching、无 game_resource、无试听键；资源判定纯函数）。
- **备注**：真机复测未做（本轮无该游戏环境）。「语音与首字形同时开始」与 500 ms 提前量是按 2026-09-03 E2E（短句 エル・プサイ・コングルゥ 恰好落进 [T-330,T-130]）推断的，未实测；engine-support.yaml 仍是 `implemented_unverified`，需要原始路径下慢文字速度长句的实测记录。
- **审查追修（PR #2991）**：
  - native 所属页规则：候选取**最早**一页，并排除语音开播前已发布（整句已显示完）的页——下一句文字淡入晚于 500 ms 提前量时，语音不再被打成仍在屏上那句的 textseq（宿主事件 ID 层全取、不做时间校验，错配比时间窗更难察觉）；已绑过语音的页也就吃不进它发布之后才开播的语音。`SgreScenarioPage` 记录发布时刻。测试 `TestScenarioPageVoiceOwnership`（去掉该排除条件后断言失败，已变异实测）。
  - 队列满淘汰与 adapter `shutdown()` 改为 final pass 落盘（所属页已发布仍带 textseq，否则无标记名），不再 `clear()` 丢弃；`adapter_structure_test.py` 守卫。
  - 文本时间戳改为首字形后，宿主无标记窗 `[T-330, T-130]` 对 SGRE 实际不再命中：未绑定的资源虽保留无标记旧名，结局是 missing。已推演旧窗口能配上的情形（语音早于整句显示完 130~330 ms）都是「本页打字期间开播」，由绑定覆盖；唯一例外是语音晚于本页首字形 >1.5 s（宿主事件 ID 容差上限）。engine-support 如实写明，删去「按宿主原有无标记契约处理」的说法。
  - 制卡路径找不到原件且禁用兜底时不再写 `backend='game_resource'`；操作目录逐句音轨的「来自游戏资源直提」note 改用 `TexthookerLineEntry.hasResourceAudio`（matched / encoded 才算），与 UI 同一判据。
  - pending 收束作用于所有资源模式引擎（有意：资源模式下 pending 本来没有终态）；收束理由改为语义化常量 `kGalResourceNotPairedReason`，UI 给中性「无原件」标 + 悬停说明（可能无配音、也可能漏抓），不再落进红色「无音频」。TTS 仍把它当 unvoiced（与 PCM 模式 missing 一致）。
