## BUG-4389 · 互联鉴权豁免按编码路径且不看方法，与路由分发的路径形态不一致
- **报告**：2026-11-10（用户：互联 host 安全审查 H10）
- **真实性**：✅ 真 bug（结构缺陷；复核确认当前不可越权利用，按结构收敛修）。`packages/fushi_engine/lib/sync/fushi_sync_server/auth.part.dart:7-60`（94317ab6295）用编码形式的 `request.url.path` 判豁免、任意方法都放行；`fushi_sync_server.dart:962` 路由按 `Uri.decodeFull('/${request.url.path}')` 分发，两套路径形态、没有「路由 → 鉴权要求」单表，安全全靠各 handler 自补 `method != 'GET'`。修复前新测试实测：无鉴权 `POST /api/ping`、`PUT /api/library/videos/x/stream` 都进了 handler 得 405；`GET /api/library/videos/abc%2Fstream?token=<有效流 token>` 豁免没命中得 401，而路由解码后本会分发到 stream handler。
- **[x] ① 已修复**（`4cd3976776a`）— `fushi_sync_server.dart` 新增 `canonicalRequestPath`，`_handleRequest` 与鉴权中间件共用；`auth.part.dart` 豁免收成 `_kPublicRoutes`（规范化路径谓词 + 方法集 + `_PublicGate`）：配对三端点 POST、`/api/ping` GET、视频流 / HLS / 蓝光码流 GET、原盘会话 GET、查词音频文件 GET/HEAD、词典媒体 GET/HEAD（query 凭据门）；路径命中但方法不在表内照常走 Basic。非法 UTF-8 转义（`%FF`）解不出规范化路径，在鉴权前统一回 400（此前鉴权后 `Uri.decodeFull` 抛出成 500）。`disc_share_routes.dart` 的 `isDiscShareSessionPath` 改吃规范化路径；`video.part.dart` 的 `_extractBareVideoId` 显式拒以流子路径结尾的 id。
- **[x] ② 已加自动化测试** — `fushi/test/sync/fushi_sync_server_public_route_table_test.dart`（真 server：无鉴权 POST ping / PUT stream → 401、`abc%2Fstream` 凭流 token → 200、OPTIONS 不 401、无 token 流仍由 handler 拒、`%FF` 路径无论带不带 Basic 都 400）；同步改 `fushi_sync_server_{ping,pair,pair_v2,dictionary_media}_test.dart` 的错方法断言为「无鉴权 401、带 Basic 405」，`disc_share_manifest_test.dart` 两处调用加前导 `/`。
- **备注**：线上契约 H：豁免路径上的非豁免方法由 405 变 401，无 client 依赖。`interconnect_token_display_guard_test.dart` 的切片终点还指着步骤 1（BUG-4387）删掉的 `_peerTokens()`，一并改成 `_validatePeerAuth(` / `_credentialSnapshot()`。
