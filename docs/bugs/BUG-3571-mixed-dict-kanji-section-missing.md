## BUG-3571 · mixed-dict-kanji-section-missing
- **报告**：2026-10-19（用户：反馈「現代新国語辞典 第七版」同时带 term 与 kanji 条目，Fushi 没导入汉字条目，Hoshi Reader 有）
- **真实性**：✅ 真 bug（展示层），但不是导入丢数据。用正式版 `fushidicts_ffi.dll` 实测：导入得 terms 82620 / kanji 2136，`probe_dict_content` 掩码 3，`query_kanji` 查「愛/亜/水」均命中；混合词典打 `hasKanji` 后也正确进汉字桶，弹窗点词头汉字能出汉字卡。用户看到的缺口在词典管理：「汉字」分区只列 `type == kanji` 的词典（`fushi/lib/src/models/dictionary_repository.dart:98` `kanjiDictionaries`，`dictionary_dialog_page.dart` `_dictionariesForType`），混合词典只在「术语」里，汉字分区是空的、计数 0，看起来像没导入；汉字部分也没法单独开关 / 排序（只能跟着整本的 `hiddenLanguages`）。Hoshi Reader 把同一本词典同时放进 Term 与 Kanji 两个列表（`Core/DictionaryManager.swift` 按 counts 各拷一份）。
- **[x] ① 已修复** — 「汉字」分区 = 纯 kanji 词典 + 混合词典的汉字部分（`kanjiSectionDictionariesOf`，`packages/fushi_dictionary/lib/src/engine/dictionary.dart`）；汉字部分的开关 / 位置独立存 metadata `kanjiHidden` / `kanjiOrder`，不碰术语分区的 `hiddenLanguages` / `order`（共用 `order` 的话在汉字分区一拖动就改掉它在术语分区的位置）；引擎汉字桶按同一顺序与开关装载（`bucketDictPaths`）；重导 / 在线更新继承这两项（`kanjiPartSettingsOf`）；行副标题标注「术语词典内附的汉字」。
- **[x] ② 已加自动化测试** — `fushi/test/models/mixed_dict_kanji_section_test.dart`（分区成员与顺序、开关独立、汉字分区重排不改术语 order、写穿 DB、重导继承）；`fushi/test/models/bucket_dict_paths_test.dart`（两部分开关各自生效、汉字桶按分区顺序）。
- **备注**：行为变化——以前在「术语」里关掉混合词典会连带关掉汉字卡；现在两部分各管各的，要关汉字卡在「汉字」分区关。无头服务端已对齐（见下「审查补丁二」）。**既定行为**：混合词典的汉字部分在用户第一次在「汉字」分区重排（管理页拖动 / 上下移，或 CLI `kanji-order`）之前，位置取它在「术语」分区的 `order`（`kDictKanjiOrderKey` 缺省回退），所以那之前在「术语」分区重排会顺带改变它在汉字分区的相对位置；第一次在汉字分区重排时整个分区的位置一次性写下，此后两边互不影响。不在「打开」汉字分区时固化：那是一次没有用户意图的写库（还会触发引擎重载），而回退语义下固化前后的顺序本来相同。说明写在 `packages/fushi_dictionary/lib/src/engine/dictionary_buckets.dart` 的 `kDictKanjiOrderKey`。
- **审查补丁（PR #2374 审查）**：① 汉字部分的开关 / 位置存在 metadataJson，而 profile 切换只回写 order / hidden 等列、metadataJson 当安装事实不回写 → 这两项会变成全局、术语部分却按 profile 各管各的；改为 apply 时只把这两个键从快照合并进 live metadata（`fushi/lib/src/profile/profile_repository.dart` `_metadataWithProfileKanjiPartSettings`，`applyDictionaryMetaProfileColumns` 新增可选 `metadataJson`），测试 `fushi/test/profile/profile_repository_test.dart`「BUG-3571」。② 桌面 CLI `PUT /api/admin/dictionaries/:name` 的 position 对 kanji 词典仍按纯 kanji 列表数位置、写 `order`，与管理页「汉字」分区（含混合词典的 `kanjiOrder`）各排各的；改为按 `kanjiSectionDictionaries` 数位置、走 `updateKanjiSectionOrder`（`fushi/lib/src/platform/desktop/ctl/ctl_dictionary_routes.dart`）。③ 在「汉字」分区删除混合词典行会删掉整本（术语词条一起），确认框加说明并指向只关汉字部分的开关（i18n `dict_mixed_kanji_part_delete_note`）。
- **审查补丁二（PR #2374 第二轮）**：① 分桶规则搬进 `packages/fushi_dictionary/lib/src/engine/dictionary_buckets.dart`（纯 Dart，经 `fushi_dictionary_core.dart` 导出）：`bucketDictPaths` / `dictPathEntryOf` 及元数据判据 `hasEmbeddedKanjiIn` / `isKanjiPartHiddenIn` / `kanjiSectionOrderIn`，app（`app_model.dart`）与无头服务端（`packages/fushi_server/lib/src/dictionary_host.dart`，删掉自己那份 `bucketServerDictPaths`）共用；服务端因此按术语 `hiddenLanguages` / 汉字 `kanjiHidden` 分别装载、汉字桶按 `kanjiOrder` 排，测试 `packages/fushi_server/test/dictionary_host_test.dart`。② 「汉字」分区（行内按钮与详情页）不再给「折叠」控件——它改的是混合词典术语部分的折叠状态，汉字卡本身不折叠；`DictionaryManagerDetail.onCollapseChanged` 可空，测试 `fushi/test/pages/dictionary_manager_page_test.dart`「BUG-3571」。③ 桌面 CLI：`ctlDictionaryJson` 对混合词典输出 `kanjiEnabled` / `kanjiOrder`；`PUT /api/admin/dictionaries/:name` 新增 `kanjiEnabled` / `kanjiPosition`（`ctlCheckKanjiPartParams` 校验适用范围），客户端新增 `dict kanji-enable` / `kanji-disable` / `kanji-order`，测试 `fushi/test/platform/desktop/ctl/ctl_dictionary_routes_test.dart`、`packages/fushi_cli/test/commands/dictionary_commands_test.dart`。④ `dict_mixed_kanji_part_delete_note` 补 ja / zh-HK 译文。
