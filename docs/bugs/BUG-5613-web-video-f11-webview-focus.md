## BUG-5613 · 网页档播放页 WebView 持焦时 F11 无反应
- **报告**：2026-11-28（用户：在「浏览器视频用 Fushi 播放」打开的网页档播放页上按 F11，窗口没进全屏，反而从最大化掉成普通窗口、播放页退回浏览器页；只出现过一次。本条记其中能沿代码路径坐实、能复现的那一半）
- **真实性**：✅ 真 bug（离屏集成测试复现）。Windows 网页档（两档都是）里，网页一拿 OS 键盘焦点（点过站点页面；「制卡优先」档的 Chromium 焦点窗是主窗口树里的子窗口，见 fork `in_app_webview_manager.cpp` 的 BUG-3871 注释），按键只进 DOM，Flutter 收不到，只有页内键盘桥 token 表里的键会回传 Dart。表由 `fushi/lib/src/media/video/web_video_session.dart:208` `webVideoKeyBridgeScript` 生成，只收 `ShortcutScope.video` 全部动作 + `globalBack`；全屏键 F11 绑在 `globalToggleFullscreen`（global 作用域，`shortcut_defaults.dart:213`），不在表里。回传后的解析 `video_fushi/web_source.part.dart:1767` `_onWebKeyToken` 也只查 video → universal（`dictionary_popup_input_bridge.dart:195`），即使进了表也解析不到。而页面持焦时的 press-time 解析（`video_player_shortcuts.dart` `resolveVideoKeyboardShortcut` 末尾的 `_resolveGlobalToggleFullscreen`，BUG-2462）是认 F11 的：同一个键，焦点在 Flutter 时进全屏，焦点在网页时死键。实测（离屏 runner，YouTube，「制卡优先」档，静音）：Flutter 持焦 `sendKeyEvent(F11)` 两次，runner 进 / 出全屏、页面标志同步；往页面 `dispatchEvent` F11 keydown 两次，修前 runner 一直不在全屏、页面标志一直 false。
- **[x] ① 已修复** — 键盘桥与页面持焦时的解析同一范围：`webVideoKeyBridgeScript` 的动作集加 `globalToggleFullscreen`（用户改绑后随注册表变）；回传解析抽成 `resolveWebVideoKeyToken`（`web_source.part.dart`），video → universal 之后只认 global 里的全屏键，其余 global 动作照旧留给 app 根。桥本来就只转按下沿（`forwardRepeats: false`），与 `kVideoPressEdgeOnlyActions` 对全屏键的约束一致。执行体不变：`videoActionCallbacks` 的全屏 → `_toggleVideoFullscreen` → 网页档 `_toggleWebWindowFullscreen`。
- **[x] ② 已加自动化测试** — 单测 `fushi/test/media/video/video_web_backend_shortcut_keys_test.dart`：默认注册表下桥脚本含 `'F11'`、`resolveWebVideoKeyToken('F11')` = 全屏、`KeyF` 仍是视频全屏、`Escape` 仍是返回；改绑全屏键到 F10 后桥只带 F10。集成测试 `fushi/integration_test/web_video_f11_itest.dart`（`FUSHI_WEB_VIDEO_F11_ITEST=1`，联网）：Flutter 持焦按 F11 与往页面派发 F11 keydown 各进 / 出一次，每步断言播放页还在、站点地址没变、runner 全屏态与页面标志一致。
- **备注**：
  - 用户现象的另一半（「最大化掉成普通窗口」「播放页退回浏览器页」）没能坐实。沿代码查过的路径：F11 在 Flutter 持焦时只走 `_toggleVideoFullscreen` → `_toggleWebWindowFullscreen`（离屏实测进出各一步、地址不变、页面不退）；F11 不在任何会退页的分支里——退页只有 `_handleBackOrExit`（返回钮 / 返回键 / 键盘桥回传的 Esc）与 `_onWebNav` 的 `webVideoLeavesPlayer`（站点主框架离开观看页）→ `_exitWebToBrowser`；runner 里能把最大化窗口变成普通窗口的只有全屏退出路径（#4585 `Win32Window::SetFullscreen` 按进入前的 placement 还原）与系统的还原命令。离屏 runner 不能验最大化起步（停在 -32000 的 zoomed 窗口客户区为负、视图没有尺寸，BUG-5591 备注），所以「最大化 + 网页档 + F11」这一格只能前台复测：最大化窗口 → 浏览器打开 YouTube 观看页「用 Fushi 播放」→ 先在站点页面点一下（让 WebView 拿焦点）→ F11；修后应进全屏，再 F11 回到最大化。若再现「掉成普通窗口 + 退页」，立即读 runner 的 `fullscreenTrace`（#4585）与错误日志里的 `_exitWebToBrowser` / 导航记录。
  - WebView2 自身对 F11 的处理文档前后不一（「browser features」页说关浏览器快捷键时一并关掉，「与 Edge 的差异」页说 WebView2 里 F11 全屏恒关）；本仓 fork 没有接 `ContainsFullScreenElementChanged`。修后键盘桥对 F11 `preventDefault`，不论运行时版本都不会再落到 WebView2 的默认处理。离屏测试派发的是合成 keydown（不触发浏览器加速键），真实按键经 WebView2 的那一段没有离屏手段验。
