## BUG-3576 · 互联客户端复习同步第二轮起 PROPFIND 404（写入者目录名带 `#`）
- **报告**：2026-10-20（用户：iOS 互联客户端点复习「立即同步」提示「还没有配置同步服务」；BUG-3581 修掉提示后实测出真实失败）
- **真实性**：✅ 真 bug，不限 iOS。实测：iOS 模拟器（FushiProbe）真 app 连 Mac 上的真 `FushiSyncServer`，第一次 `syncNow` 成功、第二次 `errors=[SyncBackendError: PROPFIND failed: 404]`（栈 `WebDavOps.propfindChildren` ← `InterconnectSyncBackend.listChildren` ← `SrsAssetStoreDirectory.listFiles` ← `SrsSyncEngine.syncOnce`）；桌面 VM 用生产后端对同一 host 连跑两轮，第二轮同样 404。根因：写入者 id 是 `<deviceId>#<化身号>`（`packages/fushi_srs/lib/src/sync/memory_replica.dart`），第一轮写入者目录走 `ensureFolder`（`encodeComponent` 编码、缓存）正常；之后每轮新建的 `SrsAssetStoreDirectory` 只能经 PROPFIND 的 href 找到它——host `packages/fushi_engine/lib/sync/fushi_sync_server/webdav.part.dart` 用 `Uri.encodeFull` 生成 href（不编码 `#`），客户端 `fushi/lib/src/sync/webdav_ops.dart` `parsePropfindResponse` 又 `Uri.decodeFull` 后把 href 原样当 URL，`buildRequest` 的 `Uri.parse` 把 `#1/` 当片段截掉，PROPFIND 打到 `…=/` 返回 404（curl 对照：`…HuHs=/` 404、`…HuHs%3D%231/` 207）。修复前提示层把这个失败显示成「没配置」（BUG-3581）。
- **[x] ① 已修复** — 客户端 `WebDavOps.decodedDavHref`：href 解码后把 `%` / `#` / `?` 重新转义，其余字符（中文、空格）保持既有可读 id 形态；单边即可连旧 host（旧 host 吐裸 `#` 同样被转义）。host 端 href 改为逐段 `Uri.encodeComponent`（`_encodeDavHref`），不再输出非法 href。WebDAV 云盘后端共用同一解析，一并受益。
- **[x] ② 已加自动化测试** — `fushi/test/sync/interconnect_srs_writer_dir_href_test.dart`：`decodedDavHref` 单测；真 `FushiSyncServer` 的 PROPFIND href 把 `#` 编成 `%23`；真 host + 真 `InterconnectSyncBackend` + `SrsAssetStoreDirectory` 连跑三轮 `SrsSyncEngine.syncOnce` 均无错（修复前第二轮 404）。
- **备注**：iOS 模拟器实测探针（未入库）在 Mac `~/dev/hibiki-srssync`。
