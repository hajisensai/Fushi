## BUG-1422 · 快捷键录入在 IME 下把物理 Z 存成 Process
- **报告**：2026-08-02（用户：）
- **真实性**：✅ 真 bug。根因在 `hibiki/lib/src/pages/implementations/shortcut_settings/binding_edit_dialog.part.dart:367`：录入侧直接 `final LogicalKeyboardKey key = event.logicalKey;` 建 `InputBinding`，**没有**复用运行时早就有的 IME 物理键回退（`hibiki/lib/src/shortcuts/shortcut_registry.dart:338`，TODO-847）。Windows 微软 IME 激活时引擎把 KeyDownEvent 的 `logicalKey` 改写成 `LogicalKeyboardKey.process`，稳定的 `event.physicalKey == PhysicalKeyboardKey.keyZ` 被丢弃 → 录进去的是 `Process`（chip 上显示成看不懂的键，运行时 `resolveKeyboard` 也永远匹配不上：`process` 回退分支要求 `kb.physicalKey != null`，而 `InputBinding(key: process).physicalKey` 恒为 null）。捕获侧与运行时用了两套契约。
- **[x] ① 已修复** — 新增 `InputBinding.normalizeCapturedKey({logicalKey, physicalKey})`（`hibiki/lib/src/shortcuts/input_binding.dart`）：由既有真相源 `_logicalToPhysical` 生成反向索引 `_physicalToLogical`，**仅当 `logicalKey == process`** 时按物理键还原真实可录入键，判据与运行时回退逐字一致；正常逻辑键一律原样返回，非美式布局（AZERTY/QWERTZ）语义不被物理位覆盖；表外物理键（numpad/F13+/game*）保持 `process` 不猜。录入 `_onKeyEvent` 在判修饰键 / 查重 / 查冲突**之前**先走这层归一化。
- **[x] ② 已加自动化测试** — `hibiki/test/shortcuts/input_binding_test.dart` 新增 group `InputBinding.normalizeCapturedKey`：`process + physical KeyZ → KeyZ`、`process + physical Space → Space`、非美式布局下真实逻辑键不被物理位覆盖、未映射物理键仍留 `process`、反向表与正向表等大（锁 1:1 不变量），外加源码接线守卫（录入对话框必须同时传 `event.logicalKey` 与 `event.physicalKey`，且归一化发生在建 `InputBinding` 之前）。
- **不迁移历史脏数据**：IME 期间已经录进库的 `Process` 绑定仍是死绑定（`serialize()` 走 `'#${keyId}'` 兜底，运行时与 WebView 键盘桥都命不中）。本次只堵住新产生的源头，旧条目需用户在设置里删掉重录；没有可靠依据把一条 `Process` 反推成用户当初按的是哪个键，硬猜属于编数据。
- **备注**：物理回退仍只在 `process` 时启用；若某 IME 把键改写成别的非 `process` 逻辑键，需要先抓真机 KeyEvent 再扩判据，不能无条件按 US-QWERTY 物理位覆盖正常布局。归一化只作用于快捷键录入这一个 `Focus`（`_captureFocusNode`，仅 `_capturing` 时构建，且原本就 `KeyEventResult.handled` 吞掉全部按键），对文本输入框、WebView 键盘桥零影响。
