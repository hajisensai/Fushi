## BUG-2511 · Windows 上 Cloudflare 的 Partitioned cf_clearance 对 CookieManager.getCookies 不可见，站点验证页永远不关
- **报告**：2026-09-13（用户：截图——rawmiu.com「站点验证」页里网页已正常渲染出搜索结果（验证通过），但页面一直停着不「自动继续加载」）
- **真实性**：✅ 真 bug。证据链：① sidecar 日志 18:54:25 rawmiu 搜索请求被 `cf-mitigated: challenge` 拦（`CloudflareInterceptor` 判据严格，确实是挑战）；② jar `support/mihon/cookies.json` 里没有任何 rawmiu 条目 → 闸门基线陈旧集为空，WebView 里只要出现 `cf_clearance` 就该判过；③ 有头 Edge 干净 profile 开同一 URL 约 20 秒后 cookie 库里出现 `.rawmiu.com` / `.rawmiu.top` 的 `cf_clearance`（TTL 1 年，`top_frame_site_key` 非空 = **Partitioned/CHIPS cookie**）；④ 用 WebView2 SDK 1.0.2792 按 fork 同一机制复现（同一环境两个 CoreWebView2，隐藏的那个发 CDP）：`Network.getCookies({urls:["https://rawmiu.com/"]})` 从隐藏与可见 WebView **都回空**（只回未分区的 `_ga`），`Network.getAllCookies` / `Storage.getCookies` 带 `partitionKey` 把 `cf_clearance` 返回。根因 `packages/flutter_inappwebview_windows/windows/cookie_manager.cpp` 的 `getCookie` / `getCookies` 只走 `Network.getCookies`，分区 cookie 被 CDP 按 target 访问语义筛掉；`aidoku_cloudflare_challenge_page.dart` 的 `_check` 经它轮询，于是永远读不到已落库的放行 cookie。同一读侧也是登录页 `mihon_web_login_page.dart` 的 `_export` 路径，任何分区会话 cookie 同样漏。
- **[x] ① 已修复** — `cookie_manager.cpp`：读侧改走 `Storage.getCookies` 拿 browser context 全量（含分区），C++ 侧 `cookieMatchesUrl` 按 RFC 6265 做域（host-only / 域后缀）+ 路径前缀 + Secure→https 匹配；`getCookie` / `getCookies` 共用 `collectCookiesForUrl` + `cookieToEncodableMap`。分区键不参与匹配（调用方要的是「该站点名下有什么」）。
- **[x] ② 已加自动化测试** — `fushi/test/build/webview2_cookie_partitioned_read_guard_test.dart`（源码守卫：读侧禁 `Network.getCookies`、必经 `Storage.getCookies` + `collectCookiesForUrl`，含合成语料自校验）；`webview2_cookie_expires_units_guard_test.dart` 同步改成认共用的 `cookieToEncodableMap`。C++ 匹配逻辑与 WebView2 原生行为只能真机验：Windows 离屏 itest 探针（临时脚本，不入库）在真 app 的 `MangaWebViewEnvironment` 里开 rawmiu 走同一条 `CookieManager.getCookies(origin)` 轮询，结果见备注。
- **备注**：Cloudflare 的 `cf_clearance` 早已带 `Partitioned`，所以这条不是 rawmiu 一家的问题——Windows 上所有过盾站点验证页都从未真正自动关过；BUG-2477（环境不一致）修完后仍然读不到，就是这一层。fork 的 `setCookie` 写侧不带 `partitionKey`，写回的是未分区副本，对 okhttp sidecar 无影响。
