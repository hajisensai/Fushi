## BUG-1676 · 制卡词典插图撑出卡片跑到屏幕右外
- **报告**：2026-08-15（用户：「这个图片怎么跑到右边屏幕外了」+ Anki 卡片截图，Lapis 卡型、小学館例解学習国語 第十二版 的「挿絵」插图）
- **真实性**：✅ **真 bug（取真实卡片 HTML + Edge headless 量几何复现，两个独立根因）**。
  - **根因 A｜导出时凭空发明尺寸与宽高比**：`fushi/assets/popup/popup.js:1035`（`createDefinitionImage` 的解构 `width = 100, height = 100`）是「词典没声明尺寸」时的**像素**兜底值。BUG-1062 修「卡片图比 Yomitan 小」时，把导出路径一律改成 `imageContainer.style.width = \`${usedWidth}em\`` + `font-size:1em`（`:1138` / `applyImageStyles` `:654`），于是这个兜底的 100 被当成 em 写进卡片：卡片正文实测 20px → `100em = 2000px`，而卡片正文宽只有 775px。同时 `invAspectRatio = height / width = 1` 把 400×300 的插图按 1:1 摆，`object-fit:contain` 又在上下补出一圈空白。弹窗端不受影响，因为它在 `img.onload` 里用 `naturalWidth/naturalHeight` 覆盖了这两个值（`:1230` 附近）——导出端没有加载事件，凭空写死就必然错。
  - **根因 B｜导出丢了表格溢出护栏**：弹窗有 `fushi/assets/popup/popup.css:904` 的 `.gloss-sc-table-container{display:block;overflow-x:auto}`（上游 Yomitan 同款）兜住超宽表格；导出只产出裸 `<div class="gloss-sc-table-container">`（`popup.js:1988` 附近），Anki 卡片上没有那份 CSS。这本词典把插图包在 structured-content 的「挿絵」表格里，而 `table-layout:auto` 计算 td 首选宽度时**不理会百分比 max-width**（循环依赖，浏览器直接忽略），所以容器上唯一的护栏 `max-width:100%` 完全失效，整张表被撑到 2095px，再被 `.main-def{overflow:hidden}` 裁掉——用户看到的就是「图跑到右边、右半边和说明文字都没了」。
  - **量化复现**（Lapis 真实卡型 CSS + 该卡真实 HTML，Edge headless，视口 1890px、卡片正文 775px）：图不在表格里 → 775px（`max-width` 正常生效）；图在 `table-layout:auto` 表格里 → 图 2000px、表 2095px、右边缘 2655px；给表格加 `max-width:100%` → **无效**，仍 2095px。本机 collection 实查：41 张卡带 `width: 100em`，其中 4 张图在表格里（真被裁到看不见），37 张把 400px 的图拉满整个卡片宽度。
- **[x] ① 已修复** — 提交 `0fb86adcb8`。两条根因分别根治，不加事后 CSS 兜底：
  - A：`createDefinitionImage` 新增判据 `naturalSizedExport = exporting && !useEmUnits && !hasDimensions && !isSvg`（`popup.js:1069`）。命中时容器 `width:auto`、`data-has-aspect-ratio=false`、关掉 aspect-ratio sizer，导出的 `<img>` 不再写 `width`/`height` 属性、改为常规流内布局（`position:static;width:auto;height:auto;max-width:100%`，见 `applyImageStyles` 的 `naturalSized` 分支）。浏览器直接用图片真实自然尺寸和真实宽高比，`max-width:100%` 负责不超出卡片。**词典声明了尺寸的图完全不受影响**，仍走 BUG-1062 的 em 语义 + sizer + 绝对定位 `<img>`（那两条必须成对，单独把 `<img>` 留在绝对定位会让 auto 宽容器塌成 0×0，图整个消失）。弹窗路径一行未改——它有 `img.onload` 能测真实尺寸，两条路径拿到的信息量不同，分流是本质不是特例。
  - B：导出时给 `.gloss-sc-table-container` 内联 `display:block;max-width:100%;overflow-x:auto;`（对齐弹窗/上游 CSS）。表格保留自己的 `table-layout:auto` 列宽算法（不动活用表等既有排版），溢出改为容器内横向滚动。
  - 三份镜像（`fushi/assets/popup/`、`fushi/assets/browser_extension/vendor/`、`tools/browser-extension/vendor/`）同步，三份 popup.js 仍逐字节相同。
- **[x] ② 已加自动化测试** — `fushi/test/pages/popup_glossary_export_parity_test.js` 新增 BUG-1676 三组断言（Node 真执行 popup.js）：① 无声明尺寸导出 → 容器 `width:auto`、绝不出现 `100em`、`hasAspectRatio=false`、`<img>` 无 width/height 属性且 `position:static`+`max-width:100%`；② 有声明尺寸导出 → 仍 `10em` + `hasAspectRatio=true` + 绝对定位 `<img>`（BUG-1062 不回归）；③ 导出的表格容器内联 `overflow-x:auto`+`max-width:100%`，弹窗路径保持零内联样式。Dart driver `popup_glossary_export_parity_test.dart` 照常在 `flutter test` 里跑。
  **变异实测（三条各自打红，还原后 sha256 比对一致）**：去掉 `naturalSizedExport` 分支 → 红；去掉表格容器护栏 → 红（`must inline the overflow guard`）；把 `<img>` 改回绝对定位 → 红（`must be in flow and capped at the card width`）。
  **端到端几何验证**：用修改后代码真实生成的导出 HTML 进 Edge headless 量——修复前 图 2000px / 表 2095px / 右边缘 2655px（卡片 775px）；修复后 图 400×300（真实自然尺寸与宽高比）/ 表 495px / 右边缘 1055px，完全在卡内。护栏单测：无护栏时容器 `overflow-x:visible`、`canScroll=false`（2095px 内容被 `.main-def{overflow:hidden}` 永久裁掉，用户够不着）；有护栏时 `canScroll=true`，内容仍完整可达。
