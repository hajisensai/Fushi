## BUG-5070 · 双栈 / 多网卡下 DHT 节点数被后到的实例覆盖，误报「DHT 一直连不上任何节点」
- **报告**：2026-11-21（用户转来的第三方报告；Windows WLAN 仅 IPv4 + Teredo `2001:0:…` 全局 IPv6，`3.4.0-debug.30040`，libtorrent 2.0.11）。DHT 运行满 90 秒后下载页 / 详情网络区持续提示 DHT 不可达，实际 IPv4 DHT 正常。
- **真实性**：✅ 沿真实代码路径与 libtorrent 2.0.11 源码证实。宿主默认双栈监听 `0.0.0.0:p,[::]:p`，libtorrent 为每个非 local-network 监听端点各建一个 DHT 实例；`session_impl::post_dht_stats`（`src/session_impl.cpp:4857`）**每个实例各投一条** `dht_stats_alert`。桥的 `drain_alerts`（`native/fushi_torrent/fushi_torrent_ffi.cpp` 旧 456–462 行）逐条 `ctx->dht_nodes = nodes` 赋值，后处理的空实例（Teredo IPv6 建不起表）把 IPv4 的几十个节点盖成 0 → `diagnoseTorrentNetwork`（`packages/fushi_engine/lib/media/torrent/torrent_network_diagnosis.dart:38`）判 `dhtUnreachable`。
- **[x] ① 已修复（根因）** — 节点数改取 `session_stats_alert` 的 `dht.dht_nodes` 指标：`dht_tracker::update_stats_counters`（`src/kademlia/dht_tracker.cpp:234`）每次 `post_session_stats` 先清零再逐实例累加，天然是跨端点汇总，不必在桥里自建 endpoint→count 表（那样还得处理网卡变更时的陈旧端点）。去掉 `dht_stats_alert` 分支和 `post_dht_stats()` 调用；DHT 关着时指标停止更新，`ht_session_status` 报 0 而不是残留值（-1「未采样」语义不变）。
- **[x] ② 已增加自动化测试** — `packages/fushi_torrent/test/detail_info_test.dart`「sessionStatus.dhtNodes（BUG-5070）」：B 会话监听 `127.0.0.1:0,[::1]:0`（两个 DHT 实例），分别向只监听 IPv4 / 只监听 IPv6 回环的 A4 / A6 补 DHT 节点，断言汇总 ≥ 2。旧实现无论 alert 先后都只能报 1，确定性失败；全回环零外网。无 `::1` 的机器跳过。
- **验证**：本机 Windows 用 `build_windows_dll.ps1` 分别编出修复前 / 修复后的桥 DLL，`FUSHI_TORRENT_LIB` 指过去跑 `packages/fushi_torrent`：修复后 `detail_info_test.dart` + `ffi_smoke_test.dart` 11 个全过（exit 0），新用例连跑 5 次全绿，整包 `dart test` 40 过 1 跳（exit 0）；修复前新用例红（汇总只报 1）。另用独立 C++ 探针核对：双栈会话两个实例各 1 个节点时 `dht.dht_nodes` = 2。没在报告人的 Teredo 环境实机复测；Linux / macOS / Android 编译看 PR CI。
- **范围**：只修节点数统计。报告附注的「国内 DNS 污染 DHT 引导域名、DoH 绕行只在 fake-ip 下触发」属于范围扩大，已写进拍板台，不在本修复内。
