## BUG-4231 · 互联客户端视频续播用旧断点并写回 host（偏好内存缓存不知道同步写库）
- **报告**：2026-11-07（Linux Phase 4 互联测试，Docker 客户端 + Windows host；证据为实测日志与截图，未入库：客户端开播用了旧断点，随后把 host 的断点从 3000 改回 8700）
- **真实性**：✅ 真 bug，复现两次（host_long：host 50 s 被客户端 22 s 覆盖；host_clip：3000 ms 被 8700 ms 覆盖）。客户端看过一次 host 的视频后，host 端更新的断点在下次打开时被忽略：sweep 后客户端库里已是 host 的新断点（新时间戳），播放器却从客户端自己的旧断点续播，随后实时上报把旧位置写回 host。
  - 根因①：开播位置读 `PreferencesRepository` 的内存缓存（`fushi/lib/src/pages/implementations/video_fushi_page.dart:5121-5145` `_readPersistedRemotePositionForEpisode` / `...AtForEpisode` → `fushi/lib/src/models/preferences_repository.dart:454` `getPref` 读 `_prefCache`），而互联 sweep / 冲突弹窗落地只写库（`fushi/lib/src/sync/interconnect_playback_position_sync.dart:328-338` `_writeLocal` → `FushiDatabase.setPrefTyped`），本机作为 host 收到的对端 PUT 也只写库。缓存里留着本机上次自己写的旧断点。
  - 根因②：另一方是 host 清单快照（`widget.remoteInfo.positionMs`，`video_fushi_page.dart:5287` `_resolveRemoteInitialPositionMs`），清单有 60 s TTL 缓存且视频页常驻保活，可能是几分钟前的值（r4-13 显示「看到 0:40」时 host 已在 0:50）。两份旧数据做 LWW：本机旧断点 20 s @ t1 胜过清单旧值 40 s @ t0 < t1。
  - 为什么时间戳 LWW 没挡住回写：实时上报（`video_fushi_page.dart:5367` `reportLive`）上报的是播放器当前位置、戳为 now，严格新于 host 的戳，host 按设计接受。LWW 本身无误，错在它的输入：开播位置选错了。
- **[x] ① 已修复** — 本机断点改为以库为唯一真相源：新增 `readLocalRemoteVideoPosition`（`interconnect_playback_position_sync.dart`，sweep 的 `localPosition` 与播放页共用）；开播判定抽成 `resolveRemoteVideoResumeMs`（`fushi/lib/src/media/video/remote_video_resume.dart`）：本机库断点、清单快照、互联 host 此刻断点（`remoteVideoPosition`，与 sweep 同一读口；host 不可达时退回前两者）三者取较新。播放页 `_resolveRemoteInitialPositionMs` / 换集回退都改走库读，不再从偏好缓存读远端断点。提交见 git log（fix/interconnect-video-resume-stale）。
- **[x] ② 已加自动化测试** — `fushi/test/sync/interconnect_video_resume_stale_cache_test.dart`（真 `FushiSyncServer` + `LocalLibraryHostService` host、真互联后端、真 sweep、真 `PreferencesRepository`）：sweep 拉到新断点后离线打开仍从新断点续播（并钉住缓存仍是旧值、旧判定得 20 s）；没 sweep 时清单过期也从 host 新断点续播；从续播点上报后 host 只前进；源码守卫禁止播放页从 prefsRepo 读远端断点键。`test/pages/video_remote_resume_guard_test.dart` 读侧守卫随之更新。
- **备注**：未在设备上复测原始失败路径（Phase 4 Docker 客户端 + Windows host），下一轮 Phase 4 需补。未改的相关现象：① 同步完成提示只统计内容 / 资产传输，播放进度（书籍进度同理）拉取不计入，所以显示「已同步 · 无变化」；② 视频页远端卡「看到 X」显示的是清单快照，sweep 后不会刷新远端清单（60 s TTL + 页面保活）。两者只影响显示，不再影响续播位置；已分别登记并修复为 BUG-4235 / BUG-4236。其他从 prefsRepo 读 `video_remote_position_*` 的地方（`anime_source_detail_page.dart`、`ctl_online_routes.dart`、`home_video_page.dart` `_adoptCloudStreamPosition`）读的是在线源 / 云流播断点，不经互联 sweep，未改。
