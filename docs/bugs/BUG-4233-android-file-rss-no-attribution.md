## BUG-4233 · Android 文件映射常驻暴涨时没有按文件分项
- **报告**：2026-11-07（崩溃报告 `#hw7f_pogDW`：Xiaomi 23113RKC6C，Android 16，3.3.0）
- **真实性**：✅ 真 bug（取证端）。采样 `10:56:24 rss=2549MB anon=246MB file=2300MB malloc=72MB`（启动后 30 s，停在 `HomePage>HomeVideoPage`），之后 2.3 GB 文件页一直常驻；报告里只有 `file=` 一个总数，看不出是哪个文件被整段读进内存。
  - 根因：`fushi/lib/src/diagnostics/native_attribution_probe.dart` `maybeDumpNativeAttribution` 只在 **malloc** 越 800 / 1600 / 2400 MB 时读 `/proc/self/smaps` 按映射名记 Rss；文件页暴涨而 malloc 不高时永远不触发。另外 `describeSmapsRss` 把文件映射按**文件名**归组，词典 / 模型各自一个目录、文件名常相同，几本词典会并成一项。
- **[x] ① 已修复** — RssFile（`/proc/self/status`）首次越过 1024 / 2048 MB（`kFileRssDumpThresholdsMb`）也触发同一份 smaps dump（诊断日志 `NativeAttribution.dump`，前缀 `file≥…MB`）；malloc 档与文件档各记各的、每档一次、一次采样最多一份。文件映射改按「上级目录/文件名」归组。
- **[x] ② 已加自动化测试** — `fushi/test/diagnostics/native_attribution_probe_test.dart`：按那份报告的读数（malloc=72、file=2300）依次触发 `file≥1024MB`、`file≥2048MB`、不再重复，malloc 越档优先；`RssFile` 解析；smaps 里两本词典的同名 `blobs.bin` 分成两项。
- **备注**：
  - `#hw7f_pogDW` 本身：pid 22446 的死因是 `SwipeUpClean`（用户从最近任务划掉，pss 1.45 GB），**不是**内存杀；同一时刻另两个 pid（29905 / 30123，`CRASH status=0 pss=0`）是划掉后被拉起又立刻崩的进程，没有任何 Java 栈 / tombstone，无法定位。2.3 GB 文件页是谁，等带本修复的版本出 `file≥` dump。候选（**推测**）：fushidicts 的词典 mmap（`native/fushidicts/fushidicts_src/memory/memory.cpp` `map_opened`，`MAP_SHARED` 只读、无 prefault，被整段扫过才会全常驻）、srs.db 的 256 MB mmap（db=0MB 排除）、本地音频库。
  - 同批 `#87LQLgdJBM` / `#o3voUUPYKz`（同一台 ZTE A103ZT，前台 `LOW_MEMORY` 反复被杀，pss 1.0–2.0 GB）：涨的是 **malloc**（06:21:25 `anon=1507MB malloc=1485MB file=276MB`，停在 `MihonExtensionsPage`），不是文件页；同一份日志 06:15 有 `AsrPcmDecodeException … ffmpeg timed out after 632s decoding block 3`（有声书 m4b 在跑 ASR）。同窗口线程 CPU：`cpu=55.2s[flutter-worker-×23 32.9s R4; DartWorker×26 7.0s; … dec#:#:aac 2.6s; enc#:#:pcm_s#l 1.0s; dmx#:mov,mp#,m# 0.7s]`——FFmpeg 在把 AAC 解成 PCM（ASR 取音频），另有一个 24 线程的 `flutter-worker-` 池吃掉大半 CPU；这个线程名在本仓源码、pub 缓存、Flutter 引擎里都搜不到，归属**未确认**（推测是 ASR 推理库的线程池）。3.3.0 已带 malloc 越 800 MB 的 smaps dump，但这份报告里没有 `NativeAttribution.dump` 条目，原因未查明。ASR 算法与线程池在上游 `fushi-subtitles`，按仓库规则不在本仓改；下一步需要该 dump 或一份同机 `dumpsys meminfo`。
  - `#h11qSuzHvF`（OnePlus PLK110，24478，`CRASH status=0`，rss 567–617 MB、file 280–290 MB 平稳）：内存不高，无栈，不属于内存问题，无法定位。
