## BUG-5411 · youtube-chat-replay-probe-isolate-capture
- **报告**：2026-11-24（用户：应用内反馈 qlMCjeA5rr「YouTube 直播聊天回放不显示」：开了自动打开、控件栏加了「聊天」按钮，看 VTuber 直播存档时聊天和按钮都不出现；截图为 Android 手机）
- **真实性**：✅ 真 bug，而且与平台无关——功能上线以来生产环境从没探测成功过。在 Windows 本机用生产同一份代码对一条有聊天回放的直播存档（`4Zp5-6Ux2ok`，curl 实测 `isReplay: true`）跑 `fetchYoutubeChatReplayEntry` 返回 null；去掉 `catch (_)` 后看到真实异常 `Invalid argument(s): Illegal argument in isolate message: object is unsendable - _Future <- _streamFuture in _HttpClientConnection`。根因：`packages/fushi_engine/lib/media/video/youtube_live_chat_replay.dart` 旧 `fetchYoutubeChatReplayEntry` 在 IO 函数体里写 `Isolate.run(() => decodeYoutubeChatReplayEntry(body))`，同一函数里另一个闭包捕获了 `http`（YoutubeHttpClient），Dart VM 的闭包上下文链把它一起带进 isolate 消息；请求完成后连接池里还挂着未完成的 Future / socket，拷贝必抛，再被 `catch (_) { return null; }` 吞成「没有聊天回放」，于是按钮永远不出、自动打开永远不触发，日志里什么都没有。单测注入 `post` 时 `http` 为 null，所以一直是绿的。innertube `next` 请求本身没问题（同意页 / 地区 / 客户端上下文都不是原因：请求 200、0.4 MB、带 `liveChatRenderer`）。
- **[x] ① 已修复** — 引擎：解码统一走独立顶层函数 `_decodeOffMainIsolate(body, decode)`（作用域只有正文与顶层函数，杜绝把 HTTP client 拖进 isolate 消息），探测与取页共用；探测改成 `probeYoutubeChatReplay` 返回 sealed 结果 `Available / Absent / ProbeFailed`，失败经 `engineLog` 写诊断日志（`YoutubeChatReplay.probe`，带 videoId）；`next` 响应没有观看页数据（只回 `error` / `playabilityStatus`）判失败而不是「没有」；会话取页失败也写日志（`YoutubeChatReplay.page`）。App：探测失败时换上 `VideoLiveChatReplay.probeFailed` 占位——按钮照出、聊天栏显示失败与「重试」，重试重新探测（期间显示加载中）；确认没有聊天回放时才不出按钮。真网络复验：有聊天回放的存档 → Available，取页得 78 条消息；普通视频 → Absent。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/youtube_live_chat_replay_test.dart`（`probeYoutubeChatReplay` 组：transport 走与生产同一条 YoutubeHttpClient 链路且故意持有不可发送的 ReceivePort；Available / Absent / ProbeFailed 三分 + 诊断日志；fetcher 同链路；会话取页失败写日志；`decodeYoutubeChatReplayEntry` 对非观看页响应抛 FormatException）、`fushi/test/media/video/video_live_chat_panel_test.dart`（探测失败占位：显示失败、重试重新探测且期间加载中、不按播放位置取页）。
