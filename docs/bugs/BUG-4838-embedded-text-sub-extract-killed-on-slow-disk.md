## BUG-4838 · 视频文本内封字幕抽取按总时长强杀：慢盘上一直在读的 ffmpeg 被杀、再整轨重读一次，最后提示「图形或不支持的轨」
- **报告**：2026-11-17（应用内反馈 ZTDA2WQJj4，Windows 3.3.0-debug.27498：「视频内封的字幕切换很卡」「切换为内封日语字幕加载不出来」；约 0.9 GiB 本地 mkv、约 30 条 subrip 轨，开播 67 s 后 `extractEmbeddedSubtitlesViaFfmpeg ... ffmpeg timed out`，再过 67 s 第二次超时，随后 `[video-embedded-sub] parsed 0 cues from embedded track`；同样大小的另一集 33 s 抽出 262 条 cue）
- **真实性**：✅ 真 bug（沿代码路径确认 + 本机 ffmpeg 实测；行号为修前 `4c347287835`）。根因：
  - `packages/fushi_engine/lib/media/video/video_subtitle_source.dart:1423-1428` `_extractAllEmbeddedSubtitles` 一次抽全部文本轨（`desktop_audio_clipper.dart:1884` `buildFfmpegMultiSubtitleArgs`），给的是 `subtitleExtractTimeoutForBytes`（`video_subtitle_source.dart:1501`，60 s + 8 s/GB）的**总时长预算**，到点由 `ffmpeg_backend.dart` 强杀。这条命令必须顺序读完整个文件（实测 1.018 GB 的 mkv 读 1,018,436,731 字节、1 次 seek，输入侧 `-discard` / `-vn -an` 不减读盘量），耗时 = 体积 ÷ 读盘吞吐；预算隐含 ≥125 MB/s，慢盘 / 与 libmpv 播放抢 IO 时把一直在推进的进程杀掉，已读部分作废。图形字幕抽轨早在 BUG-3102 改成按进度判活（`ffmpeg_watched_run.dart`），文本轨路径没跟着改。
  - `video_subtitle_source.dart:534-545` `isTransientDefaultEmbeddedSubtitleLoad` 把 `emptyCues`（含抽取超时）当瞬态，`fushi/lib/src/media/video/video_player_controller.dart:4372` 的自动加载等就绪后再起一次完整读盘——日志里两次 67 s 超时就是这样来的。`embedded_reference_subtitle_sync.dart:165-172` `loadEmbeddedReferenceTracks` 对每条候选轨各调一次 `extractEmbeddedSubtitleTrackFile`，抽取失败时每条轨各读一遍整个容器。
  - 失败原因被丢：`video_subtitle_source.dart:1216-1226` 超时 / ffmpeg 失败 / 解析 0 条统统归成 `emptyCues`、`_loadEmbeddedCues` 一律 `extractionFailed`，用户看到「无法加载该字幕（可能是图形或不支持的字幕轨）」，日志写 `parsed 0 cues from embedded track`（`video_player_controller.dart:4398`）。
  - 复核补充：用 `-progress` 判活时，PATH 上的 gyan 2025-06 ffmpeg 的 `out_time_us` 被稀疏的字幕输出卡住（视频帧在推进、out_time 只在字幕包处跳）；随包的统一 FFmpeg n9.0.1 实测随读盘位置连续推进。随包二进制是生产路径，见备注风险项。
- **[x] ① 已修复** — 提交 `1eb6b83b03a`。
  - 抽取改用 BUG-3102 的观察式运行：`extractEmbeddedSubtitlesViaFfmpeg`（`desktop_audio_clipper.dart`）经 `FfmpegWatchedRunner.runWatched` 跑，判据 `kEmbeddedSubtitleExtractStallTimeout`（90 s 无进度才判卡死），这条路径不再有总时长预算（只给不支持观察式运行的测试替身留兜底）；参数加不落盘的 `-map 0:v:0? -map 0:s -c copy -f null -` 伴随输出让进度跟着读盘位置走。卡死 / 取消时删掉全部输出（含被强杀留下的半截文件）、不逐轨回退、不写负缓存。返回 `EmbeddedSubtitleExtractResult`（落盘的轨 + `EmbeddedSubtitleExtractFailure` 原因）。`subtitleExtractTimeoutForBytes` 仍有枚举（`probeEmbeddedSubtitleTracks`）与音频能量探测两个调用方，保留并改了注释。
  - 可取消：`video_subtitle_source.dart` 的在途抽取改成 `_EmbeddedExtractJob`（按缓存目录共享），带取消信号的等待方撤走时只撤自己；可取消的等待方全部撤走、且没有不可取消的等待方（互联 host 端点 / ASR 取证）时才强杀 ffmpeg；上一个被强杀的进程退出后才起新抽取。`prewarmEmbeddedSubtitleCache` / `loadSubtitleCueResult` / `loadCuesForSource` / `loadDefaultTextEmbeddedSubtitleCues(WithReadinessRetry)` 加 `cancel`。播放页按视频路径持有取消信号（`_embeddedSubtitleExtractCancels`），换视频源时撤掉除新当前集外的全部、退页全撤；控制器每次 `load` 轮换自己的信号，`dispose` / `_releaseMediaHandles` 撤销——与图形轨 `_cancelGraphicSubtitleOcr` / `_cancelGraphicTimingFetch` 同一机制。
  - 不再重跑：`emptyCues` 不再算瞬态；新增 `extractEmbeddedSubtitleTrackFiles`（整体抽一次再读缓存），`loadEmbeddedReferenceTracks` 改用它。
  - 原因传到 UI：`SubtitleCueLoadFailure` 加 `extractionStalled` / `extractionCancelled`（`subtitleCueFailureForExtract` 映射），`DefaultEmbeddedSubtitleLoadResult.cueFailure` 带出；新文案 `video_subtitle_extract_stalled`；手动切换与自动加载的提示都按原因分流（取消不提示）；`video_player_controller.dart` 的日志改为 `embedded track load failed: <原因>`。
