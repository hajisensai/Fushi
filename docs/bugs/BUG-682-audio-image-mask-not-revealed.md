## BUG-682 · 有声书音频跨过图片不去掉防剧透遮罩(未持久·懒图漏揭)
- **报告**：2026-07-09（用户：「音频遇到图片没暂停，也没把图片遮罩去掉」）。
- **真实性**：✅ 真 bug（沿真实代码路径静态追定，运行时待真机确认）。「图片遮罩」= 图片防剧透模糊（TODO-861④，`reader_content_styles.dart:273-280` 给 `img.block-img.blurred`/`svg.block-img.blurred` 盖 `filter:blur(24px)`）；有声书音频跟随读过某张图时本应自动揭开（TODO-1178，`__hoshiRevealBlurredBetween`）。**暂停判据本身健壮**（`__hoshiImageBetween` 查裸 `img,svg`，对懒图也命中，`onImageDetected`→`triggerImagePause` 会发；`audiobook_bridge.dart:49-64`、`webview.part.dart:1714-1717`）——所以「没暂停」多半是暂停发了但视口落在 0 尺寸懒图/仍模糊的图上，用户看不出效果。**真正失效在揭遮罩**（根因 `audiobook_bridge.dart:71-88` 旧实现）：① 区间内插图常是 `loading=lazy` 离屏图（`reader_pagination_scripts.dart:1610-1611`），cue 跨过它时它还没 load、还没被 `_hoshiClassifyBlockImg`→`_hoshiBlurImage` 加 `blurred` 类（`:1618-1619`/`:1520-1524`）→ 旧选择器 `img.blurred` 抓不到 → 随后图片暂停 reveal 把视口滚到它、它才 load 并被补加 `blurred` → 暂停停在一张仍然模糊的图上。② 就算当场揭掉也不持久：与点击/手柄揭开不同（对比 `webview.part.dart:744-755`、`reader_caret_scripts.dart:1009-1015` 均回传 `onImageRevealed`），旧音频揭开路径只 `classList.remove('blurred')` 不回传 → 章节 (重)载/布局切换重跑 `_sharedInitImages` 会无条件重加 `blurred`（TODO-1289 同款重遮罩）。
- **[x] ① 已修复** — 本次 TODO-1367 修复提交（分支 `todo1367-audio-image-pause`）——`audiobook_bridge.dart`：`__hoshiRevealBlurredBetween` 改为遍历区间全部 `img,svg`（跳过 gaiji），对每张登记稳定 reveal key 进本会话已揭开活集——新 `window.__hoshiMarkImageRevealed`（`reader_pagination_scripts.dart` 的 `_sharedInitImages` 暴露，写 `_hoshiRevealedKeys` → 令懒图日后 load 时 `_hoshiBlurImage` 命中 key 跳过遮罩）+ 有 `blurred` 类当场删除 + 回传 `onImageRevealed` 让 Dart 会话集持久（重载不再遮罩）；前置 `typeof window.__hoshiImageRevealKey!=='function'` 守卫使图片模糊关闭时早退 no-op，向后兼容零副作用。`__hoshiImagePauseAdvance` 命中懒图时在 reveal 前强制 `loading=eager`+`decode()`，让图片暂停真展示插图。**不改动 `__hoshiImageBetween` 暂停判据、绝不重引 IntersectionObserver**（BUG-007 铁律）。
