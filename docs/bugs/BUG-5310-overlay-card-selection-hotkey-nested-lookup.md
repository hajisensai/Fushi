## BUG-5310 · overlay-card-selection-hotkey-nested-lookup
- **报告**：2026-11-23（用户：yimkdesu，GitHub issue #4246，应用内反馈 XjVrPWOjL6）
- **真实性**：✅ 真 bug（读代码确认，Windows 3.3.0 每次必现）。应用外查词卡片里选中一段字再按全局查词热键，卡片消失后在鼠标处重新弹出原来那个词，嵌套查词不发生。根因：`fushi/lib/src/lookup/global_lookup_controller.dart` `triggerSelectionLookup` → `_onHotKeyRouted` 先铸新路由、`GlobalLookupChannel.hide(notify: false)` 收卡，再 `SelectionCapture.captureForegroundContext / captureForegroundSelection` 抓**前台程序**的选区；卡片窗口是 `WS_EX_NOACTIVATE`，且 `fushi/windows/runner/global_lookup_window.cpp` 的 `ActivationGuardProc` 否决激活，永远不是前台，所以抓到的是底下程序里原来选中的词。整条热键路径不看卡片 WebView 里的选区（应用内弹窗能用，是因为快捷键由页面自己读弹窗选区）。
- **[x] ① 已修复** — 触发归属改为「卡片有选区就归卡片」：`triggerSelectionLookup` 在铸新路由之前，若有在途 desktop 路由（卡片在场），带着卡片自己的路由问 native `lookupOverlaySelection`（新增，`GlobalLookupWindow::LookupOverlaySelection`，判据与 BUG-2651 卡片内 Ctrl+C 接管同源：`selection_present_ && IsShowing()`）。接手时 native 调 host 新增的 `lookupSelection()`：取最近一次有选区的卡片 realm，经该 realm 自己的桥发 `textSelected`（选区文本去注音 + 首段字框，换算与 selection.js `getSelectionRect` 一致），wrapFrameBridge 照常盖 `__frameId`、换窗口坐标，Dart 走与单击正文完全相同的嵌套查词链；同时清掉 selection.js 残留的单击扫词记录，避免高亮打到旧位置。不接手（没选区 / 卡片已收 / macOS、Linux 没有该方法）时照旧收卡抓前台；host 发现现场无选区时 `resetSelectionReport` 复位 native。卡片不在场时不多一次往返。
- **[x] ② 已加自动化测试** — `fushi/test/lookup/global_lookup_card_selection_hotkey_test.dart`（控制器层：卡片不在场不问；接手时只调 `lookupOverlaySelection`、带卡片路由、卡片路由不被作废；不接手 / `MissingPluginException` 回落铸新路由；native / host 接线源码守卫）；`fushi/test/lookup/global_lookup_host_test.mjs` BUG-5310 段（host 行为：最近选区 realm、与单击正文同一锚框换算与 `__frameId`、清残留扫词记录、无选区复位去重）。
- **备注**：WebView2 覆盖窗真渲染 headless 测不了，未真机复测；需在 Windows 上复测「浏览器选词 → 热键出卡 → 卡片里拖选 → 热键」出嵌套子卡。macOS / Linux 覆盖窗没有卡片选区上报，仍是旧行为。
