## BUG-3604 · 漫画查词弹窗在整句并集放不下时被压成 0 高挤出屏幕
- **报告**：2026-10-19（用户：群反馈 9VPd0p5d0V，Android OnePlus 363x792@3.5；「查词弹窗避开气泡框过头了，空间不够时甚至会出现在屏幕外面」）
- **真实性**：✅ 真 bug。漫画选区 payload 的 `rect` 是整句 OCR 分组所有块的并集（`fushi/lib/src/reader/reader_selection_scripts.dart:3062` `rect: mangaGroupRect || ...`），不是被点的字。资料表 / 大段旁白被分组并成一句时，并集几乎占满整屏，放大后更是上下都超出屏幕。`calcPopupPosition` 为「绝不覆盖选区」（BUG-098）把弹窗高度压到剩余空间：`fushi/lib/src/pages/implementations/dictionary_popup_layer.dart:102/105`（竖排 `:151/154` 压宽度）`room.clamp(0, ...)`——空间为负就压成 0 高，弹窗只剩一条贴在屏幕边上，用户看到的是只露出右上角拖拽把手（截图 s1）。未放大时（截图 s0）并集上方还剩一点空间，弹窗被推到离被点词很远的屏顶，即「避开过头」。
- **[x] ① 已修复** — 新增纯函数 `choosePopupAnchorRect`（`dictionary_popup_layer.dart`）：按并集避让后的弹窗低于最小可用尺寸（高 120 / 宽 200，且不超过用户最大尺寸与屏幕可用空间）即判避让失败，改锚到被点字形；放得下时仍按并集避让，既有气泡避让行为不变。JS payload 在有分组并集时额外带 `glyphRect`（被点字形），`ReaderSelectionData.glyphRect` 解析；`dispatchMangaSelection` 新增 `chooseAnchor` 钩子，漫画页经 `BaseSourcePageState.choosePopupAnchor`（按本页真实 maxWidth/maxHeight/padding/预留/底部固定参数）接线。
- **[x] ② 已加自动化测试** — `fushi/test/pages/manga_selection_dispatch_test.dart`（BUG-3604 组：反馈机型几何复现 0 高、横排 / 竖排退回字形后弹窗完整在屏且不盖字、放得下时保持并集、无 glyphRect 时不变）；`fushi/test/pages/dictionary_popup_layer_test.dart`（`choosePopupAnchorRect` 判据）；`fushi/test/media/manga/manga_overlay_html_test.dart`（payload 带 glyphRect 的源码契约）。
- **备注**：待真机复测（Android 漫画放大后点资料表文字）。「未放大时弹窗被推到屏顶离词很远」只要并集旁还放得下可用尺寸的弹窗就保持原行为（是否要限制避让距离 / 拆分资料表式的大分组，属产品取舍，未改）。
- **补充修复（2026-10-23）**：复核反馈截图 s0（未放大）：资料表并集上方只剩约 130 逻辑 px，弹窗被推到屏顶、只露顶栏和词头、离被点的词半屏远——这正是标题里的「避开过头」主诉，并非产品取舍。根因是避让失败判据过松：`choosePopupAnchorRect` 的最小可用尺寸（高 120 / 宽 200）低于弹窗系统自己的下限 `kLookupPopupMinHeight`=200 / `kLookupPopupMinWidth`=250（`fushi/lib/src/lookup/effective_lookup_size.dart`，内容自适应收高、拖拽把手、设置滑杆都不会低于它）。默认阈值改为这两个常量，宿主 `BaseSourcePageState.choosePopupAnchor` 再乘界面大小；s0 的 130 高判避让失败、锚到被点字形。测试：`fushi/test/pages/dictionary_popup_layer_test.dart`「9VPd0p5d0V: room below the popup minimum height」。避让后弹窗 ≥ 最小尺寸但离词较远的情形仍按并集避让（不压住正在读的句子），是否再限制避让距离属产品取舍。
