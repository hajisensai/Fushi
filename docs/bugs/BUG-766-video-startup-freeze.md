## BUG-766 · 快速进出视频后 Windows 启动冻死在 loading
- **报告**：2026-07-13（用户：）
- **真实性**：✅ 真 bug。现场诊断（Windows 桌面、用户实机）：进程活、Win32 `responding=True`、yomitan（同 UI isolate 的 shelf server，`hibiki/lib/src/sync/yomitan_api_server.dart:92`）仍响应 ⟹ UI isolate 事件循环是活的；主窗口卡在 `hibiki/lib/main.dart:1255` 裸 loading 分支（背景 `Color(0xFF1F4959)`，截图坐实纯色空白），转圈帧时序上排在 DB 打开之前却从未 present，20s 看门狗（`hibiki/lib/main.dart:972`）逃生 UI 也从未出现 ⟹ 卡的是 **Flutter 引擎 raster / GPU present 管线**，非 Dart isolate。触发：快速进出视频 → libmpv/ANGLE/WGC churn（首开在途 controller 无法取消 `video_hibiki_page.dart:2342-2456`；退出 fire-and-forget dispose `video_player_controller.dart:2870`）污染进程共享 D3D device/swapchain → 首帧 present 楔死。
- **[x] ① 已修复** — 三层落地：①首开在途 controller 主动取消（减 GPU churn）`223911b9d`；③DB probe `busy_timeout` 前置于 WAL 切换（减脏 sidecar 同步阻塞）`6521118e5`；④present-watchdog 首帧未 raster 落盘取证 + 一次性自动重启（marker 防循环）`a03e30579`。②「退出可 await 干净释放」**评估后撤销**——`positionMs` 依赖 `_player`，提前 release 会破坏退出位置保存（Never break userspace）。引擎级 D3D device 隔离 **deferred**（Windows native/Flutter embedder，非 app Dart，需真机取证坐实 device-lost）。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_startup_freeze_guard_test.dart`（首开取消源码守卫，4 例）/ `hibiki/test/database/db_open_pragma_order_test.dart`（pragma 顺序）/ `hibiki/test/startup/present_watchdog_test.dart`（触发只一次/首帧已出不误触发/disarm/marker 防循环，10 例）。
- **备注**：Windows-only；present 楔死取证会随日志上传，真机复现后据 `present_stall.log` 坐实 device-lost 再另起 native spike 做引擎级 D3D 隔离。用户已手动重启恢复。
