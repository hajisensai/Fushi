## BUG-3819 · macOS 复习每次翻面 / 换卡都重建卡面 WebView（installLookup 打进死通道、卡顿）
- **报告**：2026-10-27（用户：应用内反馈 O1yqRPUyut「复习的时候卡住」，macOS 3.0.1-debug.21088）
- **真实性**：✅ 真 bug（日志 + 代码路径确认，非设备复现）。
  - 日志 6593 行里 610 条 `SrsWebCardFace.installLookup: MissingPluginException(... evaluateJavascript on channel com.pichillilorenzo/flutter_inappwebview_<n>)`，`<n>` 每条严格 +2、间隔 3–60 s（复习节奏，不是定时器）：每张卡新建两个平台视图、其中一次注入打进已销毁的通道。分诊稿「每 3 秒重建」不准确，是每张卡两次。
  - 根因 `fushi/lib/src/pages/implementations/srs/srs_card_face.dart:2102`（修前）：`if (_lookup == null || !hostOwnsWebViewHoverLookup) return webView; return Listener(onPointerHover: ..., child: webView);`——macOS 上（`hostOwnsWebViewHoverLookup` = macOS）卡面根 widget 的类型随查词作用域在「裸 KeyedSubtree」与「Listener」间切换。原生 Fushi 卡面的释义 WebView 正面在 Offstage 预热（`srs_fushi_card_view.dart` `_frontWithWarmDefs`，`SrsCardLookupScope(controller: null)`），翻面后进入有作用域的位置：GlobalKey 换父保住了 State，但 State 自己 build 出的根类型变了，element 整棵重建、`AppKitView` 平台视图销毁重建——翻面一次、换卡回正面一次。
  - 报错链：作用域变化 → `didChangeDependencies` 拿旧 controller 调 `_installLookup`（`:1689`）→ 同一帧 build 销毁旧视图 → 第二个 evaluate（`:1699` 门控脚本）打进已注销的通道。每次重建都要冷起 WKWebView + 重载外壳 + 重放卡面，即「复习卡住」。
- **[x] ① 已修复** — `srs_card_face.dart` `build`：平台视图上方结构恒定，始终包一层 `Listener`，只按平台决定 `onPointerHover` 接不接（`_onHostHover` 无作用域时本就 no-op）。`_installLookup` 在两次注入之间核对 controller 仍是当前这只（死亡重建 / 卸载时让新视图的 onLoadStop 重装）。诊断：卡面平台视图第二次及以后被创建时记 `SrsWebCardFace.lifecycle`（卡 id、有无作用域、存活卡面数、death epoch）；`WebViewDeathGuard` 的死亡 / 重建报告改进诊断日志（原先只 debugPrint，release 看不到）。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_web_card_face_platform_view_reuse_test.dart`：计数假 `InAppWebViewPlatform`，作用域 null → 非 null → null → 非 null（正面预热 / 翻面 / 下一张 / 翻面），断言平台视图只建 1 次。变异：退回「无作用域不包 Listener」→ 红（平台视图建了 4 次，期望 1），还原后绿。
- **备注**：未在 macOS 真机复测。截图那张卡是整面 WebView 模板（不走这条路），但日志里有 `SrsFushiCard.parseInline`，同一牌组里有原生 Fushi 卡片；整面 WebView 卡面不随卡切换作用域，不受影响。Windows / Android / iOS 修前结构恒定（`hostOwnsWebViewHoverLookup` 为 false 时恒返回裸 WebView），不受影响；修后多一层无回调的 `Listener`（`deferToChild`，不改命中）。
