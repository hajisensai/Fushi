## BUG-540 · 更新下载 404: rolling tag prune 竞态
- **报告**：2026-07-04（用户：）· 关联 TODO-1123（错误 A）
- **真实性**：✅ 真 bug。根因 `.github/workflows/release.yml` 旧「Prune stale assets from rolling debug release」步骤 + `hibiki/lib/src/utils/misc/update_checker_release.dart:305`（`asset.url` 于 check 阶段解析）与 `:834`（download 阶段直接信任旧 URL，无重取）。
- **根因**：debug 通道走镜像 manifest `latest-debug.json`（`update_checker_release.dart` `kDebugManifestUrl`）。app 在「检查」阶段解析出 `asset.url` 后，「真正下载」时**不再重取 manifest**、直接信任旧 URL（`_runDownloadAndInstall`）。CI `release.yml` 的 prune 步骤每次 push 都在 `debug-rolling` 这**一个滚动 tag** 上删掉所有**非当前 seq** 的 asset（旧逻辑 `KEEP_TOKEN` 单 token，只留当前 seq）。用户设备持旧 manifest（旧 seq，如 6421）去下载时，CI 已滚到新 seq 把旧 APK prune 掉 → 下载 URL 返回 **404**。即 rolling tag 覆盖式 prune 竞态；下载引擎对 404 抛 `HttpException('download failed (404): <url>')`，全候选 404 后冒泡为「下载失败」。
- **[x] ① 已修复** — 两处根因修复（commit 见文末）：
  1. **客户端治本兜底**（`hibiki/lib/src/utils/misc/update_checker_release.dart`）：`_runDownloadAndInstall` 把下载抽成 `downloadAsset(UpdateAsset)` 闭包，外包一层 `downloadAssetWithStaleRetry`（`@visibleForTesting`）：下载抛错经纯函数 `isStaleAssetDownloadFailure`（`update_checker_net.dart`，识别 `HttpException` 消息里的 `(404)`）判为「manifest 过期」时，调 `_reResolveDownloadAsset` **重取一次 manifest**（`_fetchReleasesForChannel` + `selectUpdateReleaseForCurrentPlatform`，通道由 `channelForUpdateVersion(version)` 推断）拿到新 `asset.url`，与旧不同则**用新 URL 单次重试**；非 404 / 重取拿不到新 URL / URL 未变 → 冒泡原错误。只重试一次，无限循环被结构性排除。
  2. **CI 缩窗加固**（`.github/workflows/release.yml` 「Prune stale assets from rolling debug release」步骤）：把只留当前 seq 的 `KEEP_TOKEN` 单 token 过滤，改为**保留最近 `KEEP_SEQS=3` 个 seq**（当前 + 前两版）。按 asset 名 `…-debug.<seq>-…` 解析 seq（`seq_of` sed），数字降序取前 3 个 seq 作保留集，只 delete-asset 不在集合里的（无 seq 的 legacy 名也当 stale）。给在途下载跨几次 push 的宽限窗口。发布通道、签名、secret 引用（KEYSTORE_BASE64 等）均未动。
- **[x] ② 已加自动化测试** — `hibiki/test/utils/misc/update_checker_404_reresolve_test.dart`（8 用例，全绿）：
  - `isStaleAssetDownloadFailure`：`HttpException(404)` → true；403 / `SocketException` / 取消异常 → false。
  - `downloadAssetWithStaleRetry`：① 旧 URL 404 → 重取 manifest 拿新 URL → 新 URL 成功，断言只重取一次、只重试一次（`[oldUrl, newUrl]`）；② 重取后新 URL 仍 404 → 冒泡原始 `HttpException`；③ 重取返回同 URL → 不重试、冒泡；④ 重取返回 null → 不重试、冒泡；⑤ 非 404（`SocketException`）→ 不重取直接冒泡；⑥ 无 404 直达成功 → 不重取。
- **备注**：CI prune 的 bash `seq_of` + 保留集逻辑已离线功能验证（keep 6425/6424/6423、prune 6421 + legacy）。release.yml YAML 校验通过、`bash -n` 语法通过。release.yml 改动待 integration owner 复核后随分支合并。
