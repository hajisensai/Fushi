## BUG-846 · 远端封面无磁盘缓存每次冷启动重下
- **报告**：2026-07-16（用户：）
- **真实性**：✅ 真 bug。远端封面走自定义 `RemoteCoverImage`（`hibiki/lib/src/sync/remote_cover_image.dart:39-50`），只依赖 Flutter 进程内 `ImageCache`（纯内存），完全没有磁盘/持久化缓存。冷启动即把所有远端封面全部重新网络拉取；滚动被 LRU 淘汰、低内存模式进后台 `imageCache.clear()` 也重下。本地封面走 `Image.file` 读盘故跨重启存活，远端封面只活在 RAM。仓库里 vendored 的 `network_to_file_image`（自带读盘缓存）并没用在封面上。
- **[x] ① 已修复** — 新增 `RemoteCoverCache`（`hibiki/lib/src/sync/remote_cover_cache.dart`）读盘缓存：`<temp>/remote_cover_cache/` 下按**稳定 id**（`video.id` / 书 `title`，非易变 `coverUrl`——换 IP / http↔https 会让 URL 变但封面不变）键控（base64url 文件名，避非法字符）。`RemoteCoverImage` 加 `cacheKey` 参数，`_loadAsync` 改「读盘 read-through」：命中直接读盘解码不发网络，未命中才走钉扎 `fetcher` 拉网并落盘；`cacheKey` 也作内存 `ImageCache` 去重键。字节仍必须经 `fetcher`（钉扎），不能用 `NetworkToFileImage`（其内部 `HttpClient` 无 `badCertificateCallback`，BUG-569 当初弃它的原因）。调用点 `home_video_page.dart:_buildRemoteVideoCover`（`cacheKey: video.id`）、`reader_history/remote.part.dart:_buildRemoteBookCover`（`cacheKey: book.title`）。提交 `0a4270e94`。
- **[x] ② 已加自动化测试** — `hibiki/test/sync/remote_cover_cache_test.dart`：未命中返回 null、write→read 命中（读盘 read-through）、空字节不落盘、含 URL/中文非法字符 id 可读写、`fileNameFor` 稳定且不碰撞。提交 `0a4270e94`。
- **备注**：缓存目录用系统临时目录（可丢弃、重下即可），不进数据根迁移白名单；封面更新极少，故不做 mtime 失效（可接受轻微陈旧）。「纯流播/无本地行的远端占位视频」封面本就走占位图，不在本修复范围。
