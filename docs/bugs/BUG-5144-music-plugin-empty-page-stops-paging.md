## BUG-5144 · music-plugin-empty-page-stops-paging
- **报告**：2026-11-22（外部审计 HBK-AUDIT-026，Codex 2026-11-21 PR 审查，PR #4034）
- **真实性**：✅ 真 bug。`packages/fushi_music/lib/src/plugin/plugin_source.dart` 的 `browseList` / `browseCatalog` 把续页状态写成 `r['hasMore'] == true && items.isNotEmpty`（PR #4034 head b721a7b2f0 的 :532 / :579）：插件自己过滤成空页、或宿主丢掉解析不了的条目后的一页，hasMore 被宿主强行置 false，后面的页再也取不到。即使源层保留 hasMore，`music_plugin_browse_pages.dart` 的两个列表页也只在滚动通知里续页：首页为空时只显示「没有结果」占位（没有可滚动的列表），中间夹一页空页时列表不变、不再触发续载，同样卡死。复现：`packages/fushi_music/test/plugin_browse_test.dart` 的 HBK-AUDIT-026 用例（插件第 0 页只有缺 id 的条目、`hasMore: true`），撤掉修复后 `p0.hasMore` 为 false。
- **[x] ① 已修复** — 新增宿主侧分页状态 `MusicPluginPager`（`packages/fushi_music/lib/src/plugin/plugin_pager.dart`）：续页只认插件 hasMore；一页没带来新条目时 `stalled`，自动续载暂停、改由用户点「加载更多」（`resume()`）继续，插件一直回空页也不会无限请求；非空页条目序列与之前某页完全相同（插件忽略页号）则判停；条目按身份跨页去重。源层两处去掉 `&& isNotEmpty`；作品列表页与分类目录页改用 pager（`music_plugin_browse_pages.dart` 的 `_loadMore` / `_maybeLoadMore` / `_browseFooter` / `_browseEmpty`），空状态与列表底部在 stalled 时给「加载更多」（i18n `music_plugin_browse_load_more`）。
- **[x] ② 已加自动化测试** — `packages/fushi_music/test/plugin_browse_test.dart`（源层保留 hasMore + pager 四个单元用例）、`fushi/test/pages/music_plugin_browse_test.dart`（首页空页 / 中间空页两个真页面用例：给「加载更多」、点了取到后续页、空页后不自动续）。
- **备注**：同类存量（develop 上已有、不在 PR #4034 范围）：`music_plugin_detail_pages.dart` 艺人专辑 / MV 页签、`music_plugin_pages.dart` 插件搜索页、`music_unified_search.dart` 统一搜索里的插件分页仍写 `page.hasMore && page.items.isNotEmpty`，插件 search / artistAlbums 的宿主解析同样会丢坏条目、产生空页。待后续改用 `MusicPluginPager` 统一（各自需要接「加载更多」入口）。
