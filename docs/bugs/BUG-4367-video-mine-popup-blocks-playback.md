## BUG-4367 · 视频查词弹窗点制卡后弹窗不关、视频停着等制卡完成
- **报告**：2026-11-07（开发者自提反馈 OeS0m8tLHc，Android 3.3.0-debug.24478：「正在制卡不要暂停我播放，点完制卡关了弹窗就继续播放了」）。修复随 PR #3140 合入 develop（`6b42923cbd`），本条为事后补记。
- **真实性**：✅ 真问题（视频车道与「查词暂停、制卡即续播」的使用预期冲突；分类原为 decision，用户在 PR #3140 拍板按 bug 收口）。修复前（`6b42923cbd^1`）沿真实代码路径：
  1. 视频页查词弹窗的制卡回调经 `DictionaryPageMixin` 包 `closePopupAfterAcceptedMine`（`fushi/lib/src/pages/implementations/dictionary_page_mixin.dart:1392`，定义 `fushi/lib/src/pages/implementations/dictionary_popup_webview.dart:290`），是否关弹窗只看阅读器偏好 `close_popup_after_mining`，默认关（`fushi/lib/src/media/sources/reader_fushi_source.dart:1693`）；开了也要等 `mine(fields)` 返回 accepted 才关（BUG-2627 为阅读器故意等结果）。弹窗不关 → `_pausedForLookup` 不清（`fushi/lib/src/pages/implementations/video_fushi_page.dart:3153`），视频一直停着。
  2. 视频制卡 `_mineVideoCard`（`fushi/lib/src/pages/implementations/video_fushi/lookup_mining.part.dart:616`）对本地视频 `resolveVideoOnlineMiningMode` 返回 `wait`（`fushi/lib/src/mining/video_online_mining_mode.dart:48`、`:50`），`lookup_mining.part.dart:1058` `return land(await job)`：accepted 要等 ffmpeg 抽媒体 + Anki 落地才回，即使开了「制卡后关闭弹窗」也会停一段时间。
- **[x] ① 已修复** — `6b42923cbd`（PR #3140）：`DictionaryPageMixin` 增加可覆写 getter `closePopupAfterMining`（默认读阅读器偏好），视频页覆写为恒 `true`（`video_fushi_page.dart` `closePopupAfterMining => true`）；`resolveVideoOnlineMiningMode` 改为 `resolveVideoMineDispatch`（`video_online_mining_mode.dart:53`），弹窗制卡本地视频也走后台立即回 `MinePopupResult.queued()`，弹窗随即关闭、按 `_pausedForLookup` 续播；只有覆写最新卡 / 回看会话 / 手机遥控制卡保留等落地。删掉「等待完成」档（旧值 `wait` 兼容读成 `background`）。后台失败 OSD 带「重试」（`card_notice_retry`），换集后重试给 `video_mine_retry_cancelled_episode` 提示。文案：`21f64bb918` 把这两条新 key 补齐 15 种语言（PR #3140 合入时除 en / zh-CN 外是英文占位），后台制卡说明 14 种语言重译见 `e432aea32b`。
