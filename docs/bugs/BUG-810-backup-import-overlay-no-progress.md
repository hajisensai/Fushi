## BUG-810 · 备份导入复制阶段无进度条遮罩
- **报告**：2026-07-14（用户："导入备份的时候还是没有进度条"）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/sync/sync_settings_schema/backup.part.dart:805`。`appModel.beginBackupImport()` 只是 SCHEDULE 根 widget 切到「正在导入备份，请勿关闭」+ 进度条 running 遮罩（`notifyListeners → markNeedsBuild`），紧接着 806 行 `await appModel.closeDatabase()` 就进入 `importBackupFiles` 的部分同步 decode/DB 工作，会在遮罩首帧 raster 之前占住 UI isolate（`await` 微任务不 pump 一帧）。结果整个复制期屏幕停在旧设置页，没有遮罩、没有进度条，直到进程重启。对照 validating 阶段（`beginBackupValidating` 后紧跟真正让出 isolate 的 `await validateBackup`）遮罩能画出来——所以校验有反馈、复制没有，与用户「导入时没进度条」吻合。进度接线本身完好：state 拥有者 `AppModel.backupImportProgress`（`app_model.dart:859`），回报 `reportBackupImportProgress`（`app_model.dart:863`），接线 `backup.part.dart:824/843` `onProgress:`，渲染 `main.dart:1300` → `BackupImportOverlayView`。缺的只是让遮罩先上屏那一帧。
- **[x] ① 已修复** — `backup.part.dart:805-806` 之间插入 `await WidgetsBinding.instance.endOfFrame`，等 running 遮罩真正 raster 出来再 `closeDatabase`，复用 validating→app 切换 `_rootContextAfterOverlay` 已依赖的同一原语。提交：<待填>
- **[x] ② 已加自动化测试** — `hibiki/test/sync/backup_import_overlay_test.dart` 源码守卫：断言 `await WidgetsBinding.instance.endOfFrame` 位于 `beginBackupImport()` 与 `closeDatabase()` 之间。提交：<待填>
- **备注**：修复早已写成 commit `233d0450f`（PR#82 草稿分支 `worktree-backup-audio-fixes`），但从未合入 develop，故用户「还是」看不到。那个 commit 把 bug 记为 BUG-780，与 develop 上已占用的 `BUG-780-backup-keep-settings-local-audio-wipe.md` 撞号——本次改为独立文件 BUG-810 落地，不整体 cherry-pick。
