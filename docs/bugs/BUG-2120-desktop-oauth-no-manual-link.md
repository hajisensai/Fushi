## BUG-2120 · 桌面云盘 OAuth 登录无「复制链接/重开/取消」兜底，浏览器页失败只能等 5 分钟超时
- **报告**：2026-09-04（用户：别人的 Windows 机器上用 Fushi 登录 Google Drive，浏览器显示 Google 通用 400 页「The server cannot process the request because it is malformed. It should not be retried.」）
- **真实性**：✅ 真 bug（但根因不在 URL）。沿真实路径验证：安装版 `fushi.exe` AOT 快照里的 client_id / `o/oauth2/v2/auth` / `drive.appdata` / `prompt=consent select_account` / 回环 `127.0.0.1` 与 develop `fushi/lib/src/sync/google_drive_auth.dart:_buildDesktopAuthUrl` 逐字节一致；该 URL 经 curl 与干净 profile 的无头 Chrome 都能到达 Google 登录页。再把 URL 的所有常见改写形态（`+`→`%2B`、`&`→`&amp;`、双重编码、截断、client_id 丢失、尾部 CRLF）逐一发给 Google，全部得到带说明的「Error 400: invalid_request / invalid_scope」OAuth 错误页，**没有任何 URL 改法能造出那张通用 400 页**——它是 Google 前端在 HTTP 请求层（cookie 超大/损坏、代理或 hosts 改写、扩展注入非法头）的拒绝，完全发生在对方浏览器里，app 看不见也改不了。app 侧真正的缺陷是 `fushi/lib/src/sync/desktop_oauth.dart:runDesktopOAuthLoopback`：拉起默认浏览器后就只 `await completer.future.timeout(5 min)`，把那条授权链接攥在手里不给用户——用户既不能复制到无痕/其它浏览器，也不能在第一次没弹出来时重开，更不能取消，只能对着登录按钮转圈等超时。Google Drive / Dropbox / OneDrive 三家共用这一条路，同病。
- **[x] ① 已修复** — `runDesktopOAuthLoopback` 拉起浏览器后把 `DesktopOAuthLaunch`（authUrl / reopenBrowser / cancel）交给观察者；`DesktopOAuthLaunchObserver.observe` 作用域挂接（进程级槽位而非改 10 个 `authenticate` 签名：桌面授权同一时刻只有一条）；新增 `SyncAuthFailureKind.cancelled`（登出判定 / 错误文案 / 守卫登记表三处显式登记，UI 静默）；新 `desktop_oauth_wait_dialog.dart` 等待对话框「复制登录链接 / 重新打开浏览器 / 取消」，生命周期钉在本次登录的完成上，遮罩不可点关、系统返回等价取消；`account.part.dart:_signIn` 接线。提交 `d94058391a`。
- **[x] ② 已加自动化测试** — `fushi/test/sync/desktop_oauth_launch_test.dart`（真回环服务器 + 桩 url_launcher：观察者拿到的 URL 与浏览器实际拉起的逐字节一致、cancel 立刻以 cancelled 收场并释放端口、reopen 再拉同一 URL、observe 作用域进出还原）；`fushi/test/sync/desktop_oauth_wait_dialog_test.dart`（复制写剪贴板、重开落到句柄、取消不自行关闭、遮罩点不掉、返回=取消、done 完成即关闭）。既有守卫 `oauth_proxy_and_browser_timeout_test.dart` 的登出登记表同步登记 `cancelled: false`。
- **备注**：flutter_test 把 `dart:io` 的 `HttpClient` 换成永远连不上的假实现，回环回调的测试打桩必须用裸 `Socket` 手写 HTTP 请求，否则静静挂到 30 秒超时。给对方用户的处置顺序：复制链接到无痕窗口 → 清 google.com cookie / 禁用可疑扩展 → 换默认浏览器 → 查 hosts / 换代理节点。
