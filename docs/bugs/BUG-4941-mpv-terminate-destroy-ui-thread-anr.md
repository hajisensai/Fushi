## BUG-4941 · Android 播放失败后关闭播放页 ANR：mpv_terminate_destroy 在 UI 线程同步阻塞
- **报告**：2026-11-21（应用内反馈 wcOJwX-sHh，Redmi Note 8 / Android 11 / 3.3.0）
- **真实性**：✅ 真 bug。反馈里两次 ANR 的主线程栈：第一次 `libc pthread_join+248 <- libmpv.so+0x2eaacc <- base.apk(Dart AOT)+0x5cd92d4`，第二次 `pthread_cond_wait <- libmpv.so+0x2d10ec <- libmpv.so+0x2eaa90 <- base.apk+0x5cd92d4`。两次的 Dart 返回地址及其以下整条 Dart 栈完全相同，libmpv 里的两个返回地址只差 0x3c 字节，是同一个 libmpv 函数里先 cond_wait 再 join——这正是 `mpv_terminate_destroy` → `mp_destroy_client(ctx, true)`（`player/client.c`：`mp_dispatch_lock` 等内核线程进入 dispatch，再 `mp_thread_join` 内核线程）。libmpv 公开 API 里只有它会 join 内核线程。调用点是 `ci/patches/hosted/media_kit-1.2.6/lib/src/player/native/player/real.dart:112`（修前）：`dispose` 用 `Future.delayed(5s)` 在 **UI isolate** 里同步 `mpv.mpv_terminate_destroy(ctx)`。Android 上 Flutter UI isolate 与平台主线程合并，内核线程卡在打不开的流 / demuxer 上（反馈日志：`Failed to recognize file format`、15 s 内媒体没打开，随后离开播放页）时，destroy 一直等内核退出 → 主线程卡 5 s 以上 → ANR。
- **[x] ① 已修复** — `real.dart` 的 `dispose`（:108 起）在等完 `_offThreadNativeCalls` 后改为 `await compute(_terminateDestroy, _TerminateDestroyData(ctx.address, NativeLibrary.path))`；新顶层函数 `_terminateDestroy`（:3258 起）在辅助 isolate 里打开 libmpv 并销毁句柄，和既有 `_hookContinue` / `_screenshot` 同一套路（BUG-3507）。销毁顺序不变：仍在 `Initializer.dispose` 摘掉唤醒回调、辅助 isolate 上的钩子放行与截帧跑完之后。`ci/patches/hosted/media_kit-1.2.6/PATCHES.md` 记了 BUG-4941 一节。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_mpv_ui_thread_native_calls_guard_test.dart` 新增「media_kit patch destroys the mpv handle off the UI thread」：补丁里 `mpv.mpv_terminate_destroy(` 只许出现在顶层 `_terminateDestroy` 内，`dispose` 必须经 `compute(` 送 `_terminateDestroy`，且排在 `_offThreadNativeCalls` 等待之后（修前该测试红：`_terminateDestroy` 不存在、调用点在 `dispose` 里）。「内核卡死」在测试环境里没有稳定的触发方式，真 libmpv 测试在无 `FUSHI_TEST_LIBMPV` 的机器上又是零执行，故锁补丁源码结构不变量（与同文件 BUG-3507 守卫同套路）。
- **备注**：内核线程若永久卡死，辅助 isolate 会一直挂着（泄漏一个线程），但不再挡 UI；那是 mpv 内核 / 流层面的独立问题。`nativeEnsureInitialized` 里热重启回收句柄时的同步 `mpv_command_string(quit)` 只在 debug 热重启残留句柄时走到，本次未动。真机复测未做（按本机约定取消真机验证）。
