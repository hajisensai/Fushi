## BUG-4940 · 安卓 app 外查词 / 悬浮字幕查词的在线 TTS 兜底发音（Edge / Google 翻译）永远失败：弹窗进程没装引擎宿主装配
- **报告**：2026-11-21（应用内反馈 IlyjkPUvJx，Android 三星 SM-C5560，3.3.0）
- **真实性**：✅ 真 bug。引擎宿主装配 `installEngineHostBindings()` / `installAsrHostBindings()` 只在 `main()` 里调（`fushi/lib/main.dart:430`），注释还写着「写在 main 里哪个入口都不会漏」。但 Android `:popup`（app 外查词、悬浮字幕查词，`PopupEngineHolder` 起的副 FlutterEngine）跑的是 `popupMain`（`fushi/lib/popup_main.dart:33`），`:second_screen` 跑 `secondScreenMain`，都不执行 `main()`；Dart 全局按 isolate 隔离，那边的 `enginePaths` 一直是 `UninstalledEnginePaths`。查词 TTS 兜底选在线预设时 `_synthesizeWithPreset` → `source.cache()`（`fushi/lib/src/creator/mining_tts_fallback.dart:459`）→ `TtsServices.cache()` 取 `enginePaths.supportRootDirectory()`（`fushi/lib/src/media/audiobook/tts/tts_services.dart:135`）→ `UninstalledEnginePaths._fail()` 抛 StateError（`packages/fushi_engine/lib/foundation/engine_paths.dart:105`），被兜底 catch 归一化成「语音服务返回的音频无效」，查词显示暂无发音。系统语音不经缓存，所以只有 Edge / Google 翻译等在线预设坏，与用户描述一致。同进程里 `engineLog` 也没装，引擎日志只进 stderr。
  - 反馈日志里 6 条 `LocalAudioEnhancement.ttsFallback`（`badResponse: empty` / `network: closed early`）都来自应用内查词，是在线服务本身的偶发失败（`tts_http.dart` 200 空体、Edge websocket 提前关闭），已按临时失败交给重试层，与本 bug 无关。
- **[x] ① 已修复** — `fushi/lib/src/engine_bindings.dart` 新增 `installEntryPointHostBindings()`（引擎包 + ASR 包装配一次装齐），`main`、`popupMain`、`secondScreenMain`、`floatingDictMain` 各自在 `ensureInitialized()` 之后、`runApp` 之前调用；更正 `engine_bindings.dart` / `asr_host.dart` / `main.dart` 里「装在 main 就不会漏」的错误注释。
- **[x] ② 已加自动化测试** — `fushi/test/build/entry_point_host_bindings_guard_test.dart`：枚举 `lib/` 根下所有 `@pragma('vm:entry-point')` 入口（跳过 `main.dart` 里的纯转发），要求函数体在 `runApp` 前调 `installEntryPointHostBindings()`；禁止入口绕开它直接调单个包的装配；行为上验证它把 `enginePaths` / `engineLog` 接到 app 实现。变异实测：去掉 `popupMain` 里那行，守卫红。
- **备注**：`flutter_test_config.dart` 全局装了引擎装配，单测里看不到未装状态，故用源码扫描守卫。未在真机 `:popup` 进程复测在线预设兜底出声（真机验证取消，缺口记此）。
