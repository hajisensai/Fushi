## BUG-2698 · 浏览器扩展「在 Anki 中打开」未接通
- **报告**：2026-09-26（用户：上游 issue #1409 B 部分——浏览器扩展查词弹窗点 ↗「在 Anki 中打开」总提示打不开。同 issue 的单词音频部分已由 BUG-2573 修，不在本条范围）
- **真实性**：✅ 真 bug。弹窗 `vendor/popup.js:2375`（真源 `fushi/assets/popup/popup.js:2375`）`openWordInAnki` 调 `callHandler('openInAnki', {expression, reading})`，期望回三态名 `'opened' / 'noMatch' / 'failed'`（`null` 专指「宿主没接这根桥」，同样提示打不开）。扩展里三个弹窗宿主都没接这根桥：
  - 页内弹窗 `tools/browser-extension/bridge-shim.js:181` 的 `switch` 没有 `openInAnki` 分支 → `default` 回 `null`；
  - Side Panel `tools/browser-extension/side-panel.js:744` 的 callHandler 兜底同样回 `null`；
  - 嵌套弹窗 `tools/browser-extension/nested-popup-host.js:99` 的转发白名单 `allowed` 不含 `openInAnki` → 回 `null`；
  - 下游也是空的：`background.js` 没有对应消息，服务端 `fushi/lib/src/sync/yomitan_api_server.dart` 的路由（`/api/duplicate` 旁）没有端点，`FushiRemoteMiningService` 也没有这个能力。
  app 内等价路径 `fushi/lib/src/lookup/overlay_bridge_handlers.dart` `_handleOpenInAnkiBridge` → `repo.openWordInAnki(expression, reading)`（BUG-2051 的单一判据）一直是通的，只是扩展这条车道从没接上。
