## BUG-4794 · Android 系统画中画里本地换集（含自动连播），新页不认领 PiP 状态：小窗里画出整套常规 chrome
- **报告**：2026-11-17（代码审查发现，优化计划 gap-vidmisc-1；没有用户报告）
- **真实性**：✅ 真 bug（沿代码路径确证，真机表现未实测）。根因 `fushi/lib/src/pages/implementations/video_fushi/mini_window.part.dart:59-68`（修前）：`_initMiniWindowSupport` 的移动分支只订阅 `AndroidPictureInPicture.modeChanges`，不读 `isActive`；而 `modeChanges` 只在状态翻转时发事件（`fushi/lib/src/platform/mobile/android_picture_in_picture.dart` 的 `_emit` 去重），`_miniSurface` 初值是 `none`（`video_fushi_page.dart:3683`）。本地换集是 `pushReplacement` 的新页（`video_fushi/episode.part.dart`），PiP 里自动连播到下一集时系统窗口没动，新页收不到任何事件，一直停在 `none`：小窗里画出顶栏 / 底栏 / 进度条，密度档按宽度而不是按 PiP 档解，悬浮球也不隐藏，直到用户退出 PiP。桌面分支用 `DesktopMiniWindowMode.claim` 接过所有权，同一门面的另一个消费方 `app_floating_ball_host.dart` 订阅前也先读了 `isActive`，只有这里漏了。
- **[x] ① 已修复** — `mini_window.part.dart` `_initMiniWindowSupport`：订阅之前同步 `if (AndroidPictureInPicture.isActive) _miniSurface.value = VideoMiniSurface.pictureInPicture;`（initState 期，直接写值）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_mini_window_wiring_guard_test.dart`「BUG-4794：新页订阅 modeChanges 之前先用 isActive 播种」（源码守卫：播种语句存在且排在订阅之前）；`fushi/test/platform/android_picture_in_picture_controls_test.dart`「modeChanges 只在翻转时发事件，晚订阅者收不到当前值——只能靠 isActive 播种」（门面行为：钉住播种之所以必需的那条契约）。视频页 State 起不了纯 widget 测试（依赖 libmpv 播放器与整套 app 模型），所以页面一侧落在源码守卫层。
- **备注**：待 Android 真机复测原始路径——本地合集进 PiP，等自动连播到下一集，小窗里不应出现控制条 / 顶栏，悬浮球保持隐藏；再退出 PiP，chrome 应恢复。同一 PR 给 PiP 窗口补了播放 / 暂停键与换集比例同步（gap-vidmisc-4，新增交互，不属于本条）。
