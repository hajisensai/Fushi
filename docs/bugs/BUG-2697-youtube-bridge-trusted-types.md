## BUG-2697 · YouTube MAIN world 解析字幕触发 TrustedHTML 报错
- **报告**：2026-09-26（上游 issue [#1495](https://github.com/hajisensai/hibiki/issues/1495)：YouTube 页面报 "This document requires 'TrustedHTML' assignment and no 'default' policy for 'TrustedHTML' has been defined"）
- **真实性**：✅ 真 bug。`tools/browser-extension/youtube-bridge.js` 经 `manifest.json` 的 `content_scripts`（`"world": "MAIN"`，`*://*.youtube.com/*`）注入页面主世界，受 YouTube 的 `require-trusted-types-for 'script'` 约束；`fetchTrack` 先取 `fmt=srv3`，再由 `parseSrv3`（修复前 `youtube-bridge.js:140`）`new DOMParser().parseFromString(text, 'text/xml')` 解析——裸字符串进 TrustedHTML sink 直接抛，被 `fetchTrack` 的 `catch (_) {}`（修复前 `:229`）吞掉后回落 `fmt=json3`。字幕仍能取到，但每条轨都白发一次 srv3 请求、扩展错误页留一条报错。
- **[x] ① 已修复**（`bb43a2ff771`）— 删除 `parseSrv3`，`fetchTrack` 直接取 `fmt=json3`（纯 JSON，不经任何 HTML/XML sink）。等价性：BUG-2629 后 json3 路径已有 `finishTrackCues` / `clampRollingCues`（自动字幕滚动双行截断、人工轨只排序），srv3 独有的「下一行是 `\n` 追加行就截断」被它覆盖；唯一差别是自动字幕截断点从 `\n` 追加行改为下一行开头（实测晚约 10ms）。app 打包镜像 `fushi/assets/browser_extension/youtube-bridge.js` 经 `scripts/sync-mirrors.mjs` 同步。
- **[x] ② 已加自动化测试**（`bb43a2ff771`）— 新增源码守卫 `tools/browser-extension/main-world-trusted-types.test.js`：从两份宿主清单（`tools/browser-extension/manifest.json`、`fushi/assets/browser_extension/manifest.json`）动态读出全部 `world: "MAIN"` 脚本，禁止 `DOMParser` / `.innerHTML` / `outerHTML =` / `insertAdjacentHTML` / `document.write` / `createContextualFragment` / `setHTMLUnsafe` / `.srcdoc =`（含正负自检；换回修复前源码即红，命中 `youtube-bridge.js L140 DOMParser`）。`youtube-bridge-rolling-cues.test.js` 改为：沙箱 DOM 解析器换成「一调用就按 Trusted Types 抛」的桩，断言只发一次 `fmt=json3`、从不请求 `fmt=srv3` 且 cue 完整发布；原 srv3 两条用例改为 json3「无 `\n` 追加行」变体。
- **备注**：`background.js` 里 `chrome.scripting.executeScript({ world: 'MAIN' })`（B 站 PGC playurl）是 `func` 注入、只 `fetch` + `res.text()`，不在 manifest 守卫面内，经人工核对无 HTML sink。
