## BUG-1770 · 发现页整源失败被显示成「无结果」
- **报告**：2026-08-22（修 [BUG-1768](BUG-1768-discovery-folder-infinite-nesting.md) 时在真机原始路径上撞见：自嵌套修好后点进目录，界面写「无结果」，而实际上那次请求是**失败**的）
- **真实性**：✅ 真 bug。`MediaDiscoveryService.load` 把逐源异常收敛进 `DiscoveryAggregateResult.failures` 并**正常返回**（`media_discovery_service.dart:175-195` 的 `_invoke`），所以页面的 `_error` 恒为 null；而失败徽标只挂在 `_buildBody` 的**非空列表**分支上（`media_discovery_page.dart` 的 `if (result != null && result.hasFailures)`），空列表在更早的 `if (_entries.isEmpty)` 就直接返回了 `discovery_empty`。于是「所有源都挂了」与「真的没有结果」在界面上完全同形。模型层其实早就有正确的语义 `DiscoveryAggregateResult.isTotalFailure`（`media_discovery_service.dart:51`，`successfulSourceCount == 0 && hasFailures`），只是 UI 没用它。
- **[x] ① 已修复** — `_buildBody` 把 `_result` 的取用提到空列表判断之前，空列表时先判 `isTotalFailure`：成立就渲染新文案 `discovery_sources_unavailable`（「全部来源都不可用」/「All sources are unavailable」，经 `fushi/tool/i18n_sync.dart --add` 加进 17 个语言文件后 `dart run slang` 重生成）并附上失败源 id，否则才是「无结果」。i18n key 按 `<域>_<子域名词>_<状态>` 命名。
- **[x] ② 已加自动化测试** — `fushi/test/pages/media_discovery_page_test.dart` 加了**成对**的两条：`_FailingSource`（browse/search 一律抛）断言显示 `discovery_sources_unavailable` 且不出现 `discovery_empty`；`_EmptySource`（成功但零条目）断言仍是 `discovery_empty` 且不出现失败文案。成对是必要的——只写第一条会被「一律报错」糊弄过去。
- **备注**：真机验证 2026-08-22（隔离实例 `FushiDiscProbe`，未碰生产库）：erogame.space 在该路径上确实整源失败，界面现在显示「全部来源都不可用 (alist-erogame)」。触发它的那个失败本身是 [BUG-1771](BUG-1771-alist-search-parent-base-path.md)（搜索路径带 base_path 前缀）；本条只负责「失败不许伪装成空结果」这条不变式，两者独立。
