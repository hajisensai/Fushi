## BUG-4389 · SRS profile conflict dialog never lays out; desktop app stops reacting to the mouse
- **报告**：2026-11-11（用户：Windows debug 版停在复习（SRS）牌组列表上，鼠标彻底失灵、不再出帧；一次在点「浏览」时，一次启动约 17 秒后无操作。日志首个错误 `LayoutBuilder does not support returning intrinsic dimensions`，随后 30 次 `Cannot hit test a render box with no size`（creator 链 `… ← Dialog ← AlertDialog ← FushiAlertDialog ← FushiGlassDialogBackdrop`）与 `mouse_tracker.dart:199` 断言）
- **真实性**：✅ 真 bug（upstream develop 上同样存在，代码来自 31d1ddcf82）。用户在复习 tab 上、同步层检出 profile 冲突时，`SrsAppRuntime._maybeShowProfileConflict`（`fushi/lib/src/srs/srs_app_runtime.dart:578`）经根导航器自动弹 `showSrsProfileConflictDialog`（`fushi/lib/src/pages/implementations/srs/srs_sync_settings.dart`）。候选行用的是 `FushiListTile`，其标题 / 副标题是 `FushiMarquee`（`fushi/lib/src/utils/components/fushi_marquee.dart:395`，`LayoutBuilder`）。`AlertDialog` 用 `IntrinsicWidth`（material_ui `dialog.dart:955`）量内容，固有尺寸查询走到 `LayoutBuilder` 即抛异常；排版异常后对话框的 `RenderConstrainedBox` 没有尺寸但也不再标脏，之后每次鼠标移动的命中测试都报错，debug 版里 `MouseTracker` 的 `_debugDuringDeviceUpdate` 卡在 true，整个 app 不再响应。与点「浏览」只是时间上重合。
- **[x] ① 已修复** — 冲突对话框的候选行改用 `FushiListItem` + 普通 `Text`（副标题最多 3 行换行，设备名 / 笔记数 / uid 能读全），不再把答不了固有尺寸的 `LayoutBuilder` 放进 `AlertDialog` 内容。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_profile_conflict_dialog_layout_test.dart`：1165×677 桌面尺寸弹出冲突对话框，断言无异常、候选行有尺寸、鼠标悬停无异常；修复前同一测试红，首个异常与用户日志逐帧一致。
- **备注**：`FushiListTile` / `FushiMarquee` 修复后在 lib 里已无调用者（只剩 golden / widget 测试），删不删另议。未在真实 Windows app 上复测。
