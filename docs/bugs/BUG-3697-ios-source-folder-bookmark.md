## BUG-3697 · ios-source-folder-bookmark
- **报告**：2026-10-23（用户：应用内反馈 Tz04dfBf2f，iOS 3.0.0——漫画 / 小说 / 视频添加常驻来源后不扫描，像是子文件夹没扫，只能手动选文件导入）
- **真实性**：✅ 真 bug。iOS 上来源页「添加本地文件夹」（`fushi/lib/src/pages/implementations/media_sources_view.dart` `addLocalFolder`）与「仅此一次」走 `pickRealDirectoryPath`（`fushi/lib/src/media/import/real_path_directory_picker.dart:46`），在 iOS 落到 file_picker `getDirectoryPath()`：交回沙盒外路径却从不 `startAccessingSecurityScopedResource()`，`dart:io` 列目录被拒（BUG-2786 同一根因；一次性导入已改整卷拷贝，常驻来源要反复复扫、视频还原地播放，不能拷）。来源行只存了路径、没有任何授权凭证，之后每次扫描都读不到。
- **[x] ① 已修复** — 方案 A（用户拍板）：iOS 选来源文件夹时在访问窗口内建安全作用域书签存进 `media_sources.configJson` 的 `iosBookmark` 键（不改 schema；白名单 `kSourceConfigAllowedKeys` 收录，凭据红线不变）。原生 `ios/Runner/FushiDirectoryImport.swift` 在现有 `app.fushi.reader/saf` channel 上加 `pickDirectoryBookmark` / `startAccessingBookmark` / `stopAccessingBookmark`（按路径计数）；Dart 门面 `fushi/lib/src/media/source_library/source_folder_access.dart`（`SourceFolderAccess`）。持有策略：app 生命周期内持有——`AppModel.initialise` 启动激活（不阻塞）、`SourceLibraryScanner._scanUnlocked` 扫描前激活、`VideoPlayerController.load` / `_loadSingle` 播放前 `ensureForPath`；`removeSourceLibrary` 与一次性导入临时行收尾时 `release` 配对 stop。书签过期回写原生重建的新书签；没书签 / 解析失败 / 文件夹被挪走时 lastScanError 写明原因（i18n `media_source_folder_access_*`）。修复前加的来源：重新添加同一文件夹即把新书签写回该行再重扫。
- **[x] ② 已加自动化测试** — `fushi/test/media/source_library/source_folder_access_test.dart`（编解码、iOS 扫描前先 start 后列目录、stale 回写、解析失败 / 无书签 / 被挪走的报错、非 iOS 不调原生、并发只 start 一次与 release 配对、启动激活 + 按路径懒激活、登记来源书签落库、一次性导入扫完释放）；更新源码守卫 `fushi/test/media/video/real_path_directory_picker_test.dart`（选目录收口到 `_pickSourceFolder`）。
- **备注**：未验证项——Swift 本机（Windows）编不了，未经 Xcode 编译；未在 iOS 真机验证选文件夹 → 建书签 → 重启后复扫 / 原地播放；iCloud Drive 与第三方文件提供者下书签解析行为未验证。已知限制：iOS 上「导入文件夹（仅此一次）」导入视频时，扫完即释放访问，视频是原地引用，之后在 iOS 上不可再播（书 / 漫画已拷进 app 不受影响）——要长期播放应登记成常驻来源。视频页拖放目录入口（desktop_drop）iOS 无实现，不受影响。
