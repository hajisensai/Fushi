## BUG-712 · 查词全链路延迟半秒级
- **报告**：2026-07-10（用户：「优化一下查词速度、包括查词弹窗。别人速度是10ms级别的。我们甚至要半秒」）
- **真实性**：✅ 真 bug。沿真实代码路径全链审计（触发→FFI 引擎→弹窗渲染），500ms 不是单点而是热路径上多处结构性浪费叠加，五个根因（P1-P5）：
  - **P1 弹窗双推双渲染**：每次查词把结果推进弹窗 WebView 两遍——`didUpdateWidget`（`hibiki/lib/src/pages/implementations/dictionary_popup_webview.dart:565`）推第一次，`_showPopupWaitingForRender` 的 postFrame 无条件 `refreshCurrentResult()`（`hibiki/lib/src/pages/base_source_page.dart:406`、`dictionary_page_mixin.dart:632`）全量重推第二次；且第二推覆写 `__hibikiRenderToken` 使第一推的 `popupRendered` 被丢弃（`dictionary_popup_webview.dart:1012`）——内容可见时刻=第二遍完整渲染完成，整段渲染成本 ×2 串行（40-240ms）。无条件重推是 BUG-523 时代的防御，其真实根因（macOS 资产路径致 popup.html 未加载）已另行修复。
  - **P2 查词历史全量重写**：每次查词 `_persistDictionaryHistory`（`hibiki/lib/src/models/dictionary_repository.dart:266`）把整份历史（默认 10 条完整 DictionarySearchResult）在 UI isolate 同步 toJson 再整表 DELETE+INSERT。生产库实测单条 54-231KB、整表 ~1.36MB/次，序列化循环恰好卡在弹窗显示帧之前（10-100ms）。
  - **P3 词典字体每推重读盘**：`DictionaryFontCss._inlineFontDataUrl`（`hibiki/lib/src/reader/dictionary_font_css.dart:97`）无缓存，配置导入字体时每次推结果都同步 readAsBytesSync+base64Encode（≤8MiB/文件）并把 MB 级 data:URL 过桥——热槽 WebView 的 `<style>` 本就跨渲染持久（0-200ms，视字体配置）。
  - **P4 原生查询管线整跑两遍**：`searchDictionary` 在 `lookup()` 拿到结构化结果后又调 `lookupPopupJson()`（`hibiki/lib/src/models/app_model.dart:3065/3087`），C++ 把同一个词的完整管线（scan×文本变体×去屈折×hash 查询×排序×zstd 解压）从零再跑一遍；FFI 缓存命中分支和 load-more 每页也照跑（原生查询成本 ×2，10-60ms）。
  - **P5 渲染完成信号被尾批拖住**：多词条结果首词条同步渲染完即可见，但 `popupRendered`（撤盖板/翻可见的唯一信号）要等 `setTimeout(0)` 尾批把全部词条 build 完才发（`hibiki/assets/popup/popup.js` renderPopup 多词条路径，10-100ms）。
- **[x] ① 已修复** — 提交：`e07e529ad`（分支 `worktree-lookup-speed-opt`）
  - P1：`refreshCurrentResult()` 改为按 `_lastPushedResult`/`_lastRenderedResult`（对象身份）去重并返回 bool：已渲染完→false（不重推）、推送在途→true（等信号）、漏推→真正补推（BUG-523 的安全网语义保留）。两个宿主 postFrame 按返回值处理「渲染信号早于盖板架起」竞态：false 时立即走既有 rendered 路径撤盖板，不空等 1.8s failsafe。
  - P2：历史落库改 trailing debounce 300ms + 2s 封顶（连续查词只写一次）+ 逐条序列化 memo（`Expando`，10 条里通常只序列化新增 1 条）；`flushDictionaryHistoryNow()` 注册进 `ExitFlushRegistry`（桌面关窗/Android 退后台写穿），`clearDictionaryHistory` 先取消 pending 防旧快照复活，`loadFromDb` 重载前先 flush 保持「变更先于重载落库」旧语义。崩溃最坏丢 ≤2s 查词历史（非用户数据）。
  - P3：`_inlineFontDataUrl` 加 (path→mtime+size) 键静态缓存，existsSync+lengthSync 合并为单次 statSync；maxBytes 检查保持在缓存命中前（小上限调用不会误吃大文件缓存）。
  - P4：两处 `lookupPopupJson` 替换为 Dart 侧 `buildPopupJsonFromLookup(results: ffiResults, ...)`（`packages/hibiki_dictionary/lib/src/language/language.dart:491`，与 C++ `build_popup_json` 逐字段对齐、有 parity 测试）。同源生成还消除「entries 来自缓存、popupJson 来自新查询」的双源分叉；C++ builder 保留（Android :popup 进程 JNI 路径继续用）。
  - P5：popup.js 多词条路径首词条（build+局部 postProcessRuby+applyCustomCSS）就绪后立即发第一次 `popupRendered`（宿主撤盖板/翻可见），尾批完成后发第二次（同 token；Dart 全部消费方幂等，Windows global-lookup host 依赖第二发量全高）。窗口期 `_renderInProgress` 令 `updatePopupIncremental` 回退全量 renderPopup（换代取消尾批，杜绝重复卡片）。三镜像已同步（assets/browser_extension/vendor + tools/browser-extension/vendor）。
  - 已评估不改：阅读器高亮 await（换精确锚点矩形，5-30ms 值得）；`maxResults=200`（load-more 分页深度硬依赖，收敛需改缓存键结构）；remoteLookupEnabled 时远端 HTTP 先于本地缓存（默认关闭；改序变更远端优先语义，留待独立决策）；C++ 引擎微优化（freq/pitch 截断后富化、排序键预计算——P4 后收益减半，留作后续）。
