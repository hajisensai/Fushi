## BUG-4394 · 扩展词典图片 URL 只能携带主机主凭据原值，且不认可吊销的设备凭据
- **曾用号**：PR 分支 `pr/interconnect-host-auth` 的提交信息把本条写作 BUG-4283（合入 develop 前的旧号；改号提交 `080b4a41c72`、`71ab2acf8c9`）。develop 上的 BUG-4283 是另一条无关的 bug，按提交信息搜号时以本文件为准。
- **报告**：2026-11-10（用户：互联 host 安全审查 H9）
- **真实性**：✅ 真 bug。（行号按 94317ab6295）`packages/fushi_engine/lib/sync/fushi_sync_server/auth.part.dart:42-51` 的豁免 gate 交给 `fushi_sync_server/lookup.part.dart:155-170` 的 `_dictionaryMediaTokenValid`，它只拿 query 值与共享 `_token` 原值比：免 Basic 的 `<img>` 入口（`GET|HEAD /api/media/dictionary`）只能把长期主凭据原值拼进 URL（进页面 DOM / 浏览器历史）；已配对设备的 peer token 不被认，也就没有可吊销的 query 凭据。修复前实测：由 peer token 或共享 token 派生的 key 都 401，`/api/extension/status` 无能力位。
- **[x] ① 已修复**（`7c456b5a88b`）— 引擎 `fushi_sync_server.dart`：新顶层 `kDictionaryMediaKeyScheme = 'fmk1'` 与 `dictionaryMediaKeyFor(credential)` = `'fmk1.' + base64url(无填充)(HMAC-SHA256(key: utf8(credential), msg: 'fushi-dictionary-media-v1'))`；凭据快照 `_CredentialSnapshot.dictionaryMediaKeys` 填共享 / peer / legacy 各自的派生 key（吊销推进代际后整体重算）；`_dictionaryMediaTokenValid` 改 async：`fmk1.` 开头的值与快照里每把 key 常量时间比（不提前退出；快照读不出按不认、落到 Basic，同 `_validateAuth`），其余值仍只与共享 token 原值比（旧扩展兼容，取舍 T6）；`/api/extension/status` 加 `dictionaryMediaKey: 'fmk1'`。扩展：新 `tools/browser-extension/dict-media-key.js`（`crypto.subtle` 同一定义，SW 与 node 两用）进 `importScripts`；`background.js` 加能力位缓存（键 = base|token，启动版本检查与站点 Cookie 导入两处 status 回包写入），`dictMediaConfig` 命中 fmk1 回派生 key、无能力位回原 token、未命中单飞地查一次 status，查询失败本次回原 token 且不写缓存；`assets/browser_extension/` 镜像同步。
- **[x] ② 已加自动化测试** — `fushi/test/sync/fushi_sync_server_dictionary_media_test.dart`（真 server：peer 派生 key 200、吊销后同一 key 401、legacy 行派生 key 200、peer token 原值进 query 401、共享 token 原值与派生 key 都 200、未知 / 空 fmk1 key 401、status 带 `dictionaryMediaKey: 'fmk1'`）；新 `fushi/test/build/browser_extension_dict_media_key_test.dart`（node 真加载随包 `dict-media-key.js`，四组 token 与 Dart `dictionaryMediaKeyFor` 逐字节一致，含空 token 与非 ASCII）；新 `tools/browser-extension/dict-media-key.test.js`（background-harness 真装载 background.js：status 报 fmk1 回派生 key、无能力位回原 token 且不多查、启动检查失败后并发两条消息只查一次并缓存、查询失败回原 token 且下次重查）。
- **备注**：只在扩展被指向 `FushiSyncServer`（典型是无头服务端）时生效；扩展默认连的 app `FushiApiServer`（19633）没有 `/api/media/dictionary`、也不报能力位，行为不变（是否因此取不到词典图另行调查）。共享 token 原值仍被 query 接受（旧扩展兼容），移除需用户拍板（取舍 T6）。本机 `node --test *.test.js` 另有 `embedded-frame-lookup.test.js` 两个真 Chrome 用例红，在未改动的 HEAD 上同样红（本机 Chrome 探针不出结果），与本修复无关。
