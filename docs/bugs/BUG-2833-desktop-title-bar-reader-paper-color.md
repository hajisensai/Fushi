## BUG-2833 · 桌面自绘顶栏不跟阅读器纸色，正文顶上一条白带
- **报告**：2026-10-01（用户：「fushi 的顶部标题好像没吃主题色？」+ macOS 录屏）EPUB 阅读器（ecru 纸色）里，窗口最上方 32px 自绘顶栏是白的，下面阅读器工具栏与正文是米黄，断成两截。
- **真实性**：✅ 真 bug。两个颜色真相源：`fushi/lib/src/utils/components/fushi_desktop_title_bar.dart` 顶栏挂在 Navigator 外（`fushi/lib/main.dart` `MaterialApp.builder`），`Theme.of` 只读得到根主题，画 `colorScheme.surface`；阅读器画的是预设纸色 `reader_fushi/chrome.part.dart` `_themeMap`（ecru `bg: #F7F6EB`）经 `_readerThemeColors` / `_themeBackgroundColor()`，而 app 的 ecru ColorScheme 由 `theme_notifier.dart` 以种子 `#8B7355` tonalSpot 生成，surface 不是 `#F7F6EB`。water / eyecare / gray / dark / black 预设同理；且页面没有任何通道把自己的底色告诉顶栏。
- **[x] ① 已修复** — `7b243c39b2`：顶栏新增 owner 语义的页面配色通道 `FushiDesktopTitleBar.setPageColors`（与全屏 owner 集合同构，build 阶段上报自动挪到帧尾发布），顶栏底色 / 标题 / 窗口按钮前景优先用页面上报值、无上报回落根主题；新组件 `FushiTitleBarColorScope` 负责生命周期——本页路由被另一 PageRoute 盖住（`secondaryAnimation` 离开 dismissed）即撤回、弹窗 / 底部面板不撤回、dispose 撤回。阅读器以 `(纸色, 字色)` 包在实际画纸色的 Scaffold 上（`f528b72e12`：不改 build 返回根，resize 通道守卫原样成立）；页面上报色先 `Color.alphaBlend` 到 surface，HDR 直通时标题行恒不透明（HDR 守卫改钉这条不变式）。
- **[x] ② 已加自动化测试** — `fushi/test/desktop/fushi_title_bar_page_colors_test.dart`（无上报用 surface 且前置断言 surface≠纸色 / 上报后底色与标题色跟随、关书回落 / 整页盖住撤回、弹窗不撤回、返回恢复 / build 中改色不抛异常且跟随；变异实测：顶栏忽略页面底色 → 用例变红）。
- **备注**：视频页底色本就是 `cs.surface`，不受影响；漫画页只有「黑 / 白 / #2B2B2B」固定底色档会有同类色差带，可同样包一层 `FushiTitleBarColorScope`，但漫画顶栏 chrome 用色未定，本次未接。录屏里阅读器内顶栏标题仍显示「书架」（首页 tab 名），是另一个问题，未在本次处理。
