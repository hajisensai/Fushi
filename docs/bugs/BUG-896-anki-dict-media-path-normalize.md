## BUG-896 · 制卡词典图片脏path未归一化导致坏图
- **报告**：2026-07-19（用户：ロープウェイ 这张卡没有词典内的图片，今天制的卡，本机视频）
- **真实性**：✅ 真 bug。直接查本机 AnkiConnect 实卡确认：ロープウェイ（note 1784350989325, Lapis）的 `Glossary`/`MainDefinition` 里外字 svg 替换成功（`hibiki_dict_04527….svg`），但 100×100 的 png/avif（词典内嵌图片）留成未替换占位符 `hoshi_dict_1.png` / `hoshi_dict_2.avif`。全库共 **25 张**卡含未替换 `hoshi_dict_` 占位符，规律确定：**未替换的永远是靠后（高 index）的图，替换成功的是靠前（低 index）的**，与格式无关（svg / png / avif 落末尾都失败）。
  - **根因** `hibiki/assets/popup/popup.js:625` `getMediaFilename`：制卡登记进 payload 的 `path` 用**生 path**，未归一化。而显示路径 `popup.js:1069` → `dict-media.js` `rewriteDictionaryMediaPath` → `normalizeDictMediaPath`（trim / `\`→`/` / 去开头 `./` 或 `/`）先归一化过。二者不对称：`writeDictionaryMediaCache`（`hibiki/lib/src/pages/implementations/dictionary_webview_media.dart:56`）拿生 path 引 `HoshiDicts.getMediaFile` → path 带开头 `./`/`/` 的词典**命中失败** → 字节不落盘缓存 → AnkiConnect/AnkiDroid/AnkiMobile 三个 repo（`ankiconnect_repository.dart:985` 等「无文件返回 null」）读不到 → `buildDictionaryMediaTags` 不建 tag → `buildMinedFields` 的 `replaceAll` 不触发 → 卡片留 `<img src="hoshi_dict_N.ext">` 坏图。显示已归一化故弹窗里图看得见，只制卡掉图；干净 path 的词典（如常见外字，多排在前面/低 index）不受影响 → 「先头替换、末尾掉图」。
- **[x] ① 已根因修复** — `commit 540c45156`。在源头把 `getMediaFilename` 登记的 path 先经 `normalizeDictMediaPath(path)` 归一化（与显示路径同款），payload.path 干净后 writer 与三个 repo 都按同一干净 path 的 sha1 命名缓存文件，契约天然一致；对干净 path 是 no-op，不影响既有能用的卡。三份镜像同步（`hibiki/assets/popup/popup.js` / `hibiki/assets/browser_extension/vendor/popup.js` / `tools/browser-extension/vendor/popup.js`）。
- **[x] ② 已加自动化测试** — `hibiki/test/anki/anki_dict_media_path_normalize_guard_test.dart`（源码扫描守卫，进 CI）：断言三份 popup.js 的 `getMediaFilename` 都用 `normalizeDictMediaPath(path)` 归一化且以 `normalizedPath` 登记（挡住退回生 path 的回归），并锁三镜像 `getMediaFilename` 逐字一致。JS 行为测试 `test/utils/misc/popup_asset_behavior_test.js`（node，本地）已确认 popup.js 仍正常加载、干净 path 行为不变。
- **备注**：
  - 正交遗留（不在本次范围）：Dart 版 `normalizeDictionaryMediaPath`（`dictionary_media_types.dart:14`）只去开头 `/+`、**不去 `./`**，与 JS 版不完全对称；当前因 JS 先去 `./` 而被屏蔽（显示/同步路径无恙）。若后续要让 Dart 侧独立健壮，可对齐补去 `./`。
  - 已存在的 25 张坏卡是历史数据，本修复只修「新制卡」；旧卡需重新制卡/覆盖才会带上图片（缓存与 collection.media 里其实已有对应字节，属复原路径而非再抽取）。
  - 最终验收：真机（本机桌面 video 制卡）重新查 ロープウェイ 制卡，确认 png/avif 出现在卡片上。
