## BUG-1864 · 视频全屏路由漏掉页级裸空格覆盖：焦点在字幕列表面板时按空格不暂停
- **报告**：2026-08-25（用户：右边（字幕列表）的时候按空格不会暂停）
- **真实性**：✅ 真 bug。根因是**窗口与全屏两条路径的输入层不对称**，不是空格绑定丢失。字幕列表是 push-aside 侧栏（`fushi/lib/src/pages/implementations/video_fushi/layout.part.dart:814-815`：`Row[Expanded(video), _subtitleJumpSidePanel]`），面板是 `Video` 的**兄弟**，故装着注册表全表（含 Space→togglePlayPause）的 media_kit `keyboardShortcuts` 根本不是面板焦点节点的祖先——那层只包 `AdaptiveVideoControls` 子树（`third_party/media_kit_video/lib/media_kit_video_controls/src/controls/material_desktop.dart:651`）。面板打开时 `PanelFocusScope`（`fushi/lib/src/focus/panel_focus_scope.dart:77-85`）主动把焦点从 `_videoFocusNode` 抢进面板，于是裸空格只剩页级兜底 `_withPageSpaceOverride`（BUG-408 的修复）。而那层**只挂在 `_buildScaffold` 上**（原 `video_fushi_page.dart:7031`），全屏是 `Navigator.push` 到根 navigator 的独立路由（`video_fushi/fullscreen.part.dart:135-237`，`pageBuilder` 只包了 `_wrapVideoGamepadControls`，见 BUG-697），**不经过本页 Scaffold** → 全屏下该层根本不存在。最外层 `Focus.onKeyEvent`（`video_fushi_page.dart:5017-5052`）也接不住：`_handleVideoImeSpacePlayPause` 的谓词 `isVideoImeSpacePlayPause`（`fushi/lib/src/media/video/video_player_shortcuts.dart:513-524`）显式要求 `logicalKey != LogicalKeyboardKey.space`，裸空格返回 false。事件最终冒到 `fushi/lib/src/shortcuts/global_navigation.dart:346-353` 的 `_neutralizeBareSpace` 被 `handled` 吞掉 =「按了没反应」。面板自身无辜：`video_subtitle_jump_panel.dart` 全文无 `Focus(`/`Shortcuts`/`onKeyEvent`，唯一的 `HardwareKeyboard` handler 恒 `return false`。
- **[x] ① 已修复** — 把裸空格覆盖层**上提到窗口与全屏的唯一共同外层** `_wrapVideoGamepadControls`（`video_fushi_page.dart`），并从 `_buildScaffold` 移除，消除「两条路径各挂各的」这个不对称本身，而不是给全屏再补一层。`_withPageSpaceOverride` 随之改为读页面字段 `_controller`（全屏 `pageBuilder` 拿不到 `_buildScaffold` 的局部变量），两条路径共用一份真相源。位置刻意放在该 wrapper 的 `Focus` **之内**（CallbackShortcuts 作为后代先于本层 `onKeyEvent` 处理），与窗口模式原有的相对顺序逐层一致，caret / holdSpeed / IME 空格的既有语义不变。这与 BUG-697 把手柄输入层收进同一 wrapper 是同一条边界：窗口与全屏共用一处，不加全屏特判。提交：<本轮 commit>
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_space_playpause_override_test.dart` 扩充：①**全屏拓扑 widget 行为测试**——`Navigator.push` 独立路由 + 真的 `PanelFocusScope`（生产组件，不复刻焦点行为）自行抢焦，断言裸空格仍触发 playOrPause；②**负向对照**——路由内不挂覆盖层则计数为 0，当场复现本 bug；③源码守卫改钉「覆盖层挂在 `_wrapVideoGamepadControls` 内」+「全屏 `pageBuilder` 真走同一 wrapper」，两条新断言均已**变异实测**（分别把 `_withPageSpaceOverride(` / `_wrapVideoGamepadControls(` 改名，守卫如期红，还原后 sha256 与变异前逐字节一致）。提交：<本轮 commit>
- **[x] ③ 同源缺口已一并根治（方案 D，本轮追加）** — 上面 ① 只让**空格**有了页级兜底，但面板持焦后焦点链绕开的是 media_kit 那层**整张注册表**：seek / 音量 / F 全屏 / L 字幕列表 / B 遮蔽等在字幕列表、剧集轨、侧栏持焦时同样失效。根因不是「少了一层兜底」，而是**注册表声明的作用域（`ShortcutScope.video`，整页）与物理挂载点（media_kit controls 子树）不匹配**——scope ≠ mount。本轮把键盘通道改成与手柄通道同构的 **press-time 解析**：
  - 新增纯函数 `resolveVideoKeyboardShortcut`（`video_player_shortcuts.dart`）：每次按键当场问注册表（`resolveKeyboard(video)` → `resolveKeyboard(universal)` 两段式兜底，与 `_handleVideoGamepadButton` 逐段对应），返回 `ignore / run / dismissPopup` 三态判决。
  - 挂载点收敛成**唯一一处**：`_wrapVideoGamepadControls` 的 `Focus.onKeyEvent`（`_handleVideoKeyboardShortcut`），窗口与全屏共用；media_kit 的 `keyboardShortcuts` 显式传**空表**（不能传 null——fork 是 `keyboardShortcuts ?? _defaultKeyboardShortcuts`，给 null 会把 media_kit 自带默认键装回来）。
  - `CallbackShortcuts` 「匹配即无条件消费」这条限制消失后，**三个绕开它的特例一次收敛回同一个判决函数**：① `videoHoldSpeed` 的 keyup 边沿；② `videoEnterCaret` 命中裸 Enter 但焦点在 chrome 按钮上时要放行给 `Enter→ActivateIntent`；③ 面板持焦时裸方向键要让位给焦点遍历（新增 `isVideoPanelFocusNavKey`，手柄侧 `isVideoPanelFocusNavButton` 的键盘对应物；带 Ctrl/Shift 的组合键仍是视频动作，照常执行）。
  - 顺带消失的两个毛病：`_withPageSpaceOverride` 整个删除（裸空格现在就是注册表里的 `videoTogglePlayPause`，不再是特例分支）；build 时冻结的表在全屏 `pageBuilder`（只跑一次）上会陈旧，press-time 永远读当前注册表，用户改键立即生效。
  - **有意保留**：`buildVideoPlayerShortcutsFromRegistry` 不删，它仍服务**推到 Navigator 上的独立弹窗**（字幕波形对轴视图）——那些路由不在视频页 Focus 的祖先链上，收不到主通道，只能自带一张表。所以那两个 `continue`（holdSpeed / enterCaret）也仍在，收益只在主通道。
  - 因此删除的三个已死纯函数：`guardVideoShortcutsWithPopupDismiss`、`guardVideoShortcutsWithSubtitleCaret`、`decideVideoEnterCaretKey` + `VideoEnterCaretKeyDecision`（语义全部迁进 `resolveVideoKeyboardShortcut`，对应测试同步迁移，不是删覆盖）。
  - **行为扩大（如实记录）**：主通道透传 `physicalKey` 给 `registry.resolveKeyboard`，于是 TODO-847 的 IME 物理键回退第一次覆盖到**整张视频表**（旧 activator 表只按 logicalKey 匹配，IME 下全表失效、只有空格由 `_handleVideoImeSpacePlayPause` 兜住）。文本框持焦时整条通道早返回，不会误触。
  - 另一处行为扩大：主通道现在能表达「文本框持焦 → 一个视频动作都不解析」，这是旧表做不到的（旧表挂在 controls 子树，只是恰好够不到弹窗里的输入框）。
  - 测试：`resolveVideoKeyboardShortcut` / `videoCaretKeyboardTakesPrecedence` 纯函数直测（喂真 `KeyEvent` + 真注册表默认绑定，不在测试里另写键位）；`video_space_playpause_override_test.dart` 补「面板持焦裸 ↓ 让位给焦点遍历」+ 负向对照「无面板时裸 ↓ 照常调音量、焦点不动」；四条源码守卫全部重钉到新架构并**逐条变异实测**。提交：<本轮 commit>
- **备注**：窗口模式下若词典浮层可见，空格按 BUG-924 语义先关浮层而非播放，这是既有设计、非本 bug。**上提带来的一处行为范围变化（已核实无害，如实记录）**：键盘通道从 Scaffold 内挪到整页外层后，也覆盖了原先不覆盖的加载态 / 失败态 / 资源缺失态。加载态 `_controller` 为 null，`_handleVideoKeyboardShortcut` 首行早返回（与原先「被全局中和层吞掉」观感一致）；失败态 `_controller` 可能仍非空（换集失败会保留旧 controller，见 `video_fushi_page.dart` 的 `if (_controller == null) controller.dispose()`），此时按空格会切换那个旧 player 的播放状态——`playOrPause()` 内部是 `_player?.playOrPause()`，player 为空即安全 no-op，不会抛未捕获异步异常；旧音频还在响时按空格能停下它，反而是合理的。为它加 `_failed` / `_missingResource` 判据等于引入两个特例分支，不做。**真机复验留用户**：全屏 → 打开右侧字幕列表 → 空格暂停；再验上下键在列表里选行（不再调音量）、Ctrl+← 上一句、Enter 确认列表行（不弹选词光标）。
