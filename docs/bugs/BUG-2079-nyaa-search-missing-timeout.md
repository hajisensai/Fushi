## BUG-2079 · NyaaClient.search 无超时，订阅检查可被单个慢响应挂住
- **报告**：2026-09-03（PR #1178「按每周更新点调节订阅检查节奏」的审查副产物。**不是该 PR 引入的**：逐字比对 merge-base 确认旧版 `checkNow()` 早返回路径与新版一致，这条是既有账，故只记录、不在那条 PR 里修。）
- **真实性**：✅ 真 bug（既有缺口）。`fushi/lib/src/media/torrent/nyaa_client.dart:461` `final http.Response res = await _client.get(uri);` **不带 `.timeout(...)`**，整条 `NyaaClient.search` 没有任何超时。同一域的 `fushi/lib/src/media/torrent/torznab_client.dart:407` 有 `requestTimeout = const Duration(seconds: 20)` 并在 `:451`/`:640`/`:744`/`:792` 四处真的 `.timeout(requestTimeout)` —— 两个客户端对同一类失败给出的是两套语义。
- **影响（修复时复核后订正）**：原记录说「串行 drain 会被无限挂住」**不准确**——`anime_download_subscription.dart:413` 与 `anime_download_dialog.dart:497` 这两个调用点各自包了 `.timeout(kDownloadDiscoveryTimeout)`（60 s），订阅 drain 与搜索对话框其实是有界的。真正无界的是**注册表两条路径**：`nyaa_discovery_source.dart:100` 与 `nyaa_resource_provider.dart:58` 直接 `await _client.search(...)`，而它们的上游 `media_discovery_service.dart:184` 只 `try/catch` 不设时限，于是一次挂死的 Nyaa 请求会把整次多源扇出一起拖住（`Future.wait` 等最慢的那个）。根因仍是同一个：时限记在每个消费方头上，谁忘了记谁就无界；`http` 包的默认连接超时依赖平台（Dart `HttpClient.connectionTimeout` 默认为 null = 不超时），站点被墙 / 代理半开的 TCP 连接可以挂到操作系统级重传耗尽为止。PR #1178 把冷窗唤醒拉长到 2 小时后，一次挂死的窗口影响更长。
- **[x] ① 已修复**（提交 `__COMMIT__`）— `NyaaClient` 加 `requestTimeout` 字段（可注入），`_client.get(uri)` 改为 `.timeout(requestTimeout)`；`TimeoutException` 直接抛给调用方，与 `:440` 承诺的「网络故障抛出、不吞成空列表」同语义，下游 `ExternalProviderFailure.fromException` 早已把它归到 `kind: timeout, retryable: true`，无需改分类。**默认值取 `kDownloadDiscoveryTimeout`（60 s）而不是本案卷原写的 20 s**：20 s 正是 BUG-1141 从这条链路上拆掉的直连口径魔法数字（代理下握手 + TLS 常年超它），而且它比上面两个调用点的外层 60 s **更紧**，落进去等于替订阅 drain 和搜索对话框偷偷回退 BUG-1141——那是用户可见的退步，不是对齐。torznab 的索引器多是自建/本机，20 s 在那边另有依据，两边仍不合并（守卫 `download_discovery_timeout_guard_test.dart` 的消费方清单已把 `nyaa_client.dart` 收进去，并把 contains 判据改成剥注释后再判，免得 doc comment 提一句常量名就假绿）。`search` 全文只有这一处网络调用，分页由调用方传 `page` 驱动、函数内没有第二次请求，已逐行复核。
- **[x] ② 已加自动化测试** — `fushi/test/torrent/nyaa_client_test.dart`：用永不 complete 的 `Completer` 喂 `MockClient`，断言 `search` 在注入的 50 ms `requestTimeout` 后抛 `isA<TimeoutException>()`（RSS 首屏与 HTML 翻页两条分支各一条），外加一条钉默认值 `== kDownloadDiscoveryTimeout`。变异实测：删掉 `.timeout(requestTimeout)` → 两条行为测试双双挂到 flutter_test 的 30 s 上限变红；把默认值改回 `const Duration(seconds: 20)` → 值断言与 `fushi/test/torrent/download_discovery_timeout_guard_test.dart` 的 B 条同时变红。
- **备注**：只改 Nyaa 一侧，不动 torznab；两者的候选归一化与错误分类已经各自独立，不要借这条顺手合并。
