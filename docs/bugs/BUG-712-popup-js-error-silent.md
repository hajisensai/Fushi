## BUG-712 · 查词弹窗 JS 渲染报错静默、错误日志为空
- **报告**：2026-07-10（用户：TODO-1392 追问「报错中止了，为什么错误日志是空的」——BUG-706 修复说明写「渲染词条时报错中止」，用户去看错误日志却是空的）
- **真实性**：✅ 真 bug（可观测性缺陷）。根因两处，查词弹窗 JS 渲染路径抛异常永不进错误日志：
  - `hibiki/lib/src/pages/implementations/dictionary_popup_webview.dart:1488`（`onConsoleMessage`）：只把 `[LONGPRESS]` / `[RENDER_CONTENT]` / `[RICHTEXT]` / `[GLOSS_SECTION]` / `[RICHTEXT_HTML]` 五个调试前缀转写进 `ErrorLogService`；`renderPopup` 的 `console.error('[popup] … render failed', e)` 与 WebView 引擎对 uncaught 错误自发的 ERROR 级 console 消息**都不匹配任何前缀**，只落 `debugPrint`，永不进错误日志。
  - `hibiki/assets/popup/popup.js`（`window.renderPopup`，~2786）：per-section `try/catch` 只 `console.error`（吞掉后不上报），且顶层**无** `window.onerror` / `addEventListener('error')`。BUG-706 那类 `__hibikiRoot` 命名冲突使 `__hibikiContainer()`（`popup.js:6`）在 marker 被覆写成函数后调 `.querySelector` 抛 `TypeError` → 该调用在 `renderPopup` 的 `try` 块**之前**（`popup.js` 冷路径 `const container = __hibikiContainer();`），异常 uncaught → renderPopup 中止 → 弹窗空白 **且** 无任何错误日志。用户遇到 JS runtime error = 静默空白 + 日志空，无从排查。
  - 四查词表面（reader base_source_page / video dictionary_page_mixin / 首页 home_dictionary_page / app 外 popup_dictionary_page）共用同一 `DictionaryPopupWebView`，故一处缺失全表面静默。
- **[x] ① 已修复** — 根治=让 JS 报错可见（**不吞异常**）：
  - `hibiki/assets/popup/popup.js:36` 顶层装全局错误上报：`window.__hibikiReportJsError(source,message,stack)` + `window.addEventListener('error', …)`（uncaught 脚本错误，带 `error.stack` 或退到 file:line:col）+ `window.addEventListener('unhandledrejection', …)`（未处理 Promise rejection），并把 `renderPopup` 的 kanji / first-entry / rest-entries 三处 catch 路由到同一上报（BUG-706 那类中止无论 caught/uncaught 都可见）。全部经已有 `flutter_inappwebview.callHandler('reportJsError', {source,message,stack})` 桥回传；浏览器扩展镜像里 `window.flutter_inappwebview` 不存在，`callHandler` 缺失时静默 no-op（三镜像逐字节一致，扩展侧安全），上报本身失败绝不再抛（杜绝二次错误递归）。
  - `hibiki/lib/src/pages/implementations/dictionary_popup_webview.dart:936` 注册 `reportJsError` handler → 顶层纯函数 `logPopupJsError`（同文件 :1783）→ `ErrorLogService.instance.log('PopupJs.<source>', message, StackTrace.fromString(stack))`，复用 TODO-1383 的串行落盘链写进错误日志页。下次 JS 崩了用户能在错误日志看到 message + stack、能排查。
  - 三份 popup.js 同步：`hibiki/assets/popup/popup.js` / `hibiki/assets/browser_extension/vendor/popup.js` / `tools/browser-extension/vendor/popup.js`，sha256 一致 `c0e57c87d7a138db0b48bb8eeb35a49688f86e18570de495bd5dd9ebad12fe3d`。提交 __COMMIT__。
- **[x] ② 已加自动化测试** — `hibiki/test/lookup/popup_js_error_reporting_guard_test.dart`（7 用例，全绿）：① 行为——把 window.onerror / renderPopup.firstEntry / unhandledrejection 的报错 payload 喂 `logPopupJsError`，断言进 `ErrorLogService.entries`（`PopupJs.<source>` + message + stack；空 stack 不伪造栈；缺字段稳健留占位不吞）；② 源码守卫——三镜像 popup.js 都装了 `window.addEventListener('error'/'unhandledrejection')` + `__hibikiReportJsError` + `callHandler('reportJsError')` + renderPopup catch 路由；③ Dart 弹窗 WebView 注册 `reportJsError` 并调 `logPopupJsError`。摘掉任一环即转红。
- **备注**：与 BUG-706（`__hibikiRoot` 命名冲突导致的空白，已修）是同根事件的**可观测性**面——706 修了「为什么空白」，708 修「为什么日志空、下次怎么排查」。`onConsoleMessage` 的调试前缀白名单未改（避免噪声/双记），JS 报错走独立 `reportJsError` 桥，确定性带全栈。
