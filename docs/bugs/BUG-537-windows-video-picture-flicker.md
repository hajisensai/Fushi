## BUG-537 · Windows video picture layer flickers (subtitle overlay stable)
- **报告**：2026-07-03（用户：Windows 用户，打开视频画面一闪一闪的，字幕不会闪，报错日志没内容）
- **真实性**：⚠️ 待真机验证（本端 Windows 桌面有 GPU，但需 `-Visible` 离屏窗口 + 真实 GPU 呈现路径复现；离屏/无头无法可靠复现 DWM/ANGLE 呈现层闪烁）。**画面层闪、字幕叠加层不闪** = 症状定位在 media_kit/libmpv 的**画面纹理呈现路径**，而非 Flutter 侧的可点字幕 overlay（后者是 Dart widget 层，与画面纹理独立合成，故不闪）。
- **平台边界（与已修项区分）**：
  - **≠ BUG-465 / board 984**（Android/realme8 HEVC `Both surface and native_window are NULL`，已由 `720f68da7` 把 Android hwdec `auto-safe`→`auto-copy` 修）。那是 Android **mediacodec surface-直渲** 与纹理渲染不匹配；Windows 完全不同渲染路径——media_kit Windows 走 **MPV_RENDER_API_TYPE_OPENGL + ANGLE + DirectX 11**（`third_party/media_kit_video/windows/angle_surface_manager.*` / `video_output.cc`），帧画进 `ID3D11Texture2D` 经 EGLSurface 上屏交 Flutter 合成，不经 mediacodec。
  - **≠ BUG-284**（视频右侧控制按钮 hover 闪烁，已由 `_railHovered` 单一真相源修）。那是 UI chrome hover 振荡，是**按钮层**闪；本 bug 是**画面帧层**闪。
- **1119 追加线索（用户）**：「如果显卡占用过高会有黑屏闪烁的问题」——**闪烁与高 GPU 负载正相关**。这把根因强指向「GPU 负载饱和时呈现管线丢帧/黑帧」，而非纯解码问题：高负载下 D3D11/ANGLE 交换链或 EGL 共享纹理呈现赶不上刷新时，Flutter 合成拿到未就绪/旧/空纹理 → 黑帧闪。**这与候选根因 1（共享纹理时序竞态）高度吻合**——共享纹理竞态本就在高负载/高帧率下更易触发（keyed-mutex 争用、上传赶不上）。也解释「字幕不闪」：字幕 overlay 是 Flutter widget 层，不吃 GPU 视频呈现管线，负载饱和只丢视频纹理帧。
- **候选根因（待真机 `[VIDEO-DIAG]` 日志 + `-Visible` 目视坐实，按可能性排序）**：
  1. **hwdec (d3d11va/dxva2) 与 ANGLE 纹理桥的帧同步/共享纹理竞态（高 GPU 负载下加剧，best 候选）**：默认 `hwdec=auto-safe`（`video_mpv_config.dart:49`）在 Windows 可能选 `d3d11va`——硬解帧在 D3D11 纹理，交给 ANGLE EGL 上屏时若共享句柄/keyed-mutex 时序不稳，会出现旧帧/黑帧交替=闪；**GPU 负载越高越易复现**（对应 1119 线索）。诊断法：设 `hwdec=no`（软解）或 `hwdec=auto-copy`（拷回内存再上传，绕开共享纹理）看是否消失。**这是最可能的低风险修**（若坐实，可对 Windows 比照 Android 做 `auto-safe`→`auto-copy` 改写，或提示用户切软解）。降负载旁证：着色器等级调低 / sigmoid 关（本轮 BUG-538 默认已关）/ 关画质增强能减轻，即坐实是 GPU 负载饱和呈现丢帧。
  2. **`video_output.cc` 的 `Resize`/纹理重注册竞态**：`Resize` 会销毁旧 `ID3D11Texture2D`+`EGLSurface` 再建新的并重注册 Flutter texture（`video_output.cc:299-353`）。若 videoParams（w/h）在开播首帧反复抖动触发多次 Resize，纹理短暂空/旧=闪。诊断法：看 `[VIDEO-DIAG]` 的 `videoParams` 与 `texture id changed` 是否在稳态播放中仍反复变化。
  3. **DWM/ANGLE present 与显示器刷新不同步**：默认 `interpolation=false`→`video-sync=audio`（`video_mpv_config.dart:363-365`，已是安全值，非 `display-resample`），故**不太可能**是 video-sync 引起；sigmoid 上采样（本轮 BUG-538 已默认关）是 GPU 算力开销、非帧同步问题，与本闪烁**无因果关联**（sigmoid 只影响单帧上采样质量/耗时，不改变呈现时序）。
- **代码路径**：`hibiki/lib/src/media/video/video_player_controller.dart` `load()`（`Player()`/`VideoController(player)` 默认配置构造，无显式 `VideoControllerConfiguration`→Windows 用 media_kit 默认硬件加速 ANGLE/D3D 路径，第 1053-1057 行）；`third_party/media_kit_video/windows/video_output.cc`（`Render`/`CheckAndResize`/`Resize` 纹理呈现）；`angle_surface_manager.cc`（EGL/D3D11 surface 管理）。
- **[ ] ① 未修复** — REAL_VERIFY_NEEDED：需 `-Visible` 离屏窗口 + 真实 Windows GPU（疑 AMD，参照 `reference_win_video_lookup_wgc_crash` 系 AMD-WGC 敏感）复现闪烁，先开视频诊断（`onDiagLog`）拿 `[VIDEO-DIAG]` 日志坐实候选根因 1/2（高负载下是否 texture id/videoParams 抖动、软解/copy 是否止闪），再定最小改（大概率是 hwdec 改写/回退一处属性，低风险）。不硬改：未见闪烁复现前盲改 vo/hwdec 属性可能对**正常出画面**的多数 Windows 用户造成回归（Never break userspace）。
- **1119 兜底 UI 提示（用户要求：若无法根因修复则必须明示「已知问题/等解决方案」，不要静默闪烁）** — **不在本轮盲加常驻横幅**：BUG-537 尚未真机坐实，给全体 Windows 用户加「视频画面可能闪烁」的常驻告警会对**多数不闪的用户**造成误导性 UX 回归（Never break userspace，不为臆想威胁加噪）。兜底提示的正确形态待 ① 真机坐实后二选一落地：**(a) 若坐实低风险根因** → 直接根因修，无需提示；**(b) 若坐实为平台/驱动（AMD 高负载呈现）限制不可根治** → 在视频「画质增强/着色器等级」设置区（`settings_schema_video.dart` 的 `video_setting_mpv_group_quality` 段）加一条**已知问题说明 + 降负载建议**（调低着色器等级 / 关画质增强 / 切软解 hwdec），并可在检测到高负载闪烁时于视频页给一次性可关提示。此形态需真机确认触发条件后再实现，避免误报。
- **[ ] ② 未加自动化测试** — 根因坐实后于 `video_mpv_config` 层加配置守卫（若修法是 Windows hwdec 改写，比照 `resolveAndroidHwdec` 加纯函数 + 单测）；若走兜底提示 (b) 则加提示文案/降负载入口的 widget 或 schema 守卫。
- **备注**：用户报「报错日志没内容」符合呈现层闪烁特征——libmpv `open`/解码成功、无 error 流输出，问题在 present/texture 桥而非解码。1119 线索（高 GPU 负载相关）进一步坐实候选根因 1。交 integration owner 安排 `-Visible` 真机验证。1116 与 1118/1120（sigmoid 上采样）无因果关联（sigmoid 只是单帧算力开销之一，见候选根因 3；关它能小幅降负载但非闪烁根因）。
