## BUG-2928 · 有声书 VN 模式跳过三段正文：ruby 並字读音让 cue 匹配越过中间句子
- **报告**：2026-10-04（用户：录屏，『やはり俺の青春ラブコメはまちがっている。』1 卷 VN 模式跟读有声书，「そういえば聞いたことがある……」之后直接跳到「三浦が驚愕のあまり呟く」那屏，中间「空気を読まない材木座…」「勝手に名前付けんなよ…」「ありえないし……」三段从没出现，『風精悪戯？』那条高亮停了 23 秒）
- **真实性**：✅ 真 bug，不在 VN 排版，在有声书对齐。用户库 `audio_cues` 第 6015 条「『風精悪戯？』」（`s=40&ns=5640&ne=5644`）跨 06:36:03.450–06:36:26.892：ASR 字幕第 5628–5633 条（「おいれんシルフィード」…「…それがやがてい」）全被并到后一处 ruby 上，VN 跟着 cue 从第 148 屏跳到第 152 屏。根因在 `packages/fushi_audio/lib/src/matching/epub_srt_matcher.dart`（修复前行号）：
  - 这本书的 ruby 按传统排版**不用小書き仮名**（`風精悪戯`→「オイレン・シルフイード」，`驚愕`→「きようがく」），ASR 吐现代写法「シルフィード」。读音轨（`:1084` 起建）与 cue 的归一化都不折小假名，第一处 ruby 在读音轨上只拿到 Dice 0.78，过不了 0.8 阈值；
  - bigram Dice 不看顺序：窗口骑在后两处**紧挨着**的同读音 ruby 之间（「…んしるふいーど|おい…」）反而凑出 0.82，模糊命中换回基底轨时一律向外扩（`:508` `toBaseStart`），落成 `ns=5640-5648`，游标越过七句正文，后面五条全 miss、回填也补不回来；
