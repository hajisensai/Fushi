## BUG-2970 · Emby 媒体服务器搜索少于四个字搜不到
- **报告**：2026-10-05（用户：群友「雪」，「emby 少于四个字的都搜不到」；服务器类型 / 版本未知，无法连上用户服务器复现）
- **真实性**：✅ 真 bug（按代码路径定位，未在用户服务器上实测）。客户端链路上**没有**任何最小长度门槛：搜索页只有 350ms 防抖（`media_server_grid_view.dart:_scheduleSearch`），`mediaServerSearchTokens` / `mediaServerSearchMatches`（`media_server_search_match.dart`）对 1 个字的 CJK 词同样做子串匹配，请求用的是 `SearchTerm` + `Recursive=true` + 单值 `IncludeItemTypes`。真正的根因是排序：
  - `fushi/lib/src/sync/jellyfin_video_client.dart` 的 `JellyfinApi.items()` 把 `SortBy=SortName&SortOrder=Ascending` 写成默认值，`search()`（上游 `:2407` 那一发 `api.items(...)`）没有覆盖它，于是每次搜索都强制按名称排序。带 `SearchTerm` 时 Emby / Jellyfin / 兼容层缺省按**相关度**排；按字模糊的服务器（BUG-2608 的 UHD Media Server 兼容层，伪装 Emby）对 1~3 字的短查询会回几千行只沾一个字的结果，按名称排序后真命中被打散到这几千行中间，超出 `kSearchScanLimit`（500 行）扫描上限，BUG-2608 的把关再把沾边行全部滤掉，结果为空或要翻很多页才出现。查询词越长，沾边行越少，扫描范围才能覆盖到真命中，这就是「四个字以上才搜得到」的长度门槛。
  - 叠加的第二处：`search()` 把「电影轮在前、剧轮在后」拼成一条序列，**每轮扫到底**才进下一轮。在按字模糊的服务器上，短查询让电影轮回几千行沾边结果，把整次调用的 `kSearchScanLimit`（500 行）全部用完，剧轮里的真命中第一页根本扫不到，页面要靠自动翻很多页才能翻到它。修复后的定向测试首轮跑红 4 条（剧集类的短查询全空，电影「千寻」通过），证实了这一点。
  - 原版 Emby 4.10 用「按空格分词 + 词首前缀」匹配（BUG-2608 用 docker 实测过）：CJK 标题没有空格，整个标题是一个词，标题中段的子串（例如在「葬送的芙莉莲」里搜「芙莉」）由**服务器**判为不命中，客户端补不回来。如果「雪」用的是原版 Emby，这一部分还需要拿到对方的服务器版本和具体查询才能继续定位，见备注。
- **[x] ① 已修复** — `api.items()` 的 `sortBy` / `sortOrder` 改为可空，为 null 时不发送；`JellyfinVideoClient.search()` 显式传 null，把排序交还服务器（带 `SearchTerm` 时即相关度排序）。浏览路径（`listChildren` 等）仍按用户选的排序，不受影响。同时在扫描循环里加了一条：结果按相关度排序时，一整页（100 行）都过不了把关，就说明本轮后面只剩沾边行，直接跳到本轮末尾去扫下一轮（`localStart = roundTotal`）。子串语义（Jellyfin）和词首前缀语义（原版 Emby）的服务器返回的每一行都能过把关，这条不会触发。提交：见分支 `claude/sh-emby-home-versions` 中 `fix(media-server): ... BUG-2970` 提交。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/media_server/jellyfin_search_short_query_test.dart`：假服务器按字模糊回 1500 行沾边结果，带 `SortBy=SortName` 时真命中埋在第 1200 行之后、不带时按相关度排在最前；断言 2 字中文（芙莉 / 千寻）、1 字中文（莲）、2~3 字日文（ゆる / キャン，按原名命中）都能搜到且排第一，并断言请求带 `SearchTerm`、`Recursive=true`、单值 `IncludeItemTypes`、`Fields` 含 `OriginalTitle`，且不带 `SortBy` / `SortOrder`；`jellyfin_media_server_test.dart` 的 BUG-2608 组改写原来的「900 条沾边电影」用例：请求序列变成 `Movie@0, Series@0`，第一页就能拿到剧集的命中；另外新增一条「每行都命中的 900 部电影」用例，用来钉住 `kSearchScanLimit` 的分页语义。
- **备注**：没有在用户服务器上实测。如果修复后仍搜不到，需要让用户提供服务器类型 / 版本，并用 `fushi/test/sync/media_server_live_search_probe_test.dart` 打一次短查询：看服务器回了几行、真命中排在第几行。如果是原版 Emby 的词首前缀语义导致标题中段子串搜不到，那是服务器侧的限制，要另外设计回退方案（比如按库列名称后在本地过滤，要权衡对大库的请求量，参考 BUG-1891），不能靠改排序解决。
