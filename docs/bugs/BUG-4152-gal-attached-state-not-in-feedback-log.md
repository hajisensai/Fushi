## BUG-4152 · attached 表面隐藏多久、为什么隐藏，反馈日志里查不到
- **报告**：2026-11-06（应用内反馈 Ny1bK1hFeJ，GitHub issue #2948，Windows 3.3.0-debug.23880，ZATO / Ren'Py 独占全屏，150% DPI：BUG-4046 之后仍是「制卡后点下一个词不弹查词卡」；报告人用 500 ms 窗口采样记下 attached 表面从 12:39:46 隐藏到 12:40:13 才重新出现，并推断查词卡 placement 跳屏外、主窗前台锁。报告人还指出 `error_log.txt` 里没有任何 `gal-shield` / `gal-click` 行，出问题时无法从日志定位）
- **真实性**：报告的三条判断逐条沿代码验：
  1. **「查词卡打开期间 attached 表面一直隐藏」——设计行为，不是挂起**。attached 点词打开的桌面查词卡带游戏 HWND 做「点卡外吞点击」，显示时 `ArmLowLevelMouseHookAndWait`（`fushi/windows/runner/global_lookup_window.cpp:1465`）拿走进程内唯一的 `WH_MOUSE_LL`；attached 表面每 500 ms 的 `SyncToTarget` 在 `SetVisible(true)` 里 `ArmLowLevelMouseHookForAttachedGlyph` 失败，按设计隐藏并报 `suspended/mouseHookBusy`（`attached_text_surface_window.cpp` `SyncToTarget` 末段），此时 Shift 悬浮查词仍可用（`HoverLookupGeometryAvailable`）。所以 27.6 s 里 12:39:46→12:40:02 是卡片在屏上的时间。
  2. **「查词卡 placement 跳到 x=1840 屏外」——❌ 不是 bug**。`GlobalLookupWindow::OffscreenX()`（`global_lookup_window.cpp:1185`）= 虚拟桌面右缘 + 200：物理 2560 + 200 = 2760，报告人的采样脚本按 150% 逻辑坐标读回正是 2760 / 1.5 = **1840**，y=0 也对得上。这是 WebView2 先离屏测量 / 游戏内查词位图采集面（`ResizeOffscreen`）的停放位，设计上就在屏外、随后才 Reveal 到词旁，不缺 clamp。
  3. **「主窗 SetForegroundWindow 唤不到前台」——未改**。报告里的 `main_window_test.ps1` 是**另一个进程**在独占全屏游戏持有前台时调 `SetForegroundWindow`，按 Windows 前台锁规则必然被拒，这个实验证明不了 Fushi 自己的路径；用户从任务栏点 Fushi 图标时由 shell 授予前台，不受此限。BUG-4046 第 4 条「只有任务栏」仍没有能落到某一行代码的证据。`AttachThreadInput` / 临时 topmost 这类绕过前台锁的手段属于掩盖外部限制，没有证据前不加。
  4. **真正查不清的是卡片 12:40:02 隐藏后表面又过了 11.5 s 才回来**：这段时间表面在 `SyncToTarget` 的十几道闸门（`targetBackground`、`shieldHandshakePending`、`geometryProviderPending`、`mouseHookBusy`…）里卡在哪一道，只能看状态时间线。而 ✅ **诊断链确有缺口**：一是 native 状态转换本身没有任何日志（`EmitStateIfChanged` 只回调 Dart，`attached_text_surface_window.cpp:3156` 起）；二是 `gal-shield:` / `gal-click:` / `lookup hide` 这些行只写进 `%TEMP%\hibiki_glookup.log`（`global_lookup_log.dart` `_logPath`、`global_lookup_window.cpp:401` `NativeGlog`），而反馈附日志的唯一汇总点 `collectFeedbackLogText`（`fushi/lib/src/feedback/feedback_diagnostics.dart:314`）只收错误日志与调试日志——BUG-4046 让用户「附日志再查」，附上来的日志里永远没有这些行。
- **[x] ① 已修复（诊断缺口）** — native 每次「state/status/reason/visible」四元组变化写一行 `gal-attached: state … tick=… held_ms=… from …`（`AttachedTextSurfaceWindow::LogStateTransition`），上一个状态持续多久直接写在行里；反馈日志（与调试日志同一道用户开关，闪退报告不带，仅 Windows）新增「game lookup diagnostics」一节，从 `hibiki_glookup.log` 末尾 2 MB 摘**白名单前缀**的结构化行（`gal-attached:` / `gal-shield:` / `gal-click:` / `gal-ingame:` / `gal-overlay:` / `global click` / `lookup hide|reveal|activation|repark`，最多 600 行；带查询词 / 台词的行不在白名单里），实现在 `fushi/lib/src/feedback/feedback_gal_lookup_log.dart`。**制卡后表面晚恢复的根因本身未修**：没有状态时间线，无法确定是哪道闸门，按规则不猜改。
- **[x] ② 已加自动化测试** — `fushi/test/feedback/feedback_gal_lookup_log_test.dart`：白名单行（Dart / `[native]` 两种格式）保留、带词的 `lookupText` 行与其它 native 行剔除、只留最近 N 行、文件不存在返回空、只读末尾并丢弃被截断的首行。native 转换日志只有 Windows runner 构建能验，没有行为级单测。
