## BUG-778 · 覆盖整库保留设置冲掉本地音频注册
- **报告**：2026-07-13（用户：qqbotxiaoxiao）
- **真实性**：✅ 真 bug。覆盖整库导入的 UI 默认是「保留本机设置」（`importSettings=false`，`hibiki/lib/src/sync/sync_settings_schema/backup.part.dart` 默认值），走 `BackupService._restoreSettingsLayer`（`hibiki/lib/src/sync/backup_service.dart`）。旧实现 `DELETE FROM preferences WHERE key NOT LIKE 'audiobook_pos_%'` + `INSERT ... FROM bak WHERE key NOT LIKE 'audiobook_pos_%'`，把**除 audiobook_pos 外的所有 pref** 从本机导入前快照 `bak` 整体回填，包括内容注册类 `local_audio_dbs` / `audio_source_configs`。于是备份随 DB blob 带来的本地音频注册被删掉、换成本机（通常为空）的值：step 2c 已把 `local_audio_*.db` 文件拷进来了，但注册没了 = **文件在、本地音频静默失效**。对比：合并模式（`BackupMergeEngine._mergeAudioSourcePrefs`，BUG-744）和覆盖模式 `importSettings=true` 分支（`_restoreExcludedSettingsLayers` 用 `settingsPrefPredicate`）都正确把这些内容注册类 pref 排除在「设置回填」之外，唯独默认的 `_restoreSettingsLayer` 用了粗糙的 `NOT LIKE 'audiobook_pos_%'`。
- **[x] ① 已修复** — 提交 `a46767c94`。新增 `_keepDeviceSettingsPrefPredicate`（= `settingsPrefPredicate` 的内容注册集：favorites / local_audio_dbs / audio_source_configs / 字体注册交还备份，但**保留 `sync_*` 从 bak 恢复**——keep-settings 路径无 sidecar 补 sync，是设备同步配置的唯一保留点）。`_restoreSettingsLayer` 的 DELETE/INSERT 改用该谓词。两条恢复路径（keep-settings vs excluded-settings）对「内容 vs 设置」分类从此一致。顺带救回同样被误删的 favorites、字体注册 pref。
- **[x] ② 已加自动化测试** — `hibiki/test/sync/backup_import_keep_settings_local_audio_test.dart`：真实 export→overwrite-import（`importSettings:false`）路径，断言导入后 `local_audio_dbs` 跟随备份（displayName='声優' 存活、`.db` 文件跨机重挂到本机目录）、纯设置 `test_pure_setting` 保留本机值、设备 `sync` backend 保留本机值。既有 66 个备份回归测试（backup_import_preserve / backup_local_audio_portability / backup_categories 等）全过。
- **备注**：`_restoreSettingsLayer` 也是 `recoverPendingImport` 的 `mode:settings` 崩溃恢复路径，故修复对崩溃恢复一致生效。待真机验证覆盖整库导入后本地音频真能发音。
