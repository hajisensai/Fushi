## BUG-2815 · 无头服务端不托管本地音频库：列表恒空、上传传完才报 UnsupportedError
- **报告**：2026-09-30（无头服务端完成度盘点：本地音频库仍是「与原设计的偏差」）
- **真实性**：✅ 真 bug。`packages/fushi_server/lib/src/headless_host.dart:485`（`_buildLibraryService`）只传了 `localAudioStagingDir`（:506），没接 `localAudioEntries` / `onLocalAudioImported` / `removeLocalAudioEntry`：`/api/library/localaudio` 清单恒空，客户端「上传本地音频到 host」在包传完后落到 `packages/fushi_engine/lib/sync/local_library_host_service/local_audio.part.dart:58` 抛 `UnsupportedError`，删除静默 no-op；而能力位 `liveLibrary.audio` 仍报 true。同一处还有一个 app 也中招的形态问题：host 服务只在互联启动时构造一次，`fushi/lib/src/models/app_model.dart:697` 传的 `localAudioEntries: localAudioDbs` 是那一刻的快照，之后新增 / 删除的库对端清单与导出都看不见（新推上来的库导出报 not found）。另外推送解包到 staging 的 DB 从不删除，每推一次在临时目录攒一份（库动辄几百 MB）。
- **[x] ① 已修复** — 按词典包的「存储中转」形态：新增引擎 `packages/fushi_engine/lib/sync/local_audio_library_store.dart`（`LocalAudioLibraryStore`：库副本 `<support>/local_audio_<n>.db`、登记 `local_audio_dbs` 偏好，与 app `LocalAudioManager` 同目录同键同形；按 displayName 去重；只做 SQLite 魔数校验；删除连带 -wal/-shm），服务端 `HeadlessHost.localAudio` 接上清单 / 导入 / 删除三件。`LocalLibraryHostService` 新增 `localAudioEntriesProvider`（现读，优先于快照），app 与服务端都改用它；`importLocalAudio` 回调后删除 staging 解包副本。服务端不做查词发音。
- **[x] ② 已加自动化测试** — `packages/fushi_server/test/local_audio_host_test.dart`：push → 同一服务实例立即列出 → 导出给另一台客户端解包字节 / enabled / 子来源一致、staging 无残留；重启（新偏好缓存 + 新 host）后清单仍在；delete 摘登记并删副本；重名推送不覆盖；登记键形与 app 一致；非 SQLite 包拒绝且不登记。变异实测：去掉三件接线 → 4/4 红（UnsupportedError）；provider 换回快照 → 2 条红。app 侧守卫 `fushi/test/sync/server_lifecycle_appmodel_guard_test.dart` 改钉 `localAudioEntriesProvider: () => localAudioDbs`。
- **备注**：服务端不消费聚合同步里的 `localaudio` 墓碑（服务端对任何域都不消费墓碑，非本条范围）；删除只经 `/api/library/localaudio/<name>` DELETE 生效。
