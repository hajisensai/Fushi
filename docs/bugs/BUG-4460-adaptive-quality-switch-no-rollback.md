## BUG-4460 · 自适应换档失败后共享档位不回滚，重试仍用没起来的档
- **报告**：2026-11-10（用户：互联远程长任务审查 R11(b)）
- **真实性**：✅ 真 bug。`fushi/lib/src/pages/implementations/video_fushi/quality.part.dart:416`（修复前）`_applyAdaptiveQuality` 先 `client.adaptiveQualityIndex = decision.targetIndex` 再停旧会话、`_loadRemoteEpisode`；后者失败只在内部置 `_failed`（`fushi/lib/src/pages/implementations/video_fushi_page.dart:5096-5104`），共享档已是目标档、不回退。页面「重试」与进程级单例 `InterconnectSyncBackend` 的下一次同 scope「自动」起播（`interconnect_sync_backend.dart` `remoteVideoStreamUrls` 只在 `adaptiveQualityIndex == null || scope 变了` 时重定起点）都会沿用这个没起来的档。同条审查里「`unawaited(_applyAdaptiveQuality)` 导致未捕获 zone error」不成立（`_loadRemoteEpisode` 主体在 try 内，`_reportRemotePlaybackStopped` 自带 try/catch），不修。
- **[x] ① 已修复** — 654bed4b8e9：`fushi/lib/src/sync/interconnect_adaptive_quality.dart` 新增纯函数 `runAdaptiveQualitySwitch`（写入目标档 → 重载 → 返回 false 或抛错时回滚原值，且只在共享档此刻仍是本次目标时回滚，换档途中用户手动选档 / backend 因换链路重定起点不被覆盖）；`_applyAdaptiveQuality` 改走该事务，`reload` 返回 `mounted && !_failed`，失败时不弹「已自动调整」OSD 并 `_adaptiveQuality.reset()`。覆盖范围只到取流 / 起播阶段：`_loadRemoteEpisode` 返回之后播放器异步暴露的失败（转码分段 503 / 410 等）不在事务内，走页面既有的播放失败路径。
- **[x] ② 已加自动化测试** — `fushi/test/sync/interconnect_adaptive_quality_test.dart` group「换档事务（失败回滚）」5 条（返回 false 回滚 / 抛错回滚并重抛 / 成功保持目标 / 外部改值不覆盖 / 原值 null 回滚到 null）；`fushi/test/pages/video_interconnect_original_quality_guard_test.dart` 源码守卫钉住 `_applyAdaptiveQuality` 走 `runAdaptiveQualitySwitch(` 且不再直写目标档（修复前红）。
- **备注**：待真机复测：Windows 开发版连互联 host 播放、「自动」档，触发换档的同时停掉 host（`/streamurl` 失败），确认失败后重试用的是原档。
