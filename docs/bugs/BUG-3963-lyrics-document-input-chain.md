## BUG-3963 · lyrics-document-input-chain
- **报告**：2026-11-02（用户：应用内反馈 NmpRV-amTY + PHs18V7U3K）——阅读器歌词模式点了「↺ 跟随音频」后 Space / Esc 失灵；点词出查词弹窗后 Esc 关不掉弹窗（Windows / macOS）。
- **真实性**：✅ 真 bug（沿代码确认，未真机复现）。歌词独立文档是「二等输入公民」：① 没有键桥（`fushi/lib/src/media/audiobook/lyrics_mode_html.dart` 原 870 行只有记录型 keydown 监听），WebView 抢走 OS 焦点后按键只到 DOM；② 「跟随音频」胶囊 `#ly-follow` 的 pointerup（`lyrics_mode_html.dart` 原 1387-1395）只调纯 JS `_lyResume`、中键点句 `onLyricsPointerSeek`（`reader_fushi/lyrics.part.dart` 原 1324-1336）都不回收焦点；③ 焦点判据 `_canOwnReaderFocus`（`reader_fushi_page.dart` 原 5108-5109、5136）以「歌词自有焦点路径」为由在 popupRendered / appResumed / overlayClosed 上一律对歌词让位，而这条路径不存在——点词出弹窗后焦点留在歌词 WebView，Esc 永远到不了 `_handleKeyEvent`。
- **[x] ① 已修复** — 「歌词模式下 `_focusNode` 仍是唯一键盘入口」：判据抽成纯函数 `readerCanOwnFocus`（`reader_fushi_page.dart`），popupRendered 不再排除歌词态，appResumed / overlayClosed 歌词态同样归位，只有加载触发的 contentReady / surfaceRemounted 仍对歌词让位（BUG-767 loadData 后夺焦闪烁）；歌词文档注入共享 `webViewKeyBridgeScript(handlerName: 'onLyricsKey')`，token 由 `lyricsKeyBridgeTokens` 按注册表当前绑定导出（`kLyricsBridgedActions` + 裸 Space），Dart 侧 `onLyricsKey` 用与正文 / spread 同一套解析（Space → `_resolveWebViewSpaceAction`，其余 → `resolveSpreadKeyBridgeAction`）执行后 reclaim；胶囊回 `onLyricsFollowResume`、中键点句都 reclaim。（未提交，由 orchestrator 统一提交）
- **[x] ② 已加自动化测试** — `fushi/test/pages/reader_lyrics_key_bridge_test.dart`（判据矩阵 / 键表与反解析 / 生成 HTML 契约 / 接线守卫）；同步更新 `fushi/test/reader/dismiss_dict_pointer_and_focus_guard_test.dart`、`fushi/test/reader/reader_chrome_focus_guard_728_test.dart` 到新语义。
