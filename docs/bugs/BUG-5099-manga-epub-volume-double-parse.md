## BUG-5099 · 漫画 EPUB 整卷导入在调用 isolate 上重复解析（HBK-AUDIT-013）
- **报告**：2026-11-22（外部审计 Codex 2026-11-21 PR 审查 HBK-AUDIT-013，来源 PR #3808）
- **真实性**：✅ 真 bug。`packages/fushi_engine/lib/media/manga/manga_archive_importer.dart` 的 `importArchive` 纯图 EPUB 分支（修前 `:663` / `:673`）在调用 isolate 上同步调两遍 `EpubParser.parseSyncFromPath`：第一遍只解 container / OPF / spine 文档判纯图，第二遍解页图——每遍各自 `ZipDecoder().decodeBuffer` 读一次中央目录、`parseFromExtracted` 解析一次 container / OPF / spine，再由两份 `EpubBook` 各扫一遍章节页图引用（`_pureImageEpubRejection` 与 `_copyEpubPages`）。App 里这条调用链在 UI isolate 上（导入对话框 → `importArchive`），整段同步执行。实测（`fushi/test/media/manga/manga_import_parse_once_test.dart` 在修前代码上）：一次 3 页整卷导入在调用 isolate 上中央目录读 2 次、OPF / spine 解析 2 次。
- **[x] ① 已修复**（92df801c07）— `EpubParser.openStagedFromPath`（`packages/fushi_engine/lib/epub/epub_parser.dart`）：中央目录只读一次、按 `deferEntry` 分两段解压，第一段解析出的 `EpubBook` 直接复用（章节 / 资源表 / 系列只由 OPF 与 spine 文档决定，补解页图不改变它们）；`parseSyncFromPath` 改成它的单段特例。`MangaArchiveImporter.stageImageEpub` 把「解析 → 判纯图 → 补解页图 → 按 spine 挪页 → 系列元数据」做成只碰文件的一段，`importArchive` 经 `_stageImageEpubInBackground` 放进一次 `Isolate.run`，解压进度经 `ReceivePort` 逐条送回、以结束标记收尾；否决理由回主 isolate 再记日志、抛 `MangaArchiveNotMangaException`。修后：调用 isolate 上中央目录 / OPF 解析 0 次；后台一段内各 1 次。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_import_parse_once_test.dart`「HBK-AUDIT-013」组：整卷导入后调用 isolate 上 `(debugZipDirectoryReadCount, debugParseFromExtractedCount) == (0, 0)` 且页序 / 进度逐条推进不丢；`stageImageEpub` 直调各计 1 次；文字 EPUB 在页图落盘前被否决。变异实测：三个源文件换回修前实现（只保留计数器）后该用例红，`Expected (0, 0) / Actual (2, 2)`。
- **备注**：未做真机 UI 帧时间测量（缺口）；中央目录在主 isolate 上还被 `_open` 读一次（ZIP / EPUB 共用的预算与 mokuro 探测，不属本条重复解析）。
