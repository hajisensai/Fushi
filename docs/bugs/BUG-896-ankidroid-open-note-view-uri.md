## BUG-896 · AnkiDroid 中打开卡片失败：ACTION_VIEW note URI 无 activity 处理
- **报告**：2026-07-18（用户：）
- **真实性**：✅ 真 bug。根因 `hibiki/android/app/src/main/java/app/hibiki/reader/AnkiChannelHandler.java:624` 的 `openNote()`——旧实现对 note ContentProvider URI（`content://com.ichi2.anki.flashcards/notes/<id>`）发 `ACTION_VIEW`，但 AnkiDroid **没有任何 exported activity** 过滤该 note URI / 其 mimeType（`vnd.com.ichi2.anki.note`），该 URI 只被 ContentProvider 服务（query/insert）。故 `intent.resolveActivity(...)` 恒为 `null` → `openNote` 返回 `false` → Dart `AnkiRepository.openNoteInAnki` 返回 `false` → note viewer `_openInAnki` 弹「无法在 Anki 中打开这张卡片。」（`anki_mined_card_action_sheet.dart:266`）。
  桌面 AnkiConnect 分支（`guiBrowse(nid:<id>)`）已用用户真实 API key 实测成功，正常；本 bug 仅 Android。
- **[x] ① 已修复** — `openNote()` 改用 AnkiDroid **exported** 的 `CardBrowserDeepLink` 别名深链：`ACTION_VIEW` `anki://x-callback-url/browser?search=nid:<id>`（scheme=anki / host=x-callback-url / path=/browser，`search` 参数直接喂给 Card Browser，`nid:<id>` 过滤到该 note）。保留 `resolveActivity` 守卫：太旧、无此深链的 AnkiDroid 仍优雅返回 `false`（沿旧行为弹 toast，不崩）。`AnkiChannelHandler.java:624`。提交：c6c09ead2
- **[x] ② 已加自动化测试** — `hibiki/test/anki/anki_open_note_deeplink_guard_test.dart`：源码扫描守卫，截出 `openNote` 方法体，断言①含 `anki://x-callback-url/browser?search=` + `nid:`、②不再含 `Note.CONTENT_URI`、③仍保留 `resolveActivity`/`return false`/`startActivity` 优雅降级。3 test 全绿。native intent 无法在 Dart 单测里真实拉起，最强可落地层即源码守卫；真机（AnkiDroid 已装）复测「note viewer → 在 Anki 中打开」为门 B 待办。
- **备注**：AnkiDroid 深链依据（main 分支 manifest `CardBrowserDeepLink` 别名 → `IntentHandler.isBrowserDeepLink` → `CardBrowser` 读 `search` query）与 issue #11885 一致。
