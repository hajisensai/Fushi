## BUG-4812 · SRS 卡面视频片段加载不了时不落占位，等它播完的复习音频序列永远不返回
- **报告**：2026-11-17（小说 / 漫画 / 视频优化清单复核 gap-vidmisc-7）
- **真实性**：✅ 真 bug（代码路径确证，未在真机上用坏文件复现）。根因 `fushi/lib/src/pages/implementations/srs/srs_card_video_clip.dart:45-74`（修前）：`SrsCardVideoPlayer` 抽象只有 `playingStream` / `completedStream` / `videoSizeStream`，没有错误出口；`_open`（修前 `:445-461`）只在 `player.open` **抛异常**时才落「视频未同步」占位，`_startRun`（修前 `:504-525`）起播后只等 `completedStream` 发 true。而 media_kit 对加载不了的文件（0 字节、没有 moov、认不出格式）既不让 `open` 抛、也不发 `completed`——`completed=true` 只来自 `eof-reached`（`ci/patches/hosted/media_kit-1.2.6/lib/src/player/native/player/real.dart:2204-2218`），错误只进 `errorController`（同文件 `:2372-2407`）。结果：卡面是一块黑框，`SrsCardVideoChannel.playToEnd` / `playToEndOrElse`（无超时）等这段片段播完的那一步永远不返回，后面的音频不播，直到用户手动点一下或翻卡。触发面：同步没传完的媒体、写了一半的片段；尾部截断但还能解码的文件会正常走到结尾，不受影响。
- **[x] ① 已修复**（912ca5eb8c5，判据在审查后改过一次）— `SrsCardVideoPlayer` 加 `loadFailedStream`：[open] 的文件加载不了时发一次。生产实现的判据是 mpv 自己的状态而不是错误日志——加载不了的文件让播放器回到空闲（`idle-active` 变回 `yes`），加载成功的文件有 `keep-open`、播完也不回空闲：发加载命令前先订阅 `idle-active` 并等到初值，之后再出现的 `yes` 即加载失败；加载命令受理后再读一次，补上「失败得太快、核心没采到过非空闲、因而没有变化事件」的情况。卡面片段订阅它 → `_failLoad`：作废进行中的序列播放（等待中的以 false 结束）、释放播放器并撤销登记（之后的序列退回只播音频）、画「视频未同步」占位。`open` 抛异常的旧分支并到同一个 `_failLoad`。**第一版**用的是「还没拿到画面尺寸时错误流里的任何一条 = 加载失败」，审查指出 media_kit 的错误流就是 mpv 的 `error` 级日志（`real.dart:2373-2407`），硬解打不开再回退软解的可播片段会在尺寸到达前报一条 `vd` 错误而被判死，纯音频片段也永远没有尺寸，故弃用；错误流现在只进诊断日志。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_card_video_clip_test.dart`：「BUG-4812 播放器判加载失败：序列以 false 结束、落「视频未同步」占位、释放播放器」「BUG-4812 没起序列时判加载失败：同样落占位，之后的序列退回只播音频」「BUG-4812 已拿到画面尺寸后才判加载失败：同样结束序列并落占位」（真 widget + 假播放器）。生产播放器的判据本身进不了 `flutter test`（加载不了 libmpv），用真 libmpv 跑过一次探针，见备注。
- **备注**：判据用 Windows 的真 libmpv（`libmpv-2.dll`，补丁版 media_kit 1.2.6，纯 Dart 脚本、不带 `VideoController`）验过：0 字节文件、截到没有 moov 的 mp4、乱码文件、不存在的路径各 3 次都判失败（`open` 不抛、`completed` 不发，前提成立）；正常的 H.264 mp4、VP9 webm、纯音频 m4a 各 3 次都不判失败并播到结尾。同一次探针里「收到错误日志时去读 `idle-active`」有一次读到 `no`（日志先于核心回空闲），所以没有用「出错时查状态」当判据。**没验的**：带 `VideoController` 的真 app 路径、Android / iOS / macOS、硬解回退场景——待真机。
