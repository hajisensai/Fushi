## BUG-4127 · 歌词模式跨章时歌词页整页重新加载（下一章文字已在窗口里仍刷新）
- **报告**：2026-10-31（用户：应用内反馈 NSP86pcPHI，Windows 桌面，《七つの魔剣》，整书 cue 窗口）
- **真实性**：✅ 真 bug。沿真实代码路径：进歌词模式 `_toggleLyricsMode` 调 `setReaderFollowOverride(true)`，正文在覆盖层下跟着音频跨章；每装一章 `webview.part.dart:3325` 调 `_injectAudiobookBridge()`，它在末尾（base `4c4c7505a3` `fushi/lib/src/pages/implementations/reader_fushi/mining.part.dart:739-743`）只要处在歌词模式就 post-frame 无条件 `_loadLyricsPage()`——重选窗口、重生成 HTML、整页重载、`_lyricsPageReady=false`。这段是覆盖层 / 整书滑动窗口架构之前（69a184e7763）留下的，没判断窗口数据源是否真变了；而同一函数里 `_onCueChanged()` 已经走 `_syncLyricsOverlayCue`，后者对无整书 cue 的书按章 cue 列表身份自己决定重载、对整书窗口只在播放句移出窗口时重载。另：跨章过渡中 `setAllBookCues`（`fushi/lib/src/media/audiobook/audiobook_controller.dart:1429`）把 `_playbackAllBookIdx` 清成 -1，`lyricsCueAllBookIdx` 退回冻结的正文跟随句，装章那一刻歌词高亮会往回跳一下、下一个 tick 再跳回来。三种 view mode（paginated / continuous / vn）的音频跨章都走 `_handleCueCrossChapter → _navigateToChapter` → 章载入 → `_injectAudiobookBridge`，共用这一条路径。
