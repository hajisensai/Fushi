## BUG-724 · 有声书正文中间插图:当前句cue锚点是含图容器时compareDocumentPosition只判PRECEDING位漏检导致不暂停不去遮罩
- **报告**：2026-07-11（用户：正文中间插图，音频读到时既不「遇图片暂停」也不去防剧透遮罩）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/media/audiobook/audiobook_bridge.dart:59`（`__hoshiImageBetween`）与 `:99`（`__hoshiRevealBlurredBetween`）。检测（暂停）与去遮罩共用「上一句锚点 prev → 当前句锚点 el 之间是否跨过 img/svg」的判定，两处 `b` 侧都只用 `b.compareDocumentPosition(m) & DOCUMENT_POSITION_PRECEDING` 判「图在当前句之前」。`compareDocumentPosition` 用 `PRECEDING(2)`/`FOLLOWING(4)` 表「前/后」，但一个节点**包含**另一个时改用 `CONTAINS(8)`/`CONTAINED_BY(16)` 位。sasayaki 锚点解析 `__hoshiSasayakiAnchorEl` 以 `startContainer.parentElement` 兜底，极易得到一个**包含该插图的段落容器**作为当前句锚点 `el`（归一化后的 `b`）；此时 `b.compareDocumentPosition(img)=CONTAINED_BY|FOLLOWING=20`，`& PRECEDING=0` → 判「图不在当前句之前」→ 漏掉图 → `onImageDetected` 不发（不暂停）、`blurred` 类不移除（不去遮罩）。真实代码 + 真实 DOM（jsdom）复现：含图容器场景 `cb=20`、旧判据漏检；标准兄弟排版 `cb=2` 正常。前锚点包含图（`ca=20`，`FOLLOWING` 位已含 `CONTAINED_BY`）本就命中，故只需修 `b` 侧。
- **[x] ① 根因修复** — `audiobook_bridge.dart:59` / `:99` 两处 `b` 侧判据 `& DOCUMENT_POSITION_PRECEDING` → `& (DOCUMENT_POSITION_PRECEDING | DOCUMENT_POSITION_CONTAINED_BY)`，把「图被当前句锚点容器包含」纳入「已跨过」。不改 `a` 侧、不破坏「图在区间外不误检」的边界。提交：849db60
- **[x] ② 自动化测试** — `test/js/audiobook_image_pause.test.mjs`（jsdom 真实 DOM 行为测试，从真实 bridge 提取 `__hoshiImageBetween`/`__hoshiRevealBlurredBetween`，检测+去遮罩 × 4 排版共 8 用例）。红→绿已在真 worktree 验：未修复 `node --test` exit=1（含图容器的检测+去遮罩 2 用例红），修复后 exit=0 全 8 绿。这是必要层——现有 `hibiki/test/media/audiobook/image_pause_detection_test.dart` 是纯源码字符串扫描，不执行判据，测不出本类位语义 bug（故当初没拦住）。
- **备注**：真机端到端未复测（按用户要求本轮先不真机；真机验收：真有声书 + 防剧透模糊开 + 图片暂停开，音频读到「与正文同段落容器内」的插图 → 应暂停、去模糊、翻回仍不模糊）。同类隐患链：`__hoshiSasayakiAnchorEl` 的 `parentElement` 兜底把台词锚点放大到含图段落容器是触发前提；更根本的修法可让锚点解析优先落到文本自身包裹的行内元素。相关：BUG-007（图片暂停假功能）。
