## BUG-550 · ffmpeg 7.1.5 本地构建二进制崩溃破坏视频制卡
- **报告**：2026-07-05（用户：视频制卡崩溃）
- **真实性**：✅ 真 bug（回归）。根因不在 Dart 调用路径，而在入库的 Windows min-CLI 二进制本身。V35（`48e426f96` chore(ffmpeg) n7.1→n7.1.5，TODO-1137）把 `third_party/ffmpeg-min/windows/ffmpeg.exe` 换成**本地 MSYS2 构建**的 7.1.5（configure `--prefix=/d/ffmpeg715/out`）。用户机上视频制卡三条 ffmpeg 链路——cue 动图 `extractClipGifViaFfmpeg`（`hibiki/lib/src/utils/misc/desktop_audio_clipper.dart:520`）、单帧 `extractVideoFrameViaFfmpeg`（:377）、句子音频 `extractAudioSegmentViaFfmpeg`（clip 链路）——全部崩溃，退出码 `-1414549496`（= `0xABAFB008`，非标准 NTSTATUS，属异常崩溃而非 ffmpeg 正常错误退出）。三操作同码崩溃指向进程启动/运行时环境问题而非编解码特定失败。
- **根因**：V35 是**本地构建**（`/d/ffmpeg715`），而崩溃前正常工作的直接前身 `a783d94f5`（TODO-1096）是**CI 干净环境构建**（`--prefix=/d/a/hibiki/hibiki/out`，GitHub Actions Windows runner）。二者都带 `--extra-ldflags=-static`（`-static` 非 V35 新增、非崩因），唯一有意义差异就是构建环境：本地 MSYS2（gcc 16.1.0 前沿工具链）产出的静态二进制在用户机崩溃，CI 产出的正常。本机（Windows 11）用标准 h264/aac 视频对两版跑三条真实命令均字节级相同、全 exit 0，无法复现 = 崩溃是用户机器/环境特定，坐实「本地构建坏」而非「7.1.5 源码真 bug」或「白名单缺组件」。
- **[x] ① 已修复** — `git checkout a783d94f5 -- third_party/ffmpeg-min/windows/ffmpeg.exe`：把入库二进制回退到 V35 前那版 CI 构建的功能完整 n7.1（含 TODO-1096 的 mov/astats/image2/aac_adtstoasc 全白名单，不退回更旧的 5a6c53f88 以免重引 BUG-460），立即恢复视频制卡。build 脚本/workflow 的 n7.1.5 pin 保留；已 `gh workflow run ffmpeg-min.yml`（ffmpeg_ref n7.1.5）在 CI 干净环境重建 7.1.5，验证不崩后再换入。回退后 worktree 二进制对三条真实命令均 exit 0、产出非空。提交见 bump commit。
- **[x] ② 已加自动化测试** — `hibiki/test/build/windows_vendored_ffmpeg_guard_test.dart` 新增守卫「vendored Windows ffmpeg.exe is a CI build, not a local dev build」：字节扫描入库 ffmpeg.exe 内嵌的 configure `--prefix`，断言含 CI 签名 `/d/a/`（GitHub-hosted runner 恒在 `D:\a\` 下 checkout）且不含本地构建标记 `/d/ffmpeg715`，从源头拦截「再次 vendor 本地构建二进制」。
- **备注**：CI ffmpeg-min.yml 7.1.5 重建 run 号见回报。CVE 修复（VP9/MOV/mpegts）随 7.1.5 延后到 CI 出验证过的干净二进制再入库。
