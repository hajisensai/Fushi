## BUG-4004 · 互联远端视频有字幕选择时 host 默认字幕从菜单消失
- **报告**：2026-11-04（用户：应用内反馈 1QkmT2vVTm，开发者自报，Android OnePlus CPH2747，3.3.0-debug.23213）——「我的互联日语字幕消失了」。截图：互联远端播放的字幕面板里「关闭字幕」处于选中，只剩一条 `Embedded 0: eng / English / ass`，没有「Fushi 互联服务端字幕」行。
- **真实性**：✅ 真 bug（沿代码路径定位；未在真机复现原始操作序列）。`fushi/lib/src/pages/implementations/video_fushi_page.dart` `_loadRemoteEpisode`（修前 :4831-4889）把 host 默认外挂字幕（host 视频旁的 sidecar，例如日语 `.ja.srt` / `.ja.ass`）的下载挂在 `if (subtitleResolved) {} else if (preresolved) {} else if (urls.subtitleUrl != null) {…}` 的 else 链末端；而字幕菜单「服务端字幕」行唯一的数据源 `_remoteSubtitlePath`（`video_fushi/subtitle.part.dart:1068` `_remoteSubtitleFileRows` → `media/video/remote_subtitle_catalog.dart` `remoteSubtitleFileEntries`）只在这条分支里赋值。于是这一集只要有持久化的字幕选择——关过一次字幕（`_clearRemoteSubtitle` 写 `off:` 哨兵，`subtitle.part.dart:2004`）、选过一次内嵌英文轨（`embedded:0`）或本机字幕档——重进时 `subtitleResolved = true`，host 默认字幕根本不下载，菜单里不再有日语字幕那一行，用户也就选不回来。截图「关闭」选中 + 无服务端行正是 `off:` 这条路径的表现。「尊重上次选择」本应只决定挂不挂，却同时决定了列不列。
- **[x] ① 已修复** — 「列」与「挂」拆开：新纯函数 `planRemoteBackendDefaultSubtitle`（`fushi/lib/src/media/video/remote_subtitle_catalog.dart`）给出 `none / listOnly / apply`；`apply` 走原来的起播挂字幕分支（下载抽成 `_downloadRemoteBackendDefaultSubtitle`，失败照旧只留痕不判播放失败）；`listOnly`（已恢复选择 / 预解析轨优先）在起播成功后 `_listRemoteBackendDefaultSubtitle` 下载、解析出 cue 才登记 `_remoteSubtitlePath`，换集作废，不碰主字幕选择与播放器 cue，不拖慢起播。手机遥控字幕列表与副字幕菜单共用同一行模型，一并恢复。提交：见 git log（`fix(video-remote): host default subtitle stays listed …`）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/video_remote_backend_default_subtitle_listed_test.dart`（计划函数四种组合 + 播放页接线源码守卫：计划由 `subtitleResolved` 驱动、listOnly 在 `_applyLoad` 之后、换集作废门、空 cue 不登记、只列不挂）；同步更新 `fushi/test/pages/video_remote_default_subtitle_failure_guard_test.dart` 的分支锚点。
- **备注**：播放页在 headless test 跑不起 media_kit，没有整页 widget 测试（与 BUG-3984 同一限制）。未在真机复测。若 host 上的日语字幕文件本身被移走（例如 host 端「清除字幕」把 sidecar 改名成 `.fushi-bak`），属另一条路径，本条不覆盖——日志里没有该操作的痕迹。
