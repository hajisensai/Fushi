## BUG-3562 · update-install-dir-needs-elevation
- **报告**：2026-10-19（用户：所有者转述用户现场截图——Fushi 装在 `C:\Program Files\Fushi`，普通权限点更新弹「更新安装器未启动 / Cannot write to installation directory … errno = 5」，以管理员打开 Fushi 才能更新）
- **真实性**：✅ 真 bug（体验缺口）。安装器 `fushi.iss` 是 `PrivilegesRequired=lowest`，选目录页对不可写目录有拦截（BUG-1483），但用户以管理员身份运行安装器即可绕过、装进 Program Files。此后应用内更新的写预检（`fushi/lib/src/utils/misc/platform_updater.dart` 旧 `ensureWindowsInstallTargetWritable`）在普通权限下必然失败并抛错，唯一出路是「以管理员身份重开整个 app」——让 app 长期以管理员运行，且每次更新都要用户自己想到这一步。
- **[x] ① 已修复** — 写不进安装目录时不再报错，改为只把**安装器**经 UAC 提权：`runAndExit` 探针失败 → 给 launcher 下发 `--elevate`、给 Inno 加 `/FUSHINORELAUNCH`；`update_launcher.cpp` 的 `LaunchInstallerElevated` 用 `ShellExecuteExW` + `runas` + `SEE_MASK_NOCLOSEPROCESS` 拉起 Inno（拿句柄照常等它结束），用户在 UAC 里拒绝（`ERROR_CANCELLED`）按启动失败记 marker 并拉回 app；`fushi.iss` 的 `[Run]` 加 `Check: ShouldLaunchAppAfterInstall`，提权安装时跳过自启（外部 runas 提权下 Inno 不知道原用户，`runasoriginaluser` 不生效，自启的 app 会继承管理员令牌），改由仍是普通权限的 launcher 在安装结束后立即拉回 app（`EnsureAppBack` 提权路径不再白等 20 s）。没有 launcher 的直启路径无从提权，保留原报错。
- **[x] ② 已加自动化测试** — `fushi/test/utils/misc/update_installer_elevation_test.dart`（参数构造、`runAndExit` 不可写→提权交接 / 可写→普通交接 / 无 launcher→仍报错且不退出、`.iss` 与 launcher 两侧接线守卫）。本地另验：`cl /W4 /utf-8` 编译 `update_launcher.cpp` 零警告，`ISCC /O-` 编译 `fushi.iss`（含 `[Code]`）通过。
- **备注**：未做真机 UAC 端到端（需要一台装在 Program Files 的正式包 + 发布产物）。已知边界：以**另一个**管理员账户的凭据通过 UAC（标准用户机器的 over-the-shoulder 提权）时，提权的 Inno 写的 HKCU / `{userdesktop}` 属于那个管理员账户——这与用户手动以管理员运行安装器的既有行为相同，不是本修复引入。
