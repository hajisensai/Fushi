## BUG-2197 · Android 上 ASR 后台 isolate 因 ffmpeg_kit 订阅 EventChannel 崩溃
- **报告**：2026-09-06（用户：手机截图，转录弹层报 `Bad state: ASR isolate crashed: Unsupported operation: Background isolates do not support setMessageHandler(). Messages from the host platform always go to the root isolate.`）
- **真实性**：✅ 真 bug。转录整条链路跑在 `Isolate.spawn` 的后台 isolate（`fushi/lib/src/asr/asr_transcribe_isolate.dart:301` `_isolateMain`），它在 isolate 里 `FfmpegAsrPcmSource()` 解 PCM；Android / iOS 的后端是 `KitFfmpegBackend`（`fushi/lib/src/media/video/ffmpeg_backend.dart:751`），走 `package:ffmpeg_kit_flutter`，其 Dart 初始化在 `third_party/ffmpeg_kit_flutter/lib/src/ffmpeg_kit_flutter_initializer.dart:311` `_eventChannel.receiveBroadcastStream().listen(...)`——平台消息处理器只能注册在根 isolate，后台 isolate 一碰就抛上面那条。桌面走 `CliFfmpegBackend`（子进程）没这一步，所以 Windows 上从来没暴露；#1231 引入 isolate 时只在 Windows 验过。
- **[x] ① 已修复** — PCM 解码留在根 isolate：新增 `fushi/lib/src/asr/asr_pcm_bridge.dart`（`AsrPcmBridgeHost` 在根 isolate 持有真 `AsrPcmSource`，`RemoteAsrPcmSource` 在转录 isolate 里按块经 `SendPort` 拉，样本以 `TransferableTypedData` 零拷贝搬，任务侧原有的「预取一块」让宿主总在解下一块）；`AsrIsolateTranscription.spawn(pcm:)` 起宿主、isolate 退出关端口；`_isolateMain` 只用远端源。不按平台分叉「哪里可以在 isolate 里解码」，五端统一。提交见本分支。
- **[x] ② 已加自动化测试** — `fushi/test/asr/asr_pcm_bridge_test.dart`：真起一个子 isolate，经桥解码 fake 源，块按序 / 零拷贝到达、`startSample` / `chunkSeconds` 原样传给真源、解码异常在远端以 `AsrPcmDecodeException` 重现、探不出时长回 null。
- **备注**：Android 真机 / 模拟器复测未做（本轮只有 Windows 真机；桥接逻辑是纯 `dart:isolate`，Windows 转录路径经桥后 E2E 仍过）。修完后 Android 上 `ffmpeg_kit` 的初始化落在根 isolate，与视频页 / 字幕抽取共用同一份 session 管理，无需再改。
