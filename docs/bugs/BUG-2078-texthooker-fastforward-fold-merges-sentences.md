## BUG-2078 · Ctrl 快进时渐进折叠把多句连同选项文本折成一条超长台词
- **报告**：2026-09-03（ceshi 批量适配的 ATRI -My Dear Moments- 真机会话，KiriKiri Z 1.2.0.3 / TextRender 线程。原记在 BUG-2070 的备注里，但它与「wuopus 语音恒降级为混音」是**两个互不相干的缺陷**，按「一 bug 一文件」拆出本号，否则索引表检索不到。）
- **现象**：按住 Ctrl 快进时，实时台词列表出现一条把连续多句**连同选项文本**（「アトリを行かせる／アトリは俺が預かる」）拼在一起的超长台词；松开 Ctrl 逐句正常推进时不复现。
- **真实性**：⚠️ 真机已观察到现象，**根因未定**（本轮未复现、未定位到确切分支，不能按已知根因写）。候选路径：`fushi/lib/src/sync/texthooker_service.dart:823` 起的渐进折叠回吞循环 + `fushi/lib/src/sync/texthooker_line_fold.dart:85` `isProgressiveTextUpdate`。该判据只要求「长的一方以短的一方为前缀或后缀」且短的一方 ≥ `kMinFoldableLength`，并不检查两次快照之间是否发生了**换句**。快进时引擎在极短时间里连续重绘同一文本框，若新句的缓冲区带着上一句的尾巴（KiriKiri 的历史/累积文本框），后到的整块就恒满足「以前一条为前缀」，于是被 `maxAbsorb = 8` 上限之内的回吞循环连着吞成一条。选项文本能被吞进去也指向同一条通路（选项与台词走同一 `textThreadKey`）。
  - 反证需要的证据本轮没有：没有抓到快进期间该线程的逐条原始快照序列（时间戳 + 原文），因此无法区分「引擎真的发了累积串」与「Fushi 的折叠判据误判」。
- **[ ] ① 未修复** — 先取快进期间 TextRender 线程的原始行序列（`text_ready` 阶段的结构化事件即可，不要真实台词入库），确认是引擎侧累积还是折叠误判；若是折叠误判，修法方向是给回吞循环加**时间/序号邻接**判据（同一句的多次重绘在毫秒级连续，快进换句之间仍有可分的间隔），而不是抬高 `kMinFoldableLength`（那会把真排版刷新一起漏折，见 BUG-1983）。
- **[ ] ② 未加自动化测试** —
- **备注**：与 BUG-2067（折叠后工作台显示中间态前缀）是同一段折叠代码的两个不同症状，但 BUG-2067 是消费端缓存问题、已修；本条是折叠**判据**本身的边界。与 BUG-2070（wuopus 语音降级）无因果关系。
