## BUG-4980 · Plex 换网络后起播一直走登录时那条不通的连接，不会自动换线路
- **报告**：2026-11-20（路线图 #3722 gap-remote-7，c42）
- **真实性**：✅ 真 bug。Plex 的连接地址只在登录时按 局域网 → 公网 → relay 探测一次（`fushi/lib/src/sync/plex_settings_widget.dart` `savePlexAccountServers`），之后每次建客户端都直接用存下的 `activeServerUrl`（`fushi/lib/src/sync/plex_video_client.dart:113` `effectiveServerUrl` → `buildClient`）。出门 / 回家换了网络后那条连接不通，从媒体库重开条目时详情请求失败只记一行日志（`fushi/lib/src/media/video/media_server/media_server_library.dart:495` 的 `catch`），起播客户端仍是旧线路的，取流随即失败；只能用户手动去服务器卡片「切换线路」。另外 `PlexApi` 把连不上（`http.ClientException`）包成裸 `Exception`（`packages/fushi_engine/lib/media/video/media_server/plex/plex_api.dart:399`），调用方分不出「这条连接不通」和「服务器答了错」。
- **[x] ① 已修复** — `PlexApi` 连不上改抛 `PlexTransportException`（文案逐字不变），`isPlexTransportFailure` 统一判「请求没到达服务器」；`PlexServerConfig.rerouteAfterFailure` 只在传输失败时把已存连接按优先级同时探测（`/identity` 核对 machineIdentifier），取排名最靠前的可达线路；`rerouteMediaServerAfterFailure` 写回 `activeServerUrl`（不存新凭据）并失效这台的远端清单缓存槽；`buildMediaServerLaunch` 详情失败时调它，拿到新配置就按新配置重建客户端（切换点在建客户端之前，已建的客户端不改地址），在新线路上取这一次详情，起播用新客户端。播放页（`video_fushi_page.dart`）接线。
- **[x] ② 已加自动化测试** — `fushi/test/sync/plex_auto_route_test.dart`（传输失败分型、局域网断切公网、回家切回局域网、别的服务器占了旧地址不切、服务器答话不探测、当前线路仍是最优不写回、全不通不动配置）；`fushi/test/media/video/media_server/media_server_library_test.dart` 的两条 BUG-4980（换线路后起播客户端是新线路的、回调返回 null 时照旧）。
- **备注**：只做了第一步（重开入库条目起播时）。媒体服务器分区里浏览 / 从浏览页直接起播、播放途中断流都没有自动换线路；Jellyfin 家族的手填备用线路也不自动切。真 Plex 局域网 / 外网切换未做设备验证。
- **后续（2026-11-21，拍板台 design-media-server-failover-transport）**：换线路下沉到传输层——`PlexApi` / `JellyfinApi` 的请求漏斗在传输失败时问按服务器共享、单飞的 `MediaServerRouteFailover`（`fushi/lib/src/media/video/media_server/media_server_route_failover.dart`），同一个客户端改走新线路并重试这一次请求；浏览、浏览起播、起播详情、播放期请求都走这一处。`buildMediaServerLaunch` 的 `rerouteAfterFailure` 回调与上面两条 launch 测试随之删除，覆盖改在 `fushi/test/sync/media_server_route_failover_test.dart`。播放途中断流由播放页（`episode.part.dart` `_handlePlaybackCompleted`）按位置判「流断了」后问一次、换成功就按当前位置重载。
