## BUG-2190 · 制卡释义外字退化 alt 文本沿用图片盒几何与正文重叠
- **报告**：2026-09-06（用户：AnkiDroid 截图「参考这两个字和其他文字重叠了」；真卡取证 note 1788020800232 `MainDefinition` 含 `<span class="gloss-image">［参考］</span>`、全字段零 `<img>`）
- **真实性**：✅ 真 bug。无头 Chrome + 用户实际 Lapis note type CSS 量得：`［参考］` 墨迹 80×27px 塞在 24×20px、`line-height:0` 的 `.gloss-image-container` 里（`data-sc-img[gaiji]` 分支 `width:auto!important;height:1.2em;line-height:0` + Anki 侧 `_ankiGaijiImageStyle` `width:1em!important`）→ 溢出压住后文；`［参照］` 同理压住蓝色链接「ねずみ色」。两层根因：① `fushi/assets/popup/popup.js` `createDefinitionImage` 导出分支在 `window.embedMedia` 为假时把 alt **文本**塞进为 `<img>` 量身定做的图片盒；② 扩展 `content.js fushiRenderEntries` 从不设 `window.embedMedia`（app 内 `popup_settings_injection.dart:840` 恒真），且服务端远程制卡 `app_model.dart` `_AppModelRemoteLookupService.mineEntry/mineImmersion` 从不 `writeDictionaryMediaCache` → 外字永远退化 alt。
- **[x] ① 已修复** — popup.js：无媒体文件时 alt 直接作为行内 `<span class="gloss-image-alt">` 输出（不套任何图片几何，文本按文本流）；content.js：`window.embedMedia = true`（与 app 内同值）；app_model.dart：远程 `mineEntry` / `mineImmersion` 制卡前 `writeDictionaryMediaCache(fields.dictionaryMedia)`（与 `overlay_bridge_handlers` 同一步骤）。三镜像已同步。
- **[x] ② 已加自动化测试** — `fushi/test/pages/popup_glossary_export_parity_test.js`（BUG-2190 段：无媒体 → 纯文本 span、无容器、无 inline 几何；有媒体 → 仍是 `<img>` 盒）；`fushi/test/sync/remote_mine_dictionary_media_cache_guard_test.dart`（远程两入口先落缓存且在 repo 之前；content.js 两镜像 renderPopup 前设 embedMedia）；`tools/browser-extension/sentence-context.test.js`「换词重渲染」用例断言 embedMedia 恒真。
- **备注**：同一张卡上大号「鼠」（明鏡 `data-sc-zoomkanji` 3em）与上一行轻微贴边是 Lapis 上游 `li[data-dictionary="明鏡国語辞典 第三版"] span{width:25em!important;vertical-align:bottom!important}` 规则 + CJK 字体内容区高于行高造成的**背景色**越界，不是文本重叠；改动需动用户 Anki 里的 note type CSS，本轮不碰。
