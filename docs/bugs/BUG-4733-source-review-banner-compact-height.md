## BUG-4733 · Android 横屏手机上卡片来源回看横幅固定两行，占顶部约 1/5 画面高度
- **报告**：2026-11-16（维护者，应用内反馈 m6TVBNxGa9）
- **真实性**：✅ 真 bug。截图是视频页「回看卡片片段」模式：顶部横幅 76dp（154/734 px @ 363dp 高横屏），视频被整体压到下面。根因 `fushi/lib/src/anki/source_review_session.dart:373`（修前）`SourceReviewBanner` 无论窗口多高都是「标题一行 + 按钮一行」的 `Column`：4 + 标题 20 + 按钮 48（padded tap target）+ 4 = 76dp，在 363dp 高的窗口里占掉 21%。另外 `fushi/lib/src/pages/implementations/video_fushi_page.dart:12778`（修前）外面又套了一层 `SafeArea`，横屏刘海那一侧被外层让成横幅底色以外的空白条（截图里横幅两侧的空白）。
- **[x] ① 已修复** — 横幅按 M3 compact height 窗口类（高 < 480dp）切到单行：按钮条按内容取宽（只在挤占标题保底 96dp 时才横向滚动），标题拿剩下的宽度 1 行省略，高度固定 48dp；更高的窗口保持两行。同一根因的三个宿主一起改：视频页去掉外层重复 `SafeArea`；漫画页 `manga_fushi_page.dart` 的外层 `SafeArea(top: _chromeTopInset == 0)` 同样把刘海一侧让成空白条、固定顶栏时又让横幅多让一遍状态栏，改成只在固定顶栏时 `MediaQuery.removePadding(removeTop: true)`；阅读器页固定高 `_kSourceReviewBannerHeight = 100` 的槽位改为 `SourceReviewBanner.reservedContentHeight(窗口尺寸)`（矮窗口 48 / 其余 100），在 `didChangeDependencies` 里随窗口尺寸维护、变化时回喂 WebView 的 chrome inset。
- **[x] ② 已加自动化测试** — `fushi/test/anki/source_review_session_test.dart`：`short landscape window folds banner into one row`（792×363 下横幅高 ≤ 48 且等于 `reservedContentHeight`、标题与「返回」同一行；修前红：`Actual: <76.0>`）、`tall window keeps title above the button row`（411×891 保持两行）、`compact banner with a draft lays out every button unscrolled`（1280×400 有草稿时四颗按钮不滚动；标题与按钮条平分宽度的写法下红）、`banner background spans the notch side and pads its content`（左刘海 40 / 顶 24 时底色从 x=0 铺起、内容让出刘海）、`pages host the banner without an extra SafeArea or fixed slot`（视频 / 漫画页横幅外无 SafeArea、阅读器槽位高与横幅同源）。
- **备注**：真机未复测（按规则不做）。
