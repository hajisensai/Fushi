## BUG-2818 · Mac/iOS 翻页每章最后一页整体错开一个边距、行尾被切（WebKit 滚动范围不含分栏容器末端 padding）
- **报告**：2026-09-30（用户转述另一位用户反馈：「mac 章节之前的一页有显示问题」，截图为 macOS 横排分页、一章的最后一页：满行末字被切掉半个（「数」「だ」「関」「が」「聞」），左侧空白约 115pt、右侧约 55pt——整页右移了约一个右边距）
- **真实性**：✅ 真 bug（WebKit 分页专属，横排 / 竖排都有）。根因在滚动范围：分页把整章排成一根多列 body，第 k 页落在 `k × 页步长`（`fushi/lib/src/reader/reader_pagination_scripts.dart` 的 `getScrollContext`），能滚到哪儿由 `physicalMaxScroll = scrollWidth − clientWidth`（竖排 `scrollHeight − clientHeight`）决定。Blink 的滚动范围包含多列容器行内方向末端的 padding，恰好够到末页；**WebKit 不含这截 padding**，物理终点比末页对齐位置少一个末端边距。`buildPaginationMetrics` 的「部分末页」分支（PR #1675 引入）于是把末页落在物理终点上，整页往前错开这个边距——横排右移、行尾被 `clip-path` 切掉；竖排下移、列尾被切掉。每章的最后一页都会中招，翻回上一章落到的就是这一页。
  - 实测（macOS 27 WKWebView，Swift 小程序加载生产 macOS 横排分页 CSS + 真书章节，1145 × 1200，左右边距 55px，按页网格滚到末页）：`scrollWidth` 25401，按 Blink 口径（含右 padding）应为 25456；末页对齐位置 24311，物理终点 24256，实际只能滚到 24256——**差 55 = 右边距**，截图与用户一致。竖排（上下边距 30px + chrome inset 40 / 30px）差 60 = 下边距 + 底部 inset。
  - 第二处（补栏后才暴露）：`buildPaginationMetrics` 的 `lastContentScroll` 没减相位 `contentStart`（列 j 的内容从 `contentStart + j × 页步长` 开始，`alignToPage` / `alignContentStartToPage` 都减了，唯独这里没减）。末行接近满行时末内容边越过下一条网格线（实测末列 29651 起、末行右缘 30659 > 29 × 1057 = 30653），`lastContentScroll` 多算一页。旧几何下它被 `maxAligned` 盖住、无人察觉；补栏后 `maxAligned` 跟着变大，末页就被推到补出来的那一栏的物理终点上（阅读器真实分页 JS 在 macOS WKWebView 实测：只补栏不修相位，末页落 30598、偏网格 55、当前页只剩 2 行）。
- **[x] ① 已修复** — 两处一起改：(1) `fushi/lib/src/reader/reader_content_styles.dart` 新增 `_webKitPaginatedScrollEndCss`：Apple 端分页给正文末尾补一个强制另起一栏的 1px 空块（`body::after { break-before: column; block-size: 1px }`），把滚动范围撑出一整栏，末页对齐位置落回物理范围之内。它不含文字和媒体，`buildPaginationMetrics` 的末页仍由内容边界（`lastContentScroll`）决定，这一栏不会变成可翻到的空白页。高度为 0 的块 WebKit 不为它另开一栏（实测无效）。只在 iOS / macOS 的分页模式发：连续滚动与 VN 不经多列分页，Blink 的滚动范围本就够到末页。(2) `fushi/lib/src/reader/reader_pagination_scripts.dart` 的 `lastContentScroll` 先减相位再求页号（Dart 影子 `resolveContentBoundsForTesting` 同步加 `contentStart`，章首那处原本漏掉的相位一并补上）。复测：几何探针横排末页滚到 24311（对齐）、截图行尾完整；**阅读器真实分页 JS**（从 `reader_pagination_scripts.dart` 原样切出 `getScrollContext` / `buildPaginationMetrics` / `setPagePosition` 等，macOS WKWebView + 生产 CSS + 真书章节）按 `maxScroll` 落末页：修前横排偏网格 55、当前页 8 段文字被切，竖排偏 60、16 段被切；修后横竖都偏 0、零被切。
- **[x] ② 已加自动化测试** — `fushi/test/reader/paged_chapter_jump_bounds_test.dart`「BUG-2818」：用 macOS 实测几何（页步长 1057、相位 55、末内容边 30659）钉住影子函数——补栏后末页落第 28 页网格、Blink 几何同样落网格、不补栏时只能落在差一个右边距的物理终点；另有一条静态断言要求 JS 的 `lastContentScroll` 同样减相位（变异验证：影子去掉末页相位，补栏用例变红）。`fushi/test/reader/webkit_paginated_scroll_end_css_test.dart`：iOS / macOS × 横排 / 竖排分页 CSS 必有强制分栏、`display: block`、非零 `block-size` 的 `body::after`；连续 / VN 与 Android / Windows / Linux 不发。变异验证：删掉 `break-before: column`，Apple 端分页 4 条用例变红。真 app 探针 `fushi/integration_test/reader_chapter_end_page_align_probe_itest.dart`（章末落页是否在页网格上、有无越出内容框被切的文字，翻页 / 连续 / VN × 横竖）。
- **备注**：未验证项——每页多列（`pageColumns ≥ 2`）且末页只填了前几个子列时，物理终点可能比整页对齐位置短不止一个边距（没填满的子列可能不产生滚动范围），本修法只补一栏，未对这种情况实测；Linux 的阅读器 WebView 未核实是否同为 WebKit 口径，门控只含 iOS / macOS。
