## BUG-2450 · 在线漫画封面与页图超时或失败后没有退避重试、没有重刷入口、加载队列排队无超时
- **报告**：2026-09-11（用户：「超时要加延迟和重刷新」「漫画图片缓存失效时间拉长」；截图「搜索全部来源」结果条里大批封面长时间停在转圈占位）
- **真实性**：✅ 真 bug，四处相互叠加：
  1. **无自动重试**：`MihonCoverCache.load/_load`（`fushi/lib/src/media/manga/mihon/mihon_cover_cache.dart:42-86`）一次 fetch 失败直接抛；`MihonSourceImage._reload`（`mihon/mihon_source_browse_page.dart:488-525`）只在 initState 与 url 变化时跑一次；页图 prefetch 失败静默吞（`mihon/manga_page_provider.dart:271-276`、`interconnect/interconnect_reader_chapter.dart:183-192`），注释说「由前台重试」但前台也没有退避。全漫画域唯一有退避的是 mokuro.moe 下载队列（`online/mokuro_moe_download_queue.dart:35-37`，2s/8s/20s）。
  2. **失败态没有重刷入口**：Mihon 封面失败只渲染 `broken_image` + `MihonCloudflareAction`，后者在非 Cloudflare 错误时 `SizedBox.shrink()`（`mihon/mihon_cloudflare_action.dart:73-76`），超时/5xx 的封面是一个不可点的破图；Aidoku 封面 `errorBuilder` 是死图标（`aidoku/aidoku_source_browse_page.dart:526-529`、`manga_global_search_page.dart:449-452`）；阅读页 `_retryChallengedImages`（`reader/manga_fushi_page.dart:783-797`）只挂在 Cloudflare 卡片 `onVerified`（`:4265-4271`）。
  3. **加载队列排队无超时**：`MihonSourceImageLoadQueue._acquire`（`mihon_source_browse_page.dart:603-611`）等待者没有超时，三处独立实例全是 `maxConcurrent: 4`（`:75-77`、`manga_global_search_page.dart:64-66`、`discovery/manga_discovery_page.dart:97-98`），而桌面封面首响应/空闲超时各 90s（`desktop_mihon_runtime.dart:20-21`）——最坏 4 并发 × 90s 串行排队，截图里成排转圈就是被队列卡住而非都在下载。
  4. **超时值不对称**：页图 `fetchImageRequest` 是 45s 整包超时（`desktop_mihon_runtime.dart:260-262`，BUG-1456 把封面改成 90s 首响应 + 空闲续期时没跟着改），慢速大图被砍；Aidoku 封面（`utils/net/app_http_image.dart:62-65`）与页图（`aidoku_reader_chapter.dart:342`）只有 20s TCP connect 超时、无读超时；Aidoku 封面还没有磁盘缓存（`AppHttpImage` 纯内存，同文件已有的 `AppCachedHttpImage` 没被用）。
- **[x] ① 已修复（封面半边，提交 33cd5ba15c）** — 原方向：① 图片加载收成一条带指数退避的通用取图原语（可抄 mokuro 队列的退避表），封面与页图共用；② 失败态统一给可点的重试入口，Cloudflare 只是其中一种错误分型；③ 队列等待加超时并按可见性优先；④ 页图超时改成与封面同构的「首响应 + 空闲续期」；⑤ Aidoku 封面接 `AppCachedHttpImage`。缓存 TTL（`mihon_cover_cache.dart:19` 30 天 / 512 项 / 64 MB，页图 `manga_page_provider.dart:16-17` 1 GB / 1024 文件 LRU 无 TTL）是配置项而非 bug，另开偏好。
  - 落地：① 通用原语 `utils/net/transient_fetch_retry.dart`（`retryTransient` + 1s/3s/8s 退避表 + 瞬时错误分型：超时 / socket / 5xx 重试，4xx 与 Cloudflare 不重试）；`MihonCoverCache._load` 在缓存层包一层重试（同 key 共享请求、退避期间释放队列名额、所有订阅者退场即停），Mihon 侧错误分型 `isTransientMihonImageError` 解 `IMAGE_HTTP_<status>` 与桥接层 `cause` 链；Aidoku 侧退避放在 `AppImageFileService.get`（5xx 抛 `HttpExceptionWithStatus` 交退避层，梯度耗尽后与 CacheManager 同款异常落 errorBuilder），并补 60s 首响应 / 空闲超时——没有超时的请求永远轮不到重试。② 统一失败态 `manga_cover_failure.dart`（Cloudflare 走既有 `MihonCloudflareAction`，其它错误一个可点的 refresh 图标）；`MihonSourceImage` 与新 `AidokuCoverImage`（`aidoku_cover_image.dart`，替换单源浏览页 / 全源搜索页两份复制的 `_AidokuCover` / `_AidokuStripCover`）都接上。③ `MihonSourceImageLoadQueue` 等待上限 30s（`IMAGE_QUEUE_TIMEOUT`，Timer 判「还在队列里」才报错，不漏名额；此码明确不自动退避），三处实例共用。⑤ Aidoku 封面改 `AppCachedHttpImage`（磁盘缓存）。偏好 `manga_cover_cache_max_age_days`（默认 180，30..360，设置 → 漫画 → 在线目录「封面缓存保留时长」），`MihonCoverCache.maxAge` 改可变、`AppModel.setMangaCoverCacheMaxAgeDays` 即时写穿已建 manager。
  - **未动**：在线阅读页图路径（`manga_page_provider.dart` / `aidoku_reader_chapter.dart` / `interconnect_reader_chapter.dart` / `manga_fushi_page.dart`）与 ④ 页图超时不对称——按整体决定该路径将整条删除，不在此修。
- **[x] ② 已加自动化测试（提交 33cd5ba15c）** — `fushi/test/media/manga/manga_cover_retry_test.dart`：`retryTransient` 在 fake_async 下只在 0s/1s/4s/12s 四次尝试后放弃、4xx 一次即抛、退场后不再打下一枪；`MihonCoverCache` 第一次超时第二次成功只等一次 1s 并落盘、4xx/Cloudflare/排队超时/取消不重试、`maxAge` 可变即时生效、`MihonManager(coverCacheMaxAge:)` 穿透；队列 30s 排队超时以 `IMAGE_QUEUE_TIMEOUT` 失败且名额不漏、超时前轮到名额者不误报；widget：假 runtime 第一次抛超时第二次成功 → `Image.memory` 渲染且 `waits == [1s]`；404 失败态存在 `manga_cover_retry` 按钮、点击后 runtime 调用数 1→2；Cloudflare 走验证按钮不出裸重试。`fushi/test/utils/net/app_image_file_service_retry_test.dart`（真实 loopback 服务器）：503→200 两次请求成功且只等退避表一档、503×2 后抛 `HttpExceptionWithStatus(503)`、404 一次不退避；`AidokuCoverImage` 404 后出现重试按钮、点击重发第二次请求并渲染出 `RawImage`。设置项登记 `settings_schema_coverage_test.dart` 的 `kCoveredElsewhere['manga/Cover cache retention']`。
- **备注（推测，未实测）**：封面缓存 key 是 `sha256(extensionPackage, sourceId, coverUrl)`（`mihon_cover_cache.dart:196-203`），源返回带签名/过期参数的 URL 时每次 key 都变，磁盘缓存 100% miss 且旧文件占满 512 条预算。修缓存时应对 URL 归一化或改用 `manga.url` 做 key；发生率需要抓真实源 URL 才能定。
