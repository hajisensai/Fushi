## BUG-3321 · Windows 选文件夹后崩溃（comdlg32 CFileOpenSave 释放已释放的 IShellItem）
- **报告**：2026-10-13（用户群反馈：Windows 安装版「导入视频」→ 选文件夹 → 无响应 → 崩溃，换别的视频文件夹同样崩；附 runner 自写的两份 dump `hibiki-207768-611427703.dmp` / `hibiki-231852-611812343.dmp`）
- **真实性**：✅ 真 bug，必现于每一次**成功**选中文件夹。两份 dump 完全一致：主线程 `0xC0000005` 读 `0x10`，`comdlg32!SafeRelease<IUnknown>` ← `CFileOpenSave::_ClearResults` ← `~CFileOpenSave` ← `CFileOpenSave::Release`（adjustor{32}，即经 `IFileOpenDialog` 接口指针），再往下是 `flutter_windows.dll`（内嵌 Dart VM）→ `user32` 消息分发 → `fushi.exe` 主循环，即 **Dart `Finalizer` 在平台线程上 Release 对话框对象**。根因在 file_picker 8.3.7 的 `getDirectoryPath()`（覆盖补丁 `ci/patches/hosted/file_picker-8.3.7/lib/src/windows/file_picker_windows.dart`，修前 92–169 行）：在平台线程上用 win32 5.15 的 COM 包装类，而 win32 5.x 的 `IUnknown` 构造时就挂了自动 `Release` 的 `Finalizer`（`win32-5.15.0/lib/src/com/iunknown.dart:29/38`）。`GetResult` 拿到的 `IShellItem` 被手动 `item.release()`（实测此后引用计数 = 1，只剩对话框结果数组持有）后，GC 时它的 Finalizer 再 release 一次 → item 被释放；随后对话框的 Finalizer 走 `_ClearResults` → 释放后使用。Finalizer 只在 `isComInitialized` 为真时 Release，Flutter 平台线程常驻已初始化的 COM，所以必中。另外模态 `Show()` 阻塞 UI isolate，选目录期间整个 app「无响应」。所有走 `FilePicker.platform.getDirectoryPath()` 的 Windows 入口都受影响（`pickRealDirectoryPath` 的导入视频 / 来源目录 / 数据根，词典文件夹导入）。
- **[x] ① 已修复** — 提交见本 PR（`fix(windows): stop folder picker double-releasing COM objects`）。只改覆盖补丁里的 `getDirectoryPath()`：对话框改在后台 isolate 跑（与同文件的 `pickFiles()` / `saveFile()` 一致，不再阻塞平台线程）；`FileOpenDialog` 与两个 `IShellItem` 创建即 `..detach()` 摘掉 win32 Finalizer，按「先子后父」在 `finally` 里各显式 `release()` 一次并 `free` 包装指针，最后才 `CoUninitialize()`；顺手释放了 `GetDisplayName` 返回的字符串（`CoTaskMemFree`，原来泄漏）。行为对外不变（返回值、取消返回 null、`lockParentWindow` / `initialDirectory` / 标题语义同前）。
- **[x] ② 已加自动化测试** — `fushi/test/build/windows_directory_picker_com_lifecycle_guard_test.dart`：① lock 里的 file_picker 版本必须有对应覆盖补丁（升级后补丁被 apply-patches 静默跳过 = bug 回归）；② `getDirectoryPath` 体内是 `Isolate.run`、不直接开 COM / `show`；③ 实现段里每个 COM 包装对象紧跟 `..detach()`，且 `release()` 次数与包装对象数相等。真实对话框无法在 CI 自动化，另做了本机 A/B 探针（纯 Dart 进程，主线程先 `CoInitializeEx` 模拟平台线程，另一 isolate 找到对话框后 `PostMessage(WM_COMMAND, IDOK)`，选中后制造 GC）：**PageHeap**（IFEO `GlobalFlag=0x02000000`）下旧实现 `0xC0000005`，Dart 栈 `IUnknown._finalizer → IUnknown._release`；新实现两轮都正常返回所选路径并扛过 GC。
- **备注**：普通堆上旧实现的 UAF 不一定立刻崩（被释放内存未被复用时读到的 vtable 仍「有效」），所以开发机上不易复现；用户机 dump 里 `rax=0` 正是那块内存已被清零。file_picker 9.0.1 起上游也把 `getDirectoryPath` 挪进了 isolate，但本仓仍钉 8.3.7（升 10+ 是 API 破坏性变更），故在覆盖补丁里修。
