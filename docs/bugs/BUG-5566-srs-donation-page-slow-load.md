## BUG-5566 · srs-donation-page-slow-load
- **报告**：2026-11-27（用户：复习历史捐赠页打开要加载好久，排版怪怪的）
- **真实性**：✅ 真 bug。`fushi/lib/src/srs/donation/srs_donation_page.dart` 的 `_load` 先在 UI isolate 上 `await previewSrsDonation`（`packages/fushi_engine/lib/srs/apkg/srs_donation_export.dart` `previewSrsDonation`：读本 profile 全部卡、全部笔记物化、逐卡历史重放），算完才把整页从转圈换成内容，捐赠状态查询（只要 profileUid）也串在它后面。实测（用户真实库副本，25500 卡 / 4638 可见卡、57428 次复习，release 库 `FUSHI_FSRS_ID_AUDIT=0`）：预览 21–27 秒，其中 `store.notes` 3223 条约 8–12 秒、内核 `entity_views` 同样 3223 条一条命令约 10 秒、`histories` 3223 张约 6–9 秒。排版：右栏三张卡，「包含我的单词」开关行没有左栏图标，文字左缘和上下行错开；操作区单独一张卡只放一颗右对齐按钮，大片空白。
- **[ ] ① 部分修复** — 页面层：预览改走 `previewSrsDonationInBackground`（后台 isolate，不占 UI）；说明 / 同意 / 捐赠卡进页即显示，统计行显示「正在统计复习…」，按钮在预览到之前禁用；状态查询与预览并行；预览按 profile + `SrsDbStore.contentFingerprint` 缓存（`srsDonationPreviewCacheProvider`），库没变再进页直接出数。右栏合成一张卡（统计 → 状态 → 单词开关 → 词表 → 操作区），各行统一 `FushiListItem` 几何。**未修**：首次统计仍要 ~20 秒，真正的耗时在内核笔记物化 / 历史重放每条约 3 ms（`entity_views` 单条命令 3223 条约 10 秒，不是 Dart 分块、也不是 ID 审计库），影响导出与所有批量读，另开任务按内核 profile 定位。
- **[x] ② 已加自动化测试** — `fushi/test/srs/donation/srs_donation_widgets_test.dart`「捐赠页：库 / 预览没到时照常显示内容，不整页转圈」（M3E / Apple 两套）：库永不返回时说明卡、同意卡、捐赠卡、单词开关与按钮都在，统计行是「正在统计」，按钮禁用、不提前显示门槛提示。
- **备注**：同一页「无法查询捐赠状态」/「捐赠失败 404」不是本 bug：`rank.fushi.moe` 上的 Worker 没部署捐赠路由（`GET /v1/srs-donations/stats` 404，同 Worker 的 `/v1/decisions` 401 正常）；服务端随 PR #4515 于 2026-11-27 00:43 进 develop，最后一次 `leaderboard-worker-deploy` 是 2026-11-26 20:34，要手动 dispatch 部署（含 D1 迁移 0027）。
