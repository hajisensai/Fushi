## BUG-665 · 远端制卡查重挂满 10s 超时（AnkiConnect 不可达/无响应，缺连接建立超时）
- **报告**：2026-07-09（用户：TODO-1334。运行时栈：浏览器扩展/远端 `POST /api/mine` → `YomitanApiServer._handleMine` → `buildRemoteMineResponse` → `_AppModelRemoteLookupService.mineImmersion` → `ImmersionMiningEngine.mine` → `AnkiConnectRepository.mineEntry` → `_mineEntryInner` → `isDuplicate` → `findNotesByField` → `_postWithStaleConnectionRetry` 卡 `TimeoutException after 0:00:10.000000: Future not completed`，日志标签 `Anki.mineEntry`）。
- **真实性**：✅ 真 bug（体验缺陷，类别 **(B) 外部 AnkiConnect 不可达/无响应 + 缺连接建立超时**，非 (A) 代码 hang/死锁）。沿真实代码路径逐帧核实：
  - **不是代码 hang/死锁**：`_postWithStaleConnectionRetry`（`packages/hibiki_anki/lib/src/ankiconnect/ankiconnect_service.dart`）的重试只在 `http.ClientException`（连接掉线）上触发，**不在 `TimeoutException` 上重试**；每次 `_post` 各自带 `.timeout(_timeout)`，超时路径只发一次请求、有界 ~10s，无未 await/漏 timeout/死锁（BUG-065/091 的幂等重试逻辑正确）。
  - **不是未捕获 500 崩溃**：报错里的 `Anki.mineEntryTimeoutException` 是 `ErrorLogService` 的**日志标签** `Anki.mineEntry`（`hibiki/lib/src/utils/misc/error_log_service.dart:503` 的 `logMineFailure`）+ `TimeoutException` 拼出来的；`TimeoutException` 已在 `_mineEntryInner` 的查重 try/catch（`packages/hibiki_anki/lib/src/ankiconnect/ankiconnect_repository.dart:422`）被 `_mineFailureFor` 接住，归类为 `AnkiErrorCode.connectionTimeout` 并**返回** `MineOutcome.failure`（不抛），远端经 `remoteMineResultFromOutcome`（`app_model.dart:4480`）→ `logMineFailure` 记诊断栈 + 回本地化「连接超时」文案。**用户拿到的是干净的本地化失败 + 一条诊断日志，不是崩溃**——报的堆栈就是这条诊断日志。
  - **真根因（10s 等待）**：`AnkiConnectService` 的 HTTP 传输用裸 `http.Client()`，**没有连接建立超时**（`ankiconnect_service.dart` 旧构造 `_client = client ?? http.Client()`）。当配置的 AnkiConnect host 不可达/被防火墙黑洞（远端 host、VPN 断、错端口有服务但不应答）时，`_post` 的合并 `.timeout(10s)`（`ankiconnect_service.dart` 的 `_post`，`Future.timeout` 覆盖 connect+send+receive 一整段）是**唯一**的兜底，连接阶段会一直悬到整段 10s 才被杀成不透明的「Future not completed」。纯文本远端制卡（无封面/音频/词典外字→`_renderMinedFields` 无网络往返）时，`isDuplicate` 是第一发真网络调用，故正好卡在它。
