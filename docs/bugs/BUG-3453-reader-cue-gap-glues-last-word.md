## BUG-3453 · reader-cue-gap-glues-last-word
- **报告**：2026-10-16（用户：英文 EPUB + SRT 有声书，一句话被拆成多条字幕时，每条字幕最后一个词点了「未找到搜索结果」——`greeted us` 的 us、`boy with` 的 with；后面紧跟标点的 `hair.` 正常）
- **真实性**：✅ 真 bug。有声书句子高亮 `wrapSentenceAudioGroup`（`fushi/lib/src/reader/reader_sentence_audio_ruby_gap_script.dart`）把每条 cue 的文字各自包进 wrapper，cue 之间的空格留在两个 wrapper 之间成为独立的纯空白文本节点；阅读器 `createWalker`（`fushi/lib/src/reader/reader_selection_scripts.dart`，TODO-956）跳过纯空白节点，`selectFromPosition` 的跨节点续扫于是从 "us" 的节点末尾直接续到下一条 cue 的 "belonged"，查询串成了 `usbelonged to a good-loo`（变异实测原样复现），英文整词匹配不到。cue 以标点收尾时标点先终止扫描，所以只有每条 cue 的末词中招。同一根因也让 `getSentenceContext` / `textBetween` 拼出的制卡句子丢掉这个空格（`greeted usbelonged`、`boy withspiky`）。
- **[x] ① 已修复** — `reader_selection_scripts.dart` 新增 `hasSkippedWhitespaceBetween`（两相邻节点间是否夹着被跳过的纯空白节点，振假名不算）+ `isWordGapBetweenChars`（缝两侧非空白、非日文才算词间空格）：`selectFromPosition` 跨节点时遇此缝终止（与 BUG-1773「新节点开头的空白不桥接」同一规则）；`getSentenceContext` / `textBetween` 拼接时还原一个空格（`sentenceOffset` 随拼接串自然对齐；归一化偏移按节点计算，不受影响）。`createWalker` 本身不改——分页 / 有声书 / VN 的归一化偏移都靠它，跳过空白节点是它们的坐标契约。日文排版里 HTML 换行缝维持旧行为（取词跨过、句子不加空格）。
- **[x] ② 已加自动化测试** — `fushi/test/lookup/reader_cue_gap_word_scan_bug3453_test.dart` + `.js`（node 真执行 `ReaderSelectionScripts.source()`：cue 末词 us / with 不粘连、cue 内短语桥接不回退、日文缝不截断、句子与 `textBetween` 还原空格、`sentenceOffset` 对齐）；修复前该测试红在 `usbelonged to a good-loo`。
- **备注**：拖选（`collectRangeBetween`）跨 cue 时选区正文同样会少这个空格，但它的 text 与 ranges 按字符数对应、下游按长度映射高亮，插字符会错位，本次未改；浮窗 / 扩展的 `selection.js` 的 walker 不跳过空白节点，不受影响。
