## BUG-5298 · 互联老库类迁入统一模块层（design-imusic-q0）
- **报告**：2026-11-23（拍板台 design-imusic-q0..q12 实现分期，PR 分支 `claude/imusic-impl`）
- **真实性**：✅ 真缺口（分期待办）。第 0 期已立 `packages/fushi_engine/lib/sync/interconnect_module.dart`（模块表分发 / 能力位 / 统一流票 `library_media_streams.dart`），六个近模块形态的功能（漫画 OCR 任务、任务、下载、BT 引擎、订阅、助手）已迁入；书 / 有声书 / 视频 / 漫画 / 词典等老库类的路由仍手写在 `packages/fushi_engine/lib/sync/fushi_sync_server.dart` 的 `/api/library/…` 分支与 `fushi_library_host_service.dart`，客户端仍走 `fushi/lib/src/sync/interconnect_sync_backend.dart` 的逐类方法。
- **[ ] ① 未修复** — 每类一个 PR 迁成 `InterconnectHostModule`（视频的流票签发已在 `LibraryMediaStreams`，只剩路由与 resolver 搬家），客户端改走统一的模块客户端；守卫 `interconnect_module_layer_test.dart` 的「服务器本体无手写前缀分支」放宽名单逐类收紧到空。
- **[ ] ② 未加自动化测试** — 每类迁移带「能力 JSON / 路由响应逐字节不变」快照测试（照 `_kLegacyCapabilitiesJson` 的做法），并收紧守卫名单。
- **进展（2026-11-28，架构重构 A1，分支 `arch/interconnect-route-table`）**：服务端一半已落地——`InterconnectHostModule` 改成声明式端点表（`InterconnectRoute` 写明方法集 / 路径模式 / 信任级，`InterconnectCapability` 给能力位），`_handleRequest` 的一级路径分支、`auth.part.dart` 的 `_kPublicRoutes`、`pairing.part.dart` 的能力位手拼段全部并进 `fushi_sync_server/host_routes.part.dart` 的模块表；整张能力表与各类端点的鉴权 / 状态码由 `interconnect_host_surface_test.dart` 逐字节钉住；守卫「服务器本体不手写路径分支」已落地（`interconnect_module_layer_test.dart`），放宽名单只剩 handler 内部的二级分发、只减不增。仍未做：老库类的二级子路由拆分、客户端统一模块客户端。
- **剩余与棘轮（2026-11-28 返修后；每一块都有守卫卡住，只减不增）**：
  - **handler 内的二级路径分发**（lookup 6 项、library 4 类「列表 vs 单项」及其后缀切分、video / video_metadata、plugin_relay、source_share）：要先给模块加「前置门 + 子路由 + 模块内兜底 404」的声明才能拆成独立路由。守卫：`interconnect_module_layer_test.dart`「服务器本体不手写路径分支」（任何名字带 path 的标识符做 `==` / `!=` / `startsWith` / `endsWith` / `contains` / `switch` 都逐项列名计数）+「`/api/` 路径字面量只在端点表里」（按文件计数）。两条都是词法棘轮，不是结构保证。
  - **免 Basic 的门不是结构保证**：`InterconnectTrust.urlTicket` / `pairingBootstrap` / `reachabilityProbe` 只让中间件放行，票据 / 配对窗口校验仍在各 handler 里（视频流 token 在 `video.part.dart` 里就有 4 处各自校验）。把校验器收进路由声明必须连 handler 里「功能关着 404 → 票无效 403」的先后一起动，归 A2。守卫：「免 Basic 的面逐条列名」——从真实服务器的端点表派生，多开一个免 Basic 的面即红。
  - **「必须 HTTPS」「仅已配对设备」「仅我的设备」仍由 handler 各判各的**（`pairedPeer` / `ownerDevice` / `tlsRequired` 没有做成路由上的声明）：各 handler 的判门顺序和错误体不一样（纯文本 403 / JSON code），统一就是改 wire，归 A2（InterconnectCaller + 统一判门）；`serviceConfig` / `profileTransfer` 能力值里手写的 `_securityContext != null` 与 handler 里的 TLS 判断是两个真相源，同批收口。守卫：「handler 里各判各的 TLS / 已配对设备 /「我的设备」门只减不增」。
  - **音乐模块「功能关着时不占前缀」**：`MusicLibraryHostModule` 只由 app（`fushi/lib/src/models/app_model.dart`）和服务端（`packages/fushi_server/lib/src/headless_host.dart`）经 `modules` 注入，不像另外六个模块那样由 `FushiSyncServer` 构造函数无条件登记（`fushi_sync_server.dart` 的 `_injectedModules`）。裸 `FushiSyncServer` 上 `/api/library/music` 不归任何路由，`PUT` 会落进 WebDAV 树回 201。两个真实装配点都注入了，线上没有这个洞；改成无条件登记会让裸 host 的这条前缀从 WebDAV 语义变成 404，属于对外行为变化，待拍板。现状由 `interconnect_host_surface_test.dart` 的 `_kMinimalSurface`（`/api/library/music` 各行）钉住。
  - **客户端那一半**（`HostCapabilities` 类型化视图、按 host 唯一的缓存、删 `interconnect_sync_backend` 的逐类 fetch）不在 A1。
- **备注**：设计与拍板见 `docs/specs/2026-11-23-interconnect-music-library-design.md` §8 / §9。
