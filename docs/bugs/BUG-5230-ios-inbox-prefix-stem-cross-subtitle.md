## BUG-5230 · iOS 收件箱搬入根上文件：stem 互为前缀时放行交叉配对，较短 stem 的视频选上别人的日语字幕
- **报告**：2026-11-22（外部审计 2026-11-22 项目审查 HBK-AUDIT-220，PR #4027）
- **真实性**：✅ 真 bug。`ImportInbox._freeGroupStem` 判交叉配对时按「stem 互为前缀时字幕归更长的 stem」放行较短的一方（修前 `fushi/lib/src/media/import/import_inbox.dart:404-430`：`stem.length >= owned.value`、`s.length >= stem.length` 两处），注释说这与 `sidecarSubtitlesForDeletedVideo` 同一归属规则——但那只是删视频时带走字幕的规则；播放器选字幕（`pickSidecar`）与列字幕（`listSidecarSubtitles`，`packages/fushi_engine/lib/media/video/video_sidecar.dart:45`、`:69`）只看自己的 stem，不看同目录别的视频。于是 `EP01.ja.mkv` + `EP01.ja.srt` 与 `EP01.mkv` 落在同一目录（同一批原名搬入，或已有其一再搬入另一组）时，`EP01.mkv` 按 `.ja.srt` 优先选上 `EP01.ja.mkv` 的字幕，违背 HBK-AUDIT-019 修复「旧视频不配上新字幕、新视频不配走旧字幕」的本意。
- **[x] ① 已修复** — 收件箱判「配得上」只用播放器的实际规则（`_pairsWith` = `listSidecarSubtitles`，`pickSidecar` 是它的子集），去掉按 stem 长度的放行：已占用且有主文件配得上的字幕会配上新 stem、或本组字幕会配上已占用主文件，都算冲突，整组按既有的 `<stem> (2)` 机制换名。组内字幕归最长 stem 的分组规则不变。
- **[x] ② 已加自动化测试** — `fushi/test/media/import/import_inbox_root_plan_test.dart`「HBK-AUDIT-220：导入计划与播放器实际选字幕同一归属」（四种组合：同批两组、同批较短 stem 无字幕、已有短 stem 再来长 stem 组、已有长 stem 组再来短 stem 视频；用计划结果拼出目录再跑生产 `pickSidecar` 断言各选各的）；`fushi/test/media/import/import_inbox_test.dart` 原「字幕只认最长匹配的视频 stem」用例按播放器规则改期望（`EP01.v2` 组整组换 stem）。
- **备注**：`EP01.mkv` 与 `EP01.v2.mkv` 同批搬入时，`EP01.v2` 组现在会改名成 `EP01.v2 (2)`（否则 `EP01.mkv` 的字幕列表里会出现 `EP01.v2.srt`）。另一条路是让播放器也按「最长 stem 认领」选字幕，会改变全库播放行为，已作为待决策项回报，未做。真机未复测。
