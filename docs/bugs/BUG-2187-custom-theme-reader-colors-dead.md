## BUG-2187 · 自定义主题的正文/背景/选区/链接色在阅读器里永远不生效（key 严格等值 + 读已停写的旧扁平偏好）
- **报告**：2026-09-06（用户：自定义主题「选的颜色跟看的颜色都不一致」，随「PC 滚动很烂 / 选项看不懂改了什么」一并报告）
- **真实性**：✅ 真 bug。两层根因，同一条链：
  1. 编辑页「应用」写的是 `setAppThemeKey('custom-theme:<id>')`（`custom_theme_page.dart` `_applyAndClose`，TODO-930 起），而阅读器三处用**严格等值**判自定义分支：`reader_fushi/chrome.part.dart:2625` `key == 'custom-theme' ? _customReaderThemeColors : null`、`:2651` `_customHighlightCss` 的 `appThemeKey != 'custom-theme'`、`reader_fushi_page.dart:366` `_resolveBaseReaderThemeColors` 的 `themeKey == 'custom-theme'`。`ThemeNotifier.isCustomThemeKey()` 早已存在但这三处没用，于是任何从编辑页保存的主题在阅读器里都走不进自定义分支。
  2. 即使走进去，`chrome.part.dart:2601-2610` `_customReaderThemeColors` 读的是 `appModel.customThemeFontColor / BackgroundColor / SelectionColor / LinkColor`——这些是 TODO-930 之前的**旧扁平偏好** `custom_theme_*_color`，唯一写入路径 `applyCustomTheme()` 在生产代码里已零调用；条目 `CustomThemeEntry.fontColor / bgColor / selectionColor / linkColor` 四个字段全仓除序列化/迁移/编辑页外**没有任何读点**。
  - 附带：`_customHighlightCss` 把钉死的主色以 `alpha 0.34` 注入 `window.__fushiCustomHighlightColor`，JS 侧 `_hlColor/_hlMarkColor` 一旦非空就把 5 色收藏句高亮**全部**顶成同一色；编辑页把这行文案标成「音频高亮」，用户无从得知。重设计后主题色默认钉死为 primary，这个隐藏耦合会让每个自定义主题都抹平收藏高亮，故一并移除。
  - 还有一层「不一致」是设计层面：旧页把「种子色」当主入口，Material tonalSpot 会重算色调并把 chroma 钳到 36，所选鲜红在 UI 上变成闷红；预览里各迷你示意也各画各的（主色@0.34 演示成「音频高亮」、选区不按纸底预合成、tertiary 用 0.5 alpha 示意派生而真实规则是向黑/白 lerp 0.7/0.85）。
- **[x] ① 已修复** — 同一提交（见 git log `fix(theme): custom theme editor redesign`）：
  - `ThemeNotifier` 新增 `_activeCustomRole()` 单一解析链（非自定义 key → null；条目字段优先；无条目才回落旧扁平偏好）+ `activeCustomThemeFontColor / BackgroundColor / SelectionColor / LinkColor / PrimaryColor` getter；`buildColorScheme` 改走同一条链；`AppModel` 转发四个 getter。
  - `resolveReaderThemeColors` 的 `customColors: ReaderThemeColors?` 改为 `customOverrides: ReaderThemeOverrides?`（四角色可空覆盖），分支判定用 `ThemeNotifier.isCustomThemeKey`；未指定的角色与 system/light 走同一条 scheme 派生链（`applyReaderThemeOverrides`：只设背景时字色按纸色亮度取黑/白、`dark` 跟最终纸色），不再在 chrome 里硬编码白底/黑字兜底。
  - `chrome.part.dart` 改读 `activeCustomTheme*`；删除 `_customHighlightCss` 与 `HighlightBridge.applyHighlights(customHighlightCss:)` / JS `__fushiCustomHighlightColor` 管线。
  - 编辑页重写为按用途命名的角色模型（主题色 / 正文文字 / 页面背景 / 链接 / 查词高亮 / 当前句高亮 / 次要强调色 / 点缀色 / 控件底色），主题色永远就是所选色（`primaryColor == seed == 所选`，只有 seed 的旧条目取其当时实际显示的 primary 钉死；用户明确不要任何会让实际颜色偏离所选的「自动调色调」开关）；预览卡走 `resolveReaderThemeColors` 同一条链、可切浅/深、按角色框出影响位置；选色器改为固定尺寸构件，宽屏（≥900）右栏常驻、窄屏弹窗，不再内联撑满宽度的 `ColorPicker`。
