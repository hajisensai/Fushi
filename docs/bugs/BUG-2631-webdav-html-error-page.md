## BUG-2631 · WebDAV 测试连接：403 网页响应体（Cloudflare 挑战）整页标记裸灌进提示
- **报告**：2026-09-22（用户截图：媒体库「网络」源弹窗选 WebDAV、地址填 `https://anidb.net/anime`、点「测试连接」，红色 toast 半屏都是 `Connection failed: SyncAuthError: Server refused (403): PROPFIND https://anidb.net/anime (<!DOCTYPE html><html lang="en-US"><head><title>Just a moment...</title><meta http-equiv=…scal...)`。）
- **真实性**：✅ 真 bug（两层都是本仓的错，虽然那个地址本身不是 WebDAV 服务器——它是 Cloudflare 挡着的网站，PROPFIND 撞上人机挑战页回 403）。
  - `fushi/lib/src/sync/webdav_ops.dart:21`（原 `readSyncErrorBody`）：BUG-1323 为了让 403 的「HTTPS required for service config」这类一句话原因到达用户，把响应体截 300 字当 `serverReason`。它没有区分**响应体是不是一份 HTML 文档**：Cloudflare 挑战页 / 反代错误页 / URL 压根是个网站，截出来的 300 字全是 `<!DOCTYPE html><html …><meta …>` 标记，零信息，还把 toast 撑爆。随后 `sync_error_messages.dart:117` 按 `forbidden` 把它塞进「服务器拒绝了这次请求：… (your sign-in is fine)」——「登录没问题」在这条上也是错的：服务端根本没走到鉴权。
  - `fushi/lib/src/pages/implementations/media_sources_view.dart:1770`（原 `_testConnection` 的 catch）：`'${t.sync_connection_failed}: $e'` 直接把异常 `toString()` 上屏，连 `SyncAuthError:` 类型名都带着；同步设置页的同一按钮早就走 `friendlySyncErrorDetail`，这里是漏掉的第二条车道。
- **[x] ① 已修复** — 新增 `SyncAuthFailureKind.htmlPage`（服务端回的是网页、凭据未被评估；登出决定显式登记为否）。`readSyncErrorBody` 改回结构化的 `SyncErrorBody`：按 `Content-Type: text/html` 或正文形状（`<!DOCTYPE html` / 前 512 字内 `<html`）识别网页，只取 `<title>`（折叠空白、解基本实体、截 120 字）当原因，整页标记不再进入任何用户可见路径；`checkStatus` 按体把 403 落成 `htmlPage` / `forbidden`，webdav 两处直接抛 403 的分支收口到同一入口。文案新增 `sync_err_html_page` / `sync_err_html_page_detail`：「服务器返回的是网页（「Just a moment...」）而不是同步响应，请确认地址指向 WebDAV / Fushi 互联端点而不是网站」。网络源弹窗的 catch 改走 `friendlySyncErrorDetail(e)`。提交见本文件所在修复提交。
- **[x] ② 已加自动化测试** — `fushi/test/sync/sync_auth_error_kind_test.dart` 新增 BUG-2631 组（真 `HttpServer` 回 403 + Cloudflare 样式 HTML）：kind=htmlPage、serverReason 只剩标题、用户文案与 i18n getter 逐字相等且不含尖括号、无 Content-Type 凭正文识别、无 `<title>` 走无标题文案、纯文本 403 逐字不变、网页型 403 不登出、`parseSyncErrorBody` 纯函数（空白折叠 / 实体 / 截断 / XML 不算网页）、`checkStatus` 随体分流、网络源弹窗 catch 的源码守卫。`fushi/test/sync/oauth_proxy_and_browser_timeout_test.dart` 的 kind 登记表补 `htmlPage: false`（该守卫要求每个新 kind 显式登记登出决定）。
- **备注**：未在真机复演原始路径（本轮在 `testConnection` 层用真 HTTP 服务复现了同形响应）。另一处相邻但**未改**的行为：`testConnection` 对任何 `< 400` 的状态都判成功，一个对 PROPFIND 回 200 HTML 的普通网站会被「测试连接」判为连通；严格要求 207 会不会误伤非标准 WebDAV 服务端没有证据，故留档不动。
