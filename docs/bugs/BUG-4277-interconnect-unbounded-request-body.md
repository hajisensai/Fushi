## BUG-4277 · 互联 host 与扩展 API 读请求体没有上限，免鉴权配对端点可被巨体耗尽内存
- **报告**：2026-11-10（用户：互联 host 安全审查 V-E2 / H2b）
- **真实性**：✅ 真 bug（94317ab6295）。`packages/fushi_engine/lib/sync/remote_lookup_routes.dart:102-113` 的 `readJsonObjectBody` 直接 `request.readAsString()` 整读；免鉴权的配对端点 `fushi_sync_server/pairing.part.dart:32,69,270` 经它读体（豁免在 `auth.part.dart:14-20`），任何人都能用巨体打满内存。各路由另有裸 `readAsString()`：`fushi_sync_server/video.part.dart:335,545,592`、`library.part.dart:290,619,670`、`sync_state.part.dart:294`、`host_update.part.dart:77`、`ai_relay_routes.dart:57`、`assistant/host_assistant_routes.dart:35`、`downloads/host_download_routes.dart:52`、`subscriptions/host_subscription_routes.dart:53,83`、`host_jobs/host_job_routes.dart:54,89`、`fushi_manga_ocr_host.dart:472`（建任务）与 `:550`（整页图 `read().forEach` 进 BytesBuilder）。扩展 API `fushi/lib/src/sync/fushi_api_server.dart:430-436` 在 header/query key 校验失败后、回 401 前 `await request.readAsString()` 整读，且 `provided == key` / `bodyKey == key` 不是常量时间比较。修复前新测试实测：`POST /api/pair/v2` 发 64 KiB 合法 JSON 得 200 并建会话；声明 `Content-Length: 100000000` 只发 1 KiB 时服务端一直挂着等体（5 s 超时）；扩展 API 不带 key 发 70 MiB chunked 正文得 401（整读完才回）。
- **[x] ① 已修复**（`8d604bb5312`）— `bounded_read.dart` 新增 `readBoundedRequestBody`（声明长度超限不等数据直接抛；累计超限立即抛）；`remote_lookup_routes.dart` 新增 `readBoundedBodyString`、`kInterconnectJsonBodyMaxBytes`（64 MiB）、`kPairingBodyMaxBytes`（16 KiB）与 `bodyLimitMiddleware()`（`BodyTooLargeException` → 413 `{"reason":"body_too_large"}`），`readJsonObjectBody` 加 `maxBytes` 并不再吞超限异常。`FushiSyncServer._buildHandler` 与 `FushiApiServer.start` 的 pipeline 挂上该中间件；配对三端点用 16 KiB，上列裸 `readAsString()` 全部换成有界读取；`host_job_routes.dart` 建任务 64 KiB、`inputs/match` 1 MiB，`fushi_manga_ocr_host.dart` 建任务 64 KiB（外层 `catch (_)` 前放行超限异常）、页图 64 MiB。扩展 API 鉴权失败分支为找 body key 最多读 64 KiB（`kApiKeyBodyProbeMaxBytes`），key 比较改走 `FushiPairingProtocol.constantTimeEquals`。
- **[x] ② 已加自动化测试** — `fushi/test/sync/fushi_sync_server_body_limit_test.dart`（真 server + 原始 socket：pair/v2 64 KiB → 413 且不建会话、声明 100 MB 只发 1 KiB → 5 s 内 413、已鉴权 2 KiB 书进度 PUT 仍 200；`/api/jobs` 与 `/api/ocr/job` 建任务超 64 KiB → 413 且不建任务、`inputs/match` 与页图声明超限 → 413 且不等正文）；`fushi/test/sync/fushi_api_server_access_test.dart`（不带 key 的 70 MiB chunked → 413；body 带 key < 64 KiB 仍放行、错 key 401）；`fushi/test/utils/bounded_read_request_body_test.dart`（声明超限 / 分块累计超限 / 恰等上限 / 声明小实际超发）。
- **评审修正（2026-11-11，`541c0965660`）**：扩展 API 鉴权失败分支探 body key 超过 64 KiB 时，若 header / query 里已带了凭据（只是不对）回 401 而不是 413——浏览器扩展（`tools/browser-extension/background.js` 的 `fetchWithAutoConfigRetry`）只在 401 时重读自动配置换新 key 重试，带截图 / 音频的大制卡请求回 413 会直接失败。没带任何凭据（body key 客户端）超限仍 413（契约 A）。测试：`fushi_api_server_access_test.dart`「Basic 头里 key 过期 + 正文超过 64 KiB → 401」。
- **备注**：dart:io 边界——HttpServer 对从未订阅过的请求体会在写响应头前整份 drain（`_HttpOutgoing.writeHeaders`），取消订阅又会让解析器直接 destroy 连接（`_HttpParser` body onCancel），两种都发不出 413；所以超限时订阅停在暂停，413 写完后 dart:io 因正文未读完关闭连接。客户端若仍在大量发送，个别平台上 RST 可能让对端读不到 413（服务端内存仍有界）。`inputs/match` 用 1 MiB 而非 64 KiB：每条 `{name, sha256, size}` 约 150–300 字节，64 KiB 只容两三百个文件，超限时 client 会静默退回整份上传。
