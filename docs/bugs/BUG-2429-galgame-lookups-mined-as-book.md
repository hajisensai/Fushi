## BUG-2429 · galgame 查词/制卡/收藏被记成 book 来源，游戏统计缺四个指标
- **报告**：2026-09-10（用户：「总览还少了统计查词制卡」「游戏查词制卡收藏收藏句子都要补上，所有界面都要统一」）
- **真实性**：✅ 真 bug，而且不是「忘了显示」——游戏域**根本没有这四个数字**。根因是三处写入面把 galgame 的查词 / 制卡 / 收藏硬写成 `kStatSourceBook`：`fushi/lib/src/lookup/global_lookup_controller.dart:1698`（`addLookupCount`）、`fushi/lib/src/lookup/overlay_bridge_handlers.dart:289/298/306`（收藏词）与 `:430/:432`（制卡 + 制卡句）、`fushi/lib/src/pages/implementations/texthooker_page.dart`（吃 `DictionaryPageMixin.dictionarySourceType` 的默认 `book`）。值域本身也只有两桶：`packages/fushi_core/lib/src/database/stat_source_kind.dart` 的 `StatSourceKind` 只有 `book` / `video`。后果是双向的：游戏 tab 的时段卡只剩「游玩次数」一行，而阅读 tab 的查词 / 制卡数**虚高**——galgame 里查的词全算在阅读头上。
- **[x] ① 已修复** — 补 `game` 来源并按真实表面分流：值域加 `kStatSourceGame` / `StatSourceKind.game`（`stat_source_kind.dart`）与 `kFavoriteSentenceSourceGame`（`packages/fushi_audio/lib/src/audiobook/favorite_sentence_repository.dart`）；判据收进唯一真相源 `fushi/lib/src/lookup/overlay_stat_source.dart`（`overlayStatSourceType()`：`GalHookSessionController.instance.activityGameKey` 非空 → 游戏域），两个 app 外写入点改用它；app 内的 texthooker 页覆写 `dictionarySourceType => kStatSourceGame`。★ 的可见行为逐字节不变：`overlayToggleOrCheckFavoriteWord` 判「已收藏」跨 book/game 两源、取消时两源都清、新增只写当前源（不产生重复计数）。消费端 `StatCounterFacts.favoriteSentenceEvents` 的穷尽 switch 补 game 分支，且 book 分支同时排除 video 与 game——漏排一个，游戏收藏句就在两域各计一次，「总览 = 三域之和」的恒等式当场破掉。游戏 tab 的时段卡补齐 5 条副行，空态判据并进 counters（只查过词没玩满一次会话时不再误判空）。
- **[x] ② 已加自动化测试** — `fushi/test/lookup/overlay_stat_source_test.dart`（判据两态 + 跨源 ★ 三条纪律，内存 DB 真读写）；`fushi/test/stats/stat_counter_facts_test.dart` 的恒等式组从「= book + video」升级为「= book + video + game」并新增收藏句三域分流；`fushi/test/database/media_domain_kinds_test.dart` 改写原先钉 `tryParse('game') == null` 的两条；`fushi/test/pages/statistics_center_static_test.dart` 把「总览计数面与域 tab 同一份切分判据」从两域扩到三域。
- **备注**：**不回填历史数据**。旧行的 `source_type` 已经是 `'book'` 落库且不带任何游戏身份，没有可靠判据能认回来，硬猜只会把阅读域的真数据搬走。所以升级后游戏 tab 这四个数字从 0 开始长，这是预期行为。另两条已知限制：① 判据是**会话级**的——游戏在跑期间用户切到浏览器里划词也会记进游戏域（精确到「这次查词的句子来自 hook」需要把来源标记从 C++ 浮窗一路穿到每个写入点，成本与收益不成比例）；② galgame 侧目前**没有任何收藏句入口**（收藏句只有阅读器与视频页写），所以游戏 tab 的「收藏语句」恒为 0，等 galgame 侧有了收藏句功能它自然会有数。
- **顺带修掉的两条本轮自伤**（写会话编辑时引入、由测试抓出）：① `FushiDatabase.getStudySegmentsByUids` 空集返回 `const []`（不可变），而调用方 `applyStudySessionEdit` 要 `sort` ——**纯时长游戏会话**（没有 hook 字数段，`segmentUids` 为空）点编辑必抛 `Cannot modify an unmodifiable list`，而那条路径正是 chars-only 段特例存在的理由；改成返回可增长空列表（与本表其余查询同契约）。② 游戏骨架行 `galgame_sessions.dateKey` 的编辑侧用了 `statDateKeyOf`（减 `statDayResetHour`），而唯一的生产写入点 `GalHookSessionController` 用的是纯日历日 `FushiTimeFormat.dayKey`——重置时刻非 0 的用户编辑一次就会把该条游玩会话挪到隔壁天、按日聚合跟着跳；编辑侧改用 `statCalendarDayKeyOf` 与写入侧对齐（只做对齐，不在本 PR 里统一两张表的口径）。
