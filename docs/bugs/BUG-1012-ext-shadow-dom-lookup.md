## BUG-1012 · 浏览器扩展无法读取Shadow DOM内文字(B站评论区)
- **报告**：2026-07-22（用户：）
- **真实性**：✅ 真 bug。根因 `tools/browser-extension/vendor/selection.js:74`（`getCaretRange`，三镜像同源 `hibiki/assets/popup/selection.js` / `hibiki/assets/browser_extension/vendor/selection.js`）。取词引擎只在顶层 `document` 上调用 `caretPositionFromPoint` / `elementFromPoint`，不穿透 open Shadow DOM。B 站新版评论区用 Web Component `<bili-comments>`（shadow root 渲染），这些 API 命中的是 shadow 宿主元素（元素节点）而非内部文字节点，`getCharacterAtPoint`（`selection.js:104` 附近）在 `nodeType !== Node.TEXT_NODE` 处直接 `return null`，取词失败。Yomitan 的 `DOMTextScanner` 会沿 `element.shadowRoot` 下钻，所以能读同一处评论。
- **[x] ① 已修复** — 提交见 PR#337（合入 develop）。`getCaretRange` 消除「caret 命中非文本节点就死」的特殊情况，统一为：caret 命中文本节点直采；否则 `deepElementFromPoint` 沿 `element.shadowRoot` 逐层 `elementFromPoint` 下钻到最深元素，再 `charRangeInContainer` 逐字几何命中；最后 webkit `caretRangeFromPoint` 兜底。三份镜像 `selection.js` 逐字节同步。向后兼容：普通网页文本走 caret 直采路径，行为不变；旧浏览器无 `caretPositionFromPoint` 时等价原 TreeWalker 几何命中。
- **[x] ② 已加自动化测试** — `hibiki/test/lookup/browser_extension_shadow_dom_lookup_bug1012_test.dart`（+ node 行为 harness `..._bug1012_test.js`）。行为级：node 真执行 selection.js，在含 shadow 宿主的 fake DOM 里断言 `getCharacterAtPoint` 穿透取到 shadow 内部文字（已硬验证：修复前源码此断言失败、修复后通过）；源码级：三份镜像都含 `deepElementFromPoint` / `shadowRoot.elementFromPoint` / `charRangeInContainer` 穿透逻辑且逐字节一致。
- **备注**：reader 阅读器用的是 `lib/src/reader/reader_selection_scripts.dart` 内联的独立 `window.hoshiSelection`（EPUB WebView 内无页面 shadow DOM），未受影响、未改动。
