## BUG-4772 · 随包的 7-Zip（7z.exe / 7z.dll，含 unRAR 派生代码）没进应用内原生许可清单
- **报告**：2026-11-17（用户：PR #3567 合入后的遗留项核实「随包的 7-Zip 没有进应用内的原生许可清单」）
- **真实性**：✅ 真 bug（许可合规缺口）。根因：
  - `tools/bundle_7za.ps1:22-25` 钉死 7-Zip 26.02（`7z2602-x64.exe`，SHA-256 `6745FA76…82EF0`），`:84-87` 把 7z.exe / 7z.dll / License.txt 放进 `{app}\7za\`；`.github/workflows/release-desktop.yml:858-866` 每次 Windows 发布都跑它，`native/fushi_shell_thumbs/src/win/sevenzip.rs:327` 的缩略图宿主也加载这份 7z.dll。
  - 但开源许可页的原生部分只来自 `native/third_party_licenses/manifest.json`（经 `fushi/tool/native_licenses.dart` 生成 `fushi/assets/licenses/native/`），它的 `prebuilt` 节只登记 pub 包 / Gradle 带进来的预编译库，发布脚本直接下载的 7-Zip 不在任何清单里：修前在 manifest.json 与 index.json 里 grep `7-zip|7zip|unrar` 零命中。7-Zip License.txt 写明「Redistributions in binary form must reproduce related license information from this file」，应用内看不到它，只有安装目录里那份 License.txt。
- **[x] ① 已修复** — `native/third_party_licenses/manifest.json` 的 `prebuilt` 节加 7-Zip 26.02 条目（LGPL-2.1-or-later AND unRAR restriction AND BSD-3-Clause AND BSD-2-Clause，platforms 只 windows，source 写明脚本、下载 URL 与 SHA-256）。许可原文取自上游真实文件：`native/third_party_licenses/texts/7zip-26.02/License.txt` = 按脚本钉的 URL 下载、SHA-256 校验一致的 `7z2602-x64.exe` 里的 License.txt（只把 CRLF 换成 LF，仓库 `eol=lf`）；`DOC-copying.txt` = `raw.githubusercontent.com/ip7z/7zip/26.02/DOC/copying.txt`（License.txt 引用的 GNU LGPL 2.1 全文）。重跑 `cd fushi && dart tool/native_licenses.dart` 更新 `fushi/assets/licenses/native/`（新增 1 份文本，LGPL 2.1 全文与已有文本去重）。
- **[x] ② 已加自动化测试** — `fushi/test/build/native_license_registry_guard_test.dart`「tools/bundle_7za.ps1 随包的 7-Zip 登记在 prebuilt 里且版本与脚本一致」：从脚本读 `$Version`，断言 prebuilt 里恰有一条 component 指向该脚本的条目、版本一致、只 windows、license 含 LGPL-2.1 与 unRAR、texts 带 License.txt 且内容含 unRAR 限制条款。撤掉清单条目或升级脚本版本不改清单都会红；已有的指纹守卫保证生成产物同步。
- **备注**：纯清单 / 资产改动，无设备相关路径；未在真机上打开开源许可页目视确认（许可页由 `registerAssetLicenses` 读 index.json，已有守卫覆盖装配）。
