## BUG-1667 · 安卓上用 android.db 配本地音频跑不通：导入被复制两次（cache + 库目录），峰值需 2 倍体积
- **报告**：2026-08-15（用户转述第三方反馈：“i can't get local audio via referencing an android.db file to work”，未给出平台与复现步骤）
- **真实性**：✅ **真 bug（沿真实代码路径 + 本机真库取证）**。
  - **根因 ①（安卓导入不可行）**：`fushi/lib/src/settings/settings_schema_lookup.dart:1084` 的 `onPickLocalDb` 是全 app **唯一**还在用裸 `FilePicker.platform.pickFiles()` 的大文件导入入口。读 pub-cache 里 file_picker 8.3.7 的安卓实现 `FileUtils.openFileStream`（`.../file_picker-8.3.7/android/src/main/java/com/mr/flutter/plugin/filepicker/FileUtils.java:288-320`）：安卓上它把选中文件**整份同步复制进 app cache**（8KB 缓冲 + `fos.getFD().sync()`），返回缓存路径；随后 `LocalAudioManager.importFile`（`fushi/lib/src/models/local_audio_manager.dart:242` 的 `sourceFile.copy(internalPath)`）**又复制一份**进库目录 → 峰值需要 **2 倍库体积的内部存储**。本机真库取证：`D:\APP\HIBIKI_date\support\local_audio_1782831652275.db` = **6.2 GB**（`entries` 877464 行 / `android` 472955 行），即安卓导入它需要 12.4 GB 内部空间、两次全量拷贝，全程只有一个转圈动画、无进度无取消，失败只弹一条裸异常。多数手机的结果就是「卡死或失败，怎么弄都不工作」。仓库里早有正解 `pickRealFilePath()`（`fushi/lib/src/media/import/real_path_directory_picker.dart`，安卓走原生 SAF + `MANAGE_EXTERNAL_STORAGE` 解析真实绝对路径、零复制），视频 / 书 / 有声书 / 漫画 / 字幕 / 制卡音频**全部已迁**，本地音频库是唯一漏网的。
  - **根因 ②（安卓没有「引用」这条路）**：BUG-483 的「引用原文件不复制」开关被 `dictionary_settings_dialog_page.dart` 用 `isDesktopPlatform` 硬门控，理由写在注释里——「移动端 file_picker 给的是会被系统清掉的缓存临时副本」。该前提在 `pickRealFilePath` 落地后**已不成立**：安卓授予全文件访问后拿到的是真实路径，根本不产生副本。判据错在拿**平台**当**路径出处**用。
  - **根因 ③（重复建索引 / 写用户的原始文件）**：`LocalAudioDb.ensureIndexes`（`fushi/lib/src/utils/misc/local_audio_db.dart`）与安卓 `TtsChannelHandler.java` 都无条件跑 `CREATE INDEX IF NOT EXISTS idx_entries_expr_read ...`，而它**只按索引名判存在**。真库自带的等价索引叫 `idx_expr_reading` / `idx_android`（本机两个真库实测都有，另有 `idx_all(expression,reading,source)` 前缀覆盖），名字对不上就照建一遍完全重复的索引。引用模式下这是**用户的原始文件**——选了「不复制」的用户被我们开 readWrite 句柄写（安卓侧还额外 `enableWriteAheadLogging()` 改库头并落 `-wal`/`-shm`）。
- **证伪记录（避免后人重走）**：曾怀疑「首次绑定重建索引期间 500ms 查询预算（`kLocalAudioQueryBudget`）恒超时 → 一直没声音」。实测**不成立**：把 6.2 GB 真库的两条索引删掉再重建，总耗时 **1.6 秒**、文件零增长（SQLite 直接从已有等价索引重建）。查询本身走索引，`食べる`/`日本語`/`帯広` 实测 0.4~1.7 ms 全部命中。桌面侧未复现任何失败。
- **[x] ① 已修复** —
  - `settings_schema_lookup.dart`：`onPickLocalDb` 改走新增的 `pickRealFilePathDetailed()`；是否引用由**路径出处**决定（`picked.isRealPath`），拿到 cache 临时副本时降级为复制并弹 `local_audio_reference_unavailable` 告知用户；移除本文件对 `file_picker` 的依赖。
  - `real_path_directory_picker.dart`：新增 `PickedFilePath{path, isRealPath}` + `pickRealFilePathDetailed()`，如实交出路径出处（安卓 SAF=true，file_picker 回退分支=false）；`pickRealFilePath()` 退化为丢掉出处的薄封装，既有 8 个调用点零改动。
  - `dictionary_settings_dialog_page.dart`：引用开关的门控从 `isDesktopPlatform` 改为 `_canReferenceOriginal`（桌面 + 安卓）；**安卓默认开**（复制 1~6 GB 进内部存储不该是移动端默认），桌面维持原默认（关）不改既有行为。
  - `local_audio_db.dart`：索引真相源从裸 DDL 串改为「表 + 列」spec，建之前先**只读**体检 `PRAGMA index_list` / `index_info`，已有等价索引（现有索引前缀列 == 目标列，排除部分索引与表达式索引）就跳过；全部齐备时**连 readWrite 句柄都不开**。
  - `TtsChannelHandler.java`：同一判据的 Java 实现（`ensureQueryIndexes` / `hasEquivalentIndex`）；绑定时**先按 `OPEN_READONLY` 开**库，只读开失败才回退到原来的 `OPEN_READWRITE` + WAL（功能永不比改前差）。
  - 新增 i18n key `local_audio_reference_unavailable`（17 语言，经 `tool/i18n_sync.dart` + `dart run slang`）。
  - 随代码迁移同步更新的既有守卫（**只改锚点，断言意图一条没减**）：`test/tools/file_picker_discipline_guard_test.dart` 按「清单只减不增」删掉本地音频那条豁免（该条注释里原本就挂着这个 TODO）；`test/utils/misc/local_audio_query_offload_test.dart` 的 DDL 区段锚点从 `_indexDdls` 改到 `_indexSpecs`→`queryMeta`；`test/media/video/real_path_directory_picker_test.dart` 的逃生口断言改查 `pickRealFilePathDetailed` / `_detailedFallback`；`test/pages/audio_db_import_error_guard_test.dart` 的条目数来源从 `result.files.length` 改到 `e.count`。
