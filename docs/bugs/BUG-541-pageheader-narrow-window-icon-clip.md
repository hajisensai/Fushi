## BUG-541 · 页头窄窗动作图标被裁切
- **报告**：2026-07-04（用户：）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/utils/components/hibiki_material_components.dart:1697`（`HibikiPageHeader.build` 动作区）。`Flexible(fit: FlexFit.loose)` 内套 `Align(alignment: Alignment.centerRight)`：`Align` 无 `widthFactor` 时会撑满其收到的最大约束，把 `Flexible` 的 loose 语义变成「恒占 flex 份额」。它与标题 `Expanded`（默认 flex=1）平分剩余宽 → 动作视口恒占页头右半幅，与图标实际总宽无关。窄窗（如桌面 master-detail 约 208px 左栏 / 手机竖屏）下 4 个动作图标（add/folder_copy/collections_bookmark/bar_chart）自然宽 > 右半幅视口，内层 `SingleChildScrollView(reverse: true)` 把最左侧 `Icons.add` 裁到视口起始边之外，用户看到像个「-」。共用面：书架（`reader_hibiki_history_page.dart`）、词典（`home_dictionary_page.dart`）、视频（`home_video_page.dart`）三个 home tab。历史：`7ce19740c`（TODO-616 引入 Flexible+scroll）、`3df631aaf`（TODO-955 加 Align centerRight）。
- **[x] ① 已修复** — 去掉 `Align`，动作区改为按内容自然宽：`Flexible(fit: FlexFit.loose)` + 横向 `SingleChildScrollView`（去 `reverse`）。内容放得下时 loose 让动作区只占自身自然宽（不撑满），标题 `Expanded`(tight) 吃满剩余把动作区挤到整条页头最右侧——所有图标可见且靠右，宽窗行为零变化；仅当动作总宽超过整行可用宽时 Flexible 才收缩 + 横滚兜底，消除 RenderFlex overflow。改动文件 `hibiki/lib/src/utils/components/hibiki_material_components.dart:1686-1711`。提交见备注。
- **[x] ② 已加自动化测试** — `hibiki/test/widgets/hibiki_material_components_test.dart` 新增窄窗守卫：4 个动作图标（含最左 `Icons.add`）在受限窄宽（300 / 208）下 pump，断言 `tester.takeException()` 为 null（无 RenderFlex overflow）且所有动作图标（尤其最左 add）水平落在页头视口内、未被裁到左缘外；宽窗对照断言动作靠右不变。既有 `right-aligns actions when content fits` / `scrolls actions without overflow on narrow width` 用例继续绿。
