## BUG-2452 · 桌面 Mihon 源被 Cloudflare 拦下时无法解题，源整个打不开
- **报告**：2026-09-11（用户：全量实测 127 个扩展后，Hachiraw / Kumaraw / RawMiu 三个源热门榜就 403；用户要求「桌面没有 Cloudflare 解题，修复一下」。）
- **真实性**：✅ 真缺口。三站实测（经本机代理、浏览器 UA 与 okhttp UA 各一次）全部 `403 + Server: cloudflare + Cf-Mitigated: challenge`，body 含 `Just a moment...` / `challenge-platform/.../chl_page` / `cType: 'managed'`——是 Cloudflare managed challenge，换 UA 无效，只能真实浏览器过盾后复用 `cf_clearance`。桌面链路上三处都是空的：sidecar `upstream_src/.../network/interceptor/CloudflareInterceptor.kt:14-20` 纯 passthrough；`desktop_mihon_runtime.dart` 的 `decodeErrorResponse` 只认 `sourceHttp`/`bridge` 两种 `errorKind`；`DesktopMihonRuntime` 不实现 `ChallengeMihonRuntime`，`MihonCloudflareAction`（`mihon_cloudflare_action.dart:73-76`）据此在桌面永远渲染成 `SizedBox.shrink()`。Android 端三处都有（`fushi/android/.../CloudflareInterceptor.kt` + `CloudflareChallengeActivity`）。
- **[x] ① 已修复** — `3ac2414346`（sidecar）+ `707c0b8d1c`（宿主）。
  - sidecar：overlay `CloudflareInterceptor.kt` 照 Android 判据逐字复刻（403/429/503 + `Server: cloudflare` + `cf-mitigated: challenge`，裸 403/503 不算），抛 `CloudflareChallengeRequiredException(url, userAgent)`；`DalvikHandler.errorResponse` 沿 cause 链找到它，编成 `errorKind: "cloudflare"` + `challengeUrl` + `userAgent`。
  - 宿主：`decodeErrorResponse` 解成 `MihonCloudflareChallengeException`；`DesktopMihonRuntime implements ChallengeMihonRuntime`，`solveCloudflare` 经 `MihonCloudflareGate.resolver`（`main.dart` 启动时 `installMihonCloudflareResolver(navigatorKey)`，桌面且非 Android）推一页解题 WebView，按 host 单飞；解题页**直接复用** `AidokuCloudflareChallengePage`（只把 jar 参数从 `AidokuCookieJar` 放宽到共同基类 `MangaCookieJar`），用 sidecar 实际发出的 UA 打开被拦 URL，轮询到值不同于 jar 现存条目的 `cf_clearance` 后整站写回**运行时自己的 jar**，下一次调用随 `X-Fushi-Cookies` 注入，不重启子进程。用户关页 → `CHALLENGE_CANCELLED`（UI 不当失败显示）；没装 resolver → `CHALLENGE_UNAVAILABLE`。
- **[x] ② 已加自动化测试** — Kotlin：`CloudflareInterceptorTest`（真实回环 HTTP：带标记 403/503 抛出并带 URL/UA、源自带 UA 优先、无标记 403/503 与非 cloudflare Server 直通）、`DalvikErrorResponseTest` 两条（裸/包裹的挑战异常都编出三字段、普通失败无挑战字段），完整 JVM 套件 63 项 0 失败。Dart：`fushi/test/media/manga/desktop_mihon_cloudflare_test.dart`（信封解码含无效 URL 退回、运行时声明 `ChallengeMihonRuntime`、resolver 缺失/取消/成功三态且收到同一 jar 实例、安装函数按 host 单飞与 navigator 早退不毒死），加既有 cloudflare/login/runtime 四个套件共 30 项通过。
- **真实验证**：修复版 jar 对真实 `hachiraw.net`：`errorKind=cloudflare`、`challengeUrl=https://hachiraw.net/list-manga?order_by=views`、`userAgent=Mozilla/5.0 (…) Chrome/91.0.4472.124 Safari/537.36`（sidecar 默认 `http.agent`）。**UI 段（弹页过盾 → cookie 回注 → 重试 200）未在真 app 里跑过**，标 `implemented_unverified`：宿主侧只有 widget 测试与 resolver 桩。
- **已知边界**：
  - `cf_clearance` 绑 IP：解题 WebView2 走系统代理，sidecar 走宿主代理策略；两者出口不一致时过盾后仍 403。本机两者都经 `127.0.0.1:34151`，一致。Android 用 BUG-2275 的隔离代理让两边同出口，桌面这轮没做。
  - sidecar 默认 UA 是 2021 年的 Chrome/91（`upstream_src/AndroidCompat/.../AndroidCompatInitializer.kt:29-32`），Cloudflare 对旧 UA 可能更敏感；解题 WebView 用同一串所以 cookie 对得上，但被拦的概率本身偏高。换 UA 要连 cookie 一起当「登录身份」整体存取（`desktop_mihon_runtime.dart:118-123` 的既有注释），另立任务。
  - `/source-image` 路径（阅读时取图）未接挑战识别；通常同站 `cf_clearance` 已在 jar 里，图片请求跟着注入。
- **备注**：`third_party/m_extension_server/UPSTREAM` 已补 overlay 清单与说明。
