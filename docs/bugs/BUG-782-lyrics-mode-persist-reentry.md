## BUG-782 · 重新进入书籍不再是歌词模式（歌词模式跨会话不恢复）
- **报告**：2026-07-13（用户：重新进入书籍又不是歌词模式了）。
- **真实性**：✅ **既有有意行为，按用户请求改为可恢复**（非缺陷回归）。`reader_hibiki_page.dart` `_initBookInner` fresh open 时 `_lyricsMode = false` 并 `await ReaderHibikiSource.instance.setLyricsMode(false)` **抹除**持久化的 `lyrics_mode` 偏好。注释原因：直接按 persisted lyrics_mode 让 WebView 整页加载歌词 HTML、跳过 EPUB 正文，iOS 大字幕书会内容超时甚至白屏。故歌词模式此前被当「瞬时显示态」每次开书重置——用户想要「重进还在歌词模式」故不满足。
- **[x] ① 已修复** — `8208be307`。改为**安全延迟恢复**：① `_initBookInner` 不再抹除偏好，改为把「上次是歌词模式」记成一次性意图 `_pendingLyricsRestore = ReaderHibikiSource.instance.lyricsMode`（仍 `_lyricsMode=false` 起步，fresh open 绝不直接整页加载歌词 HTML → 保留 iOS 白屏防护）；② `_onChapterLoadComplete` EPUB 正文首次就绪且有声书已挂载后（此刻正文已加载，切歌词等价用户手动切、已知安全），若 `_pendingLyricsRestore && _audiobookController != null && !_lyricsMode` 则 `_toggleLyricsMode()` 进入歌词模式，随即清零意图防每章重触发；无有声书则不恢复（歌词模式依赖音频）意图也一并清掉。退书时不抹偏好，故下次开书恢复。根因修（时序安全的恢复），非绕过。
- **[x] ② 已加自动化测试** — `test/pages/reader_lyrics_mode_reopen_guard_static_test.dart` 由「fresh open 绝不恢复」改写为「起步仍正文 + 捕获意图代替抹除」（守 `_lyricsMode=false` 起步防白屏、`_pendingLyricsRestore = ...lyricsMode`、`_initBookInner` 内不再 `setLyricsMode(false)`）；`test/pages/reader_lyrics_input_bridge_guard_static_test.dart` 新增 BUG-782 用例（`_onChapterLoadComplete` 的 `if (_pendingLyricsRestore)` 触发含 `_audiobookController != null` + `_toggleLyricsMode()` + 一次性清零）。
- **备注**：reader/init 时序/iOS 白屏防护类。代码 + 单测绿、`flutter analyze` 0 issue、`dart format` 0 改动。**真机复测**（在歌词模式退书 → 重开同书自动回歌词模式且不白屏；手动退歌词模式后重开为正文；无有声书的书不误进歌词；iOS 大字幕书不白屏/超时）待用户后补——iOS 白屏是平台行为必须真机验。与 BUG-781（跟随滚动）同批。
