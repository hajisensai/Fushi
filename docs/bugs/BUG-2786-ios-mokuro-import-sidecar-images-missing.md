## BUG-2786 · iOS 上导入 .mokuro 文件必失败（选单文件只拷进来 .mokuro、选文件夹无沙盒外读权限）
- **报告**：2026-09-28（转述 iPhone 用户：mokuro 文件传不上去）
- **真实性**：✅ 真 bug（代码路径确认，未在 iPhone 上复现）。漫画导入框 `fushi/lib/src/media/manga/manga_import_dialog.dart` 调 `pickRealFilePath`，`fushi/lib/src/media/import/real_path_directory_picker.dart` 在 iOS 上按「返回真实路径、不复制」处理（`isRealPath: true`），这个前提是错的：file_picker 8.3.7 iOS 选文件用 `UIDocumentPickerModeImport`（`FilePickerPlugin.m:217`），选中的文件被挪进 `NSTemporaryDirectory()/<文件名>`（`:411-427`），只有那一个 `.mokuro`；`packages/fushi_engine/lib/media/manga/manga_importer.dart` `importFromMokuroPath` 在 `.mokuro` 同目录找页图 → 缺图报错。选文件夹走 `UIDocumentPickerModeOpen`，直接返回沙盒外路径，插件和本仓（`ios/Runner`、`lib`）都没有 `startAccessingSecurityScopedResource`，`dart:io` 列目录会被拒。`Info.plist` 也没开 `UIFileSharingEnabled` / `LSSupportsOpeningDocumentsInPlace`，用户没法把卷放进 app 自己的容器。
- **[x] ① 已修复（implemented_unverified：Swift 半边未在 iOS 上编译，也未在模拟器/真机验证）** — 新增 iOS 原生 `fushi/ios/Runner/FushiDirectoryImport.swift`，实现与 Android 同名同契约的 `app.fushi.reader/saf` `pickAndCopyDirectory {destPath}`：`UIDocumentPickerViewController(forOpeningContentTypes: [.folder], asCopy: false)` 选文件夹 → `startAccessingSecurityScopedResource()` → 先删后建 `destPath` → `NSFileCoordinator` 协调读、整卷拷到 `destPath/<文件夹名>` → `stopAccessing…` → 主线程交回该路径；取消 / 下拉关闭回 `nil`，失败回 `COPY_FAILED` 并删掉半截拷贝，已有挂起回 `BUSY`，其它方法 `FlutterMethodNotImplemented`。`AppDelegate.swift` 的 `installChannels` 强引用注册（呈现者取最顶层 VC），`project.pbxproj` 四处登记。Dart 侧 `real_path_directory_picker.dart` 新增 `pickImportDirectory` / `PickedImportDirectory{path, stagingRoot}` / `DirectoryImportCopyException`：iOS 走原生拷贝到 `<临时目录>/import_staging/<stagingName>`，其它平台原样委托 `pickRealDirectoryPath`；`pickRealFilePathDetailed` 在 iOS 如实标 `isRealPath: false`（import 模式的临时副本），并改掉「iOS 返回真实路径」的错误注释。`manga_import_dialog.dart`：`_pickFolder` 改走 `pickImportDirectory(stagingName: 'manga')`，拷贝失败红 toast（不再伪装成取消），暂存副本在关框（`dispose`）或被非暂存路径替换时删除——有意不在每次导入结束就删：导入失败时对话框不关，用户原样重试需要副本还在；成功时对话框随即关闭，同样会删。`_pickFile` 在 iOS 单选的 `.mokuro` 同级没有页图（`MangaModule.canImportPath` 为 false）时直接提示「iOS 请选整卷文件夹或 zip/cbz」，不收下路径。词典目录导入（`dictionary_dialog_page.dart`）iOS 同走原生拷贝分支、改用原生**返回的**路径，拷贝失败可见。提交哈希：见本轮提交。
- **[x] ② 已加自动化测试** — `fushi/test/media/import/ios_import_directory_staging_test.dart`（经真实 channel 边界：iOS 方法名 + `destPath` 落在 `import_staging/manga`、返回原生路径与暂存根、`null` = 取消、`COPY_FAILED` / `BUSY` → `DirectoryImportCopyException`、安卓只调 `pickRealDirectory`、桌面三端只走 `getDirectoryPath` 不碰 channel、`discardStaging` 删暂存不删原位；外加接线守卫：`_pickFolder` 调 `pickImportDirectory`、AppDelegate 强引用注册、Swift channel/方法/错误码/安全作用域调用、pbxproj 四处登记）；`fushi/test/media/import/picker_extension_filter_test.dart`（iOS `isRealPath` 为 false、桌面三端为 true）；`fushi/test/tools/file_picker_discipline_guard_test.dart` 白名单理由同步。顺带发现并修掉的全平台 `.mokuro` 目录误判另记 BUG-2785。
- **备注**：本轮只修到「导入当场读目录」这一层。范围外、仍待跟进：① iOS 视频导入同样经 `pickRealDirectoryPath` / `pickRealFilePath` 拿沙盒外路径或 `tmp` 路径并**长期落库**引用，清 tmp 或重启后引用悬空；② 需要长期持有目录访问权的功能（来源库扫描根等）要改用 security-scoped bookmark 持久化，而不是一次性拷贝。Swift 半边须在 Mac 上 `flutter build ios` 编译 + 模拟器/真机走一次「选含 `.mokuro` + 页图子目录的文件夹 → 导入 → 阅读器可查词」才能升级为已验证。旧的绕行办法（整卷打包成 zip / cbz 导入，`fushi/lib/src/media/manga/import/manga_archive_importer.dart` 会读包内 `.mokuro`）仍然有效。
