## BUG-2602 · 媒体服务器库封面 404 时整格只剩占位图标
- **报告**：2026-09-19（用户：Windows 开发版接 `https://v1.uhdnow.com`，媒体服务器首页「媒体库」行 16 个库里后 4 个（国产动漫 / 日韩动漫 / 欧美动漫 / 追新）只有一个显示器图标，其余 12 个有封面）
- **真实性**：✅ 真 bug（服务端数据缺失 + 客户端无回退）。真服务器取证：`/Users/{uid}/Views` 对 16 个库**全部**报 `ImageTags.Primary`（所以 `JellyfinVideoClient.parseViews` 的 `hasPrimaryImage` 判据没错），但那 4 个库的 `/Items/{id}/Images/Primary` 任何变体（裸 / `maxWidth` / `tag=` / `/0` / `/emby/` 前缀 / CDN 直链 `/img/c/common/<id>.webp`）一律 404，正常库同路径 301 → CDN 200。客户端 `MediaServerLibraryCard`（`fushi/lib/src/pages/implementations/media_server/media_server_widgets.dart`）拿到必失败的图后 `errorBuilder` 只画类型图标，没有任何回退；而首页 `MediaServerHomeView._loadLibraryRow` 本来就为每个库拉了前 20 条有海报的条目，却没喂给库卡。
- **[x] ① 已修复** — `MediaServerLibraryCard` 新增 `fallbackItems`，库封面为 null **或加载失败**时用前 3 条有海报的条目拼成 16:9 `MediaServerLibraryCollage`（每列各自失败各自空底，不再往下回退）；首页把 `_libraryRows[library.id]` 接进去，不多发请求。服务器端真没图的库（含 Jellyfin 未配封面的库）从此显示条目海报拼贴，全部条目都无图时才画类型图标。
- **[x] ② 已加自动化测试** — `fushi/test/pages/media_server/media_server_library_card_test.dart`：库无封面 → 拼贴（跳过无图条目、只取前 3 张、不请求库封面）；库声称有封面但取图抛错（真 404 形态）→ 仍先请求库封面、失败后回退拼贴；条目也全无图 → 才画图标；首页把每库一行的条目喂给库卡。像素预览夹具 `media_server_pixel_preview_test.dart` 加了「国产动漫（404）」「追新（无封面）」两库，`FUSHI_PREVIEW=1` 出图已核对。
- **备注**：这是 UHD Media Server 兼容层（`ProductName: "UHD Media Server"`，见 `media-server-compat-embedded-subtitle-fallback` 记忆）自报 `ImageTags` 与实际图片资源不一致；原版 Emby / Jellyfin 库封面缺失时 `ImageTags` 就不带 `Primary`，走的是同一条「image == null」回退分支。不改 `hasCover` 判据——那会让正常服务器多发一次注定 404 的请求或漏掉真实封面。
