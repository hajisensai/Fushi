## BUG-3678 · Android 应用外悬浮球不认「显示按钮文字」，「打开 Fushi」关不掉
- **报告**：2026-10-23（用户：反馈 9bdhVTgq3A，vivo V2339FA / Android 14，3.0.0-debug.20585；「悬浮球取消了显示文字但无效，电脑上正常、手机不行；打开 Fushi 这一项没法关闭」，截图 s0：「显示按钮文字」关着、「应用内显示」关着，Fushi 里露出的是原生应用外球，展开后仍带「关闭悬浮球 / 打开 Fushi / 截屏识字」文字胶囊）
- **真实性**：✅ 真 bug。Dart 每次起球都下发 `startSystemBall.showLabels`（`fushi/lib/src/floating_ball/floating_ball_channel.dart` `startSystemBall`），Windows / macOS 原生都读它，但 Android 原生 `FloatingBallChannel.java` 的 `startSystemBall` 分支只把 actions / labels / icons / colors / ocrLanguage / tapClipboard 交给 `FloatingBallService.saveConfig`，`showLabels` 被丢掉；`FloatingBallService.buildMenuLabels` 只按列数与视口宽决定建不建标签胶囊，恒显示文字。规格 `docs/specs/2026-09-28-floating-ball.md` 还写着「Android 原生球只有图标、此开关不改变它」——那是补标签胶囊（M3E FAB menu）之前的描述，补胶囊时没把开关接上。「打开 Fushi」则是三端原生都硬编码在菜单里（Android `menuIds()`、Windows `FloatingBallWindow::ButtonIds()`、macOS `menuIds`），设置里没有入口。
- **[x] ① 已修复** — Android：`saveConfig` 新增 `showLabels` / `showOpenApp` 落盘（`ball_show_labels` / `ball_show_open_app`，缺省 true），`reloadConfig` 读回；`buildMenuLabels` 的建胶囊判据加 `showLabels`，`menuIds()` 按 `showOpenApp` 增删「打开 Fushi」。Windows（`Config.show_open_app`）/ macOS（`showsOpenApp`）同样按 `startSystemBall.showOpenApp` 增删。Dart：新偏好 `floating_ball.system_open_app`（默认开），设置 → 悬浮球 → 应用外按钮组第一项「打开 Fushi」开关，进起球签名，切换即重新下发。同一批（反馈同条的建议）：「点球查剪贴板」bool 升级为「点按悬浮球」三档（展开按钮 / 剪贴板查词 / 截屏识字，`floating_ball.tap_action`，旧 bool 自动迁移），原生 `tapAction` 收起态点一下直接执行、长按展开。
- **[x] ② 已加自动化测试** — `fushi/test/android/notification_small_icon_guard_test.dart`（「BUG-3678 应用外球认显示按钮文字与打开 Fushi 开关」：通道读参数、落盘读回、建胶囊判据带 showLabels、menuIds 按开关加 open_app；「点按悬浮球」动作守卫）；`fushi/test/floating_ball/round8_system_ball_motion_test.dart`（开关切换重新下发 `showOpenApp` / `tapAction`，旧 `tap_clipboard` 迁移成 `clipboard`）。
- **备注**：未上真机（Android / Windows / macOS 原生改动没有本地编译验证，CI 构建兜底）。
