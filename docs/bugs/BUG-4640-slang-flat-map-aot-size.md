## BUG-4640 · slang flat map 让 Dart AOT 胖 15 MB 并撑爆 Windows gen_snapshot 栈
- **报告**：2026-11-15（iOS 包体积调研 + Flutter 3.50 Windows release AOT 失败根因调查中发现）
- **真实性**：✅ 真问题。根因 `fushi/slang.yaml`（修复前没写 `flat_map`，slang 3.17 默认 true）：生成的 `fushi/lib/i18n/strings.g.dart` 里每种语言一个 `extension on _StringsXx { dynamic _flatMapFunction(String path) { switch (path) { … } } }`（约 1.2 万个 string case）+ `operator []`，唯一消费者是 slang 的 translation_overrides（`slang-3.17.0/lib/api/translation_overrides.dart:145`），本仓没开。代价：① iOS 真实快照画像（`--analyze-size`）里 17 个 `_flatMapFunction` 占 15.06 MB（App.framework 108.2 MB 的 14%），其它平台同比例；② Windows release AOT 时 gen_snapshot 把超长 string switch 降成 if-else 链，SSA 构建 `FlowGraph::RenameRecursive` 沿支配树递归，1 MB 主线程栈 0xC00000FD（BUG-1589，dart-lang/sdk#61935，CI 只靠 editbin 把栈拉到 128 MB 才过）。
- **[x] ① 已修复** — `fushi/slang.yaml` 加 `flat_map: false`。全仓确认没有对 Translations 的动态取值（`t['…']` / `$meta` / `getTranslation(` / `translations[`，命中的都是 Map 局部变量）；`operator []` 只在 flat map 开着时生成，所以以后有人写动态取文案会直接编译失败。唯一依赖 flat map 的是 `fushi/test/i18n/strings_test.dart` 的 `strings['…']` 自检，改成断言 getter。生成的 strings.g.dart 45.5 MB → 22.6 MB，gen_i18n 18 s。
- **[x] ② 已加自动化测试** — `fushi/test/build/slang_flat_map_disabled_guard_test.dart`（slang.yaml 必须 `flat_map: false`、不得开 translation_overrides；生成物不得含 `_flatMapFunction` / `setFlatMapFunction`，带 `class Translations` 规模哨兵）。
- **备注**：
  - Mac 实测（Flutter 3.47.6，`flutter build ipa --release --no-codesign`，与 BUG-4655 的 `--split-debug-info` 叠加）：App.framework/App 108,188,368 B（CI 11-14 develop 未签名 IPA）→ 75,971,968 B（−32.2 MB，−29.8%）。单项拆分取自 arm64 ELF A/B（同一份 kernel）：去 flat map −14.7 MB，DWARF 栈 −13.6 MB。
  - 本 PR 不动 BUG-1589 的 editbin 步骤：删它要先在 Windows 上用 stock gen_snapshot 实测一次 release 构建。（2026-11-15：PR #3400 已用 Flutter 3.50.0 stock gen_snapshot 实测通过并删除该步骤，见 BUG-1589 ①c。）
