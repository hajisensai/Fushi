## BUG-2735 · 从库移除游戏经 FK cascade 删光所有 Profile 的游玩会话
- **报告**：2026-09-27（PR #1697 审查阻断 1；所有者拍板「保留会话（改级联）」）
- **真实性**：✅ 真 bug。`galgame_sessions.gameId` 声明 `references(Galgames, #id, onDelete: KeyAction.cascade)`（`packages/fushi_core/lib/src/database/tables.dart` 旧 2592 行），生产开库 `PRAGMA foreign_keys = ON`（`database.dart:195`），于是游戏库「移除游戏」→ `GalgameRepository.remove` → `FushiDatabase.deleteGalgame`（`database_statistics.part.dart`）会级联删光该游戏在**所有 Profile** 下的游玩会话——删除框不勾「同时删除统计数据」也丢游玩时长，统计页 / 学习统计里的游戏时长跟着消失。游戏显示名只活在 `galgames` 行上，就算会话留下也只能显示裸 id。
- **[x] ① 已修复** — schema v113：`galgame_sessions.game_id` 改逻辑外键（迁移 alterTable 重建去掉 FK，保留自增 id，补回索引），新增 `game_title` 快照列；`deleteGalgame(id, sessionTitle:)` 同事务把当前显示名（含改名 / 刮削名，调用方 `GalgameRepository` 传 `displayName`，缺省回落 `galgames.name`）写进该游戏全部会话行；统计读取端（`loadStatFacts` 日面 / 会话流 / 活动流）在库内查不到游戏时用快照名（`getGalgameSessionTitles`）。勾了「同时删除统计数据」才走 `deleteGameStatisticsForId`（当前 Profile 的会话 + hook 字数段 + legacy 行）。备份「不带游戏」剥离（`_retainGames`）先显式删被剥游戏的会话，与旧 cascade 等价。提交见 PR #1697 追加提交。
- **[x] ② 已加自动化测试** — `fushi/test/database/migration_v113_galgame_sessions_logical_fk_test.dart`（v112 形态下删游戏确实 cascade → 迁移后 FK 消失、id 保留、删游戏会话仍在）；`fushi/test/database/statistics_delete_test.dart`「v113：从库移除游戏默认保留游玩会话」组（不勾保留 + 跨 Profile、快照名、勾上只删当前 Profile、统计事实面显示快照名）；`fushi/test/mining/galgame_repository_test.dart` / `migration_v55_galgame_library_test.dart` 原 cascade 断言翻面。
- **备注**：备份**合并**导入（`backup_merge_engine._mergeGalgameSessions`）仍按游戏映射 JOIN，源库里已是孤儿的会话不会被合并进来（与旧行为一致，未扩展）。
