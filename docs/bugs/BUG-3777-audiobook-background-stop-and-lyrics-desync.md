## BUG-3777 · 有声书后台久播会停；歌词模式后台播放回前台歌词与声音对不上
- **报告**：2026-10-25（用户：① 有声书后台播放时间长了会停掉；② 歌词模式后台播放一段时间回前台，歌词和声音对不上）
- **真实性**：✅ 真 bug（沿真实代码路径定位；**未真机复现**）。是 BUG-2961 之后的残留与新路径，分条（行号为 upstream/develop `9a86dbaa34` 基线）：
  - **B（确定）系统媒体按键 PLAY 被当切换**：audio_service 0.18.18（根 `pubspec.lock` 解析版本）原生 `AudioService.java:974-981` 的 `onMediaButtonEvent` 把真实的 `KEYCODE_MEDIA_PLAY` / `KEYCODE_MEDIA_PAUSE` 与 PLAY_PAUSE / HEADSETHOOK 一起走 `listener.onClick(eventToButton(event))`，`eventToButton`（`:988-1000`）对 PLAY / PAUSE 落 default 返回 `MediaButton.media`；Dart `fushi/lib/src/utils/misc/fushi_audio_handler.dart:46-50` 的 `click(media)` 按切换处理 → 播放中蓝牙 / 车机补发的 PLAY 把声音暂停（BUG-2961 备注「残留缺口 A」）。
  - **D（确定）后台图片停留永不恢复**：`fushi/lib/src/media/audiobook/audiobook_controller.dart:542` `triggerImagePause` 与 `:600` `awaitImageChapterPause` 先 `pause()` 再靠 Dart `Timer` 到点恢复；iOS 后台暂停后 App 立即被挂起，Timer 永不触发；Android 暂停让媒体会话离开 playing、前台服务降级，进程同样会被冻结 → 后台听到插图处彻底停住。
  - **R1（确定）跨章过渡期间歌词冻结**：歌词高亮下标来自 `_currentCue`（`lyrics.part.dart:746` `controller.allBookCueIdx`），而 `_updateCurrentCue` 在 `audiobook_controller.dart:1832` `if (_chapterTransition) return;` 早退、不 notify；后台时正文 WebView 被节流，跨章要等 8 秒兜底 abort（`navigation.part.dart` `_startContentReadyTimeout`），期间（以及 abort 本身不 notify）歌词停在进章那一句。
  - **R2（确定）回前台不重推歌词层**：`reader_fushi_page.dart:3782-3800` resumed 分支只调 `resyncReaderToAudio()`，它受 `shouldRevealCurrentCue` / 手动翻页护栏 / 跨章门控挡住，歌词层只能等下一句才纠正；另外 `lyrics_mode_html.dart` 的 `__lyricsSetProgress` 在 JS **执行时**才取扫过起点 t0（`_lySweepBuild` 里 `performance.now()`），Dart 发送时按真实位置算的 fraction 会因 JS 推迟执行整段落后于声音。
  - **R3（推断，未证实）**：`lyrics_mode_html.dart:683-695` 程序滚动只有 150 ms 免判窗（`_lyProgUntil`），`:837-839` 窗外任何 scroll 事件都判为用户手滑进入浏览态；回前台的 resize / 视口钳位若触发浏览器自发 scroll 会被误判。浏览器是否在 resize 时发 scroll 是 WebView 引擎行为，node vm 证实不了，**未改**。
  - **A（确定，所有者 2026-10-25 拍板「关着也保留最简通知保活」）**：关掉「显示媒体通知」后 `audiobook_session.dart:688` `_syncMediaNotification` 第一行 `if (!_showMediaNotification()) return;`，播放态从不推给 audio_service；而 audio_service 0.18.18 只在 `AudioService.java:559-560` `setState` 见到「未播放→播放」翻转时 `enterPlayingState()`（`:705-713`：`startForegroundService` + `PARTIAL_WAKE_LOCK` + `startForeground`），所以开关关着时前台服务 / 唤醒锁根本不建立，后台久播必被冻结。播放中关开关走 `:929` `clearNotification()` 推空 `PlaybackState()`（idle），`:565-567` idle 翻转直接 `stop()` 前台服务。另外设置页「听书」的开关（`settings_schema_listening.dart`）只落偏好、不通知会话，后台听书时切换要等下一次开会话才生效。
  - **F（诊断）**：控制器没订阅 `playbackEventStream` 的 error，后台被系统掐断 / 输出设备丢失时无任何日志。
