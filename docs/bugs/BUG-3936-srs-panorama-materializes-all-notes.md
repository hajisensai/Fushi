## BUG-3936 · 首页全景整批物化全部带出处的笔记，2 万卡大库启动主线程 ANR / OOM
- **报告**：2026-11-01（用户：应用内反馈 lGXA8zC1A2 / i8qNDs_V_D，同一台小米 Android 设备，约 1.9 万张卡）
- **真实性**：✅ 真 bug。i8qNDs_V_D 日志：3.1.0-debug.22074 启动阶段 `reason=ANR pss=1586632KB`，主线程（`"main"`）栈顶 `malloc` ← `ffsrs_materialize+196` ← Dart 代码；同一版本另一次 `stage=start ... maxRss=2639MB`。22074（2026-10-30 11:41）时首页全景面板默认可见（`18644e18ed` 加上首页「galaxy-first」，`81d0317f46` 10-30 23:27 才改成默认隐藏，用户打开开关后照样触发）。根因 `fushi/lib/src/media/panorama/panorama_library.dart:573`（修复前）：对「带出处修改记录的笔记」整批 `SrsDbStore.notes`，假设这种笔记很少（开发机 1.48 万条里 113 条），但全在 Fushi 里制卡的用户每条都带出处——每条笔记的全部字段原文与全部修改记录读进主 isolate、再整批交给 `ffsrs_materialize`（`packages/fushi_srs/lib/src/register_kernel.dart` `_Batch.run` 把整块原文拷进原生缓冲区，结果 JSON 再解码回 Dart）。同一用户 10-30 统计页单条 SELECT 读回超过 1 GiB（`length must be in the range [0, 1073741823]`，旧 `allNoteViews`），说明字段正文是 GB 级；全景只要每条的出处与抽中几条的字段。
- **[x] ① 已修复** — 新增 `SrsDbStore.noteFieldKeyValues(ids, fieldKey)`（`packages/fushi_engine/lib/srs/srs_db_store.dart`）：只读一个字段键的修改记录、只把它们交给寄存器内核（寄存器按键独立合并，与整条物化后取同一个键逐值相同）；全景改为只读 `source` 键，字段只为抽中且 sort_field 是内部编号的笔记物化（有上限）。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/srs_note_field_key_values_test.dart`：与整条物化的出处逐值相同（含被后来修改支配的旧值、没有出处的笔记）；2 万条笔记、每条 4 KiB 释义正文的合成大库上，读回 465 B/条（整条物化 14156 B/条），2 万条 409 ms。
- **备注**：真机未复测（按规则不做）。同一用户 3.2.0-debug.22671 同步卡在 `stage=start` 约 4.5 分钟后 scudo OOM 崩溃（`DartWorker` 线程、PSS 1.37 GB，开跑时 RSS 已 1058 MB）这一条**根因未定**，本修复不覆盖；已给一轮同步开头补细分步骤面包屑（`stage=start:<step>` + RSS，见 `fushi/lib/src/srs/srs_sync_scheduler.dart` `_step`），等下一份日志定位。
