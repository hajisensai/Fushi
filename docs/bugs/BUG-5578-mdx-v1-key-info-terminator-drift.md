## BUG-5578 · MDict 1.2 版 .mdx 导入一律报 `record block info overflow`
- **报告**：2026-11-27（应用内反馈 qC77I6m6CK：Xiaomi 2602BRT18C / 3.3.0，一次导入 5 本旧版 .mdx 词典〔金山词霸 09 转制、日汉 27 万等〕全部 `MDX parse error: mdx: record block info overflow`）
- **真实性**：✅ 真 bug。`native/fushidicts/fushidicts_src/mdx/mdx_reader.cpp` 的 key block info 遍历（修前 `:380-405`）对 v1 / v2 一律在首、尾词条副本后加 NUL 终止符（`+ null_term_bytes`）。但只有 v2 这样写；MDict 1.2 时代的容器（`GeneratedByEngineVersion="1.2"`）在 key block info 里存的是**不带终止符**的首尾词（readmdict 的 `text_term=0`）。于是每个块元数据都往后漂 1～2 字节，读出的 compressed / decompressed size 是垃圾，key block 遍历提前 break，`pos` 停在 key blocks 中间，接着把那里的字节当 record 段头读 → `record block info overflow`，整本导入失败。
- **[x] ① 已修复** — key block info 里首尾词副本的终止符只在 v2 计入（`info_term_bytes`，v1 为 0）；key block 里的词条本身两版都以 NUL 结尾，不变。另外 record 段起点改由头部的 `key_blocks_size` 定位（遍历完 key blocks 后 `pos = record_section_pos`），不再依赖逐块累加——遍历半途停下时也不会把 record 段头读偏。
- **[x] ② 已加自动化测试** — `native/fushidicts/tests/mdx_v1_container_test.cpp`（ctest `mdx_v1_container_test`）：`mdx_fixture.hpp` 新增 v1 形状（`ContainerShape::version_major` / `build_mdx_v1`：32 位数字、未压缩 key block info、8 位首尾词长度且无终止符），5 词条 v1 与 v2 容器经 `parse()` / `parse_streaming()` 都要逐条取回原释义。变异实测：把 v1 的终止符加回去 → 5 个词条全部缺失、FAIL；还原后 PASS。`mdd_*` / `mdx_streaming_blocks_test` 不受影响。
- **备注**：fushidicts 的 MDX 读取器至今**不做 GBK / Big5 等非 UTF 编码转换**（词头与正文都按 UTF-8 / UTF-16 处理）。旧版中文 .mdx 不少声明 `Encoding="GBK"`：这类词典修复后能解析出来，但词头 / 正文会是乱码。反馈人的 5 本若是 GBK，需要另做编码转换（Android 上没有 iconv，要自带码表）才能真正可用，未在本次范围内。
