## BUG-4025 · 漫画下载进度把字节数显示成页数
- **报告**：2026-11-03（用户反馈 C9yS-iqk0D，Windows 3.3.0-debug.23080：mokuro.moe 下卷时显示「第 4718782 / 31302239 页」，卷列表与顶部进度条两处都这样）
- **真实性**：✅ 真 bug。根因在进度**模型**：任务表 `manga_download_jobs` 只有 `pages_done / pages_total` 两列，mokuro 卷的 CBZ 下载阶段把字节塞进了这两列——`fushi/lib/src/media/manga/download/manga_download_service.dart` `_mokuroProgressOf()`（`downloadingCbz` 分支返回 `(done: receivedBytes, total: totalBytes)`，再经 `updateMangaDownloadJobProgress` 落库），注释还写着「UI 侧只看比值」。可消费方并不只看比值：`mokuro_moe_catalog_view.dart` `_progressLabel()` 与 `manga_download_tasks_section.dart` `_statusLabel()` 都把这两列套进 `manga_ocr_wizard_page_progress`（「第 x / y 页」）。同一对整数在不同阶段是不同单位、行里又没有单位，任何读它的 UI 都必然出错——只改文案治不了。
- **[x] ① 已修复** — 进度改成带单位的模型 `MangaDownloadProgress`（sealed：`MangaDownloadPageProgress` / `MangaDownloadByteProgress`，`manga_download_service.dart`）。页列只承载页（导入阶段）；CBZ 字节进度是瞬态，只存在服务内存（`_transfer`），经 `MangaDownloadService.progressOf(job)` 与页列合成、经 `watchJobs()`（合并表变化与字节进度变化）通知 UI。开跑先把页列清零，旧版本留在行里的字节不会被续跑的任务显示成页数。两处 UI 统一走 `mangaDownloadProgressLabel()`（`manga_download_progress_label.dart`）：字节 →「下载中 4.5 MB/29.9 MB」，页 →「第 3 / 10 页」；进度条 / 圆环取 `progress.fraction`，单位无关。附带：字节进度不再每个 chunk 写一次 DB。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_download_service_mokuro_test.dart`「进度映射：CBZ 阶段字节只进内存（页列不动），导入阶段页才落表」（预置旧版字节脏行 → 开跑清零；CBZ 事件后页列仍 0/0、`progressOf` 是字节且 `watchJobs` 有通知、文案含 MB 不含原始字节数；总量未知时比值为 null；导入阶段落页）+ `fushi/test/media/manga/online/mokuro_moe_catalog_dialog_test.dart`（真 widget：面板与卷 subtitle 两处显示「下载中 512.0 KB/1.0 MB」、不出现「第 524288 / 1048576 页」、页列为 0）。原先两份测试把「CBZ 阶段记字节进页列」当正确行为钉着，已改。
- **备注**：`ctl_online_downloads.dart` 的 `pagesDone/pagesTotal` 字段从此也只是页（下载阶段为 0）；未做真机下载复测（单测 + widget 测试覆盖了原始失败的映射与渲染路径）。
