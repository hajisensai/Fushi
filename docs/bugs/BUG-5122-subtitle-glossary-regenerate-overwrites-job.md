## BUG-5122 · subtitle-glossary-regenerate-overwrites-job
- **报告**：2026-11-22（外部审计 HBK-AUDIT-039，Codex 2026-11-21 PR 审查，来源 PR #3781）
- **真实性**：✅ 真 bug。专名表有三种写方：校对任务的 S0、`saveGlossary`、`regenerateGlossary`。BUG-5008 只让「保存 / 重新生成」在 S0 在飞时拒绝（`glossaryWriterFor`），但单独重新生成自己在飞期间没有登记为写方：`fushi/lib/src/media/video/subtitle/app_video_subtitle_service.dart` 的 `regenerateGlossary` 查完 `_refuseWhileGlossaryWriter` 就读整表、`await` 异步生成、整表写回；`_launch` 只查 `_active`，不知道有重新生成在飞，校对任务照样起，S0 读到旧表、生成、写回，两边后写者把先写者整张盖掉。保存、第二次重新生成同理。
- **[x] ① 已修复** — 服务里加同一张表的写方互斥：`_regeneratingGlossaries`（按 glossaryKey）在 `regenerateGlossary` 第一个 `await` 之前登记、`finally` 注销（含失败 / 取消）；`_refuseWhileGlossaryWriter`（保存 / 重新生成入口）与 `_launch`（仅校对任务，即会跑 S0 的任务）都同时查两种在飞写方，新拒绝原因 `AppVideoSubtitleStartProblem.glossaryRegenerating`（生成面板 / 编辑页 / ctl 各给提示）。Dart 单线程，查与登记之间无 `await`，两种启动顺序都只放行一个写方。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/subtitle/app_video_subtitle_service_test.dart`「HBK-AUDIT-039：单独重新生成在飞时…」（重新生成停在 AI 请求中间：校对任务 / 保存 / 再次重新生成都被拒，不校对任务与别的语言照常，完成后存储里是重新生成的结果、校对任务可起）与「重新生成失败 / 取消也放开写方登记」；反方向（任务先起）沿用 BUG-5008 的用例。变异实测：去掉登记后新用例变红。
- **备注**：fushi_server 的 subgen 是另一进程自己的管线，不经本服务，不在本修复范围。本修复的互斥只覆盖 `AppVideoSubtitleService` 内的三种写方；同一 app 进程里 host 任务（`VideoSubtitleHostJobRunner`）的 S0 也写同一行，不在互斥内，另记 BUG-5153。
