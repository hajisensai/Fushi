## BUG-4084 · 浏览页被视频页盖住时网页预告片仍自动播放
- **报告**：2026-11-04（用户：内置浏览器开着 Netflix 首页，从别处打开本地视频后，后面的网飞首页预告片开始自动播放；正常浏览器是同一个网页直接跳转，不会这样）
- **真实性**：✅ 真 bug。浏览页被整页路由盖住时只转告各功能（`fushi/lib/src/pages/implementations/fushi_web_browser_page.dart` `_setCovered`），没有任何功能让 WebView 知道自己看不见了；页面媒体只在「用 Fushi 播放」交接时才按住（`fushi/lib/src/web_browser/features/play_in_fushi/play_in_fushi_feature.dart` `kWebBrowserHoldMediaScript`，仅 `_holdPage` 调用）。WebView2 仍是 `IsVisible=true`，页面 `visibilityState` 一直是 `visible`，Netflix 首页预告片照常自动播。
- **范围（用户拍板）**：① 只是切走的后台标签页不暂停、不挂起，照常播放（与 Chrome 一致）；② 有手机遥控会话（`WebBrowserVideoRemote`）的那一页不暂停、不挂起；③ 只在视频页 / 播放页盖住浏览页时触发，别的整页路由（设置页、标签网格等）不算。
- **[x] ① 已修复** —
  - 播放页登记：`fushi/lib/src/media/playback_route_marks.dart`（`PlaybackRouteMarks` / `PlaybackRouteMark`），`VideoFushiPage`、`WebVideoFushiPage` 在 `didChangeDependencies` 里把自己的路由登记成播放页；`PlaybackCoverWatch` 用根栈镜像（`StudyCoverTracker.routesAbove`）判断「我之上压着播放页」，浏览页据此发新钩子 `WebBrowserFeature.onPlaybackCoverChanged`。
  - `WebBrowserPageVisibilityFeature`（`fushi/lib/src/web_browser/features/page_visibility/web_browser_page_visibility_feature.dart`）：被播放页盖住且不是遥控会话页（`WebBrowserVideoRemote.sessionTabId`）时，先跑按住脚本、再 `pause()`（Windows：WebView2 `IsVisible=false` + `TrySuspend`；Android：`onPause`）/ `setAllMediaPlaybackSuspended`（iOS / macOS / Linux），露出时倒序恢复。只管加载完过一次的页面；每一步都成功才记成目标状态，失败记「说不准」下次重做；WebView 被活 WebView 上限回收时经新钩子 `onWebViewDisposed`（`WebBrowserTabView._detachController`）撒手死控制器。
- **[x] ② 已加自动化测试** — `fushi/test/media/playback_route_marks_test.dart`（播放页盖住 / 别的整页不算 / 播放页在下面不算 / 出栈当帧露出）、`fushi/test/web_browser/features/page_visibility/web_browser_page_visibility_feature_test.dart`（顺序、后台标签页不动、遥控会话页豁免与会话结束后补隐藏、换文档重按、未加载不挂起、失败重做、回收撒手）、`fushi/test/web_browser/features/extension_host/web_browser_video_remote_test.dart`（`sessionTabId`）、`fushi/test/web_browser/tab_view/web_browser_tab_view_widgets_test.dart`（回收时发 `onWebViewDisposed`）。
- **备注**：真机复测原始失败路径（开着 Netflix 首页再从别处打开本地视频）本轮未做，待补。
