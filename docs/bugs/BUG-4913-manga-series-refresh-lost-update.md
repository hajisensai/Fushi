## BUG-4913 · 漫画作品页后台刷新覆盖刚开的订阅；下载状态旧读盖新读
- **报告**：2026-11-20（来源：c43 #3814 加宽一轮里 `manga_series_page_locked_chapter_test`「AppBar 有登录按钮」与 `manga_series_page_phase_c_test`「本作下载队列横幅」在 `test/media/manga` 全目录 concurrency 4 下不稳，单跑绿。沿代码路径查出是 develop 上就有的生产竞态 + 一条赌墙钟的测试，与 c28 / c38 / c43 的改动无关：这几个分支都没碰作品页和 `online_manga_library_service.dart`。）
- **真实性**：✅ 真 bug（沿代码路径确认，测试复现）。三处：
  1. **刷新落库丢更新**：作品页进页就后台跑 `_refreshFromSource(silent: true)`（`fushi/lib/src/media/manga/library/manga_series_page.dart:1218`），联网要几秒。`OnlineMangaLibraryService.refresh` 拿调用方进页那一刻的快照 `existing.copyWith(...)` 整条写回（develop `online_manga_library_service.dart:209-220`）。这期间用户点了书签（`setSubscription`）或选了章（`selectChapter`）的话，订阅两位和当前章会被冲回旧值，作品页还会 `setState(_entry = updated)` 把界面也退回去（develop `manga_series_page.dart:1355`）。反过来也一样：`setSubscription` 拿手里的旧快照整条写回（develop `:310-324`），会把刚刷新出来的章节表退回旧表。
  2. **下载状态旧读盖新读**：`_refreshDownloadState`（develop `manga_series_page.dart:525-557`）每次任务表变化（`watchJobs`）都触发一次，整批动作后还会再补一次。每次都要先读任务表，再扫章目录（磁盘 IO），几轮同时在途时谁先落地不确定，而且没有代次保护。先开始的一轮读到的是排队态，它最后落地时会把「暂停全部」之后的状态盖回排队：横幅又冒出「暂停全部」、计数退回排队，要等任务表下次变化才会纠正。这就是「本作下载队列横幅」用例在高并发下红的原因。
  3. （测试侧）「AppBar 有登录按钮」用例在章节一出现就断言按钮可点。但按钮在刷新途中本来就是禁用的（`onPressed: _busy || _refreshing ? null : ...`），这条用例其实是在赌后台刷新已经跑完，高并发下刷新慢一拍就红。这是测试的问题，不是生产 bug。
- **[x] ① 已修复** — `online_manga_library_service.dart` 新增唯一的读改写口 `_rewriteStoredEntry`：在事务里读库里此刻的描述符，交给调用方改自己那几个字段后写回。`refresh` 只换系列信息和章节表，当前章按 key 在库里此刻的描述符上重新定位；`setSubscription` 只改两位；`selectChapter` 的章节表和下标仍按调用方那份（调用方随后用同一个下标开章），订阅两位以库里为准。作品页 `_refreshFromSource` 最后一步重读行，读完直接 `setState`，中间不再 await。`_refreshDownloadState` 加代次 `_downloadStateGeneration`，只认最后开始的那一轮。提交见 git log（分支 `pr/manga-series-refresh-lost-update`）。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/online_manga_library_entry_v3_test.dart`「并发写不丢更新（BUG-4913）」组：用 Completer 把刷新钉在途中，覆盖三种情形：刷新在途开订阅、刷新在途选章、订阅不退回刚刷新的章节表。`fushi/test/media/manga/manga_series_page_phase_c_test.dart`「下载状态：先开始的旧一轮最后落地，不盖掉暂停后的新状态」：`_GatedDownloadService` 把一轮读任务表钉在途中，「暂停全部」之后再放行。`manga_series_page_locked_chapter_test.dart` 的 AppBar 登录用例改成先把刷新钉住、验在途禁用，放行后等刷新条消失再验可点。
- **备注**：`selectChapter` 仍把调用方那份章节表写回。阅读器拿着刷新前的表选章的话，刚刷新出来的新章要等下次刷新才回来（不丢订阅、不丢进度）。要根治得把选章 API 从「下标」改成「章 key」并改阅读器的三个调用点，超出本次范围。
- **与 c50 #3819（BUG-4909 / gap-mangamisc-1）合并后**：服务层读改写由 c50 的 `rewriteEpubBookMihonState` + `_rewriteEntry` 取代（选章同时改成按 chapterKey，上一条备注随之解决）。作品页下载状态由 c50 的 `CoalescedRefresh` 串行合并，不再有多轮同时在途，所以本修复的 `_downloadStateGeneration` 在合并时去掉了。本条的测试保留，改成在 c50 的接口上跑。
