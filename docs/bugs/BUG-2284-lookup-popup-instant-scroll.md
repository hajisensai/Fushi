## BUG-2284 · 查词弹窗「瞬时滚动」开关对滚轮完全无效
- **报告**：2026-09-08（用户：「查词弹窗瞬间滚动似乎不生效」，同时要求把弹窗配置项与 Hoshi Reader Android 对齐）
- **真实性**：✅ **真 bug（空开关）**。两条独立原因叠加，任一条单独成立就足以让开关看不出差别：
  - **① 唯一消费点的两个分支等价**：偏好 `popup_instant_scroll`（`fushi/lib/src/models/preferences_repository.dart:699`）经 `ReaderCaretScripts.instantScrollInvocation`（`fushi/lib/src/reader/reader_caret_scripts.dart:61`）只落到 JS 侧 `fushiCaret.instantScroll`，而它**唯一**的消费点是 `_scrollWindowBy` 的 `behavior: this.instantScroll ? 'instant' : 'auto'`（`fushi/lib/src/reader/reader_caret_scripts.dart:736`）。弹窗全链路**没有任何 `scroll-behavior: smooth`**（`fushi/assets/popup/popup.css` 只有 `:65 overscroll-behavior-y: contain`；`popup_settings_injection.dart` / `popup_theme_css.dart` 零命中），而 CSS `scroll-behavior` 的默认计算值就是 `auto` = 立即跳转。于是 ON/OFF 产生**逐像素相同**的滚动。`preferences_repository.dart:695` 的注释把 OFF 描述成 "smooth/animated popup scrolling"，与实现自相矛盾，是这条的直接证据。
  - **② 用户实际在滚的路径根本不读这个偏好**：桌面滚轮走的是 `fushi/assets/popup/popup.js` 的自研 wheel 接管（BUG-260/870/1026 那条比例滚动链路），`scrollBy` 的 `behavior` 硬编码 `'auto'`，全程不查 `fushiCaret.instantScroll`。走 `instantScroll` 的只有手柄/键盘驱动的 caret 移动（`reader_caret_scripts.dart:689/929/995`）与 `scrollPage`。设置项标题是「查词弹窗瞬时滚动」（泛指弹窗滚动），实现却只覆盖 caret 一条支路。
  - 附带隐患（同一行）：`fushi/lib/src/pages/implementations/dictionary_popup_webview.dart` 的 `_pushResults` 把 `window.fushiCaret.setInstantScroll(...)` **裸拼**进一整条 `evaluateJavascript`，而同一注入串里其它跨界调用一律带守卫（`window.fushiPopupScrollBy ? ...` / `window.fushiSelection?.`）。`onLoadStop` 先置 `_ready = true`、caret 源随后才落地，这个窗口内进入 `_pushResults` 会抛 TypeError 并**中止该脚本后续全部语句**（`__fushiRenderToken` / `renderPopup()`）＝ 空白弹窗。
- **[x] ① 已修复** — 本提交。按设置项自己的说明文案（「按固定距离瞬时跳动，不播放滚动动画」）定义语义并接线到真正的滚动路径：
  - 偏好新增下发通道 `window.__fushiPopupInstantScroll`：in-app 三种弹窗经 `popup_settings_injection.dart`（与 `__fushiPopupWheelSpeed` 同一注入面，并进 BUG-717 ③ 的静态段 memo 命中判据，改设置即失效重注入）；浏览器扩展经 theme 通道 `--fushi-instant-scroll`（`app_model.dart`）→ `content.js` / `side-panel.js` 落到同名全局，与 BUG-1026 的滚轮速度同法。
  - `popup.js` 的 wheel 监听器在比例滚动的 `factor` 计算**之前**加瞬时分支：步长 = 被滚表面视口 × `POPUP_EINK_WHEEL_VIEWPORT_FRACTION`(0.5) × 用户滚轮速度倍率，夹在 `[POPUP_EINK_WHEEL_MIN_STEP, 一屏]`（永不跳过整屏内容），并用 `POPUP_EINK_WHEEL_COOLDOWN_MS`(140ms) 合并同一次手势的多帧——触控板一次惯性滑动发几十帧，不合并会直接跳到底。滚动目标仍按表面解析（BUG-688：扩展滚 shadow host，in-app 滚 window），视口高度按表面换算 zoom（`popupEinkWheelExtent`）。三份 popup.js 镜像逐字节同步。
  - `instantScrollInvocation` 改为带守卫 `window.fushiCaret && window.fushiCaret.setInstantScroll(...)`，消除上述「整条注入串被中止」的隐患。caret 侧的 `'instant' : 'auto'` 三元保留并加注释说明两分支在当前弹窗里等价、真正的分流点已移到滚轮路径。
- **[x] ② 已加自动化测试** — `fushi/test/dictionary/popup_instant_scroll_guard_test.dart`（源码扫描守卫；单测层没有真 WebView，滚动本身无法直接断言，故钉「开关 → 行为」这条线上每一段的存在性）：三份 popup.js 镜像各自断言 ① wheel 路径读 `__fushiPopupInstantScroll`、② 瞬时分支位于比例滚动 `factor` **之前**、③ 步长来自视口固定比例且分支内不含 `deltaPx *`（退化回连续滚动的形态）、④ 有冷却窗口、⑤ 仍按表面解析滚动目标；另断言注入面 + memo 命中判据 + 扩展 theme 四处镜像 + caret 守卫形态。同时更新 `fushi/test/reader/reader_caret_scripts_test.dart` 的两条字面量断言（守卫化后的产物）。
- **备注**：同一提交按用户要求做了与 Hoshi Reader Android 的弹窗配置项对齐。逐项比对后，Android 有而 Fushi 缺的**弹窗渲染**设置只有一项：**Compact Glossaries**（释义列表 inline + ` | ` 分隔）。`fushi/assets/popup/popup.js` 的 `createDictionaryBlock` 一直按 `window.compactGlossaries` 产出紧凑 CSS，但全 app 从来没有任何地方给这个全局赋值（恒 `undefined` = 恒关，死代码）；本次补上偏好 `popup_compact_glossaries` + 设置项 `lookup.compact_glossaries` + 注入写入点，默认 **false**（Android 默认 true，但改默认会让存量用户的弹窗观感突变）。其余 Android 弹窗设置 Fushi 均已具备且多数更细：Width/Height→`popup_max_width/height`、Full-width→`popup_bottom_docked`、Swipe to Dismiss + Threshold→`enable_swipe_to_close` + `dismiss_swipe_sensitivity`、Max Results→`maximum_terms`、Auto-collapse→`collapse_dictionaries`(+`popup_auto_expand_dictionaries`)、Show Expression Tags / Harmonic Frequency / Deduplicate Pitch Accents / Custom CSS / Default to Dictionary Tab / Auto-play on Lookup / 音源管理 均已有。**有意未做**两项：(a) Android `scanLength`（逐字查词扫描长度）在 Fushi 对应 `kLookupQueryMaxChars = 24`（`fushi/lib/src/lookup/sentence_extraction.dart:48`），但它只覆盖 texthooker 与游戏内查词两个逐字表面，阅读器/视频的点选查词不走这条，做成全局「扫描长度」会名不副实；(b) Android 的 Background Audio（interrupt / duck / mix）属平台音频会话策略，不是弹窗渲染设置。
