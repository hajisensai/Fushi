## BUG-3608 · 纯字幕模式下 \pos 排成上下的同时间戳 ASS 两行被上下颠倒
- **报告**：2026-10-19（用户：应用内反馈 tAcx_IHmZq，Android；「两句同一时间戳的 ass 字幕显示出来上下反过来，要关掉强制字幕样式才正常；同一字幕 asbplayer 没问题」）
- **真实性**：✅ 真 bug。字幕文件里两条同起止时间的 `Default` 事件用 `\pos(820,900)` / `\pos(940,1020)` 显式排成上下两行，文件序是「上面那行先写」。「尊重字幕自带样式」关（用户说的「强制字幕样式」，即纯字幕模式 BUG-915）时，`_buildSubtitleLayer` 把整层折进**一个**底部堆叠组（`fushi/lib/src/media/video/video_subtitle_overlay.dart:1438` 的 `('plain', _uniqueByText(cues))`），`_positionCueGroup` 按活动集发现顺序（文件序）喂 `_syncGroupSlots`（`:1749`），底部锚组 slot0 贴底——于是先写的「ああ 真っ赤な羽毛の」（作者放在 y=900，靠上）被画到最下面，「でっかい鳥だ。」（y=1020，靠下）反被推到上面。位置语义归零本身是 BUG-915 的设计，但归零后行序沿用了「无位置时」的 libass 碰撞次序（先出的贴锚点），对显式 `\pos` 的字幕就成了颠倒。打开「尊重字幕自带样式」时两行各按 `\pos` 分组定位，所以正常。asbplayer 剥掉位置后按文件序自上而下排一列，恰好与这类字幕的作者次序一致。
- **[x] ① 已修复** — 纯字幕模式下组内入槽次序改按**作者排版的竖直次序**：新纯函数 `orderPlainCuesByAuthoredPosition`（`video_subtitle_overlay.dart:3828`，竖直位置取 `\pos` y / `\move` 起点 y，无显式位置时按 `\an` 竖直锚点 + MarginV/PlayResY 近似），在 `_positionCueGroup` 入槽前调用（`:1831`）；底部锚组最靠下的贴底、顶部锚组（副字幕置顶）最靠上的贴顶。竖直位置相同（无 `\pos` 的普通同样式对白、纯 SRT）稳定排序保持原发现顺序，既有行为不变。尊重样式模式不走此路径。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/video_subtitle_plain_mode_pos_order_test.dart`：纯函数四例（底锚/顶锚/同位置稳定/`\an8` 与底部混排）+ 真 `VideoSubtitleOverlay` widget 两例（用反馈截图同结构 ASS 断言「羽」行在「鳥」行之上；无 `\pos` 两行仍先写的贴底）。
- **备注**：槽位跨帧稳定（BUG-698）不变：若靠下的那行**晚于**靠上的那行入场，在屏行不会被挪动，新行仍追加到远端，这是「事件在屏期间位置不变」的既有取舍，本修复只纠正同时入场的次序。待真机复测（Android 原片）。
