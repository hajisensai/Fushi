## BUG-5186 · 主窗最小化 / 藏托盘后桌面中央点击被吞（composition 档 WebView2 代理窗仍可命中）
- **报告**：2026-11-21（外部 PR #4041，作者 zymy8848：最小化后桌面中央点不动，EnumWindows 实测两扇 `msedgewebview2.exe` 的 `Chrome_WidgetWin_1`，`WS_EX_NOACTIVATE|LAYERED|TOOLWINDOW`、无 `WS_EX_TRANSPARENT`）
- **真实性**：✅ 真 bug（沿代码路径确认）。根因 ① `packages/flutter_inappwebview_windows/windows/in_app_webview/in_app_webview_manager.cpp` 构造函数只挂了 `WM_DESTROY` 委托，主窗最小化 / 隐藏从未同步给 composition 档 WebView2，`put_IsVisible` 一直是 TRUE，Offstage / 保活的 WebView 代理窗留在桌面命中测试里；② `in_app_webview.cpp` `InAppWebView::setPosition` 在 BUG-3871 把宿主改成 Flutter 视图的 `WS_CHILD` 后仍按顶层窗口算屏幕坐标（`GetWindowRect` + `SM_CYCAPTION`/`SM_CXBORDER`），且 `custom_platform_view.cc` 用 `static_cast<size_t>` 截断负坐标，宿主 HWND 位置错，WebView2 弹出层（select、右键菜单、IME 候选窗）锚点随之错位。
- **[x] ① 已修复** — 管理器挂只观察不拦截的顶层委托（`WM_WINDOWPOSCHANGED` 为主，`WM_SIZE`/`WM_SHOWWINDOW` 冗余），把宿主可见性推给全部活动与保活 WebView；新建 / 复用 WebView 读实时顶层状态，不在插件注册时缓存（那时主窗还没显示）。可见 = 宿主可见 且 未被 Dart `pause()`。宿主位置改为 Flutter 视图客户区像素 `lround(逻辑坐标 × 窗口 dpr)`，不钳制、不用纹理栅格倍率；主窗移动只 `NotifyParentWindowPositionChanged()`。修复版 PR 见 supersedes #4041 的新 PR。
- **[x] ② 已加自动化测试** — `fushi/test/widgets/inappwebview_windows_native_guards_test.dart` 组 `composition host visibility and position (BUG-5186)`（源码守卫：委托不吞消息、不缓存注册时可见性、无 WM_MOVE、位置不钳制且不用 captureScaleFactor_）。插件包自己的 test/ 在 CI 里被跳过，所以守卫放在 fushi/test。
- **备注**：本机未做真机复测，待 Windows 构建后验：① 最小化主窗后点桌面中央不再被吞；② 藏托盘再恢复、最小化再还原，应用内浏览器与保活 WebView 不空白；③ 应用内浏览器 select 下拉框 / 右键菜单 / IME 候选窗位置正确，含 app 界面缩放 ≠ 100% 与 WebView 部分滚出视口。用户可见变化：最小化 / 藏托盘时网页 `visibilityState` 变 hidden（与 Chrome 一致），监听 visibilitychange 的站点可能暂停播放。
