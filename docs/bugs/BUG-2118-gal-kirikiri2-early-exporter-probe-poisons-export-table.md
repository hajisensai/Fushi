## BUG-2118 · 早注入时 exe 直取 TVPGetFunctionExporter 先于引擎静态构造把导出表灌满又被清空致所有插件链接失败
- **报告**：2026-09-04（ceshi 批量适配 · Fate/stay night[Realta Nua] -Fate-（KiriKiri2 2.31.2010.425 BCB，KAG 3.25 beta 10 TYPE-MOON customized）经 Fushi 库内启动**必**弹「スクリプトで例外が発生しました EAccessViolation」，主窗从未出现；用户 7-24 自己经 Fushi 启动 8 次同样全崩，普通双击启动 5 次仅 1 崩且能到脚本阶段）
- **真实性**：✅ 真 bug。分型实验（同一 helper 构建，同一天）：injector `--launch` 不带 Luna、不转区 → 崩；转区关/开 → 都崩；不注入 → 主窗出现；先起游戏再 `--pid` 晚附着 → 不崩。崩溃点由 krkr 控制台日志 + `%TEMP%\krkr_*\fstat.dll` 反汇编（RVA 0xA111 = tp_stub `TVPGetImportFuncPtr` 的「导入缺失就 `mov dword ptr [0], 0`」故意崩）定为：**插件 `QueryFunctionsByNarrowString` 全部查不到**。上游机制（krkrz `base/win32/PluginImpl.cpp`，kirikiri2 同构）：`TVPGetFunctionExporter()` 首次调用 → `TVPInitExportFuncs()` 置 `TVPExportFuncsInit = true` 并把 653 个函数 `TVPAddExportFunction` 进**静态** `tTJSHashTable TVPExportFuncs`。根因 `native/galgame_hook/hook/adapters/kirikiri_adapter.inc` `TryHookKirikiriVoiceStream()`：HookWorker 在 CREATE_SUSPENDED 早注入后立刻走 exe 直取 `ObtainExporter()`，此时 exe 的静态构造函数还没跑——表被我们灌满、随后被构造函数清空，init 标志已置，之后每个插件链接（dirlist.dll 抛 TJS 异常、fstat.dll 故意 AV）都失败。我们自己那次 `TVPCreateIStream` 查询恰好夹在灌表与清表之间，所以诊断位 `0x10000|0x20000` 看起来一切正常（decdiag=0x02a30000，`0x40000` detour 从未触发）。KiriKiri Z 样本（tenshi_sz / ATRI）exe 无导出，走 LoadLibrary→V2Link 路径，从未撞到。
- **[x] ① 已修复** — `TryHookKirikiriVoiceStream()` 的 exe 直取加门 `FindGameMainWindow() != nullptr`（引擎主窗由 TJS 脚本创建，远在 CRT/静态构造之后；主窗出现前只靠 V2Link 路径，插件链接时引擎自己已调过 `TVPGetFunctionExporter`，表必然已就绪）。真机复验见台账 `docs/plans/2026-09-04-gal-ceshi-batch-classic-kag3.md`。
- **[x] ② 已加自动化测试** — `native/galgame_hook/tests/kirikiri_lookup_source_guard_test.py`：新规则 `find_ungated_exe_exporter_probe`（`TryHookKirikiriVoiceStream` 体内 `ObtainExporter()` 前必须先出现 `FindGameMainWindow()`）；`RealAdapterTest` 真文件断言；`MutationSelfTest` 三条变异（门删掉 / 门挪到探针之后 / 函数改名）全红。
- **备注**：第一轮曾把 Locale Emulator 当嫌疑（崩溃会话都先有「Documents 存档目录不存在」），关转区后仍崩证伪；那行只是导出表空掉后 `Storages.isExistentStorage` 也查不到函数的连带症状。
