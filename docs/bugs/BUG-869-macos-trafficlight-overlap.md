## BUG-869 · macOS 交通灯按钮与顶部导航/返回按钮重叠
- **报告**：2026-07-17（用户：截图）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/main.dart:201-205` 无条件 `WindowManipulator.makeTitlebarTransparent()` + `enableFullSizeContentView()`（macos_ui ToolBar 的硬性前提），使 Flutter 内容整块延伸到红黄绿交通灯下方；而默认 `auto`/MD3 走的 Material 桌面壳 `hibiki/lib/src/pages/implementations/home_page.dart` `_buildDesktopLayout`（设置分支 ~713、主分支 ~742）只用普通 `SafeArea`。macOS full-size content view 下 embedder 不把交通灯上报为 `MediaQuery.padding.top`（上报 0），SafeArea 挡不住 → 交通灯压住导航 rail 顶部 / 返回箭头。
- **[x] ① 已修复** — 在 `_buildDesktopLayout` 两个 `SafeArea` 加 `minimum: EdgeInsets.only(top: Platform.isMacOS ? kMacTitleBarHeight : 0)`，预留一条标题栏高度的保留带让交通灯落入其中；新增常量 `kMacTitleBarHeight = 28.0`（`hibiki/lib/src/utils/adaptive/adaptive_platform.dart`）。用 `dart:io` 的 `Platform.isMacOS`（非 `isMacosPlatform`），正好覆盖"macOS 上跑 Material 桌面壳"这一 bug 场景；其它平台 top=0 零影响；不经过 `_buildMacosLayout`/根 `MacosWindow`（macos_ui 自处理让位），无双重让位。提交：ac0835ae1
- **[x] ② 已加自动化测试** — `hibiki/test/tools/macos_trafficlight_inset_guard_test.dart` 源码守卫：① 断言 `kMacTitleBarHeight` 存在且 ≥20pt；② 断言 `_buildDesktopLayout` 两个 SafeArea 都带该 macOS inset（≥2 处）。选源码守卫是因为分支门控在 `dart:io` 的 `Platform.isMacOS`，无法用 `debugDefaultTargetPlatformOverride` 在 Linux CI 上伪造 macOS 布局。提交：ac0835ae1
- **备注**：真机 macOS 验收方式——在 macOS 打开 App（auto/MD3 或 material 设计系统），确认书架侧栏 rail 顶部图标、设置页左上返回箭头都不再被红黄绿交通灯遮挡；切到显式 macos-native 设计系统时仍由 MacosWindow 让位（未受影响）。
