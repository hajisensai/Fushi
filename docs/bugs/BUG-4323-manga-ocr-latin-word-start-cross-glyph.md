## BUG-4323 · 英文漫画 OCR 点词中字母只查后半截：词首回退不跨字格文本节点（WELL 点 E 得 ELL）
- **报告**：2026-11-07（用户：应用内反馈 vXYKPudf7U 的后续回复，承 [BUG-4179](BUG-4179-manga-latin-ocr-words-glued.md)；Windows）
- **真实性**：✅ 真 bug。BUG-4179 修好词间空格后，点词首能查到整词，但点词中 / 词尾字母只查从该字母往后的部分（`WELL` 点 `E` 查 `ELL`），与「非日文命中回退到词首」的设计意图及查词页行为矛盾。根因：漫画叠加层每个字格是独立的 `<span class="ocr-char">`（`fushi/lib/src/media/manga/manga_overlay_html.dart:649`），宿主 `selectFromPosition(node, 0, …)`（同文件 :2701）；`selectionStartFor` 的拉丁词首回退（`fushi/lib/src/reader/reader_selection_scripts.dart:3366` `while (startOffset > 0 …)`）只在命中的文本节点内做，偏移 0 时直接跳过，跨不到前一个字格节点。前向扫描本来就跨节点（`walker.nextNode`），回退不对称。阅读器里被行内标签劈开的词（`<b>wel</b>l` 点后一个 l）同理。反馈里「漫画里查不到多词短语」是 BUG-4179 写明的取舍（拉丁文点词只查单词），不算本 bug。
- **[x] ① 已修复** — `selectionStartFor` 在命中节点内退到偏移 0 后调新 helper `tokenStartBeforeNode`：在同一个 `findParagraph` 容器（漫画 = 一个 `<p class="ocr-box">`，阅读器 = 段落）内按文档序取前一个可扫文本节点继续回退，遇到 `isTokenStartBoundary`（空白 / 标点 / 连字符 / 括号 / 日文）、被跳过的空白缝（`hasSkippedWhitespaceBetween`：BUG-4179 补的词间空白节点、BUG-3453 cue 缝）或容器边界即停，返回跨节点起点。不是漫画特例：所有调用方（点击、悬停去重、键盘 / 手柄光标 `manga_controller_cursor_scripts.dart:91`）共用。漫画宿主 `_selectOcrCharDetail` 的「同一个词」判定改用归一后的词首（与 `selectText` 去重同一判据），否则点同词另一字母不再是「取消」、悬停同词换字母会重复查词。提交 f668e8048c。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/manga_latin_ocr_word_gap_bug4127_test.dart`（+ `.js` harness 支持节点内偏移与多个 OCR 块）：node 真执行阅读器取词脚本，新增 Lens 区域 / 行几何回退里点词中 / 词尾字母（反馈原例 WELL 点 E → `WELL?`）、行尾词不退进上一个词、日文不回退、连字符截住回退、相邻 OCR 块不跨、阅读器单节点回退结果不变与「`BEEN ` + `WELL`」不粘连，共 21 条断言。本地以 node 直接跑 harness（用例按生成器断言手搭）21 条通过；对 origin/develop 版脚本跑同一 harness 红（`tap glyph #6` 得 `EN`）。BUG-2056 / 3664 / 1773 / 3453 / pm3A75D5xZ 五个阅读器取词 harness 用新脚本跑均通过。Dart 测试本身未在本分支运行（统一在合并后验证）。
- **备注**：阅读器里无空格、被行内标签劈开的拉丁字母串（`<i>very</i>well`）现在点后半截也回退到前半截，与前向扫描本就把两段扫在一起对称。未做设备肉眼复测（真机验证已取消）。
