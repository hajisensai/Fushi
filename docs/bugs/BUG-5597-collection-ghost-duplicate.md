## BUG-5597 · 书架「管理合集」比书架多出同名重复合集（用户合集 + 规则 playlist 永不收敛）
- **报告**：2026-11-27（用户：3.4.0-beta.32958 Windows，书架 4 张合集卡，管理合集列 8 个：多出「薬屋のひとりごと」×2、「魔女の旅々」×2，均 0 项）
- **真实性**：✅ 真 bug（重复部分）。用户库只读副本：`6387 薬屋のひとりごと collection/user organize_key=NULL` 与 `6388 薬屋のひとりごと playlist/rule t:books:薬屋のひとりごと` 成员完全相同（3 个 epub 标题形 bookKey），`6389/6390 魔女の旅々` 同构；4 行 created_at 相隔 4 ms、按自然键排序，是同一次合集同步落盘建的（`packages/fushi_engine/lib/sync/collection_sync_engine.dart:1076` `applyCollectionLocalChanges` 的 `createMediaCollection`）。同名同成员两行并存的根因在收敛：`packages/fushi_engine/lib/media/collections/library_organize/organize_convergence.dart:76`（修前）`ConvergenceCollection.participates` 只收「整理器合集」或「带分组键的用户合集」，成员重叠规则又只在两个整理器合集之间生效——一端用户手建、从没拿到分组键的同名合集，与另一端 `BookSeriesGrouper`（`book_series_grouper.dart:323`）给同一批书建的 rule playlist 是两个自然键 `(name, collectionType)`，同步把两者都带到每台设备，收敛永远连不上它们。单机上归组器「已在任何合集里的卷不动」会避免这种重复，跨端时这条不变量丢了。
  「0 项 / 书架没卡」部分**不是落库 bug**：成员是本机已删书（`book_tombstones` 早 20～70 秒）的标题形 bookKey，删书只删本机副本（`deleteEpubBook` → `removeEntryFromAllCollections`，`database_content_misc.part.dart:1930` / `database_library.part.dart:2844`，刻意不写成员墓碑，否则会把别的设备上还在的书从共享合集里移出），对端仍有这些书，同步按 v83 设计照抄透传（`collection_sync_engine.dart:966` 注释「查不上必须照抄透传，绝不丢弃」）；本机是互联 host，还要替对端转发归属。书架不出卡是因为本机没有可显示的成员，管理页列出它们是另一个用户可见取舍，见备注。
- **[x] ① 已修复** — `organize_convergence.dart:87`（`impliedTitleKeys`）/ `:230`（连组）：无键用户合集按「名字 + wire 成员域」推出标题键 `impliedTitleKeys`（只读跨端可见字段，各端算出同一结果）；整理器合集的键 / 别名命中它、同域、成员重叠过半时连成一组，整理器合集并进用户合集（用户合集当胜方并吸收分组键，败方写 `organizeMerged` 删除墓碑随同步传播）。只在用户合集与整理器合集之间连，不凭名字连两个用户合集。spec §8.3 同步补了一段。存量数据不需要迁移：收敛在每轮合集同步后都跑（`convergeCollectionsAfterSync`），用户开着自动同步，下一轮同步即收敛。用户库副本干跑（复制到 scratchpad 后 `convergeOrganizedCollections`）：计划恰为 `6387 <- [6388]`、`6389 <- [6390]`，全库无其它合并 / 建议；合后 6387 / 6389 拿到 `t:books:…` 键，6388 / 6390 留 `organize_merged=1` 墓碑；再跑一次计划为空（幂等）。
- **[x] ② 已加自动化测试** — `fushi/test/sync/collection_organize_convergence_test.dart`：纯函数两条（同名无键用户合集 + 同成员 rule 合集 → rule 并进用户合集、与输入顺序无关、不出建议；同名不重叠 / 重叠不同名 / 两个同名用户合集都不连）+ 多端真实内存库一条（A 端用户手建同名合集、B 端 rule playlist，成员是本机没有的书，任意顺序同步后两端都只剩带键的用户合集）。
- **[x] ③ 管理页（用户 2026-11-27 拍板按建议做）** — `FushiDatabase.getCollectionsWithoutLocalMembers`（`database_library.part.dart`）按成员种类查本机条目表（epub = `epub_books` uid / bookKey、srt = `srt_books.uid`、video = `video_books.book_uid`、game = `galgames.id`），成员行存在但一条都查不上的合集判为「只在其它设备上」；含本机不认识的种类的不判。只看本机条目表，与库页标签筛选、上锁、折叠归属无关（这三种情况下成员仍在本机条目表里）。`collection_management_page.dart` 把这类合集列在「仅在其它设备上」一组（`SettingsSectionHeader`，两套设计系统；同一条错峰入场序列），副标题「本机没有这些内容（N 项在其它设备上）」，N = 成员行数。库页共用的合集菜单删除确认（`collection_context_dialog.dart` `_deleteCollection`，书架 / 漫画 / 视频 / 游戏四个库页同一入口）对这类合集追加「删除后会通过同步一并删除其它设备上的这个合集」，并去掉「连同成员一起删」勾选（本机没有成员本体）。用户库副本上判出 3165 个：书域 4 个（6387–6390），其余 3161 个是视频合集（成员是本机 `video_books` 里没有的条目键）。测试：`test/database/collections_without_local_members_test.dart`、`test/pages/collection_management_page_test.dart`（MD3 / Apple 各一遍）、`test/media/collection_context_dialog_test.dart`。
- **备注**：合集 6398「BanG Dream! It's MyGO!!!!! 雨にそよいで晴れを請う」不在书架管理页不是 bug：3 本成员书 `epub_books.format = 'manga'`，按 `getMediaCollectionsInDomain` 归漫画域，出现在漫画库的卡片与「管理合集」里，书架截图里本来就不该有。
