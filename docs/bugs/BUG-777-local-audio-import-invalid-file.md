## BUG-777 · 本地音频源导入无效文件假成功
- **报告**：2026-07-13（用户：qqbotxiaoxiao）
- **真实性**：✅ 真 bug。「管理音频来源」对话框导入本地音频库时，`FilePicker.platform.pickFiles()`（`hibiki/lib/src/settings/settings_schema_lookup.dart:68`）无 `allowedExtensions` 过滤，任意文件都能选中；`LocalAudioManager.importFile`（`hibiki/lib/src/models/local_audio_manager.dart:203`）只查源文件存在 + `copy()`，**零内容校验**。无效文件（没用的 zip / 备份 zip / 非音频 sqlite / 空库）被拷进库目录并注册为 `AudioSourceConfig.localAudio`，上层无脑弹 `t.local_audio_imported`「导入成功」。无效性要等查询时才在 `LocalAudioDb.listSources`/`queryMeta` 的 catch（`hibiki/lib/src/utils/misc/local_audio_db.dart`）被静默吞成空结果 → 「导入成功但根本用不了 / 空音频」。
- **[x] ① 已修复** — 提交 `04c7b9ce6`。① 新增纯 Dart 真值判据 `LocalAudioDb.isUsableAudioSource(dbPath)`（sqlite3 只读打开 + 校验 `entries`/`android` 两表存在且 `android` 至少一行音频）；② `LocalAudioManager.importFile` 在收进库前校验源文件，无效即抛类型化 `InvalidLocalAudioDbException`，**绝不留内部副本孤儿**（校验在 copy 之前）；③ `AudioSourcesDialog._addLocalDb` catch 特判该异常，弹专属可读文案 `t.local_audio_invalid_db`（新增 17 语言 i18n key），其它真·失败仍带异常摘要。
- **[x] ② 已加自动化测试** — `hibiki/test/utils/local_audio_db_test.dart`（`isUsableAudioSource` group：接受真库 / 拒绝不存在 / 拒绝 zip-junk / 拒绝缺 schema 的 sqlite / 拒绝空库）+ `hibiki/test/models/local_audio_manager_test.dart`（importFile 拒绝 zip-junk 且不留副本、引用模式同样拒绝；旧「假内容」用例改用真实 `_writeValidAudioDb`）。
- **备注**：BUG-446 修的是「源文件不存在的假成功 + 吞异常」，未覆盖「无效内容假成功」（无效 zip 不抛异常，绕过了那次修复）。本次补齐内容校验。待真机验证。
