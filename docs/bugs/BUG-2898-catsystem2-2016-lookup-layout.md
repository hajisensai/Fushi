## BUG-2898 · CatSystem2 2016 版内嵌查词从不安装（result=3，「定向渲染」代码布局未识别）
- **报告**：2026-10-03（用户：适配 ceshi / 官方体验版，初恋サンカイメ体验版真机测试中发现）
- **真实性**：✅ 真 bug。2016 版 CatSystem2（初恋サンカイメ体验版 `data\cs2.exe`）真机日志 `catsystem2-lookup: sites unresolved result=3`（`kPageMissing`），③ 内嵌查词恒不可用。根因 `native/galgame_hook/hook/adapters/catsystem2_lookup_core.h` 的 `ResolveSites` 只认一种代码布局（グリザイア有閑版测得）：ClearPage 与 `RenderChar(renderer, record)` 在映像里紧邻、GetCharImage 是直接 rel32 调用、场景层列表 `[[scene]+0x14]` 且层内嵌在节点里。Frida 只读探针实测 2016 版是同一引擎的另一代布局：`RenderChar(renderer, record, target_image)`（`ret 8`，target 为正常页 renderer+4 或淡入淡出页 renderer+0x40）、GetCharImage 只经字体对象 vtable 槽 1（`call [esi+4]`）、ClearPage 与 RenderChar 不再相邻、场景层列表在 `[scene+4]`（无 +0x14 跳）、节点经 `[node+8]` 指向层（层字段 id +0 / visible +4 / sprite +0x10 不变）。窗口（+4 / +0x68 / +0x2ac）、屏幕、sprite、记录字段两代相同。
- **[x] ① 已修复** — 按引擎布局分两条结构证明，不按游戏：`ResolveSites` 变分发器，先跑原「相邻页」证明（`ResolveAdjacentPageSites`），只有 RenderChar 签名缺失（`kPageMissing`）才跑新「定向渲染」证明（`ResolveTargetedRenderSites`），只有完整证明才写出站点。定向渲染证明：RenderChar 序言唯一 + 记录笔位 / 字码 / `ret 8` 尾在固定偏移；GetCharImage 由 `FindVirtualCharImage` 在只读数据节扫 MSVC vtable（COL 指针为数据、槽 0/1 为代码、函数前有 int3 填充、过 `ProveCharImage` 的 GetGlyphOutlineA 链），恰一个不同函数才算（2016 映像实测唯一：0x677850 → 光栅器 0x677330）；ClearPage 由函数体（两张页图经同一填充助手）+ 至少一处 `mov ecx,[edi+0x2ac]; call ClearPage` 调用方证明；Update / reveal / SyncLayer、层查询 → Screen::QueryLayer → Scene::Visible → Scene::Find、Scene::Draw、输入处理函数 + 三个捕获导入照旧逐条证明。运行时：`Sites` 带 `variant` / `render_stack_args` / `walk`，3 参 RenderChar 走 `Cs2RenderTargetDetour`，只记录画进正常页（renderer+4，SyncLayer 拷进层的那张）的字；`ReadCs2LayerNodes` 按 `SceneWalk` 参数走两种列表。顺带修部分遮挡误杀：原先任何与上层 sprite 包围盒相交的字都被整字丢弃，导致所选台词整行匹配失败；现只有被完全盖住的字才从文本里去掉，部分相交的字保留在文本里，可点区域 `LineGlyph::hit` 只取确定未被盖住的矩形（盖住整条边则裁掉那一侧，角落 / 中间重叠则不可点）。提交：（见本分支 `fix(galgame): resolve the CatSystem2 targeted-render lookup layout`）
