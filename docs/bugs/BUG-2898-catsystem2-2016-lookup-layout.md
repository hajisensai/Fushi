## BUG-2898 · CatSystem2 2016 版内嵌查词从不安装（result=3，「定向渲染」代码布局未识别）
- **报告**：2026-10-03（用户：适配 ceshi / 官方体验版，初恋サンカイメ体验版真机测试中发现）
- **真实性**：✅ 真 bug。2016 版 CatSystem2（初恋サンカイメ体验版 `data\cs2.exe`）真机日志 `catsystem2-lookup: sites unresolved result=3`（`kPageMissing`），③ 内嵌查词恒不可用。根因 `native/galgame_hook/hook/adapters/catsystem2_lookup_core.h` 的 `ResolveSites` 只认一种代码布局（グリザイア有閑版测得）：ClearPage 与 `RenderChar(renderer, record)` 在映像里紧邻、GetCharImage 是直接 rel32 调用、场景层列表 `[[scene]+0x14]` 且层内嵌在节点里。Frida 只读探针实测 2016 版是同一引擎的另一代布局：`RenderChar(renderer, record, target_image)`（`ret 8`，target 为正常页 renderer+4 或淡入淡出页 renderer+0x40）、GetCharImage 只经字体对象 vtable 槽 1（`call [esi+4]`）、ClearPage 与 RenderChar 不再相邻、场景层列表在 `[scene+4]`（无 +0x14 跳）、节点经 `[node+8]` 指向层（层字段 id +0 / visible +4 / sprite +0x10 不变）。窗口（+4 / +0x68 / +0x2ac）、屏幕、sprite、记录字段两代相同。
- **[x] ① 已修复** — 按引擎布局分两条结构证明，不按游戏：`ResolveSites` 变分发器，先跑原「相邻页」证明（`ResolveAdjacentPageSites`），只有 RenderChar 签名缺失（`kPageMissing`）才跑新「定向渲染」证明（`ResolveTargetedRenderSites`），只有完整证明才写出站点。定向渲染证明：RenderChar 序言唯一 + 记录笔位 / 字码 / `ret 8` 尾在固定偏移；GetCharImage 由 `FindVirtualCharImage` 在只读数据节扫 MSVC vtable（恰一个不同函数才算，2016 映像实测唯一）；ClearPage 由函数体 + 调用方证明；Update / reveal / SyncLayer、层查询链、Scene::Draw、输入处理函数 + 三个捕获导入照旧逐条证明。提交 `d310cf6e37`。后续运行时逐道门修复（同一引擎变体）：
  1. **6 参输入处理函数**：定向渲染布局的 Input::Handle 以 `ret 0x18` 返回（6 个栈参数，ebp+8 输入对象 / +0xc hwnd / +0x10 msg / +0x14 wparam / +0x18 lparam / +0x1c extra），原 5 参 detour 栈失衡致崩溃；证明加 `c2 18 00` 尾校验与 `Sites::input_stack_args`，运行时按它选 6 参 detour。提交 `903f0cbbbc`。
  2. **淡入淡出页**：文本淡入开启时引擎把页拷进 renderer+0x40、在那张上画新字再交换两指针，探针实测 201 次绘制全进 +0x40；只认 +4 时 `render=0`、模型永不建立。`IsRendererPage` 两张页都认（`kRendererWorkImageOffset`）。
  3. **DPI**：2016 版进程是 DPI-aware（1280x720 客户区即物理像素），旧代码按 DPI-unaware 量逻辑客户区，按压门恒判 `client-size`。改为用游戏窗口自己的 `GetWindowDpiAwarenessContext` 量。
  4. **部分遮挡裁剪删除**：消息窗自身的菜单条层（id 60，盒 [0,658,1280,720]，y 658–688 透明）包围盒压住第二行下半，先前的「只留确定未盖住的矩形」把第二行字的可点区裁掉，点字下半落空穿透给游戏推进（破坏④）。sprite 包围盒只是不透明像素的上界，真正的遮挡物（菜单 / 回想）会整字盖住：现在完全被盖住的字仍从文本里去掉，部分相交的字整格可点（`ExcludeCover` 删除）。
  5. **有声台词带说话人后缀**：该版 Luna 文本线程（HA8:-1C）把台词报成 `「正文」【说话人】`，说话人画在独立名字层、不在文本页，整句后缀匹配恒失败（step 4），所有对白都没有模型，只有旁白能查词；首次点对白的字必穿透推进。`SpeakerTagStart` 找出行尾说话人标签，整句匹配不中时用正文（整句前缀，源索引不变）再配一次；页上真以【…】结尾的旁白仍按整句匹配。
