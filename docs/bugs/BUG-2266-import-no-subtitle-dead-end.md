## BUG-2266 · 选了音频没字幕点「导入」只提示不引导转录，用户以为语音模型选不中（Android 报告）
- **报告**：2026-09-08（用户：Android，原话「已下载语音模型，但是好像无法选定，也无法导入识别。之前可能网络问题，模型没有下载完然后用不了」；随附的 error_log 片段只有 Mihon 漫画 `InterruptedIOException` 与 UpdateChecker 超时，没有 ASR 条目。追问后补了截图：「导入书」对话框里 EPUB + `.m4b` 音频都选了、字幕行为空，点「导入」只得到 toast「音频需要配合字幕使用（给现有 EPUB 挂音频请在书架长按该书）」）
- **真实性**：✅ 真 bug，但不在模型 / 下载层，在导入门禁：`fushi/lib/src/media/audiobook/book_import_dialog.dart:_doImport`（原 `:908`）遇「有 EPUB、有音频、没字幕」只弹一句提示就 return，一个字不提转录；转录入口只是字幕行尾一枚无字图标（`Icons.record_voice_over_outlined`，f70630989d 给行本身加了「字幕来源」选择也没覆盖到这条路）。用户「下载了语音模型 → 选 EPUB + 音频 → 点导入」走到这里就是死胡同，于是把它理解成「模型选不中、导不进去」。`audiobook_import_dialog.dart:_doImport`（给现有 EPUB 附加有声书，原 `:668`）同样：没对齐文件只弹泛泛的「导入失败」。
  - 模型 / 下载 / 续传 / 弹层判定这一层**没有 bug**，全部在 Android 模拟器（`hoshi_test_api36`，API 36，x86_64）上用与 `main()` / 设置页 / 转录弹层同一份装配（`asr_host.dart` `installAsrHostBindings()` + `createAsrTranscriptionService()`）实测排除：模型目录 `/data/user/0/app.fushi.reader/files/asr_models/reazonspeech-k2-v2`；`plan()` 推荐 int8 · CPU、探测无错、两个入口结果一致；下到 2.1 MB 掐断后只留 `.part`、`plan()` 报「部分」不误判就绪（`model_file_downloader.dart` `_finalizePart` rename 前校验长度 == 清单）；再下走 Range 从 2.1 MB 续到 33.7 MB、总长正确（宿主机 `curl -r` 直连 / 经代理探四个候选源全 206，模拟器那两次中途断是本机到 HF CDN 抖动）；放入完整 int8 后真 `AsrTranscribeSheet` 1.2 s 显示「Model ready (ReazonSpeech k2-v2 · int8 · CPU)」+「开始转录」。
  - 自编 ffmpeg-kit AAR（`third_party/ffmpeg_kit_flutter/android/libs`）是全量构建（configure 行无 `--disable-everything`），arm64 的 libavformat/libavcodec 含 `mov`/`mp4`/`aac`/`s16le`/`wav`/`pcm_s16le`，用户的 `.m4b` 在 arm64 真机上解码没有硬障碍。
  - 转录本体在 x86_64 模拟器验不了：`start()` → `_probeMaterialMs` → `KitFfmpegBackend.runProbe` 抛 `createFFprobeSession failed: FFmpegKit native libraries are unavailable on … abis: x86_64`——APK 里 `libffmpegkit.so` 只有 arm64-v8a / armeabi-v7a。arm64 真机上这一段仍属未验证（BUG-2197 修复 `de650b6a3b` 已在 v2.3.0 / v2.3.0-beta.1248 内）。
- **[x] ① 已修复** — `2e207ebdbb`（审查后收口见下一条提交）。两个 `_doImport` 门禁不再一句提示了事，改走点行的同一条路，拿到字幕后 `return _doImport()` 接着导入（递归深度恒为 2：第二遍字幕已在，该分支整条跳过；`_handoffIfManga` 的整包判定被 `ImportCarrierResolver` 单槽 memo 住，第二遍不重开包也不二次弹确认）。用户关掉选择 = 取消，什么都不导。
  - `book_import_dialog._doImport`：有 EPUB + 音频没字幕，且 `shouldOfferSubtitleSourceChooser(asrSupported: isAsrSupported, hasAudio: true)` 为真 → `_onSubtitleRowTap()`。不能转录的平台**仍走原提示**——那句提示除了「要字幕」还带着「给现有 EPUB 挂音频请在书架长按该书」这条别处没有的信息，不能替换成静默弹选择器。
  - `audiobook_import_dialog._doImport`：`_hasAudioSource` 为真就无条件 `_onAlignmentRowTap()`（它自己按能否转录分流成「字幕来源」或文件选择器）。这里不再判 ASR：审查指出原写法的 `!widget.audioOnly && _alignmentPath == null` 在外层条件下恒真，而 `shouldOffer` 传的 `_audioPaths?.isNotEmpty` 与 `_hasAudioSource` 含义不一致（后者还含 `_audioDir`）——与其加条件描述特殊情况，不如让它消失。「导入失败」只留给真的什么都没选。（`_audioDir` 非空且 `_alignmentPath` 为空在当前代码里实际不可达：唯一写 `_audioDir` 的 `_enterReplaceSubtitleMode` 同时会设 `alignmentPath`。）
- **[x] ② 已加自动化测试** — `fushi/test/media/audiobook/import_dialog_no_subtitle_offers_transcribe_test.dart`：真 `BookImportDialog` / `AudiobookImportDialog` 预填音频、无字幕，点「导入」断言真的出现「字幕来源」+「转录」项，关掉后库里零记录。**刻意不写「没弹旧 toast」那种断言**：`FushiToast` 要有全局 navigatorKey 才画得出 overlay，widget 测试里没设、toast 从来进不了树，`findsNothing` 恒真守不住任何东西（审查抓出的空壳断言，已删）。另有 `fushi/integration_test/asr_android_model_ready_itest.dart`（模拟器 / 真机；`ASR_MODE=network` 真网络下载→中断→续传→就绪，`ASR_MODE=seed` 免联网验就绪→转录→弹层；素材经 `run-as` 写进 app 内部 `files/`）。
- **备注**：相邻但未改的两个缺口：① 下载流中途断一次就整条流报错、要用户再点一次「下载」（进度保留），弱网用户会反复看到「下载失败」；② `_downloadFile` 只抛最后一个候选的错，第一个候选的错被吞。
