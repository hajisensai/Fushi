## BUG-2381 · Aidoku 源报 error sending request，两层各抹掉一半原因，结构上不可诊断
- **报告**：2026-09-09（用户：iPhone 上打开 Aidoku 的 MangaDex 源，`AidokuRuntimeException(RUNTIME_FAILED): Aidoku source returned error code -3: Error: RequestError(RequestError)` / `network: GET https://api.mangadex.org/manga -> error sending request`）
- **真实性**：✅ 真 bug（诊断链路缺陷 + 中继单例不可自愈）。报错本身**无法**定位到具体失败原因，因为原因在两层被分别丢弃：
  - `native/aidoku_runtime/src/embedded.rs:807`（旧）只插值 `error.without_url()`。`reqwest::Error` 的 `Display` 只打错误**类别**：`Kind::Request` 一个词 "error sending request" 同时覆盖 DNS 失败、TCP 拒绝、本地中继隧道被拒、TLS 握手失败和 30s 默认超时，真正原因全在 `source()` 链里，被丢掉了。
  - `fushi/lib/src/utils/net/app_native_proxy.dart:_serve`（旧）的 catch-all 把 `_connect` / `_forward` 的任何异常压成一个裸 502，**不留任何日志**；而 `hyper-util` 的 `tunnel.rs` 把任何非 200 的 CONNECT 结果一律收敛成 `TunnelUnsuccessful`（Display 就一个 "unsuccessful"）。中继是唯一知道真实原因的一层，它也不说。
  - 附带查出的第二个真缺陷：`ensureAppNativeProxyEndpoint` / `ensureAppChallengeProxyEndpoint` 用 `??=` 永久缓存 Future。① 监听 socket 被系统回收（iOS 挂起 app 后可能收走）后端口还在缓存里，此后每个 native 请求都撞 connection refused，只能重启 app；② 首次 `bind` 失败时那个**已失败**的 Future 被永久缓存，后续调用重抛同一个旧异常，连重试机会都没有。这正好是「昨天还好好的，今天 aidoku 炸了」的形状。
- **不是**根因的几条（已排除）：中继的 CONNECT 隧道**与 hyper-util 兼容**——按 `tunnel.rs` 的原样字节复刻（状态行 `HTTP/1.1 200` 前缀 + 首批字节必须正好以 `\r\n\r\n` 收尾）实测建得起来，见新增测试；Cloudflare 路径没进（`is_cloudflare_challenge` 需要先拿到响应，本次连响应都没有）；也不是 429（429 会记成 `-> 429 (N bytes)`）。
- **[x] ① 已修复** — `embedded.rs` 新增 `error_chain()`，`send_request` 的两处失败分支改打完整 `source()` 链（仍不带 URL）；`app_native_proxy.dart` 新增 `appNativeProxyLogSink`（默认 `debugPrint`，被 `DebugLogService` 钩住），`_serve` 的 catch-all 把「方法 + 去 query 的目标 + 真实异常」脱敏后交出去；`ensureAppNativeProxy()` / `ensureAppChallengeProxy()` 取代 `??=`，交出前先验 `isRunning`，死了或上次启动失败就另起一个（新 Future 在 await 前写回缓存，并发调用仍只启一个）。
- **[x] ② 已加自动化测试** — `native/aidoku_runtime/src/embedded.rs` 的 `error_chain_keeps_every_cause_and_drops_repeats`；`fushi/test/utils/net/app_native_proxy_diagnostics_test.dart`（hyper-util 隧道判据、失败原因落到日志出口、凭据脱敏、中继自愈）。
- **备注**：本机是 Windows，Aidoku runtime 只在 macOS / iOS 装配（`AidokuRuntimeFactory.isSupported`），**没有做真机复测**。这轮改的是「让这条错误说出原因」和「中继不再一次坏永久坏」；用户下次复现时错误尾巴会变成 `-> error sending request: <真正的原因>`，据此再定位是网络不可达、代理拒绝还是证书不认。
