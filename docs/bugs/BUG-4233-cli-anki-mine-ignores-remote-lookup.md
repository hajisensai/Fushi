## BUG-4233 · fushi_cli anki mine 在依赖远端查词的客户端上释义为空（只查本地词典）
- **报告**：2026-11-07（Linux Phase 4 互联测试，第 5 行；证据为实测 CLI 输出与两端笔记导出，未入库）
- **真实性**：✅ 真 bug。客户端本机没有词典、开着 `lookup.remote_lookup`（app 内查词能显示 host 的词典条目），开着 `interconnect.mine_to_server` 时 `fushi_cli anki mine -w 漢字` 能把卡落到 host 的 SRS，但 glossary 是空的。
  - 根因：控制通道替**本机用户**查词时用的是本机**作为 host 替对端 / 浏览器扩展**查词的服务：`fushi/lib/src/ops/ctl_dictionary_routes.dart:383`（`anki mine`）与 `:262`（`dict search`）`searchRemoteDictionaryForRequest(app().createRemoteLookupService(), ...)`，`fushi/lib/src/ops/ctl_video_player_routes.dart:276`（`video mine`）、`fushi/lib/src/ops/ctl_game_routes.dart:755`（`game mine`）`createRemoteLookupService().searchDictionary(...)`。这个服务（`fushi/lib/src/models/app_model.dart` `_AppModelRemoteLookupService._searchDictionary`）刻意 `allowRemoteLookup: false`（`app_model.dart:13621`，防止互为 host 的两台设备互相转发），只查本机词典；瘦客户端本机没词典 → 空结果 → `buildCtlMineFields` 释义 / 读音为空。查词页走的是 `AppModel.searchDictionary` 的远端优先链，不经这里。
- **[x] ① 已修复** — 提交见下方备注。`AppModel.searchDictionaryForUser`：与查词页同一条链（`_searchDictionaryInLanguage`，远端优先、本机作品级配置），多一个调用方声明的查词语言；控制通道四处（`dict search`、`anki mine`、`video mine`、`game mine`）都改用它，不再另走 host 侧服务，查词逻辑不复制。替对端查词的服务保持只查本机。自动朗读覆盖守卫把 `searchDictionaryForUser(` 同样计为查词调用点（`auto_read_surface_coverage_guard_test.dart`）。
- **[x] ② 已加自动化测试** — `fushi/test/ops/ctl_mine_remote_lookup_test.dart`：真 host（FushiSyncServer 的 `/api/lookup/dictionary`，词典由假服务提供）+ 真客户端 AppModel（只接了数据库与偏好、本机词典引擎未起 = 瘦客户端，开着远端查词）+ 控制通道真路由：`POST /api/admin/anki/mine {word: 漢字}` 的字段带 host 的读音与释义（含词典名），`GET /api/admin/dictionaries/search` 返回 host 的词条；`createRemoteLookupService()` 仍不转问 host。
- **备注**：修复见 PR #3075。真机观察：客户端（无本机词典，`fushi_cli settings set lookup.remote_lookup true`，`interconnect.mine_to_server` 开）跑 `fushi_cli anki mine -w 漢字`，结果的 `glossary` 应含 host 词典（如「Fushi Smoke Dict」）的释义、`reading` 有值；`fushi_cli dict search 漢字` 同样列出 host 的词条（修复前为空）。
