## BUG-4323 · 游戏内卡嵌套子卡向上翻出后两张卡下方出现透明区
- **报告**：2026-10-24 / 11-07 补充（应用内反馈 SDbJAx1Db6，3.0.1-debug.21002，Windows，附 6.6 s 录屏；用户：CLANNAD 游戏内查词卡里再点一个词，下方放不下时子卡向上弹出，此后两张卡下方都出现透明部分）
- **真实性**：✅ 真 bug。录屏逐帧（6 fps 抽帧 + 与查词前帧做差分）：子卡出现后，子卡只露出贴着客户区顶边的一截（原本约 290 视频 px 高，只露约 135），根卡整体**上移约 153 视频 px**（上移量 = 子卡顶边到根卡顶边的距离），根卡左半边上端被齐平切在它原来的顶边处；差分图里两张卡原本的矩形（子卡 222→376、根卡 437→590 视频 px）仍是一块淡色区——HWND、HRGN（shellRects）与投影都还在正确的 union 几何上，**只有 DOM 内容没有按 union bbox 原点做补偿平移**，整叠卡被画回 window-local 原点。因此透明区既不是 union HWND 多出的高度，也不是 shell 没收缩；`PlaceDirectUnionAroundRoot` 的几何推导是对的（新增单测钉住 union = 两卡外接矩形）。
  - 根因：直连 present 借用 legacy `Reveal` 上屏，而 `Reveal` 无条件执行 `resetLayerOffsetForLegacyReveal`（修复前 develop 704f8c6bd9 的 `fushi/windows/runner/global_lookup_window.cpp:1514`，BUG-2123 的复位，假设窗口在「光标处 + 单卡尺寸」）。`RevealOverProcessClient`（同一版本 `global_lookup_window.cpp:2748` 的 `Reveal(screen_width, screen_height, false, game)`）却把窗口放在**已提交几何的 union bbox 原点 + union 尺寸**，图层平移是 `ResizeStackForGal` 的 `commitLayerShiftAndArmCapture(bbox_left, bbox_top)` 刚写好的。嵌套 resize 后 Dart 每次都重投 present（`fushi/lib/src/lookup/gal_ingame_lookup_controller.dart` `_onOverlayRevealed` → `_scheduleRecapture` → `_present`），于是 bbox 原点为负（子卡向上 / 向左翻出）时平移被清零。子卡向下 / 向右展开时 bbox 原点是 (0,0)，复位是 no-op，所以只有翻上 / 翻左才出现。同一次清零还让 host 的命中测试（`frameIdAtPoint` 用 `layerOffset*`）与画面错位。
- **[x] ① 已修复** — `GlobalLookupWindow::Reveal` 新增 `RevealLayerOrigin` 参数：默认 `kCursorSingleCard` 保持 legacy 复位（桌面 reveal(scalar) / READY-SAFETY 兜底不变）；`RevealOverProcessClient` 传 `kCommittedBBox`，不再复位图层，保留同一几何的 commitLayerShift(bbox)。没有加延迟、重试或特例分支。
- **[x] ② 已加自动化测试** — `fushi/test/lookup/global_lookup_shell_region_guard_test.dart`「直连 present 保留 union bbox 图层平移」：Reveal 的复位脚本只在 `kCursorSingleCard` 门内、头文件默认值、`RevealOverProcessClient` 唯一的上屏调用传 `kCommittedBBox`；原有「直连上屏不再夹 rcWork」断言同步改成新调用形态。`fushi/windows/runner/tests/gal_direct_card_geometry_test.cpp` 新增录屏同形的子卡翻上（与根卡重叠、顶到客户区顶边）用例：根卡逐像素不动、union = 两卡外接矩形、HWND 不多出高度。测试未在本分支运行（本批次统一在合并后验证）。
- **备注**：Galgame 规则下状态为 `implemented_unverified`：未在 CLANNAD 原始路径（游戏内卡 → 卡内点靠下的词 → 子卡翻上）真机复测，也未做 Windows 构建；需在用户原始路径复验两张卡下方不再有透明区、子卡完整显示、根卡不动，以及翻上后点击子卡 / 根卡内的词命中正确。
