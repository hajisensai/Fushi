## BUG-2956 · 串流主机拒绝原因一律显示成主机版本过旧
- **报告**：2026-10-05（用户截图：两端都是最新版，游戏页显示「主机版本过旧，没有游戏库」；BUG-2955 修了其中「重启后丢游戏库」那条触发路径，本条修提示本身）
- **真实性**：✅ 真 bug。服务端串流入口的几道门回的都是无结构文本：没挂串流服务回裸 404「Game stream off」，明文 HTTP 回裸 403「HTTPS required for game stream」，凭据不是已配对设备回空 403（`packages/fushi_engine/lib/sync/fushi_sync_server/game_stream.part.dart`）；没挂游戏库回裸 404「Game library off」（`game_stream_service.dart` `_handleLibrary`）。客户端 `fushi/lib/src/sync/game_stream_client.dart` 把不带版本化 `code` 的非 2xx 一律归为 `http_rejected`，`game_stream_library_page.dart` 再把 `http_rejected` 译成「主机版本过旧，请更新 Windows 端」。结果是没开 HTTPS、没开游戏模块这类只需改设置的情况，都被说成要更新版本。
- **[x] ① 已修复**（`80e80e33`，合入 `5da47392`）— 协议层新增 `GameStreamRejection`（`game_stream_off` / `https_required` / `unauthorized_peer` / `library_off`），服务端各道门统一用 `gameStreamErrorResponse` 回带版本号的 JSON 错误；客户端白名单补收 `game_stream_off` / `https_required` / `library_off`（`unauthorized_peer` 原本就在白名单）；库页面去掉单独的「过旧」状态，改为「被拒」加原因码，由 `gameStreamRejectionMessage` 按原因出文案（新增 4 条 i18n）；`library_off` 的主机图标用「游戏库关闭」而非「禁止」，因为已有会话仍可加入。只有不带原因码的裸非 2xx（真正的旧主机）仍提示更新。
- **[x] ② 已加自动化测试**（`80e80e33`，补测随后续提交）— `fushi/test/sync/fushi_sync_server_game_stream_test.dart`（真服务器：明文回 `https_required`、未配对凭据回 `unauthorized_peer`、无库回 `library_off`、无串流服务回 `game_stream_off`）、`fushi/test/sync/game_stream_client_test.dart`（四种原因码穿过传输层）、`fushi/test/pages/game_stream_library_page_test.dart`（HTTPS 未开、串流服务未开、未配对凭据、无游戏库四种原因各出对应文案，不再显示「过旧」）。变异实测（原提交）：服务端、白名单、HTTPS / 游戏库两条文案映射各撤一处，对应测试都变红；串流服务未开与未配对两条映射的页面测试为后续补齐。
- **备注**：旧客户端遇到 `game_stream_off` / `https_required` / `library_off` 时仍走 `http_rejected`，提示与修复前一样，不会更差；遇到 `unauthorized_peer` 显示通用的「被拒」，比修复前的「过旧」更准确。新增的 4 条文案除中英文外，其余 15 种语言暂时都是英文。
