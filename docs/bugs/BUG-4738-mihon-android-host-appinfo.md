## BUG-4738 · Android Mihon 宿主缺 eu.kanade.tachiyomi.AppInfo，MangaDex 等调用它的扩展 NoClassDefFoundError
- **报告**：2026-11-16（用户：应用内反馈 SuIzXwKW4_，Android SDK 36，3.3.0，漫画全局搜索 / 在线源浏览时 MangaDex 扩展反复报 `NoClassDefFoundError: Failed resolution of: Leu/kanade/tachiyomi/AppInfo;`）
- **真实性**：✅ 真 bug。Mihon extension-lib 1.3 起把 `eu.kanade.tachiyomi.AppInfo`（`getVersionCode` / `getVersionName`，1.5 加 `getSupportedImageMimeTypes`）列为宿主 API，扩展 compileOnly 引用、运行期按名解析（keiyoushi MangaDex 用它拼 User-Agent）。上游 Mihon 把它放在 app 模块而不在 `source-api`：`fushi/android/app/build.gradle:51` 的 `prepareMihonSourceApi` 只拉 `source-api/src/main/kotlin/**`，`fushi/android/app/src/main/kotlin/eu/kanade/tachiyomi/` 下也没有自己声明（只有 `network/`、`animesource/`），R8 规则 `fushi/android/app/proguard-rules.pro` 的宿主 ABI 区块同样没有它。桌面 sidecar 的 `third_party/m_extension_server/upstream_src/.../eu/kanade/tachiyomi/AppInfo.kt` 自带一份，所以只有 Android 坏。
- **[x] ① 已修复** — 新增 `fushi/android/app/src/main/kotlin/eu/kanade/tachiyomi/AppInfo.kt`（Kotlin `object`，`INSTANCE` + 实例方法，与上游描述符一致；版本取 `app.fushi.reader.BuildConfig`；图片 MIME 为阅读器能显示、`mangaImageContentType` 能嗅出的 jpeg / png / gif / webp / avif），`proguard-rules.pro` 加 `-keep class eu.kanade.tachiyomi.AppInfo { *; }`。
- **[x] ② 已加自动化测试** — `fushi/android/app/src/test/kotlin/eu/kanade/tachiyomi/AppInfoAbiTest.kt`（按名反射钉 `INSTANCE` 与三个方法的返回类型，与扩展 dex 解析方式一致）；`fushi/test/media/manga/mihon_host_app_info_guard_test.dart`（源码形状守卫）；`fushi/test/media/manga/mihon_host_abi_keep_guard_test.dart` 宿主 ABI 清单补 `eu.kanade.tachiyomi.AppInfo`（修复前两条 Dart 守卫均红）。
- **备注**：反馈里的整进程 CRASH 没有 Java 栈，本修复只消除 AppInfo 缺失这一确定的失败；该 Error 是否就是崩溃来源（如在未兜底线程抛出）未经 logcat / ApplicationExitInfo 证实，未做真机复测。桌面 sidecar 的 `upstream_src` AppInfo 缺 `getSupportedImageMimeTypes`（lib 1.5+），不在本条范围。
