## BUG-3552 · 复习：导入 Anki 包时牌组与牌组设置分两轮写，中途失败或被杀后设置永远不写
- **报告**：2026-10-19（PR #2336 审查遗留，协调要求根本性修复）
- **真实性**：✅ 真 bug，测试复现：第一次导入在算第一个牌组的预设参数时抛异常，旧实现里牌组已落库、设置没写；重导时牌组已存在不算「新建」，设置一直缺。根因（修前）`packages/fushi_engine/lib/srs/apkg/srs_apkg_import.dart` `_mapDecks`：先逐个建牌组（身份记录与名字分两次落库），全部建完再另起一轮只给本次 created 的牌组写预设 / 收起 / ext 键。
- **[x] ① 已修复** — `_mapDecks` 每个新牌组的身份记录、名字 / 父牌组、恢复标记与设置（`_newDeckSettings`）一次 `writeEdits(records:)` 同一个事务落库；改名重建分支（`renamedImport`）语义不变（不带设置，ID 派生同 createDeck）。
- **[x] ② 已加自动化测试** — `srs_apkg_import_test.dart`「建牌组途中失败：牌组与它的设置同一事务…」（引擎第一次校验参数时抛异常）；变异实测：先单独落库牌组再算设置，测试红。
