## BUG-2586 · 设置页AniDB状态按四项偏好判空，内置客户端账号测试登录成功仍显示未配置
- **报告**：2026-09-18（用户：AniDB「测试登录」已成功，在线服务页 AniDB 行仍显示「未配置」；并要求确保哈希识别刮削真正可用，且识别模型对齐 Shoko）
- **真实性**：✅ 真 bug，两个根因叠加。① `fushi/lib/src/settings/settings_schema_services.dart` `services.metadata.configure` 的 `subtitleBuilder`（修前）要求 `kVideoAniDbUsernamePref / kVideoAniDbPasswordPref / kVideoMetadataAniDbClientNamePref / kVideoMetadataAniDbClientVersionPref` **四个偏好键全非空**才算「已配置」；而真实登录路径 `VideoSourceScrapeGlobalConfig.fromPreferences` → `resolveAniDbAppClient`（`packages/fushi_engine/lib/media/video/metadata/anidb_app_client.dart`）在客户端名留空时走内置 `fushiplayer` v1，所以只填账号密码的用户「测试登录」成功、状态却说「未配置」。② `fushi/lib/src/settings/settings_schema_widgets.dart` `_routeRow` push 子页不 `await`、返回也不 `settingsContext.refresh()`，而 Flutter `ModalRoute` 缓存页面内容（`_ModalScopeState._page ??=`，`didPopNext` 只 `setState` 外壳），从 AniDB 子页填完账号弹回父页时状态行不重算——即便判据修对了也仍停在旧值。审计哈希链路时另发现三处让「哈希识别」在正常使用中失效的问题：`AnidbUdpFileClient` 与协调器同寿命，AniDB 虚拟连接 35 分钟无数据即失效，下一批第一条 FILE 回 501/506 直接判失败不重登；一次 UDP 超时立即进程级封 30 分钟；`anime-lists` 一对多映射把整个作品判 pending 且不给候选，且 AniDB 文件/分集身份从不落库、作品级 `anidb` id 只在 MAL 映射唯一时才写。
- **[x] ① 已修复** — 状态判据：`VideoSourceScrapeGlobalConfig.anidbHashReady`（`video_source_scrape_config.dart`）成为「哈希识别会不会跑」的唯一真值（`hashEnabled && anidbUdpConfig.isAvailable`，与协调器 `AnidbHashIdentityService.enabled + isConfigured` 同判据），设置页状态行与首页「配置在线服务」提醒（`video_online_services_preferences.dart`）都改用它；`_routeRow` push 子页改为 `await` + 返回后 `settingsContext.refresh()`。哈希链路对齐 Shoko：`AnidbUdpFileClient.lookup` 在 FILE 回 501/506 时清会话、重新 AUTH、同一条 FILE 重发一次；`_request` 无应答时同 tag 原样重发一次，第二次仍无应答才按封禁处理（Shoko `BanTimerResetLength` 1.5 h），320 未收录在客户端内存里只缓存 1 小时；新表 `anidb_file_identities`（schema v106，键 `(ed2k, file_size)`，`packages/fushi_core/lib/src/database/tables.dart`）经 `AnidbFileIdentityDatabaseStore`（`anidb_file_identity_store.dart`）接进 `AnidbHashIdentityService.identifyFile`——路径+大小+mtime 命中免哈希、哈希后内容键命中免 FILE、未收录也落行并 7 天后复查；`VideoSourceScrapeCoordinator._resolveWork` 不再以「作品无身份」为哈希前置（文件级第一步，已确认/已落库身份仍优先、哈希与之冲突只警告不换源），AniDB 作品 id 由全部成员一致的哈希直接落库，`anime-lists` 一对多把各 MAL id 按 id 拉成候选走既有 AI / 人工确认路径；协调器默认装配让哈希服务与离线 id 接力共用一份 Fribb 表；`VideoLibraryScrapeSweep` 在哈希就绪时让纯集号标题文件与已识别作品里尚无文件身份的成员也进补刮；哈希关闭时每批留一条说明。
- **[x] ② 已加自动化测试** — `fushi/test/settings/anidb_service_status_test.dart`（真 prefs：账号齐 + 客户端留空 → 「已配置」；自定义客户端缺版本 → 「未配置」；源码守卫状态行不得再按单个偏好键判空）；`fushi/test/settings/settings_subpage_schema_test.dart`（子页弹回后父页 refresh 一次）；`fushi/test/media/video/metadata/anidb_hash_config_test.dart`（`anidbHashReady` 四种组合）；`fushi/test/media/video/video_online_services_banner_test.dart`（自定义客户端不合规仍提醒）；`fushi/test/media/video/metadata/anidb_udp_file_client_test.dart`（501/506 重登重发一次、第二次仍拒才抛、丢包同 tag 重发一次、两次丢包才超时）；`fushi/test/database/migration_v106_anidb_file_identities_test.dart`（v105→v106 建表 + 索引 + 大小写归一 + CHECK）；`fushi/test/media/video/anidb_hash_identity_service_test.dart`（持久层：二次命中不哈希不发 FILE、搬家只重哈希不重问、未收录 7 天内不重问）；`fushi/test/media/video/metadata/mal_hash_coordinator_test.dart`（无 MAL 映射也落 AniDB id、一对多给候选并可确认、已确认 MAL 仍哈希文件但不换身份、哈希与已确认冲突只报不改、一致时补交叉引用、关闭时留一条说明）；`fushi/test/media/video/metadata/video_library_scrape_sweep_test.dart`（哈希就绪时纯集号标题进补刮、已识别作品的新文件排队且不进待确认清单）。
