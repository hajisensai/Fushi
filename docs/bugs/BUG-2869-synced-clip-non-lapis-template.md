## BUG-2869 · 视频片段制卡写进不原样渲染图片字段的模板（Kiku）后动图和音频都不显示
- **报告**：2026-10-02（用户：Discord 用户 LiFTH，使用 Kiku 笔记模板；截图为 AnkiDroid 字段编辑视图）
- **真实性**：✅ 真 bug。默认图片模式 `videoClip` 让卡片图片字段写 `<video class="fushi-inline-video">`（`packages/fushi_anki/lib/src/anki_note_composer.dart:133` `inlineVideoCoverHtml`）、句子音频字段写重播按钮 + 隐藏 `<audio>`（同文件 `:164` `inlineVideoSentenceAudioHtml`），整张卡没有 `<img>` 也没有 `[sound:]`。这套表示只在模板**原样渲染**图片字段时成立（Lapis：`<div class="image">{{Picture}}</div>`），但模式开关 `fushi/lib/src/mining/immersion_mining_engine.dart:465` `wantsSynchronizedVideo` 只看用户偏好，从不问目标笔记类型；Netflix 录制（`fushi/lib/src/models/app_model.dart` `mineImmersion`）与 galgame 窗口录制（`fushi/lib/src/mining/gal_hook_mining_coordinator.dart` `_mineLineNow`）同样按偏好直接录片段。Kiku（youyoumu/kiku `packages/note/template/back.html`）把所有字段放进 `<template data-field>` 由脚本二次解析：`PictureSection.tsx` 只取 `querySelectorAll("img")`，`<video>` 被丢弃；句子音频只认 `[sound:]` 渲染出的 `<a>` 或 `<audio>`。`LapisPreset.matches` 按字段名把 Kiku 当成 Lapis，掩盖了差异。
- **[x] ① 已修复** — 新增判据 `noteTypeRendersSynchronizedClip`（`packages/fushi_anki/lib/src/anki_synchronized_clip_template.dart`：消费 `{card-image}` 的字段在任一卡片模板的 `<template>` / `<script>` / 注释之外以裸 `{{字段}}` 出现）与解析函数 `resolveTargetMiningImageMode`（`fushi/lib/src/mining/mining_image_mode_target.dart`：`videoClip` 且模板确定不支持 → `gif`；读不到模板保持偏好）。在产出媒体之前的三个决策点求值：引擎（按时间窗抽取的路径）、galgame 协调器、Netflix 入口。提交见 git log（`fix(anki): fall back to animated cover for templates that cannot show synced clips`）。
- **[x] ② 已加自动化测试** — `packages/fushi_anki/test/synchronized_clip_template_test.dart`（内置 Lapis 判支持、Kiku 结构判不支持、过滤器/条件段/script/注释、别名映射）；`fushi/test/mining/mining_image_mode_target_test.dart`（非片段模式零读取、不支持 → gif、读不到/失败保留）；`fushi/test/mining/synchronized_video_mining_test.dart` 两条引擎端到端（Kiku 式模板不导出同步片段、出动图 + 独立句子音频；Lapis 式保留同步片段）。
- **备注**：AnkiMobile 后端读不到模板（`supportsNoteTypeEditing == false`），保持原行为。用户在设置里选的偏好值不改，只改本次制卡的生效模式。
