## BUG-3670 · 下载并自动转录的有声书无法再配上对应的 EPUB
- **报告**：2026-10-23（用户：应用内反馈 Q0kWQNkF2f（Windows 3.0.0-debug.20679）/ Ulw9gIyZGk，「有声书在 fushi 里下载并且自动转录字幕，放到阅读菜单里之后没有办法添加对应的书籍 epub」，截图是该书卡的长按菜单，只有「重新导入 / 查看插画」）
- **真实性**：✅ 真 bug。下载器导入走 `packages/fushi_engine/lib/media/discovery/import/discovery_engine_importers.dart:150` 的 `importStandaloneSubtitleBook`，落成一本**正文由 cue 生成**的字幕书（uid `srtbook_<ts>`，bookKey 指向生成的 EpubBooks 行）。之后：① 书架卡菜单（`fushi/lib/src/pages/implementations/reader_history/books.part.dart` `_srtExtraActions`）只有「重新导入」，其对话框 `SrtBookReimportDialog` 只能换音频 / 字幕两半，没有书籍文件一行；② 书籍导入对话框 `BookImportDialog` 虽支持「EPUB + 字幕 + 音频」对齐导入（`_importEpubWithAlignment` → `alignAndPersistAudiobook`），但转录出的字幕和下载的音频都在 App 私有持久目录里，用户在文件选择器里找不到，等于没有路径。
- **[x] ① 已修复** — 字幕书卡菜单加「添加书籍文件」（仅正文不是用户 EPUB 的字幕书，判据 `srtBookCanAttachEpub` 与 `reimportSrtBook` 的 uid 负向闸门同源；EPUB 有声书配对行 `srtbook_epub_<bookKey>` 不出现）。点开后 `resolveSrtBookEpubAttachPrefill`（`fushi/lib/src/media/import/srt_book_attach_epub.dart`）按播放侧同一口径 `resolveAudiobookPlaybackFiles` 解析出真实存在的音频（顺序即 `audioFileIndex`）与字幕，预填进 `BookImportDialog`，用户只选 EPUB，走唯一的对齐导入路径。`BookImportDialog` 新增 `requireBook`：此入口没选书就点导入会先弹书籍选择器，不会落进字幕书分支再生成一本重复的字幕书。对齐导入会把音频 / 字幕复制进新书自己的持久目录，所以成功后提示并弹标准删除确认，让用户决定是否删掉原字幕书（删本地文件不伤新书）。
- **[x] ② 已加自动化测试** — `fushi/test/media/import/srt_book_attach_epub_test.dart`：可添加判据三态（生成正文 / 孤儿 / EPUB 配对行）、预填音频按自然序枚举 `audioRoot` 且只含存在文件、显式 `audioPaths` 保序剔除缺失文件、字幕缺失回 null、书架入口把预填交给 `BookImportDialog` 且带 `requireBook: true`。
- **备注**：原字幕书的阅读进度 / 统计不迁移到新书——两本书的正文不同（cue 生成稿 vs 用户 EPUB），字符偏移没有对应关系。未在真机上走完整 UI 流程。
