## BUG-5159 · aggregate-cloud-snapshot-json-codec-on-caller
- **报告**：2026-11-22（PR #4062 第二轮修 BUG-5149 / HBK-AUDIT-028 时分出的残余）
- **真实性**：✅ 真问题（性能 / UI 卡顿，云通道）。BUG-5149 之后云聚合同步的 DB 读取、折叠、写回、裁剪、编码哈希都在后台所有者 `AggregateSyncOwner` 里，但传输层仍是 JSON 值级别：`packages/fushi_engine/lib/sync/sync_asset_store.dart` 的 `getJsonAsset` / `putJsonAsset` 由各云后端（`fushi/lib/src/sync/{webdav,google_drive,onedrive,dropbox,ftp,sftp,obfuscating,interconnect}_sync_backend.dart`、`packages/fushi_engine/lib/sync/local_directory_asset_store.dart`）在调用方（app 里即 UI isolate）做整份快照的 UTF-8 + JSON 编解码；对端快照缓存 `aggregate_peer_snapshot_cache.dart` 的读写同样在调用方编解码。于是 `AggregateSyncService._syncWithOwner`（`aggregate_sync_service.dart` 约 216 / 258 行）要把解码好的对端快照 Map 拷进所有者、真要上传时再把待上传 Map 拷回调用方。
- **[x] ① 已修复**（拍板台 `review-agg-cloud-bytes`，维护者 2026-11-22 拍「做」）：`SyncAssetStore` 加字节级小资产读写 `getBytesAsset` / `putBytesAsset`（上限 `kSyncBytesAssetMaxBytes` = 256 MiB），9 个实现（WebDAV / 互联 / Google Drive / OneDrive / Dropbox / FTP / SFTP / 混淆层 / 本地目录）各用已有下载 / 上传原语实现，JSON 读写改成在字节原语上解码 / 编码（不再各写一套传输）。对端快照缓存 `aggregate_peer_snapshot_cache.dart` 改存远端原样字节（一行 JSON 头 + 原样正文，后缀 `.json`→`.snap`，`kFormat` 3；旧副本不再命中，下一次 `retainOnly` 删掉）。`AggregateSyncService._syncWithOwner` 调用方只搬字节：每份对端字节随 `TransferableTypedData` 交给所有者解码 + 裁剪 + 折叠（不等折完就下载下一份，解码与网络重叠），上行报文体由所有者一步编成 UTF-8 字节、哈希直接对字节算（不再另编一遍字符串），调用方 `putBytesAsset` 原样上传。顺带：WebDAV / Google Drive 原先按 10 MiB JSON 上限读聚合快照，大库首轮会失败；字节通道用 256 MiB 上限。上行哈希口径从 UTF-16 码元换成 UTF-8 字节，含非 ASCII 的快照升级后每条通道多传一次（纯缓存，写入幂等）。
- **[x] ② 已加自动化测试**：`fushi/test/sync/aggregate_sync_off_ui_isolate_test.dart`「云通道只搬字节」——只认字节读写的资产库（`getJsonAsset` / `putJsonAsset` 一调就失败）+ 真实副本缓存跑两轮，断言调用方零整份快照工作、第二轮读副本不重下、上行字节可按同一编解码读回；`sync_asset_store_contract.dart` 加字节往返契约；`cloud_json_asset_transport_test.dart` 加 OneDrive / Dropbox 字节往返（含 >10 MiB 走上传会话）与字节副本格式 / 旧副本作废用例。
- **备注**：互联通道（client + host）已无此问题（BUG-5102 / BUG-5149）。per-device 清单镜像（合集 / 墓碑包 / 视频 / 媒体链接）与聚合快照共用同一个字节级副本类，清单本身仍走 `getJsonAsset`（每台设备一份的小文件，不在本条范围）。
