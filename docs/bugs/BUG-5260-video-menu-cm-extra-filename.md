## BUG-5260 · video-menu-cm-extra-filename
- **报告**：2026-11-23（应用内反馈 LBhq-ZoXjw）
- **真实性**：✅ 真 bug。`packages/fushi_engine/lib/media/video/metadata/video_local_extra_classifier.dart` 的文件名兜底只认 `trailer` 与 `ncop|nced|creditless op/ed|pv`，与正片同目录、只靠文件名标出的 `[Menu]` / `[CM]` 特典认不出，于是被 `video_source_work_planner.dart`（`classifyLocalVideoExtra(...) == null`）当正片进刮削计划、各自建 book-owned work，在系列墙 / 最近添加里单独出现，不挂到父作品的花絮下。发布级判据 `video_release_extras.dart` 另有一份收了 `cms?/menus?/trailers?/teasers?/bonus` 与 CJK 标记的词表，两边口径不一致。
- **[x] ① 已修复** — 新增 `packages/fushi_engine/lib/media/video/metadata/video_extra_markers.dart`：唯一一份文件名 / 标题级特典标记词表 `videoExtraMarkerKind`（ncop/nced/creditless/pv/cm → clip，trailer/予告 → trailer，teaser → teaser，menu/bonus/メニュー/特典 → extra，ノンクレジット → clip），拉丁词按字母数字边界匹配，不收 SP/OVA/Special/Extra 等宽词（BUG-1969）；明写「正片/本編/本篇」的标题不算特典（顺带修掉 `[正片+特典映像]` 打包发布被发布级判成「只有特典」）。`classifyLocalVideoExtra` 的文件名兜底与 `looksLikeExtrasOnlyRelease` 都改用它，下载整理器的文件级判据经 `classifyLocalVideoExtra` 一并生效。已入库的错误 book-owned work 由 `video_source_metadata_indexer.dart` 现有「唯一父作品 → 删 book-owned work 改挂 extras」路径在下一次索引时纠正。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/metadata/video_extra_markers_test.dart`：Menu/CM/NCED/OVA [PV]/Teaser/予告編/BDメニュー 文件名分类、宽词与「正片」不误伤、文件级与发布级同口径，以及「Menu / CM 与正片同目录时不进刮削计划、清掉历史 book-owned work、挂到父作品当 extra/clip」的索引测试。
- **备注**：特典单独放在没有正片的目录里时，`_candidatesByDirectory` 找不到唯一父作品，仍不会挂上（不会再单独刮削，但也不归属）；反馈里没有完整目录结构，未能确认用户是否有这种布局。
