## BUG-3671 · asr-unpunctuated-card-sentence-whole-paragraph
- **报告**：2026-10-23（用户：应用内反馈 fvrYPia3kW，Android 3.0.0「转文字有时转出来没有标点符号，导致生成卡片句子会变成全文」）
- **真实性**：✅ 真 bug。字幕合成书（独立 SRT 书 / 语音转录产物，`packages/fushi_audio/lib/src/matching/cues_to_epub.dart` `_groupParagraphs` + `_chapterXhtml`）把间隔 < 2 s 的相邻 cue 拼进同一个 `<p>`，每条 cue 一个 `<span data-cue-id>`。阅读器制卡取句 `fushiSelection.getSentenceContext`（`fushi/lib/src/reader/reader_selection_scripts.dart`）只在 `sentenceDelimiters`（`。！？.!?`）或块级祖先（`BLOCK_SELECTOR`，不含 `[data-cue-id]`）处停。听写稿没有句末标点时，游走一路走到 `<p>` 两端，`{sentence}` 变成整段（几十条 cue 的全文），按句裁的音频区间也随之变成整段。翻页 / 滚动 / 视觉小说三种模式共用这一个取句函数（VN 经 `sourceTextPosition` 回到源章节再取句），所以三种模式都中。
- **[x] ① 已修复** — `getSentenceContext` 向前 / 向后游走跨文本节点时，若相邻两条 cue（`[data-cue-id]`）**都**不含句末标点，就把它们之间的边界当句界（`cueSpanOf` / `hasSentenceDelimiter` / `isUnpunctuatedCueBoundary`）。cue 是转录器按停顿 / 时长（`AsrCueBuilder.gapSplitMs` / `maxCueMs`）切好的语音单元，没有标点时它是唯一可靠的句界；任一侧有标点（正常带标点的稿、被停顿切开的半句）照旧按标点取句，带标点的书行为不变。「上 N 句 / 下 N 句」上下文经同一函数，随之按 cue 步进。提交见本条所在提交（`Feedback: fvrYPia3kW` 系列）。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_get_sentence_context_boundary_test.js`（CASE 13：无标点三条 cue 的段落里取句只得当前 cue，偏移相对 cue；CASE 14：带标点、被停顿切成两条 cue 的一句话仍取整句），由 `fushi/test/reader/reader_get_sentence_context_boundary_test.dart` 驱动在 `flutter test` 里跑（执行真实的选区 JS）。
- **备注**：同一反馈的另两项（云端 Whisper 转录、LLM 校对）是功能，不在本条；LLM 校对会补标点，但本修复不依赖它——不开 AI 也不会再把整段当一句。
