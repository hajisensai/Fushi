## BUG-4390 · 经反向代理 / 内网穿透进来的公网配对请求被当成局域网免 PIN
- **曾用号**：PR 分支 `pr/interconnect-host-auth` 的提交信息把本条写作 BUG-4279（合入 develop 前的旧号；改号提交 `080b4a41c72`、`71ab2acf8c9`）。develop 上的 BUG-4279 是另一条无关的 bug，按提交信息搜号时以本文件为准。
- **报告**：2026-11-10（用户：互联 host 安全审查 H3）
- **真实性**：✅ 真 bug。`packages/fushi_engine/lib/sync/fushi_sync_server/pairing.part.dart:679-699`（94317ab6295）的 `_isLanPeerRequest` / `_remoteAddress` 只看 `shelf.io.connection_info` 的 TCP 对端，`FushiPairingProtocol.isPrivateLanAddress`（`fushi_pairing_protocol.dart:182-212`）把 127/8、::1 也当 LAN。经本机或局域网内的反代、frp、cloudflared 进来的公网请求因此被判成 LAN：无头端 `lan_requires_pin=false` 时 `_approvePairing`（`headless_host.dart:789-792`）零人工就发 token；app 审批框把公网陌生人显示成 127.0.0.1。修复前新测试实测：对端 127.0.0.1 带 `X-Forwarded-For`、对端 192.168.1.20 带 `X-Real-IP` / `Forwarded` / `CF-Connecting-IP` / `True-Client-IP` 时 `pair/v2` 都回 `pinRequired: false`；真 `HeadlessHost`（`lan_requires_pin: false`、`public_urls` 非空）从 127.0.0.1 发 `pair/v2` 同样 `pinRequired: false`。
- **[x] ① 已修复**（`ffc49be596a`）— 引擎：`fushi_pairing_protocol.dart` 新增 `FushiPairOriginClass { lan, p2p, public }`、`FushiAddressRangeSet`（IP / CIDR，v4 映射两侧还原）、`fushiRateKeyForAddress`（v4 → `ip:`，v6 按 /64 聚合 → `ip6:<前缀>/64`）；`pairing.part.dart` 把 `_remoteAddress` + `_isLanPeerRequest` 收成 `_RequestOrigin`（类别 / 展示串 / 来源键 / 来源键是否可信）与 `_classifyRequestOrigin`：P2P 区域恒 `p2p` 且不读转发头；带任一转发头恒 `public`；`loopbackPeerIsLan == false` 时回环对端 `public`；其余按私网判。`trustedProxiesProvider` 命中时只把转发头最后一跳用于展示（`<真实来源> (via <代理>)`）与来源键，不影响类别；未命中时带转发头的展示为 `<对端> (proxied)`。`_handlePair` / `_handlePairV2` / 票据会话统一读它，BUG-1555 的 v1 判据随之生效（经反代的 v1 → `upgrade_required`）。`FushiSyncServer` 新增 `loopbackPeerIsLan`（默认 true）与 `trustedProxiesProvider`。无头：`ServerConfig.trustedProxies`（YAML `trusted_proxies`，缺省 `[]`，加载时校验并点名非法条目，`toYaml` 往返），`HeadlessHost` 装配 `loopbackPeerIsLan = false` 与可信代理供给器，README 补该键。app：审批框来源是回环地址时在来源行下加一行 `sync_pair_source_loopback_hint`（`bodySmall` + `colorScheme.error`），不改按钮与默认动作。
- **[x] ② 已加自动化测试** — `fushi/test/sync/fushi_sync_server_request_origin_test.dart`（自建 `shelf.Request` + 假 `HttpConnectionInfo` 经 `handleInProcess`：五种转发头、回环 / 局域网 / 无对端、`loopbackPeerIsLan=false`（含 ::1、v4 映射回环）、可信代理 XFF / RFC 7239 `Forwarded`、对端不可信时不读头内容、P2P 区域不读转发头）、`fushi/test/sync/pairing/fushi_address_range_set_test.dart`、`fushi/test/sync/interconnect_pair_pin_per_session_test.dart` 的回环提醒用例（回环 / ::1 / proxied 回环显示提醒，局域网 / 隧道不显示；原 `interconnect_pair_loopback_hint_test.dart`，BUG-4392 并入）、`packages/fushi_server/test/server_config_trusted_proxies_test.dart`、`packages/fushi_server/test/headless_host_loopback_origin_test.dart`（升级场景：存量配置不加新键，回环来源要 PIN）。
- **备注**：线上契约 D / E / I。`lan_requires_pin=false` 的无头部署，同机客户端与经反代的局域网客户端改为要 PIN；只会 v1 的同机 / 经反代客户端拿到 `upgrade_required`。限速来源键本步只算出、尚未接入（`_pinRateLimitSourceKey` 仍按会话展示串分桶，由 BUG「PIN 防爆破」那一步替换）。`host_update.part.dart` 两处诊断日志原来调用被删的 `_remoteAddress`，改读 `_requestOrigin(request).display`。「`classifyInterconnectAddress` 与配对私网表不一致」不修（职责不同，见计划「不修」）。
