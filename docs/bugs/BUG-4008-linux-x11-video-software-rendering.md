## BUG-4008 · Linux X11（Steam 游戏模式）视频走 mpv 软件渲染、卡顿
- **报告**：2026-11-04（用户：Steam Deck 游戏模式播 Jellyfin 视频卡，桌面模式同一视频流畅）
- **真实性**：✅ 真 bug。游戏模式下 app 跑在 gamescope 的 Xwayland（X11）上，控制台日志 `media_kit: VideoOutput: EGL display or context is invalid.` → `S/W rendering.`，进程 120–150% CPU。根因 `third_party/media_kit_video/linux/video_output.cc` `video_output_new`：GPU 路径只在 GTK 线程**当前**有 EGL context 时才走。Flutter 3.47 Linux 嵌入层在 X11 上同样用 EGL（`fl_opengl_manager.cc` `EGL_PLATFORM_X11_EXT`），但 X11 下合成走 CPU 拷贝（`fl_view_renderer.cc` `shareable` 只对 Wayland 为真），平台线程从不 make current，于是 X11 永远落到 `MPV_RENDER_API_TYPE_SW`。Wayland（桌面模式）恰好由合成器把共享的 platform context 留在当前，才看起来正常。
- **[x] ① 已修复** — 当前没有 EGL context 时，用 GDK display 经 `eglGetPlatformDisplayEXT`（同平台 + 同原生 display 返回同一句柄）取 Flutter 的 EGLDisplay，并按 FlOpenGLManager 同款属性选 config，建隔离 GLES2 context，照旧经 EGLImage 与 raster context 共享纹理；用完若之前无当前 context 就释放自己的（原代码拿 `EGL_NO_DISPLAY` 去 restore 是 no-op，会把 mpv 的 context 留绑在 GTK 线程）。`texture_gl_dispose` 在 X11 无当前 context 时不能删 Flutter 侧纹理名，改为入队，下一次 populate 在 raster 线程删，不再每关一个视频漏一帧大小的显存。另外 X11 下 GTK 线程上可能还挂着 GDK 自己的 GLX context，libglvnd 一个线程同时只认一种窗口系统 API，`eglMakeCurrent` 因此报 `EGL_BAD_ACCESS`（Deck 实测 `Error: 0x3002`）；建 / 拆 mpv context 时先释放 GLX context、用完原样恢复。Wayland 路径不变。
- **[x] ② 已加自动化测试** — `fushi/test/build/media_kit_video_linux_x11_gpu_guard_test.dart`（插件无原生测试框架，守卫钉住 GDK 解析 display、GPU 路径不以当前 context 门控、释放自身 context、纹理名延后删除）。
- **备注**：真机验证 Steam Deck 游戏模式控制台出现 `H/W rendering with isolated EGL context`，见提交说明。
