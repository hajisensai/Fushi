## BUG-4387 · CatSystem2 cs2 2.6.1.90 查词与语音站点全部 unresolved
- **报告**：2026-11-11（用户：志愿者机 NOFJ 实测转述；cs2.exe FileVersion 2.6.1.90，x86，未加壳，2020 年作品，日文转区启动）
- **真实性**：✅ 真 bug。注入日志 `catsystem2-lookup: sites unresolved result=4`（kRecordInvalid）与 `catsystem2-voice: sites unresolved result=5`（kPlainBlockMissing）；用样本 exe 与主模块 dump 离线跑同一份解析器（`tools/catsystem2_site_probe.cpp`）复现出完全相同的两个 result 码。根因是这一版换了新 MSVC 且对象布局整体挪了位，而 targeted-render 证明把这些都写成了固定字节 / 固定偏移：
  - 查词 `hook/adapters/catsystem2_lookup_core.h` `ResolveTargetedRenderSites`：GetCharImage 参数块多压两个记录字段、字体字段 +0xa0/+0xac→+0xc0/+0xcc（固定字节签名失配 → result=4）；其后各环同样失配：渲染器页尺寸 +0x14/+0x18→+0x10/+0x14、渐显页 +0x40→+0x3c（ClearPage 体）、窗口 renderer +0x2ac→+0x2b0（Update / ClearPage 调用点）、窗口 screen +0x68→+0x6c（SyncLayer / 层查询）、Screen::QueryLayer `dec eax`→`sub eax,1`、Scene::Find 换寄存器、Scene::Draw 对齐由短跳改多字节 nop、Input::Handle 序言溢出顺序变化；且第二个窗口类与本窗口共用 Update 和 ClearPage 函数体（Update 签名不再唯一）。运行期还按固定常量读这些字段，站点即使找到也会读错。
  - 语音 `hook/adapters/catsystem2_voice_core.h` `MatchesPlainBlock`：归档对象的加密标志从 +0x11c 挪到 +0x220（对象前面多了一个 260 字节路径缓冲），证明里写死 `kArchiveEncryptedOffset == 0x11c` → result=5。
  - 正文道（EmbedCS2，宿主 lines=0）不在本仓解析代码里：它是 vendored LunaHook32.dll 的引擎钩子。按 LunaHook v10.16.1.2 源码对照样本：本版只导入 GetTextMetricsW、没有 GetTextMetricsA，`InsertCatSystemHook` 找不到站点，随后 `InsertCatSystem2Hook`（UTF-8 新引擎签名）命中，于是 EmbedCS2 以 UTF-8 模式挂上；本作需日文转区启动，正文更可能是 Shift_JIS，推断这条道因编码错配没有产出可用文本。这是推断，未在真机上确认。本条不修，另列待决策。
- **[x] ① 已修复** — 查词：GetCharImage 调用改按 RenderChar 自身寄存器读参数链（`HasVirtualCharImageCall`）；ClearPage 按函数体解析页尺寸 / 渐显页（`ParseClearPageT`），候选必须经 Update 证明的窗口 renderer 字段被调用，多个时取调用方也驱动 reveal 的那个（`FindClearPageT`）；Update 取 reveal 经 RenderChar 渲染的那一份；窗口 screen 字段取自 SyncLayer 并约束层查询；Screen::QueryLayer 两种 codegen、Scene::Find 两次加载、Scene::Draw 对齐通配、Input::Handle 读帧 + 消息加载 + 分发。证明出来的偏移存进 `Sites::layout`（`ObjectLayout`），`catsystem2_lookup.inc` 运行期改读它。语音：标志偏移只限定范围（dword，+0x80..+0x1000，运行期从不读它），并要求 SetFilePointer 之前加载的归档句柄（+0x10）与标志同一基址寄存器。
- **[x] ② 已加自动化测试** — `native/galgame_hook/tests/catsystem2_lookup_test.cpp`（2016 / 2020 两套 targeted-render 合成 codegen 全部解析并校验 layout；第二窗口类诱饵；每条证明单独打断都 fail closed，含 Update / ClearPage 歧义、窗口字段越界、页高 ≠ 页宽 + 4、screen 字段与层查询不一致、消息参数来源错）；`native/galgame_hook/tests/catsystem2_voice_test.cpp`（新增 cs2 2.6.1.90 codegen，标志偏移非 dword / 越界 / 句柄来自别的对象均 fail closed）；`native/galgame_hook/tests/adapter_structure_test.py` 结构守卫跟进。
- **备注**：样本离线验证见 PR。精灵字段、screen 设计尺寸只在运行期校验（不符即 fail closed）；本版记录还带一个逐字 UTF-16 标志（记录 +0x54 进栅格器的 unicode 参数），查词的 CP932 字形解码没读它，若本作消息窗走 UTF-16 则查词文本匹配会失败——要在宿主实跑时确认。真机 accept4 / 宿主复测未做，支持状态维持 `implemented_unverified`。
- **后续补充（RenderChar 尾声）**：同一版 cs2 2.6.1.90 是 VS2013 构建，RenderChar 的收尾（epilogue）在 +0x29e，而 `kRenderTailTOffset` 写死 0x298，偏差 6 字节导致查词站点解析仍返回 `kRecordInvalid`（result=4）。修复：RenderChar 尾声改为在画笔块（pen block）之后 0x400 字节范围内按结构定位，不再依赖固定偏移（`catsystem2_lookup_core.h`，测试 `catsystem2_lookup_test.cpp` 增加 VS2013 构建形状的合成 codegen）。状态仍为 `implemented_unverified`：只有离线结果，没有真机证据。
