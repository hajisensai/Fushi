## BUG-4352 · WebDAV / SFTP 同步后端没有区间读，云端旧名漫画包无法判型
- **报告**：2026-11-07（用户：开发者自提，应用内反馈 toPvLQcpex；BUG-4223 / PR #3042 遗留项）
- **真实性**：✅ 真缺口。列举时的旧名 `.epub` 漫画包判型只在 `plainAssetRangeReaderOf(backend)` 非 null 时启用（`fushi/lib/src/sync/cloud_remote_book_client.dart:55` → `_openLegacyMangaSniffer` :160），而 `SyncAssetRangeReader` 修复前只有 OneDrive / Dropbox / Google Drive 实现（`fushi/lib/src/sync/sync_asset_range_reader.dart:53-58` 注释与三个后端类声明）；`WebDavSyncBackend`（`fushi/lib/src/sync/webdav_sync_backend.dart:17`）、`SftpSyncBackend`（`fushi/lib/src/sync/sftp_sync_backend.dart:23`）没实现，于是这两种后端上无人持有的旧名漫画包永远留在书籍书架。SFTP 另有一层：`listChildren` 不给 `AssetEntry.revision`（契约如此），判型器 `CloudLegacyMangaSniffer.kindOf` 见 `revision == null` 直接不判（`fushi/lib/src/sync/cloud_legacy_manga_sniffer.dart:87-88`），即便有区间读也不会判；WebDAV `listChildren` 没把 PROPFIND 已解析的 `getcontentlength` 填进 `sizeBytes`，首读只能先读 1 字节拿总长。
- **[x] ① 已修复** — `WebDavOps.openRange`（`GET` + `Range` + `Accept-Encoding: identity`；206 按 `Content-Range` 交段；200 对部分区间请求立刻取消响应体并抛新增的 `SyncAssetRangeUnsupported`，不整包下载；416 → `SyncAssetRangeNotSatisfiable`）；`WebDavSyncBackend` / `SftpSyncBackend` 实现 `SyncAssetRangeReader`；SFTP 按偏移读抽成 `openSftpFileRange`（`fushi/lib/src/sync/sftp_range_read.dart`），来源库 `NetworkSourceFileSystem.openSftpRange` 改用同一份实现；`SftpSyncBackend._guarded` 让 `SyncAssetRangeNotSatisfiable` 原样穿过（不是传输故障）。判型器：缓存校验值 `cacheValidatorOf` = `revision`，没有时退用「服务器修改时间 + 大小」（SFTP）；遇 `SyncAssetRangeUnsupported` 本次列举停止判型、记日志、不入缓存。WebDAV `listChildren` 填 `sizeBytes`。提交见 git log（`Feedback: toPvLQcpex`）。
- **[x] ② 已加自动化测试** — `fushi/test/sync/webdav_range_read_test.dart`（回环 HttpServer：206 / 200 部分区间不支持且未读完整文件 / 200 整文件请求 / 416 / 206 缺 Content-Range）、`fushi/test/sync/sftp_range_read_test.dart`（假 SftpClient：区间、截尾、越界、句柄懒开即关、后端经 `_guarded` 读与越界穿透）、`fushi/test/sync/cloud_legacy_manga_sniffer_test.dart` 新增「server that ignores Range」「SFTP assets keyed by mtime + size」两条。测试未在本分支运行，统一在合并后验证。
