## BUG-2736 · Miruro 视频源详情/剧集/取流全 403：扩展宿主钉死 HTTP/1.1 被 Cloudflare WAF 拦
- **报告**：2026-09-27（用户：「miruro 这个 aniyomi 打开 403」）
- **真实性**：✅ 真 bug。桌面 sidecar 直驱真实 APK（`aniyomi-en.miruro-v14.11`）复现：热门列表正常（扩展在 pipe 403 后回落 AniList，掩盖了问题），`getAnimeDetails` / `getEpisodeList` 均 `HttpException: HTTP error 403`；sidecar 日志显示首页 `GET /` 200，而**每一条** `/api/secure/pipe?e=…` 都是 Cloudflare「Attention Required / you have been blocked」WAF 拦截页。变量隔离（同一 Python TLS 栈、同一套扩展 `MiruroBrowserFingerprintInterceptor` 发的 Chrome 头，各重复 3 次）：HTTP/1.1 → 403，HTTP/2 → 200 且带 `x-obfuscated: 2`（真实 API 响应）。站点 WAF 规则按 HTTP 版本拦。根因：两端扩展宿主把 OkHttp 钉死在 HTTP/1.1——`third_party/m_extension_server/overlay/server/src/main/kotlin/mextensionserver/impl/HostProxyPolicy.kt`（`configureClient` 的 `.protocols(listOf(Protocol.HTTP_1_1))`）与 `fushi/android/app/src/main/kotlin/app/fushi/reader/mihon/HostProxyPolicy.kt` 同一行。Aniyomi / Mangayomi 宿主都不钉协议，这是本仓独有的收紧（为代理策略切换后的路由确定性，见 `fushi/lib/src/utils/net/DESIGN.md`）。
- **[x] ① 已修复** — 两端 `configureClient` 去掉 HTTP/1.1 钉死，ALPN 可协商 HTTP/2；路由确定性从「连接级」挪到「交换级」守：既有网络拦截器对每次交换用该连接 Address 自己的 ProxySelector 复核路由（`routeAllowedByCurrentPolicy`，显式 `.proxy()` 的客户端不归策略管），不符则该连接 `noNewExchanges()` 并抛 `StaleProxyRouteException`（`ProtocolException` 子类——OkHttp 判不可恢复，不会走 `retryRoute` 沿被拒的旧路由重连）。零空闲连接池保留。另：Android `NetworkHelper`（`fushi/android/app/src/main/kotlin/eu/kanade/tachiyomi/network/NetworkHelper.kt`）此前没装 `BrotliInterceptor`（桌面有，`okhttp-brotli` 依赖早已声明却未用）；扩展在自己的网络拦截器里把 `Accept-Encoding` 改成含 `br`，OkHttp 的 BridgeInterceptor 只解 gzip，过了 WAF 也只会把原始 brotli 字节交给扩展当 JSON 解析。已按桌面同位置补上。
- **[x] ② 已加自动化测试** — 源码守卫 `fushi/test/media/manga/mihon_host_network_abi_guard_test.dart` 新增一条：两端都不许钉 HTTP/1.1、都有逐次交换复核、两端 `NetworkHelper` 都装 `BrotliInterceptor`。两端 `HostProxyPolicyTest`：`exchangeRefusesARouteThePolicyNoLongerAllows`（建连后策略变更 → 交换被拒、源站零命中、selector 只被问两次即无重试、之后客户端照常可用）、`http2StaysNegotiableForWafProtectedSources`；`newRequestsFollowChangedPolicyWhilePreviousResponseIsActive` 计数随逐次复核 3 → 6。Android 那份测试原先 import `com.sun.net.httpserver.HttpServer`，Android 单测编译 classpath（android.jar）没有 `jdk.httpserver`，整个测试源集从来编译不过；已在测试源集补同包同名的最小替身 `HttpServer.kt`。现 `:app:testDebugUnitTest --tests …HostProxyPolicyTest` 8 过 7，唯一失败 `authenticatedLoopbackLookupReadsUpdatedPolicyForEachUrl` 是既有的 `org.json.JSONObject not mocked`（需加 `org.json` 测试依赖，未在本 bug 内处理）。
- **备注**：代价是每次交换多一次本机回环策略查询，与 HTTP/2 复用连接省下的建连查询大致抵消。修复后桌面 sidecar 真 APK 复测：热门 20 条、详情、12 集剧集全部 200。**取流仍失败（HTTP 444），但那是扩展侧**：`sources` pipe 回的是站点自己的「502 upstream unreachable」页；真 Chrome 打开同一观看页 `sources` 为 200，逐项 A/B（同一 HTTP/2 客户端，cookie 有无均试）只有载荷里的 `category` 决定结果——站点现在用 `ssub`，扩展 v14.11 发 `sub` → 444。宿主不改写扩展请求；上游已有同症状 issue yuzono/anime-extensions#701（Error 503 & Error 444 (Videos)，open）。Android 端未在真机/模拟器上跑扩展全链路，只过了单测与守卫。
