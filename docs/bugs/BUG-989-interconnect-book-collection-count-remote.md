## BUG-989 · 互联书籍合集行计数未计入远端占位书
- **报告**：2026-07-22（用户：Mac 客户端连 Win 服务端互联，书籍合集显示的数量没计入远端书籍）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/pages/implementations/reader_hibiki_history_page.dart:1127`（修前）——书架合集横排行 `_buildShelfCollectionRow` 的行头计数用 `localCount`，`.where((it) => it.payload.remote == null && it.payload.remoteSrt == null)` 专门把折进本合集的远端占位卡（EPUB `remote` / 纯 SRT `remoteSrt`）过滤掉；而行体 `itemCount: group.items.length` 却渲染全部。于是合集有 N 本地 + M 远端时，行头显示 N，卡片排 N+M；全为未下载远端书的合集直接显示「0 items」却排着占位卡，与所见割裂。视频侧同款问题早在 [[BUG-790]]（`home_video_page.dart:1999` `memberCount = group.items.length`）已修，书架合集此前漏跟。
- **[x] ① 已修复** — `reader_hibiki_history_page.dart` 把 `localCount`（排除远端）改为 `memberCount = group.items.length`（含远端占位，与 `itemCount` 同源），`countLabel: t.series_item_count(n: memberCount)`。对齐 BUG-790 的「行头数字诚实反映看得见的卡片数」口径。远端占位与本地成员已由 `dedupeRemoteBooks`（同 bookKey 去重）保证不重复，计入不会双数。提交：见本轮提交哈希。
- **[x] ② 已加自动化测试** — `hibiki/test/pages/reader_remote_collection_membership_test.dart` 新增用例「合集行计数计入折进来的远端占位卡（旧口径只数本地成员显示 0）」：空本地合集 + 1 本 host 下发折进该合集的远端占位书 → 断言行头 `find.text('1 items') findsOneWidget` 且 `'0 items' findsNothing`。修前 `localCount=0` 会渲染「0 items」→ 用例失败；修后通过。三用例全绿。
- **备注**：原始用户报告还含「互联没下载有声书」——经排查系版本 skew：互联下载有声书包（`_downloadRemoteAudiobook`，commit `b76345790`，2026-06-23）与互联合集同步（commit `4fe62a4e6`，2026-07-12）都较新；Mac 客户端较旧则缺这些客户端接线。对 EPUB 绑定 SRT 有声书，当前 develop 下载书卡会自动带音频，合集经一次完整「立即同步」sweep 物化本地后即成组。此项为操作层（更新 Mac + 跑一次全量同步），非代码 bug，不在本 fix 范围。
