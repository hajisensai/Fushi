## BUG-3746 · Fushi SRS 的 AnkiConnect 兼容层每个请求都整库处理，大库下加卡 / 查重 / 搜索秒级
- **报告**：2026-10-23（2026-10-23 审计 srs_followup_tasks C / HBK-AUDIT-017）
- **真实性**：✅ 真 bug。基准 `packages/fushi_engine/test/srs/ankiconnect/srs_ankiconnect_large_library_bench_test.dart`（2 万笔记 / 4 万卡，后台 isolate 文件库）修前实测：`addNotes` 20 条 30.4 s、写后第一次 `canAddNotes` 1.8 s、热 `canAddNotes` / `findNotes` 0.5 s、`cardsInfo` 100 张 1.3 s、`notesInfo` 3 个未知 id 1.7 s。根因（修前行号）：
  - `packages/fushi_engine/lib/srs/ankiconnect/srs_ankiconnect_handler.dart:629` `_snapshot()` 每请求 `allCardRows()` 整表读 + 笔记类型 + 牌组树；`:606` `_liveNotes` 笔记缓存一变就 `allNoteViews()` 整库重物化。
  - `:409` `addNotes` 循环里每条都 `_snapshot()` 再 `createNote`（每条一个事务），N 条 × 整库 = O(N×M)。
  - `:734` `_matchCards` 每请求重建原生搜索语料、用完即释放。
  - `:1013` `_dupeOrEmpty` 每个候选扫全集合比首字段。
  - `:1476` `_cardsInfo` 逐张 `cardIdForAnkiNumericId` + `cardRow` + `renderCard`（又各读一遍卡 / 笔记 / 类型 / 牌组树），N+1。
  - `packages/fushi_engine/lib/srs/srs_db_store.dart:4569` `noteIdForAnkiNumericId` / `cardIdForAnkiNumericId` 未命中就整表重建数字索引（未知 id、新加的卡每次都触发）。
- **[x] ① 已修复** —
  - store：缓存行唯一写入口 `_writeCache` 同一事务里记**缓存变更日志**（`cacheGeneration` / `cacheChangesSince`）并把新行登记进**数字 ID 索引**；索引首次查询时在独占区里整表回填，之后未命中即 null。`rebuildCaches`、事务回滚（`_transactionOrReload`）、`reloadLocal` 把日志与索引一起作废（下次整份重读 / 重新回填）。导入、同步、编辑、复习、更改笔记类型都经 `_writeCache`，映射随之维护。新增成批查找 `noteIdsForAnkiNumericIds` / `cardIdsForAnkiNumericIds`；`renderCard` 可直接收已读好的 `SrsCardDetail`。
  - handler：跨请求**常驻视图**（未删笔记、可见卡、查重规范形倒排索引、原生搜索语料、查询记忆）。按 `changeFingerprint`（笔记类型 / 牌组 / 设置）+ 缓存变更日志增量刷新，只重读变了的笔记与卡；笔记类型签名（名字 / 字段 / 模板）或牌组全名变了、日界变了、到了最早一张学习卡的到期翻转时刻或次日日界，搜索语料整份作废。变过的笔记进小的增量语料、基底里屏蔽，攒到集合的 1/10 再整份重建基底。`addNotes` 整批：一次快照、一次规范化、批内重复按逐条语义判、一个 `importDrafts` 事务落库。`cardsInfo` / `notesInfo` / `cardsToNotes` / `areSuspended` / `suspend` 成批映射 id。
- **修前 → 修后**（同一基准，2 万笔记 / 4 万卡，端到端含 FFI、拷贝与数据库往返）：`addNotes` 20 条 30407 → 47 ms；`addNote` 546 → 20 ms；写后第一次 `canAddNotes` 1782 → 6 ms、`findNotes` 466 → 5 ms；热 `canAddNotes` 440–523 → 0–1 ms；`findNotes` 首次 557 → 118 ms、重复 532 → 3 ms；`findCards tag:bench` 1658 → 46 ms；`cardsInfo` 100 张 1303 → 541 ms（大头是首次查 id 时整表回填数字索引，之后不再发生）；`notesInfo` 3 个未知 id 1727 → 0 ms；冷启动第一次请求 1820 → 1694 ms（整份读一次，无法避免）。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/ankiconnect/srs_ankiconnect_resident_test.dart`（常驻 handler vs 每次新建的 handler，在标签 / 首字段 / 暂停 / 牌组改名 / 删除 / 模板改名 / 复习改状态与到期 / 学习卡与埋卡随时间翻转 / 整体重建缓存 / 在 handler 之外建笔记之后逐请求比对；addNotes 批内重复语义；未知 id 零查询；大库热请求读行数与 addNotes 事务数上限）；基准见上。
