## BUG-1069 · 视频顶部字幕盖住标题栏和菜单UI
- **报告**：2026-07-25（用户：把 UI 图层放字幕上面，字幕把 ui 挡住了；顶部标题栏 + 右上角菜单被字幕遮）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/media/video/video_subtitle_overlay.dart:2211` `_paddingFor` 的顶部锚点分支只用 `scaledMarginV ?? bottomPadding` 作顶距，**无控制条避让**；而底部锚点分支（2202-2208）控制条可见时对 `controlsBottomReserve` 取下限避让进度条。视频内嵌顶栏（标题栏 + 右上角菜单，替代被删的 AppBar，BUG-102）由 media_kit 在 `AdaptiveVideoControls` 内渲染（layout.part.dart Stack index 0），字幕层 `VideoSubtitleOverlay`（index 4）排在其后 → 顶部锚字幕（含强制置顶的副字幕，overlay 1105 `forceTop`）画在顶栏之上、把 UI 盖住。字幕在控制层之上是**故意**的（点字幕查词 hit-test，BUG-198/553/838），故不能整层调换 z-order。
- **[x] ① 已修复** — 加对称的 `controlsTopReserve`（默认 `kVideoControlsTopReserve`）：`_paddingFor` 顶部锚点分支在 `controlsVisible` 时对其取下限（`max(用户顶距, controlsTopReserve)`，与底部同为取下限非加法）→ 控制条可见时顶部字幕整体下移到顶栏下方、UI 赢重叠，隐藏时落回用户基线。复用 overlay 既有 `controlsVisible` ValueListenable + `AnimatedPadding`，不动 z-order、不碰查词 hit-test、不改 media_kit 顶栏（无桌面 hover-keep-alive 副作用）。页面按真实几何算 `_subtitleControlsTopReserve()`（顶部系统 inset + 按钮行高 + 呼吸间距），纯函数 `videoSubtitleControlsTopReserve` 收敛。提交见本轮。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_subtitle_top_reserve_test.dart`：① 纯函数几何；② overlay 真行为——副字幕（强制置顶）顶部 padding 在控制条可见时 = controlsTopReserve、隐藏时落回 bottomPadding 基线。
- **备注**：只处理顶部（用户报的标题栏/菜单）。底部锚字幕 vs 底栏本就有 `controlsBottomReserve` 避让。**需真机目视复测**（reader/播放/layout 类改动，见 CLAUDE.md 验证纪律）：控制条显隐时顶部字幕上下避让、不再压标题栏/菜单，点字幕查词不受影响。
