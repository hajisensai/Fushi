## BUG-2921 · 游戏内查词卡嵌套查词时根卡跳位、子卡标题被裁
- **报告**：2026-10-03（用户：录屏 CLANNAD，在游戏内查词卡里再点「へたへた」查词）
- **真实性**：✅ 真 bug。录屏逐帧：点子词后根卡先整体上移约 200 物理 px（不再贴着台词）持续约 4 帧，随后子卡出现在客户区顶部、盖住根卡标题栏，子卡自己的标题栏（词头 + 按钮）在淡入结束后被视口顶边切掉。两层根因叠加：
  1. 原生直连路径把**整个 union**（根卡 + 子卡）当一张卡贴字形：`fushi/windows/runner/global_lookup_window.cpp:1779`（`ResizeStackForGal`）与 `:2646`（`RevealOverProcessClient`，嵌套后每次 captureReady 都会重投）都用 `GlyphAnchoredCardOrigin(..., screen_width, screen_height)`，宽高是 union 的。子卡一出现 union 变高变宽，「上方放得下」不再成立就整体翻到字形下方再被客户区夹回，水平也改按 union 中心对齐——根卡跳位。
  2. Dart 侧子卡布局域是**画布**：`fushi/lib/src/lookup/gal_ingame_lookup_controller.dart:1218` 把画布尺寸与画布里的根卡原点交给级联布局，而直连卡片是屏幕物理 px 的真窗口、根卡由 runner 在客户区里按字形居中零间隙放置。放大/缩小运行的游戏里两域对不上，子卡按画布算出的「上方空间」与真实画面不符，落到屏幕上越出客户区顶边。
- **[x] ① 已修复** — runner 侧：`gal_direct_card_geometry.h` 新增 `PlaceDirectUnionAroundRoot`（根卡按自己的宽高贴字形并夹进客户区，union = 根卡位置 + bbox 偏移再整体夹取）；本次查词首次直连上屏时钉住根卡在 window-local 的位置与宽度，根卡实测高度随 `revealStack` 的新参数 `rootHeight` 更新（长高时仍贴字形那条边）；present 回执新增 `rootClientX/rootClientY`。Dart 侧：`GlobalLookupController.adoptGalDirectLayoutViewport` 在直连上屏后把嵌套布局域切到真实客户区、以 runner 放下的根卡为原点；galCard 的布局根卡不再做工作区夹取（`clampRootShellToWorkArea: false`），保证 runner 的根卡/bbox 关系成立。
- **[x] ② 已加自动化测试** — `fushi/windows/runner/tests/gal_direct_card_geometry_test.cpp`（录屏同形几何：子卡上方/左侧长出时根卡逐像素不动、union 顶边留在客户区、根卡长高仍贴字形、贴边时复用同一个被夹过的根卡位置，并记录旧算法让根卡从 350 跳到 600）；`fushi/test/lookup/gal_ingame_lookup_contract_test.dart`「直连 present 切换嵌套布局域」（回执带回根卡客户区位置后级联布局域 = 客户区/dpr）；`fushi/test/lookup/global_lookup_shell_region_guard_test.dart` 钉住 present / 嵌套 resize 都走 `PlaceDirectUnionAroundRoot`、不再拿 union 尺寸调 `GlyphAnchoredCardOrigin`。
- **备注**：runner C++ 已在本机 `msbuild /t:ClCompile` 全量编过、几何单测本机 cl 编译运行通过；**未在真游戏里复测**（本机用户正在使用、未起 CLANNAD 真机装置），状态按 galgame 规则记为 `implemented_unverified`，需在用户原始路径（CLANNAD 游戏内卡 → 卡内点词）复验。
