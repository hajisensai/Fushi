## BUG-615 · 导航跨章跳转首次只到章节需跳两次（TODO-1309 ②）
- **报告**：2026-07-08（用户：搜索/书签/收藏/字符跳转到别的章节的具体位置时，第一次点只落到目标**章首**，要再点一次（此时目标章已是当前章）才滚到精确位置）。TODO-1309 前次 API 中断重派。
- **真实性**：✅ **真 bug（沿真实恢复代码路径定位）**。跨章「精确跳转」是两段式：先 `_navigateToChapterAndWait` 落章首（`_beginNavigation` progress 0）→ 调用方在 `await` 返回后（restore 完成微任务里）再做章内定位（`scrollToSearchMatch` / `restoreProgress(fraction)`）。首跳那步章内定位被冲掉，只有目标章已是当前章（第二次点）走「同章直接 restore」（章节已 settle）才生效：
  - **根因①（连续模式·主因）**：`_onRestoreComplete`（`hibiki/lib/src/pages/implementations/reader_hibiki/navigation.part.dart`）里 `_restoreCompleter.complete(true)`（原 :88）在 `_reanchorContinuousAfterRestore()`（原 :150）**之前**就让调用方 `await` 恢复。调用方随后抢发的章内定位，与 TODO-718 恢复重锚竞态：重锚 `begin` 采样的是**章首**位置（在调用方定位之前入队求值），`commit` 把视口滚回**章首**采样点 → 精确定位被冲回章首（`hibiki/lib/src/pages/implementations/reader_hibiki/chrome.part.dart` `_reanchorContinuousAfterRestore`）。
  - **根因②（搜索早退）**：`chrome.part.dart` `onSearchJump` 首跳返 `!ok`（`_navigateToChapterAndWait` 10s 超时 / stale generation，`navigation.part.dart` `_navigateToChapterAndWait`）时 `if (!ok) return` 跳过章内定位、停在章首。
  - **根因③（字符跳转）**：`navigation.part.dart` `_jumpToGlobalCharOffset` 跨章分支 fire-and-forget `_navigateToChapter(progress:)`，只依赖烘进 shell 的 initialProgress（连续 settle-reflow 期竞态同①）。
