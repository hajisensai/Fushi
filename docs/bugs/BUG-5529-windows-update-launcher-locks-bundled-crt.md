## BUG-5529 · Windows 应用内更新卡在「Update did not finish」：msvcp140.dll 被 update launcher 占着换不掉
- **报告**：2026-11-26（用户转来的截图：原先「Windows 上打不开 Fushi」的那位用户，更新到 3.4.0 时弹「Update did not finish」——`The installer could not replace ...\AppData\Local\Fushi\msvcp140.dll ... (DeleteFile code 5)`，Fushi 已在拉起安装器之前退出、Update launcher PID 12648）
- **真实性**：✅ 真 bug。持有 `{app}\msvcp140.dll` 的是 `fushi_update_launcher.exe`：它用 `windows/runner/CMakeLists.txt` 里 Flutter 默认的 /MD 编译，`update_launcher.cpp` 用了 `<string>` / `<vector>`，导入 `MSVCP140.dll` / `VCRUNTIME140.dll` / `VCRUNTIME140_1.dll`（本机 dumpbin 实测）。安装器为了 BUG-1708 / BUG-1786 **刻意不杀** launcher（`fushi/windows/installer/process_control.iss` `KillProcessesUnderDir` 放过 `fushi_update_launcher*`）。这位用户的机器没装 VC++ 运行库（正是 TODO-1242 给 `{app}` 随包带 CRT 的原因，也是他之前打不开的原因），launcher 在 System32 找不到 CRT，按 DLL 搜索顺序落到继承自 fushi.exe 的当前目录（快捷方式起的就是安装目录）或安装目录本身（回退到原地 launcher 时），把随包的 `msvcp140.dll` 映射进去；`msvcp140.dll` 恰是字母序第一个 CRT 文件，复制到它时 DeleteFile code 5 → `/SUPPRESSMSGBOXES` 默认 Abort → 整包回滚。
- **[x] ① 已修复** — 两层：
  1. 根因层：launcher 挪到 `fushi/windows/update_launcher/CMakeLists.txt`，在目录作用域把 `CMAKE_{C,CXX}_FLAGS_*` 的 `/MD` 换成 `/MT`（CMake 下限 3.14、CMP0091 为 OLD，只能按目录改；留在 runner/ 会连 fushi.exe 一起改）。产物 dumpbin 只剩 KERNEL32 / USER32 / SHELL32 / bcrypt，不论从 updates 下的副本还是安装目录启动都不再映射 `{app}` 里的任何 DLL。
  2. 存量救援层（新安装器由旧 launcher 拉起时生效）：`fushi.iss` `PrepareToInstall` 在清场之后调 `MakeWayForLockedRootDlls`，把安装目录**根**下仍被占用（只剩杀不得的外部持有者：旧 /MD launcher、经 COM 加载缩略图处理器的 explorer）的 `*.dll` 同卷改名成 `*.dll.<时间>.old`，Inno 正常写新文件；安装没走到 ssPostInstall（回滚 / 中止 / 取消）时 `DeinitializeSetup` → `RestoreSetAsideDllsIfInstallFailed` 把原件改回去（回滚会删掉新建的文件，不放回 app 就缺 CRT）。残留在 ssPostInstall 与卸载时清（统一成 `FushiDeleteSetAsideDlls`，原先只清缩略图处理器的）。`voice_hook\` 不在扫描范围，被占用照旧中止（BUG-1675）。
- **[x] ② 已加自动化测试** — `fushi/test/build/update_launcher_static_crt_guard_test.dart`：launcher 在独立目录、/MD→/MT 覆盖 Debug/Profile/Release、runner 里不再定义它；`PrepareToInstall` 在清场后让路、ssPostInstall 置完成标志、`DeinitializeSetup` 调放回、装完 / 卸载清残留。
- **备注**：本机实测（2026-11-26）：① 探针 CMake 构建出的 Release launcher dumpbin 无 CRT 依赖，同源码 /MD 编译则导入 MSVCP140 / VCRUNTIME140(_1)；② 用 ISCC 6.7 把 fushi.iss 里的这几个过程原样抽进独立 AppId 的探针安装器，外部进程 `LoadLibraryEx` 映射 `{app}` 下的 DLL：正常路径改名让路后安装成功；人为让后续文件写失败触发回滚后，原件被放回原路径。完整 fushi.iss 经 ISCC 编译通过。未在该用户机器上复测（需要用户装上带本修复的版本后再走一次应用内更新）。该用户这一次可以手动关掉 Fushi 后直接运行 `%APPDATA%\Fushi\Fushi\updates\fushi-3.4.0-windows-setup.exe` 完成更新（launcher 已退出就不再占用）。
