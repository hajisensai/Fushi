## BUG-3611 · 互联子端「继续观看」远端视频不按合集归并、看完的集仍在
- **报告**：2026-10-19（用户：群反馈 nnqcwumWV-，Android，手机经互联连电脑 host 看 けいおん!）
- **真实性**：✅ 真 bug。截图里「继续观看」行是 4 张带云角标、副标题「信息」（`t.remote_video_info`，即 `_buildContinueRemoteCard`）的单集卡（主役!／部室がない!／先輩!／マラソン大会!），同屏「下一集」行却已把同一合集折成一张「けいおん! 40 集」卡——说明合集归属在客户端是解析得到的，只是「继续观看」没用。根因 `fushi/lib/src/pages/implementations/home_video_page.dart` 的 `_buildContinueRow`（修前 4815 行附近）：本地行按 `_primaryCollectionByEntry` 分组后走 `continueWatchingSeriesIndex`（Next-Up：最近播放那集没看完停在它、看完落下一集、整部看完不进行），远端占位却在单独一个循环里**逐条平铺、唯一判据是 `positionMs > 0`**——既不分组，也不看 `completedAt` / 片尾区。互联子端看过的每一集都会把断点回写给 host（看完的集断点停在片尾附近、仍 > 0），于是看过的每一集（含早已看完的）各占一张卡。两个现象（没合并 + 看完的还在）是同一处根因。「下一集」「已更新未看」两行早已改成本地行 + 远端占位合成一条集序（`_VideoSlot`），唯独「继续观看」没跟上。
- **[x] ① 已修复** — `_buildContinueRow` 改用与「下一集」行同一套 `_VideoSlot` 分组（本地行 + 远端占位按主合集归属合成一条稳定集序 → `_slotPlaybackStates` → `continueWatchingSeriesIndex`），一部合集只出一张卡、落在 Next-Up 那一集；不在合集里的远端散片按与本地散片同口径过滤（`CollectionMemberProgress.isFinished`：打勾或进度到片尾区不进行）。`_buildContinueCollectionCard` 改收 `_VideoSlot`，目标集只在 host 上时点卡走远端流播、带云角标；本地成员行为不变。删除不再使用的 `_seriesPlaybackStates`（本地合集排序时刻改用 `_slotWatchedAtMs`，即 BUG-1731 的 max(统计行, lastPlayedAt) 口径，与「下一集」行一致）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/home_video_home_rows_remote_test.dart`「「继续观看」把同一合集的远端成员折成一张合集卡，看完的集不单独出现」：4 集远端合集（1 打勾、2 片尾区、3 看到一半最近、4 未看）+ 两条远端散片（一条片尾区、一条看一半），断言只有一张合集卡、无逐集远端卡、副标题「看到第 3 集」、看完的散片不进行、看一半的散片照常进行。
- **备注**：待真机复测（本批不用真机）。远端合集卡的副标题只给「看到第 N 集」，不显示剩余分钟（远端没有本地 runtime 刮削表，保守不造）。
