## BUG-2715 · 日志面板内容变化或视口变高后长按空白处选区端点空断言崩溃
- **报告**：2026-09-26（用户：Android 手机触屏，错误日志里的 `FlutterError: while handling a gesture` / `Null check operator used on a null value`，栈 `_ScrollableSelectionContainerDelegate._updateDragLocationsFromGeometries (scrollable.dart:1361)` ← `handleSelectWord (scrollable.dart:1389)` ← `MultiSelectableSelectionContainerDelegate.dispatchSelectionEvent` ← `StaticSelectionContainerDelegate.handleSelectWord` ← `SelectableRegionState._selectWordAt (selectable_region.dart:1525)` ← `_handleTouchLongPressStart (selectable_region.dart:1003)`）
- **真实性**：✅ 真 bug，BUG-1582 的同族遗漏来源。
  - 触发面：全 `fushi/lib` 只有两处 `SelectionArea` 套 `Scrollable`——`FushiLogPanel`（`fushi/lib/src/utils/components/fushi_material_components.dart`，错误日志页 / 调试日志页共用，`SelectionArea` 套懒加载 `ListView.builder`）与 `video_discovery_detail_page.dart:228`（套全 `SliverToBoxAdapter` 的 `CustomScrollView`，懒加载横条已 `SelectionContainer.disabled`）。栈里的 `_ScrollableSelectionContainerDelegate` 只在这种结构下存在；用户当时停在错误日志页，且该页是唯一「行集合会在选区存在时被换掉」的面。
  - 框架不变式（Flutter 3.44）：`scrollable.dart:1386-1390` `handleSelectWord` **无条件**调 `_updateDragLocationsFromGeometries()`，后者 `scrollable.dart:1344-1346 / 1359-1361` 假定 `currentSelectionStart/EndIndex` 指向的 Selectable 仍持有选区，直接 `startSelectionPoint!` / `endSelectionPoint!`（debug 下先撞 `assert(geometry.hasSelection)`，release 直接 Null check）。
  - 下标怎么变陈旧：`selectable_region.dart:2513-2522` `_removeSelectable` 移除端点所在片段时只把下标减一，于是指向一个没有选区的邻居片段；`selectable_region.dart:2957-3015` `_handleSelectBoundary` 长按到命不中任何 Selectable 的位置（错误日志每条都有的空行——`paragraph.dart:504-526` 空文本不注册片段；行尾空白；列表内边距）时不改下标就返回 → 读陈旧下标崩溃。
  - 端点片段被移除的来源有三个，BUG-1582 只收口了第①个：① 用户滚动回收端点行（BUG-1582 已清选区）；② **日志内容变化**：`error_log_page.dart:39-44` / `debug_log_page.dart` 监听日志服务，新条目插在最前（`error_log_service.dart:496` `_entries.reversed`），整段重拼 → `FushiLogPanel.didUpdateWidget` 换 `_lines` → 行 Text 内容变 → `paragraph.dart:432-440` 走 layout 分支 remove 旧片段；③ **视口变高度**（转屏 / 分屏 / 键盘）：视口变矮，端点行落出 cacheExtent 被回收（此时连外层 `StaticSelectionContainerDelegate._updateLastSelectionEdgeLocationsFromGeometries`（`selectable_region.dart:2174`）也会空断言）。
  - 复现：widget test 真触屏长按（`startGesture(kind: touch)` + `kLongPressTimeout`）——「长按选中 → 日志内容被换 → 长按空白处」撞 `scrollable.dart:1345` 断言；「竖屏底部选中 → 视口变矮 → 长按空白处」撞 Null check。
- **[x] ① 已修复** — `fushi/lib/src/utils/components/fushi_material_components.dart`：选区状态与渲染快照同步——行集合被非滚动原因换掉时清选区。`didUpdateWidget` 里若 `logUpdateReplacesRows(old, new)`（某个非空既有行被改写或消失）就在换行**之前**清选区（旧片段仍在 registrar 里，清得干净）；新增 `NotificationListener<ScrollMetricsNotification>`，视口主轴尺寸变化时清选区。纯尾部追加不换既有行、不清选区，保留 TODO-1380「日志流追加期间菜单保持打开」。未改 SDK、未吞异常。提交：496727ceb83
- **[x] ② 已加自动化测试** — `fushi/test/widgets/log_panel_longpress_no_selection_crash_test.dart` 的 `BUG-2715 selection longpress null crash` 组：`logUpdateReplacesRows` 纯函数判据；「日志内容变化后长按空白处不崩」（并断言内容变化后选区被清、之后长按仍能重新选中）；「视口变矮回收端点行后长按空白处不崩」。两个 widget 用例在修复前均失败（断言 / Null check），修复后全绿。
- **备注**：
  - 为何不把 `SelectionArea` 挪进滚动视图（逐行 / 逐块）：那会失去跨行拖选与 TODO-934 恢复的「拖到边区自动滚动延伸选区」，是用户点名要过的能力；框架不变式只要求「端点片段不在持有选区时被移除」，按来源在状态层收口即可。
  - 残余风险：`video_discovery_detail_page.dart:228` 同为 `SelectionArea` 套 `CustomScrollView`；详情 `FutureBuilder` 完成时若选中的文字恰被改写，理论上同族。未复现、本次未改。
