## BUG-3668 · interconnect-auto-sync-default-off
- **报告**：2026-10-23（用户：反馈 5nWEirdCs2「Fushi 互联已开启，但是没有自动同步看过的数据，在手机上能通过互联打开视频」，Android 3.0.0-debug.20464）
- **真实性**：✅ 真缺陷（契约不成立，不是数据层坏了）。互联页「与已配对设备共享」写着统计 / 收藏「双向合并、默认开启」，但合并只发生在同步轮次里（`fushi/lib/src/sync/sync_orchestrator.dart` 的 `_syncAggregateLive` / `_syncVideoProgressLive` / `_syncCollectionsLive`），而所有自动轮次（开机 / 切后台 / 定时 / 关书 / 合集轻量）都先过 `_autoSyncGateOpen`，它只读一个全局开关 `sync_auto_enabled`（`fushi/lib/src/sync/sync_repository.dart` `isAutoSyncEnabled`，默认 false）。该开关只在「同步」分类里，互联页一字不提。于是开了互联、配好对的用户永远等不到合并：手机上看 host 视频的观看时长统计（`video_fushi_page.dart` `_ensureWatchTracker`：「host 端也从不替客户端记」）永远到不了 host。经互联串流时的播放位置不受影响——播放页按秒经 `InterconnectPlaybackPositionSync.reportLive` 直接写 host（`video_fushi_page.dart` `_persistRemotePosition`）。
- **[x] ① 已修复** — 互联通道拆出自己的自动同步开关 `interconnect_sync_auto`（默认开），云通道保留 `sync_auto_enabled`（默认关）。`sync_auto_trigger.dart` 新增 `isChannelAutoSyncEnabled` / `autoSyncChannels`：sweep / 合集轻量 / 退出书三条自动路径的锁外门与锁内最终判据都按通道过滤，各读各的开关；手动「立即同步」不经过滤。迁移在 `SyncRepository.isInterconnectAutoSyncEnabled`：新键缺行时看旧键**行是否存在**——缺行（从没动过）→ 开；有行 → 继承其值；结论读即落盘，`setAutoSyncEnabled` 写旧键前也先落迁移，之后写旧键不再影响互联。互联页共享区加真开关 `interconnect.auto_sync`（替换先前的指路行），同步分类旧开关加副标题说明只管云同步；ctl `/api/admin/sync` 与 `fushi_cli sync ls` 分开报两个开关。
- **[x] ② 已加自动化测试** — `fushi/test/sync/sync_repository_test.dart`（迁移三态 + 只迁一次 + 先写云开关不泄漏 + 互联开关独立往返）、`fushi/test/sync/sync_channel_isolation_test.dart`（全新安装只跑互联 / 只关云互联照跑 / 只关互联云照跑 / 通道身份分流）、`fushi/test/sync/sync_settings_visibility_test.dart`（共享区结构与两处文案）、`packages/fushi_cli/test/commands/data_commands_test.dart`（`sync ls` 分开报）。
- **备注**：所有者 2026-10-23 拍板方案 A（互联单独开关默认开，云保持默认关）。互联自动轮次只搬轻量数据：重内容上传开关全默认关，自动 sweep 也不会把远端独有的书导入本机（`sync_orchestrator.dart` 「远端独有书不会在自动同步中导入本机」）。已知边角：「同步方式」被选成互联（备份后端=互联）时，云那一格跑的就是互联链路，按通道身份读互联开关，此时同步分类的旧开关不管任何通道。
