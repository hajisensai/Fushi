## BUG-2566 · OALDPE10 短语动词记录带「Redirected from」标签就被当成纯跳转记录藏掉（查 give up 看不到 OALDPE10 释义）
- **报告**：2026-09-15（用户截图：查「gave up」，`give up` 卡片里 CED24 / LDOCE5 / 新英和 等都在，唯独没有 OALDPE10）
- **真实性**：✅ 真 bug。三层探针逐层排除：引擎（Release 构建自带的 `fushidicts_ffi.dll`，单挂 OALDPE10 与全部 62 个词典目录两种装载）都返回 `give up` 且带 OALDPE10 的 7 条 glossary；Dart `buildResultFromLookup` 也保留；丢在 WebView 渲染层 `fushi/assets/popup/popup.js` 的 `isRedirectGlossary`（BUG-1282 引入）。OALDPE10 的短语动词记录形态是数组：第一项是自我重定向标签 `["give up",["Redirected from give up"]]`，第二项才是真正的 structured-content 释义（503~1070 字节）；`redirectMarkerKind` 对数组取 max，任一元素含「Redirected from」整条记录就判为 redirect-only，连带释义一起藏掉。同库的纯别名记录（`give-up` / `give-up-on` → `give up`，只有那一个标签、41 字节）藏掉是对的。
- **[x] ① 已修复** — `popup.js`：新增 `hasStandaloneDefinition`（顶层数组里存在「自身无 redirect 标记且有可见文本」的项 ⇒ 记录带释义），`isRedirectGlossary` 改为「有 redirect 标记 **且** 没有独立释义项」才判 redirect-only；tag 显式标 `redirect`/`redirected` 的分支不变，LDOCE5 / OALD10 的单对象跳转形态不变。三份镜像（`assets/popup`、`assets/browser_extension/vendor`、`tools/browser-extension/vendor`）同步。提交 `abfc06788e`（fix(popup): keep definition-bearing records that carry a redirect label）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/popup_redirect_entry_filter_test.js`（经 `popup_redirect_entry_filter_test.dart` 在 node 里真跑 popup.js）新增 OALDPE10 真实形态：别名记录仍判 redirect-only；带释义的短语动词记录（对象形与桥接过来的 JSON 字符串形）都保留；`createGlossarySectionWrapper` 分组后 OALDPE10 卡片仍在。
