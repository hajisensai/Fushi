## BUG-5563 · 官网下载页没有 Linux，文档仍写「Linux 只能从源码构建」
- **报告**：2026-11-26（应用内反馈 din9GiSKFB，开发者本人提）
- **真实性**：✅ 真问题。Linux 包其实早就有了：`.github/workflows/release-desktop.yml` 的 `linux` job 每次构建 `fushi-*-linux-x86_64.flatpak` 和 `-linux-x64.tar.gz`；`publish` job 把 Flatpak 推到 GitHub Pages 上的签名 OSTree 仓库，上传 release 资产，并以 `PLATFORM_LABEL: linux` 写进 update-manifest 清单。实测 `fushi-debug-rolling` 与 `v3.4.0`（草稿）都带这两个文件，`latest-debug-fushi.json` 已经有 Linux Flatpak，`hajisensai.github.io/Fushi` 的 stable / debug 分支都在线。可官网仓 `hajisensai/fushi.moe` 有三处没跟上：下载槽位（`edge/src/manifest.ts` 的 `SLOTS`、`.vitepress/theme/DownloadPage.vue` 的 `SLOT_PATTERNS`）没有 linux；下载表没有 Linux 行；`dl.linux` 文案和多篇常见问题仍写「Linux 暂无预编译包，请从源码构建」。本仓的 `docs/agent/repo-map.md:42`、`docs/agent/rules-detail.md:60` 也还写「Linux App 只能从源码构建（CI 不出包）」，跟 `docs/agent/build.md`「Linux 桌面」（2026-11-23 起随 release 出包）对不上。反馈的 AI 总结就是照这两行写的，结论跟着错了。
- **[x] ① 已修复** — 官网 hajisensai/fushi.moe#88：加 linux 槽位和 Linux (x86_64) 下载行，写 Flatpak 安装 / 更新说明；清单里某通道缺某平台的包时，那一行如实写「暂时还没有」，不再给落到 Releases 页的假链接；17 种语言字典与常见问题同步。本仓：`repo-map.md` / `rules-detail.md` 改成与 build.md 一致。
- **[x] ② 已加自动化测试** — 官网 `edge/test/downloads-channels.test.ts`：Linux 槽位认 `-linux-x86_64.flatpak`、不把 `.tar.gz` 当安装包，改前的 `manifest.ts` 上是红的；`tool/verify-download.mjs` 加一条「有 Linux 行，直链是 Flatpak 包」。本仓只改了文档，不需要测试。
- **备注**：3.4.0 正式发布前，正式版清单（3.3.0）里没有 Linux，下载页正式版通道的 Linux 行会显示「这个通道暂时还没有该平台的包」，调试版通道可以下载。
