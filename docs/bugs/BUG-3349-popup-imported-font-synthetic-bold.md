## BUG-3349 · 查词弹窗导入字体只有常规字重时词头被合成加粗、字形中空
- **报告**：2026-10-14（用户：应用内反馈 2t6NqPuRD8，视频查词弹窗截图，词头「会費」的「費」中空）
- **真实性**：✅ 真 bug。用户把导入字体 Klee One（只有 Regular，`OS/2.usWeightClass=400`）设为词典字体；MD3 弹窗 `fushi/assets/popup/popup.css:3005` `html.fushi-m3e .expression` 给词头 emphasized 字重。导入字体的 `@font-face`（`fushi/lib/src/reader/dictionary_font_css.dart` 的 `DictionaryFontCss.build`）不声明字重、弹窗也不限制合成，于是 WebView 把唯一的常规字面合成加粗；Klee One「費」的轮廓自相交，合成加粗后被描成中空。同一卡片释义正文（常规字重）里的「会費」正常，印证是合成加粗所致。另：导入同家族的粗体文件也无济于事——导入按文件名命名（`font_download_service.dart` `_copySingleFont`），`KleeOne-SemiBold.ttf` 成了另一个家族，且 `@font-face` 不声明真实字重，浏览器永远选不到它。
- **[x] ① 已修复** — 两件事：(a) 导入字体生效时弹窗根上关掉字重合成（`dictionaryLanguageFontCss(suppressWeightSynthesis:)` 输出 `font-synthesis: style; font-synthesis-weight: none;`，in-app 弹窗 / app 外 WebView2 / 浏览器扩展同一生成器）；阅读器正文与歌词**不**关（正文有用户可调字重设置，导入单字重字体时正靠合成生效）。(b) 每条导入字体 `@font-face` 声明文件真实字重（`ReaderCustomFontCss.fontWeightDescriptor`：静态取 usWeightClass、可变取 wght 轴范围，读自 `font_file_metadata.dart` 的 `readFontFaceWeightSync`），同名条目合成一个家族；导入时按字体 `name` 表家族名（nameID 16 优先）命名，`KleeOne-SemiBold.ttf` 落成「Klee One」与 Regular 同名；扩展 `new FontFace()` 也带 weight 描述符。
- **[x] ② 已加自动化测试** — `fushi/test/reader/custom_font_weight_css_test.dart`：生成器层（单字重声明 400、同名两字重两条 `@font-face`、可变字体轴范围、合成开关、导入命名）+ 真 Chromium 截图墨量（只有 Regular 时关合成后 700 与 400 像素墨量相同、对照组不关时明显变粗；同名 Regular+600 字面时 700 选中 600 字面、不再合成）。
- **备注**：Flutter 侧（App UI / 视频字幕 / 游戏文本，`AppFontLoader`）同名第二个文件不会注册进同一家族，Skia 也不对 FontLoader 字体做合成加粗，未改。WOFF2 文件读不出字重（Brotli），不声明描述符（与改动前一致）。
