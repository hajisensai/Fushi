## BUG-1430 · 切换字幕遮罩模式卡顿：两次事务落盘 + UI 等落盘 + 全局广播重建全 app
- **报告**：2026-08-02（用户：切换字幕遮罩模式好卡；追问确认为「按下那一刻卡顿/延迟」，Windows）
- **真实性**：✅ 真 bug。按一次遮蔽快捷键（B / Shift+B / H / Shift+G / Shift+H）或点一次面板分段控件，串起三笔成本：
  - **根因 ①「一个逻辑设置写成两次事务」** `hibiki/lib/src/models/preferences_repository.dart:856`（副字幕 `:878`）——三态 `VideoSubtitleObscureMode` 被投影成 `video_subtitle_blur` + `video_subtitle_obscure_hide` 两个 bool 键，用两次 `setPref` 落盘；而 `setPref` 在 DB 层是**每键一个 transaction**，且每个事务里还带一次 prefs 版本号的 read-modify-write（`packages/hibiki_core/lib/src/database/database.dart:2304`，BUG-906 的原子性要求）。实测（Windows，真实文件 sqlite + WAL）：**两键中位 12.3ms / p90 20.1ms / 最坏 113.3ms**，单键中位 5.1ms。真实繁忙库上还要排在在途写之后（drift 单写连接串行化）。附带一个正确性问题：两次事务之间存在「blur 已落盘、hide 未落盘」的跨进程可观察窗口，:popup 进程可能读到半个设置。
  - **根因 ②「UI 更新排在落盘之后」** `hibiki/lib/src/pages/implementations/video_hibiki_page.dart:5826` / `:5848`——旧写法 `await appModel.setVideoSubtitleObscureMode(mode); if (mounted) setState(...)`。这个 await 是**纯白等**：`PreferencesRepository.setPref` 的第一行就同步写了 `_prefCache`（`preferences_repository.dart:156`），getter 在 await 之前已经返回新值。按键到画面变化因此白白多出根因 ① 的整段耗时。
  - **根因 ③「局部开关走全局广播」** `preferences_repository.dart:861`（副字幕 `:883`）的 `notifyListeners()`——`AppModel` 把本仓库的通知转成全局广播（`app_model.dart:2140` 的 `prefsRepo.addListener(notifyListeners)`），而 `BasePageState.appModel` 是 `ref.watch(appProvider)`（`hibiki/lib/src/pages/base_page.dart:39`）。于是一个只被视频页字幕层和视频设置面板读取的开关，每次切换都重建**每个 watch `appProvider` 的 widget**，包括当前路由栈下方仍挂载的整棵首页/书架树。这是高频快捷键路径上最大的一笔。
- **[x] ① 已修复** — 三条各自根治，无补丁式绕过：
  - ① 新增 `HibikiDatabase.setPrefs(Map)`（单事务多键 + **一次**版本 bump，保持 BUG-906 的「业务写与 bump 同事务」不变量）与 `PreferencesRepository.setPrefs`；两个遮蔽 setter 改走它。12.3ms → 5.1ms 量级，并消除半个设置的可观察窗口。
  - ② 视频页改为先接住落盘 Future、`setState` 之后再 `await`（异常照旧抛出，不吞）。依赖 ① 带来的不变式：`setPrefs` 的同步段一次写穿两个 key，故 setState 那一帧 getter 返回的是**完整**新三态，不会先闪一下模糊再变隐藏。
  - ③ 两个遮蔽 setter 不再全局广播（视频页自己 setState、设置面板自己 `settingsContext.refresh()`）。低频路径行为不回归：`setVideoSubtitleObscureModeDual` 在 host 缺席（= 从全局设置页改、视频页可能仍在路由栈下方）时显式调用新增的 `AppModel.notifyPreferencesChanged()` 补一次广播。
- **修复前后实测**（同一台 Windows、真实文件 sqlite + WAL、30 轮取分位）：落盘 **12.3ms → 3.7ms**（p90 20.1 → 4.8，最坏 113.3 → 6.4）；**按下到 UI 可更新 12.3ms → 0.07ms**（中位；p90 0.14ms）。第三笔（全 app 重建）不在这个基准里，由守卫 ③ 从行为上钉死。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_subtitle_obscure_switch_cost_test.dart`（10 用例）：单事务只 bump 一次版本 + 空 map no-op；落盘 Future 未 await 时 getter 已返回完整新三态（主/副）+ 跨 reload 持久化未被跳过；遮蔽 setter 零广播 + 对照普通 setter 仍广播；视频页与 `video_settings_actions` 的接线源码守卫。三处**变异实测**均被对应用例抓住：加回 `notifyListeners` → ③ 红；改回逐键 `setPref` → ② 红（读到中间态 blur）；页面改回 `await` 在前 → 接线守卫红。
- **备注**：本 bug 只处理「按下那一刻」的切换成本，用户确认的现象也仅此一种。另有一条**未处理**的相邻成本：设置面板每次 `refresh()` 都经 `collectVideoItems` → `buildSettingsSchema()` 全量构造 13 个分类的所有设置项（只为取「字幕」一组），这条影响的是面板内所有设置项的切换，不止遮罩，范围更大、应独立立项。模糊态本身的渲染成本（`ImageFiltered` sigma = 字号×0.45）用户明确表示不是他遇到的现象，未动。
