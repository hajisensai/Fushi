## BUG-826 · 查词弹窗顶栏按钮窄宽时重叠
- **报告**：2026-07-15（用户：截图，有声书查词弹窗，窄宽时顶栏按钮相互重叠）
- **真实性**：✅ 真 bug — 根因 `hibiki/lib/src/pages/implementations/dictionary_popup_layer.dart:687`（`_buildTopBar`）。顶栏用 `Stack` 把三组按钮各自 `Align` 叠在同一水平带：左端 A−/A+（`Alignment.centerLeft`）、**全宽居中**的 `headerWidget`（reader 音频控制，最多 4 颗按钮 ≈144px，`Alignment.center`）、右端关闭（`Alignment.centerRight`）。三层互不预留水平空间——弹窗宽度收窄到 `kLookupPopupMinWidth`(250) 或 UI 缩放放大时，居中的音频行向两侧张开压到 A−/A+ 与关闭按钮上（重叠即设计）。250px 时：左簇 [0,72]、居中音频 [~41,209]，41<72 → A+ 与收藏星标重叠。
- **[x] ① 已修复** — commit `a3a5cb78b`（doc 补哈希后 amend）。两处：① `dictionary_popup_layer.dart` 的 `_buildTopBar` 由三层重叠 `Stack` 改为一条顺序 `Row`：左簇（返回/A−/A+）定宽钉行首 → 中段 `Expanded(Center(headerWidget))` 把 header 夹在两簇之间的**有界宽度**里居中（不再全宽居中压两侧；`Center` 的 loose 约束保住 `ReaderChromeScaler` 需要的有界宽，UI 缩放不失效，且贪婪/无限宽 header 也不抛无界宽异常）→ 右簇（关闭）定宽钉行尾。header 缺省时中段退化 `Spacer()`。② `reader_hibiki_page.dart` 的 `buildPopupAudioControls` 音频行包 `FittedBox(fit: scaleDown)` + `Row(mainAxisSize: min)`——窄宽下整行等比缩小而非裁切/溢出。Row 顺序排布天然不重叠。
- **[x] ② 已加自动化测试** — `hibiki/test/pages/popup_topbar_no_overlap_guard_test.dart`：① 窄宽（`kLookupPopupMinWidth`=250）挂真 `DictionaryPopupLayer` + 内部可缩 header（`FittedBox(scaleDown)`+192px 行，镜像生产），断言 A−/A+、居中 header、关闭三者屏幕矩形互不水平重叠、header 不越界、且不抛 RenderFlex overflow；② 源码守卫 `buildPopupAudioControls` 含 `FittedBox`+`fit: BoxFit.scaleDown`+`mainAxisSize: MainAxisSize.min`（弹窗跑真 WebView 无法 headless 全挂）。已验证守卫①在旧 `Stack` 实现下转红（leftClusterRight=93 > header.left=29）、修复后转绿。
- **备注**：WebView 内部 header 按钮（发音/制卡/句子上下文）的窄宽收缩另由 popup.css `.header-buttons` 的 `clamp()` gap 处理（TODO-846，`popup_header_button_spacing_guard_test.dart`），与本 Flutter chrome 顶栏是两条独立路径。
