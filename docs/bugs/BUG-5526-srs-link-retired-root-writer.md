## BUG-5526 · 平板复习同步永远不采用电脑的集合：集合目录里退役旧根的写入者被当成成员，关联判成「已关联」
- **报告**：2026-11-26（用户：平板经互联与电脑同步后数据不一致——平板本机 0 张卡，电脑 17765 张；同步提示照常「已同步」）
- **真实性**：✅ 真 bug。电脑同步目录副本取证：平板集合目录 `fushi-srs/01a13dd3…/` 已立新代根 `v4/`（`meta.json` 集合 84749d00，旧根 `v2/meta.json` 是 `FUSHI-SRS-MOVED-TO-V3` 围栏、`v3/meta.json` 是 `{"moved":"v4"}` 围栏），`v4/devices/` 下只有平板自己（说明文件 `hasNotes:false, notes:0`）；但旧根 `v2/devices/01a1862a…/` 里还留着一台协议 1 时代旧设备 2026-10-30 写的 38 条操作和说明文件 `{"name":"Default","hasNotes":true}`。`srsListRemoteProfiles`（`packages/fushi_engine/lib/srs/srs_profile_link.dart`）把各根的写入者不分来源并成一个 `writers`，`srsDecideProfileLink` 的「本机目录里有别的设备 = 已关联」（同文件 `if (mine != null && otherMember(mine))`）把这台再也写不进来的旧设备算成别的成员，每轮都返回 `SrsProfileLinkKeep(linked: true)`：平板从不采用 / 提示电脑那份 15377 条笔记的集合（`01a13df1…`），只在自己的空集合上同步，提示照常「已同步」。同一份旧说明文件还让平板目录的有无笔记汇总成 true（第三台空设备会把它当成又一个有数据的候选，从「直接采用」退成「让用户选」）。
- **[x] ① 已修复** — `srsListRemoteProfiles` 按写入者分别记有无笔记 / 笔记数 / 最新时刻 / 设备名，列完再汇总：目录读得到新代根 `v4/meta.json` 的集合标识时，在 `v4/devices/` 下没有设备目录（只有 head 的也算有）的写入者记进新字段 `SrsRemoteProfile.retiredWriters`——新代立根后旧根都立了围栏，它们不会再写这个集合。`stayingWriters` 去掉它们（关联判定 `otherMember` 与认领时 `_adoptCollection` 的「旧目录里还有别人」都经它），名字 / `nameOf` / `mergingInto` / 有无笔记 / 笔记数 / 设备名 / 最新时刻都不采信它们的说明文件；`writers` 仍列全（孤儿目录清理按它判「只有本设备写过」，不放宽）。还没立新代根的目录（协议 3 位置）不变。电脑同步目录副本上复跑：平板（本机无笔记）从 `Keep(linked)` 变成 `Adopt(01a13df1…)`，本机有笔记时变成让用户选。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/srs_profile_link_test.dart`「已退役旧根里的写入者（真目录）」：真目录布置平板形状（`v4` 根 + 自己的说明文件、`v2` 旧设备、说明文件在 `v3` 但 `v4/devices` 有 head 的老新代设备），核退役集合、`stayingWriters`、汇总字段只来自在世写入者；列出来的结果交给 `srsDecideProfileLink` 判成采用电脑集合；没立新代根时旧根写入者照旧算成员；纯函数对照（同一写入者退役 → 采用，不退役 → 已关联）。
- **备注**：平板真机复测要装带修复的包（平板跑的是 debug 通道 3.4.0-debug.32705，合入 develop 后随 debug 包更新即可；不往用户平板覆盖装开发包）。采用后平板的空集合目录由认领流程照常收拾（只删本机设备目录），旧根里那台旧设备的目录不动。
