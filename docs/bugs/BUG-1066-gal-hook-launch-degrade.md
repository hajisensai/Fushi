## BUG-1066 · 已支持游戏总是启动失败或音频降级到整机混音
- **报告**：2026-07-25（用户：截图 manosaba/天使☆騒々 RE-BOOT!，`game.launch_started` 同秒 `engine.launch_or_inject_failed`，12s 后窗口出现被绑定，随即 `audio.engine_attach_failed` → `audio.loopback_active`，文本来源一直「等待」）
- **真实性**：✅ 真 bug，且与具体引擎无关——是启动/附着编排链上的三处结构性缺陷，所以「已支持的游戏」也会中招。
  1. **native 会把游戏永久挂起**：`injector/injector_main.cpp` 的 `RunLaunch` 按返回码猜游戏状态——`rc==1` 一律 `TerminateProcess`，`rc==2` 依据注释「超时但已 Resume」放着不管；但 `RunInjection` 的两个 `return 2`（就绪事件超时 `injector_main.cpp:1073`、旧映射不可复用 `:1013`）都发生在 `ResumeThread`（`:1155`）**之前**。CREATE_SUSPENDED 拉起的游戏因此永久挂起：进程在、窗口永不出现 = 用户眼里的「启动失败」。
  2. **两侧握手超时不同源**：Dart 侧等 30s（`hibiki/lib/src/mining/galgame_audio_source.dart:485`），injector 默认只等 5000ms 且 `buildEngineHookInjectorArguments` 从不下发 `--wait-ms`。杀软扫描下大 hook DLL 加载超 5s 就命中上面那条僵尸路径。
  3. **失败原因被丢弃且降级是终态**：injector 的 stdout/stderr 只进 `debugPrint`（`galgame_audio_source.dart:447`），release 包无控制台 = 证据全丢；UI 又把内部代码 `engine_attach_failed` 原样显示给用户（`texthooker_page.dart:1410`）。而 `_activateLoopback` 之后 `_engineSource=null`，**再不重试** —— 一次注入竞态就让整局只剩整机混音、没有台词。
- **[x] ① 已修复** — 两仓分别提交。
  - native（`hajisensai/hibiki-hook` `f7c92b6`，分支 `fix/launch-no-suspended-zombie`）：`RunInjection` 增加 reason/resumed 出参，把「是否已恢复」变成事实而非推断；新增 `include/launch_failure_policy.h` 按 `(created_suspended, already_resumed, reason)` 决定 leave / resume-degraded / terminate——任何失败**至少让游戏以无 hook 方式跑起来**，只有恢复动作自身失败才结束进程；所有失败出口打印 `ERR reason=<token>`；`CreateProcess` 成功后立即 `LAUNCH pid=`（跟随子进程时更新为真实游戏 PID）。
  - Hibiki 消费端：`buildEngineHookInjectorArguments` 下发 `--wait-ms`（与 `readyTimeout` 同源）；`EngineHookGalAudioSource` 保留 injector 诊断尾部与退出码，`classifyGalHookInjectorFailure` 归类成 `GalHookInjectorFailure`（新旧 helper 都兼容：优先认 `ERR reason=`，退回既有中文诊断串）；`GalHookSessionController` 把原因写进会话事件详情与 `state.injectorFailure`，降级后按 `kGalEngineRetryBackoff`（3s/8s/20s）**有界重试并升级回引擎源**，不可自愈的失败（提权/位数/缺文件）一次都不试；launch 注入失败但拿到 `LAUNCH pid` 时保留会话、降级 + 重试，不再把正在运行的游戏报成「启动失败」；UI 用 17 语言 i18n 文案给出可执行处置，不再甩内部代码。
- **[x] ② 已加自动化测试** — Dart：`hibiki/test/mining/galgame_audio_test.dart`（`--wait-ms` 同源下发、`ERR reason=` 与旧中文诊断双路归类、重试策略、`parseInjectorLaunchedPid`，63 项通过）；`hibiki/test/mining/gal_hook_session_controller_test.dart` 新增 group `engine hook failure handling` 4 项（可自愈失败重试并升级回引擎源、不可自愈失败一次不试、启动注入失败但游戏在跑不报启动失败、旧 helper 无 PID 时仍是带原因的明确失败），24 项通过。native：`tests/launch_failure_policy_test.cpp`（挂起僵尸回归 + token 契约），x64 ctest 19/19、x86 ctest 20/20 通过。
