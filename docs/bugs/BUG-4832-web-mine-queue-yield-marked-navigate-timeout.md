## BUG-4832 · 空闲自动制卡正在换视频时用户回来，那一行被永久标成 navigate_timeout
- **报告**：2026-11-17（网页视频 gap-webvideo-5 复核时发现）
- **真实性**：✅ 真 bug（代码确证）。`fushi/lib/src/pages/implementations/web_video_fushi_page.dart:1532-1548`（修前）`_navigateForMining` 返回 `bool`：等满 30 秒超时回 false，`!mounted || _mineStopRequested`（用户回来让位 / 手动停止 / 页面卸载）也回 false；调用方 `fushi/lib/src/pages/implementations/web_video_fushi_page.dart:1635-1637` 对 false 一律 `markFailed(row.id, 'navigate_timeout')`。于是让位那一刻正在导航的行被标失败——网页重放的失败行没有任何重试入口、角标也不显示，这张卡等于丢了。同一处另一个问题：某一集到不了（下架 / 地区限制 / 登录过期）时，这一集的 N 行各等 30 秒。
- **[x] ① 已修复**（`e40b885fc55`）— 导航结果改成三态 `WebMineNavigateOutcome`（`ready` / `timedOut` / `interrupted`）。`interrupted`：这一行与之后的行都留在待办，整轮停下。`timedOut`：只标这一行 `navigate_timeout`，同一视频的其余行本轮跳过、保持待办（不再每行各等一个期限；网页失败行的重试入口未拍板前不成批标失败）。判定在 `fushi/lib/src/mining/web_mine_queue_run.dart` `runWebMineQueueRows`。跨轮：空闲自动制卡一轮结束 5 秒后调度器就会再开一轮（用户不在场、待办还在），只在一轮之内记「到不了」的话 N 轮后那一集的 N 行照样全部失败、还多 N 次整页导航（窗口宿主档是 N 次整页交接）——所以超时的视频记进进程级、按书的 `WebMineIdleGiveUps`（同文件）：自动跑开跑前排除这些视频的行，剩下的待办全在到不了的视频上时整本书本次空闲不再开跑（`_canStartIdleMining` 先查，窗口档连交接都不发起）；记下之后整台机器有过输入即作废，用户手动点的不受限。
- **[x] ② 已加自动化测试** — `fushi/test/mining/web_mine_queue_run_test.dart`「BUG-4832：导航途中让位…」「导航超时：只标这一行…」「BUG-4832：空闲自动制卡跨轮…」（假空闲时钟推进 20 拍调度，到不了的视频整次空闲只导航一次、只标一行；用户回来后重新给机会）；`fushi/test/media/video/web_video_mine_queue_guard_test.dart`「导航被叫停与等满期限是两种结果」。
- **备注**：待真机复测——队列里放两集的行，空闲自动制卡换到第二集途中动一下鼠标，那一行仍在待办、下次空闲照跑。到不了的视频每次空闲（用户离开一次）仍会消耗一行（标失败）并等一次 30 秒，属现状取舍，等失败行重试入口（gap-webvideo-6）拍板后再议。
