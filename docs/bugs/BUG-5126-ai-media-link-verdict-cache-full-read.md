## BUG-5126 · ai-media-link-verdict-cache-full-read
- **报告**：2026-11-22（外部审计 HBK-AUDIT-043，Codex 2026-11-21 PR 审查，来源 PR #3810）
- **真实性**：✅ 真问题（性能）。`packages/fushi_engine/lib/ai/ai_media_link_assistant.dart` 的 `MediaLinkVerdictCache.lookup` 调 `mediaLinkAiVerdictsSince(_notBefore)`（`packages/fushi_core/lib/src/database/database_media_link_ai_verdicts.part.dart:7`）把 180 天内**整张**裁决缓存读回 Dart，再按端点对在内存里挑本次候选：查 1 对作品关系也读回全部 N 行。`store` 每记一批（每批 ≤20 条，`kAiMediaLinkMaxCandidatesPerRequest`）都跟一次 `pruneMediaLinkAiVerdicts`（全表扫 `judged_at`，无索引），一次推断分 k 批就清 k 次。实测（修前，新测试同一组合）：表里另有 300 对时查 1 对读回 301 行；45 条候选分 3 批记触发 3 次 DELETE。
- **[x] ① 已修复** — 新增 `mediaLinkAiVerdictsForPairs`（主键 `(a_kind, a_key, b_kind, b_key)` 逐对 OR 查询，去重、每条 SELECT ≤200 对分批，带有效期条件），`lookup` 改按本次候选的端点对查；清过期改独立频率：按数据库对象（`Expando`）记上次清理时刻，`kAiMediaLinkVerdictPruneInterval`（1 天）内只清一次，与批次数无关（过期行本就被读取条件挡住，不影响正确性）。修后同一组合：读回 1 行、查询计划全是 `SEARCH ... USING INDEX sqlite_autoindex_media_link_ai_verdicts_1`、3 批记录 0 次 DELETE、过了间隔再记才清 1 次。
- **[x] ② 已加自动化测试** — `fushi/test/media/links/media_link_ai_series_test.dart`「按候选端点对查缓存：读回行数 = 候选数、走主键；清过期一天一次、不随批次」（QueryInterceptor 计 SELECT 读回行数 / DELETE 次数 / EXPLAIN QUERY PLAN）；`fushi/test/database/migration_v163_media_link_ai_verdicts_test.dart`「按端点对批查」（去重、过期 / 不存在不读、450 对跨批）。变异：把 `ai_media_link_assistant.dart` 换回修前版本，前一条测试变红。
- **备注**：未加 `judged_at` 索引（要升 schema；清理已降到一天一次，全表扫一次可接受）。
