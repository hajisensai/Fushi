## BUG-5262 · interconnect-offline-log-noise
- **报告**：2026-11-22（开发者应用内反馈 w8sFMyflft：「报错里面一堆报错，该删的日志删掉，没用的」，Android 3.4.0-debug.31366）
- **真实性**：✅ 真 bug。互联对端（电脑）离线是预期状态，却被当成错误逐轮记：① `fushi/lib/src/sync/sync_auto_trigger.dart` `runOnAuthenticatedSyncChannels` 的 catch 对每个通道异常一律 `ErrorLogService.log`（带整段堆栈），每次复习自动推送遇到已类型化的 `SyncPeerUnreachableError` 都记一条用户可见错误；② `fushi/lib/src/srs/srs_sync_scheduler.dart` `_noteRoundFailure` 每轮记 `roundFailed` 诊断，`autoPush` 把离线当「细节可变的推送失败」按 10 分钟限流反复记 `autoPushSkipped`；③ `packages/fushi_engine/lib/sync/pairing/fushi_ping_client.dart` `probeFushiPing` 在 catch 里逐次记 `Ping:<url>` 诊断，而互联选路（`interconnect_peer_addresses.dart` `defaultInterconnectAddressProbe`）每轮对同一 host 的全部候选并发 ping——反馈附带日志尾巴 200 行里 37 条是 Ping 超时 / No route to host。
- **[x] ① 已修复** — `runOnAuthenticatedSyncChannels` 遇 `SyncPeerUnreachableError` 照常交回调用方（推送退避、界面显示），不进错误日志；`SrsSyncRoundStats.loggedFailure` 让 `roundFailed` 只在失败开始 / 原因变化时记，恢复时记一条 `roundRecovered`；`autoPush` 全部通道都因对端离线失败时按稳定原因 `kSrsAutoPushPeerOffline` 只在状态变化时记；`probeFushiPing` 不再自己记日志，原始异常随 `FushiPingOutcome.cause` 交回，配对两处（设置页手动配对、发现配对探测）经 `logFushiPingFailure` 每次照记，选路探测经 `noteInterconnectAddressProbe` 按地址只在状态切换（首次失败 / 分型变了 / 恢复）时记，签名只取分型不取异常原文（原文里可能带每次不同的本地端口）。
- **[x] ② 已加自动化测试** — `fushi/test/srs/srs_sync_scheduler_test.dart`「对端离线：自动推送几轮，错误日志 0 条，诊断只记状态切换」「非离线的通道异常照常记进错误日志」；`fushi/test/sync/interconnect_probe_log_test.dart`（真实 HTTP 端点 ping 4 次只记 1 条、状态切换序列、probeFushiPing 不自记日志）。
- **备注**：完整同步（`_runSyncChannel` / `logSyncReportErrors`）遇对端离线的记账不在本次反馈范围内，未改。
