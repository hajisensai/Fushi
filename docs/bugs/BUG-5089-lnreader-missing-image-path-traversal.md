## BUG-5089 · lnreader-missing-image-path-traversal
- **报告**：2026-11-22（外部审计 HBK-AUDIT-002，Codex 2026-11-21 PR 审查，来源 PR #4016：「EPUB 补图的写入路径缺少目录约束」）
- **真实性**：✅ 真 bug（安全，P1）。`fushi/lib/src/media/novel/online/lnreader_missing_images.dart` 的 `retryChapterMissingImages` 把取回的图写到 `File(p.join(extractDir, 'OEBPS', image.fileName))`（修前 :298），`image.fileName` 在 LNReader 两条管线里就是缺图占位 `data-fushi-lnreader-missing-file` 的值（`_imageOf` 修前 :105 原样解析，`LnReaderDownloadedBookImages` / `LnReaderOnlineChapterLoader` 的 fetch 把它作为 `fileName` 交给 `fetchChapterImage`，后者原样返回）。占位来自章节文件：`lnReaderDownloadedBookImagesFor` 对**任何**书行都挂补取（第三方 EPUB 只要有 `OEBPS/chapter-<n>.xhtml` 和占位、插件 id 写成本机已装插件），站点正文经 `lnreader_host.js` `toXhtml` 也不剥 `data-*` 属性。占位写成 `../../x.png`、绝对路径、驱动器号或反斜杠时，开书自动补取就把攻击者 URL 的字节（只需带图片魔数）写出书的解压目录。同源问题：`lnreader_online_book.dart` 的 `readLnReaderLoadedChapter`（在线书 / 网页小说书就地重建时搬图）按正文里 `src="images/..."` 拼路径读文件，`images/../../..` 能把书目录外的图片文件读进新书。网页小说书管线的写入名由 `webNovelImageFileName`（URL 的 SHA-1）生成，本身不受占位控制，但占位解析与重建搬图共用上述两处。
- **[x] ① 已修复** — `lnreader_missing_images.dart` 新增插图条目名的唯一判据：`isLnReaderBookImageKey`（占位键，逐字只认三条管线的生成形状：在线书 `images/<SHA-1 前 12 位>-<n>.<ext>`、下载书 `images/c<章>-<n>.<ext>`、网页小说书 `images/w<SHA-1 前 16 位>[.<ext>]`，ext ∈ jpg/png/gif/webp；复审时由宽松的 `images/<任意小写名>` 收紧，否则伪造占位仍可指名同书封面 `images/cover.<ext>` 覆盖或指名 `con` / `nul` 设备名）与 `lnReaderBookImageFile`（文件名必须带扩展名，且规范化后的绝对路径须在本书 `OEBPS/images/` 内，否则 null）。`parseLnReaderMissingImages` 不认键不合规的占位（不计数、不补取）；`retryChapterMissingImages` 的写入目标只由 `lnReaderBookImageFile` 给出，取图方返回的名字不合规按这张未补到记次、不落盘；`readLnReaderLoadedChapter` 同样只读 `lnReaderBookImageFile` 给出的文件。
- **[x] ② 已加自动化测试** — `fushi/test/media/novel/lnreader_missing_image_path_test.dart`：三条管线的合法名都认且落在图片目录；`../`、绝对路径、驱动器号、反斜杠、子目录、非图片扩展名等 19 种名字全部拒绝；伪造越界占位经 `retryChapterMissingImages` 不取图、不落盘、不计数；取图方返回越界名时记次不写；合规占位（含网页小说书无扩展名键换真文件名）照常补到；重建搬图不读书目录外文件。变异实测：撤掉修复后该文件测试变红。
- **备注**：占位里的图片 URL / 引用页 / 插件 id 同样来自章节文件，取图走既有 `isBlockedHost` 与逐跳重定向判据（防 SSRF），本修复不改。
