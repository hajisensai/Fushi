## BUG-5069 · TXT 超长段落绕过分章上限
- **报告**：2026-11-18，关联 GitHub issue #3725（外部 PR #3738，作者 JHR-deve）。用户反馈几十 KB 的 TXT 可打开、700 多 KB 的 TXT 打开超时。
- **真实性**：✅ 分章上限失效已沿真实代码路径证实。`packages/fushi_engine/lib/media/audiobook/text_to_epub.dart` 旧 `_plainTextToHtml` 只按双换行生成 `<p>`，单换行成为 `<br/>`；旧 `_splitIntoChapters` 只在 `<p` 前切，不拆超过 30000 字符的单个段落。仅单换行或无换行的小说因此生成远超上限的巨章。Markdown（单换行同样并进一个 `<p>`）与 HTML（只有一个巨大块，或 `<p>` 嵌在 `<div>` 里——旧实现还会在 `<div><p>` 中间切出未闭合标签）是同一缺陷。此缺陷与报告现象吻合，但尚未在修复版真机上确认它是该设备超时的直接原因。
- **[x] ① 已修复（根因）** — 作者初版（`a6f4fc17`）在 TXT 段落内按 token 贪心切，切点不选行边界，会在句子中间插入假段落 / 章节断点，且 Markdown / HTML 未修。合并前改为：三种输入先解析成同一棵块树（`_BodyNode`），再由同一个打包器 `_packInner` 按 `kMaxCharsPerChapter` 切章，切点优先级「块之间 > 块内换行（切点上的 `<br/>` 并入块边界、块首不留 `<br/>`）> 行内子节点之间 > 文本字素簇之间」；超长块按原标签成对重新包裹，每章都是良构 XHTML。HTML 输入改为解析后重新序列化：良构的走 XML 解析（保住 `<a id="x"/>` 这类非空元素自闭合），不良构的走 HTML5 解析。
- **[x] ② 已增加自动化测试** — `fushi/test/media/audiobook/text_to_epub_test.dart`：精确 750 KiB 仅单换行 TXT（每个切点都落在原换行、无半行）、无换行长段落、40 种边界偏移的 XML 转义 / 换行 / 非 BMP 字符、单换行长 Markdown 段落、HTML 单个巨块（每章保留祖先 `<div class="c"><p>`、切点落在 `<br>`）、XHTML 自闭合非空元素不吞后文。断言多章、各章 body HTML 不超过 30000、XML 可解析、块首不是 `<br/>`、正文无丢失。
- **验证**：上述测试文件 15 个用例全过（dist_test，退出码 0）。未进行真机 / WebView / 三种 view mode 复测，不声明 #3725 已解决。
- **范围**：只修复文本类导入的分章上限，不调整 8 秒内容就绪提示，不改书架刷新或数据库，也不重写旧书章节 / 阅读位置。旧书已生成的 EPUB 不会因本修复自动改变。
