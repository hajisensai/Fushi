## BUG-2593 · 多季对齐把映射表条目序号当本地季号，BLEACH S17 整季挂不上集
- **报告**：2026-09-19（用户：「看看死神为什么刮削有问题」+ 后台任务截图）
- **真实性**：✅ 真 bug（安装版库作品 141 + run 113/115/116 summary + Fribb 真实条目）
  - 现象：`BLEACH 千年血戦篇-禍進譚- (2026)/Season 17/… - S17E41..48.mkv` 八个文件，AniDB 哈希全部命中 anime 19079 第 01–08 集、MAL 60636；作品落库了（MAL 60636 主源 + TMDB 30984 + AniDB 19079），季表 `0:4, 1:366, 2:50, 5:0`，但每次 sweep 都报 8 条「第 17 季超出该剧已知的 5 季，未自动对齐」，`video_metadata_episodes` 里没有任何一行绑到这 8 个 book。
  - 根因 `packages/fushi_engine/lib/media/video/metadata/video_source_scrape_coordinator.dart` `_expandMalSeasons`（改前 `:1596-1612`）：本地「第 S 季」直接取 `seasonEntries[S-1]`——把「同一 TMDB 剧下 Fribb 条目的序号」当本地季号。Sonarr / Plex 式 `Season NN` 用的是 **TVDB 季号**，一个 TVDB 季装着多个 MAL cour：Fribb 里千年血战篇四个 cour 全是 `season.tvdb=17`，`episode_offset.tvdb` = 0 / 13 / 26 / 40，`anidb 19079 / mal 60636` 正是 offset 40，所以 `S17E41` = 该 cour 第 1 集，与哈希给的 `episodeNumber=01` 一致。映射条目本来就带 `tvdbSeason / tmdbSeason / *EpisodeOffset`（`anime_identity_mapping.dart`），协调器没用。
  - 第二层：MAL 60636 播出中，Jikan 给 `episodes: null`、分集 0 条（「MAL 季集资料不完整：实际取得 0 集」），即便季对上了也没有分集行可绑；而 TMDB 第 2 季 50 集里 E41–48 就是这些文件（Fribb `season.tmdb=2, episode_offset.tmdb=40`）。
- **[x] ① 已修复** — ① `_resolveMappedSeasonHit`：季提示先按映射表的 TVDB / TMDB 季号 + 集偏移解析（同命名空间取偏移最大且小于集号的条目，再用该 cour 集数验一次；TVDB 与 TMDB 解出不同结果取 TVDB 并记说明），命中即写 `episodeOverrides`（cour 序号+1, 集号−偏移）；映射表对该季无季号信息才退回旧的序号法；认识该季但集号落不进任何 cour 只记警告、交人工。② `_SeasonExpansion.tmdbSlices` 带上每个 cour 在 TMDB 剧里的 `(季, 偏移)`，`fillSeasonsFromTmdbSlices`（`video_metadata_merge.dart`）在 TMDB 补充之后按切片 `(offset, offset+count]` 重编成 1..count 补进 MAL 缺集的 cour 季（MAL 已有的集只补空；集数未知时以同季下一个 cour 的偏移为终点、末 cour 到季末）。这是映射表**显式**给的对应，不是拿 AniDB epno 去套 MAL/TMDB 集号（CLAUDE.md 跨站规则不变）。PR #1550（`f264f396926`）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/metadata/tvdb_season_offset_coordinator_test.dart`（Bleach 形状：Fribb 四 cour 同 tvdb S17、MAL 末 cour 0 集、TMDB 假源第 2 季 48 集）：`S17E41/42` → 第 5 季第 1/2 集且分集标题来自 TMDB S2E41/42 切片；`S17E14` → 第 3 季第 1 集用 cour 自己的 MAL 分集、只有 13 集不吞其余；不再落「第 17 季」；`S17E60` 落不进任何 cour → 不绑、记「不在跨站映射表已知的各季集范围内」。既有 `multi_season_coordinator_test.dart`（Frieren 序号法）保持绿。
- **[x] ③ Shoko 集级匹配移植**（同 PR 第 3 个提交）— `tmdb_episode_matcher.dart`：`MatchAnidbToTmdbEpisodes` 的 Dart 移植（四轮从强到弱、定季锁定、标题子串/相似度 + 播出日 ±2 天 / 最近 120 天、弱链接保序）；两个用法：映射表没给切片的 MAL cour 季按分集标题+播出日在 TMDB 里逐集补空（`enrichSeasonsByTmdbEpisodeMatch`），MAL 一集都没有的季用本地文件 AniDB 身份的三语集标题核对后按 AniDB 集号落集并改写成员 (季, 集)（`fillEmptySeasonsFromEpisodeTitles`）。有意差异：`firstAvailable` 只在已锁定季后接受且只往前一条链接之后填。测试：`tmdb_episode_matcher_test.dart`（6 条）、`tvdb_season_offset_coordinator_test.dart`「without mapping offsets, AniDB episode titles verify against TMDB…」。逐项对照见 `docs/specs/2026-09-19-shoko-anidb-tmdb-parity.md`（4.8：TMDB 集名只有资料语言一种，zh 用户走②路径基本不命中，仍靠 Fribb 偏移）。
