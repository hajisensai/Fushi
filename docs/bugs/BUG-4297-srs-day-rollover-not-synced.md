## BUG-4297 · 复习的「今天」日界不随同步、profile 时区字段从没有写入方
- **报告**：2026-11-10（所有者：SRS 多设备「今天」口径审查）
- **真实性**：✅ 真 bug。`SrsDbStore.dayContext()`（`packages/fushi_engine/lib/srs/srs_db_store.dart` 修复前 961–980 行）读 profile 实体的 `dayRolloverHour` / `utcOffsetMin`（`packages/fushi_srs/lib/src/field_edit.dart:154-155`），缺失时回落本机统计日界与本机偏移；但 `fushi/lib`、`packages/*/lib`、`native/fushi_fsrs/src` 里没有任何写入方（`git log -G` 查到这两个键在 lib 里只在 61da4d35d5f / f341d8ec74f 出现过读取与显示名，从没写过）。结果：两台设备统计日界不同时各算各的「今天」（每日上限、到期、今日计数各不相同），「随同步」只是注释里的设计；`utcOffsetMin` 是一条永远读不到值的死分支，按固定偏移同步时区还会在夏令时 / 换时区时出错（`day.dart` 文件头）。
- **[x] ① 已修复** — 翻日时刻接上写入方：用户在统计设置里改日界走 `AppModel.setStatDayResetHourByUser`，本机偏好之外写一条 profile `dayRolloverHour` 字段修改（`SrsDbStore.setDayRolloverHour` → `editField`，随同步 v2 传播）。写不进复习（模块关着 / 打开失败）时按 profile uid 记待写标记（偏好 `srs_day_rollover_pending::<uid>`），这份配置的复习库下次激活时补写（`SrsProfileStores.onActivated` → `AppModel.flushPendingDayRollover`）。同步拉入后 `SrsAppRuntime.adoptSyncedDayRollover` → `AppModel.adoptSyncedDayRollover`：只有生效的修改记录不是本机写下 / 采纳过的那条（偏好 `srs_day_rollover_seen::<uid>`）、且没有待写标记时，才单向改本机统计日界，不写回复习。时区恒用本机：`dayContext` 不再读 profile `utcOffsetMin`，`SrsDbStore.open` 新增 `localOffsetMin`（缺省系统时区）；删掉死常量 `SrsFieldKeys.utcOffsetMin`。首次开复习补 4 点的默认值路径只改本机偏好、从不写复习，单设备用户行为不变。远程复习库（`SrsRemoteStore`）对两个新方法显式抛 `UnsupportedError`。统计设置弹窗在复习模块开着时多一行说明（`stat_center_day_reset_hour_srs_note`）。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/srs_day_rollover_synced_test.dart`（回落值不变 / 写入即生效 / 经同步另一份库取到同值且同一条修改记录 / 存量 `utcOffsetMin` 不再生效 / 改日界后内核每日新卡上限按新「今天」重算）；`fushi/test/srs/srs_day_rollover_user_write_test.dart`（用户写入两处都落 / 仅默认值时字段始终为空 / 模块关闭期间改值→开启后补写、拉入不改回旧值 / 只有新来的修改才改本机 / 远程库显式不支持）；`fushi/test/pages/stat_day_reset_hour_dialog_test.dart`（复习开 / 关时说明行显示 / 不显示）。
- **审查补修（PR #3130）**：三个写入口（`setStatDayResetHourByUser` / `flushPendingDayRollover` / `adoptSyncedDayRollover`）原先各自是多步异步序列、互不排队，采纳又在区外先读好生效值：用户改日界与一次拉入的采纳交错时，采纳拿用户改之前那条修改把本机统计日界改回旧值、复习字段却是用户的新值，且之后生效记录已是本机写下的那条、不会再采纳，两边永久分叉（`fushi/lib/src/models/app_model.dart` `adoptSyncedDayRollover`，`fushi/lib/src/srs/srs_app_runtime.dart` `adoptSyncedDayRollover` 区外 `await store.syncedDayRollover()`）。改为三者经 `AppModel._serialDayRollover` 按调用顺序串行，采纳改收读取函数、在串行区内现读；测试 `srs_day_rollover_user_write_test.dart`「用户改日界与同步拉入后的采纳同时发生」。
- **备注**：未在真 app 里看过统计设置弹窗与说明行，也没用两台真设备跑同步。待写 / 已见标记按前缀登记为设备本地（`PrefRedactionPolicy.deviceLocalKeyPrefixes`）：备份导出剔除、恢复保留本机值、不进 Profile 快照 / 分享、不经设置同步出境（`fushi/test/sync/srs_day_rollover_prefs_device_local_test.dart`）。
