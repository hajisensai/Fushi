## BUG-4033 · 旧 fushi / hibiki 制的卡统计页「制卡来源」认不出出处
- **报告**：2026-11-03（应用内反馈 `Feedback: AhIskigAq3`：旧 fushi / hoshi 制的卡来源识别不出，希望按标签识别）
- **真实性**：✅ 真。统计页「制卡来源」只读 `srs_notes_cache.source_kind / source_title`（`native/fushi_fsrs/src/store/bulk.rs` `stats_bundle`），这两列只由 `SrsSourceRef` 填（`native/fushi_fsrs/src/store/caches.rs:256` `NoteInfo::of`，修复前）。改名前的 Hibiki / 早期 Fushi 制的卡经 Anki 迁进来，没有出处记录，只有制卡标签（`packages/fushi_anki/lib/src/anki_note_composer.dart` `buildNoteTags`：标记 `fushi` / `hibiki` + 分类 `book` / `video`（更早 `anime`）/ `game` / `music`，开「作品名挂在分类下」时 `<分类>::<作品名>`），全归「无出处」。用本机真实库只读副本核对：4048 条出处为空的笔记带 `fushi`（1730）/ `hibiki`（418）标签、分类 `video`（1744）/ `book`（395）。
- **[x] ① 已修复** — 内核 `caches.rs` `source_from_tags`：没有出处记录（含 kind 为空串）且带制卡标记的笔记按标签认 kind，层级标签给作品名（平级作品名标签与用户自己的标签分不开，不猜）；写缓存行时一并推导。老行由 Dart 缓存修订号 9（`packages/fushi_engine/lib/srs/srs_db_store.dart` `_kCacheRevision`、`_upgradeCaches`）调新命令 `backfill_tag_sources` 只补这两列（按缓存行自己的 `tags_json`，同一函数，幂等），已登记 `ffi.rs` `CHANNEL_SETTLES`。提交 `f38e37aab2efd2e5f922df248f558e5ed3babc1a`。
- **[x] ② 已加自动化测试** — Rust：`caches.rs` `source_from_tags_follows_the_mining_tag_contract`、`tag_sources_are_derived_on_cache_write_and_backfilled`（写缓存行推导、有出处记录的以记录为准、补算与写入同值、再跑为 0）；Dart：`packages/fushi_engine/test/srs/srs_stats_columns_test.dart`「没有出处记录的制卡笔记按制卡标签认出处；修订号 8 的老库打开时补齐」（真 SrsDbStore + 统计加载器）；修订号相关的 4 个测试期望改为 9。
