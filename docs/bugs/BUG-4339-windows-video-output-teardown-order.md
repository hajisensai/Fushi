## BUG-4339 · Windows 视频输出拆除顺序错：mpv 渲染上下文在 GL 上下文/共享显示销毁之后、且晚于 Dispose 回复才释放，卡面视频反复开关内存上涨后 libmpv abort / ANGLE AV
- **报告**：2026-11-10（应用内崩溃反馈 uQGVLH5PCG、DKPCqrQ2Y5，均 Windows 3.3.0）
- **真实性**：✅ 真 bug（沿代码路径定位；本批次不跑真机 / 构建，未本机复现）。
  - uQGVLH5PCG：WER 记 `libmpv-2.dll+0x96e0f` 异常 0x40000015（abort）。崩前在 `SrsReviewPage`，`_SrsCardVideoClipState._open` 每 30 s 触发 3–7 次（每张卡 new 一个 Player、翻走即 dispose），RSS 6.6→8.4 GB 持续上涨；图层里始终只有 2 个 `TextureLayer`，Dart 侧组件没有堆积。日志里的 `evt=set-size / recreate-skip-fits` 是 WebView 的 WGC 纹理桥（`packages/flutter_inappwebview_windows/.../texture_bridge.cc`），不是 media_kit，帧池 0 次重建，与本问题无关。
  - DKPCqrQ2Y5：`libGLESv2.dll+0x7ed30` read AV @0x70，栈 `libGLESv2 ← libmpv ×4 ← media_kit_video_plugin ×3`（即 media_kit 渲染线程调用 libmpv，libmpv 再调 ANGLE），`VideoFushiPage`，崩前 1 分钟 RSS 2.35→2.85 GB。minidump `hibiki-18088-2315593.dmp` 未上传，未符号化。
  - 根因 `third_party/media_kit_video/windows/video_output.cc:131-169`（修复前 `~VideoOutput`）：先注销纹理并在渲染线程 `surface_manager_.reset()`——销毁 libmpv 渲染用的 EGLContext，最后一个实例时还 `eglTerminate` 共享 EGLDisplay、释放 libmpv 解码用的共享 D3D11 设备（`angle_surface_manager.cc:206-208` `ReleaseSharedResources`）——之后才把 `mpv_render_context_free` **投递**出去且不等它，执行时没有任何 GL 上下文 current（render_gl.h：所有 mpv_render_* 都隐式使用 GL 上下文）。libmpv 渲染器（GL 对象、d3d11-egl 硬解互操作及其持有的解码帧）于是在已销毁的 ANGLE 状态上拆除。
  - 同时 `media_kit_video_plugin.cc:172-179` 对 `VideoOutputManager.Dispose` **立刻回复**，`video_output_manager.cc:57-64` 在分离线程里才销毁；`Player.dispose`（`ci/patches/hosted/media_kit-1.2.6/.../real.dart:104-113`）await 这个回复后只靠 `Future.delayed(5s)` 再 `mpv_terminate_destroy`。mpv `client.c` `mp_clients_destroy` 在渲染上下文仍存活时 `MP_FATAL("Broken API use: mpv_render_context_free() not called") + abort()`——与 uQGVLH5PCG 的 libmpv abort 吻合；内存压力下（8 GB、换页）渲染线程任务排队超过 5 s 就撞上。
  - 另外两处同一生命周期缺陷：`~VideoOutput` 的 promise 只在注销回调里兑现，`texture_id_ == 0` 时永久卡死 Dispose 线程（持有 manager 互斥量，之后所有 Create/Dispose 一起卡死、Player 永不销毁）；`angle_surface_manager.cc:581-584` `CreateAndBindEGLSurface` 每次 `glGenTextures` 一个绑定 pbuffer 的纹理从不释放，`CleanUp(true)` 在上下文仍 current 时 `eglDestroyContext`（只标记删除）。
  - 两条崩溃的共同点是同一拆除顺序（推断，未用 dump 证实 DKPCqrQ2Y5 栈落在 `mpv_render_context_free`），所以合在一个修复里。内存持续上涨归因于 libmpv 渲染器 / 硬解帧在已销毁的上下文上无法正确释放——这是由代码推断，没有实测 D3D 资源计数。
- **[x] ① 已修复** — `~VideoOutput` 先 `mpv_render_context_set_update_callback(nullptr)`，再在渲染线程一个任务里：注销纹理并等回调 → 让本输出的 GL 上下文 current 后 `mpv_render_context_free` → 释放纹理与 `ANGLESurfaceManager`，析构等该任务完成；`Render` / `CheckAndResize` 见 `destroyed_`（改 atomic）即返回；`VideoOutputManager::Dispose` 加 `on_done`，插件在它里面（主线程）才回复，`mpv_terminate_destroy` 因而必在渲染上下文释放之后；`ANGLESurfaceManager` 记下 `bound_texture_` 并在 `CleanUp` 里 release + delete，销毁上下文前先解除 current。说明见 `third_party/media_kit_video/PATCHES.md`「BUG-4339」。
- **[x] ② 已加自动化测试** — `fushi/test/third_party/media_kit_video_teardown_order_guard_test.dart`（源码扫描守卫：拆除顺序、Dispose 回复时机、destroyed_ 早退、绑定纹理释放；本仓无 C++ 测试设施）。本分支未运行，统一在合并后验证。
- **备注**：未本机复现、未拿到 minidump 符号化、未做 heavy.dart --check-only Windows 构建（本批次验证策略）；需在 Windows 上复测：复习页连续翻带视频片段的卡 100+ 张，RSS 应回落到稳定区间、无 abort；视频页切集 / 退出反复多次无 AV。Linux 版 `VideoOutputManager.Dispose` 同样是立即回复，未改（本次反馈只涉及 Windows）。
