## BUG-2816 · 无头服务端书/漫画根不对账：删掉源 EPUB/漫画卷后条目永远残留
- **报告**：2026-09-30（用户：无头服务端补完盘点，任务 B）
- **真实性**：✅ 真 bug。`packages/fushi_server/lib/src/library_scanner.dart` 的 `scanAll` 对 `book` / `manga` 根只调 `_noteUnreconciled`（只打日志）；根因是 EPUB / 漫画导入把正文拷进 `<documents>/fushi_books/<bookKey>/`（`packages/fushi_engine/lib/epub/epub_importer.dart:179` `epubPath: fileName` 只存文件名；`manga_importer.dart` 恒写 `manga.json`），服务端扫描也不写 `sourceId`，库里没有任何「源文件 ↔ 书」关系，判不出源文件被删。admin `DELETE libraries/<id>?purge=true` 对非 video 根直接 400。
- **[x] ① 已修复** — 不升 schema：书 / 漫画根登记 `media_sources`（kind book / manga）、入库带 `sourceId`；引擎新增 `packages/fushi_engine/lib/media/source_library/book_library_prune.dart`（`BookSourceIndex` 落 `preferences` 键 `media_source_scan_index_<sourceId>`，源相对路径 → 书 uid；`adoptExistingBookForSource` 按保守判据认领旧版扫描进来的存量行；`pruneMissingBookRows` 回收行 + `fushi_books/` 正文副本，不写墓碑、不删源文件）；护栏从视频对账抽成共用的 `library_prune_guard.dart`（`LibraryPruneThreshold` / `LibraryPruneReport` / `libraryRootSkipReason` / `isPathInDetachedSubtree`），视频与书共用；扫描器按索引跳过已认领的源（不再每轮重新解压整本判重复）；admin purge 支持书 / 漫画根。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/media/source_library/book_library_prune_test.dart`（回收 / 所有权 / 未认领存量 / 多源认领 / 三条护栏 / 基线 / 死条目 / 认领判据）、`packages/fushi_server/test/library_scanner_book_prune_test.dart`（真 EPUB 与 mokuro 卷的扫描→删源→重扫回收、存量回填、上传同名书不认领、客户端删书后重导、no-prune、空挂载点）、`packages/fushi_server/test/admin_library_purge_test.dart`（漫画根 / 未扫描书根 purge）。
- **备注**：认领不上的书（同名书是客户端上传 / 手动导入的，或升级前源文件就已删的存量书）不进索引、永不被对账删；有声书附件目录（`audiobooks/`）不随书回收——与 host `deleteBook` 在服务端的现状一致（服务端没接 `cleanupBookOnDisk`）。
