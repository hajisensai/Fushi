## BUG-5200 · Windows 视频每一帧都要等主线程，主线程一忙就被下一帧覆盖丢掉（平移镜头一卡一卡）
- **报告**：2026-11-22（应用内反馈 q5f7uiRd__，Windows 3.4.0-debug.31104：视频平移镜头一卡一卡地掉帧，同片源 PotPlayer 不卡，附对比录像）
- **真实性**：✅ 真 bug，离屏 runner 复现。media_kit 每出一帧在 mpv 渲染线程上调 `MarkTextureFrameAvailable`（`third_party/media_kit_video/windows/video_output.cc:279`），原版引擎把它 `RunNowOrPostTask` 到平台线程（`engine/src/flutter/shell/platform/windows/flutter_windows_texture_registrar.cc:103`），`Shell::OnPlatformViewMarkTextureFrameAvailable`（`engine/src/flutter/shell/common/shell.cc:1318`）再排 raster mark + `ScheduleFrame` 等 vsync。Windows 上平台线程与 Dart UI 线程默认合并，主线程忙过一个视频帧间隔（24 fps 是 41.7 ms），media_kit 已把下一帧画进**同一块**共享 D3D 纹理，这一帧永远不上屏。复现（1080p 24 fps，Dart 主线程每 150 ms 忙等 60 ms，10 s 窗口，原生计数）：原版引擎出 240 帧、上屏 202、丢 38，出帧到取走平均 9.8 ms；空闲窗口丢 0。桌面录屏（gdigrab 60 fps）忙窗口里同一画面停 ≥90 ms 的有 45 处。
- **[x] ① 已修复** — 新引擎补丁 `ci/patches/flutter-engine/3.47.6/engine-texture-frame-raster-thread.patch`：embedder 加 `FlutterEngineMarkExternalTextureFrameAvailableOnRasterThread`，Windows 纹理注册器的 mark 在生产方线程上直接把纹理 id 交给 raster 线程，合并后的单个 raster 任务里 `MarkNewFrameAvailable` + `Rasterizer::DrawLastLayerTrees`，不再经平台 / Dart UI 线程和 Animator（Windows DWM 合成、交换间隔 0，不需要等 vsync）。`build_patched_engine.ps1` 按序打它，引擎产物升到 `hdr-output-5`（`artifacts.json`）。同时 media_kit 原生侧加出帧 / 取走 / 丢帧 / 延迟计数（`VideoOutput::FrameStats`，方法通道 `VideoOutputManager.FrameStats`），视频诊断日志每个采样窗口打一行 `present window=.. published=.. shown=.. lost=..`（`fushi/lib/src/media/video/video_player_controller.dart` `_logPresentStats`，主线程忙时丢帧记 warn），用户再报卡顿时开诊断日志就能直接看是否还在丢帧。补丁引擎同条件实测 240 / 240、丢 0，平均延迟 0.1 ms；录屏 239 个画面、没有 ≥90 ms 的停顿。
- **[x] ② 已加自动化测试** — 引擎单测 `flutter_windows_texture_registrar_unittests.cc`：`MarkFrameAvailableFromProducerThreadSkipsPlatformThread`（独立线程 mark，断言新入口在该线程上同步被调）+ `RegisterUnregisterTexture` 改为旧入口被调即失败（`flutter_windows_unittests` 过滤 TextureRegistrar/View/Engine/CompositorOpenGL 99/99 绿）；源码守卫 `fushi/test/build/texture_frame_raster_thread_engine_guard_test.dart`（补丁存在与顺序、文件清单、注册器不再 post 平台线程、raster 任务里 swap → 清 scheduled → mark → 重画的顺序、proc table 末尾追加）；`fushi/test/diagnostics/video_diag_stats_test.dart` 的 `VideoPresentStats` 组；集成测试 `fushi/integration_test/video_present_main_thread_busy_itest.dart`（真 app、真 media_kit、真原生计数，忙窗口 lost ≤ 2%，原版引擎红、补丁引擎绿）。
- **备注**：用户本机未复测（新引擎随下一个 debug 包发出）。反馈里的片源若是 23.976 fps 高码率，用户机器上主线程卡顿来源可能还有别的（例如字幕 / 弹幕重建），新诊断行会把「仍在丢帧」与「mpv 自身掉帧」区分开。embedder 单测（`embedder_unittests`）本地没编没跑，补丁只新增入口、未改原有入口。
