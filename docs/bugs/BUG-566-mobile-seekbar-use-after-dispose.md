## BUG-566 · 移动版进度条 onPointerMove/onPointerUp 拖动中控件销毁后崩溃
- **报告**：2026-07-06（TODO-1232 A1 审计发现：BUG-235 的补丁只修了 `material_desktop.dart`，漏了移动版 `material.dart` 的同构缺陷）
- **真实性**：✅ 真 bug（BUG-235 的移动端镜像）。vendored `third_party/media_kit_video/lib/media_kit_video_controls/src/controls/material.dart` 的 `MaterialSeekBarState`：`onPointerMove()`（原 1747）与 `onPointerUp()`（原 1763）无条件执行 `controller(context).player.seek(...)`；`controller(context)` → `VideoStateInheritedWidget.of(context)` 解引用 `State.context`。本仓库 `hibiki/lib/src/pages/implementations/video_hibiki_page.dart` 在进/退全屏、切集时经 `VideoControlsFocusGate` 主动卸载 controls 子树——拖动进度条时正好触发即 State dispose、`context` 为 null，指针事件落到已销毁 State 崩 `Null check operator used on a null value`，且该次 seek 全丢。`onPointerDown()` 与 `onPan*` 系列只调已被 `if (mounted)` 守卫的 `setState` / widget 回调、不解引用 context，无需守卫（与 desktop 版处理一致）。
- **[x] ① 已修复**：在 `onPointerMove()` 与 `onPointerUp()` 函数体开头各加 `if (!mounted) return;` 前置守卫（现分别位于 `material.dart:1755` / `material.dart:1780`），注释与 BUG-235 desktop patch 同风格并互相引用；补丁记录追加到 `third_party/media_kit_video/PATCHES.md` 的「BUG-566」节。
- **[x] ② 已加自动化测试**：扩展源码守卫 `hibiki/test/third_party/media_kit_video_seekbar_guard_test.dart`——新增「MaterialSeekBarState (mobile) pointer handlers guard !mounted」group，按花括号匹配抽取移动版 `onPointerUp` / `onPointerMove` 函数体并断言各含 `if (!mounted) return`（防后续重新 vendor 时移动版补丁丢失）。
- **备注**：与 BUG-235 同源：后续升级 media_kit_video 需重新 vendor 并同时重打 desktop + mobile 两处 patch（守卫测试会分别失败提醒）；理想是上游 PR 后回退 vendor。本次为源码审计修复，未在真机复测移动端松手时序，待设备环节验证。
