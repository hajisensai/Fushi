## BUG-743 · 双轨字幕来回弹跳 + 大屏底部双语塌陷重叠
- **报告**：2026-07-12（用户：给真实 fansub `双语.ass`（喵萌 Ruri no Houseki，Dial_JP MarginV=4 + Dial_CH MarginV=30 底部双语）与 `Shunkashuutou…ToonsHub.ass`，报「双轨字幕会来回弹跳。字幕样式还是有问题」）
- **真实性**：✅ 真 bug（离屏用真实 .ass 复现，两个独立根因）
  - **① 弹跳** 根因：`packages/hibiki_audio/lib/src/parsers/json_alignment_parser.dart:155` `findActiveCueIndices` 用**闭区间** `positionMs <= cue.endMs`。相邻对白（前条 `endMs` == 后条 `startMs`，fansub 极常见，如本文件 `0:00:53.20` 收尾即下句起始）在那一毫秒**两对 cue 同时活跃**（前条未退场 + 后条已进场）。视频字幕竖排堆叠槽位表 `video_subtitle_overlay.dart` `_syncGroupSlots`（step②「新 cue 补最靠锚点空槽、没有才追加远端」）在这一帧所有锚点槽都被旧 cue 占着 → 后进 cue 被追加到**远端槽**；旧 cue 退场后 step③ 只裁**尾部**死槽，锚点侧死槽当隐形占位保留，把后一条持续顶离基线，直到出现间隙整组清空才复位。表现：连续对白里字幕被抬高、间隙落回，**来回弹跳**。离屏 @1080 逐帧追踪：`t=53.2s→54.4s` JP/CH 带整体上下跳 201px。
  - **② 大屏塌陷重叠** 根因：`hibiki/lib/src/media/video/video_subtitle_overlay.dart:638` `_positionKey` 折叠判据 `scaledMarginV <= bottomPadding` 依赖显示区高（`_scaledMarginV = marginV * 显示区高/PlayResY`）。大屏（显示区高 >> PlayResY，如 2160 高 / PlayResY 720）时第二语言 CH MarginV=30 缩放成 90 > bottomPadding=75 → 脱离基线折叠桶、独立成组，与仍折在基线的 JP 各自定位却落在相邻高度、大字号盒相交（BUG-709 仅大屏回归）。离屏高度扫描：H≤1800 `ok-gap`，H≥1820 `<<< OVERLAP`（阈值 30×H/720=75 → H≈1800）。
- **[x] ① 已修复** — 提交 `<pending>`。
  - ①弹跳：`findActiveCueIndices` 增 `bool endInclusive = true`（默认真保 HBK-AUDIT-153 契约与有声书 `findCueIndex` 一致）；视频**渲染集**两处调用（`video_player_controller.dart` `_activeRenderIndices` 主字幕 + `_syncCueForPosition` 副字幕）传 `endInclusive: false` 走**半开区间** `[start, end)`——相邻对白边界只后一条活跃，后进 cue 复用被腾空的锚点槽，弹跳根除。末条无后继时靠 `_activeRenderIndices` 并入的 `findCueIndex`（仍闭区间）代表 cue 兜底，不提前 1 tick 消失；重叠 cue 全显（TODO-1312）不回归。
  - ②重叠：`_positionKey` 底部锚点折叠判据改用**原始 MarginV**（`mvRaw <= widget.bottomPadding`，PlayRes 像素、显示无关，且以原始值入键使组身份不随窗口缩放漂移）。任何显示尺寸下 MarginV≤基线的底部对白恒折叠堆叠，只有真正高位标题（大 MarginV）独立占 authored 高度（TODO-1341 不回归）。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_subtitle_dual_bounce_test.dart`（3 例：①触边界后续存对白同基线不抬高；②2160 高 JP/CH 不重叠且 CH 堆叠在上；③触边界渲染集只后一条）。已验证 3 例在**未修复代码上全部失败**、修复后全绿；`find_active_cue_indices_test.dart`（HBK-AUDIT-153 闭区间默认）+ BUG-709/TODO-1341/1372/1312/BUG-684 既有守卫无回归。

- **追加（用户「样式最好完整呈现」）**：审计两文件全部 ASS 特性后补齐两项真缺口——
  - **③ MarginL/MarginR 水平边距整体缺失**：Style 行只捕获 MarginV（`ass_parser.dart` `_parseStyleRow`）、Dialogue 行级 Margin 覆盖列整体被忽略（只读 start/end/text/style 列）、渲染端只有竖直 padding。字幕组用行级 `MarginL=900` 把对白横移到说话人一侧（Shunkashuutou `気持ちは分かるが`）、`MarginR=500` 左移（双语 Dial_JP2）、an7 招牌样式 MarginL=40 左缘偏移——全被错误渲染成屏幕居中 / 贴左缘。修复：`SubtitleCueStyle` 加 `marginL/marginR` + `withEventMargins`（行级 >0 覆盖走 clone，共享样式实例不被污染）；`SubtitleMarkup` 加 `playResX` 透传；overlay 加 `_scaledMarginX`（显示区宽/PlayResX 缩放），`_paddingFor` 加水平 padding（Align 内侧 padding 数学恰等价 ASS 排版盒 `[L, W-R]`：居中偏移 (L−R)/2、左/右对齐贴盒缘），`_positionKey` 纳入原始 L/R（不同水平盒不同组）。
  - **④ `\N` 硬换行被压成空格**：作者排好的两行变一长行。修复：parser 内部以 `\n` 占位、扫描后记录 grapheme 下标进 `SubtitleMarkup.lineBreakGraphemes` 并替换回空格——**plainText 与历史逐字节一致**（查词/制卡/DB 零变化），仅渲染层 `_buildCueBox` 按断点切成多行 Column（断点空格不渲染，libass 同语义）。
  - 测试 `hibiki/test/media/video/video_subtitle_margin_break_test.dart`（4 例：样式捕获+行级 clone / MarginL=900 中心 (L−R)/2 / an7 左缘 / `\N` 两行+plainText 不变）；真实两文件离屏实测 MarginL=900→中心 1395（修复前 960）、MarginR=500→中心 395（修复前 640）、`\N` 块高 170（两行）全部精确命中；`test/media/` 全套 2485 无回归。仍不支持（两文件未用）：`\k` 卡拉OK、`\clip`、3D `\frx/\fry`、样式表 Angle/ScaleX/Y/BorderStyle=3、内嵌字体附件。
