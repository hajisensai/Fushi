## BUG-4007 · 歌词模式自动播放一段后后面的文字空白、拨过去整页刷新
- **报告**：2026-11-03（用户：「在自动播放到一定程度的时候，后面的文字是空白，拨过去以后会重新刷新加载……不可接受有空白的情况」）
- **真实性**：✅ 真 bug。歌词文档只装当前句前后各 300 句的窗口（`kLyricsModeMaxInitialCues = 600`，`LyricsCueWindow.select`），播到窗口尾部后面就没有句子；播放越过窗口边界才在 `_syncLyricsOverlayCue` 里整页 `_loadLyricsPage()` 重载（upstream/develop `fushi/lib/src/pages/implementations/reader_fushi/lyrics.part.dart:961`）。
- **[x] ① 已修复** — 滑动窗口原地拼接：`_slideLyricsWindow`（`reader_fushi/lyrics.part.dart`）在播放离窗口边缘不足 `kLyricsWindowEdgeMargin` 句、或 JS 报窗口首 / 末句进入视口外扩一屏（`onLyricsEdge`）时，用 `LyricsModeHtml.cueRowsHtml` 生成一段 `kLyricsWindowChunk` 句交给 JS `__lyricsSpliceCues` 原地插入，并卸掉离当前句足够远的另一端（窗口常驻上限不变）；拼接按锚点句补偿滚动、关掉浏览器滚动锚定。只有拖到窗口外很远才整页重载。提交见本 PR（`pr/lyrics-bottom-bar`）。
- **[x] ② 已加自动化测试** — `fushi/test/media/audiobook/lyrics_sliding_window_test.dart`（增量行不带 current/near、首尾标记、拼接 / 边缘请求 API、播放近边缘先滑动后重载的源码守卫）。
- **备注**：拼接 JS 只有生成器 / 源码层测试，DOM 行为在 Windows 调试实例上人工看过；三种 view mode 不适用（歌词覆盖层是独立文档）。Mac WebKit 未复测。
- **复审 R1（PR #2828 合入后审查，major）**：「窗口常驻上限不变」在手动浏览时不成立。根因：`_slideLyricsWindow` 的裁剪量只按播放句 `ctrl.lyricsCueAllBookIdx` 前后各留 `kLyricsWindowKeep` 算（合入版 `reader_fushi/lyrics.part.dart:961-974`）；暂停后一路往后滑，播放句钉在 start+300，第一次拼接后 `limit = cur-150-newStart = 0`，此后每段净加 200 句（650 → 850 → … → 整书），DOM、IntersectionObserver、全量收藏重标、resize 全量测宽随之线性变大。
  - **[x] ① 已修复** — 上限对「锚点」生效：裁剪计算收进纯函数 `planLyricsWindowSlide`（`fushi/lib/src/media/audiobook/lyrics_cue_window_slide.dart`），补装量受「另一端最多能卸多少」约束，窗口长度恒 ≤ `kLyricsModeMaxInitialCues`，锚点前后各 `kLyricsWindowKeep` 句永不卸。锚点：跟随播放（「跟随音频」开、JS 不在浏览态、焦点环不在歌词上，`_lyricsFollowsPlayback`）时是播放句；手动浏览时是视口中线句（JS `onLyricsEdge` 第三个参数 `_lyViewAnchorIndex()`）。JS 浏览态的进出经唯一写入口 `_lySetBrowsing` 回报 Dart（`onLyricsBrowse`）；浏览中播放推进不滑窗口、播放句走出窗口只摘高亮（`__lyricsSetCue(-1,false)`）不重载；回到跟随（浏览结束 / forceReveal / 退出歌词焦点环）时按播放句重推，播放句不在窗口里就以它为锚重开。`__lyricsSpliceCues` 的补偿锚点改为优先视口中线句、退回当前句，取拼接后第一个仍在文档里的，视口内的行不跳位。顺带：没下发拼接时 Dart 调 `__lyricsEdgeIdle` 复位 JS 同向请求位（此前提前 return 会让该方向永久不再请求）；点句跳播先回传 `onLyricsCueTap` 再退出浏览，免得退出浏览触发的重开让窗口内下标失效。
  - **[x] ② 已加自动化测试** — `fushi/test/media/audiobook/lyrics_cue_window_slide_test.dart`（暂停后手动往后 / 往前连续浏览 40 / 20 次：每次拼接后窗口 ≤ 上限、视口中线句 ± keep 句一直在窗口里、浏览方向真的前进；锚点钉在暂停播放句时卸不动就不再补；跟随 / 无锚点 / 首尾边界）；`lyrics_sliding_window_test.dart` 补源码 / 生成文档守卫（浏览中不滑不重载、edge 带视口锚点、浏览态只经 `_lySetBrowsing` 写、拼接锚点优先中线句）。
  - **view mode**：歌词覆盖层是独立的歌词 WebView 文档，与小说阅读器的 `paginated` / `continuous` / `vn` 排版无关，三种 view mode 不涉及。JS 拼接的真实 DOM 滚动补偿未在设备上复测（本轮只有纯函数与源码层测试）。
