## BUG-762 · 词典弹窗长按释义弹原生选择菜单后卡住
- **报告**：2026-07-12（用户：qqbotxiaoxiao）
- **真实性**：✅ 真 bug。根因 `hibiki/assets/popup/popup.css:43`（全局 `-webkit-user-select:text` 且**无** `@media (pointer:coarse)` 触屏抑制，对比阅读器 `hibiki/lib/src/reader/reader_content_styles.dart:563-569` 有此抑制）。词典弹窗 WebView 在 Android 是原生平台视图，宿主 `dictionary_popup_webview.dart` 又故意保留原生 ContextMenu + 250ms LongPress 引原生选区（`kPopupNativeSelectLongPressDuration`），native 侧无 ActionMode 拦截。触屏长按释义文本 → WebView 进原生选区态 → 系统 ActionMode 浮动工具栏（翻译/复制/分享/全选/网页搜索/朗读/AI写作）弹出并接管该区域后续触摸 → 弹窗关不掉、点击无响应，观感「卡死」。查词根本不走原生选区（`assets/popup/selection.js` 程序化 caretPositionFromPoint + CSS Custom Highlight）。
- **[x] ① 已修复** — 与阅读器 TODO-1279 同款触屏抑制：`hibiki/lib/src/pages/implementations/popup_settings_injection.dart` 新增 `_touchNoSelectStyleJs`，以 id 守卫 `<style id="hoshi-popup-touch-noselect">` 幂等注入 `@media (pointer:coarse){html,body,body *{-webkit-user-select:none!important;user-select:none!important;-webkit-touch-callout:none!important}}`。CSS 层自门控——桌面细指针（Windows 裸 WebView2 全局查词）不受影响；三种弹窗表面（in-app / 视频 / app 外悬浮）共用同一注入体一处覆盖。**刻意不放进共享 popup.css**（那份被 content.css 生成器 re-root 进浏览器扩展宿主页会误杀扩展触屏选文本，且生成器不支持 @media 嵌套 at-rule 会抛错）。提交：cc6484e87
- **[x] ② 已加自动化测试** — `hibiki/test/dictionary/popup_touch_native_selection_guard_test.dart`（源码扫描守卫：注入体含 coarse-pointer user-select/touch-callout 抑制 + id 守卫幂等）。
- **备注**：真机验证待用户（Android 词典弹窗长按释义不再弹系统 ActionMode / 不再卡死）。
- **⚠️ 已撤回（见 [BUG-926](BUG-926-popup-touch-copy-disabled.md)）**：本修复的 `_touchNoSelectStyleJs` 用 `body *` `!important` 全量禁选，把 popup.css 已精细分区的「正文可选」也碾平，导致触屏**无法复制词典释义**（1.2.0 用户报）。而本 bug 担心的「ActionMode 接管→关不掉」其实已被 `popup.js:3616` 的 click 处理器化解（有选区先 removeAllRanges 再 return）+ chrome 关闭按钮在 WebView 外兜底。BUG-926 已删除该注入，回落到 popup.css 逐元素选区分区；守卫测试 `popup_touch_native_selection_guard_test.dart` 随之反转。
