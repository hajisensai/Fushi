## BUG-697 · 视频全屏路由内手柄仅B返回可用（A/D-pad静默no-op）
- **报告**：2026-07-10（用户：TODO-1378「视频手柄小 bug：全屏模式后只有 B 键返回能用、窗口模式正常」）
- **真实性**：✅ 真 bug — 根因 `hibiki/lib/src/pages/implementations/video_hibiki/fullscreen.part.dart:78`（`_pushNeutralizedVideoFullscreen` 的 `PageRouteBuilder` 只含 Video 子树，`:166` 推到根 navigator）。窗口模式在 `video_hibiki_page.dart` `build()` 最外层用 `_wrapVideoGamepadControls`（`:5184`，Actions<GamepadButtonIntent> + 旁观 Focus）包住整页；全屏是根 navigator 上的独立路由，这层 wrapper 不是其祖先。桌面手柄轮询以 `primaryFocus.context` 为派发起点（`gamepad_service.dart:457` `_dispatchContext`），进全屏后共享 `_videoFocusNode` 被全屏侧 controls 持有，`Actions.maybeInvoke<GamepadButtonIntent>` 沿全屏子树元素树向上无人消费 → A 落 `ActivateIntent` 兜底（`:483`，视频焦点节点无 activate 语义）、D-pad 落方向焦点遍历兜底（`:496`，子树内无可聚焦兄弟）→ 全部静默 no-op；仅 B 走 `navigatorKey.maybePop` 全局返回兜底（`:486`，与焦点树无关）存活。仅桌面受影响（移动端 BUG-221 起永不进全屏路由）。
- **[x] ① 已修复** — `fullscreen.part.dart` 全屏路由 `pageBuilder` 内容包进与窗口模式**同一个** `_wrapVideoGamepadControls(Material(...))`（part-of extension 直调主壳私有方法，零新概念、不在 gamepad_service 加全屏特判）：全屏子树获得与窗口完全一致的手柄语义——A=播放/暂停、D-pad 左右=快退/快进、上下=音量、X/Y=上/下一句字幕、LB/RB=快退/快进、LT=重听当前句、RT=切换全屏、Start=字幕跳转列表、B=videoEscape 逐级退出（先关浮层/字幕列表/侧栏再退全屏，比修复前的裸 maybePop 更符合逐级退出直觉；`_videoControlsContext` 在全屏期间即全屏子树 context，`isFullscreen` 判定正确走 `_exitVideoFullscreen`，不会误退整页）。执行体与键盘/窗口手柄共用 `_buildVideoShortcutActions`（含沉浸门控），改键即时生效。提交哈希：见分支 `todo1378-fullscreen-gamepad`。
- **[x] ② 已加自动化测试** — `hibiki/test/pages/video_fullscreen_gamepad_dispatch_test.dart`（同构 harness 行为测试，沿 `video_fullscreen_focus_gate_test.dart` 范式：真实 registry/videoActionCallbacks/dispatchGamepadButtonIntent/gamepadMoveFocusInDirection，镜像 service 分发决策树；修前形状复现 A/D-pad 静默 no-op + B 兜底可用，修后形状断言 A/D-pad 四向/B 全部命中窗口模式语义）+ `hibiki/test/pages/video_fullscreen_gamepad_wiring_static_test.dart`（源码守卫：全屏 pageBuilder 必须包 `_wrapVideoGamepadControls`、窗口侧 build() 同 wrapper 不被拆，已验证在未修复代码上变红）。真实页面无法 headless 加载（无 libmpv），此为最强可落地层。
- **备注**：真手柄真机终验留给验收轮（Windows 桌面 + 实体手柄进全屏按 A/D-pad/B）。全屏切换本身行为（BUG-120/121 守卫）未触碰：只在 pageBuilder 外围加了一层无焦点 wrapper，路由推送/复位/焦点归还逻辑零改动。
