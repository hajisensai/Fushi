## BUG-5368 · sync-peer-offline-sweep-failure
- **报告**：2026-11-24（应用内反馈 AND29vti1l：互联对端离线时后台任务明细每轮多一条失败项，内容是裸英文，标题还是过时的进度阶段）
- **真实性**：✅ 真 bug。复现：手机配了互联、电脑没开 Fushi 或不在同一网段，开机 / 定时 sweep 时 `InterconnectSyncBackend` 抛 `SyncPeerUnreachableError`（`fushi/lib/src/sync/interconnect_sync_backend.dart:104`），后台任务明细里每轮多一条「正在读取远端文件清单 · 已结束，1 项失败」（最多留 `kSyncTaskBoardFinishedKeep`=3 条，红点常亮），内容是 `sync channel (interconnect=true): SyncBackendError: No reachable Fushi server address`。三处根因：① `fushi/lib/src/sync/sync_auto_trigger.dart` 自动 sweep 的逐通道 catch（原 :874-884）不分错误类型，一律 `anyChannelFailed = true` + `task.error`，把 BUG-5262 已认定为预期状态的对端离线算成失败；合集轻量同步（原 :1650）与退出书同步（原 :1912）同样如此。② 同文件五处 `task.error('… (interconnect=…): $e')`（sweep / 手动立即同步 / 资产传输 / 合集 / 退出书）把原始异常拼进用户看的任务表，绕过 BUG-1693 的 `friendlySyncErrorDetail`（`fushi/lib/src/sync/sync_error_messages.dart`）。③ `fushi/lib/src/sync/background_tasks_indicator.dart` `syncTaskToBackgroundTask`（原 :93-95）对已结束的任务仍拿最后一个进度阶段当标题。
- **[x] ① 已修复** — 新增 `SyncOutcomeReason.peerOffline`（`sync_activity.dart`）：自动 sweep / 合集 / 退出书三条自动路径遇 `SyncPeerUnreachableError` 跳过该通道，不写 `task.error`、不算失败，本轮结局记 `peerOffline`（排在 failed / cancelled 之后、completed 之前），设置页「上次同步」显示新 key `sync_last_peer_offline`；`noteAutoSweepOutcomeForBackoff` 对 `peerOffline` 同样推进失败退避，保住 BUG-1569① 不每分钟重付候选探测。手动「立即同步」/ 资产传输是显式意图，对端离线照常报错。五处 `task.error` 统一走 `_channelTaskError`：本地化通道名（+ 书名）+ `friendlySyncErrorDetail`（`SyncChannelAuthError` 先拆出内层 `SyncAuthError` 再分派）。`syncTaskToBackgroundTask` 只对在跑的任务用进度阶段，已结束的标题用 `syncActivityLine`、不带进度分数。
- **[x] ② 已加自动化测试** — `fushi/test/sync/sync_peer_offline_auto_sync_test.dart`（假通道：sweep / 合集 / 退出书遇对端离线结局 peerOffline 且任务表为空、仍推进退避；云通道真失败时失败项是「云备份: 网络友好文案」不含原始异常；手动立即同步照常抛、失败项是「互联: 对端离线友好文案」）；`fushi/test/sync/sync_auto_trigger_lifecycle_test.dart`（真实死端口集成：第一轮 peerOffline、任务表空、退避后第二轮 cooledDown；退避状态机含 peerOffline）；`fushi/test/sync/background_tasks_indicator_test.dart`「已结束的失败轮次标题说这轮是谁，不沿用最后一个进度阶段」。
- **备注**：补完 BUG-5262 备注里「完整同步这条路径没改」的缺口。
