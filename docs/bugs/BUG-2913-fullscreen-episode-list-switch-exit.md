## BUG-2913 · 全屏下从剧集列表换集会退出原生全屏
- **报告**：2026-10-03（用户：「剧集列表跳转集数会退出全屏」，Windows，本地合集）
- **真实性**：✅ 真 bug。Windows itest 复现（`win-itest-20261003-162750`）：全屏下鼠标点剧集横轨卡片换到第 2 集，t≈1.2s 起原生全屏掉线（窗口回到 2144×1431，Flutter 仍是全屏布局）。临时在 `WindowCaptionChannel.setFullscreen` 打栈定位到调用方。
  - 根因：换集是「接管」而不是 pop（`fushi/lib/src/pages/implementations/video_fushi/episode.part.dart` `_switchEpisode`：push 新集页 → `removeRoute` 旧全屏路由与旧集页）。被 `removeRoute` 摘掉的旧集页要等新页入场过渡结束才真正 dispose；这时新页已经就绪并经 `_pushNeutralizedVideoFullscreen` 压上了自己的全屏路由。旧集页的 `WindowFullscreenHost` 卸载时在帧末判 `hasVisibleHost`（`fushi/lib/src/shortcuts/window_fullscreen_hosts.dart:103`）：新集页路由被全屏路由盖住、不是 current，而**全屏路由自己从未登记为宿主**（`fushi/lib/src/pages/implementations/video_fushi/fullscreen.part.dart` `_pushNeutralizedVideoFullscreen` 的 `pageBuilder`）——注册表里没有可见宿主，于是 `exitWindowFullscreenIfActive()` 把用户正在看的全屏退掉。自动连播之所以不触发只是时序上新页就绪更晚，不是逻辑上安全。
- **[x] ① 已修复** `58c4891c85` — 全屏路由 `pageBuilder` 的根包一层 `WindowFullscreenHost`：全屏路由本就是窗口全屏的合法宿主，在栈顶时注册表即有可见宿主，任何宿主离场都不会再误归还全屏；用户真正离开内容页（全屏路由与页面一起出栈）时归还逻辑不变。F11 门（`_toggleWindowFullscreen`）在视频全屏态下原本就因真值为 true 放行，行为不变。
- **[x] ② 已加自动化测试** `58c4891c85` — `fushi/test/shortcuts/window_fullscreen_hosts_test.dart`「BUG-2913」组：按真实接管时序（宿主页 → 压全屏路由 → `removeRoute` 宿主页）断言不调 `setFullscreen(false)`，并附反向对照（全屏路由不登记时会退全屏）；`fushi/test/pages/video_fullscreen_gamepad_wiring_static_test.dart` 钉住页面接线；端到端 `fushi/integration_test/video_fullscreen_episode_list_switch_test.dart`（鼠标点卡片来回换集、每 500ms 采样原生全屏，修复后 `win-itest-20261003-163509` 两次换集零掉线、截图 3840×2160）。
- **备注**：顺带发现——全屏剧集横轨里键盘 / 手柄焦点落不到剧集卡片上（`requestFocus` 后 primary 仍是视频键盘节点，Enter 不换集），itest 因此改用鼠标驱动；未在本条修，待单独确认是否影响真实手柄用户。
