## BUG-580 · 互联下载有声书 EPUB 落盘 rename 失败中止导入
- **报告**：2026-07-07（用户：TODO-1286，「hibiki 互联没导入有声书，并且标识也没变」）
- **真实性**：✅ 真 bug。根因 `hibiki/lib/src/epub/epub_importer.dart` 的 `moveExtractedDirIntoPlace`（旧 251/262/272 行）用裸 `srcDir.renameSync(...)` 把刚解压的 `.tmp-<ts>` 目录搬到以 bookKey 命名的正式书目录。Android 应用存储层（fuse/sdcardfs、以及数据根落在可移动卷时的自定义根）可能对目录 `rename(2)` 直接抛 `FileSystemException: Rename failed, path = '.../hoshi_books/.tmp-<ts>'`。该异常从 `_importRemoteBookFile`（`reader_history/remote.part.dart:559`）→ `EpubImporter.importFromPath` 冒泡，被 `_downloadRemoteBook` 的通用 `catch`（`reader_history/remote.part.dart:422`）吞成「下载失败」并 `return`——于是**有声书补下载（`_downloadRemoteAudiobook`）、书架刷新与同步标识/ShelfEntry 更新都没执行**，正是用户「有声书没导入 + 标识没变」的完整因果链。BUG-564（`d8ae86f14`）只处理了目标目录已存在非空（ENOTEMPTY）子情形，最终 `.tmp → targetDir` 仍是裸 rename，残留失败模式仍会整链中止。
- **[x] ① 已修复** — `moveExtractedDirIntoPlace` 三处 `.tmp-<ts> → 目的地`（target-missing / owned `~n` 兄弟 / unowned 原子替换）统一改走新增私有 helper `_moveDirInto(src, dest, {forceCopy})`：先 `renameSync`，捕获 `FileSystemException` 后回退到 `_copyDirSync` 递归复制 + `deleteSync` 源（copy+delete 是可移植的目录移动原语，不会像 rename 那样因 ENOTEMPTY/ENOTDIR/EXDEV 失败）；复制中途失败会清掉半成品目的地，保证 unowned 分支的 `.bak` 回滚落在干净路径上。真实修复位置 `hibiki/lib/src/epub/epub_importer.dart`（`moveExtractedDirIntoPlace` / `_moveDirInto` / `_copyDirSync`）。提交见本轮。
- **[x] ② 已加自动化测试** — `hibiki/test/epub/epub_importer_existing_target_dir_test.dart` 新增组「EpubImporter.moveExtractedDirIntoPlace copy+delete fallback (TODO-1286)」：以 `forceCopyFallback: true` 确定性地驱动 copy+delete 分支（真实 rename 失败无法跨平台复现），覆盖 target-missing（含嵌套子目录证明递归复制、源被删）、unowned 非空目标（新内容取胜、旧孤儿清除、无 `.bak` 残留）、owned 活跃行（活跃目录不动、新书落 `~2`）三条路径。BUG-564 既有单测与端到端导入测试保持全绿。
- **备注**：Android 目录 rename 的确切 errno 需真机复现（内部 `/data/user/0/.../app_flutter/hoshi_books` 同卷通常仅 ENOTEMPTY，可移动卷/自定义数据根或 fuse 层可返回其它错误）。copy+delete 回退是移动语义的正确原语，非吞异常式补丁：rename 成功时行为逐字节不变，仅在平台拒绝 rename 时才复制。真机验收口径：互联下载带有声书的远端书 → EPUB 与有声书都导入成功、书架出现该书且有声书可播、同步标识更新。
