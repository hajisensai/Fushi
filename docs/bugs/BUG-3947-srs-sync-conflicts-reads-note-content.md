## BUG-3947 · 牌组列表的冲突角标把整库笔记正文读回来，大库同步 / 导入后原生内存分配失败闪退
- **报告**：2026-11-01（应用内反馈 i8qNDs_V_D「srs 同步时闪退」、lGXA8zC1A2「打开同步与历史时闪退」、U37Aku3oeL「导入卡片崩溃」；同一用户同一台小米 shennong / Android 16，同一台互联 host，约 1.9 万张卡，导入过 Windows 端导出的 apkg）
- **真实性**：✅ 真 bug（代码路径已验证；与闪退的对应是强推断，见备注）。
  - 日志证据：i8qNDs_V_D `Process.androidExitInfo reason=CRASH_NATIVE SIGABRT`，栈 `scudo::reportMapError … (Out of memory)`，线程 `DartWorker`，pss 1.37 GB；lGXA8zC1A2 同一签名（`Scudo ERROR: internal map failure (error desc=Out of memory)`）。同一台设备 3.1.0-debug.22074 的统计页曾报 `SrsCore.exec` → `asTypedList` `length must be in the range [0, 1073741823]`（`SrsDbStore.allNoteViews`）：这个库的笔记正文 + 修改记录物化一次就超过 1 GiB。`allNoteViews` 已在 af13213f3a 删除，但同类的整库正文物化还剩下面这一处。
  - 根因：`packages/fushi_engine/lib/srs/srs_db_store.dart` `syncConflicts()`（修前 4172–4222 行）按 `GROUP BY entity_kind, entity_id, field_key HAVING COUNT(*) > 1` 读回**所有**多候选字段键的修改记录原文（`CAST(e.json AS BLOB)`），读回来之后才在 Dart 里按 `srsFieldClassOf` 把内容类（笔记字段正文）与界面状态丢掉。笔记 ID 由 `SrsIds.note(profileUid, guid)` 确定（`srs_apkg_import.dart:1612`），两台设备各自导入同一个包（或各自写下同样的正文）后，每条笔记每个字段都留着两条互不支配的记录（`native/fushi_fsrs/src/store/sync2/mod.rs` `land_edit` 只删被支配的），这条查询就把整库正文读两遍。Rust 侧 `query_rows`（`native/fushi_fsrs/src/store/mod.rs:188`）先物化全部行再编码，在 Drift 后台 isolate（DartWorker 线程）上分配 GB 级内存。
  - 触发频率：`srsConflictCountProvider`（`fushi/lib/src/srs/srs_providers.dart:735`）watch `srsRevisionProvider`，每轮同步落了东西、每次导入结束都 +1，牌组列表（复习 tab）活着就重跑一遍；同一 Drift 执行器串行，这条大查询跑着时牌组列表的查询排在后面（U37Aku3oeL「导入完卡片没显示，后来崩了一次才出来」）。冲突中心、牌组设置页、控制通道 `/srs/conflicts` 也调它。
- **[x] ① 已修复** — 字段类别改成一张规则表（`packages/fushi_srs/lib/src/field_edit.dart` `_kSrsFieldClassRules`），`srsFieldClassOf` 与新的 `srsFieldClassSqlFilter` 都只读它；`syncConflicts` 在 GROUP BY 子查询里加 `srsFieldClassSqlFilter({flag, setting})`，内容类 / 界面状态的记录在 SQLite 里就筛掉、一条不读回。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/srs_field_class_sql_test.dart`（全部实体种类 × 全部字段键 × 全部类别子集，真 SQLite 求值与 `srsFieldClassOf` 逐项比对）；`packages/fushi_engine/test/srs/srs_db_store_test.dart`「同步冲突只读标志 / 设置类…（BUG-3947）」：两台设备 20 条笔记各写同样正文 + 一个 suspended 冲突，断言冲突只有那张卡、`debugSyncConflictRowsRead == 2`（去掉筛选时读回 42 条，测试变红，已实测）。
- **备注**：
  - 闪退与这条查询的对应是**推断**：退出原因只给到「DartWorker 上原生分配失败」，没有带帧的栈；同一库上另一处整库物化（`allNoteViews`）已用日志坐实超过 1 GiB。i8qNDs_V_D（3.2.0-debug.22671）死在复习同步面包屑 `stage=start` 阶段（链接 profile / 位置身份 / 旧根迁移 / 握手 / plan，这一段没有细分面包屑），启动 9 s 时 RSS 已约 1 GB，常驻内存的其它大户（RWKV 状态、浏览会话的字段语料、SQLite mmap 每连接 256 MB）这里没有逐项量化。
  - 未在真机复测；需要反馈人更新后确认。
