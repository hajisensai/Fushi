## BUG-2810 · iOS 分页打开书振假名压进基字（度量脚本量到跨栏被切开的注音盒，拉力顶到 1.5）
- **报告**：2026-09-30（用户：「ios之前修行高又修坏了振假名了」，截图为 iOS 竖排分页、Klee One、注音淡显，「雪ノ下」「秤」「謎」的振假名压在基字右半边上；补充「我用的是这本书（やはり俺の青春ラブコメはまちがっている。ガガガ文庫，带有声书），ios 的分页模式一打开就是这样」）
- **真实性**：✅ 真 bug（WebKit 分页专属，取决于字号 / 字体 / 本章第一颗注音落在哪一页）。根因 `fushi/lib/src/reader/reader_ruby_metrics_script.dart:56`（修前）：BUG-2779 的度量脚本拿文档里第一颗 `<ruby>` 的 `rt.getBoundingClientRect()` 当注音盒。分页多列里落在**页顶那一行**的注音会伸出本栏顶、被切进上一栏（BUG-2761 的几何：页顶预留 R 只按行高算，度量写入前的缺省拉力 0.1 下 Klee One 42px 的注音盒伸出行盒 ≈ 19.6px > R 13.65px），此时 `<rt>` 有两个 client rect，外接矩形是两页的并集——竖排宽 ≈ 整页。按它算出的拉力远超上限，被 `:99` 夹到 1.5，整章注音的 `margin-block-end` 变成 −1.6em，压进基字。
  - 截图量值（1206 × 2622，dpr 3，字号 ≈ 42px）：注音墨迹中心离基字列中心 14–16 CSS px；Klee One 下拉力 1.5 推算 13.8px、正确值（≈0.8）推算 26.9px——与夹到上限吻合。
  - 复现（iOS 26.5 模拟器 Safari；这本书的真实章节 `text/part0017.html` + 书自带 CSS + `ReaderContentStyles.css` 生产 iOS 竖排分页 CSS（行高 1.65、42px、淡显注音）+ 生产度量脚本，Klee One）：本章首颗注音「由（比ヶ浜）」在第 3 页首列；缺省拉力下 158 颗注音里 68 颗的 `<rt>` 跨栏两段，首颗的外接矩形 385.9 × 818px；脚本写出 `--fushi-ruby-pull: 1.500`，截图与用户一致（ゆき / はかり / なぞ 压进基字）。同一章 22px 时首颗注音在第 1 页、不跨栏，写出 0.813——所以只有字号 / 布局让首颗注音落到非首页页顶时才「一打开就这样」。
  - 与「修行高」（BUG-2799）的关系：把 BUG-2799 的 `!important` 去掉（回到修前、书的 `.middle-block { padding: 0 }` 压掉预留），同一章照样写出 1.500。BUG-2799 只是让段落位置整体挪了，病根是 BUG-2779 引入的度量脚本没排除跨栏的注音盒。
- **[x] ① 已修复** — 度量只认排成一整段的盒：`<rt>` 的 `getClientRects()` 必须恰好一个，否则跳过这颗、量下一颗（前 50 颗里找）；基字改量第一个非空白字符（代理对取两个码元）的单字 Range，同样只认一段（内容区逐字相同，单字也不会跨行）。全都跨栏就不写、保留原值。同一装置复测：分页 42px 写出 0.770（与 22px 的 0.813 同一标定，差异来自像素取整），截图注音贴回基字右侧；滚动 / VN 两种模式的生产 CSS 下新旧脚本都写 0.770、零跨栏（这两种模式不经多列分页，本就不触发），修复不改变它们的结果。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_ruby_metrics_behavior_test.js`（由 `reader_ruby_metrics_script_test.dart` 驱动，node 真执行 `kReaderRubyMetricsJs`）：假 DOM 扩成多颗 ruby，首颗 `<rt>` 给两段 client rect（模拟器 42px 实测尺寸）→ 必须跳过、量第二颗得 0.770；全部跨栏 → 不写；基字 Range 两段 → 跳过；基字带前导换行 / 全角空格只量「平」、代理对「𠮷」整颗量。变异验证：把 `singleRect(rt.getClientRects())` 换回取 `rt.getClientRects()[0]` 或外接矩形，跨栏用例变红。
- **备注**：修复后在正确拉力下这章仍有 1 颗注音盒跨栏（页顶行、盒伸出 ≈6px），盒外沿是注音自身的半行距，墨迹几乎不越界，不可见；度量脚本已跳过这类盒，不再受其影响。
