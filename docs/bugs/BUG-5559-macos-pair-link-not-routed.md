## BUG-5559 · macOS 原生侧没放行 fushi://pair，配对链接到不了 Dart
- **报告**：2026-11-27（用户：hajisensai，PR #4529 审查遗留）
- **真实性**：✅ 真 bug。macOS 上 Launch Services 把 `fushi://` 链接交给 `AppDelegate.application(_:open:)`，只有 host 在 `fushiRoutedUrlHosts` 里的才进 `source_urls` 事件流、到 Dart 的 `handleIncomingUrl`，其余交给 `super`（插件）。该白名单是 `["source", "widget", "shortcut", "lookup"]`（`fushi/macos/Runner/AppDelegate.swift:460`），Dart 侧 `SourceUrlChannel.routedHosts`（`fushi/lib/src/platform/source_url_channel.dart:31`）抄的同一份；可 `handleIncomingUrl`（`fushi/lib/main.dart:1979`）早已认 `fushi://pair`（扫码 / NFC 贴纸 / 系统相机唤起的互联配对）。结果 macOS 上点配对链接没有任何反应。根因是结构性的：两份手写 host 清单只互相对齐（`source_url_native_contract_test`），没有任何东西把它们和 Dart 真正分发的链接种类绑在一起，新加一类链接（pair，以及 PR #4529 的 leaderboard）只要忘了改清单就静默丢失。
- **[x] ① 已修复** — 新增 `fushi/lib/src/platform/incoming_fushi_link.dart`：`FushiIncomingLinkKind`（每类链接的 host + 是否由原生壳转交 Dart）与 `FushiIncomingLink.classify`（按原顺序逐个跑真实解析器：卡片出处 / `FushiPairLink` / `AppShortcut` / `WidgetLink` / 查词 / OAuth / AnkiMobile 回调）。`handleIncomingUrl` 改成对分类结果做穷尽 `switch`；`SourceUrlChannel.routedHosts` 由枚举派生、`isRoutedUrl` 直接用分类器，Dart 侧白名单不再单独手写。Swift `fushiRoutedUrlHosts` 补上 `pair`。
- **[x] ② 已加自动化测试** — `fushi/test/platform/source_url_native_contract_test.dart`：对 `FushiIncomingLinkKind` 穷尽 `switch` 给出每类的真实样例链接（配对链接由 `FushiPairLink.toUri()` 生成），断言分类结果、host 与「macOS 是否转交」三者一致，再与 Swift 字面量逐项对齐。新加一类链接不补样例就编不过，漏改 Swift 就红。改 Swift 之前跑过一次：`macos routes exactly the hosts Dart listens for` 红（Expected 含 `pair`，Actual 没有）。同步更新 `test/sync/interconnect_link_entry_points_test.dart`、`test/anki/ankimobile_ios_callback_static_test.dart` 的源码断言。
- **备注**：没在真 Mac 上点链接复测（本机是 Windows）。PR #4529（leaderboard 深链）也改了同一行 Swift 与 `routedHosts`；两个 PR 先合哪个，后合的那个都要做一次冲突合并：#4529 改成在 `FushiIncomingLinkKind` 里加 `leaderboard` 一项、Swift 字面量加 `"leaderboard"`。
