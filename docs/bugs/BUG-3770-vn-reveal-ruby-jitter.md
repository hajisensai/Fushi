## BUG-3770 · VN 逐字显现推进到注音词时整屏抖动
- **报告**：2026-10-24（用户：Windows 录屏 `2026-10-24 23-41-08.mp4`，「vn模式翻到下一个会抖动」；竖排 VN、逐字显现开着、有声书在播；安装版 `D:\fushi\Fushi`，app.so 2026-10-24 09:49，已含 BUG-3741 的 Range 高亮修复）
- **真实性**：✅ 真 bug。录屏逐帧量首列横坐标：翻到下一屏后显现全程 863.5px，显现推进到带注音的「<ruby>明後日<rt>あさって</rt></ruby>」那一帧整块左移 3.1px，显现结束那一帧移回 863.5px。录屏里还能看到基字没出来时注音「あさって」「いま」已经先挂在空列上。
- **根因**：`fushi/lib/src/reader/reader_visual_novel_scripts.dart:2714`（`hideCurrentScreenForReveal` → 旧 `prepareTextNodeForReveal` / `revealOneCharacter`）逐字显现把屏上每个文本节点切成「已显现文本 + `visibility:hidden` 的 span」，每个 tick 在两者之间挪字，显现完成再拆掉 span。与 BUG-3741 同一机制：Blink 对含 ruby 的段落按不同的文本节点切分排出不同行盒（含注音那列差 6px），VN 居中把整屏平移 3px。BUG-3741 只把有声书高亮改成了 Range，显现这条路径仍在切 DOM。走查器跳过 `rt`，注音从不在隐藏范围里，所以先于基字露出。
- **[x] ① 已修复** — `reader_visual_novel_scripts.dart:2714`/`2751`/`2845`：支持 CSS Highlight 的引擎上，未显现部分登记成一个 live Range（下一个要显现的字 → 屏末），`::highlight(fushi-vn-unrevealed)` 画成透明（`reader_content_styles.dart:1753`），每个 tick 只挪 Range 起点并重新登记，屏上 DOM 一字不动；注音跟同一 Range 走、基字显现完才露出。查词命中收口 `charRangeVisible` 与窄条层经 `window.__fushiTextUnrevealed` / `__fushiRevealRange` 认出未显现的字（`reader_selection_scripts.dart:568`/`2008`）。WebKit 不给直接挂在 `<ruby>` 下的基字文本画 `::highlight`（macOS WKWebView 实测，基字提前露出），建屏时（首帧之前、此后不再动）把这类文本就地包进 `fushi-hl-text`，节点身份不变、ruby 不移动。不支持 CSS Highlight 的旧 WebView 保留切节点兜底（`window.__fushiVnRevealRangeMode === false` 可强制）。
  - 验证：Chromium（headless shell 1243）生产 VN shell + 生产 VN CSS 截图：显现到「明」时「後日」与注音透明、字形与显现完成后逐像素同位。macOS 27.2 真 WKWebView（swiftc 探针，关窗口遮挡检测）：显现全程与显现完成时屏上 HTML、全部字形坐标不变，包基字后的坐标与不显现直接渲染一致，截图确认「後日」「刹那」与注音按序隐藏。
  - 真 app 复验（Windows 离屏集成测试，真 WebView2、原书 `七つの魔剣が支配するII` p-004、用户设置 Klee One 43px / 行高 1.65 / 竖排 VN block / 默认显现速度 45，从上一屏 `paginate('forward')` 翻进该屏，每 8ms 记内容盒与全部 `<ruby>` 盒位置，同一构建 A/B）：旧切节点显现 t=1306ms 内容盒宽 715.7→709.5px、整块平移 3.2px，t=2787ms 显现完成移回——与录屏的 3.1px 来回一致，原始失败复现；Range 显现全程只有一个状态，零位移。探针 `integration_test/reader_vn_reveal_layout_itest.dart` 依赖用户原书，未入库（证据 `fushi/.codex-test/windows-itest/vnrv2`）。
- **[x] ② 已加自动化测试** — `fushi/test/reader/vn_reveal_live_text_test.dart`（跑手 `vn_reveal_live_text_harness.mjs`）：生产 VN shell + 生产 VN CSS 在真 Chrome 里逐字显现录屏里那一段，断言每一步屏上 `innerHTML` 与全部字形坐标都等于直接完整渲染、未显现部分由 `fushi-vn-unrevealed` 承载且注音随基字、未显现的字点不中、显现完成后不留隐藏。变异对照：`__fushiVnRevealRangeMode=false` 退回切节点后红在 `start: revealing must not touch the screen DOM`。随改：`reader_selection_viewport_behavior_test.js` 的假 reader 补 `clearRevealRange` 桩。WebKit 的基字包裹只在 Mac 探针验过，未进自动化（CI 无 WebKit）。
