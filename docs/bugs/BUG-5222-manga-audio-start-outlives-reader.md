## BUG-5222 · 漫画阅读器起播成品音频期间退出，迟到的加载留下没人接管的会话（可能顶掉别的书）
- **报告**：2026-11-22（第三方审查 HBK-AUDIT-215，[#4110](https://github.com/hajisensai/Fushi/pull/4110)）。
- **真实性**：✅ **真 bug（会话生命周期没绑页面）**。`fushi/lib/src/media/manga/reader/manga_fushi/read_aloud.part.dart` `_startAudioIfRegistered` 起播要等 `initialiseAudioHandler` / `resolveMangaAudioSessionRequest` / `AudiobookSession.start`（播放器加载）几段异步；退出路径 `stopAudioUnlessBackground`（:601，返回路径与 `dispose` 都调）只处理已接管的 `audio`，起到一半时 `audio` 还是 null，什么都不做。迟到的 `start` 照样把会话装进全局 `AudiobookSession`：`if (driver == null || !_s.mounted) return true;` 只是不接管，会话留着——书架出一条暂停的迷你条；`start` 是「切书顶掉旧会话」语义，读者正在后台听的别的书也已被顶掉。返回路径先于 `dispose`，这段时间 `mounted` 仍为 true，所以页面还会把它接管并 `play()`。根因：起播的会话归属没绑到页面的去留上。
- **[x] ① 已修复** — 本 PR（分支 `claude/audit2-manga-audio-undo-lifecycle`）。`fushi/lib/src/media/manga/audio/manga_audio_session.dart` 新增 `startMangaAudioSessionOwned(session, req, wanted:)`：调 `start` 前已不要就不起（不顶掉别的书）；`start` 期间页面走了就停掉**这次装上的**会话（包住伴随对象工厂认出自己建的那份，会话已被别处换掉就不碰）。阅读器加 `_leaving`（返回路径 / 拆栈时由 `stopAudioUnlessBackground` 记下）与 `_wantsAudioStart = mounted && !_leaving`，起播全程（加载登记、起会话、seek 之后）按它判；退出后起播失败也不再弹 toast。
- **[x] ② 已加自动化测试** — `fushi/test/media/manga/audio/manga_audio_owned_start_test.dart`（真 `AudiobookSession` + 假 just_audio 后端）：起播前页面已退出 → 不起会话、别的书仍在；加载期间页面退出 → 会话停掉、伴随对象释放、迷你条无会话；页面仍在 → 正常装上。`fushi/test/media/manga/reader/manga_audio_reader_wiring_static_test.dart` 守住阅读器只经带归属的入口起会话、返回路径先记下 `_leaving`。
- **备注**：HBK-AUDIT-215。退出时若开着「退出后续播」，已在播的会话照旧后台续播；只有「还没起完」的那份随页面退出作废（读者在播放开始前就离开了）。
