- **报告**：2026-11-22（外部审计 Codex 2026-11-21 PR 审查 HBK-AUDIT-042，来自 PR #3835 / #3806）
- **真实性**：✅ 真问题（性能）。统计侧栏 `loadStatFacts(scope: StatFactsScope.media(...))`（`packages/fushi_engine/lib/stats/stat_facts.dart:476` 段读、`:498` 计数读）把范围下推成了 SQL 条件，但这些等值条件没有可用索引：
  - `getStudySegments`（`packages/fushi_core/lib/src/database/database_statistics.part.dart:623` 起）发 `profile_id = ? AND media_kind = ? AND (media_key = ? OR (media_key = '' AND title = ?))`，study_segments 只有 `idx_study_segments_profile_date (profile_id, date_key)`，计划是 `SEARCH … USING INDEX idx_study_segments_profile_date (profile_id=?)`——扫本 Profile 全部段。即使补了 `(profile_id, media_kind, media_key, title)` 索引，SQLite 也会把两支公共的 profile_id / media_kind 提出去，OR 本身用不上索引，计划只到 `(profile_id=? AND media_kind=?)`（变异实测原文），仍扫本域全部段。
  - `getLookupMiningCountersForBook`（同文件，修前 `:1792`，现 `:1807`）`book_key = ? OR (book_key = '' AND title = ?)`，唯一键 `(title, source_type, date_key, book_key)` 不以 book_key 打头 → `SCAN lookup_mining_counters`。
  - 同一条读路径上：`getVideoWatchStatisticsForMedia`（`:279`）的无身份支 `(book_uid IS NULL OR book_uid = '') AND title = ?` 只能按 book_uid 取出全部无身份行再比标题；`getEpubBookMetas(matchingBookKey:)`（`database_content_misc.part.dart:280`）的 `title IN (…) / title = ?` 整表扫 epub_books。

AND media_kind=? AND media_key=?)` / `(… AND media_key=? AND title=?)`，计数 `MULTI-INDEX OR` 走 `(book_key=?)` / `(book_key=? AND title=?)`。实测（内存库，同口径 50 次取均值）：10 万段 / 1000 本时单本段读 12.164 ms → 0.684 ms，5 万计数行时单本计数读 3.122 ms → 0.200 ms，返回行数不变（5000 / 2500）。
