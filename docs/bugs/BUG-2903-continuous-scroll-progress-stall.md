## BUG-2903 · 滚动模式往下滚会卡在某处停一会
- **报告**：2026-10-02（用户：「是往下滚动的时候会停下来」「不是（无极滑动），就是卡顿，会卡在一个位置停下一会」「我个人猜测是加载」）
- **真实性**：✅ 真 bug。滚动（连续）模式每个 scroll 事件经 rAF 节流回传 `onReaderScroll`（`fushi/lib/src/pages/implementations/reader_fushi/webview.part.dart` `_onReaderScrollEvent`），Dart `_refreshProgress` 随即 `fushiProgressDetails()`（同文件 `window.fushiProgressDetails`）。连续 shell 没有 `paginationMetrics`，这一次回报对整章做三遍 walk：兜底数总字数、`calculateProgress`、`getLastVisibleCharOffset`（`fushi/lib/src/reader/reader_pagination_scripts.dart` 连续 shell），后两遍对**每个**文本节点 `range.getClientRects()`。桌面 Chrome 实测 600 段（6003 文本节点、约 3.3 万正文字）一次 150–200ms。BUG-2830 把滚轮改成 rAF 缓动后，scroll 事件从「每格一次」变成「每帧一次」，Dart 侧 in-flight 守卫只防堆积、不降频，主线程被这条回报背靠背占满：真 Chrome 逐帧模拟（每帧滚 12px + 一次回报）帧间隔中位数 133ms、最长 767ms——缓动画面停在原地，就是「卡在一个位置停一会」。不是加载。
- **[x] ① 已修复** — 连续 shell 新增章内文本索引 `_textIndex`（文档序的有字文本节点 + 章内起始字数 + 章总字数，MutationObserver 记账、取用时 `takeRecords()` 同步判脏）与 `_charsBeforeEdge`（二分出第一个不整段在视口边之前的节点，结果 = 起始字数 + 跨边节点逐字计数，边语义原样透传 `countCharsBeforeViewport`）；`calculateProgress` / `getLastVisibleCharOffset` / 共享兜底 `firstVisibleCharOffsetByScan` 都改走它，宿主 `fushiProgressDetails` 先读 `chapterCharTotal()` 再退回 walk。同一模拟下帧间隔中位数 17ms、最长 67ms（首帧建索引）；横排 / 竖排各滚动位置的分子、末可见、首可见扫描与旧全章累加逐点相等。
- **[x] ② 已加自动化测试** — `fushi/test/reader/continuous_progress_text_index_test.dart`（真 Chrome 跑生产连续 shell，`continuous_progress_text_index_harness.mjs`：横排 / 竖排各 4 个位置与旧算法逐点一致、热索引后单次回报 getClientRects < 200 次（3003 节点实测 60 / 68 次）、正文插入段落后索引同步失效；去掉 `takeRecords` 判脏的变异实测两例转红；另钉宿主先读缓存总字数）。`reader_visible_range_shell_guard_test.dart` / `reader_pagination_scripts_test.dart` 的源码守卫按新结构改写，意图（字符级分子、首边 / 末边语义、到底返总字数）不变。
- **备注**：未在用户设备上真机复测（报告未说明平台；Mac / 手机 WebView 比桌面 Chrome 慢，旧实现的卡顿只会更重）。分页 / VN 不走这条路径（分页有 `paginationMetrics`，VN 有 `totalChapterChars`），本改动不触及二者。无几何的文本节点（`display:none` 等）在视口边之前时现在计入分子（旧实现恒计 0，导致这类章永远读不到 100%），属更正而非回退。
