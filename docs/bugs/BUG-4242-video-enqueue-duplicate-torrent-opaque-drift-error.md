## BUG-4242 · 重复入队同一种子报不透明的 DriftRemoteException，诊断日志无记录
- **报告**：2026-11-08（用户：`fushi_cli aidl` 提交「ガルパ☆ピコ ふぃーばー！」时，种子已被另一个任务入队，会话 failed `{"message":"DriftRemoteException"}`，error_log / video_diag_log 无记录，重试必现）
- **真实性**：✅ 真 bug（读代码确认，三处叠加）
  1. 领域层不判重：旧版 `VideoDownloadPipelineService.enqueue`（`packages/fushi_engine/lib/media/video/download/video_download_pipeline_service.dart` 旧 :1107-1160）只在「孤儿任务」时复用旧行，其余情况每次新生成 jobId 直接 `upsertVideoDownloadJob`（冲突目标只有 jobId），active / completed / 来源仍可用的 failed 旧任务一律撞部分唯一索引 `idx_video_download_jobs_fingerprint_torrent`（`packages/fushi_core/lib/src/database/database_infra.part.dart:252-258`），后台 isolate 把 SqliteException(2067) 包成 DriftRemoteException 冒出；注释原文「撞索引的老行为不变」。同类的 `enqueueManual` 却先查重抛类型化异常——同一服务两个入口语义不一致。先查后插也不在一个事务里。
  2. 失败无日志：`VideoAcquisitionService._guard`（`video_acquisition_service.dart` 旧 :468-477）只 `lastError = error` + `_describe`，不写诊断日志；`_describe` 对超 200 字符的 toString 只留 runtimeType；host 批量循环 `if (i == 0) rethrow`（`host_video_acquisition_assembly.dart` 旧 :191）首条失败直接上抛。
  3. 调用方语义不一：发现页批量提交首条重复直接冒原始异常；CLI `video get` 的 `on VideoDownloadAlreadyQueued` 分支不可达；订阅 `_enqueueItem` 预扫描只比 provider+remoteId，同 infohash 来自别的 provider 时撞索引后这一集被标 failed。
- **[x] ① 已修复** — `enqueue` 把「按 (fingerprint, hash) 查已有任务 → 孤儿改绑 / 抛 `VideoDownloadAlreadyQueued(existingJobId, existingLifecycle)` / 插入」放进同一 `database.transaction`（retryJob / wake 移到提交后），唯一索引只当最后护栏；`enqueueManual` 的重复也改抛同一类型。`_guard` 先 `engineLog.logDiagnostic('VideoAcquisition.effect', …原始错误+栈)` 再回灌 failed，`_describe` 直接放行管线 ActionRequired 的固定英文句子。AI 下视频批量入队抽成 `enqueueVideoAcquisitionPicks`，端口返回 `({int queued, int alreadyQueued})`，已在队列计数不算失败、不抛；`SubmittedEvent` / `FranchiseSubmittedEvent` 带 `alreadyQueued`，页面补一句 `download_batch_already_queued`。发现页批量提交同口径；订阅 `_enqueueItem` 收到 AlreadyQueued 时挂到既有任务（标 queued），并改正「torrentHash 没有唯一约束」的错误注释。提交哈希见 git log（BUG-4242）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/download/video_download_pipeline_service_test.dart`（group `BUG-4242 …`：active / completed 重复→类型化结果且只 1 行、并发两次只建 1 个任务、AI 批量入队首条重复返回 alreadyQueued=1；强化 `a same-hash job whose source still exists keeps blocking`）；`video_download_subscription_service_test.dart`（已在队列挂既有任务而非 failed）；`fushi/test/media/video/acquisition/video_acquisition_service_test.dart`（写入类效果失败落诊断日志含原始错误、已在队列会话以 submitted 结束）。
- **备注**：已有任务 failed 但来源可用时选择「抛已在队列、让用户去下载页重试」，不自动复活。未在真机重放 aidl 原路径（纯引擎层逻辑，服务级测试用真实 drift 内存库 + 真实唯一索引覆盖）。
