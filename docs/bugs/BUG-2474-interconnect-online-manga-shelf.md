## BUG-2474 · 互联漫画架不显示对端的在线书架漫画
- **报告**：2026-09-12（用户：「fushi 互联 书架漫画没同步」——本机 Windows Hibiki 当 host，把在线源（Mihon / Aidoku）漫画加入书架后，手机端漫画架看不到）
- **真实性**：✅ 真 bug。两道门一起把在线条目筛掉：① 在线条目入库时根目录只写占位 `manga.json = {"pages":[]}`（`fushi/lib/src/media/manga/library/online_manga_library_service.dart:111-116`），host 清单按 `hasExportableMangaContent(extractDir)` 算 `hasMangaContent`（`packages/fushi_engine/lib/sync/local_library_host_service/books.part.dart:80-81` → `manga_sync_package.dart:30` 空页表恒 false）；客户端漫画架只留 `format=='manga' && hasMangaContent`（`fushi/lib/src/pages/implementations/reader_history/remote.part.dart:89-95`），普通书架又只留 `hasContent` → 两架都丢。② wire 上没有任何字段能表达「这本按章下载在 host 上」，即使放行也无从读取。
- **[x] ① 已修复** — 对端在线漫画作为**章节式互联漫画源条目**端出来，全程 additive：host 清单加 `hasMangaChapters`（`<extractDir>/chapters/` 下至少一章有 `manga.json`）；`/api/library/manga/<bookKey>/manifest` 对章节式条目返回 `chapters[]`（只列 host **已完整下载**的章，与 host 自己「先下载再读」同律）；新增 `/chapters/<digest>/manifest` 与 `/chapters/<digest>/pages/<i>`，digest = `sha256(chapterKey)[:24]` 与目录名同算法（布局函数从 app 下沉到 `packages/fushi_engine/lib/media/manga/manga_chapter_storage.dart`，app 侧文件 re-export）。客户端 `InterconnectLibraryAdapter` 学会多章（`refresh` 按 manifest 的 `chapters` 建章表、`resolveChapterPages` 按摘要走章端点），漫画架用 `InterconnectMangaCatalog.isReadableRemoteManga` 放行，点「下载」= 以 `interconnect` 运行时加入本机书架（`_adoptRemoteChapteredManga`），之后章节走既有在线章下载链从对端逐章拉、本地落盘、本地读。
- **[x] ② 已加自动化测试** — `fushi/test/sync/local_library_host_service_manga_test.dart`（章节式：清单 `hasMangaChapters` 与旧 wire 字节不变、页表只列完整下载的章、按章页表/页图、未下载 404 形状、坏 digest 403 形状）；`fushi/test/media/manga/interconnect_manga_source_test.dart`（真 HTTP：清单放行、refresh 章表透传、按章取页字节、未下载章分类 runtimeFailure）；`fushi/test/pages/reader_remote_interconnect_test.dart`（漫画架显示章节式占位卡、普通书架不收）。
- **备注**：live 推送（`fushi/lib/src/sync/sync_orchestrator/books.part.dart:81-86` 对在线条目 `continue`）不在本轮：那条是「把我的书搬到对端」，在线条目没有可搬的整卷包；本 bug 的路径是「对端在我这儿看到并拉」。手机上读章节不需要装同款扩展——五端都经互联运行时读 host 已下载的章；host 没下的章不会出现在手机的章表里，host 下完后手机端作品页刷新即出现。
- **兼容注记（合入时补）**：新 host 上，章节式在线条目的 `/api/library/manga/<k>/manifest` 由**改前 404** 变成**改后 200 + `pages` 为空**。老 client 打到它会从 `MangaInterconnectUnsupported` → `sourceDisabled`（「对端版本过低」）变成 `runtimeFailure`（「no pages」）。实际不可达——老 client 因 `hasMangaContent=false` 根本不会把这本列出来，只有本地存着旧书架行才可能撞上；不是静默失效，两种提示都会让用户看见。
- **已知缺口**：`_chapterManifest` 把 `MangaInterconnectUnsupported` 一律翻成「对端还没下载这一章」，理由是「章端点只会在新 host 上被调用」。但已加入本机书架的章节式条目是**持久化**的：对端降级、换成不支持章端点的对端、或对端干脆关掉库服务（同样 404），都会显示成「还没下载这一章」而不是「对端版本过低」。提示会误导，但仍可重试、不致死。收窄办法是只在「本地条目已知该对端支持章端点」时才翻成 `runtimeFailure`。
