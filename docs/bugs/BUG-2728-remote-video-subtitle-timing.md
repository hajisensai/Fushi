## BUG-2728 · 远端视频缺波形对轴与重定时，导入字幕不上传服务端
- **报告**：2026-09-27（用户：所有者，「远端音频少了可视化调轴，还有字幕重定向之类的；字幕导入应该自动上传到服务端？」）
- **真实性**：✅ 真缺口。「远端音频」实为互联远端视频的音轨（远端有声书只能下载成本地书，不存在串流播放）。三处根因：
  - 波形对轴 / 自动对轴只认本地文件：`video_fushi_page.dart` 快速设置面板的 `onAutoAlign` / `loadSubtitleWaveform` 门控 `controller.videoPath?.isNotEmpty`，远端流 `videoPath` 恒 null（`video_player_controller.dart` 只从 `videoFile?.path` 赋值）；`subtitle.part.dart` 的 `_autoAlignSubtitle` / `_loadSubtitleWaveformEnvelope` / `_openSubtitleWaveformAlign` 同样早退。
  - 语音模型重定时菜单项显式 `!_isRemote && _currentVideoPath != null`（`subtitle.part.dart` 字幕菜单）。
  - 远端导入字幕 `_pickAndImportRemoteSubtitle` 只拷到本机 `video_subtitles/` 并内存应用；host 早有 `PUT /api/library/videos/<id>/subtitle`，但只被 live push 扫同目录 sidecar 时调用。
- **[x] ① 已修复** — 远端对轴音源：复用 BUG-1004 的 `clipaudio` 端点请 host 在本地裁整集当前音轨（单声道 64k AAC），落本机临时文件后喂给既有波形 / 互相关 / 设备端转录（`_resolveSubtitleTimingAudio`，老 host 也有该端点）；host 侧 `extractAudioSegmentViaFfmpeg` 超时可配，`clipVideoAudio` 按时长放大（`clipVideoAudioTimeout`）。导入 / 重定时产物自动上传：新可选能力 `VideoSubtitleDefaultHost.importDefaultVideoSubtitle` + 请求头 `X-Hibiki-Subtitle-Default: 1`，host 按自己的学习语言定后缀、压过它的旧 sidecar 改名 `.fushi-bak` 让位（原始文件只备份一次）。**混版本（审查补丁）**：老 host 不认 `X-Hibiki-Subtitle-Default`，PUT 会走 live push 旧路径 `importVideoSubtitle`，由引擎 `_moveFileInto` 的 `rename` 按 client 报的后缀（如 `.ja.srt`）**直接覆盖 host 上同名的旧字幕、不留 `.fushi-bak`**，client 还会提示「已设为默认」——所以不能「退回按 client 报的后缀落盘」。现在 host 在 `/api/capabilities` 的 `liveLibrary.videoSubtitleDefault` 声明该能力（库服务实现 `VideoSubtitleDefaultHost` 才为 true），client 经 `InterconnectSyncBackend.putRemoteVideoSubtitleAsDefault` 上传前先查它（`hostSupportsVideoSubtitleDefault`，按 host 基址缓存，同一 host 只探一次）：能力位缺失 / false / 端点 404 → **一个 PUT 都不发**，字幕只留本机，OSD 提示 `video_subtitle_host_upload_unsupported`；只有 host 回了实际落盘后缀（响应头 `x-hibiki-subtitle-suffix`）才提示「已设为默认」。新 host 的库服务不支持时对带该头的 PUT 回 409、不落盘（server 侧第二道门）。提交见 PR `pr/remote-audio-subtitle`。
- **[x] ② 已加自动化测试** — `fushi/test/sync/interconnect_video_default_subtitle_test.dart`（纯函数 / host 让位与备份 / 真实 server-client 端到端含 capabilities 能力位 / 混版本：假老 host 模拟覆盖语义，能力位缺失·false·端点 404 时零 PUT 且原字幕字节不变、能力位只探一次 / 视频页接线源码守卫：必须走 AsDefault 入口、「已设为默认」只在 applied 分支）。
- **备注**：未做的边界——host 播放列表第 2 集起（集下标 > 0）的字幕上传没有落点（host sidecar 只挂在主视频文件旁），跳过；媒体服务器（Jellyfin/Emby）与在线源远端没有「host 本地裁音频 / 收字幕」端点，对轴入口仍不显示。未在真 host 上跑两台设备的 E2E。
- **跟进（2026-09-27，所有者「加开关」）**：自动上传加了设置开关「导入的字幕自动上传到服务端」（视频设置 → 字幕分区，偏好 `video_subtitle_auto_upload_to_host`，默认开——本 bug 就是所有者要的自动上传，开关只负责「能关」）。关掉时 `_uploadRemoteSubtitleToHost` 进场即返回：不发 PUT、不提示，字幕只在本机生效。测试：`fushi/test/media/video/video_subtitle_auto_upload_pref_test.dart`、`interconnect_video_default_subtitle_test.dart`「开关关掉时不上传」。
