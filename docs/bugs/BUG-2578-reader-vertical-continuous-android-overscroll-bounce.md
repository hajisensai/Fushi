## BUG-2578 · 安卓竖排连续模式上下滑动画面回弹
- **报告**：2026-09-18（用户：「安卓端竖排滚动小说又出现上下滑动的操作空间了」，追问后澄清「就是竖排情况下屏幕上下滑动的时候会导致画面会弹」，附录屏 4.5s）
- **真实性**：✅ 真 bug。录屏逐帧量化（480×1066，6fps 抽帧）：静止时正文列顶 y=84 / 列底 y=1061；手指上划时列顶升到 66、列底仍 1060，**没有新的字露出来**，松手 1～2 帧内回到 84；下划时列顶 88 / 列底 1065。这是 Android 12+ 的过滚拉伸（底边锚定、整列缩放），不是真的纵向滚动余量——页内 `html { overflow-y: hidden }`（`fushi/lib/src/reader/reader_content_styles.dart:1172`，TODO-718）把纵轴锁得好好的。
  根因在平台层：阅读器 WebView 的 `InAppWebViewSettings`（`fushi/lib/src/pages/implementations/reader_fushi/webview.part.dart:1898`）从未设 `overScrollMode`，用 Android 默认 `OVER_SCROLL_IF_CONTENT_SCROLLS`。它只看「文档比视口高不高」（Chromium `OverScrollGlow.pullGlow` 的 `maxY > 0` 门 + `View.overScrollBy` 的 `canScrollVertical`），不看 CSS 有没有锁轴：只要章内任一元素纵向溢出让文档 `scrollHeight > 视口`，上下滑动的整段未消费位移就交给 EdgeEffect 画拉伸。竖排连续模式的纵轴本来就没有任何阅读动作，回弹只会让用户以为「页面能上下动」。
  Android 15 模拟器（上游 develop，真 app + adb 真触摸 + Chrome DevTools 读 DOM）没复现：合成书 / quirks 书 / 5% 边距 + 26px 字号 / 悬浮 chrome 显示与隐藏 / 模拟刘海 / 界面缩放 1.2 下文档 `scrollHeight` 恒等于视口，且该模拟器（swiftshader）连横轴章首的拉伸都渲不出来，无法当回弹的验证台。用户手机上文档为什么高出视口（章内哪个元素溢出）待真机探针 `fushi/integration_test/reader_vertical_continuous_axis_probe_itest.dart` 取证；那是独立的几何问题，不影响本条结论——锁死的轴不该有平台回弹。
- **[x] ① 已修复** — `webview.part.dart` 阅读器 `InAppWebViewSettings` 加 `overScrollMode: OverScrollMode.NEVER`（Android 专属，其它平台忽略）。阅读器自己拥有两条轴的滚动语义：分页 `touch-action: none` 不走原生滚动；连续模式只沿书写轴原生滚动、章边界由 onBoundarySwipe 跨章。两条轴上的 EdgeEffect 辉光 / 拉伸都不对应阅读动作，一并关掉；横轴章首/章末失去的只是拉伸动画，跨章本身不受影响。提交见 PR。
- **[x] ② 已加自动化测试** — `fushi/test/reader/reader_webview_overscroll_never_guard_test.dart`：锚在阅读器那份 `initialSettings: InAppWebViewSettings(`（以 `verticalScrollBarEnabled: false` 校验锚没漂），钉 `overScrollMode: OverScrollMode.NEVER` 且不得回到 `IF_CONTENT_SCROLLS` / `ALWAYS`。回弹是 Android 12+ EdgeEffect 的渲染期效果，本机模拟器渲不出、无法做行为级测试；真机验收：竖排连续下上下滑动画面不再弹。
- **备注**：`fushi/lib/src/media/audiobook/audiobook_clip_webview_render.dart:199` 的离屏渲染 WebView 早就 `disableVerticalScroll/HorizontalScroll: true`，阅读器不能照抄——连续模式要沿书写轴原生滚动。真机探针 itest 不进 CI 目标清单（`_itest.dart` 后缀、需宿主配合滑动），用法见文件头注释。
