## BUG-5380 · popup-source-strip-cross-line-sentence
- **报告**：2026-11-24（用户：应用内反馈 8Su1XoCjtl）Android 应用外查词（截屏识字）弹窗顶部的原文条只显示被点的那一行：「…コラボLINEスタン / プが映りました」折成两行时条上只到「スタン」，查到的词却是完整的「スタンプ」。
- **真实性**：✅ 真 bug。`fushi/lib/src/pages/implementations/popup_dictionary_page.dart`（修前 :234 `initState` 与 :339 `_lookupWidgetSource`）把原文条文字 `_sourceLookupText` 设成 `widget.searchTerm.trim()`，也就是 OCR 被点的那一行；块全文（`sourceBlock`）只用在制卡句子（:235 `_sentenceOf` → `ocrBlockSentenceAt`）和查词串的跨行续文（`_blockContinuationOf`，BUG-4707），原文条 `SourceLookupTextPanel`（修前 :986-1001）完全没用到，`initialCharIndex` 也是按行内下标算的。所以查词跨了行、制卡句子跨了行，唯独用户看得见的那条原文被行边截断，被折到下一行的字也点不到。
- **[x] ① 已修复** — `fushi/lib/src/lookup/ocr_block_sentence.dart` 新增 `ocrBlockSpanAroundLine`：把被点行扩到「行首字所在句的句首 ~ 行末字所在句的句尾」，按与制卡句子同一套折行规则拼回（`_joinRange`，`_joinLines` 改由它实现），返回带块下标 ↔ 条上下标换算的 `OcrBlockSpan`；一行装几句时几句都在条上，某一端那句太长（> 200，多半是无标点菜单）就停在行边。`popup_dictionary_page.dart` 每个宿主请求算一次 `_sourceSpan`：原文条与搜索框显示这段，`initialCharIndex` / 首查的扫描起点按 `textIndexOf` 换算，查词串的续文从这段末尾接（`_sourceStripContinuation`），条上点字按 `blockIndexOf` 换回块下标重挑制卡句子。没有块 / 块与行对不上时照旧是整行。
- **[x] ② 已加自动化测试** — `fushi/test/pages/popup_dictionary_source_line_test.dart`「feedback 8Su1XoCjtl」：反馈原样的折行块，断言条上是跨行整句、`initialCharIndex` 落在被点的「ス」、首查串与制卡句子正确，点下一行折过来的「映」能查；BUG-3487 / BUG-4707 两条原断言「条仍是被点的那一行」改成新口径（整句 + 换算后的下标）。`fushi/test/lookup/ocr_block_sentence_test.dart` 补 `ocrBlockSpanAroundLine` 的扩句、拉丁折行补空格的下标换算、超长一端停在行边、越界返回 null。
- **备注**：这改了 BUG-3487 / BUG-4707 当时「原文条仍是被点的那一行」的口径（那两条只修了查词串与制卡句子）。真机截屏识字复测未做。
