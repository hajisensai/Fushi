## BUG-4698 · 导入推荐包后漫画和小说全没了（推荐包走通用导入框、默认覆盖）
- **报告**：2026-11-15（用户 Android 实机：导入推荐包后漫画 / 小说全没了，SRS 卡片还在但背面的来源书没了）
- **真实性**：✅ 真 bug（读代码确认，未实机复现）。推荐包是一份净化过的 Fushi 备份 zip（只有 `dictionary_metadata`、`audio_source_configs` / `local_audio_dbs` 两条偏好与词典资源 / 本地发音库文件，见 `tool/pack/recommended_pack_database.dart`）。app 内三个发起点——新手引导推荐包那一步（`fushi/lib/src/pages/implementations/onboarding_wizard_page.dart:841`，「现在导入」与「选择本地包文件」共用）、首页迷你条与设置 → 系统那一行（经 `fushi/lib/src/onboarding/recommended_pack_import.dart:26`）——调 `runBackupImportFlowForFile` 都不带预设，于是弹通用备份导入确认框，而它默认选「覆盖」（`fushi/lib/src/sync/sync_settings_schema/backup.part.dart:1338`）。覆盖导入用包里的库整库替换：包里没有书 → 书库行、进度、统计全没；包里也没有书文件树，`fushi_books/` 等目录不被 swap，书文件留在盘上成了孤儿。SRS 在独立的 `srs.db`，覆盖时档案留本机，所以卡片幸存，但卡片按 bookKey 指向的书行已经没了。
  - **根因**：推荐包导入复用了「通用备份导入」的交互（让用户在默认覆盖的框里选模式），而推荐包语义上只是「装资源」，永远不该替换用户库。向导文案「确认框里选『合并』就不会动你已有的数据」把安全性押在用户改默认值上。
  - **连带根因（合并装不全）**：改成合并后要保证资源装全。合并对音频来源注册项是全有或全无（`fushi/lib/src/sync/backup_merge_engine.dart:2198`）：本机列表只要非空（用户动过发音设置就会落下 `fushiRemote` 那一行）就整份跳过包里的列表 → 发音库 `local_audio_*.db` 文件拷进来了却没登记，推荐包的发音静默不生效。
- **[x] ① 已修复** — `recommended_pack_import.dart` 新增 `kRecommendedPackImportPreset`（合并）与 `importRecommendedPackFile`，`importDownloadedRecommendedPack` 的预设参数改成非空、缺省合并；向导 `_importPackFile` 改走 `importRecommendedPackFile`。所有 app 内入口不再弹通用框（合并不删不改，无需二次确认），控制通道 `dict pack-import --merge|--replace` 仍按 CLI 显式给的模式（带 `confirm=true` 的知情选择）。通用备份导入框默认值不变。`BackupMergeEngine._mergeAudioSourcePrefs` 改成：本机列表为空仍整份采用；非空时保留本机全部条目与顺序，只把包里**有路径的本地发音库**条目（`audio_source_configs` 只收 `kind: localAudio`）按身份（内部副本认文件名、外部引用认全路径）去重追加，再由既有 rebase 重挂到本机支持目录。向导文案 `onboarding_pack_action_import_existing_desc` 换成新 key `onboarding_pack_action_import_existing_merge_desc`（旧文案让用户在确认框里选合并，已不成立）。提交：7fe9c9b5360
- **[x] ② 已加自动化测试** — `fushi/test/sync/recommended_pack_merge_import_test.dart`（推荐包形状的真备份 zip，按 `kRecommendedPackImportPreset` 折算的分类跑真实 `mergeRestoreBackup`：书库行 bookKey / uid 不变、阅读进度不变；词典行与资源文件装上；发音库文件拷入并追加登记到两份注册项、本机原有条目与文件不变、路径重挂、重复合并幂等）、`fushi/test/onboarding/recommended_pack_import_merge_guard_test.dart`（三个发起点不得直接调 `runBackupImportFlowForFile`，共享函数恒带预设、缺省合并）。
- **备注**：
  - （已过时：BUG-4701 起成功覆盖后快照改名保留，见下文「后续」）已中招用户的恢复：覆盖导入前的 `fushi.db.pre-restore.bak` 在**成功**的覆盖导入末尾就被删掉（`fushi/lib/src/sync/backup_service/restore.part.dart:1536`，仅当本机表回灌失败时保留到下次启动恢复，`recoverPendingRestore` 成功后同样删除，`:2058`），存储页「删除数据库快照」也会清它。所以正常走完覆盖导入的用户机器上没有这份快照，「从 bak 恢复书库」对他们不可用；书文件本身仍在 `fushi_books/` 等目录里。恢复方案待拍板，未在本 PR 实现。
  - 未在 Android 真机复测。

## 后续（拍板台 pr3449）

维护者拍板「要弹就得弹吧，默认合并」：app 内推荐包入口恢复弹通用备份导入确认框（导入前的最终确认、内容摘要、分类取舍、取消都在），只是打开时预选「合并」。`kRecommendedPackImportPreset` 改为 `kRecommendedPackImportMode`（合并），经 `runBackupImportFlowForFile(confirmInitialMode:)` 传给确认框；`importRecommendedPackFile` / `importDownloadedRecommendedPack` 的 `preset` 回到可空、缺省 null（弹框），只有控制通道 `dict pack-import --merge|--replace` 传预设跳过确认框。设置页通用「导入备份」预选仍是「覆盖」。测试：`fushi/test/sync/backup_import_confirm_initial_mode_test.dart`（真弹框，不碰选项直接确认 → 推荐包得合并、通用导入得覆盖，预选合并时仍可改选覆盖，取消返回 null）；守卫测试同步改为「共享函数预选合并、app 内入口不传预设」。覆盖导入后 `pre-restore.bak` 被删（PR 描述里的未做项）已由 BUG-4701 修复（成功后改名保留为覆盖前快照），本条不再处理。
