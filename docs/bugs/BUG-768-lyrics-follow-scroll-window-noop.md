## BUG-768 · 歌词模式音频跟随「高亮变但不滚动」（window.scrollBy 空转）
- **报告**：2026-07-13（用户：音频跟随没生效；确认「高亮变但不滚动」、底栏跟随开关点了也没用）。
- **真实性**：✅ **真 bug（滚动目标错，真浏览器验证）**。歌词页 CSS `html, body { height:100%; overflow-x:hidden }`（`lyrics_mode_html.dart` 生成）——按 CSS 规范，`overflow-x` 非 visible 会把 `overflow-y` 从 visible **计算成 auto**，于是 body 恰好填满 html、真正溢出滚动的是 **body**；而 `scrollToCenter` 的滚动原语 `_lyricsScrollByAxis` 用 `window.scrollBy`，作用于 `document.scrollingElement`（标准模式 = html，html 等高 body 无溢出）→ **空转 no-op**。后果：`setCue` 的高亮类更新照常（用户看到当前句变色），但页面永不跟随滚动、初始也不居中；`__lyricsScrollToCue`（切跟随开关的 snap 回中）同走 `window.scrollBy` 故也失效。用户手动滚滚的是 body 故有效——完全吻合「高亮变但不滚动」。**headless Chrome 复刻实测**：同款 CSS 下 `window.scrollBy(0,500)` → `{html:0, body:0}`（空转）；`document.body.scrollTop += 500` → `{body:500}`（有效）；`scrollingElement=html`、`bodyScrolls=true/htmlScrolls=false`、`overflow-y 计算值 auto`——四项全证实。根因点 `lyrics_mode_html.dart` 的 `_lyricsScrollByAxis`（`window.scrollBy`）。
- **[x] ① 已修复** — `ffc3f35cd`。`_lyricsScrollByAxis` 改为滚**真正有溢出的容器**：新增 `_lyricsScrollTarget()` 动态选 body/html 中 `scroll(Height|Width) > client(Height|Width)` 者，横排纵滚打 `scrollTop`、竖排横滚打 `scrollLeft`；保留原 `easeOutCubic` 增量动画与 `_animId` 取消机制；`_lyricsCenterDelta` 用 `getBoundingClientRect`（视口相对）不受滚动容器改变影响。根因修（改滚动目标到真实容器），非绕过。
- **[x] ② 已加自动化测试** — `test/media/audiobook/lyrics_follow_audio_guard_test.dart` 新增 BUG-768 用例（生成 HTML 不再含 `window.scrollBy(` 调用、含 `_lyricsScrollTarget()`、增量打到 `s.scrollTop += d` / `s.scrollLeft += d`）；`lyrics_mode_html_test.dart` 竖排断言从旧 `window.scrollBy(d, 0)` 改为 `s.scrollLeft += d`。滚动是 WebView 运行时行为，除生成器契约守卫外，已用 **headless Chrome 独立复刻验证**根因与修法（见真实性）。
- **备注**：reader/WebView/有声书/CSS 滚动容器类。代码 + 单测绿（pages/reader/audiobook 3617 全绿）、`flutter analyze` 0 issue、`dart format` 0 改动。已浏览器级验证；**真机复测**（歌词模式播放中当前句自动居中跟随、切跟随开关立即回中、横竖排均生效）待用户后补。与 BUG-769（歌词模式跨会话恢复）同批。
