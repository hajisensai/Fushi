## BUG-4232 · SRS 同步 v2：host 未点「开始同步」时客户端显示「全部已同步」、什么都没同步且无提示
- **报告**：2026-11-07（Linux Phase 4 互联测试；实测截图（未入库）：客户端显示「All changes are synced」，host 的一次性「Review sync has been upgraded → Start syncing」弹窗尚未点击）
- **真实性**：✅ 真 bug，已沿代码路径确认。host 点「开始同步」之前，客户端一轮同步显示「所有改动都已同步」，host 的卡一张没收到，也没有任何提示说 host 还没加入；host 点了之后两个方向都正常。
  - 根因（host 侧状态没有出口）：app 作为互联 host 时，客户端写进来的段由 host 的「本机目录」那一轮并入、host 自己的数据也只在这一轮发布（`fushi/lib/src/srs/srs_sync_scheduler.dart:1556` `syncLocalDirectories` → `syncWithBackend`）；这一轮被首次 v2 确认闸门挡住（`fushi/lib/src/srs/srs_sync_scheduler.dart:969` `_firstSyncConfirmed()` → `kSrsSyncAwaitingConfirm`，判据 `fushi/lib/src/srs/srs_app_runtime.dart:214` `app.srsSync2MergeConfirmed`）。而互联协议里没有任何地方让客户端知道 host 处于这个状态：客户端经 WebDAV 把段写进 host 目录、读回的只有自己的东西，这一轮报告 `error == null`；「立即同步」只看报告错误（`fushi/lib/src/srs/srs_sync_scheduler.dart:1243`、`fushi/lib/src/srs/srs_import_entry.dart:503` → 「复习数据已同步」），同步与历史页摘要只看本机未上传条数（`fushi/lib/src/pages/implementations/srs/srs_history_page.dart:67-76` `srsTimelineSummaryTitle` → 「所有改动都已同步」）。
- **[x] ① 已修复** — 提交见下方备注。协议 / 状态层修，不做字符串判断：
  - host 新增鉴权端点 `GET /api/srs/sync-status` → `{"joined": bool}`（`packages/fushi_engine/lib/sync/srs_change_feed.dart` `kSrsSyncStatusPath`，`fushi_sync_server.dart` `srsSync2Joined` 供给器；app 装配为 `srsSync2MergeConfirmed`，与本机目录闸门同一判据，`app_model.dart` → `fushi_server_controller.dart`）。没有首次确认这一步的 host（无头服务端 / 老版本）不注入 → 404 → 客户端按「不报告」处理。
  - 客户端 `InterconnectSyncBackend.hostSrsSyncJoined()`；`srs_directory_key.dart` `srsChannelPeerJoined`（只有互联后端有对端，云盘 / WebDAV 回 null）；调度器 `peerJoined` 注入，一轮成功后问一次，结果写进 `SrsSync2Report.peerNotJoined` 与 `SrsSyncScheduler.peersNotJoined`（按位置记，对端报告加入后移除；探测失败沿用上次结论并记日志，不改判这一轮）。`SrsSyncNowResult.peersNotJoined` 计数。
  - UI：「立即同步」提示改为警告「已配对设备还没开启复习同步」（`srsSyncNowToast`）；同步与历史页摘要行标题同句、副标题「在那台设备上打开复习并点「开始同步」……」、警告图标（`srsTimelineSummaryTitle(peerNotJoined:)` + 监听 `peersNotJoined`）。新 i18n key `srs_sync_peer_not_joined` / `srs_sync_peer_not_joined_hint`（en + zh-CN，经 `i18n_sync.dart --add`）。
- **[x] ② 已加自动化测试** — `fushi/test/sync/interconnect_srs_peer_not_joined_test.dart`：真 host（FushiSyncServer + 本机目录调度器，首次确认闸门）+ 真互联客户端（InterconnectSyncBackend + 客户端调度器，生产 `srsChannelPeerJoined`）。host 未确认 → 客户端「立即同步」无错误但 `peersNotJoined == 1`、收不到 host 的笔记、提示与摘要都不说「已同步」；host 确认后两边互通、提示消失；未注入供给器的 host 端点 404 → null、未鉴权 401；纯存储后端不问。
- **备注**：修复见 PR #3075。真机观察：Windows host 保持未点「开始同步」，客户端（Linux）复习 › 牌组列表「⋯ › 立即同步」应弹警告「已配对设备还没开启复习同步」，复习 › 同步与历史页「同步状态」摘要行显示同句 + 提示副标题；host 点「开始同步」后客户端再同步一次，提示变回「复习数据已同步」/「所有改动都已同步」，并收到 host 的卡。`curl -u hibiki:<token> https://<host>:38765/api/srs/sync-status` 在确认前后分别回 `{"joined":false}` / `{"joined":true}`。CLI `sync` 的结果 JSON 不含 SRS 轮次（SRS 走常规同步的后置步骤），这一处无 CLI 可见输出。
