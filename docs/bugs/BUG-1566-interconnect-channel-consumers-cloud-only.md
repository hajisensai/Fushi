## BUG-1566 · 词典删除只传播云通道、比较对话框只解析云后端：只开互联的用户两条路都断
- **报告**：2026-08-12（用户：互联 UI 层审计）
- **真实性**：✅ 真 bug（沿真实代码路径验实）。互联与云备份自 option B 起是**两条并存通道**（`fushi/lib/src/sync/sync_auto_trigger.dart:156` `enabledSyncChannelBackends`），但两个消费方还停在「只有云备份一条通道」的旧世界：
  - 根因A `fushi/lib/src/models/app_model.dart:4316`（`AppModel._propagateDictionaryDeleteToRemote`）：只对 `repo.getBackendType()` 解析出的那一条云后端传播词典删除，门控还只读云备份的 `isSyncDictionaryEnabled`。用户「云备份=Google Drive + 互联启用」时对端那份删不掉；词典是并集同步（`fushi/lib/src/sync/sync_orchestrator.dart:538` `if (syncDictionary) await syncDictionaries(report)`），下一轮又被拉回来 → 幽灵词典永远删不掉。
  - 根因B `fushi/lib/src/sync/sync_compare_dialog.dart:441`（`showSyncCompareDialog`）：同样只解析云通道去认证。只开互联、云后端从没配过的用户拿到的是一个永远认证不了的云后端，对话框恒报 `t.sync_compare_unavailable`（「请先设置同步」），整个互联比较入口不可达。
- **[x] ① 已修复** — 随本轮 fix(interconnect) 提交。两处统一复用同源枚举/门控，不再各自重抄通道逻辑：
  - A：`_propagateDictionaryDeleteToRemote` 改为遍历 `enabledSyncChannelBackends(repo)`，逐通道用 `resolveChannelSyncFlags(repo, isInterconnect: channel.isInterconnect).syncDictionary` 做门控（互联通道读互联专属 `isInterconnectSyncDictionaryEnabled`，BUG-988 分通道语义）；互联后端走 `deleteRemoteDictionary`，云后端走 `deleteRemoteDictionaryAsset`。整体仍在 `runExclusiveWithSync` 里串行（BUG-083），单条通道失败/未认证只记 `deleteDictionary.remote` 并继续下一条（一条云通道离线不得挡住互联通道的删除传播）。
  - B：`showSyncCompareDialog` 改为在 `runExclusiveWithSync` 里按枚举顺序（云在前、互联在后 → 云用户行为零变化）逐条 `restoreAuth`，取第一条 `isAuthenticated` 的后端当比较后端；一条都没有才报 `sync_compare_unavailable`（未新增 i18n key，`SyncCompareDialog(backend:)` 构造契约未动）。
  - 配套：`resolveChannelSyncFlags` 去掉 `@visibleForTesting`（已有生产消费方），`fushi/lib/src/sync/sync_auto_trigger.dart`。
- **[x] ② 已加自动化测试** — `fushi/test/sync/interconnect_channel_consumers_test.dart`（6 例）：4 例真 Drift 内存 DB 行为测试（云 Google Drive + 互联启用 → 枚举出两条通道且顺序为云、互联；互联通道词典门控读互联专属开关而非云共享开关，及其反向；互联未启用只剩一条通道），2 例源码扫描守卫（`_propagateDictionaryDeleteToRemote` / `showSyncCompareDialog` 函数体必须出现 `enabledSyncChannelBackends`、不得再出现 `resolveSyncBackend` 或 `repo.isSyncDictionaryEnabled()` 单通道解析）。四条守卫断言逐条做过变异实测（把生产代码改回旧写法 → 守卫如实变红，再反向替换还原）。另同步更新 `fushi/test/sync/google_drive_mobile_auth_test.dart` 的 BUG-047 守卫锚点（restore-before-read 不变式不变，锚点移到 `channel.backend`）。
- **备注**：并发修改窗口里曾有两条扫 `sync_settings_schema` 语料的守卫（`interconnect_tls_entry_guard_test.dart` / `interconnect_host_failure_surface_guard_test.dart`）短暂变红，起因是 BUG-1563 同期改写 `interconnect.part.dart`；锚点已随 BUG-1563 同步更新，合入前 `test/sync` 全量 2042 例已全绿。
