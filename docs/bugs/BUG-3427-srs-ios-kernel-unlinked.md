## BUG-3427 · iOS 复习页报排程内核不可用：Runner 未链入 fushi_fsrs
- **报告**：2026-10-15（用户：iOS TestFlight 包，复习页顶部红条「本机的排程内核不可用：可以浏览和编辑卡片，但暂时不能复习。」）
- **真实性**：✅ 真 bug。iOS 上 `FushiFsrs` 用 `DynamicLibrary.process()` 找 `ffsrs_*`（`packages/fushi_srs/lib/src/ffi/fushi_fsrs_library.dart:91`），但 Runner 从没链进 fushi_fsrs：`fushi/ios/Flutter/{Debug,Release}.xcconfig` 只 `#include?` fushi_p2p 单库的 xcconfig，`Runner.xcodeproj` 三个配置的 `OTHER_LDFLAGS` 只有 `$(FUSHI_P2P_LDFLAGS)`；`release-desktop.yml` 的 iOS job 注释明写「fushi_fsrs 暂不进 iOS 包」。查不到符号 → engine 为 null → `SrsDbStore.canSchedule == false`（`packages/fushi_engine/lib/srs/srs_db_store.dart:144`）→ `srs_deck_list_page.dart:355` 出红条，复习与新格式 .apkg 导入（要 zstd）一并不可用。CI 全绿、TestFlight 照发，因为没有任何核对看 Runner 里有没有 `ffsrs_*`。
- **[x] ① 已修复** — iOS 改链伞形静态库 `native/fushi_ios_umbrella`（fp2p_* + ffsrs_* 合一、Rust std 一份；两份单独 .a 同时 `-force_load` 会撞重复 std 符号）：两份 xcconfig 改 include 伞形库 xcconfig，`OTHER_LDFLAGS` 三处改 `$(FUSHI_IOS_NATIVE_LDFLAGS)`；`build-multiplatform.yml` / `release-desktop.yml` 的 iOS job 改编伞形库（持久库名 `ios_native`，输入三个 crate），未签名 IPA、TestFlight archive、PR debug 构建三处 Runner 都同时跑 p2p 与 fsrs 的 `verify_abi.sh`。顺带修伞形脚本 `verify_archive`：Xcode 自带 nm（LLVM 21）读不了 rustc 1.95 的 bitcode `compiler_builtins` 成员而退出 1，pipefail 下脚本静默挂掉。
- **[x] ② 已加自动化测试** — `fushi/test/build/ios_native_umbrella_link_guard_test.dart`（xcconfig / pbxproj 接线 + 两条 workflow 每处 fp2p_* Runner 核对都配 ffsrs_* 核对）。
- **备注**：真 iOS Release 链接在 Mac 上验证（`flutter build ios --release --no-codesign` 后对 Runner 跑两份 verify_abi.sh）。
