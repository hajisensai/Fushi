## BUG-5549 · leaderboard-deeplink
- **报告**：2026-11-27（用户：应用内反馈 ZEDeFWgPTf，Android OnePlus，3.4.0-debug.32705）——排行榜公开分享页 rank.fushi.moe/u/<id> 点「在 Fushi 中打开」没有打开 Fushi。
- **真实性**：✅ 真 bug。分享页链到 `fushi://leaderboard/user|work/<id>`（`services/leaderboard/src/pages.js:221`、`:259`），App 一侧从未接这条链接：Android 清单只为 `fushi` 注册了 auth / source / pair / lookup 四个 host（`fushi/android/app/src/main/AndroidManifest.xml:88-115`、`:247-252`），系统找不到处理者；iOS 按整个 scheme 注册、url_events 全量转交，但 `handleIncomingUrl`（`fushi/lib/main.dart:1970-2015`）没有 leaderboard 分支，链接被丢；macOS 的 `fushiRoutedUrlHosts`（`fushi/macos/Runner/AppDelegate.swift:460`）不含 leaderboard，到不了 Dart；Windows / Linux 协议注册是整 scheme，但 argv 冷启动与单实例转交（`_handleExternalVideoChannel`）同样没有分支。分享页 2026-09-28（85dc4fa61f1）上线起就断着。
- **[x] ① 已修复** — 新增 `fushi/lib/src/leaderboard/leaderboard_deep_link.dart`：`LeaderboardDeepLink.tryParse/fromUri`（id 字符集与 pages.js `PAGE_ID` 一致）、冷启动队列 `LeaderboardDeepLinkQueue`、落地 `openLeaderboardDeepLink`（已开启账户推现成的 `LeaderboardUserPage` / `LeaderboardWorkPage`；未开启或账户读取失败推 `LeaderboardPage` 显示开启说明 / 重试，而不是一个永远空着的用户页）。main.dart 三个入口（argv、`handleIncomingUrl`、`_handleExternalVideoChannel`）都接上；Android 清单加 host=leaderboard 的 VIEW/BROWSABLE intent-filter；macOS `fushiRoutedUrlHosts` 与 `SourceUrlChannel.routedHosts` 加 leaderboard。
- **[x] ② 已加自动化测试** — `fushi/test/leaderboard/leaderboard_deep_link_test.dart`：解析器正反例；守卫（pages.js 产出的每个 `fushi://` host 都在 Android 清单注册且 macOS 转交、产出的每种 leaderboard 链接都能解析、main.dart 三个入口都接线）；落地路由（已开启 → 用户页 / 作品页带对的 id，未开启 / 读取失败 → 排行榜主页）；冷启动队列。
- **备注**：排行榜不在 iOS 商店合规三类受限能力里（`store_compliance.dart` 无涉），iOS 不需额外处理。顺带发现：macOS 的 `fushiRoutedUrlHosts` 也不含 `pair`，`fushi://pair` 在 macOS 上同样到不了 Dart（另案）。
