## BUG-5276 · 「恢复本页默认」删不掉与默认同值的显式选择，跟别的设置走的行恢复后反被钉死
- **报告**：2026-11-23（合并后审查 HBK-AUDIT-235，拍板台 review-hbk-audit-235-pixi-restore 拍板「做」）
- **真实性**：✅ 真 bug。① 歌词背景（`music.lyrics_backdrop_style`）没存值 = 跟出厂默认 Pixi 走；先切走再手动选回 Pixi 后库里存着显式 `pixi`。页级「恢复本页默认」只按「生效值是否等于默认」判断（`fushi/lib/src/settings/settings_kit.dart` `settingsResetSpecFor` 分段分支 `modified: current != defaultValue`），这行永远不进恢复列表、也删不掉；以后改出厂默认它会钉在旧值上。② 同类：查词「制卡后行为」各模块行（`fushi/lib/src/settings/settings_schema_lookup.dart` `_afterMiningPopupRow`）的默认由旧开关 `close_popup_after_mining` 推出（`defaultValueBuilder`），但没声明删值写法，恢复默认走 `onChanged(此刻默认)` 把推出来的默认钉成手选——违背 `SettingsSegmentedItem.resetToDefault` 文档自己写的「默认值随别的设置变的行要清掉自己的偏好」。
- **[x] ① 已修复** — `SettingsSegmentedItem.resetToDefault` 换成 `SettingsStoredChoice storedChoice`（`isStored` 判据 + `clear` 删值成对声明），`defaultValueBuilder` 行构造期 assert 必须声明。`SettingsResetSpec` 新增 `pinnedAtDefault`（生效值等于默认但显式存着）与 `resettable`；页级恢复、ctl `config reset` 按 `resettable` 处理，分组头「N 项已修改」仍只数 `modified`。确认框里钉在默认值上的行写「Pixi（手动选择）→ 跟随默认值」（新 key `settings_page_reset_value_follow_default`），不出现「Pixi → Pixi」。歌词背景行接 `PreferencesRepository.hasStoredMusicLyricsBackdropStyle`；制卡后行为行接新增的 `ReaderFushiSource.hasStoredAfterMiningPopupAction` / `clearAfterMiningPopupAction`。settings index 输出 `pinnedAtDefault`。
- **[x] ② 已加自动化测试** — `fushi/test/settings/settings_page_reset_test.dart`：显式存默认值的行让页头按钮可用、确认框写「跟随默认值」且无「Pixi → Pixi」、确认后删值；存了非默认值的写「Mesh → Pixi」并删值；`pinnedAtDefault` 不计入分组「已修改」摘要。`fushi/test/pages/music_lyrics_backdrop_test.dart`：显式 pixi 算存值、clear 后不算。`fushi/test/pages/close_popup_after_mining_test.dart`：制卡后行为显式选默认算存值、clear 后回到跟默认走，schema 行接线。
- **备注**：没有 `storedChoice` 的普通分段 / 开关 / 滑条行，恢复默认就是把默认值写回，存不存值对它们没有可观察区别（读取端 `getPref(defaultValue:)` 与 schema 默认同源），故不纳入。
