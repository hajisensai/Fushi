## BUG-3655 · srs-rwkv-rebuild-loop-while-reviewing
- **报告**：2026-10-21（群内用户截图：复习页一直显示「RWKV 还没准备好，这个牌组暂按 FSRS-7 存下的到期日排队」；同一用户的牌组设置停在「正在回放复习历史… 0/189666」，选的是大模型）
- **真实性**：✅ 真 bug（用户机器上的日志拿不到，按代码路径与测试复现）。`packages/fushi_engine/lib/srs/srs_rwkv_service.dart` 有两处会让复习途中反复全量重建，重建期间 `ready=false`，每张卡都显示这条提示：
  1. `_rebuild` 先取日志指纹、再分块读全部历史（大收藏要几秒到几十秒）；用户这时还在复习页答题，新评分有的读进去、有的没读进去。重建完对齐时它们「早于已回放的最后一条」（`_appendNew` 的 `r.at < _lastAt`），又触发全量重建——边答边重建，形成循环；读进去的那条还会被再追加一遍。
  2. `_appendNew` 一见同一张卡有多条新评分就放弃；`SrsDbStore.answer` 不等 `onAnswered`，对齐读历史时用户又答了一题，读到的历史比指纹新、末尾对不上（`srsRwkvAppendRow` 返回 null），同样落到全量重建。
- **[x] ① 已修复** — `a67d1234d7`：重建读完历史后核对指纹，这期间有新日志的卡丢掉已加入的行（`SrsRwkvReplayBuilder.dropCards`）、按最新历史重读，直到指纹不再变；追加支持一张卡末尾的多条新评分（`srsRwkvAppendRows`），读完历史若指纹又变了就按新指纹重来，不再直接全量重建。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/srs_rwkv_service_test.dart`「两次对齐之间同一张卡答了两次……」与「全量重建读历史途中用户还在答题……」（经测试钩子 `debugAfterRebuildFingerprint` 在指纹之后、读历史之前答两张卡）。变异实测：关掉重建后的核对 → 后者红（对齐返回 false、又去重建）；把追加的「重来」改回放弃 → 前者红，原有的「同日重复的间隔守卫」用例也红（连续作答就会撞上）。
- **备注**：首次准备（下载 + 全量回放）期间显示这条提示是设计内的；大模型回放慢数倍，同一 PR 已删掉大模型。用户机器上的实际耗时未测。
