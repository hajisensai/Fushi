## BUG-5420 · 内置网页播放器页（WebVideoFushiPage）放 YouTube 时 ←/→ 快退快进没反应
- **报告**：2026-11-24（用户：应用内反馈 yPaPsQ6JYv「方向左右键也失效」，Windows，截图是 YouTube 自带播放器界面全屏态）
- **真实性**：⏳ 待真机复现。从 BUG-5417 拆出：BUG-5417 只修了原生播放器页网页档的 S / 换章门控，←/→ 在两页都没有同类门控。截图里露出站点自己的控制条（点赞 / 查看商品 / 退出全屏），原生播放器页的播放器档会藏掉站点 chrome（`web_video_session.dart` `_applyPageMode`），当初据此推断当时在内置网页播放器页；**这条推断不成立**（2026-11-25 复审）：原生播放器页网页档的网页模式（`web_video_session.dart` `playerMode` 为假，`_applyPageMode` 只在播放器模式藏站点 chrome）同样露出站点控制条，且截图底部那条紫色字幕可以是任一页的字幕层；同一会话 45 分钟前提交的 bsozOyEfi1 日志里 15:16–15:25 全是 `video.pause_ocr_tap`（`video_graphic_subtitle_ocr_overlay.dart`，只在原生播放器页），所以两页都要查。原生播放器页的 WebView 持焦入口是 `web_source.part.dart` `_onWebKeyToken` → `_buildVideoShortcutActions` → `seekBackward` / `seekForward`（过 `_runWhenImmersiveAllowsShortcuts`，沉浸锁开着时整组视频键本就不响应）→ `controller.seekRelative` → `WebVideoPlatformPlayer.seek`（没发出去会记 `seek not sent`，反馈日志里没有这条）。该页 ←/→ 的两条入口：Flutter 持焦走 `CallbackShortcuts`（`web_video_fushi_page.dart` `_keyboardShortcuts`），WebView2 持焦走键盘桥 `webVideoKeyBridgeScript` → `_onKeyToken`；两条都落到 `_seekRelative(±5000)` → glue `__fushiWebVideo.seek`（非 Netflix 直接写 `<video>.currentTime`，`assets/web_video/web_video_glue.js` seek）。
- **[ ] ① 未修复** — 已排除（BUG-5417 备注）：YouTube 先吃键（无头 Edge + CDP 实测桥先拿到键）、键位解析（单测）。2026-11-25 复审补测：同一套无头 Edge + CDP，桥收到 ←/→ 后照 glue 的非 Netflix 分支直写 `<video>.currentTime`，YouTube（`ytp-delhi-modern`）上先点画面再按、点站点全屏钮后再按、暂停态再按，四次都按 ±5 s 落地（8.79→15.25、17.26→23.71→20.16、20.39→25.39），页面侧直写 seek 没问题；无头模式进不了真全屏（`document.fullscreenElement` 恒空），站点全屏态仍未覆盖。未排除：WebView2 可捕获档持焦时键是否真进 DOM、YouTube 全屏（`document.fullscreenElement`）下焦点位置、`_relativeSeekBaseMs` 基准、glue `video()` 选中的是不是正片 `<video>`、`seek` 结果码与 seekDone 回执。需在内置网页播放器页真机加日志（`_onKeyToken` 收到的 token、`_seekMs` 的目标与结果码、seekDone）复现。
