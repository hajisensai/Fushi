## BUG-3887 · VN 按句分屏时有声书跨插图不停留；图片停留秒数不能自定义
- **报告**：2026-10-31（用户：「歌词模式有插画的时候应该跳出来停留，跟视觉小说一样，但是现在视觉小说好像不会停留，可以顺便修一下，并且支持自定义停留多少秒。」）
- **真实性**：✅ 真 bug（按句分屏）+ 设计缺口（秒数只有四档）。沿真实代码路径用真 Chrome 跑生产 VN shell + 生产 `audiobook_bridge.dart` 高亮 JS（`__fushiHighlightSentenceAudioCueById` → VN `highlightSentenceAudioCue` → `pauseAtCrossedMediaScreen`）逐句推进核对：
  1. **按块分屏（默认 `vn_screen_mode = block`）链路是通的**：开图片暂停时 cue 从图前一句推进到图后一句，先整屏停在插图并发 `onImageDetected`，再次跟随落到句子屏；`<img>` 与 `<svg><image>` 两种插图形状都一样。
  2. **按句分屏（`vn_screen_mode = sentences`，保留对白气泡关 = 默认值）断了**：`fushi/lib/src/reader/reader_visual_novel_scripts.dart` `buildSentenceUnits`（修前 :2126）把全章文字压成一条字符流、只按「。！？.!?」（:880）与 `Intl.Segmenter` 切句，不认独立单元（插图 / 表格等原子块）的位置。图前一段不以句末标点收尾（轻小说最常见的「……」对白段）时，这一句越过插图把图后的正文吞进同一个句子单元（实测字符区间 0..31，插图在 23）；`buildSentenceScreens`（:1921）按 `order` 排序后插图屏排到这句之后、字符区间倒挂。跟随从图前句推进到图后句时两句同属第 0 屏，`pauseAtCrossedMediaScreen`（:1230）在 `currentScreenIndex+1 .. targetIndex` 之间找不到插图屏 → 不停；插图要等再下一句才冒出来（此时音频早过了图）。
  3. 「自定义停留多少秒」：设置只有 0 / 5 / 10 / 15 四档分段（`reader_quick_settings_sheet.dart` `_imagePauseOptions`），控制器 `setImagePauseSec` 也夹到 15。
  - 未改但须知：图片停留是**每本书**的偏好，默认 0 = 关（`packages/fushi_audio/lib/src/audiobook/audiobook_repository.dart:363`）；关着时三种 view mode 都按设计直接越过插图（BUG-3395 备注）。歌词模式下 `pauseEnabled` 恒 false（`reader_fushi/audiobook.part.dart` `_onCueChanged` 里 `!_lyricsMode && ...`），歌词层接入图片停留由另一条分支处理。
- **[x] ① 已修复** — `buildSentenceScreens` 先算独立单元，作为硬边界传给 `buildSentenceUnits(standaloneUnits)`：相邻两字之间夹着独立单元的原文位置时强制断句，句子单元不再跨插图，插图屏回到图前句与图后句之间、字符区间保持阅读顺序。秒数改为步进器（`AdaptiveSettingsStepperRow`，0 = 关，1 秒一档，上限 `AudiobookPlayerController.maxImagePauseSec = 60`），控制器夹取同步放宽。`triggerImagePause` 签名与语义未动。
- **默认值改 2 秒（所有者 2026-10-31 拍板）**：`AudiobookRepository.defaultImagePauseSec = 2`（`packages/fushi_audio/lib/src/audiobook/audiobook_repository.dart`），`readImagePauseSec` 缺省回落到它；控制器的 `imagePauseSec` 初值与 `load(initialImagePauseSec:)` 缺省同源。存储形态可区分：偏好是逐书一行 `audiobook_image_pause_<bookKey>`，`getPrefTyped` 只在**没有行**时回落默认；唯一写入方是设置项 `setImagePauseSec`（值不变不写、载入不回写），所以显式设成 0 的书有一行（PrefCodec 编码 `i:0`）、仍读出 0 保持关闭，从未设置过的书才吃 2。TTS 朗读会话仍显式传 0（它不持久化停留设置，`tts_read_along.dart`），未改。i18n 文案没写默认值，不用动。
- **[x] ② 已加自动化测试** — `fushi/test/reader/vn_illustration_screen_test.dart`（+ `vn_illustration_screen_harness.mjs` 新增 ④：真 Chrome、生产 VN shell + CSS、按句分屏 + 保留对白关 + 「……」对白段在图前：插图是第 2 屏、各屏字符区间按阅读顺序、首屏不含图后句、跟随先停图再落句）。变异对照：换回修前 VN shell 红在「screen char ranges stay in reading order」。`fushi/test/media/audiobook/audiobook_background_resync_test.dart` 新增自定义秒数用例（37 秒照存、超上限夹到 60、负数夹到 0、持久回调收到夹取值、自定义秒数照常驱动停留）。`packages/fushi_audio/test/audiobook/audiobook_image_pause_default_test.dart`：没存过 → 2、显式 0 → 落行 `i:0` 且读回 0、显式 7 → 7 且不影响别的书。
- **验证**：三种 view mode——改动只在 VN shell 的按句分屏建屏（`buildSentenceScreens` / `buildSentenceUnits`，只有 VN 有）与有声书设置行；翻页 / 滚动 shell 与 `audiobook_bridge.dart` 的插图判定（`__fushiImageBetween` / `__fushiImagePauseAdvance`）未改，图片停留秒数对三种模式同一个 `imagePauseSec`。按块分屏的既有 ①～③ 用例照常通过（无回归）。真机未跑：本机 Windows 真 app 需要带插图且已对齐的有声书素材，本轮只在真 Chrome 跑生产引擎。
