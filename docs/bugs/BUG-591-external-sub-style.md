## BUG-591 · 外挂ASS字幕自带颜色描边不生效
- **报告**：2026-07-07（用户：外挂 .ass 字幕，开「尊重字幕自带样式」仍报「完全不生效，没颜色没描边」，强调是外挂）
- **真实性**：⚠️ 部分真。沿真实代码路径全链复核（parser + overlay + 单视频重开 rehydrate + 远端/本地 attach）后，**外挂 .ass 主路径经验证是通的**：`AssParser.parseString` 正确把 `[V4+ Styles]` 解析成 `SubtitleCueStyle`（主色/描边色/描边宽/字体，`packages/hibiki_audio/lib/src/parsers/ass_parser.dart:353`），`parseSubtitleContentAsync` 走同一 parser 天然带 markup，`VideoSubtitleOverlay._resolveStroke`/`_styleForGrapheme`（`hibiki/lib/src/media/video/video_subtitle_overlay.dart:634/668`）在 `respectAssStyle` 开时把 cueStyle/行内 span 的颜色描边应用到填充层 + 描边层；单视频重开由 `_loadSingle` 的 `_rehydratableExternalSubtitlePath`→`_loadExternalSubtitleCues` 重解析磁盘档案恢复 markup（`video_hibiki_page.dart:2148/2186`）。三处均有既有绿测（`ass_parser_test.dart` / `video_subtitle_overlay_markup_test.dart` / `video_subtitle_ass_style_rehydrate_test.dart`，本轮全绿复跑）。libmpv 对文本轨恒 `sub-visibility=no`（`video_mpv_config.dart:566`），字幕只由 Flutter overlay 渲染，故与 mpv `sub-ass-override` 无关。
  - **实测发现的真缺陷**：`packages/hibiki_audio/lib/src/parsers/subtitle_markup.dart` 的 `_applyOverrideBlock` **没有处理 ASS `\r`（复位样式）标签**——`\r` 被当未知标签静默丢弃，累积的行内 `_Style`（主色/描边/字体）不复位、泄漏到复位点之后的正文。对含 `{\c&Hxxxxxx&}...{\r}...` 的**彩色/混排**外挂 .ass（fansub 标注、看板、跨样式切换常见），复位后的文字被涂上**错误的颜色/描边**而非回到本条 cue 的 `[V4+ Styles]` 基线，即「尊重自带样式」失真。用 `AssParser.parseString` 复现：`{\c&H0000FF&}赤い部分{\r}白に戻る` → 复位后的「白に戻る」span 仍带红色 `c=ffff0000`。
  - 用户报的「白/黑普通字幕完全没变化」多是**观感等价**：典型 anime Default 样式=白字黑描边，恰与 app 统一默认外观一致，尊重后像素级不变 → 误判「开关无效」。若其安装包**早于 TODO-1105/f889ff527/2769ef02b**（feature + 重开 rehydrate 均 2026-07-07 才在 develop），则整条 feature 尚未包含，需先升级验证。
- **[x] ① 已修复** — `subtitle_markup.dart`：给 `_Style` 加 `reset()`（清空全部行内覆盖字段），并在 `_applyOverrideBlock` 加 `\r` / `\r<StyleName>` 处理分支（`tag == 'r'` 或 `^r[A-Za-z0-9_ \-]+$`，ASS 里唯一裸 `r` 起始标签就是 `\r`，`\frx`/`\fscx` 起始为 `f`，前缀判定安全）→ 复位后段落 `hasStyle==false`，渲染层落回本条 cue 的 `SubtitleCueStyle` 基线，不再泄漏上一段的错误主色/描边/字体。具名 `\r<StyleName>` 的样式切换需 `[V4+ Styles]` 映射表（本层不持有），按基线复位近似（只保证不残留错误覆盖，具名切换留待需要时串接映射表）。提交：31ae1c3b1
- **[x] ② 已加自动化测试** — `hibiki/test/media/audiobook/subtitle_markup_test.dart` 新增 group `parseSubtitleMarkup \r reset tag (TODO-1246)` 3 例：① `\r` 后正文不再继承前段红色（复位段 `colorArgb==null`）；② `\r` 同时清描边/粗体/字体覆盖；③ `\r<StyleName>` 按复位近似处理。20 项全过。既有 `ass_parser_test.dart`（cueStyle 解析）/`video_subtitle_overlay_markup_test.dart`（respectAssStyle 应用 cueStyle + 行内 span 颜色描边）/`video_subtitle_ass_style_rehydrate_test.dart`（DB 往返丢 markup + 重解析恢复）覆盖 parser→cueStyle→render→重开四端。提交：31ae1c3b1
- **备注**：主路径（fresh attach / 单视频重开 / 远端 attach / sidecar 自动探测）经全链核对均产出带 markup 的 cue 且被 overlay 尊重，未能复现「完全无色无描边」；本轮根因修复聚焦到确凿可复现的 `\r` 复位泄漏（彩色混排失真）。真机验收口径：在装有本 develop 版本的设备上，用一条含 `\r` 复位的彩色外挂 .ass（复位前后不同色）验证复位段颜色正确回退；并用普通彩色 .ass（如具名 Sign 样式橙色）验证开关开时字幕呈现 .ass 自带颜色/描边、关时回统一外观。
