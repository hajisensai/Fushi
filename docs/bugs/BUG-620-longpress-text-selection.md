## BUG-620 · 手机长按丢了文本区间选择(复制)·回归
- **报告**：2026-07-08（用户：TODO-1317「书籍里面，长按没有选择了。变成长按选择文字查词了」）
- **真实性**：✅ 真 bug —— 根因 `hibiki/lib/src/reader/reader_selection_scripts.dart` 的 `endRangeSelection`（BUG-609 / `7edfec52c`）。BUG-609 为「触屏长按拖选一段文字」把松手 `endRangeSelection` 直接 `fireTextSelected` → 走 `onTextSelected` → `_handleTextSelected` → **立刻弹查词**。于是手机长按拖选=选中即查词，丢了原有「长按拖选一段文本区间 → 复制/普通选择」的能力（TODO-1279 `user-select:none` 先掐掉原生触屏选区，BUG-609 只补回「拖选→查词」一条路，没补「拖选→复制」）。桌面（`pointer: fine`）本就有右键菜单「查词/复制/导出」共存（`chrome.part.dart:_showReaderTextContextMenu`），移动端缺这一层选择。
- **[x] ① 已修复** —— 移动端拖选松手改为**弹选区菜单（复制 / 查词）共存**，照抄桌面右键范式（不复活原生双选区、保住 BUG-609 拖选高亮）：
  - `hibiki/lib/src/reader/reader_selection_scripts.dart`：`fireTextSelected` 抽出单一真相源 `buildSelectionPayload`（tap 查词路径与拖选菜单路径同构 payload）；新增 `fireSelectionMenu`（dispatch 新 handler `onSelectionMenu`，**不**清 `this.selection` → 高亮留着给菜单叠）；`endRangeSelection` 真拖动时改调 `fireSelectionMenu`（不再直接 `fireTextSelected`），原地未拖动仍退回 `selectText` 单击查词。绝不碰 `window.getSelection`/`addRange` → 无原生双选区。
  - `hibiki/lib/src/pages/implementations/reader_hibiki/webview.part.dart`：注册 `onSelectionMenu` handler → `_handleSelectionMenu(ReaderSelectionData)`。
  - `hibiki/lib/src/pages/implementations/reader_hibiki/chrome.part.dart`：新增 `_handleSelectionMenu`——用 `_webViewKey` RenderBox 把 WebView 局部选区 rect 映射到 Overlay（BUG-381 范式，界面缩放自洽）弹 `showMenu`；「查词」复用 tap 的 `_handleTextSelected(data)`（弹窗内含制卡）；「复制」`Clipboard.setData(data.text)` + toast + 清 app 选区高亮；取消也清高亮。新增 `_clearReaderAppSelection`（只清 app 自绘选区，best-effort 吞半销毁 WebView 的 eval 异常）。**无新增 i18n key**（复用 `t.search`/`t.copy`/`t.copied_to_clipboard`）。
- **[x] ② 已加自动化测试** —— `hibiki/test/reader/reader_longpress_selection_menu_guard_test.dart`：源码扫描守卫。钉住①`endRangeSelection` 真拖动路由到 `fireSelectionMenu` 而非直接 `fireTextSelected`；②`fireSelectionMenu` dispatch `onSelectionMenu`、`fireTextSelected` dispatch `onTextSelected`、两者共用 `buildSelectionPayload`（查词与选区菜单同一 payload 契约）；③拖选 helper 仍不碰原生选区（不复活双选区）+ 原地未拖动仍 `selectText` 单击查词；④Dart `webview.part.dart` 注册 `onSelectionMenu`、`chrome.part.dart` `_handleSelectionMenu` 同时提供「复制」(`Clipboard.setData`)与「查词」(`_handleTextSelected`)两条出口（共存）。同时更新 BUG-609 守卫 `reader_longpress_drag_select_guard_test.dart` 的「松手」用例标题/断言反映菜单路由。
- **备注**：真机（Android/iOS）触屏长按拖选→选区菜单「复制」进剪贴板 / 「查词」进弹窗（含制卡）、不出双选区待用户验收（离屏 `pointer: fine` 不触发 coarse，无法复现该触屏路径）。桌面鼠标选区/右键菜单走 `pointer: fine` 分支不受影响。commit 见分支 `todo1317-longpress-text-selection`。
