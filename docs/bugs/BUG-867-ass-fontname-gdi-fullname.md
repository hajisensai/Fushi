## BUG-867 · 装了字幕指定字体 hibiki 仍用回退字体（ASS Fontname=GDI 全名解析缺失）
- **报告**：2026-07-16（用户：「我装上那个字体后，potplayer 可以正常识别，但 hibiki 还是原来那个字体」；同会话四截图=E08 对比 mpv 字号/位置不一致 + 另一片 hibiki J 字体 vs PotPlayer C 字体）
- **真实性**：✅ 真 bug。根因：ASS `Fontname` 存的是 **GDI 全名**（家族+字重后缀，如 `FOT-Matisse ProN B` = 家族 `FOT-Matisse ProN` 的 Bold 面；`Yu Gothic Bold` = `Yu Gothic`+w700）。libass/GDI/PotPlayer 按全名解析；Flutter `fontFamily` 只认 DirectWrite **家族名**——全名查不到就静默掉进 CJK 回退链，装了字体也不生效。字号/位置与 mpv 的偏差同源：两边解析到不同字体（本机 mpv --no-config 实测 `FOT-Matisse ProN B` → ArialMT→MicrosoftYaHeiUI，逐帧 fontselect 日志为证），度量（cell/em、行高、advance）全不同。
- **[x] ① 已修复** — `hibiki/lib/src/media/video/video_subtitle_overlay.dart`：`_resolveAssFontFamily` 顺序尝试①原名（有些字体全名即家族名）②剥尾部字重后缀（`assFontWeightFromSuffix` 纯函数：B/DB/EB/H/L/UL/M/R/Bold/…/W1-W9 → FontWeight，家族名成分 ProN/Std/75S/W20 等不误剥）后的家族名+映射字重；存在性用 `_fontFamilyExists` 双测量探测（候选 vs 哨兵家族各自无回退测量，度量全等=缺失；按家族缓存）。命中→真字体+命名面字重（cell/em 校准随真字体度量走）；未装→保留原名进回退链、Bold=0 仍常规字重（BUG-819 不回归）。cueStyle 与行内 `\fn` 双路径。
- **[x] ② 已加自动化测试** — `hibiki/test/media/video/video_subtitle_font_name_test.dart`（后缀映射纯函数守卫，含不误剥家族成分）；测试环境所有家族同字体→探测恒判缺失→解析器返回 null→既有字号/样式断言像素不变（回退不变性守卫）。真机离屏取证：`Yu Gothic Bold`→family=Yu Gothic+w700、`FOT-Matisse ProN B`（未装）→原名回退+w400、`Microsoft YaHei`→直接命中，字号=各字体 55.5/k（1.60/1.50/1.32）逐字体校准正确。
- **备注**：**装字体后需重启 app**（Skia/DirectWrite 字体集合进程内缓存）。J vs C 字体之谜：字体缺失时 mpv/Pot 在中文 Windows 回退到系统中文字体（YaHei=C 字形），hibiki 回退日文链（J 字形）——对日文文本 J 字形更贴作者意图，都不算「错」；装上指定字体后三家一致。E08 与 mpv 残余字号/位置差在双方都缺字体时无法逐像素一致（回退字体不同），装上 FOT-Matisse 即对齐。姊妹链：[[BUG-855]] [[BUG-819]] [[BUG-820]]。
