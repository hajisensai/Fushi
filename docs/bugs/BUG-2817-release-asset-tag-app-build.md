## BUG-2817 · 发布模型资产 release 触发整套应用构建并把安装包挂到该 release
- **报告**：2026-09-30（agent 在准备发布漫画 OCR 提速组件 `manga-ocr-kv-onnx-v1` 时发现；用户确认先修 workflow 再发）
- **真实性**：✅ 真 bug。`release.yml`（`build` / `tests`）、`release-desktop.yml`（`windows` / `macos` / `ios` / `publish`）与 `mirror-releases.yml`（`mirror`）都挂在 `on: release: types: [published]` 上，job 级 `if` 从不看 tag；`release.yml` 的 `Resolve Android release channel` 把一切 `release` 事件归为 `CHANNEL=github-release`，照正式包出 split APK 并上传到**该 release**，`release-desktop.yml` 同理出 Windows / macOS / iOS 包。
  - 实证：2026-09-21 手动发布模型资产 release `manga-panel-detector-onnx-v1`，触发了 Build Release APK / Build Desktop and Apple Release Artifacts / Mirror release assets to R2 三条 run；该 release 的资产表里除了模型 `manga_panel_detector_yolo26n_fp32.onnx`，还挂着 `fushi-2.8.0-ios.ipa`、`fushi-2.8.0-macos.zip`、`fushi-2.8.0-windows-setup.exe` 与 3 个 `fushi-manga-panel-detector-onnx-v1-*.apk`。`vendor-libmpv`、`voice-hook-helper` 两个依赖资产 release 同样各触发过一轮整套构建。
  - 影响：每发一个非应用 release 白跑一轮全平台构建（含 macOS runner），模型 release 上出现看起来像应用版本的安装包；不会上传 TestFlight（`release-desktop.yml` 的 TestFlight 门只认 `workflow_dispatch` / `push`）。
- **[x] ① 已修复**（提交见 PR）— 七个会在 `release` 事件上跑的 job 的 job 级 `if` 并上同一条判据：非 `release` 事件照旧；`release` 事件只放行 tag 为 `v<数字>…` 的应用 release。GitHub 表达式没有正则，只能逐个列 `startsWith(tag, 'v0')` .. `'v9'`——裸 `startsWith(tag, 'v')` 会把 `vendor-libmpv` / `voice-hook-helper` 放进来。`release-desktop.yml` 的 `publish` 用了 `always()`（会无视上游 job 被跳过），所以必须自己也带判据。`mirror-releases.yml` 本来就默认不镜像预发布版本，这里一并挡住，免得非预发布的资产 release 走进镜像流程。
  - 注意：`release` 事件跑的是 **tag 所指提交**里的 workflow 文件，所以守卫只对指向含本修复的提交的新 tag 生效。
- **[x] ② 已加自动化测试** — `fushi/test/build/release_event_app_tag_guard_test.dart`：扫 `.github/workflows/*.yml` 里所有 `release` 触发的 workflow，逐 job 断言 job 级 `if` 带判据（只在 `workflow_dispatch` 下跑的 job 豁免）；从判据表达式里取出前缀，按历史真实 tag 验证放行 / 跳过（`v2.8.0`、`v2.9.0-beta.1` 放行；`manga-panel-detector-onnx-v1`、`vendor-libmpv`、`voice-hook-helper`、`debug-rolling` 跳过）；合成语料自校验（步骤级 `if` 不算、裸 `startsWith(tag, 'v')` 不算）。
- **备注**：`manga-panel-detector-onnx-v1` 上多挂的 6 个安装包 / APK 与本次修复无关，是否删除由所有者决定（删之前确认没有外部链接指向它们）。
