## BUG-2087 · SGRE 游戏内查词点击后被查的词在台词里没有高亮：直连路径不把高亮区间发给 hook
- **报告**：2026-09-03（用户：「点击后，对应的词应该高亮」，SGRE 窗口模式；同批「音轨全是空的」二次报告：资源模式行的音轨对话框仍列出与本句无关的 PCM 轨）
- **真实性**：✅ 真缺口。`fushi/windows/runner/voice_hook_reader.cpp` `HandleLookupPresent`：直连呈现成功时只向 hook 写一张 dismiss 帧（退掉旧位图）并回 `directSurface: true`，`highlightStart/len` 不落到任何帧；`galLookupPresentHighlight`（highlight-only 帧）Dart 侧从未调用；hook 通用呈现器 `lookup_overlay_window.inc` 收到 highlight-only 帧直接消费丢弃。于是 KiriKiri 之外的引擎在卡片期间没有任何「被查的是哪个词」的反馈。
- **[x] ① 已修复** — Dart `GalIngameLookupController._present`：直连 present 成功且 `highlightLen > 0` 时追加 `galLookupPresentHighlight(seq, anchor, highlightStart, highlightLen)`；hook 通用呈现器把 highlight-only 帧的区间记入 `g_term_highlight_*`（dismiss / capture-suppress 帧清除）；SGRE 轮询在卡片可见期间按区间 `[start, start+len)` 取字格（UTF-16 下标与精确文本同域）在同一行内求并集，交给 BUG-2086 的高亮窗；卡片收起回到悬浮高亮。同批：工作台「这句台词的语音轨」对话框在 game_resource 行上不再列 PCM 轨，改为展示本句资源音频（来源、资源名、时长）与试听按钮（本提交）。
- **[x] ② 已加自动化测试** — 初版只断言了 `GalHookTextOverlayChannel.galLookupPresentHighlight` 的方法名与参数键，而那个方法在 `develop` 上本来就存在、本分支一个字没改；真正的改动（`gal_ingame_lookup_controller.dart` 里 `if (highlightLen > 0)` 那个调用点）零覆盖——变异掉整条修复，739 条测试全绿。2026-09-03 审查后置补：同文件新增接线层用例「reveal 报的根卡高度驱动 present anchor」，走真 `handleHit → onRoutedRevealed → _drainRecapture → _present` 链路，断言直连 present（`directSurface: true`）成功后**紧跟**一张 `galLookupPresentHighlight` 帧、锚点与 present 同值、`highlightStart/Len` 为该次命中的实际区间。hook 侧并集/清除逻辑为 Win32 UI 路径，真机验证记录见下。
- **[x] ③ 词高亮补前台判据**（缺陷 D，2026-09-03 审查后置补）：`sgre_lookup.inc` 的词高亮分支原本只看 `popup_visible && ReadLookupTermHighlight(...)`，而相邻的悬浮高亮分支用的 `game_point` 里含 `GetForegroundWindow() == game`。两个高亮窗都是 `WS_EX_TOPMOST`：卡片弹出后 Alt+Tab 走开，`FushiLookupHoverHighlight` 会一直盖在别的应用上。现在把前台判据拆成独立的 `game_foreground`，两个分支共用；不满足时 `SgreHoverHighlightScope` 的析构在下一 tick 清掉高亮窗。本条与上面「hook 侧词高亮窗的可见性只在卡片可见且游戏前台时成立」的复验描述对齐——修前代码并不成立那句话。
- **已知限制**（2026-09-03 审查）：
  - 缺陷 E：`native/galgame_hook/hook/lookup_overlay_window.inc` 里 `FushiLookupHoverHighlight` 的窗口类注册，`wc.hbrBackground = CreateSolidBrush(...)` 在 `RegisterClassExW` 返回 0 且 `GetLastError() == ERROR_CLASS_ALREADY_EXISTS` 时**不被类接管**，于是每次 overlay 线程 Stop→Start 漏一个 brush。有界（每次会话一个）但是真漏，未修——修法是把 brush 提成进程级 static 或注册失败时 `DeleteObject`。
  - 缺陷 G：`highlightStart/highlightLen` 在 Dart 侧是 **UTF-16 code unit**，hook 侧当**字格下标**用（`active.glyphs[term_start]`）。SGRE 的精确文本目前是 BMP 日文，两者恒等；一旦出现代理对（emoji / 部分汉字扩展区）或组合字，高亮会多标一格。同一份下标同时被`fushi/lib/src/pages/implementations/texthooker_page.dart` 的逐字命中消费，改口径要两侧一起改。
  - 缺陷 G（同批）：`texthooker_page.dart` 里 `line.audioBackend == 'game_resource'` 是全仓第一处拿这个 wire 值做**比较**的地方（此前只有写入方），裸字符串；抽一个 `const` 出来是正确出手，本轮不改行为，先记账。
- **真机复验**：2026-09-03 新 helper（dist x64 sha 41cb87…）装进 worktree 构建后，用户在 SGRE 窗口模式自行查词三次（`lookup seq=1..3 idx=8 query="機関”…"`，`present seq=3 anchor=(619,178) card=948x648 hl=8+2`），直连 present 后的 highlight-only 帧无失败日志；hook 侧词高亮窗的可见性只在卡片可见且游戏前台时成立，agent 在用户同时操作其它窗口期间无法抢前台复验，视觉确认交由用户。资源模式音轨对话框（本句资源音频 + 试听）已在前一版真机看到提示文案，本版新增的条目待用户目视确认。
