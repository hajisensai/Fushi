## BUG-5605 · video-network-mount-sync-stat-freeze
- **报告**：2026-11-28（用户：电脑本机播网络盘视频时 UI 冻结 7～23 秒；安装版留下 5 份 hang dump）
- **真实性**：✅ 真 bug。5 份 dump 主线程都停在同步 `File.existsSync`（`Builtin_File_Exists` → `GetTypeAndAttributes`，内核等待），路径是 Z: 盘（rclone 挂的 OpenList，WinFsp）上正在播的 mkv；同一时刻日志有成串 `extractVideoFrameViaFfmpeg` 超时。沿代码确认调用链：进度条 hover → `OffscreenVideoFrameGrabber.warmUp` / `grab`（`fushi/lib/src/media/video/video_thumbnail_preview_controller.dart`）→ `extractVideoFrameViaFfmpeg` 开头的 `videoMemberExistsSync(inputPath)`（`packages/fushi_engine/lib/utils/misc/desktop_audio_clipper.dart:1453`，修前行号）在 UI isolate 上同步 stat。rclone 缓存未命中时一次 stat 能挂十几秒。
  - 叠加的重试风暴：调度器的单飞闸门 6 s 就超时放开（`grabTimeout`），ffmpeg 自身时限 30 s，预热又与 hover 并发；熔断只看「从没成功过」，网络盘上成功过一次之后每次 hover 都再起一个注定超时的 ffmpeg、再同步 stat 一次。
  - 同类问题（同在 UI isolate、对媒体文件或用户目录同步 IO）：`desktop_audio_clipper.dart` 的封面 / 元数据 / 动图 / 内封字幕抽取入口、`video_cover_extractor.dart` 的 `extractEmbeddedVideoCoverViaFfmpeg`、`video_clip_exporter.dart` 的片段导出入口、`embedded_reference_subtitle_sync.dart` 的自动对轴入口（`hasLocalMediaFileSync`）、截图重名判定（`video_screenshot_filename.dart`，截图目录可在网络盘上）、播放页各 part 与 `video_player_controller.dart` 里的临时文件 `existsSync` / `lengthSync` / `deleteSync`。起播前的「文件丢失」检查（`video_resource_check.dart`）已是异步，但没有时限：卷卡住时起播干等十几秒，卷答复超时也没有「暂不可用」的概念。
- **[x] ① 已修复** —
  - 新增 `packages/fushi_engine/lib/media/video/media_path_probe.dart`：有界异步三态探测 `probeMediaPath`（present / missing / unavailable，默认 2 s 时限）。同路径合并在途 stat；同一挂载根并发上限 2（异步 stat 也占 dart:io IO 线程，不限会拖累本机盘上无关的 IO）；某个 stat 超时后该卷记为卡住，直到那个 stat 自己返回——期间同卷探测立刻答 unavailable、不再压新 stat，返回后 `whenMediaVolumeRecovered` 唤醒等待方。`video_member_file.dart` 加 `probeVideoMember` / `probeLocalMediaFile`。
  - 缩略图取帧器：取帧前走有界探测；取帧器自身单飞（在跑时只保留最新请求，预热不挤占）；探测 unavailable 或 ffmpeg 连续 2 次跑满时限 → 源暂停（不探测、不起 ffmpeg），卷从卡住中恢复时自动解除；源可达但 ffmpeg 仍读不动的本取帧器不再重试，换集 / 重开页会新建取帧器。`extractVideoFrameViaFfmpeg` 加 `onTimedOut` 回调与 `inputPresenceChecked`。
  - 上述抽取 / 导出 / 对轴入口改成有界探测；unavailable 一律按「这次取不到」返回，不当成文件丢失：片段导出新增 `VideoClipExportFailure.inputUnavailable`（新文案 `video_clip_export_input_unavailable`），内封字幕抽取报 `stalled`。起播检查 `isLocalVideoResourceMissing` 只在卷答复「不在」时判缺失，卷卡住照常交给播放内核。
  - 播放 UI 路径上的临时文件同步 IO 全部改异步；截图重名 helper 改成异步回调。
- **[x] ② 已加自动化测试** —
  - `fushi/test/media/video/media_path_probe_test.dart`：注入永不答复的假文件系统，验证超时答 unavailable 而非 missing、同路径合并、同卷不再压新 stat、同卷并发上限、卷恢复唤醒；起播检查卷卡住不判缺失；`extractVideoFrameViaFfmpeg` 输入卷卡住时有界返回、不起 ffmpeg；取帧器暂停 / 恢复 / ffmpeg 连续超时停手 / 单飞。
  - `fushi/test/build/video_playback_sync_io_guard_test.dart`：源码守卫两层——播放 UI 路径文件整份禁同步文件 IO；视频相关目录禁对媒体输入路径同步判存在（`videoMemberExistsSync` 等或 `File(<…inputPath|videoPath|…>).…Sync(`），白名单逐条写理由。

- **审查后修正**（独立审查第 9、10 条）：
  - 有界探测被铺到了导入 / 扫描 / 回填 / 用户主动操作上：冷挂载首个 stat 超过 2 s 就整卷标卡住，整批导入静默没封面 / 元数据，片段导出报假的「暂不可用」。根因是一个入口承担了两种意图。现分成两个入口（`media_path_probe.dart` 文件头）：`probeMediaPath` / `probeVideoMember` / `probeLocalMediaFile` 只给推测性 / 悬停类路径（缩略图取帧、起播预检）；新增必达入口 `awaitMediaPathExists` / `awaitVideoMemberExists` / `awaitLocalMediaFileExists`：无时限异步，卷卡着先等 `whenMediaVolumeRecovered` 再发 stat，自己的 stat 慢过 2 s 照样标卷卡住（让推测性路径停手）并接着等真实答复，排队期间被跳过就恢复后重来；共用同路径合并与同卷并发上限。`desktop_audio_clipper.dart` 全部抽取器入口、`video_cover_extractor.dart`、`video_clip_exporter.dart`、`embedded_reference_subtitle_sync.dart` 改用必达入口；`VideoClipExportFailure.inputUnavailable` 与文案 `video_clip_export_input_unavailable` 删除，内封字幕抽取不再因探测超时报 `stalled`。守卫第 3 层：有界探测只许出现在登记过的推测性路径文件里。
  - 缩略图：调度器不读 `isUnavailable`，每次 hover 都再问取帧器，卷恢复后暂停自动解除，本身不会永久降级；但取帧器把「ffmpeg 跑满时限」也计入「从没成功过」熔断，冷挂载上两次超时 + 恢复后一次普通失败就凑满 3 次、永久只显时间戳。改为超时不计入熔断计数。
  - 播放页异步化逐个复核：`video_player_controller.dart` 缓冲副本落盘后先做异步判存在 / 长度、再查换集（原来先查换集，await 期间换了集仍会把上一集的副本交出去）；`clip_export.part.dart` 截图重名改成原子占名（`claimVideoScreenshotFile`，独占新建），原来「异步判存在、再写」在连按截图时两次判定交错拿到同一个名字、后写覆盖先写，写失败时删掉占名留下的空文件；`advanced_mining` / `lookup_mining` / `subtitle` 三个 part 的改动只涉及临时文件清理与远端下载结果判定，await 后没有用到 `context` / 控制器状态，无需改。
