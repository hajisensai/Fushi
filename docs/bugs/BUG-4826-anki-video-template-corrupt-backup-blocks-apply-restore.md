## BUG-4826 · Anki 视频模板：备份目录里一个坏文件让应用 / 恢复全挂
- **报告**：2026-11-17（小说 / 漫画 / 视频优化清单复核 gap-vidmisc-9）
- **真实性**：✅ 真 bug（代码路径确证）。根因 `fushi/lib/src/anki/anki_video_template_service.dart:373-399`（`_findBackup`）与 `:401-427`（`_latestRestoredOptions`，均为修前行号）：列出备份目录后按文件名倒序逐个 `jsonDecode(await file.readAsString()) as Map<String, dynamic>`，没有 try。`_latestRestoredOptions` 在应用路径上，`_findBackup` 在应用与恢复两条路上，所以同一目标下任何一份写坏的备份（写到一半进程被杀、磁盘满）都让之后每次应用 / 恢复在读到它时抛 `FormatException` / `TypeError`，功能整体不可用，只能手动去删文件。写入用 `writeAsString(flush: true)`，触发概率低。
- **[x] ① 已修复**（bf6512028da）— 两个循环合成一条 `_backups(target)`（新的在前）+ `_readBackup(file)`：逐文件 try，读不出来 / 不是合法 JSON / 形状不对（`options`、`originalMappings` 缺失或类型不对，含原始映射的值不是字符串 / null）的跳过并经 `ErrorLogService.logDiagnostic` 记一条，继续找更早的有效备份。目录本身取不到（`backupDirectoryResolver` 抛）仍然照旧向上抛，不吞。同一提交把查找键里的后端标识从 `_repository.runtimeType.toString()` 冻成常量（`AnkiConnectRepository` / `AnkiRepository`，即现有两个可编辑后端的类名原值——存量持久化值，不换新值），类改名 / 抽子类 / 混淆不再让旧备份失配。
- **[x] ② 已加自动化测试** — `fushi/test/anki/anki_video_template_service_test.dart` 组「BUG-4826 坏备份不挡住有效备份」6 条（恢复 / 改字段再应用 / 恢复后重新启用 / 原始映射值类型不对的备份同样跳过 / 当前格式的存量备份（逐字写死、含值为 null 的原始映射）读得回来 / 只有坏文件时按「没有备份」报而不是 FormatException），组「备份键里的后端标识是冻结常量」3 条（真后端的子类仍写出父类名常量，文件名前缀 = sha256(target)）。
- **备注**：复核判定不做的两项没做：按时间裁剪备份（`restore` 依赖「非 restoring 且 options 相同」那一份里的原始映射，按时间删可能删掉仍在用的那份）、把键换成新的稳定标识（换键本身就是一次失配）。已知边角（审查提出，未改）：最新一份备份是**写完整之后**才坏掉的（不是写到一半），且同一目标下还有一份 options 相同的更早备份时，恢复会用更早那份里的原始映射；写到一半就坏的那种（进程被杀）模板还没写，更早那份正是该用的，两种情况从文件上分不出来，拒绝恢复等于把本 bug 放回来，所以只留诊断日志 `skipped unreadable backup`。
