## BUG-5360 · Jimaku 混合编号：本地集号命中挡住服务端按集回退，要的语言 / 版本整个漏掉
- **报告**：2026-11-24（外部审查 HBK-AUDIT-004 P2，来自 #4286）
- **真实性**：✅ 真 bug。`packages/fushi_engine/lib/media/video/jimaku_subtitle_provider.dart:107`（修前）只在本地 `parseSubtitleEpisode` 零命中时才问服务端 `?episode=`，而语言过滤在其后（修前 `:131`）。第二季第 2 集的条目里同时有本季编号的 `S2 - 02.en.srt` 和全系列连番的 `- 14.ja.srt`（服务端按 anime-relations 映射成第 2 集）时：本地命中英文 → 跳过服务端 → 英文被 `languages: [ja]` 滤掉 → 日文结果为空；同语言时也会少一个版本。区间命名（`01-02.ass`）同理。连带：服务端映射来的候选 `episode` 取的是本地解析的 14（修前 `:337` `file.episode`），`attachSubtitleSelection`（`video_download_pipeline_service.dart` `episode ?? candidate.episode`）在调用方没给集号时会把 14 落库，之后按 `row.episode == file.episode` 对不上第 2 集。
- **[x] ① 已修复** — 新增纯函数 `jimakuEpisodeNumberingAmbiguous`（全表单集文本字幕有解析不出的、有集号区间的、或续作里有同模板组从 >1 起编的连番命名 ⇒ 有歧义）。带集号搜索时「本地零命中 **或** 有歧义」都按集问一次服务端，服务端结果在前、并入本地命中，与整季包按 URL 去重后再做语言过滤。按集回退失败：本条目已拿到的本地命中与整季包照样交出，失败如实带回并停止问后续条目；什么都没拿到才整次失败。带集号搜到的单集候选 `episode` 一律是请求集号。第一季 / 无歧义的常见命名仍是「条目搜索 + 一次全表」，不多花配额（25 次/窗口）。
- **[x] ② 已加自动化测试** — `fushi/test/media/video/jimaku_search_request_budget_test.dart` 组「集号歧义：本地有命中也要问服务端（BUG-5360）」：续作混合编号 + 语言过滤（日文第 2 集保留、候选集号为 2、恰好 3 次请求）、同语言两种编号都在且去重、区间命名、续作全按本季编号不多打、按集回退 429 保留本地命中与整季包并报部分失败且不重试、回退 429 且一无所获时整次失败；另有 `jimakuEpisodeNumberingAmbiguous` 判据真值表。修前 5 条红、修后全绿。
- **备注**：歧义判据是启发式：续作里零散上传（只传了 5~8 集）也会多问一次服务端（每条目至多一次，条目数受 `kJimakuMaxEntriesPerSearch` 约束）；第一季里的连番 / 映射本就不需要。合集批量面板的搜索不带集号、按候选本地集号对集，续作连番命名的文件在那条路径上仍按 14 对集——不是本条范围，未改。
