## BUG-5117 · 断点续传把「总长相同」当版本身份，等长替换后拼成坏片
- **报告**：2026-11-22（外部审计 HBK-AUDIT-033，Codex 2026-11-21 PR 审查 `docs/reviews/2026-11-21-project-review.md`，源自 PR #3817）
- **真实性**：✅ 真 bug。`packages/fushi_engine/lib/media/video/media_server/media_server_resumable_download.dart`（修前 cbdc2a45ed）：`MediaServerResumeSidecar.hasValidator`（:55）把只有 `totalBytes` 的侧车也算「有验证器」，于是带 `Range` 续传——没有 ETag / Last-Modified 可放进 `If-Range`，服务器无从拒绝；`sameStreamAs`（:92）对 206 逐字段「两边都有才比」，只剩 `Content-Range` 总长相同也返回 true（:111 `compared > 0`）。服务器上的文件被**等长替换**、或新的 206 不再回显上次的 ETag / Last-Modified 时，旧前缀 + 新后缀被拼成一个文件。弱 ETag（`W/`）也被当作身份，并原样放进 `If-Range`（RFC 9110 §13.1.5 不允许）。修前用本机 HTTP 服务端实测：无验证器 / 弱 ETag / 206 丢 ETag / 206 丢 Last-Modified 四种等长替换都发出了 `Range: bytes=49152-` 并被接受（4 个用例红）。在线源直链下载 `fushi/lib/src/media/video/online/anime_episode_downloader.dart` 的 `DirectStreamValidator.isEmpty` / `sameStreamAs` 与 `AnimeComponentIdentity.matches` 是同一条规则的拷贝，同样成立（等长替换的完整画面分量会被直接拿去合成）。
- **[x] ① 已修复** — 版本身份规则收进 `packages/fushi_engine/lib/utils/misc/resume_validator.dart`（`ResumeValidator`）：只认强验证器（非 `W/` ETag 或 Last-Modified）；没有强验证器不续传、从 0 重下；206 必须**回显** `If-Range` 用的那个验证器且相等，其余共有字段（另一验证器、总长）任一不同也作废，总长只能否定、不能证明；`If-Range` 只放强 ETag / Last-Modified。媒体服务器侧车（`hasStrongValidator` / `sameStreamAs` / `ifRangeState`）、在线源直链续传与完整分量复用（`AnimeComponentIdentity.matches`）都改走它。旧版只有总长的侧车读到即作废。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/media/video/media_server_resumable_download_validator_test.dart`（真实本机 HTTP 服务端：无验证器 / 弱 ETag / 206 丢 ETag / 206 丢 Last-Modified 的等长替换都从 0 重下且结果是新版本；强 ETag / 仅 Last-Modified 照常带 If-Range 续上）；`fushi/test/media/video/online/anime_episode_downloader_test.dart` 新增无验证器等长替换不续传、206 丢 ETag 作废重下、无 ETag 等长替换的完整分量不复用三例。
- **备注**：代价——服务器既不给 ETag 也不给 Last-Modified（或 206 不回显）时，中断后不再续传而是整份重下；Plex 直出端点是否带这两个头未在真实服务器上核对（真机 / 真服务器验证未做）。
