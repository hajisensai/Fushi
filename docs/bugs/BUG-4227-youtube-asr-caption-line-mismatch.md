## BUG-4227 · YouTube 自动字幕制卡错位：悬停上一行配了下一行的例句与片段、Dart 解析不截滚动重叠
- **报告**：2026-11-07（用户：应用内反馈 RvwGCEtAsd，Windows 3.0.1-debug.21804；「直接打开 YouTube 视频字幕制卡（再将浏览器卡片缓存制卡）直接导出就会错位」，截图里卡片的词是 striking、例句却是另一行 "algebraic like ways to concretely"）
- **真实性**：✅ 真 bug，三处同类（都是「YouTube 滚动自动字幕上下两行 = 两句」没被正确区分）：
  - **已在 develop 修过（不在用户的包里）**：旧版 DOM live 采样把两行拼成一条 cue、起点取新行出现时刻 → `ff749a5df9`（按行采）+ `da8451255b`（后到的整轨替换自动选中的 live 轨）。
  - **悬停原生字幕取错行（develop 仍在，与截图最吻合）**：扩展 Shift 悬停 `.ytp-caption-segment` 查词时 `tools/browser-extension/content.js:2623` 给 `fushiSendLookup` 传 `cueWindow = null`，制卡时 `fushiMineContext`（`content.js:1194`）只能按当前播放时刻在整轨里取 cue（`subtitle-adapters.js:405-416` `findCueIndexAt`）。ASR 轨被 `clampRollingCues` 截断后上一行 A 的终点 = 下一行 B 的起点，此刻只命中 B：悬停 A 里的词，例句与片段时间窗都取了 B。
  - **Dart 解析不截滚动重叠（develop 仍在）**：`packages/fushi_engine/lib/media/video/youtube_source_resolver.dart` `_parseFormat3TimedText` / `_parseSrv1TimedText` 直接 `start + dur`，自动字幕每行覆盖到滚走为止，cue 尾部多带几秒下一句。BUG-2629 只修了扩展 json3 路径；原生播放器字幕（`subtitle.part.dart` → `resolveYoutubeCaptionCues`）与扩展的服务端兜底（`resolveYoutubeCaptionsForExtension`）没有。
- **[x] ① 已修复** — 扩展：悬停命中站点原生字幕时按 `fushiCaptionLineGroups`（与 live 采样同一份分行规则）取被悬停那一行的文本，在整轨里起点不晚于当前时刻的最近 4 条 cue 中匹配（全文相等优先，其次 `fushiCueTextRelated`），作为精确窗传给查词 / 制卡（`subtitle-providers.js` `fushiCaptionLineCueWindowAt`）；对不上保持按播放时刻取整轨。两份镜像经 `scripts/sync-mirrors.mjs` 同步。Dart：新纯函数 `finishYoutubeCaptionCues`（稳定排序；ASR 轨终点收到下一条起点，人工轨不动，与扩展 `clampRollingCues` 同语义），`resolveYoutubeCaptionCues` 按 `track.isAutoGenerated` 统一收尾。
- **[x] ② 已加自动化测试** — `tools/browser-extension/native-caption-line-cue.test.js`（两行 `.caption-visual-line` 夹具，now=4000，悬停 A 行取 A[1000,3000)、悬停 B 行取 B、对不上 / 非字幕节点保持原行为；改前 A 用例拿到 B 的文本）；`fushi/test/media/video/youtube_source_resolver_test.dart` `finishYoutubeCaptionCues` 组（真实 format 3 ASR 样本截到下一行起点、人工轨不截、乱序稳定排序）。
- **备注**：`resolveYoutubeCaptionCues` 的接线（IO 下载）没有单测，只测了纯函数。未在真实 YouTube 页面 / 真机复测。用户版本 3.0.1 较旧，升级后 live 采样那一半已不存在。
