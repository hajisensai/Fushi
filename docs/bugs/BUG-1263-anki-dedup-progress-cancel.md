## BUG-1263 · Anki媒体去重真删与扫描为分钟级长任务却无进度不可取消且期间Anki无响应
- **报告**：2026-07-31（用户：点「删除这些文件」（940 个副本 / 26.4 MB）后没有任何进度显示，且期间 Anki 进入不可用状态）
- **真实性**：✅ 真 bug。真删/扫描每个副本至少 2 次 `findNotes` 全库检索 + 逐条 `notesInfo`/`updateNoteFields`/`deleteMediaFile`，全部串行 HTTP（`packages/hibiki_anki/lib/src/ankiconnect/ankiconnect_repository.dart` `runMediaDedup` 主循环）；而 UI 侧 `hibiki/lib/src/pages/implementations/anki_settings_page.dart` `_runDedupPass` 只有一个 `_dedupBusy` 布尔，「立即去重」行连 trailing 转圈都没有——分钟级长任务零反馈、不可取消。「Anki 不可用」是 AnkiConnect 在 Anki 主线程执行动作的平台约束：请求风暴期间 Anki UI 必然被占满，任务结束即恢复；Hibiki 侧无法绕开，只能做可见（进度）、可控（取消）、可预期（提前告知）。
- **[x] ① 已修复** — `runMediaDedup` / `AnkiMediaDedupRunner.runNow` 增加 `onProgress`（scanning → hashing → resolving 阶段 + done/total + 当前文件 + 已释放字节）与 `shouldCancel`（副本边界干净取消，部分结果以 `cancelled: true` 如实报告，取消轮不推进自动扫描时间戳）；共享弹窗层新增 `runAnkiMediaDedupWithProgress`（模态进度对话框 + 取消按钮），设置页手动路径与首页自动确认路径共用；确认弹窗新增「执行期间 Anki 可能暂时无响应」提示（`anki_dedup_plan_busy_note`）。
- **[x] ② 已加自动化测试** — `packages/hibiki_anki/test/anki_media_dedup_orchestration_test.dart`（取消边界 + 进度阶段/计数自洽）、`hibiki/test/anki/anki_media_dedup_auto_test.dart`（runNow 回调透传 + 取消轮不推时间戳 + 源码守卫加强为自动路径正文禁现 `dryRun: false`，已变异实测）、`hibiki/test/anki/anki_media_dedup_progress_dialog_test.dart`（弹窗出现/更新/取消/关闭，含瞬间结束不留遮罩）。
- **备注**：Anki 冻结的根因（AnkiConnect 跑在 Anki 主线程）属外部平台限制，无法根治，只能缓解；若后续要压缩总时长，可把每 note 的 `notesInfo` 换成批量 `notesInfoMany`（现路径多数副本仅 1 条引用，收益有限）。
