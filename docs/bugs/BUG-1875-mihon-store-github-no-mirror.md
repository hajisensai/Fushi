## BUG-1875 · Mihon 扩展仓库索引拉取直连 GitHub 超时无镜像回退
- **报告**：2026-08-25（用户：）
- **真实性**：✅ 真 bug。用户 Windows 添加 Mihon 扩展仓库报 `ClientException with SocketException: HTTP connection timed out after 0:00:20.000000, host: github.com, port: 443, uri=https://github.com/.../raw/repo/index.pb`。根因 `fushi/lib/src/media/manga/mihon/mihon_extension_store_client.dart:300`（改前的 `_get()`）：仓库索引 / 扩展列表 / APK 全部单 URL 一次成败，直连 `github.com` 吃满 `fushi/lib/src/utils/net/app_http.dart:48` 的 20s `connectionTimeout` 后整轮失败；而 app 早有一份对 raw / release 直链有效的公共镜像名单（原 `fushi/lib/src/utils/misc/update_checker_net.dart:29` 的 `updateCheckProxyPrefixes`），这条链路从没用上。
- **[x] ① 已修复** — 本轮提交。镜像名单搬到 `fushi/lib/src/utils/net/github_mirrors.dart` 作全仓唯一真相源（`kGitHubMirrorPrefixes` / `isGitHubDownloadHost` / `gitHubMirrorCandidates` / `isTransportFailure`），`updateCheckProxyPrefixes` 改为其别名；`_get()` 改为对候选顺序尝试 `_getOnce()`，只有传输层失败（socket / timeout / TLS / `http.ClientException`）才换下一候选，`STORE_HTTP_xxx` / `TOO_MANY_REDIRECTS` 等服务端已答复的错误立即抛出，全部候选传输失败时抛直连的原始错误；302 每一跳独立回退，`downloadApk` 经 `_get()` 自动获得回退。
- **[x] ② 已加自动化测试** — `fushi/test/utils/net/github_mirrors_test.dart`（候选生成 / host 判定 / 错误判型）+ `fushi/test/media/manga/mihon_extension_store_client_test.dart` 的 group「GitHub mirror fallback」（直连失败换镜像并断言请求顺序、404 不回退、非 GitHub 域只请求一次、全失败抛直连错误、302 跳转后那一跳独立回退、`downloadApk` 同享回退）。
- **备注**：用户那条 URL 本身还有另一个与本 bug 无关的问题——yuzono/manga-repo 的 `repo` 分支没有 `index.pb`（上游死壳，README 指向 keiyoushi 官方 URL），所以即便网络通了那条地址也是 `STORE_HTTP_404`；本修复不掩盖它（404 是服务端已答复的错误，不回退镜像、原样抛出）。
