## BUG-1829 · 快速拨滚轮永远跨不了章：跨章冷却窗被每次被拦输入自我续期
- **报告**：2026-08-24（用户：「这一页上下滚轮很难滚」；现场是 `安達としまむら` 第 1 卷的零字符图片章，Windows 桌面版 2.2.1-debug.12170，`wheel_page_turn_interval=450`）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/pages/implementations/reader_fushi/chrome.part.dart` 的 `_chapterTurnCoolingDown()`：判据取「距上次**输入**多久」，且**在拦截时把时间戳滑到当下**（`if (cooling) _lastChapterTurnInputAt = DateTime.now();`）；`_paginate` 的 `_paginationInFlight` 丢弃分支与 `webview.part.dart` `onBoundarySwipe` 的同款分支也各 stamp 一次。真实滚轮每 30~100ms 一个事件，用户只要还在拨，450ms 的窗口就被自己的输入无限续期、**永远等不到过期**——拨得越快越不动。页内有可滚量的正文长章不受影响（滚轮走章内翻页，不进跨章判定）；**单页章**（封面 / 插图 / 目录 / 版权页 / 尾页）里 `paginate()` 恒返回 `"limit"`，每一次滚轮都必须走跨章判定，于是整章成为滚轮死区。
- **[x] ① 已修复** — 把冷却锚定到**跨章事件本身**而不是输入：`_lastChapterTurnInputAt` → `_lastChapterTurnAt`、`_noteChapterTurnInput()` → `_noteChapterTurn()`、纯判据参数 `lastInputAt` → `lastTurnAt`（名字本身就是那条错误判据的来源）；`_chapterTurnCoolingDown()` 改成**纯读无副作用**；删掉 `_paginate`（`chrome.part.dart`）与 `onBoundarySwipe`（`webview.part.dart`）两个在飞丢弃分支里的 stamp。窗口此后只由两种真实事件推进：① 真正发起一次跨章；② 该次跨章落地的新章 content-ready 重锚 `_noteChapterTurnSettledIfPending()`。**「跳两章」的防护没有丢**：那正是 TODO-1229 v3 加 content-ready 重锚要解决的，v2 的「每次输入滑窗」在 v3 落地后已经多余，只剩危害——同形教训见 `feedback_add_a_param_is_not_a_root_fix`（用阈值带盖住判据错误，必然在带的另一端制造对称的新 bug）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/chapter_turn_cooldown_test.dart` 重写：纯判据 4 条 + **饥饿回归 4 条**（用一个 `turnsIn(gap, ticks, stampOnBlocked:)` 模型同时跑新旧两种 stamp 规则：旧规则下任何小于冷却窗的间隔、持续 3 秒都只跨 1 章；新规则下密集输入稳定推进且不随变密而下降；节流与冷却窗同长的单页章场景仍能连续跨章）+ 源码守卫 6 条（闸门必须纯读、两条在飞分支不得 stamp、时间戳全语料唯一写入点、跨章前过闸门、真跨章时 stamp）。`chapter_turn_cooldown_ready_restamp_test.dart` 随 API 改名更新，v3 的三条重锚断言全部保持绿。**已变异实测**：把三处滑窗加回后，4 条源码守卫全部转红。
- **备注**：真机实测（用户机上的 2.2.1-debug.12170，`安達としまむら` 第 1 卷）——从零字符图片章连发 5 次滚轮：间隔 100ms **零跨章**、300ms 跨 4 章、600ms/1200ms 正常；对照组在同一本书 21116 字的正文长章用同样 100ms 快拨则完全正常（`584 → 1471 → 2342` 字）。这组对照把 bug 精确定位到「单页章 → 跨章路径」。修复后**未做真机复测**（修复只存在于 worktree，未出包）。
