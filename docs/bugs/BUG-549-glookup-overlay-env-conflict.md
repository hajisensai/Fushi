## BUG-549 · Windows app-external lookup shows no popup (overlay WebView2 env fails silently)
- **报告**：2026-07-05（用户：）
- **真实性**：✅ 真 bug（V44 真机日志坐实：覆盖窗 WebView2 从不导航 → 透明空窗）。根因 `hibiki/windows/runner/global_lookup_window.cpp::EnsureWebView`：覆盖窗独立 WebView2 env 注册 image:// + dictmedia:// 自定义 scheme，却用 `CreateCoreWebView2EnvironmentWithOptions` 第 2 参 `userDataFolder=nullptr`（进程默认 folder），与应用内 fork WebView2 env 共享同一 user data folder 但 options 不一致 → WebView2 禁止（`0x8007139F` ERROR_INVALID_STATE）→ env 创建失败。两回调静默吞（env 回调不检 HRESULT、controller 回调 `ctrl==nullptr` 直接 `return S_OK`）且同步 HRESULT 被丢弃 → `Navigate` 永不执行 → `NavigationCompleted`（`webview_ready_=true`）永不触发 → 恒 false → 强制 reveal 空透明窗。
- **[x] ① 已修复** — commit `<PENDING>`。①覆盖窗改用专属 userDataFolder（`%LOCALAPPDATA%\Hibiki\GlobalLookupWebView2`，helper `OverlayUserDataFolder()` `global_lookup_window.cpp:131`），使覆盖窗成独立 WebView2 profile scope，options 不再与主窗口 env 撞（保留 image://+dictmedia:// scheme，查词卡片图/词典媒体不裂）。②必配：`EnsureWebView` 捕获 `CreateCoreWebView2EnvironmentWithOptions` 同步 HRESULT（`global_lookup_window.cpp:621`）、env 回调检 `FAILED(env_hr)||env==nullptr`（`:547`）、controller 回调检 `FAILED(ctrl_hr)||ctrl==nullptr`（`:563`），全部经 `ReportOverlayError`（`:496`）写 `%TEMP%\hibiki_glookup.log`（`NativeGlog` `:91`）+ 经新 channel 方法 `nativeError` 上报 `ErrorLogService`（`flutter_window.cpp` SetErrorCallback + `global_lookup_channel.dart` nativeError case），对齐 TODO-1086 热键失败可见，不再静默。
- **[x] ② 已加自动化测试** — 源码扫描守卫 `hibiki/test/windows/global_lookup_env_guard_test.dart`：断言 `EnsureWebView` 不再以 `nullptr` 作 userDataFolder 创建带自定义 scheme 的 env（用 `OverlayUserDataFolder()`），且两条创建回调都有错误处理（`ReportOverlayError` / 检 `FAILED(...)||...==nullptr`），防回退到静默吞失败。
- **备注**：C++ 运行时改动无 Dart 单测覆盖真实 WebView2 行为，故加源码结构守卫 + 真机验证 `hibiki_glookup.log` 中 `webview_ready_` 逻辑通。很可能一并修 TODO-1065②/1079/1086/1095 族的「应用外查词唤不出/空窗」。
