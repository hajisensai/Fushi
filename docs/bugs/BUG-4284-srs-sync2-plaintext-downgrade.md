## BUG-4284 · SRS 同步 v2：没有密钥的设备会往已加密的位置写明文
- **报告**：2026-11-10（安全审查：存储位置端到端加密，设计 docs/specs/2026-10-25-srs-sync-v2-design.md §9）
- **真实性**：✅ 真 bug（沿真实代码路径确认，行号为修复前 `94317ab6295`）。握手只看这一刻的 `meta.json`，而它是多设备可改写的单文件：
  - (a) `meta.json` 被旧版本 / 别的设备整份重写丢了 `kdf`：`packages/fushi_engine/lib/srs/sync2/srs_location_crypto.dart:283` `if (key == null) return h;` 把无密钥设备放成明文轮次 → `srs_sync2_round.dart:258` `beforeUpload(null)`（明文媒体）、`:263-280` `outbox` 不带 key（明文段）、`:298` 转发不带 key、`:363-365` 写 head。拉到的密文段在内核只报 `Undecryptable`（`native/fushi_fsrs/src/sync2/segment.rs:650`），Dart 侧当非致命错误收下（`srs_sync2_round.dart:489-491`，字段定义 `:142-143`），不挡发件。**会**。
  - (b) `meta.json` 缺失且列目录暂时为空：`srs_location_crypto.dart:243-266` 判 `devices/`、`media-e/` 都空就 `put` 一份新 meta（无密钥时不带 `kdf`，`:257-260`，还会盖掉一份其实存在的加密 meta），随后同 (a) 发明文。**会**。
  - (c) 一台先明文写过、另一台后开加密：稳定状态下前者读到带 `kdf` 的 meta → `srs_location_crypto.dart:304-306` 报要口令，**不会**；但前者这一轮读到的仍是开加密之前的 meta（最终一致 / 并发）时走 (a) 的路径，**会**（至少一轮明文）。
  - (d) 本机用密钥同步过、之后密钥被清掉：meta 上 `kdf` 还在时同 (c) 报要口令，**不会**；再碰上 (a)/(b) 时本机对「这里加密过」没有任何记录（只有 `sync2_locations` 的 `<位置>#e…` 进度，握手不看），**会**。
  - 同一缺口还在：只做媒体的位置（`srs_folder_location.dart:222` 同一握手 → `:280` 明文媒体对账）、旧根媒体残留迁移（`srs_location_migration.dart:824` 按新根 meta 定写密钥，无 `kdf` 即明文写进新根）。
- **[x] ① 已修复** — 本机一旦见过「这个位置是加密的」就持久记进内核（新 `native/fushi_fsrs/src/store/sync2/sealed.rs`：`srs_meta` 键 `sync2_sealed/<位置>/<profile>` = `{at, kdf}`，不改表结构 / 协议 / 段格式；存量按 `sync2_locations` 的 `<位置>#e…` 进度认；命令 `location_sealed` / `location_seal`，`ffi.rs` 两条臂）。来源：握手读到带 `kdf` 的 meta、本机用密钥收发 / 开加密、`kdf` 认不出、位置上有 `media-e/`、按明文拉段时内核看段头 / 转发件封装位（`sealed_at_location`，只传每段前 8 字节）、只拉不发读到 `kdf`。拒写点：`srsLocationHandshake`（meta 缺失 + 列空不建明文 meta；`kdf` 丢失不降级；记得的校验值不符报口令不对）、`srsSync2Round` 拉段后发件前、`srsMigrateV1Media` 写残留前。错误：记得 `kdf` → `kSrsSync2NeedsKey` 并交回 kdf（界面照它让用户输入口令）；不记得 → `kSrsSync2EncryptionMissing`（界面让用户设口令重新开启）。提交 b2face00c32。
- **[x] ② 已加自动化测试** — `packages/fushi_engine/test/srs/sync2/srs_location_sealed_test.dart`（真 `SrsDbStore` + 内存位置：(a) 两条、(b)、(c)、(d) 含照记下的 kdf 输错 / 输对口令后恢复、明文位置照常）；内核 `sealed.rs` 单测三条；`srs_v1_media_migration_stop_test.dart` 的 `_NoHost` 放行只读的 `location_sealed`。
- **备注**：仍挡不住——本机**从没见过**加密（新设备 / 新装、没有任何记录）的那一轮里，`meta.json` 恰好丢了 `kdf`（或整个位置暂时列空），而这一轮又没拉到任何密封段、位置上也列不到 `media-e/`（例如它要拉的段都已经有、或列目录同样不全）：分不出是明文新位置，仍会按明文写。要彻底挡住只能让「位置是加密的」这一事实不依赖可整份重写的单文件（例如每台设备的 head 里带加密位、或 `meta.json` 只追加），属于协议改动，未做。记下就不撤：位置真的被清空后想改回明文，得换一个位置（与「开了不能在这里关」一致）。
