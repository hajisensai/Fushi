## BUG-3703 · 应用内浏览器里新窗口（target=_blank / window.open）打不开
- **报告**：2026-10-24（用户：浏览器完整化需求里列出「新窗口打不开」）
- **真实性**：✅ 真 bug（Android 真机 43f8ed58 与 Windows 实测复现）。根因：旧浏览页 `fushi/lib/src/pages/implementations/fushi_web_browser_page.dart`（upstream/develop 459d2af220）的 `InAppWebView` 只设 `javaScriptEnabled` / `sharedCookiesEnabled`，没开 `supportMultipleWindows`、没实现 `onCreateWindow` / `onCloseWindow`。Android 上 `onCreateWindow` 根本不触发，新窗口全被改成原页跳转；Windows fork（`packages/flutter_inappwebview_windows/windows/in_app_webview/in_app_webview.cpp` NewWindowRequested 默认兜底）原地 `loadUrl`，`window.open` 返回 null，`window.open('')` 再赋地址会把原页清成 about:blank。多标签页重写后另有一处：Android 发起 `window.open` 时 `action.request.url` 为 null，新标签页 url 为空被画成起始页，带 windowId 的 WebView 没建出来（`fushi_web_browser_page.dart` 的 `_buildTabBody`）。
- **[x] ① 已修复** — `ed0fd73b3f`（`web_browser_tab_view.dart`：`supportMultipleWindows` + `javaScriptCanOpenWindowsAutomatically`，`onCreateWindow` → `host.openTab(windowId:)` 同帧建 WebView 并 `return true`，`onCloseWindow` → `closeTab`）；`63bb38799a`（带 windowId 的空地址标签页照常建 WebView、不进地址栏编辑）。
- **[x] ② 已加自动化测试** — `fushi/test/pages/fushi_web_browser_shell_test.dart`（「window.open 新窗口：Android 发起时没有地址也照常建 WebView 接走 windowId，不弹地址栏」）；`fushi/integration_test/web_browser_shell_itest.dart`（Windows 真 app：`target=_blank` 与 `window.open` 都开新标签页）。
- **备注**：Android 真机复测通过（`window.open` 新标签页显示弹窗页内容）；iOS/macOS 同一实现未实机验证。
