## BUG-1061 · 制卡 {glossary} 词典名前多出自造序号「1」
- **报告**：2026-07-24（用户：「制卡的词典名前面还有个 1，这个多余的吧」）
- **真实性**：✅ **真 bug（沿真实代码路径 + 上游模板比对）**。`{glossary}` 字段的 HTML 由 `hibiki/assets/popup/popup.js` 的 `constructGlossaryHtml` 拼装，修复前它维护一个自增 `index`，每条义项的标签写成 `` `(${index}, ${tags}, ${dictName})` `` / `` `(${index})` ``，卡片上就成了「(1, 词典名)」。两个基准都没有这个序号：① 上游 Yomitan 的 `ext/data/templates/default-anki-field-templates.handlebars` 里 `glossary-single` 只输出 `(definitionTags…, dictionaryAlias)`；② 本仓同一文件的 `constructSingleGlossaryHtml`（`{glossary-first}` / `{single-glossary-*}` 走这条）一直是 `` `(${tags}, ${dictName})` `` / `` `(${tags})` ``。即同一份文件里两条制卡路径格式不一致，序号是 `{glossary}` 这一条自造的。根因 `file:line`：`hibiki/assets/popup/popup.js:889`（及 `:857` 的 `let index = 0;`、`:879` 的 `index++`，两份 vendor 镜像同行）。
- **[x] ① 已修复** — 提交 `c30d2a556`。根因修：删掉 `index` 计数器及其在标签里的插值，`constructGlossaryHtml` 的标签与 `constructSingleGlossaryHtml`、与上游 Yomitan 完全一致——同一词典的首条义项标 `(tags, 词典名)`（无 tags 时 `(词典名)`），同词典后续义项标 `(tags)`（无 tags 时为空）。三份镜像（`hibiki/assets/popup/`、`hibiki/assets/browser_extension/vendor/`、`tools/browser-extension/vendor/`）同步改。
- **[x] ② 已加自动化测试** — `hibiki/test/pages/popup_glossary_export_parity_test.js`（Node 真执行 `constructGlossaryHtml`：两词典三义项的标签必须恰为 `['(JMdict)', '', '(Daijirin)']`，且全文不得出现 `(1,` / `(1)` 形态的序号；并断言 `{glossary}` 与 `{glossary-first}` 对同一词典给出同一标签）+ Dart driver `hibiki/test/pages/popup_glossary_export_parity_test.dart`（跑 JS + 三镜像源码守卫：`let index = 0;` 与 `` label = tags ? `(${index}` `` 不得复活）。已双向验证：把序号写回去后测试变红（实测 `['(1, JMdict)', '', '(1, Daijirin)']` 与期望不符）。`flutter test test/pages/popup_glossary_export_parity_test.dart test/pages/popup_mining_hidden_dictionary_test.dart test/anki/ test/build/browser_extension_popup_parity_guard_test.dart --no-pub` → 170 绿。
- **备注**：与 BUG-1060（同一次用户报告的第一条：制卡词典图片比 Yomitan 小很多）同批修复。**真机肉眼复测待用户**：查词制卡后在 Anki 里看 `{glossary}` 字段——词典名前不再有「1，」，多词典/多义项时的分组与 Yomitan 卡片一致。
