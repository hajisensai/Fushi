## BUG-4227 · Android 平板外部查词浮卡近乎全屏、调最大宽高无效
- **报告**：2026-11-07（用户反馈 K9YPrjtZE1：Xiaomi KPad，Android 16 / HyperOS，窗口 668×1070@2.81；系统文本选择菜单 PROCESS_TEXT 与悬浮球两条入口都复现，调「查词窗口最大宽度 / 最大高度」无效）
- **真实性**：✅ 真 bug，与分诊一致。app 外独立查词窗 `PopupDictionaryPage` 的卡片尺寸在 `fushi/lib/src/pages/implementations/popup_dictionary_page.dart` `_buildPositionedCard`（修复前 :558 贴顶分支、:585 贴字分支）：高度写死 `(可用高 − 2·gap) × 0.72` 且是**固定** `SizedBox` 高度，完全不读最大高度设置；宽度读 app 内 `popupMaxWidth`（:537 `_externalPopupMaxWidth`），无视「app 外覆盖窗独立尺寸」（`AppModel.overlayLookupEffectiveSize`）。平板竖屏 1070 高时卡片高 758.88（71%），宽 480/668，于是近乎占满屏幕。
- **[x] ① 已修复** — `effective_lookup_size.dart` 新增纯函数 `resolveExternalPopupCardBounds`（宽高上界 = `overlayLookupEffectiveSize`，再以可用空间封顶：宽 ≤ 可用宽，高 ≤ 可用高 × `kExternalPopupMaxHeightFraction`(0.72，原屏幕比例天花板保留，任何屏幕都不比修复前大)）与 `resolveExternalPopupCardHeight`（按内容收缩、不超上界）。`PopupDictionaryPage` 两个分支都走它们；最上面可见层的 `layoutAutoFitHeight` 驱动外壳高度，`onContentMetrics` 经 `resolveAutoFitPopupHeight` 写 `setAutoFitHeight`，WebView 仍按上界高度布局、超出裁掉（`webViewOverflowHeight`），与 app 内弹窗同一机制；卡片包 `ListenableBuilder(_popup)` 跟随重算。提交 `41bfe28807`。
- **[x] ② 已加自动化测试** — `fushi/test/pages/popup_dictionary_tablet_size_test.dart`：纯函数 6 条 + 真 widget 4 条（668×1070 平板默认尺寸卡片 = 480×480；设了 app 外最大宽高 360×320 时卡片 = 360×320；手机竖屏 392×850 不超过旧上限；手机横屏 850×392 保持旧屏幕比例天花板）。去掉修复（页面回退到 develop）时红 3 条：平板 `Expected 480.0 / Actual 758.88`、手机竖屏 `Expected 480.0 / Actual 600.48`、设置值那条在旧代码读 `popupMaxWidth` 时崩；横屏那条修复前后都绿（证明横屏无回归）。修复后 10/10 绿。`popup_layout_width_columns_test.dart` 的 TODO-1352 源码守卫改为钉 `appModel.overlayLookupEffectiveSize`；三份页面测试桩补 `overlayLookupEffectiveSize` 覆写（桩无 prefsRepo）。
- **备注**：未上真机 / 平板复测。按内容收缩依赖 popup.js 上报的 `contentMetrics`，widget 测试里没有真 WebView，只由纯函数守住上限与收缩规则。非 Android 的 in-app 查词对话框（`openPopupDictionaryLookup` → `FushiDialogFrame`）用的是同一页面，卡片同样改为受设置约束，对话框外框尺寸未改。
- **[x] 核验补修（界面大小）** — 首版修复的尺寸链漏乘界面大小：`popup_dictionary_page.dart` 整树套 `FushiAppUiScaleNeutralizer`（净缩放 = 1），上界直接用 `overlayLookupEffectiveSize` 基准值、「未找到」空态高直接用 `kLookupPopupEmptyHeight`(280)、`onContentMetrics` 最小高直接用 `kLookupPopupMinHeight`，违背「基准逻辑像素、宿主再乘界面大小」约定（`effective_lookup_size.dart` 常量注释；`base_source_page.dart` `popupMaxWidth/Height`、`kLookupPopupEmptyHeight * appUiScale`；`global_lookup_controller.dart` `overlaySize × appUiScale`）。平板竖屏自动 appUiScale≈1.11 时：同一设置 app 外 480 而 app 内 / 桌面约 533；空态内容按 popupUiScale 放大约需 311 却只给 280，底部建议行被裁（首版引入）。修复：`resolveExternalPopupCardBounds` 新增必填 `uiScale`（设置值先乘再封顶），页面新增 `_popupBoxScale`（已初始化取 `appModel.appUiScale`，否则 1，与 popup_main 的 `FushiAppUiScale` 同口径），空态高、最小高同乘。
- **[x] 核验补测** — 同一测试文件新增：纯函数 2 条（uiScale 1.25 → 600×600；放大不越过可用空间）；widget 6 条：uiScale 1.25 贴顶卡 360×320 → 450×400、空态高 = 280×1.25；带 `anchorRect`（悬浮球 / 悬浮字幕入口）的锚点分支：平板默认 480×480、设置 360×320、uiScale 1.25 → 450×400、手机横屏 ≤ 可用高 × 0.72。变异（`_popupBoxScale` 固定 1 + 锚点分支高度还原成 `(可用高 − 2·gap) × 0.72`）红 5 条（Actual 360×320 / 280 / 480×758.9 / 360×758.9 / 360×758.9），还原后 tablet_size + popup_dictionary_page + popup_layout_width_columns 共 43 条全绿。
