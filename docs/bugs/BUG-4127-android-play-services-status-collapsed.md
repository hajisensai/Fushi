## BUG-4127 · 安卓系统 OCR 把 Play 服务所有异常码合成「缺失/停用/过旧」一句，已是最新仍提示更新
- **报告**：2026-10-30（用户：应用内反馈 Vv7cvxaZnM，Discord 用户转述）
- **真实性**：✅ 真 bug。截屏 OCR 走 unbundled ML Kit（只依赖 Play 服务），识别报 UNAVAILABLE 后（`ScreenOcrService.java:637-644`）拉起配置弹窗，弹窗查 `SystemOcrChannel.modelStatus`。根因在 `fushi/android/app/src/main/java/app/fushi/reader/SystemOcrChannel.java:169-175`（修前）的 `playServicesProblem`：`isGooglePlayServicesAvailable` 的所有非 SUCCESS 码按 `isUserResolvableError` 二分成 `play_services_resolvable` / `play_services_unavailable`，`SERVICE_MISSING`、`SERVICE_DISABLED`、`SERVICE_VERSION_UPDATE_REQUIRED`、`SERVICE_UPDATING`、`SERVICE_INVALID` 被合成同一状态，原始码既不记日志也不回传。`fushi/lib/src/ocr/system_ocr_setup_dialog.dart:132`（修前）对它统一显示「缺失、被停用或版本过旧」，唯一按钮调 `makeGooglePlayServicesAvailable`（修前 `SystemOcrChannel.java:117`）带去 Play 商店——用户看到「已是最新」就是死胡同，而且拿不到真实原因。
- **[x] ① 已修复** — 原生侧 `playServicesProblem` 改回传结构化载荷：原始 `ConnectionResult` 码、本机 Play 服务 APK 的 versionCode / versionName、库要求的 `GOOGLE_PLAY_SERVICES_VERSION_CODE`，并 `Log.w` 记原始码；`installModel` 的 `PLAY_SERVICES_UNAVAILABLE` 错误 details 带同一载荷；新增 `openPlayServicesSettings`（打开 Play 服务应用详情页）。Dart 侧 `systemOcrStatusForConnectionResult` 是唯一的码 → 状态映射（missing / disabled / update_required / updating / invalid / 其它不可用），弹窗按状态给准确文案：missing → 安装、update_required → 更新（并说明商店已是最新时就是设备拿不到所需版本，改用其它引擎）、disabled → 打开应用设置 + 重新检查、updating → 只给用户手点的「重新检查」，invalid / 其它不给修复按钮；Play 服务有问题时弹窗显示原始码与两边版本号供截图。提交见 PR（Feedback: Vv7cvxaZnM）。
- **[x] ② 已加自动化测试** — `fushi/test/ocr/system_ocr_setup_test.dart`：原始码映射纯函数、载荷解析、通道契约（modelStatus / installModel 专用异常 / openPlayServicesSettings）、`systemOcrSetupPhaseFor` 全状态、弹窗各 Play 服务状态的文案 / 按钮 / 诊断行 widget 测试。
- **备注**：这位用户设备实际返回哪个码仍未知（反馈人没有补机型 / 系统版本 / 截图）；修复合入后需请用户把弹窗诊断行截图发回确认。原生 Java 改动未在真机上复测（真机验证按规则取消），靠 Android 编译 + Dart 契约测试兜底。不依赖 GMS 的截屏 OCR 回退（复用 manga-ocr 等本地引擎）属功能扩展，未在本修复内做，建议单独立项。
