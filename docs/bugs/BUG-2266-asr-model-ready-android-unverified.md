## BUG-2266 · 语音模型已下载但转录弹层选不中/无法识别（Android，未复现）
- **报告**：2026-09-08（用户：Android，原话「已下载语音模型，但是好像无法选定，也无法导入识别。之前可能网络问题，模型没有下载完然后用不了」；随附的 error_log 片段只有 Mihon 漫画 `InterruptedIOException` 与 UpdateChecker 超时，没有 ASR 相关条目）
- **真实性**：❌ 未复现（用户描述的「选不中 / 无法识别」在生产装配路径上复现不出来；下面每一段都在 Android 模拟器（`hoshi_test_api36`，API 36，x86_64）上用与 `main()` / 设置页 / 转录弹层**同一份**装配（`fushi/lib/src/asr_host/asr_host.dart` `installAsrHostBindings()` + `createAsrTranscriptionService()`）实测）：
  - 模型目录解析正确：`/data/user/0/app.fushi.reader/files/asr_models/reazonspeech-k2-v2`（`asr_core` `AsrModelStore.open` 经 `asrSupportRootResolver` = `AppPaths.supportRootDirectory`）；`plan()` 在 Android 推荐 int8 · CPU，EP 探测无错，设置页与弹层两处 `plan(auto)` 结果一致（同平台不可能出现「设置页下了一个变体、弹层要另一个」）。
  - **下载中断不会留下坏档**：下到编码器 2.1 MB 时取消订阅（= 用户断网 / 离开设置页），盘上只有 `encoder-epoch-99-avg-1.int8.onnx.part=2101070`，`isReady` = false，`plan()` 报「部分 2101070/161016054」，不会误判就绪（`asr_core` `model_file_downloader.dart` `_finalizePart` 在 rename 前校验长度 == 清单 `expectedBytes`，截断档永远到不了最终文件名）。
  - **续传正确**：再次下载走 HTTP Range，从 2101070 续到 33.7 MB（总长 154670139 正确），期间宿主机网络抖动一次（HF CDN 连接断），下载器按候选链（huggingface.co → hf-mirror.com → 第二源 → 其镜像）逐个重试，四个都连不上后以最后一个错（`SocketException: HTTP connection timed out after 0:00:20, host: huggingface.co`）结束流；`.part` 留在 33702532 字节，下次点下载继续续传。宿主机 `curl -r` 直连 / 经代理探四个候选源均 206——协议侧没有问题，模拟器那两次失败是本机到 HF CDN 的连接抖动。
  - **弹层判定正确**：把就绪的 int8 全套（长度全部 == 清单）放进生产目录后，真 `AsrTranscribeSheet` 1.2 s 内显示「Model ready (ReazonSpeech k2-v2 · int8 · CPU)」+「开始转录」按钮，没有「需要下载」。
  - **转录本体在 x86_64 模拟器上验不了**：`start()` 在 `_probeMaterialMs` → `KitFfmpegBackend.runProbe` 抛 `createFFprobeSession failed: FFmpegKit native libraries are unavailable on … abis: x86_64 arm64-v8a`——APK 里 `libffmpegkit.so` 只有 `arm64-v8a` / `armeabi-v7a`（`third_party/ffmpeg_kit_flutter` 自编 AAR），x86_64 没有。用户的 arm64 手机不受此影响，但这条链在 arm64 真机上仍是**未验证**（BUG-2197 修复 `de650b6a3b` 已在 v2.3.0 / v2.3.0-beta.1248 内，装的是更早 beta 的用户会在转录起跑时撞 `ASR isolate crashed: Background isolates do not support setMessageHandler()`）。
- **[ ] ① 未修复** — 没有可修的根因。待用户补：a) 「无法选定」指哪一层（设置页那一行的按钮？转录弹层的语言下拉？弹层仍显示「需要下载」？还是选不中音频文件？）；b) 弹层状态行原文 / 截图；c) 当前 `error_log.txt`（贴的片段截止 08-26，早于 ASR 功能 09-05 上线）。最可能的良性解释：弹层语言初值跟随书的 `dc:language`（`asr_transcribe_sheet.dart` `languageHint`，4cd423f702 有意为之），书标成非日语时弹层会按那个语言报「需要下载」，即使日语包已下好——此时下拉切回日语即可，若下拉切不动才是 bug。
- **[x] ② 已加自动化测试** — `fushi/integration_test/asr_android_model_ready_itest.dart`（模拟器 / 真机；`ASR_MODE=network` 真网络下载→中断→续传→就绪，`ASR_MODE=seed` 免联网只验就绪→转录→弹层；素材经 `run-as` 写进 app 内部 `files/`，/sdcard/Android/data 下 shell 建的目录 app 自己 stat 会 EACCES）。本轮实测：网络用例因宿主机到 HF CDN 抖动未跑完（.part 续传正确）；转录用例在 x86_64 模拟器因 ffmpeg-kit 无该 ABI 失败；弹层用例通过。
- **备注**：两条与本报告相邻、但不是它答案的产品缺口：① 下载流中途断一次就整条流报错、要用户再点一次「下载」（进度保留），弱网用户会反复看到「下载失败」；② `_downloadFile` 只抛最后一个候选的错，第一个候选（信息量最大的那个）的错被吞。
