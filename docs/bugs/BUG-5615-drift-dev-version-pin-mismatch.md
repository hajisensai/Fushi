## BUG-5615 · drift_dev 没和钉住的 drift 成对钉版，普通 codegen 生成的 database.g.dart 编不过
- **报告**：2026-11-28（架构审计顺带发现：Drift codegen 一直要在隔离副本里换 drift_dev 版本生成、再只拷回 `.g.dart`）
- **真实性**：✅ 真 bug。`packages/fushi_core/pubspec.yaml:16` 把 drift 钉在 `>=2.33.0 <2.34.0`（锁到 2.33.0），而 dev 依赖 `drift_dev: ^2.23.0`（`packages/fushi_core/pubspec.yaml:22`，`fushi/pubspec.yaml:266` 还重复声明了一次，app 里没有 Drift 表）。工作区锁到 drift_dev 2.35.3——它自己声明 `drift >=2.30.0 <2.36.0`，生成的码却调用 drift 2.35 才有的 `$_getPrefetchedDataByColumns`。实测在 develop（4d853cf791）的 `packages/fushi_core` 下 `dart run build_runner build --delete-conflicting-outputs` 后 `dart analyze lib` 退出 3、61 个 `undefined_method` 错误。根因：drift_dev 生成码依赖 drift 运行时内部 API，上游的版本约束不可靠，本仓却只钉了运行时、生成器用宽松 `^`。
- **[x] ① 已修复** — `packages/fushi_core/pubspec.yaml` 的 drift_dev 改钉精确版本 `2.34.5`（兼容 drift 2.33.x、且与工作区 analyzer 13 共存的最新一版；2.33.x 要 analyzer <13，解析不了），删掉 `fushi/pubspec.yaml` 里多余的 drift_dev 声明，全仓只在 fushi_core 声明一处。`pubspec.lock` 随之 2.35.3 → 2.34.5。按新钉版在包目录直接重跑 codegen 并入库 `database.g.dart`：与原入库版的差异只有两类——`withReferenceMapper` 里显式泛型实参省略（类型推断结果相同），以及两处早已过时的列注释（v172 → v177 / v178，源码早改了、`.g.dart` 没跟上）；`dart analyze`（packages/fushi_core）零问题。drift 运行时不升：2.34 把事务改成 `BEGIN IMMEDIATE`，属行为变更，要升另行决策。
- **[x] ② 已加自动化测试** — `fushi/test/build/drift_codegen_pin_guard_test.dart`：全仓 `drift:` 约束单一值且是单个 minor 系列；`drift_dev` 只在 `packages/fushi_core` 声明、精确钉版，且等于登记表里为该 drift 系列验证过的版本；`pubspec.lock` 的实际解析与之一致。修复前三条中两条红（多处声明 + `^2.23.0`、锁到 2.35.3）。
- **备注**：守卫只能核「成对钉版」这一静态事实，生成码能否编过仍靠升版本时手动跑一次 codegen + `dart analyze`（登记表注释写明了流程）。codegen 在本机约 3～5 分钟。
