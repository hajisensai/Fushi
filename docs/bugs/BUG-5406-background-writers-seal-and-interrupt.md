## BUG-5406 · background-writers-seal-and-interrupt
- **报告**：2026-11-24（用户：拍板台 review-merge-1124-leftovers 第 1 条「全部根本性修复」，#4364 审查遗留）
- **真实性**：✅ 真缺陷（BUG-5387 修复的覆盖面不全）。BUG-5387 只把来源扫描、视频刮削 / 补刮、整文件哈希、封面回填、响度测量接进 `DatabaseBackgroundWork`；番剧下载入库（`fushi/lib/src/media/torrent/anime_download_importer.dart` 的 `buildAnimeDownloadImporter` 闭包，海报下载 + 首集抽帧之间穿插写库）、sidecar 封面（`cover_scraper_service.dart` 的 `applySidecarCover`）、在线视频源 / 媒体服务器入库（`anime_source_library.dart` / `media_server_library.dart` 的 `addMissing`、`registerDownloaded`，后台新集探针也走这里）、IPTV 台标回填（`iptv_playlist_import.dart` 的 `applyIptvChannelLogos`）、音乐整库识别（`music_scrape_service.dart` 的 `scrapeLibrary`）、更新探针（`app_model.dart` 的 `startUpdateChecks`）都没登记，换库时照样撞已关连接。更根本的是「登记」靠每个写手自觉：拦截器只拦已取消工作 Zone 里的 SQL，漏登记的写手在 `FushiDatabase.close()` 之后发 SQL 拿到的仍是 drift 的「connection was closed」。另外登记过的工作里，刮削 / 入库的网络请求（`createAppHttpIoClient` 出的 client）与 FFmpeg 抽帧子进程（`ffmpeg_backend.dart` 的 `_runToolProcess`、`ffmpeg_watched_run.dart`、移动端 `ffmpeg_kit_backend.dart`）不受取消约束，关库要等它们自然结束——数据根迁移的 10 秒关库超时后子进程仍可能占着库目录里的文件。
- **[x] ① 已修复** — 三层：
  1. **封口（结构保证，不靠逐个登记）**：拦截器改为每个库实例一份、绑在该实例的 `DatabaseBackgroundWork` 上（`packages/fushi_core/lib/src/database/database.dart` 全部构造路径）。`FushiDatabase.close()` 第一步 `backgroundWork.seal()`：此后发给本实例的**任何** SQL（含 `ensureOpen` / `beginExclusive` / 事务内语句）一律抛 `DatabaseWorkCancelledException`（标签 `unregistered`），在途事务整体回滚；漏登记写手第一次撞上时打一条带调用栈的诊断，便于找出来补登记。关库方的「必须落库」收尾（下载流水线 / 词典写入 drain）在 `AppModel.closeDatabase` 里早于 `_database.close()`，不受影响。
  2. **中断（登记过的工作里自动生效）**：`DatabaseWorkToken.cancelled`（工作结束自动注销的取消信号）与 `DatabaseWorkToken.abortOnCancel`（统一的「库关就中止外部操作」入口）。`createAppHttpIoClient` 返回 `DatabaseWorkAwareIoClient`：后台工作 Zone 里发的请求换成以取消信号为触发器的 `AbortableStreamedRequest`，库一关请求即中止；`_runToolProcess`（ffmpeg / ffprobe 一切 CLI 调用）、`watchFfmpegProcess`、FFmpegKit 两条会话驱动在库关时 SIGKILL / cancel 并回收子进程。全应用出站都经这个工厂，刮削、海报下载、媒体服务器取集一并覆盖。
  3. **补登记**：番剧下载视频入库（`torrent.animeImport`）、书 / 发现内容入库（`app_model.dart` 包成 `torrent.bookImport` / `torrent.discoveryImport`）、sidecar 封面、在线视频源与媒体服务器入库 / 下载登记、IPTV 台标、音乐整库识别、全部更新探针（`_probesAsDatabaseWork` 统一包）。被中断时各自不当失败处理：番剧计划保持 downloading + `importInProgress` 由幂等重放补完（`anime_download_service.dart` 三处 catch 先放行取消），批处理 / 探针循环整轮停下不吞取消，更新调度器这一轮不记「问过了」。
- **[x] ② 已加自动化测试** — `packages/fushi_core/test/database_background_work_test.dart`（封口后漏登记写手关库中 / 关库后都被拦成取消；封口让在途事务回滚并重开文件库验证；取消信号工作结束即注销；abortOnCancel；库内自关不封口）；`packages/fushi_engine/test/database_work/database_work_interrupt_test.dart`（挂住的 HTTP 请求关库即中止、工作外请求体与头原样；长跑子进程关库即被杀并回收）；`fushi/test/torrent/anime_download_importer_test.dart`（入库登记为后台工作，关库等它停稳并抛取消）；`fushi/test/torrent/anime_download_service_test.dart`（入库被取消不标 failed、留 importInProgress）；`fushi/test/updates/update_check_scheduler_test.dart`（探针被取消整轮停下、不记时刻）。
- **备注**：仍未接入的出站：`createAppDio`（Dio）与 Mihon sidecar 内部的网络不受取消信号约束；漏登记的写手关库时不会被**等**（只会被封口拦下），新增长时后台写手仍应经 `runBackgroundWork` 登记。
