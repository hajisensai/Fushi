# 漫画有声模式：演出稿 → 离线精制 → 按页播放

> 状态：设计（2026-11-16 ～ 11-17 与所有者逐轮确认方向，2026-11-17 应用外试做一段后定稿）。尚未实施。
> 相关：[TTS 管线](2026-10-11-tts-pipeline.md)（引擎层、制作台、选角表）、[漫画 OCR](2026-07-24-manga-ocr-design.md)、[有声书 / ASR 装配](../agent/asr-assembly.md)。

## 目标与非目标

- **目标**：把一卷漫画做成成品有声内容。播放时按页推进，读到哪个气泡高亮哪个气泡，无台词的页也有自己的停留时间；多角色各用各的声音，语气、停顿由 AI 看图给出。所有者的要求是「整体效果最好」，所以主线是**离线精制**，不为实时让步。
- 小说共用同一套演出稿与合成链路（AI 看正文与章内插图），本文只写漫画特有的部分，小说差异单列一节。
- **非目标**：
  - 实时朗读是**另一种模式**（现有 `MangaReadAloudController`，单声音、边读边合成），行为不变，不在本文范围；它以后可以读取同一份演出稿，但不是本设计的验收对象。
  - 不做手动逐句对齐界面，不做自动注音（[功能黑名单](../agent/feature-blacklist.md)）。
  - 不随应用分发任何角色声音；声音包由用户自己提供。

## 试做结论（应用外，`D:\APP\irodori\eval\manga_trial\`，不入库）

一卷漫画第 1 话中的 11 页（含 1 页无台词页）、46 句、两个角色，Irodori-TTS v4-large + 所有者训练的 LoRA，成品 2 分 50 秒。

| 问题 | 结果 |
|---|---|
| 看图判说话人 | 可行。10 页里 2 处单看画面定不下来，要结合前后文；没有标准答案可对，准确率未量化 |
| OCR 给的块顺序 | **多数页不是阅读顺序**，必须由标注重排；OCR 错字 46 句里改 1 处；手写旁注与拟声词不读 |
| 多种子自动挑选 | 收益很小：同一句不同种子**时长完全一样**，46 句里只有 7 句的回听字错率在种子间有差别；固定种子 0 时没有一句需要因读错而换 |
| 整卷试跑（第 2 卷，150 页、467 条，`manga_vol2\`） | 合成 0 条失败，成品 30 分 38 秒；按「页码 + 块下标」给每条音频起稳定名，演出稿增删句子后只补合成新增的。不挂 LoRA 的声音（配角、叙述）在 20 字以内的短句上时长预测偏长，模型会把这句念两遍（首轮 49 条里 19 条，挂 LoRA 的声音 0 条）；对这类短句按主角实测语速直接给定时长后消失。ASR 回听对 5 字以内的句子不可靠，只能用来查长句 |
| 回听字错率 | 平均 6.4%；偏高的 4 句都是 4–6 字短句，该长度下差一字即 25%，不能当「读错」的硬判据 |
| 合成耗时 | 每条约 8 秒（RTX 级独显）；整卷 184 页按页数外推约 1.5–2 小时，未实测 |
| 停顿 | 第一版每句只给 0.15–0.9 秒，听感是「连着的」；改成「转场基础值 + 逐句一拍」后最短 0.6 秒 |
| 只按台词翻页 | 无台词页被整页跳过，只有一句的页只停约 1 秒；改成按页分段后解决 |

所有者试听后的结论：气声组与干净组听起来差别不大。演出稿质量只有所有者试听反馈，没有客观指标。

## 设计

### 1. 演出稿

漫画的演出稿是与 `TtsCast` 并列的新类型 `MangaAudioScript`（`packages/fushi_engine/lib/tts/manga_audio/`），不往 `TtsCast` 里塞：`TtsCast.lines` 是按「章:偏移」做键的无序表，漫画的行锚在气泡块下标上、行的先后就是阅读顺序，只能是有序列表，硬并成一个类会让小说那边每处读取与合并都要分两种情况。角色表、来源（AI / 用户）、旁白 / 不明这几样复用 `TtsCast` 的定义。仍是每本书一个 JSON（`<sha1>.manga-script.json`，与小说的文件同目录互不覆盖）、原子写、用户改过的行重标时不被 AI 覆盖。小说要演出字段时在 `TtsCastLine` 上加同名字段。

**逐句**（`MangaAudioScript` 的行；小说对应 `TtsCastLine`）：

| 字段 | 内容 |
|---|---|
| 说话人 | 已有；只能从角色表里选，或「旁白」「不明」 |
| 类型 | 叙述（第三人称旁白、说明框、标题、信件等成段的正式文字）/ 独白字幕 / 心声气泡 / 说出口 / 喊 / 嘟囔 / 不读（拟声词、手写旁注、OCR 噪声） |
| 一拍 | 句后额外停顿（毫秒），叠加在转场基础值之上 |
| 情绪 + 强度 | 封闭词表 + 0–100（能本地校验、能折算成语速 / 音高 / 音量） |
| 语气说明（`tone`） | 可选的日文短句演技指令（如「おずおずと」「必死に食い下がる」），补情绪词表装不下的差别（试探 / 辩解 / 保证 / 哀求）；只去空白、截到 40 字，不做词表校验。能收自然语言指令的引擎当指令用，其余引擎忽略 |
| 语速 / 音高 / 音量偏移 | 可选；引擎不支持的字段忽略 |
| 种子 | 默认空 = 用作品默认种子；单句重生成时写入 |
| 文本修正 | 可选，仅用于改 OCR 错字；不是注音 |

**漫画的行锚点**是 `(页, [文本块下标…])`，不是文本。演出稿不存台词，合成与显示时从 OCR 结果按下标取。理由：

- 一句可以跨几个块（一个气泡被 OCR 切成两块、同一句分在相邻字幕栏），高亮要框住全部；
- AI 的输出只允许引用给定的块下标，落地前校验「下标存在、每块至多归一句」，不合格的行丢弃；
- 行的先后顺序就是阅读顺序，由标注给出，**不采用 OCR 的块顺序**。重排只用于有声模式，不改「复制本页文本」与查词用的 `mangaPageSentencesInReadingOrder`。

OCR 重跑后块下标会变：演出稿记录生成时的 OCR `engine_signature`，不一致时整卷标记为「需重新标注」，不尝试按坐标迁移。

**逐页**（新增）：

| 字段 | 内容 |
|---|---|
| `hold` | 无台词页的整页停留（毫秒） |
| `lead` | 翻到该页后、第一句之前先看画面的时间（页首有无台词分格时用） |

### 2. 时间模型：以页为单位

时间轴由页段组成，台词放在页段内。只按台词推进会跳过无台词页，这是结构问题，不靠给个别句子加长停顿解决。

句后停顿 = 转场基础值 + 该句的一拍：

| 转场 | 基础值 |
|---|---|
| 同一人接着下一个气泡 | 300 ms |
| 换人说话 | 450 ms |
| 内心（独白 / 心声 / 嘟囔）与说出口之间切换 | 900 ms |
| 翻页 | 再加 450 ms |

页的规则：

| 规则 | 默认值 |
|---|---|
| 无台词页停留 | 4000 ms，`hold` 可覆盖 |
| 有台词页最短停留 | 5000 ms，不足在页尾补静音 |
| 翻页后先看画面 | 700 ms，`lead` 可覆盖 |

这些数是试做里所有者听过两轮后的取值，不是测量结果。应用里提供一个**看图节奏倍率**（只缩放页停留与 `lead`，不动句间停顿）。

**两种播放形态共用一份音频**：静音不烘焙进音频文件。成品是「每句一段音频 + 时间表」，页停留由播放器按时间表插入：

- 边看边听：按上表插入页停留与 `lead`；
- 纯听（熄屏 / 后台 / 阅读器不可见）：页停留与 `lead` 压到 0，只保留句间停顿。判据复用 `readerVisibleForLifecycleState`。

导出 m4b 时按「纯听」时间表烘焙。

### 3. 存储与播放

- 生成结果写入现有 `Audiobooks` + `AudioCues`，`alignmentFormat` 新增一个漫画取值。cue 的 `chapterHref` 存页（`manga-page-N`，与 PDF 的 `pdf-page-N` 同构），`textFragmentId` 存块下标列表；逐句生成即有精确时间，**不跑匹配器**。
- 页段表（页、是否有台词、`hold` / `lead`）与演出稿同目录存一个 sidecar，不进 `AudioCues`（它不是句）。
- 播放走 `AudiobookSession`，后台播放、锁屏控制、小组件、悬浮字幕随之可用。
- 阅读器侧把 `MangaReadAloudController` 里与音源无关的部分（当前句、页跟随、用户翻页后重定位、打断代数）抽成共用的句序驱动，下接两种音源：现场合成（现有）与成品音频（新）。成品音频由位置流驱动：进入某条 cue 就调 `MangaReadAloudHost.show(页, 句组)`，进入无台词页段就只翻页、清高亮。
- 高亮需要支持「一句多块」：`__mangaSetSpeaking` 现在收一个句组号，改为收块下标列表。
- 用户手动翻页：跳到该页段起点继续播；关掉「跟随翻页」时音频不动。
- 播放条复用 `MangaReadAloudBar`，成品音频下多进度拖动与「跟随翻页」、少「声音」按钮。动效与图标规则沿用现有条。
- 快捷键：`ShortcutScope.manga` 加播放暂停 / 上一句 / 下一句，只开键盘通道（手柄不开，原因见 [focus-ownership.md](../agent/focus-ownership.md) 漫画页第③条）。
- 制卡：漫画制卡的句子音频优先取命中 cue 的片段（`mining_audio_clip.dart`），没有再落到现有 TTS 兜底。
- 在线未下载章节不支持，与 OCR「未下载不识别」一致。

### 4. AI 标注（看图）

新增 `AiFeature`（漫画演出标注），未指派提供商时不发请求。分三遍，离线跑，不赶时间：

1. **角色表**：封面与前若干页带图，抽角色的外貌特征、名字、称呼。之后逐句归属只能从表里选或标「不明」。
2. **逐页标注**：输入缩小后的页图 + 该页 OCR 块（下标、坐标、文字）+ 角色表 + 前几页已定的行；输出该页的行（块下标、说话人、类型、一拍、情绪 / 强度、语气说明）、行的顺序、`hold` / `lead`。提示词要求逐句定演法：同一人连说几句时不许把一套演法复制到每句，按句末语气词与这句在做什么（道歉、辩解、共情、保证、哀求、动之以情）各给各的情绪 / 强度 / 语气说明。
3. **整场复核**：以连续的一场戏为单位通读已标的行，修正说话人前后矛盾、理顺情绪曲线与节奏，但保留逐句的语气变化（一串同人台词被标成一样的，复核时拆开各给演法）。试做里定不下来的 2 处都是靠这一步的上下文判出来的。

本地校验：块下标在该页范围内且不重复、角色名在表内、类型与情绪在词表内、数值夹到范围。不合格的行丢弃，该块按「不读」处理并在复核界面列出。

页图会发给 AI 服务商：首次使用弹一次同意（与 Google Lens 上传同款），拒绝则该功能不可用。发起前显示预估请求数（每页至少一次带图请求）。

复核界面：逐页列出行，优先列「不明」与 AI 自评把握低的行；可改说话人、类型、一拍、顺序。

AI 助手可直接操作：新增 `fushi/lib/src/ops/ctl_tts_routes.dart` 与 `op_descriptions_tts.dart`（发起标注、改某句 / 某角色、单句重生成、发起整卷生成）。写操作前给演出稿拍快照，可撤销。

### 5. 声音包与引擎

所有者的角色声音是 **Irodori-TTS v4-large 上训练的 LoRA**（adapter 约 370 MB，底模 13 GB），推理时每次请求指定 adapter、多段参考音频（约 30 秒）、40 步采样、文本引导 3.0、说话人引导 5.0。LoRA 不带风格标注，`caption` 不用。

一个**声音包** = adapter 目录 + 若干组参考音频（按用途命名，如「内心」「说出口」）+ 采样参数 + 角色名。选角表里把角色指到声音包；没有声音包的角色与旁白走现有声音预设。

接入方式：离线制作不走现有的 OpenAI 兼容服务端，新增一个**批处理 worker**（本机 Python 进程，装配方式与托管沿用 `irodori_local_*` 与 `LocalServiceProcess`），一次加载底模，按「参考音频组」分批合成，逐句回报进度。理由：

- 现有部署钉的服务端（`61012c7`）请求体只有 `voice` + `caption`；它是否接受 adapter 与多参考音频**未核实**，即使支持也要逐句走 HTTP、逐句重算参考音频；
- 底模是 v4-large，现有清单只有 v4.1-Small / Small-MF，要加一个模型选项（13 GB，下载与校验走 `ResumableDownloader`）；
- 试做用的低内存 safetensors 读取（Windows 上默认内存映射加载 13 GB 会在内存紧张时崩）与 `IRODORI_SDPA_CUDNN=0`（约快 4 倍）要带进 worker。

`TtsProvider.synthesize` 加一个可选的演出参数（引擎无关的字段），各引擎声明能表达哪些并自己翻译，不支持的忽略；缓存键把演出参数与种子算进去。各引擎映射（Irodori 批处理：参考音频组 + 种子；VOICEPEAK：情感名 = 0..100；VOICEVOX：风格与三个 scale；GPT-SoVITS：按情绪换参考音频；Edge：SSML prosody）按引擎分别落地，本文不逐个展开。Azure 与 OpenAI 兼容接口是否有风格参数未查上游文档。

**声音指派在发起生成时由用户指定**，不写死规则。指派表按「角色 × 类型」取声音，从粗到细三级回落：

| 级别 | 含义 | 默认 |
|---|---|---|
| 作品默认声音 | 没有任何更细指派时用 | 当前朗读声音 |
| 角色 → 声音 | 该角色所有类型 | 角色的声音包；没有则回落到作品默认 |
| 角色 × 类型 → 声音 | 只覆盖某一类（例如某角色的内心类换一组参考音频或换一个模型） | 不设 |

「叙述」类不属于任何角色，单独一行，默认用作品默认声音，可以指给另一个声音（另一个引擎也行）；这样成段的正式文字与角色的第一人称独白不会是同一个嗓子。指派表存在演出稿里，生成任务快照一份，播放与重生成都按快照。这里的「声音」是任意一份声音预设或声音包的某个参考音频组，所以「生成时换模型」与「换参考音频组」是同一个入口。

试做里「内心类用气声组、说出口用干净组」这条，所有者听后的结论是**两组差别不大**（2026-11-17）。因此它不作为内置规则，只是指派表里可以手动设的一行；更细的情绪 → 参考音频映射同样不做。

**逐句演法进合成**（所有者 2026-11-23 拍板，取代 2026-11-17 的「情绪字段只标注、不参与合成」）：起因是长段同一人的台词全是一个语气。每句的情绪 / 强度 / 语气说明 / 语速音高音量偏移经 `TtsDirection.fromLine` 进合成通道，所有引擎都接：能原生表达情绪的引擎（风格 / 情感参数 / 指令）直接用；不能的由 `effectiveTtsDirection` 把情绪折成语速 / 音高 / 音量（只折进引擎支持的那几项）；能收自然语言的引擎再拿语气说明当演技指令。引擎表达不了的字段不声明、不下发；没有任何演出的请求与改动前逐字节一致。漫画成品清单每行记生效演出的指纹（`dir`，按引擎能力取舍 / 折算后，不含种子与时长；旧清单没有 = 无演出），整卷重跑时指纹变了才重出这句，只改了引擎表达不了的字段则照用旧音频。复核界面与操作目录（`tts.manga.line.edit` 的 `tone`）都能改语气说明，改情绪 / 语气后按改读法处理（已生成的句子提示单句重生成）。

限制：v4-large 需要大显存独显，只在桌面端可制作；其它设备播放成品。

### 6. 种子与重生成

- **整部作品一个默认种子**，生成时不让用户逐句挑。
- **单句重生成**：在制作台对某句换种子重录，试听后保留或撤回（复用现有单句重生成）。实测同一句不同种子时长一致，所以换一句不重排后面的时间表；实现上仍按实际时长重算，不依赖这个巧合。
- **自动兜底只管读错**：固定种子那条的回听字错率明显差于其它种子时才自动换。阈值对短句放宽（6 字以下不触发），因为短句的字错率不可靠。
- 不做「每句多候选自动选最好」：试做里它挑不出语气更好的，只多花 3 倍时间。

### 7. 后期

- 逐句裁掉首尾静音（停顿只由时间表给）、响度统一；内心类比说出口低一档。
- 无台词页期间是纯静音，听感可能像卡住。是否加环境声或翻页音效**未定**，等所有者听过再说。

### 8. 小说的差异

- 行锚点沿用现有 `(章, 句首匹配偏移)`，不引入块下标；
- AI 输入是正文 + 章内插图（插图主要帮角色表与场景气氛，逐句语气仍靠文字）；
- 没有页段，时间模型只用「转场基础值 + 一拍」那一半；段落 / 场景停顿沿用 `TtsPausePreset` 作默认；
- 声音包、种子、后期、AI 助手操作与漫画相同。

### 9. 音源：已有的有声书优先，其次才合成

所有者 2026-11-17：同一部作品在书库里有真的有声书时，直接用它的音频。

**逐句选音源**，一句一个结果，写进演出稿：

1. **有声书片段**：用户把这卷漫画关联到书库里一本已有有声书的书（原作小说）。那本书的 `AudioCues` 已经是「句子文本 + 起止时间」，所以这里是**文本对文本**的匹配，不需要再跑 ASR：演出稿的每一句去有声书 cue 文本里找最相近的一句（规范化后做近似匹配，按故事顺序单调推进，避免同一句短台词命中到远处的章节），命中则引用「音频文件 + 起止时间」，不复制音频。
2. **合成**：没命中的句子按指派表合成。

约束与取舍：

- 命中的片段边界取 cue 边界；漫画台词只是小说一句话的一部分时，有逐 token 时间（`CueTokenTiming`）就裁到对应区间，没有就不算命中。
- 短句（6 字以下）不参与匹配：太容易撞上无关的句子。
- 有声书通常是一位朗读者读全部角色，和合成的角色声音混在一起可能很跳。每部作品给一个音源策略：**有声书优先，其余合成**（默认）/ **只用有声书命中的句子，其余不读** / **只合成**。
- 关联是用户手动做的（选哪本书），不自动猜；同一系列的多卷小说可以一起选。
- 命中率没测过。漫画改编会删改、重排台词，独白往往被压缩，预期是「部分命中」。发起前显示命中统计，由用户决定用哪种策略。

**广播剧 / 动画音轨**（没有现成文本时间表的真人音频）是另一回事：要先 ASR 再匹配（一页 = 匹配器的一个 section，同 PDF 有声书），匹配不上的 cue 只播放不高亮。短句、高噪声文本上的匹配率没测过，改编差异更大，仍排在最后，届时另写计划。

## 实施顺序

每步独立成 PR、独立可用。

1. **引擎层**：演出稿数据结构（逐句字段、逐页字段、漫画行锚点）、时间表计算（转场基础值、页段、两种播放形态）、本地校验。纯 Dart，放 `packages/fushi_engine/`，带单测。
2. **漫画播放**：成品音频入库（`Audiobooks` / `AudioCues` + 页段 sidecar）、句序驱动抽取、多块高亮、播放条、快捷键、漫画卡有声入口。先用手写演出稿 + 现有引擎验证。
3. **已有有声书作音源**：漫画关联书库里的有声书、文本对文本匹配、音源策略、命中统计。不依赖新的合成引擎，所以排在声音包之前；没命中的句子这一步先用现有声音预设合成。
4. **声音指派与声音包**：「角色 × 类型」指派表（含叙述类）、v4-large 模型选项、批处理 worker 托管、声音包管理界面、制作台接漫画任务、单句重生成。
5. **AI 标注**：三遍流程、同意弹窗、复核界面。
6. **AI 助手操作目录**、小说接入演出稿、制卡取成品音频。
7. 广播剧 / 动画音轨匹配（另写计划）。

## 待定与风险

| 项 | 状态 |
|---|---|
| 换参考音频能否带动语气 | 所有者 2026-11-17 听后：气声组与干净组差别不大，不做内置规则。2026-11-23 起改为逐句情绪 / 语气说明直接进合成（见 §5），不靠换参考音频 |
| 漫画台词对有声书文本的命中率 | 没测过；预期部分命中，靠发起前的命中统计与音源策略兜底 |
| 有声书朗读者与合成角色声音混用的听感 | 没听过；默认「有声书优先，其余合成」是否合适待所有者试听 |
| 看图判说话人的准确率 | 只有 10 页的经验，未量化；角色多、画风相近的作品可能明显变差 |
| 官方服务端是否支持 adapter / 多参考音频 | 未核实；本设计不依赖它 |
| 无台词页的静音要不要填声音 | 未定 |
| 页停留默认值 | 所有者听感取值，非测量；靠节奏倍率兜底 |
| 整卷制作耗时 | 外推 1.5–2 小时，未实测 |
| 匹配逻辑是否按胖核心规则进 Rust | 生成路径不需要匹配；真人音频那期再定 |
| 页图上传的隐私 | 首次同意；本地视觉模型不在本期 |

## 验收

- 一卷本地漫画从「标注 → 生成 → 播放」走通：无台词页不被跳过，只有一句的页停留不低于下限，句间没有背靠背。
- 翻页式与条漫（webtoon）两种阅读方式各验一遍；条漫下「页」按现有 `isSameSpread` 的语义处理。
- 熄屏后页停留不再插入，回到前台恢复。
- 换某句种子后该句可试听、可撤回，后续高亮不错位。
- OCR 重跑后演出稿被标记为需重新标注，不带着错位的下标继续播。
- 验收作品与声音包由所有者提供；应用与仓库不含任何角色声音与作品内容。
