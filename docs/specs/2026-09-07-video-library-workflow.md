# 视频组织、身份匹配与后台任务

## 使用方式

导入本地文件夹时可选择「按作品」或「按文件夹」。已有来源可在来源设置切换，下次扫描使用新规则。

- 按作品：优先 MAL 资料，TMDB 补缺/兜底；可另启用 AniDB ED2K 文件识别。详见 [MAL/TMDB 与 AniDB 文件识别](2026-09-07-mal-tmdb-anidb-hash.md)。
- 按文件夹：每个一级子目录一个普通合集，深层文件归对应一级子目录，根直属文件归根合集。适用于难度、课程、主题目录，此模式不自动匹配作品资料；如需作品刮削，切回按作品。
- 切换不删除既有合集、观看进度、字幕或元数据；展示层按当前模式选择折叠归属。一次性导入删除临时来源后仍保留目录合集。

后台任务面板分「当前任务」「待确认」「历史记录」。关闭窗口不会取消控制器持有的任务；当前页显示手动重刮队列，未开始的请求可单独撤回。取消全部任务会停止当前刮削并清空尚未执行的请求。

手动匹配可按标题或 MAL/TMDB ID 搜索。ID 模式区分 MAL、TMDB 电影和电视剧，支持正整数和官方作品 URL，先展示资料候选，选择后才绑定。数字标题（例如 86）在标题模式仍按标题搜索。同名条目使用稳定键确定目标；缺少稳定键的旧历史遇同名歧义时要求从待确认页选择具体条目。

Nyaa 资源搜索以输入框里的明确查询词为准；仅没有明确查询词时才使用原名/别名默认候选，避免不同入口的隐藏身份信息改变用户输入。

## 数据与执行契约

- schema v98：`media_sources.video_grouping_mode` 默认 `series`；`video_books.video_grouping_mode` 保存可空快照，删除来源前保留最新选择；`media_collections.source_folder_path` 可空、本机外部路径，不作为跨端作品身份。
- 目录合集按来源内一级目录路径识别，创建和补成员处于事务中。名称冲突不认领用户的手动合集，重扫不复活删除墓碑。
- 多成员普通目录合集不能作为动画作品刮削单元。规划器和索引器均有模式边界，避免仅禁用UI按钮而后台仍写入资料。
- 手动请求在统一操作门内串行执行，每项拥有独立完成结果。标题只用于展示，执行目标可携带 `workStableKey`，失效键禁止回退到同名条目。
- 显式更换 AniDB 身份时不沿用旧 TMDB / 历史跨源身份。冲突 NFO 不并入新作品，原文件遵守写入保护，并在结果中提示；补充搜索使用新作品的标题与别名。
- 待确认、历史记录按需构建可见行，加载失败提供重载；重叠刷新用版本号拒绝过期响应。
- 保留既有 NFO / 图片覆盖保护。后续用户已明确调整为 MAL 主资料、TMDB 兜底、AniDB 文件哈希识别，旧 AniDB 主资料限制不再适用。
