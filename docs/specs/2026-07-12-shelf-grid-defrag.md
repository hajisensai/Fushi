# 库页散卡网格去碎片（合集行切碎网格）

> 状态：**已拍板**（2026-07-12 用户挨个决策：**方案 A 分区 + 合集区顶部**）。
> 源头：用户实报「书/视频和合集混在一块导致有可能出现一两本书占一行，
> 然后后面一两本书再占一行」。
> 分支：`worktree-unified-collections-plan`（PR#41 延续）。

## 1. 问题与根因

UI v2 Phase C 的布局是**保序交错**：`groupByCollections` 输出按排序键排好的
group 序列，页面按序扫描——合集 group 渲染成全宽横排行（sliver），连续散
group 段落合并成一个 `SliverGrid`。

结构性代价：**每个合集行都把散卡网格切成两段**，每段的最后一行不满列数就是
残行。K 个合集行最多切出 K+1 个散卡段 = K+1 个残行。列数越多（桌面宽屏）浪费
越明显：4 列网格里 1 本书的段落 = 75% 空行。

这不是实现 bug，是「排序语义要求同层交错」与「行/网格异构布局」的结构冲突：
交错序每打断一次网格，网格就必须重开一段。

## 2. 方案

### A（推荐）：分区——合集行集中一个区，散卡合成单一连续网格

```text
┌ 继续阅读 hero + 概览 ──────────────────┐
│ ▼ 合集A ────────────────── 查看全部 › │   ← 合集区（行形态，区内按当前
│  [卡][卡][卡][卡] →                    │     排序模式的聚合键排）
│ ▶ 合集B（已折叠）───────── 查看全部 › │   ← 刚落地的折叠让此区可收纳
├────────────────────────────────────────┤
│ [卡][卡][卡][卡]                        │   ← 散卡区：单一 SliverGrid，
│ [卡][卡][卡]                            │     全程无切割，只有最后一行
└────────────────────────────────────────┘     可能不满（不可避免）
```

- 排序模式照常作用：合集区内按聚合键排、散卡区内按条目键排——只是不再互相
  穿插。残行从「最多 K+1 个」降到恒 1 个（整个网格的最后一行）。
- Jellyfin/Netflix 同款语义（shelves 区 + 网格区，没人交错）。
- 实现小：两页的 sliver 组装函数把 groups 一分为二（collection / loose），
  先渲染合集区再渲染散卡网格。`groupByCollections` 与排序层零改动。
- 代价（诚实外显）：「最近」模式下，最近看过的**散卡**不再能排到某个更老的
  合集行之上——合集区恒在散卡区之前。若合集很多，散卡会被推得较低（折叠可缓解）。

**决策点 A-1（已拍板：顶部）**：合集区放 hero 之下、散卡之上（Jellyfin
首页语义；配合折叠可收纳）。

### B（不推荐）：合集回网格折叠卡

合集渲染成与散卡同尺寸的堆叠封面卡（`SeriesShelfCard`，代码还在），混进同一
网格 → 完全交错 + 零残行。但这正是 UI v2 Phase C 之前的形态，用户已拍板换成
独占行（「每个合集独占一行、行内横移」）；回退 = 撕掉已认可的形态。仅当
方案 A 的分区感不可接受时再议。

### C：现状不动（接受残行）

零成本，但用户已实报不满，排除。
