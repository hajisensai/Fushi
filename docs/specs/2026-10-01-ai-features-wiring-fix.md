# AI 功能接线根因修复（2026-10-01）

用户报告：视频库首页「1 部作品还没确认身份」，已在「设置 › AI」指派了视频作品识别，AI 却没有代劳；
并要求其余 AI 设置一并修。审计（全部 7 个 `AiFeature` + 提供商设置层）结论与修法如下。

## 视频作品识别（videoIdentify）

| # | 根因 | 修法 |
|---|---|---|
| V1 | 补刮账本的指纹只含刮削配置，不含 AI 能力；配 AI 之前「试过没中」的作品 7 天内不再自动重刮 | AI 识别能力（提供商 id + 协议 + 地址 + 模型）进补刮指纹，且**每轮现算**（补刮器生命周期长） |
| V2 | 协调器按「本地标题 + 候选」缓存 AI 判定（含「不选」），键里没有提供商 / 模型；下载管线协调器一次建成终身持有 | 决策器从裸函数改成带 `capabilityKey` 的对象；缓存键带能力键，换提供商 / 模型即重问 |
| V3 | AI 失败只在本趟静默跳过，运行记录无痕；失败的作品还被记成「试过」吃满 7 天 | 失败记一条 `ai:failed` 运行警告（UI 可读）；AI 失败的作品按临时失败撤账，下轮再试 |
| V4 | 待确认页没有 AI 入口 | 每行加「AI 识别」：对该作品强制重问 AI（绕过缓存），结果（采用 / AI 不确定 + 理由 / 查无候选 / 未指派）明确回给用户 |
| V5 | 零候选作品永远到不了 AI | 查无时让 AI 给出可能的正式标题（只产出搜索词），资料源按这些词重搜；新取回的候选仍要过 AI 判定 ≥0.85 才采用。不越「AI 只在已取回候选里选」的边界 |
| V6 | 低置信 AI 判定被丢弃，前台确认框看不到 AI 倾向 | 确认框里标出「AI 建议」那一条（只提示，不自动采用） |

## 提供商设置层

| # | 根因 | 修法 |
|---|---|---|
| S1 | 自动保存只写「当前有效的草稿」并整份覆盖，编辑到一半的提供商被从磁盘删除，指派悬空 | 无效草稿保留该 id 上一次的有效版本；删除只由显式删除触发 |
| S2 | 指派指向不存在的 id 时设置页显示「跟随默认」，运行时却回 null | 显示为「已失效」（与运行时同口径） |
| S3 | OpenAI 兼容协议把空 content 当成功 | 与 Anthropic / Gemini 同口径抛 `empty_response` |
| S4 | 「测试连接」只列模型，不验证所配模型与 chat 端点 | 测试改为对所配模型发一次最小 chat 请求 |
| S5 | OpenAI 官方推理模型拒收 `max_tokens` | 官方 OpenAI 端点改发 `max_completion_tokens`，其余兼容端点不变 |

## 其他功能

| # | 根因 | 修法 |
|---|---|---|
| F1 | 视频搜索辅助的设置说明宣称补搜索词 + 资源排序，生产只剩字幕补抓重排 | 说明改成真实行为；字幕重排失败记诊断日志而不是静默 |
| F2 | 游戏文本处理解析 AI 回复用硬类型转换，回复字段类型不对抛 TypeError，页面转圈停住无提示 | 解析逐字段类型校验、坏条目丢弃；全坏时报可读错误 |
