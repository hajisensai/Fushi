# 学习回顾星空（词语星图）设计

> 状态：设计已拍板，未实现。可交互原型见 [2026-10-27-learning-review-starfield/](2026-10-27-learning-review-starfield/)（用本机真实数据生成，数据文件不入库）。

## 1. 要做什么

一个 3D 星空的学习回顾页。每张自己制的卡是一颗星，星上写着这个词：

- **颜色**代表来源种类：视频、漫画、书、游戏、音乐、有声书。
- **星团**：同一部作品的卡聚成一个星团。
- **每个光点都是一张真实的卡**：没有装饰用的星尘或背景星。
- **桥星**：在多部作品里都制过卡的词，画成金色的星，连接这几个星团。
- **共享汉字连线**：选中一颗星，画出与它共享汉字的词之间的连线。
- **出处**：点开一颗星，列出这个词在哪些作品的哪个位置出现过，每条都能跳回原处（复用收藏夹的 `_openBook` / `_openVideoSentence` 跳转锚点）。
- **回放**：按制卡时间，从第一颗星开始回放星空长出来的过程。

## 3. 数据来源的现状（本机实测，2026-10-27）

- `mined_sentences` 在每次插入后由 `_trimMinedSentences`（`packages/fushi_core/lib/src/database/database_statistics.part.dart:1729`）裁到 `kMinedSentenceHistoryLimit = 1000`（`database.dart:2726`）。本机表里正好 1000 行，全是视频，最早 2026-09-07；之前的行全部被删，书的卡一条不剩。
- 计数表 `mining_statistics` 记了 2145 张（视频 1887 + 书 258），证明被裁掉的不是少数。
- Fushi SRS 牌组 `srs.db` 有 14,799 条笔记，其中挖词笔记类型 2,267 条（2026-06-09 起）才是自己制的卡；JLPT10k、Kaishi 1.5k、おにぎり文法、Basic 是导入的预制牌组，不算。
  - 每条挖词笔记有 `Expression` / `ExpressionReading` / `Sentence` / `MiscInfo` 字段，标签里带种类（`video` / `book` / `manga` / `game`）和作品名。
  - 新卡的 `MiscInfo` 是 `fushi://source?v=1&kind=…&uid=…` 深链，带 `startMs` / `chapterIndex` + `charOffset` / `pageIndex`；更新的卡还有结构化的 `source` 字段。
  - 旧卡（`hibiki` 标签那批）`MiscInfo` 只有「标题 - 集名 00:05:39」这样的文本或空，**没有可跳转的位置**。本机可定位比例：视频 999/1746、书 80/381、漫画 47/47、游戏 0/9。
  - 39 张卡标签里只记了集号（如 `S01E13`），作品名已不可考。按制卡时刻匹配 `activity_events` 观看会话只救回 1 张。
- 两份旧库备份（`fushi.db.bak.*`）各有 1000 行历史，覆盖 2026-07-26 到 2026-10-06，可补一部分旧卡的精确位置。

## 4. 存储改动（D1 / D3）

1. **删掉上限**：去掉 `kMinedSentenceHistoryLimit` 与 `_trimMinedSentences`，插入不再删行。每行只有文本与定位锚点，10 万张卡约几十 MB，可接受。
2. **收藏夹分页**：`collections_page.dart` 现在用 `getAllMinedSentences()` 一次读全表（`:381`、`:1186`），取消上限后必须改成分页 / 按需加载，否则卡多了首屏变慢。
3. **一次性回填迁移**：新版本首次启动时，从 SRS 挖词笔记生成缺失的 `mined_sentences` 行。
   - 去重键：`noteId`（AnkiConnect 制的卡）或 `(expression, sentence, createdAt 近邻)`。
   - 来源 / 作品 / 位置按 §3 的字段解析：深链优先，其次 `source` 字段，再次标签与 `MiscInfo` 文本。
   - 旧库备份里同一张卡的行（按 `expression` + `sentence` 匹配）可补精确位置。
   - 回填出的行标记来源（新增可空列，如 `backfilledFrom`），解析不出位置的照样入库，只是不可跳转。
4. **只发到外部 Anki 的卡**：不进 Fushi SRS，只能靠本表。所以本表是唯一完整来源，不能反过来让星空直接读 SRS。
5. `mined_sentences` 目前随备份走（`table_rules.part.dart:286`），**不进互联实时同步**。多设备上星空各看各的，是否要跨端合并见 §8。
6. 以上动了 schema 与迁移，按仓库规则走一次 schema bump，并补迁移测试。

## 5. 视觉方案（D5 / D6 / D7）

### 5.1 星空布局

- **星团**：每部作品一个星团，星在星团内按三维钟形分布（中心密、边缘疏），像疏散星团。星团半径 `6 + 2.1·sqrt(卡数)`。
- **星系**：星团按卡数从多到少，沿黄金角螺线从中心向外排开，铺成一个略扁的盘（高度方向有少量起伏）。卡多的作品在中心。
- **星团名**：像星座名一样标在星团上方，写星数；按星数优先占位，重叠的不显示；点星团名飞过去。走进星团内部后名字淡出。

### 5.2 星的样子（D6）

- 每个光点 = 一张卡，没有装饰星。
- **颜色**：来源种类色往白偏 30%，像真实恒星的淡彩；桥星为金色。
- **亮度 = SRS 记忆稳定度**（`srs_cards_cache.stability`，log 映射到 0–1，以 120 天封顶），没复习过的卡偏暗。记忆最稳的（映射值 > 0.7）、桥星、选中的星带十字星芒。
- **形状**：锐利星芯 + 两层淡光晕，加法混合；每颗星有自己的闪烁相位和频率。
- **屏幕尺寸有上下限**（约 4–16 px，带星芒的到约 38 px）：走近时星不会膨胀成光斑，走远时也不会消失。
- **词标签**：离星够近时淡入（普通星约 260 → 120 单位，桥星约 520 → 260），按距离排序，最多约 150 个；按屏幕格子去重叠，挤不下的不画；选中 / 相关 / 悬停的强制显示。

### 5.3 视角与缩放（D7）

- **拖动**旋转（OrbitControls，带阻尼）。
- **缩放朝光标推进**：滚轮、触控板捏合、双击、屏幕右下 ＋ / − 按钮、键盘 `+` / `-`。相机和视点中心按同一比例朝锚点收拢，光标下的东西保持在光标下；每帧按 0.16 的比例缓动，不跳变。
  - 锚点：光标 24 px 内有星就用那颗星；否则取光标射线与「过视点中心、垂直视线」平面的交点。
  - 连续滚动时，锚点按**缩放目标视角**计算，而不是当前相机（否则视角还在缓动，光标下的东西会漂）。实测连滚 8 格，距离 707 → 194，光标下那颗星的屏幕位置不变。
  - 鼠标滚轮一格约走 18%；触控板捏合（`ctrlKey`）的 delta 小而密，用更细的系数。距离限制在 6–1800。
- **回到全景**按钮飞回默认视角。

### 5.4 桥星、连线、面板、回放

- 桥星放在它连接的那几颗星的重心，往盘面上方抬一点；金色细线连到它在每个星团里的那颗星。
- 选中后，青色线连到所有共享任一汉字（CJK 统一表意文字）的词。
- 详情面板：词、读音、所属作品标签；每次出现列作品、位置（`SxxEyy mm:ss` / `第 N 章 · 第 M 字` / `p.N`）、制卡日期、原句（词高亮），以及「跳回原处」按钮；最后列出共享汉字的词，可点击跳转。
- 回放：时间轴从第一张卡到今天，默认约 28 秒放完；每颗星出现时有一次闪光（变白、放大、带星芒）。

## 6. 实现架构

按「Rust 胖核心、Flutter 薄 UI」：

- **Rust 子系统（新，`native/fushi_starfield`）** 持有星空状态：作品分组、星团与星的布局、桥星与汉字图、回放时间索引。对外是粗粒度命令：
  - `open_starfield(profile)`：一次性读入卡片行。
  - `set_camera(...)` + 时间轴 → 每帧返回一个 `Float32List` 快照（屏幕坐标、颜色、大小、透明度）。一帧一次 FFI 调用，超过 1 ms 的准备工作放后台 isolate。
  - `pick(x, y)` / `select(word)` / `related(word)` 返回面板数据。
- **Flutter** 只渲染快照：星点用 `Canvas.drawRawPoints` / `drawVertices` 配 `FragmentProgram` 光晕着色器（Impeller）；标签、面板、时间轴是普通 widget。
- **动效**：飞向星团、缩放缓动、回放闪光的时长一律取 `FushiMotion` / `fushiMotionDuration`，墨水屏与「减弱动态效果」下归零；MD3 与 Apple 两套设计系统都接。
- **工具栏**：顶栏动作走 `FushiFloatingTopBar` 的 `adaptiveOverflow`。
- **跳回原处**：复用收藏夹的跳转锚点（书 → 阅读器，视频 → 视频页，漫画 → 页码）。

## 7. 原型

`2026-10-27-learning-review-starfield/` 下是 three.js 原型：

- `preview.html`：页面本体，读取同目录的 `data.js`。
- `export_local_data.py`：只读打开本机 `fushi.db` 和 `srs.db`（sqlite backup API，不锁正在运行的 app），按 §3 / §4 的规则解析，生成 `data.js`。
- `data.js` 含个人制卡记录，`.gitignore` 排除，不入库。

```bash
python export_local_data.py --data-root "<Fushi 数据根目录>"
python -m http.server 8791 --bind 127.0.0.1
```

不要用 8765 端口：那是 AnkiConnect 的默认端口。

## 8. 待定

1. 除亮度（记忆稳定度）外，星的**大小**要不要再表示别的（查词次数？复习次数？）；目前只按稳定度和桥星区分。
2. 只记了集号、作品不可考的卡：并成一个「出处不明」星团（原型现状），还是不显示。
3. 没有出处的卡（独立查词页 / 首页词典制卡）：要不要单独放一个星团。
4. 多设备：星空是否要跨端合并各设备的制卡历史（`mined_sentences` 现在不进互联同步）。
5. 文件名式的作品标题（如 `Bad Girl 1080p x265 10bit`）：是否改用刮削元数据的作品名。
