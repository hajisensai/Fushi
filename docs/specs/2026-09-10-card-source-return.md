# 卡片来源回跳与临时回看

Lapis 卡面折叠区显示“来源”，去掉重复的 Details 行，内部字段名继续使用 `MiscInfo`。默认映射为 `{source-link} {clip-timestamp}`：作品标题本身是唯一的回跳超链接；没有可用定位时显示普通标题，不额外显示“↗ Fushi”。新制卡记录独立的随机来源 ID，并给原笔记添加对应 `fushi_source_…` 标签。回跳后的制卡覆写按这个标签唯一定位原笔记，不用词头或设备内 note ID 猜测目标。已有自定义字段映射和旧卡不批量改写。

链接形式为 `fushi://source?v=1&kind=…&uid=…&sourceId=…`，由系统唤起 Fushi：Windows 使用已有协议/单实例参数通道，Android 使用 ReceiveIntent，iOS 使用已有 URL 事件通道，macOS 使用 Launch Services 事件队列。链接只携带库身份、定位坐标和视频指纹，不携带本地路径、配对令牌或媒体服务器凭据。

- 小说使用章节索引及阅读器归一化字符锚点、选区长度；音频可另存文件索引和原始媒体毫秒区间，回跳不叠加字幕延迟。
- 漫画使用页索引；在线漫画还记录源内章节身份。索引均从零开始。
- 视频使用原始媒体毫秒区间以及整个文件的 SHA-256。已有视频库 ID 由文件名生成，因此仅有同名 ID 不足以确认作品。链接打开前及播放器加载前均验证指纹，文件不匹配就停止。
- 无本地文件的外部视频流不生成不能核验的来源链接；回看只接受本地或已缓存的实际文件，避免启动 Jellyfin 等外部播放活动。

回看与正常阅读的生命周期分开。回看期间不写阅读/播放位置、历史、学习统计、完成状态或外部播放进度；打开前先等原页面正常落盘并停止旧音频会话。点击“返回阅读”重新读取原先保存的位置；连续打开多个卡片链接仍保留最初的返回目标。只有点击“从这里继续阅读”才以当前页面开始正常记录，清除回看期间的待保存定时器与统计基线。

回写复用已有卡片弹窗的字段展示和差异选择组件。回看工具栏不再提供“修改原卡”按钮或原始字段编辑框；用户仍可通过既有制卡/覆写流程将新片段写回原卡。候选与卡片查看器在同一个对话框路由内切换，消除重复弹窗。来源会话中的制卡/覆写按钮始终绑定来源原卡，不提供误建同词重复卡的分支。提交前逐字段比较原值，提交后读回验证；冲突或网络结果不确定时不自动重试、回滚或覆盖。AnkiConnect 不提供跨应用原子锁，因此差异确认界面仍提示避免同时在 Anki 与 Fushi 编辑同一笔记。

临时音频、图片及待写字段先复制到应用目录 `card_source_drafts/<sourceId>`。失败后可恢复草稿，重新读取原卡并核对选定字段后手动提交；不自动补交。已有草稿不能被下一次编辑静默替换。配对主机草稿保存公开主机地址及配对身份摘要，不保存明文凭据；恢复时只绑定仍被授权的原对端，同一地址重新配对也会拒绝旧草稿回写，禁止切换到另一台主机或本机写入。缺少配对身份的旧远程草稿保留，但不能直接提交。iOS 的原卡编辑经已配对的桌面 Fushi / AnkiConnect 执行，AnkiMobile URL API 不承担笔记回写。

回看工具栏拥有独立的键盘导航与确认快捷键，防止媒体页将按钮的 Enter 解释成选字查词、方向键解释成翻页。已有来源卡从没有新定位的入口重制时保留原来源链接；取得新定位时只更新坐标，继续复用原卡的来源 ID。

视频回看工具栏只在回看态显示“返回原观看位置”“从这里继续观看”。继续观看同时启动播放器和正常进度记录，加载中的继续请求在播放器就绪后执行；同一刻整条工具栏**卸载**，页面回到与平常看视频完全一致的单一顶栏（BUG-102），不保留改写标签的常驻第二条顶栏。回到卡片片段不再是页内按钮，重新点一次卡片上的来源链接即可，走完整来源路由：先保存正常观看位置并关闭播放器，再核验来源、回到卡片时间点并进入新的不记进度回看；不会把回跳的 seek 写入正常观看位置。工具栏卸载后会话仍然存活，其失败提示由视频页接管 context。

验证入口：`fushi/integration_test/card_source_return_test.dart` 使用隔离数据根，检查真实阅读器回看/继续阅读的数据库行为以及单层卡片弹窗。Windows 可用 `fushi/tool/run_windows_itest.ps1`，Android 使用 `ci/integration-test.sh --only=card_source_return`。Apple 两端已接线，但本次 Windows 环境没有 Xcode，运行验收须在 Mac 上补齐。
