# 内嵌字幕擦除（video desub）设计

- 日期：2026-11-20
- 拍板：所有者 2026-11-20「都做 全部上」；高动态档用 RAFT + LaMa 自研（不接 ProPainter）；分 4 个 PR。
- 拍板：所有者 2026-11-21 按实测（§4.1）定：彻底擦除**只做 Windows**；默认 DirectML 跑 MI-GAN，有 N 卡可用 CUDA；CPU 允许但标「很慢」、只进后台任务；LaMa 不当默认；「边播边擦」延后。自导出模型托管 GitHub Release 附件（具体仓库届时再定，发布前确认）。
- 设计图：本地 `fushi/build/desub_design/index.html`（不入库）。
- 参考：[YaoFANGUK/video-subtitle-remover](https://github.com/YaoFANGUK/video-subtitle-remover)（Apache-2.0）的流程「检测字幕区 → 时序掩膜 → 补全 → 重新封装」。

## 1. 目标

学日语看动画时，片源常带烧进画面的中文硬字幕。现有「字幕遮布」（`video_subtitle_mask.dart`）只能手动摆一块模糊 / 纯色块，且只是 Flutter 叠层——mpv 截图（制卡截图、片段导出）里硬字幕还在。本设计分三档：

| 档位 | 实时性 | 原理 | 平台 |
|---|---|---|---|
| 遮布（已有，改名「手动」） | 实时 | 用户摆放的固定矩形 | 五端 |
| 智能遮布（PR1） | 实时 | 播放中抽帧跑本机 OCR，自动找到字幕框，只在有字时糊掉，框跟着字走 | 有本机 OCR 模型的平台 |
| 彻底擦除（PR2～4） | 后台生成 | 检测 → 掩膜 → AI 补全 → 只重编有字片段，另存「无硬字幕版」 | Windows 本机；手机委托互联的 Windows 电脑 |

## 3. PR1：智能遮布

### 3.1 行为

- 偏好 `video_subtitle_mask`（冻结键名）JSON 新增字段 `mode`：`manual`（缺省，兼容旧值）/ `smart`。
- `smart` 时 `rect` 的含义从「遮布位置」变成「搜索区域」：只在这块里找字，框外的字（招牌、片名、日文画面字）不动。编辑层与「调整位置」入口照旧，横幅提示文案随模式切换。
- 播放中按帧变化抽样（串行：上一帧识别完才截下一帧，最短间隔 `kSmartSubtitleMaskMinInterval`）；暂停且帧没变时不抽样。
- 迟滞：检测到字立刻显示；连续无字超过 `kSmartSubtitleMaskHoldEmpty` 才淡出——句间空档不闪。已知边界：长时间无字后的第一句，在首次识别完成前（约一个采样周期）会露出一下；要逐帧无痕得用「彻底擦除」。
- 遮布矩形 = 本帧所有横排行框的并集，四周按行高留边，再钳进搜索区域；换句时动画过渡到新框。
- 本机 OCR 模型不可用（没下载 / 平台不支持）时：遮布退回按搜索区域整块常显（等同手动档），并提示一次去设置里下载模型。

### 3.2 结构

- 截帧：`VideoPlayerController.captureRawFrameCrop(region)`——media_kit 补丁给 `screenshot` 加 `image/x-fushi-bgra` 格式 + `fushiRawTransform` 回调，在截帧 isolate 上拿到 `screenshot-raw video` 的 BGRA 缓冲后就地调用回调，**不做纯 Dart 的 PNG/JPEG 编码**（1080p 一次几百毫秒，持续采样不可接受）。只截视频本身，不合成字幕。
- 裁剪 + BGRA→RGBA 就是那个回调（`rawVideoFrameCropTransform`），只拷贝搜索区域的行，整帧不出截帧 isolate、不另起 isolate；识别走 `LocalScreenOcr.recognizeRgba`（PP 行检测 + 识别，会话常驻，与截屏识字 / 硬字幕 OCR 同一套本机模型）。
- 迟滞与框计算是纯函数 `SmartSubtitleMaskTracker`（`smart_subtitle_mask_tracker.dart`），单测覆盖；采样循环 `SmartSubtitleMaskSampler` 只负责「何时截、截完喂给 tracker」，输出一个 `ValueListenable<Rect?>` 给遮布层。
- 这里没有新的计算型子系统：识别复用现有 OCR，tracker 是几十行的几何。重活（彻底擦除）在 PR2 的 Rust crate。

## 4. PR2：擦除核心 `native/fushi_desub`（Rust 胖核心）

### 4.1 实测依据（2026-11-21）

素材：媒体库《想要成为影之实力者！》第 2 集 60 s 1080p，烧入真实字幕组双语字幕（32 句），与无字原片逐帧对齐；
装置 `D:\hibiki-tmp\desub-bench\`（不入库）。机器空闲时测。

| 每 512² 块推理 | MI-GAN | LaMa | Telea（OpenCV） |
|---|---|---|---|
| CPU | 495 ms | 1635 ms | 78 ms |
| DirectML | **22.5 ms**（输出与 CPU 一致） | 不支持（算子报错） | — |

| 60 s 片段（DirectML） | 推理次数 | 补全耗时 | 遮罩区 PSNR |
|---|---|---|---|
| 理想遮罩（原片做差）+ 分组 + MI-GAN | 345 | 21 s | 28.8 dB |
| 理想遮罩 + 分组 + 搬背景 + MI-GAN | 212 | —（脚本实现慢，非方法瓶颈） | **35.5 dB** |
| 检测框整块矩形当遮罩 | 2807 | 159 s | 17.1 dB（过盖 8 倍、误检 589 帧） |
| 检测→同句跟踪→抠笔画（§4.2 第 1–2 步）+ 搬背景 + MI-GAN | 220 | — | 30.4 dB（召回 0.97、过盖 1.35、误检 0 帧） |

结论：不需要 CUDA；MI-GAN + DirectML 比实时快；**遮罩质量决定一切**（推理次数与画质都随它走）；搬背景（同镜头静止背景从别帧取真实像素）是最大的画质项。

### 4.2 结构与管线

- Rust crate，C ABI + `dart:ffi`；推理用 `ort`（ONNX Runtime，load-dynamic），执行后端顺序 CUDA（有 N 卡且运行库齐）→ DirectML → CPU。与 `native/fushi_upscale`（漫画超分，并行开发中）共用 ort 装配方式，谁先合入谁定基线。只在 Windows 构建与装配。
- 粗粒度命令：`desub_job_start(config_json) -> job_id`、`desub_job_cancel`、`desub_job_pause/resume`；一条事件流（阶段、进度、预计剩余、错误码）。Dart 不存镜像状态。
- 管线：
  1. **检测与过滤**：PP-OCR 行检测（与 app 同一份模型文件）跑搜索区域；同一行被空格切开的框先合并；只留行高合理、横长、（默认）水平居中的框；位置常驻且跨大量镜头的判为水印，单独一类。
  2. **同句跟踪与笔画遮罩**：框跨帧连成轨迹（漏检几帧仍续上），框内亮像素图样突变处切成「句段」；一段内框固定。段内取多帧，「整段都亮且几乎不变」的像素为字芯，按行高外扩一圈盖描边与阴影（外扩在框外留边的范围内做，不被框截断）；抠不出字芯（深色字幕等）时按段内颜色聚类重抠，仍失败才退回整框。输出「有字片段表」。
  3. **补全**：
     - 按「镜头 × 句段 × 背景静止」分组，每组只补一次、贴回组内所有帧。
     - 先**搬背景**：同镜头、背景静止的其它帧里这块没被字盖住的像素直接搬来；残洞交给模型。
     - 模型：`migan`（默认，MIT，DirectML 可跑）；`lama`（仅 CUDA 可用时提供的「高质量」选项）；`flow`（高动态，RAFT 光流传播真实像素，残洞交 MI-GAN；自研，不参考 ProPainter 代码）。STTN 视真人片需求再评估，不在 PR2。
     - 只处理字幕带附近的块，不整帧送模型。
  4. **封装**：调 ffmpeg，无字片段按 GOP 边界尽量流拷贝，有字片段重编码（优先硬件编码器）；音轨 / 字幕轨 / 章节原样拷贝。产物落在视频旁 `<名字>.desub.mkv`（或任务目录），原文件不动。
- 设备提示：无 GPU 后端时允许 CPU，但 UI 明示「很慢（一集可能一小时以上）」，只作为后台任务排队。
- 模型分发：走现有本机模型下载器（manifest + 指纹），按需下载，不随包；自导出的 ONNX 放 GitHub Release 附件。
- 测试：遮罩阶段用「原片 + 烧字幕版」成对素材做回归（召回 / 过盖 / 误检帧阈值），补全阶段测分组与搬背景的确定性逻辑；模型推理只做冒烟。

## 6. PR4：手机委托电脑

- 复用「手机让电脑下」的执行设备层（`remote_download_execution`）：手机端选一台在线电脑，任务在电脑上跑，完成后回传或直接串流（设计图⑤）。

## 7. 不做

- 「边播边擦」（播放时实时补全）延后：MI-GAN + DirectML 算力够（每块 22 ms），但先把离线擦除的遮罩做稳，之后另开设计。
- 不接 ProPainter / E2FGVI（许可证）。
