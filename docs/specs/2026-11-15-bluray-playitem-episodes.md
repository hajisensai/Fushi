# 蓝光剧集盘按集入库 + 同一发布的多张盘并成一部作品

- 日期：2026-11-15
- 状态：方案已实现在分支 `claude/bluray-playitem-episodes`（叠在 PR #3458 之上）；§7 的取舍项**待拍板**，
  目前按「建议」一栏实现，改主意只动 §7 标出的那几处。
- 前置：PR #3458（`isBlurayMenuLoop`、`blurayPlaylistLooksEpisodic`、原盘搜索标题去卷标）。

## 1. 问题

只有「全部播放」、没有逐集播放列表的蓝光剧集盘，入库后是「一卷一个条目」。

真盘 `D:\video\播放列表合集\Majo no Tabitabi [BDMV]\Disc 1|Disc 2`（实测）：

| 盘 | META 盘名 | `00001.mpls` | 其它播放列表 |
|---|---|---|---|
| Disc 1 | `魔女の旅々　上巻` | 6 个 PlayItem：24.03 / 23.70 / 23.70 / 24.03 / 23.70 / 23.70 分钟，片段 `00003 00004 00005 00011 00012 00006`，每段 4～6 个章节点 | `00000` 厂标 0.6 分钟；`00002`～`00004` 特典 1.5～4 分钟；`00008` 菜单循环 150 段 540 分钟 |
| Disc 2 | `魔女の旅々　下巻` | 6 个 PlayItem：24.03 / 23.70 / 23.70 / 24.03 / 24.03 / 24.03 分钟 | 同形，`00008` 320 分钟 |

PR #3458 之后每卷能识别成《魔女の旅々》，但库里仍是两个各 143 分钟的单条目，各绑各的，没有分集。
本机库现状（只读查看）：合集 117 `魔女の旅々　上巻`（成员 `00001.mpls` + 菜单循环 `00008.mpls`）、
合集 118 `魔女の旅々　下巻`（同形），外加每卷三条特典行；两条 `00001.mpls` 行都没有观看进度。

目标：库里是**一部**《魔女の旅々》、12 集、集号 1～12 连续、各集能播，用户不用动手。

## 2. 一个 PlayItem 怎么成为库成员

### 2.1 身份：虚拟的分集路径

```
<盘根>/BDMV/PLAYLIST/<播放列表号>.p<锚点 PlayItem 序号，两位，1 起>.mpls
例：D:\…\Disc 1\BDMV\PLAYLIST\00001.p03.mpls
```

- **仍以 `.mpls` 结尾、仍在 `PLAYLIST/` 下**：`isBlurayPlaylistPath`、`blurayDiscRootForPlaylistPath`、
  `discRootForMemberPath`、互联远端按文件名认原盘成员（`isRemoteDiscMemberFileName`）、删除确认不给
  「删本地文件」、制卡裁剪强制重编码、ffmpeg 输入改写……这些「它是一条蓝光标题」的判据**原样成立**，
  不用逐个消费点加第三种分支。
- **它不是真实文件**：背后真实存在的是 `<播放列表号>.mpls`（`blurayEpisodeBackingPlaylistPath`）。
  「这一条还在不在」走 `discMemberBackingFilePath`（已有入口，加一条蓝光分集分支）；
  `videoPathFileExists*` 对它为假（它确实不是文件，不进备份包、旁边不放 sidecar）。
- **文件名去扩展名 `00001.p03` 就是派生播放列表的 id**，于是 `BlurayTitle.playlistPath`、
  `titleById[basenameWithoutExtension(path)]`、特典划分按 id 对号这些既有写法不改就对。
- 身份只编码「哪条播放列表的第几个 PlayItem 起头」，不编码累计集号——集号取决于同一发布里还有哪几张盘，
  盘增减时身份不能跟着变。

为什么不用别的方案：

| 方案 | 结论 |
|---|---|
| 新扩展名（`.mplsitem`，仿 DVD `.dvdtitle`） | 每个按 `.mpls` 认蓝光的消费点（约 29 个文件）都要补一条分支，漏一处就是静默失效；DVD 走这条路是因为它没有任何真实文件可借形 |
| 直接拿 `STREAM/<片段>.m2ts` 当成员 | 丢章节与 IN/OUT；一集跨多个 PlayItem 时没有对应文件；m2ts 已被规划层从散装视频里摘掉 |
| 不拆行，在整卷行上挂「章节 = 集」 | 进度、看完标记、刮削分集绑定、制卡来源全是按行的，一卷一行给不出逐集状态 |

### 2.2 怎么切集（`splitBlurayPlaylistEpisodes`，纯函数）

1. 前提：`blurayPlaylistLooksEpisodic`（≥ 2 段 ≥ 10 分钟、最长不超过最短 1.2 倍、合占总时长 ≥ 3/4）。
2. 每段 ≥ 10 分钟的 PlayItem 是一集的**锚点**；紧跟其后的短段（次回预告、提供画面）并入这一集，
   第一集之前的短段（厂标）并入第一集。一集 = 一段连续的 PlayItem 区间。
3. 防误切（§7-D2）：锚点每段 ≥ 18 分钟；恰好 2 个锚点时每段还要 ≤ 40 分钟。
   A/B 两半各 11 分钟的 OVA、中场休息切成两段的电影不切，照旧整条入库。
4. 拿不准就不切的另外三条（都是既有测试里的真实盘型逼出来的）：
   - **每个锚点开头都要有章节点**（容差 2 秒）。被无缝分支 / 换层切成几段等长的电影在接缝处没有章节点。
     实测本盘各段的 `connection_condition` 都是 5（无缝），与分段电影相同，不能拿它区分。
   - **锚点片段不能被盘上别的播放列表引用**（菜单循环除外，`blurayPlaylistSharesAnchorClips`）：
     另有逐集播放列表时它是漏网的「全部播放」，同片段换顺序的是诱饵播放列表。
   - `OP 集 OP 集 …`（以短段开头、以锚点结尾、锚点间夹短段）：短段归前一集还是后一集说不清，不切。

派生播放列表（`blurayEpisodePlaylist`）：片段取区间，章节只留落在区间内的并平移到本集零点，流表照抄。

### 2.3 统一读取入口

`readBlurayMemberPlaylist(memberPath)`：真实 `.mpls` 直接解析；分集路径读背后那条、切集、取对应区间；
对不上（盘被换过、判据不再切）返回 null。原先各自 `File(path).readAsBytes()` + `parseBlurayPlaylist`
的消费点全部改走它。

### 2.4 对各链路的影响

| 链路 | 结果 |
|---|---|
| 播放 | `resolveBluraySource` 走统一入口。本盘每集恰好整段用满一个 m2ts → 形态 1（真实文件路径），与逐集播放列表的盘完全同形；一集跨多段或需截取 → `edl://`，时间轴从本集 0 起 |
| 章节 | 本集内的章节点，已平移 |
| 规格探测 | `probeBlurayPlaylistFacts` 走统一入口，时长 / 字节数是这一集的；`VideoSpecsService` 的存在性 stat 改判背后文件 |
| 封面抽帧 | `primaryStreamPath` 是这一集自己的第一段码流（修前整卷封面永远是第一集的画面） |
| 制卡 / ASR / 字幕抽取 | 形态 1 时 `_videoPath` 是真实 m2ts；`edl://` 时保留分集路径，`prepareBlurayFfmpegArgs` 走统一入口按本集 IN/OUT 建时间轴。`hasLocalMediaFile*` 对分集路径按背后文件判，与整条标题同口径 |
| 外挂字幕 | 本盘 `STREAM/00003.ja.ass` 这类与 m2ts 同名的字幕，形态 1 下按真实码流路径找得到 |
| 互联远端 | host 的 `readBlurayTitleStreams` 走统一入口，段表只含这一集；成员文件名仍以 `.mpls` 结尾，client 侧判据不变 |
| 原盘菜单 | 菜单里点「本編再生」播的是整条 `00001.mpls`。绑定时照旧按既有规则给它建一行（不进合集，被划成特典挂在作品下）；下次扫描把它的进度折进对应那一集后回收（§4）。菜单内按 PlayItem 实时切换到分集行不在本期 |
| 删除 | 分集行与标题行同样不给「同时删除本地文件」 |

## 3. 同一发布的多张盘并成一个剧集单元

入库时先把本轮所有盘读完，再分「发布组」（`planBlurayReleaseSets`，纯函数）：

- **进组条件**：盘上有被切成集的播放列表（§7-D3 可放宽到多标题剧集盘）。其它盘一张一组，行为与修前逐字节相同。
- **组键** = 上级目录 + 作品名词干。词干：盘名来自 META 时取 `stripDiscVolumeMarker(盘名)`
  （`魔女の旅々　上巻` → `魔女の旅々`）；盘名就是目录名时，目录名是 `Disc 1` / `BD2` / `Vol.3` 这类
  纯卷标就取上级目录名，否则取去卷标后的目录名。
- **盘序**：卷号（`上/中/下` = 1/2/3、`第N巻`、`Vol.N`、`Disc N`、`BDN`，先看盘名再看目录名），
  再按路径自然序。
- **合集**：一组一个 `playlist` 合集，名字是词干（`魔女の旅々`），撞上别的盘 / 清单的同名合集沿用
  `blurayCollectionNameCandidates` 换名。只有一张盘在库时也用词干名——之后另一张盘到了直接并进来，不改名。
- **成员顺序** = 盘序 × 盘内集序，每轮对齐后把合集的**全部**成员重排（Disc 2 先入库、Disc 1 后到也排得对）：
  本轮读到的盘用盘内标题的卷号，本轮没读到的盘只看目录名的卷号，再按盘根、成员文件名自然序。
- **对齐按完整路径**，不按基身份：两张盘的 `00001.p01` 基身份相同，沿用 `reconcileSplitPlaylist`
  会把第二张盘的各集判成「已是成员」。本轮没读到的盘（移动硬盘没插）的成员不动。
- **集号**：刮削计划器对盘合集按合集内顺序排成员；协调器对「含分集成员或跨多张盘」的盘作品，
  按成员顺序给 `(1, 序号)` 的集号覆盖（`episodeOverrides`，与识别词偏移同一通道）。文件名
  `00001.p03.mpls` 不参与集号解析。Disc 2 的第 1 集因此是第 7 集。
- 盘面图：合集就绪回调传组内第一张盘的盘根。
- 特典仍按盘各自入库、不进合集，墓碑挂在新合集名下。

## 4. 存量迁移与清理

每张盘入库对齐后，对「库里盘根是这张盘」的行做一次对账（`DiscLibraryImporter`，同一事务）：

1. **整卷行就地改成第 1 集**：`videoPath` 从 `00001.mpls` 改成 `00001.p01.mpls`，`bookUid`、封面、
   观看统计、制卡记录全部保留；标题仍是自动名时改成新名。原断点落在第 k 集（k > 1）时，把断点减去
   该集起点写到第 k 集、第 1～k-1 集记为看完；原行已看完则本盘各集都记看完（§7-D1）。
2. **旧的单盘合集**（成员全在本盘、不是新合集）：把成员移出，移空自删。
3. **不再是标题也不是特典的成员行**——只回收能确证「永远不是内容」的两类（§7-D4）：菜单背景循环
   （`isBlurayMenuLoop`，如存量的 `00008.mpls`）、以及已被切成集的整条播放列表（第 1 步没接管的重复行，
   如菜单绑定时新建的那条，进度先按第 1 步的规则折进各集）。走既有回收路径
   `deleteVideoBooksAndReclaimAssets`（`keepLocalOnly`、不删用户文件、不写跨端墓碑）。
   其它「非标题非特典」的行（厂标、章节子集等用户从菜单点进去过的）不动。

蓝光 / DVD 既有的非剧集盘不走第 1、2 步；第 3 步的菜单循环回收对所有蓝光盘生效。

## 5. 不做的事

- 不改 schema、不新增持久化键；分集路径是 `VideoBooks.videoPath` 的一种新取值。
- DVD 不动（DVD 的 title 本来就是逐集的虚拟路径）。
- 蓝光镜像（`.iso`）仍不入库。
- 原盘菜单内按 PlayItem 实时映射到分集行（§2.4）。

### 7.1 拍板结果（2026-11-16，拍板台 `pr3461`）

维护者对 D1、D3、D4、D5 留言「怎么好怎么来」，对 D2 反问「这个好吗，会不会怪怪的」（已在拍板台留言回答）。定案：

- **D1 按建议**：整卷行就地变第 1 集、断点折算。删掉重建会丢 `bookUid` 上挂的观看统计、制卡来源、封面，不可逆；
  判据变了也有对称的反向迁移（`_revertUnsplitEpisodeRows`）把进度折回整卷。
- **D2 按建议，常量不改**：18 分钟把 TV 集（22～25 分钟）与 A/B 半集（11～12 分钟）分开，2 段 ≤ 40 分钟把
  「两集装」与两段式电影分开；真正挡误切的是三条结构判据（锚点开头有章节点、锚点片段不被别的播放列表引用、
  `OP 集 OP 集` 不切），时长只是第一道粗筛。代价是两类盘不切、仍整卷一条：泡面番（每集 < 18 分钟）、每卷
  2 集且每集 > 40 分钟的盘。回收策略已与常量解耦：分集行一律不物理删除，判据变成不切时走反向迁移改回整卷，
  以后调常量不会删用户的行。
- **D3 按建议**：只并被切成集的盘。自带逐集播放列表的多卷盘并组会把存量的每卷合集（含用户设的封面 / 排序）
  并掉，收益只是「更统一」，不值得为它改用户已有的合集。
- **D4 按建议，并修掉审查指出的丢进度**：回收范围仍只有菜单循环与被切集取代的整卷行。菜单绑定新建的整卷行
  每轮都会被回收，原先它的断点只「补空」给对应那一集，那一集早先看过时较新的断点会丢；改成按最后观看时刻
  **新者胜**（看完标记仍只补空）。
- **D5 按建议，并补上旧墓碑**：合集名用去卷标的盘内标题（与刮削 / 作品识别同口径；发布目录名常带
  `[BDMV]` / 压制组标签）。改名后用户删过的旧单盘合集（`魔女の旅々　上巻`）的墓碑查不到了：入库时对还没有
  任何分集行的剧集盘，再查它旧盘名（及「盘名 (上级目录)」消歧名）下的合集墓碑，有就整盘跳过，与修前
  「删过的盘合集重扫不复活」同一语义；恢复已解散分组 / 下载入库照旧并回来。
