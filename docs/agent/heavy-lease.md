  - **`0xC0000142` 启动即崩：根因是发起方死掉后 heavy 成了孤儿（2026-11-20 查清并修）**：21 次运行排了 12～116 分钟后一启动就以 `-1073741502`（`0xC0000142`，进程初始化失败）退出，`ranS` 为 0，成串出现（一条死掉、槽空出来、下一条进来又死）。根因：停掉 Claude Code 的 Bash 父进程链在这里断开，按进程树杀找不到它们（本次实测进程列表里 heavy 那条 bash 的父 PID 指向一个已不存在的进程）。heavy 于是继续排队，轮到时用 `inheritStdio` 把命令起进宿主已死的控制台，kernelbase 初始化控制台失败，0 秒退出、释放槽位，下一个孤儿同样崩。另有几条 `ranS` 4～30 秒的是运行途中调用方被停、孙进程再起时撞上死控制台。**修法**（`heavy_lease.dart` `HeavyCallerWatch`）：Windows 上用 `GetConsoleProcessList` 看 heavy 自己的控制台——停之前读数 5、停之后 0；只转后台没被停时一直是 5。**「调用方控制台消失 = 取消」**：启动时读数 > 0 catch 顺序取消 Ctrl-C 监听、`claimHere()` / `close()` rival 后退出；② 放行后、`Process.start` 之前再判一次（读到一次 0 时隔 1 秒再读，直到定论），已死就不起命令、放槽；③ 本地运行期间每 5 秒判一次，已死就杀进程树（不再把一次没人看的全量测试跑完）；命令自己非零退出时也再判一次，是调用方没了就记成取消而不是红；④
