# 硬字幕取时间 benchmark（帧差定字幕区间）

回答一个问题：**视频没有字幕轨、字幕烧在画面里（硬字幕）时，能不能靠对比相邻帧
找出「这一句字幕何时出现、何时消失」，给制卡的句子音频当区间。**

背景：视频制卡的音频区间完全取自字幕 cue
（`fushi/lib/src/pages/implementations/video_fushi/lookup_mining.part.dart` 的
`_resolveVideoMiningRange`）。硬字幕没有 cue → 区间 `0..0` → 卡片没有句子音频，
高级制卡的起止偏移也套不上（`video_advanced_mining.dart` 只在区间非空时才套）。

Python 原型，不参与任何构建、不被 app 引用；手动跑。真要做进 app 按「Rust 胖核心」
落在 native 侧，这里只是量具。

## 方法

1. **样片**（`burn.py`）：把本机番剧的日文软字幕用 libass 烧进画面，转 720p x264
   CRF23 模拟真实硬字幕的有损压缩。软字幕时间就是真值。
2. **模拟查词**（`truth.py`）：每条字幕在它显示期间的中点「暂停查词」一次；真值取
   查词点所在、同一区域（上 / 下）可见字幕集合不变的最大区间。
3. **检测**（`detect.py`）：解码查词点 ±8 s 的字幕带，以查词帧为锚取「文字像素」，
   逐帧算锚点文字像素的保持率，往两边走到连续 2 帧低于阈值处即为边界。
4. **OCR 字框**：产品里查词那一帧本来就要 OCR。这里用 `render_subs.py` 在黑底上
   单独渲染同一份字幕来模拟 OCR 行框（比真实 OCR 框干净，结果偏乐观）。

| 样片 | 内容 | 难点 |
|---|---|---|
| `takagi` | 高木同学 S01E01 0–8 min，CC 日字，白字黑边 | 上 / 下两种位置；字幕压在白纸、线稿上 |
| `takagi_yellow` | 8–16 min，黄字 1 px 细描边 + 阴影 | 故意做的难例 |
| `takagi_box` | 16–23 min，黑底框 | — |
| `kon` | 轻音乐剧场版 10–20 min，字幕组 ass | 自定义字体、粉色歌词、`\fad` 淡入淡出 |

## 结果（2026-11-03，620 次查词）

| 配置 | 检出率 | 检出里 ≤2 帧 | 检出里 ≤250 ms | >500 ms | 与 cue 的 IoU |
|---|---|---|---|---|---|
| `v1_auto` 纯像素特征（不用 OCR） | 96.6% | 48.9% | 56.3% | 186 | 0.73 |
| `ocrbox_k2` OCR 字框 + 稳定性 k=2 | 96.3% | 95.3% | 96.1% | 12 | 0.95 |
| **`best`** OCR 字框 + 稳定性 k=4 | **96.3%** | **96.3%** | **97.3%** | **9** | **0.95** |
| `glyph` 精确字形（理论上限）¹ | 83.5% | 98.6% | 99.0% | 2 | 0.96 |
| 对照：查词点 ±2.5 s 固定窗口 | — | — | — | — | 0.38 |

¹ `glyph` 没放低最小像素阈值，短字幕漏得多，只看精度上限。

`best` 分样片 ≤250 ms：`takagi` 97.7%、`takagi_box` 100%、`kon` 99.5%、`takagi_yellow` 91.9%。

速度（原始 1080p 片源，单次查词）：解码 ±8 s 0.46–0.75 s、±4 s 0.25–0.46 s
（H.264 BD 与 x265 10bit 都测了）；分析约 0.2 s（numpy）。

## 结论

- **必须用 OCR 字框限定**。不限定时，背景里「亮色 + 黑线」的像素被当成字
  （两个字的「も〜」掩码 1500+ 像素），静止镜头里换句看不出来，漏切成跨好几句的
  长区间。限定后 >500 ms 的错误从 186 降到 9。
- **误差里固定的那一帧是测试管线造成的**：烧录出的视频本身比 srt 晚一帧出字
  （2.544 s 的字幕在 2.586 s 才出现像素）。扣掉后检测器基本是帧级精确的。
- **剩余失败**：黄色 1 px 细描边压缩后「亮字 + 暗边」特征失效；字幕中途背后切镜头时
  框内混进的背景像素变化导致切早。「框内亮 / 暗分位像素」变体（`ocrbox2`）检出率
  反而降到 89.5%，已证伪。
- **没测到的**：真实 OCR 的框（这里是理想框）；音频能量包络吸附语音边界（没有语音级
  真值）；卡拉 OK、特效招牌字。

## 跑法

依赖：PATH 里有 `ffmpeg`，Python 3.12 + `numpy` + `opencv-python`。

```bash
cd tool/hardsub_timing_bench
python burn.py          # 烧录 4 份样片到 media/（约 2 min；片源路径在 burn.py 顶部）
python render_subs.py   # 黑底渲染字幕，模拟 OCR 字框（约 20 s）
bash sweep.sh           # 复现上表，每组配置约 45 s
python bench.py best mode=ocrbox thresh=0.45   # 单独跑一组，参数见 detect.Params
python diag.py best 20         # 误差分布 + 最差的 20 条
python diag_frames.py best     # 以帧为单位的带符号误差 + 未检出样本
```

`media/`、`results/` 不入库。
